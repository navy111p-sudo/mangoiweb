Product Proposal · 학생 학습 콘텐츠

AI 단어장, 왜 헷갈리고 어려운가 — 통합 개편 기획안

현재 단어 학습이 vocab.html(나의 단어장)과 micro-quiz.html(AI 단어 퀴즈)로 나뉘어 있어 아이들이 "뭘 눌러야 하는지" 헷갈립니다. 8가지 지적사항을 하나의 학습 사이클로 재설계하는 안입니다.

01 · 진단

말씀하신 8가지, 근본 원인으로 재정리

현재 코드(vocab.html · micro-quiz.html · review-quiz.html)를 확인한 결과, 대부분의 불만은 "기능이 없어서"가 아니라 있는 기능이 두 화면에 나뉘어 보이지 않아서 발생하고 있었습니다. 실제로 서버에는 이미 복습 예정일(SRS due), 약점 단어 가중 출제, 레벨별 단어은행이 존재합니다 — 다만 학생 눈에는 안 보입니다.

1
디자인 일관성 없음vocab.html은 짙은 남색 카드형, micro-quiz.html은 밝은 아이보리 배경 — 같은 서비스처럼 안 느껴짐
2
사용법이 어려움단어장 화면에 탭 4개(추가·복습게임·랭킹·도감) + 퀴즈는 완전히 다른 페이지 — 처음 온 아이가 순서를 모름
3
흥미가 떨어짐게임 요소(콤보·배지·망고 성장)는 이미 있지만 진입 장벽 때문에 그 앞에서 이탈
4
동기부여·격려 부족포인트 숫자는 나오지만 "잘하고 있다"는 감정적 메시지가 없음
5
전체 흐름 설명 없음오늘 뭘, 왜 해야 하는지 한 문장 안내가 없어 대시보드 숫자만 나열됨
6
사용 안내 페이지 필요첫 진입 시 그래픽 튜토리얼(닫기 가능) 부재
7
단어퀴즈 이원화vocab.html 안의 "복습 게임" 4모드와 micro-quiz.html "AI 단어 퀴즈"가 사실상 같은 일(내 단어 맞히기)을 각자 다른 화면·다른 URL에서 함
8
복습 기능 없음(으로 느껴짐)서버에는 복습 예정 단어(due count)가 이미 계산되고 있으나 화면에서 "선택해서 복습"하는 버튼이 없음
9
예습 기능 없음다음 수업/교재 단어를 미리 보는 화면 자체가 없음 — 학생게임 쪽엔 레벨·교재 매핑 API가 있지만 단어장에 연결 안 됨

02 · 벤치마킹

경쟁 서비스는 이 문제를 어떻게 풀었나

국내외 어휘 학습 서비스 5곳에서 초·중·고 학생 대상으로 검증된 패턴만 추렸습니다.

서비스핵심 패턴망고아이에 적용할 점
클래스카드
(국내 학교 표준)		 암기 → 테스트 → 순위, 3단계가 한 화면 안 탭 전환으로만 이동. 별도 페이지 이동 없음 단어장·복습게임·테스트를 URL 이동 없이 탭 3개짜리 허브 하나로 합치는 근거
Quizlet
Learn 모드		 같은 단어 세트를 플래시카드→객관식→철자쓰기 순으로 난이도를 자동으로 올려가며 반복 노출(간격반복) 지금 4모드(플래시카드/4지선다/거꾸로/철자)를 학생이 "골라야" 하는 부담을 없애고, 숙련도 낮은 단어일수록 쉬운 모드부터 자동 배정
Duolingo 연속학습일(streak) 하나를 최상단에 고정 노출 + 하루 목표 게이지 + 캐릭터가 감정 반응(웃음/실망)으로 격려 망고 캐릭터가 이미 있음(성장 단계). "며칠째 복습 중이야, 대단해!" 같은 희망톤 리액션을 정답/미션 달성 시점에 붙임
몬스터워즈/캐치잇잉글리시
(저연령 대상)		 글자 대신 큰 캐릭터 그림 + 짧은 음성으로 첫 화면을 채움, 설명은 3컷 이하 온보딩 가이드는 텍스트 설명서가 아니라 "카드 3장 넘기기"형 그래픽 튜토리얼로 — 저학년일수록 그림 비중을 높임
Kahoot 퀴즈를 "시험"이 아니라 라이브 게임쇼로 프레이밍(카운트다운, 순위 변동 애니메이션) 이미 있는 콤보·타이머·컨페티 연출을 테스트 탭 진입 화면에서부터 "게임 시작!" 톤으로 통일

03 · 설계 원칙

어린이·청소년 대상, 5가지 원칙

한 화면, 한 결정

화면마다 학생이 눌러야 할 큰 버튼은 하나만. 선택지가 2개를 넘으면 그림 아이콘으로 대체.

진입점은 하나

"단어장"과 "퀴즈"라는 두 개의 이름 대신, 하나의 이름 아래 4개의 탭(예습·학습·복습·테스트)만 존재.

실패해도 다음 문장은 희망적으로

[[student-facing-ai-text-hopeful-tone]] 원칙 그대로 — 오답이어도 "다음엔 맞힐 수 있어" 톤 유지, 과장 없이 연령대별 표현.

안 보이는 걸 보이게

서버가 이미 계산해둔 복습 예정 단어·약점 단어를 카드 형태로 꺼내 보여주는 것 — 새 알고리즘을 만드는 게 아니라 숨어있는 데이터를 노출.

비용 최소·기존 API 재사용

[[product-design-philosophy-7principles]] 원칙에 따라 새 인프라 추가 없이 기존 3개 API(vocab reward/stats, games/vocab, micro-quiz gen)를 재배선.

04 · 새로운 구조

하나의 허브, 4단계 학습 사이클

vocab.html과 micro-quiz.html을 물리적으로 한 파일로 합칠 필요는 없습니다 — "AI 단어장"이라는 하나의 진입 화면 안에서 4개 탭으로만 이동하도록 상단 탭바를 통일하고, 각 탭이 내부적으로 기존 파일의 로직을 호출하는 구조입니다.

Tab 1 예습 다음 수업 단어 미리보기. 정답 힌트 항상 표시, 포인트는 소량
→
Tab 2 학습 새 단어 추가(수동 입력 + AI 자동 뜻/예문) — 기존 vocab.html 기능
→
Tab 3 복습 오늘의 복습 예정 단어(SRS due) + 범위 선택 체크박스, 게임 4모드
→
Tab 4 테스트 micro-quiz 흡수. 출제범위(단어장/레벨은행) + 결과·랭킹

홈 화면은 "오늘 뭘 해야 하는지" 한 문장으로 시작

대시보드 숫자 나열 대신, 서버 값을 조합한 안내 문장 하나를 최상단에 고정합니다. 예: "오늘 복습할 단어 12개가 기다리고 있어요 — 5분이면 끝나요!" 복습 예정이 0개면 "새 단어 3개만 추가해볼까요?"로 자동 전환. 이미 vocab.html에 있는 updateHeroCta(due) 배너 로직을 허브 홈 전체로 확장하는 방식이라 신규 개발이 아닙니다.

05 · 항목별 해결안

9가지 지적사항 → 구체적 조치

문제 1·5

디자인 불일치 + 전체 흐름 이해 어려움

해결

vocab.html의 다크 카드 스타일을 공통 토큰으로 추출해 micro-quiz.html에도 적용. 상단 4탭 고정, 탭 밖 이동(다른 URL) 없이 동일 톤 유지근거: 두 파일 모두 vanilla CSS라 별도 프레임워크 없이 공통 CSS 파일 하나 분리 가능

문제 2·3

어려운 사용법 · 흥미 저하

해결

복습 탭 진입 시 모드를 학생이 고르지 않고 숙련도 기반 자동 배정(Quizlet Learn 방식). 선택 부담을 없애 "그냥 시작" 버튼 하나로근거: 이미 약점단어 가중 로직(wrong×3−correct)이 micro-quiz 서버에 존재 — 확장만 하면 됨

문제 4

동기부여·격려 부족

해결

망고 캐릭터 리액션에 연령대별 희망톤 문구 세트 추가(정답/오답/미션달성/스트릭 4시점), 보호자·강사 알림에도 "오늘 12단어 복습 완료" 요약 발송근거: [[student-facing-ai-text-hopeful-tone]], api-notify.ts 알림 채널 재사용

문제 6

온보딩 그래픽 안내 부재

해결

최초 진입 시 3~4컷 카드 튜토리얼(그림 중심, 텍스트 최소) 모달. 닫기(X) + "다시 보지 않기" 체크 → localStorage 플래그. 우측 하단에 언제든 다시 볼 수 있는 "?" 버튼 유지근거: 신규 UI, 서버 변경 없음 — 프론트 전용

문제 7

단어퀴즈 이원화

해결

micro-quiz.html의 화면·로직을 허브의 "테스트" 탭으로 흡수(파일은 남기고 iframe 또는 라우팅으로 내부 호출). 출제범위는 이미 있는 [내 단어장 | 내 레벨 단어은행] 토글을 그대로 승격근거: 두 화면 다 vocab_review_log에 기록하므로 데이터는 이미 통합돼 있음 — UI만 하나로

문제 8

복습 기능 없음(으로 느껴짐)

해결

"오늘의 복습" 카드에 due 단어 개수 노출 + 학생이 범위를 고를 수 있는 선택 버튼([오늘 복습 전체]/[틀렸던 것만]/[오래된 것만]) 추가근거: /api/vocab/stats가 이미 due count 계산 — 화면에 select UI만 추가

문제 9

예습 기능 없음

해결

신규 "예습" 탭 — 로그인 학생의 레벨·교재로 다음 단어를 미리 보여줌. 정답을 가리지 않고 "미리 보기" 모드로만 동작(포인트는 학습 완료 후에만 소량 지급)근거: /api/games/vocab(레벨·교재 매핑)을 그대로 재사용 — 새 데이터 파이프라인 불필요

06 · 실행 순서

3단계 로드맵 — 배포 리스크 낮은 순서

Phase 1

보이게 만들기

  • 공통 디자인 토큰 통일
  • 4탭 허브 네비게이션
  • 온보딩 그래픽 튜토리얼
  • "오늘 할 일" 한 문장 배너
서버 변경 없음 · 프론트 전용이라 가장 안전. 데이터 파괴 위험 없음
Phase 2

복습·예습 노출

  • 복습 탭에 due 카드 + 범위 선택
  • 예습 탭 신설(games/vocab API 연결)
  • 모드 자동 배정(숙련도 기반)
기존 API 재사용, 신규 엔드포인트는 예습 조회 1개 정도로 최소화
Phase 3

테스트 탭 완전 흡수

  • micro-quiz.html → 테스트 탭 내부화
  • 보호자·강사 요약 알림 연동
  • 희망톤 리액션 문구 세트 적용
가장 손이 많이 가는 단계 — 기존 게스트 토큰·포인트 멱등 로직을 건드리므로 마지막에 배치

07 · 주의사항

진행 전 확인할 것

review-quiz.html은 이번 통합 대상이 아닙니다. 이건 학생이 스스로 보는 퀴즈가 아니라 강사가 낸 시험지(교재 진도 기반, 안티치트 구조)라 성격이 다릅니다. "테스트" 탭에 합치는 건 vocab.html 복습게임 ↔ micro-quiz.html 두 가지만입니다.

담당 영역: vocab.html · micro-quiz.html · review-quiz.html은 학생 학습 콘텐츠(B) 담당 파일입니다. index.html 안에도 단어 게임 쌍둥이 로직이 있어 변경 시 동기화가 필요합니다. 실제 착수 전 A담당(배포 권한자)에게 범위 공유 권장.
