# 2. AI 말하기 자연스러움 및 응답속도 개선

검증 기준: `navy111p-sudo/mangoiweb` main `4e559303e56ee3a894fe51403f9de613c4cbc48d`.
범위: AI 말하기 본 화면(`warmup.html`)과 AI 친구(`ai-friend.html`)의 버튼·자동·얼굴 대화.
상태: **로컬 수정 및 격리 Harness 검증 완료, 실제 브라우저·음성·서비스 종단 검증은 추가 필요**.
운영 병합·배포·DB 변경·유료 AI 호출·실제 사용자 마이크 사용은 실행하지 않았다. 15:39 UTC에 main을 다시 확인해 위 커밋과 일치했다. PR #1370/#1371의 학생별 음성 속도 저장 기능을 포함한 최신 소스를 보존했다.

## 1. 현재 문제

- 얼굴 자동 대화에서 취소된 낭독의 대기 수가 남아 다음 마이크가 오래 기다릴 수 있다.
- 취소한 음성의 늦은 콜백이 새 음성의 아바타/완료 상태를 건드릴 수 있다.
- 캐시된 TTS를 새로 재생해도 이전 합성 요청이 무효화되지 않아 늦은 응답이 현재 음성을 덮을 수 있다.
- 기기 음성 4초/클라우드 음성 8초 고정 완료 타이머가 긴 음성이 끝나기 전에 완료를 알린다.
- 지연된 스트리밍 문장이 사용자의 중단 후 다시 낭독될 수 있다.
- 녹음·전사·모델·합성·출력 시작을 한 턴에서 비교하는 계측이 부족하다.
- AI 말하기의 기기/클라우드 음성도 취소된 완료 이벤트가 새 아바타를 멈출 수 있다. 기기 음성은 오류·종료 이벤트가 각각 완료를 부를 수 있다.
- AI 말하기의 이전 브라우저 인식기가 취소 후 보낸 결과가 입력칸을 덮을 수 있다.
- AI 말하기의 기존 지연 기록은 15초 넘는 첫 재생을 근거 없이 다시 듣기로 간주해 버렸다.
- 최신 main의 속도 복원 중 화면 숨김/복귀는 첫 인사를 영구 취소하고, 겹친 설정 GET은 늦은 옛 응답이 새 속도를 덮을 수 있다. 두 PR 리뷰 지적을 별도 재현했다.

## 2. 문제 재현 결과

실제 배포 소스를 Node VM에서 실행한 결정론적 격리 검사에서 기존 main은 공통 검사 37개 중 **28 통과 / 9 실패**였다. 마이크 진폭, 네트워크 응답, 재생 이벤트와 시계는 제어된 테스트 대역이다. 실제 음성인식·모델·TTS 서비스 성능 측정이 아니다.

AI 말하기 본 화면은 별도 재현 검사 **0 통과 / 5 실패**였다. 위 기기/클라우드 완료·중복 완료·늦은 인식 결과·느린 최초 출력 누락을 실제 소스에서 각각 재현했다.

최신 속도 복원/화면 복귀 별도 검사는 **4 통과 / 5 실패 → 9 통과 / 0 실패**였다.

얼굴 모드의 취소 후 재청취 대기는 가상 시계에서 **25,800ms**로 재현됐다. 실제 브라우저 검사는 실행되지 못했으므로 이 숫자를 운영 대기시간이나 실측 절감률로 해석하면 안 된다.

## 3. 확인된 원인

- `stop()`은 완료 콜백을 부르지 않지만 얼굴 모드의 `pending`은 완료 콜백에만 의존했다.
- 세대 판정이 원본 `speakText`의 아바타 정지 부작용을 보호하지 않았다.
- TTS 캐시 경로가 새 세대 번호를 만들기 전에 반환했다.
- 재생 완료 타이머가 실제 음성의 진행·종료 상태를 확인하지 않았다.
- 스트림 리더가 요청 당시의 턴 번호를 보존하지 않았다.
- STT/TTS 요청이 끝나지 않는 경우에 대한 명시적 제한이 없었다.
- AI 말하기의 네이티브 인식 콜백은 페이지 세대만 확인하고 개별 녹음 세대는 확인하지 않았다. 기존 지연 로거는 느린 응답과 명시적 다시 듣기를 구분하지 않고 시간으로 추정했다.

## 4. 수정한 내용

- 취소 시 얼굴 대기 상태를 즉시 초기화하고, 오래된 완료는 현재 발화에 영향을 주지 못하게 했다.
- 실제 음성이 재생 중이면 다음 문장/마이크로 성급하게 넘어가지 않도록 했다.
- 정체된 재생은 먼저 멈춘 후 완료 처리한다. 얼굴 모드의 장시간 안전망은 미완료 음성 위로 마이크를 여는 대신 일시정지한다.
- 캐시 재생도 새 발화로 취급하고, 새 음성을 요청할 때 이전 음성을 먼저 멈춘다.
- 중단 뒤 도착한 스트림 문장·최종 응답을 버린다.
- STT는 30초, TTS 응답과 오디오 본문은 15초 제한을 추가했다. TTS 제한 시 기존 기기 음성 대체 경로를 사용한다. 일시 실패의 400ms 한 번 재시도는 유지했다.
- 취소된 전사는 즉시 정리되고 늦은 성공·오류가 화면을 바꾸지 않는다.
- AI 말하기에도 Whisper 입력→전사→채팅→합성→실제 재생 시작을 연결했고, 브라우저 인식 결과 도착 시점은 별도로 기록한다. 인식 결과 도착을 실제 소리가 끝난 시각으로 표시하지 않는다.
- AI 말하기의 기존 지연 로거·문장 분할/스트리밍·화자/언어 처리는 유지하고, 느린 첫 출력도 기록한다. 다시 듣기는 버튼 경로로 명시적으로 제외한다.
- AI 말하기의 이전 녹음 세대·음성 콜백을 무효화하고 조용히 취소한 인식기의 타이머도 정리한다.
- AI 친구의 채팅/SSE는 30초 무응답 제한을 두고, 실제 스트림 데이터가 오면 제한을 갱신한다. 사용자가 끊으면 요청도 취소하며 늦은 오류 말풍선을 내지 않는다.
- 속도 설정의 최신 GET 세대만 적용하고, 초기 인사 완료 전 숨김으로 취소됐을 때만 복귀 후 한 번 재시도한다. 완료된 인사는 반복하지 않고 종료 요약창이 열려 있으면 계속 멈춘다.
- 속도 복원 대기 후 낭독은 같은 호출 안에서 이어가도록 해 얼굴 대기 카운터가 이중 등록되는 통합 회귀도 막았다.
- 텍스트·음성·학생 ID·토큰 없이 최근 50턴의 시간 숫자만 메모리에 보관하는 진단 기능을 추가했다. 저장·전송·새 스키마는 없다.

## 7. Sandbox 테스트 내용

제어된 실패 응답·미완료 Promise·늦은 이벤트·재시도·타임아웃·취소를 실제 소스에 주입한 격리 실행을 했다. 외부 서비스는 호출하지 않았다.

실제 Chromium 자동 실행은 운영체제의 소켓 제한으로 시작하지 못했다. 기존 클라우드 브라우저도 로컬 테스트 주소를 `ERR_BLOCKED_BY_CLIENT`로 차단했다. 이 제한을 우회하지 않았다. 따라서 실제 브라우저 Sandbox는 **미검증**이다.

## 9. 성공·실패 결과

최종 실행 검사는 전부 통과했다. 기존 main에서 실패한 AI 친구/공유 9개 및 AI 말하기 5개 재현 검사는 수정본에서 통과했다. 다만 브라우저 실행·실제 소리·영어 억양별 정확도·실제 공급자 시간은 통과로 계산하지 않았다.

## 10. 테스트 중 추가 발견된 문제

고정 완료 타이머를 단순히 늦추면 합성 요청 정체에서 무한 대기가 생길 수 있었다. 오디오 본문 수신 정체도 헤더 수신 제한만으로 해결되지 않는다. 음성 대체 API가 없는 환경에서는 새 busy 상태가 남을 수 있었다. 또한 늦은 SSE 문장은 TTS 콜백 보호만으로 막을 수 없었다. AI 말하기의 네이티브 음성인식도 조용히 취소한 뒤 늦은 결과를 받아 입력칸을 덮는 문제가 재현됐다.

## 11. 추가 문제 수정 내용

응답 본문까지 포함한 합성 제한, 전사 제한, 기기 음성 부재 시 정리, 요청 세대에 묶인 스트림 폐기, 미완료 응답 시 얼굴 모드 일시정지를 추가했다. AI 말하기에도 합성 본문까지의 제한, 네이티브 인식 세대 보호와 타이머 정리, 중복 낭독 완료 방지를 적용했다.

AI 말하기 서버에도 기존 모델 지연 기록이 있으나 이번에는 서버를 수정하지 않았다. AI 말하기 네이티브 인식의 첫 결과·마지막 결과→녹음 종료는 인식 이벤트 기준이며, 음향 발화 종료나 공급자 처리시간으로 바꿔 부르지 않는다. 음성인식 정확도와 자연스러움은 이 숫자만으로 입증되지 않는다.

## 15. 남아 있는 위험요소

- 실제 사람의 다양한 영어 발음과 소음·느린 말투·긴 대화 자연스러움은 미검증이다.
- Whisper 녹음 종료는 기존 음량 기반 판정이다. AI 친구 2.5초·AI 말하기 자동 1.6초보다 긴 생각하는 휴지, 자동 녹음 20초 이상의 발화는 별도 검증이 필요하다. AI 말하기 수동 녹음은 기존 최대 3분을 유지한다.
- 15초 TTS 제한은 매우 느리지만 정상인 공급자 응답도 기기 음성으로 바꿀 수 있다. 실제 환경에서 임계값 검증이 필요하다.
- 추가한 15초 합성/30초 채팅 무응답 기준은 실제 느린 환경에서 사용성 검증이 필요하다. 실제 영어 억양·모델 응답 품질과 시간은 공급자 호출 승인 없이는 검증할 수 없다.
- 상세 계측은 AI 친구와 AI 말하기에 모두 연결했다. 음성인식 정확도와 긴 실제 대화의 문맥·자연스러움은 승인된 샘플과 실제 모델 검증이 필요하다.
- 이력 20개 범위와 기존 프롬프트는 유지했다. 장시간 문맥 유지 품질이 개선됐다고 주장하지 않는다.
- 공유 TTS/마이크 코드이므로 실제 모바일·iOS·Android·게임 화면의 회귀 확인이 추가 필요하다.
- 기존 PR #1252는 열려 있고 충돌 중이다. 그대로 병합하지 않았다.
- 최신 학생별 음성 속도 저장 기능을 보존해 재통합했다. 다른 병렬 작업과 합칠 때 HTML의 공유 JS 버전 참조와 자산 원장 충돌만 좁게 해결하고 다시 검사해야 한다.

## 16. 최종 검증 상태

**추가 검증 필요.** 로컬 수정·재현·실패 주입·반복·관련 회귀는 통과했다. 실제 브라우저와 허가된 음성 샘플을 이용한 공급자별 측정, 전체 음성 대화 흐름 검수 후에야 운영 적용 여부를 판단할 수 있다. 사용자 최종 승인 전 병합·배포하지 않는다.

다음에 필요한 것: 테스트 가능한 승인된 브라우저 환경, 사용 허가된 비식별 음성 샘플, 실제 STT/LLM/TTS 호출 범위·비용에 대한 승인. 이 자료가 없으므로 정확도나 실제 속도 개선율을 만들지 않았다.
