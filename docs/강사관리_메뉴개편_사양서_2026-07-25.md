# 강사 관리 메뉴 개편 + 성능 개선 사양서 (Teacher Menu Redesign + Perf)

> 목적: 관리자가 **① 헷갈리지 않고·여기저기 안 찾고**(메뉴 구조) + **② 가볍게·렉/버퍼링 없이**(성능) 강사 업무를 보게 한다.
> **①과 ②는 다른 문제이고, 둘 다 병행 필수** (사장님 지시). 메뉴만 재배치하면 가벼워지지 않음.
> 담당: 화면은 `cloudflare-deploy/public/admin.html` → **A(배포권한자) 구현·배포**. 본 문서는 그대로 구현 가능한 사양.
> 시안(클릭 데모): `docs/강사관리_개편안_시안_2026-07-25.html` (또는 바탕화면 동명 파일)

## 2. 목표 구조 (New IA) — ①

### 진입 = 상단 탭 4개 (전사)
`강사 목록` · `급여 정산` · `승인 요청함` · `통계`

### 강사 클릭 → 상세 한 화면(탭 5개)
`프로필` · `수업 배정` · `급여(이 강사)` · `평가·평점(이 강사)` · `메모·MBTI`

### 16개 → 매핑
| 지금 | 새 위치 |
|---|---|
| 강사 관리 | 강사 목록 (＋등록=상단 버튼) |
| 자동 급여 / 급여 관리 | 상단[급여 정산](전사) + 상세[급여](개인) |
| 연기·변경 요청 / 연기 현황 | 상단[승인 요청함] |
| 학생 수업 평가 / 칭찬 통계 | 상단[통계] + 상세[평가] |
| 변경 이력 / 회선품질 / 슈퍼바이저 | 상단[통계] |
| 시간표 / 수업 일지 / 방 초대 | 상세[수업 배정] |
| MBTI | 상세[메모·MBTI] |
| 보고서 양식 | 시스템으로 이동 |

→ 사이드바 **16개 → 상단 탭 4 + 상세 탭 5**. 평면 나열 소멸. 두 벌 메뉴는 **한 벌로 통일**.

## 3. 성능 목표 — ② (메뉴와 병행 필수)

체감 이득 큰 순서:

- **[성능 1순위] 폴러/settle 정리 (P2)** — 렉의 진짜 원인. `__admSettleRun` 묶음 + 독립 폴러 십수 개를 감사해 (a)불필요한 것 제거, (b)스크롤/조작 중 미루기(idle에만 실행). 이전 실측: 스크롤 중 미루기로 **p95 33.2 → 16.9ms**. **메뉴 개편 없이도 즉시 효과.**
- **[성능 2순위] 지연 로드 (P3)** — 강사 상세 각 탭은 **처음 열 때만** fetch + 세션 캐시. 목록 진입 시 전 강사 급여/평가 미리 안 부름.
- **[성능 3순위] 목록 페이지네이션/가상스크롤** — 표 50행 단위. DOM 폭증 방지.
- **[성능 4순위·별도 大과제] `admin.html` 파일 분할 (P1)** — 1.3MB 단일 파일이 근본 무게. 강사 관리 뷰를 별도 로드 청크로 떼는 방향. 규모 큼 → 별도 계획.

> ⚠️ 메뉴 개편(①)만 하면 ②는 거의 안 변함. **P2(폴러 정리)를 ①과 같은 순번으로** 착수해야 "가벼워졌다"가 체감됨.

## 4. 실행 트랙 (①·② 병행)

**Track A — 메뉴/IA**
- A1: 버그 접수 제거(사이드바 `:12547`+허브 `:2880`→시스템) · 급여 중복 점프버튼 제거(`:4786~4796`). 반경 작음.
- A2: 사이드바 강사 통합 → 상단 탭 4 체계 + `강사 목록` 마스터-디테일. 허브와 한 벌 통일.

**Track B — 성능** (A와 동시 진행)
- B1: **폴러/settle 감사·정리 (P2)** ← 즉시 체감, 최우선.
- B2: 상세 탭 지연 로드 + 캐시 (P3).
- B3: 목록 페이지네이션.
- B4(별도): 파일 분할 (P1).

권장 순서: **A1 + B1 먼저**(둘 다 반경 작고 체감 큼) → A2 + B2 → B3 → B4.

## 5. 반영 전 필수 검증 (A)

1. `cd cloudflare-deploy && npx tsc --noEmit`
2. `node test-harness/run.mjs --fast`
3. **인라인 JS 문법 하니스** + 실제 브라우저 admin 로그인 후 메뉴 전수 클릭
4. 성능은 **before/after 실측**(스크롤 p95 ms, 첫 로딩 시간)으로 "가벼워졌다" 확인 — 체감 보고만으로 판단 금지
5. `deploy.ps1` 전 `git status`로 미커밋 파일 딸려감 방지

## 6. A2-2 강사 상세 페이지 구현 사양 (탭 × 필드 × API)

> 최종 확정 모습(사장님 승인): **강사 통합 → 강사 목록(표)만 → 강사 클릭 → 상세 한 화면(탭 5개)**. 전사 단위는 상단 탭 3개.
> 구현 원칙: 새로 만들지 말고 **기존 카드/엔드포인트 재사용** + 탭은 **처음 열 때만 로드(lazy)**.
> 진행 상태: 🟡 미착수(구현). 시안 = `강사관리_개편안_시안_2026-07-25.html`.

### 강사 목록 (진입) — 소스 확인 결과(2026-07-25)
- 데이터: `js/adm-core.js` `loadTeacherProfiles()` → **`GET /api/admin/teacher-profiles?status=&group=`** (credentials:include), 응답 `{ok, items:[...]}`
- 강사 필드(SELECT * 전체): `id·image_url·korean_name·english_name·mbti·status·group_name·active_region·fee_per_10min·join_date·phone·kakao_id·email…`
- 🎯 **`window._tpRowById[id]` 에 전체 행 캐시됨**(목록 렌더 시) → **프로필 탭은 재요청 없이 이 캐시만 읽으면 끝**. 상세 뷰 오픈 함수는 `window._tpRowById[id]` 사용.
- 권한: 강사(hq_teacher)는 본인만, 지사/대리점/학부모/학생은 차단 — 상세 뷰도 동일 게이트 재사용(`_effectiveRole`).
- 기존 행에 이미 **`tp-act--view`(파란 상세보기 버튼)** 있음 → 이걸 상세 뷰 트리거로 재사용 검토.
- UI: 검색 + 구분/상태/그룹 필터바(이미 있음, adm-p2/q6) + `＋등록`(기존 tp 등록폼)
- 행/뷰버튼 클릭 → **상세 뷰 전환**(현재는 카드 스크롤)

### 상세 탭 5개
| 탭 | 필드 | 데이터 API | 실세션 검증 포인트 |
|---|---|---|---|
| **프로필** | 한/영명·이메일·휴대폰·카카오·생년월일·성별·담당과목·입사일·사진/소개영상·상태·학생페이지 노출 | `/admin/teacher-profiles` | 강사1명 선택 시 필드가 실데이터로 채워지나 |
| **수업 배정** | 요일·시간(KST)·학생·교재·상태(확정/연기요청)·주간 수업수 | `/admin/teacher-classes` + `/admin/teacher-unavailability` + `card-timetable` | 이 강사 실제 수업이 뜨나 |
| **급여** | 이달 예상급여(환전전)·완료 수업수·월별 이력(지급상태) | `/admin/teacher-payroll` + `/admin/teacher-rates` (이 강사 필터) | 값이 `card-payroll`과 일치하나 |
| **평가·평점** | 평균 평점(30일·건수)·출석/정시율·최근 평가(날짜·학생·별점·코멘트) | `/admin/teacher-evaluation` + `card-class-ratings`(이 강사) | 평점이 실제 학생평가와 일치하나 |
| **메모·MBTI** | MBTI·이달 칭찬수·내부 메모 목록(작성자·날짜)+새 메모 | `teacher-profiles`(mbti) + `card-praise-stats`(이 강사) + 내부메모 | 🔴 **메모 저장 API 없으면 신규 필요** → `src/index.ts` 화이트리스트 등록 안 하면 404 |

### 상단 탭 3개 (전사)
- **급여 정산** = `card-payroll` + `card-payroll-auto` 통합 · **승인 요청함** = `card-schedule-requests` · **통계** = `card-class-ratings` 집계 + `card-praise-stats` + `card-supervisor`

### 구현·검증 순서 (실세션)
1. 목록 뷰 + 행 클릭 → 빈 상세 뷰 전환 (구조만, 캡처 확인)
2. 탭 하나씩 API 연결 → **실세션에서 데이터 뜨는지 캡처 확인 후** 다음 탭
3. 각 탭 lazy-load + 세션 캐시(재클릭 시 재요청 X)
4. 🔴 메모 저장 API 필요 시 `api-admin.ts` 핸들러 + `index.ts` 화이트리스트 함께 등록(안 하면 404)

> ⚠️ 상세 탭의 데이터 동작은 **로컬 file://에선 검증 불가**(서버 없음). 반드시 **실제 admin 로그인 세션**에서 탭별로 눈으로 확인하며 진행.
