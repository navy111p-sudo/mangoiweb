# 개발일지 원본 (Development Diary — source)

사장님이 보시는 **「최신 일지」 PDF 2개의 원본**입니다. PDF는 산출물일 뿐이고, **고칠 것은 이 폴더의 HTML 2벌**입니다.

| 파일 | 용도 |
|---|---|
| `개발일지_한국어.html` | 한국어판 원본 |
| `개발일지_영어.html` | 영어판 원본 (강사 다수가 필리핀이라 **한/영 둘 다 고쳐야 합니다**) |
| `PDF만들기.ps1` | 크롬 headless 로 PDF 2개 생성 |

## ⚠️ 사본이 두 벌입니다 — 어긋나기 쉽습니다

```
바탕화면\02_망고아이_문서보고서\개발일지_소스\   ← 지금까지 실제로 고쳐 온 곳
docs\개발일지_소스\                              ← 이 폴더 (2026-08-04 저장소에 편입)
```

고칠 때 **둘 다** 갱신하거나, 한쪽을 정해 쓰고 다른 쪽을 복사해 두세요.
이 폴더의 `PDF만들기.ps1` 은 `$PSScriptRoot` 기준으로 동작하므로 **여기서 그대로 실행됩니다.**

## 작성 규칙

- **최신 날짜가 맨 앞.** 새 날짜를 앞에 끼우고 직전 날짜는 이렇게 강등합니다:
  `datehead` → `datehead past` · `badge` → `badge past` · "오늘 한 줄" → "이날 한 줄"
- `badge">최신` (영어판은 `badge">LATEST`) 이 **파일당 정확히 1개**여야 정상입니다.
- 같은 날 작업이 추가되면 **새 날짜 블록을 만들지 말고** 그날 블록 안에 섹션을 넣고 번호를 조정합니다.
- 날짜 블록 구성: `.month` → `.datehead` → `.oneline`(파란 한 줄) → `.kpis` →
  `h2.sec` + `.star`(노란 ★) → 끝에 `<div class="pg">`(페이지 나눔)
- `.kpis` 는 `flex-wrap` 이 없어 한 줄에 5칸이 한계입니다. 더 넣으려면 `<div class="kpis">` 를 **한 벌 더** 두세요.
- 어려운 말은 `<span class="grey">(회색 괄호)</span>` 로 그 자리에서 풉니다.

## PDF 만들기

`PDF만들기.ps1` 은 끝에 `pause` 가 있고 **출력 경로가 바탕화면 루트**라 자동 실행에는 맞지 않습니다.
자동으로 돌릴 때는 로직만 인라인으로 실행하고 `--print-to-pdf` 경로를 아래로 직접 지정하세요.

```
바탕화면\개발자료(중요)\★1_반드시_할것_망고아이개발\01_개발일지_최신\
  · 망고아이_개발일지_최신.pdf
  · Mangoi_Development_Diary_LATEST.pdf
```

## 검증

고친 뒤에는 최소한 이것만 확인하세요.

- `<div>`/`<h2>`/`<span>` 여는 태그와 닫는 태그 개수가 같은가
- `최신`(`LATEST`) 배지가 파일당 1개인가
- 그날 블록의 섹션 번호에 중복·누락이 없는가

## 날짜 확인

🔴 **파일 수정시각(mtime)과 실제 작업 날짜가 어긋나 있습니다.** 날짜는 **git 커밋 시각**으로 확인하세요.
배포 커밋은 HTML 53개에 `BUILD:` 도장만 찍으므로, 그날 실제로 한 일은 이렇게 뽑습니다.

```bash
git diff -I'BUILD:' --stat <어제_마지막_커밋>..HEAD
```
