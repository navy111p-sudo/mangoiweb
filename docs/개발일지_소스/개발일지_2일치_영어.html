🔴 Most important (3 things to know)

  • A parent tapping "KakaoTalk channel" to ask a question got nothing at all. The channel itself was fine (official Mangoi channel, 1,169 followers). The problem was the "/chat" on the end of the address — on desktop web, if you are not signed in, Kakao bounces you to a login screen. Someone who just wanted to ask a question was being asked to log into Kakao first. → Switched to the channel home, which opens without a login and contains chat, chatbot, phone and location anyway. On top of that, this screen is reached from an SMS link, so it opens inside the KakaoTalk / SMS in-app browser — and those silently swallow "open in a new window." → If a new window fails to open, we now open it in the same window no matter what. The 12px text that was impossible to hit on a phone became a finger-sized yellow chip (Korean + English).
  • Teacher "lateness" was being counted by a human. Twenty teachers times a month of classes, by hand — easy to miss, easy to get wrong. And the raw data (actual join time) was already there. → Built a screen that matches class time against actual join time and shows the late minutes. ⛔ It does not dock pay automatically — a connection log is not proof of lateness (dropped lines, rejoins, clock drift). Money still uses only the number a human confirms. There is a 3-minute default grace, and we look at the earliest join only so a rejoin after a dropout is not counted as late. Where it disagrees with the human-entered number, it is flagged as "differs."
  • The test was wrong, and I nearly tore up working code because of it. A check on the level-test "my application" screen was failing and blocking deploys. Digging in, the feature was completely fine (endpoint, query and permissions all correct). The check was keying off code indentation, so when the formatting shifted slightly it declared the feature entirely absent. → Not one check was changed — only the way it locates the code, so formatting no longer shakes it (47/47 pass; 3 were failing before). 🔑 A failing test does not automatically mean the code is wrong. Yesterday had the opposite case too — the outage watchdog really was broken.

✅ Done today

  • The KakaoTalk contact button now opens without a login, and opens reliably inside in-app browsers.
  • Unblocked the deploy gate by fixing one test that was shaken by code formatting.

🔴 Most important (9 things to know)

  • Teacher pay was wrong in two directions at once. When a manager approved a postponement, the payroll calculation never looked at it. So a class that never happened was counted as "finished" and paid in full — and at the same time, since that class could have no record, it also drew a "no feedback" penalty. Teachers were being docked for a class that did not exist. → The penalty is gone. We did not touch the amount — how much a postponed class is worth is your decision, so it is now a percentage you set in the admin deduction rules (currently 100%, exactly as before).
  • The moment we switched to real payments, payments would have broken. Going from test to live meant a human changing a value hard-coded in the page AND a secret on the server, separately. Change only one and the payment window opens perfectly but every final approval fails — no money moves, and all you get is customers saying "it won't pay." → The page now fetches the value from the server, so the switch is two secrets and nothing else. If they ever disagree, the screen says "keys don't match" immediately. ⚠️ You have to issue the live keys yourself in the Toss merchant console (code is ready, waiting on keys). The "This is a test — no real payment" badge is drawn by Toss, not by us, so live keys are the only way to remove it.
  • Example text from an instruction sheet was being registered as a real secret. This is the most dangerous state there is — the screen says "configured" while nothing actually works. In practice we found a placeholder sitting in the payment key slot, and a Toss payment key sitting in the SMS key slot. → Placeholders are now rejected and the screen points at exactly what went in wrong. 🔑 But we do not try to guess whether a key is "the right shape" — we once blocked a genuine key that way and stopped payments, so arbitrary rules like "must be 20+ characters" are gone.
  • Rotated the shared key that had been publicly exposed for three months (all 4 stages done). It leaked while the repository was public. The frightening part was never payroll — it was that student data could be written from outside. → Rotated without any downtime: ① accept both old and new → ② switch our side → ③ switch the two external callers on Cafe24 (run and verified working) → ④ delete the old key. The old key now does nothing. Along the way we discovered that a long-standing comment claiming "UptimeRobot covers this" was simply untrue — that integration is a paid feature and had never been created. Phone numbers were also moved out of code into secrets.
  • Outage monitoring had only ever been one layer deep. The watchdog lived inside the service, so when the service dies, the watchdog dies with it. The more serious the outage, the quieter we got. → Built a second-layer watchdog: it runs on Cafe24 (different company, different network) every 5 minutes, pokes us from the outside, and sends SMS without going through our server at all. It distinguishes four states: ① whole site down ② domain/DNS ③ database ④ "site is fine but alerts and settlement have quietly stopped" — nobody could see ④ until now. The two layers watch each other, and it takes two consecutive failures (10 minutes) before an SMS goes out (added because I sent one real false alarm today).
  • A teacher held an empty classroom for 30 minutes and we never said a word to her. At the 18:00 level test on August 7 the student never came. The teacher re-entered four times, waiting. At 18:15 the system detected the absence but only logged it. The teacher had no way of knowing how long to wait, or whether we even knew. → Absence now sends the assigned teacher an SMS (Korean + English): "the student has not joined (+N min) / head office has been notified automatically / please wait 10 more minutes, and you may leave if they still don't come." When we can't send it, the operator summary now names who we failed to reach and why, so the blank in the roster is visible. ⛔ While doing this we found corrupted teacher contact data on applications (name says teacher A, but the phone and email belong to teacher B). So we ignore that field and go through the teacher roster instead — and if more than one candidate matches, we send to nobody (we once had "Anna" attached to "HANNAH"'s class).
  • "The teacher's face goes black when I open Google" — three reports, one single cause. The moment a teacher left the browser, their camera was switched off. The student was left looking at an unexplained black rectangle. It was built to save battery on student phones — but for a teacher who moves between Google, KakaoTalk and the textbook all class long, it became "the teacher disappeared." → Teachers are now excluded from that saving; student phones keep it. We also fixed a camera that turned itself back on after being switched off.
  • Academies that bought AI only were receiving a blank report card. Four of the five axes came only from evaluations teachers write by hand — and an AI-only academy has no teacher, so no evaluations at all. → Now only the empty axes are filled from what the student actually did with the AI. If there is not enough evidence we leave it blank (an invented score is worse). We always print what it was measured from.
  • There were TWO level-test application forms. The old page and the home popup asked for different things, so depending on which door you came through an account was created — or not. Some applicants therefore never saw their own application. → Merged into one. The old page was not deleted; it now forwards to the new door, so old links still work.
  • Three recording-upload endpoints are open to anyone — still true right now. I reviewed the fix and found two reasons it must not be merged as-is: the hourly limit is below real usage (and when it blocks, the recording silently does not get saved), and it would create a switch that kills someone else's recording in progress. → A follow-up fixing both is attached. The merge order matters (see 📌).
