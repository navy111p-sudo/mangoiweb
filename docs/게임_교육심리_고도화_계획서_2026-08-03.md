## 0. 한 장 요약 (Executive Summary)

| 구분 | 내용 |
|---|---|
| **진단** | 게임은 21종인데 **학습 루프는 사실상 1종**이다 — "뜻 보고 → 영어 고르기 → 맞추면 이긴다". 재미는 다양해졌지만 **학습 설계는 다양해지지 않았다.** |
| **핵심 문제 1** | 듣기가 **BGM처럼 흘러간다.** TTS는 나오지만, 학생이 *들어야만* 이길 수 있는 구조가 거의 없다. 대부분 화면의 한글 뜻만 보고도 클리어된다. |
| **핵심 문제 2** | 말하기가 **"통과 도장"이다.** 12개 게임에 마이크가 있지만, 채점은 글자 단위 정렬이라 **무엇을 어떻게 고쳐야 하는지**를 학생에게 못 알려준다. |
| **핵심 문제 3** | 게임에서 배운 것이 **기억 스케줄러로 흘러들어가지 않는다.** SRS는 `vocabulary` 테이블 하나에만 있고 게임 21종은 여기에 아무것도 적립하지 않는다 → 매 게임이 **매번 처음부터**. |
| **해법 골격** | ① 듣기 강제 3초 예측 → ② 발화 부하 사다리(따라말하기→변형→생산) → ③ 발음 진단 업그레이드 → ④ 게임 공통 기억 큐 → ⑤ 인지부하 분리 → ⑥ 보상 재설계(SDT) |
| **첫 착수** | Phase 1은 **게임 파일을 새로 만들지 않는다.** 공용 JS 3개(`mangoi-listen-first.js`, `mangoi-speak-score.js` 확장, `mangoi-memory.js`)를 만들어 기존 21종에 **끼워 넣는** 방식 → 충돌·사고 반경 최소 |

## 1. 현황 진단 (As-Is) — 실제 코드로 확인한 것

### 1-1. 게임 목록 (21종, `student-games.html` HUB_GAMES)

| 배지 | 게임 | 주 학습행동 | 듣기 | 말하기 |
|---|---|---|---|---|
| 단어 | 우주 괴물 사냥, 풍선 터뜨리기, 단어 매칭, 우주 배틀 | 뜻↔단어 재인(recognition) | △ | ✗ |
| 문장 | 문장 벽돌, 빈칸 채우기, 워드 파이터, 단어 테트리스, P-38, 탱크대전 | 어순 배열 | △ | △ |
| 말하기 | 탈출3종(음성·좀비·학교), 낚시, 슈팅, 말하기 퀴즈, 아바타 키우기 | 소리내어 말하기 | ○ | ○ |
| 듣말 | 용의자 추리, P-38 3D 조종석, 망고 구조선 | 듣고 찾기 + 따라 말하기 | ○ | ○ |
| 문법 | 문법 피자 | 문장 성분 | △ | △ |

- 마이크(`webkitSpeechRecognition`) 실제 사용: **12개 게임**
- 발음 채점: `js/mangoi-speak-score.js` 하나로 전부 처리

### 1-2. 냉정하게 본 3가지 구조적 한계

**① 듣기가 "확인용"이지 "관문"이 아니다**

대부분 게임에서 TTS는 **정답을 맞춘 뒤** 또는 **화면에 답이 이미 보이는 상태**에서 재생된다.
→ 학생은 소리를 **들을 필요 없이** 클리어할 수 있다. 이건 듣기 훈련이 아니라 듣기 *노출*이다.
→ 게다가 화면에 한국어 뜻이 항상 떠 있어, 인지적으로 **한글만 처리하고 영어는 스킵**하는 경로가 최단경로가 된다.

**② 말하기 채점이 "몇 점"만 주고 "왜"를 못 준다**

현재 `mangoi-speak-score.js`는 이미 잘 만들어져 있다 — 업계 표준(Azure/Speechace)의 정렬 방식을 따라 누락/삽입/치환을 구분하고, 기능어 가중치를 낮추고, 철자 기반 발음 근사로 인식기 흔들림을 구제한다. 파일 주석에 **한계도 정직하게 적혀 있다**:

> "우리는 음소(phoneme) 정보를 받을 수 없으므로(브라우저 인식·Whisper 는 글자만 준다)"

이 한계의 실제 결과: 학생이 `rice`를 `lice`로 발음해도 인식기가 `rice`로 적으면 **100점**이 나온다. 한국인 학습자의 최대 약점(R/L, F/P, TH, 어말 자음, 강세)이 **정확히 측정되지 않는 영역**에 있다.

**③ 학습 기록이 게임마다 고아(orphan) 상태다**

`api-games.ts`에 SRS가 있긴 하다:
```
const intervals = [1, 2, 4, 7, 14, 30, 60, 120];   // 고정 라이트너 사다리
```
그러나 이건 `vocabulary` 테이블(= 단어장) 전용이고, **게임 21종은 여기에 기록하지 않는다.**
→ 우주 괴물 사냥에서 3번 틀린 단어가 다음 날 탱크대전에 나올 이유가 전혀 없다.
→ "게임 많이 했는데 실력이 늘었는지 모르겠다"의 구조적 원인이 여기다.

**④ (제약) 개인화의 데이터 기반이 아직 비어 있다**

- `students_erp.level` / `textbook` = **29,377명 전원 NULL**
- `student_textbook_assignments` = **0행**
→ "학생 교재에 맞춘 출제"는 **지금은 물리적으로 불가능**하다. 이 계획서의 개인화는 **게임 내 행동 로그**(맞춤/틀림/발음점수/반응시간)를 자체 원천으로 삼아야 한다. 이게 유일하게 즉시 가능한 개인화 신호다.

**⑤ (제약) 한국어·중국어 서버 TTS는 못 쓴다**

CLAUDE.md에 명시: Cloudflare발 구글 TTS(ko·zh)는 깨진 음성이 나온다. **서버 TTS는 영어만 정상.**
→ 다행히 이 계획의 듣기 강화는 **전부 영어 음성**이므로 제약에 걸리지 않는다. 단, "한국어 지시문 음성 안내"는 브라우저 TTS로만 가능하고 기기별 품질 편차가 크다 → **지시는 글·그림으로, 음성은 영어만**이 원칙이 된다.

## 2. 이론적 근거 — 어떤 학자·논문에서 무엇을 가져오는가

### 2-1. 인지 쪽 (무엇을 어떻게 처리하는가)

**Mayer — 인지적 멀티미디어 학습 이론 (CTML)**
핵심 3전제: **이중채널**(귀/눈은 별도 통로), **제한용량**(각 통로는 좁다), **능동처리**(선택→조직→통합).
- 우리에게 주는 지시: **화면이 화려할수록 청각 통로에 남는 여유가 준다**. 우주 괴물이 3D로 날아오는 순간에 영어 문장을 들려주면, 학생 뇌는 "괴물 피하기"에 용량을 다 쓴다.
- → **"게임의 순간"과 "학습의 순간"을 시간 축에서 분리한다.** (아래 4-E)
- 멀티미디어 설계원리 메타-메타분석(2022)에서 **가장 효과가 큰 원리 3개**가 우리에게 그대로 적용된다: ① **제2언어 영상의 자막(captioning)** ② **시공간 근접성(contiguity)** ③ **신호주기(signaling)**.

**Sweller — 인지부하 이론 (외생부하 제거)**
게임의 장식·연출은 재미를 만들지만 학습에는 **외생부하(extraneous load)**다. 없애자는 게 아니라 **학습 판정 순간에만 걷어내자**는 것.

**Bjork — 바람직한 어려움 (Desirable Difficulties)**
- **인출 연습(retrieval practice) > 재학습(re-study)** — 어휘 난이도와 무관하게 일관되게 나타남
- **분산(spacing) > 집중(massed)** — 장기 파지에서 우월
- 우리에게 주는 지시: **보기 4개 중 고르기(재인)를 줄이고, 안 보고 말하기·쓰기(인출)를 늘린다.** 지금 게임 대부분이 재인 과제다.
- 주의: L2에서는 **재인이 회상보다 쉽게 성립**한다는 연구가 있다 → "게임에서 다 맞았는데 시험에서 못 한다"의 학문적 설명이 이것이다.

**Vandergrift — 메타인지 청취 순환 (Metacognitive Pedagogical Cycle)**
5단계: **계획·예측 → 1차 검증 → 2차 검증 → 최종 검증 → 반성**
- 이게 이번 계획의 **가장 저비용·고효과 아이디어**다. 게임에 이걸 넣는 데 3D도 AI도 필요 없다.
- 효과: 듣기 능력·메타인지 인식·자기효능감 향상이 여러 연구에서 보고됨(단, 최근 연구는 결과가 완전히 일치하지는 않음 — 과대주장 금물).

**Ebbinghaus → Duolingo HLR (Half-Life Regression)**
Duolingo는 고정 간격 대신 **각 항목의 "기억 반감기"를 회귀로 예측**해 복습 시점을 정한다.
- 우리 현재: 고정 사다리 `[1,2,4,7,14,30,60,120]` → **모든 학생·모든 단어에 같은 간격**
- 개선 방향: 반감기 = f(정답률, 최근 반응시간, 발음점수, 노출횟수) — Worker에서 계산 가능한 수준의 경량 모델

### 2-2. 언어습득 쪽 (왜 말이 트이는가)

**Krashen — 이해가능한 입력(i+1) + 정의적 여과기(Affective Filter)**
- 너무 어려운 입력은 입력이 아니다. 너무 쉬운 입력도 성장이 없다.
- 불안·창피함이 높으면 입력이 뇌에 안 들어간다 → **친구·선생님 앞이 아닌 게임 안에서 말하기**가 유리한 이유.

**Swain — 출력 가설(Output Hypothesis) / 압박된 출력(pushed output)**
- 듣기만으로는 문법이 안 잡힌다. **말하려고 애쓰는 순간** 학습자는 "내가 이걸 어떻게 말하지?"라는 **간극(gap)을 인지**한다.
- 우리에게 주는 지시: 따라 말하기(repetition)는 출력이 아니라 **모방**이다. 진짜 출력은 **조금 바꿔 말하기**부터 시작된다.

**Long — 상호작용 가설 / 의미 협상**
- 못 알아들었을 때 되묻고 다시 말해주는 과정에서 습득이 일어난다.
- 우리에겐 이미 `ai-friend.html`(영어친구챗)이 있다 → **게임 실패 지점을 AI친구 대화 주제로 넘기는 다리**가 미개통 상태.

**MacIntyre — 말할 의지 (Willingness to Communicate, WTC)**
- 실력보다 **"말할 마음이 드느냐"**가 실제 발화량을 결정한다.
- 2025년 연구들: AI 챗봇 대화가 **한국 EFL 학습자의 WTC를 유의하게 높이고 말하기 불안을 낮췄다**(대면 또래 대화 비교군 대비). 평가받는 느낌 없이 대화 상황을 재현하기 때문.
- 우리 게임의 최대 강점이 바로 이것 → **"게임 안 캐릭터에게 말하는 것"은 사람에게 말하는 것보다 부담이 낮다.** 이 강점을 더 밀어야 한다.

**섀도잉 + ASR 결합 (2025, Journal of Computers in Education)**
- ASR 활용 그룹이 대조군보다 **발음 정확도(accentedness·comprehensibility)와 전반적 말하기**에서 유의하게 우수
- 학생들은 이 방식을 **새롭고 흥미롭다**고 인식 → 지속 사용 의사에 "유용하다는 느낌(perceived usefulness)"이 가장 큰 영향

### 2-3. 동기 쪽 (계속 하게 만드는가) — ⚠️ 여기가 우리의 위험 지점

**Deci & Ryan — 자기결정성 이론 (SDT)**
3대 기본욕구: **자율성 / 유능감 / 관계성**

**게임화 메타분석(2023, ETR&D)의 결론이 우리에게 경고한다:**
> 게임화는 **내재동기·자율성·관계성은 높이지만, 유능감(competency)에는 영향이 미미**했다.

그리고 **과잉정당화 효과(overjustification)**:
> 포인트·배지·리더보드를 "X 하면 Y 준다"는 **통제 수단**으로 쓰면, 동기의 소재가 내부("재밌어서")에서 외부("코인 때문에")로 옮겨간다. 포인트를 빼면 흥미도 같이 사라진다.

**우리 현실 점검:** 코인 지갑(💰), EXP, 하트 3개, 난이도 7단계, 주간 보스 — **보상 장치는 이미 충분히 많다.** 더 넣을 게 아니라 **성격을 바꿔야** 한다.
- 통제형("10문제 맞히면 코인 50") → 정보형("지난주보다 R 발음이 12% 정확해졌어요")
- 이게 위 메타분석이 지적한 **"유능감에 영향 미미"를 뚫는 유일한 길**이다.

**Csikszentmihalyi — 몰입(Flow)**
도전 ≈ 능력일 때 몰입. 현재는 학생이 속도 1~7을 **직접** 고른다(자율성 ○) — 유지하되, **추천값을 옆에 띄우는 방식**으로 유능감을 보강.

### 2-4. 근거 강도에 대한 정직한 단서

- 디지털 게임기반학습 메타분석(2024, RER): 전반 학습·인지적 성과에 **중간 크기(medium)의 유의한 효과**. → "게임이 최고"가 아니라 **"잘 설계된 게임이 중간 정도 효과"**가 정확한 표현이다.
- 메타인지 청취 교수의 효과는 **연구마다 결과가 엇갈린다**. → Phase마다 **우리 데이터로 자체 검증**하는 절차를 계획에 포함시켰다(§6).

## 3. 업계 벤치마킹 — 무엇을 가져오고 무엇은 안 가져오는가

| 회사 | 핵심 설계 | 가져올 것 | 안 가져올 것 |
|---|---|---|---|
| **ELSA Speak** | 비원어민 음성 수백만 건 학습 → **모국어별 오류 패턴** 진단. "발음 체육관"처럼 오늘은 모음, 내일은 자음 식으로 **부위별 처방** | ✅ **부위별 처방 개념** — 한국인 취약 음소(R/L, F/V, TH, 어말자음, 강세)를 태그로 추적 | ✗ 자체 음향모델 학습(비용·데이터 규모 불가) |
| **Duolingo** | HLR 기반 개인 복습 스케줄 + 짧은 세션 반복 + 강력한 스트릭 | ✅ **개인화 복습 간격** ✅ 짧은 세션(3~5분) 설계 | ✗ 스트릭 압박 강화(과잉정당화·이탈 위험). 우리는 이미 스트릭이 있다 |
| **Speechace / Azure Pronunciation Assessment** | 정확도·유창성·완성도·운율을 **분리 점수**로 제공, 음소 단위 GOP | ✅ **점수 분리 표시** ✅ 유료 API를 **선택적 정밀 진단**에만 사용(전량 호출 금지) | ✗ 모든 발화를 유료 API로 채점(29,000명 규모에서 비용 폭발) |
| **Speak / 대화형 AI 앱** | 시나리오 롤플레이 → 되묻기·확장 | ✅ **게임 실패 → AI친구 대화로 이어지는 다리** | ✗ 자유대화 전면화(어린 학생에겐 부담·이탈) |

**우리만의 차별점(지켜야 할 것):** 위 어느 회사도 **"화상 수업 + 게임 + 강사 피드백"을 하나로 묶지 못한다.** 게임 데이터가 강사 화면과 학부모 리포트로 흐르는 구조는 우리 고유 자산이다. 게임 개선은 반드시 **이 파이프에 물리는 형태**로 해야 한다.

## 4. 적용안 — 우리 코드에 어떻게 넣을 것인가

> 원칙: **게임을 새로 만들지 않는다.** 공용 JS를 만들어 기존 21종에 끼운다.
> 이유: 게임 파일은 각자 독립이라 21곳을 따로 고치면 21번 사고 날 수 있다. 공용 모듈 1곳이면 롤백도 1곳이다.

### A. 「3초 예측」 — 듣기를 관문으로 바꾸기 (Vandergrift)

**신규 파일: `public/js/mangoi-listen-first.js`**

문제 출제 직전에 **0.8초 동안 화면의 한글 뜻을 가리고 영어 음성만 재생**한다.

```
[🔊 소리만]  →  "무슨 소리였을까?" 2지선다 (예측)
     ↓ 학생이 고름
[화면 복귀]  →  기존 게임 플레이 그대로 (검증)
     ↓ 라운드 끝
[한 줄 반성] →  "이번엔 첫소리를 놓쳤네요. 다시 들어볼까요? 🔊"
```

- 예측을 맞히면 **보너스**, 틀려도 **감점 없음** (정의적 여과기를 낮추기 위해 — 실패에 벌을 주면 안 들으려 한다)
- 게임 흐름을 끊지 않는 길이(≤1.5초)로 제한
- **적용 우선순위**: 우주 괴물 사냥 → 풍선 → 단어 매칭 → 우주 배틀 (지금 듣기가 가장 약한 단어형 4종)

**왜 이게 효과적인가:** 예측 → 검증 → 반성은 Vandergrift 순환의 압축판이며, "듣지 않으면 예측을 못 한다"는 **구조적 강제**를 만든다. 개발량은 게임당 3줄(`await MangoiListen.predict(item)`).

**멀티미디어 자막 원리 적용:** 예측 실패 시 **재생과 동시에 영어 자막**을 띄운다 — 제2언어 영상 자막은 메타-메타분석에서 **가장 효과가 큰 설계원리**로 보고됐다.

---

### B. 「발화 부하 사다리」 — 따라 말하기에서 진짜 출력으로 (Swain)

현재 모든 말하기 게임이 **1단계(모방)에 멈춰 있다.** 3단계로 나눈다.

| 단계 | 이름 | 과제 | 채점 기준 | 적용 시점 |
|---|---|---|---|---|
| **L1 모방** | Repeat | 들은 문장 그대로 | 정확도 ≥ 70% | 지금과 동일 (신규 학생·낮은 레벨) |
| **L2 변형** | Transform | "I have **a dog**" → **your** 로 바꿔 말하기 / 부정문으로 / 과거형으로 | **바뀐 부분이 맞았는지**만 본다 | 같은 문장 2번째 만남부터 |
| **L3 생산** | Produce | 그림·상황만 주고 **직접 문장 만들기** | 핵심어 포함 + 문법 허용 범위 | 정답 3회 누적 후 |

- **핵심 설계:** 같은 문장이라도 **만난 횟수에 따라 요구 수준이 올라간다** → 반복이 지루해지지 않고, 매번 새로운 인출이 일어난다(Bjork).
- L3의 채점은 정답 대조가 불가능하므로 **`api-ai.ts`의 AI 첨삭 라우터를 재사용**한다 (신규 API 추가 없음 = `index.ts` 금지구역 미접촉).
- **적용 우선순위**: 탈출 3종·낚시·슈팅·말하기 퀴즈 (이미 마이크가 붙어 있는 게임)

---

### C. 「발음 진단 2.0」 — 점수 말고 처방 (ELSA 벤치마킹)

**기존 `mangoi-speak-score.js`를 버리지 않고 확장한다.** (이미 잘 만들어져 있다)

**C-1. 한국인 취약 음소 태그 추가 (무료·즉시)**
```js
// 목표어와 인식결과의 차이를 '한국인 오류 패턴'으로 분류
rice → lice        : ['R_L']
think → sink       : ['TH']
coffee → copy      : ['F_P']
desk → des         : ['FINAL_CONSONANT']
```
- 브라우저 인식기가 **잘못 적어준 결과 자체가 진단 신호**다. `rice`를 말했는데 `lice`로 적혔다면, 그건 인식기 오류가 아니라 **학생이 실제로 L처럼 발음했다는 증거**다.
- 지금 코드는 이걸 `phonKey`로 **뭉개서 구제**하고 있다 → **구제는 유지하되, 뭉개기 전에 패턴을 기록**한다. (점수는 관대하게, 진단은 정확하게)
- 누적되면: **"이번 달 R 발음 82% → 지난달 71%"** 같은 학생·학부모용 지표가 나온다.

**C-2. 점수 분리 표시 (Speechace/Azure 방식)**
현재 `accuracy` / `completeness`가 이미 계산되지만 화면엔 종합점수만 보인다.
→ **정확도 / 완성도 / 속도(유창성)** 3칸으로 분리 표시. 학생이 "어디가 문제인지" 알 수 있어야 한다.

**C-3. 정밀 진단은 선택적으로 (비용 통제)**
- 평상시: 무료(브라우저 인식 + 우리 채점기)
- **주 1회 "발음 검진일"** 또는 학생이 직접 누를 때만: 유료 API 1~2문장
- 29,000명 × 매 발화 유료 호출은 **절대 금지**. 이 게이트를 코드에 박아둔다.

### D. 「게임 공통 기억 큐」 — 게임 간 학습이 이어지게 (Bjork + HLR)

**신규 파일: `public/js/mangoi-memory.js` + `api-games.ts` 확장**

```
        [우주 괴물]  [탱크]  [탈출]  [피자]  ... 21종
             ↓         ↓       ↓       ↓
        ┌────────────────────────────────────┐
        │  기억 큐 (item, 결과, 반응시간,     │
        │           발음점수, 오류태그)       │
        └────────────────────────────────────┘
             ↓
        반감기 예측 → 오늘 꺼낼 항목 20개
             ↓
        모든 게임이 여기서 문제를 받아간다
```

- **바꿀 것:** 고정 사다리 `[1,2,4,7,14,30,60,120]` → **항목별 반감기 추정**
  ```
  halflife ≈ base × (정답연속 가중) × (반응속도 가중) × (발음점수 가중)
  ```
  Worker에서 산술 몇 줄로 계산 가능. ML 모델 배포 불필요.
- **중요한 제약:** `students_erp.level/textbook`이 전원 NULL이므로 **교재 기반 출제는 지금 불가**.
  → 이 큐는 **학생이 게임에서 실제로 만난 항목**만을 원천으로 삼는다. 이건 지금 당장 100% 가능하다.
- **효과:** "게임 많이 했는데 늘었나?"에 **데이터로 답할 수 있게 된다.** (지금은 답할 수 없다)

---

### E. 「인지부하 분리」 — 게임의 순간과 학습의 순간을 떼어놓기 (Mayer/Sweller)

**규칙 3개를 21종 전체에 공통 적용:**

1. **음성 재생 중에는 화면 움직임을 멈춘다** — 괴물이 날아오는 동안 문장을 들려주지 않는다. 이중채널 이론상 시각 채널이 포화되면 청각 처리가 희생된다.
2. **말하기 판정 순간에는 배경 이펙트·BGM을 낮춘다** — 외생부하 제거. (덤: 마이크 인식률도 올라간다)
3. **한글 뜻과 영어를 화면상 붙여 놓는다** — 시공간 근접성(contiguity) 원리. 멀리 떨어져 있으면 시선 이동 자체가 부하다.

→ 신규 파일 없이 **각 게임 CSS/타이밍 3줄 수정**. 가장 싸고 가장 확실한 개선.

---

### F. 「보상 재설계」 — 코인을 늘리지 말고 성격을 바꾸기 (SDT)

⚠️ **이 항목은 아무것도 새로 추가하지 않는다. 기존 것의 문구만 바꾼다.**

| 지금 (통제형) | 바꿀 것 (정보형) |
|---|---|
| "정답! +50 코인 💰" | "정답! 이 단어 이제 **4번 연속** 맞혔어요 — 기억에 자리 잡는 중이에요" |
| "❤️ 하트 1개 남음!" | "여기까지 **12문제** 왔어요. 지난번엔 8문제였죠" |
| "⭐ 난이도 3" | "⭐ 난이도 3 — **지금 실력에 딱 맞는 속도**예요" (Flow: 추천값 표시) |
| (없음) | "이번 주 **R 발음이 12% 정확**해졌어요" ← **유능감 직격** |

- 근거: 게임화 메타분석이 **"유능감에는 영향 미미"**라고 지적했다. 유능감은 포인트가 아니라 **"내가 늘고 있다는 구체적 증거"**에서 온다.
- 문구 톤은 기존 원칙 유지 — **학생 대상 문구는 항상 동기부여·희망 톤**, 과장 금지(조건부 표현).
- 관계성(relatedness): 리더보드(경쟁) 말고 **"우리 반이 이번 주 함께 320문장 말했어요"** 같은 협력형 지표.

---

### G. 「AI친구로 넘기는 다리」 — 게임 실패를 대화로 (Long, MacIntyre)

- 게임에서 3번 이상 막힌 문장·단어를 **`ai-friend.html`의 대화 주제로 자동 전달** (`?topic=` 파라미터)
- "이 단어 어려웠죠? 망고랑 이걸로 얘기해볼까요?" — **선택 버튼**으로 (강제 금지, 자율성)
- 근거: 2025년 연구들이 AI 챗봇의 **WTC 향상·말하기 불안 감소**를 일관되게 보고. 게임의 실패 경험을 **부담 없는 대화**로 전환하면 정의적 여과기가 내려간다.
- 개발량: URL 파라미터 하나 + 버튼 하나. **신규 API 없음.**

### 어린이·어르신 배려로 **일부러 단순화**한 것

- 보기는 **2개만** (4개는 부하가 크다) · 버튼 높이 68px · 글자 18~24px
- **시간 압박 없음** — 카운트다운을 화면에 안 보여주고 12초 뒤 조용히 넘어감
- **감점 절대 없음** — 틀리면 영어 자막을 띄우고 한 번 더 들려줄 뿐
- **3문제에 1번만** 관문을 건다 (매 문제마다 걸면 훈련이 아니라 세금이 된다)
- 3번 연속 건너뛰면 그 판은 더 안 묻는다 · 🎧 버튼으로 **완전히 끌 수 있다**
- 계획서엔 "정확도/완성도/유창성 3칸 분리"를 적었지만, 만들어 보니 **숫자 3개는 이 화면에서 읽히지 않았다** → 점수 1개 + **다음에 뭘 할지 한 줄**로 바꿨다

> 실측: 목표 "He drinks cold **milk**" 에 학생이 "**mirk**" 라고 해도 통과(95점)라서
> **R/L 오류가 한 건도 기록되지 않았다.** 한국인 최대 약점이 정확히 안 잡히고 있었던 셈이다.

   통과 여부와 진단은 별개다 — **점수는 관대하게, 진단은 정확하게.**
   고친 뒤 실측: "mirk"·"mil" 이 통과하면서도 `R_L(3회 중 1회 오류)`·`FINAL(3회 중 1회)` 로 정확히 누적됐고,
   통과했으니 잔소리(처방 문구)는 안 뜬다.
   같은 패턴을 탱크·P-38·P-38 3D·구조선 4곳에 적용했다.

`stt_hardening_harness` 가 **문법 피자의 오답 안내가 통째로 안 뜨는** 상태를 잡았다.

### 알려진 한계 (숨기지 않고 적는다)

- 기억 큐가 **localStorage** → 기기를 바꾸면 이어지지 않는다. (서버 동기화는 신규 API가 필요하고, 그건 `index.ts` 금지구역이라 A 담당과 협의 필요)

- 개별 1회 판정은 못 믿는다. 화면에는 **표본 5회 이상**일 때만 쓴다.
- 브라우저 화면 캡처는 이 세션에서 **패널 미표시로 불가**했다 → DOM·계산된 CSS 값으로 검증했다(치수·글자크기·넘침 여부는 실측).
