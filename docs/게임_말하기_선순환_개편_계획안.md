# 학습 게임 21종 — 「말하기 선순환」 전면 개편 계획안

작성 2026-08-04 · 근거: 게임 학습 근거 페이지(`/game-learning-science.html`)의 이론표
지시: **모든 게임에 말하기를 반드시 넣을 것. 특히 문장으로 말하는 연습.
단어 말하기 → 문장으로 말하기 → 그 문장을 다시 듣고 → 다시 따라 말하기 = 선순환.**

---

## 1. 지금 상태 — 코드로 실측한 결과

게임 21종(`student-games.html`의 `HUB_GAMES`)을 전수 검사했습니다.
"말하기가 있느냐"뿐 아니라 **어떤 채점기를 쓰느냐**까지 봤습니다.

| 등급 | 뜻 | 게임 | 수 |
|---|---|---|---|
| **A** | 말하기 필수 + 공용 채점기(`MangoiScore`) + 발음진단(`MangoiPron`) + 기억큐(`MangoiMemory`) | 문법 피자, 탈출(말해야 열린다), 좀비 실험실, 학교 탈출, 탱크대전, P-38, P-38 3D, 슈팅+말하기, 워드 파이터, 단어 테트리스, 망고 구조선 | 11 |
| **B** | 말하기는 있는데 반쪽 | 아바타 키우기, 낚시+말하기, 용의자 추리, 말하기 퀴즈, 문장 벽돌, 빈칸 채우기 | 6 |
| **C** | **말하기가 아예 없음** | **우주 괴물 사냥**, 우주 배틀, 단어 매칭, 풍선 터뜨리기 | 4 |

### B등급이 왜 반쪽인가 (개별 사유)

| 게임 | 실측 | 문제 |
|---|---|---|
| 아바타 키우기 | `MangoiScore` 3회, `MangoiMemory` **0회** | 채점은 하는데 **기록이 남지 않는다** → 다음 게임으로 안 이어짐 |
| 낚시+말하기 | `SpeechRecognition` 2, `MangoiScore` **0** | 옛 채점 방식 — 어순이 뒤바뀌어도 통과 |
| 용의자 추리 | `SpeechRecognition` 6, `MangoiScore` **0** | 위와 같음 |
| 말하기 퀴즈 | `SpeechRecognition` 1, `MangoiScore` **0** | 이름이 「말하기 퀴즈」인데 채점기가 옛것 |
| 문장 벽돌 | 정답 후 `🎤 따라 말하기` **버튼**, 2.8초 뒤 자동으로 다음 문제 | 안 눌러도 그냥 넘어감 = 사실상 선택 |
| 빈칸 채우기 | 위와 같음(2.6초) | 위와 같음 |

> 즉 **21종 중 말하기가 진짜로 필수인 것은 11종**입니다.
> 맨 앞에 고정 노출되는 대표 게임 「우주 괴물 사냥」에 말하기가 없다는 점이 특히 큽니다.

## 2. 진단 — 왜 선순환이 안 도는가

### ① 「단어 → 문장」 사다리가 게임마다 제각각이다

지시하신 4단(듣기 → 단어 → 문장 → 되듣고 따라 말하기)의 **원형은 이미 있습니다.**
슈팅 게임에 이렇게 적혀 있습니다:

```
student-game-shooter.html:505
  • 문장 완성 → 원어민 듣고 3번 말하기 (성공마다 +100점)
```

문법 피자에도 「듣기·말하기 미션 오버레이」가 있습니다.
문제는 **이 절차가 게임 파일 안에 따로따로 복제**돼 있다는 것입니다.
그래서 게임을 바꾸면 학생이 겪는 순서가 달라지고, 어떤 게임은 문장 단계를 통째로 건너뜁니다.
고치려면 11곳을 각각 고쳐야 하고, 새 게임을 만들면 또 새로 짜게 됩니다.

### ② 오늘 막힌 문장이 내일 다시 안 나온다

기억큐(`js/mangoi-memory.js`)가 이미 있습니다. 그런데:

- **단어 위주로만 적립**됩니다. 문장은 거의 안 쌓입니다.
- `localStorage` 기반이라 **기기를 바꾸면 사라집니다.**

### ③ 🔑 서버는 이미 준비돼 있는데, 게임이 안 쓰고 있다

이게 이번 계획의 가장 중요한 발견입니다. 서버에 **이미 두 개가 다 있습니다**:

| API | 하는 일 | 위치 |
|---|---|---|
| `POST /api/games/shadow` | 따라말하기 발음 점수 적립 (`game_progress.pron_best/pron_count`) | `src/index.ts:455` |
| `GET /api/games/weak` | 오답이 많은 항목을 돌려줌 (기기 무관, 서버 저장) | `src/index.ts:452` |

그런데 실제로 이 API를 호출하는 화면은 **허브(`student-games.html`) 하나뿐**입니다.
iframe으로 도는 게임 15종은 발음 점수를 서버에 **한 건도 보내지 않고**, 약점도 읽지 않습니다.

> **결론: 선순환에 필요한 서버 기능은 이미 다 있습니다. 신규 API 0개입니다.**
> `src/index.ts`(공동 금지구역)를 건드릴 일이 없다는 뜻이기도 합니다.

## 3. 제안 — 공용 「말하기 4단 사이클」 모듈 하나

게임마다 다시 만들지 않습니다. **`js/mangoi-speak-cycle.js` 파일 하나**를 만들고,
게임은 한 줄만 부릅니다.

```js
MangoiCycle.run({
  en:    'I have a red apple',
  ko:    '나는 빨간 사과를 가지고 있어요',
  words: ['red', 'apple'],       // 이 판에서 학생이 획득한 핵심 낱말
  lang:  'en'                    // en | zh
}).then(function(result){
  // result = { passed, sentenceScore, wordScore, shadowScore, tags }
  // 게임은 점수만 받아서 자기 방식대로 보상하면 됩니다
});
```

### 4단계 구성 (이론표와 1:1로 대응)

| 단계 | 하는 일 | 근거(이론표) |
|---|---|---|
| **① 듣기 — 뜻을 가리고 소리만** | 원어민 낭독 2회. 이때 **한국어 뜻은 가려둡니다.** 그 다음 뜻 공개 | 메타인지 청취(Vandergrift) · 멀티미디어 학습(Mayer) — 소리 나오는 동안 화면·타이머 정지 |
| **② 단어 말하기** | 핵심 낱말 1~2개만. 짧아서 성공률이 높습니다 | 출력 가설(Swain) 진입점 · 성공 경험으로 말할 의지 확보(MacIntyre) |
| **③ 문장 말하기** | 문장 전체. 틀리면 **모범 문장을 다시 들려주고** 재도전 | 출력 가설 본체 — 말하려다 막히는 순간이 배움의 지점 |
| **④ 되듣고 따라 말하기** | 원어민 낭독 직후 즉시 따라 말하기 1회. 이 점수를 서버로 보냄 | 섀도잉 · 바람직한 어려움(Bjork) — 인출 연습 |

**③에서 실패했을 때**는 이미 있는 발음 처방(`js/mangoi-pron-tags.js`)을 그대로 씁니다.
「rice 를 lice 라고 말하면 → 혀끝을 입천장에 안 대고 r」 같은 한 줄이 나옵니다.
새로 만들 것이 없습니다.

### 채점은 새로 안 만듭니다

`js/mangoi-speak-score.js`(190줄)가 **이미 문장 채점을 합니다.**
단어 정렬 + 누락/치환 구분 + 기능어 가중치 완화 + 길이별 통과 기준(2단어 0.9 → 10단어 0.68)까지
다 들어 있습니다. 사이클 모듈은 이걸 **호출만** 합니다.

### 새로 만드는 것 / 재사용하는 것

| 새로 만듦 | 재사용 |
|---|---|
| `js/mangoi-speak-cycle.js` (4단 진행·UI 오버레이, 예상 250~300줄) | `mangoi-speak-score.js` 채점 |
| 서버 적립·약점 조회 배선 (모듈 안에 1회만) | `mangoi-pron-tags.js` 발음 처방 |
| | `mangoi-stt.js` / `mangoi-voice-input.js` 음성인식 (+ Whisper 대체) |
| | `game-tts.js` 원어민 낭독 |
| | `mangoi-memory.js` 기억큐 |
| | `POST /api/games/shadow` · `GET /api/games/weak` |

## 4. 선순환을 실제로 잇는 법 (③번 진단의 해결)

```
   [게임 A] 문장 말하기 실패
        │  POST /api/games/shadow  (점수·항목 적립)
        ▼
   game_progress  (서버 · 기기 바뀌어도 남음)
        │  GET /api/games/weak
        ▼
   [게임 B] 시작할 때 약점 문장을 먼저 배치
        │
        ▼
   ① 듣기 → ② 단어 → ③ 문장 → ④ 따라 말하기
        │
        └──── 성공하면 간격을 늘려 다음에 다시 만남 (기억큐)
```

핵심은 **모듈이 이 배선을 대신 해준다**는 것입니다.
게임 개발자는 `MangoiCycle.run()`만 부르면 적립·조회가 자동으로 됩니다.
지금처럼 게임마다 따로 배선하다 빠뜨리는 일이 없어집니다.

### Phase 1 — 말하기 없는 3종에 붙이기 (✅ 완료)

| 게임 | 어디에 끼웠나 |
|---|---|
| ~~우주 괴물 사냥 🛸~~ | ✅ Phase 0에서 완료 |
| **우주 배틀** ⚔️ | **문장 문제를 맞힌 직후.** 단어 문제는 4단의 ②·③이 같은 말이 되어 제외. 보스를 쓰러뜨린 한 방에서는 안 돌린다 — 승리 세리머니가 보상의 절정인데 거기서 20초를 막으면 아이들이 가장 기다린 장면을 빼앗는 셈 |
| **단어 매칭** 🧩 | 짝을 다 맞춘 뒤 |
| **풍선 터뜨리기** 🎈 | 정답 풍선을 터뜨린 뒤 |

공통 원칙: **게임 플레이 도중이 아니라 한 판이 끝난 지점**에 넣었습니다.

**🪜 「단어 → 문장」 사다리 (`_sentenceForWords`)** — 매칭·풍선은 단어만 다루는 게임이라
4단의 ③(문장)에 쓸 문장이 없었습니다. 그래서 **방금 맞힌 낱말이 실제로 들어 있는 문장**을
교재 문장에서 찾아 그걸로 4단을 돌립니다. `apple`을 맞히면 → `I have a red apple`을 말하게 됩니다.
스테이지 문장 → 교재 문장 전체 → 아무 문장 순으로 찾습니다.
(스테이지 풀만 뒤지면 사다리가 거의 안 걸립니다 — 스테이지 1은 문장이 3개뿐이라 실측으로 확인)

**🔇 우주 배틀에서 발견한 사고 요인** — 이 게임은 클라우드 TTS를 **자체 `<audio>`(ttsA)** 로
재생해서, 공용 모듈의 정지 루틴(`MangoiTTS.stop` + `speechSynthesis.cancel`)이 그 소리를 못 끊습니다.
안 끊고 마이크를 열면 **음성인식이 AI 목소리를 학생 발화로 받아 적습니다**(과거 다른 화면에서
실제로 터졌던 사고). `stopOwnTTS()`를 만들어 마이크를 열기 전에 부르도록 했습니다.

### Phase 2 — B등급 나머지 4종 정리 (✅ 완료)

| 게임 | 무엇을 했나 |
|---|---|
| **말하기 퀴즈** | 채점기 교체 + 처방 + 기억큐 + 서버 적립. 표시 '정확도'도 채점기 점수로 바꿈(예전엔 글자 편집거리라 어순이 뒤바뀌어도 높은 %가 찍혀 학생이 오해했다) |
| **낚시** | 위와 동일 |
| **용의자 추리** | **합격 판정은 그대로 둠.** 이 게임의 과제는 "이 문장을 따라 하라"가 아니라 "누가 범인인지 뜻이 통하게 말하라"라서 핵심 낱말 매칭이 맞습니다(탈출 게임 3종도 같은 이유). 처방·기억큐·서버 적립만 붙였습니다 |
| **아바타 키우기** | 기억큐 연결(0회 → 매 판정) + 발음 처방 + 서버 적립 |

교체 효과 실측 (`I have a red apple` 기준):

| 학생이 말한 것 | 예전 | 지금 |
|---|---|---|
| `I have a red apple` | 통과 | 통과 (100점) |
| `apple red a have I` (어순 뒤바뀜) | **통과** | 탈락 (11점) |
| `I have a red banana` (뜻 다름) | **통과** | 탈락 (74점) + 「"apple"을 "banana"로 말했어요」 |
| `I have a lead apple` (R/L) | 탈락 | 탈락 + 「혀끝을 입천장에 안 대고 "r"」 |

### Phase 3 — A등급 11종 서버 적립 배선 (✅ 완료)

**11개 대형 파일(최대 196KB)의 채점부를 각각 열어 고치지 않았습니다.** 그게 훨씬 위험합니다.
실측해 보니 11종이 하나같이 이렇게 부르고 있었습니다:

```js
MangoiMemory.log({ en: 목표문장 }, 통과여부, { tags, goodTags, score })
```

**서버로 보낼 재료가 이미 그 호출에 다 들어 있었습니다.** 그래서 새 모듈
`js/mangoi-shadow-sync.js`가 `MangoiMemory.log`를 한 겹 감싸, 점수가 실린 호출마다
`POST /api/games/shadow`로 같이 보냅니다. **게임 파일은 스크립트 태그 한 줄만 늘었습니다.**
앞으로 만들 게임도 기억큐만 쓰면 서버 적립이 자동으로 따라옵니다.

안전장치: 원래 `log()`를 **먼저·반드시** 실행 → 전송 실패는 전부 삼킴 · 비로그인은 전송 안 함 ·
점수 없는 호출은 전송 안 함 · 같은 (문장,점수) 3초 내 중복 차단 · 페이지당 최대 200건.

**이중 전송 방지:** `MangoiCycle`과 자체 전송 코드에 「shadow-sync가 붙어 있으면 보내지 않는다」
가드를 넣었습니다. 없으면 같은 점수가 두 번 기록되어 교사 화면의 연습 횟수가 부풀어 보입니다.

**⚠️ 일부러 안 한 것 — 11종 안의 「약점 문장 우선 출제」**
각 게임의 문제 뽑는 순서를 건드려야 하는데, 그 순서에는 **난이도 진행**이 얽혀 있습니다
(쉬운 문장 → 어려운 문장). 지금 재정렬하면 난이도 곡선이 무너집니다.
선순환 자체는 이미 닫혔습니다 — A등급 11종이 **쓰고**, 허브(`_seedMissFromServer`)와
4단 사이클(`warmWeak`)이 **읽어서** 약점 문장을 다시 냅니다.

### Phase 4 — 회귀 게이트 (✅ 완료)

이 배선은 **눈에 안 띄게 끊깁니다.** 화면은 멀쩡하고 점수도 나오는데 서버 기록만 안 남습니다.
실제로 이번 작업 전까지 15종이 한 건도 안 보내고 있었고 아무도 몰랐습니다.
그래서 `test-harness/speak_cycle_harness.mjs`를 만들어 배포 게이트에 넣었습니다.

검사: ① 점수를 적립하면 서버 경로가 반드시 있을 것 ② `shadow-sync`는 `memory` **뒤에** 실릴 것
③ `MangoiCycle` 쓰는 화면은 의존 모듈을 다 실을 것 ④ 이중 전송 금지

일부러 배선을 끊어 **게이트가 실제로 잡는 것까지 확인**했습니다(exit 1 + 고치는 방법 안내).

## 6. 결정 사항 (2026-08-04 확정 — 아래 권고안대로 진행)

### ① 말하기를 100% 강제할 것인가? → **권고안 채택**

말하기를 완전히 필수로 만들면 이런 학생이 막힙니다:

- 마이크가 없거나 권한을 막은 기기
- 카카오톡 인앱 브라우저 · 구형 iOS (음성인식 미지원 — 지금은 서버 Whisper 녹음으로 대체 중)
- 도서관·버스 등 소리를 낼 수 없는 환경

**권고안:** 말하기 단계는 **항상 뜨되**, 3초 뒤 「지금은 소리를 낼 수 없어요」 건너뛰기를 허용.
단 건너뛰면 **점수·코인을 주지 않고**, 그 문장은 **약점으로 적립**해서 다음에 다시 만나게 합니다.
→ 강제는 아니지만 건너뛴 것이 없어지지는 않습니다.

**추가 처리 (구현하며 발견):** 마이크를 **한 번도 못 쓴** 경우와 **말했는데 틀린** 경우를
반드시 구분해야 했습니다. 구분하지 않으면 마이크가 없는 학생에게 「발음 점수 0점」이 뜹니다.
→ 목소리가 한 번도 안 잡히면 ① 점수를 말하지 않고 ② 서버에 안 보내며(교사 화면 평균 왜곡 방지)
③ 재도전을 안 시킵니다(들리지도 않는데 같은 화면을 또 띄우는 것은 사공일 뿐).
실측으로 한 사이클이 22.0초 → 17.6초로 줄었습니다.

### ② 4단을 매 문제마다 돌릴 것인가, 몇 문제에 한 번인가? → **권고안 채택**

매번 돌리면 한 문장에 30~40초가 듭니다. 게임 한 판이 길어집니다.

**권고안:** **3문제에 1번**. 단, 약점으로 잡힌 문장은 무조건 4단을 돌립니다.
(이미 「게임 교육심리 Phase1」에서 같은 기준을 쓰고 있습니다 — 보기 2개·감점 없음·3문제에 1번)

### ③ 담당 분담

게임 파일은 담당 B 영역이라 진행에 문제가 없습니다.
다만 **허브(`student-games.html`)의 inline 게임 4종**과 공용 JS는 참조처가 넓어,
공용 JS를 고칠 때 `grep -rln` 으로 참조 화면을 먼저 세야 합니다.
(`index.html`은 금지구역이므로, 그쪽이 참조하는 파일은 건드리지 않고 새 파일로 분리)

## 8. 알려진 함정 (작업 시 반드시 지킬 것)

- **`?v=` 버전 가드 하니스가 있습니다.** `js/*.js`를 고치면 그 파일을 참조하는 HTML의 `?v=`를 올려야 하니스가 통과합니다. 올린 뒤 또 고치면 **다시 올려야 합니다.**
- 게임 파일이 큽니다(최대 196KB). 새 코드는 **HTML 인라인 금지**, 공용 JS로 뺍니다.
- 새 UI 문자열은 학생 화면이므로 **한국어·영어·중국어 3개 언어**가 필요합니다. i18n 사전은 전체 문자열 일치 방식이라 라벨에서 이모지만 떼도 번역이 깨집니다.
- 이모지는 **Unicode 13 이상 금지** (Windows 10에서 두부로 표시됨).
- 이 저장소는 **병행 세션의 배포가 미커밋 파일을 쓸어가는 사고**가 잦습니다. 작업 중 `git status`를 자주 확인합니다.
- 학생향 문구는 **항상 희망·동기부여 톤**. 「틀렸어요」 대신 처방 한 줄.
