## 1. 확정된 규칙 (그대로 구현)

### A. 상품·가격

| 항목 | 규칙 |
|---|---|
| 수강권 종류 | 주1회 / 주2회 / 주3회 / 주5회 × 기간(1·3·6·12개월) |
| 기본 단가 | 월 기준 60,000원(주1회) × 주당 횟수 — 예: 주2회(월8회)=120,000원 |
| 수업 길이 | 기본 20분. 40분 선택 가능(수업료 2배) |
| 기간 할인 | 6개월 일괄결제 5% / 12개월 일괄결제 10% (일괄결제 시에만) |
| 대리점별 단가 | ⚠ 대리점(학원)마다 상이 — 주1회 기준 20,000 / 22,000 / 30,000 / 35,000 / 40,000원 등 (60,000원에서 각각 할인된 값) |
| 형제 할인 | 없음 |
| 무료 제공 | 레벨테스트 1회 + 체험 수업 1회 (총 2회 무료) |

### B. 결제 시 학생(학부모)이 고르는 것

| 항목 | 규칙 |
|---|---|
| 요일 | 완전 자유 조합 (월목, 월금, 화수 등 아무 조합) |
| 시간 | 수업 길이 20분/40분 선택, 시작 시각은 10분 단위 (8:00, 8:10, 8:20 …) |
| 강사 | 학생이 목록에서 직접 선택 |
| 시작일 | 자유 (보통 그 주 또는 다음 주) |
| 자동 생성 | 결제한 회차만큼 전부 스케줄 자동 생성 (매니저 개입 0) |

### C. 연장(재결제)

- 기존 요일·시간·강사 **그대로 승계**
- 마지막 수업 **바로 다음 회차부터** 이어서 생성 (수요일 수업생이 7/22 마지막이면 7/29부터)
- 남은 회차가 있는 상태에서 재결제 → 기존 수업 유지 + **뒤에 합산**

### D. 미결제·종료

- **3주 미결제 = 종료 대상** (현재는 수동 처리 — 상담 기록 있으면 유예)
- 종료 즉시 그 시간대 슬롯이 **실시간으로 전체 오픈**
- 만료 **7일 전 + 3일 전** 재결제 요청 문자 자동 발송 (전화는 없음)

### E. 변경·연기·보강

- 연기(취소): **30분 전까지 무료** (현행 정책 유지 — 과거 2시간에서 완화된 것)
- 보강: 학생이 빈 슬롯에서 직접 잡거나 매니저 대행
- 요일·시간 변경: **제한 없음** (제한하면 오히려 탈퇴 유발 — 남용 사례 거의 없음)
- 지각: 강사가 카톡·SMS로 재촉 → 무응답 시 수업시간 끝까지 대기 후 결석 처리

### F. 중복 방지·특수 상황

- 같은 강사·같은 시간 이중 예약 = **시스템이 완전 차단 (매니저도 불가)** — 구시스템에서 간헐 버그 있었으므로 새 구현은 DB 수준 제약으로 원천 봉쇄
- 공휴일: **새벽 6시에 시스템이 그날 수업 전체 자동 연기**
- 강사 휴가: 캘린더 사전 등록 → 당일 오전 매니저가 학생들에게 안내 → **다른 강사로 수업 이관 기능** (받은 강사 스케줄에 자동 표시)
- 그룹 수업: 수강권 생성 시 '그룹수업'으로 지정하면 복수 계정이 같은 강사·같은 수업에 참여 (드묾)
- 환불: **남은 회차 × 회당 단가**를 계산해 환불 (예: 30,000원 4회 중 2회 사용 → 15,000원 환불)

## 2. 매니저가 요청한 신규 개선 3건 (개발 목록에 추가)

1. **종료 후보 명단 리포트** — "N일 이상 수업이 없는 학생" 목록 자동 추출 (수동 종료 작업을 반자동화)
2. **첫 결제 UI 직관화** — 신규 고객이 강사·시간·요일·회차 고르는 화면의 진입장벽 낮추기 (크몽 회의의 UX 지적과 일치)
3. **강사 등급별 수업료 가산** — A그룹 강사 120%, B그룹 110% 식으로 인기 강사 추가 요금

## 3. ⚠ 개발 전 확인 필요 — 5가지 (대표님/부장님 답변 요청)

| # | 질문 | 왜 필요한가 |
|---|---|---|
| 1 | **대리점별 단가표는 어디서 관리하나요?** 대리점마다 다른 단가(2만~6만)를 새 시스템에선 대리점 관리 화면에서 직접 입력하게 할까요? | 가격 계산의 뿌리 — 대리점 단가 × 주횟수 × 기간 − 할인 순서로 계산됩니다 |
| 2 | **할인 적용 순서**: 대리점 단가에 6/12개월 할인을 곱하는 방식이 맞나요? (예: 주1회 30,000원 대리점 × 6개월 × 95%) | 할인 중복 계산 방지 |
| 3 | **강사 가산 그룹(A=120% 등)은 누가·어떻게 정하나요?** 기존 급여 등급(T1/T2)과 같은 건가요, 별개인가요? | 요청 3번 구현 범위 확정 |
| 4 | **환불 시 기간 할인 소급**: 6개월(5% 할인) 결제 후 중도 환불하면, 남은 회차를 할인가로 계산하나요 정가로 계산하나요? | 환불 분쟁 방지 — 보통은 "할인 취소 후 정가 정산"이 일반적 |
| 5 | **공휴일 자동 연기 시 회차 처리**: 연기된 수업은 전체 일정이 1회씩 뒤로 밀리나요, 아니면 보강으로 따로 잡나요? | 자동 생성 로직의 종료일 계산에 영향 |

## 4. 개발 계획 (이 사양 기반, 단계별)

| 단계 | 내용 | 비고 |
|---|---|---|
| 1단계 | 결제 옵션 화면(강사→요일·시간→회차·기간→가격 자동 계산) + 토스 테스트 결제 연동 + **결제 완료 → 스케줄 자동 생성** + 중복 원천 차단 | 확인 질문 1·2 답변 후 착수 |
| 2단계 | 연장(승계·합산) + 만료 7일/3일 전 자동 문자 + 종료 후보 명단 리포트 | |
| 3단계 | 공휴일 자동 연기 + 강사 휴가 이관 + 그룹 수업 | 확인 질문 5 |
| 4단계 | 강사 등급 가산 + 환불 계산기 | 확인 질문 3·4 |

— PG 심사가 통과되기 전에도 1~4단계 전부 테스트 결제로 개발·검증 가능. 심사 통과 = 스위치만 켜면 실결제 시작.
