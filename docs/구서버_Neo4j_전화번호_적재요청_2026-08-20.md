## 무엇을 해 주셔야 하나

Cloudflare Worker 가 매일 밤 03:00 KST 에 Neo4j 로 **아래 질의를 그대로** 던집니다.
여기서 값이 나오도록 **MySQL → Neo4j 적재 단계**를 손봐 주시면 됩니다.

```cypher
MATCH (s:Student)
OPTIONAL MATCH (par:Parent)-[]->(s)
WITH s, collect(DISTINCT par.phone)[0] AS parent_phone_g
RETURN coalesce(s.student_id, s.user_id) AS user_id,
       coalesce(parent_phone_g, s.parent_phone) AS parent_phone,
       s.student_phone                          AS student_phone
ORDER BY user_id SKIP $off LIMIT $lim
```

즉 **둘 중 하나**만 채워지면 됩니다.

| 방법 | 채울 것 |
|---|---|
| **① 권장** | `:Parent` 노드에 `phone` 속성 + 그 노드가 `:Student` 로 향하는 관계 |
| ② 대안 | `:Student` 노드에 `parent_phone` 속성 (①이 없을 때만 쓰입니다) |

학생 본인 번호는 `:Student` 노드의 **`student_phone`** 속성입니다.

## 구체적으로 이렇게 넣어 주세요 (① 권장 방법)

**매일 밤 도는 스크립트라 `MERGE` 를 씁니다.** `CREATE` 로 하면 밤마다 같은 학부모가
새로 쌓입니다.

```cypher
// ── 학부모 노드 + 학생과의 관계 ──
UNWIND $rows AS row
MATCH (s:Student)
  WHERE coalesce(s.student_id, s.user_id) = row.student_id
MERGE (p:Parent { parent_id: row.parent_id })     // ← 키는 «번호» 가 아니라 «학부모 id»
  SET  p.name  = row.parent_name,
       p.phone = row.parent_phone                 // 매번 최신값으로 갱신
MERGE (p)-[:PARENT_OF]->(s)                       // ← 방향 주의: 학부모 → 학생
```

```cypher
// ── 학생 본인 번호 ──
UNWIND $rows AS row
MATCH (s:Student)
  WHERE coalesce(s.student_id, s.user_id) = row.student_id
SET s.student_phone = row.student_phone
```

### 꼭 지켜 주셔야 하는 것 세 가지

| | 왜 |
|---|---|
| **방향은 `학부모 → 학생`** | 우리 질의가 `(par:Parent)-[]->(s)` 로 **방향을 가립니다.** 반대로 만드시면(`(s)-[:HAS_PARENT]->(p)`) 값이 있어도 **한 건도 안 잡힙니다** |
| **`MERGE` 사용 (`CREATE` 금지)** | 이 스크립트는 매일 밤 돕니다. `CREATE` 면 같은 학부모가 날마다 새로 쌓여 한 학생에 노드가 수백 개 붙습니다 |
| **키는 `parent_id`** | 전화번호나 이름으로 `MERGE` 하면, 번호가 바뀔 때 **옛 번호를 가진 유령 노드**가 그대로 남아 어느 쪽이 최신인지 알 수 없게 됩니다 |

### 관계 이름은 바꾸셔도 됩니다

우리 질의가 `-[]->` 로 **종류를 안 가리므로** `PARENT_OF` 가 아니어도 동작합니다.
다만 이 그래프에 이미 `FAMILY_OF`(학생↔학생 가족 관계)가 있으니, 결이 맞는
**`PARENT_OF`** 를 권합니다.

### 학부모가 둘 이상이면

우리 쪽에서 `collect(DISTINCT par.phone)[0]` 로 **한 명만** 취합니다.
따라서 **대표로 연락받을 분을 먼저** 넣어 주시면 좋고, 굳이 한 명으로 줄이실 필요는 없습니다.

> ⚠️ 관리자 학생목록 화면(`api-admin.ts` 의 `GRAPH_STUDENT_LIST_QUERY`)이 **이미 같은 길**을 씁니다.
> 새로 만든 방식이 아니라, 그 화면이 쓰던 경로를 그대로 따라간 것입니다.

## 먼저 확인해 보실 것 (Neo4j 에서 바로 실행)

```cypher
// 1) :Parent 노드가 있나, phone 이 채워져 있나
MATCH (p:Parent)
RETURN count(p) AS 부모노드, count(p.phone) AS 번호있는것;

// 2) :Parent 가 :Student 로 실제로 연결돼 있나
MATCH (p:Parent)-[r]->(s:Student)
RETURN type(r) AS 관계종류, count(*) AS 건수
ORDER BY 건수 DESC;

// 3) Student 노드 쪽에 번호가 있나
MATCH (s:Student)
RETURN count(s) AS 학생, count(s.parent_phone) AS 학부모번호, count(s.student_phone) AS 학생번호;
```

`부모노드 = 0` 이면 **적재 자체를 안 하고 있는 것**이고,
`부모노드 > 0` 인데 `번호있는것 = 0` 이면 **노드는 만드는데 `phone` 컬럼을 안 넣고 있는 것**입니다.

## 망고아이 쪽은 무엇을 해 뒀나 (추가로 하실 것 없습니다)

번호가 Neo4j 에 들어오는 순간 **자동으로 D1 까지 흘러갑니다.**

1. **가져오기** — 위 Cypher 에 전화번호 세 칸을 넣었습니다
2. **지워지던 것 수리** — 더 큰 문제가 따로 있었습니다.
   D1 적재가 `INSERT OR REPLACE` 인데 **컬럼 목록에 전화번호가 없었습니다.**
   이 구문은 「행을 지우고 다시 넣는」 방식이라 **목록에 없는 칸은 NULL 이 됩니다.**
   즉 누가 번호를 채워 넣어도 **그날 밤 동기화가 지웠습니다.**
3. **재발 방지** — `test-harness/phone_sync_harness.mjs` 가 컬럼이 다시 빠지면 배포를 막습니다
