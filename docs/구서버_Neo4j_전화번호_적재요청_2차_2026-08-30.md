## 3. 이번에는 «어디까지 됐는지» 만 알려 주셔도 됩니다

1차 문서에 진단용 질의 3개를 넣어 두었는데, 결과를 못 받았습니다.
**아래 세 줄만 Neo4j 에서 실행해 결과를 회신해 주시면**, 저희가 다음에 무엇을 해야 하는지
바로 판단할 수 있습니다. (적재를 아직 못 하셨어도 괜찮습니다 — 상태만 알면 됩니다)

```cypher
// ① 학부모 노드가 있나, phone 이 채워져 있나
MATCH (p:Parent) RETURN count(p) AS 부모노드, count(p.phone) AS 번호있는것;

// ② 학부모가 학생으로 실제로 연결돼 있나
MATCH (p:Parent)-[r]->(s:Student) RETURN type(r) AS 관계종류, count(*) AS 건수 ORDER BY 건수 DESC;

// ③ 학생 노드 쪽에 번호가 있나
MATCH (s:Student) RETURN count(s) AS 학생, count(s.parent_phone) AS 학부모번호, count(s.student_phone) AS 학생번호;
```

읽는 법:

| 결과 | 뜻 | 다음에 할 일 |
|---|---|---|
| `부모노드 = 0` | 적재 자체를 안 하고 있음 | 1차 문서의 「구체적으로 이렇게 넣어 주세요」 그대로 |
| `부모노드 > 0` · `번호있는것 = 0` | 노드는 만드는데 `phone` 을 안 넣음 | `SET p.phone = ...` 한 줄만 추가 |
| `번호있는것 > 0` · `관계종류` 가 비어 있음 | 번호는 있는데 학생과 연결이 없음 | `MERGE (p)-[:PARENT_OF]->(s)` 추가 |
| 셋 다 값이 있음 | Neo4j 는 정상 | **저희 쪽 문제입니다 — 알려 주시면 저희가 봅니다** |

### 부탁 하나 — 전부가 아니어도 됩니다

**학생 10명분만 먼저 넣어 주셔도 큰 도움이 됩니다.** 그것만으로 Neo4j → D1 → 발송까지
경로 전체가 실제로 통하는지 저희가 확인할 수 있고, 문제가 있으면 전량 적재 **전에** 잡습니다.
전량을 한 번에 넣고 나서 문제를 찾는 것보다 훨씬 안전합니다.

## 4. 망고아이 쪽은 그 뒤로 무엇을 더 했나

1차 문서에 적은 세 가지(가져오기·지워지던 것 수리·재발 방지 하니스)에 더해,
**2026-08-28 에 한 번 더 보강했습니다.**

야간 동기화가 학생 행을 **지우고 다시 넣는** 방식이라, 컬럼 목록에 없는 칸이 매일 밤
사라지고 있었습니다. 전화번호는 1차 때 목록에 넣어 막았지만, 같은 문제가 다른 칸
(학생 비밀번호·학부모 연결·평가 밴드)에 남아 있었습니다. 이번에 **카페24가 주는 칸만
덮어쓰고 나머지는 보존하는 방식(UPSERT)** 으로 바꿨습니다.

> 👉 담당자께서 **추가로 하실 일은 없습니다.** 번호가 Neo4j 에 들어오는 순간 그날 밤
> 자동으로 D1 까지 흘러가고, 다음 날부터 알림이 나갑니다.

## 5. 확인 방법 (1차와 동일)

적재하신 다음 날 아침, 저희가 D1 에서 이 한 줄을 확인합니다.

```sql
SELECT COUNT(*) AS 전체,
       SUM(CASE WHEN parent_phone IS NOT NULL AND parent_phone <> '' THEN 1 ELSE 0 END) AS 학부모번호
FROM students_erp;
```

`학부모번호` 가 0이 아니면 성공입니다. 그때부터 결석 알림(`src/absent-sweep.ts`) ·
수업 리마인더(`src/lesson-reminder.ts`) · 미연장 안내(`src/renew-link.ts`) 가 실제로 나갑니다.

## 6. 주의사항 (1차 문서와 같습니다 — 다시 한 번)

- **번호 형식은 통일하지 마세요.** `010-1234-5678` 과 `01012345678` 을 섞어 쓰는 곳이 있어,
  한쪽으로 바꾸면 기존 조회와 어긋납니다.
- **빈 문자열(`''`) 대신 값을 넣지 않는 편이 낫습니다.** `''` 이 들어가면
  「번호 있음」으로 오판합니다.
- **매일 밤 도는 스크립트라 `MERGE` 를 쓰세요.** `CREATE` 면 밤마다 같은 학부모가 새로 쌓입니다.
- 개인정보라 지사·대리점 계정에는 뒤 4자리가 가려져 나갑니다(이미 적용돼 있습니다).
