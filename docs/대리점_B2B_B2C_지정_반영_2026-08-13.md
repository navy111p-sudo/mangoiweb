## 4. ⚠️ 중복 등록된 학원 9그룹 — 왜 문제가 안 되는지

결제내역의 B2B/B2C 분리(`src/accounting-reports.ts` `paymentsList()`)는
**ID 가 아니라 학원 «이름»** 으로 매칭합니다.

```sql
(SELECT c.payment_type FROM centers c
  WHERE c.name = s.shop_name AND c.payment_type IS NOT NULL
  ORDER BY c.id LIMIT 1)
```

즉 같은 이름이 여러 줄이면 **ID 가 가장 작은 한 줄** 이 대표로 뽑힙니다.
검토표에는 같은 이름이 여러 줄인 그룹이 9개 있는데(예: 강서SLP 7줄),
**9그룹 전부 같은 값으로 맞춰져 있어** 어느 줄이 뽑혀도 결과가 같습니다. 충돌 0건.

## 5. 실제로 무엇이 달라졌나 — 결제내역 B2B/B2C 분리

이 컬럼이 비어 있는 동안에는 분리 기능이 **사실상 동작하지 않았습니다.**

| 결제 11,640건 | 반영 전 | 반영 후 |
|---|---:|---:|
| B2B | **0건** | 41건 (290만원) |
| B2C | 11,640건 (100%) | 11,599건 (12억 4,925만원) |

반영 전에는 `centers.payment_type` 이 전부 비어 있어 학생 쪽 대체값(`students_erp.payment_type`)으로
넘어갔는데, 그 값이 `B2B%` 인 학생이 **한 명도 없어** 전건이 B2C 로 떨어졌습니다.

### 🔎 확인 부탁드릴 점 — B2B 41건의 정체

반영 후 B2B 로 잡히는 결제 41건은 **전부 사장님이 «미지정 → B2B» 로 고르신 9곳에서 나옵니다.**

| 학원명(shop_name) | 결제건수 |
|---|---:|
| 테스트 B2C | 20 |
| 미사용 | 9 |
| N 안산 SLP 가정망고 | 5 |
| N 리시움학원수업 | 5 |
| N 안산 LAB | 1 |
| N TEST대리점 | 1 |

앞의 두 개(«테스트 B2C», «미사용»)와 «N TEST대리점»은 이름만 봐서는
**실제 학원이 아니라 테스트·관리용 계정**으로 보입니다.
지금 상태로는 이 계정들의 결제 29건이 회계상 **B2B 매출로 집계**됩니다.
의도하신 것이면 그대로 두면 되고, 아니면 알려 주시면 해당 몇 곳만 미지정으로 되돌리겠습니다.
(전체를 다시 만질 필요 없이 몇 줄이면 됩니다.)

## 6. 되돌리는 방법

반영 전에는 921곳이 **전부** 미지정(NULL)이었으므로, 원상복구는 한 줄입니다.

```sql
UPDATE centers SET payment_type = NULL WHERE payment_type IS NOT NULL;
```

일부만 되돌릴 때는 마이그레이션 파일 맨 아래 ROLLBACK 주석을 참고하세요.

## 7. 앞으로 — 화면에서 고칠 수 있게 하려면

지금은 대리점의 결제유형을 **관리자 화면에서 보거나 고칠 수 없습니다.**
서버 API 는 있는데(`PATCH /api/admin/centers` — `{id, payment_type}`),
`public/admin.html` 에 그걸 쓰는 UI 가 아직 없습니다.

- 새 대리점이 생기면 결제유형이 **미지정으로 시작**하고, 지정하려면 사람이 API 를 직접 불러야 합니다.
- 대리점 목록 화면에 «결제유형» 열 + 드롭다운을 붙이는 작업이 필요합니다.
  `public/admin.html` 은 **A(배포 권한자) 담당 영역**이라 이번 작업에는 넣지 않았습니다.
  진행 여부를 정해 주시면 그때 반영하겠습니다.
