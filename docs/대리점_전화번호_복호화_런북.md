# 대리점 전화번호 복호화 런북 (카페24 서버 작업)

작성: 2026-07-17 · 대상: 가맹점 관리 > 대리점 목록의 전화번호가 `8EEDBC0C…` HEX 암호문으로 나오는 문제

## 배경

- 옛 카페24 PHP LMS가 지사(Branch) 전화번호를 **AES 암호화(HEX)** 로 MySQL에 저장.
- 야간 동기화(`/root/mangoi-sync.sh` → Neo4j → 워커 `cafe24-sync.ts` → D1)가 이 암호문을 **복호화 없이 그대로** 전달 → 관리자 화면에 노출.
- 임시조치(배포됨): 프론트에서 32자리+ HEX는 `—` 처리 (`adm-core.js` `_frnPhone()`).
- 참고: 거의 모든 대리점이 **동일한 암호문** = 같은 원문(아마 빈값/기본값). 복호화해도 실번호가 나오는 곳은 소수(예: JS 에듀(진주))일 가능성 높음.

## 작업 순서 (SSH: `ssh root@118.219.234.180`)

### 1. 현재 branches export 쿼리 확인
```bash
grep -n -i -B2 -A6 "branch" /root/mangoi-sync.sh | head -40
```
→ 어떤 MySQL 테이블/컬럼에서 phone을 뽑는지 확인 (예: `SELECT ... phone ... FROM Branchs`).

### 2. 암호화 키 찾기 (레거시 PHP 소스)
```bash
grep -rn -i -E "AES_ENCRYPT|AES_DECRYPT|aes_key|enc_key" \
  /home/hosting_users/mangoi/www/ /root/web_quarantine/ --include='*.php' 2>/dev/null | head -20
grep -rn -i -E "AES_ENCRYPT" /home/hosting_users/mangoi/www/config*.php 2>/dev/null
```
PHP 소스에서 `AES_ENCRYPT(phone, '키')` 또는 `HEX(AES_ENCRYPT(...))` 패턴의 키 문자열 확보.

### 3. 복호화 검증 (읽기전용)
```bash
mysql -u <user> -p<pw> <db> -e \
  "SELECT BranchID, name, CONVERT(AES_DECRYPT(UNHEX(phone), '찾은키') USING utf8) AS phone_plain
   FROM <branches테이블> LIMIT 10;"
```
- 정상 번호가 보이면 키 확정. NULL이면 키가 다르거나 이중인코딩 → PHP 소스의 암·복호화 함수 재확인.
- 동일 암호문 `8EEDBC0C56DA914BACD7CE3013ADBF20` 이 빈문자열(`''`)로 풀리는지도 확인.

### 4. mangoi-sync.sh 수정 (⚠️ sed 금지 — perl -i -pe 사용, 과거 sed 개행사고)
branches export SELECT에서 `phone` → 
```sql
IFNULL(CONVERT(AES_DECRYPT(UNHEX(phone), '찾은키') USING utf8), '') AS phone
```
- LOAD CSV 파싱 보호: 기존 export들처럼 REPLACE(탭·개행·따옴표 제거)로 감쌀 것.
```bash
cp /root/mangoi-sync.sh /root/mangoi-sync.sh.bak.$(date +%m%d)
# perl -i -pe 로 해당 라인 수정
bash -n /root/mangoi-sync.sh   # 문법검증 필수
```

### 5. 수동 실행 + 확인
```bash
/root/mangoi-sync.sh ; echo EXIT=$? ; tail -20 /var/log/mangoi-sync.log
```
Neo4j 확인: `MATCH (b:Branch) WHERE b.phone <> '' RETURN b.name, b.phone LIMIT 10`
