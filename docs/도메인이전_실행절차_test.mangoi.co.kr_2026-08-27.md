## 1. 무엇을 고치는 일인가

이 저장소는 워커를 **두 벌** 배포하는데, `wrangler.toml` 이 워커마다 Durable Object 를 따로
선언합니다. 그래서 **두 도메인은 같은 방 번호를 넣어도 서로 다른 방**입니다.
화상수업 WebSocket 주소가 `location.host` 로 만들어지므로 **어느 주소로 열었느냐가 곧 어느 방이냐**가 됩니다.

| | 지금 (2026-08-26 대시보드 실측) | 이전 후 |
|---|---|---|
| `test.mangoi.co.kr` | `webrtc-unified-platform` (기본) | **`webrtc-unified-platform-prod`** |
| `mangoi.ai` · `www.mangoi.ai` | `webrtc-unified-platform-prod` | 그대로 |

### 이 사고의 이력 — 두 번 났고 아직 안 고쳤습니다

- **2026-08-19** — 중국인 강선생님(구 도메인)과 사장님(mangoi.ai)이 **7/31~8/19 여덟 번의 수업에서 한 번도 만나지 못함.**
  그때 「`-prod` 로 옮겨 해결」이라고 문서 세 곳에 **완료형으로** 적혔지만 **이전은 일어나지 않았습니다.**
- **2026-08-25** — `class-895` 에서 그대로 재발(강사 `mangoi_167` · 학생 `delaware`, 둘 다 「참여자 1명」).
- **2026-08-27** — 학생 `ubckt01`(조연희)이 구 도메인으로 7회 접속, 강사(KRYSTEL)와 끝내 못 만남.

## 2. 바뀌는 것 / 안 바뀌는 것

| 항목 | 이전 후 | 근거 |
|---|---|---|
| **화상방(Durable Object)** | 🎯 **두 도메인이 같은 방** | 이번 이전의 목적. 갈려 있던 것이 이것 하나뿐 |
| D1 (`mango-db`) · KV · R2 | 그대로 (원래 두 워커가 같은 id 공유) | `wrangler.toml` 두 환경이 같은 id |
| 교사 세션 쿠키 | 그대로 | 쿠키는 **도메인** 기준이고 도메인은 안 바뀜 |
| 학생 로그인 · 언어 설정 (`localStorage`) | 그대로 | 오리진(도메인) 기준, 도메인 안 바뀜 |
| **패스키 6건** (jeong 4 · Lee 1 · kang 1) | 그대로 | `rpId` 는 도메인 기준. ⛔ **리다이렉트로 푸는 방식이면 여기서 무효화됩니다 — 그래서 리다이렉트가 아니라 이전입니다** |
| 앱(APK) 시작 URL · `app-version.json` | 그대로 동작 | 도메인이 살아 있고 워커만 바뀜 |
| **cron 5종** (야간 동기화·독촉·NPS·감시견) | 그대로 돎 | 기본 워커에 붙어 있고, 그 워커는 계속 존재. 도메인과 무관 (`[env.production.triggers] crons = []`) |
| 스모크 테스트 · 워치독 (구 주소 하드코딩) | 그대로 동작 | 주소가 살아 있음 |

**요약: 잃는 것이 없습니다.** 도메인을 «없애는» 게 아니라 «붙은 워커만 바꾸는» 것이기 때문입니다.

## 3. ⚠️ 딱 하나의 리스크 — 이전 중 짧은 다운타임

Cloudflare 는 **한 호스트명을 두 워커에 동시에 붙일 수 없습니다**(`custom_domain_already_in_use`, 409).
그래서 **① 기본 워커에서 떼고 → ② `-prod` 에 붙이는** 2단계이고, **그 사이 `test.mangoi.co.kr` 이 안 열립니다.**

- 보통 1~3분. 붙일 때 인증서(Advanced Certificate)가 새로 발급되며 몇 분 더 걸릴 수 있습니다.
- 그동안 그 주소를 쓰는 **앱 사용자도 안 열립니다**(붙이고 나면 정상 복구).
- **이전 순간 화상수업 중인 구 도메인 사용자는 끊깁니다** — 재입장하면 됩니다.

### ✅ 언제 하면 되나

**수업이 없는 시간대**에 하세요. 이 저장소 D1 기준 망고아이 화상방(`class-*`) 수업은
대체로 **KST 09:00~23:00** 에 몰립니다. **KST 새벽 1시~8시** 가 가장 안전합니다.
⚠️ 카페24 예약 수업(`c24-*`)은 망고아이 방을 안 쓰므로 이 작업의 영향을 받지 않습니다.

## 4. 실행 절차 (대시보드)

> 화면 경로는 계정에 따라 **Settings > Domains & Routes** 또는 **Domains 탭**(2026-05 신설) 둘 중 하나입니다.

### ① 떼기 — 기본 워커에서 제거

1. Cloudflare 대시보드 → **Workers & Pages**
2. **`webrtc-unified-platform`** (⚠️ `-prod` 아닌 쪽) 선택
3. **Settings → Domains & Routes** (또는 **Domains** 탭)
4. 목록에서 **`test.mangoi.co.kr`** 찾기 → **Remove / 삭제**
   - ⚠️ 이 순간부터 그 주소가 안 열립니다. 다음 단계를 바로 이어서 하세요.
   - ⚠️ `mangoi.ai` · `www.mangoi.ai` 는 **이 워커에 없습니다.** 혹시 보이면 **건드리지 마세요.**

### ② 붙이기 — 운영 워커에 추가

5. **Workers & Pages** 로 돌아가 **`webrtc-unified-platform-prod`** 선택
6. **Settings → Domains & Routes** (또는 **Domains** 탭)
7. **Add → Custom Domain**
8. `test.mangoi.co.kr` 입력 → **Add Custom Domain**
9. 상태가 **Active** 가 될 때까지 대기 (보통 1~3분, 인증서 발급 시 조금 더)

### ③ 즉시 확인 — 열리는가

10. 브라우저에서 **`https://test.mangoi.co.kr`** 열기 → 홈 화면이 뜨면 이전 완료
    - SSL 경고가 뜨면 인증서 발급 중입니다. 5분 더 기다렸다 새로고침.

## 7. 이전을 미룰 경우의 임시 대응

이전 전까지는 **구 도메인으로 들어오는 사람에게 개별 안내**가 유일한 방어입니다.

D1 `attendance.host` 칸(2026-08-26 신설)으로 누가 구 도메인을 쓰는지 셀 수 있습니다:

```sql
SELECT host, COUNT(*) rows_n, COUNT(DISTINCT COALESCE(account_uid, username)) people,
       MAX(datetime(joined_at/1000,'unixepoch','+9 hours')) last_kst
FROM attendance WHERE host IS NOT NULL AND host <> '' GROUP BY host;
```

**2026-08-27 실측 (칸 생성 후 약 35시간)**

| 접속 주소 | 기록 | 사람 |
|---|---|---|
| `mangoi.ai` | 94건 | 23명 |
| **`test.mangoi.co.kr`** | **7건** | **1명** (`ubckt01` 조연희 — 8/27 20:58~21:24) |

⚠️ **이 수치를 「이제 1명뿐이다」로 읽지 마세요.** 이 칸은 **화상수업 방에 들어온 사람만** 세고,
데이터가 **35시간치뿐**입니다. 홈만 열거나 앱으로 다른 기능을 쓰는 사람은 안 잡히고,
8/26 대시보드 실측에서 기본 워커에는 **24시간 7.26k 호출**이 들어오고 있었습니다.
확실한 것은 **「그 35시간 동안 화상수업에 구 도메인으로 들어온 사람은 조연희 한 명」**까지입니다.
