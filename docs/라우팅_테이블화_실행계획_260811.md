## 0. 먼저 — 숫자 정정

8/9 진단서의 "라우팅 if 472→609개"는 **모든 `if (`를 센 값**이라 과대평가였습니다. 오늘 라우팅만 다시 셌습니다:

| 구분 | 개수 | 처리 |
|---|---|---|
| **정확일치** `path === '/x' && method === 'Y'` | **38** | ✅ 테이블 이관 대상 |
| 프리픽스 `path.startsWith('/x/')` (라우팅) | 소수 | if 유지(또는 2차 프리픽스 테이블) |
| 정규식/파라미터 `path.match(...)` | 4 | if 유지 |
| 제네릭 폴백 `startsWith('/api/')` → `handleMangoApi` | 1 (**1968줄, 맨 뒤**) | 유지 — 미이관 경로의 안전망 |

**핵심 안전 근거:** 제네릭 `/api/` 폴백이 모든 정확일치(382~1653줄)보다 **뒤(1968줄)** 에 있습니다.
그래서 정확일치 라우트를 **앞쪽 테이블로 옮겨도 순서가 보존**됩니다(경로가 고유하므로 서로 안 겹침).
`/api/retention/` 같은 prefix는 라우팅이 아니라 **인증 판정 헬퍼**(`isAdminPath`, 4921줄)라 경쟁 대상이 아닙니다.

## 1. 설계 — "기존 if와 공존하는" 덧셈식(additive) 테이블

한 번에 다 바꾸지 않습니다. **테이블을 하나 만들고, 기존 if 체인 앞에서 먼저 조회**하되,
테이블에 없는 경로는 **그대로 아래 if로 흘려보냅니다**(fallthrough). 이관은 배치로.

```ts
// index.ts — worker.fetch 안, path/method 확정 직후, 첫 정확일치 라우트 '앞'에 1회 삽입
// (핸들러들은 async function 선언이라 호이스팅됨 → 아래에서 참조 가능)
type ApiHandler = (request: Request, env: Env, ctx: ExecutionContext) => Promise<Response> | Response;

const API_ROUTES: Record<string, ApiHandler> = {
  // ── batch-1: 순수 위임 라우트(본문이 return handleX(request, env) 하나뿐) ──
  'POST /api/streak/complete-quiz': (rq, e) => handleLearnStreakComplete(rq, e),
  'POST /api/warmup/chat':          (rq, e) => handleWarmupChat(rq, e),
  'GET /api/warmup/context':        (rq, e) => handleWarmupContext(rq, e),
  'POST /api/warmup/questions':     (rq, e) => handleWarmupQuestions(rq, e),
  'GET /api/games/vocab':           (rq, e) => handleGamesVocab(rq, e),
  'GET /api/games/zh-vocab':        (rq, e) => handleGamesZhVocab(rq, e),
  'GET /api/games/zh-passage':      (rq, e) => handleGamesZhPassage(rq, e),
  'GET /api/games/lessons':         (rq, e) => handleGamesLessons(rq, e),
  'GET /api/games/en-vocab':        (rq, e) => handleGamesEnVocab(rq, e),
  'GET /api/games/define':          (rq, e) => handleGamesDefine(rq, e),
  'POST /api/games/progress':       (rq, e) => handleGamesProgress(rq, e),
  'POST /api/games/ux-track':       (rq, e) => handleUxTrack(rq, e),
  'GET /api/games/weak':            (rq, e) => handleGamesWeak(rq, e),
  'POST /api/games/shadow':         (rq, e) => handleGamesShadow(rq, e),
  'GET /api/games/recommend':       (rq, e) => handleGamesRecommend(rq, e),
  'POST /api/games/coins':          (rq, e) => handleGamesCoins(rq, e),
  'GET /api/games/leaderboard':     (rq, e) => handleGamesLeaderboard(rq, e),
};

// 조회(첫 정확일치 if들이 있던 자리, ~422줄)에 삽입:
const _route = API_ROUTES[request.method + ' ' + path];
if (_route) return _route(request, env, ctx);
```

- **삽입 위치:** 헬스체크(383줄)·intro.mp4(382줄) 특수처리 뒤, 첫 게임/웜업 정확일치 if(422줄) **바로 앞**.
- **주의:** 스트릭 GET 정규식 블록(426~434줄, `/api/streak/:id`)은 **정규식이라 테이블 대상 아님** → 그대로 둡니다.
  batch-1에서 옮기는 건 그 위/아래의 **순수 위임 if 17개뿐**이고, 정규식 블록은 자리를 지킵니다.
- 옮긴 각 `if (...) { return handleX(request, env); }` 블록은 **삭제**합니다(테이블이 대신함).

각 핸들러의 정확한 이름/시그니처는 index.ts에서 확인 후 채우세요(위 목록은 422~499줄 기준 초안).
본문이 한 줄이 아닌(‘[body]’로 표시된) 라우트 — 예: `/api/games/session`(505), `/api/video-call/*`,
`/api/recordings/*`, `/api/admin/payroll/*` — 은 **batch-2 이후** 로 미루고, 본문을 작은 `handleX`로 먼저 감싼 뒤 옮깁니다.

## 2. 안전한 배치 순서 (각 배치 끝나면 하니스 통과 확인)

| 배치 | 대상 | 왜 이 순서 |
|---|---|---|
| **1** | 순수 위임 정확일치 17개(streak/warmup/games, 422~499) | 본문이 `return handleX(request,env)` 하나 → 기계적·최저위험 |
| 2 | 본문 있는 정확일치(video-call/recordings/retention/admin-payroll) | 먼저 본문을 `handleX`로 추출 → 그다음 테이블로 |
| 3 | 프리픽스 라우트를 2차 테이블(`prefixRoutes`)로 (선택) | `/api/admin/*` 등은 접두어 매칭이라 별도 표 |

**절대 규칙:** 배치 하나 = 커밋 하나 = 하니스 한 번. 여러 배치를 한 커밋에 몰지 않습니다.

## 3. 검증 (이 순서 그대로)

```powershell
cd cloudflare-deploy
node node_modules/typescript/bin/tsc --noEmit          # ① 컴파일 (출력 없고 exit 0 = 통과)
cd ..
node test-harness/run.mjs --fast                        # ② 회귀 하니스 (기준선 PASS 115 / SKIP 20 / FAIL 0)
```

- ②의 `admin_404_apis` · `admin_new_apis` 하니스가 **바로 이 라우팅을 지키는 그물**입니다.
  등록을 빠뜨리면 여기서 잡힙니다 — 그래서 테이블화의 안전판이 이 하니스입니다.
- ①만 통과하고 ②를 건너뛰면 안 됩니다. 순서 섀도잉/404는 ②에서만 드러납니다.
- 통과 후 `deploy.ps1` (base + `-prod` 둘 다) → 배포 스탬프로 반영 확인.

---

## 4. 되돌리기

배치마다 커밋이 하나씩이므로, 문제가 보이면 **그 커밋 하나만 revert** 하면 됩니다.
테이블은 덧셈식이라, 최악의 경우 `if (_route) return ...` 조회 한 줄만 지우면 **즉시 옛 동작**(기존 if 체인)으로 복귀합니다.

---

## 5. 얻는 것

- 새 API를 테이블에 **한 줄로 등록** → "라우팅에 빠뜨려서 404" 가 구조적으로 불가능.
- 순차 `if` 비교가 **O(1) 객체 조회**로 → 미세하지만 일관된 속도 이득.
- 라우트 목록을 **한눈에** → 어떤 주소가 있는지 파일을 안 뒤져도 됨.

> 원하시면 **batch-1 정확한 패치(diff)** 를 만들어 드립니다 — 핸들러 이름을 index.ts에서 실제 확인해
> `tsc` 통과까지 맞춘 뒤, 적용은 A가 하니스로 검증하도록 넘기는 방식입니다.
