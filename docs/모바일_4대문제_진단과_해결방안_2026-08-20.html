두 제보는 같은 문제입니다. 원인이 하나이므로 함께 다룹니다.

먼저 — 그 로고 화면의 정체

사장님이 보시는 「남색 배경 + 가운데 망고 아이콘」 화면은 망고아이 안에서 그리는 화면이 아닙니다. 휴대폰(크롬/삼성인터넷)이 웹앱을 처음 켤 때 자동으로 만들어 주는 시작 화면입니다. 근거는 이렇습니다.

단서확인 결과
배경색 public/manifest.json 의 "background_color": "#050714" — 사진의 남색과 같습니다. (참고로 안드로이드 앱(APK)의 시작 화면은 흰색입니다. themes.xml 이 밝은 테마라 배경을 정해 두지 않았습니다.)
아이콘 모양 public/img/icon-512.png — 주황 둥근사각 + 흰 원 + 헤드폰 망고. 사진과 같은 그림입니다.
시작 방식 manifest.json 의 "display": "standalone" — 주소창 없이 앱처럼 뜨는 설정입니다.
✔ 확인됨 — 「크롬 주소창에 mangoi.ai 를 쳐서」 여신다고 하셨습니다 그런데 로고 화면은 설치된 웹앱이 켜질 때만 나옵니다. 둘은 모순이 아닙니다 — 홈 화면에 한 번 추가해 두면, 크롬 주소창에 그 주소를 쳐도 안드로이드가 설치된 앱 쪽으로 넘깁니다. 그래서 사장님은 «크롬에서 열었다» 고 느끼시지만 실제로는 웹앱이 새로 켜지고, 그 시작 화면이 로고입니다.
이번 수리는 어느 쪽으로 열든 똑같이 적용됩니다 — 고친 곳이 시작 화면이 아니라 «화면을 못 그리게 붙잡고 있던 부분»이기 때문입니다.

왜 매번 처음부터 다시 켜지나 — 원인 세 겹

원인 ① 안드로이드가 뒤에 있는 망고아이를 지웁니다 (근본 원인) 수업 화면은 카메라·마이크·영상 통신·1MB짜리 화면 파일을 동시에 물고 있어 메모리를 많이 씁니다. 카톡을 켜면 안드로이드는 메모리를 많이 쓰는 뒤쪽 앱부터 지웁니다. 그래서 돌아왔을 때 남아 있는 것이 없고, 「이어서」가 아니라 「처음부터」가 됩니다. 이때 나오는 것이 그 로고 화면입니다.
원인 ② 처음부터 다시 켜지는 데 너무 오래 걸립니다
첫 화면을 그리기 전에 받아야 하는 것크기출처
index.html988 KB파일 실측
js/idx-main.js845 KB파일 실측
합계(블로킹 기준선)1,537 KBtest-harness/first-paint-budget.json

화면을 한 픽셀이라도 그리기 전에 1.5MB를 받아야 합니다. 사무실 와이파이에서는 1~2초지만, 휴대폰 데이터·필리핀 회선에서는 10~30초가 됩니다. 그동안 화면에는 로고밖에 없습니다. 「멈춘 것」이 아니라 「아직 받는 중」인데, 쓰는 사람에게는 구별이 안 됩니다.

원인 ③ 통신이 반쯤 끊기면 「영원히」 로고입니다 (진짜 고장) public/sw.js 130~161행, 첫 화면 요청 처리:
return await fetch(request, { cache: 'no-store' });  // ← 제한시간 없음
제한시간이 없습니다. 통신이 「실패」하면 캐시로 넘어가는 길이 있지만, 휴대폰이 잠자다 깨어날 때 흔한 「연결은 살아 있는데 응답이 안 오는」 상태에서는 실패로 처리되지 않고 그냥 기다립니다. 이때 로고 화면은 몇 분이고 그대로입니다. 사장님이 「로고만 나온다」고 하신 상황이 이것으로 보입니다.

덤으로 발견한 것 — 돌아올 때마다 새로고침이 걸릴 수 있습니다

public/js/idx-push-sw.js 51~53행은 화면이 다시 보일 때마다 새 버전을 확인하고, 34~40행은 새 버전이 잡히면 location.reload() 로 화면을 통째로 다시 읽습니다 (수업 중이거나 연 지 30초 안이면 건너뜁니다). 배포가 잦은 날에는 카톡 보고 올 때마다 새로고침이 걸리고, 그때마다 위의 1.5MB를 다시 받습니다.

앱(APK)을 쓰고 계신다면 — 별도로 고쳐야 할 진짜 버그가 하나 있습니다

mobile-app/.../MainActivity.java 272~276행
if (savedInstanceState == null) { webView.loadUrl(START_URL + "?_app=" + ...); } else { webView.restoreState(savedInstanceState); }  // ← 돌려주는 값을 안 봅니다
안드로이드의 restoreState() 는 복원에 실패하면 아무것도 안 하고 null 을 돌려줍니다. 수업 화면처럼 저장할 상태가 크면 실패하는 일이 실제로 있습니다. 지금 코드는 그 값을 안 보기 때문에, 실패하면 주소를 한 번도 안 여는 빈 화면이 되고 스스로 회복하지 못합니다.
고침 — 돌려받은 값이 비어 있으면 시작 주소를 다시 연다 (세 줄). 같이 앱에도 남색 시작 화면을 넣어 웹앱과 같은 모습으로 맞춥니다.
