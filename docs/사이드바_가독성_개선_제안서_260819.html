관리자 화면 · 사이드바

사이드바가 한 화면에 안 들어오는 이유

「메뉴 지도가 너무 길어서 한눈에 안 보인다」는 말씀을 받고, 실제 관리자 화면을 재 봤습니다. 메뉴를 전부 접어 놓은 기본 상태에서도 이미 한 화면을 넘습니다. 그리고 사이드바 세로 길이의 59%는 메뉴가 아닌 것이 쓰고 있었습니다. 아래는 잰 값과, 그것을 어떻게 줄일지에 대한 세 가지 안입니다. 눌러 볼 수 있는 샘플을 함께 만들었습니다.

2026-08-19 · 잰 화면 = 노트북 1440×900, 관리자 화면 확대 130% · 실제 파일(admin.html)을 그대로 띄워 잼

01지금 어떤 상태인가

사이드바는 폭 312px(화면에서는 확대 때문에 406px — 노트북 가로의 28%), 세로로 보이는 부분은 625px입니다. 그 안에 들어가야 하는 것이 이만큼입니다.

첫 번째 메뉴 그룹(「오늘」)이 시작되는 자리가 사이드바 위에서 248px 내려간 곳입니다. 화면의 40%를 지나야 메뉴가 시작됩니다. 로그인 상태에서는 여기에 「⚡ 자주 쓰는 기능」이 더 붙습니다.

이미 들어가 있는 기능 — 없어서 못 쓰는 게 아닙니다

「메뉴 닫기·열기 같은 기능」을 물어보셨는데, 실은 이미 다 있습니다. 그래서 기능을 더 넣는 것으로는 해결되지 않습니다.

  • ↧ 모두 펼치기 / ↥ 모두 접기 — 검색창 바로 아래에 있습니다. 다만 「모두 펼치기」를 누르면 화면 4.4개가 됩니다.
  • 그룹은 한 번에 하나만 열립니다(아코디언). 다른 그룹을 누르면 앞의 것이 접힙니다.
  • 메뉴 검색 · ▸ 손자 메뉴 · 🗺 메뉴 지도(별도 페이지) · ⚡ 자주 쓰는 기능도 이미 있습니다.
  • 「🙈 숨기기」 버튼은 만들어져 있지만 지금은 CSS 로 꺼 둔 상태입니다(눌러서 감추면 되돌릴 길이 마땅치 않아 막아 둔 것으로 보입니다).

02그래서 무엇이 문제인가

① 자리를 반 이상 다른 것이 쓰고 있다

시계·AI 운영비서·사용법 안내·맨 위로·계정 도크 = 498px. 메뉴는 341px. 메뉴가 세입자입니다.

② 「모두 펼치기」는 «찾기»를 더 어렵게 한다

43항목이 한 줄로 늘어서면 2,749px입니다. 목록이 길어질수록 눈은 «훑기»를 포기하고 «스크롤»만 합니다.

③ 손자 줄 수가 항목마다 너무 다르다

손자는 모두 147줄인데, 「회계」 한 항목이 19줄입니다(5줄 이상인 항목이 9개). 「회계」를 펴는 순간 713px — 화면이 그 하나로 덮입니다.

④ 바닥 127px 은 늘 가려져 있다

계정 도크가 화면 바닥에 붙어 있어, 그룹을 펴면 아래쪽 항목이 그 밑으로 들어갑니다. 지금은 스크립트가 그때마다 스크롤을 밀어 주는 방식으로 버티고 있습니다.

⑤ 「전체를 보는 길」이 화면을 떠나는 길뿐이다

🗺 메뉴 지도는 다른 페이지(사이트 지도 문서)로 갑니다. 보고 나면 돌아와야 하고, 거기서 고른다고 그 자리로 가지지도 않습니다.

03제안 — 세 가지, 순서대로

샘플의 ①②③ 탭이 각각 아래 A·B·C 에 해당합니다. 셋은 서로 독립이라 따로따로 적용할 수 있습니다.

안하는 일줄어드는 길이위험손대는 파일
A 자리 정리 시계·AI비서·사용법·맨위로를 아래 아이콘 한 줄로 접고, 검색을 위에 고정 498px → 42px 낮음 adm-ia6.js · CSS
B 펼침 규칙 손자는 6줄까지만 먼저 · 그룹에 항목 수 배지 · 줄 간격 선택 · 아이콘 레일(68px) 긴 손자 713px → 230px 중간 adm-r25.js · adm-ia6.js · CSS
C 전체보기 Ctrl+K 로 43항목을 한 판에 · 치면 즉시 걸러짐 · 골라서 바로 그 자리로 찾는 데 걸리는 «누름 3번» → 1번 낮음 새 js 1개 + admin.html 한 줄

A — 자리 정리 (가장 먼저 할 것)

아무것도 없애지 않습니다. 시계·AI 운영비서·사용법 안내·맨 위로를 사이드바 맨 아래 아이콘 네 개로 접습니다. 샘플에서 재면 977px → 536px, 즉 메뉴 7그룹이 스크롤 없이 한 화면에 들어옵니다. 검색창과 「전체보기」는 위에 고정해 스크롤을 내려도 따라옵니다(지금은 위로 사라집니다).

B — 펼침 규칙

손자는 6줄까지만 먼저 보이고 「+N개 더」로 폅니다. 「회계」 19줄이 화면을 덮지 않습니다. 그룹 오른쪽에 항목 수를 적어 열어 보기 전에 크기를 알 수 있게 합니다. 줄 간격 «좁게»와 아이콘 레일(68px)은 켜고 끌 수 있는 선택지로 둡니다 — 표가 넓은 화면(학생 관리 17칸)에서 본문을 244px 더 씁니다.

⚠️ 손자 상자의 «최대 높이 숫자»를 키워서 푸는 방법은 쓰지 않습니다. 그건 임시방편이고, 상한이 클수록 닫을 때 «반응이 없는 시간»이 길어집니다(이미 CLAUDE.md 함정표에 적혀 있는 항목입니다). 열 때만 실제 내용 높이를 넣는 방식으로 갑니다.

C — 전체보기 한 판 (효과가 가장 큼)

세로로 긴 목록을 여러 칸으로 눕히면 43항목이 한 화면에 다 들어옵니다(실측: 화면 하나에 정확히 들어맞음). 이름을 치면 그 즉시 걸러지고, 맞은 글자에 표시가 붙습니다. ↑↓ 로 고르고 Enter 로 엽니다. 「손자까지 펼쳐 보기」를 켜면 147줄이 다 나옵니다.

지금의 🗺 메뉴 지도와 결정적으로 다른 점은 화면을 떠나지 않는다는 것입니다. 지금 보던 자리 위에 떠서, 고르면 바로 그 카드로 갑니다.

04검토했다가 버린 방법

왜 다른 길로 안 갔는지를 남깁니다 — 나중에 같은 고민을 다시 하지 않기 위해서입니다.

  • ✕메뉴 개수를 줄인다 (항목·카드를 합친다) 이 시스템에서는 카드 한 장이 곧 권한 한 단위입니다(강사는 관리자 자료실 ❌, 지사는 대리점 자료실 ❌). 비슷해 보인다고 합치면 역할별 접근 경계가 무너집니다. 그래서 «카드는 그대로 두고 찾는 길만 짧게» 라는 기존 방침을 유지합니다.
  • ✕손자 상자의 최대 높이(600·900px)를 키운다 이미 한 번 밟은 함정입니다. 닫는 데 시간이 걸리고, 손자가 늘면 또 넘칩니다.
  • ✕마우스를 올리면(hover) 펼쳐지게 한다 hover 로 뜨는 상세 카드·플라이아웃은 「정신없다」는 이유로 일부러 제거한 것입니다. 되살리지 않습니다.
  • ✕이모지를 되살려 항목을 구분한다 2026-07-22 에 «컬러 이모지 88개가 한 화면에 쌓여 눈이 피로하다»는 이유로 단색 선 아이콘으로 통일한 결정입니다. 파일에 이모지가 적혀 있어도 화면에서는 벗겨집니다.
  • ✕사이드바 폭을 넓힌다 지금도 화면 가로의 28%(406px)를 쓰고 있습니다. 넓히면 표가 넓은 화면이 옆으로 넘칩니다 — 오히려 «레일로 좁히는» 선택지를 넣었습니다.
  • ✕지금의 🗺 메뉴 지도 페이지를 키운다 화면을 떠나야 하고, 예전에 이 버튼이 «누르면 9초 뒤에 열리던» 사고를 낸 자리입니다. 지금은 바로 열리도록 고쳐 놨지만, 어차피 «돌아와야 하는» 구조는 그대로입니다.
  • ✕메뉴를 스크롤 가상화(virtual list)한다 부팅 스크립트들이 getElementById 로 카드 안 요소를 찾는 자리가 300곳이 넘습니다. 목록을 DOM 에서 빼는 방식은 그것들을 조용히 죽입니다.

05만들 때 밟으면 안 되는 것

이 사이드바는 그동안 사고가 여러 번 났던 자리입니다. 구현할 사람이 먼저 확인해야 할 것만 추립니다.

  • 사이드바가 두 벌입니다. 옛 #ph85-sidebar(9그룹 87항목)는 감춰져 있고, 화면에 보이는 것은 adm-ia6.js 가 다시 그린 7그룹 43항목입니다. 옛 쪽만 고치면 «검증은 통과하는데 화면은 그대로»가 됩니다.
  • 사이드바 클릭을 가로채는 곳이 둘입니다(adm-s11.js ph97 · adm-ia6.js). 새 조작(전체보기 단축키 등)은 둘 다에 예외를 넣어야 합니다.
  • 모바일 드로어는 스크롤보다 먼저 닫아야 합니다. 열린 동안 body 가 overflow:hidden 이라 scrollIntoView 가 통째로 무시됩니다.
  • 작성자 CSS 의 !important 는 인라인 스타일도 이깁니다. 높이를 JS 로 줄 때는 setProperty(…, 'important').
  • admin-inline-c.css 는 <body> 안에 링크돼 있습니다. document.head 에 넣은 규칙은 문서 순서상 앞이라 집니다.
  • 손자 이름을 손으로 적지 않습니다. 화면에 있는 실제 칸에서 읽습니다 — 지어낸 이름 66개가 엉뚱한 곳을 열던 사고가 이미 있었습니다.
  • public/js/*.js 를 고치면 HTML 의 ?v= 도 올립니다. 안 올리면 하니스가 FAIL 냅니다.
  • 회귀 감시가 이미 걸려 있는 영역입니다 — sidebar_three_level_harness(다섯 곳 짝 맞음) · admin_grandchild_menu_harness(33종) · admin_sidebar_ia6_click_harness.

06어떻게 쟀나

이 컨테이너에서는 배포된 화면(mangoi.ai)에 접속할 수 없어, 저장소의 public/ 폴더를 그대로 띄우고 컨테이너에 들어 있는 크로미움으로 admin.html 을 실제로 렌더해서 쟀습니다. 눈대중이 아니라 값을 읽은 것입니다.

  • 창 1440×900 · 관리자 화면은 zoom:1.3 이라, 화면 픽셀을 1.3 으로 나눠 CSS px 로 환산했습니다(둘을 섞으면 30% 틀립니다).
  • 길이는 «맨 아래 칸의 바닥»으로 쟀습니다. scrollHeight 는 접혀서 안 보이는 칸까지 세는 일이 있습니다.
  • 메뉴 나무(7그룹·43항목·147손자)는 렌더된 화면에서 읽어 샘플에 그대로 넣었습니다 — 손으로 적은 이름이 하나도 없습니다.

아직 확인 못 한 것: 실제 사장님 PC 화면(브라우저 확대·글꼴이 다를 수 있음)과 휴대폰 드로어에서의 값은 사람이 한 번 봐 주셔야 합니다.

결정을 부탁드립니다

  1. A안(자리 정리) — 시계·AI 운영비서·사용법 안내를 사이드바 아래 아이콘 한 줄로 접어도 될까요? (없애는 것이 아니라 눌러서 펴는 형태입니다)
  2. C안(전체보기) — 새로 넣을까요, 아니면 지금의 「🗺 메뉴 지도」 자리를 이걸로 바꿀까요? (둘 다 두면 «둘이 다른 건가»를 매번 생각하게 됩니다)
  3. 기본 줄 간격 — 지금 간격 그대로가 좋을지, 샘플의 «좁게»가 좋을지 화면에서 보시고 골라 주세요.
