## D. 이 서버를 바라보는 "바깥" 설정 (이사 후 새 IP로 갱신 필수)

> 서버를 옮기면 IP(`118.219.234.180`)가 바뀝니다. 아래는 **그 IP를 직접 가리키고 있어서 반드시 새 주소로 고쳐야** 하는 곳입니다.

| # | 위치 | 지금 값 | 이사 후 | 어디서 바꾸나 |
|---|---|---|---|---|
| D-1 | **DNS A레코드** | `mangoi.co.kr → 118.219.234.180` | 새 서버 IP로 변경 | **Cloudflare 대시보드** (네임서버 이미 Cloudflare. 가비아·카페24 아님) |
| D-2 | **SPF (메일 인증) TXT** | `v=spf1 ip4:118.219.234.180 ~all` | 새 IP로 변경 | Cloudflare 대시보드 |
| D-3 | **Cloudflare 워커 시크릿** | `NEO4J_QUERY_URL` (Neo4j 주소) | 터널 호스트명(`neo4j.mango-i.com`) 유지하면 **변경 불필요** | (해당 시) wrangler secret |
| D-4 | **급여 집계 연동** | 카페24 서버 → D1 push (`PAYROLL_INGEST_KEY`) | 스크립트가 새 서버로 이사하면 그대로 동작, 키만 확인 | 새 서버 스크립트 |

> 📌 **가비아 = 도메인 "등록(등기소)"만** 담당 → 서버 아님, 이사 대상 아님. DNS 실제 관리·전환은 **Cloudflare**에서 함.
> 📌 전환 = Cloudflare A레코드 한 줄 교체(즉시 반영·즉시 롤백 가능) → **병행 운영 → 무중단 전환**에 최적.

## F. 이사 순서 (권장) & 주의사항

1. **백업 먼저** — MySQL 풀덤프(`mysqldump`) + Neo4j 덤프를 R2에 별도 보관 후 시작
2. **새 서버 준비** — CentOS 7 ❌ → 최신 LTS(Rocky Linux 9 / Ubuntu 22.04 LTS 등). MySQL·Neo4j·PHP 버전 호환 확인
3. **데이터 이관 + 시운전** — 새 서버에서 A~C 복원 후 충분히 테스트 (기존 서버는 계속 켜둠)
4. **새벽에 전환** — DNS(D-1) 새 IP로 변경 → SPF(D-2)·워커 시크릿(D-3) 갱신
5. **다운타임** — `mangoi.co.kr`(옛 PHP)만 잠깐 멈춤. **test.mangoi.co.kr은 Cloudflare라 영향 없음** (수업 계속 가능)
6. **끝난 뒤** — 기존 서버 일정 기간 보존 후 폐기

> ⚠️ **개발자에게 넘기기 전 결정할 것:** B-4(옛 PHP 홈페이지)를 **이사할지 / 끌지.** 안 쓰면 끄는 게 이사 비용·보안 위험을 동시에 줄이는 최선입니다.
