## 2. 전환 당일 순서 ⭐ (이 순서 그대로!)

> 핵심: **옛 크론 끄기 → 최종 데이터 동기화 → 새 크론 켜기 → DNS 전환.** 크론이 두 곳에서 동시에 도는 순간이 없어야 함.

**① 유지보수 모드 (옛 서버)**
- [ ] 옛 서버 `dbopen.php`의 `$site_status = 'close'` → 잠시 쓰기 중단(선택, 최종 동기화 정확성용).

**② 옛 서버 크론 전면 중지** 🔴
- [ ] `crontab -e`로 전체 주석처리 (또는 `crontab -r` 백업 후). → **이 시점부터 옛 서버는 알림톡·주문 발송 안 함.**

**③ 최종 데이터 동기화 (스냅샷 이후 변경분 반영)**
- [ ] 옛 MySQL `mysqldump` → 새 서버 재import (마지막 데이터까지).
- [ ] 옛 `uploads/` → 새 서버 rsync (마지막 업로드까지).
- [ ] 새 서버에서 Neo4j 재생성(mangoi-sync).

**④ 새 서버 최종 점검**
- [ ] 실 SSL 인증서 적용 확인, 각 도메인 HTTPS 200 확인, 로그인 테스트.

**⑤ 새 서버 크론 켜기** 🔴
- [ ] 새 서버 crontab 주석 해제 → **이제 새 서버가 유일한 발송처.** (옛것은 ②에서 껐으므로 이중발송 없음)

**⑥ DNS 전환 (도메인별, Cloudflare)**
- [ ] 각 도메인 A레코드: 옛 IP `118.219.234.180` → 새 IP `101.79.28.176`
- [ ] SPF TXT도 새 IP로.
- [ ] **한 도메인씩** 바꾸고 확인 → 문제없으면 다음 도메인. (mangoi.co.kr 먼저 → 이상없으면 나머지)

**⑦ 유지보수 모드 해제**
- [ ] 새 서버 `$site_status = 'open'`.

## 4. 롤백 계획 (문제 시 즉시 복구)

문제 발생 시 **몇 분 안에** 원상복구:
1. **DNS A레코드를 옛 IP(`118.219.234.180`)로 되돌리기** (Cloudflare, TTL 짧아 빠름)
2. **새 서버 크론 끄기** + **옛 서버 크론 켜기**
3. 옛 서버 `$site_status = 'open'`
→ 옛 서버가 다시 라이브. (그래서 옛 서버는 전환 후에도 **최소 1~2주 유지**)
