# 슈팅게임(student-game-shooter.html) — 좀비 접근형 실사 리메이크 계획안

> 대상 파일: `cloudflare-deploy/public/student-game-shooter.html` (담당: B — 학생 학습 콘텐츠)
> 작성일: 2026-07-30
> 목적: 캡처 화면(폐허 도시 + 좀비 실사 배경)처럼, **이모지를 전부 없애고** Higgsfield 실사 좀비가 **플레이어 쪽으로 다가오는** 조준·사격 메커닉으로 바꿔 오락실(하우스 오브 더 데드류)·닌텐도급 박진감을 낸다. 문장/단어 학습 로직(정답 판정·TTS·말하기 미션·난이도)은 그대로 둔다 — **겉(비주얼·연출)만 전면 교체**.

## 1. 현재 상태 진단 (코드 확인 완료)

- 크리처는 이미 `alien/bug/dragon/parasite/phantom/mech/oni/imp` 8종 실사 webp(`shooter-mon-*.webp`, 260×260)로 한 번 교체되어 있다(`build-shooter-assets.py`, 07-30 배포). 하지만:
  - 테마가 **SF 외계생물**이다 — 사용자가 원하는 "좀비"가 아니다.
  - 표시 크기가 44~142px로 작고, 화면을 **좌우로 부유(sway)** 할 뿐 **다가오는 원근감(스케일 확대)** 이 전혀 없다 → 화면 캡처에서 사용자가 "이모지"로 느낀 것은 이 작은 아이콘들의 밋밋한 정지감 + 실제 잔존 이모지가 섞여 보이기 때문.
  - 골든 표적 왕관(`👑`), 무기 아이콘 13종(`🔫🏹💥🎯🔭💣🤠🎖️🌀⚡🧨🔥🤾`), 속도 7단계 아이콘(`🐢🚶🙂🏃🚀⚡🔥`), 배경 위 떠다니는 장식(`🚀` 등 `.bgfx b`), 안내 문구·버튼 라벨(`🎯 단어 몬스터를…`, `문장 슈팅 + 말하기 🔫🎤`, `👑+200`, `🚀 다음 활동 고르기` 등) — 이 전부가 **실제 유니코드 이모지**로 코드에 박혀 있다. CLAUDE.md 금지 규칙(유니코드13+ 두부 표시)과 별개로, 이번 요청은 **UI 전 영역 이모지 전면 제거**다.
- 게임 자체가 "가로 슈팅(word가 좌우로 흘러가는 표적)" 구조라, **좀비가 다가온다**는 감각을 만들려면 스폰~피격까지의 이동 로직을 스케일 기반 원근 이동으로 새로 짜야 한다(아래 3장).
- 사수(플레이어 캐릭터)는 이미 9포즈 실사 webp가 있고, 무기별로 다른 총을 드는 손모양은 **미착수 상태**로 대기 중이던 계획(`shooter-armed-soldier-plan.md`)이 있다 — 이번 리메이크에 자연스럽게 흡수한다.

## 3. 핵심 메커닉 재설계 — "다가오는 좀비"

### 3-1. 이동 모델
- 좀비는 배경 원경(작게, 흐릿하게)에서 스폰 → 시간이 지날수록 **CSS `scale()` 확대 + `bottom` 값 증가**로 카메라(플레이어)를 향해 걸어오는 원근감을 낸다. 실제 3D 카메라는 필요 없다 — 기존 코드의 `requestAnimationFrame` 루프(`monsters` 배열, `m.x`)에 `m.dist`(0=최원거리~1=플레이어 앞) 값을 추가하고 매 프레임 `dist += speed*dt`로 증가시키면서 `transform: scale(0.35 + dist*0.9)` 식으로 적용.
- 좌우 위치는 기존처럼 랜덤 배치를 유지하되, 다가올수록 좌우 흔들림(sway) 폭을 줄여 "정면으로 곧장 다가오는" 압박감을 준다.
- **위협선(threat line)**: 화면 하단 15~20% 지점에 도달(`dist≈1`)하면 그대로 두지 않는다 — 플레이어 생명력(♥ 하트 아이콘, 이모지 아님 — 이미지/SVG)이 깎이고 좀비는 사라진다. 이것이 기존에 없던 "긴박감" 축이며, 하우스 오브 더 데드류 게임의 핵심 텐션이다.
- 총알이 좀비에 명중하는 판정은 기존 클릭/탭 로직을 그대로 재사용(이미 `field` 좌표 기반으로 잘 동작).

### 3-2. 좀비 유형 (최소 6종, Higgsfield 생성)
정답 표적/오답(distractor) 좀비를 시각적으로도 구분해 "정답만 골라 쏘는" 학습 판정이 더 직관적이 되도록 한다.
1. **일반 좀비** — 기본 속도, 가장 많이 등장
2. **빠른 좀비(스프린터)** — 위협선 도달이 빨라 반응속도 요구 (스테이지 상급에 등장 — 기존 `stageLvl`/`speedLvl` 난이도 체계에 연결)
3. **방호복 좀비** — 명중 판정에 1타 더 필요 없음(교육 로직 단순성 유지 위해 HP는 항상 1로 고정하고, 대신 **크기·위압감**만 다르게)
4. **골든(보너스) 좀비** — 기존 `golden` 클래스 유지, 왕관 이모지 대신 **금빛 오라 이미지 이펙트**(CSS 필터+파티클)로 대체
5. **오답 유도용(distractor) 좀비** — 기존 로직 그대로, 비주얼만 살짝 어둡게/스치듯 지나가는 실루엣으로 구분
6. **보스급(스테이지 클리어 연출용, 선택)** — `winGame()` 화면 전환 직전 등장시켜 연출 임팩트

에셋 생성은 기존 `build-shooter-assets.py` 파이프라인(그린스크린 시트→키잉→webp)을 그대로 재사용, `MON_SHEETS`/`MONS` 테이블만 좀비 프롬프트로 교체. 단, **다가오는 스케일 확대에도 뭉개지지 않도록** `MON_BOX`를 260 → 520 정도로 올려 원본 해상도를 확보한다(표시 크기는 CSS에서 축소하므로 용량은 webp 압축으로 흡수).

### 3-3. 총기·사수(대기 중이던 계획 흡수)
`shooter-armed-soldier-plan.md`에 있던 미착수 항목 두 가지를 이번 리메이크에 합친다.
- **A) 총을 실제로 손에 쥔 모습** — 현재는 사수 손이 비어 있고 총은 별도 SVG라 안 붙는다. 이번에 사수를 "총을 든 채로" 다시 촬영/생성(무기 종류별 최소 2포즈: 대기/조준), 상체 회전(±25°)으로 좌우 조준을 표현.
- **B) 게임 허브 카드 썸네일** — 현재 `img/games/shooter.webp`가 우주선 이미지라 "사격 장면"과 안 맞는다 → 좀비 접근 장면으로 재생성(제목/라벨 텍스트는 손대지 않는다).

### 3-4. 배경
- 캡처 화면처럼 **폐허가 된 도시 거리**(안개·파괴된 차량·건물) 실사 배경 1~2장을 Higgsfield로 생성. 기존 우주 배경(`shooter-space-bg.webp`)을 대체.
- 톤은 어둡되 상단 HUD·단어 라벨 가독성을 위해 중앙부는 기존과 같이 다소 어둡게 유지(디자인 원칙 그대로 승계).

## 7. 리스크 · 열린 질문

- **폭력성 톤**: 2장에서 승인 필요. 미승인 시 "좀비"를 "에너지 감염체" 등으로 순화한 컨셉아트로 우회 가능.
- **에셋 제작량**: 좀비 6종 + 배경 1~2장 + 사수 무기별 포즈(13종×2)는 만만치 않은 Higgsfield 생성/키잉 작업량. 1차는 좀비 3종 + 무기 포즈는 대표 3종(권총/장총/기관총)만으로 축소해 프로토타입 먼저 검증하는 것을 권장.
- **성능**: 저사양 기기에서 다수의 확대 애니메이션 좀비 + 파티클이 동시에 뜨면 프레임이 떨어질 수 있다 — [[home-lite-mode-devicememory-cap-bug]] 사례처럼 `navigator.deviceMemory` 기반 라이트모드 캡핑 로직을 셔터게임에도 미리 넣어둘 것.
- **i18n**: 라벨에서 이모지 제거 시 사전 매칭 깨짐 — 4장 각주 참고, 실행 단계에서 별도 확인 필요.
