얼굴 크기 컨트롤을 한 줄로

지금 얼굴 화면 크기를 정하는 버튼이 7개, 좁아지면 두 줄로 접혀 수업 화면 위쪽을 잡아먹습니다. 경쟁 화상수업 제품들이 같은 문제를 어떻게 풀었는지 보고, 한 줄에 들어가는 안 4가지를 만들었습니다. 각 안의 컨트롤은 실제로 눌러 볼 수 있습니다 — 옆 화면이 그대로 따라 움직입니다.

좋은 점

  • 줄 수가 고정입니다 — 폭이 좁아지면 손잡이만 짧아지고 두 줄이 되지 않습니다.
  • 손가락 하나로 끝까지 갑니다. 폰에서 «작은 버튼을 정확히 짚는» 일이 사라집니다.
  • 개념이 하나(얼굴 크기)로 통일돼 글자를 안 읽어도 뭘 하는 줄인지 보입니다.
  • 나중에 무단계(8단·연속)로 넓혀도 UI 를 다시 안 만듭니다.

걸리는 점

  • 「지금 1/2 인가」를 손잡이 위치로 읽어야 합니다 — 그래서 손잡이에 숫자를 얹었습니다.
  • 정확히 한 단만 옮기려면 조준이 필요합니다(키보드 ←→ 로 보완).
  • 수업 중 실수로 끌릴 위험이 버튼보다 큽니다. 폰 상단 고정 자리라면 여백을 넉넉히 줘야 합니다.

좋은 점

  • 「전체」가 실제로 무엇인지 그림이 말해 줍니다 — 지금 이름만 보고 «무엇의 전체인지» 몰랐던 문제가 사라집니다.

  • 폰에서 라벨만 떼면 그대로 축소됩니다 — 구조를 다시 안 짭니다.

걸리는 점

  • 아이콘 4개를 처음엔 눈으로 익혀야 합니다(툴팁 필요).
  • 칸이 4~5개라 슬라이더·스테퍼보다 가로를 더 씁니다. 폰 세로에서 라벨은 확실히 빼야 합니다.
  • 아이콘을 SVG 로 새로 그려야 합니다 — 이모지로는 이 그림이 안 나옵니다.

벤치마크Zoom 「나란히 보기」의 화면 분할선, Windows 창 스냅. 컨트롤을 없애고 보고 있는 것 자체를 만지게 하는 방식입니다.

좋은 점

  • 지면을 거의 안 씁니다. 상단에 남는 것은 칩 하나 — 지금 두 줄을 쓰던 자리가 통째로 수업 화면이 됩니다.
  • 원하는 비율에 무단계로 맞출 수 있습니다. 「1/2 는 좁고 3/4 는 넓다」가 해결됩니다.
  • 결과를 보면서 정합니다. 눌러 보고 되돌리는 왕복이 없습니다.

걸리는 점

  • 발견성이 가장 낮습니다. 「끌 수 있다」를 모르면 영영 안 씁니다 — 첫 수업 1회 안내가 반드시 필요합니다. 그래서 칩 메뉴에 4단계를 그대로 남겨 두었습니다.
  • 폰 세로는 분할선이 가로라 위아래로 끌어야 합니다 — PC 와 조작 방향이 다릅니다.
  • 칠판·PDF 캔버스가 끄는 내내 다시 그려집니다. 지금은 전환 후 280ms 에 한 번만 wbResize() 를 부르는데, 연속 조절이면 손을 뗄 때만 부르도록 바꿔야 합니다.
  • 얼굴 폭이 CSS 8곳에서 breakpoint 별로 재정의되고 있어, 인라인 값과 부딪힙니다 (작성자 !important 가 인라인을 이기는 구간이 있습니다).
