# 업무보고

**상관에게 보고하는 일일업무 보고서**를 남기는 곳입니다. (`docs/작업기록/` 과는 다릅니다 — 그쪽은
"왜 이렇게 했나"를 팀원에게 남기는 기술 기록이고, 여기는 "오늘 무엇을 했고 무엇이 남았나"를
상관에게 보고하는 문서입니다.)

## 파일

| 파일 | 내용 |
|---|---|
| [일일업무보고.md](일일업무보고.md) | **누적 보고서 (정본).** 가장 최근 날짜가 맨 위에 오고, 아래로 내려갈수록 과거 기록입니다. |
| [일일업무보고.html](일일업무보고.html) | 위 .md 를 화면으로 보기 좋게 그린 버전(그래픽 타임라인 포함). .md 를 고치면 이 파일도 같은 순서로 다시 만듭니다. |
| [일일업무보고.pdf](일일업무보고.pdf) | 위 .html 을 인쇄한 PDF — 대화창 다운로드 카드로 전달하는 실제 파일. 한글이 깨지지 않도록 폰트를 파일 안에 심어 둔 상태입니다. |

## 쓰는 법

작업을 마친 뒤 "오늘 한 일 보고서 작성해줘"라고 요청하면, `일일업무보고.md` **맨 위에**
그날 날짜로 새 항목을 추가합니다. 기존 기록은 건드리지 않고 그대로 아래에 남겨 둡니다.

## 항목 구성 규칙

각 업무 항목마다 다음을 반드시 넣습니다.

1. **된 것 / 안 된 것 / 진행중인 것 / 요청사항** — 넷을 각각 구분해서 적습니다.
2. **깃허브 확인 링크** — 커밋·브랜치·PR 주소를 함께 적어서, 보고받는 사람이 직접 눌러 확인할 수 있게 합니다.
3. **타임라인** — 그 업무가 지금까지 얼마나 진행됐는지 시각적으로 보여줍니다.
4. **다음에 할 일** — 앞으로 진행할 업무를 미리 적어 둡니다.

전문용어가 나오면 본문은 쉬운 말로 풀어 쓰고, 용어 설명은 별도 PDF로 전달합니다
(대화창 다운로드 카드로 받습니다 — 이 세션은 클라우드 컨테이너라 사용자 PC 바탕화면에
직접 파일을 놓을 수 없습니다).
