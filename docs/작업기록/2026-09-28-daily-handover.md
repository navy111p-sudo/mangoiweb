# 매일보고: 5분 이내 작성 흐름

요청: 승인된 테스트 화면을 결재함에 연결하고 작성 부담을 줄인다.

- `/work` 상단에 매일보고 링크. `/daily-handover.html`에서 오늘 업무·문제/조치·남은 일만 입력한다.
- 날짜·계정 자동 입력, 문제 없음/남은 일 없음, 한국어·영어 병기, 브라우저 음성 입력(지원 여부 안내).
- 기존 관리자 인증과 본사 권한 사용. 새 D1 표만 생성한다. 기존 결재 표/학생 데이터는 수정하지 않는다.
- 초안은 작성자에게만 보인다. 확인 후 전달해야 수신자와 경영진 목록에 나타난다.
- 수정 충돌은 버전으로 거부하고 재전송 키로 중복 저장을 방지한다. 수정 이력은 별도 표에 보관.
- AI는 문장 제안만 제공한다. 적용 여부는 작성자가 결정하고 적용 후 다시 점검한다. AI 실패/12초 지연은 수동 점검으로 대체한다.
- 화면 타이머는 작성 시간 피드백이며 5분에 내용을 지우거나 강제 제출하지 않는다. 실제 사용자 작성 시간은 배포 후 확인이 필요하다.
- 수신 확인과 보완 요청은 별도 상태이며 업무 완료/금융 결재를 발생시키지 않는다.
- 미작성 알림은 본인이 근무 요일과 KST 마감 시각을 확인하여 켠다. 근무표를 임의 추정해서 휴무 직원에게 경고하는 방식을 피했다. 휴가/휴무일 1일 제외 지원.
- 기존 15분 결재 cron에서 마감 30분 전/마감/30분 후를 검사한다. 제출한 보고는 제외하고 단계별 알림은 멱등 처리한다.
- 기존 구독이 있으면 Web Push로 알린다. 구독/권한이 없으면 기기에 도달했다고 표시하지 않는다. 카카오·문자 신규 발송은 추가하지 않는다.
- 목록 날짜·확인대기·보완요청·미완료·긴급 필터와 설정된 보고 대상의 미제출 목록 제공.

검증: 새 API를 격리 SQLite에서 실행하여 권한·초안 비공개·저장/재시도/충돌·확인/보완·AI 실패·기한·휴무/중복 알림을 검사한다 (`daily_handover_harness.mjs`). 브라우저에서는 실제 페이지 스크립트와 모의 API로 입력/제안 적용/확인 무효화/제출/목록 갱신 및 320·360px 폭을 검사한다 (`manual/daily-handover-browser.mjs`). 운영 AI와 실제 직원 기기 푸시는 합성 테스트로 검증된 것으로 간주하지 않는다.

## 17시 후속 개선 — PC/휴대폰 읽기·첨부·미확인 알림

사용자 승인: PC 목록/본문 분리, 휴대폰 한 건씩 읽기, 대표/부장 상단 배치, PDF 첨부 및 반드시 읽기 알림. `추진해` 요청으로 구현.

- 정우영(`admin`)·장지웅(`mgr_jjw`)은 관리자 첫 화면의 기존 바로가기 위에 매일보고 진입/미확인 건수를 표시한다. 기존 일일 매뉴얼 팝업·긴급 결재 기능은 유지한다. 결재함 상단에도 같은 안내가 있다.
- 받은 보고 우선, 내 작성은 버튼으로 열기. PC 본문 22px, 휴대폰 20px, 선택 시 26px. 모바일은 이전/다음 및 확인 후 다음 미확인 보고. 조회 옵션 접기, 본문 재확인을 막지 않도록 내용이 같으면 주기 갱신에서 다시 그리지 않는다.
- `admin`/`mgr_jjw` 우선 배치는 UI 선택이며 권한을 부여하지 않는다. 서버 기존 본사/경영진 판정을 그대로 사용한다. 푸시는 지정된 수신자에게만 간다. 수신자 대신 경영진이 확인하면 기존 공동 확인 상태에 따라 종료한다.
- PDF/PNG/JPG/DOCX/XLSX/PPTX 첨부: 최대 5개, 각각 20MiB. 업로드 경로는 인증/동일 Origin 확인 후 읽는 스트림 바이트 수까지 제한한다. 기본 파일 서명 검사. Office는 다운로드 전용(실제 OOXML 구조/악성코드 검사를 했다고 주장하지 않음). AI는 첨부 내용을 분석하지 않는다.
- R2 `RECORDINGS`의 `daily-handover/<uuid>` 키를 사용하며 키/공개 URL은 반환하지 않는다. 다운로드 때마다 보고 열람 권한과 현재 보고의 첨부 ID를 확인한다. 제출 전 파일은 작성자만 열람. 응답은 private/no-store, nosniff, sandbox. 임시 첨부를 제외해도 파일을 즉시 삭제하지 않아 버전 이력을 손상시키지 않는다. 업로드 일일 상한 30개. 장기 정리 정책은 별도 운영 결정 사항.
- 기존 표는 손대지 않고 파일 메타/읽기 알림 시간/재알림 상태 표 3개만 멱등 생성. 파일 식별자는 버전 관리되는 보고 payload에 저장. 첨부 변경 시 확인 상태를 무효화한다.
- 읽기 알림은 미작성 알림과 분리, 기본 활성. 일반 보고는 평일 09–19시(KST) 안에서 60분, 긴급은 시간 제한 없이 15분. 근무 요일/시간 설정 가능. 기존 15분 cron의 해상도 때문에 재알림 시각은 최대 약 15분 지연될 수 있다. 근무 외 일반 보고는 다음 근무 시작에 발송한다.
- 날짜가 지난 미확인도 inbox/재알림 대상. 보고를 여는 것으로 확인 처리하지 않는다. 내용 확인 완료 또는 보완 요청 시 종료. 제출 수정으로 새 버전이 되면 다시 알린다. DB 조건부 claim으로 중복 cron 방지, 같은 report/version/endpoint의 대기 푸시는 한 개로 유지. 제출 뒤 알림 단계가 실패해도 cron이 다시 생성한다. 만료 push 구독은 비활성화한다.
- 푸시 권한/구독 없으면 화면 배지와 기기 설정 링크 유지. 큐 삽입뿐 아니라 Web Push wakeup 호출. 푸시 성공 응답은 실제 기기의 수신·사람의 열람과 다르다.
- 결재함은 외부 JS/CSS 없는 설계 계약을 유지하기 위해 배너 JS를 inline 복제한다. `handover-inbox-banner.js`와 내용 동일 여부를 하니스로 감시한다. 관리자만 외부 버전 JS 사용.

검증: 격리 SQLite + 모의 R2로 업로드 서명/초안 프라이버시/권한 없는 파일 연결 및 다운로드 차단/날짜 지난 inbox/시간대/재알림 간격/중복 방지/확인 후 종료. 실제 페이지 JS + 모의 API Playwright에서 PC/320·360·390px, 확인 후 다음, 파일 업로드, 첨부 변경 확인 무효화, 상단 배너 deep link 검사. 운영 DB에 테스트 행을 넣거나 직원에게 테스트 알림을 보내지 않음. 운영 로그인/PDF 뷰어/실제 기기 푸시는 현장 확인 필요.
