# 매일보고 피드백 전달·확인 보강

요청: 대표가 팀 보고판에서 답글을 작성하고 한국·필리핀 매니저가 PC·휴대폰에서 놓치지 않도록 한다. 기존 보완 요청도 같은 확인 절차에 연결한다.

- 보고별 답글을 별도 표에 보존한다. 보고 확인과 피드백 확인은 별개이며 수정·재제출로 답글이 사라지지 않는다.
- 보고판과 읽기 화면에 여러 줄 답글 작성, 발신자·시각·푸시 상태·매니저 확인 시각을 표시한다. 접힌 보고에도 미확인 건수를 표시한다.
- 관리자·매니저·결재함·매일보고의 공용 알림 배너에서 미확인 본문을 먼저 표시한다. 닫기·Escape로 건너뛰지 못하고 5초 및 본문 끝 확인 후 본인이 확인 버튼을 누른다. 새로고침·재접속에도 서버 미확인 기록이 남는다.
- 기존 보완 요청의 한 줄 prompt를 여러 줄 dialog로 바꾸고, 새 보완 요청은 원래 상태 변경과 같은 트랜잭션으로 피드백 기록도 남긴다. 현재 보완 요청 상태인 기존 보고도 최초 조회 때 중복 없이 가져온다.
- 기기 푸시는 기존 구독/큐를 재사용하며 잠금 화면에 본문을 노출하지 않는다. 미등록·발송 실패·대기를 발신자에게 표시한다.

검토 후 제외: 문자·메일 추가 발송, 업무 완료 추적. 요청 범위에서는 기존 푸시와 접속 시 필수 확인으로 전달하고 확인 시각을 남기는 것이 가장 작다. 실제 사람이 이해했는지와 접속하지 않은 기기에서 열람했는지는 보장하지 않는다. 5초와 스크롤은 화면 장치이며 서버가 독해를 판정하지 않는다.

검증: 타입체크 통과. 메모리 SQLite 테스트로 한국/필리핀 작성자 분리, 타인 확인 차단, 중복 전송 방지, 푸시 상태, 기존 보완 요청, 보고판 건수를 확인했다. 실제 Chrome의 PC(1440px)/휴대폰(390px) 화면에서 작성→본문 표시→Escape/새로고침 유지→각 답글 확인→발신자 확인 시각까지 실행했다. 운영 DB에 시험 보고·답글을 작성하지 않았다. 전체 회귀 및 CI·병합·배포 결과는 PR과 최종 보고에 남긴다.
