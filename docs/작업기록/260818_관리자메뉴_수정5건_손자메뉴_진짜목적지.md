## 1. 왜 했나

사장님이 캡처 5장으로 수정요청을 주셨다:

1. **수업연기 버튼** — 학생 상세보기 ▸ 스케줄에서 수업을 옮길 방법이 «취소하고 다시 등록» 뿐이라, 연기 한 번에 수업 이력이 끊겼다.
2. **신규학생 등록 시 교사 종류** — 「홈교사 / 오피스」 가 회사 안에서 쓰는 말이라 학원장·학생·학부모가 뜻을 몰랐고, 결과적으로 전부 오피스로 배정되고 있었다. 성향(상냥한·재미있는·교육적인·진지한·웃음 많은)으로 고르는 칸을 원하셨다.
3. **조직 하위 정리** — 「운영자 본사-지사-대리점」 아래에 대표지사·지사·대리점 항목 신설.
4. **「조직 (지사·대리점)」 위치** — 「정산·매출」 밑에 있어서 조직을 고치러 온 사람이 정산 메뉴를 뒤져야 했다.
5. **지사 소속 대리점 찾기** — 지사에 소속된 대리점을 찾는 기능이 없었다. 대리점명 입력 검색도 함께.

배포 후 사장님이 화면을 직접 보시다가 여섯 번째가 나왔다: **「학생 명부 ▸」 를 펴면 나오는 다섯 줄(학생 등록·검색 / 학생 상세 프로필 / …)을 눌러도 이름과 다른 곳이 열린다** («여기서 어디로 가?»). 추적해 보니 사이드바 3단계(손자 메뉴) 전체가 같은 병을 앓고 있었고, 「나머지도 하나씩 진짜로 만들어 달라」 는 지시로 이어졌다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **「이름을 실제와 맞추기」(라벨만 교정) — 버림.** 데모 매핑은 허구인데 그럴듯한 이름표를 달면 영구화된다. 다음 사람이 진짜인 줄 알게 된다. 사장님 확인 후 «진짜 목적지» 방향으로.
- **새 API 경로(`/api/admin/master-branches`) — 버림.** 새 `/api` 경로는 `src/index.ts` 의 라우팅·인증 게이트 **두 곳**을 통과해야 하는데 index.ts 는 공동 금지구역. 이미 세 관문이 열린 `/api/admin/franchises` 에 `view=`/`kind=` 로 붙였다(admin_new_apis_harness 의 «도달 가능성» 원칙).
- **`franchises` 테이블에 대표지사 컬럼 추가 — 버림.** 카페24가 정본이라 야간 03:45 UPSERT 가 덮는다(CLAUDE.md «다음날 원복» 함정). `center_franchise_override` 와 같은 방식의 별도 매핑 표(`franchise_master_map`)로.
- **대리점 찾기를 이름(LIKE) 매칭으로 — 버림.** `centers.name`/`franchises.name` 이 유일하지 않아(같은 이름 5개·학생 2,603명) 엉뚱한 지사 것이 섞인다. `franchise_id` 필터로.
- **성향 안 고르면 «1개 이상 고르세요» 로 막기 — 버림.** 뜻을 모르는 사람이 아무거나 찍게 될 뿐이다. 안 고르면 오피스 배정으로 하고 그 규칙을 화면에 명시(숨은 규칙 금지).
- **남은 카드(가리킬 칸이 없는 것들)까지 앵커 강행 — 버림.** 라벨 313개 중 진짜 목적지를 댈 수 있는 것은 84개뿐이었다. 나머지는 «읽음 처리 버튼»·«중요 알림 필터» 처럼 **기능 자체가 없어서** 배선이 아니라 제품 개발이다(실측: `card-active-rooms` 는 라벨 4개인데 카드 안에 새로고침 버튼 1개·표 1개뿐, `card-admin-alerts` 는 라벨 4개에 요소 1개). 무엇을 만들지는 사람이 정할 일이라 멈추고 보고했다.
- **대표지사 «삭제» 기능 — 안 만듦.** 지우면 산하 지사 매핑이 통째로 끊겨 되돌릴 길이 없다. «중지»(active=0)만.
- **#247 «대표지사 되살리지 말 것» 과의 충돌** — #247 이 지운 이유는 «표를 채우는 JS 가 0곳»(빈 껍데기)이었고, 이번 것은 배선이 실제로 붙어 그 이유가 사라진다. **사장님 확인 후** 되살렸고 근거를 병합 커밋에 남겼다. #247 이 함께 지운 셋(독립 사이트·종전금·포인트 내역)은 지워진 채 유지.

## 5. 남은 것 / 주의할 것

- **병행 작업과 세 번 겹쳤다.** 같은 날 별도 세션들이 같은 주제를 팠다.
  - **#275** — 회계 4항목만 앵커로. 병합 때 넓은 쪽(19항목)을 쓰되 좁은 쪽의 앵커 이름(`acc-student-payments`)과 설명 주석을 살렸다.
  - **#281** — 내 17개 카드 변환을 병합한 뒤, **남아 있던 허구 항목을 통째로 지웠다**(MAP 에서 카드 **54개 삭제**). 즉 3장에서 «사람이 정할 일» 로 남겨 둔 것을 «없앤다» 로 결론 낸 셈이다.
  - **결과(2026-08-18 기준 main):** MAP 은 **17개 카드 86항목, 전부 `{ko,en,anchor}` 객체**이고 문자열(지어낸 이름) 항목은 **0개**다. 지어낸 이름이 사라졌으므로 «이름과 다른 칸이 열리는» 사고는 구조적으로 안 난다.
- **새 카드를 만들 때 손자 메뉴에 «없는 기능 이름» 을 지어 넣지 말 것.** 이 사고의 뿌리가 그것이다. 넣으려면 그 자리(앵커)를 함께 만들어야 한다.
- **`adm-q11.js` 를 고치지 말 것** — 동명 매핑이 있지만 `showFlyoutV2` 첫 줄 `return;` 뒤라 죽은 코드다(파일에 표지 주석 있음). 고치면 «고쳤는데 화면이 안 변하는» 착각만 낳는다.
- **앵커 id 는 짝이다** — `admin.html` 의 id 와 `adm-r25.js` 의 anchor 를 한쪽만 바꾸면 에러 없이 옛 «N번째 details» 방식으로 조용히 되돌아간다. `admin_grandchild_menu_harness.mjs` 가 못 박고 있으니 FAIL 나면 그 짝을 의심할 것.
- **화면 미확인 잔여** — 모바일(adm-s10 «첫 탭=설명, 두 번째 탭=이동»)에서 새 앵커 동작, PC `zoom:1.3` 에서 앵커 점프 후 스크롤 위치는 실기기 확인이 안 됐다.
- 손자 메뉴 hover 설명 사전(`GC_DESC`, adm-r16/admin-tip-i18n)이 옛 데모 이름을 키로 쓰던 것 — 새 이름은 키워드 폴백으로 일반 설명이 나온다(사고 아님, 품질 저하). 보강할지는 별건.
