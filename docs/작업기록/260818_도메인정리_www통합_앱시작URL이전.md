## 1. 왜 했나

시작은 **「전체적으로 코드를 다시 한번 정리하려는데 어떻게 생각하나」** 라는 질문이었습니다.
`www.mangoi.ai` 도메인을 추가하고 기능을 넣다 뺐다 하면서 엉켰을 것 같다는 우려였습니다.

먼저 상태를 실측했습니다.

| 항목 | 실측값 |
|---|---|
| 회귀 하니스 | PASS 153 / FAIL 0 (당시 기준선) |
| 추적 중인 백업·찌꺼기 파일 | **1개** (`intro.original.mp4`) |
| 아무 데서도 링크 안 되는 HTML | 2개 (그중 1개는 실제로는 살아 있는 페이지였음 — 3장 참조) |

**정리할 쓰레기가 거의 없었습니다.** 그래서 대규모 정리 대신, 「도메인이 바뀌었다」는
단서 하나를 끝까지 따라가는 쪽으로 방향을 잡았고 — 그 줄을 당기니 아래가 줄줄이 나왔습니다.

### 실제로 나온 문제들

1. **패스키가 깨질 상태였다** — `rpId` 로 요청 호스트명을 그대로 써서, `mangoi.ai` 와
   `www.mangoi.ai` 를 WebAuthn 이 **다른 사이트로** 취급. 한쪽에서 등록한 지문이 다른 쪽에서 거절.
2. **로그인이 통째로 갈리고 있었다** — 교사 세션 쿠키는 `Domain=` 없는 호스트 전용,
   학생 로그인·언어 설정은 `localStorage`. 둘 다 오리진별로 갈립니다.
3. **앱이 옛 도메인을 계속 보고 있었다** — `test.mangoi.co.kr` 을 병행하는 **유일한 진짜 이유**.
4. **「완료」라고 거짓 보고하던 버튼들** — 2026-08-17 에 걷어낸 시연 껍데기의 잔여분.
5. **「케이씨피M」이 API 응답에 그대로 남아 있었다** — 화면에서는 뺐지만 API 주소를 열면 보임
   (사장님이 직접 확인).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### ⛔ 「전체 코드 일괄 정리」 — 반대했고, 지금도 반대합니다

- 실측 결과 **쓸어낼 찌꺼기가 거의 없었습니다**(백업파일 1개, 하니스 그린).
- 남은 큰 덩어리(`admin.html` 1.05MB, `api-admin.ts` 11,000줄+)를 건드리는 건 정리가 아니라
  **재작성**입니다. 하니스가 지켜 주는 건 **이미 알려진 사고**뿐입니다.
- 2인 분담 구조상 그 두 파일을 넓게 건드리면 병합이 사실상 불가능합니다.
- 이번에 나온 것 중 가장 큰 건(로그인 분리)도 전체를 훑어서가 아니라
  **단서 하나를 따라가서** 나왔습니다.

### ⛔ 쿠키 `Domain=mangoi.ai` 만 넓히기 — 절반짜리라 버림

교사 세션 쿠키는 이걸로 해결됩니다. 그런데 **학생 로그인은 `localStorage`** 이고,
**오리진별로 갈리는 것이 웹 표준이라 공유할 방법이 아예 없습니다.**
그래서 「주소를 하나로 모으는」 것만이 완전한 해결책이었습니다.

### ⛔ `test.mangoi.co.kr` 도 리다이렉트 — www 와 달리 잃을 게 있어서 버림

| | www.mangoi.ai | test.mangoi.co.kr |
|---|---|---|
| 등록된 패스키 | **0건** | **6건** (계정 3개) |
| 사용자 기반 | 없음(방금 추가) | 앱 사용자가 사용 중 |

www 는 잃을 게 0이라 공짜였지만, test 쪽은 리다이렉트하면 **패스키가 무효화**되고
앱 사용자의 `localStorage` 로그인도 날아갑니다. **지금도 하면 안 됩니다.**

### ⛔ 「죽은 파일」로 보였지만 지우지 않은 것 둘

- **`app.html`** — APK 설치 안내 페이지(`/downloads/mangoi.apk` + QR).
  사이트 안에 링크가 없는 게 **정상**입니다(밖으로 뿌리는 주소). 지웠으면 앱 설치가 끊겼습니다.
- **`review-quiz-cn.html`** — 죽은 게 아니라 **입구가 없던 것**. 삭제가 아니라 연결이 정답이었고,
  연결 전에 `lang` 필터 버그부터 고쳐야 했습니다(안 고치고 걸었으면 중국어 화면에 한국어 퀴즈 14개가 떴을 것).

### 🔀 301 vs 302 — 301 선택 (사장님 확인)

정본 도메인 통합의 표준이라 301 을 썼습니다. 브라우저가 오래 캐시하므로 되돌리기 어렵다는 점을
알리고 확인받았습니다.

### 🔀 `adm-s14.js` 의 「데모 데이터 16건」 문구는 **그대로 뒀습니다**

거짓말이 아니라 **정직한 고지**입니다. 지우면 오히려 데모를 실데이터로 오인하게 됩니다.

## 5. 남은 것 / 주의할 것

### ⛔ `test.mangoi.co.kr` 은 아직 끄면 안 됩니다

이미 깔린 앱은 APK 에 박힌 옛 주소를 계속 봅니다. 먼저 죽이면 앱이 흰 화면이 되고,
**업데이트 확인 주소도 같은 도메인이라 앱이 자기 힘으로 복구할 수 없습니다.**

지우는 순서: ① 소스 이전(완료) → ② 새 APK 보급 대기 → ③ 워치독·스모크·하니스 주소 정리
→ ④ 보급률 확인 후 **맨 마지막에** 도메인 제거.

### 사람이 해야 할 일

1. **맥에서 iOS 빌드 확인**
2. **학생 안내** — 새 APK 를 켠 사람은 **한 번 로그아웃**되고, 옛 도메인에 등록한
   패스키는 재등록이 필요합니다. 오리진이 바뀌므로 피할 수 없습니다
3. **패스키 재등록 대상은 계정 3개** (그중 1개는 이미 새 도메인에 등록해 둬서 실제 영향은 2개).
   ⚠️ 세 계정 모두 **연락처가 비어 있어 문자로 닿지 않습니다** — 그래서 로그인 화면 안내(#261)가
   실질적인 유일한 경로입니다

### 새 APK 배포는 2단계입니다

`mobile-app/**` 을 머지하면 `android.yml` 이 APK 를 빌드해 main 에 커밋하지만,
**그 커밋은 사이트 배포를 못 깨웁니다.** 새 APK 파일이 사이트로 나가려면
**그 뒤에 사람 쪽 main 푸시가 한 번 더** 필요합니다.

3. **CI 체크런 0건** — 문서화된 해법(main 을 브랜치에 병합해 push)이 실제로 통했습니다.
4. **배포가 `cancelled` 로 떠도 실패가 아닙니다** — 짧은 간격으로 머지가 몰리면
   **대기 중이던 run 들이 정리되고 마지막 run 이 최신 main 을 통째로 배포**합니다.
   ⚠️ 처음엔 「`cancel-in-progress: false` 인데도 취소됐다」고 적었는데 **부정확했습니다.**

   같은 날 다른 작업자가 CLAUDE.md 2장에 더 정확히 적어 두어 그쪽을 정본으로 택했습니다.
   확인은 `git merge-base --is-ancestor <내 커밋> <배포 성공한 sha>` 로 합니다.
