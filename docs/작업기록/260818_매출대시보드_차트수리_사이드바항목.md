## 1. 왜 했나

**제보 ①** — 관리자 `정산·매출 > 📊 매출 대시보드` 에서 「📊 차트 보기」를 누르면
막대·선 그래프가 **카드 밖으로 한없이 길어져** 화면 비율을 벗어났습니다.

**제보 ②** — 위 화면을 확인하러 갔더니 **사이드바 「정산·매출」 을 펼쳐도 매출 대시보드가 없다**는
말씀이 나왔습니다. 실제로는 「회계」 카드 **안의** 접이식 줄이라, 회계를 열고 긴 목록에서
또 찾아야 했습니다 — 「메뉴에 없다」로 보이는 게 당연한 구조였습니다.

## 2. 무엇을 바꿨나

### ① 차트가 카드를 벗어나던 것 (#233)

| 파일 | 무엇 |

| `cloudflare-deploy/public/admin.html` | `#acc-sales-chart` 바깥 상자 안전망, `adm-core.js ?v=104 → v=118` |
| `test-harness/asset-versions.json` | 원장 등록 |

바뀐 핵심 두 줄:

```
- <canvas height="180"></canvas>
+ <div style="position:relative;width:100%;height:min(240px,55vh)"><canvas></canvas></div>

- grid-template-columns: 1fr 1fr
+ grid-template-columns: repeat(auto-fit, minmax(min(100%,300px), 1fr))   /* 각 칸 min-width:0 */
```

곁들여: 다시 그릴 때 이전 `Chart` 인스턴스를 `destroy()`,
x축 `maxRotation:0` + `autoSkip`, y축 `maxTicksLimit:6`.

### ④ 사이드바 항목이 눌러도 안 열리던 것 (#301)

칸은 **열려 있었습니다**(`open=true`). 화면이 거기로 안 갔을 뿐입니다 —
실측(1440×900) 칸 제목줄이 **top 1492px**, 화면(900px) 아래로 592px 밖이었습니다.

`scrollIntoView` 를 스택까지 추적해 범인을 특정했습니다:

```
 14ms  card-accounting-mgmt   ← ia6 showOnly (카드 맞추기)
 19ms  sub-acc-11             ← 우리가 칸을 맞춤
 57ms  card-accounting-mgmt   ← adm-s11.js:85  (ph97)
154ms  card-accounting-mgmt   ← adm-s11.js:90  (ph97)
```

`adm-s11.js`(ph97)는 `.ph85-sub` 클릭마다 50ms 뒤 **그 칸이 든 카드**를 따로 스크롤합니다.
`adm-ia6.js` 의 「내 목적지가 아닌 곳으로 가려는 스크롤이면 손을 뗀다」가 그걸 보고
**우리 칸 맞추기를 곧바로 죽였습니다** — 1.8초 재보정이 한 번도 못 돌았습니다.

고침은 한 조건: 조상으로 오는 스크롤은 「다른 곳」이 아니라 **「같은 목적지의 거친 판」**입니다.

```diff
- ... && this !== alignLead) alignRelease();
+ ... && this !== alignLead && !this.contains(alignLead)) alignRelease();
```

| 화면 | 수정 전 | 수정 후 |
|---|---|---|
| 1440×900 | 1,492px (밖) | **22px** |
| 1280×800 | 1,493px (밖) | **17px** |
| 820×1100 | 1,219px (밖) | **419px** |
| 500×900 | — | **176px** |

기존 항목 회귀 없음(대리점 440→214px, 회계 24px 그대로).
`admin_sidebar_ia6_click_harness` 에 「조상에는 양보하지 않는다」·「연 칸을 맨 위로」를 못 박았습니다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### 차트 (#233)

| 버린 방법 | 왜 안 되나 |
|---|---|
| **`<canvas height="…">` 값을 키운다** | **responsive 모드에서 이 속성은 무시됩니다.** 실측으로 확인했습니다 — 원래 코드에 이미 `height="180"` 이 있었는데도 캔버스가 1,175px 로 그려졌습니다. 「높이를 적어 뒀으니 괜찮겠지」가 **방어가 되지 않는다**는 것이 이 건의 핵심입니다 |
| **바깥 상자에 `max-height` + `overflow:hidden` 으로 잘라낸다** | 증상만 가립니다. 그래프 아래쪽(x축 라벨·범례)이 잘려 읽을 수 없게 되고, **리사이즈마다 캔버스가 커지는 것 자체는 그대로**입니다 |
| **그리드를 미디어쿼리로 접는다** | 이 마크업은 JS 템플릿 문자열로 만들어져 **인라인 `style` 만 쓸 수 있어 미디어쿼리를 넣을 자리가 없습니다.** 그래서 미디어쿼리 없이 접히는 `minmax(min(100%,300px),1fr)` 을 썼습니다 |

### 사이드바 (#283)

| 버린 방법 | 왜 안 되나 |
|---|---|
| **매출 대시보드를 별도 카드로 분리한다** | 회계 카드의 칸 순서와 앵커 id 를 이미 여러 곳이 참조 중입니다(#266 미수금, #268 손익, #273 손자 메뉴). 반경이 큽니다 |
| **새 카드를 만들어 사이드바에 붙인다** | 회계 카드와 내용이 중복되고, `CARD_POLICY`·`rbac` 목록을 한 벌 더 관리해야 합니다. `openSub` 는 **이미 있는 배선**이라 관리 지점이 늘지 않습니다 |

역할 숨김은 `applyRoleFilter` 가 `cards` 로 판정하므로 **「회계」 항목과 같이 움직입니다** —
회계가 감춰지는 역할에게는 이 항목도 자동으로 안 보입니다. 따로 손댈 것이 없었습니다.
