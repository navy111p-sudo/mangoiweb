## 1. 왜 했나

사장님 수정요청 프롬프트 블록 9번(2026-08-18): 「정산·매출 > 손익/재무제표 >
매출–입금 대사(장부 vs 통장)」가 KCP 결제 데이터(장부)를 기준으로 대사를 잡고
있었는데, 이걸 **통장 결제 데이터 기준**으로 바꾸고, 「케이씨피」 이외의 매출과
「케이씨피M」을 대사 대상에서 빼 달라는 지시.

이후 화면을 직접 확인하시며 지시가 네 번 확장됐다:
1. «제외했습니다» 안내 문구조차 «아직 남아 있다» 로 읽힌다 → **이름·금액 표기 전부 제거**
2. 월간 리포트의 «운영자금 보충» 줄도 제거
3. 카페24 회계 실데이터의 회계장부 **목록에서 그 행 자체를 제외**
4. «성격 미확인 입금» 줄도 제거

## 2. 무엇을 바꿨나

### 대사 기준 전환 (#231) — `src/accounting-reports.ts`
- `reconcileReport()`: 기준 = 통장의 「케이씨피」 정산금(`deposit_pg`).
  수수료(2.86%) 역산한 **«통장 기준 매출»** 컬럼 신설. 판정 % 의 분모도
  예상 입금(장부) → **실제 PG 입금(통장)**.
- `kcpSettledSql()` 신설: 장부 쪽도 KCP 정산 대상 결제(카드·정기결제)만 센다.
  ⚠️ **대사 전용**이다 — 회사 매출(`monthRevenue.total` → 손익·월간·분기·연간·KPI)은
  결제수단을 가리지 않는다. 실데이터상 시드 제외 결제는 전부 카드라 현재 차액 0원.
- 누적 합계는 **통장 자료가 있는 달만** 합산(연동 이전 달을 섞으면 판정이 무조건
  «매출 누락» 으로 기운다).
- `reconcileMonth()` 도 같은 규칙(월간 리포트 배너·CSV 와 대사 화면이 어긋나지 않게).
- 화면: `public/js/adm-core.js` `accLoadReconcile()` 컬럼 재배치(기준 컬럼 앞·주황 배경).

### 표시 제거 (#243·#249·#254·#277 + 타 세션 #234·#235·#245)
- 대사 카드: `deposit_transfer` 를 payload 에서 **아예 내보내지 않음**. 안내 문구·Excel
  「타계좌 입금」 컬럼 삭제. 하단 ※ 는 «적요가 정확히 「케이씨피」인 정산금만 대사» 로.
- 월간 리포트(`renderMonthly`): «운영자금 보충» 행·내역 펼치기·헤드라인
  「부족한 돈을 메우려고 …」 문장 삭제. «성격 미확인 입금» 행·펼치기·경고도 삭제.
- 손익계산서(`statementReport`): 케이씨피M 안내줄(타 세션 #235)·미확인 입금 각주(#254) 삭제.
- 카페24 회계 실데이터(`adm-core.js` `c24FinSummary`/`c24FinLoad`): KPI 부제
  «케이씨피M 제외»·안내 상자·장부 건수 배지·행 배지/취소선/툴팁 삭제.
- 회계장부 목록(`api-admin.ts` ledger Cypher): `WHERE NOT (…kcpmRe…)` 로 **행 자체 제외**.
  ⚠️ 월 필터를 괄호로 묶어 AND 로 붙였다 — 기존 `WHERE a.month=$month OR a.date STARTS
  WITH $month` 뒤에 그냥 붙이면 OR 가 NOT 을 무력화한다.
- Excel: 월간 리포트의 «확인필요 입금» 시트 삭제(`transfer_rows` 는 known=false 만 담게 유지).
- 손익계산서 현금흐름 각주(#277): «자금이체가 섞여 있다» → «수업료가 아닌 돈(세금
  환급·이자 등)이 섞일 수 있다» 로 정정. **예전 문구는 사실과 달랐다** —
  `monthCash` 의 `cin` 은 이미 `transferKnown` 을 뺀 값이다.

### 계산은 어디까지 그대로인가 (중요)
- `classifyDeposit()` / `isKnownTransfer()` / `KCP_TRANSFER_CYPHER_RE` 판정 정본 그대로.
- 케이씨피M 을 매출·손익·대사에 넣지 않는 집계 전부 그대로. **이번 작업은 표시만 바꿨다.**
- 값 자체는 payload 에 남아 있다: `funding_in_krw`, `deposit_transfer_unknown_krw`,
  `transfer_rows`. 화면 줄을 다시 만들지 말 것(CLAUDE.md 1-3).

### 회귀 하니스 — 게이트를 끄지 않고 규칙을 뒤집었다
- `test-harness/c24_finance_kcpm_harness.mjs` ④·⑤: «표시로 구분한다» →
  **«목록에서 뺀다 · 표시하지 않는다»**. 집계 제외 검사는 그대로라 숫자가 틀어지면 여전히 FAIL.
- `test-harness/monthly_report_internal_transfer_harness.mjs`: «모르는 돈은 계속 묻는다»
  단언 4개를 «그리지 않는다» 로 반전. 검사 전에 코드·HTML 주석을 걷어내는 `noc()`
  헬퍼 추가 — «왜 지웠는지» 적은 주석이 FAIL 을 내면 다음 사람이 주석을 지우게 된다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **화면(JS)에서만 숨기기** → 버림. Excel·CSV·API 응답으로 같은 값이 다시 새고,
  건수 배지·합계가 목록과 어긋난다. 서버 payload/쿼리에서 빼는 쪽을 택했다.
- **판정 로직에서 transfer 분류 자체를 없애기** → 버림. 케이씨피M 이 매출로 다시
  섞여 들어간다(2026-08-16 오진 사고 재발). 분류·집계 제외는 유지, 표시만 제거.
- **하니스 단언을 삭제해서 통과시키기** → 버림. 게이트가 사라지면 다음 사람이
  «없네?» 하고 표시를 되살려도 아무도 못 잡는다. 단언을 반대 방향으로 뒤집어
  «되살리면 FAIL» 로 만들었다.
- **회계장부 행을 화면에서 filter** → 버림. 서버가 주는 count 와 안 맞고, LIMIT 뒤
  잘린 페이지에서 빠진 행 수가 들쭉날쭉해진다. Cypher WHERE 로 서버에서 뺐다.
- **대사의 장부 매출에 결제수단 전부 포함(기존 방식 유지)** → 버림. 통장이 기준이 된
  이상 KCP 를 안 거치는 결제(계좌이체·가상계좌)는 「케이씨피」 입금으로 들어올 수 없어
  구조적 차이가 생긴다. 단 이건 대사 전용 — 매출 정본에는 손대지 않았다.
- **손익 각주에서 금액만 빼고 «운영자금» 문구 유지** → 버림. 문구 자체가 사실과
  달랐고(입금은 이미 이체를 뺀 값), 그 단어가 화면에 남는 것 자체가 지시 위반.

## 5. 남은 것 / 주의할 것

- ⚠️ **회계장부 목록은 이제 카페24 원본 그대로가 아니다** — 자금이체 행이 빠져 있다.
  원본 대조는 카페24에서 해야 한다.
- ⚠️ **성격이 안 잡힌 입금이 새로 들어와도 화면이 알려 주지 않는다.** 매출로는 안
  잡히지만, 그중 진짜 매출이 섞여 있으면 사람이 모르고 지나간다. 확인이 필요하면
  D1 `bankacct_transactions` 를 직접 볼 것(값은 payload 에도 남아 있다).
- ⚠️ 「케이씨피」 로 시작하는 **새 변형 적요**가 나타나면 여전히 transfer 로 분류돼
  매출에서 빠진다 — 화면 경고가 없어졌으므로 주기적으로 D1 을 봐야 한다.
- 같은 날 **여러 세션이 같은 지시를 나눠 받은** 탓에 main 이 하루에 수십 번 움직였고,
  `adm-core.js` 캐시번호가 v=104 → v=120 까지 밀리며 병합 충돌을 반복했다.
  충돌 해소 관례(번호만 새로 딴다·원장은 양쪽 다 남긴다)는 CLAUDE.md 2장 「원장」
  함정 항목 그대로 통했다.
- CLAUDE.md 1-3 «되살리면 안 되는 것» 에 이번 결정 전체가 한 항목으로 들어가 있다.
