## 1. 왜 했나

**제보** — 「`시스템 > 조직 관리 > 본사 관리` 에 본사 정보가 등록되어 있지 않다.
기존 홈페이지에 등록된 것처럼 본사 정보를 등록해 달라.」

들여다보니 **못 넣은 게 아니라 넣을 자리가 동작하지 않았습니다.**
화면(`#hq-table`)은 2026-08-08 부터 있었지만 **그 표를 채우는 JS 가 저장소에 0곳**이라
열 때마다 "데이터 없음" 만 나왔고, 그래서 하위항목 자체가 `display:none` 으로 감춰져
있었습니다. 조직 순서가 🏯 본사 › 🏢 지사 › 🏪 대리점(학원) 인데 **맨 위 한 칸만 비어 있던** 셈입니다.

## 3. 검토했다가 버린 방법 — 여기가 가장 중요합니다

### 🚫 경로를 `/api/admin/stats/hq-orgs` 로 얹기

새 `/api` 경로는 **세 관문**(index.ts 라우팅·index.ts 인증·api-mango.ts 전달)을 다 통과해야
하는데 `src/index.ts` 는 공동 금지구역입니다. 그래서 «이미 셋 다 열려 있는 접두사»인
`/api/admin/stats/` 밑에 얹는 선례가 있었습니다(`admin_new_apis_harness.mjs` 주석).

**버린 이유:** `/api/admin/stats/` 는 `TEACHER_BLOCKED_PREFIXES` 에 **없습니다.**
사업자등록번호·대표이사는 회사 법인정보인데 그러면 **강사에게 그대로 열립니다.**
`/api/admin/org/hq` 로 잡으면 `'/api/admin/org'` 가 이미 차단목록에 있어 **자동으로 닫힙니다.**
→ index.ts 에 **추가만** 하는 2줄을 택하고, 병합 전 사장님 확인을 받았습니다.

### 🚫 시드값을 매 배포마다 덮어쓰기

`hq-profile.ts` 를 «정본» 으로 삼아 부팅 때마다 UPSERT 하면 푸터와 절대 갈라지지 않습니다.
**버린 이유:** 그러면 **관리자 화면에서 고친 값이 다음 배포에 조용히 되돌아갑니다.**
`centers.franchise_id` 가 카페24 동기화에 매일 밤 덮어써지는 것과 같은 사고입니다
(CLAUDE.md 2장). → 「비었을 때 1회」만 심고, 갈라짐은 **하니스로 감시**합니다.

### 🚫 표 컬럼을 9개로 늘리기

요구된 컬럼은 7개(ID·본사명·대표이사·사업자번호·주소·대표전화·액션)인데 푸터에는 8항목이
있습니다. 컬럼을 늘리면 요구와 달라지고 표가 더 넓어집니다.
→ **7칸은 그대로 두고 `ⓘ` 상세 줄**을 펴서 나머지를 보여 줍니다. 저장은 다 합니다.

### 🚫 `hidden` 속성으로 취소 버튼 감추기

**버린 이유:** 작성자 CSS 가 `display` 를 정하면 브라우저 기본 `[hidden]{display:none}` 을
이깁니다(CLAUDE.md 2장, `teacher.html .btn` 건). → `style.display` 로 토글합니다.

### 🚫 자동 목록필터를 살리고 전용 검색창을 빼기 (#274)

**버린 이유:** 자동 필터는 «화면에 있는 행»만 거릅니다. 본사가 여러 건이 되면 서버 검색이
필요하고, 무엇보다 2026-08-08 에 대리점(학원)에서 **똑같은 이유로 반대 방향(자동필터 제거)**
을 택한 선례가 코드에 적혀 있었습니다. → 같은 해법을 따랐습니다.

### 🚫 학생관리 표의 컬럼을 줄이거나 `table-layout:fixed` 로 누르기 (#293)

**버린 이유:** 컬럼 17개는 다 쓰는 정보이고, 누르면 글자가 잘립니다.
원인은 표가 아니라 **조상 grid 칸이 줄어들지 못하는 것**이었습니다. → 원인을 고쳤습니다.

## 4. 어떻게 확인했나

### 화면을 «실제로» 렌더해서 봤습니다

작업 환경 프록시가 `mangoi.ai` 를 막아 배포된 화면을 볼 수 없습니다(CLAUDE.md 4-1-1).
그래서 **로컬에 `public/` 을 그대로 서빙하는 서버**를 띄우고 `/api/admin/org/hq` 만 시드값으로
응답하게 한 뒤, 컨테이너에 이미 있는 크로미움(`/opt/pw-browsers/chromium-1194`)으로
`admin.html` 을 열었습니다. **목업이 아니라 배포된 그 파일들**입니다.

이 방법으로 **두 개의 버그를 눈으로 찾았습니다** — 검색창 중복(#274), 학생관리 가로 넘침(#293).
둘 다 타입체크·하니스·CI 를 전부 통과한 상태였습니다. **「CI 통과 ≠ 화면이 맞다」의 실례입니다.**

메뉴 카드 **86개를 전부 열어** 훑은 결과:

| 항목 | 결과 |
|---|---|
| 가로 넘침 | 학생관리 1건 → 수리 |
| 검색창 중복 | 본사 관리 1건 → 수리 |
| 시연용 껍데기 `alert` | 0건 |
| 배선 없는 껍데기 카드 | 0건 |
| 차트 래퍼 누락 | 0건 |

⚠️ JS 오류 3건(통합 대시보드·강사관리·녹화관리)이 잡혔지만 **가짜 API 응답 탓으로 보여
버그로 단정하지 않았습니다.** 진짜 서버 응답으로 재현하지 못했습니다 — 남은 숙제입니다.
