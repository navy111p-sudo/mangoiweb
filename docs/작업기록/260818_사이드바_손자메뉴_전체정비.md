# 사이드바 손자 메뉴 — 지어낸 이름을 버리고 83칸 전부에서 진짜 목적지로

- 날짜: 2026-08-18
- 관련 PR: #270, #273, #281, #285
- 건드린 곳: `public/admin.html`, `public/js/adm-r25.js`, `public/js/adm-core.js`,
  `test-harness/admin_grandchild_menu_harness.mjs`, `CLAUDE.md`

---

## 1. 왜 했나

사장님 제보 두 개가 같은 뿌리였습니다.

1. 「**손자 메뉴가 보이는 것과 안 보이는 것이 섞여 헷갈린다**」
2. 「자식까지만 보이니 **자꾸 메인 화면을 뒤져야 해서 불편하다**」

세어 보니 자식 82칸 중 68칸에 ▸ 가 붙어 있었는데,
**그중 진짜 목적지를 가진 건 「학생 명부」와 「레벨테스트」 둘뿐**이었습니다.

나머지 66칸의 손자는 `adm-r25.js` 의 MAP 이 **스스로 「데모 매핑」이라고 적어 둔,
손으로 지어낸 이름 4개씩**이었습니다. 누르면 「카드 안 N번째 `details`」로 가는
방식인데, 그런 칸이 **0개인 카드가 63개**라 무엇을 눌러도 카드 전체가 한 번
반짝이고 끝났습니다. **에러가 안 나서 죽은 줄도 몰랐습니다.**

실제 사고: 「학생 명부 ▸ 2 학생 상세 프로필」을 누르면 **「⏰ 만료 임박 학생」**이
열렸습니다(이름과 실제가 완전히 다른 칸).

## 2. 검토했다가 버린 방법 ← 가장 중요

### ⛔ (A) 「안 보이는 14칸을 마저 지어 넣기」 — 처음 요청 그대로의 해석

가장 빠르지만 **지금보다 나쁩니다.** 82칸 전부에 ▸ 가 붙어 겉보기 일관성은
생기지만, 그중 80칸이 「눌러도 아무 데도 안 가는」 메뉴가 됩니다.
「▸ 가 있으면 안에 뭐가 있다」는 규칙을 **사장님이 믿을 수 없게 되는 것**이
진짜 손해라고 보고, 사장님께 이 판단을 먼저 말씀드리고 방향을 바꿨습니다.

### ⛔ (B) 「진짜 칸이 없는 카드는 ▸ 를 없애고 «화면 하나» 규칙으로 통일」

정직하고 하루면 끝나지만, 손자가 보이는 메뉴가 오히려 **68 → 17로 줄어듭니다.**
사장님이 「전부 보이게」를 명시적으로 고르셔서 채택하지 않았습니다.

### ⛔ (C) 손자 목록을 딴 파일(JS)에 표로 적기

옛 MAP 이 바로 이 방식이었고, **카드 구조가 바뀌면 아무 소리 없이 어긋납니다.**
같은 함정을 다시 파는 것이라 버렸습니다.

### ⛔ (D) 카드 안 블록을 「N번째」로 가리키기

「위치로 찾아감」은 이번 사고의 원인 그 자체입니다. 절대 금지.

### ⛔ (E) 헤드리스 크로미움 스크린샷으로 화면 확인

`--window-size=390` 으로 찍으면 **500px 로 레이아웃한 것을 390px 로 잘라** 저장해서
멀쩡한 화면도 잘린 것처럼 보입니다. 눈대중 대신 **DOM 을 재는** 방식으로 바꿨습니다.

### ✅ 채택 — 「화면에서 읽는다 + 그 구역에 이름표를 단다」

- 카드 안에 **진짜 접이칸(`details.sub-item` / `.sub-menu > details`)이 있으면
  그 `summary` 글자를 그대로** 손자 이름으로 씁니다 → 이름이 어긋날 수가 없습니다
- 접이칸이 아닌 구역은 **그 구역 자체에 `data-gc="이름"` 이름표**를 답니다
  (목록을 딴 파일에 적지 않는 이유가 위 (C))
- 목적지는 문자열 id 가 아니라 **DOM 참조** → 같은 id 가 두 벌 있어도
  (`sub-popup-list` 가 실제로 그랬습니다) 정확히 그 칸으로 갑니다

# 2부 — 「결제가 안 뜬다」 (같은 날 오후, 사장님 재제보)

## 왜 1부 검증을 다 통과했는데도 화면은 그대로였나

사장님이 보내 주신 스크린샷(7그룹 · 숫자 배지 · 「직원·권한」)이 아니었으면 못 찾았을 것입니다.

## 실제로 고장나 있던 네 가지 (전부 실측)

1. **묶음 항목의 손자가 «첫 카드» 에서만 나옴** — IA6 는 항목 하나가 카드를 여러 장 맡는데

## 검토했다가 버린 방법 (2부)

### ⛔ 높이 상한 숫자를 키운다 (600 → 1400 등)
가장 쉽지만, 그 CSS 주석이 이미 경고하고 있습니다 — **상한이 클수록 닫을 때 «반응 없는 시간»
이 길어지고**, 메뉴가 하나만 늘어도 또 넘칩니다. **열 때만 실제 내용 높이를 넣는** 방식으로 갔습니다.

### ⛔ 「전부 보이게」를 그대로 밀어붙인다
1부 방식(카드 안 칸까지 전부 손자)으로 IA6 에 적용하면 **256줄**이 되고,
그중 상당수가 중복이었습니다 — 같은 카드를 가리키는 항목 5개, 「회계」와 「매출 대시보드」의
손자 19줄이 글자까지 동일, 「자료실」은 «잠금 해제/자료 목록» ×5.
사장님께 계획서로 세 가지 안을 드리고 **1안**을 받았습니다.

### ⛔ 「조직 (지사·대리점)」 항목만 지운다
중복은 사라지지만 그 카드의 네 번째 칸 **「본사 관리」로 갈 길이 함께 사라집니다.**
그래서 그 칸을 항목으로 세웠습니다.

### ⛔ 「매출 대시보드」 항목을 그냥 둔다
2026-08-18 에 «사이드바에서 바로» 라는 요청(#283)으로 추가된 항목이라 지우기가 망설여졌지만,
사장님이 「회계」로 통일하라고 하셨고 **「회계 ▸ 📊 매출 대시보드」 손자 한 줄이 그 역할을 그대로**
합니다. 기능은 안 없앴습니다.

## 중복의 진짜 원인 — `openSub` 를 안 본 것

IA6 항목에는 이미 `openSub`(카드 «안의 한 칸» 을 바로 여는 id)가 있었습니다.
「대표지사」=`card-master-branches`, 「지사」=`sub-branches`, 「대리점」=`card-centers`.
그런데 **그 값이 DOM 에 실려 있지 않아** 손자 생성기가 셋 다 «카드 전체» 를 읽었고,
그래서 똑같은 4줄이 네 번 나왔습니다.
→ `data-ia6-sub` 로 실어 주고, 그게 있으면 **«잎» 으로 보고 손자를 만들지 않습니다.**

## 검토했다가 버린 방법 (3부)

### ⛔ 구성표를 손으로 고쳐서 맞춘다
40건을 손으로 고치면 그 순간은 맞지만 **다음 메뉴 변경 때 또 어긋난다.**
애초에 이 문서가 「메뉴 코드에서 자동으로 뽑습니다」라고 적어 놓고
실제로는 손으로 옮겨 적은 스냅샷이라 이 사달이 났다.
→ 실제 사이드바를 브라우저로 띄워 `.ph85-group[data-ia6]` 를 훑어 **다시 뽑았다.**

### ⛔ 「자동으로 뽑습니다」라는 설명을 그대로 둔다
문서가 스스로를 잘못 설명하고 있었다. 읽는 사람이 «그럼 안 고쳐도 되겠네» 라고 믿는다.
→ 「그대로 뽑아 **적습니다**」로 고쳤다. 사람이 하는 일임을 분명히.

### ⛔ 진단용 페이지까지 지도에 다 넣는다
`signaling`·`turn-relay`·`video-call` 은 어디서도 링크되지 않고 API 호출이 없다
(video-call 은 11KB 에 raw WebSocket 한 줄). 지도에 넣으면 «쓰는 화면» 으로 오해된다.
→ 하니스 ALLOW 에 **근거를 적어** 제외했다. 근거를 안 적으면 다음 사람이 또 고민한다.

### ⛔ /docs/ 자료실을 한 갈래에만 넣는다
같은 주소인데 **학생·학부모는 바로 받고 강사용은 비밀번호**가 필요하다.
「누가 쓰는가」 지도에서는 양쪽에 있는 것이 사실에 맞다. → 학생·선생님 두 곳에 넣었다.
