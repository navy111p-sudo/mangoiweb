## 1. 왜 했나

전국 지사·학원을 도는 본사 영업이사(김성훈, 현재 1명)의 활동이 **어디에도 기록되지 않았다.**
강사는 수업이 자동 기록돼 인사평가(teacher_evaluations)가 돌지만, 영업은 차를 타고 나가면 기록이 0이었다.

- 열심히 해도 계약이 없으면 「논 것」처럼 보임
- 방문이 적어서인지 상담이 약해서인지 구분 불가(처방이 정반대인데)
- 사람이 나가면 거래처 정보가 통째로 사라짐

사장님이 근무조건(차량·4대보험·기본급·상여·퇴직금)을 주시며 실적·평가·보상 체계화를 지시.
추가 지시: 이사는 하루 종일 운전 → **타이핑 없이 휴대폰으로**, 문구는 15세 수준.

- 담당자 본인은 계약·유지확인을 못 쓴다(자기 실적 숫자 입력 금지 — 서버 403)

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **상대평가·등급 강제배분** → 버림. 담당자 1명이라 비교 대상이 없다. 목표치 + 지난 반기의 자기 자신과만 비교.
- **성과급 환수(clawback)** → 버림. 임금성 금품 회수는 분쟁 소지. 처음부터 절반만 주고 유지 확인 후 잔여 지급으로 같은 효과.
- **유지 확인을 사람 버튼으로만** → 처음엔 그렇게 만들었다가 버림. 사장님이 바쁜 달엔 담당자 월급이 밀린다. 자동 판정 + 애매한 것만 사람에게.
  - 같이 고친 버그: 확인 전(NULL) 계약이 유지율 분모에 들어가 자동 실패로 계산되던 것. 판정 끝난 건만 분모에.
- **방문 우선순위를 LLM 으로** → 버림. 「왜 이 순서인지」를 설명 못 하면 아무도 안 따른다. 규칙 점수 + 근거 한 줄.
- **보고서 문장을 LLM 으로** → 숫자는 서버가 세고 문장은 규칙 조립. 그럴듯하게 틀린 보고서는 없는 것보다 나쁘다.
- **휴대폰 화면 = 사무실 화면 반응형** → 버림. 쓰는 상황이 다르다(운전 중·나쁜 회선). /sales 를 따로: 방문 기록 1탭, 말로 기록 3탭, 첫 화면 API 1회(/api/admin/sales/mobile), work.html 의 outbox 패턴으로 끊겨도 잃지 않음.
- **공정성 감시가 점수를 자동 보정** → 버림. 고치는 순간 «점수 부풀리기» 가 된다. 사장님께 이의 제기만.
- **AI 일지 정리에서 학원 이름 자유 생성** → 버림. 후보 학원 목록 안에서만 매칭, 없으면 unknown_lead 로 「먼저 등록하세요」.
