## 1. 왜 했나

**시작은 사장님 지시 한 줄이었습니다.**

> 「시스템 > 조직 관리(본사·지사)」 화면의 **「지사(구)」 섹션은 데이터도 없고 더 이상 필요 없어. 없애줘.**

그런데 코드를 열어 보니 그 섹션은 **이미 2026-08-08 에 `style="display:none"` 으로 감춰 둔 상태**였습니다.
「지워버리면 되살리기 어려우니 감춰만 두자」고 판단한 흔적이 주석에 남아 있었습니다.

**즉 「감췄다는데 사장님 화면에는 보인다」** — 이 모순이 이번 작업의 진짜 출발점입니다.

지우고 배포한 뒤 사장님이 보내 주신 **실제 화면 캡처**에서 결정적 단서가 나왔습니다.
「지사(구)」뿐 아니라 **대표지사·영업본부·본사 관리·독립 사이트까지 전부 보이고 있었습니다.**
이것들은 모두 `display:none` 이 걸린 «숨긴» 항목들입니다.

→ 숨김 자체가 안 먹고 있다는 뜻이고, 그렇다면 **역할별 메뉴 숨김도 같이 안 먹고 있을 것**이라는
추론으로 이어졌습니다. 전수 조사 결과 그 추론이 맞았습니다.

## 2. 무엇을 바꿨나

### 원인 (한 줄)

`cloudflare-deploy/public/css/admin-inline-c.css` 의 **PC 전용 복구 규칙**입니다.

```css
@media (min-width: 1024px) {
  #legacy-cards,
  #legacy-cards .table-card,
  #legacy-cards .menu-card,
  #legacy-cards details { display: block !important; visibility: visible !important; }
}
```

관리자 카드는 전부 `#legacy-cards` 안에 있습니다.
**작성자 `!important` 는 인라인 스타일을 이깁니다**(특정성 문제가 아니라 우선순위 단계 문제).
그래서 `style="display:none"` 도, `hidden` 속성도, `el.style.display='none'` 도 **전부 무시**됩니다.

⚠️ **휴대폰(<1024px)에서는 규칙이 안 켜져 정상 동작합니다.** 모바일로 확인하면 멀쩡해 보입니다 —
이것이 2026-08-08 부터 열흘간 발견되지 않은 이유입니다.

### 바꾼 파일

| 파일 | 무엇을 |
|---|---|
| `cloudflare-deploy/public/admin.html` | 조직 관리 카드에서 껍데기 하위 섹션 5개 제거(지사(구)·대표지사·독립 사이트·종전금 내역·포인트 내역). `?v=` 갱신 |
| `cloudflare-deploy/public/css/admin-inline-c.css` | **`.rbac-hide` 규칙 신설** — 복구 규칙 뒤, **미디어쿼리 밖** |
| `cloudflare-deploy/public/js/adm-core.js` | 숨김을 인라인 → 클래스로. `mangoi:menu-visibility` 이벤트 발신 |
| `cloudflare-deploy/public/js/adm-ia6.js` | 사이드바 항목 역할 필터(`applyRoleFilter`) 추가 |
| `cloudflare-deploy/public/js/adm-quickmenu.js` · `adm-quick-access.js` · `adm-p1.js` | 「숨김인가」 판정을 클래스 기준으로 |
| `CLAUDE.md` | 2장 함정 표에 이 함정 등재 |

### `.rbac-hide` 는 「붙이는 쪽 ↔ 읽는 쪽」이 짝입니다

**한쪽만 고치면 「사이드바엔 없는데 본문엔 있는」 불일치가 납니다.**

| 역할 | 위치 |
|---|---|
| 붙임 | `adm-core.js` — `_applyMenuVisibility()` · `_applyPayrollTeacherUI()` |
| 읽음 | `adm-core.js` — `buildMenuIndex()` · 메뉴 검색색인<br>`adm-quickmenu.js` — `visible()`<br>`adm-quick-access.js` — `roleHidden()`<br>`adm-p1.js` — `memberVisible()` · 검색색인<br>`adm-ia6.js` — `applyRoleFilter()` |

읽는 쪽은 **옛 인라인 방식도 계속 인정**하게 뒀습니다. 어딘가 옛 코드가 남아 있어도 계속 걸러집니다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### ⛔ 버린 안 ① — 문제의 복구 규칙에서 `details` 를 빼거나 규칙을 지운다

가장 먼저 떠오르는 «한 줄 수정»이고, 실제로 유혹이 컸습니다. **하지만 하면 안 됩니다.**

그 규칙은 실수로 들어간 것이 아니라 **사고의 복구책**입니다. 예전에 `ph87` 이 PC 에서
`#legacy-cards` 를 통째로 숨겨 **「메뉴를 눌러도 카드가 안 보인다」** 사고가 났고,
그것을 되살리려고 넣은 것입니다(CSS 주석에 경위가 남아 있습니다).

지우면 **그 사고가 그대로 재발**합니다. 게다가 사고 반경이 관리자 화면 전체입니다.

→ **복구 규칙은 건드리지 않고**, 그보다 특정성이 높은 전용 클래스를 새로 파는 쪽을 택했습니다.

### ⛔ 버린 안 ② — `.rbac-hide` 규칙을 `@media (min-width:1024px)` **안**에 넣는다

문제가 PC 에서만 나므로 자연스러워 보이지만, 이러면 **휴대폰에서 숨김이 통째로 사라집니다.**
JS 가 더 이상 인라인 `display:none` 을 쓰지 않게 됐으니, 모바일에는 아무 숨김 수단이 없어집니다.

→ **미디어쿼리 밖**에 두었습니다. 선택자를 세 벌 쓴 이유도 여기 있습니다:

- `#legacy-cards details.rbac-hide` (0,1,1,1) — 복구 규칙 (0,1,0,1)을 **특정성으로** 이김
- `#legacy-cards .rbac-hide` (0,1,1,0) — `.menu-card` 규칙과 동률이라 **소스 순서로** 이김
- `.rbac-hide` — `#legacy-cards` **밖** 카드 14개 + 모바일 담당

### ⛔ 버린 안 ③ — 사이드바 항목 숨김에 기존 `.ia6-hide` 를 재사용

이름도 목적도 비슷해 보여서 처음엔 이걸 쓰려 했습니다. **치명적입니다.**

`.ia6-hide` 는 **카드**를 감추는 `showOnly`(항목을 누르면 관련 카드만 보이기) 전용이고,
`showOnly` 가 실행될 때마다 `managed` 전체에서 그 클래스를 **벗겨 냅니다.**
같은 이름을 쓰면 **항목을 한 번 클릭하는 순간 숨김이 통째로 풀립니다.**

→ 전용 클래스 `.ia6-role-hide` 를 새로 팠고, **브라우저에서 클릭 후에도 유지되는지 실제로 확인**했습니다.

### ⛔ 버린 안 ④ — 사이드바 필터를 `setInterval` 로 주기 실행

가장 쉬운 「항상 최신 상태 유지」 방법이지만, 이 파일에는 **사이드바를 1.5초마다 훑어 스크롤이
뚝뚝 끊겼던 전례**가 주석으로 남아 있습니다(강사 피드백 「스크롤이 부드럽지 않다」).

→ **그린 직후 + `adm-core` 가 쏘는 이벤트 + 지연 2회**로 대체했습니다.
이벤트를 쓴 이유는 **역할 적용과 사이드바 그리기의 순서가 정해져 있지 않아서**입니다
(어느 쪽이 먼저일지 모르므로 양쪽에서 걸어야 합니다).

### ⛔ 버린 안 ⑤ — 사이드바 항목의 `data-card`(대표 카드 한 장)로 판정

이미 있는 속성이라 그냥 쓰면 편했지만, **대표 카드는 열려 있고 나머지는 다 막힌** 경우를
판정할 수 없습니다.

→ 항목이 가리키는 카드 **전부**를 `data-cards` 에 새로 남기고, **전부 감춰졌을 때만** 항목을 감춥니다.

⚠️ **DOM 에 없는 카드 id 는 「판단 보류」로 세지 않습니다.** 목록에 오래된 id 가 섞여 있을 수 있는데,
그것 하나 때문에 **멀쩡한 메뉴가 사라지는 쪽이 훨씬 큰 사고**입니다. 하나도 못 찾으면 남깁니다.

## 4. 확인한 방법

### 실제 브라우저 재현 (Chromium)

프록시 때문에 배포된 사이트를 열 수 없어, **실제 CSS·JS 파일을 그대로 불러온 시험 페이지**를
Chromium 으로 띄워 `getComputedStyle` 값을 측정했습니다. 추측이 아닙니다.

**수리 전 — 문제 재현**

| 숨기려던 대상 | PC (1440px) | 모바일 (390px) |
|---|---|---|
| `details.menu-card` + `display:none` | **보임** (block) | 안 보임 |
| `details` + `hidden` 속성 | **보임** (block) | 안 보임 |
| 일반 `<div>` + `display:none` | 안 보임 | 안 보임 |

**수리 후 — `.rbac-hide`**

| 대상 | PC | 모바일 |
|---|---|---|
| `.rbac-hide` 붙인 카드 / 하위항목 | `none` ✅ | `none` ✅ |
| 허용된 카드(클래스 없음) | `block` ✅ | `block` ✅ |
| `#legacy-cards` 밖 + `.rbac-hide` | `none` ✅ | `none` ✅ |

**사이드바 필터 — `adm-ia6.js` 를 실제로 실행해서**

| 시나리오 | 결과 |
|---|---|
| 카드가 전부 감춰진 항목(「데이터·보관」) → 항목 감춰짐 | ✅ |
| 카드가 열려 있는 항목(「오늘의 수업」) → 항목 남음 | ✅ |
| **평상시(아무것도 안 감춘 상태) → 감춰진 항목 0개** | ✅ |
| **항목 클릭(`showOnly`) 후 → 감춤 유지** | ✅ |

마지막 둘은 「멀쩡한 메뉴를 지우지 않는가」와 「클래스 충돌은 없는가」를 보는 회귀 검사입니다.

- ⚠️ **모바일로 확인하면 멀쩡해 보입니다.** 이 계열 문제는 반드시 **PC 폭(≥1024px)** 에서 보세요.

### 별건으로 남은 것 (이번에 손대지 않음)

`trap-check` 가 지적한, **이번 변경으로 생긴 것이 아닌** 기존 문제들입니다.

1. **판정 계층이 셋입니다** — ① `CARD_POLICY`→`.rbac-hide`(이번 수리) ② `adm-q10.js` PERMS→
   `.ph118-card-hidden` ③ ia6→`.ia6-hide`. ②의 `ph118-card-hidden` 은 검색·바로가기 어디서도
   읽지 않아, **PERMS 로 감춘 카드가 검색·바로가기에는 계속 나옵니다.**
2. **`adm-core.js` 의 `MENU_ALIASES` 검사는 조상을 안 봅니다** — 카드가 아닌 하위 `details` 를
   가리키는 별칭은 부모 카드가 감춰져도 검색에 남습니다. 조상을 훑는 것은 `roleHidden()` 뿐입니다.
3. **`admin.html` 의 `ph126Enforce`** 가 `card-retention`·`card-active-rooms` 를 주기적으로 강제
   표시하는데 `.rbac-hide` 는 벗기지 않습니다 → 이제 RBAC 가 이깁니다(정책상으로는 맞는 동작).

### 배포에 대해 알아둘 것

배포 워크플로는 `cancel-in-progress: false` 라, **병합이 몰리면 대기 중이던 배포가 취소**됩니다.
실제로 PR #264 의 배포 실행이 취소됐습니다. **사고가 아닙니다** — 배포는 「그 커밋」이 아니라
**저장소 현재 상태 전체**를 올리므로, 그 뒤 실행이 성공하면 함께 반영됩니다.
「내 PR 배포가 취소됐다」고 보이면 **그 뒤 배포가 성공했는지**를 확인하세요.
