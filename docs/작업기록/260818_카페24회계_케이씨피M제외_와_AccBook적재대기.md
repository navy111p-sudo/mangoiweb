# 카페24 회계 실데이터 — 「케이씨피M」 제외 작업과, 그 과정에서 드러난 «AccBook 0건»

- 브랜치 / PR: `claude/cafe24-accounting-screen-iddxpg` / PR #234(제외 로직) → PR #282(빈 화면 안내 + 적재 요청서)

## 1. 왜 했나

15장짜리 수정사항 프롬프트 블럭 5번 항목: «카페24 회계 실데이터 화면의 매출 집계에
「케이씨피M」이 섞여 있으니 제외하고, 「케이씨피」만 매출로 세라».
「케이씨피M」 = 하나은행 → 신한 운영자금 이체(매출 아님, 2026-08-17 사장님 확인).

## 2. 무엇을 바꿨나

- `src/accounting-reports.ts` — 판정 정본 `KCP_TRANSFER_CYPHER_RE`(Cypher/Java용) +
  `isKcpTransferRow()`. 통장용 `classifyDeposit()` 바로 옆에 뒀다(같은 함정의 두 얼굴이라).
- `src/api-admin.ts` `/api/admin/finance-cafe24/summary` — income·expense 양쪽에서 제외,
  뺀 금액·건수를 `excluded_transfer`/`excluded_count`/`excluded` 로 동봉.
- `src/api-admin.ts` `/api/admin/finance-cafe24/ledger` — 행마다 `excluded_from_revenue`.
- `public/js/adm-core.js` — 합계에서 제외 + 제외 안내(#c24fin-sum-total). 이후 별도 지시로
  표의 «매출 제외» 배지·취소선은 제거됨(다른 세션 작업 — 합계 제외 계산은 유지).
  마지막으로 빈 화면일 때 «카페24 쪽 적재 대기(연결은 정상)» 안내로 교체.
- `test-harness/c24_finance_kcpm_harness.mjs` — 신설. TS/Cypher 정규식 불일치·규칙 복사를 FAIL.
- `docs/카페24_회계데이터_적재요청_2026-08-18.md` — 서버 담당자용 적재 요청서.
- `CLAUDE.md` 2장 — 함정 행 추가·갱신.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **화면(JS)에서 문자열 판정** → 버림. 판정 규칙이 서버·화면 두 곳으로 복사되면 반드시
  갈라진다. 서버가 `excluded_from_revenue` 로 내려주고 화면은 그 값만 쓴다.
- **Neo4j 쿼리에 정규식을 하드코딩** → 버림. TS 쪽 정본과 어긋나도 아무도 모른다.
  문자열 상수로 export 해 파라미터로 넘기고, 하니스가 두 정규식의 본문 일치를 검사한다.
- **`LIKE '%케이씨피%'` 식 부분일치** → 처음부터 배제. 2026-08-16 대사 오진(4,632만원)의
  원인이 정확히 이것. `M` 뒤 단어경계(`\b`)를 요구해 「케이씨피MONEY」류 오탐도 막았다.
- **「케이씨피M」 행을 ledger 응답에서 아예 빼기** → 이 세션에서는 안 했다(원본 보존 원칙).
  ⚠️ 단, 병렬 세션 PR #278 이 «이름·금액이 API 주소로 그대로 보인다»는 이유로 숨기는
  방향을 진행 중 — 최종 상태는 그쪽 병합 결과를 볼 것.

## 4. 확인한 방법

- `tsc --noEmit` 통과, `node test-harness/run.mjs --fast` PASS 165→170 / FAIL 0 (시점별).
- 로컬 Chromium(playwright)으로 배포본 JS 를 떼어 렌더링 확인 — 제외 안내·배지가 실제로
  그려지는 스크린샷 확보. 빈 데이터 상황도 같은 방식으로 확인.
- **실데이터 확인** — D1 `bankacct_transactions`: 「케이씨피M」 17건 ₩51,316,575
  (hex 로 ASCII `M`(4D) 확인). 사장님 브라우저로 API 직접 조회:
  `/finance-cafe24/ledger` `count: 0`, `/summary` `months: []`, `/books/graph-list` 62건.

## 5. 남은 것 / 주의할 것

- **핵심 반전: 원 요청의 전제가 실제와 달랐다.** 「케이씨피M」은 이 화면이 보는
  Neo4j `AccBook` 에 한 건도 없고 **통장(D1)에만** 있다. #234 의 제외 로직은 현재
  **걸릴 대상이 0건**이라 화면 숫자를 바꾸지 않는다. AccBook 이 적재되는 순간부터 동작한다.
- **AccBook 자체가 0건** — 연결은 정상(Book 62건 조회됨), 적재는 카페24 서버 쪽 작업.
  `docs/카페24_회계데이터_적재요청_2026-08-18.md` 를 담당자에게 전달해야 진짜 해결.
- 교훈: **화면 수정 요청은 «그 화면에 그 데이터가 실제로 있는지» 부터 확인할 것.**
  이번엔 프록시가 실서비스를 막아 확인 없이 배포부터 했고, 헛일이 됐다.
  실서비스는 못 봐도 ① D1 은 MCP 로 SELECT 가능 ② 배포본 JS 를 떼어 로컬 Chromium 으로
  렌더링 확인 가능 ③ 사장님께 API 주소를 드려 JSON 을 직접 보시게 할 수 있다 — 셋 다 이번에 실제로 통했다.
