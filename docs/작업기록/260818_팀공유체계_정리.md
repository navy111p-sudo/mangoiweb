## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### 3-1. `.mcp.json` 을 저장소에 넣기 → 버림

노션·드라이브·깃허브 연결을 저장소에 적어 두면 팀원이 바로 쓸 것 같았지만,
**이 연결은 각자 클로드 계정에 로그인해 붙이는 방식**입니다. 저장소에 적어도
남의 계정에서는 안 붙고, 자격증명을 넣는 순간 사고입니다. → 각자 `/mcp` 로.

### 3-2. 대화 기록을 「공유되게」 만들기 → 불가능

팀 요금제로 묶어도 서로의 대화는 보이지 않습니다. 그래서 **공유 자체를 포기하고,
판단만 문서로 옮기는 경로**(`/worklog`)를 만들었습니다.
⛔ 대화 전문을 복붙하는 방식은 일부러 안 했습니다 — 남길 가치가 있는 건 판단뿐입니다.

### 3-3. npm 설치 실패를 「설치 시점에」 알리기 → **셋 다 실패, 방향 전환**

새 PC 에서 `npm ci` 가 `ERESOLVE / peerOptional workers-types` 로 죽습니다.
원인은 라이브러리가 아니라 **Node 버전**입니다(npm 11 은 통과, npm 10 은 막음).
설치 단계에서 그 사실을 알려 주려고 Node 22 에서 실제로 세 가지를 시험했습니다.

| 시도 | 결과 |
|---|---|
| `package.json` 의 `engines` | ❌ ERESOLVE 가 먼저 터짐 |
| `.npmrc` 의 `engine-strict=true` | ❌ 마찬가지 |
| `preinstall` 스크립트 | ❌ 마찬가지 |

**npm 은 항상 의존성 해석을 먼저 합니다.** 그래서 설치를 막는 방식을 버리고
**사람이 먼저 보는 자리**(`.nvmrc` · 직원용 안내 3-3절 · `CLAUDE.md` 함정 표)에
원인을 적었습니다. `engines` 는 효과가 없지만 요구 버전의 정본 자리라 남겼습니다.

⛔ **`wrangler` 를 4로 올려 충돌을 없애는 것은 안 했습니다** — 배포 도구를 바꾸는
일이라 배포 담당 판단 사항이고, 지금 CI·배포는 정상입니다.

### 3-4. 구글 드라이브에 문서 올리기 → 못 함, 대안으로 전환

사장님이 드라이브를 고르셨지만, 제가 올리려면 **파일 내용이 통째로 제 메모리를
거쳐야** 합니다. 대상이 22MB(가장 큰 pptx 하나가 13.8MB)라 불가능했습니다.
→ **HTML 원본이 있는 보고서 5건을 Artifact 로 발행**하는 쪽으로 바꿨습니다.
링크 하나로 열리고, 갱신하면 같은 주소가 유지되므로 드라이브보다 낫습니다.
(드라이브의 「망고아이」 폴더에 사람이 직접 끌어다 놓는 것이 가장 빠릅니다.)

### 3-5. A4 문서를 폰에서 「폭 맞춤」으로 축소 → 문서 성격에 따라 나눔

처음엔 A4 두 건 모두 `zoom` 으로 축소했는데, **마이마이 문서는 높이 고정이 없는
유동 문서**여서 축소하면 글자만 57% 로 작아지는 손해였습니다.
→ 고정 A4(회계)만 `zoom` 폭맞춤, 유동 문서는 `max-width:210mm` 종이 취급.
