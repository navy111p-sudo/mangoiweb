## 1. 왜 했나

필리핀 매니저·강사들이 새 강사 페이지와 참관 기능을 테스트하며 남긴 제보를 번역해 PDF로 만들었고,

가장 중요한 발견은 **제보 5건이 이미 구현돼 있었다**는 것이다.
다만 전부 «다른 화면»에 있었다 — 제보자가 쓰는 화면(`/manager`)에만 없었다.
「없다」는 제보를 받았을 때 **먼저 어느 화면을 보고 있는지 확인해야 한다**는 것을 다시 배웠다.

## 3. 검토했다가 버린 방법 ← 가장 중요

### 3-1. 매니저 화면에 강사 명부를 «옮겨» 오기 (버림)

`manager.html` 은 파일 머리말에 **설계 계약**이 적혀 있다 — 외부 리소스 0개, 첫 화면 API 2회,
차트 라이브러리 금지. 「admin.html(934KB·요청 145개)이 안 맞는 옷이라 만든 화면」이다.
강사 명부는 검색·필터·가동률·평가가 붙은 무거운 카드다. 옮기면 이 화면의 존재 이유가 사라진다.

**대신** 「강사 명부」 칩 하나를 두고 `/admin#card-teacher-mgmt` 로 보낸다. 본사(hq)일 때만 보인다.

### 3-2. 시계를 `mango-worldclock.js` 로 붙이기 (버림)

이미 있는 플로팅 시계 파일을 부르면 한 줄로 끝난다. 하지만 그게 **계약 1번(외부 리소스 0개)** 위반이다.
`Intl.DateTimeFormat` 은 브라우저 내장이라 추가 바이트가 0이다 → 직접 그렸다.

### 3-3. 강사 프로필을 망고아이에서 수정하게 하기 (버림)

제보 1-④ 원문에 「edit their information」이 있었다. 그런데 강사 명부는
`/api/admin/teachers/graph-list` → **Neo4j(카페24) 읽기 전용**이고 야간 cron 이 매일 덮어쓴다.
고쳐도 다음 날 원복된다 — `centers.franchise_id` 에서 이미 밟은 함정이다.
**정본 수정은 카페24에서 해야 한다.**

### 3-4. 참관자가 수업 중인 방에 교재를 직접 띄우게 하기 (버림)

제보 2-② 원문 요청 그대로다. 하지만 참관 기능의 설계 계약이
「학생·강사가 **모르게** 본다」(WebRTC join 알림 0, 참가자 목록에 안 들어감)이다.
참관자가 교재를 띄우면 강사는 **「내가 안 했는데 화면이 바뀌었다」** 를 겪는다. 유령이 물건을 옮기는 셈.

**대신** ⓐ 참관자가 라이브러리에 업로드(이미 관리자 권한으로 가능) ⓑ 귓속말로 「라이브러리에서 ○○ 여세요」.
정말 직접 조작이 필요하면 «참관»이 아니라 **«공동 진행(co-host)» 역할을 새로 만드는 별건 작업**이다.

### 3-5. 파닉스를 «다시 업로드»해서 분리하기 (버림)

라이브러리 묶음은 파일명 앞 `[대괄호]` **하나로만** 정해진다(`idx-x3.js _serverFilesToBooks`).
즉 재업로드가 필요 없다 — 이름만 바꾸면 그 자리에서 갈라진다.

> 🔴 **정정 (2026-08-20)** — 이 문단은 **이름에 유닛이 들어 있는 묶음에만** 맞는 말이었다.
> Phonics·BTS 2~34 의 실제 파일 이름은 `미분류 레슨 / Slide7.JPG` 로 유닛 정보가 **한 글자도 없고**,
> 업로드 순서까지 뒤엉켜 있으며, `unit_no`·`r2_key` 어디에도 원본 폴더명이 안 남았다.
> **그 묶음들은 재업로드 말고 길이 없다.** → [260820_강사제보문서_전체대조_와_교재페이지창.md](260820_강사제보문서_전체대조_와_교재페이지창.md) 3장
26개 묶음을 손으로 업로드하는 대신 **일괄 이름변경 API** 를 만들었다. BTS 유닛 분리도 같은 도구로 된다.

### 3-6. 004·007 교재를 실제로 삭제하기 (버림)

과거 수업 기록의 링크가 깨지고 R2 에서 지우면 되돌릴 수 없다.
8/11·8/13 에 「지우지 않고 안 보이게만 한다」로 이미 결정된 사안이다. 숨김 도구를 그대로 쓴다.

### 3-7. 귓속말 그리기 코드를 `idx-main.js` 에 넣기 (버림 — 하니스가 잡음)

처음엔 거기 넣었다. `first_paint_budget_harness` 가 **index.html blocking 예산 초과**로 FAIL 냈다.

## 8. 남은 운영 작업

### 8-1. 004 · 007 교재 숨기기 (배포 불필요)

관리자 → 교재 업로더(`/textbook-uploader.html`) → 「🙈 라이브러리에서 숨길 교재」 → 체크 → 저장.
즉시 반영되고, 체크를 풀면 바로 돌아온다. **파일은 지워지지 않는다.**

### 8-2. 파닉스 A~Z 분리

같은 화면의 「✏️ 교재 묶음 나누기 · 이름 바꾸기」에서:

1. 지금 묶음 이름 입력 (예: `Mangoi Phonics` — 대괄호 없이)
2. 방식 = **나누기 (슬래시 앞 칸을 묶음으로)**
3. **[👁 미리보기]** — 몇 건이 어떻게 바뀌는지, 몇 묶음으로 갈라지는지 확인
4. 맞으면 [✅ 적용]

⚠️ 미리보기를 안 하면 적용 버튼이 안 열린다. 조건을 한 글자라도 고치면 다시 잠긴다.
BTS 유닛 분리도 같은 방법이다.

### 8-3. 쌓인 중복 교재 정리 — ⛔ 아직 하지 않았다

**1단계(완료)** — 「🔍 교재 중복 진단」으로 지금 실제 숫자를 본다. 읽기 전용이라 안전하다.

**2단계(사람 판단 필요)** — 지우는 것은 **D1 DELETE + R2 삭제**다.
개발·운영이 같은 DB 이고 실제 학생 29,000명이 쓴다. CI 가 막아 주지 못한다.

정리를 진행한다면 이 순서를 지킬 것:

1. 진단 화면의 숫자를 **먼저 기록**한다 (묶음별 파일수·중복수·용량)
2. 삭제 대상 목록을 **JSON 으로 먼저 내보내 보관**한다 — 되돌릴 유일한 근거다
3. **D1 행만** 먼저 지운다. R2 오브젝트는 건드리지 않는다
   (행이 없으면 화면에서 안 보인다. 용량 회수는 그다음 문제이고, R2 삭제는 복구가 불가능하다)
4. 며칠 지켜본 뒤 문제가 없으면 R2 정리를 **별건으로** 판단한다
5. 한 묶음씩 한다. 전체를 한 번에 돌리지 않는다

⚠️ 판정 기준은 업로드 차단과 같은 `name + size_bytes` 다. 이름과 크기가 같아도
내용이 다를 가능성은 남는다 — 그래서 «지우기» 를 자동화하지 않았다.
