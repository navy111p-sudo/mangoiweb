## 2. 무엇을 확인했나 — 원인 후보를 하나씩 지웠다

### ④ 그런데 「참여자 1명」

참여자 수는 **Durable Object(방 서버)** 가 알려 주는 값이다(`idx-main.js` `updateUserCount`,
DO 의 `room-joined`·`user-joined`·`user-left` 메시지). 즉 **두 사람이 같은 DO 에 없었다.**

### ⑤ 뿌리 — 워커가 «두 벌» 이라 DO 네임스페이스가 갈린다

이 저장소는 워커를 두 벌 배포한다(`deploy.ps1` [6] 단계 · `deploy.yml` 1)2) 단계):

- `webrtc-unified-platform` (기본)
- `webrtc-unified-platform-prod` (운영)

그리고 `wrangler.toml` 이 **환경마다 `new_sqlite_classes = ["VideoCallRoom"]` 을 따로 선언**한다.
Durable Object 네임스페이스는 **스크립트마다** 만들어지므로,
`idFromName("class-849-20260819")` 이 워커마다 **완전히 다른 방**을 만든다.

화상수업 WebSocket 은 `` `${protocol}//${location.host}${path}` `` 로 붙으므로
(`public/js/idx-main.js` `createWebSocket`) **어느 도메인으로 열었느냐가 곧 어느 방이냐**가 된다.

- 강선생님 → `test.mangoi.co.kr` (당시 **기본** 워커)
- 사장님 → `mangoi.ai` (`-prod`)

**D1·KV·R2 는 두 환경이 같은 id 를 공유한다.** 그래서 `attendance`·`room_tokens` 에는

그리고 이것은 그날 하루의 사고가 아니었다. `class_no_show` 를 보니

## 4. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### ⛔ 버림 ①: `test.mangoi.co.kr` 을 `mangoi.ai` 로 리다이렉트

`www.mangoi.ai` 때 쓴 방법이라 제일 먼저 떠오른다. **그러나 여기엔 잃을 게 있다.**
오리진이 바뀌면 그 도메인으로 등록된 **패스키 6건이 무효화**되고(재등록 필요)
앱 사용자의 `localStorage` 로그인도 날아간다. CLAUDE.md 0장이 이미 ⛔ 로 못 박아 둔 항목이다.
→ **도메인을 옮기면 오리진이 그대로**라 아무것도 잃지 않는다. 이 차이가 결정적이었다.

### ⛔ 버림 ②: 강선생님에게 「`mangoi.ai` 로 들어오세요」 안내

작업 중에 사장님이 「`www.mangoi.ai` 로 들어오라고 할까?」 물으셨다. **두 가지가 틀리다.**
1. `www` 는 안내 주소가 아니다 — `src/index.ts` 가 apex 로 넘긴다. 정본은 `src/site-url.ts` 의 `SITE_ORIGIN`.
2. **애초에 옮길 필요가 없어졌다.** 도메인 이전으로 두 주소가 같은 방이 됐다.
   옮기면 오히려 패스키·로그인을 잃는다(위 ①과 같은 이유).

### ⛔ 버림 ③: WebSocket 접속 호스트를 한 워커로 고정

`createWebSocket` 이 `location.host` 를 쓰는 것을 `-prod` 호스트로 못 박으면 코드만으로 해결된다.
**버린 이유**: `public/index.html`·`idx-main.js` 는 **공동 금지구역**이고, 사고 반경이 전체 화상수업이다.
도메인 한 줄을 옮기면 되는 일을 코드로 우회하는 것은 뿌리를 그대로 두는 것이다.

### ⛔ 버림 ④: `wrangler.toml` 에 `routes` 를 적어 도메인을 «못 박기»

사장님이 명시적으로 요청하셨지만 **그대로 하면 서비스가 내려간다.**
Cloudflare 문서: 「대시보드에서 라우트를 바꿔도 **다음 배포에서 설정 파일에 적힌 라우트로 덮어쓴다**」
— `routes` 는 «추가» 가 아니라 **«전체 목록»** 이다. `test.mangoi.co.kr` 만 적고 배포하면
`mangoi.ai`·`www.mangoi.ai` 가 떨어진다. 덤으로 `routes` 를 넣는 순간 `workers_dev` 가
`false` 로 «추론» 되어 `webrtc-unified-platform-prod.navy111p.workers.dev` 가 죽고,
그 주소로 배포를 확인하는 `deploy.ps1`(77행)·`deploy-full.ps1`(130행)·`deploy.yml`(164·174행)이 함께 깨진다.
→ **넣지 않고**, 그 위험을 주석·문서·하니스에 못 박았다.
정말 넣으려면 **붙어 있는 도메인을 하나도 빠뜨리지 말고 전부 + `workers_dev = true`** 가 필요하다.

### ⛔ 버림 ⑤: 오판 노쇼 기록을 지우거나 UPDATE 로 «정리»

가장 간단하다. **버린 이유**: 학생이 못 본 것은 **사실**이다. 지우면 「왜 수업이 성립하지
않았나」라는 더 중요한 기록까지 사라진다. 컬럼으로 굳혀도 나중에 판정이 좋아졌을 때 옛 값이 남는다.
→ **읽을 때 대조**해서 «오판» 이라고 함께 알려 준다.

### ⛔ 버림 ⑥: `attendance.role = 'teacher'` 를 오판 판정 근거로 쓰기

제일 쉬운 판정이다. **버린 이유**: `role` 은 **클라이언트가 보내는 값**이고,
「먼저 들어온 학생이 강사 역할을 받는다」 사고 전례가 있다(`api-mango.ts` verify-room 주석).
그걸 믿으면 **진짜 노쇼가 오판으로 감춰지고 수업료가 전액 나간다** — 가장 나쁜 방향이다.
→ 근거는 **이름 일치뿐**. 이름은 `api-teacher.ts` 와 같은 **낱말 경계** 규칙을 쓴다
(`강선생님` ⊂ `중국어 강선생님` 은 살리고, `Anna` ⊂ `H·ANNA·H` 는 막는다).
판정 못 하면 **«모름»** — 모르는 것을 «오판» 으로 단정하지 않는다.

### ⛔ 버림 ⑦: 판정을 화면·지표·급여에 각각 짜 넣기

**버린 이유**: 이 저장소가 반복해서 밟은 사고다. 세 곳이 다른 답을 내면
「화면엔 오판이라는데 급여는 0원」이 된다. → `src/no-show-truth.ts` **한 파일**로 모았다.

### ⚠️ 되돌린 판단 하나: 노쇼 하니스의 «UPDATE 전면 금지»

처음엔 「`class_no_show` 에 UPDATE 가 없다」로 적었다가 **기존의 정당한 `contacted_at` 기록**
(누구에게 다시 연락했나)까지 잡혔다. 막아야 하는 것은 «오판 판정을 기록에 굳히는 것» 뿐이라
`false_alarm|is_false|voided|teacher_present|no_show_valid` 컬럼을 쓰는 UPDATE/ALTER 만 잡도록 좁혔다.

## 5. 🔴 하마터면 놓칠 뻔한 것 — 「문자열 검사만 하는 하니스」

병합 직전 `trap-check` 서브에이전트가 **실제 버그**를 잡았다.

강사 90일 지표 쿼리를 이렇게 썼다:

```sql
SELECT teacher_name AS tn, room_id, missing_role FROM class_no_show
```

`AS tn` 별칭만 두는 바람에 결과 행에 `teacher_name` 이 **없다.**
`teacherPresenceByRoom` 은 그 이름의 필드를 읽으므로 이름이 항상 빈 값 → 전부 «모름» →
**오판이 한 건도 제외되지 않았다.** 에러가 안 나서 조용히 예전과 같아졌다.

급여와 노쇼 리포트는 `teacher_name` 을 그대로 실어 보내 정상이었으므로,
목표한 «세 곳» 중 **한 곳만 안 먹던** 상태였다 — 코드 주석이 스스로 경고한 그 불일치.

**그리고 그때 하니스 35건이 전부 통과했다.** 「함수를 부르는가」·「`present === true` 면
`continue` 하는가」를 **문자열로만** 검사했기 때문이다.

→ 고침: 쿼리에 `teacher_name` 을 함께 싣고, **하니스가 판정 함수를 typescript 로
컴파일해 실제로 돌리게** 바꿨다(⑩, 가짜 DB + 각 호출부의 행 모양 그대로).
이번 사고 형태(`tn` 만)를 넣으면 «오판» 이라 단정하지 않고 «모름» 이 나오는 것까지 확인한다.

같이 강화한 것: 낱말 경계는 «낱말 속 우연»(Anna ⊂ HANNAH)은 막지만
«낱말 자체가 겹치는» 경우는 못 막는다 — 강사명이 한 낱말이면(예: `Len`)
같은 방의 `Len Kim` 이 걸려 **진짜 노쇼를 감추고 수업료를 전액 내보낸다.**
→ 그 방의 **학생 이름에도 똑같이 걸리는 접속은 강사로 세지 않고**, 남는 게 없으면 «모름» 으로 둔다.
