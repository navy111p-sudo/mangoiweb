# 손익계산서 「남궁국화」 계좌 출금 분류 정정 — 직원급여 → 지사수수료

- 날짜: 2026-08-19
- 작업자: Claude Code (mangoi 계정 세션)
- 브랜치 / PR: `claude/github-repo-connection-check-6is84j` — #326

## 1. 왜 했나

사장님이 관리자 화면의 손익계산서(2026년 7월)를 보다가 "직원 급여와 강사 급여 중
겹치는 항목이 있는 것 같다"고 제보. 코드를 확인해 보니 실제로는 두 줄(COGS
「강사 급여」·SG&A 「직원급여」) 사이의 이중계산은 없었다(카테고리가 상호배타적으로
집계되어 판관비 합계와도 정확히 일치). 대신 그 자리에서 별도로, 사장님이 직접
"남궁국화, 남궁국화A는 지사수수료야"라고 정정을 지시했다 — 즉 실제 버그는
「직원급여」 줄에 지사수수료가 잘못 섞여 있던 것이었다.

## 2. 무엇을 바꿨나

- `cloudflare-deploy/src/bankacct-sync.ts` `BANK_CAT_RULES`(70~89행): 은행 적요를
  이름으로 판별해 「직원급여」로 분류하는 정규식 `/이병엽|남궁국화|장지웅/` 에서
  **남궁국화를 제거**. 이제 `/이병엽|장지웅/` 만 남는다. 이 파일은 계좌 동기화 시점에
  거래마다 카테고리를 정해 D1 `bankacct_transactions.category` 에 저장하고, 동기화마다
  **기존 행도 소급 재분류**한다(`runBankSync` 의 `recategorize` 루프) — 그래서 코드만
  고치면 다음 일일 동기화(cron) 때 과거 거래도 자동으로 다시 분류된다. 별도 D1 UPDATE
  불필요.
- `cloudflare-deploy/src/accounting-reports.ts` `monthActualOpex` 안의 「기타출금
  쪼개기」 로직(296~324행 부근): "남궁국화"/"남궁국화A" → 「지사수수료」로 직접
  매칭하는 정규식 `KNOWN_FRANCHISE_PAYEE_RE = /^남궁국화A?$/` 를 추가하고, 기존
  `franchises.owner_name` 자동매칭보다 먼저 검사하게 배치.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **D1 `expense_payee_category` 표에 직접 INSERT** → 버림. 이 세션에서 `wrangler d1
  execute` 자체가 권한 정책으로 막혀 있어(실행 요청이 거부됨) 실행할 수 없었고,
  설령 가능했더라도 그 표는 「사람이 관리자 화면에서 지정한 예외」용이라 소스코드에
  이미 하드코딩돼 있던 이름 목록(이병엽·남궁국화·장지웅)과 성격이 다르다. 애초에
  잘못 들어간 곳이 소스코드이므로 소스코드에서 빼는 것이 정본을 하나로 유지한다.
- **`franchises.owner_name` 자동매칭만 믿고 코드 추가 없이 두기** → 버림.
  "남궁국화A" 처럼 은행 적요에 접미사가 붙은 변형 표기가 franchises 표의
  `owner_name` 과 문자열이 정확히 일치한다는 보장이 없다(그 표는 exact-match 비교).
  일치하지 않으면 그냥 「기타출금」 미분류로 남아 화면이 다시 "분류해 주세요" 로
  요구하게 된다 — 사장님이 이미 답을 준 상태이므로 하드코딩으로 확실하게 잡는 쪽을
  택했다.
- **BANK_CAT_RULES 에 「지사수수료」 카테고리를 직접 추가** → 버림. 그러면
  `monthActualOpex` 의 `bankAll`(DB GROUP BY 결과)에 이미 「지사수수료」 항목이
  하나 들어오고, 「기타출금 쪼개기」 로직이 **다른** 지사 대표자 이름들을 걸러
  또 하나의 「지사수수료」 항목을 만들어 push 하면서 같은 이름의 카테고리 줄이
  두 개로 쪼개져 화면에 중복 표시될 위험이 있었다(합계 자체는 맞지만 표는
  지저분해짐). 「기타출금」 단계 한 곳에서만 「지사수수료」를 만들게 두어 항상
  하나의 Map 으로 합산되게 했다.

- 리포 루트에서 `node test-harness/run.mjs --fast` — PASS 181 / SKIP(E2E) 20 / FAIL 0.

  찍혀 있는지, franchises.owner_name 에 이 이름이 있는지는 이 세션에서 D1 조회
  권한이 막혀 직접 보지 못했다. 배포 후 사람이 화면에서 손익계산서 「지사수수료」
  줄 금액이 늘고 「직원급여」 줄이 그만큼 줄었는지 확인이 필요하다.

## 5. 남은 것 / 주의할 것

- 코드 수정만으로는 **다음 계좌 동기화(일일 cron)가 한 번 돌아야** 기존 거래의
  category 가 실제로 바뀐다. 급하면 관리자 화면에서 수동 동기화 버튼(`runBankSync`
  호출 API, `api-admin.ts` 11417/11453행)을 눌러도 된다.
- 이 작업 중에 별도로 발견한 것(이번에는 고치지 않음): 강사 급여명세(payslips)가
  실제로 없는 달에는 「강사 급여」 줄이 메트로은행(필리핀) 송금분만 잡고, 「급여이체」
  로 분류된 국내 급여성 출금은 "강사급여와 중복이라 제외"라는 각주 아래 판관비
  에서도 빠지면서 **어디에도 반영되지 않을 수 있다** — 이중계산이 아니라 반대로
  비용 누락 방향의 문제. 사장님께 먼저 보고했고 구체적 조치는 다음 지시를 기다리는
  중이다.
