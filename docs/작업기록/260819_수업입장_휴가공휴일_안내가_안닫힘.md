## 2. 무엇을 확인했나 (원인 후보를 하나씩 지움)

배포된 화면은 볼 수 없으므로(프록시가 `mangoi.ai` 차단) **로컬에서 `public/` 을 그대로
서빙 + 컨테이너의 크로미움을 CDP 로 조종**해 같은 화면을 재현했다(CLAUDE.md 2장의 방법).

| 후보 | 결과 |
|---|---|
| 무언가가 위를 덮어 클릭이 안 닿는다 | ❌ `elementsFromPoint` 로 재니 ✕ 버튼이 맨 위였다(뒤는 `#vc-free-btn`·`.video-size-bar`) |
| 사진에 보이는 «비스듬한 주황 줄» 이 덮개다 | ❌ 재현 화면에도 똑같이 나온다 — 반투명 상자 **뒤에 비치는 배경 버튼**이지 덮개가 아니다 |
| CSP 가 인라인 `onclick` 을 막는다 | ❌ `src/index.ts` 는 `frame-ancestors` 만 설정한다 |
| 클릭을 삼키는 window 캡처 핸들러가 있다 | ❌ 실제 마우스 이벤트를 쏴 보니 캡처·버블 모두 정상 도달 |
| 상자가 매번 다시 만들어진다 | ❌ 부르는 곳은 `idx-main.js` 한 곳뿐 |
| **같은 id 상자가 두 벌 쌓였다** | ✅ 코드상 가능 — 아래 3장 |

## 3. 진짜 뿌리 — «하나만 지우는 닫기» + «두 벌 만들어질 수 있는 만들기»

```
if(document.getElementById('mangoi-class-notice'))return;   // ← 검사
...
var res = await fetch('/api/calendar/events?...');           // ← 여기서 기다린다
...
document.body.appendChild(box);                              // ← 그리고 만든다
```

검사와 만들기 사이에 **네트워크 대기**가 있다. 그 사이에 함수가 한 번 더 불리면
둘 다 검사를 통과해 **똑같은 상자가 겹쳐서 두 개** 붙는다. 그런데 닫기는

```
var el=document.getElementById('mangoi-class-notice'); el.parentNode.removeChild(el);
```

로 **첫 하나만** 지웠다. 사람 눈에는 «클릭해도 그대로» 로 보인다.
(수업 입장은 자동입장·로비·마이페이지 등 경로가 여럿이라 두 번 불릴 여지가 있다.)

두 번째 원인 후보도 함께 막았다 — ✕ 가 26px 로 작아 **살짝 빗맞히면 아무 일도 안 일어난다.**

## 4. 검토했다가 버린 방법과 그 이유

### ❌ 「닫기 버튼만 크게」
빗맞히는 문제만 풀리고, 두 벌 쌓인 경우는 그대로다. 제보의 «클릭해도» 를 설명 못 한다.

### ❌ 「상자를 아예 없애기 / 수업 중에는 띄우지 않기」
일부러 넣은 안내다(1-3 「되살리면 안 되는 것」의 반대 — **없애는 것도 사람이 결정할 일**).
사장님이 원한 것은 «안 뜨게» 가 아니라 «닫으면 닫히게» 다.

### ❌ 「`sessionStorage` 에 «다시 보지 않기» 저장」
오늘 처음 들어간 수업에서 한 번은 보여야 하는 안내다. 기기에 영구 기억을 남기면
다음 날 새 공휴일이 생겨도 안 보일 수 있다. → **그 페이지가 열려 있는 동안만** 기억한다.

### ❌ 「`document` 전역에 클릭 캡처를 걸어 어디를 눌러도 닫기」
수업 화면 클릭(카메라·교재·필기)까지 우리 코드를 거치게 된다. 사고 반경이 너무 크다.
→ 리스너는 **상자 자신에게만** 붙였다.

## 5. 고친 것 (`cloudflare-deploy/public/index.html` 한 파일)

1. **닫기는 `querySelectorAll` 로 «전부» 지운다** — 두 벌 쌓여도 한 번에 사라진다.
2. **만들기에 «만드는 중» 잠금**(`N_NOTICE_BUSY`) — `await` 중 두 번째 호출은 만들지 않는다.
   실패했으면 `finally` 로 풀어서 다음 입장 때 다시 뜬다.
3. **사람이 닫았으면 다시 만들지 않는다**(`N_NOTICE_CLOSED`, 그 페이지가 열려 있는 동안만).
4. **인라인 `onclick` 하나에 기대지 않는다** — 캡처 단계 `click`·`touchend` 리스너를
   상자에 직접 달고, **상자 아무 곳이나 눌러도 닫히게** 했다(부제에 안내 문구 추가).
5. **✕ 를 26px → 32px** 로 키웠다.
6. **20초 안전망** — 어떤 이유로든 닫기가 안 먹어도 스스로 사라진다(수업 화면을 계속 가리지 않게).
7. 덤: 사진에 「Cdo Fiesta」가 두 줄이었다 — **날짜·제목·나라가 같으면 한 줄만** 그린다
   (6줄뿐인 자리를 중복이 먹지 않게. 원본 데이터는 건드리지 않았다).

## 9. 덤 — 캘린더 중복 등록 확인과 삭제 (사장님 지시)

사장님: **「캘린더에 중복 등록됐는지 확인해줘」 → 「중복된 거 지워줘」**

### 확인 (SELECT)

D1 `calendar_events` 를 전부 훑어 «날짜·종료일·제목·나라·종류가 같은 줄» 을 묶어 보니
**중복은 딱 한 쌍**이었다.

| id | 일정 | 날짜 | 나라 | 방식 | 등록 시각(KST) |
|---|---|---|---|---|---|
| 39 | Cdo Fiesta | 2026-08-28 | PH | manual | 2026-07-29 **19:45:32** |
| 40 | Cdo Fiesta | 2026-08-28 | PH | manual | 2026-07-29 **19:46:42** |

**70초 차이** = 「➕ 추가」를 한 번 더 누른 것. 제목·색·나라까지 같고 비고(note)는 둘 다 비어 있어
한쪽을 지워도 잃을 정보가 없었다. 전체 39건 중 나머지 37건은 6/9 자동 시드(`source='seed'`)라
깨끗했고, 휴가(`vacation`) 등록은 0건이었다.

### 삭제 (사장님 지시를 받고 실행)

```sql
DELETE FROM calendar_events
 WHERE id=40 AND title='Cdo Fiesta' AND date='2026-08-28' AND country='PH' AND source='manual'
```

→ **1행 삭제.** 확인: 「Cdo Fiesta」 1건(id 39)만 남고, 전체 39 → **38건**, 중복 쌍 **0**.

- **id 만 믿지 않고 내용까지 조건에 넣었다** — 개발·운영이 같은 DB 라(CLAUDE.md 1-1)
  id 하나가 어긋나면 엉뚱한 학생 데이터가 지워진다. `WHERE id=?` 만 쓰지 말 것.
- 먼저 등록된 쪽(39)을 남겼다. 나중 것을 남기면 «먼저 만든 기록» 이 사라진다.
- ⛔ **되돌릴 수 없다.** D1 은 테스트 DB 가 따로 없다. 그래서 삭제는 **사장님 지시를 받고서만** 했고,
  그전(「확인해줘」 단계)에는 SELECT 만 돌렸다.

### 왜 화면 고침과 DB 삭제를 «둘 다» 했나

한쪽만으로는 부족하다.
- **삭제만** 하면 — 다음에 또 두 번 누르는 순간 안내 팝업에 두 줄이 다시 뜬다.
- **화면 중복 제거만** 하면 — 팝업은 한 줄이지만 관리자 › 📅 캘린더 관리에는 두 줄이 그대로 남고,
  나중에 「왜 두 개지?」로 다시 올라온다.
→ 화면은 **중복이 있어도 안 보이게**, DB 는 **실제로 있던 한 건을 정리**했다.

### 남은 것

- 등록 API(`POST /api/admin/calendar/events`, `api-lessons.ts`)에는 **같은 날·같은 제목을 막는 검사가 없다.**
  자동 시드(`seed`)에만 「이미 있나?」 검사가 있고, 사람이 손으로 넣는 경로에는 없어서 이번 일이 생겼다.
  → 막고 싶으면 등록 시 `event_type+date+title+country` 중복 확인을 넣으면 된다.
  **이번에는 지시 범위 밖이라 손대지 않았다**(관리자 화면·API 변경은 A 담당 영역이기도 하다).
