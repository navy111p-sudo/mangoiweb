## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### 3-1. 판 번호 충돌 — 「내 것으로 몰기」를 버림

`main` 이 `adm-core.js` 를 **v=133** 으로 먼저 올려서, 세션 1 의 **v=132** 와 부딪혔습니다.
CLAUDE.md 4-1-1 이 말하는 **「진짜 충돌」**(둘이 같은 파일의 버전을 각자 올린 경우)입니다.

| 버린 방법 | 왜 버렸나 |
|---|---|
| `--ours` / `--theirs` 로 한쪽 몰기 | 어느 쪽으로 몰든 **다른 쪽 수정이 조용히 묻힙니다.** 이 줄은 「어떤 js 를 캐시에서 새로 받을지」를 정하는 줄이라, 잘못 몰면 브라우저가 옛 파일을 계속 씁니다 |
| 원장(`asset-versions.json`)을 손으로 편집 | 원장은 **해시가 들어 있어** 손으로 쓰면 값이 틀립니다. 그리고 CLAUDE.md 함정표에 「`git stash pop` 을 `--theirs` 로 풀었다가 main 항목 4개를 날릴 뻔한」 실측 기록이 있습니다 |
| `.gitattributes` 의 `merge=union` | CLAUDE.md 가 **명시적으로 금지**합니다 — 마지막 줄 쉼표가 없어져 **깨진 JSON** 이 되는데 git 이 「병합 성공」이라고 조용히 넘어갑니다 |

**택한 방법** — CLAUDE.md 「원장」 함정이 적어 둔 그대로.

1. `admin.html` — main 의 v=133 줄을 살리고 **양쪽보다 큰 v=134** 로 재승격, 변경이력은 양쪽 다 남김
2. `asset-versions.json` — `git checkout origin/main -- test-harness/asset-versions.json` 으로 **main 것을 되살린 뒤**
   하니스를 다시 돌려 기록하게 함 → diff 가 **「내가 추가한 한 줄」** 로 깨끗하게 남음

```
+  "/js/adm-core.js?v=134": "4af239289ada028a",
```

### 3-2. 「반쪽만 고쳐진」 #353 을 그래도 올린 이유

운영 D1 을 조회해 보니 이 PR 은 **상담 «슬롯» 쪽만 고치고 «예약» 쪽은 못 고칩니다**(5-1).
그래서 세 가지를 놓고 고민했습니다.

| 버린 방법 | 왜 버렸나 |
|---|---|
| 내가 빠진 `ALTER` 3줄을 직접 넣어서 올리기 | 사장님이 **「장부장님께 요청사항을 카톡문자로 만들어줘」** 라고 하셨습니다. 원저자가 고칠 몫으로 남기는 것이 지시에 맞습니다. 남의 브랜치에 내 판단으로 기능을 더하지 않습니다(CLAUDE.md 4-2) |
| 예약 쪽이 안 되니 PR 자체를 보류 | **예약은 이 PR 이전에도 동작하지 않던 상태**입니다. 슬롯 쪽 수정만으로도 순증이고, 보류하면 이미 된 것까지 함께 멈춥니다 |

**택한 방법** — PR 본문과 카톡 문자에 **「무엇이 아직 안 되는지」를 명시**하고 그대로 올림.

### 3-3. #354 를 「그냥 통과」로 보지 않고 D1 까지 확인한 이유

해시가 맞아도 **UPDATE 가 로그인이 읽는 행에 닿지 않으면** 「저장됐습니다」만 뜨고 아무 일도 안 일어납니다.
CLAUDE.md 함정표의 「헬퍼에 행을 넘겼는데 아무 일도 안 일어남」과 같은 형태를 의심했습니다.

- 로그인(`api-students.ts`) — `WHERE user_id = ?`
- 이 UPDATE(`api-mango.ts`) — `WHERE student_id = ? OR login_id = ? OR username = ?`

**칸 이름이 다릅니다.** 그래서 실제로 세어 봤습니다.

```sql
SELECT COUNT(*), SUM(CASE WHEN user_id = student_id THEN 1 ELSE 0 END) FROM students_erp;
-- 29,399 / 29,399  → 전부 일치. 매칭됨 ✅
```

문자열 검사로는 절대 못 잡을 것이었고, **실제로 돌려 보거나 데이터를 세어 봐야** 알 수 있었습니다.

### 3-4. 검증 환경 — `--legacy-peer-deps` 를 버림

`npm ci` 가 `ERESOLVE / peer` 로 죽었습니다. CLAUDE.md 함정표에 **「Node 버전 문제이지 의존성 문제가 아니다」** 라고
이미 적혀 있어서, 우회 플래그 대신 `.nvmrc` 대로 **Node 24 를 설치**해서 풀었습니다(컨테이너에 22 만 있었음).
우회했다면 CI(Node 24)와 다른 의존성 트리로 검증하게 되어 **검증 자체가 의미를 잃습니다.**

ALTER TABLE counseling_bookings ADD COLUMN date TEXT
ALTER TABLE counseling_bookings ADD COLUMN start_time TEXT
