# 카톡에서 연 관리자 화면이 「로그인했는데 또 로그인하래요」 — 2026-08-19

## 1. 왜 했나

사장님: **「내 관리자페이지 admin 으로 mangoi.ai/work 에서 로그인이 안 되지?」**
→ 사진: `/admin/login` 화면. 로그인해도 **같은 화면이 다시 나온다.**

## 2. 무엇을 확인했나 — 추측하지 않고 서버 기록을 봤다

| 확인 | 결과 |
|---|---|
| 비밀번호가 틀렸나 | ❌ 최근 24시간 `wrong_password` **0건** |
| 계정이 잠겼나(브루트포스 15분 차단) | ❌ 해당 기록 없음 |
| 2FA 때문인가 | ❌ `ADMIN_2FA_DISABLED="true"` 라 코드 안 물음 (단 5장 참고) |
| 권한이 없나 | ❌ `admin` 은 `admin_scope.scope_type='hq'` = 본사. `/work` 는 본사면 통과. 게다가 `EXEC_USERNAMES=['admin']` (결재 최종승인자) |
| **로그인 자체가 실패했나** | ❌ **성공했다** — 21:44:50 · 21:45:10 둘 다 `success=1` |

여기서 막혔다가, **세션 표를 본 것이 결정적**이었다.

```
admin_sessions (username='admin')
 21:45:09  살아 있던 시간 0초   ← 카카오톡 인앱
 21:44:50  살아 있던 시간 0초   ← 카카오톡 인앱
 21:03:59  살아 있던 시간 52분  ← PC 크롬
 20:57:13  살아 있던 시간 40분  ← 휴대폰 크롬
 08/17     살아 있던 시간 46시간 ← 휴대폰(다른 앱)
```

`last_seen_at == created_at` = **세션이 만들어지고 한 번도 쓰이지 않았다** = 쿠키가 서버로
돌아오지 않았다. 그 두 건의 `user_agent` 에 **`KAKAOTALK/26.7.1 (INAPP)`** 이 찍혀 있었다.

## 3. 뿌리

1. 카톡에서 `mangoi.ai/work` 를 연다 → 미로그인이므로 `/admin/login?next=%2Fwork` 로 보낸다
2. 아이디·비번을 넣는다 → **서버는 로그인 성공 처리하고 `mango_admin_session` 쿠키를 내려준다**
3. **카카오톡 인앱 브라우저가 그 쿠키를 다음 요청에 붙이지 않는다**
4. `/work` 가 «미로그인» 으로 보고 다시 로그인 화면으로 → **사장님 눈에는 「로그인이 안 된다」**

⚠️ 사장님만의 문제가 아니다. **알림톡·카톡으로 보낸 링크는 받는 사람도 카톡에서 연다.**
강사·매니저가 `/teacher`·`/manager`·`/work` 를 카톡 링크로 열면 똑같이 반복된다.

## 4. 검토했다가 버린 방법과 그 이유

### ❌ 쿠키 설정을 바꾼다(Domain 넓히기 · SameSite=None)
**쿠키는 이미 제대로 내려가고 있다.** 돌려주지 않는 쪽이 앱이라 서버가 무엇을 적어 보내도
결과가 같다. `SameSite=None` 은 보안만 낮추고(교차사이트 전송 허용) 증상은 그대로다.

### ❌ 쿠키 말고 토큰(localStorage)으로 관리자 세션을 옮긴다
관리자 세션이 쿠키(HttpOnly)인 것은 **XSS 로 토큰을 훔길 수 없게 하려는 설계**다.
학생 쪽(`mango_token`)과 갈라 둔 이유이기도 하다(CLAUDE.md 2장). 인앱 브라우저 하나 때문에
전 계정의 세션 방식을 바꾸는 것은 사고 반경이 너무 크다.

### ❌ 로그인 뒤 그냥 `/work` 로 보낸다(지금 동작)
보내 봐야 로그인 화면으로 되돌아온다 — **무한 반복**이고, 사용자는 «비밀번호가 틀렸나» 로 오해한다.

### ❌ 「크롬으로 여세요」 문구만 적는다
안드로이드는 `intent://` 로 **버튼 한 번에 크롬으로 넘길 수 있다.** 문구만 적으면
⋮ 메뉴 위치를 모르는 사람은 못 넘어간다(문구는 버튼이 안 될 때의 안내로 함께 둔다).

## 5. 고친 것 — `public/admin/login.html` 한 파일

1. **UA 로 인앱 브라우저를 알아챈다** — 카카오톡·네이버·인스타·페이스북·라인·다음/밴드,
   그 외 안드로이드 `; wv)` 웹뷰.
2. 알아채면 **경고 상자**를 폼 위에 띄운다 — 「카카오톡 안에서는 로그인이 유지되지 않습니다」
   + **[🌐 크롬으로 열기]** + **[📋 주소 복사]** + ⋮ 메뉴 안내.
   - 안드로이드: `intent://<주소>#Intent;scheme=https;package=com.android.chrome;end`
   - 아이폰: 버튼 문구가 「사파리로 열기」로 바뀌고 `x-safari-…` 시도 + ⋯ 메뉴 안내
   - **`next` 가 붙은 현재 주소 그대로** 넘기므로 원래 가려던 화면으로 간다
3. **로그인 성공 뒤 «쿠키가 정말 남았는지» 확인한다** — 인앱일 때만 `/api/admin/me` 를 한 번
   호출해 실패하면 **보내지 않고** 위 안내를 「로그인은 됐지만 저장하지 못했습니다」로 바꿔 띄운다.
   확인 자체가 실패하면(회선 문제 등) 원래대로 진행한다 — 멀쩡한 사람을 막지 않는다.
4. **일반 브라우저에는 아무 변화가 없다**(판정에 걸리지 않으면 상자도 안 뜨고 추가 호출도 없다).

## 6. 어떻게 확인했나

로컬 서버 + 크로미움에 **실제 UA 를 바꿔 넣어** 확인했다.

| UA | 결과 |
|---|---|
| `KAKAOTALK … (INAPP)` (안드로이드) | 경고 상자 **보임**, 버튼 「🌐 크롬으로 열기」 |
| 카카오톡 (아이폰) | 경고 상자 **보임**, 버튼 「🌐 사파리로 열기」, 안내 「⋯ → Safari로 열기」 |
| 일반 크롬(안드로이드) | 경고 상자 **안 보임** (변화 없음) |
| 안드로이드 버튼이 만드는 주소 | `intent://mangoi.ai/admin/login?next=%2Fwork#Intent;scheme=https;package=com.android.chrome;end` |

- 회귀 하니스 `--fast`: 기준선과 동일.
- ❗ 실제 카카오톡에서의 최종 확인은 **사람이 한 번** 해야 한다(이 컨테이너에서는 카톡을 못 띄운다).

## 7. 남은 것 / 다음 사람에게

- **`admin` 계정에 2FA 가 «켜짐» 으로 저장돼 있다**(`admin_2fa.enabled=1`). 지금은
  `wrangler.toml` 의 `ADMIN_2FA_DISABLED="true"` 로 건너뛰는 중이라 아이디+비번만으로 들어간다.
  **그 값을 `false` 로 되돌리는 순간 admin 은 인증앱 6자리를 요구받는다** — 앱이 없으면 잠긴다.
  이번에 손대지 않았다. 정리하려면 사람이 결정할 일이다.
- 근본 해결(인앱에서도 되게)은 **쿠키 말고 다른 방법이 필요**한데, 4장에 적은 이유로 권하지 않는다.
  대신 **문자·알림톡에 넣는 관리자 링크는 「크롬에서 열어 주세요」를 함께 적는 것**이 싸고 확실하다.
