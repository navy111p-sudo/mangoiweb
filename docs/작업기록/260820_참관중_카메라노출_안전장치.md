# 참관(Ghost) 중 카메라·마이크가 열려 있던 것 — 안전장치와 「직접 입장」 카메라 끄기

*2026-08-20 · 브랜치 `claude/problem-and-solution-n3yxnt`*

## 1. 왜 했나

필리핀 매니저 제보(스크린샷 포함):

> **Camera Automatically Displayed While on Observer Mode**
> While observing the class inside the MangoEye Management Dashboard.
> Can we suggest automatically hiding the observer's camera so that the student
> won't be confused when someone enters the class midway?

즉 「참관 중인데 카메라가 뜬다 → 수업 중간에 낯선 얼굴이 나타나 학생이 혼란스럽다」.

## 2. 코드를 열어 보니 — 뿌리가 둘이었다

### ① 참관 모드는 «안 보내게» 잘 만들어져 있었다. 그런데 버튼이 살아 있었다

참관(`/?observe=방ID`)은 원래 «투명 유령» 설계다.

| 곳 | 무엇 |
|---|---|
| `src/video-call-room.ts` `handleJoinObserve` | `joined:false` — 인원수·`existing-users`·입퇴장 방송 어디에도 안 나온다 |
| `js/idx-main.js` `vcCreatePeer` | 참관자는 `addTransceiver(..., 'recvonly')` — 트랙을 안 붙인다 |
| `js/idx-main.js` `vcJoinAsObserver` | 빈 `MediaStream` + 내 얼굴 타일 숨김 |

**그런데 하단 조작 독은 그대로 보였다.** `vcJoinAsObserver` 가 숨기려는 `#vc-bottom-toolbar`
는 **지금 어느 HTML 에도 없는 옛 id** 였다(하단 조작은 `vc-dock.js` 의 `#vc-dock` 으로 바뀜).
`getElementById` 가 `null` 을 돌려주고 조용히 넘어가므로 **에러도 안 났다.**

게다가 그 마이크 버튼은 장식이 아니다 — `vcToggleMic()` 은 **오디오 트랙이 없으면 마이크를
새로 획득해 모든 피어에 `addTrack`** 한다. 참관자는 항상 트랙이 0개라 **버튼 한 번이면
그대로 수업에 등장**할 수 있었다.

### ② 「직접 입장」 은 참관이 아니라 실제 참가자다

관리자 화면에는 참관 옆에 «직접 입장» 버튼이 있다
(`ghEnterRoom` — 실시간 수업 현황, `tcEnterClass` — 오늘 수업 목록).
`/?vc_autojoin=1&vc_role=teacher&…` 로 **카메라·마이크가 켜진 채** 들어간다.
확인창은 있었지만 초록 버튼에 「🚪 입장」 이라 참관과 구분이 약했다.
제보 화면처럼 **하단 독이 다 보이는 상태**는 이 경로일 가능성이 크다.

## 3. 검토했다가 버린 방법

| 버린 방법 | 왜 |
|---|---|
| **`idx-main.js` 안에 가드·CSS 를 직접 넣기** (처음 만든 안, +5.2KB) | `first_paint_budget_harness` 가 FAIL. 실측 여유가 **0.5KB** 뿐이었다(기준선 1537KB + 여유 12KB, 현재 1548.x KB). 게다가 그 파일은 학생 29,000명이 첫 화면에서 받는 **850KB blocking** 이다 |
| **예산 기준선을 `--update` 로 올리기** | CLAUDE.md 가 «마지막 수단» 이라고 못 박은 것. 그 예산은 필리핀 회선을 지키려고 둔 값이다 |
| **`idx-main.js` 의 죽은 `#vc-bottom-toolbar` 두 곳을 청소** | 청소하려면 `?v=` 를 올려야 하고, 그러면 **전원이 850KB 를 다시 받는다.** 주석 한 줄 값으로는 손해라 그대로 뒀다(새 파일 머리말에 사실을 적어 뒀다) |
| **참관자에게 채팅·나가기까지 감추기** | 참관자도 나가야 하고, 무슨 일이 오가는지 보기는 해야 한다 |
| **학생 화면에 「관리자가 참관 중」 을 띄우기** | 서버가 참관자를 인원수·방송에서 통째로 빼는 «투명 유령» 설계다. 화면에만 표시를 만들면 서버 설계와 어긋난다 |
| **직접 입장에서 카메라 트랙을 아예 안 만들기** | 이 앱은 최초 협상 뒤 **자동 재협상을 하지 않는다.** 트랙이 없으면 sender 도 없어서 나중에 [카메라] 를 눌러도 영영 안 나간다 → `enabled=false` 로만 둔다 |
| **트랙만 직접 `enabled=false` 로 끄기** | `idx-main.js` 안의 `vcCamOn`(let)은 `true` 로 남아, 나중에 버튼을 누르면 «켜짐→꺼짐» 으로 뒤집혀 **두 번 눌러야 켜진다.** 그래서 앱 자신의 `vcToggleCam()` 을 한 번 부른다 |
| **직접 입장 버튼을 없애기** | 「강사가 못 들어왔을 때 매니저가 대신 맡는」 실제 용도가 있다. 없애지 않고 **카메라만 꺼서** 들어간다 |

## 4. 한 일

**새 파일 `cloudflare-deploy/public/js/vc-observe-guard.js`** (defer, `index.html` 한 줄) —
`idx-main.js` 는 **한 줄도 안 고쳤다.**

1. 참관 중(`body.vc-observer`)에는 독의 **마이크·카메라·화면공유**를 숨긴다.
   인라인 style 이 아니라 **클래스 + `!important`** (독이 다시 그려져도 살아남는다).
   나가기·채팅·상담·설정은 남긴다.
2. `vcToggleMic`·`vcToggleCam` 을 **감싸서** 참관 중이면 막고 안내를 띄운다.
   버튼을 숨겨도 호출 경로가 여럿이라(옛 툴바 인라인 `onclick`·타일 아이콘·`vcMobileToggle*`)
   **함수 자체**를 막는 편이 확실하다. 붙는 방식은 `mango-consent.js` 와 같다.
3. `&vc_cam=off` 가 붙어 있으면 **카메라를 끈 채로 입장**한다(트랙은 살려 둔다).
   내 타일에 「카메라가 꺼져 있어요」 안내 + 상대에게 `cam-state` 통지(검은 화면 오인 방지).

**관리자 화면 두 곳** — 직접 입장 URL 에 `&vc_cam=off`, 확인창에 「카메라는 꺼진 채로 입장」,
버튼을 **주황 + 「(보임)」** 으로 바꿔 참관(보라)과 눈으로 갈라지게 했다
(`js/adm-s1.js`, `js/adm-today-classes.js`).

**회귀 하니스** `test-harness/observer_camera_guard_harness.mjs` (30건).

## 6. 남겨 둔 것 (다음 사람에게)

- `idx-main.js` 의 죽은 `#vc-bottom-toolbar` 참조 2곳 — 위 3장 이유로 그대로 뒀다.
  그 파일을 **다른 이유로** 고쳐 `?v=` 를 올릴 때 함께 지우면 공짜다.
- **참관자 채팅은 학생에게 보인다.** 서버 `broadcast()` 는 `joined` 를 안 보고 소켓 전체에
  뿌리므로, 참관자가 채팅을 쓰면 수업에 뜬다. 이번엔 «보기는 해야 한다» 고 판단해 두었지만,
  「참관자는 강사에게만 귓속말」 로 바꾸려면 별도 결정이 필요하다(귓속말은 `idx-whisper.js` 로 이미 있다).
- 첫 화면 예산(`index.html` blocking)이 **사실상 0KB** 다. 다음에 `idx-main.js` 에 무엇을
  더하려는 사람은 반드시 별도 파일 + `defer` 를 먼저 검토해야 한다.
