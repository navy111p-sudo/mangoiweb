## 2. 무엇이 원인이었나

### 2-1. 뿌리 A — 나간 사람이 서버 방에서 안 없어진다 (제보 2·3·4, 5의 일부)

화상수업 방은 Durable Object(`src/video-call-room.ts`)입니다.
참가자 명단(`joinedUsers()`)은 소켓의 `readyState` 만 봅니다.
휴대폰이 화면잠금·앱전환·회선전환으로 **종료 신호 없이** 끊기면 서버 쪽 소켓은
한참 `OPEN` 으로 남는데, 이 DO 에는 **「N초 응답 없으면 내보낸다」 판정이 아예 없었습니다.**

브라우저는 25초마다 ping 을 보내고 2회 무응답이면 스스로 끊습니다(`createWebSocket`).
**감시가 한쪽 방향에만 있었습니다.**

#### 증거 — D1 `attendance` 실측 (SELECT 만)

| 입장 | 퇴장 기록 | 사람 |
|---|---|---|
| 19:19:48 | 19:21:46 | jeong |
| 19:21:19 | 19:21:46 | jeong ← **앞 줄과 27초 겹침** |
| … | | |
| 19:39:46 | **없음** | jeong ← **퇴장 기록 없이 사라짐** |
| 19:40:39 | **없음** | jeong |

25분 동안 학생 7회 · 교사 3회 재입장. 스크린샷의 타이머(03:32 / 05:29 / 00:08)가
세션 길이와 정확히 맞아떨어져 **어느 스크린샷이 어느 세션인지 특정**됐습니다.

#### 🔴 여기서 제일 중요한 것 — 출석표만 보면 멀쩡해 보인다

퇴장 시각(`attendance.left_at`)은 브라우저가 **HTTP** 로 `/api/attendance/leave` 를
불러야 기록됩니다. 그런데 휴대폰은 **WebSocket 만 먼저 조용히 죽는** 일이 흔합니다.
그래서 **출석표에는 「정상 퇴장」이라 적히는데 화상방에는 그 사람이 계속 앉아 있는**
어긋남이 생깁니다. 「출석 기록이 멀쩡하니 방도 멀쩡하겠지」로 판단하면
이 사고는 영원히 안 보입니다.

#### 2차 피해가 더 컸다 (제보 5)

유령 타일은 `vcghost-` 가 아니라 **정상 `vc-video-*` id** 로 만들어집니다.
그래서 감시 로직들이 「진짜 사람인데 영상이 안 온다」로 오판했습니다.

- 고착 워치독(`vcStuckPeerWatch`) → 유령마다 **최대 4회 강제 재연결**.
  mesh 구조라 재협상 때마다 **전원의 업로드가 흔들립니다.**
- 오디오 감시 → 스크린샷의 빨간 띠 「🎤 상대 소리가 안 와요 (상대방 마이크 확인)」.
  **오경보였습니다.** 교사 마이크는 멀쩡했습니다.

### 2-2. 뿌리 B — 교재로 돌아갈 길이 없다 (제보 1·6)

탭바에 **「교재」 버튼이 없었습니다.** 2026-06-27 에 「중복」이라고 제거했는데,
그 뒤 교재가 **기본 화면**이 되면서 전제가 바뀌었습니다.
칠판·동영상·게임을 한 번 누르면 **돌아올 버튼이 화면에 하나도 없습니다.**

유일한 입구인 「📚 교재도구」 칩의 위치를 실측했습니다
(로컬 서버 + 컨테이너 크로미움, `getBoundingClientRect()`):

| | PC 1440×900 | 폰 390×844 |
|---|---|---|
| 칩 위치 | x 659 ~ 870 | x 659 ~ 870 |
| 탭바가 보이는 폭 | 1040px | **375px** |
| 칩이 보이는가 | ✅ | ❌ **화면 밖** |

**「휴대폰에서만 그런가?」의 답은 이 항목만 «예»** 입니다.
게다가 교재 탭이 아닐 때는 「잠시만 기다려 주세요」 안내조차 안 뜹니다
(`vcWaitCardSync` 가 교재 탭일 때만 동작) → 학생에게는 **아무 설명 없이 교재가 사라진 것**으로 보입니다.

## 3. 검토했다가 버린 방법 ← 가장 중요

### ⛔ 버림 ① — `clientId` 를 `localStorage`(기기 단위)로 넓히기

재입장 시 서버가 옛 소켓을 닫아 주는 `clientId` 가 지금은 `sessionStorage`(탭 단위)라,
새 탭·앱으로 들어오면 중복 정리가 통째로 건너뛰어집니다. 그래서 넓히려 했습니다.

**버린 이유:** CLAUDE.md 가 경고하는 **무한 킥 루프**에 닿습니다.
같은 기기의 다른 탭에서 열어 둔 **관리자 Ghost 참관**까지 같은 열쇠를 갖게 되어
참관 소켓이 닫힙니다. 「같은 이름이면 닫는다」로 바꾸는 안도 검토했지만,
가족 공용 계정이 한 방에 둘 들어오면 **A 가 B 를 닫고 → B 가 재연결하며 A 를 닫고**
가 무한 반복됩니다. 2026-07-14 에 이미 한 번 밟은 사고입니다.

→ 대신 **서버 생존 판정(A-1)** 과 **화면 청소(A-4)** 로 풀었습니다.
   두 방법 모두 「누구를 닫을지」를 상대가 아니라 **자기 상태**로 판단하므로 킥 루프가 없습니다.

### ⛔ 버림 ② — 오경보를 「띄운 뒤 지우기」

처음엔 `idx-vc-dupghost.js` 가 매 틱 `.vc-noaudio-hint` 를 지우게 했습니다.
**버린 이유:** 감시견도 3초, 청소도 3초라 **3초마다 깜빡입니다.**
「계속 떠 있는 것」보다 나을 게 없습니다.

→ **띄우기 전에** 막습니다. 감시견은 `pc.__audPrev.noTrack` 이 3틱 연속이어야 띄우므로,
   붙은 적 없는 상대의 그 값을 되돌립니다. 값이 1을 못 넘어 **애초에 안 뜹니다.**
   이미 떠 있던 띠를 걷는 코드는 안전망으로만 남겼습니다.

### ⛔ 버림 ③ — 오경보 차단을 `idx-main.js`(감시견 옆)에 넣기

제자리는 감시견 안입니다. 실제로 거기에 먼저 구현했습니다.

**버린 이유:** 첫 화면 예산에 **여유가 194바이트**밖에 없었습니다.
실측 — main 의 `index.html` blocking 이 **1,586,494B = 1549.31KB**, 상한은 1549.5KB.
기준선 1537KB + slack 12KB 를 main 이 이미 꽉 채운 상태입니다.
주석 한 문단(432B)만 넣어도 게이트가 빨간불이었습니다.

→ CLAUDE.md 가 말하는 대로 **별도 파일 + `defer`** 로 뺐습니다(blocking 예산에 안 잡힘).
   `idx-main.js` 에는 「어디서 막는지」 한 줄 포인터만 남겼습니다(총 170B 사용).
   ⚠️ `--update` 로 기준선을 올리는 것은 하지 않았습니다 — 그 예산은 필리핀 회선을 지키는 것입니다.

### ⛔ 버림 ④ — `pagehide` 에서 `sendBeacon` 으로 퇴장 API 호출

WebSocket 이 죽어도 HTTP 는 사는 경우가 많으니 가장 확실합니다.

**버린 이유:** 새 API 라우트가 필요하고 `src/index.ts`(공동 금지구역)의
라우팅 + 인증 게이트 + ASSETS 재작성 **세 곳**을 건드려야 합니다.
서버 생존 판정(2분)이 이미 그 구멍을 막으므로 사고 반경 대비 이득이 적습니다.

→ 대신 `pagehide` 에서 **기존 WebSocket 으로 `leave-room` 을 한 번 더** 보냅니다.
   새 라우트 없이 「뒤로가기·주소이동·탭닫기」를 덮습니다.
   ⚠️ 소켓이 이미 죽어 있으면 이 신호도 못 갑니다 — 그때가 서버 판정의 몫입니다. **둘은 짝입니다.**

### ⛔ 버림 ⑤ — 무응답 임계값을 짧게(30~60초)

빨리 치울수록 좋아 보입니다.

**버린 이유:** ping 주기가 25초입니다. 임계값을 그 근처로 두면
지연이 잦은 필리핀·중국 회선에서 **멀쩡한 수업을 끊습니다** —
2026-07-24 에 pong 워치독이 정확히 그 실수(20초 vs 주기 25초)를 했습니다.
→ **120초(= ping 4회분)**. 게다가 닫을 때 `1000` 이 아니라 **`4003`** 을 쓰므로
   학생 화면은 `dropped`(재연결 대기)로 받습니다 — **오판이어도 수업이 끝나지 않습니다.**

### ⛔ 버림 ⑥ — 유령 타일을 `vcRemovePeer(id, 'left')` 로 지우기

「완전히 지우려면 사유가 `'left'` 여야 한다」고 읽고 그렇게 짰습니다. 검증 중에 잡았습니다.

**버린 이유:** `index.html` 이 `vcRemovePeer` 를 **후킹**해 두었습니다 —
`reason === 'left'` 면 10초 뒤 `remoteCount() === 0` 일 때 **`endOfClassFlow()`(수업 종료)** 를 돌립니다.
교사가 아직 안 들어온 학생 화면에서 내 옛 세션 하나를 치웠을 뿐인데
**「수업이 끝났어요」가 뜹니다.** 고치려던 것보다 큰 사고입니다.
`'dropped'` 로 부르면 20초짜리 «재연결 중» 유령으로 바뀌어 또 남습니다.

→ **사유를 비워서** 부릅니다. `vcRemovePeer` 의 `box && reason` 이 거짓이라 타일을 완전히 지우고,
   후킹의 `if (reason !== 'left') return` 에 걸려 종료 흐름도 안 탑니다. 둘 다 만족하는 값은 이것뿐입니다.

### ⛔ 버림 ⑦ — `pagehide` 에서 무조건 `leave-room` 보내기

같은 뿌리의 형제입니다. `pagehide` 는 **앱 전환·화면잠금에서도 뜨는 브라우저가 있습니다**
(그때는 `event.persisted === true` = 페이지가 살아 있는 채로 물러난 것).
그 상태에서 `leave-room` 을 보내면 서버가 `reason='left'` 로 방송하고
→ 위 후킹이 **학생 화면에 「수업이 끝났어요」를 띄웁니다.**
**교사가 폰을 잠깐 내려놓은 것만으로 수업이 끝납니다.**

→ `if (e && e.persisted) return;` — 진짜로 문서가 헐릴 때만 보냅니다.

⚠️ CLAUDE.md 는 「`dropped` 로 수업을 자동 종료하지 말 것 — `left` 만 종료」라고 적어 두었는데,
   그 뒷면이 이것입니다. **`left` 는 함부로 보내면 안 되는 신호입니다.**
   회귀 감시는 `vc_ghost_liveness_harness` 의 ②번 마지막 두 줄이 못 박아 두었습니다.

### ⛔ 버림 ⑧ — 유령 타일을 「이름이 같으면」 지우기

가장 간단합니다.

**버린 이유:** 가족 공용 계정처럼 「같은 이름 두 사람」이 실제로 있을 수 있습니다.
양쪽이 서로를 지우면 버림 ① 과 같은 무한 킥입니다.
→ **비대칭이 확인될 때만** 지웁니다. 조건은 둘뿐입니다.
   ① 이름이 **내 이름과 같다** (내 옛 세션이 확실 — 남일 수가 없다)
   ② 같은 이름의 **다른 타일이 실제로 붙어 있다** (그쪽이 진짜다)
   둘 다 미수신인 쌍은 **건드리지 않습니다.**

### trap-check 서브에이전트가 잡아 준 것 (커밋 후 수리)

1. **`🫀` 는 Unicode 13.0 이라 금지 대상**(CLAUDE.md 1-4, Win10 두부). 주석 8곳에 썼습니다
   → `💓`(U+1F493, Unicode 6.0)로 교체. 하니스에 검사 추가.
   ⚠️ 경계는 **U+1FAC0** 으로 잡았습니다 — 같은 블록의 U+1FA70~1FA9F 는 Unicode 12.0 이라 허용이고,
   이 파일엔 이미 `🪞`(U+1FA9E, 2026-08-12)가 있습니다.
2. **생존 판정이 `getAutoResponseTimestamp()` 에 사실상 단독 의존**이었습니다.
   자동응답이 켜지면 ping 이 **DO 를 깨우지 않아** 메모리 `lastSeen` 이 안 갱신되는데,
   hibernation 으로 그 Map 이 비면 남는 바닥값이 «입장 시각» 뿐입니다.
   → **조용한 수업에서 120초 뒤 전원이 끊기는 루프**가 될 수 있었습니다.
   1분에 한 번 `attachment` 에도 `seenAt` 을 적어(hibernation 을 넘어 살아남음) 단일 의존을 없앴습니다.
3. **알람에서 `this.roomId` 가 빈 문자열**이라 청소 로그가 `room=-` 로 남았습니다
   → `att.roomId` 로 되살립니다(`webSocketMessage` 와 같은 방식).

### 🔴 확인하지 못한 것 (정직하게)
1. **실제 2인 통화 재현.** 프록시가 `mangoi.ai` 를 막아 배포된 화면을 못 봅니다.
   위 검증은 전부 **로컬에서 같은 파일을 렌더한 것**입니다.
   **화면이 바뀌는 작업은 병합 후 사람이 한 번 봐야 끝난 것입니다.**
2. **제보 1번(교재가 아예 안 보임)의 클라이언트 경로.**
   스크린샷 ①②는 교재 탭이 켜진 채 대기 카드였는데, 바로 다음 세션에서는 8초 만에 교재가 떴습니다.
   서버에는 교재가 있었는데 **그 세션에서만 못 받은** 것으로 보입니다.
   후보(`_vcJoinedRoomId` 폴링 게이트 / `vcJoinRoom()` 이중 호출 경합)는 **코드 정독 수준의 추정**입니다.
