## 무엇이 진짜 원인이었나

### ① · ④ 로고 화면 (같은 문제)

그 화면은 망고아이가 그리는 것이 아니라 **설치된 웹앱의 시작 화면**이다.
근거: `manifest.json` 의 `background_color:#050714` 가 사진의 남색과 같고, 아이콘이 `img/icon-512.png` 와 같은 그림.
(앱 APK 의 시작 화면은 `themes.xml` 이 밝은 테마라 **흰색**이다 — 그래서 웹앱 쪽으로 갈렸다.)

사장님은 「크롬 주소창에 mangoi.ai 를 쳐서」 여신다고 하셨는데 모순이 아니다 —
**홈 화면에 한 번 추가해 두면 그 주소를 쳐도 안드로이드가 설치된 웹앱으로 넘긴다.**

원인은 «시작 화면이 뜨는 것» 이 아니라 **그 뒤에 화면을 못 그리는 것**이었다.

| 겹 | 무엇 | 근거 |
|---|---|---|
| ① | 안드로이드가 뒤에 있던 앱을 지워 «처음부터» 켜진다 | 수업 화면이 카메라·영상통신·1MB HTML 을 물고 있어 메모리를 많이 쓴다 |
| ② | 첫 화면 blocking **1,549KB** | `first-paint-budget.json` · 실측 |
| ③ | **`sw.js` 의 첫 화면 요청에 제한시간이 없었다** | 130~161행. 통신이 «실패» 하면 캐시로 가지만, 휴대폰이 잠자다 깨어날 때 흔한 «응답이 안 오는» 상태는 실패가 아니라 **그냥 기다림** → 로고가 몇 분이고 남는다 |
| ④ | 돌아올 때마다 `location.reload()` | `idx-push-sw.js` 34~53행 — visibilitychange 마다 새 버전 확인 → controllerchange → 통째로 새로고침 |

### ② 매니저와 안 만나짐

사진이 답을 갖고 있었다 — `meet-1234` 에선 두 분 다, 다음 사진은 `mangoi-class` 에 혼자.

**주범은 `idx-main.js` 2066행 `roomInput.value = ''`.** 로비에 들어갈 때마다 방번호 칸을 비운다.
2026-06-01 에 「옛 자동생성 코드가 몰래 채워져 서로 다른 방으로 갈리던」 사고를 막으려 넣은 것인데,
**방금 쓴 번호까지 지운다.** 그래서 빈 칸 → 공용방(`mangoi-class`) → 상대는 `meet-1234` 에 그대로.

겹친 것: 공용방 정원 4명(`video-call-room.ts:29`) · 워커가 두 벌이라 도메인이 갈리면 같은 이름도 다른 방 · 예약이 없으면 자동교정이 안 돈다.

### ③ 세로 아이콘

`index.html` 한 파일에 `position:fixed` **70곳**. 새 버튼이 생길 때마다 «몇 px 아래로» 를 손으로 맞춰 왔다.
실측(헤드리스 크로미움 500×757, in-call 세로):

```
본문(#vc-main-row) 시작 t=51 · 통합바 8~34
바구니(뜬) t=56~88 좌 · 라이트 t=56~88 우   ← 둘 다 «영상 위»
☰기능 t=654~699 (독 열면 580~625)          ← 안내 카드(64~666) «위»
```

즉 «윗줄(8~40)» 은 원래 비어 있었고, 문제는 **그 아래 56px 줄에 얹은 것**이었다.

## 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| **`sw.js` 의 서브리소스(js/css/이미지)에도 타임아웃 복원** | 2026-08-08 에 「느린 회선에서 옛것을 내준다」며 **일부러 없앤** 것이다. 그 판단은 그대로 옳다 — 서브리소스는 늦어도 화면이 그려진다. 타임아웃은 **첫 화면 HTML 하나에만** 넣었다(못 그리면 화면이 아예 없으니 판단 기준이 다르다) |
| **캐시된 첫 화면의 «신선도» 를 며칠로 제한** | 필요 없었다. `?v=` 는 쿼리스트링이라 **파일 경로가 아니다** — 옛 HTML 을 그려도 참조하는 js/css 는 그대로 있어 404 가 안 난다. 대신 성공한 HTML 을 매번 `/` 에 갱신해 캐시가 묵지 않게 했다 |
| **첫 화면 예산을 `--update` 로 올리기** | CLAUDE.md 가 «마지막 수단» 이라 못 박았고, 그 예산은 필리핀 회선용이다. 실측해 보니 **HEAD 가 이미 1549.31KB 로 상한(1549)에 붙어 있었다**(여유 12KB 는 다른 작업이 다 쓴 상태). → 새 코드를 **전부 defer 파일로** 빼서 blocking 증가 **+107바이트**로 맞췄다 |
| **`idx-vc-screenmode.js`(12KB, blocking)에 `defer` 붙이기** | 예산이 12KB 넉넉해지는 «옳은» 수였지만, 지시가 「다른 것들 건드리지 말고」였다. 로드 순서를 바꾸는 것은 별건으로 남긴다 |
| **얼굴 타일 «안» 바구니를 숨기고 떠 있는 미러만 쓰기** | 미러(`#vc-basket-float`)는 `!isTeacher()` 조건이라 **강사에게는 안 뜬다** → 숨기면 정보가 사라진다. 자리만 모서리(46px→6px)로 옮겼다 |
| **♻ 새로고침·세계시계도 함께 정리** | 사장님이 표시하신 곳이 아니고, 그 둘의 좌표는 **서로를 피하려고** 맞춰 둔 것이다(`#ph52-cache-fab` bottom 166 = 시계 78+70 위). 하나 옮기면 다른 겹침이 난다 |
| **「정원이 찼습니다」 문구 보강** | idx-main.js(blocking)에 +700B 라 예산을 넘긴다. 새로 넣은 **공용방 안내 배너**가 같은 내용을 알려 주므로 뺐다 |
| **아이콘을 px 오프셋으로 «맞추기»** | 지금까지 그렇게 해서 어긋나 온 것이다. 사장님 2차 지시(「일자로 맨 위에」) 때 **통합바 «안» 으로 옮기는** 방식으로 바꿨다 — flex 가 자리를 정하므로 폭이 바뀌어도 한 줄이 유지된다 |

## 🔴 작업 중 실제로 밟은 함정 셋 (CLAUDE.md 2장에 등재)

1. **body class 를 `MutationObserver` 로 지켜봤더니 브라우저가 멎었다.**
   이 저장소엔 body class 를 자주 다시 쓰는 코드가 있어 콜백이 쉴 새 없이 돈다.
   헤드리스 크로미움이 45초 타임아웃까지 아무 로그도 못 냈다(`boot()` 를 비활성화하니 즉시 정상).
   `idx-vc-screenmode.js` 주석의 **2026-07-14 라이브 장애**(홈 전체 먹통)와 같은 뿌리.
   → 화면 전환 순간(`showView`)에만 30초 확인하는 방식으로 교체.

2. **버튼을 상단바에서 빼냈더니 상단바가 쪼그라들어 본문이 위로 올라왔다.**
   라이트·번개를 통합바로 옮기자 `.toolbar` 의 보이는 자식이 0 이 되어 51px → **15px**.
   본문이 그만큼 올라와 **통합바가 다시 «영상 위»** 에 얹혔다 — 고치려던 것이 그대로 재발.
   → `.toolbar{min-height:56px}` 로 자리를 못 박았다.

3. **`#vc-dock-func{display:none}` 하나로는 `#vc-dock button{display:flex}` 를 못 이긴다.**
   id 하나(1,0,0) < id+요소(1,0,1). PC·가로에서 화면공유와 기능이 **둘 다** 나와 버튼이 8개가 됐다.
   → `#vc-dock #vc-dock-func` (2,0,0) 로 수정. 세 폭(PC·가로·세로)에서 각각 확인.
