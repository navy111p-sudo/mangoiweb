# 관리자 버튼 색 — 「참관」과 「직접 입장」을 눈으로 가르기 (2026-08-21)

## 왜 했나

8/20 에 참관 안전장치(PR #366)를 넣으면서 «참관 = 보라 · 직접 입장 = 주황» 으로 색을 갈라 두었다.
그런데 안내문을 쓰려고 화면을 다시 들여다보니 **「🔴 실시간 수업 현황」의 [👁 GHOST 참관] 버튼만 주황**이었다.
다른 두 목록에서 주황은 정반대 뜻(«학생에게 보이는» 직접 입장)이다. 사장님께 그 불일치를 보고하고
「보라로 바꾸겠습니다」 로 시작한 작업이다.

## 그런데 진짜 문제는 따로 있었다

색을 바꾸고 **브라우저로 확인**했더니 보라도 주황도 아닌 **흰색**이었다.
헤드리스 실측(1500×950, 가짜 수업 1건):

| 버튼 | 코드에 적힌 색 | 화면에 실제로 나온 색 |
|---|---|---|
| 👁 GHOST 참관 | `#8b5cf6` | `rgb(255,255,255)` |
| ⏳ 연장 | `#2563eb` | `rgb(255,255,255)` |
| 🛑 강제 종료 | `#dc2626` | `rgb(255,255,255)` |
| 🚨 즉시 개입 | `#ef4444` | `rgb(255,255,255)` |

즉 **8/20 에 «색을 갈라 뒀다» 고 적은 것이 화면에서는 사실이 아니었다.**
그리고 이건 참관 문제만이 아니다 — **「강제 종료」(수업 전체 연결 해제)의 빨강도 안 나오고 있었다.**
되돌릴 수 없는 행위가 예사 버튼과 똑같이 보였다.

## 원인 — 세 겹이 순서대로 덮는다

CDP 로 매칭된 규칙을 직접 읽어 하나씩 벗겼다.

1. **`admin-inline-c.css` 3279행** — `details.menu-card button:not(…)` 가 **파랑 그라데이션 `!important`**
2. **같은 파일 9072행** — `html[…ivory][…slate] [id^="card-"] button:not([class])` 가 **`#ffffff !important`**
   그 규칙이 스스로 적어 둔 근거는 «클래스가 없다 = 의도한 색이 없다» 인데,
   **색을 인라인으로만 준 버튼에서 그 전제가 틀린다.** 의도는 분명히 있었고 표현 방식만 인라인이었다.
3. **`js/adm-light-surfaces.js` 페인터** — «어두운 배경»(상대휘도 < 0.16)을 찾아
   **인라인 `!important` 로 밝게** 눌러 버린다. 파랑 `#2563eb` 이 `rgb(244,246,251)` 이 됐다.

한 겹을 벗기면 다음 겹이 나왔다 — 클래스를 달아 ②를 벗어나니 ①이 잡아 전부 같은 파랑이 됐고,
CSS 를 맨 끝에 `!important` 로 적었는데도 ①에 졌다(특이성 (0,5,2) 대 (0,2,1)).

## 고친 방식

세 겹을 각각 막았다.

1. **클래스를 단다** — `rm-act` / `gh-act` / `tc-act` + 버튼별 이름(②를 벗어남).
   ⛔ 이름을 «-btn» 으로 끝내면 `[class$="-btn"]` 규칙(3894·9012행)에 다시 걸린다.
2. **색은 CSS 한 곳에서만** — `admin-inline-c.css` 맨 끝, **특이성 꼬리**(`:not()` 5개 이상 → (0,8,1))로 ①을 이긴다.
   이 파일이 9062행에 이미 적어 둔 방식이다 — «항상 참인 `:not()` 을 덧붙여 대상은 그대로 둔 채 힘만 올린다».
3. **페인터 `SKIP_SEL` 에 등재** — 그 목록의 선례(주간 스케줄 `.ph54-ev`, 「유형별 색이 구분 정보다」)와 같은 이유다.

그리고 **JS 에서 색 인라인을 걷어냈다.** 색이 두 곳에 있으면 그게 바로 이 저장소가 문서로 남긴 함정이다.

## 검토했다가 버린 방법

- **①②의 거대한 선택자에 우리 클래스를 `:not()` 으로 추가** — 이미 8줄짜리 선택자다.
  건드리면 그 규칙이 원래 잡던 수백 개 버튼의 판정이 함께 흔들린다. 새 규칙을 뒤에 두는 편이 사고 반경이 작다.
- **페인터의 휘도 임계값을 올린다** — 관리자 화면 전체의 «너무 진한 패널 완화»가 함께 약해진다.
  그 기능은 2026-07-22 사장님 지시로 들어온 것이다. 우리 버튼 여섯 개 때문에 전체를 흔들 이유가 없다.
- **인라인에 `setProperty(…, 'important')` 로 이긴다** — 이길 수는 있지만 색이 JS 에 남는다.
  다음 사람이 CSS 만 보고 «여기가 정본» 이라 믿게 되고, 페인터(③)와는 여전히 «인라인 !important 끼리» 싸운다.
- **색만 바꾸고 끝낸다(원래 지시)** — 화면에 안 나오므로 아무것도 고치지 못한다.
  코드만 보면 고쳐진 것처럼 보이는 것이 이 건에서 제일 위험한 결과다.

## 확인한 방법

- `bash test-harness/ci-gates.sh` → **4종 전부 통과**(tsc · 하니스 **PASS 192 / FAIL 0** · 인라인 JS · `?v=` 197건)
- 새 하니스 F절 15건 + **역검증 4건**(인라인 색 복귀 · 특이성 꼬리 제거 · 페인터 목록에서 제외 · 참관을 주황으로)
  → 네 경우 모두 실제로 FAIL 발생 확인
- **브라우저 실측**(컨테이너 크로미움 + 로컬 서버 + 가짜 API), 페인터가 도는 2.5초 뒤에 측정

| 화면 | 결과 |
|---|---|
| 🔴 실시간 수업 현황 | 참관 `rgb(139,92,246)` · 연장 `rgb(37,99,235)` · **강제 종료 `rgb(220,38,38)`(빨강 복구)** |
| 👀 수업 관찰 카드 | 참관 선택 `rgba(139,92,246,.22)` · 직접 입장(보임) `rgba(245,158,11,.22)` |
| 🚪 오늘 수업 | 입장(보임) `rgba(245,158,11,.16)` · 참관 `rgba(139,92,246,.16)` · 페인터 덧칠 없음 |

⚠️ **측정에서 한 번 오독했다** — 배경이 그라데이션이면 `backgroundColor` 가 **투명**으로 나온다.
「투명이니 색이 없다」고 읽었지만 실제로는 파랑 그라데이션이 칠해져 있었다. `backgroundImage` 를 함께 재야 한다.

## 남겨 둔 것

- 이 세 겹은 **관리자 화면 전체**에 걸린다. 이번에 고친 것은 참관·직접입장·위험 버튼 여섯 개뿐이다.
  다른 카드에도 «코드에는 색이 있는데 화면은 흰색» 인 버튼이 남아 있을 수 있다(전수 조사는 안 했다).
- 색맹·흑백 출력 대비로 «(보임)» 글자 구분은 그대로 뒀다. 색만으로 가르지 않는다.
