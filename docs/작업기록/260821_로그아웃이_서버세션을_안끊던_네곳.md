# 🚪 「로그아웃」을 눌러도 세션이 안 끊기던 네 곳 (2026-08-21)

## 1. 왜 했나 — 출발은 전혀 다른 질문이었다

사장님이 홈 화면 스크린샷을 주시며 물으셨다.

> 「이거 로그인 학생으로 하면 관리자도 자동으로 열리는 거야?」

상단에 학생 `jeong`(343 P)으로 로그인돼 있는데 그 옆에 「🔒 관리자」 칩이 함께 보이는 화면이었다.

**답은 「아니오」였다.** 확인한 것:

- 「관리자」 칩(`index.html:5041` `#admin-shortcut-chip`)은 **역할 검사가 없다.** `ph50-chip-row` 가
  조건 없이 칩 줄에 넣으므로 학생 29,000명 전원에게 똑같이 보인다. 로그인한 사람이 관리자라서
  나온 것이 아니다.
- 두 신분은 **완전히 분리**돼 있다 — 학생은 `localStorage`(`mangoi_logged_user`·`mango_token`),
  교사·본사·지사는 **HttpOnly 쿠키** `mango_admin_session` + D1 `admin_sessions`.
  `/admin.html` 게이트(`src/index.ts:301`)는 **쿠키만** 본다.
- `jeong` 은 관리자 계정이 아니다(D1 확인: `admin_account` 에 `%jeong%` 0건. 정우영 = `admin` 한 건).
- 학생 로그인이 **성공하면** 관리자 폴백(`tryAdminLoginFallback`)은 아예 안 돈다 —
  폴백은 `user_not_found` 일 때뿐이라 관리자 쿠키가 만들어질 길이 없다.

**사장님 PC 에서 열린 이유는 따로 있었다** — 전에 `admin` 으로 로그인한 쿠키가 아직 살아 있었다.
실측: `admin_sessions` 의 `admin` 세션이 08-20 06:38 생성 → **09-19 만료**, 마지막 사용 08-21 16:25.
「로그인 유지」가 30일(`SESSION_REMEMBER_MS`)이라 그 뒤 학생으로 갈아타도 관리자 쿠키는 남는다.

## 2. 그 과정에서 찾은 진짜 문제

세션 코드를 훑다가, **「로그아웃」이라고 적힌 자리가 서버 세션을 안 끊는 곳이 네 군데** 나왔다.
쿠키는 HttpOnly 라 JS 로 못 지운다 — `POST /api/admin/logout` 외에 방법이 없는데, 그 호출이 없었다.

| 자리 | 증상 |
|---|---|
| `manager.html` (필리핀 매니저) | 버튼이 `href="/admin/logout"` — **그 경로에는 핸들러가 없다.** `src/index.ts` 에서 「인증 없이 통과」 목록(5378행)에만 있고 처리하는 곳이 없어 **SPA 폴백으로 홈 화면(index.html)이 떴다.** 누른 사람에겐 로그아웃처럼 보이지만 세션은 그대로 |
| `work.html` (결재 전용) | 위와 똑같은 죽은 링크. **하니스를 붙이고 나서야 발견했다** |
| `js/idx-user-session.js` (홈 화면) | `logout()`·`logoutAdminSession()` 둘 다 `localStorage.removeItem` 만. 「🚪 로그아웃되었습니다」 토스트까지 띄우는데 `/admin.html` 을 치면 그대로 들어가짐 |
| `admin.html` 의 「🚪 로그아웃 (다른 계정으로)」 | `ph116BackToAdmin()` — 역시 localStorage 만. 확인창까지 띄우고 로그인 화면으로 보내면서 쿠키는 살려 둠 |

**나머지 관리자 화면은 전부 제대로 하고 있었다**(`teacher.html`·`mypage`·`exec`·`adm-core.js`·
`capitown`·`finance-realtime`). 이 넷만 예외였다.

위험한 이유는 공용 PC 와 분실한 폰이다. 누른 사람은 「끊었다」고 믿고 자리를 뜨는데 최대 30일 산다.

## 3. 검토했다가 버린 방법

### ⛔ 「학생으로 로그인할 때 관리자 쿠키를 끊는다」 — 안 했다
처음 선택지로 올렸다가 스스로 뺐다. 사장님·매니저는 학생 화면 점검하러 학생 계정으로 자주 들어가신다.
그때마다 관리자 세션이 조용히 죽으면 **CLAUDE.md 2장의 「로그인했는데 또 로그인하래요」가 새 경로로
재발**한다. 두 신분이 따로 사는 것은 사고가 아니라 설계다. 끊어야 할 것은 **「로그아웃을 눌렀을 때」**지
「학생으로 갈아탔을 때」가 아니다.

### ⛔ 「관리자 칩을 학생에게 숨긴다」 — 이번에 안 했다(2순위로 미룸)
값싸게 된다(그 화면은 이미 `mangoi_admin_session` 을 읽고 있어 네트워크 요청도 필요 없다).
다만 **보안 효과는 0** 이다 — 서버 게이트가 이미 막는다. 학생 화면을 덜 헷갈리게 하는 일이라
급하지 않고, `public/index.html`(공동 금지구역)을 만져야 해서 따로 결정할 일로 남겼다.

### ⛔ `/admin/logout` 에 서버 핸들러를 만들어 링크를 살리는 방법 — 안 했다
`src/index.ts` 는 공동 금지구역이고, 이미 `POST /api/admin/logout` 이 있는데 GET 판을 하나 더
만들 이유가 없다. 다른 화면 6곳이 전부 POST 를 쓰고 있으니 **거기에 맞추는 쪽**이 맞다.

### ⛔ work.html 의 「못 보낸 결재」를 로그아웃 때 지우는 것 — 일부러 안 지웠다
`mangoi_work_outbox_v1` 은 **아직 서버에 없는 결재**다(연결되면 자동 전송). 공용 PC 관점에선
지우는 게 깨끗하지만 지우면 남의 일이 그냥 사라진다. 그래서 **캐시(`mangoi_work_home_v1`)만 지우고**,
대기 건이 있으면 **먼저 물어본다**(「보낼 수 없습니다. 그래도 로그아웃할까요?」).
초안(`mangoi_work_draft_v1`)도 같은 이유로 남긴다.

### ⛔ `admGoLogin()`(admin.html) 은 안 건드렸다
「세션이 이미 죽었으니 로그인 화면으로」 라는 복구 경로다. 사람이 누르는 로그아웃이 아니라
범위를 넓히지 않았다. 하니스 C절 주석에 그 예외를 적어 뒀다.

## 4. 고친 내용

- `manager.html` — `<a href="/admin/logout">` → `<button id="logout">` + `POST /api/admin/logout`.
  개인 캐시(`mgr_cache_*`, 연기·변경 요청과 대기자 **이름**)도 함께 지운다. 홈 칩이 읽는
  `mangoi_admin_session` 도 지워 로그아웃 뒤에 이름이 남지 않게 했다.
- `work.html` — 같은 방식 + 위에 적은 「못 보낸 결재」 확인.
- `js/idx-user-session.js` — 폐기 헬퍼 `mangoiRevokeAdminCookie()` 하나를 두고
  `logout()`·`logoutAdminSession()` 둘 다 부르게 했다. 실패해도 화면은 로그아웃된 것으로 둔다.
- `admin.html` — `ph116BackToAdmin()` 이 POST 한 뒤 로그인 화면으로 간다.
- 회귀 감시 **`test-harness/logout_session_revoke_harness.mjs`**(18건) 신설 —
  A 죽은 경로 링크 금지 · B 로그아웃 자리마다 POST · C localStorage 만 지우고 끝내지 않기 ·
  D 서버가 `admin_sessions` 행을 실제로 지우는가.

## 5. 확인한 방법

| 무엇 | 결과 |
|---|---|
| 타입체크 (`node node_modules/typescript/bin/tsc --noEmit`) | 통과 |
| 회귀 하니스 (`node test-harness/run.mjs --fast`) | **PASS 193 · FAIL 0 · SKIP 20** (총 213 — 새 하니스 포함) |
| CI 게이트 (`bash test-harness/ci-gates.sh`) | 4종 전부 통과 |
| 실제 브라우저(로컬 서버 + 컨테이너 크로미움) | **25건 전부 통과** — 네 화면 모두 클릭 → `POST /api/admin/logout` 1회 발생, 버튼 높이가 옆 버튼과 같음, `elementFromPoint` 로 가려지지 않음 확인 |

브라우저 검사에서 확인한 것(요지):
- `manager.html` 클릭 → POST 1회 · `mgr_cache_*` 0건 남음 · `mangoi_admin_session` 지워짐
- `work.html` 대기 0건 → 확인창 없이 POST / 대기 2건 → 확인창, 취소하면 **POST 0회이고 대기 2건 그대로**
- 홈 화면 `logout()`·`logoutAdminSession()` 각각 POST 1회, 학생키·토큰·관리자키 모두 정리
- `admin.html` `ph116BackToAdmin()` → 확인 후 POST 1회

⚠️ **아직 사람이 봐야 하는 것** — 프록시가 `mangoi.ai` 를 막아 배포된 실제 화면은 못 봤다(CLAUDE.md 4-1-1).
병합·배포 뒤 **네 화면의 로그아웃을 한 번씩 눌러** 로그인 화면으로 가는지 확인이 필요하다.

## 6. 남긴 것 / 다음 사람에게

- **첫 화면 예산이 매우 빠듯하다.** `js/idx-user-session.js` 는 `index.html` 에서 **defer 없이**
  불린다(77KB). 한글 주석은 UTF-8 로 글자당 3바이트라 **설명을 길게 쓰면 그것만으로 예산이 터진다** —
  실제로 이번에 한 번 FAIL 났고 주석을 한 줄 포인터로 줄여 통과시켰다(그래서 이 문서가 있다).
  실측 여유: 상한까지 약 **768바이트**(이 작업 전 약 1,304바이트).
- **관리자 칩을 학생에게 숨기는 건 아직 안 했다**(위 3장). 사장님 결정 사항.
- 사장님 PC 는 지금 **학생 로그인과 관리자 쿠키가 동시에** 살아 있는 상태다.
  학생 화면 점검은 **시크릿 창**으로 하셔야 실제 학생이 보는 것과 같다.
