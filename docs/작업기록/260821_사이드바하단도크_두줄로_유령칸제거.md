# 사이드바 하단 도크를 두 줄로 — 「빈 곳」의 정체는 유령 칸이었다

- **날짜** 2026-08-21
- **PR** #388 (main 병합·배포 완료)
- **바꾼 파일** `public/admin.html` · `public/css/admin-inline-c.css` · `CLAUDE.md` · `test-harness/asset-versions.json`

---

## 1. 왜 했나

사장님 지적(사진 두 장, 빨강·노랑 동그라미):

> 휴대폰과 PC 모두 사이드바 아래에 있는 것이 부피를 너무 많이 차지하고,
> **사이트 홈과 관리자 칸 사이가 너무 비어 있어.**

두 가지가 한 문장에 들어 있었다 — ①두껍다 ②사이가 비었다.
②는 「디자인 취향」이 아니라 **버그였다.**

## 2. 원인 — 숨겼다고 적어 둔 칸이 살아 있었다

계정 카드와 「사이트 홈」 사이의 빈 자리는 여백이 아니라 **옛 상단바의 사용자 버튼**
(`#topUserBtn`)이었다. 배경만 투명해서 안 보일 뿐 그리드 한 줄을 그대로 차지한다.

`admin.html` 9811행 주석에는 이렇게 적혀 있었다 —
「⚠️ `#topUserBtn` 은 화면에 안 보인다(`admin-inline-c.css` 의 `#ph115-user-unified` 블록이 `display:none`)」.
**그 주석이 틀렸다.** 특정도 싸움에서 지고 있었다:

```
#topUserBtn          display:none        !important   (1,0,0)   ← 5389행, 숨기려던 쪽
#topUserBtn.th-user  display:inline-flex !important   (1,1,0)   ← 1944·4922행, 이기는 쪽
```

게다가 도크는 그리드라 자식이 **blockify** 되면서 `inline-flex` → `flex` 로 승격,
49×28 짜리 투명 버튼이 **한 줄을 온전히** 먹었다.

실측(2026-08-21, 헤드리스 크로미움, `public/` 을 그대로 로컬 서빙):

| | 옛 도크 |
|---|---|
| PC(1440·zoom 1.3) | **227px** — 사이드바로 보이는 높이 757px 의 **30%** |
| 휴대폰(390) | **172px** (진단·EN·음성 32 / 계정 32 / **빈칸 22** / 홈 40) |

## 3. 샘플 3안을 먼저 보여 드림

사장님 요청이 「3가지 샘플로 디자인 보여줘, 휴대폰·PC 각각」이라 아티팩트로 목업을 만들어
드리고 고르시게 했다(관리자 화면 ivory 의 실제 색·글자 크기·여백 그대로, 높이는 브라우저가
직접 재서 표시).

| | A 아이콘 바 | B 두 줄 균형 | C 접이식 |
|---|---|---|---|
| PC | −92px (38%) | −106px (44%) | −157px (65%) |
| 휴대폰 | −119px (63%) | −82px (44%) | −121px (64%) |

목업을 만들고 나서야 보인 것: **휴대폰에서는 A 와 C 의 두께가 사실상 같다**(69 vs 67px).
폰은 드로어가 화면을 100% 덮어 가로가 넉넉하니 «접을 이유» 자체가 없다.

## 4. 검토했다가 버린 방법

- **A안(아이콘 바)** — 사이트 홈을 아이콘+9px 라벨로. ⛔ 버림:
  그 버튼은 2026-08-20 필리핀 매니저의 「나가는 문이 안 보인다」 제보로 넣은 것이다.
  글자를 줄이는 방향은 그 제보를 반쯤 되돌리는 셈.
- **C안(접이식)** — 가장 얇지만, 접히면 «음성이 지금 켜져 있나»를 한눈에 못 본다.
  그 버튼을 그렇게 만든 이유가 정확히 그것이고(`adm-r15.js` 주석), EN 을 자주 쓰는
  필리핀 매니저에게는 매번 한 번 더 누르는 일이 생긴다.
  → 나중에 「역시 더 얇게」가 되면 B → C 는 쉽다. 반대는 비싸다.
- **도크를 4칸/6칸 그리드로 바꿔 홈 칸을 넓히기** — ⛔ 버림:
  `adm-r15.js` 가 `.has-voice` 로 3칸을 못 박고 있어 그 파일까지 함께 고쳐야 한다.
  칸 수를 그대로 두면 그 코드를 아예 안 건드린다(사고 반경 최소).
- **`grid-column: 1/3` · `3/-1` 로 앞에서부터 세기** — ⛔ 버림:
  음성 토글이 못 붙는 브라우저에서는 도크가 **2칸**이라(`.has-voice` 미부착) 칸이 모자라
  암시적 열이 생기며 배치가 무너진다. → **끝에서부터**(`1/-2`, `-2/-1`) 세면 2칸·3칸 둘 다 맞는다.
- **`#topUserBtn` 을 admin.html 에서 삭제** — ⛔ 금지:
  `adm-core.js` 의 `initTopUserMenu()` 가 `/api/admin/me` 를 부르는 이 화면의 **유일한**
  서버 신원 조회 자리다. 보이지만 않으면 된다.

## 5. 만든 것 (B안)

- `#ph162-dock #topUserBtn, #ph162-dock #topUserPopup { display:none !important }`
  — 도크 id 를 앞에 붙여 (2,0,0) 으로 이긴다.
- 사이트 홈: 「맨 아래 한 줄 전체」 → 「계정 카드 옆 마지막 한 칸」
  (`#ph115-user` = `1 / -2`, `#ph162-sitehome` = `-2 / -1`), 인라인 `grid-column` 은 제거.
- 좁아진 칸(PC 91px)에 맞춰 여백 `8px 6px` · 그림 22→18px · 글자 12→11.5px,
  넘칠 때는 라벨에 «…». **글자는 안 뺐다.**
- `admin-inline-c.css` `?v=39 → 40` + 원장(`asset-versions.json`) 기록.

결과: **PC 227 → 130px(−43%) · 휴대폰 172 → 100px(−42%)**, 네 줄 → 두 줄.

## 6. 확인한 방법

- `bash test-harness/ci-gates.sh` **4종 전부 통과** — tsc · 회귀 하니스 `PASS 191 / FAIL 0 / SKIP 20`
  · 인라인 JS 문법 484조각 0건 · `?v=` 197건 0건. (CI 체크런도 success, 91초)
- 헤드리스 실측 3폭(1440 · 1024 · 500=휴대폰 대역), 환영 오버레이(`#aw-overlay`)를 닫고
  휴대폰은 드로어(`body.mga-open`)를 연 상태에서:
  - 도크 높이 130 / 130 / 100px
  - **`elementsFromPoint` 로 «맨 위에 무엇이 있나»** 를 재서 진단·EN·음성·계정·사이트 홈
    다섯 개 모두 자기 자신이 맨 위(가려짐 없음) — 「보인다」와 「눌린다」는 다르므로 이 검사를 했다
  - KO 「사이트 홈」 · EN 「Site home」 둘 다 `scrollWidth ≤ clientWidth`(안 잘림),
    계정 이름을 길게 넣어도 홈 칸 폭은 그대로(옆 칸을 안 민다)
- ⚠️ **사람 눈확인은 아직**. 작업 컨테이너는 프록시 때문에 배포된 실제 화면을 못 본다(CLAUDE.md 4-1-1).
  게다가 이 컨테이너에는 한글 폰트가 WenQuanYi 하나뿐이라 **글자 폭이 실제 윈도우(맑은 고딕)와 다를 수 있다** —
  칸이 빠듯한 「사이트 홈」 라벨은 사장님 화면에서 한 번 봐 주셔야 끝이다.

## 7. 남긴 함정

`CLAUDE.md` 2장에 등재: 「`display:none !important` 로 감췄다고 주석까지 적혀 있는데 그 요소가
자리를 차지하고 있음」 — id 하나(1,0,0)는 id+클래스(1,1,0)를 못 이긴다.
주석을 믿지 말고 `getComputedStyle` 을 재고, 이기는 규칙은 `document.styleSheets` 를 훑어
`el.matches(selectorText)` 로 찾을 것.
