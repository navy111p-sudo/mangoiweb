# 2026-08-22 — 사이드바 배경 불투명화 + 게임 잠금을 「미리보기 + 순차 잠금」으로

## ① 홈 사이드바 배경 — 투명 22% → 진한 유리 94~97%

### 왜 했나

사장님 스크린샷: 사이드바를 연 채인데 뒤의 우주 배경·「MANGO AI」 글자·우주인·검색창이
메뉴 글자와 겹쳐 읽혔습니다. 「이거 투명으로 하니까 뒤가 다 보여」.

### 원인 — 흐림에 기대고 있었다

`cloudflare-deploy/public/index.html:4587`

```css
#mg-drawer{ … background:rgba(11,16,32,0.22);
            backdrop-filter:blur(10px) saturate(130%); … }
```

배경색이 **22% 뿐**이고 나머지 78%를 `backdrop-filter` 가 메워 주기로 돼 있었습니다.
그런데 **카카오톡 인앱 브라우저·구형 안드로이드 WebView·저전력 모드에서는 그 흐림이 통째로
무시됩니다.** 그러면 남는 건 22% 얇은 색 한 겹뿐입니다. 스크린샷의 배경 글자가 흐리지 않고
선명했던 것이 그 증거입니다.

📌 **같은 저장소가 이 교훈을 이미 배웠습니다** — 전체메뉴 오버레이(`js/idx-allmenu.js` 81행)에
「어둡게 하는 힘을 filter 가 아니라 **배경 레이어에 직접 구운 그라디언트**로 확보한다.
CSS filter/backdrop-filter 미지원 환경에서도 글자 대비가 항상 보장된다」고 적혀 있습니다.
드로어만 그 규칙을 못 받고 있었습니다.

### 네 가지 안을 만들어 고르시게 했다

실제 `#mg-drawer` CSS 를 홈 배경 위에 그대로 얹은 비교 페이지를 만들어 드렸습니다
(흐림이 안 되는 폰으로 보는 스위치 포함).

| 안 | 내용 | 판단 |
|---|---|---|
| **①안 진한 유리** | 94~97% 그라디언트 + blur 유지 | **← 채택.** 흐림이 되면 지금 그 유리, 안 되면 진한 남색 패널. 어느 쪽이든 글자가 읽힌다 |
| ②안 불투명 딥네이비 | 100% 단색 그라디언트, blur 없음 | 가장 안전·가장 빠르지만 유리 느낌이 완전히 사라진다 |
| ③안 우주 배경 사진 | 전체메뉴와 같은 딥필드 + 어둡게 구운 그라디언트 | 브랜드감 최고. 다만 사이드바를 쓰는 26개 화면이 40KB 사진을 새로 받는다(필리핀 회선) |
| ④안 앰버 다크 | 거의 검정 + 앰버 미광, 앰버 테두리 | 홈의 파란 우주와 색 온도가 달라 튈 수 있다 |

### 고친 것

```diff
- background:rgba(11,16,32,0.22);
+ background:linear-gradient(180deg,rgba(12,18,38,0.94),rgba(6,10,22,0.97));
  backdrop-filter:blur(14px) saturate(135%);   /* 있으면 덤, 없어도 글자는 읽힌다 */
```

- `cloudflare-deploy/public/index.html:4587` (홈 인라인 드로어)
- `cloudflare-deploy/public/js/mg-sidebar.js` (홈 밖 26개 화면) — **같은 줄이 한 벌 더 있습니다.**
  한쪽만 고치면 「홈은 바뀌었는데 교재 화면은 그대로」가 됩니다.

⚠️ `public/index.html` 은 CLAUDE.md 4-2 의 **공동 금지구역**입니다. 사장님이 「1안으로 해줘」라고
직접 지시하셔서 적용했습니다. 배경 선언 한 줄 + 주석 4줄이 전부입니다.

### 검토했다가 버린 것

- **뒷막(`#mg-drawer-overlay`, `rgba(2,6,18,.55)`)만 진하게 하기** — 드로어 «뒤» 만이 아니라
  화면 전체가 어두워집니다. 드로어를 열 때마다 페이지 전체가 캄캄해지는 건 다른 문제입니다.
- **`backdrop-filter` 를 더 세게(blur 20px)** — 안 되는 브라우저에서는 0 입니다. 원인을 안 고칩니다.

## ② 게임 목록 — 「미리보기 + 순차 잠금」

### 왜 했나

사장님 지시: 전체 게임 목록은 처음부터 다 보여 주되, 잠긴 게임은 **눌렀을 때 미리보기**를
보여 주고 해금 조건 두 가지(게임 N개 클리어 / 레벨테스트)를 함께 안내할 것.
그리고 **자물쇠가 제목·설명 글자를 가리지 않게** 할 것.

### 전에는 이랬다

잠긴 카드에 `.lockveil` 이 **카드 한가운데를 통째로 덮고** 있었고
(`filter:grayscale(.85) brightness(.86)` 로 사진도 회색), 누르면 토스트 한 줄만 떴습니다.
무슨 게임인지 알 수 없으니 「열고 싶다」는 마음이 안 생겼습니다.

### 고친 것

**화면 — 층을 나눠 겹칠 자리를 없앴다**

| 요소 | 자리 | 왜 |
|---|---|---|
| 사진 | 채도·밝기만 낮춤(`saturate(.62) brightness(.78)`) | 미리보기가 목적이라 무슨 게임인지 보여야 한다 |
| 옅은 막 | `.phwrap::before` (사진 안) | `.body`(제목·설명)에 닿지 않는다. ⚠️ `::after` 는 배지용 그라디언트가 이미 쓴다 |
| 🔒 미리보기 칩 | 사진 **왼쪽아래** | 배지(`.badge`)는 오른쪽위라 안 겹친다 |
| 🗝️ 해금 조건 | 설명 **아래 제 줄**(`.locknote`) | `.body` 안 형제라 구조적으로 못 겹친다 |

**미리보기 창** — `cloudflare-deploy/public/js/game-preview.js` (신규, defer)

`.pv-media`(사진·클립 + 자물쇠) / `.pv-body`(제목·설명) / `.pv-gate`(해금 안내) 세 층.
하단에 여는 방법 두 가지:
1. **지금 열린 게임부터 하기 · <다음에 할 게임>** — `_nextPlayable()` 이 «열려 있고 아직 안 깬» 것을 고른다
2. **🎫 레벨테스트로 바로 열기** — `/?menu=leveltest`

**해금 규칙** (전 지점 동일 — 대리점별 커스텀 없음)

- 앞 2개(`QUEST_START = 2`): 조건 없이 바로 플레이 (기존 그대로)
- 3번째부터: **서로 다른 게임 클리어** 또는 **레벨테스트 통과** 중 하나
- 레벨테스트 통과는 «지름길» — 통과하면 **전부 한 번에** 열린다

**서버 — 레벨테스트 «통과» 신호**

`src/index.ts` 의 `handleGamesRecommend` 응답에 `leveltest_passed` 를 실었습니다.

```sql
SELECT final_level, status FROM leveltest_applications
 WHERE student_uid = ?
   AND ( (final_level IS NOT NULL AND TRIM(final_level) <> '') OR status = 'done' )
```

- **`final_level` 이 채워졌다 = 강사·본사가 레벨을 확정했다**(관리자 화면의 «결과 확정»).
- ⛔ **`status='confirmed'`(일정만 잡힘)는 통과로 세지 않습니다.** 그러면 신청만 하고 안 본
  학생까지 전부 열려서 「레벨테스트로 바로 열기」가 그냥 «잠금 해제 버튼» 이 됩니다.

### 검토했다가 버린 것

- **`GET /api/games/gate` 새 엔드포인트** — 새 API 는 `src/index.ts` 의 라우팅 + 인증 게이트에
  등록해야 하고(CLAUDE.md 2장), 게임 허브가 요청을 한 번 더 보냅니다.
  허브는 **이미 `/api/games/recommend` 하나를 받아 잠금 판정에 쓰고 있으므로**
  그 응답에 한 칸 얹는 쪽이 실수할 자리가 적습니다. 금지구역(`index.ts`) 변경도 최소가 됩니다.
- **퀘스트 모드를 전 학생에게 강제로 켜기** — 지시문의 「전 지점 동일」은 *대리점 커스텀 없음*을
  뜻하지, 기존 학생 29,000명을 하루아침에 2개로 잠그라는 뜻으로 읽지 않았습니다.
  CLAUDE.md 와 기존 하니스가 「기존 학생은 절대 잠기면 안 된다」를 명시하고 있어 그대로 뒀습니다.
  **전원 강제가 맞다면 `_isReturning()` 판정을 빼면 되고, 별건으로 지시해 주십시오.**
- **미리보기에서 실제 게임을 30초 돌려 주기** — 「실제 플레이 대신」이라는 지시와 어긋나고,
  잠금 자체가 무의미해집니다. 하니스가 「미리보기가 잠긴 그 게임을 바로 실행하지 않는다」로 못 박았습니다.
- **없는 미리보기 파일 경로를 미리 적어 두기** — 열 때마다 404 가 납니다
  (전체메뉴 아이콘에서 이미 밟은 함정). `GAME_PREVIEW` 는 **실재하는 파일만** 적고,
  하니스가 파일 존재를 검사합니다.

### ⚠️ 아직 안 된 것 — 미리보기 미디어가 없습니다

지시문의 「30~60초 영상 또는 스크린샷 슬라이드」를 **받을 그릇은 만들었지만 내용물이 없습니다.**
저장소에 게임 플레이 클립도, 게임당 여러 장의 스크린샷도 한 장도 없습니다
(`/img/games/<mode>.webp` 카드 사진 한 장씩이 전부).

지금은 **그 카드 사진 한 장**으로 미리보기를 그립니다. 촬영본이 생기면
`js/game-preview.js` 의 `GAME_PREVIEW` 에 경로만 채우면 됩니다 — 코드는 안 고쳐도 됩니다.

```js
var GAME_PREVIEW = {
  spacemonster: {
    clip:  '/video/games/spacemonster.mp4',
    shots: ['/img/games/preview/spacemonster-1.webp', '…-2.webp']
  },
};
```

### 첫 화면 무게 예산 — 기준선을 올렸습니다

`student-games.html` 288 → **303KB** (`test-harness/first-paint-budget.json`).

- 15KB 중 **11KB 는 이번 작업 이전에 이미 main 에 있던 것**입니다. 파일을 건드리기 전 실측이
  **299KB**(상한 300 = 기준선 288 + 여유 12)였습니다. 누군가 기준선을 안 올린 채 11KB 를 넣어
  여유를 다 써 둔 상태였습니다.
- 이번 작업이 실제로 더한 것은 **4KB**(잠금 카드 CSS + 해금 판정). 미리보기 창 8.9KB 는
  처음부터 `js/game-preview.js` 로 빼서 **defer** 로 내렸습니다.
- ⚠️ **이건 «시간 벌기» 입니다.** 이 화면의 blocking 외부 스크립트 113KB 중
  `mangoi-speak-cycle.js`(43KB)·`mangoi-listen-first.js`(13KB)·`game-tts.js`(10KB)·
  `mangoi-memory.js`(10KB)는 **게임을 시작한 뒤에만** 쓰입니다. defer 로 내리면 기준선을
  오히려 «내릴» 수 있습니다. 다만 이 화면은 `hubRenderMenu()` 를 파싱 중에 부르므로
  **로드 순서 변경은 별도 PR 로 제대로 검증**해야 합니다(라이브 장애 전력 있음).
- `admin.html`(296)·`index.html`(1550)은 원래 값으로 되돌려 뒀습니다 —
  `--update` 는 세 페이지를 전부 리셋하므로 남의 여유까지 가져오면 안 됩니다.

브라우저 실측이 확인한 것 (문자열 하니스로는 못 보는 것):

- 잠긴 카드 19/21, 자물쇠 칩·해금 안내가 **제목·설명과 한 픽셀도 안 겹침**
- 제목이 `elementsFromPoint` 기준으로 **아무것에도 안 가려짐**(「보인다」와 「안 가려졌다」는 다름)
- 미리보기 창이 열리고 제목·설명·해금 조건·두 버튼이 다 나옴, 자물쇠가 글자를 안 가림
- 레벨테스트 통과를 주입하면 잠긴 카드 **0개**
- 문서가 가로로 안 넘침

### 브라우저 실측이 실제로 잡은 버그 1건

`.locknote` 를 `display:flex` 로 두었더니 390px 에서
**「게 1 클리어하면 열 / 임 개 려요」** 로 쪼개졌습니다. flex 가 글자마디와 `<b>` 를 각각
아이템으로 만들어 따로 줄바꿈한 것입니다. `display:block` 으로 고쳤고,
**CLAUDE.md 2장에 함정으로 등재**했습니다(하니스에도 「줄 수」 검사 추가).

⚠️ 이 버그는 타입체크·회귀 하니스 195개를 **전부 통과한 상태**였습니다.

### 사람이 확인해 주셔야 하는 것

작업 환경(원격 컨테이너)의 프록시가 `mangoi.ai` 를 막아 **배포된 실제 화면은 못 봅니다.**
위 실측은 로컬에서 같은 파일을 렌더한 것입니다. 병합·배포 후:

1. 홈에서 ☰ 를 열어 **사이드바 뒤가 안 비치는지** (특히 **카카오톡으로 링크를 열었을 때**)
2. 게임 목록에서 잠긴 카드의 **자물쇠가 글자를 안 가리는지**, 눌렀을 때 미리보기가 뜨는지
