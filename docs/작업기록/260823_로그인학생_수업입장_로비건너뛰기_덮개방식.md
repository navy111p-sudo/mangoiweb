## 1. 왜 했나

사장님 제보(스크린샷 첨부) — **「로그인 한 학생이 수업 입장할 땐 위의 로그인 표시 없이 바로
수업화면으로 나오게 해 줘」.** 스크린샷은 학생 홈에서 이미 로그인한 계정(`jeong`)인데
수업 입장을 누르자 아이디·비밀번호 칸이 있는 화상통화 로비가 다시 뜬 화면이었다.

### 그 화면은 인증을 하고 있지 않았다 (조사 결과)

「그냥 불편하다」가 아니라, **아무것도 지키지 않으면서 문만 하나 더 세우고 있었다.**

- `js/idx-main.js:2654` — `const vcPassword = document.getElementById('vc-room-input').value.trim();`
  주석에 「인증용으로 저장만 함 (실 운영 시 백엔드 검증)」이라고 적혀 있다.
  이 변수의 **유일한 사용처는 2854행 `localStorage.setItem(…pw, vcPassword)`** 뿐이다.
  서버로 가지 않는다 = 무엇을 넣어도 통과한다.
- 게다가 로그인한 학생에게는 코드가 **비밀번호를 대신 채워 준다** — `'0000'`.
  네 곳이 같은 일을 한다: `index.html`(ph59FillVcInputs 13790행) · `js/idx-main.js:2113` ·
  `index.html:16524` · `js/idx-vc-room.js:283`. 스크린샷의 점 4개가 그것이다.
- CLAUDE.md 2장 「로그인했는데 또 로그인하래요」와 같은 뿌리다(Kaye 17번, Karl Double Login).

부작용도 있었다 — 학생이 「내 비밀번호는 0000」이라고 배우고, 수업 시작 직전 1분에
화면이 하나 더 뜨면 지각·미입장이 되며, 그 미입장이 다시 **「강사 미입장」 오판 알림**
(학생 브라우저가 만드는 기록)으로 이어진다.

### 그런데 자동 건너뛰기는 «이미» 있었다 — 네 벌이나

| 위치 | 언제 도는가 |
|---|---|
| `js/idx-main.js:2105` | `showView('view-videocall-lobby')` 후 **+220ms** |
| `index.html` `mangoiJoinClass` (16396행) | `?room=` · 원클릭, **+350ms** |
| `index.html` `armAutoEnter` (16503행) | +520ms 부터 폴링 |
| `js/idx-vc-room.js:256` `armAutoEnter` | +520ms 부터 폴링 |

넷이 `window.__vcLobbyAutoJoined` 하나로 서로를 막고 있다. 즉 **입장은 이미 자동으로
되고 있었고, 문제는 그동안 로비가 «보인다»는 것**이었다. 220ms 는 사장님 폰에서
눈에 띄는 시간이고, 입장이 막히면(예약 없음·촬영동의 대기) 로비에 그대로 남는다.

## 2. 무엇을 바꿨나

### 새 파일 — `cloudflare-deploy/public/js/idx-vc-fastentry.js`

로비가 열리는 **그 순간(0ms)** 화면 전체를 「🎓 수업에 들어가는 중이에요…」 덮개로 덮고,
결과에 따라 걷는다. **입장은 시키지 않는다** (§3 참조).

| 상황 | 덮개가 하는 일 |
|---|---|
| 수업에 들어감(`body.vc-in-call`) | 덮개만 사라짐 — 학생은 로비를 본 적이 없다 |
| 촬영동의 모달 · 입장시간 대기창이 뜸 | **즉시** 걷는다 (사람이 눌러야 하는 화면이므로) |
| 예약 없음·이미 종료 (`alert`) | 걷고 **이유를 한/영으로 로비에 적고 「⚙️ 방 코드 직접 입력」을 펴 준다** |
| 자동입장이 아예 안 돌았다 | 1.5초 안에 조용히 걷는다 = 예전과 100% 같은 로비 |
| 비로그인 · 학생 키 없음(강사·본사) | 덮개를 아예 안 씌운다 |

안전장치: 3초가 지나면 「로비 화면 보기」 탈출 버튼이 뜨고, 20초면 무조건 걷는다.

### `cloudflare-deploy/public/index.html`

**`<script defer src="/js/idx-vc-fastentry.js?v=1">` 한 줄 + 주석뿐**이다.
인라인 JS 는 한 글자도 안 늘렸다(첫 화면 예산 여유가 5KB 뿐이라).

### 새 검사 — `test-harness/manual/vc-fastentry-browser.mjs` (34건)

실제 Chromium 에 그려서 `elementsFromPoint` 로 «맨 위에 무엇이 있나» 를 잰다.
`test-harness/manual/README.md` 에 사용법을 등재했다.

### `CLAUDE.md` 2장

이번에 밟은 함정을 한 줄 추가했다(§3-D).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### A. 「로비를 아예 안 그린다 / 없앤다」 → 버림

로비는 **유일한 탈출구**를 겸한다 — 「⚙️ 방 코드 직접 입력」. 예약이 없거나 조회가 실패하면
매니저가 방 번호를 주는 것이 실제 운용 경로다. 없애면 막힌 학생이 갈 곳이 사라진다.
그래서 「없애기」가 아니라 **「성공하면 안 보이게」** 로 방향을 잡았다.
막혔을 때의 처리는 사장님이 **①번(로비 + 방 코드 입력)** 을 고르셨다.

### B. 「덮개에서 직접 `vcJoinRoom()` 을 부른다」 → 버림 ⛔

자동입장이 이미 네 곳에 있다. **다섯 번째 입장 경로를 만들면 소켓이 두 개 열려
유령 참가자가 된다** — `js/idx-vc-room.js` 머리말이 그 사고를 그대로 적어 두었다
(「여기서 아이디/비번을 일찍 채우면 뒤따라 도는 mangoiJoinClass 가 한 번 더 입장한다」).
그래서 이 파일은 **입장 로직을 한 줄도 건드리지 않는다.** 화면만 덮는다.
검사 ②-B 가 「덮개가 입장 결과를 바꾸지 않는다」를 못 박는다.

### C. 「자동입장 4벌을 한 곳으로 합친다」 → 이번에는 안 함

CLAUDE.md 가 반복해서 경고하는 «복제된 판정» 형태이므로 합치는 것이 옳다.
다만 그 넷은 **서로 다른 진입 경로**(홈 클릭 · `?room=` · `?meet=`)를 맡고 있고,
합치다 어긋나면 B 의 유령 참가자 사고가 난다. **지시 범위 밖의 큰 수술**이라 이번 PR 에서
분리했다. 별건으로 남긴다(§5).

### D. 「촬영동의 함수(`mangoConsentEnsure`)를 감싸서 덮개를 걷는다」 → 버림 🔴 (실제로 밟음)

처음엔 그렇게 짰다. **정상 입장마다 240ms 에 덮개가 걷혀서 고치려던 로비가 그대로 다시
보였다.** 원인: 그 함수는 **모달을 안 띄우고 그냥 돌아오는 경우가 대부분**이다
(`askedBefore()`·`fetchExisting()` — 이미 동의한 학생 = 거의 전원).
「함수가 불렸다」와 「창이 떴다」는 다른 것이었다.

- ⚠️ **타입체크·회귀 하니스 195건·CI 게이트 4종이 전부 초록불**인 채로 그러고 있었다.
  함수는 «불렸고» 코드도 «맞다». 문자열로는 볼 수 없는 종류다.
- ✅ 지금은 `MutationObserver` 의 **`childList`** 로 `#mangoi-consent-modal`·`#vc-class-gate`
  가 **붙는 순간**을 본다(덮개가 떠 있는 동안만). 200ms 폴링은 그대로 안전망으로 둔다.
- ⚠️ body 의 **class** 를 감시하는 것과는 다르다 — 그건 홈 전체를 멎게 한 전력이 있다(CLAUDE.md).

### E. 「`'0000'` 채우기를 없앤다」 → 이번에는 안 함 ⚠️ (당초 제안에서 뺀 것)

제안 단계에서는 없애겠다고 했으나, 조사해 보니 **load-bearing 이었다** —
`index.html:16414` 의 `if (ni && ni.value && pi && pi.value && …)` 가 비밀번호 칸이
**비어 있지 않을 것**을 원클릭 입장(`?room=`)의 조건으로 쓴다. 지우면 그 경로가 조용히 죽는다.
덮개가 씌워지면 학생은 그 칸을 애초에 못 보므로 「0000 을 내 비번으로 배운다」 문제는
사라진다. 값 자체를 걷어내는 것은 별건으로 남긴다(§5).

### F. 「덮개 z-index 를 제일 위로 올린다」 → 부분적으로만

`2147483001` 로 뒀다 — 「A.i 상담사」 위젯(`2147483000`) **바로 한 칸 위**.
⛔ 더 올리지 않았다. `#mg-fab-wrap`(2147483200)·`#vc-reconnect-banner`(2147483646) 는
덮개보다 **위에 있어야 한다**(재연결 안내가 가려지면 수업이 끊긴 걸 학생이 모른다 — CLAUDE.md).

### G. 「스크롤바까지 덮으려고 `html{overflow:hidden}`」 → 버림 ⛔

`position:fixed` 는 스크롤바 폭(≈15px)을 못 덮는다(PC 1440 에서 1425px 로 측정).
그걸 덮겠다고 루트에 `overflow` 를 걸면 **`position:sticky` 가 통째로 죽는다**
— CLAUDE.md 에 2026-08-19·08-20 두 번의 전력이 적혀 있다. 그냥 둔다.

## 4. 확인한 방법

### 브라우저 검사 (사람이 부르는 것) — **34 통과 / 0 실패**

```
PW_DIR=/tmp/pw node test-harness/manual/vc-fastentry-browser.mjs
```

390×844(폰)과 1440×900(PC) 두 폭. 로컬 `python3 -m http.server` 로 `public/` 을 띄우고
`/api/class/sessions/today`·`/api/consents/` 를 스텁으로 물렸다(**운영 D1 에 아무것도 안 씀**).

- ① 로그인 학생 + 예약 있음 — 0ms 덮개 · 불투명 · 아이디 칸 자리를 덮개가 가림 ·
  `class-9001-YYYYMMDD` 예약방 입장 · 덮개 안 남음
- ②-A 예약 없음 + 학생게이트 ON — 덮개 걷힘 · 이유 한/영 표시 · 방 코드 칸 펴짐·보임
- ②-B 예약 없음 + 학생게이트 OFF(현재 운영값) — **예전 그대로 공용방 입장**, 안내 안 붙음
- ③ 비로그인 — 덮개 안 뜸, 아이디 칸 그대로
- ④ 촬영동의 미기록 — 모달이 뜨고 **덮개가 그 위를 안 덮음**(`elementsFromPoint`)
- ⑤ PC — 화면 덮음(스크롤바 제외) · `position:fixed` · 가로 안 넘침 · A.i 위젯보다 위

**이 검사가 실제로 버그 2건을 잡았다**: §3-D 의 240ms 조기 해제, 그리고 ②-A 의
전제 오류(예약이 없어도 지금은 공용방으로 들어간다는 사실 — 학생게이트가 OFF 라서).
