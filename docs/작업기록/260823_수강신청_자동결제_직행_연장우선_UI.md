③ 검증 결과: **화면·서버·관리자 문서 세 곳이 전부 일치**(수정 불필요).

## 2. 무엇을 바꿨나

### `cloudflare-deploy/src/api-pay.ts`

- **`POST /api/pay/billing/charge-now` 신설** — 등록된 빌링키로 **결제창 없이 즉시 결제**.
  1·3·6·12개월 지원(기간할인 동일 적용). 로그인 필수(rt 연장토큰 불가 — renew-link 3경로 규칙 유지).
  더블클릭 방어: `last_billed_at` 60초 안이면 429.
- **`chargeSubscriptionOnce(env, sub, months=1)`** — months 파라미터 추가.
  청구 성공 후 `next_billing_at` 을 «등록 +30일» 이 아니라 **«새 수강 종료일 3일 전»**(`nextBillingFromLastDate`)으로.
  구독의 `amount` 는 개월 수와 무관하게 **월 견적**으로 기록(화면이 «매월 ○원» 으로 읽는 값).
- **`billing/confirm`** — 첫 청구일도 «현재 수강 종료 3일 전» 기준으로(수업 공백/이른 청구 방지).
- **`activateEnrollment` → `syncSubscriptionNextBilling`** — 결제창으로 수동 연장한 학생의 구독 청구일도
  새 종료일 기준으로 재동기화(미리 3개월 결제했는데 옛 날짜에 또 청구되는 사고 방지).
- **`sendPrebillNotices`** — cron 스윕(라이브일 때만)에서 결제 3일 전 학부모 폰에
  «○일에 ○원 자동결제 예정 + 해지 안내» 문자. 멱등 = `enroll_notify_log (kind='prebill', day=결제예정일)`.
  전화번호 조회는 만료문자와 같은 곳(`students_erp` parent_phone→phone). 링크는 `siteUrl()`.

### `cloudflare-deploy/public/enroll.html`

- **상단 ← 뒤로 / 🏠 홈** — `#app` **밖**에 둠(미로그인·링크만료 화면이 `app.innerHTML` 을 갈아치워도 남는다).
  인앱 브라우저는 히스토리가 없을 수 있어 `history.length>1 ? back() : '/'` 폴백.
- **연장 카드(`#stRenew`)를 폼 맨 위로** 이동(기본 display:none 이라 신규 방문자 화면은 그대로).
- **`body.renew-first` 모드** — 로그인 학생이 수강 중이면 신규 폼·하단 결제바를 접고 연장 카드만.
  「➕ 다른 요일·시간·강사로 새로 신청하기」 버튼이 유일한 복귀 문. rt(문자 링크) 모드는 기존 renew-only 그대로.
- **구독 있으면(`SUB`) 연장 버튼이 결제창 대신 charge-now** — confirm(금액·개월 표시) 뒤 즉시 결제.
- **카드 등록 직후 «지금 바로 1개월 결제» 제안** — 거절해도 종료 3일 전 자동 결제라 손해 없음.
- 제목 이모지 → **`/img/mango-char.png`(Mr.Mango)**, JS 로 그리는 제목 3곳도 동일.
- 문구를 «자동연장» → «자동결제» 로, «매월 자동» → «수업 종료 3일 전 자동 + 사전 문자 안내» 로.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **자동결제 전용 «별도 페이지»** ← 버림. 같은 성격 화면이 늘어나면 「화면마다 답이 다른」 사고가
  시작된다(CLAUDE.md 2장 — 관리자 화면 4벌 함정). 이미 검증된 rt 연장 전용 모드(클래스로 폼 접기)와
  같은 방식의 `renew-first` 클래스로 해결.
- **cron 자동청구를 이 PR 에서 켜기** ← 안 함. `billing:auto_renew_live` KV 킬스위치는 오청구 방지로
  일부러 둔 것이고, **실돈 스위치는 사람이 결정**(4-1-1 표의 「CI 가 판단 못 하는 것」).
  대신 사람이 버튼을 눌러 시작하는 charge-now 는 수동 「연장 결제」와 같은 급의 동의라 스위치와 무관하게 동작.
- **카드 등록(confirm) 때 서버가 무조건 첫 달 청구** ← 버림. 수강 중간에 자동결제만 켜려는 학생에게
  한 달 이른 청구가 된다. 등록 후 **confirm 대화상자로 물어보고** 원할 때만 charge-now.
- **`next_billing_at` 을 계속 +30일로 두기** ← 버림. 회차제라 구독 기준일이 수강 종료일과 어긋나면
  «수업 공백»(종료가 먼저) 아니면 «이른 청구»(청구가 먼저)가 난다. 종료일−3일로 통일하고,
  수동 연장·빌링 청구·카드 등록 세 경로가 전부 같은 함수(`nextBillingFromLastDate`)를 쓴다.
- **사전고지 문자를 dry-run 때도 보내기** ← 버림. 청구가 안 나가는데 «결제 예정» 문자를 보내면 거짓말이 된다.
- **topnav 를 #app 안에 두기** ← 버림. 미로그인 화면이 `app.innerHTML` 을 통째로 갈아 버튼이 사라진다.
- **연장토큰(rt)으로 charge-now 허용** ← 안 함. `renew_link_harness` 가 «rt 는 3경로만» 으로 못 박고 있고,
  카드 결제 지시는 진짜 로그인 뒤에만.

## 5. 남은 것 / 주의할 것

- ✅ (같은 날 후속) **자동청구 스위치를 관리자 화면에서 켜고 끌 수 있게 함** — 관리자 › 「💳 정기결제 자동화」
  카드에 「♾️ 자동청구 마스터 스위치」. 청구 예정 미리보기(누가·얼마, 읽기 전용 `GET /api/admin/billing/auto-renew-due`)를
  보고 confirm 뒤 토글(`POST /api/admin/billing/auto-renew-live`, **본사 hq 스코프만** — 강사는 scope 'none' 이
  canEditOrg 를 통과하는 함정 때문에 isTeacher 로 따로 막음). wrangler CLI 없이 사장님이 직접 결정·실행.
  ⚠️ 미리보기에 cron-check(POST)를 쓰면 안 된다 — 스위치가 켜져 있으면 그 자리에서 실청구가 나간다.
  스윕 dry-run 응답에도 대상자 상세(`due` 목록)를 넣었다. 스위치를 켜는 판단 자체는 여전히 사람 몫.
- 이미 등록된 옛 구독(있다면)의 `next_billing_at` 은 +30일 기준 그대로다 — 다음 청구·수동 연장 때
  종료일 기준으로 자동 보정된다(`syncSubscriptionNextBilling`).
- 사전고지 문자의 «해지» 는 로그인 후 enroll.html 에서만 가능. 학부모 폰(비로그인)용 토큰 해지 경로는
  별건 과제(rt 토큰 스코프 확장은 renew_link_harness 규칙과 함께 설계해야 함).
- Mr.mango 캐릭터는 다른 화면 제목에도 순차 적용할 수 있다(이번엔 enroll.html 만).
