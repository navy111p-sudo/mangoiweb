## 1. 왜 했나

배포된 화면을 보시고 사장님이 물으셨습니다 — **「이상호 두 개는 무슨 차이야?」**

같은 이름이 두 표에 나란히 나와 있었습니다.

| 어디 | 무엇 |
|---|---|
| 「🏪 거래처별 합계」 | 이상호 · 지사수수료 · **₩514,477** · 건수 2 |
| 「🧾 출금 내역」 | 2026-07-31 17:54 · 이상호 · 지사수수료 · **₩235,481** |

**둘 다 맞는 숫자**입니다 — 위는 2건 합계, 아래는 그중 한 건(나머지는 ₩278,996).
구분하는 단서는 「건수 2」 칸 하나뿐이었고, **스크롤하면 표 제목이 안 보여** 더 헷갈렸습니다.

> 🔑 이건 버그가 아니라 **화면이 스스로 설명하지 못한 것**입니다. 숫자가 맞아도
> 「무슨 차이냐」를 사람이 물어야 한다면 그 화면은 아직 덜 된 것입니다.

## 2. 무엇을 했나

### 2-1. 합계 줄이 «합계» 라고 스스로 말한다

- 표 헤더 「금액」 → **「합계 금액」**
- 2건 이상이면 금액 밑에 작게 **「2건 합계」**
- 표 아래에 한 줄: 「이 표는 «합계» 입니다 … 아래 「출금 내역」 표는 «한 건» 씩입니다」

### 2-2. 이름을 누르면 그 자리에서 개별 건이 펼쳐진다

`▸ 이상호` 를 누르면 바로 아래에 그 거래처의 개별 건(일시·적요·계정과목·금액)이 펼쳐집니다.
다시 누르면 접힙니다.

- **서버를 다시 부르지 않습니다** — 그 달 전건이 이미 `_data.rows` 에 있습니다
- **묶는 키를 서버와 똑같이** 맞췄습니다(`payee || remark || '(적요 없음)'`).
  여기서 다르게 묶으면 **「합계는 2건인데 펼치면 1건」** 같은 어긋남이 조용히 생깁니다
- **1건짜리 거래처는 누를 수 없게** 했습니다 — 펼칠 것이 없는데 누르게 두면
  「눌렀는데 아무 일도 안 일어남」이 됩니다
- **펼친 상태는 다시 그려도 유지**됩니다 — 계정과목을 지정하면 화면 전체가 재조회되는데,
  그때 접혀 버리면 하던 일을 놓칩니다

## 3. 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| **개별 건을 별도 API 로 가져오기** | 그 달 전건이 이미 payload 에 있다. 왕복만 늘고 «합계와 개별이 다른 시점 자료» 가 될 위험이 생긴다 |
| **두 표 중 하나를 없애기** | 둘은 쓰임이 다르다 — 합계는 «어디에 많이 나갔나», 내역은 «언제 얼마가 나갔나». 없애면 한쪽 쓸모가 사라진다 |
| **펼치기를 `<button>` 으로** | `details.menu-card button` 전역 규칙이 **인디고 그라데이션 알약 + `padding:9px 18px`** 로 만든다(CLAUDE.md 2장). 표 칸 안에서 레이아웃을 밀어낸다 |
| **hover 에 확대(`transform`) 주기** | ⛔ 1-3 「hover 확대 금지」. 강조는 **색과 밑줄만**, 크기·위치는 고정 |
| **색을 인라인 `style` 로** | 전역 CSS + 페인터가 `!important` 로 갈아엎는다. `admin-inline-c.css` 맨 끝 `#acc-bankacct` 꼬리 블록에 넣었다 |

브라우저 검사에 넣은 것 — 씨앗을 **«한 거래처 2건»** 으로 바꿔 사장님이 보신 상황을 그대로 재현했습니다:

- 합계 줄에 「2건 합계」가 적히는가 · 헤더가 「합계 금액」인가 · 설명 줄이 있는가
- 2건 이상만 누를 수 있고 **1건짜리는 못 누르는가**
- 눌렀을 때 **합계 건수만큼**(2건) 나오는가 · 개별 금액이 맞는가
- **계정과목 지정 뒤 재조회해도 펼침이 유지**되는가
- 다시 누르면 접히는가
- 누를 수 있다는 것이 **실제로 색으로 보이는가**(`getComputedStyle` 실측 — 전역 CSS·페인터가 덮던 자리)

⏳ **배포된 실제 화면은 여전히 못 봅니다**(프록시가 `mangoi.ai` 차단). 사람이 한 번 봐야 끝납니다.

## 5. 함께 눈에 띈 것 (고치지 않음)

출금 내역의 **잔액이 마이너스**입니다(₩-2,281,098 → ₩-2,386,034).
두 줄의 계산은 서로 맞으므로(−2,281,098 − 104,936 = −2,386,034) **데이터가 어긋난 것은 아닙니다.**
마이너스 통장이면 정상이고, 아니라면 바로빌이 준 잔액 값을 봐야 합니다.
