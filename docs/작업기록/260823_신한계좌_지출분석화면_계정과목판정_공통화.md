## 2. 무엇을 했나

### 2-1. 🧭 계정과목 판정을 «한 곳» 으로 (가장 중요)

이 판정은 원래 `monthActualOpex()` **안에만** 있었습니다. 그대로 화면을 만들면
화면은 DB 의 `category`(9종)를, 손익계산서는 계정과목(13종)을 보게 되어
**같은 달인데 두 화면의 분류가 어긋나는** 구조였습니다.

그래서 `src/accounting-reports.ts` 에 함수로 뺐습니다:

- `loadExpenseAccountRules(env)` — 지정표(`expense_payee_category`) + 지사 대표자명을 한 번에 읽음
- `resolveExpenseAccount(rules, remark, storedCategory)` — 행 하나 → 계정과목
- `expenseRoleOf(account)` — 그 과목이 손익계산서에서 어떻게 취급되는가
  (`opex` 포함 / `dup` 중복제외 / `moved` 다른 줄로 / `review` 확인 필요)

`monthActualOpex()` 가 이제 그 함수를 씁니다. **판정 규칙이 한 벌뿐이라 두 화면이 갈라질 수 없습니다.**
(같은 뿌리의 선례: `src/no-show-truth.ts`)

### 2-2. 새 API — `GET /api/admin/reports/bank-expenses?month=YYYY-MM`

돌려주는 것: KPI 요약 · 계정과목별 합계 · 거래처별 합계 · 출금 전건 · 12개월 추이 · 연동 상태.

### 2-3. 화면 — 「🏦 신한 계좌 입출금 (지출 분석)」

`admin.html` 회계관리 카드 안, 「💳 법인카드 사용내역」 바로 다음.
로직은 `public/js/adm-bankacct.js` (신규, `defer`).

KPI 4개 · 계정과목 도넛 · 12개월 막대 · 계정과목별 표 · 거래처별 표(20) · 출금 내역 표.

## 3. 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| **`/api/admin/bankacct/expenses` 로 만들기** | 계정과목 판정이 `accounting-reports.ts` 에 있다. 거기 두면 손익계산서와 «같은 함수» 를 쓰는 것이 코드 배치로도 드러난다. 덤으로 `/api/admin/reports/` 는 인증 게이트·강사 차단에 이미 등록돼 있어 **`src/index.ts`(공동 금지구역)를 안 건드려도 된다.** |
| **DB 의 `category` 를 계정과목으로 덮어쓰기(UPDATE)** | 지정한 것이 바로 반영되지 않고 동기화(배포 권한자만 실행)를 기다려야 한다. 원본을 건드리지 않고 «읽을 때» 판정하는 지금 방식이 맞다. |
| **입금(kind='in')도 함께 그리기** | ⛔ 「케이씨피M」·«운영자금 보충»·«성격 미확인 입금» 은 2026-08-18 사장님 지시로 매출·회계 화면에서 **전부 뺀 것**이다. 입금 표를 그리면 그게 그대로 되살아난다. 이 화면은 «출금» 전용. |
| **`adm-core.js` 에 로직을 넣기** | 이미 굵고, 이 화면은 회계 담당만 여는 카드다. 별도 파일 + `defer`. |
| **KPI 증감을 «색으로만» 말하기** | 아래 4-2 참고 — 테마에 따라 KPI 타일이 어두운 면이 되고, 그때 페인터가 빨강을 읽히는 색으로 바꾸는 것이 **맞다.** 그래서 ▲▼ 기호를 함께 쓴다. |
| **`.bk-sig` 를 `adm-light-surfaces` 의 `SKIP_SEL` 에 등재** | 한 번 넣었다가 **되돌렸다.** 그 페인터는 «대비가 3 미만일 때만» 고치는 가독성 구제라, 예외로 빼면 어두운 타일 위에 **안 읽히는 빨강**이 그대로 박힌다. |

## 4. 브라우저로 눈으로 찾은 것 (타입체크·하니스는 전부 초록이었음)

`test-harness/manual/bank-expenses-browser.mjs` (신규, 26건)로 실제 Chromium 에 그려서 쟀습니다.

### 4-1. 🪤 `getBoundingClientRect()` 가 1.3배로 나옴 — **거짓 실패**

차트 래퍼는 `height:220px` 인데 rect 로는 **286px**. `body{zoom:1.3}` 때문입니다.
레이아웃 값은 **`offsetHeight`** 로 재야 합니다. (검사 쪽을 고쳤고, 화면은 정상이었습니다.)

### 4-2. 🔴 인라인 색이 화면에 안 나옴 — **진짜 버그**

`color:#b91c1c` 로 적은 빨강이 실제로는 **`rgb(248,250,252)`**(흰빛)로 나왔습니다. 세 겹입니다:

1. `admin-inline-c.css` 8743·8744 행 — `[id^="card-"]` 안 글자를 `#101828 !important`
2. `.kpi-tile *` — `rgb(249,250,251) !important`
3. `js/adm-s13.js` 의 `fixTextOnDark()` — 대비<3 이면 인라인 `!important` 로 다시 칠함

**고친 방법 (2026-08-21 참관·직접입장 버튼 건과 같은 방식):**

- 뜻이 있는 색은 클래스로(`.bk-sig`, `.bk-role-*`)
- 값은 `admin-inline-c.css` **맨 끝**에 **조상 id 를 앞에 붙여**(`#acc-bankacct …` = ID 한 칸) 정의
  → 클래스를 아무리 쌓은 규칙도 ID 칸을 못 이긴다
- KPI 타일처럼 «어두운 면이 될 수 있는» 자리는 색에 기대지 않고 **▲▼ 기호**로 방향을 말한다

⚠️ **코드만 보면 색이 있는 줄 압니다.** 판정은 반드시 브라우저 `getComputedStyle` 로.

### 4-3. 카드가 «보이지 않아» 검사가 실패

관리자 카드는 `adm-ia6.js` 가 `ia6-hide` 로 **한 번에 한 장만** 보여 줍니다.
`waitForSelector` 는 `state:'attached'` 로 기다리고, 띄우는 것은 `jumpToMenu('card-accounting-mgmt')` 로.
