## 2. 무엇을 했나

### 2-1. 🧭 계정과목 판정을 «한 곳» 으로 (가장 중요)

이 판정은 원래 `monthActualOpex()` **안에만** 있었습니다. 그대로 화면을 만들면
화면은 DB 의 `category`(9종)를, 손익계산서는 계정과목(13종)을 보게 되어
**같은 달인데 두 화면의 분류가 어긋나는** 구조였습니다.

그래서 `src/accounting-reports.ts` 에 함수로 뺐습니다:

- `loadExpenseAccountRules(env)` — 지정표(`expense_payee_category`) + 지사 대표자명을 한 번에 읽음
- `resolveExpenseAccount(rules, remark, storedCategory)` — 행 하나 → 계정과목
- `expenseRoleOf(account)` — 그 과목이 손익계산서에서 어떻게 취급되는가
  (`opex` 포함 / `dup` 중복제외 / `moved` 다른 줄로 / `review` 확인 필요)

`monthActualOpex()` 가 이제 그 함수를 씁니다. **판정 규칙이 한 벌뿐이라 두 화면이 갈라질 수 없습니다.**
(같은 뿌리의 선례: `src/no-show-truth.ts`)

### 2-2. 새 API — `GET /api/admin/reports/bank-expenses?month=YYYY-MM`

돌려주는 것: KPI 요약 · 계정과목별 합계 · 거래처별 합계 · 출금 전건 · 12개월 추이 · 연동 상태.

### 2-3. 화면 — 「🏦 신한 계좌 입출금 (지출 분석)」

`admin.html` 회계관리 카드 안, 「💳 법인카드 사용내역」 바로 다음.
로직은 `public/js/adm-bankacct.js` (신규, `defer`).

KPI 4개 · 계정과목 도넛 · 12개월 막대 · 계정과목별 표 · 거래처별 표(20) · 출금 내역 표.

## 3. 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| **`/api/admin/bankacct/expenses` 로 만들기** | 계정과목 판정이 `accounting-reports.ts` 에 있다. 거기 두면 손익계산서와 «같은 함수» 를 쓰는 것이 코드 배치로도 드러난다. 덤으로 `/api/admin/reports/` 는 인증 게이트·강사 차단에 이미 등록돼 있어 **`src/index.ts`(공동 금지구역)를 안 건드려도 된다.** |
| **DB 의 `category` 를 계정과목으로 덮어쓰기(UPDATE)** | 지정한 것이 바로 반영되지 않고 동기화(배포 권한자만 실행)를 기다려야 한다. 원본을 건드리지 않고 «읽을 때» 판정하는 지금 방식이 맞다. |
| **입금(kind='in')도 함께 그리기** | ⛔ 「케이씨피M」·«운영자금 보충»·«성격 미확인 입금» 은 2026-08-18 사장님 지시로 매출·회계 화면에서 **전부 뺀 것**이다. 입금 표를 그리면 그게 그대로 되살아난다. 이 화면은 «출금» 전용. |
| **`adm-core.js` 에 로직을 넣기** | 이미 굵고, 이 화면은 회계 담당만 여는 카드다. 별도 파일 + `defer`. |
| **KPI 증감을 «색으로만» 말하기** | 아래 4-2 참고 — 테마에 따라 KPI 타일이 어두운 면이 되고, 그때 페인터가 빨강을 읽히는 색으로 바꾸는 것이 **맞다.** 그래서 ▲▼ 기호를 함께 쓴다. |
| **`.bk-sig` 를 페인터 `SKIP_SEL` 에 등재** | 한 번 넣었다가 **되돌렸다.** 그 페인터들은 «대비가 모자랄 때만» 고치는 가독성 구제라, 예외로 빼면 어두운 타일 위에 **안 읽히는 빨강**이 그대로 박힌다. ⚠️ 되돌린 뒤 **주석 두 곳에 「등재했다」가 그대로 남아 있었다** — 함정 대조가 잡아 고쳤다(「했다고 적힌 것」과 「실제로 된 것」이 다른, CLAUDE.md 2장 그 함정). |
| **「🔄 계좌 동기화」 버튼** | 한 번 넣었다가 **뺐다.** `POST /api/admin/bankacct/sync` 는 적재만 하는 게 아니라 끝에서 `UPDATE bankacct_transactions SET category=?` 로 **전 기간 소급 재분류**를 한다. D1 은 개발·운영이 같은 DB 이고(CLAUDE.md 1-1), 지금까지 그 UPDATE 를 도는 것은 밤 자동 동기화뿐이었다. 버튼을 붙이면 본사 관리자 누구나 브라우저에서 돌릴 수 있게 된다. **조회만으로 화면은 충분하다** — 새 거래는 밤에 들어오고, 계정과목 지정은 «읽을 때» 판정이라 동기화를 안 기다린다. |

`color:#b91c1c` 로 적은 빨강이 실제로는 **`rgb(248,250,252)`**(흰빛)로 나왔습니다.

3. `js/adm-s13.js` 의 `fixTextOnDark()` — 대비<3 이면 인라인 `!important` 로 다시 칠함

**고친 방법 (2026-08-21 참관·직접입장 버튼 건과 같은 방식):**

- 뜻이 있는 색은 클래스로(`.bk-sig`, `.bk-role-*`)

## 6. 2단계 — 거래처 표에서 그 자리에서 계정과목 지정

### 6-1. 왜

「무엇을 지정해야 하는지」는 이 표를 봐야 아는데, 지정 화면(「🏷️ 지출 계정과목 분류」)은
카드 아래 따로 있습니다. 두 화면을 오가면 **금액이 큰 것부터 처리하기가 어렵습니다.**
그래서 보는 자리에서 바로 정하게 했습니다.

### 6-2. 무엇을

- 거래처 표에 「계정과목 지정」 칸 신설. 고르면 바로 저장 → **화면 전체 재조회**
  (계정과목이 바뀌면 KPI·도넛·계정과목 표·내역 표가 전부 따라 움직여야 하므로)
- 저장은 **기존 API 그대로** `POST /api/admin/reports/payees` — 지정 화면과 규칙이 갈라질 수 없음
- 서버가 payload 에 두 가지를 새로 실어 보냄:
  - `can_assign` — 본사(hq)인가. **화면 감추기와 서버 403 은 둘 다 필요**하다(서버만 있으면
    «눌러도 안 되는 칸» 이 남고, 화면만 있으면 URL 로 뚫린다)
  - `assignable` — 그 거래처에 «저장된 1차 분류가 「기타출금」인» 행이 있는가

### 6-3. `assignable` 이 왜 필요했나 ← 안 넣었으면 「저장이 안 된다」가 됐을 것

`resolveExpenseAccount()` 는 저장된 `category` 가 **「기타출금」일 때만** 쪼갭니다.
급여이체·카드대금처럼 은행 적요로 이미 분류가 붙은 행은 **지정해도 안 바뀝니다.**
그런데 **에러가 안 납니다** — 저장은 성공하고 화면만 그대로입니다.

그대로 뒀으면 사장님이 「신한카드」에 「지급수수료」를 지정해 놓고
「저장이 안 된다」고 하셨을 겁니다. 그래서 서버가 미리 알려 주고, 화면은 그런 거래처에
칸 대신 **「은행 적요로 이미 분류됨 — 지정해도 안 바뀝니다」** 를 적습니다.

### 6-4. 브라우저가 또 진짜 버그를 잡았습니다 — 저장 실패 되돌리기가 **무효**

실패했을 때 고른 값을 되돌리려고 `var prev = sel.value` 를 썼는데, 그건 `change` 가
발화한 **뒤**라 **이미 바뀐 값**이었습니다. 되돌려도 같은 값이라 아무 일도 안 일어나고,
저장에 실패했는데 화면에는 고른 값이 그대로 남아 **«저장된 줄» 아는 상태**가 됩니다.
→ 그릴 때 `data-prev` 에 원래 값을 적어 두고 거기서 되돌립니다.
(⚠️ 타입체크·하니스로는 안 보입니다 — 코드도 조건도 다 «있습니다». 값이 틀렸을 뿐입니다.)

### 6-5. 2단계에서 지킨 것

- **낙관적 갱신 금지** — 서버가 «저장했다» 고 답한 뒤에만 다시 그립니다
- **실패는 말로** — 403·통신 오류를 안내줄에 그대로 적습니다(조용히 두면 저장된 줄 압니다)
- **«지난 출금까지 바뀐다»를 반드시 알림** — 표 아래 안내줄. 모르고 누르면 지난달
  손익계산서가 움직입니다
- ⚠️ 이 D1 쓰기는 1단계에서 뺀 sync 버튼과 **성격이 다릅니다** — 학생 데이터가 아니라
  «설정표»(`expense_payee_category`)이고, 기존 「🏷️ 지출 계정과목 분류」 패널에서
  사람이 이미 하던 바로 그 동작입니다. 새로 생긴 위험이 아니라 **자리만 옮긴 것**입니다

계좌 출금은 임대료·보험·구독료처럼 **매달 같은 곳에 비슷한 금액**이 나가는 것이 많습니다.

**판정** — 당월 포함 4개월 창에서 그 거래처가 **3개월 이상** 나왔고 월별 합계의
**최대/최소가 ×1.25 이하**면 「고정비」. 3개월 이상이지만 금액이 흔들리면
「반복(금액 변동)」, 나머지는 「변동비」.

⚠️ **회계 기준이 아니라 «패턴 추정»** 입니다. 그래서 화면이 근거(몇 달 나왔는지 · 금액 폭 ×N)를
같은 줄에 함께 그리고, 창 기간을 표 아래에 밝힙니다. 자료가 4개월치 없는 초기에는 대부분
「변동비」로 나오는데 그건 틀린 게 아니라 **«아직 모른다»** 는 뜻입니다.

⚠️ **«매달 나온다»만으로 고정비라고 하면 안 됩니다** — 금액이 2.4배 흔들리는 카드대금이
고정비가 되면 「고정비는 그대로인데 변동비만 늘었다」는 판단이 통째로 틀어집니다.
그래서 반복과 고정을 갈랐습니다.

### 7-2. 📈 전월 대비 증감 Top 5

⚠️ **이번 달에 «없어진» 거래처도 넣습니다.** 정기결제가 끊긴 것·지사수수료가 안 나간 것은

## 8. 2단계 함정 대조가 잡은 것 (3단계와 함께 반영)

| 지적 | 조치 |
|---|---|
| 🔴 `<select>` 인라인 style 이 **통째로 죽음** — `[id^="card-"] select{…!important}` 가 이겨서 11px→**13.5px**, 여백 3px 5px→**8px 12px**, max-width 150px→**100%** | 크기·테두리를 CSS 꼬리 블록(`#acc-bankacct td select.bk-assign`)으로 옮김. `box-sizing:border-box` 함께 명시 |
| 🔴 안내줄·설명 글자 색이 **`#101828` 로 눌림** — 「지난 출금까지 바뀐다」가 경고로 안 읽힘 | `.bk-note`·`.bk-note-mute` 클래스 + 꼬리 블록 |
| 🟡 「기타출금」 = DELETE 인데, **지정이 없던 거래처**에서 고르면 아무것도 안 지워지고 «성공» 으로 보임 | 라벨을 «지정 지우기» 로 밝히고, 지울 것이 없으면 **고를 수 없게**(`disabled`) |
| 🟡 적요가 빈 행(`(적요 없음)`)은 저장해도 **영영 안 먹음** | 서버에서 `assignable=false` 로 — 칸을 아예 안 냄 |
| 🟡 저장 중 두 번째 선택이 **조용히 버려짐** | 「아직 저장 중입니다」를 알리고 값을 되돌림 |
| 🟡 휠·방향키만으로도 `change` 가 발화해 운영 DB 에 즉시 쓰임 | **확인 대화상자** 추가(「지난 출금까지 함께 바뀝니다」). 취소하면 원래 값으로 |
| 🟡 낡은 주석 — 「계정과목 지정은 지출 계정과목 분류에서 하며」 | 2단계 사실에 맞게 갱신 |

**그리고 이 사고들을 다음에도 잡도록** 브라우저 검사에 **`getComputedStyle` 실측**을
넣었습니다([9] 6건 — 글자 크기·여백·box-sizing·max-width·경고색·설명색).

## 8-2. 3단계 함정 대조 (🔴 0건 · 🟡 6건 — 고칠 수 있는 것은 전부 반영)

| 지적 | 조치 |
|---|---|
| 🟡 **「기타출금」 옵션이 selected + disabled** → 닫힌 select 에 **「기타출금 (지정 지우기)」가 «현재 계정과목»** 인 것처럼 보임. 「기타출금」이 계정과목 목록에도 있어서, 이 화면이 줄이려는 바로 그 거래처(아직 미지정)가 그렇게 됨 | 라벨에 «지정 지우기» 를 붙이는 것은 **지울 것이 있을 때(`assigned`)뿐**으로. 검사도 보강 — **닫힌 select 가 무엇을 보여 주는지**를 재게 했고(`selectedIndex` → 표시 문자열), **변이시험으로 그 검사가 옛 버그를 실제로 잡는 것**을 확인 |
| 🟡 고정비 판정에 **«이번 달은 아직 진행 중»** 이 근거에 안 적힘 — 한 달에 여러 번 나가는 곳은 월 중반에 금액 폭이 부풀어 「고정비」가 「반복」으로 내려앉음 | 서버가 `recurring.period_in_progress` 를 함께 주고, 화면 안내에 그 한 줄을 덧붙임. ⛔ **판정을 흔들지 않았다** — 진행 중인 달을 판정에서 빼면 창이 3개월로 줄어 「3개월 이상」이 «세 달 모두» 가 되어 더 빡빡해진다 |
| 🟡 `assignable=false` 인데 `assigned=true` 면 **이 화면에서 지정을 지울 칸이 없음**(«(지정됨)» 배지는 뜸) | 설명에 **«지우려면 아래 「🏷️ 지출 계정과목 분류」에서»** 를 덧붙여 막다른 길로 보이지 않게. (그 화면에서는 지울 수 있으므로 진짜 막힌 것은 아님) |
| 🟡 `asset-versions.json` 에 **어느 HTML 도 안 쓰는 `?v=3` 잔재** | 원장에서 제거(참조 0건 확인). 나중에 v=3 을 다시 쓰면 «내용이 다른데 같은 번호» 로 헷갈림 |
| 🟡 증감 칸이 `krw(...).slice(1)` 로 **₩ 를 떼어** 같은 표의 다른 금액과 표기가 어긋남 | ₩ 를 그대로 둠 |
| 🟡 하니스 ⑦ 의 입금 누출 검사가 **시트 «이름» 만** 봄 — 다른 이름으로 담으면 안 걸림 | **내용까지** 검사(「케이씨피M」·«운영자금 보충»·«확인필요 입금»·«성격 미확인») |
| 🟡 4개월 창 확대 — 규칙 위반은 없으나 **실데이터 행수는 «확인 못 함»** | 그대로 둠. 바인드 2개 · 새 `IN` 없음 · 실행계획 동일이고, 바뀐 것은 «가져오는 행 수 약 4배» 뿐. ⚠️ **배포 권한자가 한 번 확인해 주세요** — `SELECT substr(trans_at,1,7) ym, COUNT(*) FROM bankacct_transactions WHERE kind='out' GROUP BY ym` |
| 🟡 `?format=csv` 는 요약 한 장만 나감 | 그대로 둠 — 이 저장소의 기존 동작이고(`out()` 이 csv 일 때 extra 시트를 버림) 화면에는 xlsx 버튼만 냈음 |

**대조가 «문제없음» 으로 확인해 준 것** — 엑셀에 「케이씨피M」 누출 0건 · 공동 금지구역 무접촉 ·
새 쓰기 API 없음(강사·지사 차단이 export 에도 그대로) · D1 `UPDATE`/`DELETE` 추가 0건 ·
바인드 2개 · 지난 달 행이 이 달 표에 안 섞임(변이시험으로 확인) · 고정비 경계값(0 나눗셈·자료 없음·
연도 넘김·합계 정합) 안전 · `confirm()` 은 인앱 브라우저에서 표준 동작 · **거짓 주석 0건** ·
새 하니스가 «조용히 통과» 하지 않음(변이 2건으로 확인).
