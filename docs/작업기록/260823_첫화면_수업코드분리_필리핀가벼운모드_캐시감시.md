## 2. 무엇을 바꿨나

### [1번] 캐시 헤더 — **코드는 한 줄도 안 고쳤다**

확인해 보니 이미 되어 있었다. `src/index.ts:2150` 이 2026-07-22 부터 `?v=` 붙은 js/css 를
1년 immutable 로, 2026-08-14 부터 이미지·폰트·소리·영상에도 캐시 지시를 준다.
→ **`test-harness/asset_cache_policy_harness.mjs`(5건) 신설.** 이 줄이 사라져도 화면은 똑같이
나오고 «느려질 뿐» 이라 아무도 눈치 못 채고, 느려진 것은 «회선 탓» 으로 오해된다.

### [4번] 필리핀 = 가벼운 모드 — 새로 만들지 않고 **있던 것을 고쳤다**

`window.mgIsSlowNet()`(2026-07-23, 같은 CDO 콜센터 대책)에 구멍이 둘 있었다.
① `navigator.connection` 은 크로미움 전용 → **아이폰 강사는 이 보호를 한 번도 못 받았다.**
   기기 시간대(`Asia/Manila`)를 한 번 더 본다.
② 정의가 문서 아래쪽(4590행)이라 `<head>` 의 배경 고르기에서 못 불렀다 → `<head>` 로 올렸다(정의는 한 벌).
가벼운 모드에서 빼는 것: 큰 배경 그림 40~147KB(`html.mg-lite` CSS 가 끈다) + 홍보 영상 353KB(기존 분기).
시험용 강제 `?lite=1` / `?lite=0`.

### [5번] `idx-main.js` 851KB 를 «홈» 과 «수업» 으로 가르기

- `js/idx-main.js` **451KB**(홈) + `js/idx-main-vc.js` **402KB**(수업, `defer`)
- 옮긴 것: 최상위 `function vc*` 선언 · `window.vc*=` 대입 · vc 를 직접 가리키는 최상위 리스너/타이머 **235덩어리**
- 본문은 한 글자도 고치지 않았다. 옮기기만 했다.
- **첫 화면 blocking 1,557 → 1,159KB.** 예산 기준선도 1550 → 1159 로 **내렸다**(올린 게 아니라 내린 첫 사례).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **나라별로 다른 HTML(cf.country)** ← 버렸다. 화면이 갈리면 「필리핀에서만 나는 버그」가 시작되고
  한국에서 재현이 안 된다(관리자 화면 4벌 함정). 나라를 안 가르고 «스위치» 로 풀었다.
- **`ph-lite` 라는 새 클래스·새 판정 함수** ← 버렸다. `mgIsSlowNet()` 이 이미 있었다.
  새로 만들면 판정이 두 벌이 되어 한쪽만 고쳐지는 사고가 시작된다.
- **함수 선언만 옮기기** ← 실패했다. `window.vcManualReconnect = vcManualReconnect;` 같은
  **최상위 내보내기 줄 80개**가 홈 쪽에 남아 부팅 중 `ReferenceError`. 실험에서 잡았다.
  → 대입·리스너·타이머까지 함께 옮기니 통과.
- **수업 코드를 «들어갈 때 받기»(동적 로드)** ← 이번엔 안 했다. 그래야 **바이트도** 아끼는데,
  입장 경로 전부(`vcJoinRoom`·자동입장·데모방·참관)가 «있는 함수» 를 전제로 짜여 있어 전부 손봐야 한다.
  defer 는 **첫 그림을 안 막을 뿐 받기는 그대로 받는다** — 이 차이를 흐리지 않으려고 기준선 주석에 적어 뒀다.
- **하니스 2건이 깨진 것을 «예외 처리» 로 넘기기** ← 안 했다. 깨진 이유가 «분해하면 깨지는» 구조적
  문제(어느 파일에 있는지·바로 다음 줄이 무엇인지에 기대는 검사)라, 검사 쪽을 고쳤다.

## 6. 🪤 새로 배운 함정 — 「분해하면 하니스가 깨진다」의 2차판

`page-source.mjs` 머리말이 이미 경고한 그것이다(2026-08-09: 762KB 를 옮겼더니 하니스 17개가
동시에 깨졌다). 이번에도 **14개**가 깨졌고, 원인이 두 종류였다.

**① `idx-main.js` 를 «파일 하나» 로 직접 읽는 하니스 (10개)**
   → 두 파일을 이어서 읽게 고쳤다. `page-source.mjs` 를 쓰면 애초에 안 겪는다.

**② «붙어 있는 다음 줄» 로 함수 끝을 찾는 하니스 (4개)**
   `slice(시작표시자, 다음줄표시자)` 방식이라 코드가 옮겨져 사이가 벌어지면 끝을 못 찾고
   **파일 끝까지 훑어** 통째로 죽는다. 셋은 «중괄호를 세어 끝을 찾기» 로 바꿨고
   (코드가 어디로 가든 맞는다), `vc_defaults` 는 «설정 블록» 자체가 두 조각으로 갈려
   두 조각을 이어 보게 했다.

⚠️ **다음에 또 분해할 사람에게** — 새 하니스는 처음부터
   `readPageSource('index.html')` 로 읽고, 함수를 떼어낼 때는 «다음 줄» 이 아니라
   **중괄호를 세세요.** 그 두 가지만 지키면 이 14개짜리 뒷정리가 없습니다.
