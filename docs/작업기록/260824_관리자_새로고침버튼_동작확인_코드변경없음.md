- **날짜** 2026-08-24 (UTC 기준 · 한국시간 8/25 새벽)
- **작업자** navy111p (Claude Code)
- **브랜치** `claude/admin-homepage-refresh-ebcuie`
- **바꾼 파일** 없음 (코드 변경 0) · 이 문서 + `CLAUDE.md` 2장 한 줄 + `docs/INDEX.md` 등록만

## 1. 왜 했나

사장님이 관리자 화면 우하단 스피드다이얼 스크린샷에 **파란 ↻ 버튼만 빨간 동그라미**를 치고
물어보셨다.

> 「여러분 관리자가 관리자 홈페이지에 새로 고침 되긴 되는 거야.」

버그 신고가 아니라 **「이게 진짜 동작하긴 하냐」는 확인 요청**이다.
그런데 이 저장소에는 그렇게 물어볼 만한 전례가 실제로 여러 건 있다 —
「비밀번호 변경」이 `alert()` 만 띄우던 시연 껍데기 **네 벌**, 직원 등록이 `localStorage` 에만
쓰던 것, 참관 중 카메라를 숨기려던 `#vc-bottom-toolbar` 가 **죽은 id** 였던 것.
그래서 **「코드에 있으니 된다」로 답하면 안 되는 질문**이었다.

## 2. 무엇을 바꿨나

**아무것도 안 바꿨다.** 확인해 보니 정상 동작해서 고칠 것이 없었다.
대신 「어디를 보면 되는지」를 남긴다.

| 무엇 | 어디 |
|---|---|
| 동작 정의 `window.admRefresh()` | `cloudflare-deploy/public/admin.html` **314~333행** |
| 버튼에 클릭 리스너 바인딩 | 같은 파일 **336~339행** (`#adm-refresh-fab`) |
| 버튼 마크업 (스피드다이얼 맨 위) | 같은 파일 **658~665행** |
| 스피드다이얼 스타일 | `cloudflare-deploy/public/css/admin-inline-c.css` **14~110행** (`#mi-speed-dial`, z-index 9992) |

`admRefresh()` 는 그냥 F5 가 아니라 **하드 리프레시**다. 순서대로:

1. 등록된 **서비스워커 전부 해제**(`getRegistrations()` → `unregister()`)
2. **캐시 전부 삭제**(`caches.keys()` → `caches.delete()`)
3. `sessionStorage.clear()`
4. 주소에 `?_cb=<현재시각ms>` 를 붙여 `location.replace()` 로 이동

버튼은 2026-06-18 에 통합 스피드다이얼(`#mi-speed-dial`) 안으로 **자리만 옮겼고**,
`id` 를 그대로 둬서 옛 바인딩이 살아 있다. 그 설계가 실제로 유지되고 있음을 확인했다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

**① 코드만 읽고 「정의돼 있으니 됩니다」라고 답하기 — 버렸다.**
위 1장의 전례(시연 껍데기 4벌·죽은 id) 때문에 이 저장소에서는 그 답이 신뢰를 못 받는다.
특히 이번 건은 `id` 만 남기고 마크업을 딴 자리로 옮긴 구조라, **버튼이 리스너를 못 받는
경우가 실제로 가능한 모양**이었다. 눌러 보는 것 말고는 확인이 안 된다.

**② 배포된 `mangoi.ai` 를 열어 확인 — 불가능.**
작업 컨테이너의 프록시가 그 도메인을 막는다(`CLAUDE.md` 4-1-1). 시도하지 않았다.

**③ `playwright-core` 로 크로미움 구동 — 버렸다.**
`CLAUDE.md` 2장이 권하는 방법인데, **이 컨테이너에는 `node_modules` 자체가 없다**
(`npm ci` 미실행). `find / -name playwright-core` 0건.
→ 크로미움을 `--remote-debugging-port=9222` 로 띄우고 **CDP 를 직접** 말했다.
Node 22 에는 `WebSocket` 이 전역으로 들어 있어 라이브러리 없이 된다.

**④ `window.location.replace` 를 후킹해서 「이동했다」를 잡기 — 실패해서 버렸다.**
첫 시도에서 이렇게 짰는데, 최신 크롬은 `Location` 의 메서드 재정의를 막는다.
**예외도 안 나고 조용히 원본 그대로**였다(후킹 확인 결과 `false`).
그대로 믿었으면 「클릭해도 아무 일도 안 일어난다」고 **오진**할 뻔했다.
→ `Page.frameNavigated` 이벤트 + **클릭 후 `location.href` 를 다시 읽는** 방식으로 바꿨다.

**⑤ 「안 눌리니 버튼을 다시 만들자」 — 버렸다.**
첫 클릭이 안 먹은 진짜 이유는 버튼이 아니라 **화면을 덮고 있던 환영 오버레이**였다
(아래 4장). 코드 문제가 아니어서 고칠 것이 없었다.

**⑥ 라벨 오타(「세로고침」) 수정 — 안 했다. 오타가 아니었다.**
스크린샷에는 「세로고침」처럼 보였지만 저장소 전체 grep 결과 **0건**이고
소스는 「새로고침」이다. 스크린샷 해상도 문제였다. 없는 버그를 만들 뻔했다.

## 4. 확인한 방법

`cloudflare-deploy/public` 을 `python3 -m http.server 8899` 로 그대로 서빙하고,
컨테이너에 이미 있는 `/opt/pw-browsers/chromium-1194/chrome-linux/chrome` 를
헤드리스로 띄워 **실제 마우스 좌표로 클릭**(`Input.dispatchMouseEvent`)했다.

| 확인 항목 | PC 1440×900 | 휴대폰 390×844 |
|---|---|---|
| `typeof window.admRefresh` | `function` | — |
| 버튼 `__admBound`(리스너 바인딩) | `true` | — |
| 접힘 상태 `pointer-events` | `none` | — |
| 펼친 뒤 `pointer-events` / `opacity` | `auto` / `1` | `auto` / `1` |
| 클릭 지점 맨 위 요소(`elementsFromPoint`) | `BUTTON#adm-refresh-fab` | `BUTTON#adm-refresh-fab` |
| 버튼 위치 | 78×78, 화면 안 | 54×54, 화면 안 |
| **클릭 후 주소** | `admin.html?_cb=1787273155651` | `admin.html?_cb=1787273196882` |
| 캐시 개수 (클릭 전 → 후) | **3개 → 0개** | — |
| `sessionStorage` 값 | 있음 → **삭제됨** | — |

클릭 전 캐시 3개는 `mangoi-20260813015745-fresh`, `mangoi-assets-v1`, 테스트용 1개였다.

**타입체크·회귀 하니스는 돌리지 않았다** — 소스 코드 변경이 0건이라 해당 사항이 없다.
(이 문서와 `CLAUDE.md`·`INDEX.md` 등록 뒤에는 하니스를 돌려 확인한다.)

**사람 확인** — 사장님이 「이제 잘 된다」고 확인해 주셨다.

## 5. 남은 것 / 주의할 것

- ⚠️ **접혀 있으면 절대 안 눌린다.** `#mi-speed-dial` 이 닫힌 상태의 액션 버튼은
  `pointer-events:none` 이다. 아바타(트리거)를 먼저 탭해 펼쳐야 한다.
  「눌렀는데 반응 없다」 제보의 1순위 원인.
- ⚠️ **첫 화면에서는 환영 오버레이(`#aw-overlay.aw-on`)가 화면 전체를 덮는다.**
  헤드리스 첫 시도에서 클릭이 그쪽으로 먹혔다(맨 위 요소가 `IMG#aw-img`).
  실제 사용자도 그 안내를 닫기 전에는 못 누른다.
- ℹ️ **이 버튼은 그 브라우저의 캐시·서비스워커를 오리진 전체 기준으로 지운다.**
  홈 화면(`sw.js`)의 캐시까지 함께 사라진다. **누른 본인 기기에만** 해당하고
  다른 사람 화면과는 무관하며, 그 기기에서 홈 화면 다음 로딩이 한 번 느려지는 정도다.
  「캐시 비우고 최신」이라는 툴팁대로의 의도된 동작이라 고치지 않았다.
- 📌 헤드리스로 「진짜 눌리는지」를 확인하는 이 방법(로컬 서버 + CDP 직접)은
  이번에 정리한 것이라 `CLAUDE.md` 2장에 한 줄 넣어 두었다.
