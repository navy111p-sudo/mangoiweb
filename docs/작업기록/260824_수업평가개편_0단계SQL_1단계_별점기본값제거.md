# 수업평가 리포트 개편 — 0단계 확인 SQL 준비 + 1단계 별점 기본값 제거 (2026-08-24)

## 왜 했나

사장님 제보에서 출발: «평가항목이 한 가지뿐이면 학생의 나이·학년·수준을 고려하지 않아
편파적이고 비객관적일 것 같다». 코드로 확인해 보니 사실이었다 —

- 강사 「1분 수업 일지」(teacher.html)의 별점은 **참여도·이해도 2개뿐**이고,
  둘 다 **기본값 4가 미리 찍혀** 있어 안 만지면 그대로 전송된다 → 사실상 변별력 0.
- DB(`student_evaluations`)와 학부모 화면(eval.html)은 말하기·숙제·태도까지 5칸을
  이미 지원하는데 강사 화면이 2칸만 쓰고 있었다.
- 나이·학년·수준이 평가에 반영되는 곳은 한 군데도 없다.

타사 5곳(51Talk·Novakid·Cambly Kids·Cambridge YLE·국내 주니어) 조사 후
**「뼈대(축 5개)는 하나, 문항·기준만 연령 밴드 3개」 + 「매수업 라이트 / 월간 딥」** 안을
제안했고 사장님이 채택. 추가 지시: **AI가 최대한 평가하게 해서 강사 시간과 주관을 줄일 것.**
제안서 정본: [../수업평가_리포트_개편_제안서_2026-08-24.html](../수업평가_리포트_개편_제안서_2026-08-24.html)

## 무엇을 했나

1. **0단계 — 데이터 확인 스크립트** `cloudflare-deploy/scripts/eval-phase0-select.ps1` (SELECT만)
   - 학년(grade) 채움율·값 분포 → 밴드 자동 배정 가능성 판단
   - 별점 분포(참여4·이해4 조합 비율) → «기본값이 그대로 쌓인다» 가설 검증
   - AI 평가 원료 재고: `chat_messages`·`recordings`·`feedback_drafts`·`homework`·`review_quiz_results`·`leveltest_applications`
   - ⚠️ **원격 컨테이너에는 Cloudflare 토큰이 없어 여기서 못 돌린다**(실측 — env 에 CF 토큰 없음).
     배포 권한 PC에서 한 번 실행하고 결과를 클로드에게 붙여 주면 2단계 설계를 확정한다.
     (선례: 260820 레벨테스트 정리 — SQL 준비까지만, 실행은 사람 PC)
2. **1단계 — 별점 기본값 4 제거** (teacher.html `stars()`)
   - 안 고르면 그 항목은 null(«미평가»)로 저장. eval.html 은 null 항목을 안 그리므로
     학부모에게 거짓 점수가 나가지 않는다.
3. **1단계 — 말하기(score_speaking) 별점 노출** (teacher.html 일지 모달 + payload + composeFromChips)
   - 서버(`/api/eval/create`)와 eval.html 은 이미 이 칸을 지원하고 있어 화면 3곳만 고쳤다.
4. **웹푸시 문구 수리** (api-lessons.ts) — 별점 미선택이면 overall 이 null 이라
   «종합 점수 null/10» 이 나갈 뻔 → 점수 문구 생략. 겸사겸사 «/10» 오기를 실제 척도 «/5» 로.
5. 제안서 v2 — «AI 자동 평가» 장 추가(축별 자동화 소스 표 + 흐름 + 유의점).

## 검토했다가 버린 방법

- **태도·숙제 별점을 강사 화면에 수동으로 추가** — 제안서 1단계 원문에는 있었지만,
  같은 날 «AI가 최대한 평가, 강사 시간 축소» 지시가 와서 뺐다. 숙제는 homework 테이블,
  참여도는 출석+채팅으로 자동 산출할 자리라 수동 입력을 늘리는 것은 방향 역행.
- **연령×수준 완전 다양화(양식 6~9종)** — 강사가 양식을 외워야 하고, 축이 달라지면
  지난달과 비교가 끊기며, 유지보수가 양식 수만큼 늘어 기각.
- **원격 컨테이너에서 D1 직접 SELECT** — CF 토큰이 없어 불가. wrangler 로그인도 프록시 환경에서 무리.
- **기본값을 3으로 낮추기** — 기본값이 있는 한 «안 만진 평가»가 그 숫자로 쌓이는 구조 자체가
  문제라, 숫자를 바꾸는 게 아니라 기본값을 없앴다.
