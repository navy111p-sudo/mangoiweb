# 🧱 신한 계좌 화면 — 다섯 구역 구분선 굵게 + 네 표에 정렬·필터

*2026-08-24 · 사장님 제보 「선이 흐려서 잘 보이지 않아」 + 「모두 필터를 달아줘」*

---

## 1. 왜 했나

배포된 「🏦 신한 계좌 입출금 (지출 분석)」 화면을 보시고 두 가지를 요청하셨습니다.

1. **「하위 메뉴들이 서로 선이 흐려서 잘 보이지 않아. 각각의 그룹들이 분명하게 보이게 선을 좀더 굵게 해줘」**
   — 고정비·변동비 / 전월 대비 증감 / 계정과목별 합계 / 거래처별 합계 / 출금 내역
   다섯 구역이 전부 똑같은 `1px solid #e5e7eb` 라 스크롤하면 경계가 안 보였습니다.
2. **「모두 필터를 달아줘. 오름차순, 내림차순, 같은 이름 등등 분류」**

## 2. 무엇을 했나

### 2-1. 구분선 — 구역은 굵게, 표 안은 얇은 그대로

- 다섯 구역(`.bk-sec`)에 **2px 테두리 + 왼쪽 6px 색 띠**(구역마다 다른 색) +
  구역 사이 여백 22px + 제목 밑줄 2px. 색 띠만 보고도 어느 구역인지 압니다.
- ⛔ **표 «안» 줄은 굵히지 않았습니다** — 줄이 굵어지면 숫자가 더 안 읽힙니다.
  브라우저 검사가 「표 안 줄은 얇은 그대로인가」를 함께 재서 못 박았습니다.

### 2-2. 정렬 — 법인카드 표와 같은 조작

- 네 표(고정비·계정과목·거래처·출금내역)에 **헤더 클릭 정렬**
  (한 번=내림, 두 번=오름, 세 번=해제, Shift+클릭=2차 키). 화면마다 조작이
  다르면 그게 또 혼란이라 이미 있는 `.pr-th` 방식을 그대로 따랐습니다.
- 지금 무슨 순서인지 제목 옆 **칩**으로 말하고 ✕ 로 해제합니다.
- **증감 표에는 정렬을 안 달았습니다** — «증감 큰 순» 이 그 표의 존재 이유라
  순서를 바꾸면 뜻이 없어집니다. 대신 「▾ 전체 보기」로 Top 5 너머를 봅니다.
  더 볼 것이 없으면 그 글자를 아예 안 내밉니다(눌러도 아무 일 없는 것 방지).

### 2-3. 필터 — 서버를 다시 부르지 않는다

- 검색창(거래처·적요)과 분류 드롭다운(성격 / 손익계산서 취급 / 계정과목).
  계정과목 목록은 **그 달에 실제로 나온 과목만** 채웁니다 — 안 나온 과목을
  고를 수 있으면 빈 표가 되어 「검색했는데 아무것도 없다」가 됩니다.
- 「같은 이름 분류」는 거래처별 합계 표(+ ▸펼치기)가 이미 그 역할이라 중복 구현하지 않았습니다.
- 거르면 위 KPI(그 달 전체)와 표가 어긋나 보이므로 **「N건 중 M건 · 표시 중 합계 ₩…」**를
  표마다 적습니다.
- 거래처 표는 거르고 **나서** 상위 20을 자릅니다 — 먼저 자르면 21번째부터는 검색해도 영영 안 나옵니다.

## 3. 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| 표 안 줄까지 굵게 | 숫자 가독성이 죽는다. 가르는 것은 «구역» 이다 |
| 증감 표에도 정렬 헤더 | «증감 큰 순» 이 존재 이유 — 순서를 바꾸면 표의 뜻이 사라진다 |
| `ph-frn-filter-js` TABLES 에 등록해 자동 검색창 받기 | 그 필터는 MutationObserver 가 다시 그린 행을 또 걸러서, 정렬·펼치기로 다시 그릴 때마다 어긋난다(2장 「검색창이 두 개」 함정) |
| 필터를 서버 쿼리로 | 그 달 전건이 이미 payload 에 있다. 왕복만 늘고 «합계와 목록이 다른 시점 자료» 가 될 위험 |
| 정렬 해제를 `<button>` 으로 | `details.menu-card button` 전역 규칙이 인디고 알약(padding 9px 18px)으로 만들어 제목줄을 밀어낸다 |

## 4. 이번에 새로 잡은 함정 — 페인터가 «테두리 색» 까지 덮는다

구분선을 CSS 로 적어도 화면에는 다섯 구역 전부 흐린 회색(`rgba(15,23,42,0.1)`)으로
나왔습니다. 범인은 `js/adm-s13.js` 페인터 — 구역 상자의 계산된 배경이 (옛 다크 규칙에
덮여) 어두웠기 때문에 상자를 밝게 다시 칠하면서 **`border-color` 를 인라인
`!important` 로 함께** 덮은 것입니다. 인라인 `!important` 는 어떤 CSS 도 못 이기므로,
**칠해지지 않게 배경을 CSS 꼬리 블록에서 흰색으로 못 박아** 원천 차단했습니다
(배경이 처음부터 밝으면 페인터의 `isDarkGray()` 가 거짓이라 손대지 않습니다).
⛔ 페인터를 고치거나 예외 등재로 풀지 않았습니다 — 그건 가독성 구제입니다.

덤: `body{zoom:1.3}` 때문에 테두리 굵기가 2px → 1.538px 로 «계산» 됩니다(기기 픽셀
반올림 후 역산). 그래서 검사는 절대값이 아니라 **「표 안 줄 대비 몇 배인가」** 로 잽니다.
