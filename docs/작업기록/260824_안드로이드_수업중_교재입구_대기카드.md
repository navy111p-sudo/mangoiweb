- 브랜치: `claude/android-book-upload-bug-2xdawn`
- 파일: `cloudflare-deploy/public/js/idx-vc-wait-actions.js`(새로 만듦, defer),

## 1. 왜 했나 — 제보

안드로이드 폰으로 **체험수업**에 들어간 매니저(`mgr_karl`) 제보:

> 「교재를 쓰려는데 **라이브러리에서도, 폰 파일에서도** 올릴 수가 없다」

첨부 스크린샷에는 미스터망고 대기 카드와 함께
「📚 Pick a textbook from the Library · 라이브러리에서 교재를 선택하세요」가 떠 있었다.
즉 **화면이 시키는 그 일을 할 방법이 화면에 없었다.**

## 2. 실제로 무엇이었나 — 실측

헤드리스 Chromium 390×844(세로) · 수업 중 · 강사 역할 · 교재 탭에서 잰 값:

| 입구 | 상태 |
|---|---|
| 교재 툴바 `.pdf-controls`(📁 교재 업로드 · 📎 파일 업로드 · 📚 라이브러리) | ≤1024px 에서 `ph49-collapsed` → **display:none** |
| 탭바 「📚 교재도구 ▾」 칩 | **x = 735** (화면 폭 390) |
| 탭바 「📖 교재 고르기」(`#vc-lib-open-btn`) | **x = 1157** |
| 가로용 하단 폴더 바 `vcFolderOpen('material')` | 세로에서 display:none |
| 「☰ 기능」 FAB | (297, 791) — **화면 안에 있는 유일한 것** |

탭바는 `clientWidth 390` 인데 `scrollWidth 1865` 다. 즉 입구들은 «있지만» 전부
옆으로 밀어야 나오고, 그걸 알 길이 없다. 남은 하나인 「☰ 기능」은 이름만으로는
교재가 그 안에 있다는 걸 알 수 없다(누르면 탭바가 큰 그리드로 펼쳐지고, 거기 들어 있다).

📜 **CLAUDE.md 2장의 「탭바 칩이 x 659~870 이라 폰에서 안 보인다」와 같은 뿌리다.**
2026-08-20 에 그 함정을 밟고 「📖 교재」 버튼만 탭바 맨 앞으로 되살렸는데,
**라이브러리·업로드 입구는 여전히 x≥735 에 남아 있었다.**

⚠️ 코드·문자열 하니스로는 절대 안 보인다 — 버튼은 «존재하고» onclick 도 «맞다».
틀린 건 좌표뿐이다(CLAUDE.md 「화면 좌표가 틀린 버그를 하니스가 못 잡음」).

## 3. 검토했다가 버린 방법

| 방법 | 왜 안 했나 |
|---|---|
| **탭바에서 `#vc-lib-open-btn` 를 맨 앞으로 옮기기** | `public/index.html` = 공동 금지구역이고, 탭바 순서는 2026-08-20 에 「📖 교재를 반드시 맨 앞에」로 못 박은 자리다. 그 앞에 하나 더 끼우면 그때 고친 것이 다시 밀린다. 게다가 폰 탭바에 들어갈 자리가 애초에 1~2개뿐이라 «다음에 또 밀리는» 구조가 그대로 남는다 |
| **폰에서 `.pdf-controls` 접힘(`ph49-collapsed`)을 풀기** | 그 툴바는 버튼이 15개다. 390px 화면에서 펴면 교재가 보일 자리를 통째로 먹는다. 접어 둔 것이 2026-07-14 사장님 지시(「모바일 수업화면 최대한 깨끗하게」) |
| **「☰ 기능」 메뉴 안내 토스트를 띄우기** | 문제는 «모른다» 가 아니라 «두 단계 건너에 있다» 는 것. 수업 중 강사가 눌러야 할 횟수가 줄지 않는다 |
| **`idx-vc-textbook.js` 안에 코드 넣기** | 그 파일은 blocking 이고 index.html 첫 화면 예산 여유가 **1,164바이트**뿐이다(실측). CLAUDE.md 지시대로 **별도 파일 + defer** 로 뺐다 |
| **버튼을 카드 «흐름대로 맨 아래» 두기** | 처음엔 그렇게 만들었는데, 9점 실측에서 떠 있는 듀얼 시계 `#mgWorldClock`(z-index 2147483000)이 390·360·412 세로 전부에서 버튼 왼쪽을 덮었고, 가로 740×360 에서는 독의 「•••」(`#vc-dock-more`)가 버튼 **한가운데**를 덮었다. `#vc-wait-card` 가 `z-index:8` 로 자기 쌓임 맥락을 만들기 때문에 **안에서 z-index 를 올려서는 못 이긴다** → 「겹치지 않는 자리」(카드 맨 위)로 옮기는 것이 유일한 해법 |
| **라벨을 「📚 라이브러리에서 고르기」로 길게** | 390px 에서 두 줄로 접히고, 그만큼 카드 위를 비우다 보니(padTop 102px) 미스터망고와 안내문이 266px 짜리 카드 밖으로 **잘렸다.** 「📚 교재 고르기」·「📁 내 파일 올리기」로 줄여 한 줄에 맞췄다 |

## 4. 한 일

교재가 없을 때 뜨는 **그 대기 카드 맨 위**에 입구 두 개를 붙였다.

- 「📚 교재 고르기 / Choose textbook」 → `openTextbookLibrary()`
- 「📁 내 파일 올리기 / Upload a file」 → `triggerUpload('pdf')`

지킨 것:

- **강사·관리자에게만** 보인다 — 판정은 정본 `vcCanControlTextbook()` 하나로.
  두 함수가 안에서 같은 판정으로 다시 거르므로, 다른 기준을 쓰면 「보이는데 거절당하는」 버튼이 된다
- `#vc-wait-card` 는 `pointer-events:none` 이라(아래 ◀▶ 화살표용) 상자·버튼에 `auto` 를 되돌린다
- `data-ko`/`data-en` 을 그릴 때 함께 박아 🌐 를 따라가게 했다(「JS 로 그린 라벨」 함정)
- **상주 `setInterval` 을 안 늘렸다** — 대기 카드가 이미 600ms 마다 도는
  `window.vcWaitCardSync()` 를 감싸서 같은 틱에 얹었다
- `triggerUpload` 는 사용자 제스처 «안에서 동기로» `#pdf-upload.click()` 을 부른다.
  ⛔ `setTimeout` 으로 미루면 안드로이드 크롬이 파일창을 안 열 수 있다
- 이모지는 📚(U+1F4DA)·📁(U+1F4C1) — 둘 다 Unicode 6.0(Win10 두부 방지)

## 6. 남은 일 (이번 범위 밖)

- **교재를 한 번 연 뒤에는** 대기 카드가 사라지므로 이 입구도 함께 사라진다.
  수업 중 교재를 «바꾸려면» 여전히 「☰ 기능」 → 「📚 교재도구」/「📖 교재 고르기」를 거쳐야 한다.
  폰 탭바에 상시 입구를 두는 것은 자리 다툼이 있어(2026-08-20 「📖 교재」 맨 앞 규칙) 사람이 정해야 한다
- 폰 탭바가 `scrollWidth 1865` 인 것 자체가 구조적 문제다.
  옆으로 밀 수 있다는 신호(그림자·화살표)가 하나도 없다 — 별건 과제
