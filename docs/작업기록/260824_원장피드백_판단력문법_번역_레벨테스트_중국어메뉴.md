# 이보영 학원 원장 피드백 6건 → 실행 계획 1~4번 수정

- 날짜: 2026-08-24
- 작업자: Claude (사장님 지시)
- 브랜치 / PR: `claude/english-app-feedback-3xkw10`

## 1. 왜 했나

이보영 학원 원장님이 폰으로 학생 앱을 둘러보고 6가지를 지적했다
(분석 보고서: `docs/이보영학원_원장피드백_분석보고서_2026-08-24.pdf`).

1. 웜업 「뜻」이 "Let's warm up before class" → **「수업 전에 따뜻하게하자」** 직역
2. 영어 앱인데 **중국어 복습퀴즈**가 메뉴에 떠서 "뭐지" 싶음
3. 판단력 훈련 보기에 **마침표 등 문장부호 누락**
4. "Can I buy?" → "Can I buy it?" 이 맞음 (목적어 빠짐)
5. "want play" → "want to play" (**문법 오류**)
6. **레벨테스트**가 처음엔 있었는데 다시 못 찾음

사장님 추가 지시: 「문법은 최대한 고도화 — 영어교육 기관이라 문법 실수는 안 된다」.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **(지적 2) 서버에서 중국어 수강생 판별** — 버림. `class_schedules`·`students_erp` 어디에도
  «이 수업/학생이 중국어» 라는 구조화된 칸이 없다(교재 이름·강사 국적뿐 → 추측 조인은
  «남의 이름» 함정과 같은 뿌리). 새 API 를 만들면 `src/index.ts`(공동 금지구역) 등록이 필요.
  → 화면 신호 2개로 판별: ① `mangoi_lang='zh'` ② 중국어 퀴즈 화면을 연 적 있음(`mangoi_zh_learner`).
  직접 주소·AI 명령 검색으로는 여전히 열리고, 한 번 열면 그 뒤로 메뉴에도 보인다.
  localStorage 접근 불가 환경에서는 **보이는 쪽**(수강생이 기능을 잃는 쪽이 더 나쁨).
- **(지적 2) index.html 의 버튼 3곳을 직접 수정** — 버림. 공동 금지구역 + 첫 화면 예산 여유가
  194B 라 코드를 넣을 수 없다. → 이미 로드되는 `idx-allmenu.js` 에서 숨김.
  「AI와 친구하기」 목록은 처음 열 때 생성되므로 body **childList** MutationObserver 로
  붙는 순간 한 번 가리고 disconnect (⚠️ body class 감시는 홈 전체를 멎게 한 전력 — CLAUDE.md 2장).
- **(지적 3·4·5) 문법 오류 시 재생성(retry)** — 버림. 기존 재시도 4회 루프에 얹으면 실패가
  누적될 때 «문제를 아예 못 주는» 쪽으로 기운다. → 교정 호출이 **문장을 고쳐서** 살린다.
  교정이 뜻까지 바꾸는 것은 `keepsMeaning()`(원문 단어 50% 잔존 + 길이 2배 이내)으로 차단 —
  오답 보기의 «일부러 어긋난 말투» 를 공손하게 «고쳐버리면» 문제 자체가 망가지기 때문.
  교정 호출 실패 시엔 원문 그대로 출제(문제를 못 주는 것이 더 나쁘다 — 기존 재시도 철학).
- **(지적 1) 웜업 전 문장을 사람이 번역** — 불가. AI 가 실시간 생성하는 대화라 고정 사전이
  안 된다. 고정된 건 첫인사뿐 → 첫인사만 선탑재, 나머지는 chat 모드(화상수업 채팅 번역과
  같은 경로, 존댓말·숙제 오역 방지 프롬프트 이미 검증됨).
- **(지적 1) KV 의 옛 직역 캐시 삭제** — 불필요. chat 모드는 캐시 키 접두사가 다르다
  (`trc4:` ↔ `tr:`, `api-mango.ts` 2041행). 경로를 바꾸는 순간 옛 캐시는 자연히 안 읽힌다.

## 4. 확인한 방법

- 타입체크: `node node_modules/typescript/bin/tsc --noEmit` → 통과 (exit 0)
- 회귀 하니스: `node test-harness/run.mjs --fast` → **PASS 198 / SKIP 20 / FAIL 0**
  (asset_version_harness 가 `idx-allmenu.js?v=5` 원장 등록)
- 실제 크로미움 렌더 15건 (로컬 http.server + API 스텁, `/opt/pw-browsers` 크로미움):
  - 비수강생: 중국어 버튼 전부 숨김(드로어·퀵버튼 2곳 + 늦게 생기는 「AI와 친구하기」 목록까지),
    전체메뉴에 중국어 타일 없음 / `mangoi_zh_learner=1` 후 전부 복귀
  - 전체메뉴 「레벨 테스트」 타일 존재, `?placement=1` 진입 시 곧장 「레벨 찾기 1/6」
  - 문제 화면 「레벨 다시 재기」 버튼 노출 + 클릭 시 배치테스트 시작
  - 웜업 첫인사 「뜻」 = 사람이 쓴 한국어(번역 API 0회 호출), 새 문장 「뜻」 은 `mode:'chat'` 로 발신
- ⚠️ **2차 문법 검수(polishScenarioEnglish)는 실제 Workers AI 로는 미검증** — 로컬에 AI 바인딩이
  없다. 배포 후 `/judgment.html` 에서 문제 몇 개를 뽑아 보기 문장을 눈으로 확인해야 한다.

## 5. 남은 것 / 주의할 것

- **배포 후 사람 확인 필수**: 판단력 훈련 보기 문법(2차 검수 실동작), 웜업 「뜻」 한국어 품질.
- 2차 검수로 문제 생성이 **LLM 호출 2회**가 됐다 — 체감 +1~2초. 미리 받아두기(prefetch)가 있어
  일반 풀이는 티가 안 나지만, 배치테스트 6문항은 문항마다 기다린다. 느리다는 제보가 오면
  배치 문항만 검수 생략(원래 판단력 지수에 안 들어가는 문항)이 첫 후보.
- 중국어 복습퀴즈가 **처음부터 안 보이는 것이 정상**이 됐다. 중국어 수업 학생에게는
  `/review-quiz-cn.html` 링크를 한 번 안내해야 그 뒤로 메뉴에 보인다(강사·매니저 공지 필요).
- 전체메뉴의 「중국어 발음 코치」 타일은 이번에 안 건드렸다(지시 범위 밖). 같은 조건을 달지는
  사람이 결정.
- 문법 100% 보장은 즉석 생성 구조에선 불가능 — 근본 해결은 보고서 실행 계획 6번(검수된 문제은행).
- chat 모드 번역은 **응답 첫 줄만** 취하고 max_tokens 300 이다(`api-mango.ts` 주석의 note 모드 경고와
  같은 성질). 웜업 말풍선은 한 덩어리 문장이라 보통 한 줄로 번역돼 문제없지만, «여러 줄» 뜻이
  잘렸다는 제보가 오면 note 모드처럼 별도 모드를 검토할 것 (trap-check 지적).
