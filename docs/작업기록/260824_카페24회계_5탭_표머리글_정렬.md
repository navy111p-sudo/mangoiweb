# 「카페24 회계 실데이터」 다섯 탭 표에 정렬(올림순·내림순) 달기

- 날짜: 2026-08-24
- 브랜치: `claude/card-menu-numbering-g1x6n5`
- 건드린 곳: `cloudflare-deploy/public/js/adm-core.js`(c24FinLoad 주변) · `cloudflare-deploy/public/admin.html`(안내 줄 한 개 + `?v=` 올림) · `cloudflare-deploy/public/css/admin-inline-c.css`(맨 끝 강조 블록)
- 새 검사: `test-harness/manual/c24-finance-sort-browser.mjs`(브라우저 50종 — **자동으로 안 돕니다, 사람이 부릅니다**)

## 1. 왜 했나

사장님이 관리자 › 회계관리 › 「🧾 카페24 회계 실데이터」 화면을 캡처해서
탭 다섯 개(📒 회계장부 · 💵 급여명세 · 🧾 지출결의 · 🏛 세금계산서 · 💳 예치금)와
그 아래 **표 머리글 줄**(일자·구분·계정과목·금액·거래처·적요·귀속월)에 동그라미를 치시고
「이 카드 안에 있는 메뉴들에 필터를 만들어 달라 — 번호가 아니라 필터, **내림순·올림순**」이라고 하셨습니다.

그 표는 서버가 준 순서(날짜 내림차순 1,000건)를 그대로 그리기만 했습니다.
그래서 「이번 달 제일 큰 지출이 뭔가」·「어느 거래처가 많이 나오나」를 보려면
사람이 눈으로 훑는 수밖에 없었습니다.

## 2. 무엇을 했나

**표 머리글이 곧 정렬 단추입니다.** 한 번 누르면 올림순 ▲, 다시 누르면 내림순 ▼,
한 번 더 누르면 **원래 순서**(서버가 준 날짜 내림차순)로 돌아옵니다.
다섯 탭 모두에 붙고, 칸 목록이 탭마다 다르므로 탭을 바꾸면 정렬은 초기화됩니다.

- 금액 칸(₩ 서식이 붙은 칸)과 근무일은 **숫자로** 비교합니다.
  글자로 비교하면 `₩45,000` 이 `₩5,000,000` 보다 커집니다.
- 글자 칸은 `localeCompare(…, 'ko', {numeric:true})` — 한글 가나다 + 「2 · 10」 같은 숫자 섞인 이름 처리.
- **빈 값은 방향과 상관없이 늘 아래로.** 내림순으로 뒤집었더니 빈 칸(—)이 맨 위를 덮는 일을 막습니다.
- 오른쪽에 「정렬: 금액 · 내림순 ▼」처럼 **말로도** 적습니다(`#c24fin-sortnote`).
  화살표만으로는 «올림순인지 내림순인지»가 안 읽히고, 관리자 화면은 글자색을 통째로 덮는
  CSS 가 여러 겹이라 색에 기대면 안 됩니다(CLAUDE.md 2장 「카드 안 글자에 색을 줬는데」).
- 정렬은 **이미 받아 온 행을 다시 그리는 것**입니다 — 서버를 다시 부르지 않습니다.

⚠️ 서버가 `limit=1000` 으로 잘라 준 목록을 정렬하는 것이라, 「제일 큰 금액」이 아니라
**「가져온 1,000건 중 제일 큰 금액」** 입니다. 건수 줄에 «(표시된 건 기준)» 이 붙는 이유와 같습니다.

## 3. 검토했다가 버린 방법

1. **표 위에 «정렬 기준» 드롭다운 + «올림/내림» 버튼을 따로 두기**
   → 버림. `admin-inline-c.css` 의 전역 규칙이 카드 안 `button`(파란 그라데이션 `!important`,
   `padding:9px 18px`)과 `select`(`padding:8px 12px`·`font-size:13.5px`)의 **인라인 style 을 통째로 이깁니다.**
   되살리려면 파일 맨 끝에 «조상 id 를 앞에 붙인» 규칙을 또 쌓아야 하는데, 머리글 클릭이면
   그 싸움 자체가 없습니다(CLAUDE.md 2장 「표 안의 작은 아이콘 버튼」·「표 안에 select」).

2. **서버에 `?sort=&order=` 를 붙여 Cypher `ORDER BY` 로 정렬하기**
   → 버림. 이 API 는 KV 캐시(120초)를 **`fin:{kind}:{month}:{limit}` 키**로 잡고 있어서
   정렬 조합마다 캐시가 갈라지고, Neo4j 는 8초 타임아웃이라 홉을 늘릴 이유가 없습니다.
   1,000건은 브라우저에서 정렬해도 체감이 없습니다.

3. **`ph-frn-filter-js`(admin.html 의 표 자동 필터)에 이 표를 등록하기**
   → 버림. 그건 «검색» 이지 정렬이 아니고, 그 `MutationObserver` 는 표가 다시 그려질 때마다
   화면에 있는 행을 자기 입력값으로 한 번 더 걸러 **서버가 찾아 준 행까지 숨깁니다**
   (2026-08-08·08-18 에 두 번 밟은 함정).

4. **머리글 라벨과 화살표를 한 덩어리 글자로 쓰기**(`'금액 ▲'`)
   → 버림. i18n 사전이 **전체 문자열 일치**라 「금액」과 「금액 ▲」이 다른 말이 됩니다.
   라벨과 화살표를 **다른 `<span>`** 에 담았고, 브라우저 검사가 그 사실을 못 박습니다.

5. **원본 배열을 제자리(`sort()`)에서 뒤집기**
   → 버림. 그러면 «원래 순서» 로 못 돌아옵니다. `slice()` 사본을 정렬합니다.

6. **정렬 상태를 탭 사이에 유지하기**
   → 버림. 탭마다 칸 이름이 다릅니다(`money`·`actual`·`total`·`amount`). 유지하면
   «어떤 탭에서는 정렬이 조용히 안 먹는» 상태가 됩니다.

7. **«정렬 중» 강조를 JS 인라인 `style` 로 주기** ← **처음엔 이렇게 짰다가 잡혔습니다**
   → 버림. **화면에 안 나옵니다.** 커밋한 뒤 함정 대조에서 실측(1440×900, `getComputedStyle`)으로
   드러났습니다 — 인라인 `color:#b45309` → 실제 `rgb(16,24,40)`,
   인라인 `border-bottom:2px solid #f59e0b` → 실제 `0.769px rgba(15,23,42,.1)`.
   정렬한 칸과 안 한 칸의 계산값이 **완전히 같았습니다.**
   이기는 규칙 두 개가 `admin-inline-c.css` 에 있습니다:
   **8770행** `…[id^="card-"] :is(…,span,th,…){color:#101828!important}` ·
   **8793행** `… table th{border-bottom:1px solid rgba(15,23,42,.10)!important}`.
   ⚠️ **테마 조건부가 아닙니다** — `admin.html` 283·284행이 `data-admin-theme="ivory"`·
   `data-admin-tone="slate"` 를 무조건 박고 전환 기능도 없어서 **항상** 이 규칙이 이깁니다.
   ✅ 고침은 **클래스(`.c24fin-on`·`.c24fin-note-on`) + 조상 id 두 개**(`#card-accounting-mgmt
   #c24fin-head th.c24fin-on` = 2,1,1)를 그 파일 **맨 끝**에 두는 것. 신한 계좌 화면(`#acc-bankacct`)에
   같은 사정의 선례가 있습니다.
   ⚠️ 그래서 **기능이 색에 기대지 않게** 해 둔 것이 다행이었습니다 — 강조가 통째로 안 그려지던
   동안에도 `⇅ ▲ ▼` 기호와 안내 줄 글자는 정상이었습니다.

  「케이씨피M」 제외 계산(`excluded_from_revenue`)도 그대로입니다.
- **「(표시된 건 기준)」 꼬리표를 다섯 탭 모두에 붙였습니다**(예전엔 회계장부 탭에만).

  잘렸다는 사실이 탭을 가리지 않고 보여야 합니다.
- **머리글 영문은 `C24FIN_COLS_EN`(칸 키 단위)** 입니다. 그래서 탭마다 다른 뉘앙스가 한 낱말로 모입니다

  사전을 «탭+칸» 두 겹으로 바꿔야 합니다. 🌐 를 눌렀을 때 따라오게 하는 것은
  `mangoi:lang-changed` 리스너가 맡습니다 — 그 줄을 지우면 탭을 다시 눌러야만 바뀝니다.

## 6. 🔀 PR #465(지출결의 화면 정리)와 같은 화면에서 만났습니다 — 어떻게 갈랐나

병합하려고 `main` 을 가져오니 **같은 카드**를 고친 PR #465 가 먼저 들어와 있었습니다
(「카페24 지출결의 화면 정리 — 늘 비던 칸 제거 · 분류(추정)·상태 · 검색·칩·**정렬**」).
`adm-core.js`·`admin.html`·`admin-inline-c.css`·`asset-versions.json` 네 파일이 충돌했습니다.

**#465 가 한 일**: 지출결의 탭만 전용 화면(`window.__c24ExpSetup`)으로 떼어내
분류 칩·검색·상태 배지·**자체 정렬**(`c24x-th`, ▲▼)을 붙이고, 늘 비던 칸(`organ`·`method`)을 뺐습니다.
카페24 원본에 그 속성이 아예 없다는 **실측**에 근거한 것이라 되돌리면 안 됩니다.

**어떻게 갈랐나** — 한 탭에 정렬 UI 를 두 벌 두지 않는 쪽으로:

| 탭 | 정렬 담당 |
|---|---|
| 회계장부 · 급여명세 · 세금계산서 · 예치금 | 이 작업(머리글 ▲▼ · `c24FinDrawBody`) |
| **지출결의** | **#465 의 전용 화면**(칩·검색·자체 정렬) |

- `C24FIN_COLS.expenses` 는 **#465 의 새 칸 정의**(`__kind`·`state`, `organ`·`method` 제거)를 그대로 받았습니다.
- `c24FinLoad` 는 `kind === 'expenses'` 면 **전용 화면으로 넘기고 `return`** 합니다(#465 의 줄 유지).
- 🌐 언어 변경 리스너는 **지출결의일 때 다시 그리지 않습니다** — 그리면 전용 화면의 머리글(`data-s`)을
  제 것(`data-c`)으로 덮어써 **그쪽 정렬이 죽습니다.** 그 탭은 통째로 다시 불러 전용 화면이 그리게 합니다.

**⚠️ 병합에서 실제로 밟은 것 두 가지**

1. **버전 번호를 두 작업이 동시에 썼습니다** — `adm-core.js?v=158` 과 `admin-inline-c.css?v=53` 을
   양쪽이 각자 다른 내용으로. 그래서 이쪽이 **`v=160`·`v=54`** 로 새 번호를 땄습니다
   (`v=159`·`v=53` 은 중간 번호로 남습니다). 원장(`asset-versions.json`)은 **main 것을 되살린 뒤
   하니스를 다시 돌려** 새 항목만 기록했습니다 — CLAUDE.md 2장 「stash 충돌을 `--theirs` 로」 항목의 방식.
2. 🔴 **CSS 충돌에서 닫는 `}` 하나가 사라졌습니다.** 둘 다 파일 «맨 끝» 에 블록을 붙였는데,
   공통 문맥이던 마지막 `}` 가 한쪽에만 붙어 **#465 블록의 마지막 규칙이 안 닫히고 제 블록을 통째로
   삼켰습니다.** 증상은 「앰버 강조가 또 안 나옴」 — 3장 「버린 방법 7」 과 **똑같이 보이는데 원인이 다릅니다.**
   ✅ 브라우저 검사(2-2)가 6건 FAIL 로 잡았습니다. 문법 검사가 없는 CSS 라
   **중괄호 균형(`s.count('{') == s.count('}')`)을 세어 보는 것**이 가장 빨랐습니다.
