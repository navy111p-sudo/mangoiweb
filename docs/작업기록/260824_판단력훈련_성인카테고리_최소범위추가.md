# 판단력 훈련 — 성인 카테고리를 최소 범위로 추가 (2026-08-24)

## 왜 했나

「학생 나이에 따라 질문·대답 수준이 달라야 하지 않을까」라는 제안에서 시작해, 벤치마킹
(Khan Academy·ELSA Speak·Cambridge YLE/for Schools/adult exams·COPPA 가이드)과 코드 조사를
거쳐 「기존 것은 그대로 두고 성인 카테고리 하나만 최소 범위로 추가」 방향으로 좁혔다
(1장 제안서 + before/after 샘플로 사전 합의). 사장님 최종 지시: 「너무 부담 갖지 말고
기존의 것들 사용하고, 문장·단어·질문·대답만 성인으로 고려」.

## 조사에서 확인한 것

- **실력 축(읽기 밴드 1~8·배치테스트)은 이미 있다.** 없는 것은 «소재·어투» 축뿐.
- `students_erp.grade`(학년, 카페24 연동)는 있지만 채움율을 이 세션에서 직접 확인할 수
  없었다(Cloudflare 인증 정보 없음). `students_erp.birth_date`는 코드 주석으로
  **29,373명 전원 미입력(0%, 2026-07-25 확인)**임을 이미 알고 있었고, 같은 이유로
  «연령대별 톤»(`api-reports.ts` `computeAgeBand()`)이 지금껏 한 번도 작동한 적 없는
  죽은 기능이었다 — 학생 데이터에서 나이를 자동으로 읽어오는 접근은 신뢰할 수 없다는
  뜻이라, **학생이 직접 고르는 토글**로 방향을 정했다.
- 코드 전체에 «성인반» 개념이 전혀 없다(그 죽은 함수도 아동~13세까지만 구간이 있음).

## 설계 원칙 — 두 축을 섞지 않는다(Cambridge 방식)

- **실력(밴드 1~8, 문장 길이·문법 범위)**: 나이와 무관. 성인 초보자도 아이 초보자와
  같은 3~5단어 규칙이 맞다. **손대지 않았다.**
- **소재·어투(누구를 위한 문제인가)**: 이번에 새로 추가한 유일한 축. `AgeGroup =
  'child'|'adult'`, 기본값 `'child'`(=지금까지의 전부, 변화 없음).

## 무엇을 바꿨나 — 새 화면·새 API·새 D1 테이블 없음

- **`judgment-level.ts`**: `AgeGroup`·`DEFAULT_AGE_GROUP`·`normalizeAgeGroup()` 신설.
  `bandPromptLine(band, ageGroup?)` — 인자 생략 시 예전과 100% 동일 문구(하위호환).
  성인용은 "the child" → "the adult learner", "a child would really say" →
  "an adult would really say"만 바뀐다. 단어 수 스펙(BAND_SPECS)은 무변경.
- **`judgment-english.ts`**: `englishQualityRules()`·`grammarCheckPrompt()`에
  `ageGroup` 파라미터 추가(둘 다 기본값 `'child'`, 생략 시 기존과 동일 출력).
  문법 연습 문항(오답에 실수 심기)에서 "a Korean child" → "a Korean adult learner"만 교체.
- **`api-judgment.ts`**:
  - `ADULT_SCENARIO_THEMES` 신설(직장·일상 24개) — 기존 `SCENARIO_THEMES`(학교·놀이터 등)와
    분리. 판단 각도(`SCENARIO_ANGLES`)는 나이·언어 중립 축이라 그대로 공유.
  - `BandState`에 `ageGroup: AgeGroup` 필드 추가 — 읽기 밴드와 **같은 KV 한 칸**
    (`judglvl:<uid>`)에 둔다(새 KV 키·새 테이블 없음). 옛 저장값(필드 없음)은
    `normalizeAgeGroup(undefined)` → `'child'`로 안전 폴백.
  - `generatePersonalizedScenario()`: `bandOpts.ageGroup`을 받아 실력(밴드/모드)과
    완전히 독립적으로 처리·저장. 성인 모드면 소재 풀·생성 프롬프트·문법 재검증
    (`englishLooksCorrect`)까지 전부 성인 톤으로 분기.
  - `evaluateJudgmentAnswer()`: 채점 피드백도 **서버가 KV에 저장해 둔 나이대만** 믿는다
    (기존 정답지 KV 보호 원칙과 동일 — 클라이언트가 나이대를 조작해도 기록은 안 흔들림).
- **`judgment.html`**: 기존 「🎚️ 문장 난이도 설정」 화면(레벨 고르기 진입점 그대로 재사용)에
  「누구를 위한 문제인가요?」 토글 두 개 추가. 기존 `.lvm-btn` CSS를 그대로 재사용해
  **새 CSS 없음**. 캐릭터·콘페티·XP 팝 등 게임 연출은 한 줄도 안 건드림.

## 실제로 밟은 버그와 고침 — trap-check 가 잡음

- **🔴 토글이 서버까지 안 이어져 조용히 무동작할 뻔했다.** `/api/judgment/scenario`의
  실제 HTTP 핸들러는 `src/index.ts`가 아니라 `src/api-points.ts` 안에 있는데,
  `generatePersonalizedScenario()`에 `ageGroup`을 넘기도록 다 고쳐 놓고도 **그 핸들러가
  `body.age_group`을 안 읽고 있었다.** 화면은 "성인용 문제로 바꾸고 있어요…" 안내까지
  정확히 뜨고 요청도 정확히 보내지만, 서버가 그 필드를 조용히 버려 **에러 없이 계속
  아이 문제만 나갔을 것**이다. 기존 `nudge`/`setBand`/`mode`/`probeBand`/`src` 배선
  바로 옆에 `ageGroup: (body.age_group || '').toString().trim() || null` 한 줄만
  빠져 있었다 — CLAUDE.md 2장 「값을 넣었는데 payload 엔 늘 빈 값(에러 없음)」과
  같은 뿌리. **신설 하니스(59건 전부 ✅)도 이걸 못 잡았다** — `judgment-level.ts`·
  `judgment-english.ts`·`api-judgment.ts`·`judgment.html`만 대조하고 `api-points.ts`를
  아예 열어보지 않았기 때문. trap-check 서브에이전트가 실제 라우트 핸들러 위치를
  추적해서 잡아냈다. 고침: `api-points.ts`에 한 줄 추가 + 하니스에 D-3절(3건) 신설.
- **🔴 나이대 분기를 만들면서 삼항연산자 밖에 있던 문장 두 곳이 child/adult 구분 없이
  통째로 바뀔 뻔했다.** ① 시나리오 생성 프롬프트의 난이도 설명이 "for **this** child"
  → "for **the** child"로(지시사 누락), ② 채점 프롬프트의 register_awareness 설명에서
  "**a child who picked** the right register…"가 통째로 빠지고 "picking the right
  register…"로 뭉개졌다. 둘 다 기존 아이 학생 29,000명에게 실제로 들어가는 AI 프롬프트
  문자열이 미세하게 달라지는 것이었다 — 이 저장소는 프롬프트 한 줄 차이(단어 수 지시 등)로
  실사고를 겪은 전례가 있어(2026-08-24 "Want play with me") 가볍게 넘길 문제가 아니다.
  둘 다 정확한 원문으로 되돌리고 성인 분기만 새로 갈라 넣었다(child 분기 = 원문과
  글자 하나까지 동일). 하니스 D-2절(4건) 신설로 재발 방지.

## 밟을 뻔한 함정과 고침

- **버튼 클래스 재사용 충돌**: 기존 난이도 모드 버튼 핸들러가 `.lvm-btn` 전체를
  `querySelectorAll`로 잡고 있어서, 새 나이대 버튼(같은 CSS 클래스 재사용)도 그 핸들러가
  집어 `data-m`이 없는데 모드 전환 로직을 잘못 태울 뻔했다. → 기존 핸들러 선택자를
  `.lvm-btn[data-m]`으로 좁히고, 나이대 버튼은 `.lva-btn` 전용 핸들러로 분리.
- **prefetch 오염**: 밴드·모드 전환과 같은 이유로, 나이대를 바꾼 직후 미리 받아둔
  '옛 나이대' 문제가 나가면 안 된다 → `loadScenario`의 폐기 조건(`if(focusMisc||nudge||
  setBand||mode)`)에 `ageGroup`도 추가.
- **문법 검증(직전 PR)이 깨지지 않게**: `englishLooksCorrect`·`englishQualityRules`가
  이미 하고 있던 "Want play with me" 류 방지 로직은 그대로 두고 인자만 추가 — 재검증은
  `judgment_agegroup_harness.mjs` B절이 두 버전(child/adult) 모두에서 문법 안전장치
  문구가 살아있는지 확인.

## 검토했다가 버린 방법

| 방법 | 버린 이유 |
|---|---|
| `students_erp.birth_date`/`grade`로 나이 자동 추정 | `birth_date`는 이미 0% 확인됨. `grade`도 신뢰성 미확인. 자동 추정은 실패하면 조용히 틀린 소재를 준다 — 학생이 직접 고르는 편이 안전 |
| 매 세션마다 나이/학년 질문 | 이 팀이 최근 계속 진입 장벽을 없애는 방향(로비 스킵 등)으로 가고 있어 정반대. 계정에 저장하고 설정에서 바꾸는 쪽으로 |
| 새 D1 테이블·새 API 경로 | `src/index.ts`가 공동 금지구역이라 새 라우팅 없이 기존 `/api/judgment/scenario` 요청 바디에 필드 하나만 추가 |
| 판단 각도(SCENARIO_ANGLES)도 성인용 별도 목록 | 실제로 나이·언어 중립적인 축이라("정중하게 부탁하기" 등은 아이·성인 다 통함) 굳이 나눌 이유가 없음 |
| 성인용 밴드 스펙(단어 수) 별도 정의 | 실력 축은 나이와 무관 — Cambridge YLE/for Schools/adult 시험도 CEFR 레벨 자체는 공유하고 소재만 갈림 |

  기존 하니스 중 2건이 함수 시그니처 변경으로 정규식이 안 맞아 FAIL → 정규식만
  새 코드에 맞춰 갱신(검사 완화 아님, `englishQualityRules(allowBroken, ageGroup)`
  등 새 인자 반영) → 재통과
- `node test-harness/run.mjs --fast` — **PASS 200 / FAIL 0 / SKIP 20(E2E)**(하니스 파일 수 기준)
- `bash test-harness/ci-gates.sh` — 배포 게이트 4종 전부 통과
- **trap-check 서브에이전트 대조 — 🔴 2건 실발견**(위 「실제로 밟은 버그」 절). 둘 다
  수정 반영 후 재검증 완료. 이번 기능 중 가장 위험했던 부분(서버 배선 누락)을
  타입체크·기존 하니스·신설 하니스 어느 것도 못 잡았고 trap-check 만 잡았다 —
  «/api/judgment/scenario의 진짜 핸들러가 src/index.ts가 아니라는 것»은 코드를
  직접 추적해야만 나오는 사실이라 문자열 대조 하니스의 구조적 사각지대였다.
- 브라우저 시각 검증(Playwright + 컨테이너 내장 Chromium, fetch 스텁): 토글 클릭 →
  「지금」 칩 이동 → 재진입 시 상태 유지 → 기존 난이도 모드 버튼과 충돌 없음(콘솔 에러 0건)
  까지 확인. ⚠️ 이 검증은 fetch 응답을 직접 가로채는 스텁이라 **서버 코드 자체의 정확성은
  증명하지 못한다** — 위 배선 누락 버그를 못 잡은 이유가 이것. 서버 로직 검증은
  하니스(소스 대조)와 trap-check 몫이었다.
