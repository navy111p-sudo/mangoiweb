# 수업평가 개편 0단계 실측 — 가정이 뒤집힌 것들 (2026-08-24)

## 왜 했나

PR #446(0·1단계) 병합 후 「추진해줘」 지시로 0단계 데이터 확인을 진행. 이번에 세션에
Cloudflare D1 MCP 연결이 붙어(`mcp__Cloudflare_Developer_Platform__d1_database_query`),
배포 권한 PC 없이 이 세션에서 직접 SELECT 로 확인했다(모두 읽기 전용, mango-db).

## 실측 결과 — 제안서·PR #446 의 전제 세 가지가 틀렸다

1. **학년(grade) 자동 배정이 불가능하다.** `students_erp` 29,417명 중 `grade` 채움
   **0명(0%)**. `school` 447명(1.5%), `age`·`birth_date`·`level`·`program`·`textbook`
   **전부 0명**. `cafe24-sync.ts` 는 `grade` 를 동기화 컬럼 목록에 넣고 있어 코드는
   맞는데, **카페24 원본 자체에 값이 없는 것**으로 보인다. 제안서 5장 「1차 자동
   배정 — 학년으로」는 지금 데이터로는 성립하지 않는다.

2. **강사 「1분 수업 일지」 기능이 실사용 거의 0건이다.** `student_evaluations`
   104행 중 `eval_type` 이 채워진(=api-mango.ts 의 **다른** 기능, 월간 4대영역 평가)
   행이 104행 **전부**이고, `student_uid` 가 채워진(=진짜 teacher.html 1분 일지) 행은
   **2건뿐**(그중 1건은 `student_name='홍길동'` 테스트 데이터로 보임). 즉 PR #446
   본문에 적은 「거짓 4점이 쌓이고 있었다」는 표현은 과장이었다 — 쌓인 게 아니라
   **애초에 거의 안 쓰이고 있었다**. 별점 기본값 제거 자체는 여전히 옳은 예방 조치지만,
   「이미 쌓인 나쁜 데이터를 고쳤다」가 아니라 「앞으로 쌓일 나쁜 데이터를 막았다」로
   정정한다.

3. **`score_speaking` 컬럼이 두 기능에서 공유되고 있었다.** `student_evaluations` 는
   `api-mango.ts`(레거시 4대영역 평가)와 `api-lessons.ts`(1분 일지, 2026-06-13
   가산 마이그레이션으로 컬럼만 얹음)가 **같은 테이블**을 쓰는데, `ensureEvalTable()`
   의 `ALTER TABLE ADD COLUMN` 은 **이름이 이미 있으면 건너뛴다**(`if (!have.has(col))`).
   `score_speaking` 은 이미 레거시가 REAL 로 만들어 놨었고(실측값 3.5~4.9 소수,
   90·95 백분율까지 척도가 제각각), PR #446 에서 강사 별점(1~5 정수)을 그 자리에
   쓰기 시작한 것이다. 데이터가 행 단위로는 안 섞이지만(별개 INSERT), **같은 컬럼
   이름을 두 척도가 같이 씀** — CLAUDE.md 2장에 함정으로 등록. 실사용이 2건뿐이라
   지금 당장 사고는 아니지만, 2단계에서 AI 가 대량으로 이 칼럼에 쓰기 시작하면
   레거시 기능 쪽 통계가 오염될 수 있다.

## 검토했다가 버린 방법

- **원격 세션에서 배포 권한 PC 를 계속 기다리기** — 마침 이 세션에 Cloudflare D1
  MCP 연결이 새로 붙어서 직접 SELECT 가 가능해졌다. PowerShell 스크립트
  (`scripts/eval-phase0-select.ps1`)는 그대로 남겨 둔다 — 다음에 이 연결이 없는
  세션에서도 같은 검사를 할 수 있어야 한다.
- **grade 가 비었다고 코드(cafe24-sync.ts)부터 의심하기** — 컬럼 목록·바인딩을
  다시 읽어 코드는 맞다는 것을 먼저 확인했다. 원본 데이터 문제로 결론짓고 코드를
  건드리지 않았다(공연히 고쳤다간 아무 일도 안 하는 코드를 «고쳤다»고 착각할 뻔).
- **score_speaking 컬럼을 바로 분리/이름변경** — 실사용이 2건뿐이라 지금 시급한
  사고는 아니고, `api-mango.ts` 쪽 레거시 기능의 스키마를 건드리는 것은 사고 반경이
  더 큰 별건 작업이라 이번엔 «읽을 때 갈라서 본다」는 함정 기록만 남기고 미룸.
