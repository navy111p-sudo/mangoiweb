# 수업평가 개편 2단계 — 강사 수동 밴드 태그 (2026-08-24)

## 왜 했나

0단계 실측(260824b)에서 `students_erp.grade`가 0% 채워져 있어 «학년으로 자동 배정»이
불가능하다는 게 드러났다. 사장님께 밴드 배정 방식을 여쭤 **「강사가 수업 중 수동
태그」**를 골라 주셨다(추천안). 이 커밋은 그 첫 슬라이스 — 밴드를 매기는 자리와
저장 경로를 만든다.

## 무엇을 했나

- `students_erp` 에 `eval_band` TEXT 컬럼 추가(`ALTER TABLE ADD COLUMN`, `ensureEvalTable()`
  안에서 함께 보장 — 다른 테이블이지만 `/api/eval/create` 가 유일한 기록 경로라 같은
  게이트에 묶었다). 값은 `sprout`(새싹)·`grow`(자람)·`fruit`(열매) 셋만 허용.
- `teacher.html` 「수업 일지」 모달 맨 위에 🌱새싹·🌿자람·🥭열매 칩 3개 — 단일선택(별점과
  같은 자리). 그 학생에게 이미 값이 있으면(`c.eval_band`) 미리 켜져서 온다. 다시 누르면
  «모름» 으로 되돌린다(잘못 눌렀을 때 물릴 방법).
- `/api/eval/create` — `body.band` 가 화이트리스트 안이면
  `UPDATE students_erp SET eval_band=? WHERE user_id=? OR login_id=?`. 실패해도 평가
  저장 자체는 막지 않는다(`.catch(()=>{})`).
- `api-teacher.ts` 의 강사 수업 목록 두 경로(예약표 `class_schedules` 조인,
  카페24 출석 `attendance` 조인) 모두에 `se.eval_band` 를 붙여 화면이 미리 채울 수 있게 함.

## 검토했다가 버린 것

- **grade 대신 program/level/textbook 으로 자동 추정** — 0단계에서 이미 셋 다 0%로
  확인됐다(260824b). 추정할 원료 자체가 없다.
- **밴드를 새 테이블로 분리** — 학생 1명당 값 하나뿐이라 `students_erp` 컬럼 하나가
  가장 적게 부순다. `student_evaluations` 처럼 두 기능이 한 테이블을 공유하는 함정을
  새로 만들지 않으려고 일부러 기존 학생 원부 테이블에 얹었다.
- **eval_band 를 eval.html(학부모 화면)에도 표시** — 이번 슬라이스 범위 밖으로 미룸.
  강사가 태그를 시작해 데이터가 쌓인 뒤에 붙이는 게 순서에 맞다.

## 실수할 뻔한 것 — 카페24 방 목록이 통째로 사라질 뻔함

`api-teacher.ts` 의 카페24 출석 기반 조회(`lmsRs`, `room_id LIKE 'c24-%'`)에 처음엔
`se.eval_band` 를 그냥 SELECT 목록에 추가했다. 그런데 이 쿼리는 **폴백이 없는 채로**
바깥 try/catch 에 걸려 있었다 — 배포 직후처럼 컬럼이 아직 없는 순간(첫 `/api/eval/create`
호출 전)에 `no such column: eval_band` 로 **통째로 실패**하면, 카페24 실제 예약 수업이
전부 강사 화면에서 사라진다. CLAUDE.md 의 「🔴 실시간 수업 현황이 비었는데 수업은 돌고
있음」과 같은 뿌리 — 코드 리뷰 없이 배포했으면 재현됐을 사고. 위쪽의 `sqlJoin`/`sqlPlain`
과 같은 폴백 패턴(조인 실패 시 컬럼 없이 재시도)을 그대로 적용해 막았다.
