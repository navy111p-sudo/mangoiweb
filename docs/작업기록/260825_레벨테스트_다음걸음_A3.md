## 1. 왜 했나

레벨테스트 결과는 **이미 잘 나오고 있었습니다.**
`leveltest_applications` 에 `final_level`·`recommended_textbook`·`next_class_guide` 세 칸이 있고,
결과 화면(`t.html`)과 학부모 화면(`parent.html`)이 그 값을 그대로 보여 줍니다.

없던 것은 **그 다음** 이었습니다 — 「그래서 이제 뭘 하면 되나」에 답하는 자리가 한 곳도 없어서,
레벨을 받은 학부모가 스스로 수강신청 화면을 찾아가야 했습니다.
찾아가더라도 신청 화면에는 자기 레벨이 어디에도 안 나와서
「내 레벨이 반영된 게 맞나」를 확인할 방법이 없었습니다.

덤으로 확인된 것: `final_level` 은 AI 추정치가 평가 화면에 미리 채워지는데
**`recommended_textbook` 만 늘 빈 칸**이라, 강사가 매번 처음부터 판단하고 있었습니다.

## 2. 한 일

| 화면 | 무엇 |
|---|---|
| `public/t.html` | 결과가 확정된 티켓에 **「▶ 이 결과로 수업 신청하기」** 버튼. 레벨·추천 교재를 주소에 실어 보냅니다 |
| `public/parent.html` | 레벨테스트 현황 카드 밑에 같은 버튼. **가장 최근 결과 하나만** 씁니다 |
| `public/enroll.html` | 받은 레벨·교재를 맨 위에서 되짚어 주는 상자(`#stLtResult`) + 로그인 왕복을 견디는 기억 |
| `src/api-admin.ts` | 레벨별 «지금까지 실제로 추천한 교재» 최빈값을 `book_hints` 로 내려줍니다 |
| `public/admin/mypage.html` | 평가 화면에서 교재 칸이 **비어 있을 때만** 그 제안을 채웁니다 |

### 결과가 나왔을 때만 낸다
테스트 «전» 에 신청을 권하면 순서가 뒤집힙니다. `if (r.final_level)` 안에서만 그립니다.

### 그 값으로 아무것도 결정하지 않는다
주소로 온 레벨·교재는 **표시 전용**입니다. 금액·강사·권한은 서버가 따로 계산합니다.
그래서 주소를 손으로 고쳐도 손해가 없고, 반대로 **이 값을 근거로 무언가를 정해서도 안 됩니다.**
강사에게 전달되는 진짜 근거는 `leveltest_applications` 에 이미 남아 있습니다.

## 3. 검토했다가 버린 방법

### ⛔ 「A1 이면 파닉스」 같은 레벨→교재 고정표를 코드에 박기
가장 쉬운 길이었지만 **교재 선택은 레벨만으로 정해지지 않습니다.** 나이(초등/중등/성인),
목적(회화/시험대비/비즈니스)이 함께 걸린 사업 판단입니다. 코드가 그 표를 «지어내면»
그때부터 그 표가 정책이 되고, 바꾸려면 배포를 해야 합니다.

대신 **사람이 실제로 고른 것을 세어서 되돌려 줍니다** — `GROUP BY final_level, recommended_textbook`
로 레벨마다 최빈값 하나. 데이터가 없으면 빈 값이고, 그때는 지금까지처럼 빈 칸으로 시작합니다.
하니스가 「고정표를 박지 않았는가」를 부정 검사로 못 박아 뒀습니다(E절).

### ⛔ 로그인 안 된 사람을 그냥 통과시키기
계정 없는 체험 학생이 버튼을 누르면 `enroll.html` 이 로그인 화면으로 잠급니다.
「기왕 결과까지 냈으니 열어 주자」는 유혹이 있었지만, 그 잠금은 남의 수강·결제를 막는
자리입니다(`enroll-ops.ts` `authUidOrAdminSession`). **잠금은 그대로 두고**,
잃는 것만 막았습니다 — 결과를 `sessionStorage` 에 담아 두고 로그인 화면에
「기억해 뒀어요」라고 적어 줍니다.

### ⛔ 그 결과를 `localStorage` 에 굳히기
탭을 닫아도 남으면 **그 폰을 다음 사람이 써도 남의 레벨이 뜹니다.**
로그인 왕복만 견디면 되는 값이라 `sessionStorage` 로 충분합니다.
브라우저 검사가 「다른 문맥에는 안 새어 나간다」로 확인합니다.

### ⛔ 학부모 화면에서 결과 여러 건을 다 보여 주기
`items` 에 결과가 여러 건이면 **옛 레벨로 신청하게 됩니다.**
`created_at` 내림차순 첫 건 하나만 씁니다.

## 4. 🔴 도중에 잡은 진짜 버그 — `&lt_level` 이 `<_level` 로 읽힘

처음에 링크를 이렇게 적었습니다.

```js
var q = '?from=lt&lt_level=' + encodeURIComponent(r.final_level);
```

브라우저가 만들어 낸 실제 주소:

```
/enroll.html?from=lt<_level=A2<_book=BTS%203
```

**`&lt` 는 세미콜론이 없어도 `<` 로 디코딩됩니다**(HTML 표준의 legacy named character reference).
그래서 **레벨이 통째로 사라졌습니다.**

무서운 것은 **어디서도 티가 안 난다**는 점입니다 —
소스에는 `&lt_level=` 이라고 멀쩡히 적혀 있고, 링크는 그려지고, 눌리고, 이동까지 «성공» 합니다.
받는 쪽만 조용히 「값이 없네」로 판단해 아무것도 안 그립니다.
**타입체크도 문자열 하니스도 못 잡습니다** — 코드도 값도 다 맞고,
틀린 것은 «브라우저가 그걸 어떻게 읽는가» 하나뿐입니다.

고침은 `&amp;` 로 적는 것(`'?from=lt&amp;lt_level=' + …`).
브라우저가 `&` 로 되돌려 주므로 주소는 정확히 맞습니다.

→ **CLAUDE.md 2장에 함정으로 추가**했습니다. 이 저장소는 HTML 문자열로 링크를 만드는
코드가 많아서 언제든 재현됩니다(`lt_`·`gt_`·`amp_`·`copy_` 로 시작하는 파라미터 이름이 특히 위험).

## 5-2. 🔴 세 번째 — `data-ko`/`data-en` 을 달았더니 «오히려» 번역이 죽을 뻔했다

처음에는 CLAUDE.md 2장 「JS 로 그린 라벨」을 문자 그대로 따라 새 요소마다
`data-ko`/`data-en` 을 달았습니다. **그 화면에서는 정반대로 동작합니다.**

- `enroll.html` 이 부르는 스크립트는 `session-guard.js` · `i18n-sweep.js` · `ux-track.js`
  **셋뿐**이고, **`mango-i18n.js`(=`applyLang`·`getLang` 정본)가 없습니다.**
- 유일한 엔진인 `i18n-sweep.js` 는 `_i18nManaged()` 로 `[data-ko],[data-en]` 을 만나면
  **`FILTER_REJECT` 로 서브트리째 건너뜁니다** — 「applyLang 이 권위를 갖는다」는 전제입니다.
- 맡을 applyLang 이 없으니 결과는 **«아무도 번역하지 않음»** = 영어 사용자에게 한국어 그대로.
  **속성을 안 달았으면 스윕이 영어로 바꿔 줬을 자리**였습니다.

덤으로, 제가 `window.getLang() === 'en'` 으로 분기해 둔 줄도 **그 함수가 이 화면에 없어서
조건이 항상 거짓** — 에러 없이 늘 한국어였습니다.

고침: **새 요소에서 그 속성을 전부 뗐습니다.** 스윕은 `document.body` 를
`MutationObserver`(childList·subtree)로 지켜보므로 **JS 로 나중에 붙인 줄도 알아서 번역합니다.**

⚠️ 이 파일에는 **이미 같은 상태인 요소가 44곳** 있습니다. 그건 별건이고
(`mango-i18n.js` 를 붙일지부터 사람이 정해야 합니다), 새로 만드는 것만 안 달았습니다.
하니스 D절에 「이 화면은 여전히 applyLang 엔진을 안 부른다」는 **전제 확인** 줄을 함께 둬서,
나중에 그 화면이 `mango-i18n.js` 를 부르게 되면 검사가 먼저 알려 주도록 했습니다.

→ **CLAUDE.md 2장에 함정으로 추가**했습니다.
📜 이건 `trap-check` 서브에이전트가 잡았습니다 — 타입체크·하니스·브라우저 검사 31종이
전부 초록불이던 상태였습니다(브라우저 검사도 한국어 문구만 확인하고 있었습니다).
