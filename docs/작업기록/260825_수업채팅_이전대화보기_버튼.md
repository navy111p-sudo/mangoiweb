# 수업 채팅 「이전 대화 보기」 — 누를 때만 불러오는 방식

- **날짜** 2026-08-25
- **요청** 사장님. 화상수업 채팅창 스크린샷 두 장과 함께
  「학생이나 선생님이 미리 먼저 들어와서 채팅을 남기고 다시 나갔다가 나중에 들어오더라도
  채팅에 글이 남아 있게 할 수 있어? 얼마나 남아 있어야 하는지? 다음 수업까지? 24시간? 48시간?」
  → 의견을 HTML 로 드린 뒤 **「이전대화 보기 방식으로 해줘」** 로 확정.
- **바꾼 파일**
  `cloudflare-deploy/public/js/idx-vc-chat-history.js`(신규) ·
  `cloudflare-deploy/public/index.html`(버튼 1개 + script 1줄) ·
  `cloudflare-deploy/src/api-notify.ts`(GET 에 `since` 추가) ·
  `test-harness/chat_history_button_harness.mjs`(신규) ·
  `test-harness/manual/chat-history-browser.mjs`(신규)

---

## 1. 왜 했나

「먼저 들어와 남긴 말이, 나갔다 들어오면 사라진다」는 불편입니다.

확인해 보니 **저장은 원래부터 되고 있었습니다** — 전체 채팅은 보낼 때마다 D1
`chat_messages` 에 쌓이고, 불러오는 함수(`vcLoadChatHistory`)도 화면 코드에 그대로
있습니다. 다만 **2026-07-24 에 사장님 지시로 «자동 불러오기» 를 껐습니다.**
그때 이유가 코드 주석에 남아 있습니다 — 「상담 내용이 다음 수업에 그대로 남는 문제」.

즉 없는 기능을 만드는 일이 아니라, **7월 지시를 지키면서 이 불편만 푸는 방법**을
찾는 일이었습니다.

## 2. 먼저 의견서를 드리고 방식을 고르시게 했다

코드를 바로 고치지 않고 검토 결과를 HTML 로 정리해 드렸습니다. 핵심은
**「몇 시간이냐」가 문제 되는 것은 방 한 종류뿐**이라는 점입니다.

| 방 이름 | 성격 | 기간의 의미 |
|---|---|---|
| `class-{예약id}-{YYYYMMDD}` | 이름에 **날짜**가 있어 하루 지나면 다른 방 | 길게 줘도 «그날 그 수업» 밖은 못 나온다 |
| `mangoi-class` (기본방·회의방) | 이름이 **고정** — 앞 타임·어제 수업이 같은 방 | 길게 주면 남의 수업 대화가 넘어온다 |

→ 그래서 한 숫자로 통일하지 않고 **수업방 48시간 / 고정 기본방 3시간**으로 갈랐습니다.

의견서에 「더 조심스럽게 가는 방법」으로 적어 둔 **버튼 방식**을 사장님이 고르셨습니다.
기본은 지금처럼 빈 채팅, 필요한 사람이 누를 때만 불러옵니다. **7월 지시와 부딪히지 않는
것이 이 방식의 핵심**입니다.

## 3. 검토했다가 버린 방법

| 버린 방법 | 왜 안 했나 |
|---|---|
| **자동 로드 스위치를 그냥 켜기** (`__vcChatAutoLoadHistory = true`) | 한 줄이면 되지만 그것이 정확히 7월에 끈 동작입니다. 기본방에서는 남의 수업 대화가 그대로 올라옵니다 |
| **24시간·48시간으로 일괄 적용** | 기본방에서 어제 저녁 수업이 오늘 저녁 수업에 붙습니다. 수업방에서는 반대로 24든 48이든 결과가 같습니다(날짜로 이미 갈려서) |
| **「다음 수업까지」** | 뜻은 가장 정확한데 **시스템이 그 경계를 모릅니다** — 기본방은 예약과 연결이 없어 다음 수업 시각을 알 방법이 없습니다 |
| **「방이 완전히 빈 뒤부터」** | 가장 그럴듯해 보이는데 **사장님이 말씀하신 그 상황을 깨뜨립니다.** 학생이 먼저 들어와 메모를 남기고 **나가면** 방이 비고, 뒤늦게 들어온 강사에게 그 메모가 안 보입니다 |
| **idx-main.js 에 코드 넣기** | 첫 화면 예산이 index.html 상한(1550+12KB)에 **이미 닿아 있습니다**(실측 1562KB). 별도 파일 + `defer` 로 뺐습니다 |
| **버튼을 JS 로 만들어 끼우기** | 정적 마크업이라야 i18n(`data-ko`/`data-en`)이 그대로 먹고, 그리는 순서 경합도 없습니다 |

## 4. 어떻게 만들었나

- **버튼** — 채팅창 아래 「채팅 지우기」 옆에 「이전 대화 보기」. 누를 때만 동작합니다.
- **기간** — 방 이름이 `class-…-YYYYMMDD` 모양이면 48시간, 아니면 3시간. 최대 200개.
- **「채팅 지우기」와 짝** — 지운 시각을 방마다 기억해(`mangoi_chat_cleared_{방}`) **그 뒤 것만**
  불러옵니다. 없으면 「지웠는데 다시 들어오니 살아 있다」가 됩니다.
  기억은 `vcResetChat` 을 **감싸서** 합니다 — idx-main.js 를 안 건드리려고.
  ⚠️ 서버 기록은 그대로 둡니다(감사·분쟁 대비). 화면에 안 보여 줄 뿐입니다.
- **알림이 안 울립니다** — 불러온 줄에는 `_loadedAt` 을 붙입니다. 이게 안읽음 배지·채팅창
  자동열기를 막는 표시입니다(idx-main.js `vcReceiveChat`). 빠뜨리면 재입장마다 배지가 200개로 뜹니다.
- **순서** — `vcReceiveChat` 은 항상 **맨 뒤에** 붙이므로, 채팅창을 비우고 → 이력을 먼저 그리고
  → 원래 있던 것을 다시 붙이는 순서라야 시간순이 맞습니다.
- **서버** — `GET /api/chat/messages` 에 선택적 `since` 를 더했습니다. 안 보내면 예전 그대로라
  관리자 조회·기존 호출은 안 바뀝니다. 새 경로가 아니라 **기존 경로에 파라미터만** 더한 것이라
  `src/index.ts` 의 «관문 셋» 은 건드릴 필요가 없었습니다.

### 밟을 뻔한 함정

- `vcRoomId` 는 `let` 이라 **`window` 에 없습니다.** `window.vcRoomId` 로 읽었으면 항상
  undefined 가 되어 «조용히 아무 일도 안 일어나는» 상태가 됩니다(CLAUDE.md 함정).
  맨이름으로 읽습니다.
- 라벨을 바꿀 때 `textContent` 만 쓰면 🌐 를 눌렀을 때 i18n 엔진이 옛 글자로 되돌립니다.
  `data-ko`/`data-en` 을 **함께** 갱신합니다. (아이콘 버튼이 아니라 글자 버튼이라
  「아이콘이 문장으로 바뀌는」 반대쪽 함정에는 안 걸립니다.)
- 부정 검사가 있는 하니스라 **주석을 벗겨 낸 사본**으로 판정합니다 — 설명 주석에 적은
  `window.vcRoomId` 가 자기 검사에 걸립니다.

## 5. 함정 대조에서 잡혀 고친 것 (커밋 전)

`trap-check` 로 CLAUDE.md 와 대조해 네 가지를 고쳤습니다. **전부 하니스·타입체크가
통과한 뒤에 나온 것들**이라, 검사만 믿으면 그대로 나갈 뻔했습니다.

1. **「불러올 이전 대화가 없어요」 뒤에 다시 못 누름** — 주석에는 「버튼은 눌린 채로 둔다」고
   적어 놓고 `disabled` 를 안 풀었습니다. 수업 도중 뒤늦게 이력이 생겨도 부를 방법이 없었습니다.
2. **구분선이 🌐 를 안 따라감** — «─ 이전 대화 N개 ─» 를 `textContent` 로만 그렸습니다.
   버튼 라벨은 `setLabel()` 로 `data-ko`/`data-en` 을 함께 넣고 있었는데 구분선만 빠져 있었습니다.
3. **같은 기능이 두 벌** — 옛 `vcLoadChatHistory()` 가 그대로 살아 있는데, 그 경로는
   「채팅 지우기」 시각을 몰라 **지운 대화를 되살립니다.** 옛 이름을 이쪽으로 모았습니다.
4. **`innerHTML` 로 퍼냈다 되붙이기** — 지금은 순수 HTML 이라 무해하지만, 버블에 리스너가
   붙는 날 조용히 날아갑니다. 노드를 그대로 들고 있다가 되돌리게 바꿨습니다.

## 7. 아직 안 한 것 (사람 결정 필요)

- **자동 삭제가 여전히 안 돕니다.** 30일 정리 API(`POST /api/admin/chat/cleanup`)는 있는데
  cron 에 안 걸려 있어 사람이 눌러야 합니다. 계정 cron 이 5/5 로 꽉 차서 기존 새벽 작업에
  얹어야 하고, **지우는 변경이라 지시 없이 하지 않았습니다.** 의견서에서는 90일을 권했습니다.
- **개인정보 안내에 보관 기간 문구**가 필요합니다(채팅에 학생 이름·학부모 연락처가 오갑니다).
- 1:1 귓속말은 **원래 저장하지 않습니다**(개인 대화). 복원되지 않는 것이 정상이라
  강사에게 안내가 필요할 수 있습니다.
- **고정 기본방(`mangoi-class`)은 3시간 창 안에서 앞 타임 대화가 버튼 한 번에 보일 수 있습니다.**
  7월 지시의 «목적» 에 닿는 부분이라 적어 둡니다. 더 좁히려면 1시간으로 줄이거나,
  버튼을 날짜 박힌 수업방에서만 보이게 하는 방법이 있습니다 — 사장님 판단입니다.
- **「3시간·48시간」은 화면이 정하는 값이고 서버가 강제하지 않습니다.** 열람 자격은 예전과 같이
  그 수업 참여자로 제한되고 이 API 는 전에도 전체 이력을 주고 있었으므로 새로 뚫린 구멍은
  아니지만, «3시간만 본다» 를 보안 경계로 읽으면 안 됩니다.
