# 펼친 갤럭시 Z 폴드 수업화면 + 교재 확대 (2026-08-25)

> 사장님 제보 6건. 브랜치 `claude/textbook-layout-size-issues-7a4bfr`.

## 1. 왜 했나 — 받은 제보

1. 교재가 깨져서 잘 안 보인다
2. 교사 화면이 작고 학생 화면이 크다 (반대이거나 최소한 같아야 한다)
3. 가로로 보이지 않는다
4. 교재가 왼쪽·얼굴이 오른쪽이어야 하는데 지금 **위**에 있다.
   휴대폰 세로가 아니라 **폴더를 펼친** 상태다 (갤럭시 Z 폴드)
5. 선생님은 교재를 키웠다는데 학생은 아직도 작게 보인다
6. 교재를 손가락으로 크게 해도 커지지 않는다

## 2. 무엇이었나 — 실측으로 확인한 원인

헤드리스 Chromium 에 실제로 그려서 쟀다(`test-harness/manual/vc-fold-layout-browser.mjs`).

### ① 펼친 폴드는 «폭이 넓은데 orientation 은 portrait» 이다

실측 **738×830**. 이 저장소의 수업 레이아웃은 `@media (max-width:920px) and
(orientation:portrait)` = 「휴대폰 세로」로 단정하고

- `#vc-main-row { flex-direction: column }` → 얼굴이 **위**, 교재가 아래
- 교재 상자(`#pdf-scroll-wrap`) 높이가 **244px** 밖에 안 남음
- 「화면을 가로로 돌려주세요」 오버레이가 `display:flex` 로 **떠서** 수업 UI 를
  blur + `pointer-events:none` 으로 통째로 막음

폴드를 몇 도만 돌려 830×738 이 되면 landscape 로 잡혀 «교재 왼쪽 · 얼굴 오른쪽»
으로 확 바뀐다. **같은 기기 같은 자세인데 픽셀 몇 개로 배치가 뒤집히고 있었다** —
제보 ①③④ 가 전부 이 하나에서 나왔다.

### ② 교사 얼굴이 «작아» 보인 이유는 타일 크기가 아니라 여백이었다

`vcSmartFitVideo`(`js/idx-main.js`)는 「상대 타일은 무조건 꽉 채움(cover)」을
**≤920 + 세로일 때만** 한다. 펼친 폴드는 그 조건에서 빠지므로 16:9 교사 영상이
세로 타일에 `contain` 으로 들어가 위아래 검은 띠가 생겼다. 게다가 세로용
`#vc-local-box` 규칙들이 섞여 학생 타일만 커 보였다.

### ③ 「교재를 키워도 안 커진다」 — 배율은 올라가고 있었다

실측: `pdfSetZoom(3)` → 캔버스 **그림**은 428px → **1283px** 로 3배가 됐다.
그런데 화면에 보이는 크기는 **452px 그대로**였다.

원인은 `css/mangoi-layout.css` 84행의 전역 초기화

```css
img, video, canvas, svg, iframe { max-width: 100%; }
```

가 교재 캔버스에도 걸려 **3배로 그린 그림을 원래 폭으로 도로 줄여** 보여주고 있던 것.
「가로 스크롤 방지」라는 옳은 목적의 규칙인데, 확대해서 보라고 만든 캔버스에는 독이었다.

> 📌 2026-07-28 에 고친 「`window.pdfZoom` 대 `let pdfZoom`」과는 **다른 두 번째 원인**이다.
> 그때 값은 고쳤지만 화면은 그대로였고, 그래서 🔍+ 버튼도 핀치도 더블탭도
> 「눌리기는 하는데 아무 일이 없어」 보였다. **PC 에서도 마찬가지였다.**

### ④ 핀치 설치가 늦고, 손가락 이동은 JS 로 하면 «거의 안 움직인다»

앱 핀치(ph260)는 `vcJoinRoom` **안**에서 300~3000ms 뒤에 붙는다 — 설치 전 구간이 있다.
→ `js/idx-vc-fold.js` 가 로드 시점에 한 벌 더 단다(계산식이 같아 둘이 있어도 같은 값).

그리고 **`.pdf-scroll-wrap` 에 `scroll-behavior: smooth`** 가 걸려 있다(index.html 2112행).
JS 가 `wrap.scrollLeft = …` 로 끌면 매 프레임 애니메이션이 새로 시작돼 실제로는
거의 안 움직인다 — 실측(확대 3배): smooth **0px** · auto **120px**.
지금까지 안 보인 이유는 `touch-action: pan-x pan-y` 라 **브라우저가 대신 굴려 주고
있었기** 때문이다.

### ⑤ 교재 배율은 방에 전달되지 않았다

`pdf-share`·`pdf-page-change` 는 방 전체로 나가지만 **확대 배율은 각자 로컬**이었다.
교사가 키워도 학생 화면은 그대로다 — 제보 ⑤ 그대로다.

## 3. 어떻게 고쳤나

| 파일 | 한 일 |
|---|---|

## 4. 검토했다가 버린 방법 ← 가장 중요

### (a) 세로 미디어쿼리 10개에 `max-aspect-ratio` 를 붙여 폴드를 빼기

가장 «정공법» 처럼 보였고 실제로 코드도 적다. **버린 이유** — 그 미디어쿼리 블록들은
수업 레이아웃만이 아니라 통합바·바구니·동영상 탭·PIP 등 세로 화면 전반을 함께 담고 있다.
조건을 좁히면 폴드·태블릿이 **한 번도 시험된 적 없는 데스크톱 규칙**으로 떨어진다.
학생 29,000명이 쓰는 화면의 규칙을 건드리는 것보다, 새 클래스로 **덮는** 쪽이
되돌리기도 쉽고 폰 화면은 한 글자도 안 바뀐다.

### (b) `idx-main.js` 의 `vcSmartFitVideo` 조건을 고치기 (교사 영상 cover)

한 줄이면 끝나는 일이었다. **버린 이유** — `index.html` 첫 화면 blocking 예산의
여유가 **약 100바이트**다(실측 1,599,895B / 상한 1,600,512B). `idx-main.js` 는
blocking 이라 55바이트만 더해도 배포 게이트가 빨간불이 된다.
그래서 인라인 `!important` 를 이기는 유일한 방법인 «인라인으로 되돌리기» 를
얼굴 격자 안 `style` 속성만 보는 좁은 `MutationObserver` 로 했다.
(⛔ body class 감시는 홈 전체를 멎게 한 전력이 있어 쓰지 않았다 — CLAUDE.md)

### (c) 전역 `img,video,canvas{max-width:100%}` 를 고치기

교재 확대가 안 되던 진짜 원인이지만 **버린 이유** — 그 규칙은 사이트 전체의
가로 밀림 방어다. 교재 캔버스 4개(`#pdf-canvas`·`-2`·`#pdf-anno`·`-2`)만 예외로 뒀다.
필기 캔버스도 **함께** 풀어야 한다 — 한쪽만 풀면 필기가 그림과 어긋난다.

### (d) 새 메시지 종류를 안 만들고 기존 릴레이(`pdf-pointer`)에 배율을 얹기

`src/video-call-room.ts` 는 공동 금지구역이라 안 건드리고 싶었다. **버린 이유** —
옛 클라이언트가 그 메시지를 `pdfReceivePointer` 로 처리해 좌표 없는 화살표를 그린다.
결국 일반 릴레이 목록에 `case 'pdf-zoom':` **한 줄**만 더했다(가드·기록은 그대로 공유).

### (e) 학생 → 교사 방향도 동기화

**안 했다.** 학생이 자기 화면을 조정할 때마다 교사가 보던 배율이 제멋대로 바뀐다.
교사 → 학생 한 방향이고, 받는 쪽에서 `data.role` 을 한 번 더 거른다.

### (f) `pdf-zoom` 을 `QUEUEABLE_TYPES` 에 넣기

연결이 끊긴 동안의 배율을 나중에 몰아 보내면 «지난 배율» 이 뒤늦게 적용된다. 안 넣었다.

### (g) 폰에도 `touch-action: none` 을 걸기

처음엔 수업 중 전 기기에 걸었다. **되돌린 이유** — 그 순간 교재 이동이 전부 JS 몫이 되는데,
위 ④ 의 `scroll-behavior: smooth` 때문에 **실측 0px** 로 «안 움직이는» 화면이 된다.
`scroll-behavior:auto` 로 그 함정을 막아 두긴 했지만, 학생 29,000명이 쓰는 화면에서
브라우저가 대신 굴려 주는 것을 끌 이유가 없다. 게다가 헤드리스 실측에서
`pan-x pan-y` 로도 핀치가 3.25배까지 정상 동작했다 —
`touch-action:none` 은 «폴드에서 확실히 되게» 하는 보험이지 폰에 필요한 것이 아니다.

### (h) `vcScreenSet('half')` 하나로 «떠 있는 얼굴창» 모드 되돌리기

**버린 이유** — `vcScreenSet` 의 초기화 목록에 **`video-free` 가 없고**(idx-main.js 3368행),
자유크기는 `#vc-video-pane` 에 인라인 top/left/width/height 까지 박는다. 그 둘을 함께
걷는 것은 `vcSetVideoSize()` 뿐이라 그것을 먼저 부르고, «사용자가 골랐다» 를 알리려
`vcScreenSet('half')` 도 이어서 부른다. (trap-check 가 잡아 준 건이다 — 에러가 안 나서
자유크기로 들어와 있으면 조용히 얼굴 창이 교재를 덮은 채로 남았을 것이다.)

### (i) `apply()` 마다 PIP 를 되돌리기

**버린 이유** — 태블릿은 주소창이 접히기만 해도 resize 가 난다. 매번 되돌리면 사용자가
일부러 고른 PIP 가 계속 반강제로 풀린다. **넓은 화면으로 «바뀌는 순간» 에만** 되돌린다.

### (j) 상대 영상을 무조건 `cover` 로 채우기

**버린 이유** — 상대가 «세로 카메라» 인 경우 `<style id="vid-portrait-fix">` 가 일부러
`contain` 으로 두어 얼굴이 안 잘리게 한다. `.vid-portrait` 타일은 예외로 뒀다.
(이것도 trap-check 가 잡았다.)
