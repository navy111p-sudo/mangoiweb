## 1. 왜 했나

2026-08-24 외주 제안서(크몽 6,600만원 MVP) 대조 검토에서 확인된 **유일한 실제 결손**이었습니다.
사장님이 「환불 실행·기록(A-1) 먼저 만들어줘」라고 지시하셨습니다.

### 그때까지의 상태 — 코드로 확인한 사실

- 있던 것: 환불 **금액 계산기** 하나 (`GET /api/pay/enroll/admin/refund-quote`, `enroll-ops.ts`)
  - 그 코드 주석에 이미 적혀 있었습니다: 「계산만. 실제 환불 실행은 사람이」
- 없던 것: **토스 결제취소 호출이 0건**
  - 토스 API 를 부르는 곳은 네 군데였는데 전부 승인(`payments/confirm`)·빌링키 발급·빌링 결제·주문 조회였고,
    `payments/{paymentKey}/cancel` 은 저장소 어디에도 없었습니다.
- 그래서 실제 운영은: 담당자가 **토스 대시보드에서 직접 취소** → 우리 DB 에 아무 기록도 안 남음
  → 나중에 신한 통장 적요를 「학생환불」로 분류해 **금액만 사후 인식**.
  「누가·왜·어느 주문을·언제」 는 복원할 수 없었습니다.

환불은 분쟁이 가장 잦은 지점인데, 응대와 회계 대사가 **사람 기억**에 의존하고 있었습니다.

## 3. 설계에서 «택한 것»과 «버린 것»

### 3-1. 🔴 기록을 PG 호출 «앞»에 둔다 (write-ahead)

**택함**: `INSERT ... status='requested'` → 토스 취소 호출 → 그 행을 `done`/`failed` 로 갱신.

**버린 안**: 취소가 성공한 뒤에 기록 남기기 (짧고 단순함).

**이유**: 호출 도중 워커가 죽거나 네트워크가 끊기면 「**PG 에서는 취소됐는데 우리 기록엔 없는**」
상태가 됩니다. 이건 이 기능을 만든 이유 자체를 무너뜨립니다(=지금까지의 상태와 똑같아짐).
먼저 적어 두면 «요청했는데 결과 모름»으로 남아 사람이 찾아갈 수 있습니다.
화면 맨 위 「확인 필요」 숫자가 그 행들을 셉니다.

### 3-2. 네트워크 오류를 `failed` 로 «확정하지 않는다»

**택함**: 통신이 끊기면 상태를 `requested` 로 **그대로 두고** 사유만 적습니다.

**버린 안**: 예외가 나면 `failed` 로 마감 (코드가 깔끔해짐).

**이유**: 그 순간 우리는 **취소가 됐는지 안 됐는지 모릅니다.** `failed` 로 적으면 사람이
「안 됐구나」 하고 한 번 더 누릅니다 → **두 번 환불**. 모르는 것은 모른다고 남기는 편이 안전합니다.

### 3-3. 멱등키를 «먼저 만든 기록의 id» 로

`Idempotency-Key: mgi-refund-{id}`. 같은 행으로 재시도하면 토스가 같은 요청으로 봅니다.
시각·난수 기반으로 만들면 재시도마다 키가 달라져 **멱등의 의미가 사라집니다**.

### 3-4. 「장부에만 기록」(`record_only`) 을 남겨 둔다

**택함**: PG 를 부르지 않고 기록만 남기는 길을 둡니다.

**버린 안**: 실행만 지원 (기능이 깔끔해짐).

**이유**: 지금까지의 환불이 **전부 토스 대시보드에서 직접** 처리됐습니다. 그 과거 건들을
시스템에 넣을 길이 없으면 이 기능은 반쪽입니다. 또 결제키가 없는 주문은 자동 취소가 아예 안 됩니다.

### 3-5. 자동연장은 «경고만» 하고 자동 해지하지 않는다

전액 환불했는데 정기결제가 살아 있으면 **다음 청구일에 또 결제**됩니다. 그래서 미리보기와
실행 결과에 빨간 경고를 띄웁니다. 그러나 **해지는 하지 않습니다** — 구독 해지는 학생의
전체 계약에 걸리는 별개 결정이고, 환불 한 건의 부수효과로 처리할 일이 아닙니다.

### 3-6. 남은 수업은 «지우지» 않고 끈다

`DELETE` 가 아니라 `status='cancelled'` + 수업 메모에 「환불로 취소 (refund #N)」.
되돌릴 수 있어야 하고, 「왜 이 수업이 사라졌나」가 남아야 합니다
(스케줄 자리표시 정리와 같은 방식).

### 3-7. 권한 — 강사를 «따로» 막는다

⛔ `canEditOrg()` 하나로 막으면 **강사가 통과합니다**(그 함수는 scope `'none'`=내부직원·교사에 true).
CLAUDE.md 2장에 적힌 함정 그대로라, 두 겹으로 봅니다:

1. `getAdminActor().isTeacher` → 403
2. scope 가 `branch`/`agency`/`franchise` → 403 (지사·대리점은 남의 돈)

⚠️ scope 를 `=== 'hq'` 로만 좁히지 **않았습니다** — `admin_scope` 행이 아직 없는 본사 직원 계정이
`'none'` 으로 잡혀 **정작 환불해야 할 사람이 막히는** 사고가 납니다.

### 3-8. 화면을 admin.html 밖에 따로 만든다

`admin.html`(1.1MB)에 넣으면 그 파일의 전역 규칙이 버튼 색·크기와 `select` 여백을
`!important` 로 덮습니다(CLAUDE.md 2장 「표 안의 작은 아이콘 버튼」·「select 판」).
**돈을 되돌리는 화면에서 빨간 실행 버튼이 흰색으로 나오는 것 자체가 위험**이라
`duplicate-payments.html` 과 같은 방식으로 독립 화면을 뒀습니다.

### 3-9. `src/index.ts`(공동 금지구역)를 건드리지 않았다

- API: `index.ts` 가 `/api/pay/` 접두사를 **통째로** `handlePayApi` 에 넘깁니다 → 새 경로 등록 불필요
- 화면: `/admin/` 아래는 `isAdminPath` 가 **default-deny** 라 인증이 자동으로 걸립니다

### 3-10. 안전장치 — 사람이 실수하기 어렵게

- `confirm:true` 없이는 실행하지 않음 (먼저 «이대로 실행합니다» 계획을 보여 줌)
- 화면에서 **「환불」 두 글자를 직접 입력**해야 실행 버튼이 켜짐
- 금액·모드를 바꾸면 **앞서 받은 확인이 무효**가 됨
- 사유가 비면 진행 불가 (나중에 남는 것은 그 한 줄)
- 같은 주문에 결과 미확인 요청이 있으면 409 로 거절
- 금액 상한은 서버가 다시 계산 (결제액 − 이미 환불한 합계)

### 계산을 «실제로 돌려» 본 것 (하니스 ⑫)

문자열 검사는 「그 함수를 부르는가」만 봅니다. 그래서 `refundPreview` 를 typescript 로
컴파일해 **가짜 D1 로 실제 실행**했습니다(`c24_expense_filter_harness` 방식).
가장 중요한 검사는 이것입니다:

> **이미 30,000원을 환불한 주문에서 권장 금액이 그만큼 줄어드는가** — 줄지 않으면 두 번 줍니다.

계산기(`enrollRefundCalc`)는 «결제액 기준»이라 그대로 쓰면 이미 준 돈을 또 계산합니다.

### 브라우저 검사가 잡은 «진짜 버그» 2건

문자열 하니스·타입체크가 전부 초록불인 상태에서 나왔습니다.

1. **환불 성공 메시지가 곧바로 사라짐** — 성공 후 상태를 다시 읽는 `loadPreview()` 가
   내부에서 `resetRun()` 을 불러 방금 쓴 결과 칸까지 비웠습니다.
   사람 눈에는 «깜빡했다 없어진» 것으로 보이고 실행 여부조차 알 수 없습니다.
2. **폰에서 표가 화면을 옆으로 밀어냄** — 내역 표 619px 가 390px 화면에서 문서를 664px 로 만듦.
   → 표를 `overflow-x:auto` 상자에 넣어 고쳤는데, 그때 `min-width:560px` 를 박았더니
   이번엔 칸이 9개라 한 칸이 60px 이 되어 **「김하나」가 «김/하/나»로 쪼개졌습니다.**
   `width:max-content` + `min-width:100%` + 칸 `nowrap` 으로 다시 고쳤습니다.

두 번째는 **가로 넘침 숫자만 보면 통과**합니다(상자 안에서 굴러가니까) — 그래서 검사에
「칸 높이 ÷ lineHeight 가 3 이상이면 실패」를 함께 넣었습니다.

## 5. 새로 발견해 CLAUDE.md 2장에 넣은 함정 4건

1. 표에 `min-width` 를 **숫자로** 박으면 낱글자로 쪼개진다 (가로 넘침 검사로는 못 잡음)
2. playwright `isMobile:true` 문맥은 좌표가 어긋나 **없는 버그**를 만든다 (실측: 844 지정에 innerHeight 1437)
3. 처리 후 «상태 다시 읽기»가 방금 띄운 완료 메시지를 지운다 (+ 그 함수를 리스너에 그대로 넘기면 반대로 안 지워짐)
4. 이 저장소는 `strictNullChecks:false` 라 **판별 유니온 좁히기가 안 된다** (게이트 헬퍼는 한 가지 모양으로)

## 6. 아직 안 한 것 · 사람이 판단할 것

- ⛔ **실제 환불을 실행해 보지 않았습니다.** 실서비스 결제를 취소하는 일이라 사람이 해야 합니다.
  검증은 전부 «가짜 응답»으로 했습니다.
- ⚠️ **토스 문서를 눈으로 확인하지 못했습니다** — 이 작업 환경의 프록시가 `docs.tosspayments.com`
  을 막습니다. 그래서 코드가 응답 «모양»에 기대지 않게 짰습니다(HTTP 2xx 를 성공으로 보고,
  `status`·`cancels` 는 있으면 기록). **첫 실행은 소액·테스트 결제로 한 번 해 보시길 권합니다.**
- 가상계좌 환불은 돌려줄 계좌(은행·계좌번호·예금주)를 화면에서 받아 넘깁니다.
  실제로 토스가 어떤 은행 코드 표기를 요구하는지는 첫 실행 때 확인이 필요합니다.
- 사이드바(관리자 메뉴)에는 넣지 않았습니다 — 사이드바가 두 벌이라 별건입니다.
  지금은 사이트 지도(`/admin/site-structure-map.html` ▸ 돈 관리)와 직접 주소로 들어갑니다:
  **`https://mangoi.ai/admin/refunds.html`**
- 카페24 결제(`student_payments`)는 이 기능의 대상이 아닙니다 — 토스 결제(`payment_orders`)만입니다.
  회계 화면의 「환불/취소 내역」은 여전히 카페24 장부를 봅니다(별개 계통).
