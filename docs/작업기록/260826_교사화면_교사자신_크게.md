## 1. 왜 했나

PR #502 를 배포한 직후 사장님이 **「교사 화면에서도 교사 자신이 크게 해줘」** 고 하셨습니다.

🔴 **그것은 제가 바로 앞 PR 에서 «버린 방법» 으로 적어 둔 것이었습니다.**

PR #502 작업기록에 저는 이렇게 적었습니다 —

> | 역할(teacher)로 판정해 교사 타일을 키우기 | 그러면 **교사 자기 화면에서 자기 얼굴이 커집니다.** «상대» 기준이 맞고, PC 가 이미 그렇게 동작하고 있었습니다 |

그 근거 두 가지가 모두 약했습니다.

1. **「자기 얼굴이 화면을 지배하면 안 된다」는 우리 짐작이었습니다.** 사장님께 여쭤본 적이 없습니다.
2. **「PC 가 이미 그렇게 동작한다」를 근거로 삼았습니다.** 기존 동작이 곧 옳은 결정이라는 보장은 없는데, 그것을 판단의 근거로 썼습니다.

사장님 판단은 달랐습니다 — 커져야 하는 것은 «상대» 가 아니라 **«교사»** 이고, **누가 보든** 그렇습니다.

> 📌 이 건은 「무엇을 고쳤나」보다 **「왜 내가 먼저 틀렸나」가 남길 값어치가 큽니다.**
> 짐작을 «버린 방법» 표에 단정형으로 적어 두면, 그 뒤로는 아무도 다시 묻지 않습니다.
> 이 저장소가 가장 크게 데인 「«하기로 한 것» 이 «했다» 로 적히면」(2026-08-19 도메인 건)과 같은 뿌리입니다.
> ✅ **사람에게 물어볼 수 있는 것을 코드 주석에서 혼자 결론내지 마세요.**

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### 3-1. 🔴 PC 에서 폭(62%)만 좌우로 뒤집기 — **실제로 해 봤고 실패했습니다**

처음엔 PC 도 폭 문제로 봤습니다. `vc-teacher-first` 의 「내 타일 62% 축소」를 교사 화면에서만 상대에게 옮겼는데, 재 보니 **상대가 여전히 4.44배**였습니다.

`getComputedStyle` + `document.styleSheets` 를 훑어 «이기는 규칙» 을 찾아보고서야 원인이 보였습니다:

```json
"grid":  {"disp":"block", "cols":"1fr", "h":"686.703px"}
"other": {"rect":"211x687", "ar":"auto"}
"mine":  {"rect":"210x158", "ar":"4 / 3", "order":"96"}
```

**≥1024px 에서는 그리드가 아니었습니다.** `css/vc-refresh.css` 53~66행이 —

```css
@media (min-width:1024px){
  #vc-video-grid[data-count="2"]{ display:block !important; grid-template-columns:none !important }
  #vc-video-grid[data-count="2"] .video-box{ position:absolute !important; inset:0 !important }
  #vc-video-grid[data-count="2"] #vc-local-box{
    inset:auto 14px 14px auto !important; width:24% !important; max-width:210px !important;
    aspect-ratio:4/3 !important; z-index:40 !important;
    box-shadow:0 0 0 2px rgba(251,191,36,.6) …   /* 앰버 링 */
  }
}
```

즉 **「상대 전체화면 + 내 타일은 오른아래 작은 PIP」** 입니다. 크기를 정하는 것은 fr 비율도 폭도 아니라 **«누가 PIP 인가»** 하나였습니다. 높이는 `aspect-ratio`·`inset` 이 정하므로, 폭만 바꾸면 **«전체화면인데 폭만 62%»** 라는 어정쩡한 상태가 됩니다.

→ 교사 화면에서는 그 둘을 **맞바꿨습니다**(내가 `inset:0`, 상대가 PIP).

> ⚠️ **같은 화면인데 폭 구간마다 «구조» 가 다를 수 있습니다.** 폰에서 통한 방법이 PC 에서 안 통하는 것이 «규칙이 약해서» 가 아니라 **«레이아웃 방식 자체가 달라서»** 인 경우입니다. 코드만 봐서는 안 보이고, `getComputedStyle` 로 `display` 를 재야 보입니다.

### 3-2. 🔴 PIP 크기를 `vc-refresh.css` 의 `24%` 로 베끼기 — **82px 이 나왔습니다**

맞바꾼 뒤 상대 PIP 가 **82×61** 로 나와 학생 화면의 PIP(210×158)와 짝이 안 맞았습니다.

학생 화면의 그 PIP 는 실제로는 **`vc-teacher-first` 의 62%(상한 210px)** 로 그려집니다 —

| 규칙 | 선택자 | 특정성 |
|---|---|---|
| `vc-refresh.css` `width:24%` | `body.vc-in-call #vc-video-grid[data-count="2"] #vc-local-box` | **(2,2,1)** |
| `vc-teacher-first` `width:62%` | `body.vc-in-call #vc-main-row:not(…):not(…):not(…) #vc-video-grid[data-count="2"] #vc-local-box` | **(3,5,1)** ← 이김 |

→ 62% 로 맞추니 학생 화면과 **정확히 거울**이 됐습니다.

> ⚠️ **CSS 파일에 적힌 값이 화면에 나오는 값이 아닙니다.** 베낄 때는 파일이 아니라 `getComputedStyle` 을 보세요.

### 3-3. 🔴 PC 용 규칙에 미디어쿼리를 안 씌우기 — **폰이 2.58배가 됐습니다**

3-1 의 PC 규칙에 미디어쿼리를 안 두었더니 **폰까지 닿아** 위 fr 규칙과 겹쳐 상대가 **두 번** 줄었습니다.

```
폰 세로·교사 화면:  144px  ×  0.62  =  89px   →  230 ÷ 89 = 2.58배   (1.6배여야 함)
```

→ `@media (min-width:1024px)` 로 묶었고, 하니스가 **«크다» 만이 아니라 상한(1.75)도 함께** 보게 했습니다. 상한이 없었다면 이 사고는 초록불로 통과했을 것입니다.

### 3-4. 🔴 참관(Ghost)을 빼는 것을 잊었습니다 — **trap-check 가 잡았습니다**

`vcIsStaffNow()` 는 `vcMyRole==='admin'` 에도 **true** 를 줍니다. 그런데 **참관자의 `#vc-local-box` 는 영상이 없는 «빈 타일»** 이고 `index.html` 에 정적으로 있어 지워지지도 않습니다.

→ 방에 참가자가 한 명뿐일 때 `data-count="2"` 가 되어 **«빈 내 타일이 전체화면 + 진짜 수업 참가자가 210px PIP»** 가 됐습니다.

실측(1280×800, `admin` + `body.vc-observer`) — 고치기 전:

```
참관자   상대 210x158   나 341x687   → 내가 큼 7.07배   ← 빈 타일이 화면을 덮음
```

고친 뒤:

```
참관자   상대 341x687   나 210x158   → 상대가 큼 7.07배  ← 정상
```

**막은 방법은 두 겹입니다** — 판정에서 `body.vc-observer` 를 빼고(뜻이 코드에 보이게), 선택자에도 `:not(.vc-observer)` 를 걸었습니다. 그 클래스를 붙이는 `js/vc-observe-guard.js` 와 이 파일의 **실행 순서에 기대지 않기 위해서**입니다.

⚠️ **넓게 막지 않았습니다** — 관리자가 «직접 입장»(참관이 아님)한 경우는 그대로 자기 타일이 큽니다. 하니스가 그 줄까지 함께 못 박습니다(⑨-3절).

> 📌 **이건 문자열 하니스로도, 제 눈으로도 못 잡았습니다.** 「역할 판정을 정본으로 했는가」만 보면 통과입니다.
> 잡아 준 것은 **함정 대조 서브에이전트(`trap-check`)** 이고, 근거는 「그 정본이 `admin` 에도 true 를 준다」는 코드 경로였습니다.
> ✅ 정본 판정 함수를 새로 쓸 때는 **«그 함수가 true 를 주는 대상이 전부 내가 생각한 그 사람인가»** 를 한 번 세어 보세요.

### 3-5. 그 밖에 버린 것

| 버린 방법 | 왜 |
|---|---|
| `css/vc-refresh.css` 의 PIP 규칙을 직접 고치기 | **학생 화면까지 함께 바뀝니다.** defer 파일에서 `body.mg-teacher-self` 일 때만 얹으면 원래 규칙이 그대로 남고, **⑨절만 지우면 되돌아갑니다** |
| `index.html` 의 「반반」 규칙(3272·3392·3412)을 고치기 | 같은 이유 + **원래 결정이 왜 그랬는지가 지워집니다**(2026-07-14 「겹침·축소·가림 절대 금지」) |
| `MutationObserver` 로 역할 변화 감시 | body class 를 지켜보면 화면이 멎습니다(2026-07-14 라이브 장애) |
| 3명 이상에도 적용 | **주인공이 정해지지 않습니다.** `data-count="2"` 일 때만 |
| `window.vcMyRole` 을 직접 읽어 판정 | 역할 판정 정본은 `vcIsStaffNow()` 입니다 — 두 벌이 되면 어긋납니다 |

### 🟡 trap-check 가 지적했지만 «결함이 아니었던» 것 — 재 봤습니다

**「넓고 낮은 창(1280×600)에서 폰용 미디어쿼리와 PC 블록이 동시에 참이다」**

| 창 | 학생 화면 | 교사 화면 |
|---|---|---|
