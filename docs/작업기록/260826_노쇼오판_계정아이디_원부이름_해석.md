## 1. 왜 했나

8/25 21:30 수업(`class-895-20260825`, 학생 delaware ↔ 강사 Farrah)에서 두 사람이
같은 방 번호로 들어가고도 서로를 못 봤다. 그 조사 중에 **급여 쪽에서 별개의 문제**가 나왔다.

노쇼 알림이 실제로 떴고(`class_no_show #26`, `teacher_name='HANNAH'`),
`no-show-truth.ts` 를 컴파일해 **운영 실데이터로 돌려 보니**:

```
판정 결과: { present: false }   → 「강사가 없었다」로 **확정**
```

`present === false` 면 급여가 되돌려지지 않는다(`api-admin.ts:2065` — `present===true` 일 때만).
**들어와서 수업한 강사에게 0원이 나갈 상태였다.**

### 뿌리 — 이름이 두 갈래다

| | 값 |
|---|---|
| 예약(`class_schedules.teacher_id=24`) | **HANNAH** |
| 화상수업 출석부에 찍힌 이름 | **교사 mangoi_167** (계정아이디) |

낱말 경계로 맞추므로 `MANGOI_167` ↔ `HANNAH` 는 안 맞는다 → `hit` 이 비고 → `present:false`.

⚠️ **강선생님 건 13건이 잘 걸러진 것은 «우연»이었다** — 예약명 「중국어 강선생님」과
출석명 「교사 강선생님」의 표기가 마침 맞았기 때문이다. 표기 규약은 사람마다 다르다.

같은 모양이 하나 더 있었다: `class-915-20260824` (HANNAH ↔ 교사 **M**angoi_167).

## 2. 무엇을 바꿨나

`teacher_account_links` 로 **계정 → 원부 이름**을 한 번 풀어서도 맞춘다.
`mangoi_167 → HANNAH` 로 풀리므로 제대로 걸러진다.

```ts
// 계정아이디 → 원부 강사 이름. 후보가 하나일 때만 쓴다.
async function accountToTeacherName(db, accounts): Promise<Map<string,string>>

const namesOf     = (username) => [적힌 그대로, 계정을 푼 원부 이름];
const isSamePerson = (username, target) => namesOf(username).some(n => sameTeacherByWord(n, target));
```

### 넓히지 않으려고 둔 안전장치

이 파일에서 **가장 나쁜 실수는 «진짜 노쇼를 오판으로 감춰 수업료를 전액 내보내는» 것**이다.
그래서 푸는 쪽에 빗장을 넷 걸었다.

| 상황 | 동작 | 왜 |
|---|---|---|
| 한 계정이 **여러 강사**로 풀림 | 그냥 버린다 | 틀린 이름을 붙이면 진짜 노쇼가 감춰진다 |
| 링크 조회 **실패**(표 없음 등) | 던지지 않고 예전 동작 | 이 해석은 «덤» 이다. 리포트가 안 뜨는 게 더 나쁘다 |
| 푼 이름이 **학생과도** 걸림 | «모름»(null) | 강사 쪽만 넓히면 기존 안전장치가 한쪽만 헐거워진다 |
| 링크가 **다른 강사**를 가리킴 | 안 걸린다 | 올리는 근거는 여전히 «이름 일치» 뿐 |

⛔ **계정 조회는 대소문자를 무시한다.** `mangoi_167` 과 `Mangoi_167` 이 실제로 둘 다 있고,
**링크는 대문자 쪽에만 붙어 있다**(CLAUDE.md 2장 「같은 사람인데 계정이 두 개」).
대소문자를 구분하면 고쳐 놓고도 안 걸린다.

## 3. 검토했다가 버린 방법

| 버린 방법 | 왜 버렸나 |
|---|---|
| **출석부에 계정아이디 대신 원부 이름을 찍게** 한다 | 근본적이지만 **이미 쌓인 기록은 안 고쳐진다.** 노쇼·급여는 과거 기록을 읽는다. 그리고 입장 이름을 만드는 자리가 여러 곳(`teacher.html`·경량 화면)이라 반경이 넓다 |
| `class_no_show.teacher_name` 을 **UPDATE** 로 정정 | ⛔ 이 파일의 1원칙 위반 — 「기록을 지우거나 고쳐 쓰지 않는다. 읽을 때 대조한다」. 게다가 운영 DB 쓰기 |
| `attendance.role='teacher'` 를 근거로 올린다 | ⛔ role 은 클라이언트가 보내는 값이고 「먼저 들어온 학생이 강사 역할을 받는」 전례가 있다. 진짜 노쇼가 감춰진다 |
| 이름 비교를 **부분일치**로 넓힌다 | ⛔ `Anna ⊂ HANNAH` 류 우연이 걸린다. 낱말 경계를 둔 이유가 그것이다 |
| `teacher_account_links` 대신 `admin_account.name` 을 쓴다 | 그 칸은 「Teacher - Hannah」처럼 표시용이라 규약이 또 다르다. 링크 표가 **관리자가 지정한 정본**이다 |
