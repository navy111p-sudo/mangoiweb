# 로그인 아이디 대소문자 무시 — 어린이 학생이 제일 헷갈리는 것

**날짜** 2026-08-26 · **지시** 사장님
> 「mangoi.ai 사이트 접속시 아이디와 비번을 소대문자 구분을 주지 말아줘.
>  가장 어린이 학생들이 헷갈리는게 소대문자야. 한국어에는 소대문자가 없어서 다들 헷갈려해.」

---

## 1. 왜 했나 — 그리고 먼저 확인한 사실

지시는 「아이디와 비번 둘 다」였지만, 손대기 전에 실제 상태를 재 봤습니다. 둘의 사정이 전혀 달랐습니다.

| | 실측(2026-08-26 운영 D1) |
|---|---|
| 학생 계정 | **29,417명** |
| 그중 **비밀번호가 설정된 계정** | **0명** |
| 아이디에 대문자가 섞인 계정 | **8,652명** |
| 비밀번호가 실제로 있는 계정 | 강사·관리자 `admin_account` **49개**(대문자 섞인 것 2개) |

즉 **학생에게 「비밀번호 대소문자」 문제는 존재하지 않습니다.** 학생 로그인 화면의 비밀번호 칸은
「비밀번호 (없으면 비워두기)」이고, 실제로 전원이 비워 둡니다. 헷갈릴 것은 **아이디뿐**입니다.

반대로 비밀번호가 실제로 있는 49개는 **급여·회계·학생 29,000명 명부를 여는 열쇠**입니다.

→ 사장님께 이 숫자를 보여 드리고 **「비번은 그대로 두기」** 를 선택받았습니다.

### 그리고 고쳐야 할 진짜 구멍이 따로 있었습니다

2026-08-24·25 에 대소문자 무시를 넣었지만 **로그인 쪽이 반쪽**이었습니다.

`/api/student/login` 은 `COLLATE NOCASE` 는 있는데 **`ORDER BY` 가 없어**
대소문자만 다른 두 행 중 **아무거나** 집었습니다. 그리고 그런 행이 **실재합니다** —

```
Kim  (korean_name=Kim)     kim  (korean_name=김민수)
Lee  (korean_name=Lee)     lee  (korean_name=이병엽)
```

`kim` 으로 로그인해도 `Kim` 이 잡힐 수 있었습니다. 출석·포인트·평가서가 통째로 남의 것이 됩니다.
같은 규칙(⛔ NOCASE 하나로만 찾지 말 것)이 **관리자 로그인에만** 적혀 있었던 것이 원인입니다.

## 2. 무엇을 했나

### 서버 — 아이디는 완전히 대소문자 무시 (`src/api-students.ts`)

「**정확일치를 먼저** 보고, 없을 때만 대소문자만 다른 행」 — 관리자 로그인(`auth-admin.ts`)과 같은 규칙을
아직 안 걸린 **네 곳**에 넣었습니다.

| 경로 | 전 | 후 |
|---|---|---|
| `/api/student/login` | NOCASE 만 (아무거나 집음) | + 정확일치 우선 · LIMIT 1 |
| `/api/student/lookup` (연장 결제 본인확인) | **NOCASE 없음** | NOCASE + 정확일치 우선 |
| `/api/student/set-password` | **NOCASE 없음** | NOCASE + 정확일치 우선 + **UPDATE 는 DB 표기로** |
| `/api/parent/dashboard` | **NOCASE 없음** | NOCASE + 이후 조회를 전부 DB 표기로 통일 |

⚠️ `set-password` 의 UPDATE 가 중요합니다 — 입력 표기로 쓰면 대소문자가 다른 순간
「저장했다는데 새 비번으로 로그인이 안 되는」 상태가 되는데 **0건 UPDATE 는 에러를 내지 않습니다.**

### 화면 — 폰 키보드가 아이디를 대문자로 만드는 것

서버로는 못 막는 부분입니다. 이유가 둘입니다.

1. `autocapitalize` 기본값이 `sentences` 라 폰이 **첫 글자를 대문자로** 만듭니다.
   서버가 무시하니 로그인은 되지만, **화면에 대문자가 찍히는 것 자체가 아이를 멈춰 세웁니다.**
2. **자동고침(autocorrect)은 아예 딴 낱말로 바꿉니다** — 이건 서버가 대소문자를 무시해도 로그인이 깨집니다.

그래서 아이디 칸에 `autocapitalize="off" autocorrect="off" spellcheck="false"` 셋을 함께 답니다.

- `admin/login.html`(`#username`) · `parent.html`(`#uid-input`) → 마크업에 직접
- `index.html` 안의 칸(`vc-name-input`·`ext-uid`)과 **모달을 열 때 JS 가 만드는 `lm-uid`**
  → **`js/session-guard.js` 꼬리에서 밖에서 입혀 줍니다**

### 비밀번호 — Caps Lock 안내 (`admin/login.html`)

비밀번호는 대소문자를 그대로 봅니다. 그래서 **「틀렸습니다」 뒤가 아니라 치기 전에** 원인을 보여 줍니다.
`getModifierState('CapsLock')` 을 `keydown`·`keyup` 둘 다에서 봅니다.
(폰에는 Caps Lock 이 없어 안 뜹니다 — 폰은 기존 👁 「비밀번호 보기」가 그 역할입니다.)

## 3. 검토했다가 버린 방법 ← 가장 중요

### ⛔ 비밀번호를 소문자로 바꿔서 해싱 (= 진짜 «비번 대소문자 무시»)
지시의 문자 그대로지만 버렸습니다. ① **기존 49개 비밀번호가 전부 안 맞게 되어** 전원 재설정이 필요하고
② 그 계정들이 급여·회계·학생 명부를 여는데 강도를 크게 낮추며
③ **정작 헷갈리는 학생에게는 이득이 0** 입니다(비밀번호를 쓰는 학생이 없습니다).
숫자를 보여 드리고 사장님이 「비번은 그대로」를 선택하셨습니다.

### ⛔ 비밀번호 변형 3종 시도 (입력 그대로 → 전부 뒤집기 → 첫 글자만 뒤집기)
Caps Lock·폰 자동대문자 두 가지 실제 오타를 덮는 알려진 절충안이고 안전 손실도 작습니다(약 1.5비트).
사장님께 선택지로 올렸지만 같은 이유로 **채택되지 않았습니다.** 필요해지면 이 방식이 1순위입니다.

### ⛔ 스키마를 `COLLATE NOCASE` 로 바꾸기
대소문자만 다른 행이 **실재**해서(Kim/kim, Lee/lee) UNIQUE 에 걸리고 표를 다시 만들어야 합니다. 운영 DB 라 반경이 큽니다.

### ⛔ 중복 계정(Kim/kim, Lee/lee)을 지워서 정리
지시 범위 밖이고 D1 변경입니다. 게다가 `created_at=1751500000000`(카페24 센티넬)이라
**지워도 밤에 되살아납니다.** 정리가 필요하면 `student_erp_override` 로 사람이 판단할 일입니다.

### ⛔ `index.html` 을 직접 고쳐서 속성 달기
**공동 금지구역**입니다. 게다가 첫 화면 blocking 예산 여유가 **350바이트**뿐이라
`js/idx-user-session.js`(blocking) 에 적는 것도 예산을 갉아먹습니다.
→ **이미 실려 있는 defer 파일**(`session-guard.js`, 학생 로그인 화면 3곳을 모두 덮음)에 넣어
**blocking 0바이트**로 해결했습니다(1562KB 그대로).

### ⛔ 상주 `MutationObserver` 로 새 입력칸 감시
`lm-uid` 는 모달을 열 때 생기므로 감시가 필요해 보이지만, 이 저장소에는 그것이
**홈 화면을 통째로 멎게 한 전력**이 있습니다(CLAUDE.md 2장). 대신 `pointerdown`·`focusin` **캡처**로
누르는 순간 손봅니다 — 포커스보다 먼저라 키보드가 뜨기 전에 속성이 박힙니다.

| 검사 | 결과 |

### 되돌려 보면 실제로 FAIL 나는가
`/api/student/login` 의 `ORDER BY` 만 빼서 옛 동작으로 돌려 보았고,
⑥절이 **FAIL(PASS 51/FAIL 1)** 을 냈습니다. 되돌린 뒤 다시 58 PASS.

### 새로 만든 검사
- `test-harness/login_username_case_harness.mjs` **⑥·⑦절 추가**
  - ⑥ 소스에서 로그인 SQL 을 오려 내 **진짜 SQLite** 에 `Kim`/`kim`·`Lee`/`lee` 를 넣고
    「`kim` 으로 치면 정확히 `kim`」 을 확인. 문자열이 아니라 **무엇을 고르는가** 로 판정합니다.
  - ⑦ 화면 속성·Caps Lock 배선
- `test-harness/manual/login-case-browser.mjs` **(신규, 12종)** — 진짜 Chromium.
  `lm-uid` 는 **소스에 속성이 없다**는 전제까지 함께 확인합니다(밖에서 입히는 것이 유일한 방어라서).
  ⚠️ `manual/` 이라 **게이트가 물어 가지 않습니다.** 로그인 화면·`session-guard.js` 를 건드리면 사람이 부르세요:
  `node test-harness/manual/login-case-browser.mjs`

### 🐞 만들다가 밟은 함정 두 개 (CLAUDE.md 2장에 넣었습니다)
1. **부정 검사가 자기 주석을 잡음** — 「MutationObserver 를 쓰지 않는다」 검사가
   그 낱말을 적어 둔 **설명 주석**에 걸려 FAIL. 문서화된 `stripComments` 방식으로 고쳤습니다.
2. **반투명 배경을 합성하지 않아 대비를 잘못 읽음** — `rgba(251,191,36,0.14)` 를 그대로 배경색으로 써서
   멀쩡한 대비를 **1.16** 으로 읽었습니다. 불투명 층까지 모아 `c*a + bg*(1-a)` 로 겹치니 통과.
   ⛔ 이걸 「디자인이 틀렸다」로 읽고 색을 고치러 갔으면 없는 버그를 쫓았을 것입니다.

## 5. 남은 것 · 주의

- ⚠️ **화면이 바뀌는 작업이라 사람이 한 번 봐야 끝납니다**(CLAUDE.md 4-1-1).
  프록시가 `mangoi.ai` 를 막아 배포된 실제 화면은 확인할 수 없습니다.
  볼 곳: 홈 로그인 모달 · `/admin/login.html`(Caps Lock 안내) · `parent.html`.
- ⚠️ **`public/admin/login.html` 은 관리자 영역(A 담당)입니다.** 아이디 칸 속성 3개와
  Caps Lock 안내를 넣었습니다 — A 에게 알려야 합니다(CLAUDE.md 4-2).
- ⚠️ **`Kim`/`kim`·`Lee`/`lee` 중복 행은 그대로 둡니다.** 이제 정확일치가 이기므로 안전하지만,
  둘 다 카페24 센티넬이라 지우려면 카페24에서 해야 합니다. 확인:
  `SELECT LOWER(user_id) k, COUNT(*) n, GROUP_CONCAT(user_id) FROM students_erp GROUP BY k HAVING n>1`
- ℹ️ 앞으로 새 로그인 화면을 만들면 아이디 칸에 **`autocomplete="username"` 만 달아도**
  `session-guard.js` 가 자동으로 잡습니다(그 파일이 실린 화면에 한해).
