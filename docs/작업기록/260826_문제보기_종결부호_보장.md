## 1. 왜 했나

사장님이 판단력 훈련 화면을 보시고 물으셨다 — 「**답변의 각 문장 끝에 마침표를 찍어야 하니? 아니면 나둬도 될까?**」

실제 화면(`mangoi.ai/judgment.html`)이 이랬다.

| 자리 | 끝 |
|---|---|
| 상황문 `Elevator doors close on my coworker's briefcase.` | **`.` 있음** |
| 보기 A `What's wrong with you?` | **`?` 있음** |
| 보기 B `Sorry, that was my fault` | **없음** |
| 보기 C `You're really careless` | **없음** |
| 보기 D `Be more careful next time` | **없음** |

문제는 「마침표가 없다」가 아니라 **한 카드 안에서 규칙이 갈렸다**는 것이었다.
**물음표·느낌표는 «뜻을 지고 가는» 부호라 뺄 수 없다.** 그래서 가지런하게 만드는 길은
**마침표를 찍는 쪽 하나뿐**이고, 「전부 빼기」는 애초에 성립하지 않는다.

거기에 이 화면은 **영어를 가르치는 화면**이다. 보기는 버튼 «라벨» 이 아니라 학생이
실제로 입으로 할 **완결된 문장**이고, 옆의 상황문·해설은 이미 마침표를 찍고 있었다.

그렇게 답을 드리자 사장님이 범위를 넓히셨다 — 「**여기 뿐만 아니라 모든 문제나 답변에
마침표나 물음표 등등 자세히 구석구석 찾아보고 찍어줘.**」

## 2. 무엇을 바꿨나

### 정본 — `cloudflare-deploy/src/sentence-punct.ts` (신설, **import 가 하나도 없는 순수 모듈**)

`endSentence()` 하나가 정본이고 **«찍지 않는 쪽» 으로 실패**하도록 짰다.

| 입력 | 출력 | 근거 |
|---|---|---|
| `Sorry, that was my fault` | `Sorry, that was my fault.` | 평서문 |
| `Can you help me` | `Can you help me?` | 영어 의문문 — **첫 낱말**로 판정 |
| `이 문장이 맞나요` | `이 문장이 맞나요?` | 한국어 **종결어미** |
| `🎧 잘 듣고 알맞은 답을 고르세요` | `… 고르세요.` | 한국어 평서·명령 어미 |
| `你好` · `我很好` | **그대로** | 한자는 「。」를 쓴다 |
| `Sounds good 😊` · `Sorry,` | **그대로** | 붙일 수 없는 글자 |
| `The manager ____` | **그대로** | TOEIC 빈칸 |
| `고마워` · `뭐 해` | **그대로** | **반말은 평서·의문 어미가 같아 판정 보류** |
| `Mr. Kim` | `Mr. Kim.` | 약어 뒤에 낱말이 더 있으면 문장 끝이 아니다 |
| `Wait...` · `What's wrong with you?` | **그대로** | 이미 끝났다 |
| `"Sorry"` | `"Sorry."` | 통째로 싸인 따옴표는 **안쪽** |
| `정답: 你好 (nǐ hǎo)` | `정답: 你好 (nǐ hǎo).` | 끝에 달린 괄호 주석은 **뒤** |

보조로 `PUNCTUATION_PROMPT_RULE`(생성 프롬프트에 넣는 지시 한 줄)도 같은 파일에 뒀다.

### 적용한 자리 — **문장인 칸만**

| 파일 | 찍은 곳 | ⛔ 안 찍은 곳 |
|---|---|---|
| `api-judgment.ts` | 보기(`opts4`) · 상황문 · 해설 `why`·`why_ko` | — |
| `api-exam.ts` | `question_text` · `audio_script` | **`choice_a~d`** (TOEIC 식 낱말·구) |
| `api-games.ts` 복습퀴즈 | `q` · `explain` · `audio_text` · `answer_text` · **`listen` 의 `opts` 만** | **`choice` 의 `opts`** (낱말) · `accept[]`(화면에 안 보임) |
| `api-games.ts` 단어장 | AI `example` · 유의어 `example` | **`korean`**(낱말 뜻) · 단어퀴즈 보기 |

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### ⛔ ① 「한 규칙으로 전부 찍기」 — 가장 위험했던 길

구석구석 찾아보니 **같은 «보기» 칸인데 문장인 곳과 낱말인 곳이 섞여** 있었다.

- 판단력 보기 → `Sorry, that was my fault` (**문장**)
- 단어퀴즈 보기 → `어려운` · `你好` · `go to school` (**낱말**)
- 복습퀴즈 `opts` → **`choice` 는 낱말인데 `listen` 은 «들려준 문장 + 오답 문장»**

즉 **문장/낱말이 칸 이름으로 갈리지 않는다.** 일괄로 찍었다면 「어려운.」·「你好.」 가 되어
**고치려던 것보다 큰 고장**이 났을 것이다. 그래서 자리마다 «문장인가» 를 사람이 판단해 걸었다.

### ⛔ ② 「프롬프트에 한 줄 넣기」로 풀기

문항은 문제은행이 아니라 **LLM 이 요청마다 실시간 생성**한다. 이 저장소에는
**지시만으로는 안 지켜진다**는 반복 실측이 있다 — 단어 수(`situationFitsBand`)와
문법(`grammarCheckPrompt`)이 그래서 «세어 보고 / 다시 읽혀 보고 다시 뽑는» 구조가 됐다.

프롬프트만 넣으면 **절반만 찍힌 상태**가 되는데, 그건 지금보다 나쁘다
(지금은 최소한 「물음표만 있다」는 일관된 규칙이라도 있었다).
`PUNCTUATION_PROMPT_RULE` 은 **보조로만** 넣고 정본은 결정론 함수다.

### ⛔ ③ 한국어 어미 판정을 넓히기

「고마워」·「뭐 해」 같은 **반말은 평서문과 의문문의 어미가 같다.** 넓히면
**반말 의문문에 «.» 이 박힌다.** 그래서 확신이 서는 어미(`까`·`나요`·`가요`… / `요`·`다`·`오`…)만
넣고, 「…단어는」처럼 판정이 안 서면 **손대지 않는다.**

### ⛔ ④ 닫는 부호를 무조건 벗겨 내고 안쪽에 찍기 — **실제로 밟았다**

처음엔 「끝의 닫는 부호를 벗겨 내고 그 안쪽에 찍는다」로 짰다. `"Sorry"` → `"Sorry."` 는 맞는데,
`정답: 你好 (nǐ hǎo)` 가 **`정답: 你好 (nǐ hǎo.)`** 가 됐다 — 괄호 주석 안에 마침표가 들어간 것이다.
지금은 **통째로 한 쌍의 따옴표로 싸인 문장만** 안쪽에 넣고, 나머지는 **뒤**에 찍는다.

### ⛔ ⑤ `listen` 의 대본과 보기를 따로 처리하기

영어 복습퀴즈 프롬프트에 「듣기 보기에는 **들려준 문장 자체**가 정답 보기로 들어가야 한다」가 있다.
`audio_text` 만 다듬고 `opts` 를 그냥 두면 **정답 보기와 대본이 «마침표 하나 차이» 로 어긋난다.**
그래서 `listen` 일 때만 둘을 함께 다듬는다(`choice` 는 낱말이라 그대로).

### ⛔ ⑥ 이미 저장된 옛 문항을 일괄 UPDATE

개발·운영이 **같은 D1** 이라 사람 확인 없이 하지 않았다. 이번 변경은 **«앞으로 생성되는» 문항에만** 적용된다.

### ✅ 채점을 건드리지 않는다는 것을 먼저 확인했다

`answer_text` 를 다듬어도 안전한 이유는 채점 정규화 `rqNorm` 이
`replace(/[^a-z0-9가-힣一-鿿\s']/g, ' ')` 로 **구두점을 통째로 지우기** 때문이다.
같은 이유로 `countWords`(구두점 토큰 안 셈)·`normSituation`(영숫자만 남김)도 영향이 없다.
⚠️ **그 전제가 깨지면 채점이 흔들린다.**

## 5. 남은 것 / 주의할 것

### ⏳ 사람이 확인할 것

판단력 훈련에서 **문제를 새로 한 번 뽑아** 보기 네 개가 모두 `.` 또는 `?` 로 끝나는지 봐야 한다.
⚠️ **새로고침만으로는 안 보인다** — 이미 뽑아 둔 문제는 그대로이고, **새 문제를 받아야** 반영된다.

### ⏳ 옛 데이터는 그대로다

D1 `vocabulary.example` · `review_quizzes.questions` 에 이미 저장된 문장은 손대지 않았다.
정리하려면 건수를 먼저 세고 사람이 결정해야 한다(운영 DB).

### ⚠️ 이 모듈을 새 자리에 쓸 때

**«문장인가» 를 먼저 판단하고 부르세요.** 낱말 보기에 부르면 「어려운.」 이 된다.
`endSentence` 는 한자·이모지·빈칸을 스스로 걸러 주지만, **한국어 낱말**(「어려운」)은
평서 어미로 끝나면 마침표를 붙일 수 있다 — **호출하지 않는 것이 방어선**이다.

### ⚠️ 담당 영역

`api-games.ts` 는 CLAUDE.md 4-2 상 **B 담당**이다. 사장님 지시로 함께 고쳤으니 공유가 필요하다.
`src/index.ts`(공동 금지구역)는 **손대지 않았다.**

### 📌 CLAUDE.md 2장에 함정 한 줄을 넣었다 (PR #501 에 포함)

「문제·보기 끝에 **마침표를 일괄로 찍으려** 할 때」 — 낱말 보기가 고장난다는 것,
반말 보류, 괄호 주석의 부호 자리, 프롬프트로 풀면 안 되는 이유, `rqNorm` 전제까지.
