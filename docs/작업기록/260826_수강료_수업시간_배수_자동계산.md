# 수강료가 «수업 시간 배수» 를 타게 (2026-08-26)

> 사장님 지시 — 「수업 시간 배수대로 수강료도 자동 계산되게 해줘」.
> 앞선 [PR #541](https://github.com/navy111p-sudo/mangoiweb/pull/541) 보고에서
> 「40분을 골라도 요금은 사람이 적은 값 그대로」라고 올린 것에 대한 결정입니다.
> 브랜치: `claude/work-progress-review-ncanfv`

---

## 1. 왜 했나

`class-policy.ts` 가 직접 경고하는 대목입니다 —

> ⚠️ 수업료(enroll-ops)와 강사료(api-admin 급여)가 **반드시 같은 배수**를 써야 한다.
> 한쪽만 바꾸면 강사가 30분을 가르치고 20분 값을 받는다.

그런데 관리자 수강신청 등록은 `monthly_fee_krw` 를 **사람이 적은 값 그대로** 저장하고 있었습니다.
수업 시간 칸(20/30/40분)이 2026-08-26 에 생겼는데도 요금은 따라가지 않았습니다.

학생 연장결제 경로(`enroll-ops.ts` 의 `enrollQuoteCalc`)는 **이미 길이 배수를 제대로** 쓰고 있었습니다.
즉 같은 회사 안에서 **두 경로의 요금 규칙이 서로 달랐던** 것입니다.

---

## 2. 어떻게 고쳤나

### 2-1. 계산 정본을 파일 하나로 — `src/enroll-fee.ts`

```
월 수강료 = 기준가(20분) × 길이배수 (10원 절사)
기준가   = ① 사람이 적은 값  ② 없으면 대리점 단가 × 주 횟수  ③ 둘 다 없으면 null
```

* 길이 배수는 `class-policy.ts` 의 `classLengthMultiplier` 를 그대로 씁니다(20분 1.0 / 30분 1.5 / 40분 2.0).
* 10원 절사 자리는 `enrollQuoteCalc` 와 같게 맞췄습니다 — 두 화면의 금액이 어긋나지 않게.
* 대리점 단가는 이미 있는 정본 `priceForUid()` 를 씁니다. **새 요금 정책을 만들지 않았습니다.**

### 2-2. 🔴 곱하는 자리는 «저장하는 순간» 딱 한 곳

이 작업에서 제일 무서운 것은 **«두 번 곱하기»** 입니다. 화면이 곱해서 보내고 서버가 또 곱하면
40분이 **4배**가 되어 그대로 과금 사고입니다.

그래서 —

| 자리 | 무엇을 하나 |
|---|---|
| `api-admin.ts` 의 `POST /api/admin/enrollments` INSERT | **여기서만 곱합니다** |
| 확정 단계(`enroll-activate.ts`) · 정기결제 예약 · CSV · 워드 요약 | 저장된 최종값을 **그대로** 씁니다 |
| 화면(`adm-core.js`) | 곱하지 않고 **보여 주기만** 합니다 |
| `api-pay.ts` 토스 결제 자동활성화 | **손대지 않았습니다** — 그 금액은 이미 `enrollQuoteCalc`(길이배수 포함)을 지난 «실제 결제액» 이라 여기서 또 곱하면 곧바로 과금 사고입니다 |

곱하기 **«전»** 값은 `base_fee_krw` 컬럼에 따로 남깁니다. 안 남기면 「이 금액이 왜 이 금액인지」가
사라져 되돌아볼 수도, 다시 계산할 수도 없습니다.

### 2-3. 사람이 확정 «전에» 근거를 봅니다

확정 패널(「확정하면 이렇게 됩니다」)에 한 줄을 넣었습니다 —
**「요금 근거 — 20분 기준 60,000원 × 30분 1.5배」**

숫자만 보여 주면 틀려도 아무도 모릅니다. 이 금액은 정기결제 자동화가 **실제로 청구**합니다.

## 3. 검토했다가 버린 방법

| 버린 방법 | 왜 |
|---|---|
| **화면에서 곱해서 보내기** | 서버가 또 곱하면 4배. 화면은 보여 주기만 하고 서버가 정본입니다 |
| **읽을 때마다 곱하기**(확정·CSV·워드에서 각각) | 판정을 여러 곳에 복제하는 것 — 이 저장소가 반복해서 밟은 사고입니다. 한 곳만 빠뜨리면 화면마다 금액이 달라집니다 |
| **기준가가 없을 때 «그래도 뭐라도» 넣기** | 그 금액이 실제로 청구됩니다. 못 구하면 `null` 로 두면 확정 단계가 예전처럼 「월 수강료가 0원입니다」 로 멈춥니다(=오늘과 같은 동작) |
| **대리점 단가로 사람이 적은 값을 덮어쓰기** | 협의가가 사라집니다. **입력값이 이깁니다** |
| **기간할인(6개월 95%·12개월 90%)까지 월 요금에 얹기** | 지시는 «길이 배수» 였습니다. 기간할인은 패키지 선결제에 붙는 것이고, 월 구독에 얹는 것은 새 요금 정책이라 사람이 정할 일입니다 |
| **`enrollQuoteCalc` 를 그대로 부르기** | 그 함수는 «N개월 패키지 총액» 을 냅니다. 여기 필요한 것은 «월 요금» 이고, `months` 허용 목록도 [1,3,6,12] 뿐이라 등록 표의 1~12개월·무기한과 안 맞습니다 |
| **옛 행을 일괄 UPDATE 해서 소급 적용** | 운영 DB 이고 실제 청구가 걸립니다. 새로 등록하는 것부터 적용합니다 |

## 4. 확인한 방법

| 무엇 | 결과 |
|---|---|
| 타입체크 `tsc --noEmit` | exit 0 |
| 회귀 하니스 `run.mjs --fast` | **PASS 220 / SKIP 20 / FAIL 0** |
| 신규 `enroll_fee_length_harness.mjs` | **25건** — 계산 정본을 **컴파일해 실제로 돌립니다** |
| 되돌리면 FAIL 나는가 | ✅ 확인 — 저장을 옛 방식으로 되돌리니 FAIL 1 |

하니스가 못 박는 것 중 중요한 둘:

* **분당 단가가 20·30·40분에서 모두 같은가** — `class-policy.ts` 가 「길이로 깎아 주면 그 순간 손해」라고
  못 박은 규칙을 숫자로 확인합니다.
* **두 번 곱하면 4배가 된다** — 그 상태를 «틀린 값» 으로 적어 두어, 나중에 누가 곱하는 자리를
  하나 더 만들면 바로 드러나게 했습니다.

## 5. 확인하지 못한 것 · 남은 것

* 🔴 **운영 D1 실측을 못 했습니다** — 이 세션의 Cloudflare D1 도구가 계정 권한 오류(403)로 막혀,
  `enrollments` 에 월 수강료가 실제로 몇 건이나 채워져 있는지 **세어 보지 못했습니다.**
  판단 근거는 **코드 경로 읽기까지**입니다. 확인하려면:
  `SELECT COUNT(*), SUM(monthly_fee_krw > 0), SUM(duration_min IS NOT NULL) FROM enrollments`
* **옛 행은 그대로입니다** — 이미 저장된 수강신청의 금액은 바뀌지 않습니다(소급 적용 안 함).
* **`base_fee_krw` 칸은 첫 등록 요청이 돌아야 생깁니다**(`ALTER TABLE ADD COLUMN` 방식).
  배포 직후 SQL 을 돌리면 `no such column: base_fee_krw` 가 날 수 있는데 **배포 실패가 아닙니다**
  (`attendance.host`·`vc_quality.novideo` 와 같은 사정).
* **그룹수업(1:N) 요금**은 손대지 않았습니다 — 인원별 단가는 별건이고 지시 범위 밖입니다.
* **기간할인을 월 요금에 얹을지**는 사장님이 정하실 일로 남겨 두었습니다(3장).
* ⏳ **화면은 사람이 한 번 봐야 끝납니다** — 프록시가 `mangoi.ai` 를 막아 배포 화면을 못 봅니다.
  30분·40분으로 등록해 보고 확정 패널의 「요금 근거」 줄이 맞는지 확인해 주세요.
