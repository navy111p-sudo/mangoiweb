## 2. 실측 — 짐작이 아니라 숫자로 좁혔다

### 2-1. 다락원 문항에서 «영어로 오인되는» 것이 무엇인가

```sql
SELECT COUNT(*) total,
  SUM(CASE WHEN v GLOB '*[A-Za-z]*' THEN 1 ELSE 0 END) has_latin,
  SUM(CASE WHEN v GLOB '*[A-Za-z]* *' AND length(v)<=90 THEN 1 ELSE 0 END) multiword
FROM (SELECT COALESCE(NULLIF(json_extract(j.value,'$.answer_text'),''),
                      NULLIF(json_extract(j.value,'$.audio_text'),''),
                      NULLIF(json_extract(j.value,'$.target'),''), '') v
      FROM review_quizzes rq, json_each(rq.questions) j
      WHERE rq.active=1 AND rq.textbook='다락원')
```

| | 값 |
|---|---|
| 문항 총수 | **178** |
| 라틴 글자를 가진 것 | **14** |
| 두 낱말 이상 | **0** |

그 14개가 전부입니다 — `dìtiě` `jīpiào` `dìzhǐ` `dòngwùyuán` `diànhuà` `yīyuàn` `kělè`
`cāochǎng` `wéijīn` `shuāngyǎnpí` `lánqiú` `yùxí` `túshūguǎn` `Hànyǔ`.

이 숫자가 세 갈래를 갈랐습니다.

| 자리 | 옛 판정 | 결과 |
|---|---|---|
| `handleGamesVocab` (`pushSentence`) | `/[a-zA-Z]/` + 90자, **낱말 수 하한 없음** | 🔴 **14개가 그대로 영어 게임 문장으로 나감** |
| `handleGamesLessons` 영어 갈래 | 같은 판정 + `w.length < 2` continue | 한 낱말이라 전부 걸러짐 → 문장 0건 |
| `warmupLessonContext` | 같은 판정 | 배정 학생에게만 — 아래 2-3 |

### 2-2. 🔴 그런데 문장을 걸러도 «코스 목록» 은 안 고쳐진다

`/api/games/lessons` 의 영어 코스 목록은 **`review_quizzes` 를 통째로 훑어** 만듭니다.

```sql
SELECT textbook FROM review_quizzes WHERE active=1 … GROUP BY textbook ORDER BY textbook ASC
```

실측(2026-08-26) 결과 활성 교재 문자열은 **14개**이고 그중 하나가 **「다락원」** 입니다.
즉 **영어 게임의 코스 고르기에 중국어 교재가 한 칸 섞여 나옵니다.**
그리고 골라도 **레슨이 0개**입니다 — 그 교재의 라틴 글자 값은 전부 한 낱말 병음이라
영어 갈래의 `w.length < 2` 에 전부 걸립니다.

### ⚠️ 여기서 제가 한 번 틀렸습니다 (정정)

처음에 저는 이렇게 적었습니다 —

> ~~「다락원이 활성 15건으로 가장 큰 코스라 목록 1위가 되고, `courses[0]` 이 기본 코스이므로
> 교재 미배정 학생 29,417명 «전원»에게 기본 코스가 다락원이었다」~~

**틀렸습니다.** `count` 는 «퀴즈 건수» 가 아닙니다 —

```ts
cc.keys.push({ key: p.key, seq: p.seq, title: p.title }); cc.count = cc.keys.length;
```

**«그 코스로 묶이는 distinct textbook 문자열 수»** 입니다. `GROUP BY textbook` 이라
다락원은 15건이어도 **문자열이 하나** → `count = 1`.

실제 순위(같은 날 실측):

| 코스 | 묶이는 교재 문자열 | count |
|---|---|---|
| **BTS 1** | `BTS 1 001` ~ `BTS 1 008` | **8** ← 1위·기본 코스 |
| 기타 교재 | `004. …` · `007. …` | 2 |
| BTS 12 Korea / BTS 2 Korea / SIU BOOKS / **다락원** | 각 1개 | 1 |

`Array#sort` 가 안정 정렬이라 동점은 삽입 순서(=`textbook ASC`, 한글이 ASCII 뒤)를
유지하므로 **다락원은 오히려 목록 맨 뒤**입니다.

**고쳐야 할 것은 맞지만 심각도는 제가 말한 것보다 낮습니다.**
`trap-check` 서브에이전트가 코드를 읽고 짚어 줬고, D1 로 다시 재서 확인했습니다.
심각도를 부풀린 문장이 규칙서·코드 주석에 박히면 **다음 사람이 엉뚱한 것을 고칩니다** —
이 저장소가 가장 크게 데인 방식(「하기로 한 것」이 「했다」로 적힌 것)의 사촌입니다.
그래서 코드 주석·CLAUDE.md·이 문서를 전부 정정하고, 하니스에
「그 문장으로 되돌아가지 않았는가」를 검사로 박아 뒀습니다.

### 2-3. 반대로 «오늘 당장은 안 새는» 것도 정확히 적어 둔다

- `warmupLessonContext` 와 `handleGamesVocab` 은 학생의 **배정 교재/레벨**이 있어야 문장을 뽑습니다.
  전원이 NULL 이라 오늘은 실제로 안 샙니다. **교재를 배정하는 순간** 샙니다.
- 다만 `handleGamesVocab` 의 레벨 폴백에는 웜업과 달리 **`AND (textbook IS NULL OR textbook='')` 가 없습니다.**
  그리고 `level='Lv 3'` 인 활성 퀴즈는 **전부 다락원**입니다 —
  즉 호출자가 `?level=Lv 3` 를 넘기면 순수 병음만 돌아옵니다.
  ⚠️ 이번에 **그 SQL 은 안 건드렸습니다**(게이트가 이미 막습니다). 별건으로 남깁니다.

## 3. 어떻게 고쳤나

### 3-1. 판정 정본을 전용 파일로 (`src/english-only.ts`)

PR #498 에서는 게이트가 `warmup-graph.ts` 안에 `isEnglishWarmupText` 라는 이름으로 있었습니다.
이제 게임도 같은 규칙을 쓰므로 **이름의 «Warmup» 이 거짓말**이 됩니다.
그대로 두면 다음 사람이 「이건 웜업 거니까」 하고 **두 번째 사본**을 만듭니다.

→ `src/english-only.ts` 로 옮기고 `isEnglishText` / `isEnglishQuestion` 으로 바꿨습니다.
이 저장소가 이미 쓰는 방식입니다(`c24-expense-filter.ts` · `no-show-truth.ts` · `judgment-english.ts`).

### 3-2. 길이 상한을 «부르는 쪽» 이 정하게

`isEnglishText(raw, maxLen = 80)`.

옛 코드는 자리마다 상한이 달랐습니다 — **웜업 80 · 게임 90 · 단어장 30**.
전부 80으로 통일하면 «고치려던 것» 이 아니라 **«되던 것» 을 깨는 변경**이 됩니다
(81~90자 영어 문장이 게임에서 사라짐).

### 3-3. `src/index.ts` 네 자리

| 자리 | 무엇 |
|---|---|
| `warmupLessonContext()` | 문항 게이트 + 글자 게이트(80) |
| `handleGamesVocab()` `pushSentence` | 글자 게이트(90) |
| `handleGamesVocab()` 문항 루프 | 문항 게이트 |
| `handleGamesVocab()` 학생 단어장 | 글자 게이트(30) |
| `handleGamesLessons()` 영어 갈래 | 문항 게이트 + 글자 게이트(90) |
| **`handleGamesLessons()` 코스 목록** | **중국어 교재 제외** |

### 3-4. 「중국어 교재」를 어떻게 아는가 — `zh_vocab`

```ts
const zhCourses = new Set<string>();
if (glang !== 'zh') {
  try {
    const zr = await env.DB.prepare(
      `SELECT DISTINCT textbook FROM zh_vocab WHERE textbook IS NOT NULL AND textbook != ''`).all();
    …
  } catch {}
}
```

**중국어 게임이 이미 `zh_vocab` 을 정본으로 씁니다**(`/api/games/zh-vocab` · `/api/games/zh-passage`,
그리고 `handleGamesLessons` 자신의 `glang==='zh'` 갈래). 그래서 새 규칙을 만들 필요가 없습니다 —
「그 표에 있는 교재 = 중국어 코스」.

실측: `zh_vocab` 의 교재는 **「다락원」 하나뿐**(266행 · 12개 과).

## 4. 검토했다가 버린 방법 — ★ 가장 중요한 부분

### ⛔ 버린 것 ①: 교재 «이름» 으로 중국어인지 판정
「다락원은 한글 이름이고 BTS 는 영문이니까」 — **안 됩니다.**
영어 교재에도 한글 이름이 있고(`004. I visited my grandparents` 는 영문이지만 `기타 교재` 로 묶입니다),
새 중국어 교재가 영문 이름으로 들어오면 그대로 샙니다.
사람 이름·교재 이름으로 짐작하는 판정은 이 저장소가 여러 번 데인 방식입니다
(CLAUDE.md 「Joy 를 아무 칸에서나 찾지 마세요」).

### ⛔ 버린 것 ②: 코스 목록도 «문장이 나오는가» 로 걸러 내기
「그 교재에서 영어 문장이 하나라도 나오면 목록에 넣는다」 — 판정이 정확해지긴 합니다.
그런데 코스 목록 SQL 이 `questions` 까지 읽어야 해서(현 `LIMIT 500`) **목록 조회가 통째로 무거워집니다.**
지금은 퀴즈가 34건이라 괜찮지만 늘어나면 첫 화면이 느려집니다.
`zh_vocab` 조회는 한 줄짜리 가벼운 쿼리이고 뜻도 더 분명합니다.

### ⛔ 버린 것 ③: 낱말 수 하한(「두 낱말 이상만」)으로 병음 막기
`handleGamesLessons` 는 이미 그렇게 하고 있었고 **실제로 14개를 다 걸러 냈습니다.**
그래도 이 방법을 `handleGamesVocab` 에 복사하지 않았습니다 —
**영어 교재의 정답이 한 낱말인 문항이 많습니다**(BTS 2 「빨간색의 영어 단어를 쓰세요」 → `red`).
초급 학생의 단어 연습이 통째로 사라집니다. 우연히 맞는 방법을 규칙으로 삼으면 안 됩니다.

### ⛔ 버린 것 ④: 길이 상한을 80으로 통일
3-2 참고. 되던 것을 깨는 변경입니다.

### ⛔ 버린 것 ⑤: `handleGamesVocab` 의 레벨 폴백 SQL 에 교재 조건 추가
웜업에는 있고 게임에는 없는 `AND (textbook IS NULL OR textbook='')` 를 맞추고 싶었습니다.
**안 했습니다** — 게이트가 이미 병음을 막고, 그 조건을 넣으면 «교재는 있지만 레벨로 찾던» 기존 동작이
조용히 바뀝니다. 지시 범위 밖이라 별건으로 남기고 이 문서에 적어 둡니다.

### ⛔ 버린 것 ⑥: `zh_vocab` 조회 실패 시 영어 목록도 멈추기
표가 없는 환경이 있을 수 있습니다. `try/catch` 로 감싸 **빈 집합으로 두고 그냥 진행**합니다 —
중국어가 섞이는 쪽보다 **영어 목록이 통째로 안 나오는 쪽이 훨씬 나쁩니다.**
