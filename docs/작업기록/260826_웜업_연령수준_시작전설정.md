# 웜업 — 연령·수준을 «먼저» 고르고 시작하게 (2026-08-26)

> 사장님 지시: 「웜업도 판단력 테스트처럼 연령·수준에 맞춰서 대화하게. 난이도 설정이
> 웜업에서 처음에 나와서 먼저 설정부터 하게 해줘. 그리고 웜업 시작하게.」

## 1. 왜 했나

`warmup.html` 에는 «대화 레벨 1~8»(영어 실력)만 있었고, 그것도 **⋮ 메뉴 안에 숨어** 있었습니다.
그래서 두 가지가 동시에 어긋나 있었습니다.

- **연령 축이 아예 없었다.** 성인 수강생에게도 학교·친구·선생님 이야기가 나가고,
  초등 저학년에게는 진로·시험 이야기가 나갔습니다.
  (판단력 훈련은 2026-08-24 에 같은 구멍을 `age_group`(child/adult)으로 메웠습니다 — `judgment-level.ts`)
- **고르기 전에 대화가 이미 시작됐다.** `initGreeting()` 이 **즉시실행(IIFE)** 이라 페이지를 여는
  순간 `/api/warmup/chat` 이 나갔습니다. 첫 질문이 나간 뒤에 레벨을 바꿔 봐야
  **이미 나간 그 질문은 되돌릴 수 없습니다.**

## 2. 무엇을 했나

### ① 시작 전 «연령 · 수준» 화면 (`public/warmup.html`)
판단력 훈련의 «문장 난이도 설정» 과 **같은 순서**로 맞췄습니다 — ① 누가 ② 어느 수준 ③ 🚀 시작.

- 연령대 4종: 유아·초등 저학년(`kid`) / 초등 고학년·중학생(`child`, 기본) / 고등학생(`teen`) / 성인(`adult`)
- 대화 수준 8단계: 이름·교재 Lv 구간을 **판단력 훈련(`BAND_SPECS`)과 같은 말**로 통일
  (첫걸음 Lv 1-4 … 최상급 Lv 31-34). 두 화면이 같은 Lv 을 다르게 부르면 학생·강사가 매번 되묻습니다.
- 🎯 **내 수준 찾아줄까요?** — 영어 문장 3개를 보여주고 «읽고 바로 이해되나」만 묻습니다.
  가운데(4)에서 시작해 보폭을 줄이는 규칙은 판단력 배치테스트와 같습니다.
- 고른 값은 저장돼(`mangoi_warmup_age` · `mangoi_warmup_level`) 다음에 올 때 미리 선택돼 있습니다.
  → 단골 학생은 **한 번만 누르면 시작**됩니다.
- 대화 중에도 ⋮ 메뉴에서 «연령·수준 다시 고르기» 로 바꿀 수 있고, 이때는 **대화를 새로 시작하지 않습니다**
  (매 요청에 값을 함께 보내므로 다음 발화부터 바뀝니다).
- `?setup=0` 이면 설정 화면 없이 곧바로 대화 — 수업 흐름에서 눈높이를 이미 정해 보낼 때.

### ② 서버 — 연령대 축 (`src/warmup-audience.ts` 신설 + `src/index.ts` 배선 7줄)
- `WARMUP_AGE_IDS` · `normalizeWarmupAge()` · `warmupAgeLine()` 만 있는 **import 없는 순수 모듈**
  (하니스가 그대로 불러 돌립니다).
- `handleWarmupChat` · `handleWarmupQuestions` 가 `age_group` 을 받아 프롬프트에 한 줄 얹습니다.
- ⚠️ **난이도와 독립인 축**입니다. 문장 길이·문법은 `WARMUP_LEVELS` 가 그대로 담당합니다.
  한 축으로 묶으면 「성인인데 유아 문장」 이나 「초등학생인데 직장 이야기」 중 하나가 반드시 생깁니다.
  그래서 «성인 + 레벨 1» 처럼 두 축을 각각 고릅니다.

## 3. 검토했다가 버린 방법

- **연령대를 난이도 8단계 안에 섞기**(1~3=아이, 6~8=어른 식) → 성인 초보자가 갈 곳이 없어집니다.
  판단력 훈련이 이미 «실력 축 / 소재 축» 을 갈라 둔 이유가 이것이라 같은 결정을 따랐습니다.
- **연령대를 판단력처럼 2종(child/adult)만** → 웜업은 «대화» 라 소재 폭이 훨씬 넓습니다.
  7살과 중학생, 고등학생과 성인이 각각 다른 이야기를 합니다. 4종으로 나눴습니다.
  (판단력의 `age_group` 과는 **별개 저장소·별개 값** 입니다 — 같은 이름으로 묶지 않았습니다.)
- **연령대를 `lesson_topic` 에 얹어 보내기**(서버 안 고치기) → `src/index.ts` 를 안 건드리는 유일한 길이었지만,
  주제 칩이 깨지고 프롬프트에 지시를 몰래 태우는 방식이라 다음 사람이 못 읽습니다. 하지 않았습니다.
- **수준 찾기를 판단력처럼 AI 문항 6개로** → 웜업은 첫 화면부터 AI 호출이라 시작이 그만큼 늦어집니다.
  여기서 재는 것은 «읽기 부담» 이라 **고정 문장 3개면 충분**하고, 서버를 한 번도 안 부릅니다.
- **설정 화면을 세션당 한 번만 띄우기** → 지시가 「처음에 나와서 먼저 설정부터」 였습니다.
  대신 지난 선택을 미리 골라 둬서 한 번 누르면 넘어가게 했습니다.

## 4. 새로 밟은 함정

- **CSS 주석에 홑낫표(「」)를 썼다가 하니스 2개가 FAIL** — `admin_lazyload_harness` ②-3 과
  `subtitle_meaning_harness` 는 `<style>` 안 장식 문자를 «한자 폰트를 부르는 화면» 으로 셉니다
  (CLAUDE.md 2장에 이미 있는 함정). 주석에서는 `« »` 를 씁니다.
- **시작 버튼이 휴대폰에서 화면 밖으로 밀림** — 수준이 8줄이라 390px 에서는 끝까지 내려야 보였습니다.
  `position:sticky; bottom:-2px` 로 바닥에 붙였습니다(스크롤 상자가 `.wu-setup` 자신이라 sticky 가 삽니다).
- **`[hidden]` 방어** — `.wu-setup` 에 `display` 를 정했으므로 `.wu-setup[hidden]{display:none !important}`
  를 함께 뒀습니다(작성자 CSS 가 브라우저 기본 `[hidden]` 을 이기는 자리).

## 6. ⚠️ 병합 전에 확인이 필요한 것

`src/index.ts` 는 **공동 금지구역**입니다(CLAUDE.md 4-2). 이번 변경은 그 파일에 **7줄**입니다 —
import 1줄 + `handleWarmupChat` 3줄 + `handleWarmupQuestions` 2줄(+주석). 라우팅·인증 게이트는
건드리지 않았고 전부 웜업 두 함수 «안» 입니다. 그래도 병합은 배포 권한자가 판단합니다.

  화면에만 늘리면 서버가 모르는 값이라 조용히 기본값(child)으로 떨어집니다(하니스가 잡습니다).

  «같은 말» 로 베껴 두었고, 어긋나면 `warmup_age_level_harness` C절이 FAIL 냅니다.
