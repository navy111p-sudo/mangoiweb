## 1. 왜 했나

필리핀 매니저 제보(학생 화면 캡처 1장 + 영어 메시지).

> Sir, my account seems to be different from Ma'am Mel's. When I join a class as an observer,
> students can see me as "Teacher." But when Ma'am Mel joins, she's completely invisible to the students.

캡처에는 **「Teacher」라는 이름의 타일**이 「Camera is off」·「No sound coming in」 상태로 학생 화면에 떠 있었습니다.
제보자는 이것을 **«계정 권한 차이»** 로 읽었고, 사장님도 「이것 문제 확인해줘 · observer 는 ghost watch 라서 보이면 안 되는데」 로 이어서 물으셨습니다.

## 2. 무엇이 사실이었나 — 잰 값

**계정 차이가 아니었습니다. 누른 버튼이 달랐습니다.**

운영 D1 을 SELECT 로만 조회했습니다(아무것도 바꾸지 않음).

| 시각(KST) | 표 | 내용 |
|---|---|---|
| 20:36:05 | `admin_observations` | `mgr_jjw` · Ghost (`class-959`) |
| 20:42:04 | `attendance` | 「교사 Teacher - Hannah」 = 담당 강사 입장 |
| **20:43:42.306** | `admin_observations` | **`mgr_jjw` · Ghost (`class-963`)** |
| **20:43:42.931** | `attendance` | **이름 「교사」인 «실제 참가자» 입장 (+625ms)** |
| 20:53:09 | `admin_observations` | `mgr_jjw` · Ghost |
| 20:53:20 | `attendance` | 「교사」 퇴장 |
| **20:57:50** | `admin_observations` | **`mgr_melca` · Ghost — 그 전후로 `attendance` 행이 하나도 없음** |
| 21:05:54 → 21:12:03 | `attendance` | 「교사」 두 번째 입장 · 퇴장 |

판정의 근거는 **이름 「교사」의 출처가 한 곳뿐**이라는 것입니다.

- `js/idx-main.js` 의 자동입장 처리 — `var name = sp.get('vc_name') || '교사';`
- 저장소 전체에서 `'교사'` 를 기본값으로 쓰는 곳은 **이 한 줄뿐**(grep 1건)
- `vc_name` 없이 `vc_autojoin=1` 을 만드는 링크는 **«🚪 직접 입장(보임)» 버튼 셋**뿐
  (`js/adm-s1.js` · `js/adm-today-classes.js` · `manager.html`)
- 참관(`/?observe=`)은 이름이 `관찰자` 이고, `js/mango-attendance.js` 가 참관 모드를 **통째로 건너뛰어** 출석 행 자체를 안 만듭니다

⟹ Mel 선생님(`mgr_melca`)은 **진짜 유령이었고 그것이 정상 동작**입니다.
제보자 쪽에서는 참관과 **함께 직접 입장 링크가 열렸습니다.**

### 여기서부터는 «판단» — 기록에 없는 것

- 두 기록의 간격이 **625ms** 라 같은 순간의 연속 조작으로 보이지만,
  **어느 화면의 어느 버튼을 눌렀는지는 어디에도 안 남습니다.**
- 관리자 화면에서 두 버튼이 나란히 있는 곳이 두 군데(«오늘 수업» 카드 · «실시간 수업 현황» 표)라,
  참관을 누른 뒤 영상이 곧바로 안 뜨자 옆 버튼을 눌렀을 가능성이 큽니다 — **추론이지 측정이 아닙니다.**

> ⚠️ 이 구분을 문서에 남기는 이유는 CLAUDE.md 2장 「원인을 «찾았다» 고 보고했는데 알고 보니 추론이었음」 때문입니다.
> 단정형으로 적으면 다음 사람이 그 추론대로 «고치러» 갑니다.

## 3. 사용자 실수로 닫으면 안 되는 이유

8/20 에 **같은 매니저가 같은 성격의 제보**를 했고(「참관 중인 사람 카메라가 수업에 보인다」),
그때 «직접 입장은 카메라를 끈 채로 시작» 하도록 고쳤습니다. 그런데 **카메라만 꺼졌고 사람은 그대로 보였습니다.**
그래서 6일 뒤 「이름이 Teacher 로 보인다」로 다시 올라온 것입니다. 고친 것이 증상의 절반이었습니다.

화면이 사람에게 말해 주지 않던 것 셋:

1. **들어가기 전** — 두 버튼이 나란히 있고 색과 확인창 문구로만 구분됩니다(급한 상황에서 문구를 읽을 사람은 많지 않습니다).
2. **들어간 뒤** — 수업 화면 어디에도 «지금 내가 보이는 상태인지» 가 없습니다. 참관 배너는 **실패했을 때만** 뜨고, 직접 입장은 아무 표시도 없습니다.
3. **나온 뒤** — 관리자 표에 «내가 이 방에 참가자로 들어가 있다» 는 표시가 없어, 탭을 닫지 않으면 수업 내내 남아 있어도 본인이 모릅니다.

이번 작업은 **2번**을 고쳤습니다(1·3 은 별건 — 5장).

## 4. 무엇을 바꿨나

전부 **기존 defer 파일 `js/vc-observe-guard.js` 안**입니다. `index.html` 은 `?v=` 한 글자만 바뀌었습니다(**바이트 증가 0**).

### ⑤ 모드 배지

수업 화면 **상단바 아래**에 지금 상태가 계속 떠 있습니다.

| 모드 | 배지 | 판정 근거 |
|---|---|---|
| 참관 | 보라 「👁 참관 중 · 학생·강사에게 보이지 않습니다」 | `observing()` |
| 직접 입장 | 빨강 「🔴 참가자로 입장 · 학생·강사에게 보입니다」 | URL 에 `vc_autojoin=1` **그리고** `vc_cam=off` |
| 그 외(평소 수업) | 없음 | — |

- **진짜 강사에게는 빨간 배지가 안 뜹니다** — 강사 화면(`teacher.html`)·마이페이지 링크에는 `vc_cam=off` 가 없습니다.
- `pointer-events:none` — 읽기 전용이라 클릭을 통과시킵니다.
- 자리는 **상단바를 재서** 그 아래에 놓습니다(`.toolbar` 의 `getBoundingClientRect().bottom + 6`).
- 언어는 `mangoi:lang-changed` 에서 다시 씁니다.

### ⑥ 학생 화면의 «교재 업로드» 버튼 감추기 (마이마이 요청 8/20 ①)

- 실측해 보니 그 버튼에 **역할 구분이 전혀 없었습니다** — 학생에게 그대로 보이고 있었습니다.
- 판정은 **`vcIsStudentNow()`**(«확실한 학생만 true» 정본). 모르면 **그대로 보여 줍니다**(안전한 실패).
- **라이브러리·다운로드는 그대로** 둡니다 — 요청은 «올리기» 만이고, 보는 기능까지 빼면 복습이 막힙니다.
- 서버는 이미 막고 있습니다(`video-call-room.ts` 의 `staffOnly`) — 이건 화면에서 지우는 것뿐입니다.

## 5. 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| **새 defer 파일 추가** | `index.html` 첫 화면 예산 여유가 100바이트대라 `<script>` 한 줄(약 60바이트)도 부담입니다. 이미 두 모드를 다 다루는 파일이 있어 거기에 넣었습니다 |
| **`!vcIsStaffNow()` 로 학생 판정** | 역할이 아직 확정되지 않은 강사를 학생으로 오판해 **«강사가 교재를 못 올리는»** 사고가 납니다(2026-08-10 필리핀 매니저 재신고와 같은 뿌리). 그래서 `vcIsStudentNow()` 를 씁니다 |
| **배지에 «참관으로 바꾸기» 버튼** | 클릭을 받는 순간 «보이는데 안 눌린다» 함정의 후보가 됩니다. 1차는 읽기 전용, 전환은 별건 |
| **고정 좌표(`top:8px`)** | 상단바 버튼을 덮습니다. 상단바 높이는 화면·방향마다 다릅니다 |
| **`#vc-room-name` 안에 글자로 넣기** | 그 자리는 참관 입장이 이미 `innerHTML` 로 갈아쓰고, 폰에서 보이는지 확신할 수 없었습니다 |
| **직접 입장 버튼 자체를 없애기** | 강사가 갑자기 못 들어올 때 매니저가 대신 수업을 맡는 **실제로 쓰는 문**입니다. 없애는 것은 기능 삭제라 사람이 결정할 일입니다 |
| **참관자에게 교재 업로드 권한 열기** (요청서 항목) | 서버 권한이 `isJoined && (teacher\|admin)` 인데 참관자는 정의상 `joined:false` 라 조건을 영영 통과하지 못합니다. 권한만 열면 **유령이 학생 화면을 «이유 없이» 바꾸는** 것이 되어 더 나쁩니다 → 「강사가 승인하면 도우미로 승격」 설계가 필요(별건) |

## 7. 이번에 밟은 함정

- 🪤 **줄 수를 «상자 높이 ÷ lineHeight» 로 세어 한 줄짜리가 2줄로 잡혔습니다.** padding 이 섞입니다.
  이미 CLAUDE.md 2장에 등재된 함정인데 그대로 밟았습니다 — 글자 상자만 남기고 세야 합니다.
- 🪤 그런데 그 잘못된 측정을 고치는 과정에서 **진짜 문제**를 찾았습니다:
  `position:fixed; left:50%` 는 «화면의 오른쪽 절반» 만 쓸 수 있는 것으로 폭이 계산돼,
  390px 폰에서 배지가 250px 로 좁아져 실제로 두 줄이 됐습니다 → **`width:max-content`** 로 고침.
- 🪤 `asset_version_harness` 를 **두 번 밟았습니다** — 파일을 고칠 때마다 `?v=` 를 올려야 하는데,
  한 번 올린 뒤 파일을 또 고쳐서 「내용이 바뀌었는데 `?v=` 가 그대로(현재 4)」로 FAIL 났습니다(→ `v=5`).
  원장(`test-harness/asset-versions.json`)은 **함께 커밋**했고, 실제로 배포되지 않은 `?v=4` 항목은 지웠습니다.
- 🪤 이 컨테이너에서는 **`&` 로 띄운 배경 프로세스가 다음 Bash 호출까지 살아남지 않습니다.**
  서버·브라우저·측정을 **한 번의 호출 안**에서 다 해야 합니다.
- 🪤 **작업기록 PR(#545)에 CI 가 2시간 5분 동안 한 건도 안 붙었습니다.**
  «닫았다 다시 열기» 는 안 통했고(같은 날 다른 세션에서는 통했습니다), **`main` 병합 푸시**로 깨어났습니다
  (run #612 `success`, 109초). 그때도 체크런 API 는 `in_progress` 인 채였고 run 은 이미 `success` 였습니다.
  ⚠️ 로컬 `ci-gates.sh` 는 대체 근거가 못 됩니다 — `node_modules` 가 없어 ①·②가 **환경 사유로** 실패합니다.
