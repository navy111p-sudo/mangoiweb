## 2. 무엇이 안 되고 있었나

### 2-1. 「올려도 안 커진다」에 «작게만 되는» 슬라이더가 붙어 있었다

`HTMLMediaElement.volume` 은 **상한이 1 = «지금 소리»** 입니다. 기본값도 1 입니다.
그래서 0~100% 슬라이더는 **«작게» 만 되고 «크게» 는 구조적으로 불가능**합니다.

제보는 「하드웨어 볼륨키를 눌러도 안 커진다」였습니다. 즉 **그 기능은 제보 방향으로
한 칸도 못 움직입니다.** 화면에는 슬라이더가 멀쩡히 보이고 값도 저장되므로
«고쳐졌다» 로 읽히는 것이 더 나쁩니다.

> 같은 파일 머리말이 「2026-08-06 «마이크 음량» 가짜 슬라이더(부르는 함수가 없어 무동작)를
> 반복하지 않으려고 이 파일이 실제로 `.volume` 을 바꾼다」고 적고 있었습니다.
> `.volume` 을 바꾸는 것은 맞지만, **쓰는 사람 눈에는 똑같이 「올려도 안 커진다」** 입니다.
> 「함수가 없어서 안 되던 것」이 「함수는 있는데 방향이 반대인 것」으로 바뀌었을 뿐입니다.

### 2-2. 값이 «유지되지도» 않았다 — 되돌리는 놈이 둘

`idx-main.js` 에는 소리 자가복구가 **둘** 있고, 둘 다 `volume = 1` 하드코딩이었습니다.

| 무엇 | 언제 도는가 | 무엇을 되돌리는가 |
|---|---|---|
| `vcEnsureRemoteAudio` | 수업 중 **아무 터치·키 입력마다** (`pointerdown`·`touchstart`·`keydown`) | `v.volume = 1` · `aux.volume = 1` · `v.muted = false` |
| `vcAudioWatchdog` | **3초마다** (`setInterval`) | 같음 (「매 틱 자동 복구」) |

그래서 학생이 30% 로 내려도 **화면을 한 번 만지면 즉시 100% 로 튕겨 올라갑니다.**
새 파일은 1.5초마다 저장값을 다시 쓰고 있었으므로, 실제 동작은 **두 값 사이의 진동**입니다.

CLAUDE.md 2장 「`pointerdown` 자동정지와 `click` 토글이 서로를 뒤집은 것」·「핀치를 놓으면
100% 로 돌아감」과 **같은 뿌리**입니다. 그 항목의 경고 그대로, **문자열 하니스 211건이
전부 초록불**이었습니다 — 함수도 값도 다 «있고» 틀린 것은 «순서» 뿐이니까요.

### 2-3. 상주 `setInterval`(1.5초) — CLAUDE.md 명시 금지

```js
setInterval(function () {
  if (document.body.classList.contains('vc-in-call')) applyVolume(savedVolume());
}, 1500);
```

이 파일은 `index.html`(홈)에 붙습니다. 즉 **수업에 한 번도 안 들어간 학생 폰까지**
1.5초마다 깹니다 — 학생 29,000명 전원이 대상입니다. 주기도 기존 것들(오디오 감시견 3초,
적응 루프 4초)보다 빠릅니다.

주석은 「새 참가자 타일에 값을 물려주려고」라고 근거를 댔지만, 2-2 에서 봤듯이
`idx-main.js` 는 오히려 그 값을 **덮어쓰는** 쪽입니다. 그 폴링이 실제로 하던 일은
«물려주기» 가 아니라 **«감시견과 싸우기»** 였습니다.

### 2-4. 표에 열을 더했는데 휴대폰에서 «맨 앞» 으로 튀어나옴

수강신청 등록 표는 휴대폰에서 `<tr>` 를 카드로 눕히는데, 칸마다 `order: 1~8` 을 손으로
매겨 둡니다(`admin-inline-c.css`). 새 「수업 시간」 칸에는 그 규칙이 없었습니다.

**`order` 의 기본값은 «DOM 순서» 가 아니라 «0»** 입니다 → 학생 아이디보다 **앞** 에 놓입니다.
`grid-column` 도 없어 `span 1`(12칸 중 하나)만 차지합니다.

trap-check 서브에이전트가 실제 Chromium 으로 잰 값:

| 뷰포트 | order | grid-column | 자리 | 폭 |
|---|---|---|---|---|
| 1500px | **0** | auto(=span 1) | **맨 앞** | **68px** (형제는 152~320px) |
| 1150px | 0 | auto | 맨 앞 | **39px** — 「20분」 글자 폭 29px + 화살표 16px → **잘림** |

12칸 합이 어긋나 원래의 「첫 줄 = 누구를·어떻게 / 둘째 줄 = 언제」 배치도 무너졌습니다.
⚠️ 그 블록은 **미디어쿼리 밖** 이라 넓은 화면에도 적용됩니다 — 폰으로만 보면 못 봅니다.

## 3. 어떻게 고쳤나

### 3-1. 100% 초과는 WebAudio 로 «실제 증폭»

* 슬라이더 상한 100 → **300%**, 지금 값을 **글자로** 함께 표시.
* 100% 이하 → **WebAudio 를 아예 안 씀** (`element.volume` 만). 가장 단순한 경로가 가장 안전합니다.
* 100% 초과 → `createMediaStreamSource` → `GainNode` → `DynamicsCompressor`(리미터) → 출력.
  리미터를 둔 이유는 300% 로 올리면 큰 소리가 잘려 «찢어지는» 소리가 나기 때문입니다.

**안전 원칙 — 실패하면 «고치기 전» 으로 되돌아간다**

| 위험 | 대책 |
|---|---|
| 자동재생 정책에 막혀 `AudioContext` 가 `suspended` 인데 타일을 음소거하면 **소리가 통째로 사라짐** | 슬라이더를 움직이는 **그 자리**(=사용자 제스처)에서 `resume()` 하고, `state === 'running'` 을 확인한 **뒤에만** 음소거 |
| 3초 감시견이 «증폭용 음소거» 를 «소리 막힘» 으로 오판 → 「🔊 소리 켜기」 배너 + 헛된 보조 오디오 | `window.vcOutBoost` 를 **음소거보다 «먼저»** 켜고, 감시견이 그때는 `outputBlocked = false` 로 보게 함 |
| 보조 오디오(`vc-aud-*`)는 **같은 트랙을 새 `MediaStream`** 에 담음 → 스트림으로 세면 **같은 소리를 두 번 증폭** | 묶음 키를 «스트림 id» 가 아니라 **«오디오 트랙 id»** 로 |
| WebAudio 를 못 쓰는 브라우저·붙일 트랙이 하나도 없음 | 어느 단계든 실패하면 `applyPlain(1)` 로 원래 경로 복귀 (최악이어도 오늘과 같아짐) |

### 3-2. 되돌리는 두 곳을 «값을 읽게» 고침

`idx-main.js` 에 `vcOutVol()` 정본을 두고, 자가복구 두 곳이 그것을 읽게 했습니다.
증폭 중에는 `vcEnsureRemoteAudio` 가 **첫 줄에서 그냥 돌아갑니다**.
⚠️ **값이 기본(1)이면 예전과 완전히 같은 동작**입니다 — 오늘 쓰는 학생 전원에게는 변화가 없습니다.

### 3-3. 상주 setInterval → 범위를 좁힌 감시

`#vc-video-grid` 에만 건 `MutationObserver`(childList) + `showView` 감싸기.
수업을 나가면 감시를 끊고 증폭도 끕니다. 본보기는 `js/idx-vc-toprow.js` 입니다.
⛔ body class 감시는 쓰지 않습니다(홈 전체를 멎게 한 전력).

### 3-4. 카드 배치 다시 짜기

order 1~9 / span **3+3+4+2 · 4+4+4 · 6+6** — 줄마다 합이 정확히 12 입니다.
표 `min-width` 도 1180 → 1270px (새 열 90px).
