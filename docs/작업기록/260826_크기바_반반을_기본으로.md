## 1. 왜 했나

PR #486(크기바를 그림 4칸으로) 배포 직후, 사장님이 실제 화면에서 확인하시다 나온 것 —
**1920px 창에서 「반반」을 골랐는데 얼굴칸이 절반이 아니라 24%** 였다.

눈대중이 아니라 실측했다(1920×1080, 로컬 서버 + 헤드리스 Chromium):

| 칸 | 실제 얼굴칸 | 이름이 약속하는 것 |
|---|---|---|
| 교재 크게 (`quarter`) | 16% (300px) | 25% |
| **반반 (`half`)** | **24% (460px)** | **50%** ← 이름이 거짓말을 한다 |
| 얼굴 크게 (`threequarter`) | 45% (857px) | 75% |
| 모두 보기 (`full`) | 100% | 100% |

원인은 데스크톱(≥1025px)에 걸린 상한이다:

```css
body.vc-in-call #vc-main-row.video-half > #vc-video-pane {
  width: clamp(260px, 27%, 460px) !important;
}
```

**칠판·교재가 좌우로 좁아지는 것을 막으려고 일부러 넣은 상한**이다.

⚠️ **내가 만든 문제는 아니다** — 옛 이름 `1/2` 도 똑같이 24% 였다.
다만 #486 에서 내가 붙인 **「반반」이 «절반»을 더 분명히 약속**해서 어긋남이 드러났다.
나머지 셋(교재 크게·얼굴 크게·모두 보기)은 «상대적인 말» 이라 지금도 거짓말을 하지 않는다.

## 2. 무엇을 바꿨나

같은 말을 **네 곳**에 적는 자리라, 하나만 고치면 어긋난다.

| 곳 | 파일 | 전 → 후 |
|---|---|---|
| 크기바 라벨 | `cloudflare-deploy/public/index.html` (`#vc-size-bar` 의 `data-size="half"` 칸) | 반반 → **기본** / Split → **Standard** |
| 크기바 툴팁·aria | 같은 버튼 `title`·`data-ko-title`·`data-ko-aria` | 「얼굴과 교재를 반반」 → 「교재와 얼굴을 함께 (기본 크기)」 |
| 하단 독 「화면 분할」 시트 | `cloudflare-deploy/public/js/idx-main.js` (`VC_FOLDERS.screen`) | `'반반 (Split)'` → `'기본 (Standard)'` |
| 전환 토스트 | 같은 파일 `vcScreenSet` 의 `labels` | `half:'반반'` → `half:'기본'` |
| 감시 정본 | `test-harness/vc_sizebar_labels_harness.mjs` | `CANON.half` |

곁들여 처리한 것:

- `idx-main.js` 내용이 바뀌어 `?v=` 를 올렸다. 그런데 그 사이 병합된 **PR #489 도 36→37 로 올려
  번호가 겹쳤다** → 병합 후 **38** 로 새로 매겼다(`index.html` + `teacher.html` preload **둘 다**).
- **폭·레이아웃은 한 줄도 안 건드렸다.**

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

사장님께 세 갈래를 드리고 **「이름만 바꾸기」** 를 고르셨다.

| 버린 것 | 왜 |
|---|---|
| **폭을 이름에 맞추기**(상한 460px 을 풀거나 올려 실제 50% 로) | 그 상한은 「칠판·교재가 좌우로 좁아지는 것을 막으려고」 **일부러 넣은 것**이다. 풀면 수업의 주된 화면인 교재가 좁아진다. 게다가 얼굴 폭 규칙은 **CSS 8개 블록**에 breakpoint 별로 흩어져 있어 한 곳만 고치면 다른 폭에서 어긋난다 |
| **그대로 두기** | 「반반」은 50:50 을 **분명히** 약속하는 말이다. 컨트롤이 스스로 거짓말을 하면 나머지 표시도 못 믿게 된다 |
| **네 이름을 «작게/보통/크게/전체» 로 전부 갈기** | 지금 이름은 «교재를 크게 볼까, 얼굴을 크게 볼까» 라는 **선택의 축**을 알려 준다. 그 정보를 버리게 된다. 어긋난 것은 「반반」 하나뿐이라 하나만 고치는 게 맞다 |
| **「나란히」** | 네 모드가 **전부** 나란히 배치라 구분이 안 된다 |
| → **「기본」** | 비율을 약속하지 않고, **실제로 입장 시 기본값**이라 사실과도 맞는다. 좁은 칸에 들어가는 두 글자 |

## 5. 밟은 것 — CI 를 두 번 빨갛게 만든 진짜 원인

### 🔴 `asset_version_harness` 는 «로컬에서는 통과하고 CI 에서만 FAIL» 한다

생성물(`*_report.txt`)을 되돌리려고 `git checkout -- test-harness/` 를 했는데,
**`asset-versions.json` 의 새 `?v=` 항목까지 함께 되돌아갔다.** 그 상태로 커밋이 올라갔다.

- **로컬**: 하니스가 「🆕 새 버전 1건 기록 (정상)」이라며 **스스로 원장에 적고 통과**한다
- **CI**: 원장을 되돌려 쓸 수 없으므로 **FAIL**

그래서 내 로컬 검증은 계속 초록이었는데 CI 만 빨간불이었다(run #542 — 게이트 ②·④가
**같은 한 건**으로 터졌다). 원장 변경은 **반드시 커밋에 함께 담아야 한다.**

### 🔴 감시 스크립트가 인증 없이 GitHub API 를 부르고 있었다

비공개 저장소라 인증 없는 호출은 **403** 이 오는데, 내 파서가 그것을 **「실행 없음(NORUN)」**
으로 읽었다. 그래서 「CI 가 이 PR 에만 안 붙는다」는 잘못된 보고를 여러 번 드렸다
(실제로는 그때 이미 통과해 있던 적도 있다). 코드에는 영향이 없었지만 상황 보고를 어지럽혔다.
환경에 `GH_TOKEN` 이 있지만 **GitHub API 용으로는 안 통한다**(`AUTH_ERR` 실측) —
GitHub 상태 조회는 **MCP 도구**(`mcp__github__*`)로 해야 한다.

### 감시가 제 몫을 한 사례

`git checkout` 으로 하니스 정본만 되돌아간 순간, **`vc_sizebar_labels_harness` 가
그 자리에서 FAIL 3건**을 냈다(크기바·시트·토스트가 정본과 어긋남 → 22 PASS / 3 FAIL).
어제 만든 감시가 하루 만에 값을 했다. push 전에 잡혔다.
