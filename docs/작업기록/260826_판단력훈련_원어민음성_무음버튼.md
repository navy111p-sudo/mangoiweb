# 판단력 훈련(judgment.html) 원어민 음성 · 무음 버튼

- 날짜: 2026-08-26
- 브랜치: `claude/native-speaker-audio-p3cla5`
- 대상 화면: `cloudflare-deploy/public/judgment.html` (판단력 훈련)

---

## 1. 왜 했나

사장님 지시 — 「여기도 원어민 음성을 달아 줄래? **듣기 연습도 같이 하게.**
자연스러운 **미국 원어민 여성** 음성으로. **무음버튼**도 만들어 주고.」

이 화면은 상황문과 보기 A~D 가 전부 **영어 문장**인데 **읽어 주는 자리가 한 곳도 없었다.**
학생은 눈으로만 고르고 있었고, 「어떤 말투가 맞나」를 가르치는 화면에서 **정작 그 말투가
어떻게 들리는지는 못 듣는** 상태였다.

## 2. 무엇을 했나

소리는 **공용 모듈 `js/game-tts.js` 하나로만** 낸다(새 TTS 스택을 만들지 않았다).
서버 `POST /api/voice/tts` → Deepgram **Aura-2** → Aura-1 → MeloTTS → 브라우저 음성 순 폴백이고,
서버 응답은 R2 에 캐시되므로 같은 문장은 두 번째부터 뉴런을 안 쓴다.

| 자리 | 동작 |
|---|---|
| 상황문 | 새 문제가 오면 **자동 낭독** + 옆의 🔊 로 다시 듣기 |
| 보기 A~D | 각 보기에 🔊(다시 듣기) · **고르면 그 표현을 읽어 준다**(고르는 순간이 듣기 연습) |
| 레벨 찾기(placement) | 상황문 자동 낭독 + 보기마다 🔊 (고를 때는 안 읽는다 — 바로 다음 문제로 넘어가 잘린다) |
| 채점 결과 | 표현별 점수표 4줄 · 「가장 자연스러운 표현」 · 「내가 고른 표현」에 🔊, **모범 표현은 한 번 자동 낭독** |
| 상단바 | 🔊/🔇 **무음 버튼** — 새 재생을 막고, 켜는 즉시 나던 소리도 끊고, `mangoi_judgment_muted` 로 기억 |

화자는 **`asteria`**(미국 영어 여성). `MangoiTTS.setLang('en')` + `setSpeaker('asteria')`.

## 3. 검토했다가 버린 방법과 그 이유

1. **이 화면 전용 TTS 코드를 새로 쓰기** → 버림.
   이미 게임 4종이 스택을 각자 복사해 갖고 있어 이모지 정제 같은 규칙이 갈라진 전력이 있다
   (`game-tts.js` 머리말). 같은 실수를 한 벌 더 늘리지 않는다.
2. **스피커를 `<button>` 으로** → 버림(그리고 하니스로 못 박음).
   보기(`.opt`)가 **그 자체로 `<button>`** 이라, 안에 `<button>` 을 넣으면 HTML 파서가
   **바깥 버튼을 먼저 닫는다.** 보기 카드가 통째로 무너지는데 **에러가 안 난다.**
   → `<span role="button" tabindex="0">` + 캡처 단계 위임 + `stopPropagation`.
3. **`화자 = thalia`(더 «캐주얼»한 미국 여성)** → 버림.
   Aura-2 에만 있고 **Aura-1 목록에는 없다.** 서버가 한 단계 폴백하는 순간 기본값으로 떨어져
   목소리가 바뀐다. `asteria` 는 **두 목록에 다 있어** 폴백해도 같은 여성 목소리가 유지된다.
4. **자동 낭독을 렌더할 때마다** → 버림.
   🌐 언어 토글이 `renderQuestion`/`renderResult` 를 **다시 부른다.** 조건 없이 읽으면
   언어를 누를 때마다 문장이 다시 낭독된다. → `_autoSay` 를 «막 도착했을 때» 만 세우고 소비한다.
5. **보기를 고를 때 낭독을 레벨 찾기에도** → 버림. 고르면 바로 다음 문제로 넘어가 잘린다.
6. **문서 클릭에 «아무 데나 누르면 멈춤» 을 달기** → 버림.
   게임 허브에서 `pointerdown` 자동정지와 `click` 토글이 서로를 뒤집어 **소리를 못 끄던 사고**가
   있었다(CLAUDE.md 2장). 무음은 «지금 소리를 낼 것인가» 한 값만 뒤집는 단순 토글로 뒀다.
7. **무음 버튼에 `data-ko`/`data-en`** → 버림. i18n 엔진이 아이콘의 `textContent` 를 문장으로
   갈아끼운다(홈 오프닝 버튼에서 실제로 밟은 함정). 뜻은 `title`·`aria-label`·`aria-pressed` 로만.

## 5. 이번에 새로 밟은 함정 (CLAUDE.md 2장에 넣었다)

- **「소리가 안 난다」를 `/api/voice/tts` 요청 수로 세면 안 된다.**
  이 화면은 문제를 그릴 때 보기까지 `prefetch()` 해 두므로, 눌렀을 때는 **캐시에서 바로 재생**되어
  요청이 **0건**이다. 멀쩡한 동작이 실패로 보인다 — 실제로 검사 2건이 그렇게 거짓 실패했다.
- **`game-tts.js` 는 `defer` 라 화면의 인라인 스크립트보다 나중에 온다.**
  서버가 문제를 캐시로 즉시 주면 첫 화면에서 `window.MangoiTTS` 가 아직 없어 **첫 문장만 무음**이 된다.
  → 적어 뒀다가 로드 뒤 마저 읽는 `_pending` + `DOMContentLoaded`/`load` 로 막았다.
- **주석 안에 route glob 을 그대로 적으면** 별표+슬래시가 **블록주석을 거기서 닫아** 뒷부분이
  코드가 되고 「api is not defined」 로 죽는다(브라우저 검사를 쓰다 실제로 밟았다).

## 6. 남은 것 / 알려진 한계

- **첫 문제는 소리가 안 날 수 있다.** 브라우저 자동재생 정책상 그 문서에서 사용자가 아직
  아무것도 누르지 않았으면 재생이 막힌다. 그래서 🔊 를 문장·보기마다 두었고, 한 번 누른 뒤부터는
  새 문제마다 자동으로 읽는다. (막힌 것을 «다시 시도» 로 우회하지 않았다 — 정책을 억지로 뚫는
  코드는 기기마다 다르게 깨진다.)
- `MangoiTTS.setLang('en')` 은 공용 키 `mangoi_game_lang` 을 쓴다(다른 게임과 공유).
  영어 화면이라 `micro-quiz.html`·`ai-friend.html` 과 같은 전례를 그대로 따랐다.
- 이 화면의 UI 언어는 한/영/중 3개인데, **읽어 주는 것은 영어 문장뿐**이다(보기·상황문이 영어).

## 7. 후속 — 읽기 속도 조절 (같은 날)

사장님이 배포된 화면에서 들어 보시고 — 「목소리는 좋은데 **속도가 좀 빠르다.**
속도 조절 기능을 간단하고 직관적으로 넣어 줄 수 있니?」

### 무엇을

상단바 무음 버튼 왼쪽에 **속도 버튼** 하나. 누를 때마다 **느리게(0.75) → 보통(0.9) → 빠르게(1.0)**
로 돌고, **지금 속도를 글자로** 보여 준다(`🐢 느리게` · `🚶 보통` · `🐇 빠르게`).
**기본을 0.9 로 낮췄다** — 「조금 빠르다」는 제보에 대한 답이 조작 수단만은 아니라고 봤다.
고른 값은 `mangoi_judgment_rate` 로 기억한다.

바꾸는 즉시 **지금 화면의 대표 문장을 그 속도로 한 번 들려준다**(문제 화면=상황문,
결과 화면=모범 표현). 「0.75배」라고 적어 두는 것보다 한 번 들어 보는 편이 빠르다.

### 검토했다가 버린 방법

1. **슬라이더(0.5~1.5 연속)** → 버림. 폰에서 정확히 집기 어렵고, **지금 몇 배속인지가 안 보인다.**
   학생이 제일 자주 쓸 조작이라 «한 번 눌러 세 단계» 가 맞다고 봤다.
2. **아이콘만 바꾸기(🐢/🐇)** → 버림. 무엇이 켜져 있는지 글자 없이는 안 읽힌다.
   (반대로 무음 버튼은 🔊/🔇 두 상태뿐이라 아이콘만으로 충분하다 — 규칙이 다른 이유가 이것이다.)
3. **속도 버튼에 `data-ko`/`data-en`** → 버림. i18n 엔진이 `textContent` 를 갈아끼우므로
   버튼이 스스로 그리게 두고 `applyStatic()` 에서 `applySpeedUI()` 를 함께 부른다.
4. **속도를 «바꿀 때만» 적용** → 버림. 다음 문장부터 다시 빨라진다.
   `say()` 가 **언제나** `rate()` 를 넘기도록 한 곳에서만 쓴다.
5. **화자 바꾸기** → 필요 없었다. 사장님이 「목소리는 좋다」고 하셨고, 문제는 속도뿐이었다.

### 검증

- 브라우저 실측 **30건 PASS**(21 → 30, 속도 9건 신설) — 눌러서 바뀌는가 · 그 속도로 읽는가 ·
  **그 뒤 스피커를 눌렀을 때도 같은 속도인가** · 기억하는가 · 언어를 바꿔도 글자가 따라오는가
- 문자열 하니스 **18건 PASS**(12 → 18)
- 회귀 하니스 PASS 210 / FAIL 6(변경 전과 같은 6건 — 컨테이너에 `node_modules` 없음)

### 🪤 이번에 새로 밟은 것

- **빈 브라우저는 늘 «첫 방문자»** — 그 사이 main 에 들어온 «시작하기 전에 두 가지만 정할게요»
  카드가 첫 진입을 가로채, 어제 통과하던 브라우저 검사가 `.opt` 를 못 기다려 죽었다.
  `mangoi_judg_setup_v1='1'` 로 본 것 표시하고 연다(관리자 `#aw-overlay` 와 같은 사정).
- **언어는 ko → en → zh 로 «돈다»** — 검사에 「두 번째 토글이면 영어」로 적었더니
  멀쩡한 화면이 거짓 실패했다(실제로는 중국어가 맞다).

## 8. 후속 2 — 눈금을 한 칸씩 더 내림 + 폰 헤더 넘침 (같은 날)

사장님이 다시 들어 보시고 — 「**0.75 도 좀 빠르다.**」

### 무엇을

- 세 단계를 **0.75/0.9/1.0 → 0.6/0.75/0.9** 로 내리고, **기본도 제일 느린 0.6**(느리게)으로.
  두 번 연속 「빠르다」였으므로 아무것도 안 눌러도 느린 쪽에서 시작하고, 빠르게 듣고 싶은
  학생은 한 번 누르면 된다(그 선택은 기억된다).
- ⛔ **0.5 아래로는 내리지 않는다** — `playbackRate` 가 그 아래에서는 음높이 보정이 한계에
  부딪혀 소리가 뭉개진다. 더 느려야 하면 화자·엔진을 바꾸는 별건이다.

### 덤으로 고친 것 — 폰에서 화면이 옆으로 밀리던 것

브라우저 검사가 **문서 81px 가로 넘침**을 잡았다. **내 변경 전 `main` 에서도 나는 것**이라
확인하고 원인을 재 보니, 그 사이 들어온 「🧑‍🎓 학생」 칩까지 더해져 헤더 버튼 상자가
**467px**(화면 390px)이 돼 있었다. `.top .btns` 가 `flex:0 0 auto` 라 **줄어들지도 줄바꿈하지도**
않는 것이 뿌리다. 속도 버튼의 「느리게」가 「보통」보다 길어 95px 로 더 키우고 있었다.

`flex-wrap:wrap` + `flex:0 1 auto` + `justify-content:flex-end` 한 줄로 풀었다(실측 485 → 375px,
헤더는 두 줄로 접힌다). ⛔ 폭 상한을 숫자로 박지 않았다 — 칩은 앞으로도 늘어난다.

> 🪤 **이 버그는 어제 검사에서 0px 이었다.** 남의 변경이 내 화면의 레이아웃을 밀어낸 것이고,
> 「내 변경 탓인가」를 가르려면 **같은 검사를 변경 전 트리에서 한 번 더 돌리는 것**이 가장 빠르다.

### 검증

- 브라우저 실측 **30건 PASS**(속도 값 0.6/0.75/0.9 와 가로 넘침 0 포함)
- 문자열 하니스 **18건 PASS** — 단계 검사를 「0.75 가 있는가」에서 **「0.5~1.0 안에서 오름차순
  세 개인가」**로 바꿨다(다음에 또 내릴 때 검사가 먼저 깨지지 않게)
