## 1. 왜 했나

사장님 제보(화면 캡처 2장).

> 「왜 교사 화면이 작고 학생 화면이 크지. 학생수업입장에선 학생이 작고 교사가 커야 하는데 이유가 뭐지?」

첫 캡처: **`jeong (나)` 가 전체화면**, 「교사 강선생님」이 오른아래 210px PIP. 타이머 09:57 — **10분째 그 상태**였습니다.
두 번째 캡처(같은 날 `class-849-20260826`, 1분 32초): **정상**(강선생님이 크고 `jeong (나)` 가 PIP).

> 「이제는 교사가 크고 학생이 작아졌어 .. 왜 아까는 반대였지??」

즉 **재현이 들쭉날쭉**했습니다. 이것이 원인을 가르는 결정적 단서였습니다 — CSS 라면 매번 같아야 합니다.

## 3. 원인 — CSS 가 아니라 «역할» 이었다

화면을 가르는 것은 `body.mg-teacher-self` 하나입니다.

| body 클래스 | 큰 쪽 | 작은 PIP |
|---|---|---|
| 없음 (정상 학생 화면) | 상대(교사) | 나 — `index.html` `vc-teacher-first` 의 62% 규칙 |
| **`mg-teacher-self`** | **나 자신** | 상대 |

그 클래스는 2026-08-26 사장님 지시 「교사 화면에서는 교사 **자신**이 크게」의 스위치이고, 붙는 조건은 `vcIsStaffNow()` 하나였습니다.

**그런데 `jeong` 은 학생 세션이 없습니다.** 홈 통합 로그인에서 관리자 폴백(`tryAdminLoginFallback`, `js/idx-user-session.js`)으로 들어가면 `mangoi_admin_session` 만 만들고 `mangoi_logged_user` 는 만들지 않습니다. 그래서 입장 역할 판정 사슬(`js/idx-main.js`)이 계정 역할을 못 찾고 마지막에 이렇게 떨어집니다:

```js
else if (_admUid) window.vcMyRole = 'admin';   // 관리자 세션이 있으면 — 묻지도 않는다
```

→ `vcIsStaffNow()` 참 → `mg-teacher-self` → **사장님 얼굴이 전체화면, 강선생님이 PIP.**
화면은 지시대로 「교사(=너)를 크게」를 한 것이고, 틀린 것은 **역할 판정**이었습니다.

### 🔴 왜 «수업 내내» 뒤집힌 채로 갔나 — 서버 교정이 admin 만 건너뛴다

원래 이 사고를 막는 안전장치가 있습니다. 입장할 때 `/api/class/verify-room` 이 「이 예약의 학생이 누구인가」를 보고 `resolved_role:'student'` 를 돌려주면 클라이언트가 스스로 역할을 내립니다(`idx-main.js`, 2026-08-08 Teacher Ana ① 대응). 내려가면 `syncTeacherSelf` 가 6초 안에 클래스를 벗깁니다.

그런데 서버가 **`admin` 이면 그 검사를 아예 하지 않습니다** — `src/api-mango.ts`:

```ts
if (role === 'admin' || role === 'observer') return json({ ok: true, authorized: true, reason: 'privileged' });
```

`resolved_role` 이 없으니 내림이 영영 안 일어납니다. 정리하면:

| 입장 시 잡힌 역할 | 서버 교정 | 결과 |
|---|---|---|
| `student` · `teacher` | 돈다 | 몇 초 만에 정상 |
| **`admin`** | **건너뜀** | **수업 내내 뒤집힘**(실측 10분) |

같은 사람이 같은 수업에 두 번 들어가도 브라우저 상태(관리자 세션이 살아 있었나·학생 로그인이 있었나)에 따라 갈립니다 — **「다시 들어가니 괜찮던데」의 정체**입니다.

## 4. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### ⛔ `idx-main.js` 의 `else if (_admUid)` 를 고쳐 admin 승격을 막기

가장 곧아 보이지만 **그 승격은 사고의 원인이 아니라 «해결책» 입니다.** 2026-08-12 IT 담당자 건 — 관리자로 로그인한 브라우저에서 수업에 들어가 장치 도우미로 강사 장치를 봐 줘야 하는데, 이 사슬이 관리자 세션을 안 봐서 재입장마다 «학생» 으로 떨어졌고 🎛·칭찬이 전부 사라졌습니다. 되돌리면 그 사고가 재발합니다.
덤으로 `idx-main.js` 는 **849KB blocking** 이라 첫 화면 예산(여유 수백 바이트)이 걸립니다.

### ⛔ 서버 `verify-room` 이 admin 에도 `resolved_role` 을 주게

**방향은 이쪽이 옳습니다.** 다만 `src/index.ts`·인증 경로에 닿는 별건이고, 화면 문제는 그것 없이도 고쳐집니다. 지시 범위를 넘기지 않고 **5장에 남겼습니다.**

### ⛔ ⑨ 절(「교사 자신 크게」)을 통째로 되돌리기

2026-08-26 사장님 지시입니다. 교사 본인 화면에서는 그대로 유지돼야 합니다.

### ⛔ `vcIsStaffNow()` 정본을 손보기

그 값에는 **화면공유·교재 페이지 넘김·장치 도우미 권한**이 걸려 있습니다. 여기서 필요한 것은 «누가 주인공인가» 뿐이라 **권한은 그대로 두고 크기만** 바로잡았습니다.

### ⛔ 이름 휴리스틱으로 «내 역할을 올리기»

「교사 …」 이름 판정은 **내 타일을 내리는 데만** 씁니다. 권한을 올리는 데 쓰면 아이디에 `teacher` 가 든 학생이 반 전체 교재를 넘깁니다(CLAUDE.md 등재 함정).

### ⛔ 상주 `setInterval` · body class `MutationObserver` 로 감시

둘 다 이 저장소에서 라이브 장애를 낸 방식입니다(2026-07-14 홈 전체 먹통). 대신 **`vcApplySpotlight` 를 감쌌습니다** — 그 함수는 ① 타일을 만들 때 ② 로스터에서 역할이 도착할 때 불리므로, **교사가 나중에 들어오거나 역할이 늦게 와도** 그 순간 다시 봅니다.
(`vc-spotlight.js` 는 `index.html` 15092행, 이 파일은 16367행 — 둘 다 defer 라 실행 순서가 보장돼 원본이 안전하게 잡힙니다.)

### ⛔ 판정 로직을 이 파일에 새로 쓰기

`idx-main.js` 에 이미 `vcBoxIsStudent()`(역할 + 이름 휴리스틱)가 있습니다. 그것을 씁니다. 다만 **그 이름이 바뀌면 조용히 헛돌므로**(CLAUDE.md 「칸 이름이 바뀌면 조용히 헛돈다」) 같은 뜻의 대비책을 옆에 두고, 하니스가 **둘 다** 확인합니다.

### 시연용 선생님 타일은 제외

`vcAddDemoTeacher()` 가 만드는 `data-demo="1"` 타일은 사람이 아닙니다. 여기에 걸리면 진짜 교사 화면이 「자기 자신 크게」를 잃습니다 — 회귀 방어로 하니스에 못 박았습니다.
