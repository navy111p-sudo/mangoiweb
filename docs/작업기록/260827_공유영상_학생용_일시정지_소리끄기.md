## 1. 왜 했나

2026-08-27 사장님·Karl 매니저의 실수업 테스트(class-1003-20260827) 제보 3-1:

> 한번 소리를 켜면 다시 끄는 버튼이 없고, 영상도 멈추는 버튼이 없어서 계속 플레이하게 됩니다.
> 학생쪽에도 영상을 일시정지하는 버튼과 소리를 다시 끄는 버튼이 있으면 좋겠습니다.

구조적 원인이 둘 겹쳐 있었다.

- 학생 쪽 공유 영상은 **2026-08-12 Melca 결정**으로 조작이 통째로 잠겨 있다
  (「학생이 빨리감기하면 수업을 건너뛴다」 — iframe `pointer-events:none`, `controls=0`,
  파일 영상은 `controls=false`).
- 유일한 조작 수단인 「🔊 소리 켜기」 버튼(`vpAddSoundOverlay`, `idx-main.js:13357`)은
  자동재생 정책상 첫 사용자 제스처를 받으려고 있는 것인데, **한 번 누르면 `btn.remove()` 로
  스스로 사라진다.** 그 뒤로는 소리를 끌 길도, 영상을 멈출 길도 화면에 하나도 없었다.

      Vimeo 는 `pause/play`, 파일은 `video.pause()/play()`

  - 강사·관리자에게는 붙이지 않는다(원래 컨트롤이 있다). 못 찾으면 `typeof` 검사로
    조용히 건너뛴다(이 파일 공통 원칙 — 이것 때문에 수업이 멈추지는 않는다).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **⛔ 일시정지·음소거를 방 전체에 동기화** — 프로토콜(`video-share` 메시지·DO)을 건드려야
  하고, 학생의 멈춤이 다른 학생·강사 화면까지 세우는 것은 요청 범위 밖이다. **내 화면에만**
  적용으로 한정 — Melca 결정(강사만 제어)과도 충돌하지 않는다. seek 잠금은 그대로 뒀다.
- **⛔ iframe 잠금(`pointer-events:none`) 해제** — YouTube 기본 컨트롤이 살아나면
  빨리감기·다른 영상 추천까지 통째로 열린다. Melca 결정을 뒤집는 별건.
- **⛔ `idx-main.js` 직접 수정** — blocking 849KB 파일이고 첫 화면 예산 여유가
  백 바이트대다. defer 파일에서 전역 함수를 감싸는 기존 ⑧⑨⑩⑪절 방식 그대로.
  `vpAddSoundOverlay` 는 최상위 `function` 선언이라 window 재대입이 bare 호출
  3곳(13328·13336·13345)에 실제로 걸리는 것을 확인했다(let/const 였다면 불가능).
- **⛔ 버튼에 `data-ko`/`data-en` 툴팁** — 두 i18n 엔진이 textContent 를 통째로 갈아끼워
  아이콘이 문장으로 바뀐다(등재된 함정). 설명은 `data-ko-title`/`data-en-title` +
  `data-*-aria` 로만 달고, 상태 라벨이라 paint() 마다 함께 갱신한다.
- **⛔ 소리 꺼짐 상태를 처음부터 🔊 아이콘으로** — 수신 영상은 음소거 자동재생으로
  시작하므로(`mute=1`) 초기 상태는 🔇 가 사실과 일치한다. 기존 `#mango-promo-mute`
  등과 같은 «상태 표시» 규약을 따랐다.

## 5. 남은 것 / 주의할 것

- **YouTube/Vimeo postMessage 가 실기기에서 실제로 먹는지는 사람이 봐야 한다** —
  헤드리스에서는 iframe 내부(외부 도메인)가 로드되지 않아 DOM 부착·명령 발송까지만
  확인했다. 배포 후 폰에서 유튜브 영상 하나로 ⏸·🔇 를 눌러보면 끝.
- 학생의 일시정지는 **자기 화면만** 멈춘다 — 강사 쪽은 계속 재생되고, 재개하면 멈춘
  지점부터 이어진다(재생 위치는 방에 동기화되지 않는 기존 구조 그대로). 「학생도 같은
  위치를 보게」 하려면 재생 위치 동기화라는 별건이다.
- 같은 테스트의 제보 1(칼 화면 4~5초 끊김 2회)은 이번에 손대지 않았다 — 재발하면
  `X-Turn-Source`/`X-Turn-Detail` 헤더부터 볼 것.
