## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

**원인 진단(잰 값과 판단을 구분해 적는다):**
- 잰 값: 해당 녹화 행이 「참가자 **1명** (동의 1)」 = 녹화 시작 시점에 방에 혼자였다(자동녹화는 수업 화면 진입 «즉시» 시작). `vc_quality` 실측(이병엽 브라우저 21건): 손실 0~0.9%·RTT 130~230ms 로 건강, 단 수업 ~6분 지점(14:03)에 RTT 627ms 스파이크 1회. `attendance` 는 교사 Farrah 23분 접속·`spk_diag an=1;mic=1;ac=running`. TURN 은 `X-Turn-Source: kv-cache`(정상).
- 판단: ① 상대 목소리 없음 = 늦게 입장한 상대의 트랙이 믹서에 영영 안 붙는 구조 때문(확정 — 코드에서 읽힘). ② 5분부터 전부 무음 = 그 스파이크 무렵 재연결로 새 피어의 «새 트랙» 이 생겼는데 믹서는 죽은 옛 트랙만 물고 있었기 때문(시기 일치 — 재연결 시각의 직접 기록은 없어 추론). 영상은 `collectVideos()` 가 매 프레임 DOM 을 다시 읽어 저절로 복구되므로 «영상만 나오는» 녹화가 된다.

**버린 방법:**
- (다운로드) 서버 `/api/recordings/blob/` 에 `dl=1` + `Content-Disposition` 추가 — `src/index.ts`(공동 금지구역)를 건드려야 해서 버림. 같은 오리진 `<a download>` 로 충분하다.
- (다운로드) 「크롬 플레이어 ⋮ / 우클릭 저장을 쓰세요」 안내 — 실제 화면에서 **둘 다 비활성/무동작으로 실측**돼 버림.
- (오디오) 피어 연결의 `ontrack` 이벤트를 후킹해 이벤트 구동으로 — `idx-main.js`(blocking·예산 빠듯) 쪽 연결 생성부를 건드려야 하고, 재연결·마이크 재취득 등 «트랙이 생기는 모든 자리» 를 좇아야 해서 버림. 3초 재스캔이 자리 하나로 전부 커버한다.
- (오디오) body class `MutationObserver` 로 상태 감시 — **CLAUDE.md 2장 금지 함정**(홈 전체 정지 전력). 인터벌은 녹화 동안만 살게 설계.
- (오디오) 죽은 옛 소스를 믹서에서 끊기 — 죽은 트랙은 무음만 내보내 무해하고, 끊기 추적이 오히려 사고 지점이라 버림(연결만 하고 안 끊는다).

## 5. 남은 것 / 주의할 것

- **수리 전에 찍힌 무음 녹화는 소리를 되살릴 수 없다** (녹화 파일에 소리가 아예 안 담겼음)
- **끊김 3회의 원인은 미확정** — 이병엽 쪽 회선·TURN 은 실측 정상. 교사(Farrah) 쪽 `vc_quality` 로그가 **0건**이라 판정 근거가 없다. 교사 브라우저가 옛 캐시 JS 일 가능성 → 다음 수업 전 강력 새로고침(Ctrl+Shift+R)을 요청해 두면 다음부터는 숫자로 판정 가능
- 이미 열려 있던 수업 탭은 옛 코드로 돌므로 **새로 여는 수업부터** 적용
- 관리자 저장 버튼의 파일명은 방번호 기준이라, 같은 방을 두 사람이 각자 녹화한 경우(한 수업에 녹화 행 2개) 파일명이 겹칠 수 있다 — 브라우저가 `(1)` 을 붙여 구분하므로 실해는 없음
