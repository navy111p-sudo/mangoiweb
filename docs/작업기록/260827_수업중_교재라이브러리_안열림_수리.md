# 수업 중 교재 라이브러리가 «눌러도 안 되던» 것 수리 (2026-08-27)

> 마이마이 제보 · 파일 `cloudflare-deploy/public/js/idx-x3.js`

---

## 1. 왜 했나

> 「The library doesn't work sir, even I restarted my pc, clear cache and refresh.
>  Details: After uploading book folder at the library, we can't now open the library during the class」

스크린샷에는 교재도구 팝오버의 **Library** 버튼이 동그라미로 표시돼 있고, 본문은
「Please wait · 선생님이 교재를 여는 중이에요」 대기 카드 그대로였습니다.

### 처음에 잘못 짚은 것

「업로드한 파일이 많아 느려진 것」 → 「권한 게이트가 조용히 막은 것」 순으로 의심했습니다.
게이트(`openTextbookLibrary` 의 `vcCanControlTextbook()` 검사)는 실제로 **조용히** 막지만,
스크린샷에 Library 버튼이 **보이는** 것으로 보아 그녀는 staff 였습니다
(`vcRenderTextbookControls` 가 학생에게는 그 버튼을 숨깁니다 —
`.pdf-controls` 가 `#tab-pdf` 안에 있는 것을 확인했습니다).

### 진짜 뿌리 — 파일이 스플라이스돼 있었다

`js/idx-x3.js` 를 줄 단위로 읽다가 발견했습니다:

```
 99|           function chk(){
100|             if (tbs === null || fls === null) return;
...
104|             if (done) return; done = true; clearTimeout(to);
105|   window.selectFromTextbookLibrary = async function(id, url, kind, name) {   ← 🔴
...
170|   };
172|             console.log('[ph245] IDB 교재', tbs.length, '· 파일', fls.length);
173|             resolve({textbooks:tbs, files:fm, err:null});
```

**교재를 실제로 여는 함수가 `_loadAllIDB` 안 `chk()` 한가운데에**, 그것도
`if (done) return;` **뒤**에 들어가 있었습니다. 그래서 그 함수는
**«IndexedDB 읽기가 5초 안에 성공했을 때만» 정의**됩니다.

| 그 밖의 경우 | 결과 |
|---|---|
| 읽기 시간 초과(5초) — 교재를 많이 올린 뒤 | `done` 이 이미 true → 104행에서 return → **정의 안 됨** |
| DB 열기 실패 (`req.onerror`) | `chk()` 자체가 안 돔 → **정의 안 됨** |
| store 누락 / 예외 | 같음 → **정의 안 됨** |

그런데 라이브러리 **목록**은 서버(`/api/textbook-files?group=1`)에서 받아 와 멀쩡히
그려집니다. 그래서 **«목록은 보이는데 눌러도 아무 일도 안 일어나는»** 상태가 됩니다.
에러도 안 납니다.

**브라우저 실측** — 페이지 로드 직후:
```
openTextbookLibrary: "function"   loadTextbookLibrary: "function"
closeTextbookLibrary: "function"  selectFromTextbookLibrary: "undefined"   ← 🔴
```

### 왜 «업로드 뒤» 부터인가

업로더(`textbook-uploader.html` 의 `openDB`)에는 store 가 없을 때
**`indexedDB.open(DB_NAME, (d.version || 3) + 1)`** 로 **버전을 올려** store 를 만드는 길이
있습니다. 한 번 4가 되면 수업화면의 `indexedDB.open('mangoi-textbooks', 3)` 은
**VersionError 로 열기 자체가 실패**합니다.

**IndexedDB 는 캐시가 아닙니다** — 재시작·캐시삭제·새로고침으로 안 풀립니다.
제보의 「even I restarted my pc, clear cache and refresh」와 정확히 맞습니다.

**버전 4로 올려 재현**했습니다:
```
selectFromTextbookLibrary: "undefined"    [ph245] IDB 교재 … 로그: 0건
```

### 세 번째 문제 — 거절이 완전히 조용했다

`vcTextbookDenied()`(idx-main.js)는 「교재는 선생님만 바꿀 수 있어요」를 `mangoToast` 로
띄우려 합니다. 그런데 **`mangoToast` 는 저장소에 정의가 없습니다** —
`js/idx-chatbot-frame.js` 주석이 이미 그 사실을 적어 뒀습니다. `typeof mangoToast === 'function'`
검사에 걸려 **아무것도 안 뜹니다.** 즉 권한이 없어 막힌 경우도 「버튼이 고장났다」로 보입니다.

## 2. 검토했다가 버린 방법

| 버린 방법 | 왜 |
|---|---|
| **IDB 읽기 5초 타임아웃을 늘린다** | 증상 하나만 가립니다. 열기 실패·store 누락·예외에서는 그대로 깨지고, 타임아웃을 늘리면 그만큼 모달이 「로딩 중…」으로 멈춰 있습니다. **정의를 옮기는 것이 뿌리**입니다 |
| **`getAll('files')` 를 커서로 바꿔 블롭을 안 읽는다** | 읽기 속도 개선은 맞지만, 이번 사고는 «느림» 이 아니라 «정의 위치» 입니다. 게다가 IndexedDB 의 Blob 은 디스크 참조라 메모리를 그만큼 쓰지 않습니다 — **재 보지 않고 최적화하면 엉뚱한 것을 고칩니다** |
| **업로더의 «버전 올리기» 를 없앤다** | 그건 store 가 없을 때의 복구책입니다(ph261 — 자동 `deleteDatabase` 를 없애며 넣은 것). 없애면 store 누락 브라우저가 영영 못 씁니다. **읽는 쪽이 버전에 관대해지는** 편이 맞습니다 |
| **수업화면에서도 버전을 올려 store 를 만든다** | 학생 29,000명의 브라우저에서 DB 버전을 올리게 됩니다. 수업 중에 할 일이 아니고, 로컬 IDB 교재는 «올린 사람 PC» 전용 기능입니다(공유는 서버 경로) |
| **`vcCanControlTextbook` 게이트를 푼다** | 그건 2026-08-12 Melca 7·8번 수리 — 학생이 반 전체 교재를 갈아치우던 것을 막은 것입니다. 조용한 것이 문제였고 **막는 것 자체는 맞습니다** |
| **`mangoToast` 를 idx-main.js 에 정의한다** | 849KB blocking 파일이고 첫 화면 예산이 빠듯합니다. classic script 는 전역을 공유하므로 **다른 파일에서 `window.mangoToast` 를 채우면** bare `mangoToast` 도 그것을 찾습니다 |

## 3. 고친 것 (`js/idx-x3.js` 하나 + `index.html` 의 `?v=` 한 글자)

1. **`window.selectFromTextbookLibrary` 를 파일 최상위로** 되돌렸습니다(`_loadAllIDB` 밖).
2. **`_loadAllIDB` 가 버전을 지정하지 않고** 엽니다 — `indexedDB.open('mangoi-textbooks')`.
   버전을 안 주면 `onupgradeneeded` 는 «DB 가 아예 없을 때» 만 돕니다(그때만 store 생성).
3. **`window.mangoToast` 폴백**을 뒀습니다(이미 있으면 덮지 않음). z-index 2147483001 —
   홈 위젯(2147483000) 바로 한 칸 위, 재연결 안내(2147483646) 아래.

⚠️ `index.html` 은 **공동 금지구역**입니다. 바꾼 것은 `idx-x3.js?v=10` → `?v=11`
**한 글자**뿐이고, 이것은 `asset_version_harness` 가 요구하는 필수 변경입니다
(안 올리면 immutable 캐시에 옛 파일이 남습니다).

### 밟은 함정 두 개 (다음 사람용)

- **`elementsFromPoint` 는 `pointer-events:none` 요소를 건너뜁니다.** 토스트가 그 값이라
  「다른 것이 가린다」는 **거짓 실패**가 났습니다. 잠시 `auto` 로 켜서 재야 합니다.
- **로컬 A/B 재현은 테스트마다 포트를 바꿔야** 합니다. `sw.js` 가 내비게이션을 캐시해
  **옛 `index.html`(옛 `?v=`)** 을 주어, 고친 뒤에도 `undefined` 가 나왔습니다.
