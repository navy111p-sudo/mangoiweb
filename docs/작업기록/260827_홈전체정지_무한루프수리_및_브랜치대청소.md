### 원인 (CDP 로 멈춘 스택을 직접 떠서 확인)

PR #544 «모드 배지»(전날 밤 머지)가 넣은 코드였다. 이 파일의 `watchBody()` 는
body 의 class 속성을 MutationObserver 로 감시하고, 콜백(`sync`)이 `syncModeBadge()` 를
부른다. 새 `syncModeBadge()` 는 수업 중이 아니면 **매번 무조건** `classList.remove()` 를
불렀는데 — **`remove()` 는 지울 토큰이 «없어도» class 속성을 다시 쓴다**(DOM 스펙의
update steps 가 무조건 실행됨). 속성이 다시 쓰이면 값이 같아도 옵저버가 재발화한다.

```
sync → syncModeBadge → classList.remove → 속성 재기록 → 옵저버 재발화 → sync → …
```

옵저버 콜백은 마이크로태스크라 이벤트 루프가 **영영 양보하지 않는다** → 화면 정지.
얄궂게도 같은 파일 121줄 주석이 「classList.toggle 은 값이 같으면 attribute 를 안
건드린다(콜백이 안 돈다)」고 정확히 적어 두고 있었다 — toggle 과 remove 의 차이가 함정.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

**진단 단계**
- ~~도메인/DNS/CDN 의심~~ — mangoi.ai 신규 도메인이라 처음엔 도메인 문제로 보였지만, HTML 이 test.mangoi.co.kr 과 **바이트 동일**하고 test 쪽도 똑같이 멈춤 → 배포 코드 문제로 확정. **「특정 도메인만 안 된다」는 제보라도 다른 도메인을 같은 방법으로 꼭 재봐야 한다.**
- ~~코드 diff 를 눈으로 뒤져 루프 찾기~~ — index.html 1MB + js 82개에서 `while` 그물질은 전부 헛손질이었다(범인은 while 문이 아니라 옵저버 피드백 루프). **멈춘 페이지는 추측 말고 CDP 로 스택을 뜬다**: 이미 멈춘 페이지에는 디버거가 안 붙으므로, **새 탭 → `Debugger.enable` 먼저 → `Page.navigate` → 수 초 뒤 `Debugger.pause`** (Node 24 내장 WebSocket + `chrome.exe --headless=new --remote-debugging-port`). 스택 두 줄로 파일·함수가 바로 나왔다.
- ~~`?v=` 범프 없이 파일만 고쳐 배포~~ — 장애 중 접속자의 서비스워커가 깨진 v=5 를 ASSET_CACHE 에 **cache-first 영구 캐시**로 물고 있어, 같은 URL 로는 영영 깨진 채 남는다. 범프 필수.
- 로컬 A/B 검증에서 「고쳤는데도 FROZEN」 미스터리 — 원인은 위와 같은 SW 캐시. **첫 방문은 SW 미제어라 통과**하고 2번째 방문부터 캐시가 물린다. **대조 실험은 테스트마다 포트를 바꿔(=새 origin) SW 오염을 끊어야 한다.** FROZEN 재현 탭은 닫아도 좀비 렌더러가 CPU 를 먹으니 브라우저를 새로 띄우는 게 깔끔.

**배포 단계**
- ~~리포 루트 deploy.ps1~~ — 메인 작업 폴더는 8/13 브랜치 + 남의 미커밋이 섞여 있어, 통째 업로드하면 라이브를 되감는다. **origin/main 기준 깨끗한 worktree** 에서 수리·검증·배포(기존 등재 수법).
- 되감김 게이트(0b/7)가 「라이브에만 있는 줄: v=5 스크립트」로 배포를 막았다 — 이번엔 그 줄이 **바로 내가 의도적으로 교체한 줄**이라 오탐. 이런 경우만 `-SkipLiveDrift` 가 정당하다(분류기가 막으므로 사장님이 직접 실행).

**대청소 단계**
- ~~일괄 삭제~~ — 전 worktree 의 미커밋·전 브랜치의 미머지 커밋을 **개별 판정** 후 삭제. 원격에 없던 브랜치 4건은 내용까지 대조(감시 코드·녹화 계정아이디 수리·docs 정정 → 전부 다른 경로로 main 에 반영돼 있었고, 나머지는 BUILD 스탬프 커밋뿐).
- 사장님 터미널용 정리 스크립트 함정 둘: ① bash 명령을 PowerShell 에 붙이면 `&&` 부터 파싱 실패 — **PS 용은 .ps1 로 따로**. ② 그 .ps1 에 한글을 넣으면 PS 5.1 이 BOM 없는 UTF-8 을 ANSI 로 읽어 **문자열이 깨지며 파싱까지 무너짐** — 사람에게 줄 .ps1 은 영문으로만 쓰거나 BOM 을 붙인다.

- 원인: CDP `Debugger.pause` 스택 = `sync → syncModeBadge` (vc-observe-guard.js) 실측

- 대청소 후: 원격 219→67, **main 머지 완료분 잔존 0** 을 `merge-base --is-ancestor` 전수 재검사로 확인

## 5. 남은 것 / 주의할 것

- **장애 중(26일 밤~27일 아침) 접속했던 사용자**는 SW 에 깨진 시절 HTML 이 남아, 다음 방문이 아주 느린 회선이면(3.5초 nav-timeout 폴백) 한 번 더 멈춘 화면을 볼 수 있다. 그 방문 중 배경에서 새 HTML 이 캐시되므로 **그다음 방문부터 자동 회복** — 별도 조치 불요.
- `lesson-pay-policy-m1-heartbeat` (원격 백업됨): 수업료정책 v5 문서 개정 초안. 정책이 확정되면 머지하거나 폐기 결정 필요.
- 이 파일의 body-class MutationObserver 는 「홈 전체를 멎게 한 전력」이 이제 두 번이다. 다음에 이 옵저버 콜백 경로에 뭔가 추가할 때는 **콜백 안의 모든 classList 쓰기가 «바뀔 때만» 인지**부터 볼 것 (CLAUDE.md 2장 함정 표에 등재).
