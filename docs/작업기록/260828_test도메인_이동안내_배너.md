# test.mangoi.co.kr 접속 시 「잘못된 주소」 인지 배너

- 날짜: 2026-08-28
- 작업자: Claude (원격 세션)
- 브랜치 / PR: `claude/class-feedback-form-access-ng305m` (PR 미생성 — 사용자가 명시적으로 요청하지 않아 생성하지 않음)

## 1. 왜 했나

사장님이 "학생들이 아직 test.mangoi.co.kr로 접속하는 경우가 있는 것 같다, test.mangoi.co.kr로
접속했을 때 mangoi.ai로 들어가도록 안내할 방법이 없을까" 라고 요청함.

## 2. 무엇을 바꿨나

**자동 리다이렉트는 만들지 않았다.** 대신 `cloudflare-deploy/public/js/idx-legacy-domain-notice.js`
(신규, defer)를 추가해 — `location.hostname === 'test.mangoi.co.kr'` 일 때만, 화면 우상단에
"잘못된 주소로 접속했습니다 · 이 주소는 옛 주소입니다. mangoi.ai 로 접속해 주세요." 라고만
알려 주는 카드를 띄운다.

- **클릭 한 번으로 넘어가는 링크·버튼은 없다** — 순수하게 "인지"만 시키고, 실제로 옮겨가는
  것은 사용자가 직접 주소창에 mangoi.ai를 치는 몫으로 남긴다(아래 3절 참고 — 사장님이 직접
  이렇게 결정함).
- `vc-in-call` 중에는 CSS로 숨긴다(수업 화면을 가리지 않게).
- 한 번 닫으면(✕) `localStorage.mangoi_legacy_domain_notice_dismissed` 로 그 기기에서는
  다시 안 뜬다 — 관리자 "환영 안내" 오버레이와 같은 방식.
- 대상은 역할 구분 없이 test.mangoi.co.kr 로 들어온 사람 전원(학생·교사·관리자 모두 이제
  mangoi.ai만 쓰는 게 맞다는 사장님 확인 — 4절 참고).
- `cloudflare-deploy/public/index.html` — 위 파일을 부르는 `<script defer>` 한 줄 추가
  (`idx-vc-outputvolume.js` 스크립트 태그 바로 뒤).
- `test-harness/asset-versions.json` — 신규 자산 버전 자동 등록(하니스가 채움, v1→v2 갱신 포함).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

**1차 판단: 서버에서 자동으로 리다이렉트(301/308)하는 방법을 검토했다가 버렸다.**
`src/index.ts` 에 이미 `www.mangoi.ai → mangoi.ai` 자동 리다이렉트 코드가 있어서 같은
패턴을 `test.mangoi.co.kr` 에도 적용하는 게 가장 간단해 보였지만, CLAUDE.md 0장과
`src/site-url.ts` 머리말에 **명시적으로 금지**돼 있다:

- `test.mangoi.co.kr` 로 등록된 패스키 **6건**(계정 3개: jeong 4·Lee 1·kang 1)이 자동
  리다이렉트 시 무효화되고 재등록이 필요해진다(호스트별로 `rpId` 가 갈리기 때문).
- 앱(APK) 사용자의 시작 URL이 아직 `test.mangoi.co.kr` 로 박혀 있고, 그 도메인의
  `localStorage` 로그인 세션이 리다이렉트로 오리진이 바뀌면 통째로 날아간다.
- 이미 `test.mangoi.co.kr` 은 앱 업데이트 확인 주소(`app-version.json`)로도 쓰이고 있어서,
  이 주소를 강제로 끊으면 구버전 앱이 흰 화면이 되고 자기 힘으로 복구할 수 없다.

**2차 판단(1차 구현 후 수정): "누르면 바로 mangoi.ai로 이동하는 링크/버튼"도 만들었다가 뺐다.**
처음엔 배너 안에 "mangoi.ai로 이동" 버튼(누르면 같은 경로로 즉시 이동)을 넣었는데, 이 버전을
trap-check 서브에이전트로 검사한 결과 — 배너가 역할 구분 없이 전원에게 뜨므로, 패스키가
걸린 계정(jeong·Lee·kang)이나 앱 사용자가 그 버튼을 눌러 실수로 넘어가면 결국 위에서 피하려던
바로 그 위험(패스키 무효화·로그인 유실)을 사용자 클릭으로 유도하는 셈이라는 지적을 받았다.
이걸 사장님께 그대로 여쭤봤고("이대로 둘까요, 특정 계정만 배너를 숨길까요, 관리자·교사
전체에게 숨길까요"), 사장님 답은 셋 다 아니었다 — **"학생, 교사, 관리자 모두 mangoi.ai만
사용하고 있다. test.mangoi.co.kr로 들어오면 잘못 들어왔다는 것만 알려주면 충분하다.
'바로가기' 등은 또 다른 문제를 야기할 수 있다."** 그래서 대상을 역할별로 가르는 대신,
**바로가기 자체를 없애는 쪽**으로 풀었다 — 이러면 애초에 "클릭 한 번으로 옮겨가다 패스키가
깨지는" 경로 자체가 사라져서, 대상을 전원으로 유지해도 안전하다. 결과적으로 구현이 더
단순해졌다(URL 조립 로직·앵커 태그 삭제).

**함께 고친 것: 배너 문구의 사실 단정.** 최초 문구 "이 주소는 곧 사용할 수 없어요"는
trap-check가 지적한 대로 CLAUDE.md 0장이 실제로 확정한 적 없는 폐쇄 시점을 암시하는
과장이었다 — "이 주소는 옛 주소입니다"로 순화했다.

- **배치 위치**: 새 전체 폭 상단 고정 바를 새로 설계하는 대신, 이미 검증된 패턴
  (`window.mangoiClassEntryNotice` 의 휴가·공휴일 안내 카드 — `top:72px 근처, z-index
  2147482000`)과 같은 좌표계·z-index를 재사용했다. 이 저장소는 z-index·sticky 겹침 사고가
  아주 흔해서(CLAUDE.md 2장에 십수 건), 새 값을 추측하는 대신 이미 안전하다고 확인된 값을
  그대로 썼다. 다만 좌표가 완전히 같으면 같은 시점에 휴가 안내 카드와 겹칠 수 있어 top을
  16px로 살짝 낮춰 시각적 충돌 가능성을 줄였다(둘 다 닫기 가능한 카드라 겹쳐도 기능은 안
  깨진다).
- **blocking vs defer**: `index.html` 은 blocking 스크립트 예산이 극도로 빠듯하다고
  CLAUDE.md에 반복적으로 나와 있어서, 처음부터 `defer` 파일로 분리했다(인라인으로 넣는
  안은 검토하지 않고 바로 버림). 회귀 하니스의 `first_paint_budget_harness` 가 통과했다.
- **body class 를 지켜보는 방식(MutationObserver)** 은 쓰지 않았다 — 2026-08-27 홈 전체
  정지 사고(무한루프)의 원인이 정확히 이 패턴이라, `vc-in-call` 진입 시 배너를 숨기는 것은
  **CSS 규칙 한 줄**(`body.vc-in-call #mg-legacy-domain-notice{display:none!important}`)로
  처리했다. JS 로 상태를 감시하지 않는다.
- **i18n**: `data-ko`/`data-en` 속성을 쓰지 않았다 — 이 배너는 `textContent` 로 그리는
  라벨이 아니라 매번 새로 `innerHTML` 로 통째로 그리는 카드라 그 두 속성이 필요 없고,
  아이콘 버튼(✕)에 잘못 달았다가 문장이 들어앉는 함정과도 무관하다. 대신 언어 판정은
  `window.getLang()` 을 우선 쓰고 없으면 `mangoi_lang`/`document.documentElement.lang` 으로
  떨어지는 방식을 그대로 재사용했다.

## 4. 확인한 방법

- 타입체크: `cd cloudflare-deploy && node node_modules/typescript/bin/tsc --noEmit` — 출력 없음(통과).
- 회귀 하니스: 리포 루트에서 `node test-harness/run.mjs --fast` — **PASS 232 / SKIP(E2E) 20 / FAIL 0**
  (v1→v2 버전업 직후 한 번은 `asset_version_harness` 가 "내용이 바뀌었는데 ?v= 가 그대로"로
  FAIL 냈고, `index.html` 의 `?v=1`→`?v=2` 를 함께 올려서 다시 통과시켰다).
  `first_paint_budget_harness.mjs` 포함 전부 통과. 새 자산 버전이
  `test-harness/asset-versions.json` 에 알파벳 순서로 자동 등록된 것을 확인하고 커밋에
  포함시켰다. 하니스 실행 중 생성된 `*_report.txt` 타임스탬프 변경분은 커밋에서 제외하고
  되돌렸다.
- trap-check 서브에이전트로 CLAUDE.md 함정 표(특히 test.mangoi.co.kr 리다이렉트 금지·
  첫 화면 예산·공동 금지구역·z-index 겹침·body class MutationObserver 금지·i18n data-ko/en
  오용)와 대조 검사를 1차 구현본에 대해 실행 — "고쳐야 할 것"은 없었지만 "사람 확인 필요"로
  위 3절의 두 가지(전원 대상 + 링크의 패스키 위험, 문구 과장)를 지적받아 반영함.
- **화면은 직접 못 봤다** — 이 작업 환경 프록시가 `mangoi.ai`/`test.mangoi.co.kr` 을 막아
  배포된 실제 화면을 볼 수 없다(CLAUDE.md 4-1-1 문서화된 제약). 배너가 실제로 보기 좋게
  뜨는지, 다른 상단 요소(로고·메뉴)와 안 겹치는지는 **사람이 test.mangoi.co.kr 에서 직접
  확인해야 끝난 것**이다.

## 5. 남은 것 / 주의할 것

- 이 배너는 test.mangoi.co.kr 을 완전히 없애는 작업이 아니다. CLAUDE.md 0장에 이미 나온
  대로, **설치 기반이 새 버전으로 넘어갈 때까지 그 도메인은 계속 살려 둬야 한다** — 이
  작업은 그 전제를 그대로 유지한 채 "인지"만 추가한 것이다.
- 배너를 닫으면 그 기기에서는 다시 안 뜬다(영구 dismiss). 사람이 배너를 안 보이게 됐다고
  "다 옮겨갔다"고 오판하지 않도록 유의 — 이건 그 기기의 그 브라우저에서만의 상태다.
- 바로가기 링크가 없으므로, 사용자가 직접 mangoi.ai로 이동하기 전까지는 아무 것도 안 바뀐다
  — 패스키·로그인 위험은 "그 사람이 직접 주소창에 쳐서 넘어갈 때"에만 발생하고, 그건 이
  배너가 없어도 이미 가능했던 일이라 이 작업이 새로 만든 위험은 없다.
- 브라우저 실사용 확인(배너 위치·겹침 여부·문구 가독성)은 사람이 test.mangoi.co.kr 에서
  직접 확인 필요.
