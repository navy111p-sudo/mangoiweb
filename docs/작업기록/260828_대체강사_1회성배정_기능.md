# 대체강사 1회성 배정 기능

- 날짜: 2026-08-28
- 작업자: Claude (원격 세션)
- 브랜치 / PR: `claude/class-feedback-form-access-ng305m` (PR 미생성 — 사용자가 명시적으로 요청하지 않아 생성하지 않음)

## 1. 왜 했나

사장님이 "오늘의 수업"(관리자 「🔴 실시간 수업 현황」 화면 스크린샷)을 보여주며, 강사 휴가가
잡히거나 강사가 병가로 갑자기 못 나오는 경우 수업이 가능한 다른 강사로 대체할 수 있는
버튼·기능이 필요하다고 요청함. "오늘수업 메뉴에 들어가는 게 좋을지, 따로 만드는 게 좋을지는
모르겠다" 며 판단을 맡김.

## 2. 무엇을 바꿨나

**핵심 설계**: 매주 반복되는 정기수업을 강사 병가로 대신할 때 "이번 주만 대체하고 다음 주는
자동으로 원래 강사로 돌아가는" 진짜 1회성 대체를 사용자가 명시적으로 선택함(더 큰 개발
범위를 감수하기로 확인).

- `cloudflare-deploy/src/enroll-ops.ts`
  - 신규 테이블 `class_substitutions`(schedule_id, sub_date, original_teacher_id,
    substitute_teacher_id, reason, created_by, created_at, status) — `ensureEnrollTables()`
    안에 추가. `UNIQUE(schedule_id, sub_date)` — 한 회차·한 날짜엔 대체 오버레이가 하나뿐.
  - 신규 헬퍼 `subScheduleDow(scheduledDate, dayOfWeek, date)` — 이 class_schedules 행이
    그 날짜에 실제로 열리는지 판정.
  - 신규 `GET /api/pay/enroll/admin/substitute-candidates` — `teachersFreeAt()` 재사용해
    그 시간에 비어 있는 강사 후보를 가려서 보여줌(🟢/🔴 표시). 기존 활성 대체가 있으면
    같이 반환.
  - 신규 `POST /api/pay/enroll/admin/substitute` — 등록/취소를 한 엔드포인트에서 처리.
    `enrollConflicts()` 재사용으로 대체강사의 시간 충돌 검사. `class_audit_log` 기록.
- `cloudflare-deploy/src/api-admin.ts` — `/api/admin/classes/today`(오늘의 수업 화면의
  데이터 소스) 응답에 그 날짜의 활성 대체 오버레이를 LEFT JOIN 으로 반영 —
  `teacher_id`/`teacher_name` 을 대체강사로 덮어쓰고 `substituted`/`substituted_from` 추가.
- `cloudflare-deploy/src/api-mango.ts` — `/api/class/verify-room`(화상수업 입장 시 "담당
  강사가 아니다" 경고 판정)에 그 날짜의 대체강사도 담당으로 인정하는 분기 추가. room_id
  정규식(`class-(\d+)-(\d{8})`)에 날짜 캡처그룹을 추가해 오버레이 조회에 씀.
- `cloudflare-deploy/src/api-teacher.ts` — 강사 포털(`/api/teacher/portal`) "오늘 수업"
  목록에 오버레이 반영: 원래 강사 쪽엔 그 날 목록에서 빼고(`hiddenToday`), 대체강사 쪽엔
  끼워 넣음(`subToday` → `classes` 배열에 합성 항목 추가, `substitute:true`,
  `covering_for:원래강사이름`).
- `cloudflare-deploy/public/js/adm-today-classes.js`(v9→v10) — "🚪 오늘 수업(바로 입장)"
  화면의 강사 칸에 🔄 버튼 추가. 클릭하면 모달에서 후보 강사(가능/불가 표시) + 사유를 받아
  등록. 기존 대체가 있으면 "🔙 되돌리기" 버튼도 보임. 반복 수업이면 "이번 회차만 바뀌고
  다음 회차는 자동 복귀"라는 문구를 명확히 표시.
- `cloudflare-deploy/public/admin.html` — 위 스크립트 버전 태그(`?v=10`) 갱신, 카드 안내
  문구 한 줄 추가(🔄 버튼 설명).
- `cloudflare-deploy/public/teacher.html` — 강사 화면 "오늘 수업" 목록에 "🔄 대신 · X"
  배지 추가(대체로 들어가는 회차에만 표시. 서버가 이미 판정해 내려주는 값을 그리기만 함).
- `test-harness/d1_bind_limit_harness.mjs` — 신규 `IN (...)` 목록(api-teacher.ts, 로그인한
  강사 본인의 teachers.id 후보 + username, teachers 표 전체가 100행 미만이라 안전)을
  ALLOW 목록에 등록.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

**가장 중요한 판단: "매주 반복 수업" 을 대체할 때 정본 행을 손댈지 여부.** 사용자에게
AskUserQuestion 으로 직접 확인 — "영구 변경(간단, 오늘 당장)" 대신 **"1회성 기능을 새로
개발(하루만 대체, 다음 주는 자동 복귀)"** 을 명시적으로 선택함. 검토 후 버린 안:

- **정본 행의 teacher_id 를 그냥 바꾸는 안(이미 있던 `/api/pay/enroll/admin/teacher-leave`
  bulk API 재사용)**: 조사해 보니 그 API 는 애초에 `scheduled_date` 가 있는(=날짜지정)
  행만 골라서 바꾼다 — `schedule_kind='recurring'`(요일 반복, 무기한) 행은 손도 안 댄다.
  즉 실사용의 대부분인 정기수업(수강신청이 만드는 반복 수업)에는 원래도 안 먹히는
  기능이었다. 이 사실을 확인한 뒤, recurring 행에도 되는 새 기능이 필요하다고 판단.
- **오버레이 없이 recurring 행의 teacher_id 를 직접 바꾸는 안**: 사용자가 원하는 "다음 주는
  자동 복귀"를 만족 못 한다(그 행이 무기한 반복 정의라 바꾸면 영구히 바뀐다) — 버림.
- **"1회성 예외"를 위한 완전히 새로운 스케줄 자료구조(하루치를 별도 행으로 쪼개기)**: 급여·
  강사포털·room_id 생성 등 `class_schedules.id` 를 참조하는 곳이 전부 갈라져야 해서 반경이
  너무 커짐(payroll 이 특히 위험 — teacher_id 세 갈래 번호공간 함정과 겹칠 위험). 대신
  **오버레이 표(class_substitutions) 하나만 추가하고, "누가 담당인가"를 읽는 자리마다 그
  오버레이를 겹쳐 보여주는** 쪽으로 범위를 좁혔다 — 정본 데이터는 안 건드리고 표시만 겹친다.
- **되돌리기(취소) 를 별도 `/cancel` 엔드포인트로 분리하는 안**: 처음엔 그렇게 설계했다가,
  "원래 강사로 다시 배정 = 취소와 동치"라는 점을 이용해 **같은 `/substitute` 엔드포인트가
  자기 자신에게 배정하면 취소로 처리**하도록 단순화했다. 그런데 이 과정에서 실제로 버그를
  하나 밟았다 — recurring 행에 대해 "원래 강사로 되돌리기"를 일반 배정과 똑같이
  `enrollConflicts()` 로 충돌검사하면, **그 행 자체가 이미 원래 강사의 그 시간 커밋이라
  자기 자신과 충돌 판정이 나 버린다**(다른 방에서 "그 강사가 바쁘다"고 잘못 거절함).
  → recurring 행에서 `substitute_teacher_id === 현재 teacher_id`(=원래 강사 그대로) 일 때는
  **충돌검사를 완전히 건너뛰고** 오버레이만 취소하도록 고쳤다. dated 행은 이 문제가 없다
  (한 번 바뀌면 행의 teacher_id 자체가 대체강사로 바뀌어 있어서, 원래 강사로 되돌릴 때
  스캔에서 자기 자신이 안 잡힌다).
- **강사 포털의 주간표(weekDays)·앞으로7일(upcoming) 까지 전부 오버레이 반영**: 시간 대비
  위험이 크다고 판단해 **오늘 목록만** 처리하고 범위를 잘랐다(4절에 한계로 명시). 이유는
  weekDays 가 day_of_week 로 "그 요일이면 매주" 매칭하는 구조라, 특정 날짜 하나만 겹치는
  오버레이를 정확히 끼워 넣으려면 날짜별 필터링을 새로 얹어야 하고, 이 파일은 이미
  "Anna → HANNAH" 류 신원판정 사고가 여러 번 난 곳이라 최소침습을 우선했다. 대체강사가
  실제로 "오늘 들어갈 수 있다"(=핵심 가치)는 이미 만족되고, 주간표 표시는 부가 기능이라
  판단.
- **급여(payroll) 자동 반영**: 손대지 않았다 — teacher_payroll_auto·attendance 기반 계산은
  강사 번호 세 갈래(카페24/원부/프로필) 함정이 이미 걸려 있는 영역이라, 이번 범위에서는
  건너뛰고 **문서로 한계를 명시**하는 쪽을 택했다(CLAUDE.md "모르면 모른다고 표시" 원칙).

## 4. 확인한 방법

- 타입체크: `cd cloudflare-deploy && node node_modules/typescript/bin/tsc --noEmit` — 출력
  없음(통과), 매 단계(엔드포인트 추가·오버레이 3곳·UI)마다 반복 확인.
- 회귀 하니스: 리포 루트에서 `node test-harness/run.mjs --fast` — 최종 **PASS 232 /
  SKIP(E2E) 20 / FAIL 0**. 중간에 신규 `IN (...)` 목록 하나가 `d1_bind_limit_harness` 에
  걸려(api-teacher.ts) ALLOW 목록에 근거를 적어 등록.
- 전체(비-fast) 하니스도 한 번 돌림 — `changes_qa_harness.mjs` 하나만 FAIL/크래시났는데,
  **이 저장소를 건드리기 전(git stash)에도 똑같이 크래시**하는 것을 확인함(존재하지 않는
  `mangoi-speech-patch/` 디렉터리를 읽으려다 ENOENT). 그 전에 뜬 "FAIL"들(api-mango.ts·
  admin.html 이 「바뀌면 안 된다」)은 이번 기능이 의도적으로 그 파일들을 고쳤기 때문에 뜬
  것이고, 이 하니스 자체가 과거 특정 PR의 "관련 없는 파일이 안 바뀌었나" 를 확인하던
  일회성 진단이라 — 이번 변경과는 무관. `--fast` 표준 게이트에는 포함되지 않는다.
- trap-check 서브에이전트로 CLAUDE.md 함정 표(강사 번호 세 갈래·D1 IN 100개 한도·관리자
  쓰기 API 강사 차단 가드·신원판정 로직 중복·NOT_PLACEHOLDER 일치·새 API 게이트 등록·
  자산버전·i18n·급여 미반영 명시)와 대조 검사를 요청함 — 결과는 별도 확인.
- **화면은 직접 못 봤다** — 프록시가 mangoi.ai 를 막아 실제 배포 화면을 볼 수 없다.
  관리자 화면의 🔄 버튼·모달, 강사 화면의 배지가 실제로 보기 좋게 뜨는지는
  **사람이 직접 확인해야 끝난 것**이다.

## 5. 남은 것 / 주의할 것

- **급여(payroll) 는 이 대체 배정을 아직 자동으로 따라가지 않는다.** 대체강사가 실제로
  수업을 진행해도, 월급 계산은 여전히 기존 로직(teacher_payroll_auto/attendance 기반)을
  그대로 쓴다 — 대체가 있었던 달은 **사람이 급여 화면에서 수동으로 확인·조정**해야 한다.
  `class_audit_log` 에 `action='teacher_change'`, `source='admin-substitute-recurring'` 또는
  `'admin-substitute-dated'` 로 근거가 남으니 그걸로 대체 내역을 찾을 수 있다.
- **강사 포털의 주간표·앞으로7일 목록에는 아직 대체가 안 보인다** — "오늘"만 처리했다(3절
  참고). 대체강사가 며칠 뒤의 대체를 미리 알고 싶다면 아직 이 기능으로는 안 된다(관리자
  화면에서 확인해서 별도로 알려줘야 함).
- **데이트지정(dated, 수강신청 자동생성) 행에는 "되돌리기" 편의기능이 없다** — 한 번 다른
  강사로 바꾸면 그 회차의 "원래 강사가 누구였는지"는 이 표에 안 남는다(class_audit_log
  에는 남아 있음). 되돌리려면 관리자가 목록에서 원래 강사를 다시 선택하면 된다.
- 관리자 화면·강사 화면 모두 실사용 확인(버튼 위치, 모달, 배지 노출)이 사람 손으로
  필요하다.
