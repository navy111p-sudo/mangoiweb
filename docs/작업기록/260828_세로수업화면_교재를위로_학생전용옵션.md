## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### 3-1. ⛔ index.html 3248행(2026-07-14 결정)을 고쳐서 뒤집기

그 줄은 「위: 교사·학생 얼굴 / 아래: 당일 교재 크게. **모드와 무관하게 항상 강제**」로
사장님이 정하신 것이다. 고치면 **학생 29,000명 전원의 기본 화면**이 바뀐다.
그래서 그 줄은 손대지 않고, **켠 사람에게만 위에 덧씌운다**(⑨절이 「반반」 결정을
바꿀 때 쓴 것과 같은 방식). 되돌리려면 ⑬절만 지우면 된다.

### 3-2. ⛔ 빈자리를 `margin-bottom` 으로 두기 → **`padding-bottom` 으로 바꿈**

얼굴이 아래로 내려오면 화면 아래에 떠 있는 것들(☰ 기능 버튼·⋯)이 **학생 얼굴을 덮는다.**
지금은 아래가 교재라 교재 여백을 덮고 있어 아무도 몰랐다.

처음에 `margin-bottom` 으로 빈자리를 뒀더니 **교재 칸이 그만큼 줄었다**(브라우저 실측 −15px).
이 기능의 목적 자체가 「교재를 크게 위에서 보는 것」이라 목적에 어긋난다.
이 저장소는 `* { box-sizing: border-box }` 라 **`padding-bottom` 으로 두면 칸의 바깥 크기가
안 변한다** → 교재 칸 403px → 403px(**차이 0**), 대신 얼굴이 그려지는 칸이 353 → 296px.

### 3-3. ⛔ 빈자리 크기를 숫자로 박기 → **재서 넣기**

독은 접힘·안전영역·화면폭에 따라 높이가 다르다. 숫자를 박으면 반드시 어긋난다.
→ 켤 때 실제로 재서 `--mg-tb-gap` 에 넣는다(40~160px 로 자름, 못 재면 76px).

⚠️ **처음엔 `#vc-dock` 하나만 쟀는데 그게 틀렸다.** 폰에서 독은 「⋯」 뒤에 접혀
`display:none` 이라 **0px** 로 나온다. 390×844 실측(2026-08-28):

| 요소 | 상태 | 덮는 높이 |
|---|---|---|
| `#vc-dock` (독) | 접힘(display:none) | 0px |
| `#vc-dock-more` (⋯) | 보임 | 42px |
| `.vc-phero-ctrl` (☰ 기능) | 보임 | **53px** |

→ **보이는 것들을 전부 훑어 제일 위로 올라온 것**을 쓴다(실측 59px).

### 3-4. ⛔ 「떠 있는 모드에서는 버튼을 흐리게」 → **먼저 2단으로 옮기고 적용**

세로 진입 기본은 `video-pip`(교재 전체 + 우상단 작은 얼굴)이라 **위아래 개념이 없다.**
거기서 눌렀을 때 아무 일도 안 일어나면 「고장났다」 제보가 된다.
→ `vcScreenSet('half')` 로 먼저 옮긴 뒤 적용한다.
⚠️ 끌 때는 pip 로 되돌리지 않는다 — 그 사이 사람이 크기바로 또 바꿀 수 있어 더 헷갈린다.

### 3-5. ⛔ 「학생만」을 `vcMyRole` 하나로 판정

jeong(사장님)은 홈 통합 로그인에서 관리자 폴백으로 들어가 `vcMyRole` 이 admin 으로
**수업 내내 굳는다**(⑨-3 주석, 실측 10분). 그러면 사장님이 학생 자리로 들어가셔도 버튼이 안 보인다.
→ 스태프로 잡혀도 **상대편에 교사가 있으면 학생 자리로 본다**(`mgRemoteTeacherPresent()` 재사용).
어느 쪽으로 틀려도 피해는 「버튼이 보이거나 안 보이거나」뿐이고, 이 옵션은 **자기 화면만** 바꾼다.

### 3-6. ⛔ 상주 감시자

`body` class 를 `MutationObserver` 로 지켜보거나 상주 `setInterval` 을 두지 않았다
(둘 다 이 저장소에서 홈을 멎게 한 전력). ☰ 메뉴 열기 직전 · 입장 직후 6초 ·
`vcApplySpotlight` · 회전/리사이즈, **끝이 있는 네 순간**에만 다시 본다.

## 4. 🔴 이번에 새로 밟은 함정 — id 두 개짜리 `order` 규칙

**규칙을 다 써 놨는데 화면이 그대로였다.** 문자열 하니스는 전부 초록이었고,
브라우저에서 `getComputedStyle(...).order` 를 재고서야 보였다 — **얼굴=1 / 교재=2**,
내가 쓴 것과 정확히 반대였다.

원인: `index.html` 17455행 `#mg-vc-right-sidebar` 블록(2026-07-28 「교재 왼쪽」 개편)이
같은 두 칸의 `order` 를 **id 두 개짜리 선택자**로 이미 못 박고 있었고,
세로에서는 그것이 다시 「얼굴=1 / 교재=2」로 되돌린다(2026-07-14 결정을 지키려고 일부러).

```css
/* index.html 17484~17491 — 세로폰: 기존 배치 유지 */
body.vc-in-call #vc-main-row > #vc-content-pane { order: 2 !important; }
body.vc-in-call #vc-main-row > #vc-video-pane   { order: 1 !important; }
```

내 선택자는 **id 1개 + 클래스 7개**였다. **id 수가 먼저 비교되므로 클래스를 아무리 쌓아도 진다.**
→ 우리도 `#vc-main-row > #vc-video-pane` 처럼 **id 두 개**로 쓴다.

📌 **이 함정은 CLAUDE.md 2장에 추가했다.**
