# 수업 종료 화면에 파일럿 피드백 폼 버튼 추가

- 날짜: 2026-08-28
- 작업자: Claude (원격 세션)
- 브랜치 / PR: `claude/class-feedback-form-access-ng305m` (PR 미생성 — 사용자가 명시적으로 요청하지 않아 생성하지 않음)

## 1. 왜 했나

사장님이 구글폼(파일럿 수업 피드백 설문)을 별도로 열어야 하는 게 번거롭다며,
파일럿 테스트 참여자가 수업이 끝나면 그 링크를 쉽게 열 수 있게 해 달라고 요청함.

링크: `https://docs.google.com/forms/d/e/1FAIpQLSfXE_y6emnTSRjI-WRWvqzkaXg4Ae4_Ii6me6tE8B0LAsal4A/viewform?usp=sharing&ouid=111183699114886824623`

## 2. 무엇을 바꿨나

`cloudflare-deploy/public/index.html` — 학생이 수업을 마칠 때 이미 뜨는 필수 평가 모달
(`showRatingModal()`, `#vc-rate-modal`) 안에 `📝 수업 피드백 남기기` 버튼(`#vc-pilot-fb-btn`)을
하나 추가했다. 새 화면·새 흐름을 만들지 않고 **이미 모든 학생이 수업 종료 시 보는 화면**에
버튼 하나만 얹은 것이라, 반경이 그 모달 안으로 국한된다.

- 클릭 시 `window.open(URL, '_blank')` 로 새 창을 열고, `null` 이 돌아오면(카톡·인앱
  브라우저가 팝업을 막는 경우) `location.href` 로 같은 창에서 이동 — CLAUDE.md 2장
  「window.open 이 안 열림」 함정에 이미 나온 대응 방식을 그대로 적용.
- 자동으로 열리지 않는다. 버튼을 눌러야만 열린다(사용자가 명시적으로 이 방식을 선택).
- 평가 제출 자체는 이 버튼과 무관 — 버튼은 별점 제출·복습퀴즈 흐름을 막지 않는다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **누구에게 보일지**: 강사 전용/특정 강사 계정만/학생 전용 중 사용자에게 직접 물어
  **학생 전원**으로 확정했다(AskUserQuestion). 강사 화면(teacher.html)에 넣는 안도
  검토했지만, 사용자가 학생 전원을 택함.
- **자동으로 새 탭을 여는 안**도 물어봤으나, 사용자가 "버튼만 표시" 를 택함 — 자동 팝업은
  차단되거나(브라우저 팝업 차단) 원치 않는 순간에 열릴 수 있어 더 안전한 선택.
- **새 화면(별도 팝업/오버레이)을 만드는 안**은 버리고, 기존 평가 모달에 얹는 쪽을 택함 —
  index.html 은 공동 금지구역이라 반경을 최소화하려면 새 상태·새 트리거를 만들지 않고
  이미 있는 "수업 종료 시 뜨는 화면"에 얹는 것이 가장 안전하다고 판단.
- **`<a target="_blank">` 대신 버튼+`window.open`+fallback** 을 택한 이유: CLAUDE.md 에
  이미 문서화된 인앱 브라우저 대응 패턴을 그대로 재사용하기 위함(검증된 방식).
- 이 버튼은 "당분간"(파일럿 기간 한정) 코드이므로 주석에 `🧪 (2026-08-28) 파일럿 테스트
  기간 한정` 이라고 명시해 나중에 지우기 쉽게 표시해 두었다. 삭제 시 `#vc-pilot-fb-btn`
  블록(버튼 markup 1줄 + 클릭 핸들러 IIFE)만 지우면 된다.

## 4. 확인한 방법

- 타입체크: `cd cloudflare-deploy && node node_modules/typescript/bin/tsc --noEmit` — 출력 없음(통과).
  ⚠️ 컨테이너에 `node_modules` 가 없어 `npm ci --legacy-peer-deps` 로 먼저 설치함
  (Node 22/npm 10 환경의 문서화된 ERESOLVE 회귀 — CLAUDE.md 2장 「새 PC 에서 npm ci 가
  ERESOLVE로 죽음」 항목과 동일. 배포용 설정은 건드리지 않음, 로컬 검증 목적으로만 설치).
- 회귀 하니스: 리포 루트에서 `node test-harness/run.mjs --fast` — **PASS 232 / SKIP(E2E) 20 / FAIL 0**.
  `first_paint_budget_harness.mjs` 를 포함해 전부 통과. 하니스 실행 중 생성된
  `test-harness/*_report.txt` 타임스탬프 변경분은 커밋에 안 담고 되돌림.
- **화면은 직접 못 봤다** — 이 작업 환경 프록시가 `mangoi.ai` 를 막아 배포된 실제 화면을
  볼 수 없음(CLAUDE.md 4-1-1 문서화된 제약). 브라우저에서 버튼이 실제로 보이는지,
  눌렀을 때 정말 새 창이 열리는지는 **사람이 직접 확인해야 끝난 것**이다.
- 자산 버전(`?v=`) 확인: 해당 없음 — `public/js/*.js`·`public/css/*.css` 를 건드리지 않고
  `index.html` 인라인 스크립트만 수정함.

## 5. 남은 것 / 주의할 것

- **파일럿이 끝나면 이 버튼을 지워야 한다.** 코드에 "당분간" 이라고 적어 뒀지만, 지우는 걸
  잊으면 29,000명 학생 전원이 계속 이 폼 링크를 보게 된다 — CLAUDE.md 2장 「문서에 「고쳤다」고
  적혀 있는데 같은 사고가 또 남」 함정과 같은 이유로, 완료가 아니라 "임시로 켜 둔 상태"임을
  명확히 남겨 둔다.
- 이 폼이 학생용 설문인지 재확인이 필요하면(원래 "파일럿 테스트를 하는 사람들" 이 누구인지
  질문했을 때 사용자가 "학생 전원" 을 택함) 실제 운영 중 폼 응답을 봐서 의도한 대상과
  맞는지 사람이 검토해야 한다.
- 브라우저 실사용 확인(버튼 노출 위치, 클릭 시 새 창 동작, 카톡 인앱에서의 폴백)은
  사람이 배포 후 mangoi.ai 에서 직접 확인 필요.
