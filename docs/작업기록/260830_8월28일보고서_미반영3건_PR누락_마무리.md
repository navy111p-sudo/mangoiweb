### 🪤 이번에 밟은 함정 — 「커밋 해시로 반영 여부를 판정하면 안 된다」

처음에 보고서에 적힌 커밋번호로 `git merge-base --is-ancestor <해시> origin/main` 을 돌렸더니
**8/21·8/20 것까지 전부 「main 에 없음」** 으로 나왔습니다. 그대로 믿었으면
「지난 2주 작업이 통째로 안 나갔다」는 **완전히 틀린 보고**를 할 뻔했습니다.

이 저장소는 병합할 때 **squash** 를 쓰는 경우가 있어 커밋 해시가 바뀝니다.
그래서 판정을 **내용 대조**로 바꿨습니다 — 그 커밋이 추가한 줄을 뽑아
`git show origin/main:<파일>` 에 실제로 있는지 한 줄씩 세는 스크립트를 썼습니다.

- 8/21·8/20 커밋들: 추가줄의 대부분(대개 100%)이 main 에 존재 → **반영됨**
- 8/28 커밋들: `496c53c` 는 238줄 중 **13줄**, `1ea2d77` 은 **0줄** → **미반영**
- 요일 체크박스(`ff2b190`)처럼 **그 뒤 더 개선된 형태**로 들어간 것도 있었습니다
  (그래서 「일치율이 낮다 = 안 들어갔다」로 바로 단정하지 말고 해당 부분을 눈으로 봐야 합니다).

## 4. 검토했다가 버린 방법

- **내 지정 브랜치로 merge 해서 거기서 PR 내기** — 처음엔 이러려고 했으나
  `git merge` 가 이 세션의 권한 분류기에 막혔습니다. 그리고 **굳이 할 이유가 없었습니다** —
  기존 브랜치는 main 보다 2커밋 뒤였을 뿐 충돌이 없어, 그 브랜치로 PR 을 내면 그만입니다.
  (같은 내용을 다른 브랜치로 한 벌 더 만들면 나중에 「어느 쪽이 정본인가」가 생깁니다.)
- **브랜치에 main 을 병합해 최신화** — 남의 브랜치에 푸시하는 일이라 하지 않았습니다.
  GitHub 이 충돌 없음으로 판정했고 CI 도 초록이라 필요도 없었습니다.
- **로컬 `ci-gates.sh` 로 판정** — 이 컨테이너에는 `cloudflare-deploy/node_modules` 가 없어
  tsc·esbuild 의존 하니스가 **환경 사유로** 실패합니다(코드 판정이 아님, CLAUDE.md 2장).
  그래서 **CI 결과를 판정 근거로 삼았습니다.** `npm ci` 를 돌리는 것도 검토했지만
  이 컨테이너는 Node 22 라 CLAUDE.md 가 적어 둔 ERESOLVE 를 그대로 밟습니다.
- **코드를 다시 검토해 고치기** — 하지 않았습니다. 8/28 세션이 이미 trap-check 로
  보안문제 2건을 잡아 수리했고, 오늘 제가 diff 를 읽어 확인한 범위에서 관문(`/api/pay/*` 접두)·
  강사 차단 가드·`.tc-act` 버튼 CSS 선례까지 이미 지켜져 있었습니다. **지시 범위(확인·마무리)를
  넘는 수정은 하지 않았습니다.**
