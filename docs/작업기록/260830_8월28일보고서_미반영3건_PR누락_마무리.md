## 1. 왜 했나

사장님이 **8/28 업무보고서 PDF** 를 주시며 「이거 다 되었는 지 확인하고 만약 안되었으면 작업해줘」.

그 PDF 는 누적본이라 **8/28(3건) · 8/21(5건) · 8/20~8/19(여러 건)** 이 한 파일에 들어 있었습니다.
즉 확인해야 할 것은 3건이 아니라 **25건**이었습니다.

## 2. 🪤 이번에 밟은 함정 — 커밋 해시로 «반영됐나» 를 판정하면 안 된다

보고서에 적힌 커밋 해시로 `git merge-base --is-ancestor <해시> origin/main` 을 돌렸더니
**8/21·8/20 것까지 전부 「main 에 없음」** 으로 나왔습니다.

그대로 믿었으면 **「지난 2주 작업이 통째로 안 나갔다」는 완전히 틀린 보고**를 할 뻔했습니다.
사장님이 그 보고를 받으면 이미 잘 돌고 있는 기능들을 다시 «적용» 하러 가십니다.

**원인**: 이 저장소는 병합할 때 커밋을 하나로 합치는 방식(**squash**)을 쓰는 경우가 있습니다.
그러면 원래 커밋 해시는 **어디에도 존재하지 않게** 됩니다. 보고서에 적힌 「PR #341(병합됨)」
같은 건까지 「main 에 없음」으로 나온 것이 그 증거였습니다.

**대신 쓴 방법** — 그 커밋이 **추가한 줄이 main 에 실제로 있는가**를 파일별로 셌습니다.

```bash
# 커밋이 추가한 줄(주석·빈 줄 제외)을 뽑아 main 쪽 같은 파일에 있는지 센다
git show $c -- "$f" | grep '^+' | grep -v '^+++' | sed 's/^+//' \
  | while read -r line; do grep -qF -- "$line" <(git show origin/main:"$f") && echo hit; done
```

실측 결과가 깨끗하게 갈렸습니다.

| 커밋 | 추가줄이 main 에 있는 비율 | 판정 |
|---|---|---|
| `496c53c` (대체강사) | **13 / 238** | 미반영 |
| `1ea2d77` (test 도메인 배너) | **0 / 3** + 새 파일 자체가 없음 | 미반영 |
| `19a6501` (피드백 버튼) | **3 / 9** | 미반영 |
| `f23125e` (8/21 학당 드롭다운) | 24 / 24 | 반영됨 |
| `c02ccc0` (8/19 대리점 계정) | 62 / 64 | 반영됨 |
| `7017fb1` (8/19 · 보고서엔 «병합됨») | 139 / 144 | 반영됨 |

⚠️ **낮은 일치율을 곧바로 「안 들어갔다」로 읽지 마세요** — 요일 체크박스(`ff2b190`)는 1/5 였는데,
main 에는 **그 뒤 더 개선된 형태**(체크박스가 글자 «위», 여백 정리)로 들어가 있었습니다.
숫자로 후보를 좁히고 **그 부분은 눈으로 확인**해야 합니다.

> ✅ **다음에도 이렇게 하세요.** 보고서·문서에 적힌 해시로 「했나 안 했나」를 판정하지 마세요.
> squash 한 번이면 그 해시는 사라집니다. **코드가 main 에 있는가**로 보세요.
> (같은 뿌리: CLAUDE.md 2장 「문서에 「고쳤다」고 적혀 있는데 같은 사고가 또 남」 — 그쪽은
> «적어 둔 것 ≠ 사실», 이쪽은 «해시가 없는 것 ≠ 안 한 것» 입니다. 둘 다 **지금 코드를 보라**로 끝납니다.)

## 4. 검토했다가 버린 방법

- **내 지정 브랜치로 옮겨서 PR 내기** — 하지 않았습니다. 기존 브랜치가 main 을 전부 포함하고
  있어(`0 6`) 충돌이 없었고, 같은 내용이 두 브랜치에 생기면 「어느 쪽이 정본인가」가 남습니다.
  (같은 날 다른 세션은 그 반대로 지정 브랜치로 옮겨 갔는데, 그쪽은 **거기서 코드를 더 고쳤기**
  때문에 그게 맞습니다 — 목적이 다르면 답도 다릅니다.)
- **브랜치에 main 을 병합해 최신화** — 남의 브랜치에 푸시하는 일이라 하지 않았습니다.
- **로컬 `ci-gates.sh` 로 판정** — 이 컨테이너에는 `cloudflare-deploy/node_modules` 가 없어
  tsc·esbuild 의존 하니스가 **환경 사유로** 실패합니다(코드 판정이 아님). **CI 결과로 판정**했습니다.
  `npm ci` 도 검토했지만 이 컨테이너는 Node 22 라 CLAUDE.md 가 적어 둔 ERESOLVE 를 그대로 밟습니다.
