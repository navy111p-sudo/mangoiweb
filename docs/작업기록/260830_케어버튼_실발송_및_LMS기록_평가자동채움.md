## 1. 왜 했나

### 1-1. 「보냈습니다」라고 하는데 아무 데도 안 갔음 (이탈 위험 케어 버튼)

보고서 항목을 확인하러 이탈 위험 카드를 훑다가 발견했습니다.

관리자 › 이탈 관리 › 위험 학생 카드의 **[💬 카톡]·[📱 문자]** 버튼은
`POST /api/admin/retention/care` 를 부르는데, 그 핸들러는
`retention_care_log` 에 **줄 하나만 남기고 `status='queued'`** 로 응답했습니다.

**그 큐를 읽어 실제로 보내는 코드가 저장소에 한 곳도 없습니다.**
(`grep -rn "retention_care_log" src/` = INSERT·SELECT 뿐, 발송 없음)

그런데 화면(`js/adm-q1.js`)은 `if (!d.ok) throw` 만 보고
**「✅ 발송됨」** 을 띄웠습니다. `ok` 는 「요청이 접수됐다」는 뜻이지
「학부모 폰에 도착했다」가 아닙니다.

⟹ 몇 달 동안 **아무 데도 안 가는 버튼이 「보냈다」고 말하고 있었습니다.**
매니저가 그걸 보고 「케어했다」고 판단하면 그 학생은 아무 연락도 못 받은 채
「연락 완료」로 처리됩니다.

### 1-2. 강사 평가 5개 축을 사람이 매번 손으로 채움

관리자 › 강사 평가 모달의 5개 축(수업력·행정·유지·시간엄수·기여)을
전부 손으로 입력합니다. 그런데 그중 **둘은 이미 시스템에 기록이 있습니다** —
학생 별점(`class_ratings`)과 수업일지 작성률(`student_evaluations`).

## 2. 무엇을 했나

### 2-1. 케어 버튼 — 실제로 보냅니다 (`src/api-admin.ts`)

`POST /api/admin/retention/care` 가 solapi(`sendPlainSms`)로 **진짜 보냅니다.**

| 결과 | `status` | 화면 |
|---|---|---|
| 실제 발송됨 | `sent` | ✅ 초록 |
| 테스트 모드(키 없음) | `mock` | ℹ️ 노랑 |
| 통화는 사람이 하고 기록만 | `logged` | ℹ️ 노랑 |
| 번호 없음·본문 없음·발송 실패 | `failed` | ❌ 빨강 |

**화면 판정을 `ok` 가 아니라 `status` 로 바꿨습니다**(`js/adm-q1.js`).
`ok:true` 는 「서버가 요청을 처리했다」까지만 뜻하므로,
`ok` 로 성공을 판정하면 똑같은 거짓말이 다시 시작됩니다.

⚠️ **[카톡] 버튼도 문자(LMS)로 나갑니다.** 알림톡은 사전 승인 템플릿만
보낼 수 있어서 매니저가 그 자리에서 쓴 자유 문구는 구조적으로 못 실립니다.
화면이 그 사실을 그대로 적습니다 — 「카톡 자유문구는 알림톡으로 못 보내 문자(LMS)로 보냈습니다」.

⛔ **일괄(bulk) 카톡·문자는 막았습니다.** 발송이 진짜가 된 순간
「전체 선택 → 문자」 한 번이 되돌릴 수 없는 대량 학부모 발송이 됩니다.
한 명씩만 보냅니다(`arrBulkAction` 에서 거절).

📵 **전화번호는 기록·화면에 통째로 안 남깁니다**(`maskPhoneForLog` — 뒤 4자리만).
케어 기록은 관리자 여럿이 봅니다.

### 2-1-2. 같은 거짓말이 두 갈래 더 있었습니다

- **[🎪 이벤트 초대]** — 기록만 남기는데 `status='sent'` 였습니다. 이 큐를 읽어
  보내는 코드도 저장소에 없습니다 → `queued` 로 바꾸고 「안내는 아직 자동으로
  나가지 않습니다」를 적습니다.
- **[🚀 컴백 번들]** — 확인창이 「500P + **무료 보강 1회** + **학부모 카톡 안내**」를
  약속했지만 **실제로 일어나는 것은 500P 적립뿐**입니다(보강 예약도, 카톡도 코드가 없습니다).
  → 이름을 **「컴백 500P」** 로 바꾸고 확인창이 사실만 말하게 했습니다.
  ⛔ 여기에 문자 발송을 붙이지 않았습니다 — 이 액션에는 **일괄 버튼이 있어서**
  붙이는 순간 학부모 전원 대량 발송이 됩니다.
- 일괄 처리의 성공 판정도 `d.ok` → `d.ok && d.status !== 'failed'` 로 바꿨습니다.

### 2-2. 「🤖 LMS 기록으로 채우기」 (`GET /api/admin/payroll/auto-evaluate`)

강사 평가 모달에 버튼 하나. **제안만 하고 저장은 사람이 합니다.**

| 축 | 근거 | 표본 부족(<3)이면 |
|---|---|---|
| 수업력 | `class_ratings` 학생 별점 평균 | 안 채움 |
| 행정 | `student_evaluations` 수업일지 작성률(`student_uid IS NOT NULL`) | 안 채움 |
| 유지·시간엄수·기여 | **못 잽니다** | `unmeasured[]` 에 이유를 적어 화면에 표시 |

⛔ **못 재는 축을 그럴듯한 숫자로 채우지 않습니다** — 그 값이 급여로 갑니다.
화면에 「무엇을 근거로 얼마를 넣었는지」와 「왜 나머지는 못 채웠는지」를 함께 그립니다.

⛔ 강사는 403(`getAdminActor().isTeacher`) — 자기 평가를 못 봅니다.

### 2-3. 급여 CSV 에 `evaluated` 칸 추가

평가가 있으면 1, 없으면 0. **미평가를 「0점」으로 쓰지 않습니다** —
「아직 평가 안 함」과 「0점을 받음」은 다른 사실이고, 이 값은 인센티브 근거입니다.

## 3. 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| **문구만 「접수됨」으로 고치기** | 사장님 선택은 「실제로 보내기」였습니다. 문구만 고치면 버튼이 영영 아무것도 안 하는 상태로 굳습니다 |
| **큐를 두고 cron 이 비우게** | cron 은 «기본» 워커에만 있고(`[env.production.triggers] crons = []`), 발송이 최대 15분 늦습니다. 케어 문자는 매니저가 «지금» 보내는 것입니다 |
| **[카톡] 을 알림톡으로 보내기** | 자유 문구는 승인 템플릿이 없어 못 나갑니다. 「카톡이라고 적고 문자로 나간다」를 숨기는 것보다 화면에 적는 쪽이 맞습니다 |
| **`#594` 의 장기결석 퀵케어도 같이 고치기** | 그쪽은 `sms:`·`tel:`·카톡채널 **링크** 방식이라 거짓말하지 않습니다(폰 앱이 열립니다). 건드리면 되던 것을 깰 뿐입니다 |
| **평가 5개 축을 전부 자동으로** | 유지·시간엄수·기여는 원료 데이터가 없습니다. 넣으면 전원이 같은 값으로 몰리고 그 숫자가 급여가 됩니다 |
| **`calcPayrollOne` 에 5번째 인자 추가**(중복 SELECT 제거) | 🔴 **밟았다가 되돌렸습니다.** `payroll_minutes_source_harness` 가 그 함수를 소스에서 오려 내 **고정 4인자로 재작성해 실행**하므로, 5번째 인자는 «선언되지 않은 이름» 이 되고 그것을 읽는 줄이 `try/catch` 안이라 **ReferenceError 가 조용히 삼켜집니다** → 카페24 «분(minutes)» 갈래가 통째로 안 돌아 급여가 20분 기준으로 계산(3,000₱ 차이). 타입체크는 통과합니다. 성능보다 급여가 큽니다 |
