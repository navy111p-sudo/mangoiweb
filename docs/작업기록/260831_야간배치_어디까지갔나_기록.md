## 4. 한 것

**신설 `src/nightly-run.ts`** — 기존 `metaSet`/`metaGet`(corpcard-sync)에 기록합니다.

- `nightly:<cron>:run` — 이번 판의 시작 시각·마지막 단계·완료 여부

## 5. 밟은 함정 (이번에 새로 배운 것)

### ① 🔴 표시 16개가 전부 `catch` 블록 «안» 에 들어갔는데 하니스는 초록불이었습니다

배선 스크립트가 `try` 의 짝 `}` 를 찾을 때 **글자 단위로 «처음 깊이가 0이 되는 순간»** 에 멈췄습니다. 그 지점이 바로 `} catch (err) {` 줄이라, 표시가 **catch 본문 첫 줄**로 들어갔습니다.

결과가 그냥 «안 남는 것» 이 아니라 **뜻이 뒤집힙니다**:
- 정상적인 밤에는 catch 로 안 들어가므로 **기록이 한 줄도 안 남습니다.**
- 남은 기록의 뜻이 「그 작업이 끝났다」가 아니라 **「그 작업이 에러를 던졌다」** 입니다.
- `steps[].ms` 는 «앞 단계 합을 뺀 값» 이라, 처음 실패한 작업 하나가 그때까지의 **전체 경과시간을 뒤집어씁니다** → 「오래 걸린 작업」이 «에러 난 작업» 을 가리킵니다. 순서를 바꿀 근거로 쓰려던 숫자가 거짓이 됩니다.

**하니스는 `try` 개수와 표시 개수만 비교**해서 16 == 16 으로 통과했습니다. **trap-check 가 잡았습니다.**
→ catch 블록을 중괄호 짝으로 잘라 **그 안에 표시가 없는지**를 봅니다.

### ② 그 «catch 안인가» 검사도 처음엔 헛돌았습니다

`} catch (err) {` 줄부터 통째로 브레이스를 세면 **그 줄 안에서 다시 0** 이 되어 본문을 한 줄도 안 보고 멈춥니다. 표시를 실제로 catch 안으로 옮겨 놓고도 15/15 초록불이었습니다.
→ **catch 의 여는 중괄호부터** 셉니다. 그리고 가짜 회귀로 **실제 FAIL 이 나는지** 확인했습니다.

### ③ 「쓰기가 try 안인가」는 문자열로 잴 수 없습니다

브레이스를 세는 것으로는 **객체 리터럴의 `{` 와 블록의 `{`** 를 가를 수 없어 멀쩡한 코드 두 줄이 거짓 양성으로 나왔습니다(`try { await metaSet(…); }` 한 줄짜리, `JSON.stringify({` 로 끝나는 줄).
→ 그 계약은 **«전부 던지는 DB» 를 넣어 실제로 돌려** 확인합니다(세 함수 모두 던지지 않아야 함).

### ④ 부정 검사는 주석을 벗긴 사본으로

`!/CREATE TABLE/` 를 원본에 걸면, 누가 「⛔ CREATE TABLE 을 새로 쓰지 말 것」이라고 **주석을 쓰는 순간 거짓 FAIL** 입니다. 이 저장소가 이미 여러 번 밟은 함정입니다.
