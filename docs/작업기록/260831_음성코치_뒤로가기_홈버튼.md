# AI 음성 코칭 화면 — 뒤로가기 화살표 + 홈 버튼 (2026-08-31)

## 1. 왜 했나

사장님이 `mangoi.ai/speech-coach.html` 화면 사진과 함께 **「뒤로가기 화살표와 홈버튼
만들어줘」**.

먼저 확인한 사실:

- **뒤로가기 화살표(←)는 이미 있었습니다** — `js/back-nav.js` 가 왼쪽 위에 넣습니다
  (사진의 왼쪽 위 동그란 ←). 그래서 실제로 없던 것은 **홈 버튼 하나**입니다.
- 홈 버튼은 **2026-08-04 에 사장님 지시로 «일부러» 뺀 것**이었습니다. 그때 근거는
  「← 로 나가면 바로 앞이 곧 홈이라 같은 일을 하는 버튼이 둘이 된다」였고, 그 결정이
  세 곳에 적혀 있었습니다 — `<meta name="mangoi-no-global-bar">`(공용 [🏠][🌐] 바 끄기),
  마크업 자리의 주석, 파일 맨 아래 `.home-btn{display:none}`.
- 그 뒤 이 화면으로 들어오는 길이 늘었습니다(수업 화면·게임 허브·카톡 링크). ← 한 번이
  홈이 아닌 경우가 흔해졌고, 앱(APK)·카톡 인앱은 **주소창도 뒤로 버튼도 없습니다.**
  ⟹ 2026-08-31 사장님 지시로 **되살립니다**(CLAUDE.md 1-3 「되살리면 안 되는 것」에
  해당하지만, 그 항목을 만든 사람이 직접 되살리라고 한 경우입니다 — 근거를 코드 주석과
  이 기록에 함께 남깁니다).

## 2. 무엇을 했나

`cloudflare-deploy/public/speech-coach.html` **한 파일**만 고쳤습니다(js·css 파일 무접촉
⟹ `?v=` 원장 무관, 공동 금지구역 0줄).

- 왼쪽 위 ← **오른쪽에** `<a id="sc-home-btn" href="/">🏠 홈</a>` 을 붙였습니다.
  모양(남색 알약·앰버 글자·같은 테두리)을 back-nav.js 의 ← 와 같게 맞췄습니다 — 나란히
  놓이는 두 버튼이 서로 다르게 생기면 하나는 «다른 기능» 으로 읽힙니다.
- 자리는 **스크립트가 ← 를 재서** 붙입니다(top·left·height). 좌우 클러스터가 차지한
  실제 폭도 재서 CSS 변수로 넘겨, 제목이 그만큼 비켜서고 남은 폭에 맞게 줄어듭니다.
- 역할 분담은 2026-08-03 사장님 지시 그대로입니다 — **← 는 직전 페이지**(back-nav.js 의
  `history.back()`), **🏠 는 처음 화면(/)**. 바뀐 것은 🏠 의 «자리» 뿐입니다.

## 3. 검토했다가 버린 방법

| 버린 방법 | 왜 버렸나 |
|---|---|
| `<meta name="mangoi-no-global-bar">` 한 줄만 지워 공용 [🏠 홈][🌐 EN] 바를 되살리기 (주석이 「되살리려면 이 meta 한 줄만 지우면 된다」고 안내) | 그 바는 **우상단 고정(z-index 99999)** 인데, 그 자리는 **2026-08-31 에 ☰(AI 친구 고르기, `right:12px`)** 가 차지했습니다. 겹칩니다 |
| 홈 버튼을 우상단 ☰ 왼쪽에 두기 | 폰(390px)에서 제목 글자가 x 328 까지 오고 그 자리가 x 286~328 이라 **글자 위에 얹힙니다** |
| 옛 `.home-btn`(우상단 노란 알약) 클래스를 그대로 재사용 | 파일 맨 아래 `.home-btn{display:none}` 안전망에 걸려 **넣었는데 안 보이는** 상태가 됩니다. 그 규칙은 그대로 두고 새 id 를 씁니다 |
| ← 와 🏠 를 우리 마크업으로 **둘 다** 새로 만들기 | 「뒤로」 판정(`history.length` + 같은 오리진 referrer + 폴백)을 복제해야 합니다. 그 판정의 정본은 back-nav.js 이고, 복제하면 한쪽만 고쳐지는 사고가 시작됩니다 |
| ← 옆 예약 폭(`.brand{padding-left}`)을 46 → 107px 같은 **숫자로** 올리기 | back-nav.js 는 자기 좌표·크기를 `innerWidth<=480` 으로 가르는데 이 화면 CSS 의 모바일 기준은 640px 입니다. 숫자를 복사하면 480~640px 구간에서 어긋나고, 그쪽 값이 바뀌면 여기도 조용히 깨집니다 |
| 제목을 두 줄로 흘려보내기 | 이 화면의 대전제가 «폰에서 스크롤 없이 한 화면» 입니다(작은 폰에서 녹음 버튼이 화면 밖으로 밀립니다) |
| 버튼을 제목 위 별도 줄(sticky nav)로 내리기 | 세로를 40px 넘게 먹습니다. 2026-08-04 주석이 같은 이유로 이미 거절한 방법입니다 |
| 홈을 아이콘(🏠)만 두고 설명은 `title` 로 | 폰에는 hover 가 없어 아무것도 안 보입니다(CLAUDE.md 함정). 그래서 「홈」 글자를 함께 그립니다 |
| 아이콘 버튼처럼 `data-ko`/`data-en` 없이 두기 | 이 버튼은 **글자가 있으므로** 그 둘이 맞습니다(엔진이 `textContent` 를 갈아끼우므로 이모지를 값 안에 함께 넣었습니다). ☰ 처럼 아이콘 전용 버튼에는 쓰면 안 됩니다 |

## 4. 밟은 함정 (둘 다 브라우저 실측으로만 드러났습니다)

1. **왼쪽만 비우면 오른쪽에서 겹칩니다.** 제목이 가운데정렬이라 왼쪽 예약폭이 커진
   만큼 오른쪽으로 밀려, ☰ 가 제목 글자 위에 얹혔습니다(390·430px 실측). ⟹ **양쪽**을
   재서 비웁니다.
2. **`100vw` 는 세로 스크롤바 폭까지 포함합니다.** 제목 크기를 `calc((100vw - …)/11.4)`
   로 맞췄더니 320px 창에서 계산은 13.4px(≈147px)인데 제목 상자는 **138px** 이라 두 줄로
   쪼개졌습니다. ⟹ 스크립트가 잰 **실제 폭**(`clientWidth` 기준)을 `--sc-logo-avail` 로
   넘겨 씁니다.

⛔ 상주 `MutationObserver`·`setInterval` 은 쓰지 않았습니다(홈 화면을 통째로 멎게 한
전례 — 2026-08-27). 처음 세 번(0·420·900ms)과 `resize` 때만 잽니다. back-nav.js 가
`DOMContentLoaded + 350ms` 에 ← 를 넣기 때문에 그 뒤에 재야 합니다.
