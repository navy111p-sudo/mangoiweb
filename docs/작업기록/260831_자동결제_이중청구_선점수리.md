# 2026-08-31 — 자동결제 이중청구 구조 차단 (청구 전 «선점»)

## 왜 했나

8/28 크론 점검에서 남긴 목록의 **1순위**였다. 자동결제를 켜는 순간
**카드가 두 번 긁히는 구조**라, 켜기 전에 반드시 손봐야 했다.

## 무엇이 잘못돼 있었나

`chargeSubscriptionOnce` 는 «주문을 새로 만들고 → 토스에 청구» 한다.
주문번호가 매번 새로 생성되므로 **토스는 두 요청을 서로 다른 주문으로 보고 카드를 두 번 긁는다.**
그런데 이 함수를 지나는 경로가 **넷**이다.

| 경로 | 위치 |
|---|---|
| cron 자동연장 스윕 | `runAutoRenewChargeSweep` |
| 관리자 「지금 청구」 | `api-admin.ts` |
| 학부모 「즉시 결제」 | `/api/pay/billing/charge-now` |
| 관리자 스윕 수동실행 | `api-admin.ts` |

**아무 선점도 없었다.** charge-now 에 60초 가드가 있었지만 «읽고 나서 쓰는» 방식이라
동시에 들어온 두 요청은 둘 다 통과한다.

> ⚠️ 크론 중복 실행은 PR #584 로 없앴지만, 그것은 «동시에 두 번 불리는 한 가지 이유» 를
> 없앤 것이지 **함수를 멱등하게 만든 것이 아니다.** 둘을 같은 것으로 보면 안 된다.

## 측정이 방향을 정했다

D1 을 **SELECT 로만** 재서 `subscriptions` 50행·active 45·**`billing_key` 0건**·due 0건임을
확인했다. 즉 **아직 아무도 청구된 적이 없다.**
→ 긴급 장애가 아니라 «켜기 전에 막아야 할 잠복» 으로 판단했고, 그래서 라이브 결제 흐름을
건드릴 걱정 없이 구조를 바꿀 수 있었다.

## 수리 — 스윕이 아니라 «함수 자체» 에

네 경로를 모두 덮으려면 스윕이 아니라 함수에 넣어야 한다.

- `subscriptions` 에 `charge_lock_at` 을 **멱등 ALTER 로만** 추가(CREATE 는 안 건드림 — `schema_drift`)
- 청구 전 조건부 UPDATE 로 선점. D1(SQLite)이 쓰기를 직렬화하므로 동시 요청 중
  **정확히 하나만** `changes=1` 이 된다. 진 쪽은 청구하지 않는다.
- 리스 10분 — 워커가 청구 도중 죽어도 스스로 풀린다.
- **실패 쪽으로 닫는다** — 선점 자체가 실패하면 청구하지 않는다.
- 해제는 `finally` 로 항상, 그리고 **내가 잡은 표식일 때만.**

## 검토했다가 버린 방법

- **스윕에만 선점 넣기** — 네 경로 중 하나만 막힌다. 관리자 수동과 cron 이 겹치는 것이
  정확히 문제였는데 그걸 못 막는다.
- **`next_billing_at` 을 미리 밀어 선점** — 그 칸은 «다음 청구일» 이라는 뜻이 있고 실패
  경로가 그 값을 다시 쓴다. 잠금과 의미를 겹치면 실패 처리와 서로 덮어쓴다.
- **주문번호를 결정론적으로(토스 멱등키)** — 2차 방어로는 옳지만, 주문번호 생성이 일반
  수강신청과 공용이라 반경이 크다. 그리고 카드 거절 뒤 «정당한 재시도» 를 막을 수 있다.
- **`last_billed_at` 60초 가드를 늘리기** — 읽고 나서 쓰는 방식이라 동시성에 무력하다.

## 🔴 trap-check 가 잡은 것

1. **학부모 화면이 «진행 중» 을 「결제에 실패했어요」라고 말하고 있었다.**
   더블클릭이면 두 요청이 60초 가드를 나란히 통과한 뒤 하나만 선점하는데, 진 쪽이
   「실패」라고 듣고 **다시 누르면 60초 뒤엔 진짜 두 번째 청구**다.
   이중청구를 막으려 넣은 장치가 **사람을 통해 이중청구로 되돌아오는** 모양이었다
   → 409 + 「결제를 이미 처리하고 있어요」로 갈랐다.
2. 해제가 소유권을 확인하지 않아, 리스 만료로 남이 정당하게 가져간 표식을 지우면
   세 번째가 들어오는 경로 → `AND charge_lock_at = ?` 추가.
3. 스윕 요약이 «건너뜀» 을 `failed` 로 세던 것 → `skipped` 분리.
4. 해제 실패를 무음으로 삼키던 것 → `console.warn`.
5. 하니스가 검사 범위를 «길이» 로 자르던 것 → 중괄호 짝(등재된 함정).

### 오탐도 하나 있었다 — 되돌리지 않았다
「DDL 이 메모된다」는 주석이 거짓이라는 지적이 있었지만, `ensureSubscriptionsSchema`
**안**이 아니라 `src/index.ts` 의 fetch·scheduled 양쪽 진입부가 `env.DB` 를
`wrapDbDdlOnce` 로 감싸고 있었다(`src/db-ddl-once.ts`). 주석은 사실이었다.
→ 되돌리는 대신 **근거 위치를 주석에 적어** 다음 사람이 한 번에 확인하게 했다.
⚠️ 검사 결과를 그대로 따르지 말고 **한 번 더 확인**해야 하는 이유의 사례다.
