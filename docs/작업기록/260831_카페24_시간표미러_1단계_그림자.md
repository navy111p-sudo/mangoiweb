  **전부 `status='cancelled'`** 이었습니다(26건 `user_id='lms'` 옛 LMS 자리표시,
  7건 `type_seed` 시연 시드).

그리고 **Janice 만의 문제가 아니었습니다.** 재직 강사 29명 중 `class_schedules` 에
살아 있는 행이 있는 강사는 **7명뿐**이고, 카페24에서 실제로 수업 중인데 망고아이
시간표가 빈 강사가 **17명**이었습니다.

⚠️ 처음에 저는 그 7명을 **「이관 완료」로 잘못 적었습니다.** 사장님이 「그건 파일럿

`source='adm-enroll:78~85'` 이고 생성 시각이 **8/27~9/1** 입니다. 즉 최근에 손으로
넣은 파일럿 수업이지 카페24 이관분이 아닙니다.

이어서 사장님이 진짜 목표를 말씀하셨습니다.

> 파일럿이 끝나면 카페24에서 실시간으로 도는 수업을 mangoi.ai 로 덮어씌우고 싶다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### ⛔ 「아침 6시에 한 번 덮어쓰기」 (사장님 최초 안)

버렸습니다. 실측상 **9월 수업이 하루 2~25건뿐**인데 실제 수업은 하루 140건쯤입니다.
카페24 예약이 **며칠 전~당일에 채워진다**는 뜻이라, 6시에 한 번만 돌면 그 뒤에 잡힌
수업은 그날 못 넘어옵니다.
→ **15분마다 «오늘~모레» 좁은 창** + 밤 3시 «±두 달» 넓은 창으로 설계했습니다.

🔴 **덤으로, 6시 cron 은 애초에 만들 수 없습니다** — Cloudflare 계정 cron 한도가 5개인데
`wrangler.toml` 이 이미 5개를 다 쓰고 있습니다. 기존 15분 감시견과 밤 동기화에 얹는 것이
유일한 길이자 더 나은 설계였습니다.

### ⛔ 카페24로 되쓰기(양방향 동기화)

만들지 않았습니다. 사고 반경이 너무 큽니다. **한 방향(카페24 → 망고아이)만** 합니다.

### ⛔ 1단계부터 바로 쓰기

「전환일에 급하게 하지 않으려면」이 요구의 핵심이므로, **위험 0인 그림자 단계**를
먼저 뒀습니다. 매일 성적표만 내고 아무것도 안 만듭니다. 며칠 돌려 보면 전환일에 무슨
일이 날지 미리 보입니다.

### ⛔ 화이트리스트를 코드에 박기

사장님이 「스케줄이 바뀌거나 새 참여자가 들어오면 다른 강사가 할 가능성이 높다」고
하셔서, **표(`c24_mirror_teachers`)로** 뒀습니다. 배포 없이 화면에서 켜고 끕니다.
모드는 `off` / `whitelist` / `all` 셋이고 기본값은 가장 안전한 `off` 입니다.

### ⛔ 도장(수동 수정 표시)을 자동으로 떼기

「카페24가 정본이되 **사람 손이 이긴다**」가 사장님 결정입니다. 그런데 이 규칙의 뒷면은
**「한 번 손대면 그 수업은 영영 카페24를 안 따라간다」** 입니다. 그렇다고 시스템이
자동으로 도장을 떼면 사람이 일부러 고친 것을 되돌리는 셈이라 더 나쁩니다.
→ **어긋남 목록(`diverged`)** 으로 매일 보여 주고, **되돌리기는 사람이** 누릅니다.

### ⛔ `loadCafe24TeacherMap()` 을 api-admin.ts 에서 import

같은 판정이 거기 이미 있지만 import 하면 **순환 참조**가 생깁니다
(`api-admin` → `accounting-reports` → `c24-mirror` → `api-admin`).
→ `enroll-ops.ts` 가 쓰는 방식대로 **판정을 복제하고, 두 함수가 같은 답을 내는지
하니스가 실제로 돌려서 대조**합니다(F절 — api-admin 의 함수를 오려 내 실행).

### ⛔ 새 API 를 `/api/admin/c24-mirror` 로

`src/index.ts`(공동 금지구역)의 게이트 3곳을 고쳐야 합니다.
→ **`/api/admin/reports/` 밑**에 뒀습니다. 그 접두사는 인증·라우팅·강사차단에 이미
등록돼 있어 금지구역을 **한 줄도** 안 건드렸습니다.

### ⛔ 강사 번호를 숫자로 잇기

카페24 강사번호(9~196) ≠ 원부 `teachers.id`(1~30)이고 겹치는 자리에서 **다른 사람**입니다.
→ `teacher_payroll_auto`(번호와 이름을 함께 받은 유일한 표)로 **이름을 거쳐** 잇고,
정규화 후 **유일하게 맞을 때만** 채웁니다. 애매하면 비워 두고 리포트에 남깁니다.
