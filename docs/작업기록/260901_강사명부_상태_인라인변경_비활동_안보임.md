# 강사 명부 — 상태를 그 자리에서 바꾸기 (활동중 · 비활동 · 안보임)

- **날짜** 2026-09-01
- **지시** 사장님 — 「강사가 퇴사해서 활동하지 않는 경우, 강사 명부에 들어가서 비활동으로 바꾸는 기능.
  안보임이 아니라 비활동으로. 즉 **활동, 비활동, 그리고 안보임.**」
- **고른 안** 세 가지 설계안 중 **A안(인라인 상태 드롭다운)**

---

## 1. 왜 했나 — 그리고 «이미 있던 것»

먼저 운영 D1 을 직접 셌습니다(추측이 아니라 실측).

```sql
SELECT COALESCE(status,'(NULL)') st, COUNT(*) FROM teacher_profiles GROUP BY st;
-- 활동중 32 · 퇴사 1 · 비활동 0   (전체 33행, 퇴사일이 적힌 강사 0명)
```

**상태 세 값은 원래도 있었습니다.** 수정 모달 드롭다운·필터·배지 색·`PATCH /api/admin/teacher-profiles/:id`
까지 전부. 그런데 「비활동」이 한 번도 안 쓰인 이유는 **바꾸는 길이 멀어서**였습니다 —
✏️ 수정 → 모달 열기 → 스크롤 → 드롭다운 → 저장.

그 결과 **명부에서 사람을 빼는 실제 수단이 🗑 «영구 삭제» 뿐**이었습니다
(`DELETE FROM teacher_profiles`, 화면 문구도 「되돌릴 수 없습니다」).

⟹ 이번 작업의 값어치는 «상태 세 개를 만드는 것» 이 아니라
**«영구 삭제 말고 다른 길을 손닿는 곳에 두는 것»** 입니다.

## 2. 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| **「안보임」을 status 의 네 번째 값으로 넣기** | 사장님 말씀 그대로 옮기면 이게 제일 쉽습니다. 그런데 한 축으로 합치면 ①«퇴사했지만 이번 달 정산이 남아 명부에 남길 사람» ②«활동중인데 감추고 싶은 행» 을 동시에 못 적습니다. ②는 가정이 아닙니다 — 명부에 「테스트강사」·「파라테스트」가 **활동중으로 섞여 34명에 포함**돼 있었습니다. 그래서 status(3값) × `list_hidden`(0/1) **두 축**으로 갈랐고, 화면에서는 사장님이 원하신 대로 «활동 / 비활동 / 안보임» 으로 보입니다. |
| **B안 — 퇴사 처리 마법사** (퇴사일·사유·남은 수업 정리) | 사고 예방으로는 제일 좋지만 4~6일짜리이고, 여러 명을 훑어 정리하기엔 무겁습니다. 사장님이 A안을 고르셨습니다. **「남은 예약 수업 N건」을 먼저 보여 주는 부분은 여전히 필요합니다 — 2단계 과제로 남깁니다.** |
| **C안 — 체크박스 일괄 처리** | 34명 첫 대청소에는 압도적이지만, 체크박스 열이 늘면 휴대폰 카드 배치(`order`/`grid-column`)를 다시 짜야 합니다(이 저장소가 실제로 밟은 함정). 첫 정리 뒤에는 거의 안 쓰입니다. |
| **🗑 영구 삭제 버튼을 좁히기 / 없애기** | 지우는 방향의 변경이라 사람이 정할 일입니다(CLAUDE.md 4-1-1). **손대지 않았습니다.** 다만 비활동·안보임이 생겼으니 「수업 기록 0건일 때만」으로 좁히는 것을 권합니다 — 별건. |
| **서버 8곳의 `status='활동중' OR status IS NULL` 을 정본 함수로 리팩터** | 그 조건은 비활동·퇴사를 **이미** 제외하므로 동작이 옳습니다. 급여·배정이 걸린 자리를 이번 PR 에서 함께 흔들 이유가 없어, 새 코드만 정본을 보게 했습니다. |
| **글자색 페인터 3종을 «전부» 손보기** | 배지만 예외 등재했습니다. 페인터 자체의 판정 규칙은 안 건드립니다. |

## 3. 무엇을 만들었나

### 서버
- **`src/teacher-status.ts` (신규, 판정 정본)** — 허용 상태 3종, `canonTeacherStatus`(옛 별칭 「재직」→활동중),
  `isTeacherStatus`, `isActiveTeacherStatus`, `toTeacherListHidden`, `teacherVisibleSql`.
- `teacher_profiles.list_hidden` **지연 ALTER**(멱등, try/catch). 배포 직후 SQL 에
  `no such column: list_hidden` 이 나오는 것은 배포 실패가 아닙니다 — 첫 목록 조회가 돌면 생깁니다.
- `GET /api/admin/teacher-profiles` — 기본은 **보이는 행만**, `?hidden=1` 은 숨긴 행만, `?include_hidden=1` 은 전부.
- `PATCH …/:id` — **모르는 상태값을 400(`bad_status`)으로 거절**합니다. 전에는 어떤 문자열이든
  그대로 들어가서, 오타 하나가 저장되면 그 강사가 배정·급여·순위 어디에도 안 잡혔습니다.
- **대량 임포트(구글시트 붙여넣기)도 같은 문을 지납니다** — `UPD_COLS` 에 `status` 가 있어
  시트에 적힌 문자열이 그대로 들어가고 있었습니다. 지금은 모르는 값이면 **그 칸만 빼고**
  나머지는 넣고, **뺐다는 사실을 화면에 돌려줍니다**(조용히 넣지도, 조용히 버리지도 않음).
- 상태·숨김 변경은 `admin_audit_logs` 에 `teacher_status_change` 로 before/after 를 남깁니다(try/catch).

### 화면
- 명부 **상태 배지를 누르면** 그 자리에 메뉴(활동중·비활동·퇴사 + 🙈 명부에서 숨기기).
- 고르면 즉시 PATCH → **5초 되돌리기 토스트**. 되돌리기도 서버로 나갑니다.
- 상태만 바뀌면 **칸만 다시 칠합니다**(표를 다시 그리면 조준한 버튼이 움직입니다).
  숨김은 목록 소속이 바뀌므로 다시 읽습니다(안 그러면 「N명」이 거짓말).
- 필터에 「🙈 안보임」 추가 — 값은 `__hidden__` 이고 **`?hidden=1`** 로 나갑니다(status 로 안 보냄).

## 4. 브라우저로 잡은 것 — 문자열 하니스가 전부 초록이던 5건

`--fast` 246건이 통과하는 상태에서, 실제 Chromium 으로 재서 **다섯 가지**를 찾았습니다.

1. **메뉴가 열리자마자 사라짐.** 버튼을 누르면 포커스가 가며 브라우저가 스스로 스크롤하고,
   그 `scroll` 이 여는 클릭 직후 도착해 «닫기» 로 읽혔습니다.
   → 스크롤에 **닫지 말고 따라가게**(`_tpStFollow`). 버튼이 화면 밖으로 나가면 그때만 닫습니다.
2. **배지가 세 줄로 쪼개짐** — 좁은 상태 칸에서 「🚪 퇴사」가 «🚪 / 퇴 / 사» 로.
   실측 배지 높이 48px → `white-space:nowrap` 뒤 24px.
3. **`background:#fee2e2` 인라인이 통째로 무시돼 배경이 투명**(computed `rgba(0,0,0,0)`).
   `admin-inline-c.css` 의 옛 다크 규칙이 `!important` 로 덮습니다.
   → **`background-color:`** 로 쓰면 어느 선택자에도 안 걸립니다(CLAUDE.md 2장에 이미 적혀 있던 함정).
4. **글자색을 인라인 `!important` 로 덮는 페인터가 «셋»** 이었습니다
   (`adm-s12`(darken) · `adm-s13`(fixTextOnDark) · `adm-light-surfaces`).
   그대로 두면 퇴사 배지가 **연분홍 위 흰 글자(대비 2.2)** 가 됐습니다.
   CSS 로는 못 이깁니다(인라인 !important) → **세 곳 모두**에 `.tp-st-badge` 를 등재.
   수리 뒤 대비 **활동중 16.16 · 퇴사 14.53**.
5. `body{zoom:1.3}` 좌표 — `getBoundingClientRect()` 는 배율이 곱해진 화면 좌표인데
   body 안의 `position:fixed` 는 zoom «안쪽» 좌표계라, **나누지 않으면 메뉴가 밀립니다**.

> ⚠️ 다섯 건 모두 **함수도 값도 다 «있고»** 틀린 것은 「몇 px 인가·무슨 색인가·누가 맨 위인가」뿐입니다.
> 문자열 하니스로는 구조적으로 못 잡습니다.

## 6. 남은 일 / 확인 필요

- 🔴 **「퇴사한 강사에게 파란색 불이 나타난다」** — 강사 명부 코드에서 파란 표시를 **찾지 못했습니다.**
  명부 배지는 초록·노랑·빨강이고 「지금」 칸은 🟢·🟡·⚪ 입니다. 강사 스케줄 캘린더의
  **파란 점선 카드**(카페24 겹쳐 그리기)일 가능성이 있으나 **이건 짐작이지 확인한 사실이 아닙니다.**
  화면 이름이나 스크린샷을 받으면 그 자리도 함께 봐야 합니다.
- **B안 2단계** — 상태를 퇴사로 바꿀 때 **그 강사에게 남은 예약 수업 N건**을 먼저 보여 주기.
  지금은 안 보여 줍니다. 학생이 빈 방에서 기다리는 사고를 막는 부분이라 별건으로 남깁니다.
- **로그인 차단은 별개입니다** — `teacher_profiles.status` 를 퇴사로 바꿔도 그 계정은 그대로
  로그인됩니다(계정 정본은 `admin_account`). 화면이 아직 이걸 말해 주지 않습니다.
- **`teacher_profiles` CREATE 문이 두 벌**입니다(`api-admin.ts` 1946행 7칸 · `ensureTeacherProfilesSchema` 27칸).
  둘 다 `IF NOT EXISTS` 라 먼저 도는 쪽이 이깁니다. 지금 문제는 없지만 새 칸을 더할 때 조심.
- **퇴사일(`leave_date`)이 33명 전원 비어 있습니다.** A안은 퇴사일을 안 받습니다(B안의 몫).

### 「안보임」이 미치는 범위 (일부러 정한 것)

`GET /api/admin/teacher-profiles` 를 부르는 곳은 넷이고, **넷 다 «누구를 고를까/보여줄까»** 라
숨긴 강사가 빠지는 것이 맞습니다 — 강사 명부(`adm-core`) · 레벨테스트 배정 후보(`_ltLoadTeachers`) ·
`adm-p5` 강사 목록 · 학생 홈 강사 소개의 **폴백**(`idx-grid-menu.js`).

⚠️ **학생 페이지의 «주» 경로(`GET /api/teacher-profiles`, `api-mango.ts`)는 안 건드렸습니다.**
그쪽은 `status='활동중'` 으로만 거릅니다. 즉 지금 규칙은 **「관리자 화면에서 안 보임」** 이고,
학생에게도 감추려면 그 API 에 조건을 한 줄 더해야 합니다 — **일부러 안 했습니다**:
「명부 정리하려고 숨겼는데 학생 사이트에서도 사라졌다」가 더 놀라운 일이라서입니다.
사장님이 원하시면 한 줄이면 됩니다(그때 `list_hidden` 지연 ALTER 가 그 경로에도 필요합니다).
