## 3. 검토했다가 버린 방법

- **「한 방에 `host` 가 두 종류면 알린다」** — 오늘 원인을 5초 만에 찾아 준 조회지만,
  **감시 장치로는 못 씁니다.** 도메인을 합친 지금은 host 가 섞여도 정상(같은 워커라 만납니다)이라
  멀쩡한 상태에 문자가 갑니다. 알림이 무뎌지면 정작 진짜 사고 때 무시됩니다.
- **`BUILD_STAMP` 등 vars 로 워커를 구분** — `[vars]` 와 `[env.production.vars]` 에 **같은 값**이라
  구분자가 못 됩니다. 구분자를 새로 만들려면 `wrangler.toml`(공동 금지구역)에 값을 더해야 합니다.
- **컨테이너에서 두 도메인을 직접 찔러 비교** — 프록시가 `mangoi.ai`·`test.mangoi.co.kr` ·
  `*.workers.dev` 를 전부 403 으로 막습니다(CLAUDE.md 4-1-1). 사람이 대시보드를 봐야 합니다.
- **`routes` 를 `wrangler.toml` 에 못 박기** — ⛔ 그 목록은 «전체 목록» 이라 적지 않은 도메인이
  다음 배포에 지워집니다(= `mangoi.ai` 가 내려갑니다). 이미 CLAUDE.md 2장이 금지하고 있습니다.

## 4. 택한 방법 — 원인 그 자체를 잰다

`idFromName()` 은 **네임스페이스마다 다른 값**을 돌려줍니다. 방이 갈리는 이유가 바로 그것이므로,
그 지문이 도메인마다 다르면 **그 두 도메인의 방은 반드시 갈려 있습니다.** 대리지표가 아닙니다.

정본: `cloudflare-deploy/src/room-split-guard.ts`

1. 수업 입장(`POST /api/attendance/join`)에서 그 요청을 **받은 워커**가 자기 지문을 계산해
   KV `roomns:<host>` 에 적습니다. 네트워크 호출 0회(순수 계산), 값이 그대로면 쓰지 않습니다.
2. 15분 감시견(`runSiteWatchdog`)이 도메인들의 지문을 대조해 갈렸으면 사장님께 **문자 1회**.
   문자에 갈린 두 도메인과 옮길 워커 이름을 함께 담습니다.

`src/index.ts`(공동 금지구역)는 **한 줄도 건드리지 않았습니다** — 감시견 본체가
`api-uptime.ts` 이고 이미 매 cron 마다 불리고 있어서 그 안에 얹었습니다.

### 조심한 것

- **모르는 Host 는 기록하지 않습니다.** Host 헤더는 호출자가 마음대로 보냅니다 → `SITE_HOSTS` 화이트리스트.
- **절대 던지지 않습니다.** 감시 장치가 던지면 출석 기록과 감시견이 함께 멈춥니다.
  ⚠️ 첫 판에서 `kv.get(k).catch(...)` 를 썼는데 **KV 가 «동기적으로» 던지면 `.catch` 에 닿지도
  못합니다.** 하니스 ④절이 «전부 던지는 가짜 KV» 로 이 구멍을 실제로 잡아냈습니다 →
  `kvGet`/`kvPut`/`kvDel`/`smsSafe` 헬퍼로 전부 감쌌습니다.
- **14일 지난 기록은 버립니다.** 옛 값으로 계속 문자하면 안 됩니다.
- 오래돼 판단을 못 하게 된 것을 **«복구됐다» 고 말하지 않습니다**(거짓말이 됩니다). 침묵하되
  «알림 보냄» 표시만 지워, 나중에 진짜로 갈리면 다시 알립니다.
- 같은 상태가 이어지면 **문자는 1회**(15분마다 스팸하지 않습니다).
