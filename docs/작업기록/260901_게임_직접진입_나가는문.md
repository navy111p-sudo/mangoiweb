# 게임 주소 직접 진입 — 나가는 문 (2026-09-01)

## 1. 왜 했나

같은 날 「나가는 문」 전수 점검에서 남긴 마지막 항목입니다. 학생 게임 16개는
게임 허브(`student-games.html`)가 **iframe** 으로 감싸 열고, 나가는 문은 허브 좌상단의
「← 게임 선택」이 맡습니다. 그런데 **게임 주소로 직접** 열면(북마크·카톡 링크·관리자
사이트 구성표) 그 문이 없습니다 — 화면은 멀쩡히 돌아가는데 나갈 길만 없습니다.

사장님 「게임 주소 직접 진입도 막아줘」.

## 2. 「막다」를 두 가지로 읽을 수 있어 먼저 물었습니다

| 방법 | 대가 |
|---|---|
| **허브로 리다이렉트**(하드 차단) | 🔴 `admin/site-structure-map.html`·`site-structure-more.html` 이 게임 16개를 **`href` 로 직접 열도록** 링크해 두었습니다. 되돌려보내면 그 관리자 도구가 깨집니다. 게다가 «허브 안인가» 판정이 한 번이라도 틀리면 **수업 중 학생이 게임에서 튕겨나갑니다** |
| **나갈 문을 준다** | 허브 안(정상 경로)에서는 아무 변화가 없고, 직접 열었을 때만 문이 생깁니다 |

⟹ 사장님 선택: **「나갈 문을 준다」**.

## 3. 무엇을 했나

**⛔ 판정을 16벌 복제하지 않았습니다.** 정본은 새 파일 하나
`public/js/game-standalone-exit.js` 이고, 게임 16개는 그것을 **한 줄로** 싣습니다.

- 허브 안(`window.top !== window.self`)이면 **아무것도 하지 않습니다.** 크로스오리진이라
  접근이 던지면 그것도 «남의 프레임 안» 이므로 역시 아무것도 하지 않습니다.
- 이미 나가는 문이 **보이는** 게임은 건드리지 않습니다(`shooter`·`battle-3d`·`p38-3d` 는
  자기 ← 가 있고 단독 실행일 때 게임 목록으로 가도록 이미 짜여 있습니다).
  ⚠️ `back-nav.js` 를 여기서 싣지 않습니다 — 실으면 그쪽이 「보이는 ← 가 없다」고 판단해
  자기 동그란 ← 를 넣어 **문이 둘**이 됩니다.
- 버튼은 **동그란 ← 하나(34px)**, `href="/student-games.html"` 이라 JS 가 죽어도 동작합니다.
- ⛔ 상주 `MutationObserver`·`setInterval` 을 쓰지 않습니다(홈을 통째로 멎게 한 전례).
  처음 두 번만 봅니다.

## 5. 🔴 내 검사가 «거짓 통과» 했습니다 — 요소 상자로 재면 두 방향으로 다 틀립니다

④까지 하고 「13/13 통과」라고 적었는데, 그 검사가 **`elementFromPoint` 로 요소 «상자» 를
찍는** 방식이었습니다. 그게 두 방향으로 다 틀립니다.

**① 덮지도 않았는데 «덮었다» 로 읽습니다.** `space-monster` 의 문제 문장은 상자가
`x=12..378`(폭 전체)인데 **실제 글자는 가운데 `x=137..253`** 에만 있습니다. 버튼은
`x=10..44` 라 글자를 한 자도 안 덮는데, 상자로 재면 «덮었다» 가 됩니다.
그리고 하필 제 판정 함수가 그 상자의 조상 중 `DIV#game`(폭 전체)을 **«시작 오버레이»로
잘못 분류**해서 「시작화면 장식이니 괜찮다」로 통과시켰습니다 — **틀린 이유로 맞는 답**을
낸 것이라 더 나쁩니다.

**② 반대로, 오른쪽에 있는 글자를 통째로 놓칩니다.** 옛 `avoidOverlap` 은 상자의
**왼쪽 한 줄(x+6)만 3점** 찍었습니다. 그래서 판정을 글자 자리로 바꿔 다시 재니
**5개 게임이 실제로 글자를 덮고 있었습니다**:

| 게임 | 덮고 있던 것 |
|---|---|
| `escape-school`·`escape-voice`·`escape-zombie` | 「성공 0」(진행 점수 — 시작화면이 아니라 **지속 HUD**) |
| `grammar-pizza` | 제목 「🍕 망고아이 문법 피자 마스터」 |
| `wordfighter` | 제목 「🧟 워드 파이터」·「점수」·「0」 |

✅ 그래서 판정을 바꿨습니다 — **글자는 텍스트 노드마다 `Range.getClientRects()`** 로
실제 글자 자리를 재고, **누를 수 있는 것은 상자 그대로**(상자가 곧 탭 표적) 셉니다.
비켜서기도 3점 찍기가 아니라 그 자로 재서 **가장 아래까지 한 번에** 내려가고, 내려간 자리에
또 무언가 있을 수 있어 **최대 5번** 되풀이합니다.

🔴 **덤 — 상한 숫자를 «대충» 정했다가 가장 나쁜 상태를 만들었습니다.** 처음 상한이 120px
이었는데 `grammar-pizza` 는 왼쪽 위를 **y=132 까지** 씁니다(제목·난이도 바·「🏷️ 성분 ON」·
「💡 힌트!」). 그래서 상한에 걸려 **포기하고 「🏷️ 성분 ON」 버튼을 덮은 채 멈췄습니다** —
글자를 덮는 것보다 **누를 수 있는 것을 덮는 것이 최악**인데 거기로 떨어진 것입니다.
✅ 실측해 **160px**(844px 화면의 19% = 아직 위쪽)로 정하고, 그 근거를 소스 주석에 적었습니다.
그러니 `grammar-pizza` 만 폰에서 y=140 입니다.

⚠️ **이 종류는 문자열 하니스로 절대 안 보입니다** — 함수도 값도 다 «있고» 틀린 것은
«몇 px 이고 무엇을 덮는가» 뿐입니다. 그래서 이 작업의 검사를 저장소에 남겼습니다:
**`test-harness/manual/game-standalone-exit-browser.mjs`**(브라우저 45종 —
**자동으로 안 돕니다, 사람이 부릅니다**).
그 파일의 자와 정본(`blockedBottom`)은 **같은 규칙**이라 한쪽만 고치면 검사가 헛돕니다.

## 6. 🔴 내가 만든 결함 하나 — 주석에 태그 이름을 적어 하니스 2개를 깼습니다

`escape_school_mic`·`escape_zombie_mic` 하니스는 **«body 닫기 직전의 인라인 코드»** 를
정규식으로 오려 내 가짜 브라우저에서 돌립니다. 두 번 걸렸습니다.

1. 처음엔 내 태그를 **`</body>` 직전**에 넣어, 그 정규식이 요구하는 «인라인 코드가 마지막»
   구조가 깨졌습니다 → `SyntaxError: Unexpected token '<'`.
   ✅ 태그를 **마지막 인라인 코드 «앞»** 으로 옮겼습니다(defer 라 실행 시점은 그대로).
2. 그런데도 깨졌습니다 — 내가 넣은 **주석 안에 그 태그 이름을 꺾쇠째로** 적어서, 정규식이
   **주석에서부터** 잘랐습니다 → `SyntaxError: Invalid or unexpected token`.
   ✅ 주석에서는 꺾쇠를 빼고 «script 태그» 로 풀어 썼습니다.

📜 이 저장소에 이미 있는 함정의 형제입니다 — 「부정 검사에 걸릴 이름을 주석에 적지 마세요」·
「주석 안에 route glob 을 그대로 적지 마세요」. **하니스가 잡아 준 것이고, 브라우저 검사만
돌렸다면 놓쳤습니다.**
