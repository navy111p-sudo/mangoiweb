## 1. 왜 했나

사장님이 **표 머리글 캡처 한 장**(방 · 교사 · 시작 · 시간 · 크기 · 참가자 · 상태 ·
시선 점수 · 말하기 점수 · 총 참여도 · 스토리지 · 재생)을 주시며 「이거 필터를 만들어줘」.

그 표는 **관리자 › 🎥 녹화 관리 › 🎬 영상 목록**(`#recordings-table`)입니다.

거기에는 이미 **서버 검색**(`#rec-search-bar` — 방·교사 글자, 날짜 구간, 상태, 쪽 크기)과
**출처 알약**(`.rec-filter` — 전체 / ✅ 정상 / ⚠️ 영상 없음 / ⚠️ 기록 없음)이 있었습니다.
그런데 **화면에 그려져 있는데 손댈 수 없는 칸이 그대로 남아 있었습니다** —
시간 · 크기 · 참가자 · 시선 점수 · 말하기 점수 · 총 참여도. 정렬도 한 칸도 없었습니다.

그래서 「참여도 낮은 수업만 보자」·「길게 찍힌 것부터 보자」·「저장이 안 된 것만 보자」를
**눈으로 훑어야** 했습니다. 한 쪽이 기본 50건이라 훑는 것 자체가 일이었습니다.

### `cloudflare-deploy/public/js/adm-core.js`

`_recBlobTruncated` 선언 바로 아래에 한 덩어리로 모았습니다.

- `_recColF` · `_recSort` — 상태 (`dir`: 1=▲ / −1=▼ / 0=원래 순서)
- **`_recPartScore(r)`** — 총 참여도 계산 **정본**. 시선·말하기 평균, 한쪽만 있으면 그쪽, 둘 다 없으면 `null`
- `_recUserCount(r)` — `participant_names` 는 JSON 문자열, 고아 blob 은 «모름»(`null`)
- `_recPassColF(r)` — 한 줄 통과 판정
- `_recSortVal(r,key)` / `_recApplySort(rows)` — 정렬
- `_recSyncSortHead()` — `data-ar` 속성 갱신
- `window.recSortBy(key)` — ▲ → ▼ → 원래 순서
- `renderRecordingsTable()` — `viewRows = _recApplySort(filtered.filter(_recPassColF))` 로 갈아끼우고, 카운트·빈 표 문구 추가
- `bindRecColFilter()` IIFE — 컨트롤 바인딩 + 🌐 언어 전환 재렌더
- 세 곳(`loadRecordings` 꼬리 · `vcRecordingsToolsOpen` · `vcRecordingsShow`)에 `#rec-colfilter` 표시 배선

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### ⛔ 서버(`/api/recordings`)에 필터 파라미터를 더하기

가장 «제대로» 인 길이고, 전체 29,000건에서 걸러 줍니다. 하지만 버렸습니다.

- 참여도·시선·말하기는 **D1 컬럼이 아니라 `attendance` 를 집계해 붙이는 값**이라
  SQL `WHERE` 로 못 거릅니다. 서버를 고치려면 집계 구조부터 손대야 합니다.
- 「필터를 만들어줘」에 **API 변경 + 서버 배포 반경**은 과합니다.
- ⇒ 화면에서 «이 쪽» 만 거르고, **그 범위를 화면이 직접 말하게** 했습니다.
  전체를 좁히려면 위쪽 서버 검색을 쓰면 됩니다(두 줄이 역할을 나눠 가집니다).

### ⛔ 「이 쪽 N건 중 M건」을 안 보여주기 (화면이 깔끔해집니다)

**절대 안 됩니다.** 이 필터는 «지금 불러온 쪽»(기본 50건) 안에서만 돕니다.
숫자를 감추면 「전체에서 걸렀다」로 읽혀 **없는 결론을 내리게** 됩니다
(예: 「참여도 80 이상이 3건뿐이네」 — 실제로는 이 쪽에서만 3건).

### ⛔ 빈 표에 「녹화 기록 없음」 그대로 두기

«없다» 와 «걸러서 안 보인다» 는 **다른 사실**입니다. 필터를 켜 둔 것을 잊으면
「녹화가 없다」로 읽습니다. 그래서 「표 안 필터에 맞는 녹화가 없습니다 (이 쪽에 N건 있음)」
로 갈랐습니다. 📜 이 표가 2026-08-28 에 「업로드 대기」 한 문구로 성격이 다른 1,312건을
뭉뚱그려 사고를 냈던 바로 그 자리입니다.

### ⛔ 카운트 배지(`#rec-counts`)를 필터에 맞춰 다시 세기

그 줄은 「총 N건 · ✅ 정상 · 🔴 저장 실패 · ⚠️ 영상 없음 …」을 말하는 자리이고
**«이 쪽에 무엇이 있나»** 가 본분입니다. 필터로 흔들리면 그 정보가 사라집니다.
그래서 **거르기 전 `rows` 를 세는 그대로** 두고, 필터 결과는 `#recf-count` 라는
**별도 자리**에 적었습니다.

### ⛔ 머리글 안에 `<span>` 을 넣어 ▲▼ 그리기

이 표의 `<th>` 는 `data-ko`/`data-en` 을 달고 있고, i18n 엔진은 그 요소의
**`textContent` 를 통째로 갈아끼웁니다** → 🌐 를 누르는 순간 자식 span 이 사라집니다
(CLAUDE.md 2장 「JS 로 그린 라벨」·「아이콘 버튼에 data-ko 를 달았더니」).

⇒ 화살표를 **`data-ar` 속성 + CSS `::after { content: attr(data-ar) }`** 로 그렸습니다.
가상요소는 `textContent` 와 무관해서 살아남습니다.
브라우저 검사에서 EN 전환 뒤에도 ▲ 가 남아 있는 것을 실제로 확인했습니다.

### ⛔ 총 참여도 계산을 그리는 쪽에 그대로 두고 정렬용으로 하나 더 만들기

같은 판정이 두 곳이면 **한쪽만 고쳐집니다**(이 저장소가 반복해 밟은 형태).
그러면 「그린 숫자와 정렬 순서가 다르다」가 됩니다.
⇒ 기존 `calcParticipation`(map 안 지역 함수)을 지우고 **`_recPartScore` 하나**로 모았습니다.

### ⛔ 점수 없는 행(—)을 그냥 0으로 취급해 정렬

내림순에서 맨 뒤로 가는 건 맞지만, **올림순에서 맨 위를 통째로 덮습니다.**
⇒ `null` 은 **방향과 무관하게 항상 뒤**로 보냅니다.

### ⛔ 정렬을 «올림 ↔ 내림» 2단으로만

되돌릴 길이 없어집니다(서버가 준 최신순이 이 표의 기본값이고, 그게 대개 맞습니다).
⇒ **▲ → ▼ → 원래 순서** 3단(`c24fin` 회계 표의 선례와 같은 방식).
원본 배열은 `slice()` 사본으로만 정렬합니다 — 제자리에서 뒤집으면 못 돌아옵니다.

### ⛔ 필터·정렬 컨트롤을 `<td>`/`<th>` 안에 넣기 (엑셀식)

`admin-inline-c.css` 의 전역 `!important`(`[id^="card-"] select{padding:8px 12px}` 등)가
인라인 style 을 이겨 **칸을 밀어냅니다**(CLAUDE.md 2장 「표 안의 작은 아이콘 버튼」·「`<select>` 판」).
⇒ 표 **밖 한 줄**로 뺐습니다. 기존 `#rec-search-bar` 와 같은 모양이라 규칙 충돌도 없습니다.

### ⛔ `#recf-reset` 이 필터만 지우게 하기

정렬이 남아 「왜 순서가 이상하지」가 됩니다. ⇒ **둘 다** 지웁니다.

### ⚠️ 색은 `background-color:` 로만, 글자색에는 `!important`

`background:#f…` 는 `admin-inline-c.css` 의 옛 다크 규칙이 `!important` 로 덮고,
카드 안 글자는 `#101828 !important` 로 통째로 덮입니다(CLAUDE.md 2장).
