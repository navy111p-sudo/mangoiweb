# 소셜 로그인이 «화면만 로그인» 이던 것 + 그 페이지의 토큰 탈취 구멍 (2026-09-01)

## 1. 무엇이 잘못돼 있었나

이 저장소의 학생 로그인은 **두 벌이 짝**입니다.

| 키 | 쓰임 |
|---|---|
| `mangoi_logged_user` | 화면이 «누가 로그인했나» 를 그림 |
| `mango_token` | 서버가 «정말 본인인가» 를 가림 |

그런데 OAuth 콜백(`/api/oauth/:provider/callback`)은 **앞의 것만** 저장하고 토큰을 안 줬습니다. 헤더에는 로그인한 것처럼 보이는데, 본인 확인이 필요한 API(포인트·단어장·판단력·동의 등)가 전부 «남» 으로 판정합니다 — CLAUDE.md 2장 「로그인했는데 또 로그인하래요」와 같은 뿌리입니다.

⚠️ 2026-09-01 에 그 API 들의 소유자 게이트를 조였으므로(PR #581) 앞으로 더 아프게 드러납니다.

## 2. 잰 것 / 거기서 내린 판단

**잰 것**
- 라이브 `/api/oauth/status` → kakao·naver·google **전부 false**(클라이언트 ID 미등록). `/api/oauth/kakao/url` 은 503 `not_configured`.
- D1 에 `oauth_users` 표가 **아직 없음**.
- `students_erp` 의 social 접두 계정 **52개**(google 30·kakao 22)는 전부 **카페24 센티넬**(`created_at = 1751500000000`) → **이 경로가 만든 것이 아님**.

**판단(측정 아님)**: 지금 이 경로를 밟는 사람은 없고, **클라이언트 ID 를 등록하는 순간** 터지는 자리입니다. 등록 전에 막아 둡니다.

## 3. 🔴 고치다가 «더 나쁜 것» 을 만들 뻔했습니다

토큰을 발급해 응답 HTML 에 실었는데, **그 페이지에 이스케이프 안 된 자리가 둘**이었습니다.

```
<p …>${name}님 환영합니다!</p>     ← 안 막힘.  <script> «위» 라 파싱 중 먼저 돈다
<script> const u = ${userPayload}   ← 처음에 여기만 막았다
```

`name` 은 **프로바이더가 준 값**입니다. 거기에 스크립트 종료 태그를 넣으면 같은 오리진에서 코드가 돌고, 제가 방금 그 페이지에 올려 둔 `localStorage.mango_token` 을 그대로 읽어 갑니다.

**즉 «토큰이 없어서 안 되던 것» 을 고치면서 «토큰이 털리는 길» 을 열 뻔했습니다.** trap-check 가 잡았습니다.

> sink 가 둘이면 한 곳만 막는 것은 «안 막은 것» 입니다.

## 4. 한 것

- **토큰 발급** — `/api/student/login` 과 **같은 방식**(`startSession` + `signUidToken`, 인자·TTL 동일). 발급이 실패해도 로그인을 깨뜨리지 않습니다(try/catch). 토큰이 없으면 **옛 토큰을 지웁니다**(남의 토큰이 남는 쪽이 더 나쁩니다).
- **HTML 로 들어가는 값 전부 이스케이프** — `esc()` 헬퍼로 `&`·`<`·`>`·`"`·`'`. payload 쪽은 JSON 을 살려야 하므로 `<` 치환.
- **캐시 금지** — 본문에 30일짜리 토큰이 있습니다. 지금 CF 기본값은 `/api/` 를 캐시하지 않지만, 누가 「Cache Everything」을 걸면 **한 사람 토큰이 다른 사람에게** 나갑니다. `private, no-store, max-age=0`.
- **에러 페이지** — 그 문자열도 프로바이더 응답에서 옵니다(`no_access_token` 에 응답 본문이 붙습니다). 큰따옴표만 지우던 것을 안전한 문자만 남기도록 좁히고, 자세한 사유는 로그로 보냅니다. `charset` 도 붙였습니다.

**신설 `test-harness/oauth_token_harness.mjs`**(18건) — payload 식을 소스에서 오려 내 **실제로 평가**하고, 콜백 블록 전체에서 «프로바이더가 준 값이 그대로 꽂히는 자리» 를 셉니다.

## 5. 제가 밟은 것 / 하니스가 무르던 것

- **백슬래시 한 겹.** `'<'` 는 JS 가 `<` 로 해석해 **무의미한 치환**입니다. `'\\u003c'` 여야 합니다. 문자열 검사였으면 못 봤을 텐데, 식을 **실제로 평가**하는 검사라 잡혔습니다.
- **하니스가 payload 한 곳만 보고 「탈출 차단」이라 말했습니다** — 읽는 사람은 «이 페이지는 안전하다» 로 읽습니다. 콜백 블록 전체를 훑도록 고쳤습니다.
- **캐시 검사가 「파일 어딘가에 no-store 가 있나」였습니다** — 에러 경로에도 그 헤더가 있어서, **토큰이 실린 성공 응답**에서 빼도 초록불이었습니다(실측). 그 응답 하나를 콕 집도록 고쳤습니다.
- **`provider` 를 «못 믿는 값» 목록에서 뺐습니다** — 라우트 정규식이 `kakao|naver|google` 로 못 박기 때문입니다. 다만 **그 근거를 검사로 함께** 남겼습니다(정규식이 느슨해지면 FAIL).

## 7. 남은 것 / 사람이 볼 것

- 🔴 **OAuth `state` 를 콜백이 검증하지 않습니다**(기존 코드). `/url` 에서 만들어 내려보내지만 콜백에 `searchParams.get('state')` 가 없습니다. 이 변경으로 콜백이 «진짜 자격증명 발급 지점» 이 됐으므로 로그인 CSRF 반경이 커졌습니다 — 사람 판단이 필요합니다.
- **`SINGLE_SESSION='on'`** 이라 소셜 로그인도 다른 기기 토큰을 끊습니다. `/api/student/login` 과 **같은 방식**이라 일관되지만, 소셜은 폰·PC 를 오가는 경우가 많아 「방금 로그인했는데 PC 가 튕겼다」 제보가 나올 수 있습니다.
- **소셜로 만든 학생은 `status='신규'`** 인데, 활성 학생 판정(`'정상','활동','active'` 또는 빈 값)에 **어디에도 안 들어갑니다** — KPI·명부·ARPU 분모·이탈 카운트 전부에서 «아무 데도 없는 학생» 이 됩니다(기존 코드, 이 변경 아님).
- 야간 동기화는 **안 지웁니다**(센티넬이 아니라 `Date.now()`). 다만 같은 `user_id` 가 카페24에서 오면 `INSERT OR REPLACE` 로 덮여 그다음 밤부터 삭제 대상이 됩니다.
- 담당: `src/api-students.ts` 는 4-2 표에 없습니다.
