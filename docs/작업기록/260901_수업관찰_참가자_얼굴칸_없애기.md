## 2. 무엇을 바꿨나

### 뿌리 — 서버가 참관자의 이름을 «지어내고» 있었습니다

참관은 **«투명 유령»** 설계입니다. `handleJoinObserve`(`src/video-call-room.ts`)가
`joined:false` 로 붙이고 **방송을 하나도 하지 않아** 인원수·입퇴장·로스터
(`existing-users`·`user-joined`) 어디에도 안 나옵니다.

그런데 참관자는 영상을 받으려고 **recvonly offer 를 직접 보냅니다.**
그 offer 를 중계하던 한 줄이 이랬습니다:

```ts
fromUsername: this.usernameOf(userId) || '참가자'
```

`usernameOf()` 는 **`att.joined` 인 사람만** 이름을 돌려줍니다 →
참관자는 **언제나 `null`** → **언제나 `'참가자'`**.

받는 화면(`js/idx-main.js` `vcHandleOffer:5360`)이 그 이름으로 피어를 만들고,
그 이름이 그대로 얼굴 칸 이름표가 됩니다(`vcEnsureParticipantBox:5469` 의 `escHtml(username || '참가자')`).

⟹ **유령 설계가 «화면에서만» 깨져 있었습니다.**

### 고친 파일

| 파일 | 무엇 |
|---|---|
| `cloudflare-deploy/src/video-call-room.ts` `handleOffer` | 참관자 offer 에 **`fromObserver:true`** 를 싣고, 참관자에게는 **이름을 지어내지 않습니다**(빈 값). 판정은 본문 값이 아니라 **소켓 attachment 의 `role`** |
| `cloudflare-deploy/public/js/vc-observe-guard.js` **⑩절(신설)** | 서버가 참관자라고 말해 준 id 에 대해서만 얼굴 칸을 만드는 **세 경로**(`vcHandleOffer`·`vcEnsureParticipantBox`·`vcAddRemoteVideo`)를 막고, 이미 생긴 칸은 걷어냅니다 |
| `cloudflare-deploy/public/index.html` | `vc-observe-guard.js?v=8` → **`?v=9`** (한 줄) |
| `test-harness/observer_camera_guard_harness.mjs` | **H절 14종** 추가 |
| `CLAUDE.md` 2장 | 함정 한 줄 추가 |

⚠️ **⑩절은 참관자가 아니라 «참관을 당하는 쪽(강사·학생)» 에서 돕니다.**
그래서 같은 파일의 ⑦⑧ 처럼 `?observe=` 로 걸러서는 안 됩니다 — 별도 IIFE 로 뒀습니다.

### 덤

그 칸에는 `📷 연결 중…` 힌트가 남아 있었기 때문에, 고착 워치독(`vcStuckPeerWatch`)이
그것을 «진짜 사람» 으로 보고 **피어당 최대 4회 강제 재연결**을 걸 수 있었습니다
(mesh 라 전원의 업로드가 흔들립니다). 칸이 아예 안 생기므로 그 경로도 함께 사라집니다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### ⛔ 이름이 「참가자」인 칸을 지운다
가장 먼저 떠오르는 방법이고 **가장 위험합니다.**
`'참가자'` 는 «이름을 아직 모를 때» 쓰는 기본값이라, **이름이 안 붙은 진짜 학생 칸**까지 지웁니다.
그래서 판정 근거를 **«서버가 참관자라고 말한 id» 하나**로 좁혔습니다.
하니스 `H⑬` 이 이 경계를 못 박습니다 — 「이름이 「참가자」여도 서버 표시가 없으면 지우지 않는다」.

### ⛔ 참관자 이름을 «관찰자» 같은 다른 값으로 바꾼다
그러면 낯선 이름이 학생·강사 화면에 뜹니다. 참관자는 **이름이 «있으면» 안 됩니다.**
(같은 이유로 `handleObserverWhisper` 도 학생에게 보낼 때 보낸 사람 이름을 안 넘깁니다.)

### ⛔ `vcRemovePeer(id, 'left')` 로 지운다
`public/index.html` 이 `vcRemovePeer` 를 후킹해 **`reason === 'left'` 면 10초 뒤 수업을 종료**합니다.
학생 화면에 「수업이 끝났어요」가 뜹니다(CLAUDE.md 2장). → **DOM 칸만 걷어냅니다.**

### ⛔ 상주 `setInterval` · body class `MutationObserver` 로 감시한다
이 저장소는 같은 뿌리로 **홈이 두 번 멎었습니다**(2026-07-14 · 2026-08-27).
→ offer 를 받은 그 순간부터 **끝이 있는** 확인만 합니다(`[0, 400, 1500, 4000]ms`).

### ⛔ `js/idx-main.js` 를 고친다
그 파일은 **849KB blocking** 이고 첫 화면 예산 여유가 **100바이트대**입니다.
→ `vc-observe-guard.js`(defer, 예산 밖)에서 **window 함수를 감싸는** 기존 방식을 그대로 씁니다.
세 함수 모두 classic script 최상위 `function` 선언이라 `window` 속성이고,
호출부도 같은 바인딩을 보므로 덮으면 호출부가 이 함수를 부릅니다.

### ⛔ 참관 자체를 막는다
`vcHandleOffer` 원본은 **그대로 이어서 부릅니다** — answer 를 보내야 참관자가 영상을 받습니다.
막은 것은 «얼굴 칸» 뿐입니다(하니스 `H⑨`).

## 5. 남은 것 / 주의할 것

### 🔴 배포 화면은 확인하지 못했습니다

작업 컨테이너의 프록시가 `mangoi.ai` 를 막아 **저는 배포된 화면을 못 봅니다.**
제가 확인한 것은 **「배포 워크플로가 성공했다」까지**입니다.

**사람이 수업 관찰을 한 번 걸어 「참가자」 검은 칸이 사라졌는지 봐야 끝난 것입니다.**
확인할 때 **강사 쪽 화면은 새로고침을 한 번** 해야 합니다 — 화면 코드를 `?v=9` 로 올렸기 때문에
이미 열려 있던 창은 옛 파일을 그대로 씁니다.

### ⚠️ 코드만으로는 «타일이 생기는» 경로를 끝까지 못 짚었습니다

설계상 참관자는 트랙을 안 보내므로 `ontrack` 이 안 불리고, 타일은 `ontrack`(`idx-main.js:5313`)
에서만 만들어집니다. 즉 **코드만 읽으면 타일이 안 생겨야 맞습니다.**
그런데 스크린샷에는 있습니다. 그래서 ⑩절은 **«만드는 세 경로를 전부» 막고 이미 생긴 칸도 걷어내는**
방식으로 넓게 잡았습니다 — 제가 못 본 경로가 하나 더 있어도 걸리도록.

**여전히 「참가자」 칸이 보인다면 그 경로가 따로 있는 것입니다.** 그때 확인할 것:
```js
// 강사 화면 콘솔
[...document.querySelectorAll('#vc-video-grid .video-box')].map(b => [b.id, b.querySelector('.video-label')?.textContent])
window.__vcObserverPeers   // 서버가 참관자라고 말해 준 id 목록
```
`__vcObserverPeers` 가 **비어 있는데** 「참가자」 칸이 있으면 → 서버 표시가 안 오는 것(서버 쪽)
`__vcObserverPeers` 에 **id 가 있는데도** 칸이 있으면 → 제가 못 막은 네 번째 경로(화면 쪽)

### ⚠️ 배포 run 이 `cancelled` 여도 배포는 나갔을 수 있습니다

제 run **#2902 는 `cancelled`** 였습니다. 이것은 `deploy.yml` 의 `concurrency` 가
«대기 중» run 만 정리하고 **마지막 run 하나가 최신 main 을 통째로 배포**하는 **정상 동작**입니다.
