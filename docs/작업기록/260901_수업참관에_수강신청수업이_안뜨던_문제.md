## 1. 왜 했나

사장님 제보 — **「최윤서 학생이 지금 수업참관에 뜨지 않아. 이유가 뭐지?」**

먼저 «고장인가» 부터 D1 으로 확인했습니다(2026-09-01 21:52 KST 실측).

| 확인 | 값 |
|---|---|
| 학생 | `cys01` = 최윤서, `students_erp` 에 active |
| 그날 수업 | `class_schedules` **id 1086** · 2026-09-01 **21:20~21:40**(20분) · 강사 **JANE**(원부 6) |
| 만든 경로 | `source='adm-enroll:91'` — **그날 12:11 에 수강신청 확정으로 생성** |
| 방 | `class-1086-20260901` — 강사 `mangoi_114` **21:23 입장**, 학생 **21:41 입장**, 둘 다 접속 중 |
| 카페24 기록 | `attendance` 의 `c24-*` 행 **0건**(전 기간) |

즉 **수업은 정상적으로 돌고 있었고**, 화면이 그 사실을 말하지 못한 것이었습니다.

**뿌리** — 수업참관 화면의 아래 목록 「📅 예약 기준 지금 수업」이 부르는
`GET /api/admin/classes-now` 는 `attendance` 에서 **`room_id LIKE 'c24-%'` 씨앗만**
읽었습니다(`api-admin.ts`). `class_schedules` 는 **한 줄도 안 봤습니다.**
그래서 수강신청 확정으로 만든 망고아이 수업은 카페24에 기록이 없어
**그 목록에 뜰 방법이 구조적으로 없었습니다.**

반경은 최윤서 한 명이 아니었습니다 — 그 시각 돌고 있던 망고아이 수업 **8건이 전부**
빠져 있었습니다(최윤서·김선우·김사랑·이수현·김연숙·박주형·김수희·지승연).
아래 목록에 이름이 쭉 보이던 원재희·오연준·윤설아는 전부 카페24 수업이라,
사장님 눈에는 **「다른 애들은 뜨는데 최윤서만 없다」** 로 보였습니다.

그리고 위쪽 「화상방 접속」 목록은 **사람이 실제로 붙어야** 뜹니다. 그래서
21:20 수업은 강사가 들어온 **21:23 까지 3분간 어느 목록에도 없었습니다** —
정작 그때가 「왜 아직 아무도 안 들어왔지」 하고 봐야 할 시각입니다.

⚠️ 더 나쁜 것은 **같은 시각에 두 화면이 서로 다른 말을 하고 있었다**는 점입니다.
「오늘 수업」(`/api/admin/classes/today`)은 **이미** ①`class_schedules` + ②카페24를
합쳐 보여 주고 있었습니다. 「같은 배정을 두 API 가 서로 다르게 확인」(CLAUDE.md 2장)의
또 하나의 사례입니다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### ⛔ 화면(클라이언트)에서 두 API 를 각자 불러 이어 붙이기
같은 목록을 그리는 화면이 **넷**입니다. 판정이 네 벌로 복제되고, 서버가 주는
`counts` 와도 어긋납니다. 이 저장소는 판정 복제로 이미 여러 번 사고가 났습니다.

### ⛔ `live_room` 에 방 번호를 그냥 채워 버튼을 살리기
버튼은 생깁니다. 그런데 그 칸의 뜻은 **«접속이 확인된 방»** 이라, 화면이
「접속 기록 없음」이라고 쓰면서 동시에 접속했다고 말하는 셈이 됩니다.
그래서 `live_room` 의 뜻은 그대로 두고 **`observable` 을 새로 뒀습니다.**

### ⛔ 참관 버튼을 `live_room` 유무로 가르기 (원래 방식 유지)
그러면 **시작 직전, 아무도 안 붙은 그 순간에 버튼이 사라집니다.**
정작 그때가 「왜 아직 아무도 안 들어왔지」 하고 참관해야 할 시각입니다.
망고아이 방은 `class-{예약id}-{YYYYMMDD}` 로 **결정론적**이라 접속 전에도 존재합니다.

### ⛔ 판정을 `classes-now` 핸들러 안에 그대로 두기
여기서 틀리는 것은 전부 «무슨 답이 나오는가» 입니다 — 요일 표기, 자정 넘김,
미러 중복. **문자열 검사로는 하나도 안 보입니다.** 그래서 순수 함수로 빼서
하니스가 **실제로 돌려** 볼 수 있게 했습니다.

### ⛔ 요일 파서를 `classes-now.ts` 안에 새로 쓰기
운영 `class_schedules.day_of_week` 에는 `'Thu'`·`'목'`·`'1,3,5'`·`'tue'` 가 섞여
있습니다. `Number()` 비교는 NaN 이 되어 **반복수업이 통째로 사라집니다**(2026-08-06
매니저 화면 사고). 정본 `admDowMatches` 를 **인자로 주입**해 두 판정이 갈릴 수 없게 했습니다.

### ⛔ SQL 에서 하루치만 뽑기
「15분 뒤까지 / 끝난 뒤 5분까지」 창이 자정을 넘습니다. 양끝 날짜를 각각 봅니다.

### ⛔ 카페24 미러 수업을 두 줄로 그대로 두기
`c24-mirror` 가 만든 `class_schedules` 행은 카페24 씨앗과 **같은 수업**입니다.
그냥 합치면 한 수업이 두 줄이 됩니다. 망고아이 쪽만 남깁니다(그쪽만 참관할 방이 있음).

### ⛔ `adm-core` 버튼을 인라인 `onclick` + 새 클래스로 만들기
`admin-inline-c.css` 의 `details.menu-card button{…!important}` 가 **파란 알약**
(padding 9px 18px)을 씌워 좁은 칸을 밀어냅니다(CLAUDE.md 2장 「표 안의 작은 아이콘
버튼」). 같은 표의 «화상방» 줄이 이미 쓰는 **위임 + `rm-act`** 방식을 그대로 썼습니다.

### 🔧 하니스 쪽에서 고친 것 — 옛 사실을 «글자 그대로» 못 박아 둔 검사
`observer_camera_guard_harness` 가 「**참관 버튼이 생기지 않습니다**」·「지금은 참관할
수업이 없다는 뜻입니다」를 정규식으로 못 박고 있었습니다. 그때는 이 목록에 카페24
수업만 와서 **사실이었지만** 지금은 수강신청 수업에 버튼이 «있습니다».
⇒ 물어야 할 것을 **«두 갈래를 갈라 말하는가»** 로 바꿨습니다.
(CLAUDE.md 2장 「검사가 옛 숫자·옛 식을 못 박아 두면 보장을 강화한 수리에 FAIL 이 난다」)

⚠️ 그 과정에서 제가 **헛도는 검사를 한 줄 만들었습니다** — `!/…/.test('')`
(빈 문자열을 재고 있어 언제나 통과). 알아채고 「참관 대상을 `live_room` 으로 정하지
않는다」로 바꿨습니다. **검사를 고칠 때는 그 검사가 무엇을 재고 있는지 다시 보세요.**
