## 4. 한 것

**신설 `src/notify-contacts.ts`** — 받는 사람은 서버가 정합니다.
- `resolveNotifyPhones` : 학생 계정(uid)으로 `students_erp` 에서 번호를 찾습니다. **못 찾으면 빈 값**(본문으로 되돌아가지 않습니다).
- `phoneForTeacher` : 원부 강사번호(`teachers.id`)로 **정본 `findTeacherContact` 에 위임**합니다(0순위 수동연결 → 낱말경계 이름일치 → 후보 2명 이상이면 포기).
- `partiesForRoom` : `class-{예약id}-{YYYYMMDD}` 로 예약을 풀어 강사·학생 이름과 번호를 돌려줍니다. 못 풀면 `null`.

**`src/api-notify.ts`** — 본문 전화번호 읽기 **10곳을 전부 제거**. `no-show` 는 강사·학생 이름도 예약에서 풀고, 못 풀 때만 본문 폴백.

**`src/absent-sweep.ts`** — `findTeacherContact` 를 `export` (복제 대신 재사용).

**신설 `test-harness/notify_body_phone_harness.mjs`**(26건) — 해석기를 esbuild 로 컴파일해 가짜 D1 로 **실제로 돌립니다.**

## 5. trap-check 가 잡아 준 것 (전부 반영)

1. 🔴 **「강사 전화번호 칸이 없다」는 제 말이 틀렸습니다.** `teacher_profiles.phone` 이 있고 값도 있습니다(실측 22건 중 21건이 09xx 필리핀 번호). 더 나쁜 건 **제 하니스가 그 거짓을 정규식으로 못 박아** 뒀다는 것입니다(`phoneForTeacher … return '';`) — 나중에 누가 제대로 이으면 오히려 FAIL 이 났을 것입니다. → 정본에 위임하도록 고치고, 검사도 「빈 값을 돌려주는가」가 아니라 「정본에 위임하는가」로 바꿨습니다.
2. **「번호가 적재되면 저절로 나간다」도 틀렸습니다.** 다섯 중 넷은 **호출자가 uid 를 안 보냅니다**(`idx-main.js` 3662·3689·3700·13842행). 주석을 사실대로 고쳤습니다.
3. **「한 번도 발송된 적 없다」** — 측정과 추론을 갈라 적고, `alimtalk_log` 가 증거가 될 수 없다는 이유를 함께 남겼습니다.
4. **대소문자 타이브레이크 누락** — 정본(`api-students.ts`)은 `ORDER BY (user_id = ?) DESC, user_id ASC` 인데 `, user_id ASC` 를 빠뜨렸습니다. `Kim`/`kim`·`Lee`/`lee` 가 실재하므로 번호가 적재되면 엉뚱한 사람에게 갈 자리였습니다.
5. **하니스 A 가 파일 전체를 훑고 있었습니다** — 나중에 정당한 `body.phone` 핸들러가 생기면 거짓 FAIL. 다섯 핸들러 블록만 중괄호 짝으로 잘라 판정하도록 좁혔습니다.
6. **「누구나 심을 수 있었다」가 과거형이라 다 막힌 것처럼 읽혔습니다** — `no-show` 는 여전히 무인증이고, 막은 것은 «번호 위조» 와 «이름 위조» 둘뿐이라고 갈라 적었습니다.

## 6. 제가 스스로 잡은 것

강사 번호 검사를 넣자마자 1건이 FAIL 했는데, 원인은 **가짜 D1 이 `.bind()` 없이 부르는 `.all()` 을 못 받아** 정본이 통째로 `lookup_failed` 로 빠진 것이었습니다. 그 바람에 옆의 «ambiguous»·«부분일치» 검사 2건이 **빈 문자열이라 헛돌며 통과**하고 있었습니다. 두 층 모두에 `first`/`all` 을 두어 고쳤습니다.
