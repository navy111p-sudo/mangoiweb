# 「오늘 수업」과 「지금 수업」 — 이름·자리 정리 (B안)

- **날짜** 2026-09-01
- **지시** 사장님 — 「오늘수업과 오늘의 수업이 헷갈려. 그리고 찾기도 어려워.
  이거 두개를 찾기 쉽게 하고 같은 메뉴에 넣으면 어떨까?」 → 설계안 3개 제시 → **B안 채택**
  (「내 의견대로 B안 만들고 A안으로 진행해줘」 — **A안은 다음 단계**)

---

## 1. 왜 헷갈렸나 — 코드로 확인한 것

| 화면 | 무엇 | 어디 있었나 |
|---|---|---|
| 🚪 오늘 수업 (바로 입장) | 오늘 예약된 **모든** 수업, 시간순 | `details#sm-today-classes` — **`card-students-mgmt` 안의 칸** = 사이드바 **학생 › 학생 명부** |
| 🔴 실시간 수업 현황 | 지금 망고아이 **화상방에 붙어 있는** 것 | 사이드바 **오늘 › 오늘의 수업** (+ 「화상강의실 초대(JWT)」 카드가 **함께** 묶여 있었음) |

⟹ 문제가 **둘**이었습니다.
1. 이름이 **「의」 한 글자** 차이인데 서로 다른 화면.
2. 「오늘 수업」은 **「오늘」 그룹에 아예 없었습니다** — 손자 메뉴나 ⚡자주 쓰는 기능으로만 닿았습니다.
   («찾기 어려움» 의 진짜 원인은 이름보다 이쪽이었습니다.)

**사장님 이해는 맞았습니다.** 「오늘 수업」 = 오늘 전체 · 「오늘의 수업」 = 실시간.
다만 두 가지를 덧붙였습니다 — 실시간 카드가 재는 것은 «화상방 접속» 이라 카페24 수업은 안 뜨고,
그 카드 왼쪽 숫자(「지금 수업 N」)는 **예약 기준**이라 「오늘 수업」과 **뿌리가 같은 데이터**입니다.
⟹ 두 화면은 «다른 기능» 이 아니라 **«같은 목록의 두 가지 보기»** 이고, 그래서 A안(탭으로 합치기)이 성립합니다.

## 2. 검토했다가 버린 방법 (제시한 3안 중)

| 버린 것 | 왜 |
|---|---|
| **A안 — 한 항목 + 탭으로 합치기** | 사장님 요청에 가장 가깝지만, 지금 두 화면은 **DOM 상 서로 멀리 떨어진 카드 두 장**이라 탭 한 겹을 새로 짜야 합니다. **버린 것이 아니라 «다음 단계»** 입니다 — B안 위에 얹습니다. |
| **C안 — 「수업 관제탑」을 정본으로 승격** | 관제탑에 **「오늘 전체」 목록이 아직 없습니다.** 지금 정본으로 올리면 있던 기능이 없어진 것처럼 보입니다. 관제탑을 키운 뒤에 다시 볼 일입니다. |
| 카드를 **DOM 째로 옮기기** | `admin.html` 1.3MB 에서 카드를 옮기는 것은 사고 반경이 큽니다. **가리키는 곳만** 바꾸면 같은 결과를 훨씬 싸게 얻습니다. |
| 이름에 «설명 괄호» 넣기(「오늘 수업 (전체)」) | 처음에 그렇게 적었다가 **`sidebar_three_level_harness` ⑧에 걸렸습니다** — 2026-08-19 에 「수강 운영(배율·정원)」을 「수강 운영」으로 줄이며 정한 규칙(설명은 툴팁으로). 규칙이 맞습니다 — 「오늘 수업」·「지금 수업」만으로 이미 갈립니다. |
| 「화상강의실 초대」 카드를 **지우기** | ⛔ 그 카드를 맡은 사이드바 항목이 하나뿐이라, 빼면 토큰 발급·회수 화면이 **메뉴에서 통째로 사라집니다**(이 저장소가 `card-inquiry-mgmt` 에서 실제로 밟은 사고). → 「시스템」 그룹으로 **옮겼습니다.** |
| 권한 표(`realtime_class`)의 「실시간 수업 현황」 라벨까지 바꾸기 | 그건 **다른 화면**(역할 권한 매트릭스)의 행 이름이고 `adm-r28.js` 번역표와 짝입니다. 건드리면 그쪽이 어긋납니다. **그대로 뒀습니다.** |

## 3. 한 일

**사이드바 「오늘」 맨 위 두 칸** (`js/adm-ia6.js`)

- **「오늘 수업」** → `card-students-mgmt` + `openSub: 'sm-today-classes'` (카드 «안의 칸» 을 바로 폅니다)
- **「지금 수업」** → `card-active-rooms` 하나만 (초대 카드는 뗐습니다)
- **「시스템 › 화상강의실 초대」** 신설 → `card-room-invite`

**같은 말로 맞춘 곳** — 카드 제목 `🚪 오늘 수업 (전체 · 바로 입장)` · `🔴 지금 수업 (실시간)`,
⚡자주 쓰는 기능 라벨, 구성표·지도 문서.
⚠️ ⚡자주 쓰는 기능의 **`key` 는 그대로** 뒀습니다 — 사용기록(`mangoi_qa_use`)이 그 키로 쌓여 있어서
바꾸면 사람이 쌓아 둔 순서가 통째로 초기화됩니다.

**이사표 한 줄** — `'today:오늘의 수업' → 'today:지금 수업'`.
없으면 어제 그 메뉴를 보던 사람이 아침에 **딴 데로 튑니다**(항목 키가 `그룹키:한글이름`).

## 4. 밟을 뻔했던 함정

| 함정 | 어떻게 피했나 |
|---|---|
| 사이드바 항목 이름을 바꾸면 **마지막으로 보던 화면이 미아**가 된다 | RENAMED 이사표 한 줄 + 하니스가 «이사표 목적지가 실제 항목인가» 까지 확인 |
| 카드를 떼면 그 카드가 **메뉴에서 사라진다** | 「시스템」에 새 항목. 하니스가 «그 카드를 맡은 항목이 정확히 하나» 인지 셈 |
| 항목이 **한 줄**로 시작하지 않으면 기존 하니스가 «갈 곳 없는 항목» 으로 FAIL | 실제로 FAIL 났고, 한 줄로 고쳤습니다 |
| 이름에 설명 괄호 | 위와 같은 하니스 ⑧에 걸렸고, 괄호를 뺐습니다 |
| **「열렸다」와 「보인다」는 다르다** — openSub 항목은 칸이 `open=true` 인데 화면은 카드 맨 위에 멈출 수 있다 | 브라우저 검사가 **그 칸의 제목줄 top 이 화면 안인지** 잽니다 |
| 구성표·지도 문서가 낡는다 | `admin_site_structure_sync_harness` 가 GROUPS 와 대조합니다 — 개수(중분류 45→47)까지 함께 고쳤습니다 |
| `?v=` 원장에 **배포된 적 없는 중간 버전**이 남는다 | 코드를 다시 고친 뒤 그 항목을 지우고 **현재 내용으로 다시 기록**했습니다 |

## 6. 다음 단계 (A안)

「오늘 수업」·「지금 수업」이 **같은 목록의 두 가지 보기**라는 것이 확인됐으니,
한 항목 안에서 **탭**(전체 / 🔴 진행 중 / 화상방 접속)으로 합치는 것이 A안입니다.
B안이 이름과 자리를 정리해 두었으므로 그 위에 **탭 한 겹**만 얹으면 됩니다.

⏳ **배포된 실제 화면은 제가 못 봅니다**(프록시가 `mangoi.ai` 를 403 으로 막습니다).
사장님이 관리자 › 오늘 에서 두 칸이 보이는지, 「오늘 수업」을 눌렀을 때 그 칸으로 화면이 가는지
한 번 봐야 끝난 것입니다.
