## 1. 왜 했나

사장님이 관리자 › 학생 명부 › 「🚪 오늘 수업 (바로 입장)」 화면을 캡처해 보내시며
툴바 줄에 빨간 동그라미를 치고 **「카페24 수업들과 새로 추가한 수업들을 구분해서 보려고 해.
이거 필터하는 검색창 기능을 적당한 자리에 만들어 줄래?」** 라고 하셨습니다.

캡처의 건수 줄은 **「166건 · 지금 입장가능 0건 · 카페24 142건」** 이었습니다.
즉 화면에 보이는 줄의 **85%가 카페24**라, 우리가 망고아이에 새로 넣은 수업이 그 안에
파묻혀 눈으로 찾을 수가 없는 상태였습니다. 목록은 시간순이라 카페24 줄과 망고아이 줄이
서로 섞여 나오고, 카페24 줄에는 입장·참관 버튼이 없어 스크롤을 훑으며
「입장 불가」 글자를 눈으로 건너뛰어야 했습니다.

⚠️ 「구분이 없다」가 아니었습니다 — 구분 표시는 **이미 있었습니다**(강의실 칸의 `LMS` 배지,
학생 칸의 「카페24 수업 · 입장 불가」 글자, 건수 줄의 「카페24 142건」).
없던 것은 **그 구분으로 «걸러 내는» 방법**입니다. 이 차이가 무엇을 만들지 정했습니다 —
표시를 더 크게 하는 것이 아니라 «안 보이게 하는 손잡이» 를 다는 것.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### 3-1. 가르는 근거를 «방 번호» 로 하지 않았다

카페24 줄은 방 번호가 `c24-512074` 처럼 시작하므로 `room_id.startsWith('c24-')` 로 가를 수
있어 보입니다. **쓰지 않았습니다.** 서버(`src/api-admin.ts` 의 `/api/admin/classes/today`)가
줄마다 **`source: 'mangoi' | 'cafe24'`** 를 이미 실어 주고 있고, 그것이 정본입니다.

방 번호로 짐작하면 판정이 두 벌이 되어, 카페24가 번호 체계를 바꾸거나 우리가 다른 접두사를
쓰는 순간 **에러 없이** 어긋납니다. 이 저장소가 반복해서 밟은 형태입니다(CLAUDE.md 2장
「같은 배정을 두 API 가 서로 다른 방식으로 확인」).

### 3-2. 서버에 `source=` 파라미터를 새로 받게 하지 않았다

처음에 떠올린 것은 「API 에 `?source=mangoi` 를 더한다」였습니다. 버린 이유:

- 이 목록은 **이미 통째로 받아 둔 상태**입니다(`_rows`). 한 글자 칠 때마다 요청이 나갈 이유가
  없습니다. 실제로 브라우저 검사에서 «출처·검색을 아무리 만져도 요청 0건» 을 확인합니다.
- 새 관문 등록이 필요해집니다(CLAUDE.md 2장 「새 API 추가 — 관문이 셋」).
  얻는 것 없이 404 위험만 늘어납니다.
- 날짜만 서버를 다시 부릅니다 — 그건 **다른 날의 데이터**라 화면에 없기 때문입니다.

### 3-3. `ph-frn-filter-js` 의 자동 검색창(`TABLES`)에 이 표를 넣지 않았다

`admin.html` 에는 표에 「🔍 목록 검색」을 자동으로 끼워 주는 장치가 있습니다.
거기에 이 표를 등록하면 코드가 거의 안 들어갑니다. **버렸습니다** — 그 필터의
`MutationObserver` 가 표가 다시 그려질 때마다 «화면에 있는 행» 을 자기 입력값으로 한 번 더
거르기 때문에, **우리가 찾아 준 줄까지 `display:none` 으로 숨깁니다**
(CLAUDE.md 2장 「표에 전용 검색창을 달았더니 검색창이 두 개」 — 2026-08-08 `centers-table`,
2026-08-18 `hq-table` 이 같은 이유로 그 목록에서 빠졌습니다).

그래서 이 표는 그 `TABLES` 목록에 **없고**, 앞으로도 넣으면 안 됩니다.
HTML 주석에 그 경고를 적어 두었습니다.

### 3-4. 입력칸을 `#tc-body` «밖» 에 두었다

`render()` 는 `#tc-body` 의 `innerHTML` 을 통째로 다시 씁니다. 입력칸을 그 안에 두면
한 글자 칠 때마다 요소가 새로 만들어져 **커서가 날아가고 「한 글자만 쳐진다」** 가 됩니다.
툴바(밖)에 두어 구조적으로 그 사고가 안 나게 했습니다 — 검사 한 줄로 못 박아 두었습니다.

### 3-5. 「카페24 + 지금 입장가능만 = 0건」을 **막지 않았다**

카페24 줄은 `join_open` 이 **항상 false** 입니다(망고아이 화상방이 없습니다).
그래서 그 조합은 언제나 0건입니다. 선택지를 비활성화하거나 자동으로 되돌리는 것도
생각했지만, **화면이 대신 판단해 주면 「왜 안 되는지」가 사라집니다.**
그대로 두고 **0건인 이유를 글자로 말하게** 했습니다 — 아니면 「검색이 고장났다」로 읽힙니다.

### 3-6. 화면(클라이언트)에서 거르되, «건수» 는 둘 다 보여 준다

거른 건수만 보이면 「수업이 사라졌다」로 읽히고, 합계만 보이면 「검색했는데 숫자가 안 변한다」가
됩니다. **「표시 2건 / 전체 166건」으로 둘 다** 보여 줍니다.

ℹ️ 이 화면은 서버 페이징이 없어 «화면에서 거르기» 가 성립합니다.
서버가 잘라 주는 목록이었다면 `total` 이 거짓말을 하므로 서버 `WHERE` 에서 잘라야 합니다
(CLAUDE.md 2장 녹화 목록 항목).

## 5. 남은 것 / 주의할 것

### 5-1. 새로 발견한 함정 — CLAUDE.md 2장에 넣었습니다

브라우저 검사를 만들다 **멀쩡한 화면이 FAIL 로 나오는** 일을 두 번 겪었습니다.
둘 다 화면 버그가 아니라 **검사 환경** 문제였습니다.

1. **헤드리스 창은 «포커스가 없는 창»** 이라 `el.focus()` 가 통째로 안 먹습니다
   (예외도 안 나고 `document.activeElement` 가 계속 `BODY`).
   → CDP `Emulation.setFocusEmulationEnabled {enabled:true}` 를 켜야 합니다.
2. **관리자 카드는 IA6 가 «한 번에 한 장»(`.ia6-hide` = `display:none`)만 보여 줍니다.**
   표는 DOM 에 있으므로 «글자를 읽는» 검사 20여 건이 전부 초록인데,
   상자가 숨어 있어 «보인다·눌린다·포커스» 검사만 헛돕니다
   (실측: `offsetParent=null` · 폭 0).
   → `jumpToMenu('card-students-mgmt')` 로 먼저 열고,
   **`!!el.offsetParent` 를 검사 한 줄로 박아 두었습니다** — 안 박으면 다음 사람이 또
   «화면 버그» 로 오진합니다.

### 5-2. 이 화면을 또 손댈 때
