# 포인트 적립을 원장(point_transactions)에 남기게 함 — 금액은 그대로 (2026-09-01)

## 1. 무엇이 잘못돼 있었나

단어장 보상·복습퀴즈 보상이 `student_points.balance` 만 직접 올리고 **원장에 한 줄도 안 남겼습니다.** 그래서 그 포인트는 다음 세 화면 어디에도 안 보입니다:

- 학생 **본인의 포인트 내역**(최근 30건)
- **학부모 대시보드**(자녀 최근 10건)
- 관리자 **월간 포인트 합계**

잔액만 늘고 **「왜 늘었는지」가 어디에도 없었습니다.**

## 2. 잰 것

| 무엇 | 값 |
|---|---|
| `student_points.lifetime_earned` 합계 − 원장 양수 합계 | **원장 밖 적립 2,746점**(9계정, 대부분 테스트 + jeong) |
| `vocab_rewards` / `review_quiz_rewards` | 9행 / 10행 = **1,136점**, 8계정 |
| `student_points` | 88행 중 **이름 칸이 아이디와 같은 행이 12개**, `balance IS NULL` 0건 |

그리고 정책의 `GAME_QUIZ_RULES` 에 **`vocab_review`·`review_quiz_done` 이 이미 적혀 있는데** 실제 적립 경로는 그 이름을 한 번도 안 썼습니다 — **이름만 있고 연결이 없었습니다.**

## 3. 한 것 — «기록만» 남기고 금액은 한 푼도 안 바꿈

두 곳을 정본 `applyPointTransaction` 호출로 바꿨습니다. `rule_code` 는 정책이 이미 이름 붙여 둔 것을 씁니다.

**금액이 안 바뀌는 근거**: 단어장 400점·복습퀴즈 500점 상한이 그 앞에 그대로 있고, `applyPointTransaction` 자체는 상한을 걸지 않습니다.

**상한 계산에서는 뺐습니다**(`CAP_UNCOUNTED_RULES`). 안 그러면 원장에 기록이 남는 순간 총량 상한(100점)과 게임 묶음 상한(30점)이 갑자기 조여져 **학생 보상이 최대 10분의 1로 줄어듭니다.** 그건 버그 수리가 아니라 **보상 정책 변경**이라 사장님이 정할 일입니다.

## 4. 🔴 고치다가 «로그인 정보 유출» 을 만들 뻔했습니다

정본은 `student_name = COALESCE(?, student_name)` 입니다. 제가 빈 값 대신 `uid` 를 넘겼는데, 그러면 **기존에 들어 있던 진짜 이름이 아이디로 바뀝니다.**

그 칸은 **무인증 공개 리더보드**가 그대로 내보냅니다. 그리고 이 저장소는 바로 그 자리에 **「이름이 없을 때 아이디로 폴백하지 말 것」** 을 못 박아 뒀습니다 — 제가 2026-08-28 에 직접 적은 것입니다. 비밀번호가 설정된 학생이 **0명**이라 **아이디를 아는 것이 곧 로그인**이기 때문입니다.

옛 코드는 `ON CONFLICT` 목록에 `student_name` 이 없어 기존 행을 안 건드렸습니다. 즉 **제 변경이 새로 만드는 위험**이었습니다. trap-check 가 잡았습니다.

→ 진짜 이름이 없으면 `undefined` 를 넘겨 기존 값을 그대로 둡니다. 하니스에 그 검사를 넣었습니다.

## 5. trap-check 가 잡은 나머지 (전부 반영)

- **하니스 검사 세 건이 «되돌려도 통과»** 했습니다:
  - 가짜 D1 이 질의문과 무관하게 늘 0을 돌려줘 「단어장 400점을 받은 날에도」 **시나리오가 한 번도 만들어지지 않았습니다** → 제외가 실제로 걸렸는지 질의문에서 읽어 답을 바꾸게 고쳤습니다.
  - 「그 이름이 정책 목록에 있다」가 파일 전체를 봐서 **제가 새로 만든 `CAP_UNCOUNTED_RULES` 가 자기를 잡고** 있었습니다 → `GAME_QUIZ_RULES` 목록만 잘라서 봅니다.
  - 「잔액 직접 올리기가 없다」가 **줄 단위**라 두 줄로 쓰거나 `UPDATE` 로 쓰면 못 잡았습니다 → 뜻으로 찾습니다.
- **`checkEarnAllowed` 부정 검사가 파일 전체**였습니다 → 나중에 다른 게임 보상이 정당하게 쓰면 거짓 FAIL. 두 호출 부근만 봅니다.
- **실효 상한이 1,000점이 아니라 1,050점**입니다 — 단어장 미션 50점이 `kind !== 'mission'` 조건 때문에 400점 상한 **밖**입니다. 그리고 하니스가 「1,000점」을 정규식으로 못 박고 있어서 **바로잡는 순간 FAIL** 날 뻔했습니다 → 숫자 대신 «근거» 를 검사합니다.
- **`applyPointTransaction` 은 던질 수 있습니다**(옛 직접 UPSERT 는 안 던졌습니다). 단어장 쪽에는 try/catch 가 없어 **HTTP 500** 이 될 수 있었습니다 → 감싸고 크게 로그를 남깁니다.
  ⚠️ `balance IS NULL` 은 실측 **0건**이라 오늘 그 경로가 열릴 가능성은 낮습니다.
- **아직 남은 원장 밖 경로 두 곳**(`api-admin.ts` 이탈관리 🎁 기프트·컴백 번들)을 주석·하니스에 적어 뒀습니다 — 이 수리가 «다 고쳤다» 로 읽히지 않게.
