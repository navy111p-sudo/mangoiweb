# 학습 화면 4곳 — 화살표를 «뒤로가기» 로 (2026-09-01)

## 1. 왜 했나

같은 날 「나가는 문」 전수 점검에서, 네 화면의 화살표가 **뒤로가기가 아니라 홈** 이었습니다.

| 화면 | 그전 | 문제 |
|---|---|---|
| `review-quiz.html` | `<a href="/">← 홈</a>` | 화살표가 홈. 우상단 공용 [🏠 홈]과 합쳐 **홈이 두 개**, «직전 페이지» 는 **없음** |
| `review-quiz-cn.html` | `<a href="/">← 首页</a>` | 같음 |
| `ai-write.html` | `<a href="/">← 홈</a>` | 같음 |
| `ai-friend.html` | `<a href="/">←</a>` | 화살표 모양인데 홈으로 감 (게다가 눌림 영역 **14×21px**) |

2026-08-03 사장님 지시(「← 는 항상 직전 페이지, 처음 페이지로 나가는 문은 홈 버튼 하나」)와
어긋나는 상태였고, 점검 보고 뒤 사장님이 **「나머지 4개도 화살표는 뒤로가기로 고쳐줘」**.

## 2. 무엇을 했나

**⛔ 판정을 4벌 복제하지 않았습니다.** 「히스토리가 있으면 뒤로 → 없으면 같은 오리진
referrer → 그것도 없으면 홈」은 `js/back-nav.js` 의 `goBack()` 이 이미 갖고 있습니다.
그 함수를 **`window.mangoiGoBack` 으로 내보내고**(순수 추가 1줄), 네 화면의 화살표가
그것을 부르게 했습니다.

```html
<a href="/" onclick="if(window.mangoiGoBack){event.preventDefault();window.mangoiGoBack();}">← 뒤로</a>
```

- ✅ **`href="/"` 를 남겨 둔 것이 중요합니다** — back-nav.js 가 아직 안 왔거나(defer),
  캐시에 옛 사본이 있거나, 홈 화면처럼 그 함수가 없는 경우에도 **«홈으로는 갑니다».**
  `href="#"` 로 두면 무반응이 되어 「버튼이 고장났다」가 됩니다.
- ✅ 화살표가 화면에 보이므로 back-nav.js 는 **자기 동그란 ← 를 안 넣습니다**
  (`hasVisibleBack`) → 화살표가 둘이 되지 않습니다.
- `review-quiz-cn.html` 은 back-nav.js 를 안 싣고 있어 **그 한 줄을 추가**했습니다.
- 라벨: 「← 뒤로」(KO/EN `data-ko`/`data-en`) · 중국어판은 「← 返回」 ·
  `ai-friend` 는 헤더가 좁아 **화살표만** 두고 `aria-label`·`title` 로 설명.
- 홈으로 가는 문은 **우상단 공용 바 [🏠 홈]**(`mango-i18n.js`)이 이미 넣어 줍니다 →
  결과적으로 **홈 두 개 → 하나**, 뒤로가기 **없음 → 하나**.
- 덤: `ai-friend` 화살표의 눌림 영역을 `padding:8px 10px; margin:-8px -10px` 로
  **14×21 → 34×37** 로 넓혔습니다(음수 margin 이 되돌려 주므로 옆 요소는 제자리 — 실측 확인).

## 3. 검토했다가 버린 방법

| 버린 방법 | 왜 |
|---|---|
| 네 화면에 뒤로 판정을 각각 복제 | 이 저장소가 반복해서 밟은 형태입니다(같은 판정이 여러 벌이면 한쪽만 고쳐집니다). 게다가 이미 5개 화면이 각자 복제해 두었는데, 여기서 4벌을 더 만들면 9벌이 됩니다 |
| 화면의 화살표를 **지우고** back-nav.js 가 자기 ← 를 넣게 | 그 버튼은 `position:fixed` 라 각 화면의 `.top` 바 위에 얹힙니다 — 어제 speech-coach 에서 밟은 «제목을 덮는» 함정을 4곳에서 다시 재야 합니다. 헤더 모양도 4개가 바뀝니다. 사장님 지시는 «화살표가 하는 일» 을 바꾸라는 것이었습니다 |
| `onclick` 대신 `href="#"` + JS | 함수가 없을 때 **무반응** = 「고장났다」. `href="/"` 폴백이 낫습니다 |
| 네 화면의 back-nav.js 태그에 `?v=` 를 붙여 새 사본을 강제 | 같은 파일이 «두 주소» 로 갈려 다른 화면과 캐시가 나뉩니다. 폴백이 있으니 최악이어도 옛 동작(홈)이라 **회귀가 아닙니다** |
| 나머지 5개 화면(복제본)까지 정본으로 통일 | 이번 지시 범위 밖입니다. 6장에 남겼습니다 |

## 4. 확인한 것

- **브라우저 실측 17건 PASS / 0 FAIL** — 네 화면 각각:
  ① 화살표가 `window.mangoiGoBack`(function)에 배선됨
  ② 홈은 우상단 공용 바 하나(동그란 ← 중복 주입 0)
  ③ 화살표가 `elementsFromPoint` 로 **맨 위**
  ④ **`vocab.html` → 그 화면으로 이동한 뒤 화살표를 실제로 클릭 → `/vocab.html` 로 돌아감**
     (전에는 `/` 로 갔습니다 — 이것이 이번 수리의 핵심 증거입니다)
- **공유 파일 회귀 확인** — `back-nav.js` 를 고쳤으므로 그것에 의존하는 화면을 함께 재습니다:
  `speech-coach`·`speech-coach-cn`·`vocab` 은 여전히 동그란 ← 를 **주입**(inj=Y),
  홈 화면(`/`)에서는 **주입 안 함 + `mangoiGoBack` 없음**(맨 위에서 return — 의도대로).
- 폰 390 · PC 1280 둘 다 재고 가로 넘침 0.
- **회귀 하니스** `--fast`: PASS 246 / SKIP 20 / **FAIL 9 — 전부 환경 사유**(이 컨테이너에
  `cloudflare-deploy/node_modules` 없음 → `esbuild ENOENT`). 이 변경 전에도 같은 9건입니다.
- ℹ️ `?v=` 원장(`asset-versions.json`)은 **변화 없음** — `back-nav.js` 는 어느 화면에서도
  `?v=` 없이 실립니다.
- ⚠️ **확인하지 못한 것**: 「히스토리가 아예 없는 진입」(앱 첫 화면·카톡 링크)은 헤드리스
  탭이 히스토리를 물고 있어 재현하지 못했습니다. 그 경로의 판정은 **제가 만든 것이 아니라
  back-nav.js 의 기존 정본**이고 이번에 한 줄도 바꾸지 않았습니다 — 「테스트했다」고 적지
  않습니다.
