## 3. 원인 — 네 가지

1. **평균이 사고를 가린다.** 1분 평균 1.9% 는 어느 화면에서도 «양호» 다.
2. **화질 자동조절이 진동한다.** 최저까지 16초(4틱), 회복 12초(3틱). 스파이크가 1분마다 오니
   내려가다 올라오기를 반복했다.
3. **음성전용 구제(AAO)가 한 번도 안 걸렸다.** 문턱이 「오디오 손실 12%가 3틱 연속」이었다.
4. 🔴 **근본 — 잴 수단이 없었다.**
   - `vc_quality` 742건이 **전부 학생(8명), 강사 0건**. 로그가 `getCurrentUser()`
     (=학생 전용 `mangoi_logged_user`)로만 uid 를 만드는데 강사는 쿠키 세션이라 늘 null 이고,
     서버가 `if (!b.uid) return` 으로 **조용히 버렸다.** 관리자 「📶 강사 회선품질」 화면은
     **개설 이래 강사 데이터가 0건**이었다.
   - 적응 루프도 로그도 `sender.getStats()` 만 본다 = **«받는 쪽» 을 한 번도 안 쟀다.**
     그런데 제보는 전부 «내가 받는 화면·소리» 다.

## 4. 고친 것

### 1단계 — 계측 (통화 경로 안 건드림)

- `js/idx-vc-qlog.js` — uid 를 **학생 키 → `mangoi_admin_session` → 화면 이름표** 순으로.
  수신 통계(`receiver.getStats()` inbound-rtp) 추가: `rx_loss`·`rx_aloss`·
  **`rx_conceal`(끊겨서 메워진 소리 비율 = 「소리 끊김」의 직접 지표)**·`rx_freeze`(영상 멈춤).
  `p95_loss`(평균이 가리는 스파이크)·`peers`(동시 연결 수)도 함께.
- `src/api-mango.ts` — 새 칸 6개를 **ALTER 로만** 붙이고 INSERT 에 추가.
- `src/api-admin.ts` — 집계에 반영. `admin.html` 「📶 강사 회선품질」 표에 컬럼 3개 추가.

### 2단계 — 통화 경로 (사장님 지시)

- 화질 회복 조건 **3틱(12초) → 8틱(32초) + 스파이크 후 30초 홀드** (진동 제거).
- `tuneReceiveLatency` 게이트를 같은 근거로 조임(+ RTT 250→150ms).
  **이 줄이 「소리가 끊긴다」에 직접 걸린다** — 스파이크 사이 조용한 4초마다 켜졌다 꺼지며
  그 파일 주석이 스스로 경고하는 «불필요한 재설정 = 소리 튐» 을 1분에 몇 번씩 일으켰다.
- AAO 문턱 오디오 손실 **12% → 8%** (진입 조건 3틱은 그대로).
- `js/idx-vc-dupghost.js` — **붙었다가 죽은 연결**(`failed`/`closed`)도 유령으로 본다.

## 5. 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| AAO 진입 조건(3틱)도 함께 낮추기 | 스파이크 한 번에 영상이 꺼진다. 필리핀·중국 회선에서 멀쩡한 수업이 자꾸 깜깜해진다. 문턱(12→8)만 내렸다 |
| `disconnected` 도 유령으로 보기 | 그 회선들에서 몇 초씩 흔한 «잠깐» 상태다. 지우면 멀쩡한 수업이 끊긴다. 되돌아올 수 없는 상태만 본다 |
| 이름만 같으면 유령 정리 | 가족 공용 계정에서 서로를 지우는 무한 킥(CLAUDE.md). 기존 «비대칭 확인» 을 그대로 통과해야 지운다 |
| 오디오 지터버퍼 목표값을 0 → 40ms 로 올리기 | 숫자를 바꾸는 대신 **켜지는 조건**을 조였다. 그만큼 조용한 적이 없는 회선에서는 아예 안 켜지고 브라우저 적응 버퍼가 쓰인다 — 손실 있는 회선의 옳은 기본값 |
| 강사에게 `mangoi_logged_user` 만들어 주기 | 학생 전용 기능이 통째로 열린다(CLAUDE.md 1장). 로그에 적을 «이름» 만 가져왔다 |
| 유령 의심을 보고서에 단정으로 쓰기 | samples 두 배는 «추론» 이다. 그래서 `peers` 를 남기게 하고 문장도 추론으로 적었다 |
| 화질 진동을 «상한을 키워서» 풀기 | 회선이 정말 좋아졌는데도 흐린 채로 남는다. 회복 «시간» 만 늘렸다 |

## 7. ⏳ 확인 «못» 한 것

- **`X-Turn-Source` / `X-Turn-Detail`** — 이 컨테이너 프록시가 `mangoi.ai` 를 막는다
  (curl CONNECT 403 실측). `public-fallback` 이면 **그것이 1순위 원인**이고 코드 수리보다 먼저다.
  사람이 한 줄로 확인해야 한다.
- **배포된 화면** — 같은 이유로 못 본다. 사장님이 한 번 봐야 끝난 것이다.
- **원인 확정** — 이번 수리는 «다음 수업부터 숫자가 남게» 한 것이다.
  강사 회선인지 학생 회선인지 중계서버인지는 **다음 수업 한 번의 기록**으로 갈린다.
- **유령 연결 여부** — samples 두 배의 정체는 `peers` 기록이 쌓여야 확정된다.
