한편 AI 도구가 매칭에 쓰는 이름은 그게 아닙니다:

- `review_quizzes.textbook` = 「BTS 1 001 (Welcome to school)」 (과 단위)

`warmupLessonContext` 는 `LOWER(textbook)=LOWER(?)` **완전일치**라, 「BTS」를 배정하면
**에러 없이 아무것도 안 맞습니다.** 배정은 «성공» 하고 학습만 조용히 헛돕니다.

## 2. 무엇을 했나

### (A) `src/student-placement.ts` 신설 — 배정의 정본

- `bandFromCefr()` / `textbookLevelFromCefr()` — CEFR → 「Lv N」
- `applyPlacementLevel()` — 학생 명부에 기록 (**비어 있을 때만**)
- `loadTextbookChoices()` — 배정할 수 있는 «실재하는» 교재 목록

**⛔ 새 눈금을 만들지 않았습니다.** CEFR ↔ 단계 ↔ 교재 Lv 는 이미 두 정본이 있고
하니스가 서로 대조 중이라, 그 둘을 **이어 읽기만** 합니다:

```
CEFR 'B1' --AI_FRIEND_CEFR 역인덱스--> S4 --> 밴드 4 --> BAND_SPECS[3].lvFrom --> 'Lv 13'
```

### (B) 레벨테스트 → 학생 명부 (`/api/leveltest/diagnose`)

배정 화면은 세 묶음으로 그립니다 — **「✅ 바로 쓸 수 있는 교재(복습퀴즈 있음)」 /

문항 수·페이지 수를 라벨에 적고 중국어는 🈶 로 표시합니다.

### (D) `public/signup.html` 신설 — 학생 자가가입 화면

### (E) 🔴 야간 동기화가 그 값을 지우던 것 — `cafe24-sync.ts`

**함정 대조 검사(trap-check)가 잡았습니다.** 저는 「UPSERT 의 `SET` 목록에 없으니 보존된다」고
판단했는데 **그 앞의 `DELETE` 를 놓쳤습니다.** `importCafe24Students` 는 매일 밤 03:00 KST 에
카페24 학생 전원을 지우고 다시 넣습니다 — 보존 조건(`password_hash`·`parent_user_id`·`eval_band`
세 칸)에 `level`·`textbook` 이 없어서, 행이 사라진 뒤 **새 INSERT 로 들어와 NULL** 이 됩니다.

실측(그 SQL 을 오려 내 진짜 SQLite 에 돌림):

```
밤 전 : c24_student  level="Lv 13"  textbook="BTS 1 001 (…)"
DELETE: (행이 사라짐)
밤 후 : c24_student  level=null     textbook=null      ← 카페24가 다시 넣음
        self_student level="Lv 5"                      ← 자가가입 학생만 살아남음
```

⚠️ **고치려던 대상에게만 안 들었습니다.** 배경이 「29,462명 전원 비어 있다」인데
그 29,462명이 곧 카페24 학생입니다. 낮에는 멀쩡히 보이고 다음 날 조용히 «미배정» 으로
돌아옵니다(에러 없음). ⇒ DELETE 보존 조건에 두 칸을 더하고(기존 세 칸과 같은 방식),
그 조건이 읽는 칸이라 **멱등 ALTER 를 DELETE 앞에** 두었습니다.

### (F) 함정 검사가 잡은 나머지 셋

| 잡힌 것 | 무엇 |
|---|---|
| `data-ko` 안에 `<b>` | i18n 엔진이 `textContent` 를 갈아끼워 **「`<b>`」가 글자로 드러남**. 5폭 × 2언어 전부 재현. CLAUDE.md 함정을 알고도 밟았고, 제 하니스는 `<input>` 만 봐서 `<p>` 를 놓쳤습니다 → 강조 조각을 별도 요소로 떼고, 검사를 **모든 요소**로 넓힘 |
| `updated_at` 멱등 ALTER 누락 | 자가가입이 만드는 최소 스키마에 그 칸이 없어 `no such column` → 레벨이 **조용히 안 적힘**. 하니스 픽스처가 그 칸을 갖고 있어 **구조적으로 못 잡던** 것도 함께 고침(픽스처에서 뺌) |
| 전역바가 제목 글자를 덮음 | 320px KO 61.6×17px · 390px EN 27×15px. 바 폭을 **재서** 자리를 비우고, `min-width:120px` 가 좁은 폭에서 그 예약을 넘던 것도 `min-width:0` 으로 고침 → 5폭 전부 겹침 **0** |

## 3. 검토했다가 버린 것

| 버린 것 | 왜 |
|---|---|
| **CEFR 로 교재까지 자동 배정** | 「B1 = BTS 3권」인지 「SIU Basic」인지는 **시험 점수가 정할 일이 아닙니다.** 지어내면 학생이 엉뚱한 교재로 공부합니다. 레벨만 적고 교재는 사람이 정합니다 |
| **본문 `student_uid` 로 레벨 기록** | 그 경로는 **무인증 공개**입니다. 본문 값을 믿으면 아무나 남의 학생 레벨을 바꿉니다(CLAUDE.md 「본문에 적힌 «누구에게» 를 그대로 쓴다」). **토큰으로 확인된 uid** 로만 적고, 없으면 **폴백하지 않습니다** |
| **이미 있는 레벨 덮어쓰기** | 관리자가 정한 값을 시험 한 번이 뒤집으면 안 됩니다. 사람 손이 이깁니다 |
| **`textbooks` 표에 실재 이름 INSERT** | 교재 이름의 **세 번째 체계**가 생깁니다. 읽어 오기만 합니다 |
| **`items` 응답 모양 바꾸기** | 이 API 를 쓰는 화면이 다섯 곳(`adm-core.js` 4곳·`admin/health.html`)입니다. `library` 를 **더하기만** 했습니다 |
| **기본으로 실재 목록 계산** | `textbook_files` 전수 GROUP BY 라, 교재 목록만 필요한 호출에 비용을 얹을 이유가 없습니다 → `?library=1` 일 때만 |
| **교재 이름을 보고 중국어 판정** | 근거는 `zh_passage`·`zh_vocab` 에 실재하는가입니다(정본 `resolveZhTextbook`) |
| **개별 학생 배정 UI 새로 만들기** | 일괄배정에 `q`(아이디 검색) + 「미배정만」 체크 해제가 이미 있습니다. 같은 기능이 두 벌이 되면 「화면마다 답이 다른」 사고가 시작됩니다 |
| **홈(`index.html`)에 가입 입구 추가** | **공동 금지구역**이고 첫 화면 예산 여유가 얼마 없습니다. 어디에 노출할지는 사업 판단이기도 해서 **사장님 결정 사항으로 남깁니다** |
| **레벨 표기를 'A1' 그대로 넣기** | `review_quizzes.level` 이 「Lv 1」 형식이고 완전일치 비교입니다. 'A1' 은 영영 안 맞는데 **에러가 안 납니다** |
