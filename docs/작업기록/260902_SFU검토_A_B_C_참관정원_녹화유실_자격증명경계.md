## 0. 먼저 — 제안서에서 틀린 것 두 가지를 정정합니다

작업하면서 확인해 보니 **제안서 B안의 전제가 틀렸습니다.** 그대로 두면 다음 사람이
없는 기능을 만들려고 하게 되므로 여기 크게 적습니다.

### ⛔ 정정 ① — Cloudflare 는 WebRTC 방송을 «녹화하지 않습니다»

제안서에 「SFU 로 옮기면 서버가 녹화한다」고 적었는데, Cloudflare 문서가 **세 곳에서**
정반대를 명시합니다.

| 문서 | 문장 |
|---|---|
| Stream 요금 | `WebRTC broadcasts cannot currently be recorded, thus no storage is consumed` |
| Stream WebRTC(베타) 제한 | `Recording and live HLS playback are not yet supported` |
| Stream WebRTC 요금 | `WebRTC is not currently eligible for recording` |

- **Stream 라이브 입력 + WHIP** → 브라우저가 올릴 수는 있지만 **녹화가 안 됩니다.**
  Stream 이 녹화하는 것은 RTMP/SRT 인제스트뿐이고, 브라우저는 그 둘을 못 씁니다.
- **Realtime SFU** → 녹화 기능이 **없습니다.** WebSocket 어댑터가 PCM 오디오·JPEG 프레임을
  흘려 줄 뿐이고, 그걸 영상 파일로 굽는 것은 우리 몫인데 Worker 에서는 불가능합니다
  (Containers 를 새로 도입하는 별건).
- 합성 녹화가 실제로 있는 것은 **RealtimeKit** 입니다 — 가상 봇이 회의에 들어와 녹화해
  R2 에 올려 줍니다. 다만 그건 화상수업 스택 전체를 그 SDK 로 갈아 끼우는 일이라 **D안**입니다.

→ 그래서 B 는 «목표(녹화 유실을 줄인다)» 를 유지하고 **실제로 실패하고 있는 자리**를 고쳤습니다.

### ⚠️ 정정 ② — 「녹화 실패 27.2%」는 과장이었습니다

`aborted` 135건은 **size 0 인 빈 껍데기**라 소스 주석이 「사고가 아니라 올바른 뒷정리」라고
못 박고 있고(`api-mango.ts`) 목록 쿼리도 이미 감춥니다. 그걸 실패로 세면 안 됩니다.

- 진짜 실패는 `upload_failed` — **634건(성공 561 + 실패 73) 중 73건 ≈ 11.5%**
- 심각도를 부풀린 문장이 규칙서에 박히면 다음 사람이 엉뚱한 것을 고칩니다(CLAUDE.md 2장)

## 1. A안 — 참관자 정원 2 → 4

### 왜

관제탑이 생기면서 «사장님 + 한국 매니저 + 필리핀 매니저» 가 동시에 보는 자리가 실제로
생겼는데 정원이 2명이었습니다. 죽은 참관 소켓 하나가 한 자리를 먹으면 실질 1명이 됩니다.

### 무엇을

- `src/video-call-room.ts` — `OBSERVER_MAX` 2 → **4** (공동 금지구역 · 사장님 승인)
- `room-joined` 에 `observers`·`observerMax` 를 실어 화면이 «얼마나 붐비는지» 를 알 수 있게
- `admin/monitor-wall.html` — **«관찰 N/4»** 배지, 이미 2명 이상이면 **🎧 소리만이 primary**,
  정원이 차면 참관 버튼 셋을 `disabled`(눌러 놓고 room-full 로 튕기지 않습니다)

### 왜 무한이 아닌가

참관자 한 명 = 방 안 **각자**의 업로드 한 갈래입니다. PC 상한 1,200kbps 기준으로
참관자 4명이면 강사 업로드가 최대 **4.8Mbps** 늘어납니다 — 필리핀 회선에서는 그 자체가
수업을 깹니다. 무한 참관은 mesh 로 못 풉니다(그게 C안).

### 검토했다가 버린 것

| 버린 것 | 왜 |
|---|---|
| 참관 «화면» 에서 붐빔을 안내 | 소리만/영상은 **입장할 때** 정해집니다(재협상 없음). 들어간 뒤에 알려 주면 늦습니다 — 관제탑(들어가기 전)이 맞는 자리입니다 |
| 3번째부터 «자동으로» 소리만 | 사람이 모르는 사이에 동작이 바뀝니다. 권하기만 합니다 |
| 하니스 40KB 상한을 그냥 유지 | 실측 40.8KB. 상한의 취지는 «admin.html 에 얹지 않는다» 이지 40 이라는 숫자가 아닙니다 → 44KB 로 올리고 **근거를 파일에 적었습니다** |

## 2. B안 — 녹화 유실이 «없던 일» 로 파묻히지 않게

### 무엇을 쟀나 (운영 D1, 조회만)

| 잰 것 | 값 |
|---|---|
| `upload_failed` 73건의 `duration_ms` | **전부 0** |
| 그중 여럿의 `size_bytes` | 611KB · 1.4MB · 1.7MB · 4.5MB … (조각은 올라갔는데 마무리가 실패) |
| 일자별 실패율 | 8/24 **39%**(14/22) → 8/26 16% → 8/28 8% → **9/1 7%**(3/41) |

8/26~27 수리가 크게 줄였지만 0 은 아닙니다.

### 뿌리 — 실패 분기가 «무엇을 잃었는지» 를 안 적었다

`recordings-r2.ts` 의 `upload/complete` 실패 분기가 `status`·`storage` **만** 적고
`ended_at`·`duration_ms`·`size_bytes` 를 안 썼습니다. 그래서 두 가지가 함께 망가집니다.

1. 화면이 «몇 분짜리 수업을 잃었는지» 를 말할 수 없습니다.
2. `duration_ms` 가 0 이면 나중에 오는 `/api/recordings/stop` 의 `nothingRecorded` 판정이
   **«없던 일(aborted)»** 쪽으로 기울고, 목록은 «aborted + size 0» 을 통째로 감추므로
   **진짜 잃어버린 수업이 «정상 정리분» 에 파묻힙니다.**
   (CLAUDE.md 2장 「정상 정리분 66% 에 진짜 저장 실패 76건이 파묻혔다」와 같은 뿌리)

### 고친 것 셋

1. `recordings-r2.ts` — 실패해도 `ended_at`·`duration_ms`·`size_bytes` 를 남깁니다.
   ⚠️ `COALESCE`·`MAX` 로 **덮어쓰지 않습니다** — 늦게 온 비콘이 이미 적힌 값을 0 으로 지우면 안 됩니다.
2. `api-mango.ts` — `/stop` 의 «없던 일» 판정이 **DB 에 이미 적힌 값도** 봅니다(둘 중 큰 쪽).
   탭을 닫으면 `onstop` 이 안 돌아 0·0 으로 오는데, 그 사이 조각 업로드가 이미 `size_bytes` 를
   적어 뒀을 수 있습니다.
3. `mango-rec.js` — 마무리(`upload/complete`)가 실패하면 **1.5초 뒤 한 번만** 다시 보냅니다.
   서버는 complete 가 실패해도 `head()` 로 실물이 있으면 자가복구하는데, 그 안의 300ms
   재시도로 못 덮는 구간이 있습니다. 서버는 이 재요청에 **이미 안전**합니다
   (완료면 그대로 성공, `upload_failed` 면 일부러 통과시켜 자가복구).
   ⛔ 무한 재시도 금지 — 수업이 끝날 때마다 도는 자리입니다.

### 검토했다가 버린 것

| 버린 것 | 왜 |
|---|---|
| Stream 라이브 입력 + WHIP | 위 정정 ① — **녹화가 안 됩니다** |
| SFU + WebSocket 어댑터로 우리가 인코딩 | Worker 에서 불가(Containers 별건) |
| RealtimeKit(합성 녹화 있음) | 화상수업 스택 전체 교체 = D안 |
| complete 실패 때도 스냅샷 되살리기 | 코드가 **일부러** 막아 둔 것 — 「앞부분만 담긴 파일을 완성본인 척 내놓게 된다」 |
| IndexedDB 에 조각을 쌓아 다음 접속 때 올리기 | 미성년자 수업 영상을 브라우저 저장소에 남기는 일입니다. 별건이고 사람이 정할 일 |

## 3. C안 1단계 — Realtime SFU «자격증명 경계» (⛔ 꺼진 채로)

### 무엇을

- `src/realtime-sfu.ts` — 시크릿·신원·방·세션 소유권 **네 가지만** 지키는 프록시
- `POST /api/class/sfu/*` (`api-mango.ts`) — `/api/class/` 는 라우팅 허용목록에 **이미** 있어
  `src/index.ts`(공동 금지구역)를 **한 줄도 안 고쳤습니다.** 인증은 여기서 직접 확인합니다
  (CLAUDE.md 2장 「라우팅 허용목록에 올렸으니 인증도 된 것」)
- `docs/ENVIRONMENT.md` — 시크릿 표 + 켜는 절차 + 요금 + 「SFU 는 녹화를 안 한다」

### 지금은 꺼져 있고, 그게 의도입니다

`REALTIME_APP_ID`·`REALTIME_APP_TOKEN` 이 **둘 다** 없으면 `{ ok:true, enabled:false }` 만
돌려주고 `rtc.live.cloudflare.com` 을 **한 번도 부르지 않습니다.** 서비스 동작이 안 바뀝니다.

### 브라우저 쪽은 «일부러» 안 썼습니다

이 환경은 프록시가 `rtc.live.cloudflare.com`·`developers.cloudflare.com` 을 막고
시크릿도 없어서 **실제 SFU 와 한 번도 맞춰 보지 못했습니다.** 검증 못 한 WebRTC 코드를
수업 경로에 올리는 것이 이 저장소가 겪은 최악의 사고 유형입니다(홈 전체 정지 2회).

같은 이유로 **`tracks/new` 의 본문 «모양» 을 서버에 박아 넣지 않았습니다.** 문서를 못 열었기
때문입니다. 본문은 브라우저와 SFU 가 주고받게 두고 우리는 경계만 지킵니다 —
Cloudflare 자신의 설계 안내(「백엔드가 시크릿을 갖고 사용자를 인증하고 발행·구독을 인가한다」)와
같은 모양이라, 나중에 브라우저 쪽을 쓸 때 이 파일을 고칠 필요가 없습니다.

**확정된 것만 코드에 넣었습니다** — 베이스 URL `https://rtc.live.cloudflare.com/v1/apps/{APP_ID}/…`,
`Authorization: Bearer`, 엔드포인트 넷(`sessions/new`·`tracks/new`·`tracks/close`·`renegotiate`).

### 안전장치 (전부 하니스가 «실제로 돌려서» 확인)

| # | 지키는 것 |
|---|---|
| ① | 시크릿 없으면 `fetch` **0회** |
| ② | 신원 없으면 401 (fetch 0회) |
| ③ | 아는 op **넷만** — 임의 경로 전달(SSRF) 차단 |
| ④ | 세션 id 에 경로 글자가 섞이면 400 |
| ⑤ | 남의 세션·다른 방이면 403 |
| ⑥ | 소유권 확인 불가(KV 없음)면 **막는 쪽**으로 503 |
| ⑦ | 응답 어디에도 시크릿·`Bearer` 문자열이 없다 |
| ⑧ | SFU 실패 시 **상태 코드까지만** — 본문·예외 메시지를 그대로 안 흘림 |

## 5. ⏳ 사람이 확인해야 끝나는 것

이 환경은 프록시가 `mangoi.ai` 를 막아 배포된 화면을 못 봅니다.

1. **A** — 수업이 도는 시간에 관제탑에서 «관찰 N/4» 가 보이는지, 2명이 보고 있을 때
   🎧 소리만 이 진한 버튼이 되는지, 4명이 차면 버튼이 눌리지 않는지
2. **B** — 며칠 뒤 `upload_failed` 건수가 실제로 줄었는지, 남은 실패 행에
   `duration_ms`·`size_bytes` 가 찍히는지
   ```sql
   SELECT date(started_at/1000,'unixepoch','+9 hours') d,
          SUM(status='completed') 성공, SUM(status='upload_failed') 실패
     FROM recordings WHERE status<>'deleted'
      AND started_at >= (strftime('%s','now')-14*86400)*1000 GROUP BY d ORDER BY d;
   ```
3. **C** — Cloudflare 대시보드에서 **TURN 사용량이 무료 1,000GB 중 얼마인지**.
   SFU 는 TURN 과 **합산해 한 줄**로 청구됩니다.
   ⚠️ 지금 시크릿을 넣어도 **화면은 달라지지 않습니다**(브라우저 쪽이 없습니다).
