# 게임 나가기 화살표 3개를 34px 로 통일 (2026-09-02)

## 1. 왜 했나

사장님 「나머지 3개 나가기 화살표도 34px로 키워줘」.

전날 「게임 주소 직접 진입」 작업에서 허브 «밖» 에서 열 때만 나가는 문을 띄웠는데
(`js/game-standalone-exit.js`, **34px** 동그란 ←), **자기 나가는 문을 이미 가진 3개**
(`shooter`·`p38-3d`·`battle-3d`)는 건드리지 않았습니다. 그래서 같은 화면에서 나가는 문의
크기가 게임마다 달랐고, 그 별건을 작업기록 「남은 일」에 적어 두었습니다.

## 2. 🔴 먼저 — 제가 그 「남은 일」에 적은 숫자가 틀렸습니다

작업기록·INDEX 에 「그 셋의 ← 는 **22~23px**」이라고 적었는데, 실제로 재 보니 아니었습니다.

| 게임 | 폰 390 | PC 1280 | 제가 적었던 것 |
|---|---|---|---|
| `shooter` | **35×27** | 35×27 | 22~23px |
| `p38-3d` | 73.3×**31** | 83.6×**36** | 22~23px |
| `battle-3d` | **30×30** | 30×30 | 22~23px |

⚠️ 특히 `p38-3d` 는 **PC 에서 이미 36px** 로 34 를 넘고 있었습니다. 「전부 22~23px 이라
작다」는 제 문장을 그대로 믿고 세 개를 똑같이 조였다면 그 화면은 오히려 **줄어들** 뻔했습니다.
✅ 지시를 받았을 때 **먼저 다시 쟀고**, 그래서 이 어긋남이 드러났습니다.

## 3. 세 파일의 사정이 서로 다릅니다 — 한 규칙으로 쓸어버리면 안 됩니다

| 게임 | 버튼 모양 | 손댄 방법 |
|---|---|---|
| `shooter` | 아이콘만 (`←`) | **34×34 정사각** (`#backBtn.gunbtn`) |
| `battle-3d` | 아이콘만 (`←`) | **34×34 정사각** (`#backBtn.iconbtn`) |
| `p38-3d` | **글자 있는 알약** (`← 나가기`) | **`min-height:34px`** — 정사각으로 만들지 않음 |

⛔ **`p38-3d` 를 34px 정사각으로 조이면 안 됩니다** — 글자가 있는 버튼이라 그 폭에 가두면
낱글자로 쪼개집니다(이 저장소의 「짧은 라벨에 flex 를 썼더니 낱글자로 쪼개짐」 함정과 같은
줄기). 맞추는 것은 «높이» 입니다. 그래서 PC(이미 36px)는 그대로이고 폰만 31 → 34 로 올라갑니다.

⛔ **공용 클래스를 직접 키우지 않았습니다** — 둘 다 `id` 로 좁혔습니다.
- `battle-3d` 의 `.iconbtn` 은 **🔊 음소거(`#muteBtn`)도 씁니다.** 그것까지 키우면 지시 범위
  밖입니다.
- `shooter` 의 `.gunbtn` 은 지금 이 버튼 하나뿐이지만, 그 클래스가 다시 쓰이면 엉뚱한
  버튼까지 34px 정사각이 됩니다.

ℹ️ 세 파일 모두 `*{box-sizing:border-box}` 임을 **먼저 확인**했습니다. `content-box` 였다면
`p38-3d` 의 `min-height:34px` 가 34+16+2 = **52px** 이 됐습니다.

## 4. 🔴 CLAUDE.md 에 적혀 있는 함정을 그대로 밟았습니다

`p38-3d` 의 `<style>` 안 CSS 주석에 **홑낫표 「← 나가기」** 를 썼더니
`admin_lazyload_harness` 가 FAIL 했습니다 — 「한자 없는 화면이 장식 문자로 983KB 폰트를
부르지 않는다」를 그 문자로 판정하기 때문입니다(그 검사는 `<script>` 와 HTML 주석만 벗기고
**CSS 주석은 그대로 셉니다**).

CLAUDE.md 2장에 **이미 두 곳**에 적혀 있는 함정이고(「`<style>` 안 CSS 주석에 「」 를 썼더니」·
「한자 폰트 장식 문자로 FAIL」), 저는 그것을 읽고도 밟았습니다. ✅ `« »` 로 바꿨습니다.
**함정 등재는 그대로 두고 새로 더하지 않았습니다** — 같은 함정을 세 곳에 적으면 한 곳만
고쳐집니다.

## 5. 확인한 것

**게임을 실제로 시작시킨 뒤** 쟀습니다(시작 오버레이가 덮고 있으면 「눌린다」를 잴 수 없습니다).
`shooter` 는 `#startBtn`, `p38-3d` 는 `#btnStart`, `battle-3d` 는 레슨을 눌러 시작했습니다.

- **폰 390 · PC 1280 두 폭 × 3게임 = PASS 24 / FAIL 0**
  — 34px 이상 · `elementsFromPoint` 로 **맨 위** · 누를 수 있는 것/글자 **0** 덮음 · 라벨 **한 줄**
  (`Range.getClientRects()` 로 줄 수를 셉니다 — 쪼개짐 감시)
- **허브(iframe) 안 = PASS 7 / FAIL 0** — 커진 ← 가 게임 HUD 를 덮지 않고, 허브의
  「← 게임 선택」이 여전히 맨 위입니다. `p38-3d` 는 허브 안에서 자기 ← 를 숨기는 것(기존 동작)도 확인.
- **주입되는 나가는 문이 여전히 «안» 생깁니다** — `game-standalone-exit-browser.mjs`
  **PASS 45 / FAIL 0**(③절이 세 게임 모두 `주입=false`). 문이 둘이 되지 않습니다.
- **회귀 하니스** `--fast`: **PASS 260 / SKIP 20 / FAIL 12** — 🔑 **기준선과 대조했습니다.**
  변경 전에도 260/12 였고(`git stash` 로 실제로 두 번 돌려 비교), 12건은 이 컨테이너에
  `cloudflare-deploy/node_modules` 가 없어 나는 환경 사유입니다.
  ⚠️ 처음에는 259/**13** 이었고 **그 1건이 제 변경 때문**이었습니다(4장) — 실패 목록을
  `comm` 으로 대조해 `admin_lazyload_harness` 를 특정했습니다. 「환경 사유겠지」로 넘기지
  않은 것이 이번에 값을 했습니다.
- **`tsc` 는 못 돌렸습니다** — 같은 환경 사유. 이 변경은 `.ts` 파일을 **0개** 건드렸습니다.
- `main` 대비 **삭제줄 1줄**이고 그것도 제 것입니다(`p38-3d` 의 그 규칙 마지막 줄을
  `min-height` 를 더해 다시 쓴 것).

## 6. 남은 일 / 안 한 것

- ⏳ **사장님 화면 확인** — 배포 화면은 프록시에 막혀 못 봅니다.
- 🟡 **`battle-3d` 의 🔊 음소거는 30×30 그대로입니다.** 두 버튼은 `right:8px` 로 오른쪽을
  맞춰 세로로 쌓이므로 **왼쪽 끝이 4px 차이** 납니다(실측). 지시가 «나가기 화살표» 였으므로
  음소거는 건드리지 않았습니다 — 맞추는 편이 나으면 한 줄이면 됩니다.
- ℹ️ `shooter`·`battle-3d` 는 **허브 안에서도 자기 ← 를 보여 줍니다**(허브 문과 둘). 기존
  동작이고 둘 다 «게임 목록으로» 가므로 고장은 아닙니다. `p38-3d` 만 숨깁니다 — 통일할지는
  별건입니다.
