## 1. 왜 했나 — 조사에서 나온 사실 (2026-09-02 실측)

### 🔴 「BTS 5과 문장으로 퀴즈」는 지금 **구조적으로 불가능**합니다

| 잰 것 | 값 |
|---|---|
| 교재 파일 | **17,196장 전부 이미지(JPG)** · 본문 텍스트(`description`) **0건** |
| 영어 본문 표 | **없음** (중국어는 `zh_passage` 14과가 있어 「본문 기반 출제」가 됩니다) |
| `en_vocab` | 76행인데 **교재 칸이 없음**(밴드별 문장 은행) |

즉 교재 안에 무슨 문장이 있는지 **시스템이 전혀 모릅니다.** 그래서 지금 영어 출제의 근거는
**교재 «이름»(「BTS 10 Korea (Weather)」)과 레벨뿐**입니다.

📌 사장님 확인: **BTS 교재는 레벨에 따라 글자 수가 다릅니다 — 낮은 레벨은 적고 높은 레벨은 많습니다.**
⟹ A(OCR) 시험을 낮은 권으로만 하면 「OCR 해도 소용없다」는 **잘못된 결론**이 납니다.
시험 대상은 **낮은 권 + 높은 권 두 개**여야 합니다.

### 🔴 「전체 교재 40문제 은행」 기능은 **이미 있었고, 9분 만에 멈춰 있었습니다**

`source='bank'` 문항 11개가 전부 **2026-06-13 16:45~16:54** 에 만들어지고 그 뒤로 **0건**.
교재는 45개인데 11개에서 멈췄습니다.

원인은 그 기능이 **브라우저 탭에 묶여 있다**는 것입니다 — 화면 스스로
「끝날 때까지 이 탭을 열어두어야 해요」라고 경고합니다. 수십 분 걸리는 작업이라 한 번 끊기면 그대로 끝입니다.

### 🔴 그리고 **생성물 검증이 0**이었습니다

`rqAiGenerate` 의 영어 갈래는 프롬프트로 규칙을 **지시만** 하고 결과를 한 번도 확인하지 않았습니다.
그런데 이 저장소의 반복 실측은 **「지시만으로는 안 지켜진다」** 입니다:

- 판단력 훈련: 「Want play with me」(to 누락)가 보기로 그대로 나감
- AI 영어친구: 길이를 조이자 「You have dog?」 같은 전보문이 나옴

복습퀴즈는 학생이 **정답으로 외우는** 문장이라 그 사고가 더 나쁩니다.

## 2. 무엇을 했나

### `src/quiz-quality.ts` 신설 — 문항 검사기 (정본)

**⛔ 판정 규칙을 새로 쓰지 않았습니다.** 이미 정본이 셋 있고 하니스가 지키고 있어 **불러 쓰기만** 합니다:

| 이어 쓴 정본 | 무엇 |
|---|---|
| `isEnglishQuestion` (english-only.ts) | 중국어·병음 섞임 |
| `aiFriendBrokenQuestions` (ai-friend-level.ts) | 전보문 의문문 |
| `BAND_SPECS` (judgment-level.ts) | 레벨별 단어 수 |

**이 파일만 아는 것** — 프롬프트가 «요구만» 하고 아무도 안 보던 것들:

- 🎧 **listen 문항의 보기에 정답 음성문장이 실제로 있는가** ← 없으면 **정답이 없는 문항**입니다. 학생은 무엇을 골라도 틀리고, 에러는 안 납니다
- `choice` 의 `answer` 인덱스가 보기 범위 안인가 (밖이면 영원히 오답)
- 보기에 같은 값이 두 개인가 (정답이 둘이 됩니다)
- 한 세트 안에 같은 문장이 반복되는가

### 세 호출부의 정책 — 「다 떨어졌을 때」가 자리마다 다릅니다

| 자리 | 정책 |
|---|---|
| 학생 즉석 출제 | 통과분이 0이면 **한 번 더** 뽑고, 그래도 0이면 **`{ok:true, quiz:null}`** |
| 관리자 미리보기 | 통과분 + **탈락 이유**를 함께 (관리자가 프롬프트·레벨을 고칠 수 있게) |
| 은행 생성 | **통과분만** 누적, 탈락 수를 화면에 표시 |

## 3. 검토했다가 버린 것

| 버린 것 | 왜 |
|---|---|
| **중국어에도 검사 적용** | 검사기는 영어용(`isEnglishQuestion`)이라 **전부 떨어집니다.** 중국어는 이미 `zh_vocab` 그라운딩으로 「목록 밖 글자 금지」가 걸려 있습니다 |
| **떨어진 문항을 「그래도 낸다」** | 여기서 걸러지는 것은 «정답이 보기에 없는 문항»·«문법이 깨진 문장» 입니다. 내보내면 학생이 그것을 **정답으로 외웁니다** — 못 주는 것보다 나쁩니다 |
| **학생 경로에서 502 + 영문 코드** | 화면이 그 코드를 그대로 그립니다 — `quiz_quality_failed` 는 학생에게 아무 뜻이 없고 「고장」으로 읽힙니다. `{ok:true, quiz:null}` 로 답하면 그 화면이 **이미 아는 모양**이라 「맞춤 퀴즈가 아직 없어요. 전체 목록을 보여드릴게요」로 그린 뒤 목록으로 데려갑니다 |
| **학생 화면(`idx-x8.js`) 고치기** | 그 파일은 `index.html` 의 **blocking** 스크립트입니다 — **공동 금지구역**이고 첫 화면 예산 여유가 6KB뿐입니다. 실제로 한 번 고쳤다가 **되돌리고** 서버만 바꿨습니다 |
| **재시도를 여러 번** | 학생이 기다리는 경로라 왕복을 늘리면 그게 또 사고입니다. 한 번만 |
| **탈락 수를 감추기** | 감추면 관리자는 「AI 가 4개만 만들었네」로 읽고 프롬프트·레벨을 고칠 기회를 잃습니다 |
| **`active=0` 초안 + 사람 전량 승인** | 45개 교재 × 40문항 = 1,800문항을 사람이 다 검토하는 것은 비현실적입니다. **검사기가 자동 승인 역할**을 하고, 관리자는 탈락 이유를 보며 **표본**으로 판단합니다(기존 검토·수정 화면이 이미 있습니다) |

| **관리자 화면이 거짓 원인을 말했다** | 통과 문항이 0이면 `throw` 가 먼저 나서 서버가 보낸 `dropped`·`raw_count` 가 버려지고 「**Workers AI 응답 문제**」라고 표시 | AI 는 정상 응답했고 **우리 검사기가 떨어뜨린 것**입니다. 「상한을 조이는 변경은 그 실패 경로를 처음으로 «닿게» 만든다」 — 학생 경로는 이 함정을 피해 놓고 관리자 경로에서 놓쳤습니다 |
| **탈락 수가 정작 필요한 분기에서 감춰짐** | `failedBooks === 0` 일 때만 표시 | 은행이 안 차는 상황이 바로 `failedBooks > 0` 인데, 그때 「다시 눌러 재시도하세요」만 나옵니다(다시 눌러도 같은 이유로 또 떨어집니다) |
| **listen 완전일치로 오탈락 가능** | 「I like apples!」와 「I like apples.」가 다른 문장으로 판정 | 채점 정본 `rqNorm` 이 구두점을 지우는데 검사기만 완전일치였습니다 ⇒ 같은 방식으로 맞추고, **「그렇다고 진짜 다른 문장까지 통과시키지 않는가」를 짝으로** 검사 |
| **프롬프트와 검사 상한이 다른 말** | 프롬프트는 레벨 무관 「max 8 words」 고정, 검사기는 레벨별 상한 | 지금은 무해하지만(밴드 1에서만 같고 위로는 프롬프트가 더 엄격) 「여러 곳이 서로 같은 말을 하는가」 관점에서 프롬프트에 실제 상한을 주입 |
