# 화상수업 회선품질을 «회선별» 로 — 사무실 회선이 몇 시에 막히는지 보이게 (2026-09-03)

- 사장님 「필리핀쪽 인터넷라인?? 해결할 방법 없을까」 → 제가 드린 3번 첫 항목
  「IP 별 회선 기록·관리자 표」를 「바로 만들어줘」.
- 바뀐 파일: `cloudflare-deploy/src/net-prefix.ts`(신설) · `src/api-mango.ts` · `src/api-admin.ts` ·
  `public/admin.html` · `test-harness/vc_net_line_harness.mjs`(신설 74건)

---

## 1. 왜 했나

9/3 필리핀 수업 사고를 조사하다 `admin_login_history` 에서 나온 사실:
**강사 계정 약 10개와 매니저 둘(Karl·Melca)이 같은 공인 IP 하나로 로그인**합니다
(216.247.55.144, 8/28 이전엔 216.247.53.158). 즉 **사무실 인터넷 회선 하나를 전원이 나눠 씁니다.**

그런데 회선품질 기록(`vc_quality`)은 **사람(uid)별로만** 남습니다. 그래서

- 「그 회선이 **매일 몇 시에** 막히는가」를 볼 수 없고
- 통신사에 항의할 **시각이 찍힌 근거**를 만들 수 없었습니다.

Farrah 강사 한 사람만 보면 「그 강사 인터넷이 나쁘다」로 읽히는데, 같은 회선의 Hannah·Win·
Krystel 은 9/1 저녁에 멀쩡했습니다(170~190ms). **사람이 아니라 회선·시간대의 문제**일 수 있는데
그것을 가릴 눈이 없었습니다.

## 2. 무엇을 만들었나

| 곳 | 무엇 |
|---|---|
| `src/net-prefix.ts` (신설) | `ipToNet()` — IPv4 는 **/24**, IPv6 는 **/48** 로 잘라 «회선» 문자열을 만든다. `asLabel()` — ASN+조직명(`AS9299 PLDT`) |
| `src/api-mango.ts` | `/api/vc/quality-log` 가 `net`·`isp`·`country` 를 **ALTER 로만** 붙이고 INSERT |
| `src/api-admin.ts` | `/api/admin/vc/quality?by=net` — 회선별 목록 · `&net=…` 을 더하면 **그 회선의 시간대별(KST)** |
| `public/admin.html` | 「📶 강사 회선품질」 카드에 **보기: 사람별 / 회선별**. 회선을 누르면 시간대 표가 펼쳐짐(막대 그래프) |

시간대 표가 이 작업의 핵심입니다 — 「매일 14~16시에 이 회선이 막힌다」가 한 화면에 보이고,
그 표를 그대로 통신사에 보여 줄 수 있습니다.

## 3. 판단한 것과 그 이유

### ⛔ IP 를 통째로 남기지 않았습니다

이 표에는 **학생 29,000명**의 기록도 함께 쌓이고 다수가 미성년자입니다. «어느 회선인가» 를
묶는 데 필요한 것은 네트워크 부분뿐이라 마지막 옥텟(IPv4)·인터페이스 부분(IPv6)을 버립니다.

- 사무실처럼 여럿이 **같은 공인 IP** 를 쓰는 경우는 어차피 값이 완전히 같아 묶임이 안 흐트러집니다.
- 강사·관리자의 **정확한 IP 가 필요하면 `admin_login_history.ip` 에 이미 있습니다**(예전부터 전량 저장).
  그래서 여기서 덜 남겨도 잃는 것이 없습니다.

### ⛔ 본문(요청 body)에서 받지 않습니다

`/api/vc/quality-log` 는 **무인증**입니다(fire-and-forget). 본문에서 `net` 을 받으면 아무나
위조해 남의 회선을 나쁘게 만들 수 있습니다. **서버가 본 값만** 씁니다 —
`CF-Connecting-IP` 헤더와 `request.cf`.

### ⛔ ASN 을 함께 남깁니다

/24 만으로는 부족합니다 — 그 사무실이 실제로 8/28 에 `216.247.53.x` → `216.247.55.x` 로
대역을 옮겼습니다. /24 는 갈리지만 **통신사(ASN)는 같습니다.** 덤으로 통신사 이름을 알 수 있는데,
웹 검색으로는 그 IP 의 통신사를 특정하지 못했습니다.

## 4. 검토했다가 버린 것

| 버린 것 | 왜 |
|---|---|
| 전체 IP 저장 | 학생 29,000명(다수 미성년자)의 정확한 IP 를 새로 쌓게 됩니다. 회선을 묶는 데 필요 없습니다 |
| IP 해시 저장 | 묶이기는 하지만 **통신사·대역을 알 수 없어** 「통신사에 항의」라는 목적 자체가 사라집니다 |
| 새 표 만들기 | 같은 사실을 «묶는 축» 만 바꿔 보는 것입니다. `live=1`(방 단위)이 이미 같은 방식입니다 |
| `net` 을 CREATE 문에 넣기 | `vc_quality` 의 CREATE 가 **두 벌**입니다(`api-mango.ts`·`api-admin.ts`). `IF NOT EXISTS` 는 먼저 실행된 쪽이 이기므로 모양이 갈립니다 — `novideo`·`rx_*` 와 같은 사정이라 ALTER 로만 |
| 빈 `net` 도 한 줄로 그리기 | 이 기능 배포 전 기록은 `net` 이 빕니다. 목록에 끼면 «모름» 이 하나의 «회선» 이 되어 숫자를 오염시킵니다 → 제외 |
| 칸이 없을 때 «조회 실패» | ALTER 는 첫 로그가 들어와야 돕니다. 그건 실패가 아니라 «아직 수집 전» 이라 그렇게 말합니다 |
| 이 값으로 사람 특정·차단 | 같은 /24 에 남남이 섞일 수 있고 한 사무실이 대역을 옮겨 다닙니다. 주석·화면 안내에 못 박았습니다 |

## 5. 확인한 방법

- **신규 하니스 `vc_net_line_harness.mjs` 74건 전부 통과.**
  - `net-prefix.ts` 를 **오려 내 실제로 돌립니다**(타입만 벗겨 `new Function`). 실측 IP
    (`216.247.55.144`·`2406:5900:1003:55cf:...`)를 그대로 넣고, 못 읽는 값 12종이 빈 문자열인지 확인.
  - 집계 SQL 을 **소스에서 오려 내 진짜 SQLite 에 돌립니다** — 회선 두 줄로 묶이는지, KST 시각으로
    갈리는지(UTC 였다면 05시·12시가 나옵니다), 사람 수·통신사·나라가 붙는지.
  - 🪤 **되돌림 시험** — `CASE WHEN avg_loss >= 0` 을 빼면 손실이 실제로 낮게 뒤집힙니다(1.2% → 0.7%).
    그 대조가 없으면 검사가 헛돌아도 알 수 없습니다.
  - 서버 쪽은 «본문에서 안 받는가»·«CREATE 에 안 넣었는가»·«INSERT 칸 수와 물음표 수가 같은가» 를 검사.
- 관련 하니스: `admin_lazyload` · `page_contract` · `schema_drift` · `admin_write_guard` ·
  `hanzi_font` · `asset_version` 전부 통과.
- `run.mjs --fast` — 아래 «검증» 줄.
- tsc — 이 컨테이너에 `cloudflare-deploy/node_modules` 가 없어 못 돌렸습니다. CI 가 대신 돕니다.

## 6. ⏳ 사람이 확인해야 끝나는 것

- **기록은 배포 뒤 첫 수업부터 쌓입니다.** 그 전 기록에는 `net` 이 없어 목록에 안 나옵니다.
  즉 이 화면이 쓸모 있어지려면 **며칠치가 쌓여야** 합니다.
- `request.cf.asOrganization` 이 실제로 통신사 이름을 주는지는 **배포된 워커에서만** 확인됩니다
  (이 컨테이너에는 `request.cf` 가 없습니다). 안 나오면 `isp` 칸이 비고 화면은 «—» 로 그립니다.
- 화면(보기 전환·시간대 표)은 프록시가 `mangoi.ai` 를 막아 제가 못 봅니다.
