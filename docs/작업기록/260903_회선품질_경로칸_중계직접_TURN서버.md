## 2. 거기서 내린 판단

- 「mangoi.ai 라서」가 아니라 **«그날 그 시간» 강사 쪽 경로가 막힌 것**이다(측정: 같은 두 사람이 2분 뒤 60~85ms).
  BODA 수업이 언제였는지는 모르므로 그 비교는 시각이 다르면 성립하지 않는다.
- [추론] 손실은 낮고 RTT 만 1초 = «업로드가 꽉 차서 줄을 서는» 모양. Globe 가 LTE 모뎀이면 LAN 케이블은 뜻이 없다.
- 「오디오 전용」 안내는 코드로 확정 — 오디오 RTT 600ms 초과 12초 지속이면 켜진다(손실 0% 여도).
  「카메라 경고」(`카메라 트랙은 있지만 영상이 안 들어옴`)는 입장 3초 뒤 로컬 카메라 프레임 0 판정이라 **회선과 다른 원인**이다.
- 🔴 **그런데 «경로가 바뀐 것인지 회선이 풀린 것인지» 를 가릴 칸이 이 표에 없었다.** 손실·RTT·수신 4종·p95·peers 까지
  있는데 «어떤 길로 갔는가» 는 0칸. TURN 을 탔는지, Cloudflare 인지 무료 openrelay 인지, 매번 추측으로 끝났다
  (`X-Turn-Source` 는 «발급» 이지 «실제 사용» 이 아니다). ⟹ 이번 작업은 그 사각지대를 메우는 것 하나다.

## 3. 고친 것 (2층 1번 — «중계인지 직접인지 기록하기»)

- **클라이언트** `vcqPathProbe(id, pc)` — 4초 수신 틱마다 `pc.getStats()` 로 선택된 candidate-pair 를 읽어
  local/remote `candidateType` 을 본다. 한쪽이라도 `relay` 면 «중계», 둘 다 host/srflx/prflx 면 «직접».
  내 쪽이 relay 면 `url`·`relayProtocol` 로 TURN 서버 `host:port proto` 를 남긴다(상대만 relay 면 서버는 «모름» — 빈 값).
  바뀔 때만 콘솔 `[vc-path]` 한 줄. 수업 끝 정리에서 `__vcPath` 비움.
- **payload 4칸** — `path`('relay'|'direct'|'mixed'|''), `relay_ticks`, `path_ticks`, `turn`.
  ⛔ **«모름» 은 빈 값이지 'direct' 가 아니다** — getStats 없음·연결 전은 `path_ticks 0` 으로 남겨 화면이 «—» 로 그린다
  (0/0 을 «직접 100%» 로 읽으면 이 칸을 만든 이유가 사라진다. CLAUDE.md 2장 「표본이 없을 때 0 으로 적지 마세요」와 같은 뿌리).
- **서버 쓰기** — ALTER 로만 4칸 추가(CREATE 두 벌 함정 그대로), `path` 는 아는 값 셋만 받고 `turn` 은 글자를 좁혀 96자에서 자름
  (무인증 경로라 본문이 곧 남의 손이고 관리자 화면에 그대로 그려진다).
- **서버 읽기** — 집계에 `relay_ticks`·`path_ticks`·`turn` 추가. 칸이 없는 DB 는 기존 폴백(옛 질의)으로 떨어진다.
- **관리자 화면** 「📶 강사 회선품질」에 **「🛰경로」** 칸 — 직접(초록) · 중계(보라) · 혼합 N%(주황) + 작은 글자로 TURN 서버.

## 4. 검토했다가 버린 것

| 버린 것 | 왜 |
|---|---|
| 모름을 'direct' 로 기본값 | 위 ⛔ — 옛 브라우저·연결 전 학생 전원이 «직접» 으로 찍혀 경로 통계가 거짓이 된다 |
| candidate-pair 의 `currentRoundTripTime` 도 함께 저장 | 이미 `avg_rtt`(remote-inbound-rtp) 가 있다. 두 RTT 가 갈리면 다음 사람이 어느 것을 믿을지 모른다 |
| 서버에서 `turn` 을 그대로 저장 | 무인증 POST 라 임의 문자열이 관리자 화면에 그려진다 → 글자 제한·길이 제한 |
| `live=1`(관제탑) 집계에도 경로 추가 | 관제탑은 «지금 흔들리나» 를 보는 눈이라 경로는 사후 진단용 표에만. 필요하면 별건 |
| 2층 2~4번(낮게 시작·둘째 탭 경고·안내 문구) 함께 | 사장님이 1번만 고르셨다. 1번은 «다음 사고 때 원인을 잡는 도구» 라 제일 값이 싸다 |
