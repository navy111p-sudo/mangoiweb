## 2. 🔴 이번에는 왜 SQL 집계를 그대로 써도 되는가

C안(지출 정리)은 `canView` 를 못 걸어 **행을 읽어 코드로** 셌습니다.
여기는 다릅니다 — 범위를 **`canView` 가 무조건 통과시키는 두 가지**로만 잡습니다:

1. **경영진** → 세 열람등급(`exec`·`chain`·`broadcast`)을 **전부** 통과합니다
2. **그 밖** → **본인이 올린 것만** (`canView` 첫 줄 「내가 올린 건은 언제나 본다」)

그래서 SQL 이 준 행이 곧 «볼 수 있는 행» 이고 거를 것이 없습니다.
하니스가 그 전제 자체를 **`canView` 를 실제로 불러** 확인합니다(경영진은 남의 인사·급여를 보고,
직원은 못 본다 — 넷).

> ⛔ **이 조건을 «본사 직원은 전체» 로 넓히지 마세요.** 그 순간 인사·급여가 요약으로 샙니다.
> 바로 앞 PR(C안)에서 정확히 그 유출이 있었고, 하니스가 그 변이를 잡습니다.

## 3. 검토했다가 버린 방법

| 안 한 것 | 왜 |
|---|---|
| **요약을 위해 API 를 하나 더 부르기** | 이 화면은 「첫 화면 API 한 번」 설계입니다 → 이미 받는 `/api/approval/home` 안에 실었습니다 |
| **「진행 중」을 화면의 `mine` 으로 세기** | `mine` 은 최근 **15건**뿐이라 16번째부터 조용히 빠집니다 → SQL `COUNT` 로 정확히 |
| **「진행 중」도 경영진은 전체로** | 그 칸은 「**내가 올린 것**이 어떻게 됐나」입니다. 넓히면 뜻이 달라집니다 |
| **금액 타일을 모두에게 전체로** | 직원이 남의 지출 총액을 보게 됩니다 → 경영진만 전체, 그 밖은 내 것, **그리고 화면이 어느 쪽인지 적습니다** |
| **범위를 감추기** | 경영진과 직원이 같은 타일에서 **다른 숫자**를 봅니다. 안 적으면 둘 중 하나는 거짓입니다 |
| **통화를 합쳐 하나로** | 환율을 우리가 모릅니다(C안과 같은 규칙 — `repMoney` 를 그대로 씁니다) |
| **금액 없는 승인을 0원으로** | 「모른다」와 「0원」은 다른 사실 → 「금액 없음 N건」 |
| **경고 줄을 늘 그리기** | 늘 뜨는 경고는 아무도 안 읽습니다 → 없으면 안 그립니다 |
| **달 눈금을 새로 정하기** | 지출 정리와 다른 달로 자르면 사람이 숫자가 안 맞는다고 느낍니다 → **같은 규칙**(지출일 우선) |

### 🔴 그리고 감추지 않은 것

「손봐야 할 것」은 **최근 15건 안에서만** 찾은 것입니다.
그보다 많이 올렸으면 더 있을 수 있으므로, 화면이
**「진행 중 30건 가운데 최근 15건만 살펴본 것입니다」**라고 말합니다.
안 적으면 「손봐야 할 것 1건」이 거짓이 됩니다.

## 4. 검사에서 걸린 것

| 무엇 | 어떻게 |
|---|---|
| SQL 이 **삼항 연산자로 나뉜 템플릿**이라 «글자» 로 오리면 JS 조각이 섞여 SQLite 가 문법 오류 | 식 전체를 잘라 **`new Function` 으로 평가** — 범위 조건까지 정본이 만들게 |
| 범위 조건을 빼는 변이에서 **검사가 통째로 죽음**(바인드 수 불일치) | `try/catch` 로 **깔끔한 FAIL** 로 남깁니다(2장 「버튼 없을 때 click」과 같은 함정) |
| 「진행 중을 최근 15건으로 세기」 변이가 **통과** | 시험 데이터에서 두 값이 **같았습니다** → `my_open 30` · 화면 1건으로 **다르게** 만들어 확인 |
| 「금액 없는 건을 0으로」 변이가 통과 | 그 자리에서는 **동작이 같았습니다**(검사 이름이 과장) → 이름을 바로잡고 **NaN 유입** 검사를 짝으로 추가 |
| `topGo` 검사를 «앞 N자» 로 자름 | 함수만 **중괄호 짝**으로 잘라 그 안을 봅니다 |
| 🔴 **내 검사 하나가 헛돌았습니다** — 「화면이 `mine_shown` 이 아니라 `my_open_shown` 으로 비교하는가」를 «파일 어딘가에 그 이름이 있는가» 로 물었더니, **바로 위에 제가 쓴 설명 주석**이 그 낱말을 갖고 있어 되돌리는 변이가 **그대로 통과**했습니다 | 판정을 **그 값을 정하는 대입문 한 줄**로 옮겼습니다(주석 줄은 제외). 되돌리면 이제 **2건 실제 FAIL** |

### 🔴 함정 대조(`trap-check`)가 잡은 것 — 셋은 **거짓말하는 화면**이었습니다

| 무엇 | 잰 것 | 고침 |
|---|---|---|
| 🔴 **「금액 없음 N건」이 «금액 칸이 아예 없는 종류» 까지 셌습니다** | 같은 데이터에서 D안 **6건** 대 C안 **0건** — 긴급·휴가·문서는 금액을 받지도 않는데 「금액 없음」으로 셌습니다. 게다가 제 주석은 「C안과 같은 규칙」이라고 **틀리게** 적혀 있었습니다 | 지출성 종류만 세도록 SQL 에 `instr(?, ','⎪⎪req_type⎪⎪',')` 를 걸었습니다(⛔ `map(() => '?')` 는 이 저장소가 금지 — 콤마 문자열 한 개로 바인딩) |
| 🔴 **「최근 15건만 봤다」 안내가 «다른 모집단» 과 비교하고 있었습니다** | `mine_shown`(모든 상태 15건) 대 `my_open`(진행 중만) — 진행 중 12건이 창 밖에 있어도 **조용**했고, 15건 중 진행 중이 6건뿐이면 **없는 누락을 알렸습니다** | `my_open_shown`(화면에 보이는 «진행 중» 수)으로 바꿔 같은 모집단끼리 비교합니다 |
| 🔴 **그 안내가 «손봐야 할 것이 있을 때만» 떴습니다** | `if (stuck.length)` 블록 «안»에 있어서, 정작 필요한 「멈춘 게 안 보이는데 창 밖에 더 있다」일 때 **사라졌습니다** | 블록 밖으로 뺐습니다 |
| **조회가 실패해도 «0» 으로 보였습니다** | 「모른다」와 「0건」은 다른 사실입니다 | `money_unknown`·`open_unknown` 을 실어 화면이 **«—»** 로 그립니다 |
| **결재함이 20건에서 잘리는데 그대로 «N건»** | `inbox` 는 상한 20 | 상한에 닿으면 **`20+`** 와 「적어도 이만큼」 |
| 요약 계산이 **304 «앞»** 에 있었습니다 | 안 바뀐 화면에도 D1 조회 두 번 | 304 return **밑**으로 내렸습니다 |
| **글자 대비가 4.5 미만**(3.46~4.49) | 타일의 범위 줄(`.tn`)·라벨(`.tl`), 특히 강조 카드 위 | 색을 조정하고, 브라우저 검사가 **타일 전부를 밝게·어둡게 두 번** 훑도록 넓혔습니다(한 자리만 재고 「안전하다」로 끝내지 않기) |
