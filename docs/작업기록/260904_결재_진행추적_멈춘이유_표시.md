## 2. 무엇을 했나

### 서버 — `src/api-approval.ts`

* **`approverCounts()` 신설** — 「이 건들을 **지금 결재할 수 있는 사람이 몇 명인가**」를 센다.
  기존 `approversFor()` 와 같은 규칙(`canDecideStage` + 기안자 제외)을 쓰되
  **계정 조회는 한 번만** 한다.
* `/api/approval/home` 의 `mine` 중 **대기 중인 건에만** `approver_count`·`blocked` 를 얹는다.
* **ETag 에 hq 계정 수를 넣었다**(`a3-` → `a4-`) — 안 넣으면 경영진을 추가해도
  「바뀐 것 없음(304)」으로 옛 화면이 최대 1시간 남는다.

### 화면 — `public/work.html`

* **진행바**(`trackHtml`) — 올림 → 단계마다 → 완료. 상태별 색(승인 초록 · 진행 앰버 ·
  반려/멈춤 빨강). **내가 올린 건에만** 그린다.
* **「N일째」** — 「대기 중」만으로는 며칠 지났는지 알 수 없어 숫자를 함께 적는다.
* **「이대로는 처리되지 않습니다」**(`stuckHtml`) — 서버가 «0명» 이라고 알려 준 건에만.
  막힌 단계 이름과 이유(본인 결재 금지)를 함께 말한다.
* **「멈춤」 칩** + `hot` 테두리 — 지연(`Overdue`)과 **다른 사실**이라 따로 센다.

## 3. 검토했다가 버린 방법 ← 여기가 이 문서의 핵심

| 버린 방법 | 왜 |
|---|---|
| **화면이 «막힘» 을 스스로 판정** | 화면은 계정 목록도 결재 규칙도 모른다. 추측하면 「승인할 사람이 없습니다」라는 **틀린 말**을 사람에게 하게 된다. 서버가 세서 내려준다 |
| **건마다 `approversFor()` 호출** | 목록 15건이면 D1 조회가 15번 나간다. 필리핀 회선에서 그대로 대기 시간이 된다 → 계정 조회 **1회** + 메모리 계산 |
| **저장된 단계 역할을 «지금 정책» 으로 다시 판정** | 9/2 에 정책이 바뀌었으니 옛 건도 `any` 로 보면 «풀린 것처럼» 보인다. 그러나 그건 **역사를 덮어쓰는 것**이고, 왜 5일을 서 있었는지가 사라진다 |
| **D1 `UPDATE` 로 그 건의 role 을 고쳐 풀기** | 개발·운영이 같은 DB다(CLAUDE.md 1-1). 운영 데이터 변경은 사람이 결정할 일 |
| **경영진 계정을 코드로 추가** | 급여·회계를 여는 권한이다. 누구에게 줄지는 **사장님이 정할 일** |
| **새 API 경로 신설** | `src/index.ts` 라우팅 허용목록은 **공동 금지구역**(4-2). 기존 `/api/approval/home` **응답에 필드만 얹어** 금지구역을 한 줄도 안 고쳤다 |
| **서버가 «며칠째» 를 계산해 내려주기** | 응답이 매초 달라져 **304 가 영영 안 나온다**. 이 API 의 설계 취지가 그것이라(주석에 명시) 지연 판정과 같이 **화면이** 센다 |
| **결재함(`inbox`)에도 진행바** | 거기는 «내가 지금 눌러야 할 것» 이라 버튼이 더 중요하다. 화면만 길어진다 |
| **`stuckHtml` 을 모든 대기 건에** | 그러면 정상적으로 기다리는 건까지 「처리되지 않습니다」라고 겁을 준다 |

  CLAUDE.md 2장에 있는 그 함정을 쓰는 도중 밟아 `« »` 로 바꿨다.
