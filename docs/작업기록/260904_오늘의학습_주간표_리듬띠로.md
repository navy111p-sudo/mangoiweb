# 「오늘의 학습」 주간표를 «이번 주 리듬 띠» 로 (2026-09-04)

## 1. 왜 했나

사장님이 `/today.html` 의 「이번 주」 칸을 빨간 동그라미로 표시한 스크린샷과 함께
「이거 샘플 4개 보여줘. 이해하기 쉽고 직관적으로 보이게」라고 하셨습니다.

그 칸은 이랬습니다 — 요일 아래에 도구 이모지를 2~3개씩 뭉쳐 놓고, 표 밑에 범례를
한 줄로 눌러 두었습니다.

```
 일    월    화    수    목    금    토
🎤   🤖⚡🧭  🤖⚡  🤖⚡🧭  🤖⚡  ✍️⚡  🎤🎮
 집    집   🏫    집   🏫    집    집
```

🎤 가 음성코치인지 🧠 가 복습퀴즈인지 알려면 범례를 읽어야 합니다. 그래서
「오늘 뭐 하지」에는 답이 되는데 — 그건 바로 위 「오늘 할 일」 카드가 이미 맡고 있고 —
정작 이 칸이 있어야 할 이유인 **「이번 주가 어떻게 흘러가지」에는 답을 못 했습니다.**

## 2. 네 가지를 만들어 보여 드림

같은 학생(화·목 수업 · 오늘은 금요일) 기준으로 넷을 실제 앱 색으로 그려
아티팩트로 보여 드렸습니다 — <https://claude.ai/code/artifact/64d3aff0-becf-4632-ab69-54fc03e035a9>

| 안 | 무엇이 바뀌나 | 좋음 | 아쉬움 |
|---|---|---|---|
| A 요일마다 한 줄 | 이모지를 글자로 —「🏫 웜업 → 수업 → 복습퀴즈 · 25분」 | 범례 불필요 · 순서까지 보임 | 세로 7줄이라 자리를 많이 씀 |
| B 칸은 그대로, 오늘만 펼침 | 7칸 유지 + 이모지 대신 막대, 아래에 오늘 할 일을 번호로 | 지금 크기 그대로 «오늘» 만 확실히 | 다른 날은 여전히 안 보임 |
| **C 이번 주 리듬 띠** | 수업일 = 진한 파랑(🏫 19:00) · 집 = 옅은 초록(분 수) + 요약 칩 | 학부모가 「일주일에 몇 번, 몇 분」을 한 줄로 | 무슨 도구인지는 안 나옴 |
| D 두 묶음으로 | 표를 버리고 「학원 가는 날 / 집에서 하는 날」 두 카드 | 가장 단순 · 규칙을 바로 이해 | 요일별 차이(금요일 글쓰기)가 사라짐 |

**사장님이 「추천한 대로」 = C 를 기본으로 + 오늘 칸만 B 처럼 펼치기** 를 고르셨습니다.

## 3. 무엇을 했나

- **정본**(`src/today-plan.ts`) — `WeekDay` 에 두 칸을 더했습니다.
  - `start: string | null` — 수업일의 시각 라벨. **수업일이 아니면 언제나 null**
  - `minutes: number` — 그날 `tools` 의 `TOOLS[k].minutes` **합**(지어낸 값이 아니라 계획의 합계)
- **입력**에 `weekClassTimes?: Record<number,string>` 추가.
  ⛔ 이 값으로 «수업일인가» 를 판정하지 않습니다 — 정본은 여전히 `weekClassDows` 하나이고,
  `buildWeek` 이 **dows 에 없는 요일의 시각은 버립니다.**
- **API**(`api-students.ts`) — `class_schedules`(정기·날짜지정)와 카페24 씨앗에서
  요일별 «가장 이른» 시각을 모아 넘깁니다.
- **화면**(`today.html` · `js/today-page.js`)
  - 띠 7칸 — 파랑 = 학원 수업일(`🏫` + 시각) · 초록 = 집(`N분`) · 금색 테두리 = 오늘
  - 오늘 칸만 아래 상자에 **도구 이름을 글자로**(`1. 🎤 AI 음성코치 — 7분`)
  - 요약 칩 `🏫 수업 2회` · `🤖 AI 약 140분` — **주간표를 그대로 센 값**
  - 안내 한 줄이 «색» 을 설명합니다(범례를 읽게 하지 않습니다)
- 사용법 문서 6절의 캡처와 설명을 **새 화면으로 다시 떴습니다**(HTML·PDF 둘 다).
  하루 전 병합한 문서라 그대로 두면 캡처를 믿을 수 없게 됩니다.

## 4. 검토했다가 버린 것

- **화면에서 분 수를 계산하기** — 서버가 정한 `tools` 와 화면의 합이 언젠가 어긋납니다.
  판정은 서버, 화면은 그리기만 — 이 화면의 처음 원칙 그대로입니다.
- **`weekClassTimes` 로 «수업일» 을 판정하기**(dows 를 버리기) — 정본이 한 벌로 줄어드는
  것처럼 보이지만, 시각을 못 읽은 수업(=`start_time` 이 빈 행)이 통째로 «집» 이 됩니다.
- **요약 칩에 🔥 연속일 넣기** — 아티팩트 C 안에는 있었는데, 위 카드 칩에 이미 있어
  한 화면에 같은 칩이 두 번 나옵니다. 뺐습니다.
- **수업일 칸에도 분 수 적기** — 칸이 좁아 「🏫 19:00 25분」이 세 줄이 됩니다.
  주간 합계는 요약 칩이 말합니다.
- **네 안을 다 만들어 고르게 하기(설정)** — 고르는 화면이 하나 더 생기고, 그걸 아무도
  안 건드리면 결국 기본값 하나만 쓰입니다.

## 5. 🔴 함정 대조 검사가 잡은 진짜 결함 — 「오늘 칸」이 바로 아래 상자와 다른 말을 함

병합 «전에» `trap-check` 를 돌렸고, 그것이 이 변경의 진짜 결함 하나를 찾았습니다.

띠의 오늘 칸은 `w.minutes`(= `w.tools` 의 합)를 그리는데, 바로 아래 펼침 상자는
`p.steps` 를 나열합니다. **두 값의 출처가 다릅니다.** `buildTodayPlan` 은 레벨이 없으면
(`band == null`) steps 를 «레벨테스트 + AI 친구» 로 통째로 바꾸는데, `buildWeek` 은
그 분기를 모르고 `HOME_WEEK` 를 그대로 씁니다.

```
band=null · 금요일 →  띠 「14분」   /   상자 「🎯 레벨테스트 10분 · 🤖 AI 친구 7분」(17분)
```

상자 제목이 「금요일 · 오늘」이라 «이 칸을 풀어 쓴 것» 으로 읽히는데 숫자가 다릅니다.

⚠️ **예외가 아니라 «거의 전원» 입니다** — 2026-09-04 운영 D1 실측(SELECT 만):

```sql
SELECT COUNT(*), SUM(level IS NOT NULL AND TRIM(level)<>'') FROM students_erp
→ 29,475명 중 레벨 있음 1명
```

**이 변경이 만든 사고는 아닙니다** — 고치기 전에도 오늘 칸이 🗣️🧠⚡ 를, 카드는 🎯🤖 를
보여 주는 같은 어긋남이 있었습니다. 이번 변경은 그 이모지 충돌을 오히려 없앴고,
숫자로 바뀌면서 어긋남이 «정확히» 보이게 됐습니다.

✅ 고침 — 정본에 `todayFromSteps()` 를 두어 **오늘 칸을 실제 steps 로 맞춥니다.**
⛔ 반대로 고치지 마세요(steps 를 week 에 맞추기) — 「오늘 할 일」의 정본은 steps 입니다.

함께 고친 것(같은 검사의 지적):

- **`noteTime` 의 정규식이 `hhmmToMin` 보다 좁았습니다**(`\d{2}:\d{2}` 대 `\d{1,2}:\d{2}`).
  `'9:00'` 이면 헤더는 「오늘 9:00 수업」인데 띠 칸만 조용히 빕니다 → 폭을 맞췄습니다.
- **하니스가 «실제로 흔한 모양» 을 한 번도 안 그렸습니다** — 둘 다 `band:3` 으로만 돌아
  `mode:'unassigned'`·`isToday && isClass`·`start === null` 이 한 번도 렌더되지 않았습니다.
  ①-7c 5가지 × 3검사 + 브라우저 «레벨 미배정» 절을 더했습니다.
- **브라우저 검사에 `serviceWorkers: 'block'` 이 없었습니다** — 지금 구조에서는 안 물리지만,
  변이시험은 `?v=` 를 안 올린 채 파일을 고쳐 돌리는 작업이라 정확히 그 함정 자리입니다.
- **범례가 «드는 시간» 이라고 말했습니다** — `ToolSpec.minutes` 주석은 「실제 소요와 무관한
  권장 눈금」인데 문구가 측정처럼 읽혔습니다 → 「그날 하기로 한 AI 학습 시간」으로.

## 6. 고치면서 밟은 것

- **CSS 주석의 홑낫표** — `<style>` 안 주석에 「」 를 8자 썼더니
  `admin_lazyload_harness` 가 「한자 없는 화면이 장식 문자로 983KB 폰트를 부른다」로
  FAIL 냈습니다. CLAUDE.md 2장에 이미 적혀 있는 함정이고 또 밟았습니다 → `« »` 로.
- **브라우저 검사가 «정상» 을 «쪼개짐» 으로 읽음** — 수업일 칸은 `🏫`(display:block) 때문에
  `.v` 가 두 줄인 것이 정상인데, 상자를 통째로 재니 늘 2가 나왔습니다.
  진짜 쪼개짐(「19:」/「00」)을 보려면 **값 글자 그 자체(마지막 텍스트 노드)** 를 재야 합니다.
  FAIL 이 나면 검사 쪽을 먼저 의심하라는 그 항목입니다.
