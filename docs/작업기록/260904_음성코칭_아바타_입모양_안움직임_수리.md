# 음성 코칭 — 아바타 입모양이 안 움직이던 것 수리 (2026-09-04)

> 사장님 제보: 「아바타 입모양이 움직이지 않아」 (음성 코칭 화면, `mangoi.ai/speech-coach.html`,
> 5번째 문장 「Thank you very much for your help.」 화면)

---

## 1. 무엇이 잘못됐나

**서버 TTS 로 소리가 나는 모든 갈래에서 아바타 그리기 루프가 «시작조차» 안 되고 있었습니다.**

`MangoAvatar.attach(audioEl)` 는 이름과 달리 **음량 분석 그래프를 잇기만** 합니다.
캔버스에 그리기를 «켜는» 것은 **`plainStart()` 뿐**인데, 음성 코칭의 서버 TTS 경로
(`speakWord()`·`speakTarget()`)에는 그 호출이 **한 줄도 없었습니다.**

```js
// 고치기 전 — 두 곳에 똑같이 복제돼 있었다
if (!ttsAudio) { ttsAudio = new Audio(); ttsAudio.preload = 'auto';
                 if (window.MangoAvatar) MangoAvatar.attach(ttsAudio); }
ttsAudio.src = url;
await ttsAudio.play();          // ← plainStart() 가 없다 → 그리기 루프가 안 돈다
```

비교하면 다른 두 화면은 **둘 다** 부르고 있었습니다 — 즉 **이 화면만 빠져 있었습니다.**

| 화면 | attach | plainStart |
|---|---|---|
| `warmup.html` | ✅ | ✅ (재생 직전) |
| `ai-friend.html` | ✅ | ✅ (`playing` 이벤트) |
| **`speech-coach.html`** | ✅ | ❌ **없음** (브라우저 음성합성 폴백에만 있었음) |

### 왜 여태 안 드러났나 — 「가끔은 움직여」

커리큘럼 5문장은 **미리 만든 립싱크 클립**(`playClip`)으로 재생되는데, 그 함수는
**자기 안에서** 그리기를 켭니다. 그래서 **Emma 를 고르고 그 다섯 문장만 들으면 멀쩡해 보였습니다.**
멈추는 것은 그 밖의 전부였습니다 — 직접 입력한 문장 · 다른 친구(Lily·Noah·Jake) · 단어 하나 듣기.

### 문자열 하니스가 못 잡는 종류

`attach` 도 «있고» 오디오도 «재생»됩니다. 빠진 것은 «그리기를 켜는 한 줄» 뿐이라
**수리 전에도 회귀 하니스 264건이 전부 초록이었습니다.**

---

## 2. 덤으로 나온 것 — 물린 오디오가 «입을 굳히는» 문제

`attach()` 로 한 번 물린 오디오 요소는 **영영 `boundEl` 로 남습니다.**
그 뒤 브라우저 음성합성(speechSynthesis)으로 말하면, 그리기 루프가
«멈춰 있는 그 오디오» 를 보고 **「말 안 하는 중」으로 판정해 입을 다문 채 굳히고 5초 뒤 그리기를 끕니다.**

즉 음성 코칭에서 **영어를 한 번 들은 뒤에는 한국어 문장도 입이 안 움직였습니다.**

---

## 3. 고친 것

### `speech-coach.html`
- 복제돼 있던 `ttsAudio` 생성 **두 곳을 최상위 함수 `scEnsureTtsAudio()` 한 곳으로** 모으고,
  거기서 `attach` 와 아바타 배선을 **요소당 한 번만** 겁니다.
  - `playing` → `plainStart()` · `ended`·`pause`·`error` → `plainStop()`
- `speakFallback` 의 `u.onstart` 를 **`plainStart({ analyzed: false })`** 로.

### `js/mango-avatar.js` (v8)
- `plainStart(opts)` 가 옵션을 받습니다. `analyzed:false` 는 «이 소리는 물린 오디오가 아니다» 라는 뜻이고,
  그동안은 `boundEl` 을 보지 않고 폴백 애니메이션을 씁니다.
- **인자 없이 부르면 종전 동작 그대로** — `warmup.html`·`ai-friend.html` 의 기존 호출은 영향 없음.
- 🛟 **그 분기에 «끝» 을 놓쳤을 때의 경계를 함께 넣었습니다**(함정 대조 지적).
  `analyzed:false` 분기에는 위쪽 «5초 무음» 안전망이 없어서, `plainStop` 이 유실되면
  (크롬의 `speechSynthesis` `onend` 유실은 알려진 문제) **소리 없이 입만 계속 움직입니다** —
  이 파일이 2026-07-26 에 일부러 좁혀 둔 「말은 안 하는데 입만 움직인다」 그 모양입니다.
  ⛔ 새 타이머를 만들지 않고(상주 `setInterval` 금지) **이미 도는 rAF 안에서** 셉니다.
  ⚠️ **틱이 아니라 «시간»(700ms)으로** 셉니다 — rAF 속도가 기기마다 다릅니다
  (헤드리스 실측 **약 10fps**, 보통 화면 60fps. 틱으로 세면 느린 기기에서 몇 초씩 늦게 멈춥니다).

### 캐시
- `mango-avatar.js` 를 싣는 **세 화면 전부** `?v=16` → `?v=18`(안전망을 넣느라 한 번 더 바뀌었습니다).

## 4. 검토했다가 «안» 한 것

| 안 한 것 | 이유 |
|---|---|
| `plainStart()` 를 `play()` **직전**에 부르기 | 소리가 실제로 나기 전에 입이 움직이면 「말은 안 하는데 입만 움직인다」가 됩니다 — `mango-avatar.js` 가 2026-07-26 사고로 적어 둔 바로 그 문제. **`playing` 이벤트**에서 부릅니다. |
| `speakWord`·`speakTarget` 각각에 두 줄씩 넣기 | 지금도 복제 때문에 한쪽만 고쳐지는 사고가 났습니다. 세 번째 호출부가 생겨도 저절로 적용되도록 **한 곳으로** 모았습니다. |
| 루프가 «물린 오디오가 멈춰 있으면» 폴백 애니메이션으로 알아서 넘어가게 하기 | 그러면 「말은 안 하는데 입만 움직인다」가 되살아납니다. 말하는 쪽이 **명시적으로 알려 주는** 방식(`analyzed:false`)을 골랐습니다. |
| `warmup.html`·`ai-friend.html` 도 함께 고치기 | **지시 범위 밖**이라 손대지 않고 보고만 합니다(CLAUDE.md 4-1-1). 아래 5장. |

---

## 5. 아직 안 고친 것 (사람이 정할 일)

같은 뿌리의 결함이 다른 두 화면에 남아 있습니다. 이번 변경으로 **고칠 수단(`analyzed:false`)은 생겼습니다.**

- **`warmup.html`** — 서버 TTS 는 정상. 다만 speechSynthesis 폴백이 `plainStart()` 를 인자 없이 불러,
  서버 TTS 를 한 번 들은 뒤에는 **입이 굳습니다.** (한 줄이면 고쳐집니다)
- **`ai-friend.html`** — 서버 TTS 는 정상. 기기 목소리 폴백 때는 `plainStart` 자체가 안 불려
  **아바타가 아예 안 움직입니다.**

## 7. 재는 과정에서 밟은 함정 (CLAUDE.md 2장에 추가함)

측정 쪽이 틀려서 **고쳐 놓은 화면을 «안 고쳐졌다» 고 한 번 오판했습니다.**

1. **검사 서버가 Range(206)를 안 주면** `<video>` 의 `seekable` 이 `[[0,0]]` 이 되어
   아바타 입모양의 **타임스탬프 seek 이 통째로 씹힙니다.** `readyState` 는 4 이고
   `buffered` 는 `[[0,8]]` 인데도 `currentTime = 4.0` 이 **0 그대로**였습니다.
   → 검사 서버에 206 을 넣자마자 같은 코드가 네 갈래 전부 통과했습니다.
   (`python3 -m http.server` 는 Range 를 안 줍니다)
2. `new Audio()` 는 **DOM 에 안 붙습니다** — `document.querySelector('audio')` 가 못 찾고,
   이 화면에는 `<audio id="speech-voice">` 가 따로 있어 **엉뚱한 요소를 잡고도 그럴듯한 값**을 돌려줬습니다.
3. `let ttsAudio` 는 `window` 에 안 붙습니다 — `window.ttsAudio` 는 늘 `undefined`,
   **bare `ttsAudio`** 로 읽어야 합니다.
