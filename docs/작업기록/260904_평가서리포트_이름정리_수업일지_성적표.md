# 평가서·리포트 이름을 「오늘 수업일지」·「월간 성적표」로 — 점수 만점 표기도 함께

- 날짜: 2026-09-04
- 작업자: 사장님 지시 + Claude Code
- 브랜치: `claude/assessment-report-difference-yuy3xa`

---

## 1. 왜 했나

사장님이 홈 전체메뉴 그리드에서 **「평가서」와 「리포트」 타일을 동그라미 쳐서** 물으셨습니다.

> 「평가서와 리포트는 같은 거야 다른 거야? 이게 둘다 뭐지 들어가보니 이상해」

확인해 보니 **서로 다른 화면이 맞는데**, 이름만으로는 그것을 알 수 없었습니다.
그리고 들어가 보면 «이상해» 보이는 이유가 넷이었습니다.

| 무엇 | 실측 (2026-09-04 운영 D1) |
|---|---|
| 이름이 둘 다 «성적 종이» 라는 뜻 | 「평가서」=낱장 · 「리포트」=한 달치 합본인데 이름에 그 말이 없음 |
| 볼 것이 거의 없음 | 두 화면이 읽는 «진짜 1분 수업일지» 행이 **107건 중 5건** (나머지 102건은 `student_uid` 가 빈 옛 스키마라 두 화면 다 안 읽음) |
| 사장님 계정으로는 로그인 창부터 뜸 | 두 화면은 학생 세션(`mangoi_logged_user`)만 본다. `jeong` 은 관리자 폴백이라 그 키가 없다 — **고장이 아니라 설계** |
| 점수 만점이 틀림 | `report.html` 이 「/10」으로 못 박아 두었는데 실제 척도는 **1~5 아니면 0~100** |

### 🔴 마지막 항목이 이번에 새로 찾은 결함입니다

`student_evaluations.score_overall` 은 **한 칸에 두 척도**가 섞여 들어옵니다.

- 강사 1분 수업일지 — `/api/eval/create` · `/api/eval/bulk-create` → **1~5**
- AI 수업 리포트 — `/api/eval/ai-lesson-report`(`api-lessons.ts:848`, `overall_score` 0~100) → **0~100**

실측: 1~5 행 3건(delaware×2 · heyst) · 0~100 행 2건(honggildong 88·84).
그래서 「/10」은 **두 갈래 어느 쪽도 아닌 숫자**를 학부모에게 보여 주고 있었습니다.

그리고 그 옆에서 `eval.html` **목록이 통째로 안 그려지는** 버그가 딸려 있었습니다 —
별점을 `'☆'.repeat(5 - Math.round(88))` 로 그리는데 이것이 실제로 던집니다.

```
$ node -e "'☆'.repeat(5-88)"
RangeError: Invalid count value: -83
```

즉 **0~100 척도 행이 목록에 하나만 있어도 그 학생의 수업일지 목록이 전부 안 보였습니다.**
에러는 콘솔에만 나고 화면에는 「목록을 불러오지 못했습니다」로만 보입니다.

## 2. 무엇을 바꿨나

사장님이 네 가지 이름 쌍 중 **1안**을 고르셨습니다.

| | 낱장 (`/eval.html`) | 월간 합본 (`/report.html`) |
|---|---|---|
| KO | **오늘 수업일지** | **월간 성적표** |
| EN | Today's Lesson Note | Monthly Report Card |

「오늘」·「월간」이라는 **기간 단어가 이름 맨 앞**에 와서 나란히 놓였을 때 차이가 한눈에 보이게 한 것이 고른 이유입니다.

| 파일 | 바꾼 것 |
|---|---|
| `cloudflare-deploy/public/js/idx-allmenu.js` | 전체메뉴 타일 이름 + `en:` 필드. 라벨 span 에만 `data-ko`/`data-en` |
| `cloudflare-deploy/public/eval.html` | 제목·머리글·로그인 문구·목록·낱장·꼬리말. **`evalMax()`·`evalOn5()` 신설** — 만점을 값에서 읽고 별점을 0~5 로 맞춤 |
| `cloudflare-deploy/public/report.html` | 제목·머리글·로그인 문구·통계 타일. **「/10」 → `evalMax()`** |
| `cloudflare-deploy/public/js/idx-ai-home.js` | 홈 검색 라벨. **kws 는 «옛 말 + 새 말» 을 모두 받음** |
| `cloudflare-deploy/public/admin/site-structure-map.html` | 그 두 화면의 잎 이름 4곳 |
| `cloudflare-deploy/public/index.html` | **`?v=` 숫자 두 개만**(allmenu 11→12 · ai-home 12→13). 바이트 증가 **0** |
| `test-harness/eval_report_naming_harness.mjs` | **신설** — 아래 4절 |

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### ⛔ 옛 낱말을 검색어에서 빼기
`idx-ai-home.js` 의 `kws` 에서 `'평가서'`·`'리포트'` 를 지우면 **그 말로 찾던 사람이 못 찾습니다.**
label 만 새 이름으로 바꾸고 kws 는 옛 말·새 말을 **둘 다** 받게 했습니다. 하니스 ③절이 이것을 못 박습니다.

### ⛔ i18n 사전(`js/i18n-sweep.js`)을 고치기
그 파일의 `REPL` 에 「님의 학습 평가서」·「평가서 #」 같은 옛 문구가 들어 있습니다.
고치면 맞지만 **42개 화면이 그 파일을 함께 싣고 있어** `?v=` 를 42곳 올려야 하고,
무관한 화면 40개가 이 PR 에 딸려 들어옵니다.
→ 대신 바뀐 문구에 **`data-ko`/`data-en` 을 직접** 달았습니다(사전 없이도 EN 이 됩니다).
남은 옛 REPL 항목은 이제 아무것도 안 잡는 **죽은 항목**입니다 — 해롭지는 않지만 5절에 남깁니다.

### ⛔ 만점을 `/5` 로 못 박기
「/10」이 틀렸다고 `/5` 로 바꾸면 **0~100 행이 「88 / 5점」** 이 됩니다. 새 거짓말을 만드는 것입니다.
→ **값에서 척도를 읽습니다**(`> 5` 이면 100점 만점). 임의의 숫자로 «환산» 하지 않고 만점을 그대로 말합니다.

### ⛔ 행을 조인해서 두 갈래를 가르기
`ai_lesson_reports.evaluation_id` 로 가르는 것이 원리상 맞지만,
**실측에서 그 칸이 2건 모두 비어 있어** 조인이 성립하지 않습니다(`api-lessons.ts` 가 채우지 않습니다).
그래서 «행» 이 아니라 «값» 으로 판정합니다.

### ⛔ `data-ko`/`data-en` 을 타일 `<a>` 나 아이콘에 달기
두 i18n 엔진이 그 요소의 `textContent` 를 **통째로 갈아끼웁니다** → 사진이 사라지고 글자가 들어앉습니다
(CLAUDE.md 2장 「아이콘 버튼에 달았더니」). **글자만 담은 span** 에만 답니다.
하니스 ①절이 «`<a>` 에는 안 단다» 를 함께 검사하고, 변이시험에서 실제로 FAIL 합니다.

### ⛔ 홈 드로어의 「📋 평가표(성적표)」까지 손대기
`index.html` 4667·7164 행이 **공동 금지구역**이고, `js/mg-sidebar.js` 63 행에 같은 라벨이 한 벌 더 있습니다.
한쪽만 고치면 **홈과 나머지 26개 화면의 드로어가 서로 다른 말**을 하게 됩니다.
→ 손대지 않고 5절에 남깁니다(둘 다 `/report.html` 로 가고 「성적표」라는 말이 이미 들어 있어 모순은 아닙니다).

## 4. 확인한 방법

### 회귀 하니스 — **깨끗한 `main` 과 나란히** 잼
이 컨테이너에는 `cloudflare-deploy/node_modules` 가 없어 esbuild 의존 하니스가 환경 사유로 실패합니다.
그래서 «내 탓인가» 를 가리려고 `git worktree` 로 **`origin/main` 사본을 따로 만들어 같은 검사를 돌렸습니다.**

| | PASS | SKIP | FAIL |
|---|---|---|---|
| 깨끗한 `origin/main` | 261 | 20 | 13 |
| 이 브랜치 | **262** | 20 | 13 |

FAIL 13건은 **두 사본이 똑같고**, 13건 전부 `esbuild`·`node_modules` 없음이 원인임을 하나씩 실행해 확인했습니다.
PASS 가 1 늘어난 것은 이번에 더한 하니스입니다.

> ⚠️ 처음 한 번은 `PASS 260 / SKIP 21` 이 나와 「기준선 이탈」 경고가 떴습니다.
> 다시 돌리니 261/20 으로 `main` 과 같았습니다 — **흔들린 한 번**이었고, 두 사본의 SKIP 목록을 `comm` 으로 대조해 차이가 0인 것을 확인했습니다.

### 타입체크
**돌리지 못했습니다** — `node_modules` 가 없습니다(환경 사유).
다만 이번 변경에 **TypeScript 파일은 한 개도 없습니다**(전부 `public/` 밑 HTML·JS).

### 새 하니스 — `test-harness/eval_report_naming_harness.mjs` (30종)
「여러 곳이 서로 같은 말을 하는가」로 검사합니다. 타일 · 화면 제목 · 홈 검색 · 사이트 구성표 네 곳을 대조하고,
만점 계산은 **문자열이 아니라 두 파일에서 함수를 오려 내 실제로 돌려** 같은 답을 내는지 봅니다.

**변이시험 6종 전부 진짜 FAIL 이 났습니다**(안 그러면 검사가 헛돌고 있는 것입니다).

| 되돌린 것 | 결과 |
|---|---|
| 타일 이름을 「평가서」로 | FAIL 1 |
| `report.html` 을 「/10」으로 | FAIL 2 |
| 목록 별점을 옛 `repeat()` 로 | FAIL 2 |
| 홈 검색에서 옛 낱말 `'평가서'` 제거 | FAIL 1 |
| 두 화면의 만점 판정을 서로 다르게 | FAIL 1 |
| `data-ko` 를 `<a>` 카드에 달기 | FAIL 1 |

### 브라우저 실측 (헤드리스 크로미움 + 로컬 서버) — **14종 전부 통과**
「있다」가 아니라 **«화면에 무슨 글자가 나오는가»** 를 쟀습니다.

- 전체메뉴 타일이 「오늘 수업일지」·「월간 성적표」로 그려지고, 옛 이름은 안 나온다
- 두 타일에 `data-ko`/`data-en` 이 달려 🌐 를 눌러도 따라온다
- **0~100 행(88점)을 섞어도 목록이 그려진다** — 옛 코드는 여기서 죽었다
- 낱장에서 1~5 행은 「종합 / 5점」, 0~100 행은 「종합 / 100점」
- 별점이 **언제나 5칸**
- 성적표에서 「/10」이 사라지고 `5/5`·`88/100` 으로 나온다

> 🪤 처음엔 CDP `Fetch` 스텁으로 쟀는데 헛돌아 «멀쩡한 코드가 FAIL» 로 나왔습니다.
> `Page.addScriptToEvaluateOnNewDocument` 로 **`fetch` 를 문서 로드 전에 덮는** 방식으로 바꾸니 통과했습니다.
> 그리고 한 검사는 목록에 안 그려지는 `student_name` 을 찾고 있어 거짓 FAIL 이었습니다 — **검사 쪽이 틀린 경우**였습니다.

### ⚠️ 확인하지 못한 것
**배포된 실제 화면은 못 봤습니다** — 이 환경의 프록시가 `mangoi.ai` 를 막습니다.
위 브라우저 검증은 **같은 파일을 로컬 서버로 띄워** 잰 것입니다. 병합·배포 뒤 사람이 한 번 봐야 끝난 것입니다.

## 5. 남은 것 / 주의할 것

1. **홈 드로어 라벨 「📋 평가표(성적표)」는 그대로입니다** — `index.html` 4667·7164 행(공동 금지구역)과 `js/mg-sidebar.js` 63 행.
   둘 다 `/report.html` 로 갑니다. 바꾸려면 **세 곳을 한꺼번에** 해야 합니다(한쪽만 고치면 홈과 나머지 26개 화면이 다른 말을 합니다). **사장님 판단이 필요합니다.**
2. **성적표의 「평균 점수」 타일은 아직 만점이 없습니다** — `buildMonthlyReportData`(`src/api-reports.ts`)가 **두 척도를 섞어 평균**을 냅니다.
   한 달에 두 갈래가 같이 있으면 5 와 88 의 평균이 46.5 가 되어 뜻이 없습니다. 서버를 고쳐야 해서 **별건**으로 남겼고 `report.html` 주석에 적어 두었습니다.
3. **`js/i18n-sweep.js` 의 REPL 항목 세 개가 죽었습니다** — 「님의 학습 평가서」·「의 평가서」·「평가서 #」.
   화면 글자를 바꿔 이제 아무것도 안 잡습니다. 해롭지는 않지만, 그 파일을 다른 일로 만질 때 함께 정리하면 좋습니다.
4. **볼 것이 거의 없는 것은 그대로입니다** — 강사가 1분 수업일지를 거의 안 써서 **진짜 일지가 3건**뿐입니다(홍길동 2건은 데모).
   이름을 고쳐도 「들어가 보니 비어 있다」는 남습니다. 이건 코드가 아니라 **운영** 쪽입니다.
5. **관리자 계정으로 열면 여전히 학생 로그인 창이 뜹니다** — 두 화면은 학생 전용 세션만 봅니다. 설계대로이고 이번에 손대지 않았습니다.
