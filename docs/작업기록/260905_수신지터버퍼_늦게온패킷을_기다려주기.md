## 1. 왜 했나 — 처음엔 «화질 복원» 을 만들고 있었습니다

사장님이 처음 요청하신 것은 **허깅페이스 AI 얼굴복원**이었습니다. 만들어 드린 뒤 사장님이
물으셨습니다 — 「내가 원하는 것은 멈춤·끊김이 없는 것인데, 이것이 그것과 상관없어?」

**거의 상관없었습니다.** 뭉개짐(화질)과 끊김(연결)은 다른 문제이고, AI 복원은 CPU 를 더 먹어
오히려 끊김을 악화시킵니다(2026-09-02 에 「녹화가 인코더와 CPU 를 나눠 쓴다」로 강사 자동녹화를
껐던 그 자리). **질문을 먼저 여쭙지 않고 코드부터 만든 것이 잘못이었습니다.**

그래서 방향을 바꿔 **먼저 쟀습니다.**

## 3. 무엇을 고쳤나

`tuneReceiveLatency(pc, good)` 가 **2상태**(low / auto)였습니다:
- `low` — 회선이 «지금 정말 좋다» → 지연 0 (대화 최우선)
- `auto` — 그 외 전부 → `null` = 브라우저 자동

필리핀·중국 회선은 `low` 조건(RTT 150ms 미만)에 **구조적으로 절대 안 맞아** 항상 `auto` 였습니다.
그리고 **버퍼를 «키우는» 쪽은 아예 없었습니다.**

**3상태로 넓혔습니다** — `low` / `auto` / **`buf`**(300ms).

```
buf 조건:  rb >= 300        (그 연결의 «기준 RTT» 가 구조적으로 멀다)
        || __qLate >= 3     (지금 rttDown 을 넘긴 지 3틱 = 12초)
```

- ⚠️ 대가는 **지연 +300ms** 입니다. 그래서 «먼 회선»·«지금 막힌 연결» 에만 겁니다.
- 🔴 **정정** — 처음에 「가까운 회선은 한 글자도 안 바뀝니다」라고 적었는데 **사실이 아닙니다.**
  `__qLate >= 3` 은 `rb` 와 **무관하게** 걸리므로, 국내 회선(rb=80)도 450ms 초과가 3틱 이어지면
  `buf` 가 됩니다(판정식을 돌려서 확인). 정확히는 **「기준 RTT 가 멀거나, 지금 3틱 막힌 연결」**
  입니다. 심각도를 낮추는 문장은 다음 사람이 믿고 다시 안 보므로 바로잡습니다.
- 시험 손잡이: `window.__vcRxBufMs` (0 = 끔)

## 4. ⛔ 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| **비트레이트를 더 낮추기** | 원인이 손실이 아니라 지연입니다. 더 낮춰도 «늦게 오는 것» 은 그대로입니다 |
| **AI 화질 복원 붙이기** | 뭉개짐이지 끊김이 아니고, CPU 를 더 먹어 **반대 방향**입니다 |
| **defer 파일에서 `window.__vcTuneReceiveLatency` 를 감싸기** | 내부 호출은 **지역 바인딩**(`tuneReceiveLatency(...)`)이라 전역을 덮어도 **안 걸립니다.** CLAUDE.md 의 `mark()`/`__vcRejoinMark` 함정과 같은 자리 |
| **defer 파일에서 독립 루프로 receiver 를 직접 만지기** | `tuneReceiveLatency` 와 **서로 싸웁니다.** 게임 허브의 «`pointerdown` 자동정지 대 `click` 토글» 사고와 같은 모양 |
| **버퍼를 RTT 에 비례해 «연속» 조절** | 매 틱 재설정 = **소리가 튑니다.** 그 함수 주석이 스스로 경고하는 것이고, 2026-09-01 class-1015 사고가 정확히 그것이었습니다. 그래서 **상태를 셋으로 양자화**했습니다 |
| **200~300ms 구간(끊김 9.6% · 117분)까지 넣기** | 지연을 300ms 더하는 대가가 그 이득에 맞는지는 **사람이 정할 일**입니다. 배포 뒤 `rx_conceal` 이 실제로 내려가는 것을 보고 정합니다 |
| **`playoutDelayHint` 만 쓰기** | 표준은 `jitterBufferTarget` 이고 **단위가 다릅니다**(ms 대 초). 둘 다 맞춰 씁니다 |
| **SFU 로 옮기기** | CLAUDE.md 가 「1:1 수업에 안 닿는다 · 사람이 정할 일」로 못 박았습니다. 실측도 `peers` 평균 1 입니다 |

## 5. 🪤 만들면서 밟은 함정

**① 첫 화면 예산 138B 초과** — 주석을 길게 썼더니 넘쳤습니다. CLAUDE.md 규칙대로
(「설명이 길면 코드에는 한 줄 포인터만」) 본문을 하니스 머리말로 옮겨 통과.
🔴 **정정** — 그때 「여유 599B」라고 적었는데 **틀렸습니다.** 하니스는 `Math.round(bytes/1024)` 로
**KB 반올림 비교**를 하므로 FAIL 문턱은 1,613,312B 이고 실제 여유는 **1,111B** 입니다
(안전한 쪽으로 틀렸지만 틀린 값입니다). 이 변경이 쓴 양은 `idx-main.js` **+1,654B** 이고,
그중 **약 1,091B(45%)가 주석**입니다 — 그만큼 쓸 값어치가 있는지는 사람이 정할 일입니다.

**② 하니스가 함수 시그니처를 «글자 그대로» 못 박고 있었습니다** —
`/function tuneReceiveLatency\(pc, good\)/`. 상태를 셋으로 넓히자 **보장은 세졌는데 검사만**
빨간불. 「뜻으로 묻도록」 고쳤습니다(`\(pc,\s*\w+\)`).

**③ 검사 정규식이 «호출부» 대신 «함수 정의» 를 잡았습니다** — `[\s\S]{0,400}?` 가 본문 안의
`');'` 까지 삼켜서, 멀쩡한 코드가 FAIL 났습니다. 인자에 `; { }` 가 없다는 성질로 좁혔습니다.

**④ 🔴 변이시험 하나가 «통과» 했습니다** — 「손잡이 값을 바꾸면 다시 걸린다」 검사에서 이전
상태를 `'buf300'` 이라고 **손으로 적어** 뒀더니, 상태 키에서 ms 를 빼는 변이(`'buf'`)에서도
이전 값과 달라 **«다시 걸린 것처럼» 보였습니다.** ⟹ **같은 연결에 두 번 걸어서** 확인하도록
고쳤고, 그러자 실제로 FAIL 합니다.

**⑤ 🔴 먼 회선이 `buf` ↔ `low` 로 뒤집혔습니다** (함정 대조가 잡음, 커밋 뒤 수정) —
`low` 게이트에 `rtt === 0` 탈출구가 있고, 먼 회선은 `rttUp = rb+100` 이라 `__qGood >= 8` 을
쉽게 채웁니다. 그래서 **RTT 보고가 빠진 틱마다** 300ms → 0ms 로 재설정되어, 그 함수 주석이
경고하는 «불필요한 재설정 = 소리 튐» 이 **하필 이 기능이 겨냥한 인구(rb≥300)** 에서 났습니다.
전에는 진폭이 0↔null 이라 덜 아팠고, 제 변경이 0↔300ms 로 키운 것입니다.
⟹ low 게이트에 **`rb < 300`** 한 조건을 더했습니다(rb≥300 이면 `rtt < 150` 은 원래 불가능하므로
«RTT 를 못 잰 틱» 이라는 그 구멍만 정확히 막습니다). ⛔ 그 조건을 빼지 마세요.
🪤 **하니스가 이걸 못 잡은 이유**: 1-c 절이 호출부를 «문자열로만» 봤습니다. 이제 식을 오려 내
**실제로 돌립니다**(가드를 빼면 2건 실제 FAIL).

**⑥ `?v=` 를 한 곳만 올렸습니다** — `teacher.html` 의 미리받기 목록에 `?v=49` 가 남아
**아무도 안 쓰는 851KB 를 필리핀 강사가 미리 받는** 상태가 됐습니다.
`home_bg_preload_harness` ⑦이 잡아 줬습니다.
