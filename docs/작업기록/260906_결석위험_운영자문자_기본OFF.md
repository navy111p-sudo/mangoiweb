## 1. 왜 했나

사장님 지시: 「01089862224 나에게 학생 입장 문자오는 것 안오게 해줘 / 멈추게 해줘」

첨부해 주신 문자 스크린샷이 이랬습니다.

```
[Web발신]

· 현주아 19:30 수업 (+15분 미입장)
```

**「학생 입장」 안내가 아니라 «결석 위험» 알림**이었습니다. `src/absent-sweep.ts` 가 15분 cron 으로
「시작 +10~40분 사이인데 학생이 아직 입장하지 않은」 수업을 찾아 `OWNER_ALERT_PHONE` 으로 요약 1통을
보내는데, **학생이 조금 늦게 들어오는 흔한 경우까지 전부 걸려** 수업 시간대마다 문자가 갔습니다.

⚠️ 제보를 받았을 때 문자 «문구» 로 소스를 찾은 것이 빨랐습니다 — 「학생 입장」으로 grep 했다면 못
찾았을 것입니다. 사장님이 주신 스크린샷의 마지막 줄(「학부모 발송 OFF 관리자 확인용」)이

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

| 버린 방법 | 왜 버렸나 |
|---|---|
| **`OWNER_ALERT_PHONE` 시크릿을 지운다** | 제일 간단해 보이지만 **결제·환불·이상 로그인·사이트 장애(uptime)·방 갈림 감시견이 같은 번호**를 씁니다(전수 grep: `api-pay.ts` 7곳 · `api-pay-refund.ts` · `auth-admin.ts` 2곳 · `api-uptime.ts` 4곳 · `room-split-guard.ts` 2곳 · `api-admin.ts` 1곳). 그것들까지 조용히 끊깁니다. |
| **감지·기록까지 끈다** | 「왜 수업이 성립하지 않았나」가 함께 사라집니다. 규칙서가 못 박은 「노쇼 기록을 지우지 마세요」와 정면으로 부딪힙니다. 결석 위험은 관리자 › 노쇼 리포트에 그대로 쌓여야 합니다. |
| **담당 강사 알림도 함께 끈다** | 사장님이 안 받겠다고 하신 것이지 강사가 안 받아도 된다는 뜻이 아닙니다. 그 알림은 2026-08-07 실사고(강사가 빈 방을 30분 지킴)의 대책입니다. |
| **코드에서 아예 지운다** | 되돌릴 길이 없어집니다. KV 스위치면 배포 없이 한 줄로 되켭니다. |
| **감지 창(+10분)을 늘려 덜 걸리게 한다** | 문자 양은 줄지만 사장님 요청은 「안 오게」였고, 늦게 오는 학생 판정을 흔들면 강사 알림·노쇼 리포트까지 함께 바뀝니다. |

### 🔴 함정 대조(`trap-check`)가 잡은 것 — 첫 커밋이 스스로 만든 결함 3건

이 셋은 **제가 만들었고, 하니스도 타입체크도 전부 초록이었습니다.**

1. **「강사에게 못 보냄 + 사유」 줄이 아무 데도 안 가게 됐습니다.**
   `ownerLines` 를 소비하는 곳이 운영자 문자 **하나뿐**이라, 그것을 끄자 그 줄이 통째로
   사라졌습니다. 소스 주석은 「조용히 넘기지 않는다」고 말하는데 실제로는 조용히 넘겼습니다.
   → 꺼져 있어도 `owner_sms.unsent_lines` 로 cron 로그·진단 응답에 남깁니다.

2. **그 죽은 경로를 «지킨다»며 초록불이던 검사.**
   「`ownerLines.push(...)` 하는 코드가 있는가」만 봤습니다. **「닿는 곳이 있는가」로** 바꿨습니다.

3. 🔴 **「강사 알림은 그대로」를 지키는 검사가 헛돌았습니다.**
   `!/ownerMode[\s\S]{0,400}?sendEmail/` 이었는데, 강사 알림 블록을 `if (!dry && ownerMode)` 로
   바꿔 **스위치가 강사 알림까지 삼키게 만들어도 38/38 전부 초록**이었습니다
   (실측 거리 **759자**(메일)·**1,486자**(문자)로 둘 다 창 밖).
   하필 **이 PR 이 가장 크게 약속한 것**을 지키는 검사였습니다.
   → 규칙서대로 **중괄호 짝으로 «감싸는 블록» 을 함수 경계까지 거슬러 올라가** 조건을 모읍니다
   (`enclosingConds()`). 「반대로 운영자 문자는 그 스위치가 실제로 감싼다」를 **짝으로** 뒀습니다.

그 밖에 이른 `return` 을 없애 `if (ownerMode) / else` 로 바꿨고(뒤에 정리 코드가 붙으면 OFF 인
날에만 조용히 건너뛰어집니다), 「dry run 에서 보인다」는 부정확한 주석을 고쳤습니다
(그 자리는 `!dry` 조건 «안» 이라 dry run 에서 실행되지 않습니다).
