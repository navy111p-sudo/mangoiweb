# 결재 — 회수한 건을 「없었던 것으로」 지우기

**2026-09-06** · 사장님 「그냥 삭제 버튼도 필요할 것 같아. 내려보내서 그냥 없었던 것으로.
내가 상신을 했는데 보니까 굳이 필요가 없더라고 … 그럼 이 파일이 삭제되어야 하는데」

## 1. 무엇이 문제였나

전날 ①회수를 넣었더니 **회수한 건이 목록에 계속 남았습니다.**
「이 내용으로 다시 올리기」만 있고 **없앨 방법이 없었습니다** — 사장님 화면에 회수된 두 건이
그대로 쌓여 있었습니다.

## 2. 🔴 왜 «회수된 건만» 지울 수 있나

회수는 **아무도 결재 도장을 안 찍은 상태**입니다. 결재선에 판단이 하나도 안 남았으니
그건 「올렸다가 거둬들인 초안」이고, 회사 기록으로서 가치가 없습니다 — 지워도 잃을 게 없습니다.

⛔ **지우면 안 되는 셋**:

| | 왜 |
|---|---|
| **승인된 건** | 돈이 나갔거나 **바깥으로 나갔습니다**(휴가→예약 차단, 인사·급여→달 잠금). 그건 ③ **취소 결재**가 할 일입니다 |
| **반려된 건** | 결재자가 **「아니오」라고 판단한 기록**입니다. 기안자가 지울 수 있으면 **«반려당한 적 없는 것처럼»** 만들 수 있습니다 |
| **대기 중인 건** | 지금 **남이 보고 있습니다.** 먼저 회수해야 합니다 |

⚠️ 「회수 → 삭제」 **두 단계인 것이 맞습니다** — 회수는 되돌릴 수 있고 삭제는 못 되돌립니다.

## 3. 사장님이 짚으신 「파일」 — 맞았습니다

[잰 것 — 2026-09-06 운영 D1] 그때 회수된 두 건(#2·#4)은 **첨부가 없었습니다**(`file_key` 둘 다 NULL).
첨부가 있는 건은 Karl 의 승인 건 하나뿐(`approval/…-vctzr1.jpg`, 194KB).

**하지만 앞으로는 있습니다.** 그래서 삭제할 때 **R2 첨부와 `approval_steps` 이력까지 함께** 지웁니다 —
안 지우면 지운 결재의 영수증 사진만 저장소에 고아로 남습니다.

## 4. 🔴 지우는 «순서»

1. **행을 조건부로 먼저** — `WHERE id=? AND status='withdrawn' AND requester_username=?`.
   그사이 상태가 바뀌었으면 **0행이 되고 아무것도 안 잃습니다.**
2. 그 뒤에 `approval_steps` 와 **R2 첨부**를 치웁니다.

⛔ **뒤집으면 안 됩니다** — R2 를 먼저 지우고 ①이 0행이면
**「결재는 남았는데 영수증만 사라진」** 상태가 됩니다(「첨부 보기」가 깨집니다).

⚠️ 지금 순서에서 R2 삭제가 실패하면 **고아 파일이 남습니다.** 조용히 넘기지 않고
`console.error` 로 크게 남기고, **화면도 「첨부는 지우지 못했습니다」라고 말합니다** —
「지웠습니다」라고만 하면 저장소에 남은 것을 아무도 모릅니다.

⛔ 열쇠는 **접두사를 확인**하고 지웁니다(`isApprovalFileKey`) — 그 칸에 다른 것이 들어 있으면
엉뚱한 파일을 지우게 되고 **되돌릴 수 없습니다**(녹화 파기가 `rec/` 를 확인하는 것과 같은 이유).

## 4-2. 🔴 작업기록을 쓰다 찾은 구멍 — 「지연을 지우는 우회로」

원본을 지우면 **그것을 이어받아 다시 올린 건**(`origin_id` 로 가리키는 자식)의
`origin_created_at` 이 NULL 이 되어 **「6일째」가 오늘로 초기화됩니다.**

⟹ **«회수 → 다시 올리기 → 원본 삭제»** 가 곧 **지연을 지우는 길**이 됩니다.
전날 ①②를 만들 때 막으려던 **바로 그 구멍이 다시 열립니다.**

✅ 그래서 **이어받은 결재가 있으면 원본을 못 지웁니다** —
화면·서버가 「이 건을 이어받아 다시 올린 결재가 있어 지울 수 없습니다」라고 말합니다.

⚠️ 이 경우는 사장님이 말씀하신 시나리오(「올렸는데 필요 없어서 취소」)와 겹치지 않습니다 —
그때는 다시 올리지 않았으므로 그냥 지워집니다.

## 4-3. 🔴 함정 대조가 잡은 것 — 「모르면 막는다」가 빠져 있었습니다

| 지적 | 무엇이 문제였나 | 고침 |
|---|---|---|
| **`has_child` 가드가 fail-open** | 자식 조회를 `safe(…, null)` 로 감싸 **조회가 실패하면 «없다»** 로 떨어졌습니다 → 삭제가 그대로 진행되어 4-2 에서 막으려던 우회로가 **한 번의 D1 흔들림으로** 다시 열립니다. 게다가 `hasResubmitChild?` 가 optional 이라 **안 넘기면 안전장치가 꺼진 것이 기본값**이었습니다 | 정본 `canDelete` 가 `null`·`undefined` 를 **`lookup_failed`** 로 거절(503). 서버는 `try/catch` 로 «모른다» 를 그대로 넘깁니다 |
| **TOCTOU** | 상태·소유자는 조건부 DELETE 의 WHERE 가 한 번 더 보는데 **자식 여부만** SELECT 시점 판정뿐 — 그 사이에 「다시 올리기」가 들어오면 부모가 지워집니다 | WHERE 에 `AND NOT EXISTS (SELECT 1 … origin_id = approval_requests.id)`. 0행이면 **재조회해서 «자식이 생겼다»(403) 와 «상태가 바뀌었다»(409) 를 갈라** 말합니다 |
| **하니스 검사가 헛돌았음** | 「삭제 버튼은 회수된 건에만」을 `'withdrawn'[\s\S]{0,400}askDelete(` **거리**로 재서, 버튼을 블록 **밖**(모든 건에 그림)으로 옮겨도 253자라 **통과**했습니다 | 중괄호 짝으로 그 블록을 잘라 **«안에 1개 · 밖에 0개»** 를 셉니다(변이 C 가 실제로 FAIL) |
| **화면이 자식 있는 건에도 「삭제」를 그림** | 「되돌릴 수 없습니다」라고 말해 놓고 서버가 403 — 누른 «뒤» 에 거절받는 흐름 | 세 SELECT 가 **`has_child`** 를 뽑고(rowOf) 화면은 버튼 대신 이유를 적습니다. ⚠️ 한 SELECT 만 빠져도 **그 화면에서만** 버튼이 뜨므로 하니스가 셋을 대조 |
| **404·409 에 문구가 없음** | 지운 뒤 한 번 더 누르면 404 → 「지우지 못했습니다」 — **성공한 조작이 실패로 읽힘** | `DEL_MSG` 한 표로 모든 실패 경로에 문구 |
| **R2 고아를 사람이 찾을 길이 없음** | 이 저장소의 R2 청소기는 `rec/`·`recordings/` 만 치우고 **`approval/` 은 아무도 안 치웁니다**. 행이 사라져 `/file` 로도 못 닿는데 화면은 「본사에 알려 주세요」라고만 했습니다 | 실패 시 응답에 **`file_key`** 를 실어 화면이 그 이름을 보여줍니다 — 사람이 R2 대시보드에서 지울 수 있게 |
| **회수의 기존 fail-open** | `anyDecided` 도 `safe(…, null)` — 단계 조회가 실패하면 **도장 찍힌 건도 회수**되고, 이제 그 뒤 삭제까지 이어져 **결재자의 판단 기록이 통째로 사라질 수 있습니다** | 회수도 모르면 503 `lookup_failed` |
| **브라우저 fixture 자기모순** | 새 회수 건 id **110** 이 `mineCancelled.cancelled_by_id: 110`(=106 을 취소시킨 결재)과 겹쳤습니다 — 회수된 건은 남을 취소시킬 수 없습니다. 그리고 `mine` 에 **반려 건이 없어** 「반려 건에 삭제 안 뜸」이 브라우저에서 확인되지 않았습니다 | 111 로 옮기고 반려(112)·자식 있는 회수(113) fixture 추가 |

⚠️ **사람이 정할 것으로 남긴 것** — ① 삭제 흔적을 D1 에 한 줄도 안 남깁니다(`console.log` 뿐 — Workers 로그는 보존이 짧습니다). 「없었던 것으로」와 「나중에 어디 갔나 물을 수 있게」 사이의 선택입니다 ② 회수 알림이 아직 안 나간 채 지우면 `push_queue` 의 `/work?id=` 링크가 빈 화면으로 갑니다(id 는 AUTOINCREMENT 라 **남의 건으로 가는 일은 없습니다**) ③ 주간 리포트의 「올라온 결재 N건」에서 올렸다 회수하고 지운 건이 빠집니다(합은 맞습니다).

## 5. 검토했다가 버린 것

| 안 한 것 | 왜 |
|---|---|
| **목록에서 «감추기»**(soft delete) | 사장님이 원한 것은 「없었던 것으로」이고, 감추면 **R2 파일이 그대로 남습니다** |
| **대기 건에서 바로 삭제** | 지금 남이 보고 있습니다. 회수가 먼저이고, 두 단계인 것이 오히려 안전합니다 |
| **승인·반려 건 삭제** | 2장 — 기록을 지우게 됩니다 |
| **삭제 이력을 표로 남기기** | 「없었던 것으로」와 정면으로 어긋납니다. **서버 로그 한 줄**만(⛔ 제목·본문은 안 남깁니다) |
| **관리자가 남의 건 삭제** | 남의 결재를 지울 수 있으면 그 자체가 사고입니다 |
