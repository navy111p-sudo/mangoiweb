# 학생 자동녹화 «최대한 가볍게» — 해상도가 아니라 «그리는 fps» 를 낮췄다

- 날짜: 2026-09-06
- 지시: 사장님 「학생 자동녹화 진행하지만 최대한 가볍게 해줘」
- 고친 파일: `cloudflare-deploy/public/js/mango-rec.js` · `cloudflare-deploy/public/index.html`(`?v=` 한 줄)
- 감시: `test-harness/rec_teacher_skip_harness.mjs` ⑧절 신설(9종 → 전체 25종)

---

## 1. 왜 했나

2026-09-02 에 **강사** 자동녹화를 껐습니다(`isStaffSkipRecording`). 남은 것은 학생 쪽 한 벌인데,
사장님이 그것도 켜 두되 부하를 더 줄여 달라고 하셨습니다.

바로 앞 대화에서 「학생 폰 자동 녹화 꺼줘」가 먼저 나왔다가, **끄면 서버에 아무것도 안 남는다**는
사실(브라우저가 굽는 구조 — Cloudflare 에는 WebRTC 녹화 기능이 없습니다)을 확인하신 뒤
**「끄지 말고 가볍게」로 방향을 바꾸셨습니다.**

---

## 2. 잰 것 — 무엇이 낭비였나

`makeComposeStream()` 의 `draw()` 는 `requestAnimationFrame` 으로 돕니다 = **화면 주사율(보통 60fps)**.
그런데 그 밑에서 `composeCanvas.captureStream(15)` 는 **초당 15장만** 가져갑니다.

⟹ **그린 것의 3/4 이상을 그리자마자 버리고 있었습니다.**

그 CPU 는 남는 것이 아닙니다 — WebRTC 실시간 영상 인코더와 **같은 CPU** 입니다
(CLAUDE.md 「수업이 흐리고 소리가 끊긴다」 줄이 그 사슬을 적어 두었습니다).

---

## 3. 검토했다가 버린 방법

| 방법 | 왜 안 했나 |
|---|---|
| **해상도를 1280×720 → 960×540 으로** | 🔴 `CONTENT_W` 가 896 → 672px 로 줄어 **교재 글자를 잃습니다.** 그리고 파일에 이미 경고가 있습니다 — 「글꼴(13~20px)·탭바 32px·REC 배지(190×32)·미니플레이어(240×135)는 **고정 픽셀**이라 비례해서 안 줄어든다」. 녹화의 존재 이유가 «수업을 다시 보는 것» 인데 교재가 안 읽히면 그 목적이 사라집니다 |
| **`captureStream` 만 15 → 10 으로** | 그리기는 그대로 60fps 라 **CPU 가 한 톨도 안 줍니다.** 버리는 프레임만 더 늘어납니다 |
| **rAF 를 `setInterval` 로 갈아치우기** | ⛔ 2026-08-05 실장애(id=2022, 93.7분 수업이 15MB) — 탭이 숨으면 rAF 가 멎어 캔버스가 얼어붙고 녹화가 빈 껍데기가 됩니다. 그 방어가 **rAF + keepAlive 짝**이라 구조를 건드리면 안 됩니다 |
| **오디오 비트레이트도 낮추기** | 소리는 수업의 핵심입니다. 기본값 그대로 뒀습니다 |
| **`video-call/js/recorder.js` 도 함께** | 확인해 보니 **캔버스 합성을 안 합니다**(`drawImage` 0건 — 원본 스트림을 그대로 녹화). 이 낭비가 원리상 없어 손대지 않았습니다 |

## 4. 한 것

`REC_FPS = 10` **한 상수**가 «그리기 가드» 와 «captureStream» 을 함께 정합니다
(숫자를 두 곳에 적으면 반드시 다시 어긋납니다).

1. `draw()` 첫머리 fps 가드 — 그릴 차례가 아니면 **건너뛰되**
   - `composeTickAt` 을 갱신하고 (⚠️ 안 하면 keepAlive 700ms 가 «rAF 가 멎었다» 로 오판해 **오히려 두 번 그립니다**)
   - rAF 를 **다시 겁니다** (⚠️ 안 걸면 그 자리에서 그리기가 **영영 멎습니다** — 화면은 멀쩡한데 녹화만 얼어붙습니다)
2. `captureStream(15)` → `captureStream(REC_FPS)`
3. `getContext('2d')` → `getContext('2d', { alpha: false })` — 매 프레임 `fillRect` 로 전체를 불투명하게 칠하므로 투명 채널이 필요 없습니다
4. `videoBitsPerSecond` 1.2 → **0.9Mbps**
5. 해상도 1280×720 **그대로**

### 효과 (산술)

| | 전 | 후 |
|---|---|---|
| 캔버스에 그리는 횟수 | ~60회/초 | **10회/초** (약 1/6) |
| 버리는 프레임 | 45/60 (75%) | **0** |
| 업로드 | 1.2Mbps | **0.9Mbps** (−25%) |
| 프레임당 비트 | 80kb | **90kb** (오히려 늘어남) |
| 교재 글자 화질 | — | **한 픽셀도 안 바뀜** |

프레임당 비트가 늘어난다는 것이 중요합니다 — 교재처럼 **정지한 화면**은 fps 를 낮춰도 안 나빠지고,
같은 비트를 더 적은 프레임에 나눠 담으니 오히려 한 장이 선명해집니다.

### 함께 본 것 — 스냅샷 사각지대

비트레이트를 내리면 **첫 5MiB 파트가 생기기까지가 길어집니다**(그 전에는 서버에 아무것도 없습니다).
영상만 세는 보수적 값으로 35초 → **47초**. `SNAP_FIRST_MS` 9초 + `SNAP_EVERY_MS` 12초라 **4회**가 덮습니다
(⑦절이 «2회 이상» 으로 못 박습니다).

## 5. 🪤 검사가 헛돌았던 이야기 — 이게 이번 작업의 핵심입니다

⑧절을 처음 짤 때, 가드 식을 소스에서 정규식으로 오려 낸 뒤
**정작 돌릴 때는 제가 손으로 다시 적은 `_now - composeDrawAt < FRAME_MS - 2` 를 썼습니다.**

그래서 변이시험에서:

- 변이 1 (가드 통째로 제거) → ❌ FAIL **났습니다**
- **변이 2 (문턱을 `0` 으로 = 고치기 전과 동일) → ✅ 통과했습니다**

즉 **「가드는 있는데 아무것도 안 막는」 상태를 못 잡고 있었습니다.**
하필 그것이 이 작업의 유일한 보장입니다.

✅ 고침: 오려 낸 식을 **`new Function` 으로 평가**합니다. 검사 코드에 손으로 적힌 숫자가 없습니다.

```js
const condExpr = guardM[1].trim();          // 소스에서 오려 낸 문턱 식 그대로
const cond = new Function('_now', 'composeDrawAt', 'FRAME_MS', 'REC_FPS',
                          `return _now - composeDrawAt < (${condExpr});`);
```

고친 뒤 변이 **4종 전부 실제 FAIL**:

| 변이 | 결과 |
|---|---|
| fps 가드 제거 | ❌ FAIL 1건 |
| 문턱을 0 으로 (가드 헛돎) | ❌ FAIL 2건 |
| `captureStream` 에 숫자 다시 적기 | ❌ FAIL 1건 |
| 건너뛸 때 rAF 안 걸기 | ❌ FAIL 1건 |
| (되돌린 뒤) | ✅ 전부 통과 |

📜 같은 뿌리가 CLAUDE.md 에 이미 있습니다 — 「하니스가 자기가 새로 만든 상수를 잡아 통과」·
「브라우저 검사에서 «설정표» 를 손으로 적으면 같은 일이 납니다」. **읽고도 밟았습니다.**
