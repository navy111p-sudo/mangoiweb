## 3. 🔴 제일 중요한 것 — 연락처는 대부분 «—» 이고, 그게 정상입니다

**요청 그대로 「연락처 칸을 만들어라」만 했으면 «칸은 생겼는데 늘 비어 있는» 화면이 됐을 것입니다.**
그래서 먼저 **운영 D1 에서 직접 셌습니다**(SELECT 만).

### 📊 잰 것 (2026-09-07 운영 D1)

| 칸 | 출처 | 채워진 정도 |
|---|---|---|
| 🆔 아이디 | `class_schedules.user_id` / `attendance.user_id` | **100%** |
| 🏫 학원 | `students_erp.shop_name` | 29,079 / 29,484 = **98.6%** (오늘 카페24 수업 128줄 기준 **128/128**) |
| ☎️ 연락처 | `student_retention.phone` | 오늘 카페24 수업 128줄 중 **35줄(27%)** |

### 🔴 `students_erp` 의 전화번호 칸은 **세 칸 전부 0건**입니다

```sql
SELECT SUM(phone IS NOT NULL AND TRIM(phone)<>''),
       SUM(parent_phone IS NOT NULL AND TRIM(parent_phone)<>''),
       SUM(student_phone IS NOT NULL AND TRIM(student_phone)<>'')
  FROM students_erp;      -- 29,484행 → 0 · 0 · 0
```

카페24 원본에 값이 없어서입니다(CLAUDE.md 2장 「학생 전화번호로 문자를 보내려는데 아무에게도 안 감」).
**코드로 풀 수 있는 문제가 아닙니다.** 그래서 그 칸은 **읽지 않았습니다** — 읽어 봐야 영원히 빈칸이고,
그러면 다음 사람이 「연락처 기능이 고장났다」로 오진합니다.

### ⚠️ 지금 보이는 번호의 정체 — «이탈 위험 학생 명단»

D1 에서 학생 번호가 실제로 남아 있는 표는 **`student_retention` 하나뿐**입니다(223행 중 199행에 번호).
그런데 그 표는 전체 명부가 아니라 **카페24 서버가 밀어 넣는 «이탈 위험 학생 스냅샷»** 입니다
(`api-retention.ts` `handleRetentionIngest`).

| category | 행 | 번호 있음 |
|---|---|---|
| expired(만료) | 59 | 59 |
| expiring(만료임박) | 61 | 57 |
| inactive(장기결석) | 103 | 83 |

⟹ 두 가지가 따라옵니다. **둘 다 사장님이 아셔야 합니다.**

1. **잘 다니는 학생은 원리상 번호가 없습니다.** 「왜 어떤 학생만 번호가 뜨냐」의 답이 이것입니다.
2. **있던 번호가 사라질 수 있습니다.** 그 함수는 스냅샷 방식이라 **이번 명단에 없는 학생을 DELETE** 합니다.
   학생이 이탈위험에서 벗어나면 다음 동기화에서 번호가 없어집니다.

그래서 화면은 **«—» 와 «왜 없는지»** 를 함께 말합니다(툴팁). 빈칸만 두면 «고장» 으로 읽힙니다.

> 📌 **전체 학생 연락처를 보시려면 코드가 아니라 카페24 쪽에 «전화번호 적재» 를 요청해야 합니다.**
> 선례: `docs/카페24_회계데이터_적재요청_2026-08-18.md`

## 4. 검토했다가 버린 방법

### 4-1. ⛔ 없는 번호를 «그럴듯하게» 채우기
`students_erp.phone` 을 읽어 두거나, 학부모 계정·카카오 번호로 대충 잇는 길이 있었습니다.
⛔ 안 했습니다 — CLAUDE.md 2장 「측정할 수 없는 값을 그럴듯하게 채우고 싶을 때」.
**틀린 번호로 학부모에게 전화하는 것**이 빈칸보다 나쁩니다.

### 4-2. ⛔ Neo4j(카페24 그래프)에서 번호를 실시간으로 가져오기
`/api/admin/students/unified` 의 Cypher 에 `par.phone`·`s.student_phone` 이 있습니다.
⛔ 안 했습니다 —
- 「오늘 수업」은 매니저가 **자주 새로고침하는** 화면인데 외부 홉이 하나 더 붙습니다.
- 그 그래프에 번호가 실제로 얼마나 있는지 **여기서 잴 수 없었습니다**(프록시가 `mangoi.ai` 를 막습니다).
  **재지 않은 것을 근거로 설계하지 않는다** — 필요하면 그때 사람이 한 번 재고 결정할 일입니다.

### 4-3. ⛔ 표에 「아이디」 칸을 따로 만들기
칸이 하나 더 늘면 좁은 화면에서 줄이 밀립니다. **이름 바로 밑 작은 줄**로 붙였습니다
(동명이인 확정이 목적이라 이름 옆에 있어야 뜻이 있습니다).

### 4-4. ⛔ admin 화면만 고치기
피드백 문구가 «managers schedule» 이고 스크린샷은 `admin.html` 의 표였지만,
`manager.html` 도 **같은 API** 를 씁니다. 한쪽만 그리면 「화면마다 답이 다른」 상태가 됩니다
— 이 저장소가 반복해서 밟은 사고라 **둘 다** 그리게 했습니다.

## 4-5. 🪤 함정 대조(`trap-check`)가 잡아 준 것 — **제가 만든 결함 3건**

전부 «타입체크도 하니스도 초록불» 인 상태에서 나온 것입니다.

### ⓐ 없는 «이유» 를 `title` 로만 말하고 있었습니다 — 폰에서는 영원히 안 보입니다

`title` 툴팁은 **마우스 전용**입니다(CLAUDE.md 2장 「버튼에 title 로 설명을 달았는데 폰에서는 안 뜸」).
매니저는 대부분 폰으로 봅니다. 실측대로면 **줄의 약 4분의 3이 «이유 없는 —»** 이 되는데,
그게 바로 같은 장이 금지한 「빈칸은 «고장» 으로 읽힌다」 상태입니다.

⚠️ **더 나쁜 것은 제 하니스가 그 틀린 모양을 «정답» 으로 못 박고 있었습니다**(`⑤-6` 이 `title=` 을 봤습니다).

✅ 고침: 칸에는 «—» 만 두고, **이유는 목록 위에 보이는 줄로 한 번**(`contactNote`).
줄마다 반복하면 4분의 3이 같은 문장으로 시끄러워지므로 한 번만 적습니다.
근거는 **서버가 준 `contact_source` 로만** 판정합니다 — 화면은 자기 역할도 그 표의 성격도 모릅니다.

### ⓑ 화면에 보이는 대로 검색하면 0건이었습니다

화면은 `010-1234-5678` 로 끊어 그리는데 검색은 저장값(`01012345678`)만 훑고 있었습니다.

| 검색어 | 고치기 전 |
|---|---|
| `5678` | 찾음 |
| **`010-1234-5678`**(화면에 보이는 그대로) | **0건** |

⚠️ 제 하니스 `⑥-2` 는 뒷자리만 시험해서 **통과**했습니다 — 거짓 안심이었습니다.
✅ `rowText` 에 `telFmt(...)` 도 넣고, 검사에 **보이는 표기 검색을 짝으로** 넣었습니다(`⑥-3`·`⑥-4`).

### ⓒ 🔒 지사·대리점이 **처음으로** 학생 전화번호를 볼 뻔했습니다

이 API 는 `isAgencyAllowedApi` 에 올라 있어 지사·대리점(manager.html)도 부릅니다.
그런데 지금까지 그 번호를 내주던 유일한 경로 `/api/admin/retention` 은 **그들에게 403** 이었습니다.

⟹ 그냥 실었으면 **매니저 요청에 없던 «개인정보 공개 범위 확대»** 가 조용히 따라붙습니다.
✅ 그래서 연락처는 **본사·내부직원(hq/none)에게만** 싣습니다(`_ctSeeContact` 한 줄).
지사·대리점 화면은 「☎ 연락처는 본사 계정에서만 보입니다」라고 **말합니다**(감추고 침묵하지 않습니다).

> 📌 **여는 것은 사장님이 정하실 일입니다** — 그 한 줄만 바꾸면 열립니다(범위 격리는 그대로라
> 자기 학원 학생만 보입니다). 학원 이름·아이디는 그 청중이 이미 보던 값이라 그대로 둡니다.

### 그 밖에 함께 고친 것

- ☎️ 전화번호가 실리는 응답에 **`Cache-Control: private, no-store`**
  (공유 캐시에 앉으면 한 사람 것이 남에게 나갑니다)
- 연락처 조회에 **`ORDER BY`** — `LIMIT` 만 있으면 «어느 2000» 인지 정해지지 않고 나머지가
  조용히 «—» 가 됩니다(지금 223행이라 영향 0이지만, 잘리면 로그로 말하게 했습니다)
- `manager.html` 도 **같은 근거로 같은 말** 을 하게(전에는 번호가 없으면 아무 말도 안 했습니다)

## 5. 밟지 않으려고 조심한 함정 (CLAUDE.md 2장)

| 함정 | 어떻게 피했나 |
|---|---|
| 표에 칸을 늘리면 머리칸·줄칸·colspan 이 어긋난다 | 하니스가 **실제로 그려서** th 8 = td 8 을 센다 |
| 화면에 그린 칸을 검색이 안 훑으면 「보이는데 0건」 | `rowText` 에 학원·연락처 추가 + 하니스가 실제로 검색해 확인 |
| 짧은 글을 `display:flex` 로 감싸면 낱글자로 쪼개진다 | 아이디·학원 줄은 보통 텍스트 흐름 |
| 아이디 칸에 `font-family` 를 쓰면 한자 폰트 가드가 FAIL | 안 씀(`letter-spacing` 만) |
| 조회 실패가 목록 전체를 멈춘다 | 연락처 조회는 **독립 try/catch** — 실패하면 연락처 칸만 빈다 |
| 개인정보가 범위 밖으로 샌다 | 스코프(`scopeStudentCond`)로 이미 잘린 줄에만 붙임 · 강사는 기존 403 그대로 |
| `js/*.js` 를 고치고 `?v=` 를 안 올린다 | `v=18 → 19` + 원장 커밋 |
