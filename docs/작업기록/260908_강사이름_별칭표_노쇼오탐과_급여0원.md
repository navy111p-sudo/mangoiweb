## 3. 고친 것

`src/no-show-truth.ts` 에 **`NAME_ALIASES`**(«완전일치 쌍» 만 손으로 적는 표)와 `aliasesOf()` 를
넣고 `sameTeacherByWord()` 가 그것을 씁니다. 지금 한 줄뿐입니다: `['FAR', 'FARRAH']`.

기존 동작은 그대로 보존됩니다 — 별칭은 **이름 «전체»** 가 표에 있을 때만 걸립니다.

## 4. 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| **부분일치를 열기**(`FAR ⊂ FARRAH` 니까 `includes` 로) | 그 순간 **`ANNA` ⊂ `HANNAH` 가 되살아납니다.** 남의 이름이 붙으면 **진짜 노쇼가 오판으로 감춰지고 수업료가 전액 나갑니다** — 이 파일이 가장 나쁘다고 못 박은 방향입니다. 변이시험에서 실제로 B-4·D-8·D-9 가 FAIL 났습니다 |
| **예약표(`teachers.name`)를 `FARRAH` 로 고치기** | D1 변경이고(개발·운영 같은 DB) 그 이름이 뜨는 화면이 여럿입니다 — **사람이 정할 일**입니다 |
| **강사 입장 이름을 계정으로 통일** | `teacher.html` 수정 + 강사 습관이 걸립니다. 근본 해결이지만 별건입니다 |
| **`api-teacher.ts` 의 `wordMatch` 도 함께 넓히기** | 거기는 «내 수업만 보이게» 하는 **접근제어**라 넓히면 **남의 수업·학생 이름이 보일 위험**이 생깁니다. 게다가 그 경로는 `teacher_account_links` 수동 연결이 **0순위**라 FAR 강사는 이미 붙습니다 — 이 사고가 원리상 안 납니다 |
| **낱말끼리도 별칭 확장** | 그것이 곧 부분일치입니다. `aliasesOf` 는 «이름 전체» 일 때만 걸립니다 |
| **오늘 것을 D1 `UPDATE` 로 정정** | 규칙서 1-1(운영 DB). 그리고 기록을 고치면 «왜 수업이 성립하지 않았나» 가 사라집니다 |
