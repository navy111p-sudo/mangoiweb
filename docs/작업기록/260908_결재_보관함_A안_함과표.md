## 1. 무엇이 없었나

| 있었다 | 없었다 |
|---|---|
| 「지난 결재 찾기」 — 함 6종 · 검색 · 기간 · 분류 · 항목 · 상태 · 엑셀 | 맨 위 요약 줄에서 **바로 들어가는 입구** |
| «내가 올린 것» 축과 «전체»(권한자) | **「내가 결재한 것」 함** — 내가 도장을 찍은 건만 모아 보는 것 |
| 조건을 한 번씩 «좁히기» | **결재자별 · 종류별 · 기간별로 «묶어서» 보는 함** — 그리고 함 옆에 «몇 건인지» |

사장님이 실제로 물으신 「내가 결재한 것」은 함으로도, 고르기 칸으로도 **없었습니다**.

## 2. 무엇을 만들었나

**공통 — 다섯째 카드 「결재 보관함」**(`paintTop`, `.tile.arch`). 「올해 N건 · 전체/내가 올린 것 · 마지막 결재 9/7 장지웅 · 열기 →」.
범위는 옆의 금액 타일과 같습니다(서버 `sumAll` — 경영진=전체, 그 밖=내가 올린 것). 누르면 문서함이 열리고 권한자는 «전체» 로 시작합니다.

**왼쪽 함 트리**(`#findBox`, `paintFindBox`) — 그룹웨어처럼 함이 곧 «보는 방식» 입니다.

| 묶음 | 함 | 누르면 |
|---|---|---|
| 전체 | 전체 결재(권한자만) · **내가 결재한 것** · 내가 올린 것 | scope 를 바꿉니다 |
| 기간별 | 이번 달 · 지난 달 · 이번 분기 · 올해 | 시작일·종료일을 **서버가 준 경계**로 채웁니다(한 번 더 누르면 풂) |
| 결재자별(권한자만) | 도장을 찍은 사람마다 한 줄, 많이 결재한 순 | `decided_by` 로 거릅니다(scope 는 전체) |
| 종류별 | 지출·구매·휴가… (0건은 감춤) | 분류 칸을 바꿉니다 |

함은 **축을 겹칩니다** — 「장지웅」 + 「이번 달」 + 「지출」. 「보는 중: 전체 결재 · 결재자 장지웅 · 9/1 ~ 9/30」 한 줄이 지금 조건을 말하고, 「함 조건 지우기」가 결재자·기간·종류를 한 번에 풉니다.
오른쪽은 지금 있는 표·필터·엑셀 그대로 — 서버도 **같은 경로**(`GET /api/approval/requests`)에 파라미터만 늘었습니다(`scope=decided` · `decided_by=` · `view=facets`).

## 3. 🔴 「내가 결재한 것」은 어느 칸을 보나

`approval_requests.decided_by` 가 **아닙니다.** 그 칸은 «최종 처리자» 라서
- 회수하면 **기안자 이름**이 들어가고(회수는 결재가 아닙니다),
- 다단계면 1단계 결재자가 **안 남습니다.**

정본은 `approval_steps` 의 도장입니다 — `DECIDED_BY_SQL`(`approval-policy.ts`): 그 사람이 `approved`·`rejected` 로 찍은 단계가 있는 건.
⛔ **`skipped`(전결로 건너뜀)는 도장이 아닙니다** — `decided_by` 가 적혀 있어도 세지 않습니다. 하니스 fixture 에 «유일한 흔적이 건너뜀인 사람» 을 넣어야 이 조건을 뺀 변이가 잡혔습니다(4장).

## 4. 🔴 함 옆 «건수» 와 오른쪽 «표» 가 같은 말을 하는가

함 옆 숫자는 SQL 집계인데 표는 `canView` 로 한 번 더 거릅니다. 둘이 어긋나면 「전체 24」라고 써 놓고 표에는 21건 — **에러 없이 숫자만 거짓**이 됩니다(2026-09-04 C안에서 canView 를 안 걸어 인사·급여가 합계에 섰던 것과 같은 자리).

그래서 범위 조건(`archiveVisibleCond`)을 **canView 의 세 분기를 SQL 로 옮긴 것**으로 만들었습니다.

| 등급 | canView | SQL |
|---|---|---|
| 경영진 | 전부 | 조건 없음 |
| 본사 직원 | 내가 올린 것 ∪ exec 등급(인사·급여) 아닌 전부 | `requester_username = ? OR instr(<exec 종류 목록>, ','||req_type||',') = 0` |
| 필리핀 매니저 | 내가 올린 것 ∪ 결재선에 내가 있음 ∪ 긴급(broadcast) | `requester = ? OR DECIDED_BY_SQL OR instr(<broadcast 목록>, …) > 0` |

⚠️ 처음엔 «그 밖 = 내가 올린 것 ∪ 내가 도장 찍은 것» 으로 짰습니다 — **canView 를 끝까지 안 읽고** 짠 것이고, 그러면 본사 직원의 「전체 결재」 숫자가 표보다 작게 나옵니다. canView 마지막 줄(`return isHqStaff(actor)`)을 읽고 등급을 셋으로 갈랐습니다.
✅ 하니스 ②절이 **다섯 계정**(경영진 둘 · 본사 직원 둘 · 필리핀 매니저)마다 «SQL 이 준 행 집합 == canView 가 참인 행 집합» 을 진짜 SQLite 에서 대조합니다. 「본사 직원도 전체로 세기」 변이에서 실제로 3건 FAIL.

**「전체 결재」 건수와 「결재자별」 묶음은 결재 권한자에게만** 줍니다 — 직원의 `all_n` 은 «내가 볼 수 있는 것» 이라 「전체」라는 이름이 거짓이 되고, 결재자 목록은 직원에게는 결재자 명부가 될 뿐입니다. 서버(`approver && tot` · `if (approver)`)와 화면(`canAll`) 둘 다.

## 5. 검토했다가 버린 것

| 안 한 것 | 왜 |
|---|---|
| **새 API 경로** | 관문 셋 중 둘이 공동 금지구역(`src/index.ts`). 기존 경로에 `view=facets`·`decided_by` 만 얹었습니다 |
| **화면이 함 옆 건수 세기** | 화면은 최근 15건·표 20건만 갖고 있어 그 안에서만 세게 됩니다 — 서버가 셉니다 |
| **화면이 «이번 달» 날짜 계산** | 서버는 KST 로 세고 브라우저는 자기 시계라 두 벌이 어긋납니다(필리핀 매니저는 UTC+8). 서버가 `archivePeriods` 로 경계를 함께 내려줍니다 |
| **`approval_requests.decided_by` 로 「내가 결재한 것」** | 3장 — 회수는 결재가 아니고 다단계 1단계가 사라집니다 |
| **비권한자에게 「전체」 함을 «—» 로라도 그리기** | 눌러도 서버가 403 — «눌러도 안 되는 버튼» 이 됩니다. 아예 안 그립니다 |
| **함 옆 건수를 못 읽었을 때 0** | «0건» 과 «못 읽음» 은 다른 사실 — `null` → 화면 «—» + 「일부 건수를 읽지 못했습니다」 |
| **폰에서 함을 드로어로** | 시안에 적은 A 의 약점이 「두 번 눌러야 한 번에가 안 됨」이었습니다 — 720px 아래에서 **가로로 굴리는 칩 줄**로 접어 한 화면에 남겼습니다 |
| **결재자 함을 누르면 다른 축 지우기** | 「장지웅이 이번 달 결재한 지출」이 세 번 누르기로 됩니다 — 축을 겹치고 「함 조건 지우기」를 따로 |

## 5-2. 🪤 만드는 사이 main 이 같은 화면을 세 번 고쳤습니다

다른 세션이 9/7~9/8 에 `work.html` 을 바꿨습니다 — 문서함을 **처음부터 펼침**(사장님 지시) · **「지출 정리」를 문서함 위로** · **범위 기억(`fscopePick`, `localStorage`)**.
squash 병합 뒤 브랜치를 main 에서 다시 시작해 두 커밋만 체리픽했더니 `work.html` 세 곳·`INDEX.md` 한 곳이 **진짜 충돌**(같은 자리를 둘이 고침)이었습니다.
✅ main 구조를 정본으로 두고 함 트리를 그 안에 넣었습니다 — 펼쳐진 패널을 `.findlay` 로 감싸고, `fscopePick`(기억) 뒤에 `fbScopeChanged`(함 동기화·조회)가 이어지며, 첫 자동 조회(`findAutoOpen`)에서 함 트리와 건수(`loadFacets`)도 함께 그립니다. 카드(`topArchive`)는 «전체» 로 바꾼 뒤 **같은 기억 경로**를 탑니다.
⚠️ 그래서 브라우저 검사의 전제가 바뀌었습니다 — 「처음엔 닫혀 있다」가 아니라 「처음부터 펼쳐져 있고 카드는 접지 않는다」.
