## 1. 왜 했나

사장님 질문 **「왜 FAR 대신 id 3으로 만들어졌는지 확인해줘」** 에서 시작했습니다.

`class_schedules` 16건이 `teacher_id='3'`(HT FARRAH)로 만들어져 있었는데, 그 강사의 «지금 쓰는»
원부 번호는 **22(FAR)** 입니다. 조사 결과 **자동 배정이 아니라 사람이 화면에서 고른 것**이었고,
고를 수 있었던 이유는 **원부에 같은 사람이 두 줄로 있었기 때문**이었습니다.

이어서 사장님 **「HT FARRAH id 3 명부에서 정리할 방법 알려줘」** → **「1번으로 진행해줘」**.

## 2. 📏 잰 것 (D1 실측 · 2026-09-09)

### 2-1. 16건은 «사람이 고른 것» 입니다

`class_schedules.notes` 에 그때 고른 이름이 그대로 박혀 있습니다.

| source | 건수 | 만든 사람 | 생성(KST) | notes 의 강사 |
|---|---|---|---|---|
| `adm-enroll:60` | 8 | `admin` | 08-24 21:09 | **HANNAH** → 08-26 20:25 「강사 변경 HANNAH→**HT FARRAH** (사장님 지시)」 |
| `adm-enroll:68` | 4 | `mgr_jjw` | 08-25 21:47 | **HT FARRAH** (레벨테스트) |
| `adm-enroll:70` | 4 | `mgr_jjw` | 08-26 **15:15:08** | **HT FARRAH** |

### 2-2. 5분 뒤 같은 사람이 FAR 로 다시 만들었습니다

```
08-26 15:15:08  adm-enroll:70  → HT FARRAH (id 3)
08-26 15:20:08  adm-enroll:70  취소 (updated_at)      ← 35초 전
08-26 15:20:43  adm-enroll:71  → FAR (id 22)  ✅
```

그 뒤 `71·72·73·74·77·84·98` 은 **전부 FAR(22)** 입니다.
`teacher_id='3'` 은 **8/24 21:09 ~ 8/26 15:15 사흘 창에만 16건**, 전원 같은 학생(`delaware` 김연숙)이고
**그 뒤로 한 건도 없습니다.**

### 2-3. 그 목록은 `active = 1` 인 강사만 담습니다

- 확정 화면 드롭다운 = 응답의 `teacher.free` (`adm-core.js:6590` 이 그대로 `<option>` 으로 그림)
- `free` 의 출처 = `SELECT id, name FROM teachers WHERE active = 1` (`enroll-activate.ts:205`)
- `teachers.id=3` 의 `updated_at` = **2026-08-31 19:23:45**, 지금 `active=0`

### 2-4. id 3 은 프로필 없는 «고아 행» 입니다

`teacher_profiles` 에서 Farrah 를 가리키는 것은 27번 하나뿐이고 `linked_teacher_id = **22**` 입니다.

### 2-5. 지금 id 3 이 «보이는» 화면은 한 곳뿐이었습니다

| 화면 | 무엇을 그리나 | id 3 |
|---|---|---|
| 관리자 › 강사 명부 | `teacher_profiles` | ❌ 프로필이 없어 애초에 안 보임 |
| 수강신청 **확정 드롭다운** | `teacher.free` = `active=1` | ❌ 안 보임 (재발 불가 상태) |
| `/api/admin/teachers` 를 쓰는 화면들 | 기본 `WHERE active=1` | ❌ 안 보임 (`include_inactive=1` 쓰는 화면 **0곳**) |
| 🔴 관리자 › **강사 계정 연결** | `/api/admin/teachers/links` | ✅ **보임** — `adm-teacher-links.js` 가 `active` 를 **안 걸렀음** |

### 2-6. 걸려 있는 참조

## 3. 🧠 그래서 내린 판단 (추론 — 측정과 구분)

- **자동 배정이 아닙니다.** `free[0]` 이었다면 id 3 이 id 22 보다 앞이라 같은 시기 다른 신청
  (56·57·65·75 → KRYSTEL·HANNAH·ANA·SID)에도 섞였어야 하는데 하나도 없습니다.
  `continuity` 도 아닙니다(그 학생의 id 3 수업 자체가 이 16건이 처음).
- **뿌리는 「명부에 같은 사람이 두 줄」** — 8/25~26 당시 목록에 `FAR`(22)와 `HT FARRAH`(3)가
  둘 다 떠 있었고(목록이 `active=1` 만 담으므로 그때 id 3 은 `active=1`), 사람이 위쪽을 골랐습니다.
- **그 자리에서 알아채고 고쳤습니다** — 70 을 35초 만에 취소하고 71 을 FAR 로 다시 만든 흔적.
  다만 먼저 만든 60·68 이 남아 16건이 됐습니다.

⚠️ **「8/26 당시 id 3 이 `active=1` 이었다」는 직접 측정이 아니라 추론입니다.**
근거는 «목록이 `active=1` 만 담는데 그 이름이 notes 에 박혔다» + «그 행의 마지막 변경이 8/31»
두 가지뿐이고, `teachers` 표에 이력 칸이 없어 그때 값을 직접 읽을 방법은 없습니다.

이름을 바꾸면 그 둘이 **에러 없이 조용히 어긋납니다.**

  CLAUDE.md 1-1 상 사장님 결정 사항입니다
- 외래키가 없어 `class_schedules` 16건의 `teacher_id='3'` 이 **«누구인지 모를 번호»** 로 남습니다

### ⛔ 「목록에서 아예 빼기」 (라벨도 없이)
이미 퇴사자에게 이어진 계정이 있으면 그 줄이 「연결 안 됨」으로 보여, **사람이 멀쩡한 연결을
다시 만들려 듭니다.** 그래서 `mine` 은 절대 숨기지 않습니다.
