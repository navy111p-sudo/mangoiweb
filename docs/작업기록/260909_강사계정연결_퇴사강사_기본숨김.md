## 1. 왜 했나

사장님 질문 **「왜 FAR 대신 id 3으로 만들어졌는지 확인해줘」** 에서 시작했습니다.

`class_schedules` 16건이 `teacher_id='3'`(HT FARRAH)로 만들어져 있었는데, 그 강사의 «지금 쓰는»
원부 번호는 **22(FAR)** 입니다. 조사 결과 **자동 배정이 아니라 사람이 화면에서 고른 것**이었고,

이어서 사장님 **「HT FARRAH id 3 명부에서 정리할 방법 알려줘」** → **「1번으로 진행해줘」**.

## 7. 남은 것 (사람이 정할 일)

- **`teachers` 에 같은 사람이 두 줄로 있는 상태 자체**는 그대로입니다. 지금은 id 3 이 `active=0`
  이라 어느 화면에도 안 뜨지만, 원부를 합치는 것은 되돌릴 수 없는 조작이라 사장님 결정 사항입니다.
- ⚠️ **`active` 의 NULL 처리가 저장소 안에서 두 갈래입니다.** 이번 판정과
  `api-admin.ts`·`leveltest-schedule.ts` 는 `COALESCE(active,1)` = «모르면 재직» 인데,
  **`enroll-ops.ts` 네 곳은 `WHERE active = 1`** 이라 NULL 이면 제외합니다. 지금은 NULL 행이
  0건이라 무해하지만, 하나라도 생기면 **수강신청에서는 사라지고 계정 연결에서는 보이는**
  어긋남이 납니다(그 파일은 「다른 도메인을 import 하지 않는다」 원칙이라 별건).
- 근본은 **표기를 한쪽으로 맞추는 것**입니다(예약표를 고치거나 입장 이름을 계정으로 통일).
  그때 `no-show-truth.ts` 의 별칭표에서 그 줄을 지웁니다.

## 8. 후속 (같은 날) — 곁가지로 찾은 정렬 결함까지 고침

위 §7 에 「고치지 않았습니다 · 사람이 정할 일」로 적어 두었던 항목입니다. 보고 후
사장님 「정렬도 고쳐줘」 지시로 같은 날 고쳤습니다.

### 8-1. 무엇이 틀렸나

`adm-tlink.js` 의 `render()` 정렬 키가 이랬습니다.

```js
// 급한 것부터 위로 — 연결 안 됨 → 헷갈림 → 자동매칭 → 연결됨
var order = { unlinked: 0, ambiguous: 1, auto: 2, linked: 3 };
var d = (order[a.status] || 9) - (order[b.status] || 9);
```

첫 칸이 **0** 이라 `0 || 9` → **9**. ⟹ 바로 위 자기 주석과 **정반대로 「연결 안 됨」이 맨
아래**로 갑니다. 1・2・3 은 truthy 라 멀쩡히 동작해서 «절반만 맞는» 모양이고,
**에러도 경고도 안 납니다.**

반경: 이 표는 「손봐야 할 계정」을 사람이 찾아 고치라고 만든 화면인데, 정작 제일 급한 줄이
맨 아래에 있었습니다. 계정이 많으면 스크롤 밖입니다.

### 8-2. 어떻게 고쳤나

순위 표를 밖으로 빼고 «있는 키인가» 를 명시적으로 묻습니다 — `||` 를 안 씁니다.

```js
var TLK_ORDER = { unlinked: 0, ambiguous: 1, auto: 2, linked: 3 };
function tlkRank(st) {
  return Object.prototype.hasOwnProperty.call(TLK_ORDER, st) ? TLK_ORDER[st] : 9;
}
```

⛔ 되살아나지 않게 **그 함정을 주석에 이름으로** 적어 두었습니다.
`admin.html` 의 `adm-tlink.js?v=3` → **`?v=4`**(원장 항목 함께 커밋).

ℹ️ 형제 화면 `adm-teacher-links.js` 에는 **정렬이 없습니다**(대신 「연결 안 된 것만 보기」
필터). 그래서 이번은 복제가 아니라 한 곳짜리 수리입니다.

### 8-3. 확인 — 검사를 두 층으로, 그리고 «되돌려서» 확인

| 층 | 무엇을 재나 |
|---|---|
| `teacher_link_left_hidden_harness` ⑧절 (자동) | 순위 표·함수·**정렬식을 소스에서 오려 내 실제로 돌립니다** |
| `manual/teacher-links-left-hidden-browser.mjs` ⑧절 (사람이 부름) | 그려진 `<tr>` 을 위에서부터 읽습니다 |

둘이 필요한 이유 — 자동 하니스는 «식이 맞나» 까지이고, «그 식이 진짜로 이 표를 그리는가» 는
브라우저에서만 보입니다.

**변이시험 (전부 실제로 FAIL 났습니다)**

1. **M2 가 «깔끔한 FAIL» 이 아니라 하니스를 «크래시» 시켰습니다** — `결과:` 줄조차 안 나왔습니다.
   `new Function` 의 «만들기» 만 `try` 로 감싸고 «부를 때» 는 안 감쌌기 때문입니다(표 이름을
   바꾼 변이는 만들 때는 멀쩡하고 부를 때 `ReferenceError` 를 던집니다). CLAUDE.md 2장이
   「스택트레이스만 남아 무엇이 깨졌는지 안 보입니다 — `try/catch` 로 깔끔한 FAIL 로」라고
   못 박은 그 모양입니다 → 호출을 `rk()` 로 감쌌습니다(FAIL 1 → **FAIL 6**).
2. **M1 에서 검사 6건이 «FAIL» 이 아니라 조용히 «사라졌습니다»**(PASS 49 → 39, 합계가 43). ⑧-5・⑧-6 이
