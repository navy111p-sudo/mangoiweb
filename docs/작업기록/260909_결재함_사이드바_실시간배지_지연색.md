## 1. 먼저 확인한 사실 — 배지는 «이미 있었다»

사장님 화면(사이드바 드로어 「결재함」에 표시 없음)을 코드와 D1 로 대조했습니다.

| 잰 것 | 값 |
|---|---|
| 사이드바 배지(`#ia6-appr-n`)·켜짐(`.on`) 코드 | **있음**(2026-08-20 부터) |
| 그 시각 `approval_requests` 대기 건수 (D1 SELECT) | **0건** → 배지가 비어 있는 것이 정상 |
| 결재 조회 횟수 | 화면 열 때 **3초 뒤 1회만** — 그 뒤 도착한 건은 새로고침 전까지 안 뜸 |
| 지연 표시 | 「자주 쓰는 기능」 칸의 **마우스 툴팁에만** — 폰·사이드바에서는 못 봄 |
| `#ia6-appr` `<a>` 의 `data-ko`/`data-en` | **있음** → EN/KO 를 누르면 i18n 이 `textContent` 를 갈아끼워 **배지 요소가 지워짐** |

즉 「표시가 안 난다」의 절반은 «그때 결재가 없었다» 이고, 나머지 절반이 위 세 가지입니다.

## 2. 무엇을 만들었나

### A — 실시간 갱신 (`/js/adm-appr-badge.js`)
- 첫 조회는 **그대로 3초 뒤**(첫 화면과 경쟁 금지). 그 뒤 **60초마다**(`POLL_MS`), **숨은 탭은 건너뜀**(`document.hidden`).
- **탭 복귀(`visibilitychange`)·창 포커스**에 한 번 더 — 5초 안 중복은 한 번으로 합침(`lastLoadAt`).
- 건수가 **늘어난 순간만** `.fresh`(앰버 outline) 1.5초 — 첫 조회·줄어들 때는 아님. transform 없음(CLAUDE.md 1-3).
- 조회 실패 → **마지막 값 유지**(거짓 0건으로 지우지 않음).

### B — 지연 색 + 며칠째
- `apprSummary(inbox, now)` 순수 함수: `late` = `stage_due_at` 이 지난 건 수, `days` = 가장 오래된 건(`origin_created_at` 우선 — 회수 후 다시 올린 건은 원래 날부터, `work.html` 의 `daysWaiting` 과 같은 규칙).
- 지연 ≥ 1 → `#ia6-appr.late`(테두리·글자 `#b42318`, 켜짐이면 배경까지) + 부제 `#ia6-appr-sub` 「· 지연 N · N일째」(EN 「· late N · N days」). 0 이면 둘 다 걷힘(`:empty{display:none}`).

### ③ i18n 함정 수리 (`js/adm-ia6.js` v=57)
- `data-ko`/`data-en` 을 `<a>` 에서 **라벨 `<span class="ia6-appr-l">`** 로 옮김. 배지·부제는 그 옆 형제라 토글에 안 지워집니다.

### 구조 — admin.html 인라인 → defer 파일
- `first_paint_budget_harness` 가 admin.html blocking(인라인 script 포함)을 재는데 **main 이 315KB / 상한 317KB 로 여유 2KB** 였고, A+B 를 인라인에 더하자 318KB 로 넘쳤습니다.
- 규칙(CLAUDE.md 2장 「첫 화면 예산이 FAIL」 — `--update` 는 마지막 수단)대로 결재 IIFE 8KB 를 **`cloudflare-deploy/public/js/adm-appr-badge.js`** 로 빼고 `<script src="/js/adm-appr-badge.js?v=1" defer>` 로 실었습니다. 결과 admin.html blocking **311KB**(여유 6KB — 주기 전보다 넓어짐). CSS(`<style id="ia6-appr-css">`)는 admin.html 에 그대로.
- ⚠️ `/js` 루트에 두었습니다(`/admin/` 밑은 로그인 게이트가 자산까지 삼킴).

## 4. 만들면서 밟은 것

1. **`<script>` 라는 글자를 HTML 주석에 적었더니 `inline_js_syntax_harness` 가 인라인 스크립트로 오인** — 주석 뒤 텍스트를 JS 로 파싱해 SyntaxError. 「스크립트 태그」로 풀어 썼습니다(2장 「부정 검사가 자기 주석을 잡음」의 형제).
2. **오려 낸 `apprSummary` 가 바깥 상수 `DAY_MS` 를 읽어 ReferenceError** — 손으로 다시 적지 않고 **블록에서 `var DAY_MS` 선언을 읽어** 앞에 붙였습니다(값이 바뀌면 검사도 따라옴).
3. **변이시험용 sed 가 JS 를 깨뜨려 하니스가 «크래시»** — 크래시는 FAIL 이 아니라 «검사가 안 돈 것». 변이는 python 으로 `count==1` 을 확인하며 넣었습니다.
4. **`.catch(function(){})` 문자열이 admin.html 에 여럿** — 첫 매치가 서비스워커 코드였음. 앵커(`🧾 결재 대기 알림`) 뒤에서 찾아야 합니다.
5. **브라우저 검사의 «줄 높이 < 60px»** 은 근거 없는 숫자였습니다(zoom 1.3 + padding 11px → 67px 인데 텍스트는 한 줄). «텍스트 상자 scrollHeight ≤ clientHeight» 로 바꿨습니다.
6. **`.late` 규칙 하나만 지운 변이는 브라우저 검사가 못 잡음** — 켜짐 상태에서는 `.late.on` 규칙이 테두리를 그리기 때문. 다섯 규칙을 전부 지워야 FAIL(정확한 변이가 아니면 검사가 헛도는 것처럼 보입니다).
