## 3. 원인 넷

### ① PC 에서 가로 통합검색 드롭다운이 «구조적으로» 안 보였다
`css/admin-inline-c.css` 2896·3082행, `@media (min-width:1024px)` 안:

```css
.menu-search-wrap, .menu-search-input, .menu-search-dropdown,
.menu-search-clear, .menu-search-item { display: none !important }
```

2026-05-25 **Phase 89**「우측 메인 영역의 옛 메뉴(가나다 순) 검색 카드 제거」 규칙입니다.
그런데 2026-06-24 에 되살린 **히어로 검색창의 드롭다운이 같은 클래스**(`menu-search-dropdown`)를
달고 있어 함께 걸립니다. 작성자 `!important` 라
`admin-inline-a.css` 의 `.hero .hero-search-dropdown.show{display:block}`(important 없음)을
**언제나 이깁니다.** `admin.html` 의 `ph89Clean` 이 박는 **인라인** `display:none` 도 같은 자리입니다.

### ② 「녹화」의 1순위가 녹화 페이지가 아니었다
`js/adm-core.js` 의 `MENU_ALIASES` 한 줄에 «녹화» 와 «활성방» 이 함께 묶여 있었습니다:

```js
{ kw:'녹화 녹화본 활성방 recording', card:'card-active-rooms', label:'녹화·활성 방' }
```

라벨이 「녹화」로 **시작**해 정렬 1위가 되고, 진짜 녹화 카드
(`card-recording-storage` = 「🎥 녹화 관리」)는 2위로 밀립니다.
Enter·➡️ 는 1위를 실행하므로 **「🔴 실시간 수업 (활성 룸)」** 으로 갔습니다.

### ③ 세로 검색이 «옛 사이드바» 까지 훑었다 + 결과가 없어도 아무 말도 안 했다
이 화면 사이드바는 **두 벌**입니다 — 옛 9그룹(`data-ia6-legacy`, CSS 로 `display:none`)과
그 위에 IA6 가 다시 그린 것. 검색이 둘 다 훑어서, 옛 쪽에만 있는 말은
«찾았다»고 판단해 그룹까지 열어 놓고 **화면에는 0건**이었습니다.
게다가 «없다»는 말도 안 해서 사람에게는 «검색이 고장났다» 로 보였습니다.

### ④ 세로 검색이 영어를 안 봤고, 결재함은 아예 안 봤다
`textContent`(한글)만 대조했습니다 — EN 으로 쓰는 필리핀 매니저는 영어로 자기 메뉴를
못 찾았습니다. 그리고 결재함은 `.ph85-sub` 가 아니라 `<a id="ia6-appr">` 라
필터 루프가 아예 안 봤습니다.
