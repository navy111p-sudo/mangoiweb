## 2. 무엇을 바꿨나

### 2-1. 판정 정본 — `cloudflare-deploy/src/recording-dup-guard.ts` (신규)

순수 함수 `recordingDupGate({ rows, now, windowMs })` 하나.
「그 방에 **아직 살아 있는** 녹화가 있으면 막는다」만 판정합니다.

- **살아 있는가** = `recording_parts.created_at` 의 **최댓값**이 최근 **3분**(`REC_DUP_LIVE_WINDOW_MS`) 안
- 미래 시각은 `FUTURE_SLACK_MS`(60초) 밖이면 **안 믿습니다**
- 판정 불가는 `reason` 으로 갈라 말합니다 — `lookup_failed` · `none` · `stale` · `live`

**🔴 fail-open 입니다** — 조회 실패·시각 이상·예외는 **전부 «찍는 쪽»** 으로 떨어집니다.
잃을 것이 «수업 녹화 그 자체」(학부모 약속·미성년자 기록)라, 이 자리에서만은
이 저장소의 평소 규칙(「되돌릴 수 없는 조작은 막는 쪽으로 실패」)과 **반대**입니다.

### 2-2. 서버 — `cloudflare-deploy/src/api-mango.ts` (`/api/recordings/start`)

속도제한 뒤 · 참가자 채우기와 `INSERT` 앞에 게이트를 넣었습니다.

- `room_id` 가 **비어 있으면 건너뜁니다**(빈 방번호끼리 묶으면 남남인 수업이 서로를 막습니다)
- 바깥 `try/catch` 는 **로그만** 하고 통과(fail-open), 안쪽은 D1 오류 때 `dupRows = null`
- 거절은 **HTTP 200 + `{ok:false, error:'already_recording', retry_after_ms, message}`**
  (기존 `consent_required` 와 같은 모양 — 재시도 폭주 방지)

### 2-3. 화면 — `cloudflare-deploy/public/js/mango-rec.js`

- `dupBlocked` · `startRetryAt` · `START_RETRY_MS = 60초`
- 배지 **본문 글자**로 사유를 말합니다 — 「⏸ 다른 기기가 녹화 중」 / 「⛔ 녹화불가 · 학생 미동의」
- 자동 시작 폴링은 `Date.now() >= startRetryAt` 일 때만

### 2-4. 감시 — `test-harness/recording_dup_guard_harness.mjs` (신규, 53종)

A절 정본을 `--experimental-strip-types` 로 **실제로 돌리고**(17종) ·
B절 서버 SQL 과 인터페이스 칸을 **소스에서 읽어** 대조 ·
C절 실패 방향(200 응답 · catch → null · 게이트가 try 안인지 **중괄호 짝**으로) ·
D절 화면 배선 · E절 **변이 9종**.

### 2-5. CLAUDE.md 2장 (#859 · #878)

「‘강사는 자동 녹화 안 함’이 날마다 갈립니다」 함정 한 줄과,
9/9 사장님 결정(「미동의 자동 재시도 유지」)을 **되돌리지 못하게** 못 박는 한 줄.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| **화면(`isStaffSkipRecording`)을 더 세게 고치기** | 왜 안 걸렸는지를 **못 쟀습니다**. 캐시가 원인이면 화면을 고쳐도 그 브라우저에는 안 갑니다. 서버가 마지막 관문이어야 합니다 |
| **`recordings` 에 「자동/수동」 칸 추가** | 지연 `ALTER` 는 없는 DB 에서 조회를 통째로 죽입니다(`no such column` — CLAUDE.md 2장). 그리고 원인 규명용이지 **사고를 막지는 못합니다** |
| **`recordings` 에 「마지막 하트비트」 칸 추가** | 같은 이유. **`recording_parts.created_at`** 이 이미 있고 그 값이 곧 «살아 있다» 입니다 |
| **막는 쪽으로 실패(fail-closed)** | 조회가 한 번 흔들리면 **그 수업 녹화가 0벌**이 됩니다. 사장님 지시(「수업에 덜 지장있게」)와 정반대 |
| **HTTP 409 로 거절** | 클라이언트가 오류로 보고 재시도 폭주. 이 저장소는 `consent_required` 에서 이미 **200 + `ok:false`** 로 풀었습니다 |
| **거절 응답에 「누가 찍고 있나」 싣기** | 🔴 **함정 대조가 잡았습니다** — `recordings.teacher_name` 은 화면의 **아이디 입력칸**(`#vc-name-input`, `autocomplete="username"`)에서 옵니다. 실측값이 `ysyt01`·`mby1`(**학생 계정**)이었고, `/api/recordings/start` 는 **무인증**이며 방번호는 `class-{예약id}-{YYYYMMDD}` 로 **열거 가능**합니다. 이 서비스에서 아이디는 곧 비밀번호(`password_hash` 설정 학생 **29,417명 중 0명**) ⟹ 응답에서 **뺐습니다**(서버 로그용으로만) |
| **같은 기기의 재시작을 예외로 두기** | 기기를 식별할 열쇠가 없습니다. 넣으려면 새 칸이 필요하고 **사람이 정할 일**로 남깁니다 |
| **창을 1분으로 좁히기 / 10분으로 넓히기** | 짧으면 느린 회선의 «살아 있는» 녹화를 죽은 것으로 봐 두 벌이 다시 생기고, 길면 유령이 오래 남습니다. **3분** + 막힌 기기가 **60초마다 재시도**라 상대가 죽어도 **최악 3분** 뒤 이어받습니다 |
| **(9/9) 「미동의만 골라 재시도에서 빼기」** | ⛔ 그 재시도는 `if (!isRecording) autoRecStarted = false;` **한 줄**이고, 그 줄이 **동시녹화 이어받기의 전부**입니다. 빼는 순간 상대 기기가 죽어도 그 방 녹화가 통째로 사라집니다. 사장님이 **유지**를 택하셨습니다 |
