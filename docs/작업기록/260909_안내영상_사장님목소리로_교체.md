# 안내 영상 짧은 판 — AI 복제 목소리를 «사장님이 주신 진짜 목소리» 로 교체

**날짜** 2026-09-09 · **지시** 사장님
> 「여기 들어간 동영상 목소리가 이상해. 내가 다시 준 MP3로 목소리 바꿔서 다시 편집해서 만들어줘.
>  배경음악은 그대로 유지하고 다시 할 수 있지?」 (mp3 첨부 · `today.html` 화면 캡처)

---

## 1. 무엇이 문제였나 — 지난번의 오판

올려주신 mp3 를 먼저 **md5 로 대조**했더니 2026-09-05 작업 때 쓴
`.audit/sample.mp3`(video9 브랜치)와 **바이트 단위로 같은 파일**이었습니다
(`679e1b4dc3e3a0c5b804c92d3dac2a59` · 1,174,509 B · 29.36초 · 320kbps 모노).

그래서 「같은 파일이니 복제해도 결과가 같다」로 끝낼 뻔했지만, **그 파일이 무엇인지**를
러너에서 받아쓰기(faster-whisper large-v3)로 확인했습니다. 결과 —

```
[  0.00 →  2.96] 영어는 매일 조금씩 만날 때 가장 오래 남아요.
[  3.60 →  5.82] 그래서 망고아이가 오늘 할 일을 정해줘요.
[  6.48 →  9.52] 수업이 있는 날은 수업 전 10분, 그리고 수업 후 10분.
…
[ 22.98 → 26.00] 오늘의 AI 학습을 열고 위에서부터 하나씩 하면 돼요.
[ 26.80 → 28.74] 자, 이제 우리 한번 재밌게 시작해봐요.
```

🔴 **이 파일은 «목소리 복제용 샘플» 이 아니라 짧은 판 대본 7줄을 그대로 읽은 «완성 나레이션»
이었습니다.** 2026-09-05 에 그것을 샘플로 보고 Higgsfield 로 목소리를 복제해 AI 가 다시 읽게
했고, 그래서 「목소리가 이상해」가 나왔습니다 — 사람 목소리가 있는데 그 목소리의 «복제본» 을
쓰고 있었던 것입니다. 마지막 한 줄(「자, 이제 우리 한번 재밌게 시작해봐요」)은 대본에도 없어
AI 판에는 아예 빠져 있었습니다.

⚠️ **지난번에 「샘플이 3~15 kHz 잡음으로 꽉 찬 녹음이라 복제가 그 성질을 베꼈다」고 적은 진단은
원인의 절반만 짚은 것이었습니다** — 진짜 원인은 «복제를 한 것» 자체였습니다.

## 2. 무엇을 했나

| | 전 (배포본) | 후 |
|---|---|---|
| 목소리 | AI 복제(Higgsfield seed_audio) | **사장님이 주신 원본 그대로** |
| 만드는 방식 | 7줄을 따로 뽑아 잘라 이어붙임 | **한 덩어리를 자르지 않고 통째로** |
| 길이 | 36.3초 | **30.10초** |
| 용량 | 5.59 MiB | **4.56 MiB** |
| 배경음악 | 같은 곡 · 시작·끝에만 | **그대로**(같은 URL·같은 봉투) |

✅ **오디오를 자르지 않는 것이 이번 설계의 핵심입니다.** 줄마다 잘라 이어붙이던 구조가
사라지므로 2026-09-05 에 두 번 잡았던 «툭»·«삡»·이음매 잡음이 **원천적으로 생길 수 없습니다.**
화면(슬라이드)만 문장 사이에서 넘깁니다.

### 장면 전환 — 시간을 손으로 적지 않았다

`silencedetect` 로 무음 구간을 **실측**하고, 받아쓰기 세그먼트와 대본 7줄의 매핑
(4·6번 줄은 두 문장으로 읽혔습니다)을 써서 «그 사이 무음의 한가운데» 를 전환점으로 삼았습니다.

```
t1  0.00 →  3.35   t2  3.35 →  6.17   t3  6.17 →  9.88   t4  9.88 → 15.57
t5 15.57 → 18.54   t6 18.54 → 22.71   t7 22.71 → 30.10
```

  게다가 사장님 지시(「이 MP3로 목소리 바꿔서」)의 뜻은 «이 소리를 넣어라» 였습니다.
- **잡음 제거 체인 걸기**(`afftdn`·`deesser` 등) — 걸지 않았습니다. 사장님 원본이고,
  이 컨테이너에는 오디오 디코더가 없어 **제가 들을 수 없습니다.** 세게 걸면 «물속 소리» 가
  된다는 것이 2026-09-05 실측입니다. 들어 보시고 잡음이 거슬리면 그때 겁니다.
- **모자란 6초를 늘려 36초에 맞추기** — 말을 늘리거나 여백을 넣는 것이라 부자연스럽습니다.
  대신 화면이 말하는 길이를 30초로 고쳤습니다.
- **긴 판(3분 47초)도 함께 교체** — 그 대본(18줄)을 읽은 음성은 없습니다. 손대지 않았습니다.

## 4. 밟은 함정

### 4-1. 낡은 사본을 보고 «배포가 안 됐다» 고 판단할 뻔했다
작업 시작 때 `cloudflare-deploy/…/ai-tools-short-kr.mp4` 가 5,887,335 B 라 「video11 수리본이
배포되지 않았다」고 읽었습니다. 그런데 그것은 **세션 시작 시점(9/8 14:12)의 사본**이었고,
`git fetch origin main` 뒤에 보니 PR #832(9/6 00:31)로 **이미 배포돼 있었습니다**(5,864,638 B).
✅ CLAUDE.md 의 「코드를 재기 전에 `git fetch origin main` 을 돌려라」 그대로입니다.
⟹ 그 덕에 「삡·중복은 이미 고쳐진 상태였고 남은 문제는 목소리 자체」라는 것이 분명해졌습니다.

### 4-2. 커밋 메시지의 `[skip ci]` 가 내 워크플로를 재웠다
받아쓰기 워크플로를 푸시했는데 실행이 **0건**이었습니다. 커밋 메시지에 `[skip ci]` 를 넣었기
때문입니다(CLAUDE.md 에 이미 있는 함정). 문구 없이 다시 푸시하니 즉시 돌았습니다.

### 4-3. 하니스가 `?v=7` 을 «글자 그대로» 못 박아 두었다
`today-page.js` 를 고쳐 규칙대로 `?v=8` 로 올리자 `today_plan_harness` 가 FAIL 했습니다 —
검사가 `/today-page\.js\?v=7/` 였습니다. **보장은 그대로인데 검사만 깨지는** 그 형태입니다.
✅ 「몇 번인가」가 아니라 **「버전을 달고 부르는가 + 그 번호가 원장에 있는가」**로 고쳤습니다.
변이시험: `?v=` 를 떼면 FAIL, 원장에 없는 `?v=99` 도 FAIL — 헛돌지 않는 것을 확인했습니다.
