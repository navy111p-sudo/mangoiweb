# 역할별 사이드바 숨김 — 「붙긴 하는데 안 감춰지던」 것 수리 (2026-09-09)

## 1. 왜 했나

사장님 「역할별 사이드바 숨김도 고쳐줘」.

바로 앞 작업(관리자 두 검색창, PR #908)에서 곁가지로 발견해 «지시 범위 밖» 으로 보고만
해 둔 것입니다. 그때 보고 문장은 이랬습니다 —

> 「CSS 특이성이 동률(둘 다 1,1,0)이라 문서 순서상 뒤가 이깁니다 —
>  지사·대리점 계정에서 감춰야 할 메뉴가 그대로 보일 수 있습니다.」

이번에 실측해 보니 **그 문장은 절반만 맞았습니다.** 특이성 동률은 사실이었지만
원인이 **하나가 아니라 둘**이었고, 둘째가 더 컸습니다.

## 2. 잰 것

### 2-1. 원인 ① — 이기는 규칙 (특이성 동률 + 문서 순서)

`adm-ia6.js` 의 `css()` 가 `document.head` 에 주입:

```
#ph85-sidebar .ia6-role-hide { display:none !important }      ← (1,1,0)
```

`cloudflare-deploy/public/css/admin-inline-c.css` — 겨루는 규칙이 **셋**입니다
(⛔ 행 번호로 적지 않습니다. 그 파일은 계속 자라서 곧 어긋납니다):

```
#ph85-sidebar .ph85-group { display:block !important }        ← (1,1,0)
#ph85-sidebar .ph85-sub   { display:block !important }        ← (1,1,0)
#ph85-sidebar .ph85-sub   { display:flex  !important; … }     ← (1,1,0)
```

그 블록의 자기 주석은 「권한 시스템이 어떤 역할로 hide 해도 ph85 사이드바는 강제 visible」입니다
— 즉 **역할 감춤을 이기려고 만들어진 규칙**입니다.

특이성이 같으니 **문서 순서상 뒤가 이깁니다.** 그런데 그 CSS 파일은 `<head>` 가 아니라
**`<body>` 안**에서 링크됩니다(`admin.html` — 그 파일 주석이 「head 로 올리면 안 됨」이라고
못 박아 두었습니다). ⟹ head 에 주입한 규칙은 **언제나 앞이고 언제나 집니다.**

**[잰 것 — 2026-09-09, 브라우저]** 강사 역할로 열고 「환불 처리」 항목:

```
class = "ph85-sub ia6-role-hide"     ← 붙긴 붙었다
getComputedStyle(el).display = "flex" ← 그런데 안 감춰졌다
```

⟹ **역할 감춤이 한 번도 안 먹고 있었습니다.** 카드 기반 항목까지 전부 포함해서입니다
(아래 회귀 검사에서 「카드를 감췄는데 항목은 그대로」로 재현됐습니다).

### 2-2. 원인 ② — 판정이 그 항목을 아예 안 본다

`applyRoleFilter()` 는 «가리키는 카드가 전부 감춰졌나» 로 판정합니다. 그런데 딴 페이지로
가는 항목(`href`)은 **카드가 아예 없어서** `known = 0` → 언제나 «남긴다» 입니다.

그 사실은 `adm-ia6.js` 안에 **주석으로 두 곳이나 적혀 있었습니다** —

* 수업 관제탑 옆: 「⚠️ href 항목은 카드가 없어 역할 필터를 못 받는다 — 강사·지사에게도 «보인다»」
* 환불 처리 옆: 「⚠️ 이 항목은 **역할 필터를 받지 않는다** … «메뉴를 아예 감추는» 일을 하려면
  href 항목용 역할 판정을 새로 만들어야 하고, 그건 사이드바 공용 로직이라 별건이다」

이번 지시가 정확히 그 «별건» 입니다.

⚠️ **«평소 화면» 이 그랬다고 읽으면 안 됩니다** — 강사가 `/admin.html` 을 열면
`teacherPortalRedirect` 가 `/teacher` 로, 조직 계정은 `managerPortalRedirect` 가 `/manager` 로
302 합니다(둘 다 `?full=1` 로만 우회). 그래서 이 감춤이 실제로 걸리는 곳은
**`?full=1` 로 콘솔에 들어온 경우**입니다 — 문서화된 탈출구이고 시연 계정 점검이 실제로 있습니다.
**그 빈도는 재지 않았습니다.**

## 3. 무엇을 바꿨나

`cloudflare-deploy/public/js/adm-ia6.js` 한 파일 (+ `admin.html` 의 `?v=58 → 59`).

1. **이기는 규칙을 (1,2,0)으로** — `#ph85-sidebar .ph85-sub.ia6-role-hide` ·
   `#ph85-sidebar .ph85-group.ia6-role-hide` 를 앞에 두고, 옛 (1,1,0) 줄은 폴백으로 남깁니다.
2. **항목마다 금지목록** — `hideFrom: ['teacher']` 처럼 GROUPS 에 적고, `build()` 가
   `data-ia6-hide-from` 으로 DOM 에 싣고, `applyRoleFilter()` 가 그것으로 판정합니다.
3. **신원이 늦게 와도 따라오게** — `document` 의 `mangoi:identity` 를 듣습니다.
4. **역할은 «이번 방문에 서버가 확인해 준 것» 만** — `window.__ADM_ME` 만 읽습니다.
   ⛔ `admIdentity()` 로 떨어뜨리지 않습니다: 그 함수는 `localStorage['admin_session']` 의
   **지난 방문 값**을 돌려주므로, 공용 PC 에서 앞사람이 강사였다면 본사 사람이 열 때 잠시
   «강사» 로 판정돼 **메뉴가 사라집니다**(빠지는 쪽 — 이 파일이 피하기로 한 바로 그 방향).
   ⚠️ 함정 대조가 잡았습니다. 제 하니스는 그 키를 지우고 시작해서 이 경로를 한 번도 안 밟았습니다.

## 4. 검토했다가 버린 것

* **허용목록(«이 역할만 보인다»)** — 나중에 역할이 하나 늘면 그 사람의 메뉴가 «조용히»
  사라집니다. 이 저장소는 빠지는 쪽을 더 나쁘게 봅니다 → **금지목록**으로 했고,
  모르는 역할·신원 미도착은 언제나 «보인다» 로 떨어집니다.
* **`admin-inline-c.css` 의 `display:flex !important` 를 지우기** — 사이드바 항목 전체의
  배치(별점·말풍선 정렬)가 그 규칙에 걸려 있습니다. 반경이 너무 큽니다.
* **역할 감춤 CSS 를 `admin-inline-c.css` 꼬리로 옮기기** — 되긴 하지만 판정과 규칙이
  두 파일로 갈립니다. `adm-ia6.js` 가 자기 규칙을 들고 있는 지금 구조가 낫습니다.
* **카드 쪽 역할 어휘(`hq_exec`·`hq_mgr`…)를 쓰기** — 서버 게이트와 어휘가 달라
  대조가 불가능합니다. 서버가 확인해 주는 `window.__ADM_ME.role` 을 씁니다.
* **「수강 운영」도 함께 감추기** — ⛔ 하지 않았습니다. 아래 5절.
