# 운영자 문자 — 「사이트 장애랑 감시견만 다시 켜줘」

- **앞 이야기**: [260908_운영자문자_전부_음소거.md](260908_운영자문자_전부_음소거.md) (PR #856)

## 1. 왜 했나

9/8 에 운영자(`OWNER_ALERT_PHONE`) 문자를 **전부** 껐고, 그때 작업기록의 「남은 것」에
이렇게 적어 두었습니다.

> **「사이트 장애(uptime)」와 「방 갈림 감시견」 둘만 나중에 되살릴지.**
> 그 둘은 «사람이 안 보면 며칠씩 모르는» 종류라 다른 알림과 성격이 다릅니다.

거기에 대한 사장님 답이 **「사이트 장애랑 감시견만 다시 켜줘」** 입니다.

**왜 그 둘만인가** — 나머지(결제·환불·이상 로그인·상담 리드)는 관리자 화면·D1 에 기록이 남아
나중에라도 사람이 볼 수 있습니다. 그런데 이 둘은 다릅니다.

- **사이트 장애** — 사이트가 죽으면 «화면을 열어서 확인하는» 그 화면이 안 열립니다
- **방 갈림 감시견** — 도메인이 갈리면 학생·강사가 같은 방 번호인데 서로 못 만납니다.
  이 저장소가 **네 번 사고**를 낸 자리이고, 매번 «사람이 제보할 때까지» 몰랐습니다

## 2. 무엇을 바꿨나

### `cloudflare-deploy/src/owner-sms-mute.ts` — 축을 «하나» 더

```ts
export const OWNER_ALWAYS_KINDS: readonly string[] = ['uptime', 'room-split'];

export function ownerSmsBlocked(v, kind): boolean {
  const s = String(v ?? '').trim().toLowerCase();
  if (s === 'off') return false;   // 전부 보냄 (음소거 해제)
  if (s === 'all') return true;    // 전부 막음 — 예외도 없음
  return !OWNER_ALWAYS_KINDS.includes(String(kind ?? '').trim().toLowerCase());
}
```

KV `owner_alert_mute` 가 세 갈래가 됐습니다.

| 값 | 뜻 |
|---|---|
| `off` | 전부 보냄 (9/8 이전으로) |
| `all` | 전부 막음 — **예외도 없음** (완전 침묵으로 되돌릴 길) |
| 그 밖(기본·없음·모르는 값) | **지금 정책** — 장애·감시견만 보내고 나머지는 막음 |

### `cloudflare-deploy/src/solapi-client.ts` — 게이트가 종류를 본다

`sendPlainSms(env, phone, text, { kind })` 로 **«무슨 알림인가» 를 밝힌 것만** 예외가 됩니다.

```ts
let muted = ownerSmsBlocked(null, opts?.kind);   // KV 를 못 읽어도 «지금 정책대로»
try { muted = ownerSmsBlocked(await env.SESSION_STATE?.get(OWNER_MUTE_KV_KEY), opts?.kind); } catch {}
```

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### ⛔ 버림 ① — 그 두 파일에서 게이트를 «건너뛰게» 하기

가장 짧습니다(`api-uptime.ts` 가 `sendPlainSms` 대신 다른 함수를 부르게 하거나, 게이트에
파일 이름을 넣거나). **그런데 CLAUDE.md 1-3 이 그 방식을 이미 금지하고 있습니다** —

> ⛔ **호출부 17군데를 각각 막지 마세요** — 새 알림이 생기면 조용히 새어 나갑니다

그 금지의 뜻은 «판정을 정본 밖에 두지 말라» 입니다. 그래서 **판정은 정본에 그대로 두고**,
호출부는 «내가 무슨 알림인지» 를 밝히기만 합니다(`kind`). 판정도 목록도 여전히 한 곳입니다.

🔑 **핵심 성질: 안 밝히면 막힙니다.** 나중에 누가 새 알림을 만들어도 `kind` 를 안 주면
그대로 음소거이므로, 9/8 사고(새 알림이 조용히 새어 나감)가 재현되지 않습니다.

### ⛔ 버림 ② — KV 에 종류별 스위치를 여러 개 두기

`owner_alert_uptime`·`owner_alert_payment` … 처럼 나누면 배포 없이 하나씩 켤 수 있습니다.
**그런데 켜야 하는 것이 두 개인데 스위치가 일곱 개가 되고**, 어느 것이 켜져 있는지 사람이
KV 를 하나씩 열어 봐야 알 수 있습니다. 지금 필요한 것은 «둘만» 이라 코드에 목록으로 두는 편이
읽기 쉽고, 되돌리는 길(`off`·`all`)은 그대로 KV 한 줄입니다.

### ⛔ 버림 ③ — 음소거를 통째로 풀고 결제·로그인 쪽만 막기

같은 결과처럼 보이지만 **실패 방향이 반대**입니다. 그렇게 하면 «막는 목록에 없는 새 알림» 이
자동으로 나가게 되어, 사장님이 9/8 에 고르신 방향(기본은 조용히)이 뒤집힙니다.

### ✅ KV 오류 때 «예외는 나가는» 쪽으로

9/8 에는 「모르면 안 보냄」이 맞았습니다(끄라는 지시였으므로). 지금은 정책이
「장애·감시견은 나간다」이므로 **모르면 «지금 정책대로»** 떨어지게 했습니다.
사이트가 죽어 KV 까지 흔들릴 때 장애 문자가 안 가면 이 변경의 의미가 사라집니다.

### 4-1. 🔴 함정 대조가 잡은 것 — 따옴표 한 종류로 뚫렸습니다

처음에 예외 가로채기 검사를 이렇게 썼습니다.

```js
/sendPlainSms\([^;]*?kind:\s*'([a-z-]+)'/g     // ← 홑따옴표만
```

`trap-check` 가 결제 알림에 **쌍따옴표**로 `{ kind: "uptime" }` 를 붙여 보니
**하니스가 65/65 초록**이었습니다. **이 PR 의 핵심 보장이 따옴표 하나로 조용히 사라진 것**입니다.
하필 그 자리가 9/8 지시를 되돌리는 자리입니다(결제·이상 로그인이 예외를 받으면 그 지시가 무의미해집니다).

✅ `['"\`]` 로 세 종류를 다 보게 고치고, **쌍따옴표·백틱 변이를 목록에 짝으로**(M4c·M4d) 넣었습니다.
⚠️ 남은 한계 — `[^;]*?` 라 **인자 문자열 안에 `;` 가 있는 호출은 못 봅니다**(지금 호출부에는 없습니다).

### 4-2. 같은 대조에서 함께 고친 것

- **⑧절이 «호출 개수»(3·1)를 못 박고 있었습니다** — 나중에 장애 알림이 하나 늘면
  보장은 세졌는데 검사만 빨간불이 됩니다. 「그 파일의 `sendPlainSms` 호출 중 **`kind` 를 빠뜨린 것이 0개**인가」로 바꿨습니다.
- **`src/` 훑기가 비재귀**였습니다(지금은 하위 폴더가 없어 통과 — «없어서 통과» 와 «봐서 통과» 는 다릅니다). 재귀로.
- **예외 집합이 두 벌**이었습니다(값 `OWNER_ALWAYS_KINDS` + 타입 `OwnerSmsKind`).
  `as const` + `typeof …[number]` 로 **타입을 목록에서 파생**시켜 한 벌로 묶었습니다.
- **하니스에 실번호가 박혀 있었습니다** — 검사는 `isOwnerPhone` 의 양쪽을 다 통제하므로
  가짜 번호로도 같은 답입니다. 바꿨습니다.
- **숫자 표기가 파일마다 달랐습니다**(`room-split-guard.ts` **2** vs **1곳**).
  둘 다 사실입니다 — 알림 «자리» 는 2곳인데 둘 다 `smsSafe()` 하나를 지나 **`sendPlainSms` 호출은 1곳**입니다.
  「하나 빠뜨렸나」로 읽히지 않게 주석에 한 절을 덧붙였습니다.

### 이 검사에서 조심한 것

🔑 **«막힌다» 와 «나간다» 를 짝으로** 두었습니다.
「예외가 나간다」만 검사하면 결제가 몰래 예외를 받아도 초록이고,
「나머지가 막힌다」만 검사하면 예외가 죽어도 초록입니다. 둘 다 필요합니다.

🔑 **목록을 «길이·순서» 로 못 박지 않았습니다.**
`OWNER_ALWAYS_KINDS.length === 2` 로 쓰면 나중에 정당하게 늘 때 **멀쩡한 수리가 빨간불**이 됩니다
(이 저장소가 여러 번 밟은 함정). 대신 「지금 꺼져 있어야 할 것(`payment`·`refund`·`login`·`lead`·
`absent`·`no-show`)이 켜져 있지 않은가」로 묻습니다.

🔑 **호출부는 소스 전체를 훑어 셉니다.** 목록만 좁게 두고 결제 쪽에서 `kind:'uptime'` 을 달면
그대로 새어 나가므로, `src/*.ts` 전부에서 «`kind` 를 넘기는 `sendPlainSms` 호출» 을 뽑아
**파일 이름까지 대조**합니다(M4b 가 그것으로 잡혔습니다).

### ❌ 아직 못 본 것

**「정말 장애 문자가 온다」는 확인 못 했습니다.** 사이트가 죽어야 발화하는 알림이고,
방 갈림도 도메인이 갈려야 울립니다. **일부러 만들 수는 없습니다.**
확인은 다음에 실제로 그 일이 생길 때이거나, 사장님이 원하시면 **`/api/uptime-hook?…&sim=down`**
(그 핸들러가 시뮬레이션을 받습니다)을 한 번 쏘는 것으로 됩니다 — **그건 사람이 정할 일입니다**
(진짜 문자가 한 통 갑니다).

**KV `owner_alert_mute` 의 «현재 값» 도 못 봤습니다** — Cloudflare 대시보드(코드 밖)입니다.
지금 코드는 그 값이 무엇이든(없어도) 장애·감시견이 나가지만, 누가 `all` 을 넣어 뒀다면
여전히 침묵합니다.

## 5. 되돌리는 법

| 원하는 것 | KV `owner_alert_mute` |
|---|---|
| **지금 상태** (장애·감시견만) | 값을 안 두거나 아무 값 |
| 전부 다시 받기 | `off` |
| **완전 침묵** (장애·감시견도 안 받기) | `all` |

Cloudflare 대시보드 > Workers & Pages > KV > `SESSION_STATE`. **배포 불필요, 즉시 적용.**

「결제만 다시 켜기」처럼 종류를 더 켜려면 `owner-sms-mute.ts` 의 `OWNER_ALWAYS_KINDS` 에
이름을 더하고 그 호출부에 `{ kind: … }` 를 답니다 — **그건 사장님이 정할 일입니다.**
