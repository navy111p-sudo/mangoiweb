## 1. 왜 했나

사장님 제보 —

> 회의방 1234에서 교사가 만나려고 하는데 학생이 아이디와 비번 넣으면 자꾸 `mangoi-class` 방으로 와 있어.
> 교사가 1234 누르면 방이름이 `meet-1234`로 되는데 그럼 학생은 `mangoi-class`에서 기다리고 있어.

스크린샷에는 교사 화면의 「🚪 회의방 — 방 번호로 만나기」 모달이 열려 있고 「지금 방: meet-1234」가 찍혀 있었습니다.

**⚠️ 에러가 한 줄도 안 납니다.** 양쪽 다 정상적으로 만들어진 방이고 각자 「참여자 1명」일 뿐이라, 화면·콘솔·D1 어디에도 «고장» 으로 보이지 않습니다. 이 저장소가 **네 번 사고**를 낸 「같은 방 번호를 넣었는데 서로 안 보이고 둘 다 참여자 1명」과 증상이 같습니다(그쪽은 «워커가 갈린» 것, 이쪽은 «방 이름을 만드는 규칙이 갈린» 것).

## 2. 무엇을 바꿨나

### 원인 — 방 이름을 만드는 규칙이 «두 곳» 이고 서로 달랐습니다

| | 넣은 값 | 실제 방 id |
|---|---|---|
| 교사 — 🚪회의방 모달 (`public/js/idx-vc-room.js`) | `1234` | **`meet-1234`** |
| 학생 — 로비 «⚙️ 방 코드 직접 입력» | `1234` | **`1234`** ← 다른 방 |
| 학생 — 아이디·비번만 (코드 빈칸) | — | **`mangoi-class`** ← 제보된 증상 |

- 모달은 `normalize()` 뒤에 `PREFIX = 'meet-'` 를 붙입니다(`idx-vc-room.js:12`·`46`).
- 로비는 `public/js/idx-main.js:2778` 의 **`vcRoomId = vcTypedRoom || VC_DEFAULT_ROOM`** 이라 **친 값을 그대로** 씁니다.
- 그래서 모달이 화면에 「**양쪽이 같은 번호를 넣어야 만납니다**」라고 약속해 놓고, 학생이 그 «같은 번호» 를 넣으면 **다른 방**으로 갔습니다.

코드를 아예 안 넣으면 공용방으로 가는 이유는 **따로**입니다 — 「빈칸 → 오늘 예약 방으로 자동 교정」 경로(`idx-main.js:2685~`)가 `class_schedules` 를 보는데, **회의방은 예약이 없어** 그 경로를 통째로 비켜 가고 `student_gate=off` 폴백으로 떨어집니다.

### 고친 파일

**`cloudflare-deploy/public/js/idx-vc-roomcode.js`** (defer — 첫 화면 예산 0바이트)

- `resolveRoomCode(raw)` 신설 — 접두사가 없는 값은 회의방 번호로 보고 `meet-` 을 붙입니다.
- `meetSlug(c)` — 모달의 `normalize()` 와 **같은 다듬기**(소문자 · 공백→`-` · 허용문자 밖 제거).

- 이미 있던 `vcJoinRoom` 래퍼가 입장 **직전**에 방 코드 칸을 해석한 값으로 다시 적습니다.

**`cloudflare-deploy/public/index.html`** — `?v=1` → `?v=3` **한 줄만**(공동 금지구역).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

### 3-1. ⛔ 모달에서 `meet-` 접두사를 없애기

가장 단순해 보이지만 **접두사가 일을 하고 있습니다.** `__vcIsMeetingRoom()`(`idx-vc-room.js:41`)이 그 접두사 하나로 판정하고, 그 값을 보는 곳이 다섯입니다 — 출석 포인트 적립(`idx-main.js:3717`) · 강사 AI 코칭 카드(`idx-main.js:7040`) · 복습퀴즈 안내 3곳(`index.html`). 없애면 회의가 «수업» 으로 집계됩니다.

### 3-2. ⛔ 학생 로비의 빈칸 폴백을 「교사가 지금 있는 회의방」으로 보내기

증상만 보면 이게 «가장 친절한» 답이지만 **추측입니다.** 지금 어느 교사의 어느 회의방으로 보낼지 알 방법이 없고, 틀리면 학생이 남의 회의에 들어갑니다. 이 저장소의 원칙(「모르면 붙이지 않는다 — 모르는 것보다 틀린 게 나쁘다」)에 어긋납니다.

### 3-3. ⛔ 학생 로비의 초록 안내문을 고치기

「아이디·비밀번호만 입력하면 선생님과 같은 수업방에서 자동으로 만나요」는 **회의방일 때 사실이 아닙니다.** 하지만 그 문구는 `public/index.html:8130`(**공동 금지구역**) 안이고, 이번 지시 범위 밖입니다 → **안 건드리고 「남은 것」으로 넘겼습니다**(5-1).

📌 **2026-09-09 후속 — 사장님 「응」으로 승인받아 고쳤습니다.** 아래 6장을 보세요. 이 절은 «그때 왜 미뤘는지» 로 남깁니다 — 공동 금지구역은 승인 없이 안 건드린다는 판단 자체는 그대로 맞습니다.

### 3-4. 🔴 접두사 목록에 `meet-` 을 넣었다가 **뺐습니다** (#901 → #903)

#901 에서는 `KNOWN_ROOM` 을 `/^(?:meet-|class-|demo-|room-|c24-|mangoi-class$)/i` 로 두었습니다. 「이미 접두사가 있으니 그대로 둔다」는 뜻이었는데, **그 정규식이 `/i` 라 대문자 `MEET-` 도 걸려 «원문 그대로» 돌아갔습니다.**

[잰 것 — 두 규칙을 소스에서 오려 내 실제로 돌림]

| 입력 | 모달(교사) | 로비(학생) |
|---|---|---|
| `1234` | `meet-1234` | `meet-1234` ✅ |
| `MEET-1234` | `meet-1234` | **`MEET-1234`** ❌ |
| `Meet-1234` | `meet-1234` | **`Meet-1234`** ❌ |

방은 `env.VIDEO_CALL_ROOM.idFromName(roomId)` 로 갈리는데 그것은 **대소문자를 구분**합니다 → `meet-1234` 와 `Meet-1234` 는 다른 Durable Object 입니다. 하필 그 입력칸(`index.html:8135`)에는 `autocapitalize` 가 **없어서** 폰 키보드가 첫 글자를 대문자로 만듭니다 — 계정 아이디에서 이미 밟은 함정입니다(CLAUDE.md 2장 「같은 사람인데 계정이 두 개」).

⟹ **#901 이 고치려던 사고가 대문자로 그대로 남아 있었습니다.** #903 에서 `meet-` 을 목록에서 빼 회의방은 접두사가 붙었든 아니든 `meetSlug()` 한 자리로 모으게 했습니다.

⛔ **다른 접두사까지 소문자로 내리지는 않았습니다** — 서버가 내는 값(`class-`·`c24-`·`demo-`)은 전부 소문자라 안전해 보이지만, 사람이 `Class-849-…` 를 쳤을 때 `meet-class-849-…` 가 되어 오히려 나빠집니다. 「회의방만 고친다」가 이 변경의 범위입니다.

### 3-5. ⛔ `idx-vc-room.js`(blocking)에 정본을 두기

규칙의 «주인» 은 모달 쪽이라 거기에 두는 것이 자연스러워 보이지만, **첫 화면 무게 예산 여유가 325바이트**뿐입니다(실측 1,612,986B / 하니스가 막는 선 1,613,311B). 그 예산은 필리핀 회선을 지키려고 둔 것이라 defer 파일에 뒀습니다.

⚠️ 대가: **규칙이 두 파일에 있습니다.** 그래서 하니스가 두 규칙을 **오려 내 실제로 돌려 답을 대조**합니다(어느 쪽을 고쳐도 어긋나면 FAIL).

## 5. 남은 것 / 주의할 것

### 5-1. ✅ 학생 로비의 초록 안내문 — **고쳤습니다**(같은 날 후속, 6장)

`index.html:8130` 의 「✅ 아이디·비밀번호만 입력하면 선생님과 같은 수업방에서 자동으로 만나요」는 **예약된 수업(`class-…`)에만** 참이었습니다. 회의방은 예약이 없어 그 자동 연결을 못 탑니다.

처음에는 **공동 금지구역**이라 안 건드리고 넘겼는데, 사장님이 「응」으로 승인해 주셔서 같은 날 고쳤습니다 → **6장**.

⚠️ 그래도 **가장 확실한 안내는 여전히 모달의 「🔗 초대 링크 복사」** 입니다(번호 오타·대소문자 사고가 함께 사라집니다).

### 5-2. ⚠️ «번호만 친 방» 의 포인트·퀴즈가 꺼집니다 — 반경을 못 쟀습니다

이번 수리로 접두사 없는 코드는 전부 `meet-` 이 됩니다 → `__vcIsMeetingRoom()` 이 참이 되어 그 방에서 **출석 포인트 적립 · 복습퀴즈 안내 · 강사 AI 코칭이 꺼집니다**(에러 없음).

회의·비상수업 용도면 맞는 동작입니다. 그런데 `idx-main.js:2665` 주석이 이렇게 **문서화**하고 있습니다:

> 이제 비우면 모두가 같은 방(mangoi-class)으로 모여 서로 보임. **(반/수업별로 나누려면 같은 코드를 입력)**

즉 bare 코드가 «반별 수업방» 으로 쓰이고 있었다면 오늘부터 조용히 멈춥니다.

**이 컨테이너에서는 D1 을 못 잽니다**(`node_modules` 없음 → wrangler 없음). 반경 조회:

```sql
SELECT room_id, COUNT(*) n, COUNT(DISTINCT username) u
FROM attendance
WHERE joined_at > (unixepoch()-90*86400)*1000
  AND room_id NOT LIKE 'class-%' AND room_id NOT LIKE 'c24-%'
  AND room_id NOT LIKE 'meet-%'  AND room_id NOT LIKE 'demo-%'
  AND room_id NOT LIKE 'room-%'  AND room_id <> 'mangoi-class'
GROUP BY room_id ORDER BY n DESC LIMIT 30;
```

- **0건이면** 해당 없음.
- 몇 건이라도 나오면 그 학생들의 출석 포인트가 안 쌓이므로 **별건으로 처리해야 합니다**(그 방 이름을 `KNOWN_ROOM` 예외로 넣거나, `__vcIsMeetingRoom` 쪽을 좁히거나 — 사람이 정할 일).

### 5-4. 함께 정리한 것

- **⑥ 검사 이름이 실제 보장보다 넓었습니다** — 「빈칸은 **공용방 폴백 보존**」이라 적었는데, 배선(`normalizeRoomInput`)은 `!fixed` 면 **칸을 안 건드립니다**. 즉 `'!!!'` 는 공용방으로 가는 게 아니라 `'!!!'` 그대로 남습니다(옛 동작 그대로라 회귀는 아니지만, 그 이름을 다음 사람이 근거로 삼습니다). → 「방 이름을 만들 수 없는 값은 만들지 않는가」로 좁히고, 배선 검사를 ⑥-2 로 따로 뒀습니다.
- **부정 검사가 자기 주석을 잡던 것** — 「칸에 보여 주는가」 검사가 `// input.value = fixed;` 로 **주석 처리해 죽여도 통과**했습니다(변이시험에서만 드러남). 주석을 벗겨 낸 사본으로 판정하도록 고쳤습니다.
- **브라우저 하니스의 죽은 코드 3줄** 삭제 — 주석이 「원본을 가짜로 바꿔 치고」라고 말하는데 실제로는 아무 일도 안 하고 있었습니다.

### 5-5. 검사 환경에서 밟은 것 (다음 사람 시간 아끼라고)

- **헤드리스에서 `alert` 이 뜨면 렌더러가 멈춥니다.** 처음에 로비 이름 칸을 채우고 `vcJoinRoom()` 을 불렀더니 미디어·소켓까지 진행되어 검사가 통째로 멈췄습니다. → **이름 칸을 «비워» 두면** 진짜 `vcJoinRoom` 이 첫 줄에서 곧바로 `return` 하고, 그때 `normalizeRoomInput()` 은 **이미** 돌았으므로 «래퍼가 한 일» 만 깨끗하게 잽니다.
- 한 번 멈춘 페이지는 **다음 `Runtime.enable` 도 함께 멈춥니다** — 브라우저를 새로 띄워야 합니다.
- 로컬로 다시 잴 때는 `Network.setCacheDisabled` **와** `Network.setBypassServiceWorker` **둘 다** 켜야 합니다(SW 가 cache-first 라 «고치기 전» 사본이 나옵니다).

### 6-4. 🔴 그 대비를 «CSS 를 읽어 합성하는» 방식으로 재려다 두 번 틀렸습니다

처음에는 조상들의 `background-color`·그라데이션을 읽어 알파 합성했습니다. 그 방식이 **이미 몇 달째 배포돼 잘 보이던 초록 줄까지 「실패」로** 판정했습니다. 원인 셋:

1. 한 요소의 `background-color` 와 `background-image` 는 «둘 중 하나» 가 아니라 **«색 위에 이미지»** 입니다. 나란히 «후보» 로 세는 바람에, 불투명한 색이 있는데도 아래가 비쳐 보이는 조합이 만들어졌습니다.
2. 이 화면 뒤는 **사진(`url(...)`)** 이라 CSS 만으로는 색을 알 방법이 **원리상 없습니다.**
3. 그래서 최악 조합이 `body` 의 흰색(`rgb(244,247,252)`)까지 끌어와 대비를 2.94 로 계산했습니다.

⟹ **«틀린 실패» 는 다음 사람이 멀쩡한 색을 고치러 가게 만듭니다.** 그래서 **픽셀을 직접 재는 방식**으로 바꿨습니다 — 글자를 잠깐 `color:transparent` 로 만들어 그 자리를 `Page.captureScreenshot` 으로 찍고(= 진짜 배경), 계산된 글자색을 그 위에 합성합니다. 사진·그라데이션·반투명이 몇 겹이든 원리상 안 틀립니다(PNG 는 `node:zlib` 로 직접 풉니다 — 8bit·비인터레이스).

그 뒤에도 **두 번 더** 틀렸고 둘 다 잰 값이 이상해서 잡았습니다:

- **정규식이 통째로 깨져 있었습니다.** JS 템플릿 리터럴 안에 `/rgba?\(([^)]+)\)/` 를 그냥 쓰면 `\(` 가 **`(` 로 풀려** `/rgba?(([^)]+))/` 가 됩니다. `parseFloat('(110')` → `NaN` → 글자색 R 이 `null`. 템플릿 안에서는 **`\\(`** 로 써야 합니다.
- **`captureScreenshot` 의 `clip` 은 «문서» 좌표인데 `getBoundingClientRect()` 는 «뷰포트» 좌표입니다.** `scrollIntoView` 한 뒤 스크롤을 안 더해 **엉뚱한 자리(배경 사진)를 찍고** 「대비 1.17」이 나왔습니다.
