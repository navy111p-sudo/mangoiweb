# 결재함 「알림 받기」 — 실패를 한 줄로 뭉개지 않고 «사유» 를 말하게 (2026-09-10)

> 사장님 제보 — **「알람받기 안 안켜진다고 나오지?」** (스크린샷에 「알림을 켜지 못했습니다.」 토스트)

---

## 1. 무엇이 문제였나

버튼을 누르면 이 네 단계를 거칩니다.

```
① /api/push/vapid-public-key 로 발급 키 받기
② navigator.serviceWorker.register('/sw.js')
③ reg.pushManager.subscribe(...)
④ /api/push/subscribe 로 서버에 저장
```

그런데 옛 코드는 넷을 **`catch` 하나**로 받아 전부 같은 문장을 냈습니다.

```js
.then(function(j){ pushOn = !!(j && j.ok); paintPushBtn(); return pushOn; })
.catch(function(){ return false; });      // ← 사유가 여기서 통째로 사라진다
...
toast(ok ? '결재가 오면 알려 드립니다.' : '알림을 켜지 못했습니다.');
```

**「알림을 켜지 못했습니다」는 틀린 말이 아닙니다 — 다만 아무것도 알려 주지 않습니다.**
서버에 키가 없는 것인지, 이 브라우저가 거절한 것인지, 마지막 저장만 안 된 것인지가
전부 같은 문장이 되어 **다음에 무엇을 해야 하는지가 정해지지 않습니다.**

## 2. 고친 것

`subscribePush()` 가 **`{ ok, why }`** 를 돌려주고 화면이 `why` 를 그대로 말합니다
(`cloudflare-deploy/public/work.html`).

| 단계 | 화면에 나오는 말 |
|---|---|
| `net` | 서버에 닿지 못했습니다. 연결을 확인하고 다시 눌러 주세요. |
| `http` | 서버가 알림 키를 주지 못했습니다 (HTTP 500). 잠시 뒤 다시 눌러 주세요. |
| `key` | 서버에 알림 키(VAPID)가 아직 없습니다. 관리자가 등록해야 합니다. |
| `sw` | 이 브라우저에서 알림용 백그라운드 등록에 실패했습니다. |
| `subscribe` | 이 브라우저가 알림 구독을 거절했습니다. |
| `save` | 이 기기에서는 등록됐지만 서버가 저장하지 못했습니다. |

곁가지 둘도 함께 고쳤습니다.

- **연결 실패를 `key` 로 읽지 않습니다.** 그대로 두면 「서버에 키가 없다」고 말해
  **관리자를 엉뚱한 곳(시크릿 등록)으로 보냅니다.** 끊긴 것과 없는 것은 다른 사실입니다.
- **`repaint()` 마다 조용히 재시도하던 것을 한 번으로 막았습니다**(`pushSilentTried`).
  실패하면 `pushOn` 이 다시 `false` 가 되므로, 가드가 없으면 화면을 그릴 때마다
  발급요청·SW등록·POST 가 새로 나갑니다. ⛔ **버튼(`askPush`)은 이 가드에 안 걸립니다** —
  사람이 누르면 언제든 다시 시도해야 합니다.
- 진짜 예외는 **콘솔에도** 남깁니다(`console.warn('[push] 실패 step=…')`). 토스트는 몇 초 뒤 사라집니다.
- **단계를 새로 넣고 문구표를 잊으면 「알 수 없는 단계」라고 말합니다.** 옛 코드는 기본값이
  「이 브라우저가 알림 구독을 거절했습니다」여서 **틀린 문구가 조용히** 나갈 자리였습니다.

### 🔴 함정 대조가 잡은 것 — 제가 방금 쓴 규칙을 그 자리에서 어겼습니다

**`fetch` 는 404·500·502 에도 reject 하지 않고 resolve 합니다.** 그래서 처음 고침은
`TypeError` 한 갈래(`.catch`)만 잡았고, **HTTP 오류는 그 갈래를 지나가** 본문이 JSON 이
아니니 `null` → `!j` → `no_key` 로 떨어졌습니다.

> 화면 문구: 「서버에 알림 키(VAPID)가 아직 없습니다. **관리자가 등록해야 합니다.**」

즉 **서버가 잠깐 흔들린 것**을 「키를 등록하라」로 말해 관리자를 엉뚱한 곳으로 보냅니다 —
2026-08-26 TURN 실사고(`public-fallback` 하나가 «키 없음 / 거절 / 연결 실패» 셋을 뭉뚱그려
반나절을 잘못 짚음)와 **같은 모양**입니다. `r.ok` 를 보고 `http` 단계로 가릅니다.

같이 잡힌 것 둘 — **거짓 주석**(「json() 을 안 잡으면 엉뚱한 단계로 밀린다」고 적었는데
그 시점의 `step` 은 언제나 `'key'` 라 결과가 같습니다. 주석이 «막았다» 고 말하면 다음 사람이
위 결함을 «이미 처리된 것» 으로 읽고 지나갑니다) · **`pushSilentTried` 가 끊긴 사람을 영구히
막던 것**(태풍·정전으로 오프라인에서 열면 첫 회차가 `net` 으로 실패하며 가드가 박혀,
회선이 돌아와도 그 탭이 사는 동안 안 붙습니다 — 하필 이 화면이 겨냥한 사용자입니다.
지금은 `net` 이면 가드를 풀어 다음 회차에 붙습니다).

## 3. 검토했다가 버린 것

| 버린 것 | 왜 |
|---|---|
| **VAPID 시크릿을 지금 등록하기** | 🔴 **어느 단계가 실패하는지 아직 안 쟀습니다.** 이 컨테이너는 프록시가 `mangoi.ai` 를 403 으로 막아 `/api/push/vapid-public-key` 를 부를 수 없습니다. 이미 있는 키를 덮어쓰면 **「고쳤다」는 기록만 남고 원인은 그대로**입니다(2026-08-26 TURN 실사고와 같은 모양). |
| **불리언을 그대로 두고 사유를 전역 변수에 담기** | 호출부가 둘인데 전역 상태는 다음 사람이 어디서 읽히는지 못 찾습니다. |
| **`''`(성공) / 사유 문자열 로 돌려주기** | 🔴 호출부의 `if (!ok)` 가 **성공에서 참**이 되어 정반대로 동작합니다. `{ ok, why }` 는 `r.ok` 라 오해할 여지가 없습니다. |
| **자동으로 권한 창 띄우기** | 옛 주석이 이미 못 박아 둔 것 — 묻지도 않고 뜨는 권한 창은 대부분 거절당하고, 거절은 되돌리기 어렵습니다. |
| **`controllerchange` 자동 reload 되살리기** | CLAUDE.md 1-3 「되살리면 안 되는 것」. |

## 5. ❌ 아직 못 쟀습니다 — 사람이 확인해야 하는 것

**사장님 화면에서 실제로 어느 단계가 실패하는지는 모릅니다.** 프록시가 막아
제가 직접 부를 수 없고, 옛 코드는 그 사유를 남기지 않았습니다.

배포 뒤 결재함에서 「알림 받기」를 한 번 더 누르면 **화면이 이유를 말합니다.**
그전에 지금 당장 가리고 싶으면 브라우저 주소창에 이것을 열면 5초면 됩니다.

```
https://mangoi.ai/api/push/vapid-public-key
```

- `{"ok":true,"key":"","mode":"disabled"}` → **서버에 VAPID 키가 없습니다**(관리자 등록 필요)
- `key` 에 긴 문자열이 있고 `mode":"real"` → 서버는 정상 · 원인은 브라우저·기기 쪽

관리자로 로그인한 상태면 `https://mangoi.ai/api/admin/push/status` 가
`has_pub_key`·`mode`·`active_subs` 까지 함께 보여 줍니다.

> ℹ️ 아이폰은 **「홈 화면에 추가」한 뒤에만** 웹푸시를 받을 수 있습니다(플랫폼 제약).
