## 1. 왜 했나

전날(2026-09-09) 역할별 사이드바 숨김을 고치면서 **「수강 운영」만 일부러 안 감췄습니다.**
서버에 가드가 없는데 메뉴만 감추면 ⓐ 진짜 문제가 눈에서 사라지고 ⓑ 그 화면을 쓰던
조직 계정이 이유도 모른 채 못 쓰게 되기 때문입니다. 그때 사장님께 「그 엔드포인트에
게이트를 달지 여부」를 결정 사항으로 올렸고, 이번에 「달아줘」로 정해졌습니다.

## 2. 잰 것

### 2-1. 무엇이 열려 있었나

`/api/pay/enroll/admin/*` 의 게이트는 **`checkAdminSession` 하나뿐**이었습니다.
즉 **로그인한 사람이면 강사든 지사든 대리점이든 전부 실행**할 수 있었습니다.

| 경로 | 열려 있던 것 |
|---|---|
| `prices` GET/POST | 전국 학원별 학생 수 + 주1회 단가 300개 읽기·쓰기 |
| `teacher-rates` GET/POST | 활성 강사 300명 **이름 + 급여 배율 + 긴 수업 정원** 읽기·쓰기 |
| `holidays` GET/POST | **회사 전체** 공휴일 등록·삭제 |
| `ending-soon` GET | 전국 만료 임박(종료 후보) 학생 명단 |
| `expiry-sweep` GET | 만료 안내 스윕 실행 — **`?dry=0` 이면 학부모에게 문자가 실제로 나갑니다** |
| `holiday-shift` GET | 공휴일 연기 스윕 실행 |
| `teacher-leave` POST | **하루치 수업의 담당 강사를 통째로 다른 강사로 변경** |
| `refund-quote` GET | 주문 환불 계산 |

### 2-2. 왜 어느 감시에도 안 걸렸나

- `src/index.ts` 의 **강사 차단**(`TEACHER_BLOCKED_PREFIXES`)과 **스코프 차단**(`forbidden_scope`)은
  **`/api/admin/` 접두사에만** 걸립니다. 이 경로는 `/api/pay/` 밑이라 둘 다 비켜 갑니다.
- `admin_write_guard_harness`(「강사가 부를 수 있는 새 관리자 쓰기 API」 탐지)도
  **`/api/admin/*` 만 훑습니다.** 그래서 이 구멍은 그 감시망 «밖» 이었습니다.

### 2-3. 화면은 무엇을 부르나 (막아도 되는지 확인)

| 화면 | 부르는 것 | 판단 |
|---|---|---|
| `/enroll-ops.html` 「수강 운영」 | teacher-rates · holidays · ending-soon · expiry-sweep · holiday-shift · teacher-leave · refund-quote | 여섯 탭이 **전부 회사 전체 운영**. 조직 계정용 칸 0개 |
| `/enroll-pricing.html` 「대리점 단가 관리」 | prices | 화면 자체가 「본사가 입력합니다」라고 적혀 있음 |
| `js/adm-today-classes.js` 「오늘 수업」 | substitute-candidates · substitute | 🔴 **조직 계정이 실제로 쓰는 자리** — 손대면 안 됨 |

### 2-4. 🔴 `getAdminActor().role` 만 보면 fail-open 이다

`isOrgScopedRole(actor.role)` **하나만** 두려다 함정을 찾았습니다.

`getAdminActor()` 는 안에서 `getScope()` 를 부르는데 그 호출이 `try/catch` 로 감싸여 있어
**실패하면 예외를 삼키고 `scopeType='none'`** 이 됩니다(`auth-admin.ts`). 그러면
`resolveRole('none', username, '')` 이 어느 분기에도 안 걸려 **`staff`(본사 동급)** 를 돌려줍니다.

⟹ **D1 이 한 번 흔들리면 지사 계정이 그대로 통과합니다.** 에러도 로그도 안 납니다.

D1 실측(2026-09-10, SELECT 만):

```
scope_type   n   계정
teacher     23   mangoi_* 등
branch      11   branch_busan, branch_daegu, capi_*
hq           6   admin, mgr_jjw, mgr_karl, mgr_lby, mgr_maimai, mgr_melca
none         4   hq_t_001, hq_t_anna, hq_t_kang, hq_t_len
(행 없음)    4   agency_sc002, capitown, cfo, ops_lead
agency       1   agency_gn001
```

**행이 없는 4개**는 매번 `autoSeedOne()` 의 «이름으로 추측» 을 탑니다 —
`서초 대리점`→agency · `캐피타운 본사`→franchise(capi 접두사) · `본사·재무(CFO)`→hq ·
`본사·관리자`→hq 로 **전부 정확히 추측됩니다.** 즉 평소에는 잘 돌고 **흔들릴 때만 샙니다.**

## 3. 무엇을 바꿨나

### 3-1. 서버 — 정본 한 곳 (`src/enroll-ops.ts`)

`handleEnrollApi` 첫머리에 **제외 목록 방식**의 게이트를 한 번 둡니다.

```ts
if (path.startsWith('/api/pay/enroll/admin/') && !ENROLL_ADMIN_SELF_GATED.has(path)) {
  const denied = await enrollAdminHqOnly(request, env);
  if (denied) return denied;
}
```

- **제외 목록 방식**이라 이 접두사에 새 엔드포인트가 생기면 **아무것도 안 해도 본사 전용**입니다.
  허용 목록으로 짰다면 새 API 가 조용히 열린 채 나갑니다 — 이 파일이 방금 그래서 뚫려 있었습니다.
- 제외는 **대체강사 두 경로뿐**입니다. 2026-08-30 사장님 지시로 «차단» 이 아니라
  «스코프로 자르기» 를 택한 자리라(`subScopeDenied`) 함께 막으면 그 결정을 되돌리는 것이 됩니다.

`enrollAdminHqOnly()` 는 **«모르면 막는 쪽»** 으로 실패합니다:

1. 세션 없음 → 401
2. `actor.isTeacher` → 403 `forbidden_teacher`
3. **`admin_scope.scope_type` 를 삼키지 않고 한 번 더 읽습니다.**
   던지거나 · 행이 없거나 · 값이 비면 → 403 `scope_unknown`
4. `teacher` → 403 `forbidden_teacher` (이름 기반 판정을 못 탄 계정까지)
5. `isOrgScopedRole(scopeType)` → 403 `forbidden_scope`
6. 그 외(hq·none·staff) → 통과

「행이 없으면 막는다」가 안전한 이유: 바로 앞 `getAdminActor()` 가 `getScope()` →
`autoSeedOne()` 으로 **행을 심어 놓습니다.** 그러고도 없다면 심기까지 실패한 것입니다.

### 3-2. 화면 — 짝 (`js/adm-ia6.js` · `admin.html`)

사이드바 「수강 운영」에 `hideFrom: ['teacher', 'franchise', 'branch', 'agency']`.
서버만 있으면 «눌러도 안 되는 버튼» 이 남고, 화면만 있으면 URL 로 뚫립니다(CLAUDE.md).
`admin.html` 의 `adm-ia6.js?v=59` → **`?v=60`**.

⚠️ 값은 **순수 리터럴**입니다 — 상수 이름을 쓰면 GROUPS 를 오려 내 `eval` 하는 하니스 셋에서
GROUPS 가 통째로 `null` 이 됩니다(PR #912 에서 실제로 밟은 함정).

## 4. 검토했다가 버린 것

### 4-1. 「스코프로 자르기」 — 버림

CLAUDE.md 는 「차단보다 «스코프로 자르기» 를 먼저 검토하라」고 합니다. 그래서 봤습니다.
후보는 `ending-soon`(만료 임박 학생) 하나였는데 버렸습니다:

- 나머지 여섯 탭이 전부 회사 전체 정책이라 **한 엔드포인트만 잘라도 화면이 성립하지 않습니다.**
- 조직 계정에는 **자기 소속 학생의 이탈·만료를 보는 자리가 이미 따로 있습니다**
  (관리자 카드 「⏰ 만료 임박 학생」·「이탈 관리」 — 그쪽은 `/api/admin/` 접두사라 스코프가 걸립니다).

즉 막아도 **조직 계정이 다른 데서 못 얻는 정보를 잃지 않습니다.**

### 4-2. `getAdminActor().role` 하나로 판정 — 버림

위 2-4 의 fail-open 때문입니다. 두 줄이 늘지만 이 경로에는 **문자 발송**과
**수업의 담당 강사 변경**이 있어 «되돌릴 수 없는» 쪽입니다.

### 4-3. `getAdminActor()` 자체를 고치기 — 안 함

그 함수는 저장소 전역이 씁니다. 실패를 던지게 바꾸면 반경이 너무 큽니다.
대신 **이 게이트가 자기 근거를 한 번 더 확인**하는 쪽을 골랐습니다.

## 5. 안 한 것

### 5-1. `subScopeDenied`(대체강사)의 같은 fail-open

`subScopeDenied()` 도 `actor.role` 만 보고 `isOrgScopedRole` 이 거짓이면
**조건절 검사 자체를 건너뜁니다** — 위와 같은 병입니다. 기존 코드이고 이번 지시 범위 밖이라
**안 고쳤습니다.** 👉 고칠지는 사람이 정할 일입니다.

### 5-2. `/enroll-ops.html`·`/enroll-pricing.html` 화면 자체의 로그인 게이트

두 화면은 `/admin/` 아래가 아니라 사이트 루트라 `isAdminPath` 의 default-deny 를 안 받습니다.
HTML 에 자료가 없고 안의 값은 전부 API 로 받으므로 **지금은 빈 화면만 보입니다.**
바꾸려면 `src/index.ts`(공동 금지구역)를 고쳐야 해서 안 했습니다.

### 5-3. `admin_write_guard_harness` 의 범위 확대

그 하니스가 `/api/admin/*` 만 훑는 것이 이 구멍을 못 본 이유입니다. 범위를 넓히면
무관한 경로가 대량으로 목록에 올라오므로 **별건**입니다. 대신 이번 하니스가
`/api/pay/enroll/admin/*` 전수를 봅니다.
