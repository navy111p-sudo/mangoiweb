## 0. 한 줄 요약

**화면은 고장난 것이 아니라 «사실» 을 말했습니다** — 그 순간 회선이 실제로 무너져 있었고(왕복 8.8초·
소리 끊김 51%), 자동 음성전용(AAO)이 설계대로 카메라를 껐습니다. **고쳐야 할 것은 «왜 그 회선이
무너졌나»(=TURN 릴레이 우회 + 카톡 인앱 브라우저)와 «화면이 그것을 한국어로 말하지 않은 것» 입니다.**

## 2. 그 두 문구가 «왜» 떴는지 — 코드 근거

### 2-1. 「Weak connection — audio only for now」 = 자동 음성전용(AAO)

`js/idx-main.js` 의 4초 주기 판정입니다.

```js
if (alp > 8 || art > 600) { A.sev++; A.good = 0; }   // 오디오 손실 8%↑  또는  RTT 600ms↑
...
if (!A.active && A.sev >= 3 && ...) { …영상 트랙 끔… }  // 3틱(12초) 연속이면 진입
```

상대에게는 `vcBroadcastCamState(false,'aao')` 로 알려 주고, 받는 쪽이
`vcApplyRemoteCamHint()` 로 그 얼굴칸에 그 문장을 그립니다. **즉 스크린샷의 안내는
«상대 기기가 스스로 카메라를 껐다» 는 뜻이고, 검은 화면을 «고장» 으로 오해하지 말라고
일부러 넣어 둔 안내입니다.**

🔑 **어느 가지로 발화했나** — 위 표의 마지막 칸이 답입니다.
**음성전용이 켜진 4분 전부에서 송신 오디오 손실이 `0.00%`** 였습니다.
⟹ **손실 가지(8%)가 아니라 RTT 가지(600ms)로 발화**했습니다.

### 2-2. 「Receiving low quality」 = 저화질 수신 배지

`js/idx-vc-qlog.js` 의 ③절. 받는 영상 가로폭이 «그 상대에게서 본 최대 폭» 의 1/2.5 이하면
2틱(8초) 뒤 붙습니다. 그 1분에 영상 멈춤 20회였으니 **이 배지도 사실입니다.**

## 3. 원인 — 세 겹

### ① 회선이 «직결» 이 아니라 «릴레이 우회» 였다  〔잰 것〕

원장님 쪽은 73분 중 **60분(82%)이 `relay`**, TURN 서버 `turn.cloudflare.com:3478 udp` 경유였습니다.
같은 방의 강사는 `direct`/`mixed` 였습니다 — **한쪽만 우회**했습니다.

최근 7일 전수로 봐도 경로가 곧 품질입니다.

| 경로 | 기록 분 | 평균 RTT | **평균 소리끊김** | 음성전용 분 | 사람 |
|---|---|---|---|---|---|
| `direct` | 397분 | 195 ms | **0.78 %** | 9분 | 17명 |
| **`relay`** | 166분 | 284 ms | **8.21 %** (10.5배) | **24분** | 12명 |
| `mixed` | 38분 | 253 ms | 2.88 % | 0분 | 10명 |

**릴레이는 전체 시간의 27%인데 음성전용의 73%(24/33분)를 차지합니다.**

### ② 업링크가 막혔다(«손실 0% 인데 RTT 8.8초»)  〔잰 것 + 추론〕

손실은 0인데 지연만 8,840ms까지 치솟는 것은 **패킷을 버리는 것이 아니라 줄 세워 두는**
전형적인 상향 포화(bufferbloat) 모양입니다.
⟹ 이 경우 **영상을 끄는 것(=AAO)이 실제로 옳은 처방**입니다. 이번 건에서 음성전용은
«오작동» 이 아니라 «제 일을 한 것» 입니다.
⚠️ 다만 «릴레이 우회가 그 포화를 만들었는가» 는 **재지 않았습니다** — 상관이지 증명이 아닙니다.

### ③ 카카오톡 인앱 브라우저로 수업에 들어갔다  〔스크린샷 · 코드〕

스크린샷 상단이 카톡 인앱 브라우저(`mangoi.ai` · 가가 · 노란 말풍선)입니다.
이 저장소는 인앱 브라우저를 **화상수업에 부적합**으로 이미 못 박아 두었고
(`js/inapp-escape.js` 머리말: 카메라 차단 · CLAUDE.md: 세션 쿠키 미반환 · 새 창 못 엶),
**「브라우저로 열기」 배너**까지 만들어 두었습니다.

🔴 **그런데 그 배너는 실제 수업 화면에서 «선제적으로» 뜨지 않습니다.**

```js
var isVideoPage = location.pathname.indexOf('/video-call') !== -1 ||
                  window.MANGO_VIDEO_PAGE === true;
if (isInApp && isVideoPage) { …배너… }
```

- 수업은 `index.html`(주소 `/`)에서 돌아갑니다 → `/video-call` 아님
- `window.MANGO_VIDEO_PAGE = true` 는 **`precheck.html` 한 곳에만** 있습니다(전수 확인)

⟹ **수업 화면에서는 `getUserMedia` 가 «실패할 때만»** 배너가 뜹니다.
원장님은 카메라가 **정상 동작**했으므로(영상이 흐름) **배너를 볼 수 없었습니다.**
= 만들어 둔 안전장치가 정작 필요한 화면에서 한 번도 안 도는 상태입니다.

## 4. 화면이 말하는 방식에서 찾은 결함

### 🔴 (가) 상대 타일 안내가 «한 언어만» 나옵니다 — 확실

같은 AAO 인데 **자기 화면 토스트는 한/영 병기**이고 **상대 타일 안내는 한 언어만**입니다.

```js
// 내 화면 (idx-main.js) — 병기
vcAAONotify('📶 <b>Your internet is weak …</b> …<br>인터넷이 약해 잠시 <b>음성만</b> 전송합니다 …');

// 상대 타일 (idx-main.js vcApplyRemoteCamHint) — 하나만 고름
el.innerHTML = en ? 'Weak connection — audio only for now.<br>The class continues.'
                  : '연결이 약해 지금은 <b>음성만</b> 전송 중이에요.<br>수업은 계속됩니다.';
```

병기는 **2026-08-08 사장님 지시**(「라벨만 영어이고 내용이 한국어면 읽을 수 없다」)로 들어간 것인데
**한쪽에만 적용**돼 있습니다. 스크린샷이 영어인 것은 그 기기의 언어 판정(`miIsEn()`)이 EN 이었다는
뜻이고, **한국인 원장님이 못 읽는 안내를 받았습니다.**
같은 함수의 「Camera is off / 상대가 카메라를 껐어요」도 같습니다.

### 🟡 (나) 음성전용의 RTT 문턱만 «절대값» 입니다 — 옆 위험

적응 화질 루프는 2026-09-02 에 **기준 RTT 대비**로 이미 고쳤는데(`rttDown = max(450, rb+200)`),
음성전용은 **`art > 600` 절대값 그대로**입니다.
⟹ 기준 RTT 가 높은 회선(필리핀·중국·릴레이)은 조금만 흔들려도 카메라가 꺼지고,
기준이 낮은 회선은 600ms 까지 방치됩니다.
⚠️ **이번 건의 원인은 아닙니다** — 8,840ms 는 어느 문턱으로도 걸립니다. 곁에 있는 위험입니다.

### 🟡 (다) 안내가 «무엇을 하면 되는지» 를 말하지 않습니다

「연결이 약해」 뒤에 다음 행동이 없습니다. 사람은 그 앞에서 할 수 있는 일이 없습니다.

## 5. 해결 방법

### 5-1. 지금 바로 (운영 — 코드 수정 없음)

1. **카톡 인앱 브라우저로 수업에 들어가지 않기.**
   카톡에서 링크를 받으면 오른쪽 위 메뉴 → **「다른 브라우저로 열기」/「Safari로 열기」**
   → 크롬·사파리에서 `https://mangoi.ai` 로 수업 입장.
2. **수업 중 같은 회선의 다른 업로드를 멈추기**(다른 영상통화·클라우드 백업·대용량 전송).
   손실 0% 에 지연만 8초 = 상향이 막힌 모양이라 여기서 가장 크게 풀립니다.
3. 가능하면 **Wi-Fi 공유기 가까이 또는 유선**, 모바일 데이터보다 유선/Wi-Fi 우선.
4. 안내가 뜨면 **끄지 말고 기다리기** — 32초 연속 안정되면 영상이 자동으로 돌아옵니다.

### 5-2. 코드로 고칠 것 (제안 · 우선순위)

| 순위 | 무엇을 | 어디를 | 왜 |
|---|---|---|---|
| **1** | 상대 타일 안내를 **한/영 병기**로 | `idx-main.js` `vcApplyRemoteCamHint()` | 사장님 지시(2026-08-08)가 한쪽에만 적용됨. 못 읽는 안내는 없는 것과 같음 |
| **2** | 수업 화면에서 **인앱 브라우저 배너를 선제적으로** | `index.html` 에 `window.MANGO_VIDEO_PAGE=true`, 또는 `inapp-escape.js` 조건에 수업 진입 추가 | 만들어 둔 안전장치가 정작 수업 화면에서 안 돎 |
| **3** | 안내에 **다음 행동 한 줄** 추가 | 같은 함수 | 「연결이 약해」만으로는 할 일이 없음 |
| 4 | 음성전용 RTT 문턱을 **기준 RTT 대비**로 | `idx-main.js` AAO 판정 | 적응 루프와 판정 근거를 맞춤. ⛔ 손실 문턱(8%)은 그대로 |

⛔ **주의 — 하지 말아야 할 것**
- 음성전용 자체를 끄거나 문턱을 크게 올리는 것 → 소리까지 끊깁니다(그게 마지막 방어선입니다).
- 「연결 나쁘면 화면을 자동으로 작게」 → P2P 라 받는 쪽 타일 크기는 보내는 쪽에 **한 바이트도** 영향이 없습니다.
- ⚠️ 1번은 `index.html`, 2번도 `index.html` 로 **공동 금지구역 + 첫 화면 예산(여유 186B)** 입니다 →
  defer 파일에서 덮어쓰는 방식이어야 하고, **배포 권한자 승인이 필요합니다.**

## 6. 못 잰 것 · 미확인

- **릴레이 우회의 원인**(학원 방화벽? 모바일 CGNAT? 인앱 WebView?) — 재지 않았습니다.
- **인앱 브라우저가 이 품질 저하를 «만들었는가»** — 상관만 확인했고 증명하지 않았습니다.
- 그 기기의 **언어 설정이 왜 EN 이었는지** — 서버에서 알 수 없습니다(병기하면 물음 자체가 사라집니다).
- 14:24:33 이후 강사 쪽 60초 요약이 없어 **강사 기기의 음성전용 여부는 확인 불가**입니다.
- 스크린샷의 **얼굴칸 주인**(원장님 기기인지 강사 기기인지)은 해상도상 단정하지 않았습니다.

## 7. 되짚어 볼 SQL

```sql

SELECT datetime(ts/1000,'unixepoch','+9 hours') kst, uid, avg_loss, avg_rtt,
       aao, rx_conceal, rx_freeze, path, turn, peers
FROM vc_quality WHERE room='class-1896-20260910' ORDER BY ts;
```
