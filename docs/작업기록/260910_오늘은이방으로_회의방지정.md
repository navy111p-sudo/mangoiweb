## 1. 왜 만들었나

사장님 질문이 출발점입니다 — **「방 이름 어떻게 학생이 바꿔서 들어가지?」**

답을 하려고 입장 경로를 읽다가, **길이 사실상 없다**는 것을 확인했습니다.

### 1-1. 방 번호를 넣을 창이 «0.22초» 만 열린다

`index.html` 의 원클릭 입장 블록 주석이 그 이유를 이미 적어 두고 있었습니다.

| 시각 | 무슨 일이 |
|---|---|
| 0ms | 로비가 열린다 — ⚙️「방 코드 직접 입력」은 **접혀 있다** |
| **+50ms** | `vcRestoreCredentials` 가 **방 코드 칸을 강제로 비운다** |
| **+220ms** | **자동으로 입장한다** — 코드가 비었으니 예약방 또는 공용방으로 |

⟹ 사람이 톱니를 펼쳐 번호를 칠 시간이 **구조적으로 없습니다.**
어제(9/9) 넣은 노란 안내줄(「⚙️ 에 번호를 넣으세요」)은 **자동로그인이 꺼진 학생에게만**
실제로 쓸 수 있는 말이었습니다.

### 1-2. 「로그인 두 번」은 홈 로그인이 없을 때만 생긴다

홈에 로그인돼 있으면 로비의 아이디·비밀번호는 **코드가 이미 채웁니다**
(`index.html` 의 `ph59` · `js/idx-vc-roomcode.js` 의 `armAutoEnter`).
그래서 이 작업의 목표는 「로그인을 없애는 것」이 아니라 **「번호를 넣을 자리를 만드는 것」** 입니다.

## 2. 무엇을 만들었나

### A안 — 서버가 「오늘은 이 방」이라고 대신 답한다 (학생 화면 코드 0줄)

로비는 **이미** 「빈 칸이면 오늘 예약 방을 물어보고 자동으로 채우는」 동작을 합니다
(`js/idx-main.js` — 「빈 방코드 → 오늘 예약 방으로 자동 교정」).
**그 답만 바꿉니다.** 그래서 학생이 하는 일은 «평소처럼 「수업 입장」을 누르는 것» 뿐입니다.

| 조각 | 어디 |
|---|---|
| 판정 정본 | **`src/class-room-override.ts`** (새 파일) |
| 표 | `class_room_override` — **`PRIMARY KEY (schedule_id, ymd)`** |
| 적용 | `src/api-mango.ts` 의 `/api/class/sessions/today` — 세션을 만든 뒤, `current` 를 고르기 전 |
| 지정 API | **`PUT /api/admin/class-schedules`** (본문 `action`) |
| 선생님 화면 | `teacher.html` 「오늘의 수업」 각 줄의 **「🚪 오늘은 다른 방으로」** |
| 학생 안내 | `js/idx-vc-roomcode.js`(**defer**) 의 `assignedBanner()` |

### B안 — 링크 (이미 있는 것을 그 자리에 붙임)

지정이 끝나면 서버가 **`d.link`** 를 함께 돌려주고, 선생님 화면이 그것을 보여 주며
휴대폰이면 **공유 시트**(`navigator.share`), PC 면 **클립보드**로 넘깁니다.
도메인은 **서버가 `SITE_ORIGIN` 정본으로** 만듭니다 — 화면이 조립하지 않습니다
(어제 그 조립이 갈려서 로그인이 깨지던 것을 고쳤습니다).

## 3. 일부러 그렇게 한 것 (되돌리기 전에 읽어 주세요)

### 3-1. 만료를 «표의 열쇠» 에 박았다

`ymd` 가 열쇠의 일부라 **「오늘 하루」가 구조적으로 보장**되고 **따로 지우는 작업이 없습니다.**

⛔ 「만료 컬럼 + 청소 크론」 으로 바꾸지 마세요 — 이 저장소는 «지우는 일을 잊어 다음
수업까지 끌고 가는» 사고를 여러 번 냈습니다. 게다가 cron 은 **5개를 다 써서 새로 못 만듭니다.**

### 3-2. `src/index.ts`(공동 금지구역)를 한 줄도 안 건드렸다

새 경로를 만들면 라우팅 허용목록에 한 줄이 필요한데 그 파일은 금지구역입니다.
그 목록의 등록은 **메서드를 안 가리므로**, 이미 등록된 `/api/admin/class-schedules`(정확일치)의
**비어 있는 PUT** 에 얹었습니다(실측: 그 경로는 GET·POST 만 씁니다 — CLAUDE.md 2장의 그 길).

⛔ 그래서 본문에 `action` 을 두고 **모르는 값은 거절**합니다. 안 그러면 나중에 이 경로에
다른 뜻을 넣을 때 «모르는 요청» 이 조용히 흘러 들어갑니다.

### 3-3. 실패 방향을 **자리마다 다르게** 잡았다

| 자리 | 실패하면 | 왜 |
|---|---|---|
| `applyRoomOverrides`(학생 입장) | **막지 않는다**(fail-open) | 학생이 «입장을 누르는» 경로다. 던지면 수업 입장이 통째로 막힌다. 지정이 안 걸리면 예약방으로 가므로 «고치기 전» 과 같을 뿐 |
| `teacherOwnsSchedule`(권한) | **막는다**(fail-closed) | 「남의 학생을 다른 방으로 보내는」 조작이라 되돌릴 수 없다 |

⛔ 이 방향을 서로 바꾸지 마세요.

### 3-4. 담당 강사 판정에 **이름 매칭을 쓰지 않았다**

근거를 결정론적인 둘로만 제한했습니다 — ① `teacher_account_links` 연결(대소문자 무시 완전일치)
② `class_schedules.teacher_id` 에 로그인 계정명이 그대로 들어간 행.

⛔ `api-teacher.ts` 의 «낱말경계 이름 매칭» 은 여기서 **안 씁니다.** 거기는 «내 수업을 보여 준다» 라
못 보면 문의하면 끝이지만, 여기는 되돌릴 수 없습니다. 강사 번호가 세 갈래인 이 저장소에서
이름으로 이으면 조용히 남의 수업이 붙습니다. 연결이 없는 강사는 본사에 요청하면 됩니다.

### 3-5. 지정 버튼을 [수업 입장] 과 **줄을 나눠** 두었다

2026-08-08 에 [연기] 버튼을 뺀 이유가 «[수업 입장] 바로 옆이라 잘못 누른다» 였습니다.
같은 실수를 반복하지 않으려고 **아래 줄 · 작은 글씨 · 오른쪽 정렬**로 두었습니다.

### 3-6. 🔴 QR 은 **안 만들었습니다**

B안에 「QR 을 더할 수 있다」고 제안했지만 재 보고 **안 하기로** 했습니다.

- 이 저장소가 `admin.html` 에서 쓰는 방식은 **`api.qrserver.com`**(제3자 서비스)입니다.
  그건 **아이 수업 링크를 제3자에게 보내는** 것이고, 중국 회선에서 막히면 그 자리가 **조용히 빕니다.**
- 손으로 QR 인코더를 쓰는 것은 되지만, **이 환경에서 «맞는지 재 볼 방법이 없습니다»**
  (스캔·디코드를 못 합니다). 못 재는 것을 «된다» 고 넣지 않았습니다.

⟹ 대신 **링크 복사 + 공유 시트**로 같은 일을 하게 했습니다. QR 이 꼭 필요하면
«어느 QR 서비스를 쓸지» 는 사람이 정할 일입니다.

## 4. ⚠️ 사장님이 정하셔야 할 것 하나

**회의방(`meet-…`)은 예약 수업방이 아니라서 «출석 포인트 · 복습퀴즈 안내 · 강사 AI 코칭» 이 꺼집니다**
(`__vcIsMeetingRoom`).

지금은 **꺼진 채로** 두고 **화면이 그 사실을 말하게** 했습니다 — 선생님에게도(지정할 때),
학생에게도(입장 배너). 감추면 「수업은 했는데 포인트가 0이다」가 되고 아무도 이유를 모릅니다.

**바꿀 수 있습니다** — 「서버가 지정한 방은 수업으로 쳐 준다」로. 서버가 지정한 방이라
학생이 임의로 만든 회의방과 **구별됩니다**(`room_override` 표시가 이미 응답에 실려 있습니다).
다만 그건 **「어디까지를 수업으로 볼 것인가」** 를 정하는 일이라 제가 혼자 정하지 않았습니다.

## 6. 아직 못 한 것 · 못 잰 것

- **실제 브라우저로 눌러 본 적이 없습니다.** 이 환경의 프록시가 `mangoi.ai` 를 막아
  배포된 화면을 제가 못 봅니다. 선생님 화면에서 한 번 눌러 봐 주셔야 끝입니다.
- **D1 표는 첫 지정 때 만들어집니다**(`ensureRoomOverrideTable`). 배포 직후 SQL 로 조회하면
  `no such table` 이 나는데 **배포 실패가 아닙니다**(`attendance.host` 와 같은 사정).
- **관리자 화면(`admin.html`)에는 아직 안 붙였습니다** — 지금은 **강사 화면**에서만 지정합니다.
  API 는 본사 계정도 그대로 쓸 수 있으니, 관리자 카드에 붙이는 것은 이어서 하면 됩니다.
- 지정을 **누가 언제 했는지**는 표에 남지만(`created_by`·`created_at`) **화면에서 볼 곳이 없습니다.**
