## 2. 무엇을 했나

### 2-1. 송신 — 끄는 «방법» 을 바꿨다 (`js/idx-main.js`, `vcAAOApply` 만)

```
옛: vcLocalStream 의 영상 트랙에 t.enabled = false     → 검은 프레임을 «보낸다»
새: sender.getParameters() → encodings[0].active=false → 아무것도 «안 보낸다»
```

그리고 **알림(`vcBroadcastCamState`)을 «끄기 전» 으로 옮겼습니다.**

`idx-main.js` 는 blocking 이라(예산 여유 186B) **구현은 넣지 못합니다.**
그래서 호출부만 남기고 실제 구현은 defer 파일로 위임했습니다 — **+52B**.
(구현을 그대로 넣었으면 +500B 가 넘어 애초에 못 들어갑니다.)
그 파일이 없으면 `catch` 가 **옛 동작으로 폴백**합니다.

### 2-2. 수신·표시 — `js/idx-vc-qlog.js` ⑤절 신설

- `vcAAOVideo(on)` — 위 스위치. 화면공유 중이면 손대지 않음
- `window.vcApplyRemoteCamHint` 를 **밖에서 덮어** `reason==='aao'` 일 때만
  전면 덮개 대신 **위쪽 띠 + 흑백 + «N초 전 모습»**
- 내 타일에는 **「지금 상대에게는 안 나갑니다」**
- AAO 중에 늦게 들어온 상대의 sender 에도 4초 타이머가 다시 적용

## 3. 검토했다가 버린 방법과 그 이유  ← 가장 중요

### A안 — 덮개만 아래쪽 띠로 줄이기 (가장 쌈)

**버렸습니다.** 밑이 검정이라 얼굴이 안 돌아옵니다.
브라우저가 «검은 프레임을 실제로 보내기» 때문입니다(4-1 실측).
결과는 「검은 사각형 + 띠」 — 사장님이 원하신 것이 아닙니다.

### C안 — 받는 쪽에서 1~2초마다 캔버스에 한 장씩 미리 떠 두기

**버렸습니다.** 송신 경로를 안 건드려 안전하지만

- 영상 인코더와 **같은 CPU** 를 수업 내내 씁니다
- 보여 주는 것이 «몇 초 전» 그림이라 B안보다 낡습니다

B안이 막혔을 때의 차선책으로만 남겨 둡니다.

### `replaceTrack(null)` — 처음에 이걸로 가려다 버렸습니다

실측상 **똑같은 «멈춤»** 을 줍니다(재협상 0회, 복구 98ms). 그런데:

- `sender.track` 이 비어서, 이 저장소에서 영상 sender 를
  `s.track && s.track.kind === 'video'` 로 찾는 코드가 **10곳 넘게 조용히 헛돕니다**
  (화면공유·가상배경·카메라 자가치유·장치교체·사무실모드)
- 특히 **화면공유 시작**은 sender 를 못 찾으면 `addTrack` + **재협상** 으로 빠집니다.
  그 자리 주석이 「대역폭 위기 중에 연결을 다시 맺는 것은 최악」이라고 못 박아 둔 동작입니다.

`active=false` 는 트랙을 그대로 두므로 그 코드들이 **전부 그대로 삽니다.**

### `enabled=false` 를 «함께» 쓰기 (강사 자기 미리보기를 옛날처럼 검게)

**버렸습니다.** 검은 프레임 한 장이 먼저 나가면 받는 쪽이 **그 «검정» 에서 얼어붙습니다.**
경합이라 «되다 안 되다» 가 되는데, 이 저장소가 가장 싫어하는 형태입니다.
대신 자기 타일에 「지금 상대에게는 안 나갑니다」를 적었습니다.

### 화면공유까지 끄기 (대역폭은 더 아낌)

**안 했습니다.** 옛 코드도 결과적으로 안 끄고 있었고
(`enabled=false` 는 카메라 트랙에 걸렸는데 sender 는 화면 트랙을 쥐고 있었습니다),
끄면 **강사가 공유 중인 교재가 사라집니다.** 지시 범위 밖입니다.

## 4-4. 🔴 함정 대조가 잡은 실제 결함 (커밋 뒤, 병합 전)

**처음 판에는 「영상이 수업 내내 안 돌아오는」 결함이 있었습니다.**

`vcAAOVideo` 첫 줄이 이랬습니다:

```js
function vcAAOVideo(on) {
    if (window.__vcScreenSharing) return;   // ← on=1(되살리기)에도 걸린다
```

「화면공유 중에는 영상을 끄면 안 된다」는 맞는 의도인데, 그 가드가 **«켜기» 까지 막았습니다.**

```
1) AAO 진입(공유 아님)       → active = false
2) 그 상태에서 화면공유 시작  → vcSwapVideoTrack 이 getParameters→setParameters 라
                               active=false 를 그대로 물고 감 → 학생에게 교재가 안 감
3) 회선 회복 → vcAAOVideo(1) → 조기 return → 그대로 false
4) 공유 종료                 → 다시 부르는 코드가 없음 → active = false 영구
```

`encodings[0].active = true` 로 되돌리는 코드는 **저장소 전체에서 그 함수 한 곳뿐**이고
`vcAAOVideo(1)` 을 부르는 곳도 `idx-main.js:5196` **한 곳뿐**입니다(grep 전수 확인).
**옛 코드에는 이 함정이 없었습니다** — 복구가 `t.enabled = true` 였고 화면공유 가드가 없었습니다.
즉 **이 변경이 만든 회귀**입니다.

더 나쁜 것은 회복 시점입니다. 회복 알림(`cam-state camOn:true`)은 나가므로
받는 쪽이 **띠와 흑백을 걷어냅니다** — 새 프레임은 안 오는데 표시만 사라져
**아무 안내 없는 멈춘 그림**이 됩니다. 이 수리가 셋(띠·흑백·N초 전)을 붙여
막으려던 **바로 그 상태**입니다.

### 고침 — «건너뛰기» 가 아니라 «상태를 지정»

```js
var want = window.__vcScreenSharing ? true : !!on;   // 공유 중에는 언제나 보낸다
```

한 줄로 넷이 전부 성립합니다:

| 상황 | 결과 |
|---|---|
| 공유 중에 AAO 진입 | 끄지 않음(교재 그대로) |
| AAO 중에 공유 **시작** | 4초 안에 되살림 |
| 공유가 **끝남**(AAO 계속) | 다시 멈춤 |
| 회복(공유 중이든 아니든) | 반드시 켜짐 |

그리고 «실제로 보내는가» 가 뒤집히면 **상대에게 다시 알립니다** —
안 그러면 살아 움직이는 교재 위에 「N초 전 모습」이 얹힙니다.

### 왜 하니스가 못 잡았나 — «짝» 이 빠져 있었습니다

- 「공유 중엔 **안 끈다**」만 묻고 「공유 중에도 **켠다**」를 안 물었습니다.
- 「AAO 중이면 **다시 건다**」만 있고 「AAO 가 **아니면 안 건드린다**」가 없었습니다.
  → `if (A && A.active)` 를 `if (true)` 로 바꾸면 **모든 수업에서 4초마다 전원의 영상을 끄는데**
  그 상태로 **46/46 초록**이었습니다(함정 대조가 실제로 넣어 확인).

하니스를 **46종 → 60종**으로 늘렸습니다(변이 8 → **12종**, 전부 실제 FAIL).
**결함이 있던 판으로 되돌리면 B-10·B-11·B-12 가 실제로 FAIL** 나는 것까지 확인했습니다.

| | 고치기 전 | 고친 뒤 |
|---|---|---|

띠는 `top:0` 전폭 · `z-index:9` 인데 버튼들은 `top:6/8px` · `z-index:8` 이라

「맨 위가 누구인가」를 물으면 **«버튼 자신» 이라고 정상으로 답합니다.**
이 사고는 «무슨 색으로 칠해졌나» 로만 드러납니다.

### 고침 — 띠를 옮기지 않고, 그 밑의 것을 내립니다

`vcAaoFreeze` 가 띠 높이를 재서 타일에 `--aao-h` 로 넘기고,
`.video-box.vc-aao-on` 에 걸린 CSS 가 모서리 조각을 그만큼 내립니다.

- 클래스는 **«버튼» 이 아니라 «타일» 에** 붙입니다 → `vcRefreshPraiseUI` 가 버튼을 다시 그려도 살아남습니다.
- `transform` 은 **쓸 수 없습니다** — `.vc-star-btn:hover{transform:scale(1.1)}` ·
  `.vc-star-toast.show{transform:translateY(0)}` 가 이미 쓰고 있어 서로 지웁니다.
  그래서 `top:calc(base + var(--aao-h))` 입니다.
- `!important` 가 필요합니다 — `#vc-local-box .vc-star-btn{top:6px}` 이 특이성으로 이깁니다.

가린 것을 옮겨 **또 가린** 것입니다. 타일 위쪽에는 여섯이 한 줄로 쌓여 있었습니다:

```
⭐ vc-star-btn      top  6px
💬 vc-dm-btn        top  8px
🎛 vc-devhelp-btn   top 40px
   vc-star-toast    top 48px   (+1P 토스트)
   vc-point-basket  top  6px   (학생 본인 화면)
   vpb-fly          top 48px
```

여섯을 **같은 만큼** 내려야 합니다. 잡아 준 것은 새로 넣은
**「누를 수 있는 조각끼리 서로 겹치지 않는가」** 검사입니다
(「덮였나」만 물었으면 이 결함은 통과했습니다 — 실제로 첫 판이 그랬습니다).

### 🔴 그 짝으로도 못 본 것이 둘 더 있었습니다 (함정 대조가 잡음)

| 조각 | 왜 안 걸렸나 |
|---|---|
| ⇱ **분리 버튼** `.video-detach-btn` (`z-index:5`) | 「겹침」 검사가 **눌리는 조각끼리만** 봅니다. 게다가 검사가 타일을 «손으로» 만드느라 `vcAddDetachButton` 을 안 불러 **0 of 0 으로 통과**하고 있었습니다 |
| 📶 **회선 경고** `.vc-netlow-hint` (`z-index:9` · `pointer-events:none`) | 띠와 **z-index 가 같아** 「아래 깔렸나」에 안 걸리고, `pointer-events:none` 이라 「겹치나」에도 안 걸립니다. 자동 하니스는 base top 을 `index.html`+`idx-main.js` 에서만 읽어 **`idx-vc-qlog.js` 안의 이 조각을 아예 못 봤습니다** |

📶 경고는 하필 **AAO 와 같은 조건**(회선이 나쁠 때)에 뜨는 문구라, 강사 화면에서 두 안내가 같은 자리에 겹쳐 있었습니다.

✅ 그래서 최종 검사를 **「띠와 겹친 조각의 가운데가 띠 색으로 칠해졌는가」** 하나로 바꿨습니다 —
z-index·DOM 순서·`pointer-events` 와 무관하게 **«보이는가» 만** 봅니다.

⚠️ **띠 색을 «띠 가운데 픽셀» 로 재면 안 됩니다** — 거기는 글자가 지나가 회차마다 값이 바뀝니다
(`rgb(111,49,14)` ↔ `rgb(156,111,84)` 가 번갈아 나와 변이시험이 되다 말다 했습니다).
글자를 잠깐 `color:transparent` 로 만들고 찍으면 그 자리가 **합성이 끝난 진짜 배경**입니다.

⚠️ 역할에 따라 붙는 것이 다릅니다 — ⇱ 분리는 **학생 화면**(칭찬 UI 가 없을 때), 📶 경고는 **강사 화면** 전용입니다.
한 시나리오로는 둘 다 못 봅니다.

이제 목록은 **아홉**입니다: ⭐6 · ⇱분리6 · 포인트바구니6 · 🖥공유배지6 · 💬8 · 📶경고8 · 🎛40 · +1P토스트48 · vpb-fly48.

### 검사 자신의 위생 (함정 대조 지적 반영)

- 변이용 **백업을 `public/` 밖(`os.tmpdir()`)으로** 옮겼습니다 — `deploy.ps1` 이 그 폴더를 통째로 업로드해서
  중간에 죽으면 57KB 사본이 실서비스로 나갑니다. 그리고 **다음 실행이 먼저 복구**하게 했습니다.
- `Page.addScriptToEvaluateOnNewDocument` 는 **한 번만** 겁니다(회차마다 부르면 누적).
- 실패해도 `process.on('exit')` 에서 **크로미움을 반드시 끕니다**.
- `vcAaoShift` 가 실패하면 여전히 «고치기 전»(버튼이 덮인 상태)으로 떨어지지만 — 방향은 맞습니다 —
  이제 **한 번은 `console.warn`** 을 남깁니다(조용하면 「⭐ 가 안 보인다」가 영영 안 밝혀집니다).
