## 2. 무엇을 했나

### 2-1. 송신 — 끄는 «방법» 을 바꿨다 (`js/idx-main.js`, `vcAAOApply` 만)

```
옛: vcLocalStream 의 영상 트랙에 t.enabled = false     → 검은 프레임을 «보낸다»
새: sender.getParameters() → encodings[0].active=false → 아무것도 «안 보낸다»
```

그리고 **알림(`vcBroadcastCamState`)을 «끄기 전» 으로 옮겼습니다.**

`idx-main.js` 는 blocking 이라(예산 여유 186B) **구현은 넣지 못합니다.**
그래서 호출부만 남기고 실제 구현은 defer 파일로 위임했습니다 — **+52B**.
(구현을 그대로 넣었으면 +500B 가 넘어 애초에 못 들어갑니다.)
그 파일이 없으면 `catch` 가 **옛 동작으로 폴백**합니다.

### 2-2. 수신·표시 — `js/idx-vc-qlog.js` ⑤절 신설

- `vcAAOVideo(on)` — 위 스위치. 화면공유 중이면 손대지 않음
- `window.vcApplyRemoteCamHint` 를 **밖에서 덮어** `reason==='aao'` 일 때만
  전면 덮개 대신 **위쪽 띠 + 흑백 + «N초 전 모습»**
- 내 타일에는 **「지금 상대에게는 안 나갑니다」**
- AAO 중에 늦게 들어온 상대의 sender 에도 4초 타이머가 다시 적용

## 3. 검토했다가 버린 방법과 그 이유  ← 가장 중요

### A안 — 덮개만 아래쪽 띠로 줄이기 (가장 쌈)

**버렸습니다.** 밑이 검정이라 얼굴이 안 돌아옵니다.
브라우저가 «검은 프레임을 실제로 보내기» 때문입니다(4-1 실측).
결과는 「검은 사각형 + 띠」 — 사장님이 원하신 것이 아닙니다.

### C안 — 받는 쪽에서 1~2초마다 캔버스에 한 장씩 미리 떠 두기

**버렸습니다.** 송신 경로를 안 건드려 안전하지만

- 영상 인코더와 **같은 CPU** 를 수업 내내 씁니다
- 보여 주는 것이 «몇 초 전» 그림이라 B안보다 낡습니다

B안이 막혔을 때의 차선책으로만 남겨 둡니다.

### `replaceTrack(null)` — 처음에 이걸로 가려다 버렸습니다

실측상 **똑같은 «멈춤»** 을 줍니다(재협상 0회, 복구 98ms). 그런데:

- `sender.track` 이 비어서, 이 저장소에서 영상 sender 를
  `s.track && s.track.kind === 'video'` 로 찾는 코드가 **10곳 넘게 조용히 헛돕니다**
  (화면공유·가상배경·카메라 자가치유·장치교체·사무실모드)
- 특히 **화면공유 시작**은 sender 를 못 찾으면 `addTrack` + **재협상** 으로 빠집니다.
  그 자리 주석이 「대역폭 위기 중에 연결을 다시 맺는 것은 최악」이라고 못 박아 둔 동작입니다.

`active=false` 는 트랙을 그대로 두므로 그 코드들이 **전부 그대로 삽니다.**

### `enabled=false` 를 «함께» 쓰기 (강사 자기 미리보기를 옛날처럼 검게)

**버렸습니다.** 검은 프레임 한 장이 먼저 나가면 받는 쪽이 **그 «검정» 에서 얼어붙습니다.**
경합이라 «되다 안 되다» 가 되는데, 이 저장소가 가장 싫어하는 형태입니다.
대신 자기 타일에 「지금 상대에게는 안 나갑니다」를 적었습니다.

### 화면공유까지 끄기 (대역폭은 더 아낌)

**안 했습니다.** 옛 코드도 결과적으로 안 끄고 있었고
(`enabled=false` 는 카메라 트랙에 걸렸는데 sender 는 화면 트랙을 쥐고 있었습니다),
끄면 **강사가 공유 중인 교재가 사라집니다.** 지시 범위 밖입니다.

## 4. 확인한 방법

### 4-1. 브라우저 실측 (Chromium 1194 · WebRTC 루프백 · 30ms 간격 픽셀 측정)

| 잰 것 | `enabled=false` (옛) | `encodings[0].active=false` (새) |
|---|---|---|
| 받는 쪽 화면 | **49ms 만에 완전 검정**(밝기 0) | **마지막 장면에서 멈춤**(7초 뒤까지 픽셀 동일) |
| 보내는 바이트 | **약 10 kbps** 계속 | **정확히 0** |
| `sender.track` | 유지 | **유지** |
| 재협상 | — | **0회** |
| 복구 | 즉시 | **96ms** |

추가로 잰 것:

- **`applyStep` 왕복**(4초마다 `getParameters`→상한 수정→`setParameters`) 뒤에도
  `active=false` 유지 · 바이트 0 · 같은 한 장 → **깜빡임 없음**
- **AAO 중 가상배경 켜기**(`replaceTrack(canvas)` + `vcSwapVideoTrack` 의 `setParameters`)
  뒤에도 멈춤 유지 · 바이트 0 → 검토 보고서의 **R1(가장 큰 미지수)이 닫혔습니다**
- **전역 덮어쓰기**가 먼저 로드된 blocking 파일 «안» 의 **맨이름 호출까지 따라온다** —
  추론이 아니라 브라우저에서 확인(`bare: "NEW(orig=ORIG:u1)"`)

### 4-2. 하니스

- 신규 `test-harness/aao_freeze_harness.mjs` — **46/0**
  가짜 peer·가짜 DOM 으로 **실제로 돌립니다**. 변이 **8종 전부 실제 FAIL**.
  **실제 소스를 되돌려도** A-1~A-3 이 실제로 FAIL 나는 것까지 확인했습니다.
- 짝으로 물은 것들: «음성전용이면 멈춘다 ↔ 사람이 끈 카메라는 전면 덮개 그대로» ·
  «영상을 멈춘다 ↔ 트랙은 안 건드린다» · «띠를 붙인다 ↔ 보여 줄 장면이 없으면 안 붙인다»
- 내가 건드린 파일을 읽는 하니스 **58개**를 `origin/main` 워크트리와 1:1 대조 → **회귀 0건**
- `--fast` PASS 302 → **303** / FAIL 14 (전부 이 컨테이너에 `node_modules` 가 없는
  환경 사유이고 **기준선과 목록이 같습니다**)
- 첫 화면 예산 **여유 186B → 134B**

### 4-3. 못 한 것 (정직하게)

- **tsc 를 못 돌렸습니다** — 이 컨테이너에 `node_modules` 가 없습니다.
  바뀐 `.ts` 파일은 **0개**입니다.
- **실제 회선**(중국·필리핀)과 **실제 타일 위 렌더링**은 아직 사람이 안 봤습니다.
  띠가 이름표·소리 안내·저화질 배지(bottom 8/34/58px)와 안 겹치도록 **위쪽**에 뒀지만,
  브라우저에서 `elementsFromPoint` 로 재 보지는 않았습니다.
- 강사·학생이 이 화면을 **실제로 더 낫다고 느끼는지** — 수업에서 사람이 볼 일입니다.
