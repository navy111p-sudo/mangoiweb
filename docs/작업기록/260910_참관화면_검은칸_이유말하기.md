# 참관 화면의 «검은 칸» 이 왜 검은지 말하게 하기

- 날짜: 2026-09-10
- 제보: 사장님 — 「👁 바로 참관」으로 `class-1896-20260910` 에 들어갔더니 검은 화면이 나온다.
  이어서 「학생과 선생님도 참관자가 들어온 걸 알게 되는 것 아니냐」는 걱정.
- 바꾼 것: `cloudflare-deploy/public/js/vc-observe-guard.js` ⑪절 신설 ·
  `public/index.html` 의 `?v=9 → v=10` 한 줄 · `test-harness/observer_camera_guard_harness.mjs` I절

---

## 1. 왜 했나 — 걱정의 «전제» 부터 확인했다

제보를 그대로 받으면 「참관이 새고 있다」가 되지만, 코드를 재 보니 그 전제가 성립하지 않았다.

**[잰 것]**

- 서버는 참관자를 «입장한 사람» 목록에 넣지 않고 **방송을 한 건도 하지 않는다**
  (`src/video-call-room.ts` `handleJoinObserve` — `joined:false · role:'observer'`).
  그래서 참여자 수·입장 알림·참가자 목록 어디에도 안 나온다.
- 얼굴 칸은 2026-09-01(⑩절)에 이미 막혀 있고 그 수리는 `origin/main` 에 그대로 있다
  (가드 4곳·서버 3곳). `observer_camera_guard_harness` H절을 **실제로 돌려** 확인했다(PASS).
- 사장님이 보신 화면은 `?observe=` 였고 참여자 수도 2명이었다.

**⟹ 그 검은 칸은 참관자 «자신» 의 화면이고 두 사람에게는 가지 않는다.**
고칠 것은 「참관이 새는 것」이 아니라 **「참관 화면이 이유를 말하지 않는 것」** 이었다.

## 2. 무엇이 비어 있었나

칸을 만들 때 「📷 연결 중…」(`index.html` 의 `.vc-connecting-hint`)을 함께 그린다 —
**즉 안내가 없는 것이 아니라 이미 있다.** 그런데 그것은 **영상이 도착하는 순간
`vcAddRemoteVideo` 가 지운다.** 그래서 그 «뒤» 에

- 상대가 카메라를 끄거나 (원격 비디오 트랙이 `muted` 로 바뀐다)
- 영상이 얼어붙으면 (트랙은 `live` 인데 프레임이 안 는다)

**아무 설명 없는 검은 칸**만 남는다. 참관자는 그것을 «고장» 으로 읽는다.

> ⚠️ 저는 처음에 「연결 중 안내가 없으니 넣자」고 사장님께 말씀드렸다. **틀렸다.**
> 코드를 열어 보고서야 이미 있는 것을 알았고 제안을 정정했다.
> 「없다고 단정하고 새로 만들지 말 것」(CLAUDE.md 2장)을 그대로 밟을 뻔했다.

## 3. 검토했다가 버린 방법

| 버린 방법 | 이유 |
|---|---|
| 「연결 중」 안내를 새로 만든다 | **이미 있다**(위 2장). 두 벌이 되면 같은 말을 두 번 한다 |
| `index.html` 에 CSS·마크업을 넣는다 | 공동 금지구역이고 첫 화면 예산 여유가 **186바이트**뿐. CSS 는 JS 에서 주입(이 파일 ⑦절의 방식) |
| `js/idx-main.js` 에 넣는다 | blocking 849KB — 학생 29,000명이 첫 화면에서 받는다 |
| 수업 화면(강사·학생)에도 같은 배지를 단다 | 반경이 학생 전원. 그쪽에는 이미 다른 안내가 있고, 이번 제보와 무관하다 |
| `MutationObserver` 로 칸 상태를 감시한다 | 홈이 통째로 멎은 전력 2회(2026-07-14·08-27) |
| «끝이 있는 확인» 몇 번으로만 본다 | 카메라를 껐다 켜는 것은 수업 내내 일어난다 — 몇 번으로는 못 잡는다 |

## 4. 무엇을 했나 — ⑪절

`vc-observe-guard.js` 끝에 새 IIFE 를 붙였다.

- **🔒 주소에 `?observe=` 가 없으면 곧바로 반환한다.** 수업 화면에는 한 줄도 돌지 않는다 —
  이것이 이 절의 안전장치 전부다.
- 참관 화면에서만 2초 타이머를 돌리고, **참관이 아니게 되면 스스로 끈다**
  (`js/idx-vc-qlog.js` 의 수신 계측 타이머와 같은 방식).
- 판정(`stateOf`)은 DOM 을 읽기만 한다 — 하니스가 이 함수를 오려 내 실제로 돌린다.
  - 비디오 트랙이 없다 → 「🎤 소리만 오는 중」
  - 트랙이 `muted` 이거나 `live` 가 아니다 → 「📷 상대가 카메라를 껐습니다」
  - 프레임이 4초째 그대로 → 「⏳ 영상이 멈췄습니다 — 다시 받는 중」
- **모르면 말하지 않는다** — 프레임 수를 못 재는 브라우저(`-1`), `<video>` 가 `paused`
  (자동재생 정책 — 기존 「소리 켜기」 배너가 담당), 영상이 아직 안 붙음,
  「📷 연결 중…」이 살아 있음 → 전부 **판정 보류**. 틀린 설명은 설명이 없는 것보다 나쁘다.

⛔ `vcRemovePeer(id,'left')` 는 부르지 않는다(학생 화면에 「수업이 끝났어요」).

## 5. 확인한 방법

- `observer_camera_guard_harness` **I절 17건 신설** — 판정 함수를 소스에서 오려 내
  `new Function` 으로 **실제로 돌린다.** 「말한다」와 **「함부로 말하지 않는다」를 짝으로** 두었다
  (짝이 없으면 «항상 말하기» 도 통과한다).
- **변이시험 6종 전부 실제 FAIL** — 수업 화면 가드 제거 · 「못 재면 말하지 않는다」 제거 ·
  자동재생 보류 제거 · `muted` 판정 빼기 · 「연결 중」 양보 제거 · 타이머 자동정지 제거.
- 🪤 **첫 판에서 검사 하나가 헛돌았다** — 「못 재면 말하지 않는다」를 **한 번만 불러** 재고 있었다.
  첫 호출은 «프레임 수를 기억하는» 자리라 어차피 `null` 이라, 그 줄을 지워도 통과했다.
  그 줄이 실제로 일하는 곳은 **4초 뒤 두 번째 호출**이다 → 두 번 부르도록 고치니 FAIL 이 났다.
- 🪤 **H절이 파일 «끝까지» 를 자르고 있었다** — ⑪절을 붙이자 H⑭(「상주 setInterval 을 쓰지 않는다」)가
  ⑪절의 타이머를 잡아 **거짓 FAIL**. 절 하나만 자르도록 고치고 H④-2 로 못 박았다.
- 🪤 **`window.vcIsObserver` 로 읽었다가 `let_on_window_harness` 에 걸렸다** —
  `vcIsObserver` 는 `idx-main.js` 의 `let` 이라 `window` 속성이 아니다(늘 `undefined`).
  맨 이름으로 고쳤다.
- 회귀: `run.mjs --fast` 를 `origin/main` 사본(`git worktree`)과 나란히 돌려 **실패 «목록» 을 대조** —
  기준선 PASS 278 / FAIL 14, 이번 PASS 300 / FAIL 14, **새로 생긴 실패 0건**.
  (FAIL 14 는 이 컨테이너에 `node_modules`·esbuild 가 없어서 나는 환경 사유다.)

## 6. 못 잰 것 / 남은 것

- **진짜 브라우저에서 배지가 실제로 그려지는지는 못 봤다.** 이 환경은 프록시가 `mangoi.ai` 를 막고,
  참관은 WebSocket(DO)이 있어야 성립해 로컬 재현이 안 된다. 판정은 실제로 돌려 확인했지만
  «화면에 보이는가» 는 사람이 한 번 봐야 끝이다.
- 사장님 화면에서 「📷 연결 중…」이 왜 눈에 안 띄었는지는 **여전히 모른다**(몇 초라 지나쳤는지,
  칸이 작아 가려졌는지, 아니면 이번에 고친 «영상이 온 뒤» 구간이었는지).
- 보고서(사장님용): 참관이 들키는 자리 — 얼굴 칸(막힘) · 「직접 입장」(열림·설계대로) ·
  업로드 증가로 인한 화질 저하(구조적) · 참관자 채팅(의도된 동작).
  「직접 입장」을 접어 둘지, 참관자를 SFU 로 옮길지는 **사람이 정할 일**로 남겼다.
