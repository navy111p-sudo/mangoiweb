## 1. 왜 했나 — 하루 전 실사고

**틀린 말은 아닙니다 — 다만 «지금 누구로 들어와 있는지» 를 말해 주지 않습니다.**

## 3. 한 일

### 정본 하나 — `src/forbidden-teacher.ts` (신설)

```
forbiddenTeacherBody(actor, 사유?, 사유_영문?)
  → { ok:false, error:'forbidden_teacher',
      username, account_name, who,          // 「강선생님(hq_t_kang)」
      who_line, who_line_en,                // 완성된 «한 문장»
      message, message_en }                 // 사유 + who_line
```

- **서버 44곳**이 이 함수를 부릅니다(응답 자리 42 전환 + 게이트 호출부 2 · 리터럴 0건).
- **화면 다섯**은 `who_line` 을 **붙이기만** 합니다 — ⛔ 문장을 베껴 적지 않습니다.
  베끼는 순간 정본이 여섯 벌이 되고 문구를 고칠 때 한쪽만 고쳐집니다.

### 지킨 것

| 지킨 것 | 왜 |
|---|---|
| **`error` 코드는 그대로** (`forbidden_teacher`) | 화면 다섯이 그 코드로 가릅니다. 바꾸면 전부 「알 수 없는 오류」가 됩니다 |
| **계정을 모르면 «지어내지» 않음** | 사유만 두고 계정 줄을 뺍니다(빈 괄호가 더 헷갈립니다) |
| **순수 게이트 둘은 안 건드림** | `textbookPurgeGate`·`teacherMoveDenyReason` 은 코드만 돌려주는 함수라, 계정은 «응답을 만드는 자리»(호출부)가 붙입니다. 게이트에 계정을 넘기면 그 함수들의 기존 하니스가 잡고 있는 입력 모양이 깨집니다 |
| **`src/index.ts` 는 3줄만** | 공동 금지구역이라 최소로. 중앙 게이트 1 + 급여 환율·지급 상태 2 |

### 🔴 덤으로 찾은 것 — 매니저 화면의 **죽은 줄**

`manager.html` 의 `reqErrOf(st, j)` 가 이 순서였습니다.

```js
if (st === 403 || e === 'forbidden_scope') return '다른 지사·대리점 요청입니다.';
...
if (e === 'forbidden_teacher')             return '강사는 승인·거절할 수 없습니다.';
```

서버는 `forbidden_teacher` 를 **403** 으로 주므로 **첫 줄이 언제나 먼저 걸립니다** —
즉 강사 갈래는 **한 번도 닿지 않는 죽은 줄**이었고, 강사가 누르면 「다른 지사·대리점
요청입니다」라는 **엉뚱한 말**이 나왔습니다. 코드를 먼저 가르도록 순서를 바꿨습니다.

⚠️ 이건 **제 변경이 만든 것이 아니라 원래 있던 결함**이고, **문자열 검사로는 못 봅니다** —
함수도 값도 다 «있고» 틀린 것은 «어느 줄이 이기는가» 뿐입니다. 화면 함수를 **오려 내
실제로 돌리는** 검사를 넣고서야 나왔습니다.
