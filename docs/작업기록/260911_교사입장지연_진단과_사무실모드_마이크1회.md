## 3. 잰 것

진짜 Chromium 으로 입장 경로를 단계별로 계측했습니다.
느린 환경 = RTT 220ms · 5Mbps · CPU 1/4 (**우리가 정한 가정값** — 실제 강사 노트북은 재지 못했습니다).

| 단계 | 빠른 환경 | 느린 환경 |
|---|---|---|
| 홈 화면 load | 1.3초 | **8.4초** |
| 로비 조작 가능까지 | 3.9초 | **12.6초** |
| 입장 버튼 → 수업 화면 | 0.18초 | 0.22초 |

**입장 자체는 0.2초**입니다. 시간은 그 앞(홈 화면 준비)에서 갑니다.

교사에게만 있는 추가 단계도 찾았습니다 — 호출 스택으로 확인:

```
#1  입장기준   26ms · 소요 109ms  ← acquireLocalMedia (카메라+마이크)
#2  입장기준  893ms · 소요 438ms  ← idx-vc-officemode.js enable()   ★교사 전용
```

운영 D1(`attendance`, 최근 14일): 교사–방 66쌍 중 **3분 내 재입장 15건 · 1분 내 7건**.
⚠️ 이것이 전부 「느려서」인지 「회선이 끊겨서」인지는 **가릴 수 없습니다.**

## 4. 고친 것 — ① 사무실 모드가 마이크를 두 번 열던 것

### 처음 시도한 방법과 왜 버렸나

「이미 열린 트랙에 `applyConstraints` 로 AGC 만 끄고 빌려 쓰자」로 짰습니다.
**크로미움이 그것을 조용히 무시합니다** — 실측:

```
초기: autoGainControl=true
applyConstraints({autoGainControl:false}) → 예외 없음
적용 후: autoGainControl=true   ← 안 바뀜
```

`getCapabilities()` 에는 `autoGainControl` 이 있는데도 적용되지 않습니다.
오디오 처리 체인은 **트랙을 만들 때 정해지고 그 뒤로는 못 바꾸는** 것으로 보입니다.

✅ 그때 제가 넣어 둔 **「getSettings 로 실제로 꺼졌는지 확인하고서만 빌린다」 가드**가
이것을 잡아 안전하게 폴백했습니다. 그 확인이 없었다면 AGC 가 켜진 채로
「사무실 모드가 켜진 척」 했을 것이고, **소리는 정상이라 아무도 몰랐을** 것입니다.

### 채택한 방법

`getUserMedia` 를 **밖에서 감싸(`hookGum`) 처음부터 AGC 를 끈 채로** 엽니다.
그러면 사무실 모드가 그 트랙을 그대로 빌려 써서 장치를 다시 열지 않습니다.

- 교사(`isStaff`)이고 · 켤 예정(`wantOn`)이고 · 이 페이지에서 실패한 적 없을 때만
- ⛔ 학생에게는 걸지 않습니다 — 아이 마이크의 자동 게인을 말없이 끄면 조용한 목소리가 작아집니다
- 끌 때도 빌린 트랙의 제약만 되돌려 그대로 씁니다(되돌리기에서도 장치를 안 엽니다)

### 이 수리가 만든 결함 하나 — 검사가 잡았습니다

`swapTrack` 이 **같은 트랙을 자기 자신으로** 갈아끼울 때 `stop()` 해서,
켜기가 도중에 실패하고 되돌릴 때 **교사가 무음**이 되었습니다.
브라우저 검사 ⑧ 「실패해도 마이크가 살아 있다」가 실제로 FAIL 을 냈고,
`if (old === next) return true;` 한 줄로 고쳤습니다.

### 확인한 방법

- 마이크 열림 **2회 → 1회**(진짜 Chromium, 입장 경로 전체를 실제로 돌려 셈)
- `vc-office-mode-browser.mjs` **PASS 82 / FAIL 0**(74종 → ⑱절 8종 추가)
- **변이시험 3종 전부 실제 FAIL** — hookGum 무력화 4건 · swapTrack 가드 제거 1건 · teardown 되돌리기 1건
- 회귀: `run.mjs --fast` 를 `origin/main` 사본과 나란히 돌려 **새로 빨간 것 0건**
  (양쪽 다 PASS 305 · ⚠15는 `node_modules` 없음으로 인한 환경 사유)

### 검사도 함께 고쳤습니다

⑧절이 「`getUserMedia` 거부」로만 실패를 만들어서, 마이크를 빌려 쓰게 된 뒤로는
**그 경로를 안 지나 켜기가 성공해 버려 3건이 거짓 FAIL** 이었습니다.
경로와 무관한 자리(`AudioContext`)를 함께 막도록 고쳤습니다.

## 4-1. 안 고친 것 — ② 「캐시 비우기」 버튼

사장님 화면 주소의 `?_cb=` 는 그 버튼(`ph52ClearCache`)이 남긴 흔적입니다.
그 버튼은 **서비스워커를 전부 해제하고 캐시를 통째로 지웁니다** —
평소 재방문을 빠르게 해 주던 `?v=` 붙은 js 23개(1,293KB)가 함께 날아가,
그 다음 한 번은 전부 다시 받습니다.

**그런데 코드를 고치지 않았습니다.** 이유:

- 그 버튼은 **최후의 구제 수단**입니다. `docs/작업기록/260827_홈전체정지…` 가
  「깨진 버전이 SW 캐시에 **영구 보관**된다」는 실사고를 적어 두었고, 그때 이 버튼이 탈출구입니다.
  자산 캐시를 남기도록 고치면 **그 탈출구가 사라집니다.**
- 확인창을 한 겹 넣는 안도 검토했지만, 급할 때 단계가 늘어납니다.
- 버튼 배선이 `fab.addEventListener(… ph52ClearCache())` 로 **클로저 지역 함수**를 부르므로
  `window.ph52ClearCache` 를 바꾸는 방식으로는 안 먹고, defer 에서 캡처로 가로채야 합니다 —
  그 가로채기가 잘못되면 **버튼이 아예 안 먹습니다.**
- `index.html` 은 공동 금지구역이고 첫 화면 예산 여유가 **70바이트**입니다.

⟹ 이건 **운영 안내**가 맞습니다: 「화면이 진짜 깨졌을 때만 누르세요」.

## 4-2. 되돌린 것 — ③ 홈 화면 blocking → defer

첫 화면은 `index.html` 1,034KB + blocking JS 24개 1,300KB = **원본 2,334KB**
(압축 전송 brotli 529KB · gzip 695KB)입니다.

### 실제로 해 보고 되돌렸습니다

`idx-main.js` 가 **로드 시점에** 쓰는 것을 기계로 걸러(아래) 안전한 8개(126KB)만 defer 로 옮겨
`origin/main` 사본과 같은 조건에서 번갈아 쟀습니다:

| | FCP | 조작 가능 |
|---|---|---|
| 기준선(main) | 1,352ms | 8,625ms |
| defer 8개 이동 | 1,260ms | **8,622ms** |

**개선 3ms** — 회차 편차(±120ms) 안입니다. ⟹ 되돌렸습니다.

### 왜 효과가 없었나

**defer 도 `DOMContentLoaded` 전에 실행됩니다.** 옮기면 HTML 파싱은 안 막지만
그 코드를 **파싱·실행하는 일은 그대로** 일어납니다.
병목은 «바이트» 가 아니라 «실행» 입니다(brotli 529KB 는 5Mbps 에서 0.85초인데 전체는 8.6초).

### 🪤 하마터면 「1.3초 개선」으로 보고할 뻔했습니다

처음에는 defer 판만 `route.fulfill` 로 HTML 을 바꿔 주고 기준선은 그냥 서빙했는데,
그때 **1.3초 개선**으로 나왔습니다. 압축·캐시 동작이 달라진 것이고 **불공정한 비교**였습니다.
두 쪽 다 실제 파일로 서빙해 재니 3ms 였습니다.

### 옮기면 안 되는 파일 (기계로 확인)

`idx-main.js` 가 **로드 시점에** 이들의 전역을 부릅니다:

- `idx-x3.js` — `vcSwitchTab`·`pdfLoad`·`pdfSetZoom`
- `idx-vc-textbook.js` — `vcSwitchTab`·`_pdfToast`
- `idx-vc-chat.js` — `getLang`·`vcSendChat`·`vcReceiveChat`
- `idx-vc-seg-lessonchange.js` — `vcOnSegResults`
- `idx-x6.js` — CLAUDE.md 가 「blocking 이라 못 고쳐서 캐시 칸을 미리 채운다」는 수리를 그 위에 올려 둠

ℹ️ `onclick=` 속성이 부르는 것은 defer 여도 안전합니다(클릭 시점엔 이미 정의돼 있습니다).
⚠️ `vcScreenSet` 은 **기준선에서도 `undefined`** 입니다 — 옮긴 뒤 그것을 보고 「내가 죽였다」고 오해하지 마세요.

### 진짜로 빠르게 하려면

첫 화면에서 **아예 실행하지 않는 것**(수업 전용 코드를 입장할 때 동적 로드)이어야 하고,
그건 반경이 훨씬 큰 **별건**입니다. 사람이 정할 일로 남깁니다.
