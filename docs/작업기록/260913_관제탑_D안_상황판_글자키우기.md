## 1. 왜 했나

사장님 캡처(관제탑, 2026-09-12)에 빨간 표시 셋:

1. 「자동 새로고침 **10초**」 (`#sel-poll`)
2. 「**20초씩**」 (`#sel-dwell`)
3. 화면 전체 — 「글자가 작아서 잘 보이지 않아」

### 1-1. 1번과 2번은 «다른 것» 입니다 — 코드로 확인

| | 무엇 | 언제 동작 | 코드 |
|---|---|---|---|
| **1번** 자동 새로고침 | **이 화면의 표**를 서버에서 다시 읽어 오는 주기 | 항상(순회를 안 켜도). 탭이 숨겨지면 멈춤 | `pollMs()` → `startPoll()` `setInterval(tick, ms)` |
| **2번** N초씩 | 「🔁 순회 참관」 창이 **한 방에 머문 뒤 다음 방으로 옮기는** 시간 | 순회 참관을 켰을 때만 | `dwellSec()` → `rotHop()` 의 `rot.left` |

**왜 헷갈렸나** — 2번 앞에 라벨이 없고(`lb-poll` 만 있었음) 「순회 참관」 버튼 오른쪽에 붙어 있어 1번의 짝처럼 보였습니다.
게다가 두 선택지가 같은 «N초» 꼴이라(「10초」·「20초씩」) 눈으로는 같은 종류로 읽힙니다.

### 1-2. 글자 크기 — 잰 것

수리 전 `monitor-wall.html`: 본문 14px · 표 13px · 표 머리 12px · 툴바 12.5px · 칩 12.5px · 각주 12px.
관리자 화면(admin.html)은 `zoom:1.3` 이 걸려 있는데 이 화면은 별도 파일이라 그 배율을 안 받습니다 — 그래서 상대적으로 더 작게 보였습니다.

## 2. 무엇을 했나

샘플 4안(A 밝게 크게 · B 관제실 다크 · C 카드 보드 · D 상황판)을 아티팩트로 만들어 보여 드렸고 사장님이 **D** 를 고르셨습니다.

D안 = **위에 큰 숫자 띠, 급한 것부터**:

| 자리 | 수리 전 | 수리 후 |
|---|---|---|
| 요약 | 알약 칩 한 줄(12.5px) | **남색 띠 `#chips .k`** — 수업방·이상 알림(빨강)·혼자 대기(주황)·영상 중계(초록)·회의방·예약 기준. 숫자 36px |
| 급한 방 | 없음(표 정렬로만) | **`#urgent` 「🚨 지금 손봐야 할 방 N」** — 심각도 1 이상인 «수업방» 만 시각·이름·이유·참관 버튼으로 (`renderUrgent`). 없으면 통째로 숨김 |
| 두 «초» 설정 | 라벨 없이 나란히 | 각각 점선 상자(`.grp`)로 묶고 이름표 — 「🔄 표 새로고침 / 이 화면을 다시 읽는 주기 · **N초마다**」, 「🔁 순회 참관 · 한 방에 머물기 / 그 뒤 다음 방으로 · **N초**」 |
| 글자 | 본문 14 · 표 13 | 본문 16 · 표 17 · 시각 19(모노) · 버튼 16 · 표 머리 13.5(대문자·자간) · 각주 14.5 |
| 상태 알약 | 11px | 13.5px + 1.5px 테두리(옅은 바탕은 테두리가 없으면 «그냥 글자» 로 읽힘 — CLAUDE.md 2장 배지 항목) |

**표는 그대로 둡니다** — 정상 수업도 아래에 전부 있습니다. 급한 방 상자는 «봐야 할 것» 과 «참고» 를 가르는 것이지 표를 대신하지 않습니다(참관 버튼은 같은 위임 리스너가 `data-room` 을 읽습니다).

## 3. 검토했다가 버린 것

- **C안(카드 보드)·B안(다크)** — 사장님 선택으로 정리. C 는 폰에서 좋지만 방 20개를 넘으면 표보다 길고, 표를 그리는 JS 를 통째로 바꿔야 해 반경이 큽니다.
- **요약 띠를 새 id 로 만들기** — `meet_room_split_harness ⑩` 이 `#chips` 의 «수업방<b>N</b>» 모양을 그대로 읽고, 브라우저 검사가 `#chips` 의 textContent 에서 「영상 중계 정상」 을 찾습니다. id 와 «라벨<b>숫자</b>» 모양을 그대로 두고 **겉모습(class)만** 바꿨습니다 — 라벨과 `<b>` 사이에 태그를 넣으면 그 검사가 깨집니다(주석으로 못 박음).
- **급한 방 판정을 새로 쓰기** — 표가 이미 쓰는 `severity()` 를 그대로 씁니다(«화면마다 답이 다른» 사고 방지). 회의방은 `visibleRooms()` 가 이미 빼 줍니다.
- **`.tablewrap`·`.acts .go2` 규칙을 합치거나 이름 바꾸기** — `monitor_wall_harness ⑫-3`·`observer_camera_guard G⑪` 이 그 선택자 문자열을 읽습니다.
- **CSS 를 `/css/monitor-wall.css` 로 빼서 HTML 을 줄이기** — HTML 은 10.5KB 로 이미 상한(12KB) 안이고, 합계 상한은 CSS 를 빼도 같은 문제라 하지 않았습니다(하니스도 CSS 를 안 세니 «게이트 우회» 모양이 됩니다).

## 4. 🔴 합계 상한 50KB → 52KB — 사람이 알아야 할 것

`monitor_wall_harness ①-2`(HTML+JS ≤ 50KB)가 **51.9KB** 로 빨간불이었습니다.

- 먼저 **덜어 냈습니다**: HTML 머리말(2.5KB 이력 주석 → 5줄) · JS 머리말(14줄 → 4줄). 둘 다 작업기록·`docs/` 에 있는 내용의 중복이었고, HTML 쪽은 «매번 새로 받는 부분» 이라 줄이는 것이 상한의 취지와도 맞습니다. → **51.2KB**.
- 그래도 **1.2KB** 가 남았습니다. 하니스 주석의 «뺄 후보»(카페24 예약 목록 ~2KB · 강제 종료 ~2.5KB)는 **기능**이라 지시 없이 뺄 수 없습니다(CLAUDE.md 4-1-1 «지우거나 되돌리는 변경»).
- 그래서 **최소로 올렸습니다**(52KB, 이유·날짜를 하니스 이력에 적음). 52KB 도 admin.html 의 4% 입니다.
- ⚠️ 더 가볍게 하고 싶으시면 위 «뺄 후보» 둘 중 하나를 정해 주시면 됩니다 — 카페24 예약 목록은 다른 화면 4곳에도 있고, 강제 종료는 admin.html 에 같은 API 가 있습니다.
