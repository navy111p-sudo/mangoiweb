## 1. 왜 했나

중국어 수업이 실재하는데(강선생님) 수업 전 웜업은 영어 전용이었습니다.
제안서에서 네 갈래(A 웜업만 / B 친구하기만 / C 새 화면 / D 둘 다)를 재고,
**「엔진은 하나로 두고 웜업 먼저, 쓰이면 친구하기」** 를 추천했고 사장님이 그것을 고르셨습니다.

### 계획을 세우며 제 전제 두 개가 틀렸던 것 (고쳐서 v2 로 다시 올림)

| 처음 적은 것 | 실제 (D1 실측) |
|---|---|
| 「웜업은 창이 좁다」 | 중국어 수업은 **주 4일** — 창이 좁지 않음 |
| 「친구하기가 더 쓰일 것」 | 실제 사용 **웜업 10세션 / 친구하기 0세션** |

⛔ 「그럴듯한 근거」로 순서를 정하지 말 것 — 세어 보니 결론이 뒤집혔습니다.

## 2. 무엇을 했나

웜업 설정 화면 맨 위에 **「🗣️ 무슨 말로 이야기할까요?」**(영어 / 중국어).
고른 언어가 **대화 · 교재 소재 · 교정 카드 · 대답 보기 · 마이크 · 목소리**까지 한 줄기로 흐릅니다.

- **기본은 영어.** 모르는 값·조회 실패는 **전부 영어 쪽으로 실패**합니다.
- 중국어 수업이 잡힌 학생은 설정 화면이 기본을 중국어로 켭니다 — **힌트일 뿐 저장하지 않습니다.**
  ⛔ `setWarmLang` 을 쓰면 «학생이 고른 것» 이 되어 나중에 기본값을 되돌릴 수 없습니다.
- 이 변경이 없으면 **영어 웜업은 한 글자도 다르게 동작하지 않습니다.**

### 새 파일을 만든 이유 — `src/warmup-zh.ts`

웜업 서버 코드는 `src/index.ts`(공동 금지구역)에 있습니다. 중국어 지시문·레벨·칩·안전망 질문을
거기 적으면 금지구역이 그만큼 커지고 영어 규칙과 섞여 「한쪽만 고쳐지는」 사고가 시작됩니다.
⟹ **중국어에만 해당하는 것은 전부 새 파일**, `index.ts` 는 **부르기만**.
실제 `index.ts` 변경 = 언어로 고르는 분기 7개 + `hint=1` 갈래 1개.

## 3. 검토했다가 **버린** 방법 (이게 이 문서의 핵심입니다)

| 버린 것 | 왜 |
|---|---|
| **교정 규칙(`WARMUP_ZH_CORRECTION_RULE`)을 `warmup-zh.ts` 에 두기** | 교정은 **JSON 출력 계약(`fixJsonLine`)과 한 몸**입니다. 스키마를 두 파일에 적으면 「파서·검증 한 벌이 두 화면을 받는다」는 전제가 깨집니다 → `warmup-correction.ts` 에 영어 규칙과 **나란히** 뒀습니다 |
| **중국어 «양자택일·Yes/No» 보기 칩 만들기** | 중국어 문형에서 답을 유도할 방법이 지금 없습니다. CLAUDE.md 「만들 수 없으면 **안 만듭니다**」 → 1·2단계 탈출구(`再说一遍。`·`我不知道。`)만 |
| **칩에 병음·한국어 뜻 붙이기** | 칩은 누르면 **그 글자가 그대로 학생 발화로 전송**됩니다(`pickAnswer`). 「我不知道。(모르겠어요)」가 학생이 한 말로 모델에게 갑니다. ℹ️ AI **말풍선** 안의 괄호는 괜찮습니다(`_speechText()` 가 낭독에서 걸러 냅니다) |
| **「🎯 내 수준 찾아줄까요?」를 중국어 예문으로 살리기** | 여덟 단계 중국어 예문을 손으로 만들어야 합니다(별건). 지금은 **감추는 편이 거짓말을 안 합니다** |
| **`isEnglishText` 를 중국어까지 넓히기** | 웜업·게임·단어장이 함께 쓰는 정본이라 그 화면들의 전제가 바뀝니다 |
| **화면이 스스로 언어를 가리기(`srcOf` 복제)** | 「같은 판정이 두 곳」 — 서버가 가린 것을 화면은 **그리기만** 합니다 |
| **`ai-friend.html` 까지 한 PR 에** | 그 화면은 영어 전용 장치가 더 많습니다(전보문 검사·오늘의 단어·응원 문구·「한자 금지」 규칙). 반쯤 번역된 화면이 서로 싸우게 됩니다. 사장님 지시도 «웜업 먼저» |
| **cron 신설로 중국어 소재 미리 만들기** | 계정 cron 한도 5/5 (CLAUDE.md 2장) |

## 4. 작업 중 찾은 것 — 이 일이 아니었으면 안 보였을 자리

1. **`src/reply-sanity.ts` 가 중국어에 원리상 눈이 없었습니다.**
   `words()` 가 `[a-z가-힣0-9' ]` 밖을 전부 지워서 **순수 중국어 문장은 `w` 가 빈 배열**이 되고
   길이 조건(12·25·40)에 한 번도 안 걸려 **무슨 죽이 와도 통과**합니다. 글자 단위 확인(⑤절)을 더했습니다.
   ⚠️ 임계값은 영어보다 훨씬 느슨하게(30자·12회·20%) — 중국어는 的·了 가 원래 자주 나오고,
   **멀쩡한 문장을 버리면 대화가 끊겨 깨진 문장 하나보다 나쁩니다.**

2. **교재 소재 캐시 키에 언어가 없었습니다.** `sig` 에 `o.lang` 이 빠져 있어
   같은 세션에서 **영어 소재가 중국어 대화로 샐** 수 있었습니다(에러 없음).

3. **`warmupAnswerChips` 를 중국어에 그대로 쓰면 영어 칩이 샙니다.** 1·2단계에서
   «막혔을 때» 칩(`One more time, please.`)이 **조건 없이** 붙습니다 — 유도 결과가 0개여도 붙습니다.

4. **안전망 질문도 같은 모양.** `WARMUP_FALLBACK_QUESTIONS` 는 모델이 실패했을 때만 오는
   갈래라, 그대로 두면 **중국어 대화에 영어 질문 세 개**가 조용히 뜹니다.

5. **중국어에는 «낱말 수» 상한이 성립하지 않습니다**(띄어쓰기가 없습니다) → `sanityCap = 0`.
   글자 수 상한(`WARMUP_ZH_CHAR_CAP`)은 **프롬프트로만** 전하고 사후 절단은 하지 않습니다.

## 4-2. 🔴 함정 대조(trap-check)가 잡은 것 — **처음 판은 절반이 죽어 있었습니다**

작업기록을 쓰고 PR 을 연 «뒤» 에 함정 대조가 돌아 **실제 결함 5건**을 찾았습니다.
CI 도 하니스 53건도 전부 초록이던 상태입니다 — 아래 다섯 개는 **전부 «에러가 안 나는» 종류**입니다.

| # | 무엇이 | 왜 하니스가 못 잡았나 |
|---|---|---|
| 🔴1 | **중국어 교정 카드가 원리상 한 번도 안 뜹니다.** `verifyWarmupFix` 298행이 `isEnglishText(was,120)` 로 재서 **한자가 100% 탈락**하고, 그 아래 `normEn()` 이 `[^a-z0-9' ]` 를 지워 **두 겹으로** 막았습니다. 새로 만든 `WARMUP_ZH_CORRECTION_RULE`·`ZH_MEANING_CHANGING_TAGS`·`opts.majorTags` 배선이 **전부 죽은 코드**였습니다. 더 나쁜 쪽: 교정 규칙은 출력을 평문 → JSON 으로 바꾸므로, **버려질 fix 를 위해 토큰 예산을 계속 씁니다**(2장 「JSON 으로 받게 바꿨더니 본문 예산이 줄어 잘림이 잦아진다」) | 제 ⑤절이 **문자열 4건**(「축이 따로 있다」·「넘긴다」)뿐이고 `verifyWarmupFix` 를 **한 번도 안 돌렸습니다.** 제가 이 파일에 「정본을 오려 내 실제로 돌리세요」라고 적어 놓고 그 절만 안 지켰습니다 |
| 🔴2 | **언어를 바꾸면 폴백 목소리가 이전 언어 그대로 남습니다.** `pickVoice()` 는 로드 때와 `voiceschanged` 에만 돌아서 `setWarmLang` 을 안 따라옵니다 → 같은 페이지에서 중국어로 바꾼 학생이 서버 TTS 실패로 폴백하면 **한자를 영어 목소리로 읽습니다**(이 코드 자신의 ⛔ 주석이 금지한 상태). `setVoiceMode` 에는 그 두 줄이 이미 있었습니다 | ⑧절이 **「그 줄이 있는가」** 만 봤습니다 — 가드 코드는 «있고» 틀린 것은 «그때 `_enVoice` 가 무엇인가» 뿐입니다 |
| 🔴3 | **중국어 프롬프트에 「아주 쉬운 «영어» 질문을 물어봐」가 그대로** 들어갑니다(`index.ts` 교재 소재 블록 두 줄). 이 줄은 `warmupZhSystem()` 의 「[언어] 중국어로 말해」 **뒤에** 붙어 더 뒤·더 구체적인 지시가 이깁니다 | 소재를 `zh_vocab` 에서 오게 고친 것만 검사하고 **그 값을 «감싸는 말»** 은 안 봤습니다 |
| 🔴4 | **「질문 골라 보기」가 중국어 프롬프트에 영어 교재 소재를 넣습니다.** `qLang` 을 만들어 놓고 `warmupLessonContextCached(…)` 에 안 넘겨 캐시 키가 `…|en` 이 됩니다 | 대화 경로만 보고 **형제 경로를 안 봤습니다**(2장 「한 곳만 고치면 반쪽」) |
| 🟡5 | `WARMUP_ZH_CHIP_MAX_LEVEL = 3` 인데 함수는 `lv <= 2` — **참조 0건**이라 동작 영향은 없지만, 다음 사람이 「상수는 3인데?」를 보고 **함수를 «고치러»** 갑니다 | 「같은 판정이 두 곳」이 새로 생긴 유일한 자리였습니다 |

**그리고 제 검사 자체에 구멍이 둘 있었습니다(함정 대조가 직접 재서 보여 줬습니다):**

- **영·중을 «뒤바꾼» 변이를 못 잡습니다.** 「영어 정본이 있는가 + 중국어 정본이 있는가」 짝만으로는
  `ctxLang === 'zh' ? 영어 : 중국어` 가 **둘 다 true** 입니다. 옛 «식 모양» 검사는 이것을 잡았는데,
  뜻으로 바꾸면서 **되돌려 FAIL 확인을 안 해** 그 한 겹이 사라졌습니다.
  → 이제 삼항식을 **오려 내 실제로 평가**해 «zh 일 때 무엇이 나오는가» 를 봅니다.
  ⚠️ 그때 상수 이름을 그대로 평가하면 `… is not defined` 로 죽어 **조용히 catch 로 빠집니다** —
  이름을 표식으로 바꿔 넣고 **「식을 찾아 평가했다」를 전제 검사로** 뒀습니다(실제로 한 번 밟았습니다).
- **`ALTER` 가 한 번 실패하면 세션 기록이 «통째로» 죽습니다.** `_schemaReady = true` 는 catch 뒤에도
  세워지고 INSERT 는 이미 `lang` 을 요구해 `no such column` 으로 던집니다 → 바깥 catch 가 삼킵니다.
  잃는 것은 이 파일이 존재하는 이유인 「몇 단계로 쓰는가」·「입을 뗐는가」 **분모 전체**입니다.
  → 칸이 없으면 **lang 없이라도 적습니다**(언어 한 칸 때문에 분모를 잃지 않습니다).
  ⚠️ 그 검사도 「`_hasLangCol` 이라는 이름이 있는가」로 쓰면 **`if (true)` 로 바꿔도 통과합니다**(실측) —
  **«그 INSERT 를 감싸는 조건» 이 그것인가**로 물어야 잡힙니다.

⇒ 다섯 건 전부 고치고, **변이 22종이 전부 실제 FAIL** 하는 것을 확인했습니다(수리분 9 + 기존 13).
하니스는 53 → **81건**이 됐고 그중 ⑪절은 `verifyWarmupFix` 를 **번들해 실제로 돌려** 중국어 교정 세
가지가 «정말 통과하는지» 와 **「영어는 예전 그대로 통과한다」를 짝으로** 봅니다.

📌 **남긴 교훈** — 「배선했다」와 「닿는다」는 다릅니다. 새 언어·새 축을 붙일 때는 **끝에서 끝까지 한 번
실제로 돌려 보는 검사**가 없으면, 규칙·상수·배선이 다 있는 채로 **아무 일도 안 일어납니다.**
