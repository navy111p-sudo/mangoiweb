## 1. 왜 했나

중국어 수업이 실재하는데(강선생님) 수업 전 웜업은 영어 전용이었습니다.
제안서에서 네 갈래(A 웜업만 / B 친구하기만 / C 새 화면 / D 둘 다)를 재고,
**「엔진은 하나로 두고 웜업 먼저, 쓰이면 친구하기」** 를 추천했고 사장님이 그것을 고르셨습니다.

### 계획을 세우며 제 전제 두 개가 틀렸던 것 (고쳐서 v2 로 다시 올림)

| 처음 적은 것 | 실제 (D1 실측) |
|---|---|
| 「웜업은 창이 좁다」 | 중국어 수업은 **주 4일** — 창이 좁지 않음 |
| 「친구하기가 더 쓰일 것」 | 실제 사용 **웜업 10세션 / 친구하기 0세션** |

⛔ 「그럴듯한 근거」로 순서를 정하지 말 것 — 세어 보니 결론이 뒤집혔습니다.

## 2. 무엇을 했나

웜업 설정 화면 맨 위에 **「🗣️ 무슨 말로 이야기할까요?」**(영어 / 중국어).
고른 언어가 **대화 · 교재 소재 · 교정 카드 · 대답 보기 · 마이크 · 목소리**까지 한 줄기로 흐릅니다.

- **기본은 영어.** 모르는 값·조회 실패는 **전부 영어 쪽으로 실패**합니다.
- 중국어 수업이 잡힌 학생은 설정 화면이 기본을 중국어로 켭니다 — **힌트일 뿐 저장하지 않습니다.**
  ⛔ `setWarmLang` 을 쓰면 «학생이 고른 것» 이 되어 나중에 기본값을 되돌릴 수 없습니다.
- 이 변경이 없으면 **영어 웜업은 한 글자도 다르게 동작하지 않습니다.**

### 새 파일을 만든 이유 — `src/warmup-zh.ts`

웜업 서버 코드는 `src/index.ts`(공동 금지구역)에 있습니다. 중국어 지시문·레벨·칩·안전망 질문을
거기 적으면 금지구역이 그만큼 커지고 영어 규칙과 섞여 「한쪽만 고쳐지는」 사고가 시작됩니다.
⟹ **중국어에만 해당하는 것은 전부 새 파일**, `index.ts` 는 **부르기만**.
실제 `index.ts` 변경 = 언어로 고르는 분기 7개 + `hint=1` 갈래 1개.

## 3. 검토했다가 **버린** 방법 (이게 이 문서의 핵심입니다)

| 버린 것 | 왜 |
|---|---|
| **교정 규칙(`WARMUP_ZH_CORRECTION_RULE`)을 `warmup-zh.ts` 에 두기** | 교정은 **JSON 출력 계약(`fixJsonLine`)과 한 몸**입니다. 스키마를 두 파일에 적으면 「파서·검증 한 벌이 두 화면을 받는다」는 전제가 깨집니다 → `warmup-correction.ts` 에 영어 규칙과 **나란히** 뒀습니다 |
| **중국어 «양자택일·Yes/No» 보기 칩 만들기** | 중국어 문형에서 답을 유도할 방법이 지금 없습니다. CLAUDE.md 「만들 수 없으면 **안 만듭니다**」 → 1·2단계 탈출구(`再说一遍。`·`我不知道。`)만 |
| **칩에 병음·한국어 뜻 붙이기** | 칩은 누르면 **그 글자가 그대로 학생 발화로 전송**됩니다(`pickAnswer`). 「我不知道。(모르겠어요)」가 학생이 한 말로 모델에게 갑니다. ℹ️ AI **말풍선** 안의 괄호는 괜찮습니다(`_speechText()` 가 낭독에서 걸러 냅니다) |
| **「🎯 내 수준 찾아줄까요?」를 중국어 예문으로 살리기** | 여덟 단계 중국어 예문을 손으로 만들어야 합니다(별건). 지금은 **감추는 편이 거짓말을 안 합니다** |
| **`isEnglishText` 를 중국어까지 넓히기** | 웜업·게임·단어장이 함께 쓰는 정본이라 그 화면들의 전제가 바뀝니다 |
| **화면이 스스로 언어를 가리기(`srcOf` 복제)** | 「같은 판정이 두 곳」 — 서버가 가린 것을 화면은 **그리기만** 합니다 |
| **`ai-friend.html` 까지 한 PR 에** | 그 화면은 영어 전용 장치가 더 많습니다(전보문 검사·오늘의 단어·응원 문구·「한자 금지」 규칙). 반쯤 번역된 화면이 서로 싸우게 됩니다. 사장님 지시도 «웜업 먼저» |
| **cron 신설로 중국어 소재 미리 만들기** | 계정 cron 한도 5/5 (CLAUDE.md 2장) |

## 4. 작업 중 찾은 것 — 이 일이 아니었으면 안 보였을 자리

1. **`src/reply-sanity.ts` 가 중국어에 원리상 눈이 없었습니다.**
   `words()` 가 `[a-z가-힣0-9' ]` 밖을 전부 지워서 **순수 중국어 문장은 `w` 가 빈 배열**이 되고
   길이 조건(12·25·40)에 한 번도 안 걸려 **무슨 죽이 와도 통과**합니다. 글자 단위 확인(⑤절)을 더했습니다.
   ⚠️ 임계값은 영어보다 훨씬 느슨하게(30자·12회·20%) — 중국어는 的·了 가 원래 자주 나오고,
   **멀쩡한 문장을 버리면 대화가 끊겨 깨진 문장 하나보다 나쁩니다.**

2. **교재 소재 캐시 키에 언어가 없었습니다.** `sig` 에 `o.lang` 이 빠져 있어
   같은 세션에서 **영어 소재가 중국어 대화로 샐** 수 있었습니다(에러 없음).

3. **`warmupAnswerChips` 를 중국어에 그대로 쓰면 영어 칩이 샙니다.** 1·2단계에서
   «막혔을 때» 칩(`One more time, please.`)이 **조건 없이** 붙습니다 — 유도 결과가 0개여도 붙습니다.

4. **안전망 질문도 같은 모양.** `WARMUP_FALLBACK_QUESTIONS` 는 모델이 실패했을 때만 오는
   갈래라, 그대로 두면 **중국어 대화에 영어 질문 세 개**가 조용히 뜹니다.

5. **중국어에는 «낱말 수» 상한이 성립하지 않습니다**(띄어쓰기가 없습니다) → `sanityCap = 0`.
   글자 수 상한(`WARMUP_ZH_CHAR_CAP`)은 **프롬프트로만** 전하고 사후 절단은 하지 않습니다.

  - 「막힌다」 옆에 **「영어는 그대로다」를 짝으로** 뒀습니다(짝이 없으면 «전부 중국어로 만들기» 도 통과)

  캐시 키에서 언어 빼기 / 중국어에 낱말 수 상한 걸기 / 한자 죽 검사 끄기 /

  기본값을 중국어로 / 힌트를 저장까지 하기 / 기록표 언어 칸 이름 바꾸기

느슨하게 풀지 않고 **경계를 옮겨 적고 짝 검사를 더했고**, 그 넷도 변이로 실제 FAIL 을 확인했습니다.

## 6. ❌ 못 한 것 / 다음

- **중국어 소리를 제가 들어 보지 못했습니다.** 이 작업 환경에 오디오 디코더가 없습니다.
  `/api/voice/tts` 의 zh 경로(구글 만다린)는 **사장님이 2026-09-13 에 「잘들려」로 확인**해 주신 그 경로이고,
  이 변경은 화면이 그 경로로 `lang:'zh'` 를 보내게 한 것까지입니다.
- **배포된 화면을 눈으로 못 봅니다**(프록시가 `mangoi.ai` 를 막습니다) — **병합 뒤 사람이 한 번 봐야 끝**입니다.
- **아는 채로 둔 한계**
  - 중국어 TTS 는 **화자를 안 가립니다**(구글 만다린 한 목소리) — 친구를 골라도 목소리는 같습니다(얼굴·이름은 바뀜)
  - 중국어에는 양자택일·Yes/No 보기가 없습니다(§3)
  - 「내 수준 찾아줄까요?」는 중국어에서 감춥니다
  - `warmup_session_log.lang` 은 **첫 기록이 들어와야 칸이 생깁니다**(지연 ALTER) — 배포 직후
    `SELECT lang …` 은 `no such column`. **배포 실패가 아닙니다**
- **다음 단계 — A.i 친구하기**(`ai-friend.html` · `src/api-ai.ts`).
  엔진은 이미 공용으로 준비돼 있고, 남은 것은 그 화면 전용 재료입니다:
  레벨 규격(낱말 수 → 글자 수) · 전보문 검사(**영어 문법이라 중국어에서는 꺼야 합니다**) ·
  오늘의 단어 · 응원 문구 · **「한자를 쓰지 마」 규칙 뒤집기**.
  05안의 순서대로 **웜업이 실제로 쓰이는지 `warmup_session_log.lang` 으로 세어 본 뒤** 진행합니다.
