## 1. 왜 했나
- 사장님(관리자 › 📇 강사 연락처 연결 화면을 보시며): 「카카오톡으로도 교사들에게 가지 못해? 갈 수 있게 할 수 없어?」
- 화면에 강사마다 💬 카카오ID(`TeacherAna18` 등)가 보이는데 알림은 「📧 이메일로 자동 발송」뿐이고, 이메일이 없는 두 명(중국어 강선생님·JED)은 「자동 발송 불가」였다.
- [사실 — 저장소가 이미 적어 두고 있던 것 (`src/teacher-kakao.ts` 머리말 · `js/adm-tcontact.js` 머리말)]
  - 카카오톡에는 «카카오ID 로 메시지를 보내는» 공개 API 가 없다. 화면의 카카오ID 는 사람이 채팅방을 찾을 때 쓰는 이름표다.
  - 알림톡·친구톡은 «전화번호» 로 보내고 **한국 통신사 번호로 가입한 카카오계정**에만 닿는다. 강사 전화는 22건 중 21건이 필리핀 09xx.
  - 카카오 로그인 기반 «친구에게 메시지 보내기» API 는 강사의 카카오 로그인 + 친구 관계 + 사업자 앱 검수 + 일일 한도가 걸려 서버 자동 발송용이 못 된다.
- [판단] 카카오 «자동» 발송은 이 강사들에게 구조적으로 불가. 자동으로 «폰에 뜨는» 수단은 웹푸시(무료 · 국가 제한 없음)와 해외 문자(유료)뿐 → 웹푸시를 추천했고 사장님 「추천으로 가」·「웹푸시」로 결정.

## 3. 검토했다가 버린 것
- **카카오 알림톡/친구톡** — 한국 번호 전용. 필리핀 강사에게 원리상 불가. 한국 번호 강사(강선생님)도 지금 번호가 비어 있어 같음.
- **카카오 로그인 «친구에게 메시지» API** — 강사가 우리 앱에 카카오 로그인 + 보내는 계정과 카카오 친구 + 사업자 앱 검수 + 일 한도. 결석 알림 같은 서버 자동 발송에 못 씀.
- **SOLAPI 해외 문자(country=63)** — `teacher-kakao.ts` 에 경로가 이미 있고 되긴 하지만 건당 비용이 나가고 SOLAPI 계정에 «해외 발송» 을 열어야 함 → 사람이 정할 일. 이번엔 무료인 웹푸시부터.
- **푸시로 이메일을 대체** — 푸시는 켠 사람에게만 가고 기기가 꺼져 있으면 못 받음. 이메일은 그대로 두고 «더한다».
- **구독의 `user_id` 를 강사 원부 번호로** — 결재함이 이미 계정명으로 쓰고 있어(매니저는 결재함·강사 화면이 같은 계정) 계정명으로 통일. 원부 → 계정 다리는 서버가 `teacher_account_links` 로 건넌다.
- **`sendPushToUser` 재사용** — 순환 import(absent-sweep → api-notify → notify-contacts → absent-sweep). 큐 INSERT + wakeup 만 정본에서 직접.
- **강사 화면에 «켜라» 배너** — 자주 쓰는 기능 바의 버튼 하나로 두고, 켜졌는지 여부는 관리자 연락처 화면이 «+ 🔔 푸시» 로 보여 줌. 배너는 화면을 어지럽히고(강사 화면 첫 줄이 이미 붐빔) 첫 화면 «정하세요» 카드가 스크롤 밖으로 밀리는 함정이 있음.

## 5. 남은 일 (사람이 정할 것)
- **`/api/push/subscribe` 는 무인증이고 본문 `user_id` 를 그대로 믿는다**(기존 그대로). 이번 배선으로 «강사 계정명만 알면 아무 endpoint 나 그 이름으로 구독해 결석 알림(학생 이름·수업 시각)을 받을 수 있는» 통로의 값이 «학생 화면이 teacher_uid 를 보낼 때만» 에서 «결석 감지 매 건» 으로 넓어졌다. 이 변경이 만든 구멍은 아니지만 커졌다 — 구독 저장에 세션(`checkAdminSession`)을 요구할지는 사람 결정(학생 구독은 토큰으로).
- **학생 갈래의 `notified_push` 도 원래부터 부풀어 있다** — `sendPushToUser` 가 `sent 0` 이어도 `ok:true` 를 돌려준다(이번에 안 건드린 자리).
- **대소문자** — `teacher_account_links.username` ↔ `push_subscriptions.user_id`(=`me.username`)를 정확일치로 잇는다. 링크 표기와 로그인 정본의 대소문자가 어긋난 강사가 있으면 조용히 `no_subscription`. D1 을 못 봐 실재 여부 미확인.
- `WEB_PUSH_MODE=mock` 이면 보내지 않고도 `sent` 가 올라 운영자 «못 보냄» 경고가 억제된다(운영은 그 변수가 없어 real/disabled).
- **강사에게 「알림 받기」를 켜 달라고 안내** — 켜지 않으면 아무것도 안 간다. 아이폰은 사파리 «공유 → 홈 화면에 추가» 뒤 거기서 열어야 켜진다(버튼이 그 말을 한다).
- **VAPID 키 등록 여부** — 결재함 웹푸시가 이미 쓰고 있으므로 등록돼 있을 가능성이 크지만 확인은 사람이(대시보드 Variables and Secrets 에 이름이 보이는지).
- **해외 문자(유료)** — 푸시를 안 켠 강사에게까지 닿게 하려면 SOLAPI «해외 발송» 을 열고 `absent-sweep` 판정을 넓히는 별건.
- 이메일이 없는 두 강사(중국어 강선생님·JED)는 **푸시를 켜기 전까지 여전히 자동 알림이 없다** — 화면 배지가 그 사실과 다음 할 일을 말한다.
