# 마이페이지 — 홈에서 로그인했으면 비밀번호를 다시 묻지 않기 (2026-09-14)

## 1. 왜 했나

사장님 캡처(마이 페이지 화면에 학생 ID `jeong` 이 «채워진 채» 「조회하기」 버튼만 있음) +
「**로그인 하면 다시 로그인 안해도 바로 마이페이지 내용들이 모두 보이게 해줘**」.

홈(`index.html`)에서 로그인한 학생은 `localStorage` 에 `mangoi_logged_user` 와 **서버 서명 토큰 `mango_token`** 을
이미 갖고 있습니다. 그런데 `parent.html`(마이페이지)의 부팅 코드는 **`mangoi_parent_token`(이 화면 전용 30일 토큰)만**
보고 자동 조회를 했습니다 — 홈 로그인 학생에게는 ID 만 채워 주고 「조회하기 → 비밀번호」를 **또** 시켰습니다.

## 2. 잰 것

- `/api/parent/dashboard` 는 `authUidFromRequest` → `verifyUidToken` 으로 토큰을 검증하고(`src/auth-token.ts`),
  홈 로그인(`/api/student/login` → `signUidToken`)과 마이페이지 로그인(같은 API)이 **같은 함수로 발급**합니다.
  ⟹ 홈 토큰을 그대로 넘겨도 서버가 «본인» 으로 인정합니다(uid 일치 + 비밀번호 설정 계정일 때).
- 이 흐름을 못 박아 둔 하니스는 없었습니다(`parent.html` 을 읽는 6개 전부 로그인 판정과 무관).

## 3. 한 것 — `cloudflare-deploy/public/parent.html` 한 파일

1. **부팅**: `mangoi_parent_token` 이 없고, 보려는 uid 가 **홈에 로그인한 그 계정**(대소문자 무시)이고, `mango_token` 이 있으면
   그 토큰으로 바로 `pdLoad()`. `?uid=남의아이` 는 예전처럼 비밀번호.
2. **실패 처리**: 자동 시도가 `auth_required`(만료) 면 **경고창 없이** 입력화면만. `password_not_set` 이면
   「조회하기」를 또 누르게 하지 않고 **비밀번호 «설정» 단계를 바로** 엽니다(수동 조회에서도 같은 단계 + 안내 한 줄).
3. **「다른 ID 로 조회」**: 홈 세션은 안 끊고 `sessionStorage['mangoi_parent_switch']` 로 **이 탭에서만** 자동 조회를 쉽니다.
   직접 비밀번호로 들어오면 그 표시를 지웁니다. (없으면 그 버튼이 «되돌아올 길 없는» 상태 — 새로고침마다 자동으로 다시 열림)
4. `loggedInUid()` 가 `uid` 만 보던 것을 `uid || user_id || id` 로 — CLAUDE.md 「로그인한 학생인데 손님으로 봄」 함정.

## 4. 검토했다가 버린 것

- **홈 로그인을 «부모 토큰» 으로 복사해 저장하기** — 2026-07-30 제보 #3(자녀가 같은 기기에서 비번 없이 열람)의 「체크 안 하면
  아무것도 안 남긴다」를 깨뜨립니다. 지금 방식은 **저장하지 않고 읽기만** 하므로 홈 로그인이 살아 있는 동안만 열립니다.
- **「다른 ID 로 조회」가 홈 로그인까지 끊기** — 반경이 홈 전체라 안 했습니다.
- **`password_not_set` 에 예전처럼 경고창** — 「다시 로그인해주세요」는 틀린 말입니다(로그인은 됐고 비밀번호가 «없는» 것).

## 5. 보호 수준은 안 낮아집니다

홈 로그인은 비밀번호가 설정된 계정이면 `/api/student/login` 이 `password_required` 로 막습니다. 즉 홈 토큰을 가진 사람은
**이미 그 비밀번호를 댄 사람**이고, 마이페이지가 그 토큰을 인정하는 것은 보호 수준을 홈과 «같게» 하는 것입니다.
(비밀번호가 없는 계정은 서버가 `password_not_set` 으로 여전히 막고 설정을 요구합니다.)
