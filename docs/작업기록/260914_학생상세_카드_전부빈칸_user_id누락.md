# 2026-09-14 관리자 학생 상세 — 카드가 전부 «—» (조회가 `user_id` 를 안 봤음)

## 1. 왜 했나
- 사장님 캡처: 학생 `yahee` 의 상세 화면(`/admin/student.html`) 왼쪽 카드가 **가입일·수강 종료·주당 수업·결제 유형·가맹점 전부 «—»**.
  달력에는 수업(9/16·9/18 20:00)이 보이는데 카드만 비어 「수업 입력했는데 왜 모두 비어있지??」.
- **[잰 것 — D1 SELECT]** `students_erp` 에 `yahee` 행은 있었다: `user_id='yahee'` · `signup_date='2026-09-14'` ·
  `shop_name='망고커뮤니케이션'` · `source='admin_manual'` · **`student_id=NULL` · `login_id=NULL` · `username='정예희'`**.
- `/api/admin/student/:uid/full`(`src/api-mango.ts`)이 그 행을 `WHERE student_id = ? OR login_id = ? OR username = ?` 로 찾는다 —
  **`user_id`(PRIMARY KEY) 를 안 본다.** 세 조건 어느 것도 `yahee` 와 안 맞아 `erp = null` → 카드 전부 «—». 에러 없음.
- **[잰 것]** 왜 지금까지 몰랐나 — 카페24 동기화 행 **29,494건은 `student_id = login_id = user_id`** 라 우연히 걸린다.
  관리자 「학생 등록」(`POST /api/admin/students/create`)이 만든 행 **3건만** 그 두 칸이 NULL(홈 회원가입 1건은 채움).

| 행의 출처 | 건수 | 옛 조건으로 못 찾는 행 |
|---|---|---|
| 카페24 동기화 | 29,494 | 0 |
| 관리자 수동 등록(`admin_manual`) | 3 | **3** |
| 홈 회원가입(`self_signup`) | 1 | 0 |

- 같은 조건이 **다섯 곳** — 상세 조회 · 학생 정보 수정(preRow·UPDATE) · 수강 연장(SELECT·UPDATE). 수정·연장은 **0행 갱신**으로
  조용히 안 먹고 있었다(UPDATE 0행은 에러가 아니다).

## 3. 검토했다가 버린 것
- **D1 `UPDATE students_erp SET student_id=user_id, login_id=user_id WHERE source='admin_manual'`** — 1-1(운영 DB 변경 금지). 읽는 쪽 수리로 충분하고, 새 등록은 INSERT 가 채우므로 필요 없다.
- **조회만 고치고 INSERT 는 그대로** — 그러면 `student_id`/`login_id` 로만 찾는 코드가 딴 곳에 또 생길 때 같은 사고. 행 모양을 맞추는 쪽이 싸다.
- **INSERT 만 고치고 조회는 그대로** — 이미 등록된 3명이 그대로 «—» 로 남고, D1 을 만져야 한다.
- **다섯 자리에 `user_id = ? OR …` 를 각각 적기** — «한 곳만 고쳐지는» 그 형태. 정본 조각 하나로.
