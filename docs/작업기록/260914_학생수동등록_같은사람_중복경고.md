## 3. 검토했다가 버린 것
- **로그인 쪽에서 «같은 사람이면 하나만 열기»** — 서버는 누가 같은 사람인지 확실히 모른다. 오판하면 멀쩡한 학생을 막는다(빠지는 쪽이 더 나쁨). 막는 자리는 «등록».
- **이름만으로 경고** — 동명이인이 실재해(「김사랑」 6계정) 정상 등록마다 경고가 뜨고, 그러면 사람이 경고를 안 읽게 된다. 이름 + 번호 «둘 다» 같을 때만.
- **아예 막기(409 로 끝)** — 형제가 같은 부모 번호로 등록되는 경우가 실재할 수 있다. «묻고 사람이 정한다»(force).
- **`students_erp` 에서 `yahee1`·`yahee2` DELETE / 코드로 자동 숨김** — D1 변경은 사람이 정할 일(CLAUDE.md 1-1). 숨김은 관리자 명부 「명부에서 숨기기」로 사장님이 직접(로그인까지 막힌다 — `isStudentHidden`).
- **전체 학생 비밀번호 강제** — 어린 학생 29,000명의 로그인 방식이 바뀌는 큰 결정. 이번 건의 답으로는 과함.
- **응답 `existing` 에 전화번호까지 싣기** — 관리자 전용 API 이긴 하지만 화면이 아이디만 그리므로 `matched_on`(어느 번호가 같았는지)만 싣고 번호 자체는 안 싣는다.
- **화면에서 판정 복제(등록 전에 명부를 훑어 경고)** — 정본이 두 벌이 된다. 화면은 서버 답을 그리기만.
