# 💸 무인증 `/api/voice/tts` — Azure 성우 호출에 IP 하루 상한 (2026-09-15)

## 1. 왜 했나

사장님 **「1번에서 대략 돈이 얼마나 나갈지 알려줘」 → 「진행해줘」**.

「1번」은 9/14 중국어 남성 성우(Azure Speech) 수리를 마치며 **«사람이 정할 일»** 로 남겨 둔 것입니다 —
`/api/voice/tts` 는 **로그인 없이 누구나** 부를 수 있는데 그 뒤에 종량제 Azure 가 붙어 있고,
IP·하루 상한이 **한 줄도 없었습니다**.

### 잰 것 (2026-09-15)

| | |
|---|---|
| 한 번 호출 상한 | **300자** (`AZURE_TTS_MAX_CHARS`) — 넘으면 Azure 를 아예 안 부릅니다 |
| 성우 | 아는 이름 **4명만** (`AZURE_ZH_VOICES`) |

### 그래서 얼마인가 (단가는 «가정» — 아래 4장)

- 1건 ≈ **6.3원** · 정상 사용 12세션 ≈ **101원**
- 남용: 초당 1건이면 **하루 54만원**, 초당 10건이면 **하루 544만원**

## 3. 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| **전역(서비스 전체) 하루 상한** | KV 는 같은 칸에 **초당 한 번**만 쓸 수 있습니다. 전역 키는 모든 요청이 같은 칸이라 **정확히 남용 때 안 세어집니다** — «남용 때 고장나는 방어». 키를 10개로 쪼개면 읽기가 10회로 무겁습니다 |
| **429 로 끊기** | 소리가 통째로 사라집니다. 이 저장소의 일관된 방향은 「소리가 아예 안 나는 것이 최악」 |
| **인증을 요구하기** | 그 API 를 부르는 학생 화면이 토큰을 안 싣고, 싣게 하려면 `index.html`(공동 금지구역 · 첫 화면 여유 8바이트)을 고쳐야 합니다 |
| **Cloudflare WAF 속도제한** | **이쪽이 더 정확합니다**(IP 를 인프라가 셉니다). 다만 대시보드 = 코드 밖이라 **사람이 정할 일**로 남겼습니다 |
| **상한 200** | 사장님께 200 이라 말씀드렸지만, 세는 단위가 «사람» 이 아니라 **«IP»** 였습니다. 학원 한 곳이 회선 하나를 나눠 쓰면 합산됩니다(녹화 상한을 30→300 으로 올린 그 이유). **학생 IP 는 저장소 어디에도 기록이 없어 «한 회선에 몇 명» 인지 못 쟀습니다** ⟹ 선례와 같은 300. 차이는 1,260 ↔ 1,890원 |

## 4. 코드로 못 막는 것 (정직하게)

1. **IP 를 바꿔 가며** 두드리면 그대로 나갑니다.
2. **KV 는 정확한 카운터가 아닙니다** — 쓰기는 같은 칸에 초당 한 번, 읽기는 콜로에 **최소 60초** 캐시(`cacheTtl` 하한). ⟹ **60초 안의 짧은 폭주는 그대로 통과**합니다. 이 상한은 «꾸준한 사용» 에는 걸리지만 «폭주» 에는 약하고, 그런데 폭주가 이 상한을 만든 이유입니다.
   ⚠️ 이건 Cloudflare 문서 기준의 «아는 것» 이고 여기서 «잰 것» 이 아닙니다(프록시가 그 문서를 막습니다).
3. **단가($15/100만 자)를 확인하지 못했습니다** — 프록시가 Azure 요금 페이지를 막습니다.

✅ **진짜 안전판은 Azure 쪽입니다** — 그 Speech 리소스가 **F0(무료)면 최대 손해 0원**(월 50만 자 넘으면 그냥 실패), **S0(종량제)면 상한이 없습니다.** 포털에서 30초면 갈립니다. **사람이 확인할 일.**

## 5. 남은 것 (사람이 정할 일)

- **게이트가 살아 있는지 알 방법이 지금은 없습니다** — 유일한 신호인 `console.warn` 이 `head_sampling_rate = 0.05` 라 20건 중 19건 버려집니다. 확인은 KV 에 `ttsazcap:` 칸이 쌓이는지 보는 것.
- **«돈이 안 나가는 실패» 도 셉니다** — 부르기 전에 세기 때문입니다(키 미설정 · 301자 이상 거절). 301자 이상을 300번 보내면 그 IP 의 진짜 성우가 하루 꺼집니다(소리는 계속 나므로 피해는 «음질» 까지).
- 영어 경로(Workers AI 뉴런)에는 이 상한이 안 걸립니다 — 이번 지시는 Azure 건이었습니다.

### 🪤 함정 대조가 잡은 것

| | |
|---|---|
| **하니스가 «크래시»** | 「429 로 끊기」 변이에서 `결과:` 줄조차 안 나왔습니다. `runCap` 이 async IIFE 의 Promise 를 돌려주는데 그것을 `await` 하는 자리가 try **밖**. 하필 그 변이가 **「막혀도 소리는 난다」는 가장 중요한 보장**을 깨는 것이었습니다 → 고친 뒤 **깔끔한 FAIL 4건** |
| **「화면이 사유를 말한다」가 거짓** | 그 헤더를 읽는 것은 성우 견본뿐이고 **학생 화면(`warmup.html`)은 안 읽습니다.** 동작은 옳고 **문장만** 틀렸습니다(세 곳 정정) |
| **변이 숫자 불일치** | 커밋엔 9종, 머리말엔 11종. 실측대로 **14종**으로 고치고 «⑥절이 자동으로 도는 것은 7종» 임을 명시 |

### 🪤 내가 먼저 밟은 것 (CLAUDE.md 2장에 기록)

- **카운터 `put` 한 줄을 지워도 58/0 통과** — 「`SESSION_STATE` 가 있는가」로 물었기 때문(`get` 만 남아도 그 글자는 있습니다). 상한이 영영 안 걸리는데 초록이던 자리 → ④-2절 신설
- **「상한 숫자를 라우트에 복제했나」를 숫자로 물어 거짓 FAIL** — 구글 응답 크기 검사 `gb.byteLength < 300` 이 상한값 300 과 우연히 같았습니다 → «어디서 가져오는가» 로 고침
