## 3. 그래서 무엇이 원인인가 (추론 — 측정 아님)

137초는 `src/video-call-room.ts` 의 죽은 소켓 청소 구간과 정확히 겹친다
(`LIVENESS_STALE_MS` 120초 + `LIVENESS_ALARM_MS` 45초 → 실제 절단은 120~165초 사이).

그 판정의 정본은 `getAutoResponseTimestamp()` 다. 그런데 ping 이 `setWebSocketAutoResponse`
로 처리되면 **`webSocketMessage` 가 안 불리므로** 나머지 두 근거(`lastSeen` 메모리,
`att.seenAt`)가 갱신되지 않는다. 즉 그 정본이 비면 남는 바닥값이 «입장 시각» 뿐이라
**입장 120초 뒤 끊기고, 재접속 후 또 120초 뒤 끊긴다** — 관측된 주기와 일치한다.

⚠️ **이 마지막 한 단계는 추론이다.** 확정하려면 Workers 로그에서
`[VideoChat][liveness] … auto=없음 → 정리` 를 봐야 하는데, `head_sampling_rate = 0.05`
라 20건 중 19건은 남지 않는다. 그래서 이번 변경에 **그 진단을 함께 넣었다**(4-2).

## 4. 고친 것

### 4-1. 끊지 않는 쪽으로 실패하게 (`src/video-call-room.ts`)

`LIVENESS_NOPING_STALE_MS = 600 * 1000` 을 두고, ping 근거를 **한 번도** 못 잡은 소켓은
그 상한까지 기다린다. 판정은 순수 함수 한 곳에 모았다:

```ts
static livenessVerdict(now, seen, autoAt, staleMs, nopingMs): 'alive' | 'grace' | 'kill'
```

`alarm()` 은 그것을 «부르기만» 한다.

### 4-2. 왜 끊었는지 세 근거를 각각 로그로

`silent=` 만으로는 사후에 가를 수 없어 `auto=` · `mem=` · `att=` 를 따로 남긴다.
유예가 발동할 때도 한 줄 남긴다 — 그 갈래가 도는 것 자체가
「자동응답 시각을 못 쓰고 있다」는 신호다.

## 5. 검토했다가 버린 방법

| 안 | 왜 버렸나 |
|---|---|
| **클라이언트 ping 문자열을 바꿔 자동응답을 비켜 가게** (`{type:'ping2'}`) | `idx-main.js` 는 blocking 이라 첫 화면 예산이 없다(한 글자도 못 넣는다). 게다가 DO 가 25초마다 깨어나 hibernation 설계가 통째로 뒤집힌다 |
| **`setWebSocketAutoResponse` 를 끄고 `webSocketMessage` 가 ping 을 받게** | 가장 확실하지만 같은 이유로 hibernation 이득을 버린다. 2026-08-20 에 «DO 를 깨우지 않는다» 를 이유로 고른 설계를 근거 없이 뒤집게 된다 |
| **`LIVENESS_STALE_MS` 를 늘리기** | ping 근거가 «있는» 진짜 유령까지 함께 늦게 치워진다. 고치려는 것은 «근거가 없을 때» 뿐이다 |
| **알람에서 서버가 ping 을 보내 유예** | 클라이언트가 서버발 ping 에 답한다는 보장이 없다 |
| **유예를 무한으로(안 끊기)** | 2026-08-20 「왜 3명이 나와?」 유령 사고가 되살아난다. 상한을 둔 이유 |

| 변이 | FAIL |
|---|---|
| 유예 갈래 제거(= 고치기 전) | 2 |
| 조건 뒤집기 `!autoAt` → `autoAt` | 3 |

하니스는 판정 함수를 **오려 내 실제로 돌린다**(문자열 검사로는 `if (false && …)` 한 글자를
못 잡는다). 「근거가 없으면 안 끊는다」 옆에 **「근거가 있으면 예전대로 끊는다」·
「상한을 넘기면 끊는다」를 짝으로** 뒀다 — 짝이 없으면 «전부 살려 두기» 도 통과한다.

## 7. 남은 것 (사람이 정할 일)

1. **확정** — 배포 뒤 Workers 로그에서 `auto=없음` 인지 확인. 그래야 3장의 추론이 사실이 된다.
   `auto=` 에 값이 있는데도 끊긴다면 원인이 다른 데 있다.
2. **창 밖 수업이 무방비** — 배포 보류 창이 화·목 14:00~23:00 뿐이라 12:30·12:54 수업은
   보호받지 못한다(그날 13:03 배포가 실제로 그 수업 중에 나갔다). 창을 넓힐지,

3. **유예 600초가 맞는 값인지** — 로그로 실제 빈도를 보고 조정.
