# 음성전용(AAO) 에서 회선이 회복돼도 영상이 안 돌아오던 것 — «끄기» 만 다시 걸고 «켜기» 는 한 번뿐이었다

- 날짜: 2026-09-15
- 브랜치: `claude/festive-bell-brttqe`
- 고친 파일: `cloudflare-deploy/public/js/idx-vc-qlog.js`(defer) · `cloudflare-deploy/public/index.html`(`?v=` 한 글자) · `test-harness/aao_freeze_harness.mjs`

## 1. 왜 했나

제보 넷을 받았습니다.

1. 수업이 2~3분 주기로 끊긴다
2. 회선이 약하면 «음성만 전송» 이 되고 영상이 검은 화면이 된다
3. **회복된 뒤에도 영상이 자동으로 돌아오지 않는다**
4. 원인이 교사 회선인지·학생 회선인지·서버 판정인지 로그로 가릴 수 없다

먼저 **①·②가 이미 고쳐져 있다**는 것을 확인했습니다 — 그래서 다시 고치지 않았습니다.

|---|---|---|
| ① 2~3분 끊김 | **이미 수리됨**(2026-09-15, `55b8767`) | `livenessVerdict()` 순수함수 + `LIVENESS_NOPING_STALE_MS` 600초 유예. `vc_ghost_liveness_harness` 57종 |

## 2. 찾은 원인 — 재적용이 «한쪽» 만 있었다

`js/idx-vc-qlog.js` 의 4초 타이머가 이랬습니다.

```js
function vcAaoTick() {
    var A = window.__vcAAO;
    if (A && A.active) { try { vcAAOVideo(0); } catch (_) {} }   // «끄기» 만 다시 건다
```

- **끄기**: AAO 중이면 4초마다 다시 걸림 → 튼튼함
- **켜기**: `vcAAOApply()`(`idx-main.js`)의 복구 갈래에서 **딱 한 번** `vcAAOVideo(1)`

그런데 그 한 번의 `setParameters` 는 `.catch(function () {})` 로 **거절을 통째로 삼켰습니다.**
그리고 `active=true` 로 되돌리는 코드는 저장소에 `vcAAOVideo` **한 곳뿐**이고 그것을 부르는 곳도 한 곳뿐입니다.

⟹ **그 한 번이 거절되면 되살릴 사람이 아무도 없습니다.** 소리는 멀쩡하고 영상만 마지막 장면에
멈춘 채 수업이 끝나며, **에러도 화면 표시도 로그도 남지 않습니다.**

### 왜 하필 그 한 번이 거절되나 — [추론, 측정 아님]

`getParameters()` 는 스냅샷이고 `setParameters()` 는 그 스냅샷이 최신일 때만 받습니다.
그런데 같은 sender 에 `getParameters→setParameters` 를 거는 곳이 여럿입니다.

| 부르는 곳 | 파일 | 주기 |
|---|---|---|
| `applyStep`(화질 단계) | `idx-main.js` | **4초** |
| `vcAAOVideo` | `idx-vc-qlog.js` | **4초** |
| `vcBg`(가상배경)·저전력 | `idx-main.js` | 이벤트 |

`applyStep` 의 화질 «회복»(`__qGood >= 8`)과 AAO 의 «복구»(`good >= 8`)는 **둘 다 «약 32초 조용함»**
이 조건이라, **같은 틱에 함께 발화할 개연성이 높습니다.**

⚠️ **이 마지막 한 단계는 코드를 따라간 추론이고 라이브에서 잰 것이 아닙니다.**
확정하려면 이번에 넣은 `[vc-aao] setParameters 거절` 로그를 봐야 합니다.
⚠️ 다만 **원인이 무엇이든 «한 번뿐인 켜기» 가 되돌릴 길 없는 구조**라는 것은 추론이 아닙니다.

## 3. 고친 것

전부 `js/idx-vc-qlog.js`(**defer**)입니다. `idx-main.js` 는 **한 줄도 안 건드렸습니다**
(blocking 이고 첫 화면 예산 여유가 8바이트라 주석도 못 넣습니다).

### ① 4초 타이머가 «양방향» 을 다시 건다 — 이번 수리의 핵심

```js
var want = (A && A.active) ? 0 : 1;
if (!(want && vcAaoSfuCut())) { try { vcAAOVideo(want); } catch (_) {} }
```

`vcAAOVideo` 가 **자기 주석에 이미 적어 둔 설계**(«상태를 지정» 하는 방식)를 타이머가 안 따르고
있던 것입니다. 이제 한 번 거절돼도 **4초 뒤 스스로 되살아납니다.**
평소에는 `cur === want` 조기반환이라 **아무 일도 하지 않습니다**(불필요한 `setParameters` 0회).

### ② SFU 가 mesh 를 끊어 둔 동안에는 «켜지» 않는다

`idx-vc-sfu.js` 의 `cutMeshVideo()` 가 **같은 `vcPeerConnections`** 의 영상 sender 에
`encodings[].active=false` 를 겁니다. 대칭 재적용을 그냥 넣으면 **SFU 가 일부러 끈 것을 4초마다
되살려 영상이 두 갈래(mesh+SFU)로 나갑니다.** `vcAaoSfuCut()` 가드로 막았습니다.

### ③ `setParameters` 거절을 더는 삼키지 않는다

`[vc-aao] setParameters 거절 — uid … 켜기/끄기 …` 로 남깁니다.
②의 원인 추론을 **다음 사람이 사실로 확정할 수 있는 유일한 근거**입니다.

### ④ 「켰다」와 「나간다」를 가른다 — `vcAaoVerify()`

`active=true` 로 되돌린 것을 **복구 성공으로 판단하지 않습니다.** 되살린 뒤 30초 동안
`outbound-rtp.framesSent` 가 실제로 느는지 보고, 3틱(≈12초) 동안 안 늘면 말합니다.

```
[vc-aao] 영상을 되살린 뒤 12초 동안 프레임이 안 나갑니다 — uid … · framesSent …
```

## 4. 검토했다가 버린 방법

| 안 | 왜 버렸나 |
|---|---|
| **`vcAAOApply`(idx-main.js)에서 복구를 여러 번 재시도** | `idx-main.js` 는 blocking 이고 첫 화면 예산 여유가 **8바이트**입니다. 한 줄도 못 넣습니다 |
| **프레임이 안 오면 `restartIce()`·재협상** | 이 자리는 «회선이 방금 나빴던» 곳입니다. 저장소가 이미 「대역폭이 나쁜 상황에서 연결을 다시 맺는 것은 최악」이라고 못 박아 뒀습니다. **되살리는 일은 ①이 하고, ④는 «말하는» 일만** 합니다 |
| **`vcAAOVideo` 안에 SFU 가드를 넣기** | 그러면 `vcAAOApply` 의 «한 번뿐인» 직접 호출 동작까지 바뀝니다. 그건 **기존 동작**이라 이번 범위 밖입니다. 새로 «되풀이» 하는 쪽(타이머)만 막았습니다 |
| **재적용 주기를 더 짧게** | 4초면 충분하고, `setParameters` 를 자주 부르면 인코더가 흔들립니다(그 파일 주석의 경고) |
| **`?v=` 를 안 올리기** | immutable 캐시라 최대 1년 옛 파일이 남습니다. 고쳐도 **아무에게도 안 갑니다** |

## 5. 확인한 방법

### 변이시험 — **실제 소스를 되돌려** 빨간불이 나는지

| 변이 | 결과 | 잡은 검사 |
|---|---|---|
| «켜기» 재적용을 옛 한쪽짜리로 되돌리기 | **FAIL 4, exit=1** | **C-21** |
| SFU meshCut 가드 빼기 | **FAIL 3, exit=1** | **C-22** |
| 프레임 확인 통째로 빼기 | **FAIL 2, exit=1** | **C-23** |
| 사람이 끈 카메라 가드 빼기 | **FAIL 1, exit=1** | **C-25** |
| (원상복구) | **PASS 83 / FAIL 0, exit=0** | — |

`aao_freeze_harness` 는 **가짜 DOM 에서 그 절을 실제로 돌립니다**(문자열 검사가 아닙니다).

### 짝 검사 — 한쪽만 두면 반대 사고가 통과합니다

- C-21 «복구 뒤 다시 켠다» ↔ **C-17 «AAO 중에는 끈다»**
- C-22 «SFU 중엔 안 켠다» ↔ **C-18 «AAO 가 아니면 안 건드린다»**
- C-23 «프레임이 안 늘면 말한다» ↔ **C-24 «늘면 말하지 않는다»** · **C-25 «카메라 끈 사람에겐 말하지 않는다»**

### 회귀

| 검사 | 결과 |
|---|---|
| `aao_freeze_harness` | 74 → **83종**, FAIL 0 |
| `vc_ghost_liveness_harness`(2~3분 끊김 수리) | **57 통과 / 0 실패** — 커밋 당시와 같음 |
| `first_paint_budget_harness` | **✅ 유지** (blocking 1575KB 그대로 — defer 만 커짐) |
| `asset_version_harness` | 226건 ✅ |
| `run.mjs --fast` **기준선 대조** | ▶ 346 · ✅ 330 · ⚠ 16 → **새로 생긴 FAIL 0건** |

⚠️ 그 16건은 **기준선(HEAD)에서도 똑같이 빨간불**입니다(이 컨테이너에 `node_modules` 가 없어
나는 환경 사유). `git worktree add … HEAD` 로 «내 편집 전» 을 그대로 재현해 **목록을 `comm` 으로**
대조했습니다 — 숫자만 비교하지 않았습니다.

⚠️ **타입체크(tsc)는 이 컨테이너에서 못 돌렸습니다**(`node_modules` 없음). 다만 이번 변경은
**`.ts` 파일을 한 개도 건드리지 않아** 타입체크 대상이 아닙니다.

## 6. 아직 남은 것 / 위험

- 🔴 **원인의 마지막 한 단계는 여전히 추론입니다.** 배포 뒤 Workers 로그에서
  `[vc-aao] setParameters 거절` 이 실제로 찍히는지 봐야 «경합» 이 사실이 됩니다.
  ⚠️ `head_sampling_rate = 0.05` 라 **20건 중 19건은 로그가 안 남습니다.**
- ⚠️ **브라우저에서 «실제로 얼굴이 돌아오는지» 는 못 쟀습니다.** 이 컨테이너는 프록시가
  `mangoi.ai` 를 막고, 진짜 WebRTC 회선 붕괴를 재현할 수 없습니다. 하니스는 «판정과 배선» 까지입니다.
- ⚠️ `vcAAOApply` 의 **직접 호출**(`vcAAOVideo(1)`)은 SFU meshCut 중에도 여전히 켭니다 —
  **고치기 전부터 그랬고** 이번에 «되풀이» 만 막았습니다. 바꾸려면 별건입니다.
- ⚠️ ④의 경보는 **콘솔 로그뿐**입니다. 화면·D1 에는 안 남습니다(사람이 보러 가야 보입니다).

## 7. 실제 수업에서 확인할 것

1. 회선이 나빠져 「음성만 전송」 안내가 뜬 뒤, **회복되면 영상이 실제로 돌아오는가**
2. 강사 콘솔에 `[vc-aao] setParameters 거절` 이 찍히는가 → 찍히면 **경합 추론이 사실**
3. `[vc-aao] 영상을 되살린 뒤 12초 동안 프레임이 안 나갑니다` 가 찍히는가
   → 찍히면 `active` 말고 **다른 것**(인코더·트랙)이 막고 있다는 뜻
4. 카메라를 끈 학생에게 3번이 **안** 찍히는가(거짓 경보 확인)
