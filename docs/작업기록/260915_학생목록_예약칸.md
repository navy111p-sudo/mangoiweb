# 학생 목록·상세에 「예약」 칸 — 수업을 넣어도 «—» 이던 것

- **날짜**: 2026-09-15
- **제보**: 사장님 「수업 입력했고 스케줄에도 잇는데 왜 여기 없어?? 학생목록에는 안보여」
  → 이어서 「정우영도 마찬가지야. 학생목록에도 안보이고 상세 사이드바에도 없어」
- **PR**: #988
- **관련**: #986(같은 뿌리의 형제 제보 — 「수강신청 목록엔 없는데 수업은 있다」)

---

## 1. 왜 했나

학생 `lee`(이병엽)·`jeong`(정우영) 둘 다 **스케줄 화면에는 수업이 멀쩡히 보이는데**
학생 목록과 상세 좌측 카드는 「결제타입 · 수강 시작일 · 수강 종료일 · 수업회수(주)」가
전부 «—» 였습니다.

## 2. 잰 것 (운영 D1, SELECT 만)

### 수업은 제대로 저장돼 있었습니다

`class_schedules` 에서:

| 학생 | 활성 예약 | 비고 |
|---|---|---|
| `lee` | 2건 — 9/18 14:00(MAIMAI) · 9/21 14:00(FAR) | 9/15 15:00 은 `cancelled` |
| `jeong` | 5건 — 반복 화·수·목·금 19:20(강선생님, `teacher_id=29`) + 일회성 9/14 18:30 | 스케줄 탭의 「총 5건」과 일치 |

### 목록이 읽던 칸은 «다른 표» 였습니다

```sql
SELECT user_id, payment_type, signup_date, end_date, classes_per_week, created_at
FROM students_erp WHERE user_id IN ('lee','jeong');
-- 두 행 모두 payment_type·signup_date·end_date·classes_per_week 가 NULL
-- created_at = 1751500000000  ← 카페24 센티넬
```

- 목록 화면(`js/adm-core.js` `_smRowHtml`)과 상세 카드(`admin/student.html` `renderCard`)가
  그리는 그 네 칸은 전부 **`students_erp`** 의 칸입니다.
- 그 표는 **카페24가 정본**이라(`created_at` 센티넬) D1 에 채워도 **매일 밤 03:00**
  `importCafe24Students` 가 덮습니다.
- 같은 이름 4계정 중 `unistudy` 만 날짜(2012-09-13~2019-05-15)가 보이던 것도
  «카페24에 그 값이 있어서» 였습니다.

⟹ **관리자 「수업 예약 등록」은 `class_schedules` 에만 씁니다. 두 표 사이에 배선이
아예 없었습니다.** 고장이 아니라 설계가 그랬습니다.

> 이 사실은 CLAUDE.md 에 이미 한 줄 적혀 있었습니다(2026-09-14 작업의 ℹ️ 줄) —
> 「예약표에서 계산해 그릴지는 **사람이 정할 일**」. 이번에 그 결정을 받았습니다.

## 3. 검토했다가 버린 방법

### (A) 빈 칸을 예약값으로 «채우기» — 버렸습니다

「수강 종료일」에 마지막 예약일을, 「수업회수(주)」에 예약 건수를 넣는 방법입니다.
그럴듯하지만 **뜻이 달라집니다**:

- 「수강 종료일」의 원래 뜻은 «결제한 수강권이 끝나는 날» 입니다. 마지막 예약일은
  «지금까지 잡아 둔 마지막 수업» 이라 **수업을 더 잡을 때마다 저절로 늘어납니다.**
- 「수업회수(주)」도 — 실측된 그 예약들은 **전부 `one_off`(일회성)** 라 «주당 회수» 가
  아닙니다.

CLAUDE.md 2장 「측정할 수 없는 값을 그럴듯하게 채우고 싶을 때 ⛔ 지어내지 마세요」에
정면으로 걸립니다.

### (B) 빈 칸일 때만 회색으로 채우기 — 버렸습니다

카페24 값이 있으면 그대로 두고 비었을 때만 예약값을 넣는 안. 칸이 안 늘어나는 이득은
있지만 **같은 열에 두 가지 뜻이 섞입니다**(어떤 행은 «수강권», 어떤 행은 «예약»).
정렬·CSV·필터가 전부 그 혼선을 물려받습니다.

### (C) 「예약」 칸을 새로 추가 — **택함** (사장님 선택)

기존 칸은 한 글자도 안 건드리고 사실만 말하는 칸을 하나 답니다.

## 4. 한 일

### 정본 하나 — `src/student-schedule-summary.ts` (신규)

- `summarizeStudentSchedules(rows, todayYmd)` — 순수 함수.
  반복 → `weekly`, 날짜 지정 → `upcoming`/`past`.
- **라벨(`label_ko`·`label_en`)도 서버가 만듭니다.** 그리는 화면이 둘이라, 화면이 각자
  조립하면 「화면마다 답이 다른」 상태가 됩니다.
- `loadSchedSummaryMap(env)` — 목록용. **활성 예약 전체를 한 번에** 읽어 메모리에서
  묶습니다(학생마다 조회 금지 · 바인드 100개 한도 회피). 실측 1,518행 / 492명.
- `loadSchedSummaryOne(env, uid)` — 상세용.
- 조회 조건은 `schedule-conflict.ts` 의 `NOT_PLACEHOLDER` 와 **같은 문자열**
  (LMS·시드 자리표시 제외) — 하니스가 두 곳을 대조합니다.

## 6. 검사가 헛돌던 것 — 함께 고침

1. **`admin_student_list_harness` 가 열 수를 «19» 로 못 박아** 두어, 칸을 하나 더하는
   정당한 수리에 **보장은 그대로인데 검사만** 빨간불이 났습니다.
   → 「**col·th·td·colspan 네 곳이 서로 같은가**」로 고쳤습니다(변이 4종 실제 FAIL).
   ⚠️ td 를 셀 때 `<td` 만 세면 안 됩니다 — 헬퍼(`_ct`·`_schedTd`)가 한 칸을 통째로
   돌려줍니다. ⛔ 그렇다고 헬퍼 «이름» 을 검사에 적으면 새 헬퍼가 생길 때 또 어긋납니다.
2. **부정 검사를 «파일 전체» 에 걸어 거짓 FAIL** — `adm-core.js` 의 **무관한 기능**
   (10899행 `schedule: '주 ' + classes_per_week + '회'`)이 걸렸습니다.
   → 그 칸을 그리는 «그 자리» 만 잘라서 봅니다.
3. **fail-open 변이가 «0건» 으로 나와** 검출한 줄 알 뻔했습니다 — 정본이 던지자
   **하니스가 크래시**해 ❌ 가 한 줄도 안 찍힌 것이었습니다(그 상태로 `grep -c ❌` 를
   세면 «통과» 로 위장). → 부르는 자리를 `try` 로 감싸 «깔끔한 FAIL» 이 되게.
