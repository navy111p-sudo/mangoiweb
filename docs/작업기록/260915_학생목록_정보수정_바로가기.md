# 학생 목록에서 «정보 수정» → 상세 › 연락처·정보 로 바로 (2026-09-15)

## 1. 왜 했나

사장님 지시가 세 번에 걸쳐 좁혀졌습니다.

1. 「보다시피 기존학생 자료나 정보를 수정하는 기능을 학생목록에 추가해줘」
2. 「정보 수정 카드를 학생 등곡(등록) 옆에 만들어서 클릭하면 상세에 있는 연락처,정보로 가게 해줘」
3. 「빨리 신속하게 수정할 수 있게」 · 「정보수정 > 연락처,정보 이렇게 상세안에 있는 것으로 바로 가게해줘」 · **「위에 것 말고」**

첫 지시만 보고 목록에 **수정 폼 모달**을 만들기 시작했는데(모달 마크업까지 넣었다가 되돌림),
2·3번 지시가 그것을 명확히 부정했습니다 — **고치는 화면은 이미 있는 것을 쓰고, 거기로 «바로» 보내라.**

## 2. 잰 것

- 학생 정보를 고치는 화면은 **`/admin/student` 의 「👨‍👩‍👧 연락처·정보」 탭 하나**뿐이고
  `PATCH /api/admin/student/:uid/contact` 를 부른다(`public/admin/student.html:1694`).
- 그 상세 페이지는 **`?tab=contact` 딥링크를 이미 받는다** — `_initTab`(`student.html:2753~2761`).
  ⟹ **상세 화면은 한 줄도 안 고쳐도 된다.**
- 학생 목록 표: `col` 20 · `th` 20 · 한 줄 `td` 20 인데 **JS 의 빈 줄 `colspan` 만 19** 로 남아 있었다
  (9/15 「예약」 칸을 더할 때 네 자리를 빠뜨림).
- `students_erp` 의 `parent_phone`·`student_phone`·`phone` 은 **카페24 야간 UPSERT SET 목록**에 있다
  (`cafe24-sync.ts` 271행~). `teacher_phone` 은 그 목록에 **없다**(= 안 덮인다).

## 3. 한 것

### 3-1. 화면 — 입구 둘, 주소 정본 하나

정본 `smContactUrl(uid)` → `/admin/student?uid=…&tab=contact` (`js/adm-core.js`).

| 입구 | 동작 |
|---|---|
| 표 각 행 「✏️ 수정」(`<a>`) | 그 학생의 연락처·정보 탭으로 곧장 |
| 도구 줄 「✏️ 정보 수정」(`#sm-edit-student`, 「➕ 학생 등록」 옆) | 지금 목록(`_smRows`)이 1명이면 **바로**, 여러 명이면 고르기 창, 목록이 없으면 「불러오기」를 눌러 주고 안내 |

### 3-2. 서버 — 고친 번호가 «밤에» 사라지지 않게

`PATCH …/contact` 가 번호를 `students_erp` 에만 썼다 ⟹ 하룻밤이면 사라진다.
그래서 `setOverridePhones` 로 **`student_erp_override` 에도 함께** 적는다
(수업 안내문자가 읽는 정본 `phonesForStudent` 가 그 표를 «먼저» 본다).

- 마스킹 표시값은 기존 `PII_GUARD` 가 이미 거른다.
- 실패해도 저장은 막지 않되 **응답 `phone_kept`** 를 상세 화면 토스트가 읽어 사람에게 말한다
  (흔한 실패는 «숫자 9자리 미만» — 그때 「저장되었습니다」만 띄우면 번호는 `students_erp` 에만
  들어가 그날 밤 사라지고 문자는 영영 안 간다).

🔴 **「빈 칸으로 저장 = 지우기」는 «지금 닿지 않습니다» — 처음에 사실이 아닌 것을 세 곳에 적었습니다.**
유일한 호출부(상세의 «연락처·정보» 탭)는 빈 칸을 `value || null` 로 보내므로
`typeof v === 'string'` 이 거짓 → `_ovTouch=false` → override 를 안 건드립니다
(식을 오려 내 실제 payload 로 돌려 확인). 함정 대조가 잡았고, 주석·작업기록·INDEX 세 곳을
사실대로 고쳤습니다.
⟹ 그래서 **빈 칸으로 저장하면 `students_erp` 만 NULL 이 되고 override 는 옛 번호를 들고 있어
「명부에서는 지웠는데 문자는 계속 그 번호로」가 남아 있습니다.** 아래 §6 참고.
⛔ 이것을 「`null` 도 지우기로 받기」로 고치면 **더 나쁜 사고**가 납니다 — 그 폼은
`students_erp` 값으로 칸을 채우는데 그 칸은 카페24가 매일 밤 비워 **실측 29,485행 전부
비어 있어서**, 번호를 넣어 둔 학생의 폼을 열어 «학교만» 고쳐 저장해도 번호 칸이 빈 채로 가
**어제 넣은 번호가 오늘 지워집니다.**

### 3-3. 곁가지

빈 줄 `colspan` 19 → 20 · 「상세보기」 열 폭 80 → 112px · `adm-core.js?v=223`.

## 4. 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| **목록에 수정 폼 모달** (처음에 만들던 것) | 사장님 「위에 것 말고」. 같은 폼이 두 벌이 되면 한쪽만 고쳐지는 사고가 시작된다. 고치는 화면은 하나여야 한다 |
| 폼에 **결제타입·수강 시작/종료·수업회수·상태·포인트** 넣기 | 서버 `allowed` 목록에 없어 **조용히 저장되지 않고**, 카페24가 정본이라 고쳐도 밤에 덮인다. 화면이 «왜 못 고치는지» 를 말하는 쪽을 택했다 |
| 표에 **칸을 새로 추가** | `col`·`th`·`td`·`colspan`·CSV 가 전부 짝이라 반경이 크다. 「상세보기」 칸 **안**에 넣어 칸 수를 안 바꿨다 |
| 고르기 줄을 `<button>` 으로 | `details.menu-card button{…!important}` 전역 규칙이 파란 알약으로 만든다. `<a>` 는 안 걸린다 |
| `franchise`(지사) 칸 | 표의 「지사명」은 `branch2_name` 이라 **다른 칸**이다. 헷갈리는 칸은 넣지 않았다 |

## 5. 확인한 방법

- **`test-harness/student_contact_edit_harness.mjs` 신설 44종** — 문자열이 아니라 **실제로 돌린다**:
  주소 정본·버튼 동작을 오려 내 가짜 DOM 으로, 서버 번호 보관 절은 타입만 지워 가짜
  `setOverridePhones` 로. 「된다」 옆에 **짝**(「여러 명이면 함부로 안 연다」·「번호를 안 고친
  요청은 override 를 안 건드린다」)을 두었다.
- **변이 14종 전부 실제 FAIL.**
  🪤 그중 Ⓗ(«넣기» 호출만 죽이기)가 **문자열 검사로 한 번 뚫렸다** — 호출이 둘이라
  `setOverridePhones(` 가 다른 쪽에 남아 통과했다. 그래서 ⑤절을 실행 검사로 바꿨다.
  🪤 ④(`colspan`)도 처음엔 **파일 전체**의 다른 표까지 세어 거짓 FAIL 이 났다 — 학생 목록을
  그리는 세 함수 몸통 안에서만 세도록 좁혔다.
- `--fast`: PASS 325 → **326** · FAIL 16 그대로 · **새로 깨뜨린 것 0건**(이름 목록 `comm` 대조).
- 타입체크: 이 컨테이너에 `node_modules` 가 없어 **CI 게이트 ①**이 맡는다.

## 6. 아직 안 한 것 · 사람이 볼 것

- **화면은 사람이 한 번 봐야 끝입니다** — 프록시가 `mangoi.ai` 를 막아 배포된 화면을 여기서 못 엽니다.
- 결제타입·수강 시작/종료·수업회수·상태·포인트는 **여전히 못 고칩니다**(카페24 정본).
  그것까지 우리 쪽에서 고치려면 «카페24가 덮지 않는 자리» 를 칸마다 만들어야 하고 — 사람이 정할 일입니다.
- 🟡 **같은 폼의 `school`·`grade`·`shop_name`·`franchise` 도 야간 동기화가 덮습니다**(함정 대조 실측 —
  `cafe24-sync.ts` 의 `DO UPDATE SET` 목록). 번호와 이름만 override 로 지켜지고 그 넷은 안 지켜집니다.
  ⟹ 학교·학년을 고친 매니저가 **다음 날 되돌아간 것을 보게 됩니다(에러 없음).**
  `teacher_phone`·`kakao_id`·`parent_kakao_id`·`address`·`birth_date`·`notes` 는 안 덮입니다.
- 🟡 **번호를 «완전히 비우는» 길이 없습니다**(위 §3-2). 새 번호로 «덮어쓰는» 것은 됩니다.
  제대로 고치려면 **폼이 override 번호를 보여주는 것이 먼저**입니다 — 사람이 정할 일.
- 🟡 **그 PATCH 는 강사도 부를 수 있습니다**(`/api/admin/student/` 가 `TEACHER_BLOCKED_PREFIXES` 에 없음).
  이번 변경이 그 쓰기를 «밤에 안 지워지는 문자 목적지» 로 만들었으므로 반경이 커졌습니다
  (지사·대리점은 `forbidden_scope` 로 이미 막힙니다). 게이트를 달지는 **사람이 정할 일** —
  달 때는 `canEditOrg()` 금지(scope `'none'` = 교사에 true), `getAdminActor().isTeacher` 로.
- ℹ️ 도구 줄 버튼·행 링크의 **인라인 색·여백은 한 글자도 안 먹습니다**(브라우저 실측) —
  `details.menu-card button{…!important}` 와 `[id^="card-"] button:not([class])` 가 이깁니다.
  **옆의 「학생 등록」 버튼과 완전히 같은 모양**이라 새 회귀는 아니고, 뜻이 색에 실려 있지도
