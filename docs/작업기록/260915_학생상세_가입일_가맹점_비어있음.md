# 학생 상세 「가입일」·「가맹점」이 비어 있던 것 — 표시 폴백 + 편집 지속성

- 날짜: 2026-09-15
- 작업자: Claude Code
- 브랜치 / PR: claude/happy-johnson-3gbj4k

## 1. 왜 했나

사장님 제보(스크린샷 첨부): "학생 정보 화면이야. 왼쪽에 가입일, 가맹점이 비어있어.
이 부분을 채워줘." — 관리자 › 학생 상세(`admin/student.html`) 왼쪽 요약 카드의
「📅 가입일」·「🏢 가맹점」 두 칸이 비어 있는 문제.

## 2. 무엇을 바꿨나

**① 가입일 — 표시 필드를 바로잡았다 (버그).**
- `cloudflare-deploy/public/admin/student.html` — `renderCard()`(요약 카드)와
  `renderExtension()`(KPI 카드) 두 곳 모두 「가입일」이 `erp.signup_date` 만 읽고
  있었는데, 관리자 학생 **명부 표**(`admin.html`)는 이미 「가입일」을 **`created_at`**
  으로 정해 두고 있다(`js/adm-core.js` 의 `data-sort-key="created_at" data-ko="가입일"`
  + 그 정렬 기본값을 정할 때 남긴 주석 「실제 표에 있는 열(가입일 = created_at)로
  명시한다」). `signup_date` 는 명부 표에서는 **다른 이름**(「수강 시작일」)으로 따로
  있는 카페24의 «수강 시작일» 이지 「가입일」이 아니다. 두 화면이 같은 라벨을 다른
  필드로 읽고 있던 것 — 카페24 원본에 `signup_date` 가 없는 학생은 명부에는 가입일이
  뜨는데(`created_at` 을 보므로) 상세 카드만 늘 «—» 였다. 고침: 두 곳 모두
  `erp.signup_date || fmtDay(erp.created_at)` 로 — `signup_date` 자체는 지우지
  않는다(«수강 시작일» 이라는 별개의 사실이라 다른 화면이 그 뜻으로 쓸 수 있어야 한다).

**② 가맹점 — 편집이 «오늘 밤» 지워지지 않게 지속성을 더했다 (신규 기능).**
- 표시 자체(`erp.franchise || erp.shop_name`)는 이미 최선의 폴백이라 코드 버그가
  아니었다. 대신 이 화면의 편집칸(`cFranchise`/`cShop`)으로 관리자가 값을 채워도,
  `students_erp.franchise`·`shop_name` 은 카페24 UPSERT 의 SET 목록에 있어(`cafe24-sync.ts`)
  **매일 밤 03:00 KST 에 그대로 지워진다** — 같은 화면의 전화번호가 9/10 에 이미 겪은
  것과 정확히 같은 사고(`student-override.ts` 머리말)를 franchise·shop_name 칸에서
  반복하게 되는 것이었다. 이번에 그 구멍을 전화번호와 같은 방식으로 닫았다:
  - `cloudflare-deploy/src/student-override.ts` — `student_erp_override` 표에
    `franchise`·`shop_name`·`org_by`·`org_at` 칸을 지연 ALTER 로 추가하고,
    `getOverrideOrg()`·`setOverrideOrgField()` 두 함수를 새로 뒀다.
    `applyStudentErpOverrides()` 에 franchise·shop_name 을 **각각 독립된 UPDATE
    문으로** 재적용하는 로직을 추가했다(korean_name 과 같은 「지정 후 재적용」 패턴).
  - `cloudflare-deploy/src/api-mango.ts` — `PATCH /api/admin/student/:uid/contact`
    가 franchise·shop_name 을 고쳤을 때 `orgTouched` 로 추적해 `setOverrideOrgField`
    를 **필드마다 따로** 부르고, 실패하면 응답에 `org_override_warning` 을 싣는다.
    `GET /api/admin/student/:uid/full` 은 `getOverrideOrg()` 로 override 값이 있으면
    (PII 마스킹 전에) `erp.franchise`/`shop_name` 을 덮어 보여준다(전화번호와 같은
    「쓰는 쪽·읽는 쪽」 짝).
  - `cloudflare-deploy/public/admin/student.html` — `org_override_warning` 을
    받으면 「저장은 됐지만 오늘 밤 지워질 수 있다」 토스트를 띄운다(전화번호와 같은 문구
    패턴, `orgOverrideWarn` 사전 항목 신설).
- 신규 하니스: `test-harness/student_contact_org_override_harness.mjs` (34종)

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **가맹점을 「센터/대리점 표에서 자동으로 찾아 채우기」** — 버렸다. 등록 모달의
  「소속 대리점·학원명」 입력칸(`sm-reg-shop` → `shop_name`)은 `/api/admin/centers`
  에서 온 이름을 `<datalist>` 로 보여줄 뿐 `franchise_id` 를 저장하지 않고, 이 저장소의
  `centers.name`/`franchises.name` 은 **유일하지 않다**(CLAUDE.md 「가맹점 정산에서
  특정 지사 매출이 통째로 안 잡힘」과 같은 뿌리 — 여러 지사가 같은 이름을 쓸 수 있다).
  이름만으로 자동 매칭하면 후보가 둘 이상일 때 엉뚱한 지사가 붙는다. 「모르면 붙이지
  않는다」 원칙을 지키기로 하고, 대신 **사람이 직접 채운 값이 지워지지 않게** 하는
  쪽으로 방향을 잡았다.
- **관리자 학생 명부 표의 「지사명」 칸(`branch2_name`)을 `franchise` 로 바꾸는 것** —
  조사는 했지만(그 칸이 legacy demo-seed 전용이라 실사용자 전원에서 항상 비어 있는
  것을 확인) 이번 수정 범위 밖으로 남겼다. `franchise`·`branch1_name`·`branch2_name`
  세 필드의 조직 계층 뜻이 `org-settlement.ts`/`migration-org-graph.sql` 주석에서
  이미 복잡하게 얽혀 있는 것으로 보여, 확신 없이 그 매핑을 바꾸는 것은 사장님 화면의
  다른 화면(가맹점 정산 등)에 예기치 못한 파급을 낼 위험이 있었다. **사람이 정할 일로
  남긴다.**
- **`students_erp.franchise`/`shop_name` 을 직접 UPDATE 하는 관리 API 를 새로
  만드는 것** — 버렸다. 카페24 UPSERT 가 매일 밤 덮으므로 그 자체로는 지속되지
  않는다(전화번호가 이미 겪은 사고). 반드시 override 표를 거쳐야 한다.
- **`setOverridePhones` 처럼 한 호출에 franchise·shop_name 을 함께 넘기는 시그니처** —
  버렸다. 바로 전화번호 코드에 trap-check 가 잡은 교차 오염 사고(한쪽을 `clear` 하면
  전역 `clear` 플래그 탓에 다른 쪽 값도 함께 지워짐)가 있었다. `setOverrideOrgField` 는
  **한 번에 한 필드만** 받도록 시그니처 자체를 그렇게 만들어, 호출자가 규율을 지킬
  필요 자체를 없앴다.

## 5. 남은 것 / 주의할 것

- **가맹점이 여전히 비어 있을 수 있다** — 카페24 원본에 `franchise` 도 `shop_name`
  도 없는 학생이라면(코드 버그가 아니라 데이터 자체가 없는 경우) 이번 수정으로는
  자동으로 채워지지 않는다. 그럴 때는 관리자가 「연락처·정보」 편집란에서 가맹점을
  **직접 입력**해야 하고, 이번 수정 덕분에 그 값이 이제는 다음 날 밤에 지워지지 않고
  남는다. "이 부분을 채워줘"의 절반(지속성)만 코드로 풀었고, 나머지 절반(어떤 값을
  넣을지)은 사람이 정할 몫이다 — CLAUDE.md 의 「측정할 수 없는 값을 그럴듯하게
  채우고 싶을 때」 원칙에 따라 값을 지어내지 않았다.
- 관리자 학생 **명부 표**(`admin.html`)의 「지사명」 칸이 legacy 전용 필드
  (`branch2_name`)를 보고 있어 실사용자 전원에서 항상 비어 있다 — 위 3절에서 서술한
  대로 이번 범위 밖으로 남겼다. 필요하면 별도 작업으로 조직 계층(hq_name·
  branch1_name·franchise·shop_name) 뜻을 먼저 확인하고 진행해야 한다.
- `student_erp_override` 표에 franchise·shop_name 칸이 새로 생겼다 — 운영 DB 는
  지연 ALTER 라 이 코드가 실제로 한 번 돌기 전까지는 그 칸이 없다(정상 — 다른 지연
  ALTER 칸들과 같은 사정).
