# 수업 종료 후 남는 녹화중 상태

## 제보와 확인

2026-09-18 관리자 화면의 2907(13:36 KST)·2909(13:43) 녹화가 수업 종료 후에도 recording이었다. 이전 턴의 운영 조회에서 2907은 완성 파일 대신 재생 가능한 2,350,370바이트 임시본(.snap), 2909는 파일 키·크기·종료 시각이 없는 행이었다. 중간 2908은 completed였다. 종료 요청 누락의 직접 계기(탭 종료·통신 오류 등)는 확인하지 못했다.

코드 확인: 파트 없는 기록은 12시간을 기다렸다. 완성 객체가 있어도 상태 수정을 건너뛰었고, 6시간 후 야간 정리가 임시본과 파트를 확인하지 않고 실패로 내려 복구 대상에서 빼기도 했다. 관리자는 recording을 곧바로 수업 중으로 표시했다.

## 수정

- 실제 녹화 중지와 pagehide에 기존 /stop으로 종료 힌트를 전송한다. cancel 가능한 beforeunload에는 새 힌트를 보내지 않는다. complete fetch는 keepalive를 쓴다.
- 종료 힌트와 마지막 업로드 이후 5분 무활동이면 기존 15분 cron에서 복구한다. 종료 힌트 없는 구 클라이언트는 시작 4시간 + 업로드 30분 무활동 보호선을 유지한다. 처리량·cron 지연·저장소 오류에 따라 더 늦어질 수 있다.
- 완성 객체 확인, multipart 재완료, 임시본 복구, 빈 행 정리를 구분한다. 저장소 오류는 보류하고, multipart 실패 시 복구 장부를 유지한다. 야간 정리는 복구 가능한 기록을 남긴다.
- 임시본 승격은 If-None-Match 조건부 쓰기로 정상 저장을 덮지 않는다. r2_snapshot으로 표시하고 길이는 NULL로 남긴다. 부분 영상을 multipart 성공의 증거로 삼지 않는다.
- 관리자 표시: 저장 마무리 중 / 종료 확인 필요 / 임시본 복구·부분 영상. 미완료 행이 있는 표를 보는 동안만 60초마다 갱신한다.
- HTML 세 곳은 수정된 JS의 캐시 버전만 변경한다. DB 스키마, DO, cron, 배포 설정은 변경하지 않는다.

## 검증과 상태

- 실제 TypeScript 핸들러 + 메모리 SQLite + 가짜 R2: 22개 시나리오 통과. 진행 중 업로드, 임시본/정상 완료 경합, 늦은 파트, 저장소 오류, 재시도, 종료 힌트 키 대조 포함.
- 종료 판정 54개, 상태 문구 53개, 녹화 정체 보호선, 자산 버전, TypeScript 검사 통과.
- 전체 fast 하니스와 PR CI 결과는 PR에 기록한다. 운영 DB에 테스트 쓰기는 하지 않는다.
- 첫 수정본은 코드 게시 자동 승인 검토에서 막혔다. 사용자가 이 저장소 게시·검사 후 배포를 명시적으로 승인했다. 그 사이 환경 자동 정리로 로컬 커밋이 사라져 최신 main에 재구현하고 재검증했다. 이전 로컬 커밋과 동일한 파일이라고 주장하지 않는다.
- 이 문서 작성 시점에는 배포 전이다. 배포 여부는 GitHub Actions 결과 및 공개 자산에서 별도로 확인한다.

## 택하지 않은 방법

base Worker cron에서 DO 접속자로 수업 종료를 판정하지 않았다. prod와 네임스페이스가 달라 실제 수업도 빈 방으로 오판할 수 있다. 모든 기록을 짧은 시간만으로 강제 종료하거나, 파일 확인 없이 완료로 바꾸지도 않았다. 복구 임시본이 전체 수업을 담는다고 약속하지 않는다.
