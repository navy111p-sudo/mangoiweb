## 1. 왜 했나

사장님 제보(그대로):

> 「게임을하면 내가 얼만큼 더해야하는지 얼마나 남았는지 시각적으로 보이면 좋겠어요.
>  무작정 언제까지 해야 끝나는지 모르니 몇번하다가 나가게돼요.」

A안은 `/today.html`(오늘의 A.i 학습)에 도구마다 「N / M · 얼마 더」를 붙였고,
B안은 발음에 「하루 5문장」 미션을 붙였습니다. **게임만 목표가 없었습니다** —
`TOOL_GOALS.games.goal` 이 `null` 이었고, 그래서 게임 카드는 오늘 무엇을
얼마나 해야 하는지 **한 글자도 말하지 않았습니다.**

## 2. 🔴 먼저 부딪힌 것 — «판» 으로는 목표를 둘 수 없다

`today-plan.ts` 의 그 `null` 에는 이유가 적혀 있었습니다:

> 「목표를 «3판» 으로 두면 **아무것도 안 하고 세 번 들락날락한 학생이 «달성»** 이 된다」

**[잰 것 — 2026-09-21, D1 `game_sessions` 전수]** 한 판의 중앙값이 40초입니다.
⟹ **그 반론은 지금도 옳습니다.** 단위를 그대로 두고 숫자만 채우는 것은
«빠뜨린 것을 채우는» 일이 아니라 **그 결정을 되돌리는** 일입니다.

✅ 그런데 같은 표에 **`items` 칸(그 판에서 실제로 푼 학습 항목 수)** 이 있습니다.
들락날락한 판은 `items` 가 **0** 이라 한 문제도 안 세어집니다 —
**반론이 그 자리에서 사라집니다.**

⟹ 단위를 **«판» → «문제»** 로 바꾸고 목표를 **5문제**로 두었습니다.

## 7. ⚠️ 이 변경이 바꾸는 «뜻»

- 게임 카드의 숫자가 **«판» 이 아니라 «문제»** 입니다. 그래서
  **「게임을 켰지만 한 문제도 안 푼 날」(실측 35%)이 이제 `0` 으로 읽힙니다** —
  옛 셈법에서는 «몇 판 했다» 로 보이던 날입니다. 고장이 아니라 **사실** 입니다.

**[잰 것 — 2026-09-21, 게스트 제외 전 기간 학생-일 115]** 옛 셈법(모든 행 `COUNT(*)`)과
새 셈법(게임만 `SUM(items)`)을 나란히 놓으면 —

| | 값 |
|---|---|
| 옛 합계 | **685** |
| 새 합계 | **256** |
| 숫자가 줄어드는 날 | **102** |
| 오히려 늘어나는 날 | **13** (한 판에서 여러 문제를 푸는 게임) |

⟹ 절반 아래로 내려갑니다. **부풀어 있던 것이 사실대로 내려간 것**이고
(대부분은 학습 도구가 게임으로 세어지던 분 + 들락날락한 판), 사장님께
「게임 숫자가 왜 줄었는지」를 먼저 말씀드려야 하는 자리입니다.
- `/today.html` 의 games 줄도 같은 값으로 바뀝니다(정본이 하나라 저절로 따라갑니다).

## 9. 🪤 만들다가 밟은 함정 (전부 CLAUDE.md 2장에 넣었습니다)

### 9-1. `display:none` 을 CSS 기본값으로 두면 `el.hidden = false` 로 못 엽니다

`#gm-today{display:none}` + `el.hidden=false` 로 짰더니 **세 폭 모두 칸 0px · 채움 0px**
이었습니다. `hidden` 을 떼도 작성자 CSS 의 `display:none` 이 그대로 이깁니다.
✅ 기본값을 `display:block` 으로 두고 **`[hidden]{display:none!important}`** 를 짝으로.
⚠️ 자동 하니스는 이걸 **원리상 못 봅니다** — 브라우저 검사가 잡았습니다.

### 9-2. 브라우저 하니스의 `localStorage` 가 회차 사이에 넘어갑니다

같은 크로미움 프로필이라 앞 회차의 로그인이 남아, 「로그인 안 함」·「토큰 없음」
시나리오가 **앞 회차의 로그인을 물려받아** 조용히 헛돌았습니다.
✅ 회차마다 `mangoi_logged_user`·`mango_user`·`mango_token` 을 **명시적으로 지우세요**.

### 9-3. 게스트 게이트를 «null 인가» 로만 물으면 검사가 헛돕니다

```js
await M.gameItemsToday({}, 'guest') === null   // ← 게이트를 지워도 통과
```
`{}` 를 넘기면 `env.DB.prepare` 가 던져 `catch` 가 **어차피 null** 을 줍니다.
⟹ **변이 Ⓜ 이 0건으로 통과했습니다.**
✅ «조회까지 갔는가» 를 스파이로 재고 **«안 간다 / 간다» 를 짝으로** 두세요.

### 9-4. 새 `IN (?,?,…)` 목록은 `d1_bind_limit_harness` 가 잡습니다

처음엔 `game NOT IN (${marks})` 였는데 그 하니스가 FAIL 을 냈습니다(D1 바인드 100개 한도).
✅ **콤마 문자열 한 개 + `instr`** 로 바꿨습니다(조직 스코프 조회와 같은 방식).
⚠️ `game` 이 NULL 인 행은 `COALESCE(game,'other')` 로 «모를 때» 취급 — 게임이 아닙니다.

### 9-5. 단위를 바꾸면 «옛 경계를 못 박은 검사» 가 깨집니다

`today_goal_harness` 의 세 줄(「games.goal 은 null 이다」·「게임은 아무리 해도
달성이라 말하지 않는다」·「목표 없는 도구는 한 번이라도면 완료」)이 한꺼번에 빨간불이
났습니다. **검사가 헛돈 것이 아니라 그 검사가 지키던 전제를 사람이 바꾼 것**입니다.
✅ 느슨하게 풀지 말고 **새 경계로 옮겨 적었습니다** —
「목표가 있다」 + **「⛔ 단위가 «판» 으로 되돌아가지 않았다」** 짝,
그리고 「⛔ «목표가 없으면 한 번이라도» 갈래가 정본에 그대로 남아 있다」
(표의 도구 아홉이 전부 목표를 가지게 되어 그 갈래가 `buildTodayPlan` 으로는
더 안 닿지만, **표에 없는 새 도구가 그리로 떨어지므로 지우면 안 됩니다**).
옛 단정을 왜 버렸는지 날짜와 함께 하니스 머리말에 남겼습니다.

### 9-6. 🔴 「배선했다」와 「닿는다」는 다릅니다 — 🌐 다시 그리기가 죽은 줄이었습니다

처음엔 이렇게 썼습니다:

```js
/* ⚠️ 이 화면의 발행처는 window 다(js/mango-i18n.js). 관리자 화면(document)과 다르다. */
window.addEventListener('mangoi:lang-changed', ...);
```

**그 주석은 거짓이었습니다.** 재 보니 게임 허브는 —

- `js/mango-i18n.js` 를 **안 실습니다**(⟹ `window.getLang` 도 없습니다)
- `js/i18n-sweep.js` 는 `<html lang>` 변화만 보고 **그 행사를 쓰지 않습니다**
- 이 화면의 토글은 자기 함수 `toggleSiteLang()` 이 저장값과 `<html lang>` 만 바꿉니다

⟹ 제 배선은 **한 번도 안 불리는 줄**이었고, 학생이 🌐 를 누르면
그 줄만 **옛 언어로 남습니다**(사전이 전체 문자열 일치라 `i18n-sweep` 도 못 고칩니다).

⚠️ **제 하니스가 그것을 못 봤습니다** — 「`mangoi:lang-changed` 를 듣는 줄이 있는가」로
물었기 때문입니다. 줄은 «있고» 발행만 없습니다.

✅ 고침 — **그 화면의 토글을 밖에서 감쌉니다**(인라인 `onclick` 은 언제나 `window` 에서
이름을 찾으므로 `window.toggleSiteLang` 을 대체하면 그대로 걸립니다).
⛔ 원래 토글을 **반드시 먼저 부릅니다** — 안 부르면 사이트 언어가 통째로 죽습니다.
⛔ `<html lang>` 을 상주 MutationObserver 로 지켜보는 방식은 쓰지 않았습니다(홈을 멈게 한 전력).

✅ 검사도 같이 바꿨습니다 — 자동 하니스에 **「이 화면은 그것을 발행하지 않는다」를
전제 검사**로 박고, 브라우저 검사가 **🌐 버튼을 진짜 좌표로 눌러** 글자가 바뀌는지 재게 했습니다
(감싸기를 지우면 실제로 **2건 FAIL**).
