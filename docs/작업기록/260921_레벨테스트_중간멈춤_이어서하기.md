# AI 자동 진단 — 중간 멈춤 · 이어서 하기 · 2026-09-21

> AI level test — pause & resume (progress survives a phone call)

## 1. 왜 했나 / Why

사장님 제보:

> AI 학습하기에서 AI와 레벨테스트 하기 24문항 중에 **14문제 풀고(약 7분) 전화가 와서
> 전화받고 다시 돌아오니 약 7분간 문제풀었던게 초기화되어 처음부터 다시 시작해야됨.**
> "중간 멈춤" 기능이 있었으면 함

## 2. 원인 / Root cause

**진행 상태가 그 화면의 JS 변수에만 있었습니다.** `level-test-ai.html` 의
`var questions = [], answers = {}, idx = 0;` 이 전부였고 어디에도 안 적혔습니다.

폰은 **전화·앱 전환만으로도 탭을 버립니다.** 돌아오면 페이지가 새로 로드되고
그 세 변수는 초깃값이라 «처음부터» 가 됩니다.

⚠️ **에러가 안 납니다.** 화면도 코드도 정상이고 틀린 것은 «남는가» 하나뿐이라,
수리 전에도 이 화면을 물고 있던 하니스 3종(`leveltest_my_page`·`student_ai_onboarding`·
`teacher_page_problem_260813`)이 전부 초록이었습니다.

## 3. 무엇을 바꿨나 / What changed

`cloudflare-deploy/public/level-test-ai.html` 한 파일입니다(서버 변경 0줄).

| 무엇 | 내용 |
|---|---|
| **자동 저장** | 답을 «고르는 즉시» `localStorage['mangoi_leveltest_ai_progress']` 에 적습니다. 넘어가기 **전**에 적어 마지막 한 문항이 안 날아갑니다 |
| **이어서 하기** | 시작 화면에 «⏸ 풀던 진단이 있어요 — 14 / 24 문항 · 오늘 오후 12:17에 저장됨» + [▶ 이어서 하기] [🔄 처음부터]. 이름도 되살아납니다 |
| **⏸ 잠시 멈추기** | 문항 화면의 버튼 → «여기까지 저장했어요 · 14 / 24 문항» 화면 → [▶ 이어서 풀기] / [← 나중에 하기] |
| **화면이 말하게** | 시작 화면 «중간에 멈춰도 괜찮아요», 문항 화면 «푼 문항은 자동으로 저장돼요 · 전화를 받거나 앱을 닫아도 이어서 풀 수 있어요» |
| **채점 실패 복구** | 24문항을 다 풀고 채점이 실패해도 답이 남아, 이어서 하기가 **문항을 다시 풀리지 않고 채점만 다시** 합니다 |

**저장 모양** — `{ v:1, name, answers:{a1_1:0,…}, done, total, ts }`

## 4. 왜 그렇게 했나 / Decisions

- **문항 «번호»(idx)가 아니라 «id»(a1_1…)로 저장** — 서버 문항은행(`CEFR_BANK`)이
  바뀌면 번호로 되살릴 때 **남의 답이 엉뚱한 문항에 붙는데 에러가 안 납니다.**
  되살릴 때 지금 받은 문항에 없는 id 는 버립니다.
- **답이 `0`(A번)인 경우** — `firstUnanswered`·`countDone` 을 `== null` 로 판정합니다.
  falsy 로 보면 **A번을 고른 문항이 «안 푼 것»** 이 됩니다(하니스 변이시험으로 확인).
- **보관기간 24시간** — 5분짜리 시험이라 하루 지난 답과 오늘 답을 섞느니 새로 푸는 쪽이
  정확하고, 그 점수가 `students_erp.level` 로 들어갑니다. ⛔ 소리 없이 지우지 않고
  **언제 저장한 것인지 화면에 적어** 사람이 고르게 합니다.
- **저장본은 «결과가 확인된 뒤에만» 지웁니다** — 제출 전에 지우면 채점 실패에 24문항이
  통째로 날아갑니다(하필 다시 채점해야 할 때).
- **저장본이 있으면 큰 버튼이 «처음부터 새로 하기» 로 바뀝니다** — «진단 시작하기» 로
  남아 있으면 눌러서 날립니다. 그래도 한 번 더 되묻습니다.

## 5. 덤으로 고친 것 / Fixed along the way

🔴 **채점 오류가 «결과» 로 통과하고 있었습니다.** `finish()` 가
`.then(showResult).catch(...)` 뿐이라, **`fetch` 는 HTTP 500 에 reject 하지 않으므로**
서버 오류 응답이 그대로 결과 화면에 흘러 «—» 만 찍힌 채 «끝» 으로 보였습니다.
그대로 두면 제 `clearSaved()` 가 그 자리에서 24문항을 지웁니다.
→ **«성공이라고 말했는가»(`d.ok === true && d.level`)로 가릅니다**(CLAUDE.md 2장).

## 6. 검토했다가 버린 것 / Rejected

- **`sessionStorage`** — 탭이 버려지면 같이 사라집니다. 고치려던 그 경우입니다.
- **서버에 중간 저장** — 이 화면은 **로그인 없이도** 씁니다(uid 가 없을 수 있습니다).
  새 API 는 `src/index.ts`(공동 금지구역) 관문 셋을 건드려야 하고, 얻는 것은 «기기를
  바꿔도 이어짐» 뿐인데 제보는 «같은 폰에서 돌아왔다» 입니다.
- **중간까지만 제출해 부분 채점** — 서버 채점은 없는 답을 «틀림» 으로 세므로
  14문항만 제출하면 **점수가 깎입니다.** 다 푼 뒤에만 제출합니다.
- **`beforeunload` 로 «나가시겠습니까?»** — 전화는 막을 수 없고, 폰에서는 안 뜨거나
  무시됩니다. 막는 것이 아니라 **남게** 하는 것이 답입니다.
- **자동 저장만 하고 버튼은 안 만들기** — 사장님이 요청한 것이 «중간 멈춤» 이고,
  버튼이 없으면 학생이 «나가면 날아간다» 고 여겨 전화도 못 받습니다. 화면이 말해야 합니다.
