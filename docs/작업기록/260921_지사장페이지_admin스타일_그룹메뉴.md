# 지사장 페이지(manager.html)를 admin.html 스타일 + 그룹 메뉴로

- 날짜: 2026-09-21
- 작업자: Claude Code
- 브랜치 / PR: `claude/jolly-gauss-k8qenf` (PR 없음 — 사용자가 요청하지 않음)

## 1. 왜 했나

사장님이 스크린샷 3장을 보내며:

> "지사장 페이지가 기존 lms와 너무 달라. 현재 mango.ai 관리자 페이지의 기능들을
> 지사페이지에도 구성해줘."
> "전체적인 디자인은 현재 mangoi.ai 총괄관리자와 동일하게 만들어줘."

보낸 스크린샷: ① 지금의 `manager.html`(가벼운 카드 나열형) ② 옛 LMS(`mangoi.co.kr/lms`)의
햄버거(☰) 서랍 메뉴 — KR/PH 시계 + 「가맹점 관리·학생관리·수강신청관리·수업 관리·
정산통계관리·운영관리」 6분류.

즉 두 가지를 동시에 요구: (a) 옛 LMS 같은 그룹 서랍 메뉴로 기능을 «더 많이» 보이게,
(b) 동시에 시각 디자인은 `admin.html`(아이보리 배경 + 호박색 강조)과 «똑같이».

## 2. 무엇을 바꿨나

파일 하나만: `cloudflare-deploy/public/manager.html`

- **CSS**: `admin.html`(`css/adm-light-theme.css`)의 아이보리 배경·호박색 강조 색값을
  **그대로 복사해 인라인**으로 넣었다(`<link>` 로 부르지 않음 — 이 화면의 "외부 리소스 0개"
  설계 계약을 지키기 위해).
- **사이드바**: `#sideOverlay` + `<nav id="side">` — 옛 LMS 의 6분류를 이 포털이 실제로
  쓸 수 있는 기능으로 재구성해 그룹핑. `openSide()`/`closeSide()`/`sideGo(id)` 세 함수로
  열고 닫고, 카드로 스크롤(기존 `openCard()` 재사용).
- **새 카드 3개** — 전부 서버가 지사·대리점에게 **이미 열어 준**(`isAgencyAllowedApi`
  화이트리스트) 주소만 썼다. 서버 코드는 한 줄도 안 바꿨다.
  - `c-org` (🏢 가맹점 · 대리점 명부) — `GET /api/admin/franchises` + `/centers`
  - `c-attn` (📋 학원별 출석 현황) — `GET /api/admin/attendance/school-stats`
  - `c-settle` (💰 지사 · 대리점별 정산) — `GET /api/admin/settlement/branch-summary`
    (수수료율을 바꾸는 `/rate-config` POST 는 넣지 않음 — 그건 본사 전용 설정)
- **카드 재배치** — `c-today`(오늘 전체 수업)·`c-util`(강사 가동률)·`c-search`·`c-me` 를
  "본사 매니저 전용"(`#hqCards`) 칸 **밖으로** 옮겼다. 이 넷의 API 는 원래부터
  `scopeStudentCond()` 등으로 자기 범위만 잘라 주던 것들이라 지사·대리점에게 보여도 안전.
- **`IS_HQ` 플래그** 신설 — `paintMonth()` 가 `exec/summary` 응답의 `scope.type` 을 받으면
  세팅. 「교재 미배정 ▸」 배지(눌러서 배정 창을 여는 것)는 `IS_HQ` 일 때만 클릭 가능하게
  했다 — 그 창이 쓰는 `/api/admin/textbook-files` 는 지사·대리점 허용목록에 없어서,
  안 가리면 지사장이 눌러도 403 인 "안 맞는 옷"이 된다(교재 이름 자체는 모두에게 보임).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **admin.html 의 `CARD_POLICY`(카드 등급)를 그대로 참고할까 했다가 버림.**
  `CARD_POLICY` 가 'agency'/'branch' 에 보이는 것으로 표시한 카드 중 일부
  (`card-enrollments`·`card-level-tests`·`card-community`·`card-textbooks`·
  `card-data-export`·`card-recording-storage`)는 실제로 `isAgencyAllowedApi()`
  화이트리스트에 없다 — 즉 admin.html 자체에 "보이는데 누르면 403" 인 잠복 버그가
  있다는 뜻. 프론트엔드 등급 표시는 신뢰하지 않고, **서버 소스(`index.ts`)의
  화이트리스트를 직접 읽어서만** 새 기능을 골랐다.

- **`/api/active-rooms`(지금 진행 중인 수업, `c-live`) 를 일반 카드로 옮길까 했다가 버림.**
  `c-today` 등과 마찬가지로 hq 전용 칸 안에 있어서 똑같이 취급하려 했으나,
  `handleActiveRooms()` 소스를 직접 읽어 보니 **franchise 스코프 없이 회사 전체 방
  목록을 그대로 준다.** 옮기면 지사장 화면에 남의 지사 방 번호·인원이 샌다 —
  본사 전용에 그대로 뒀다.

- **옛 LMS 의 「수강신청관리」·「운영관리」(강사 계정 관리·회계 지출 등) 처리 기능은
  넣지 않았다.** 서버가 지사·대리점에게 그 API 를 안 열어 줬으므로, UI 만 만들면
  "눌러도 403" 인 안 맞는 옷이 그대로 재현된다. 이건 서버 권한 모델을 바꿔야 하는
  별도 작업 — 이 화면 안에서 처리할 문제가 아니라고 판단.
