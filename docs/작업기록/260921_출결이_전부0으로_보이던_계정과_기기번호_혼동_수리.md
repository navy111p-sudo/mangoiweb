## 1. 무엇이 문제였나 (한 줄)

`attendance` 의 **`user_id` 는 «접속마다 새로 발급되는 기기 임시번호»**(`u_oqipkl162d`)이고
**계정은 `account_uid`** 라는 다른 칸인데, «학생 한 명» 을 찾는 자리들이 전부
`WHERE user_id = ?` 에 **계정**을 바인딩하고 있었습니다 ⟹ 실측 **0건**.

에러가 안 나고 «0건» 이 정상값처럼 보여, 화면은 「출석 0일 · 출석률 0%」라고 말했습니다
(실제로는 최근 30일 **23일 · 108세션**).

**왜 몇 달 동안 아무도 몰랐나** — 카페24가 «예약» 을 `attendance` 에 미리 만들어 두는데
그 씨앗 행은 `user_id` 가 «계정» 입니다. 그래서 카페24 학생은 «채워져» 보였고,
카페24에 없는 학생(`jeong`)만 통째로 비어 보였습니다.

| [잰 것 — 2026-09-21, `attendance` 전체 180,885행] | 행 수 | 그중 실제 접속 |
|---|---|---|
| 계정형 `user_id` + `c24-` 방 (카페24 예약 씨앗) | **177,461** | **0** |
| 기기번호 `user_id` + `class-` 방 (망고아이 화상수업) | 439 | 432 |

⚠️ 씨앗의 `status` 는 **`present` 11.9만 · `scheduled` 5.8만** 이라
`status <> 'scheduled'` 필터로는 **안 걸러집니다.**

## 2. 고친 것

### 2-1. 정본 하나로 모음 — `src/attendance-uid.ts` (새 파일)

```
ATTENDANCE_BY_UID        = (account_uid = ? OR user_id = ?)
ATTENDANCE_BY_UID_NOCASE = (account_uid = ? COLLATE NOCASE OR user_id = ? COLLATE NOCASE)
attUidBinds(uid)         = [uid, uid]
ensureAttendanceAccountUid(env)  // 칸·인덱스 멱등 보장
```

⛔ **«바꾸기» 가 아니라 «넓히기»** 입니다 — `account_uid` 만 보게 바꾸면
카페24 학생 화면이 **통째로 비어 지금보다 나빠집니다**(그 행에는 그 칸이 없습니다).

### 2-3. 인덱스 — 없으면 풀스캔입니다

[잰 것] `account_uid` 에 인덱스가 없어 그 OR 이 `EXPLAIN` 에서 **SCAN** 으로 떨어졌고
단순 조회 한 번이 **rows_read 180,885** 였습니다. 날짜 범위가 붙은 쿼리는
`joined_at` 인덱스가 잘라 줘 **4,417행 · 5.3ms** 로 괜찮지만, «전체 기간» 을 세는
자리(총 세션 수 · 배지)는 범위가 없어 그대로 풀스캔입니다.

⟹ 정본이 **`idx_attendance_account_date`** 를 멱등 생성합니다(배포되면 저절로).
⛔ 지우지 마세요.

### 2-4. 화면이 «모르는 것» 을 0 으로 말하지 않게 — `admin/student.html`

### 🪤 그 전수 검사가 «세 번» 뚫렸습니다 — 셋 다 «범위를 어떻게 자르는가»

| 방식 | 왜 뚫렸나 |
|---|---|
| 정규식 `` /`[^`]*`/ `` | 파일 중간의 큰 HTML 템플릿(`${}` 안에 또 따옴표)에서 짝이 한 번 밀려 **그 뒤가 통째로 안 보임** |
| 줄 창 `slice(i-3, i+8)` | **옆 줄이 정본을 쓰면 그 줄에 가려** 새 실수를 놓침 |
| 파일 첫 글자부터 문자열 수집 | 위와 같은 이유로 밀림 |

✅ 남은 방식 — **「FROM attendance」 자리마다 «가장 가까운 백틱까지» 좌우로 넓히기**(`sqlAt`).
밀림과 무관하고 SQL 안의 `'c24-%'` 도 안 잘립니다.

### 🪤 그 밖에 검사가 스스로 헛돌던 것 둘

- **ALLOW 를 «파일 단위» 로 두면** 그 파일의 «새» 실수를 전부 통과시킵니다
  (변이 Ⓔ 가 실제로 그렇게 뚫렸습니다) → **«그 SQL 의 지문» 으로** 좁혔습니다.
- **변이가 «크래시» 가 되면 ❌ 0건으로 위장합니다** — 조건의 `?` 개수를 바꾸는 변이는
  prepare 가 던져 결과줄조차 안 나옵니다 → 돌리는 자리를 `try` 로 감싸 «깔끔한 FAIL» 로
  바꾸고, 변이시험은 **❌ 개수와 종료코드를 «함께»** 보게 했습니다.
