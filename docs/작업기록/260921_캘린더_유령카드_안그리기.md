# 학생 상세 캘린더 — 「신청만 있고 실제 수업은 없는」 수강신청을 **안 그린다**

- **날짜**: 2026-09-21
- **지시**: 사장님 — (9/25 금 14:20 「체험수업」 카드를 빨간 동그라미·가위표로 표시한 화면과 함께)
  **「체험수업이 없는데 나오는 것은 안돼. 캘런더에 나오지 않게 해줘」**
- **앞 판**: PR #1059 — 같은 카드를 «회색으로 낮추고 사실을 적기»

---

## 1. 왜 했나 — 같은 자리를 하루에 두 번 정했습니다

9/21 오전에 PR #1059 로 그 유령 카드를 **회색 + 「신청만 · 수업 없음」** 으로 바꿨습니다.
그때 고른 이유는 「감추면 **신청서와 실제 수업이 어긋났다**는 것을 아무도 못 본다」였고,
그 문장을 CLAUDE.md 에 **⛔ 감추지 마세요** 로 박아 두었습니다.

사장님이 그 화면을 보시고 뒤집으셨습니다 — 회색이든 무슨 색이든 **없는 수업이 캘린더에
있는 것 자체가 안 된다**는 것입니다.

⟹ 이것은 「검사가 헛돈 것」이 아니라 **사람이 결정을 바꾼 것**입니다. 그래서 옛 경계를
«느슨하게 푼» 것이 아니라 **새 경계로 옮겨 적었습니다**(아래 5장).

## 3. 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| **그냥 감추기만 하기** | 「신청서와 수업이 어긋났다」가 화면에서 통째로 사라집니다. 앞 판이 지키려던 값이라, 카드 대신 **한 줄**로 남겼습니다 |
| 건수를 «날짜» 로 세기 | 한 신청이 9월 금요일 세 번(11·18·25)에 걸리면 **「3건」** 이 됩니다. 신청 id 로 세어 «1건» |

| 안내 줄에 밝은 글자(`#cbd5e1`) | 이 화면은 `adm-light-theme.css` 로 **밝은 테마**라 대비 **1.36** — 안 읽힙니다(아래 4장) |

## 4. 밟을 뻔한 함정 — 밝은 테마인데 어두운 줄 알았습니다

이 화면의 패널은 인라인 style 이 어둡게 적혀 있어(`rgba(15,23,42,0.5)` 류) 어두운 화면으로
보입니다. 그런데 220행이 `adm-light-theme.css` 를 싣고, 그것이 `!important` 로 밝게 덮습니다.

처음에 안내 줄을 `color:#cbd5e1` 로 줬는데 실측 대비가 **1.36** 이었습니다
(`#475467` + 배경 `#f1f5f9` 로 고쳐 **7.02**).

⚠️ 그대로 나갔으면 「안내를 넣었다」는 기록만 남고 **아무도 못 읽는** 상태가 됩니다.

### 🪤 기준선을 한 번 틀리게 쟀습니다

처음에 `git worktree add --detach … origin/main` 으로 기준선을 만들었는데, **로컬
`origin/main` ref 가 낡아** 어제 만든 하니스 파일이 그 사본에 없었고, 그래서 멀쩡한
환경 사유 FAIL 하나가 **「내가 새로 만든 FAIL」** 로 보였습니다.
`git fetch origin main` 뒤 `HEAD` 로 다시 만들어 대조했습니다.
(CLAUDE.md 「fetch 먼저, 기준은 merge-base」와 같은 뿌리)

## 7. 남은 것 — 사람이 정할 일

- 이 판정은 **「아직 수업이 안 만들어진 신청」도 «수업 없음»** 으로 봅니다. 화면이 하는 말이
  「신청만 있고 수업이 없다」라서 그 경우에도 사실이지만, 확정 직후 잠깐 그렇게 보일 수 있습니다.
- 어긋난 신청을 **고치는 길**(신청을 닫거나 수업을 다시 만드는)은 이 화면에 없습니다 —
  지금은 **「📝 등록·수강」 탭**에서 사람이 봅니다(⚠️ 「🧾 수강신청 이력」은 **다른 표**입니다 — 카페24 ClassOrders 이고 📋 평가서 탭 안이며 없을 수도 있습니다. 처음에 안내 문구가 그쪽을 가리켜 함정 대조가 잡았습니다).
