# 낱말 사진 — 「단어와 그림이 상관없다」 전수 수리 (2026-09-22)

## 1. 제보

사장님이 장면 탐험 낱말 카드 세 장을 보내며 **「실사이미지들과 단어들이 연관성이 없어.
이런 것들 모두 너가 수정해 줄 수 있어??」**

| 낱말 | 화면에 뜬 사진 | 교재 예문 |
|---|---|---|
| `name` | 글자 없는 **빈** 금속 명패 | Let me introduce myself. My name is Tom. |
| `english` | 그냥 교실(강사 + 학생 둘) | We have English class tomorrow. |
| `clearly` | 창밖 나무가 보이는 창문 | He explains everything clearly. |

## 2. 까닭 — 게이트가 「그 낱말이 설명에 있는가」만 묻습니다

근거 정본(`scripts/scene-picture-evidence.mjs`)은 **사진을 볼 수 없습니다.** 볼 수 있는 것은
«그 사진을 만들 때 쓴 지시문» 뿐이라, 물을 수 있는 것도 「그 지시문이 이 낱말을 «글자로»
담았는가」까지입니다. 그런데 프롬프트를 **낱말만 보고** 썼으니 모델이 «가장 흔한 뜻» 을
그렸고, 게이트는 그것을 **정직하게** 통과시켰습니다.

⟹ **에러도 없고, 타입체크·회귀 하니스도 전부 초록입니다.** 사람이 화면을 봐야만 드러납니다.

## 3. 잰 것 — 표 3,229개 전수 대조

교재 예문과 대조해 **400개(12.4%)가 어긋났습니다.**

| 형태 | 보기 |
|---|---|
| 다의어의 다른 뜻 | `treats` 간식→**치료한다** · `nails` 못→**손톱** · `theme` 주제→**놀이공원** · `stock` 재고→주식 · `transmission` 감염전파→변속기 |
| 고유명사를 일반명사로 | `tiger`·`woods` = Tiger Woods · `graham` = Graham Bell · `prejudice`·`pride` = 소설 |
| 품사 뒤바뀜 | `showcase` · `breed` · `produce` |
| 추상어를 글자대로 | `reflection`(성찰→물에 비친 모습) · `weakness` · `vision` |
| **«없는 것» 을 그림** | `name` 빈 명패 · `anyone` 빈 책상 — 뜻이 **정반대** |

**399개를 다시 만들었습니다.** `clear` 하나만 구조적으로 불가 — 프롬프트 틀의
「Clear recognizable subjects」에서 오는 **껍데기 낱말**이라 게이트가 근거에서 뺍니다
(README 의 «못 채우는 넷» 가운데 하나).

### 🔴 그 전수 대조가 «사장님이 보기로 든 `name`» 을 놓쳤습니다

위 표에 형태로 적어 놓고도 `name`(13125)은 **400 안에 없었습니다.** 그래서 399 를 고쳐
배포한 뒤에도 그 낱말은 **빈 명패 그대로**였고, 사장님이 시키는 대로 열면 **신고한 화면이
그대로** 나왔습니다. 2026-09-22 뒤늦게 손으로 찾아 **401번째로** 고쳤습니다
(「자기소개하며 이름을 말하는 아이」 — 예문 `Let me introduce myself. My name is Tom.`).

⟹ **400 은 «바닥» 이지 «전부» 가 아닙니다.** ⛔ 「전수로 다 고쳤다」고 적지 마세요.
✅ 기계로 훑히는 형태 하나(«빈·없는» 모양 — `blank|empty|bare|no one` 로 넓히면 **87건**)는
눈으로 전수 확인했고 **뜻이 뒤집힌 것은 `name` 하나**였습니다(나머지는 `bare foot`·
「빈 좌석이 있는 영화관」처럼 멀쩡해서, 게이트로 걸면 86건이 거짓 FAIL 입니다).
나머지 네 형태는 훑을 기계가 없습니다 — 제보가 오면 그 낱말부터 보세요.

## 4. 그 교체가 만든 두 번째 사고 — 빌려 쓰던 낱말 14개가 카드로 내려감

사진 한 장은 «그 사진이 실제로 보여 주는» 여러 낱말에 붙습니다(rank 0 = 자기 전용,
rank 1 = 남의 사진을 빌림). 399장을 갈아 끼우자 **rank 1 로 붙어 있던 낱말 14개**가
근거를 잃었습니다 — 옛 프롬프트가 **우연히** 그 낱말을 담고 있던 것입니다.

```
카드 줄 25 → 39 · 사진 붙은 낱말 4,543 → 4,529
dog's touches skateboard shovel joke entertaining treats
prizes theme electronics canopy north historic nails
```

🔴 **기존 검사는 이것을 원리상 못 봅니다** — 「근거가 있는데 카드면 FAIL」만 보는데
여기서는 근거가 **통째로 사라졌습니다.** 잡아 준 것은 **manifest 대조** 하나뿐이었습니다
(CLAUDE.md 2026-09-21 밤 줄: 「개수만 보면 어느 낱말이 내려갔는지 모릅니다」 — 실제로 일했습니다).

✅ 전용 사진 14장을 새로 만들어 되돌렸습니다. 되돌린 뒤 **manifest 스칼라 칸이
`maxBookBytes`·`maxBookGzipBytes`·`imageAssets` 말고 전부 이전과 같고**, payload 를
낱말 단위로 대조해 **내려간 낱말 0 · 올라온 낱말 0** 입니다.

⚠️ `north` 는 예문이 “North Korea is a mysterious country…” 지만 **나라를 그리지 않고
«방위 북쪽»(나침반)** 으로 두었습니다 — 정치적 소재를 실사로 그리는 것을 피한 판단입니다.

⚠️ 157개 낱말이 «다른 사진» 으로 옮겼습니다(전부 근거 게이트 통과). 낱말 수는 그대로이고
어느 후보를 고르는지만 바뀐 것입니다.

## 5. 검사 — 무엇을 막을 수 있고 무엇을 못 막나

### ⛔ 못 막는 것 — 「예문 뜻인가」

두 신호를 재 보았고 **둘 다 게이트가 못 됩니다.**

| 신호 | 옛 프롬프트 | 새 프롬프트 | 표 전체 | 판정 |
|---|---|---|---|---|
| 「«빈·없는» 모양인가」 | 3/400 | 1/400 | 15건 | **판별력 없음**(`bare foot`·`bare arm` 이 대부분) |
| 「예문의 내용어를 공유하는가」 | 11/400 | **326/400** | **2,216/3,243 안 겹침(68%)** | 판별은 세지만 전수로 걸면 **거짓 FAIL 2천 건** |

「environmental」 사진이 예문과 낱말을 안 나눠 가져도 그 낱말을 잘 그립니다. ⟹ **절차로
지킵니다** — 프롬프트를 쓰기 전에 그 낱말이 교재에서 쓰인 문장을 읽습니다(**`typeof w.ex === 'number' ? b.examples[w.ex] : b.scenes[w.scene].text`**).
⛔ **뒤엣것만 읽지 마세요** — 예문은 `examples` 배열에 한 번만 담고 낱말 줄에는 번호만
싣습니다. [잰 것] 사진 붙은 낱말 줄 **39,885개 중 39,143개**가 `w.ex` 쪽이라,
`scenes[].text` 만 보면 거의 다 «예문 없음» 으로 보입니다.

### ✅ 막는 것 — 「카드가 늘면 사진이 사라진 것」

`test-harness/scene_curriculum_harness.mjs` 에 **짝으로** 넣었습니다.

```
ok(live.cardRows<=25,          '그림문자 카드 줄이 늘지 않았다')
ok(live.wordPictureForms>=4543,'낱말 사진이 붙은 낱말이 줄지 않았다')
```

**변이 실측** — 14장을 치우고 다시 빌드하면 `39 ≤ 25` 와 `4529 ≥ 4543` 이 **각각** FAIL 이고
하니스 **종료코드 1** 입니다(이 저장소에는 「FAIL 인데 exit 0」 전례가 있어 따로 확인).
짝 없이 카드 상한만 두면 «사진을 빼고 카드도 안 그리기» 가 통과합니다.

⚠️ 그 숫자는 «상한·하한» 이지 «정답» 이 아닙니다. 교재 문장을 더해 새 낱말이 들어오면
정당하게 카드가 늘 수 있고, 그때는 사진을 만들거나 숫자를 올리며 «왜» 를 적습니다.

## 6. 🪤 제 검증이 두 번 헛돌았습니다

1. **`pictureEvidence` 를 `clips:[]` 로 불렀습니다.** 빌드는 `assets.concat(wordAssets)` 와
   `clips` 를 **함께** 넣습니다 — 껍데기(shell)는 «전체 설명을 모아 한 번» 세므로 인자가
   다르면 판정이 달라집니다. **검증은 빌드와 «같은 인자» 로 돌려야 합니다.**
2. **「표의 모든 항목이 통과한다」만 물었습니다.** rank 1 로 빌려 붙는 낱말은 그 검사의
   **범위 밖**이라, 14개가 떨어지는 것을 한 번도 재지 않았습니다.

그리고 한 번은 **0/3,229** 라는 결과가 나왔는데, 그것은 데이터가 아니라 **호출이 틀린**
신호였습니다(키 접두사를 `word-image:` 가 아닌 것으로, `sceneText` 를 Map 이 아닌 것으로).
