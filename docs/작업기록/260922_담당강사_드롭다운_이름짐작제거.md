**날짜** 2026-09-22 · **화면** `admin/student.html` › 📅 스케줄 › ➕ 수업 예약 등록

## 2. 잰 것 — 편의 문제가 아니라 «버그» 였습니다

그 칸은 글자를 그대로 서버에 보내고, 서버가 이렇게 찾습니다(`src/api-admin.ts`):

```sql
SELECT id, name FROM teachers WHERE name = ? OR name LIKE ? LIMIT 1
```

**부분일치 + `LIMIT 1` + `ORDER BY` 없음.** 운영 D1 에서 그대로 돌려 봤습니다
(2026-09-22 · `SELECT` 만):

| 잰 것 | 값 |
|---|---|
| `teachers` 전체 | **30명** (재직 25 · 퇴사 5 · active NULL 0) |
| 서로를 «품는» 이름 쌍 | **1쌍** — `FAR`(id 22, 재직) ⊂ `HT FARRAH`(id 3, **퇴사**) |
| `WHERE name='FAR' OR name LIKE '%FAR%' LIMIT 1` | **→ id 3 · `HT FARRAH` (퇴사)** |

> ⟹ **「FAR」을 «정확히» 쳐도 퇴사 강사가 붙습니다.**
> 규칙서가 2026-08-26 사고(「퇴사 강사가 드롭다운에 그대로 떠서 잘못 이어짐」 —
> 스케줄 16건이 죽은 행에 붙음)로 못 박아 둔 그 쌍이 **아직 살아 있었습니다.**

⚠️ **에러가 안 납니다.** 등록은 «성공» 하고 틀린 것은 «누가 붙었는가» 뿐입니다.

## 3. 고친 것

### ⓐ 화면 — 자유 입력 → 드롭다운 (`admin/student.html`)

* `GET /api/admin/teachers?include_inactive=1` 로 명부를 받아 그립니다.
  * ⚠️ `include_inactive=1` 이라야 **`active` 칸이 내려옵니다.**
    ⛔ 서버에서 걸러 달라고 하지 않았습니다 — 규칙서: **거르는 것은 화면 몫**.
      걸러 버리면 퇴사 강사가 «없는 사람» 이 되어, 이미 그 강사에게 붙은 수업을
      사람이 못 알아봅니다.
* **퇴사 강사는 «기본으로 뺍니다»** — 2026-08-26 사고가 바로 그 목록에서 죽은 행을 고른 것입니다.
  ⛔ 그렇다고 **영영 빼지는 않습니다** — 되돌릴 길(**「퇴사 강사도 보기 (N명)」 체크박스**)을
     화면에 둡니다. 체크하면 `<optgroup>` 「퇴사·비활동」에 **「(퇴사)」** 를 달고 나옵니다.
  ⚠️ **감춘 «명 수» 를 체크박스가 말합니다** — 말없이 빼면 「그 강사가 없다」로 읽힙니다.
     감춘 사람이 0명이면 체크박스 자체를 안 보입니다(잃는 정보가 없습니다).
  ⛔ **`adm-teacher-links.js`(2026-09-09)와 «같은» 방식입니다** — 그 화면도 같은 쌍
     (`FAR`/`HT FARRAH`)을 근거로 그렇게 정해 두었습니다. **두 화면이 서로 다른 말을 하면
     다음 사람이 어느 쪽을 믿을지 모릅니다.** 한쪽만 바꾸지 마세요.
  ⚠️ 그 화면에는 「이미 그 강사에게 «이어진» 계정은 절대 숨기지 않는다」는 예외가 있는데,
     **여기는 «새로 만드는» 폼이라 그 경우가 없습니다** — 예외를 베껴 오지 마세요.
  ⚠️ 다시 그리면 고른 값이 날아갑니다(진짜 `<select>` 는 options 를 갈면 선택이 맨 앞으로
     돌아갑니다) — 아직 목록에 있으면 되돌려 놓습니다.
* `active` 가 **NULL·빈 값이면 «재직»**. `Number(null) === 0` 이라 **null 검사가 먼저**여야 합니다.
  숨기는 쪽으로 실패하면 멀쩡한 강사가 목록에서 조용히 사라집니다(빠지는 쪽이 훨씬 나쁩니다).
* 고른 값은 **`teacher_id`(id)** 로 보냅니다 — 이름을 안 보내므로 위 «짐작» 을 아예 안 탑니다.
  이름(`teacher_name`)도 함께 싣지만 **서버는 id 를 우선**합니다.

**폴백** — 목록을 못 받으면(403·404·통신 오류·빈 목록) **옛 텍스트 칸으로 떨어집니다.**
그때는 서버가 예전처럼 이름으로 찾습니다. 강사 칸이 통째로 막히면 «되던 것» 이 깨집니다.
왜 그런지도 화면이 말합니다(「⚠️ 강사 목록을 못 받아 이름을 직접 입력합니다 (HTTP 403)」).

> ⚠️ 판정은 «실패라고 말했는가» 가 아니라 **«성공이라고 말했는가»**(`r.ok` + `j.ok === true`)
> 로 했습니다 — 404 본문은 `{error:'Not Found'}` 라 `ok` 칸이 없고,
> `j.ok === false` 만 보면 **그냥 통과**합니다(규칙서의 그 함정).

### ⓑ 서버 — id 로 고르면 이름을 «id 로» 되찾습니다 (`src/api-admin.ts`)

옛 코드는 `teacher_id` 를 받으면 `teacherName` 이 **`null` 인 채로 남았습니다.**
그러면 바로 아래의 **일회성 예약 휴가 충돌 검사**(`if (kind === 'one_off' && teacherName)`)가
**통째로 건너뛰어집니다** — 자유 입력 경로는 받던 검사입니다.

```ts
if (teacherId) {
  const t = await env.DB.prepare(`SELECT name FROM teachers WHERE id = ? LIMIT 1`)
    .bind(teacherId).first<any>();
  if (t?.name) teacherName = String(t.name);
} else if (tRaw) {
  /* ⛔ 이 «부분일치 + LIMIT 1» 은 자유 입력 폴백 전용 — 넓히지 말 것 */
}
```

* ⛔ **못 읽었을 때 `body.teacher_name` 으로 떨어뜨리지 않았습니다** —
  화면이 보낸 글자로 «막는» 검사를 돌리는 것이 되고, 그 자리에서는 지금처럼
  «검사 안 함» 이 맞는 실패 방향입니다.
* ⛔ **자유 입력 폴백의 `LIKE` 경로는 그대로 뒀습니다** — 없애면 폴백이 죽습니다.

**새로 «켜지는» 것은 휴가 충돌 검사 하나입니다** — [잰 것 — 2026-09-22]
`calendar_events` 의 `event_type='vacation'` 행이 **0건**이라 **오늘은** 아무 데도 안 닿습니다.

> ⚠️ **「다른 화면에 영향 0」이라고 적지 마세요 — 그건 «오늘» 만 참입니다.**
> 휴가 행은 사람이 넣는 D1 데이터라 아무 날에나 생길 수 있고, 그 순간부터
> **`weekly-schedule.html` 의 일회성(one_off) 등록도** 이 검사를 처음으로 타서
> `409 teacher_unavailable` 로 막힙니다(그 화면은 이미 `teacher_id` 를 보내고 있습니다).
> 그리고 그쪽 `postClassScheduleAsk` 는 **`error === 'conflict'` 일 때만 다시 묻기** 때문에
> **force 로 밀어 넣을 수도 없습니다.** 막히는 것 자체는 «맞는» 동작이지만
> (자유 입력 경로는 원래 받던 검사입니다) **처음 막히는 날 「왜 갑자기?」가 됩니다** —
> 그때 이 줄을 보세요.
