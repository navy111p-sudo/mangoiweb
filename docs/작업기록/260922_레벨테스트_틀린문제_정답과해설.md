## 1. 왜 했나

사장님 **「AI 레벨테스트에서 결과만 나오는데 틀린문제에 대한 해설과 정답이 나왔으면 좋겠음」**.

재 보니 정말로 «한 줄도» 없었습니다 — `/api/leveltest/diagnose` 가 돌려주던 것은
`ai_score` · `level` · `correct` · `total` · `breakdown`(밴드별 막대)뿐이고,
**문항별 결과·정답·해설은 응답에 존재하지 않았습니다.** 24문항을 풀어도 학생이 알 수 있는 것은
「52점 · B1 · 18/24」까지였고, 무엇을 왜 틀렸는지는 알 방법이 없었습니다.
진단만 있고 배움이 없는 상태였습니다.

---

## 2. 🔒 먼저 재야 했던 것 — 정답이 새는 창

`/api/leveltest/questions` 는 정답(`a`)을 **일부러** 숨깁니다. 그 자리 주석이
「변별력·객관성의 핵심: 문항은행과 채점을 서버가 소유(클라이언트 조작 불가)」라고 못 박고 있습니다.
이번 기능은 정확히 **그 반대 방향**이라, 아무 제약 없이 실으면 새 구멍이 생깁니다.

그리고 **이 두 경로는 무인증 공개**입니다(`src/index.ts` 허용목록) —
즉 누구나 부를 수 있습니다. 그대로 두면:

> 답을 **하나도 안 내고** `diagnose` 를 한 번 부르면 24문항 정답이 통째로 온다.

그래서 정본(`src/leveltest-review.ts`)이 **세 겹**으로 좁힙니다.

| 겹 | 무엇을 막나 |
|---|---|
| ① 학생이 **실제로 고른** 문항만 | 「답 없이 호출해 훑기」 |
| ② 그 값이 **보기 범위 안의 정수**일 때만 | 「`99`·`-1`·`1.5`·`'x'` 를 24개 보내 훑기」 |
| ③ **틀린 문항만** | 맞힌 문항의 정답은 본인이 고른 값이라 새 정보가 아님 |

⚠️ **남는 것** — 「24문항을 전부 답하면 그중 틀린 것의 정답은 온다」는 그대로입니다.
**그것이 이 기능 자체**라 막으려면 기능을 없애야 합니다. 대신 «시험을 끝까지 봐야» 하는 비용이
붙었고, 배치 결과는 `applyPlacementLevel` 이 «이미 레벨이 있으면 안 덮는다» 라
재응시로 점수를 올려도 **학습도구 배정은 안 바뀝니다.**

⛔ ①②③ 중 하나라도 풀면 그 창이 도로 넓어집니다 — 하니스가 셋을 **각각** 못 박습니다.

## 3. 고친 것

### 3-1. 서버

- **`src/leveltest-review.ts`(신규)** — 판정 정본.
  `buildLeveltestReview(bank, answers)` 가 위 세 겹을 걸어 «틀린 문항 + 정답 + 해설 + 완성 문장» 을 만듭니다.
  `filledSentence()` 는 빈칸(`___`)을 정답으로 채운 영어 문장을 만들되,
  **빈칸이 없는 문항이면 빈 문자열** 입니다 — 문장을 지어내지 않습니다(실측 빈칸 있음 20 · 없음 4).
- **`CEFR_BANK` 24문항에 한국어 해설(`why`) 추가.** 문법 문항은 규칙을, 어휘 문항은 뜻과 오답 보기의 뜻을 적었습니다.
- **타입을 정본 `LtBankItem` 으로 교체** — ⛔ 모양을 두 곳에 적으면 «해설 칸을 늘렸는데 한쪽만 아는» 상태가 조용히 생깁니다.
- `diagnose` 응답에 `review` 추가. **`try` 로 감쌌습니다** — 해설을 못 만들었다고 채점 결과까지 잃으면 안 됩니다.
- `/api/leveltest/questions` 는 그대로 `a`·`why` 를 **안 싣습니다**(주석으로 이유를 박아 뒀습니다).

⛔ **`src/index.ts` 는 한 줄도 안 건드렸습니다** — 두 경로가 이미 허용목록에 있어 공동 금지구역을 피했습니다.

### 3-2. 화면

결과 카드에 **「📘 틀린 문제 다시 보기」** 섹션. 문항마다:

```
 3번 문항  Level A2
 We ___ finished our homework yet.
    A. didn't
 ✕  B. haven't            내 답        ← 빨강
 ✓  C. don't              정답        ← 초록
    D. aren't
 ✅ We haven't finished our homework yet.
 왜? yet 은 현재완료와 짝이에요 — have/has + not + 과거분사(finished).
```

- 🔴 **CTA(발음 평가·레벨테스트로) «아래»** 에 뒀습니다. 위에 끼우면 틀린 문항이 20개일 때
  그 버튼이 통째로 스크롤 밖으로 밀립니다(CLAUDE.md 「배너를 얹었더니 아래 조작이 스크롤 밖으로」).
  대신 요약 바로 밑에 **「👇 아래에 틀린 N문항의 정답과 해설이 있어요」** 한 줄을 둬 길을 알려 줍니다.
- ✅ 색«만» 으로 뜻을 지지 않습니다 — `✓`/`✕` 기호와 「정답」·「내 답」 꼬리말이 늘 함께 갑니다.
- 0건에는 뜻이 **둘** 입니다(다 맞혔거나, 답을 고른 문항이 없거나) — 한 문장으로 뭉치면
  중간에 멈춘 학생에게 「전부 맞혔다」고 거짓말합니다. `correct === total` 로 갈라 말합니다.
- `review` 가 **없는** 응답(옛 서버·배포 중)에는 **아무것도 안 그립니다** — 0건을 «만점» 으로 읽으면 안 됩니다.

## 4. 검토했다가 버린 것

| 안 한 것 | 왜 |
|---|---|
| 맞힌 문항도 해설 붙이기 | 요청 범위 밖이고, 맞힌 문항의 정답은 본인이 고른 값이라 새 정보가 없습니다. 덤으로 정답 유출 창이 넓어집니다 |
| 해설을 접어 두고 버튼으로 펴기 | 사장님 지시가 「나왔으면 좋겠음」이라 바로 보이는 쪽이 맞습니다. CTA 아래에 둬서 길이 문제를 풀었습니다 |
| 해설을 한/영 두 벌로 | 이 화면은 i18n 엔진(`mango-i18n.js`)을 **안 싣습니다** — `data-ko`/`data-en` 이 무의미하고, 엔진을 새로 싣는 것은 반경이 큽니다. 대신 **문제·보기·완성 문장이 영어(EN)** 이고 **해설이 한국어(KO)** 라 화면에서 자연스럽게 병기됩니다 |
| 해설을 LLM 으로 생성 | 학생이 그대로 배우는 문장입니다. 이 저장소의 반복 실측이 「지시만으로는 안 지켜진다」라 **결정론(손으로 쓴 표)** 이어야 합니다 |
| 화면에서 정답을 계산 | 정답은 `questions` 응답에 애초에 없습니다. 화면은 «그리기만» 합니다 |

### 🪤 검사가 «헛돌던» 것 넷 — 전부 변이시험에서만 드러났습니다

1. **「`renderReview(d)` 가 파일에 있는가」로 호출을 물었더니 «함수 선언» 이 잡혔습니다** —
   호출을 통째로 지운 변이(Ⓛ)가 **그대로 통과**했습니다.
   ✅ `showResult` 몸통을 잘라 «그 안에서» 부르는지 묻고, 「선언은 정확히 하나」를 짝으로 뒀습니다.
   📜 CLAUDE.md 에 이미 두 번 적힌 함정인데 **세 번째로 밟았습니다.**
2. **「그 호출이 `try` 안인가」를 «첫 번째 이름 위치» 로 물었더니 `import` 줄이 잡혔습니다** —
   늘 참이라 아무것도 안 봤습니다. ✅ try 블록을 중괄호 짝으로 잘라 «호출 위치가 그 범위 안인가» 로 고쳤습니다.
3. **중괄호 짝 자르기의 «꺾쇠 세기» 가 HTML 을 조립하는 JS 함수에서 엉뚱한 `{` 를 잡았습니다** —
   `'<div …>'` 문자열 때문에 `<`/`>` 짝이 안 맞아 `r is not defined` 라는 **거짓 실패**가 났습니다.
   ✅ JS 선언에는 반환 타입이 없으니 «선언 뒤 첫 중괄호» 부터 짝만 맞추면 됩니다.
4. **왼쪽 «메뉴» 손잡이 겹침을 안 보고 있었습니다** — 스크린샷에서 눈으로 발견했습니다.
