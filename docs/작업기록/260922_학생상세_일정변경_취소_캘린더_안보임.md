## 2. 잰 것 — 버튼도 서버도 멀쩡했습니다

헤드리스 크로미움에 `admin/student.html` 을 실제로 그려서 눌렀습니다(API 는 스텁).

| 확인 | 결과 |
|---|---|
| 콘솔 에러·예외 | **0건** |
| `openReschedule`·`submitReschedule`·`cancelAiSchedule` 전역 | 셋 다 `function` — 인라인 `onclick` 정상 |
| 📅 일정변경 클릭 | 패널 열림, 값도 정확히 채워짐(`2026-09-23`/`16:00`/`20`) |
| 저장 클릭 | `PATCH /api/admin/class-schedules/9001` **실제로 나감** |

⟹ **「작동 안 한다」의 정체는 버튼이 아니었습니다.** 실제로 틀린 것은 넷이었고
**넷 다 문자열 하니스로는 원리상 못 보는 종류**였습니다(수리 전 `--fast` 가 전부 초록).

## 3. 원인 A — 입력칸이 «흰 바탕에 흰 글자» (대비 1.14)

실행 중 인라인 style 을 읽으니 이렇게 바뀌어 있었습니다:

```
background-color: rgb(244,246,251) !important   ← 누가 밝게 칠함
color: rgb(226,232,240)                          ← 어두운 테마용 «거의 흰색» 그대로
```

`document.styleSheets` 를 훑어 이 요소에 매치되는 CSS 규칙은 **0건** —
즉 CSS 싸움이 아니라 **인라인 `!important` 를 쓰는 페인터**입니다
(CLAUDE.md 의 가르는 법: `getPropertyPriority('color')` 가 비면 CSS, `'important'` 면 페인터).

범인은 `js/adm-light-surfaces.js` 이고, 구조적입니다:

```js
function fixText(el) { if (!el.firstChild) return; ...   // ← void 요소는 여기서 끝
```

- `lightenSurface()` 는 어두운 배경을 흰색으로 **칠하고**
- 짝인 `fixText()` 는 **자식 텍스트 노드가 없는 `<input>`·`<select>` 를 원리상 한 번도 안 봅니다**

⟹ 배경만 희어지고 글자는 `#e2e8f0` 그대로 → **합성 대비 1.14.**
값은 들어 있는데 **화면에 안 보입니다.** 사장님이 가위표를 치신 칸들이 정확히 이것이고,
타이핑해도 글자가 안 보이니 「작동 안 한다」로 읽힙니다.

**고침** — 그 화면 입력칸 6곳의 인라인 값을 밝은 테마 값으로
(`background:#ffffff; color:#101828; border:1px solid #cbd5e1`).

> ⛔ **페인터를 «input 도 보게» 고쳐서 풀지 않았습니다** — 그 파일은 관리자 화면 전체가 싣습니다.
> 반경이 이 화면 밖으로 나가고, 그 파일을 부르는 HTML 의 `?v=` 가 전부 걸립니다.

## 4. 원인 B — 캘린더가 «반복 수업» 을 한 칸도 안 그림

`renderDSchedWeek()` 안:

```js
const dowToIdx = { sun:0, mon:1, tue:2, wed:3, thu:4, fri:5, sat:6 };  // 소문자 3글자만
const i = dowToIdx[dCode];
if (i === undefined) continue;   // ← 조용히 버려진다
```

그런데 **실제로 저장되는 값은 이 목록에 하나도 없습니다**:

| 경로 | 저장되는 `day_of_week` | 근거 |
|---|---|---|
| 예약 등록 폼 | **숫자 `'0'`~`'6'`** | `api-admin.ts` POST 의 `days.map(d => ({ dow: String(d) }))`, 화면 체크박스 `value="0"…"6"` |
| 일정변경(PATCH)·운영 D1 정본 | **`'Wed'`·`'Fri'`** | 같은 파일 `normDow()` |
| AI 명령 | `'mon'` 등 소문자 | (유일하게 옛 표가 읽던 것) |

⟹ 앞의 둘이 전부 `undefined` → **반복 수업은 캘린더에 영영 안 그려졌습니다.**

**고침** — 판정 정본 한 곳(`mgsDowIdx` / `mgsSchedHitsDate`)을 만들어 숫자·영문·한글을 다 받고,
주간·월간이 그 하나를 부릅니다. 모르는 값은 **`null`(«모름»)** 이고 지어내지 않습니다.

곁들여 **날짜가 요일을 이기게** 순서도 맞췄습니다 — `/api/class/sessions/today` 가
`if (scheduled_date) … else if (day_of_week)` 라 화면도 같아야 합니다. 예전 코드는 요일을 먼저 봐서,
두 칸이 다 찬 행(`js/adm-q6.js` 가 날짜 행에도 `day_of_week` 를 보냅니다)이
**엉뚱한 요일에 «매주»** 그려질 수 있었습니다.

## 5. 원인 C — 월간 뷰에는 예약 수업 레이어가 **아예 없음**

`renderDSchedMonth()` 를 훑으면 `aiSchedules`·`scheduled_date`·`day_of_week` 가 **한 번도 안 나옵니다.**
월간은 `enrollments`(수강신청)만 그렸습니다.
⟹ **월간에서는 1회차든 반복이든 예약 수업이 구조적으로 한 건도 안 보였습니다.**

**고침** — 같은 정본(`mgsSchedHitsDate`)으로 판정하는 ⭐ 카드 레이어를 월간에도 넣었습니다.
⛔ 판정을 월간에 다시 적지 않았습니다(한쪽만 고쳐지는 사고).

## 6. 원인 D — 등록에 성공해도 캘린더를 다시 안 읽음

```js

try { loadAiSchedules(); } catch(_) {}          // 목록만
```

등록 경로에만 빠져 있었습니다 → 「✅ 등록됐습니다」를 보고 캘린더로 가도
**탭을 다시 누르거나 새로고침하기 전까지 그대로**입니다. 한 줄 추가로 맞췄습니다.

## 7. 검토했다가 버린 방법

| 버린 것 | 왜 |
|---|---|
| `adm-light-surfaces.js` 의 `fixText` 가 input 도 보게 고치기 | 관리자 화면 **전체**가 싣는 파일. 반경이 이 화면 밖으로 나가고 `?v=` 가 여럿 걸린다 |
| 옛 `dowToIdx` 에 `'3'`·`'Wed'` 만 덧붙이기 | 표가 «화면 안» 에 남아 월간이 또 복제하게 된다. 정본 한 곳으로 뺐다 |
| 월간에서 요일을 다시 푸는 코드 쓰기 | 두 뷰가 어긋나는 사고가 이 저장소에 이미 여럿 |
| 서버(`api-admin.ts`)가 `day_of_week` 를 한 표기로 통일 | 운영 D1 에 이미 세 표기가 섞여 있어 **읽는 쪽을 넓히는 쪽**이 안전하다. 통일은 마이그레이션이 걸린 별건 |
| 화면이 «시각» 을 다시 재게 하기(등록 뒤 상태 갱신) | 판정이 두 벌이 된다. 서버가 준 값만 쓴다 |

## 8. 확인한 방법

### 자동 — `test-harness/student_sched_calendar_harness.mjs` (PASS 38)
정본 블록을 **소스에서 오려 내 `new Function` 으로 실제로 돌립니다**.
숫자·영문·한글·쉼표 나열·«두 칸이 다 찬» 행·취소된 행·시간대 경계까지 넣어 답을 봅니다.
「읽는다」 옆에 **「모르는 값은 `null` 이다」·「취소된 예약은 안 열린다」를 짝으로** 두었습니다
(짝이 없으면 «전부 0(일요일)» 같은 엉터리도 통과합니다).
배선은 두 뷰 함수를 **중괄호 짝으로 잘라** 그 안에서만 묻습니다.

### 브라우저 — `test-harness/manual/student-schedule-calendar-browser.mjs` (PASS 21)
**자동으로 안 돕니다 — 사람이 부릅니다:**
```
node test-harness/manual/student-schedule-calendar-browser.mjs
```
대비는 반투명 층을 모아 합성해 재고, 카드는 `innerHTML` 이 아니라 **DOM 으로** 셉니다.

### 🪤 그 검사가 두 번 헛돌았습니다 — 둘 다 실측으로 잡았습니다
1. **시각을 `innerHTML` 에서 찾으면 «격자의 시간 눈금» 이 걸립니다.**
   「취소된 18:00 이 안 그려진다」가 눈금 때문에 FAIL 났고, 반대로
   「16:00 이 보인다」는 눈금 덕에 **저절로 참**이었습니다 → `div[title^="🤖 …"]` 로 콕 집었습니다.
2. **자리를 `style.left` 문자열로 물으면 안 됩니다** — 브라우저가 calc 를 정규화해
   `calc(71.4286% + 19.1429px)` 로 돌려줍니다(`* 5 / 7` 을 기대했다가 거짓 FAIL).
   **카드 중앙 x 가 어느 요일 머리글 칸 안인가** 로 바꿨습니다.

## 9. 못 한 것 · 남은 것

- **사람이 브라우저에서 직접 봐야 끝입니다.** 이 작업 환경은 프록시가 `mangoi.ai` 를 막아
  배포된 실제 화면을 볼 수 없습니다(4-1-1).
- `STUDENT_UID`·`STUDENT_NAME` 이 **저장소 어디에도 대입되지 않습니다**(읽는 곳만 4군데).
  uid 는 URL 파라미터로 떨어져 무해하지만 **학생 이름이 늘 빈 값**이라 이 화면에서 등록한 수업의
  `student_name` 이 NULL 로 저장됩니다. 이번 제보와는 별개라 **안 건드렸습니다** — 사람이 정할 일.
- `day_of_week` 표기를 한 가지로 통일하는 것은 운영 D1 마이그레이션이 걸린 **별건**입니다.
  지금은 «읽는 쪽을 넓히는» 쪽으로만 막았습니다.
- 월간 뷰는 주간과 달리 **시간대(09~24시) 제한이 없습니다** — 새벽 수업도 월간에는 그려집니다.
  주간 격자가 09시부터라 생기는 차이이고, 그대로 두었습니다.
