# 결재함 자동화 4단계 — 영수증 재사용 · 결재 전 이력 · 첫 번에 통과 비율 (2026-09-24)

## 왜 했나
- 사장님 「다음 단계로 계속 해줘」「결제 자동화」. 1~3단계(#1182·#1183)가 배포된 뒤, 제안서에 «아직 안 만든 것» 으로
  남아 있던 항목 가운데 **코드만으로 되는 것**을 골랐다.
  - 「영수증 사진 자동 검사 — 같은 영수증 재사용」
  - 「결재 전 AI 질문 — 이 거래처 지난달에도?」
  - 「필리핀 쪽 반려 줄이기 점수 — 매니저별 첫 번 통과율」

## 한 것
1. **같은 영수증 재사용 → 🔴**: 올릴 때 첨부 «내용» 의 SHA-256 을 `approval_requests.file_hash` 에 적는다.
   같은 해시가 «살아 있는» 다른 결재(반려·회수·취소·취소결재 제외)에 있으면 `receipt_reused` 표시 → 신호등 🔴.
   올리기 전 점검(`/precheck`)도 화면이 계산한 해시로 같은 판정을 미리 보여 준다.
   ⚠️ 해시는 INSERT 가 아니라 저장 «뒤» UPDATE — ALTER 가 실패한 DB 에서도 올리기가 안 죽는다.
2. **결재 전 이력** `GET /api/approval/requests/:id/history` → 결재함 카드의 「지난 기록 보기」.
   같은 사람·같은 분류 최근 6개월에서 «같은 제목(끝의 달·숫자는 무시)» 으로 **승인된** 건·금액, 평소 대비 배수,
   그 사람의 결정 건수·반려 수. AI 대화가 아니라 조회(`historyCard`) — 같은 질문에 늘 같은 답이어야 결재 근거가 된다.
   권한은 그 결재와 같다(`canView`).
3. **주간 요약에 「첫 번에 통과(14일)」** — 올린 사람별(결정 2건 이상), 대기 건은 분모에서 빼고 다시 올린 건은 «첫 번» 아님(`firstPassRates`).

## 검토했다가 버린 것
- «AI 에게 자유롭게 물어보기» — 같은 질문에 매번 다른 답이 나오면 결재 근거가 못 된다. 계산판으로 대신.
- 파일 이름·크기로 재사용 판정 — 이름은 누구나 바꾼다. 내용 해시로.
- 흐림·잘림 검사 — 판정 기준을 세울 데이터가 없고, 멀쩡한 사진을 되돌리면 필리핀 업무가 멈춘다. 뒤로.
- ARS(전화 음성) — SOLAPI 계정 확인이 먼저(사람 할 일).
