2. **질문 두 개(결정론)** — 정본 `askCard`(`approval-policy.ts`):
   - 같은 가게에서 최근 90일 승인된 횟수 · 마지막 날짜 · 그중 다른 사람 몫. 처음 보는 가게면 🟡 색으로.
   - 이번 달(KST) 같은 항목 승인 합계(₱·₩ 따로).
   - 승인된 지출만 셉니다. 대기·반려·취소 결재·이 건 자신은 뺍니다.
3. **이력 카드에 붙임** — 기존 「지난 기록 보기」 응답에 `ask` 를 싣고 화면이 아래에 두 줄로 그립니다.
   다른 사람이 올린 건도 세므로 **행마다 `canView` 로 거릅니다**(결재선을 넘기지 않아 좁게 실패).

## 검토했다가 버린 것
- **대화 모델에 질문을 그대로 묻기** — 같은 질문에 매번 다른 숫자를 주면 결재 근거가 못 됩니다. 질문을 두 개로 정해 D1 을 셉니다.
- **자유 질문 입력칸** — 휴대폰에서 글을 쓰는 순간 결재가 미뤄집니다(제안서 ②). 누르기만으로 답이 보이게 했습니다.
- **분류 목록을 `IN (?, ?)` 로** — 손으로 적으면 분류가 늘 때 어긋납니다. `TYPES` 에서 만든 콤마 문자열을 `instr` 로 씁니다.

## 한계 (사실대로)
