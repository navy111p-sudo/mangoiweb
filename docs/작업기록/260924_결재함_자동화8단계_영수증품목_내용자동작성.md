# 결재함 자동화 8단계 — 영수증 사진으로 «내용(품목 목록)»·«항목» 자동 작성 (2026-09-24)

## 왜 했나
사장님 「영수증 사진 촬영해서 업로드 하면 자동으로 내용과 목록 그리고 금액이 결제서에 작성되게도 추가할 수 있어?」
확인해 보니 **금액·날짜·가게 이름(제목)** 은 이미 자동으로 채워지고 있었습니다(`/api/approval/ocr`).
빠진 것은 **무엇을 샀는지(품목 목록)** 와 **지출 항목** 이었습니다.

## 한 것
1. **서버 판독에 품목 추가** — 비전 모델에게 `items:[{name, qty, price}]` 도 묻습니다(최대 15줄, 토큰 160 → 480).
   받은 값은 정본 `normReceiptItems` 로 정리합니다 — 이름 없는 줄 버림 · 수량 1~999 · 가격 모르면 null ·
   **할인 줄(-₱3)은 +3 이 아니라 null**(숫자만 남기면 부호가 사라지는 함정).
2. **글은 정본 순수 함수가 만든다** — `receiptBody(items, amount, 통화)`:
   ```
   Items (read from the receipt — please check / 영수증에서 읽음 · 확인해 주세요):
   - Bond paper × 2 — ₱240
   - Ink — ₱360
   ```
   품목 합계 ≠ 총액이면 «다릅니다 — 확인해 주세요» 한 줄(숫자를 맞춰 «고치지» 않음).
   가격 모르는 품목이 있으면 합계 경고를 안 합니다(모르는 것을 틀렸다고 하지 않음). 품목이 없으면 빈 글.
3. **항목 짐작** — `guessCategory`: 가게·품목 낱말(종이·펜 → 사무소모품, Grab → 교통, Jollibee → 식대,
   Meralco → 공과금 …). 모르거나 동점이면 null — 사람이 고릅니다.
4. **화면** — 판독 성공 뒤 `fillFromReceipt`: **비어 있는 칸만** 채웁니다(이미 적은 내용·고른 항목은 안 덮음),
   항목은 목록에 실제로 있는 값일 때만. 통화는 화면이 고른 것(`?cur=`)으로 적습니다.

## 검토했다가 버린 것
- **모델이 글까지 쓰게 하기** — 같은 영수증에 매번 다른 문장이 나오면 결재자가 믿지 못합니다. 모델은 «목록» 만, 글은 코드가.
- **합계가 다르면 총액을 품목 합으로 바꾸기** — 판독이 틀렸을 수도, 봉사료·세금이 따로일 수도 있습니다. 사실만 적습니다.
- **항목을 모델에게 고르게 하기** — 목록 밖 값을 지어낼 수 있습니다. 낱말 표 + 모르면 빈칸.

## 한계 (사실대로)
- 품목은 **AI 판독**이라 빠지거나 틀릴 수 있습니다 — 글 머리에 «확인해 주세요» 를 적어 둡니다.
  실제 영수증으로 얼마나 잘 읽는지는 **아직 못 쟀습니다**(이 환경에서 AI 를 부를 수 없음).
- 항목 짐작 낱말 표는 필리핀 가게 이름 위주의 첫 판입니다 — 틀리면 사람이 바꾸면 되고, 자주 틀리는 낱말은 표에 더합니다.
