## 1. 왜 했나

사장님 제보: AI 단어 퀴즈 「듣고 맞히기」(문제 4/5, 「잘 듣고 뜻을 고르세요」) 화면에서 **원어민 발음이 이상하다.**
화면 파일은 `cloudflare-deploy/public/micro-quiz.html`.

## 2. 무엇을 바꿨나

- `cloudflare-deploy/public/micro-quiz.html` — `speakWord()` 앞에 `ttsWord()` 를 새로 두었다.
  소리를 만들 때만 낱말을 **첫 글자 대문자 + 마침표**(`study` → `Study.`)로 보낸다. 화면 글자는 그대로.
  - 이미 `. ! ?` 로 끝나면 그대로
  - 영문자·숫자·`'`·`,`·`-`·공백 밖의 글자(한자·한글)가 섞이면 그대로
  - 빈 값은 빈 문자열
- `test-harness/micro_quiz_tts_word_harness.mjs` — 새 하니스 14종(아래 4장).

소리 경로(참고): `speakWord` → `MangoiTTS.speak()`(`js/game-tts.js`) → `POST /api/voice/tts`(`src/api-games.ts`)
→ Deepgram **Aura-2**(`asteria`) → 실패 시 Aura-1 → MeloTTS → 서버 전부 실패 시 기기 목소리(`speechSynthesis`).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

원인 후보는 셋이었다(코드 읽고 좁힌 **추론** — 이 환경은 소리를 들을 수 없고 `mangoi.ai` 도 프록시에 막혀 응답 헤더도 못 봄).

1. **낱말 하나만 보냄** — 문장용 AI 음성은 낱말 하나를 받으면 첫소리를 자르거나 억양이 어색해지는 경우가 흔하다. 코드에 한 단어용 처리가 없었다. ← 사장님이 이 방법을 골라 적용
2. 폴백 목소리(Aura-1·MeloTTS·기기 음성)로 떨어졌을 가능성
3. 서버 R2 캐시(7일)에 옛 이상한 음성이 남았을 가능성 — 보내는 글자가 바뀌면 캐시 키도 바뀌어 이것도 함께 비켜 간다

버린 방법:
- **공용 `js/game-tts.js` 에서 고치기** — 여러 게임·AI 친구·판단력 훈련이 함께 쓰므로 반경이 크고, 문장을 넘기는 화면까지 모양이 바뀐다. 제보된 화면 하나로 좁혔다.
- **서버(`/api/voice/tts`)에서 짧은 입력을 다듬기** — 모든 화면의 캐시 키가 한꺼번에 바뀌어 뉴런을 다시 태운다. 반경 대비 이득이 없다.

- **배포 보류 중**: 병합 시각이 목 14:09 KST 라 배포 보류 창(화·목 12:00~16:00)에 걸렸다. 16시 이후 몰아 배포로 나간다(실측상 1~3시간 늦게 오는 일이 많음). 17:30 KST 에 배포 확인을 예약해 두었다.
