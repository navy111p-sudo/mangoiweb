# 2026-09-25 A.i 사용료 — «신청한 학생만» + 자동 청구 스위치(기본 꺼짐)

## 1. 왜 했나
사장님 캡처(관리자 › 정산·매출 › A.i 사용료): 망고아이 SSO전용 «재원 680 · 화상반 4 · A.i반 676 · ₩3,042,000».
사장님 말씀 — 「아직 A.i 학습만 신청한 사람 아무도 없어. 지금은 테스트 기간이고 아무도 유료 신청 안 했어.
화상반은 A.i 학습 포함이라 무료야.」

[잰 것] 옛 규칙은 **A.i반 = 재원 − 화상반** 이라 «화상반이 아닌 학원생 전원» 을 A.i 단독으로 **추론**했다.
신청 0명인데 약 7,300명이 청구 대상으로 잡혀 있었고, **10월 1일 월 cron(`generateMonthlyAiInvoices`)이
그대로 청구서를 만들 참**이었다.

제안서(추천안 A): https://claude.ai/artifact/LFEd2MjFAAtFyyGSRBZQrK → 사장님 「추천한대로 진행해」.

## 2. 무엇을 바꿨나
| 자리 | 전 | 후 |
|---|---|---|
| 청구 인원 | 재원 − 화상반 (추론) | 재원 ∩ **신청 명단** − 화상반 |
| 신청 명단 | 없음 | 새 표 `ai_billing_optin`(uid_lc PK) — 학원이 명세에서 학생을 체크하면 들어가고, 체크를 풀면 빠짐 |
| 월 cron | 무조건 생성 | **스위치(`ai_billing_meta` k=`auto_billing`) 가 `on` 일 때만** — 기본 꺼짐, 꺼지면 `status:'disabled'` 기록 |
| 신청 0명 학원 | 빈 청구서 | 월 cron 은 건너뜀(`skipped`), 학원이 직접 누르면 만듦 |
| 학원 화면(branch·manager) | 금액 카드 | 꺼져 있으면 「테스트 기간 — 청구하지 않습니다」 한 줄 |
| 생성·결제 API | 동작 | 꺼져 있으면 409 `billing_disabled` |
| 관리자 표 | 재원/화상반/A.i반 | 재원/화상반(무료)/A.i 단독 신청(청구)/**신청 안 함**/예상 청구 + 본사 전용 ON/OFF 버튼 |
| 학생 구분(4계층) | 화상+AI / AI만 | 화상+AI / **A.i 단독 신청**(명단 ∪ 개인 유료 `AI 콘텐츠 전용`) / **수업 기록 없음**(idle) |

모르면 청구 0명(fail-closed): 스위치·화상반·신청 명단 중 하나라도 못 읽으면 청구서를 만들지 않는다.

## 3. 검토했다가 버린 것
- **학원 카드를 통째로 숨기기** — 추천안에는 «숨김» 으로 적었지만 숨기려면 첫 화면에서 스위치를 따로 물어야 해 요청이 하나 는다. 이미 부르는 `/invoice` 가 `billing_enabled:false` 를 주므로 그 자리에서 «테스트 기간» 문구로 바꿨다(사실을 말하는 쪽).
- **개인 유료 결제(`ai_content`)도 학원 청구에 넣기** — 학생이 이미 개인으로 냈는데 학원에 또 청구하면 이중 청구. 명부 «표시» 에만 쓰고 학원 청구는 학원 체크 명단만.
- **스위치 기본 켜짐** — 테스트 기간이라 켜면 10/1 에 바로 청구된다. 본사가 켜는 순간부터.

## 4. 알고 둔 한계
- 학원이 **화상반 학생을 체크**하면 명단에는 들어가지만 화상반이 이기므로 청구되지 않는다(의도).
- 옛 청구서 명세 줄은 다음 생성/보강 때 `planItemTrackSync` 가 «신청 안 함» 으로 자동 제외한다(학원이 손댄 줄 `user_set=1` 은 포함 여부 그대로 · 표시만).
- D1 데이터는 한 줄도 안 바꿨다(새 표는 `CREATE TABLE IF NOT EXISTS`).
