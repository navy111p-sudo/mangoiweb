# 결재함 자동화 10단계 — 요약 알림에서 바로 «한 번에 승인» · 대표님 주간 요약에 지출 합계 (2026-09-25)

## 1. 왜 했나
사장님 「다음단계 진행해줘」. 제안서(결재함 AI 비서)에 남아 있던 두 가지입니다.
- ② «요약에서 🟢 건은 **알림 한 번 눌러** 묶음 승인까지»: 9시·17시 요약 알림을 누르면 `/work?id=0` 으로 결재함 첫 화면만 열렸습니다.
  «한 번에 승인» 칸은 2건 이상일 때만 보여서, 🟢 가 1건이면 그 칸이 아예 없었습니다.
- ③ «대표님께 주 1회 건수 · **합계** · 🟡/🔴 였던 건만 따로»: 주간 요약에는 건수·처리시간·늦은 건만 있고 **돈의 크기가 없었습니다.**

## 2. 무엇을 바꿨나
| 자리 | 내용 |
|---|---|
| `approval-policy.ts` | `digestUrl(green)`: 🟢 가 있으면 `/work?bulk=1`, 없으면 `/work`. `weeklySpend(rows)`: 승인된 지출만 통화별 합계, 그중 🟡/🔴 였던 건 수. 지출 판정은 정본 `isSpendRow` 를 그대로 씁니다. |
| `api-approval.ts` | `notify()` 에 `urlOverride` 인자를 더했습니다. `/work` 로 시작하는 주소만 받고, 나머지는 예전처럼 `/work?id=N`. 요약 알림은 `digestUrl(green)` 을 넘깁니다. 주간 요약에 「승인된 지출: ₱… (N건) · ₩… — 그중 🟡/🔴 였던 건 N건」 한 줄을 더했습니다. |
| `work.html` | `?bulk=1` 로 들어오면 🟢 가 1건이어도 «한 번에 승인» 칸을 보여 주고, 그리로 스크롤해 초록 테두리로 강조합니다. 남은 🟢 가 없으면 「지금 한 번에 승인할 건이 없습니다」라고 말합니다. |

## 3. 검토했다가 버린 것
- **알림을 누르면 바로 묶음 승인** — 버렸습니다. 요약은 몇 시간 전 숫자라 그사이 건이 바뀔 수 있습니다. 돈이 나가는 결정이니 화면에서 확인창을 한 번 거칩니다(제안서의 «AI 는 승인하지 않는다» 원칙).
- **notify 가 아무 주소나 받게** — 버렸습니다. 알림 링크가 우리 사이트 밖으로 나가지 않도록 `/work` 로 시작하는 것만 받습니다.
- **통화를 원화로 환산해 합산** — 버렸습니다. 환율을 지어내게 됩니다. ₱ 와 ₩ 를 따로 적습니다.

## 4. 주의
- 요약 알림은 푸시로만 갑니다(문자는 원래 안 보냈고, 그대로입니다).
- 주간 합계는 «이번 주에 올라와서 승인된 건» 기준입니다. 결재된 날이 아니라 올린 날로 셉니다(다른 주간 숫자와 같은 창).
- «한 번에 승인» 에서 빠지는 건(늦은 건·결재권자 몫·경고 있는 건)은 예전 규칙 그대로 빠집니다.
