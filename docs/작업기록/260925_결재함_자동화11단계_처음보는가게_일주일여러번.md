# 결재함 자동화 11단계 — 🏪 처음 보는 가게 · 🔁 일주일에 여러 번 (2026-09-25)

## 1. 왜 했나
사장님 「다음단계로 가줘」. 제안서(결재함 AI 비서)의 🟡 «확인 필요» 목록에 있던 네 가지 중 두 가지가 아직 없었습니다.
- «처음 보는 거래처·항목»
- «같은 사람이 일주일에 여러 번»

제안서 ③의 «평소와 다른 건(큰 금액, **처음 보는 거래처, 같은 사람이 짧은 기간에 여러 번**)만 대표님께 즉시» 도 그 두 신호가 없어서 큰 금액만 걸리고 있었습니다.

## 2. 무엇을 바꿨나
| 자리 | 내용 |
|---|---|
| `approval-policy.ts` | `FREQUENT_WEEK_MIN=3`(이 건 말고 7일 안에 같은 분류 3건 이상 → 「이번 주 N번째」) · `VENDOR_HISTORY_MIN=10` · `isNewVendor()`(비교 열쇠는 6단계 정본 `vendorKey`) · `runChecks` 가 돈 나가는 분류에서만 `frequent`·`new_vendor` 를 **info(🟡)** 로 붙임 · 대표님 즉시 알림 신호를 `EXEC_WATCH_CODES` 로 정책 파일에 옮기고 두 신호를 더함 |

## 3. 검토했다가 버린 것
- **🔴(되돌림)로 올리기** — 버렸습니다. 새 가게·바쁜 주는 흔하고 멀쩡합니다. 참고(🟡)만 붙입니다.
- **기록이 적어도 «처음» 이라고 말하기** — 버렸습니다. 가게 이름 칸은 2026-09-24(6단계)에 생겨 아직 기록이 적습니다. 그대로면 모든 건이 «처음 보는 가게» 가 되어 소음입니다. 서로 다른 가게가 **10곳 이상** 쌓이기 전에는 말하지 않습니다.
- **돈 안 나가는 분류(휴가·문서)에도 «여러 번»** — 버렸습니다. 휴가는 여러 번 올리는 것이 정상입니다.

## 4. 주의
- «처음 보는 가게» 는 **영수증 판독 이름** 기준이라 판독이 틀리면 잘못 뜰 수 있습니다(6단계와 같은 한계).
- 🟡 가 늘면 「알림에서 바로 승인」·「한 번에 승인」 대상(🟢)에서 빠지는 건도 그만큼 늘 수 있습니다 — 제안서의 의도(사람이 한 번 보기)대로입니다.
- 가게 이름 기록이 10곳 미만인 동안은 «처음 보는 가게» 가 **뜨지 않습니다.** 고장이 아닙니다.
