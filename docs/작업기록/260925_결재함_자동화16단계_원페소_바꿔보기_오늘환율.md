## 2. 정본과 원칙

- **«보기» 만 바꿉니다** — 합계·엑셀·경고 판정은 원래 통화 그대로입니다. 환산 값으로 판정하지 않습니다.
- `approval-policy.ts`
  - `fxSane` — 1페소가 10~60원 범위 밖이면 버립니다.
  - `parseFxResponse` — API 응답을 읽습니다.
  - `fxConvert` — 환율이 없으면 null.
  - 화면 `ledConv` 는 이것과 같은 계산이고, 하니스가 전수로 대조합니다.
- `fx-rate.ts` `getTodayFx` — 아래 순서로 찾습니다.
  1. 오늘자 KV 캐시
  2. 공개 환율 API(open.er-api.com, 키 없음, 3초 제한)
  3. 마지막으로 받은 값
  4. 급여 화면에 **사람이 저장한** 환율(행이 있을 때만)
  5. 없으면 null
- 어디서 왔는지와 날짜를 화면이 그대로 적습니다(「지난번에 받은 환율 — 오늘 것을 못 받음」 등).
- ⛔ 기본값을 지어내지 않습니다. 급여 화면의 `getPhpKrwRate` 는 행이 없으면 24를 돌려주므로 쓰지 않았습니다. 못 구하면 버튼을 끄고 「오늘 환율을 불러오지 못해…」 라고 말합니다.
- ⛔ 던지지 않습니다. 환율 때문에 장부가 죽지 않습니다(`.catch(() => null)`).

## 3. 버린 방법

- **급여 환율(24원)을 그냥 쓰기** — 「당일 환율」이 아니고, 저장값이 없으면 지어낸 숫자입니다.
- **서버가 환산한 금액을 내려주기** — 응답이 통화 수만큼 커지고, 누를 때마다 다시 불러야 합니다. 환율 하나만 받아 화면이 곱합니다(계산은 정본과 대조).
- **엑셀도 환산** — 장부는 결재에 적힌 그대로가 정본입니다.
