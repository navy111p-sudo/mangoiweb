# 2026-09-25 급여 표·결재함 카드 — ₩ 원화로 보기

## 1. 왜 했나
- 사장님: 「급여에서 버튼 만들어서 누르면 페소와 원화 현재 환율로 변해서 보이게 해줘. 위에 환율도 보여줘. 실시간 환율」
- 이어서 결재함 목록 카드(₱2,500·₱4,600·₱2,800) 사진과 함께: 「여기는 왜 바뀌지 않았어??」
  → 같은 날 #1215(결재함 16단계)가 원·페소 바꿔 보기를 **회계장부 칸에만** 넣었고, 목록 카드는 `money()` 로 원래 통화만 그리고 있었다.

- 환율 정본은 **하나** — `src/fx-rate.ts` 의 `getTodayFx`(KV 캐시 → open.er-api.com → 지난 값 → 급여 저장값 → null).
  급여 화면은 `GET /api/admin/reports/fx-rate` 로, 결재함은 장부 응답의 `fx` 로 같은 함수를 받는다.
- 결재함 카드의 선택은 회계장부와 **같은 상태(`LED.show`, localStorage `mangoi_led_show`)** 를 쓴다 — 한쪽에서 바꾸면 둘 다 바뀐다.

- ⚠️ **같은 일을 두 번 밟았다** — 「카드」만 고치고 같은 화면의 다른 금액(맨 위 카드·지출 정리)을 안 셌다. 금액을 그리는 곳은 `money(` 호출을 `grep` 으로 세면 30초. 이제 `fxRepaintAll()` 에 «금액을 그리는 곳 전부» 를 모았고, 새로 만들면 거기에 한 줄 더한다.

## 3. 검토했다가 버린 것
- **급여용 환율 모듈을 따로 두기** — 처음엔 `open.er-api → frankfurter` 로 따로 만들었으나, 병합 직전 #1215 가 같은 이름 파일로 먼저 들어와 버렸다. 두 화면이 다른 환율을 말하면 안 되므로 내 모듈을 버리고 그 정본을 부르게 바꿨다.
- **결재함 `money()` 자체를 환산하게 바꾸기** — 장부의 `lm()` 이 이미 환산한 값을 `money()` 로 그리므로 두 번 환산된다. 카드 전용 `cardAmtHtml()` 을 따로 뒀다.
- **카드에서 원래 금액을 지우고 ₩ 만 보이기** — ₱5,000 결재 기준 등 판정이 원래 통화라, 원래 금액이 사라지면 결재자가 기준을 오판한다. 원래 금액 + ≈환산으로.
- **환율이 없을 때 급여 설정값(기본 24원)으로 채우기** — 지어낸 숫자가 «오늘 환율» 로 보인다. 정본이 `source` 로 «지난 값»·«급여 저장값» 을 밝히고, 아무것도 없으면 바꾸지 않는다.

## 4. 한계(사실대로)
- «실시간» 이 아니다 — 공개 환율 API 는 하루 1회 안팎 갱신. 화면이 날짜를 함께 적는다.
- 결재함 목록의 환율 줄은 **회계장부를 받은 뒤** 나온다(장부 응답에 환율이 실려 온다). 장부를 못 받으면 카드는 원래 금액만.
- 프록시가 외부 환율 API·mangoi.ai 를 막아 **실제 워커가 환율 API 에 닿는지는 못 쟀다** — 배포 후 사람이 화면에서 확인.
