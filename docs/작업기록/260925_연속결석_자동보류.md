# 연속 결석 «자동 보류» — 말없이 그만둔 학생 때문에 강사가 기다리고 강사비가 나가던 것 (2026-09-25)

## 1. 왜 했나
B2B·B2C 학생이 그만둔다는 말 없이 안 나오는 경우가 있습니다. 그러면 강사는 방에서 계속 기다리고,
본사는 강사비를 계속 내고, 학생은 결석으로만 쌓입니다. 사장님이 먼저 4가지 대안 제안서를 요청하셨고
([제안서 artifact](https://claude.ai/artifact/D8U4zmsfdTsR4oa4eYHVHp)), 추천안 A+B 가운데 **1단계(A)** 를 만들었습니다.

사장님이 정하신 조건:
1. **2회 연속 결석**이면 보류
2. 보류 중에는 **강사비 0%**. 강사는 기다리지 말고 **필리핀 매니저에게** 계속 다니는지 그만뒀는지 물어볼 것
3. 연락 수단은 **문자·카톡·알림톡**
4. 근거는 **수강등록 때 적은 번호**(= 학생 목록, `phonesForStudent`)
5. 강사·매니저에게는 **이메일과 알림(푸시)**, 그리고 mangoi.ai **관리자·/teacher·/manager 화면에 자동으로** 뜨게

## 3. 판정 규칙 (왜 이렇게)
- **모르는 회차는 연속을 끊음.** 출결이 불분명하면 보류하지 않습니다. 잘못 걸어서 강사비를 막는 쪽이 더 나쁘기 때문입니다.
- **보류 구간은 두 번째 결석 «다음 날»부터** 시작합니다. 두 번째 결석 당일은 기존 결석 수당 규칙을 그대로 따릅니다.
- **학생이 다시 들어오면 자동으로 재개**됩니다(`decided_by='auto:returned'`).
- **[그만둠]은 기한 없이 보류**로 남고 0% 입니다. 나중에 [재개] 를 누르면 되돌릴 수 있습니다.
- 끄는 스위치(KV `SESSION_STATE`):
  - `absence_hold`='off' → 새 보류를 걸지 않음
  - `absence_hold_notify_student`='off' → 학생 문자만 끔

## 4. 검토했다가 버린 방법
- **`class_schedules.status='cancelled'` 로 보류 처리** → 버림. 급여가 그 예약의 과거 회차(실제로 가르친 수업)까지 통째로 빼고, 카페24 미러가 취소된 행을 다시 만듭니다. 그래서 별도 표로 구간만 기록했습니다.
- **예약 행 단위 보류** → 버림. 수강등록이 회차마다 일회성 행을 만들기 때문에 **학생 단위**로 했습니다.
- **manager.html 에 script 태그 추가** → 「외부 리소스 1개」 계약 하니스(㉕)가 FAIL. 조건부 동적 로드로 바꿨습니다.
- **매니저 이메일을 `IN (?,?,?)` 로 조회** → D1 바인드 한도 가드가 FAIL. `selectInChunks` 로 바꿨습니다.

## 4-1. 함정 대조가 잡은 것 (커밋 전에 고침)
- 🔴 **«2회 연속» 이 실제로는 «3회» 였음.** 결석 감지는 «시작+10~40분» 에 기록하고 곧바로 판정하는데, 판정은 «끝난 회차» 만 셌습니다. 그래서 방금 기록된 결석이 빠졌습니다. → 이미 시작한 회차 중 기록이 있는 것도 셉니다. 진행 중인데 기록이 없는 회차는 «모름» 으로 빼서 연속을 끊지도 잇지도 않습니다.
- 🔴 **가르친 수업이 0원이 될 수 있었음.**
  - ① 급여가 «보류 구간인가» 만 보고 «학생이 실제로 들어왔나» 는 안 봤습니다 → `attendedStudentRooms` 로 그 회차 예약방의 학생 접속을 확인해 지급합니다(못 읽으면 보류를 적용하지 않음).
  - ② [그만둠] 뒤에 돌아온 학생은 자동 재개가 안 됐습니다 → `ended` 도 봅니다.
  - ③ 계정 칸이 빈 접속을 못 잡았습니다 → 예약방 번호로도 봅니다.
- 🔴 **강사 보류 카드에 입장 버튼이 없어**, 학생이 돌아와도 강사가 못 들어갔습니다 → 회색 보조 버튼 «학생이 왔으면 입장» 을 넣었습니다.
- 🟡 **중복 보류:** 중복 확인 조회가 실패하면 «없음» 으로 떨어져 문자가 두 번 나갈 수 있었습니다 → 그 조회는 실패하면 보류 안 함(fail-closed).
- 🟡 **결정 API:** `getAdminActor().role` 만 봤습니다 → `admin_scope` 를 한 번 더 읽고, 못 읽으면 막습니다(`enrollAdminHqOnly` 방식).
