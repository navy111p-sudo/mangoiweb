# 교사 [수업 입장]이 방이 바뀐 뒤에도 옛 방으로 가던 결함 (2026-09-29)

## 왜 했나
사장님: 학생 수업 스케줄 변경·연기, 관리자 드래그 이동 뒤에도 교사·학생이 서로 보이고 같은 방에서 만나는지 확인·해결.

## 원인 (잰 것)
- `teacher.html` `renderClasses()` 는 지문(sig)이 같으면 다시 그리지 않고, 버튼 onclick 은 «그린 순간» 의 `list` 를 쥔다.
- 지문에 `room_id` 가 없었다 → 「🚪 오늘은 다른 방으로」·이동으로 서버 room_id 가 바뀌어도 45초 자동 갱신이 DOM 을 안 바꿔 **[수업 입장]이 옛 방으로** 갔다.
- 방 지정 성공 뒤 재조회도 없었다(최대 45초 옛 방).
- 실제 Chromium 에서 고치기 전 판으로 재현: 새 방 meet-1234 인데 입장은 class-7-20260929.

## 고친 것
- 지문에 `room_id`·`duration_min`·`close_at_ts`
- `freshClass()` — 입장·일지·일지보기·AI리포트·방지정이 누르는 순간 최신 DATA 에서 같은 수업(schedule_id+kind)을 다시 찾음. 못 찾으면 받은 줄 그대로(= 예전).
- 방 지정 성공 직후 `scheduleAutoRefresh(300)`

## 버린 방법
- 버튼마다 서버를 다시 묻기 — 요청 수가 늘고 이 화면은 «요청 수» 를 아끼는 계약.
- 지문 검사 자체를 없애기 — 저사양 폰 60초 움찔 문제가 되살아남.
