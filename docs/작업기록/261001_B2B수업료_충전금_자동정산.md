# 261001 B2B 수업료 — 충전금 자동 정산 (mangoi.co.kr 12가지 문제 개선)

## 왜 했나
옛 사이트(mangoi.co.kr)의 대리점·학원 결제가 12가지 문제를 안고 있었습니다(사장님 정리):
충전금 자동 차감 없음 · 잔액 소진 알림 없음 · 결제 화면 복잡 · 학원은 월 단위인데 본사는 회차 단위 ·
미리 알린 연기가 결석으로 청구 · ± 이월이 어려움 · 25일~말일 독촉 문자를 손으로 · 금액 차이를 매번 설명 ·
자동결제 없음 · 주1회도 달마다 3·4·5회 · 첫 달 두 달 치 청구 · 결제에 관리자 로그인 필요.

## 무엇을 만들었나 (12 → 해결)
| # | 문제 | 해결 |
|---|---|---|
| ① | 충전금 자동 차감 없음 | 회차 원장(`session-ledger`)으로 지난 수업을 하루 단위로 차감(`b2b_tuition_charges`) |
| ② | 소진 알림 없음 | 앞 2주 수업보다 잔액이 적으면 «부족» 경고 + 보충 청구서 |
| ③ | 결제 화면 복잡 | 로그인 없는 한 장짜리 링크 `/b2b-pay.html?t=…` (금액·이유·결제 버튼) |
| ④ | 월/회차 단위 불일치 | 매월 20일 «다음 달 실제 수업 날짜» 로 정기 청구서 1장 |
| ⑤ | 미리 알린 연기가 결석 | 30분 전 연기 신청 = 무료 · 결재 대기 중에도 차감 보류 |
| ⑥ | ± 이월 이해 어려움 | 「① 다음 달 수업 − ② 남는 충전금 = ③ 청구액」 세 줄 설명 |
| ⑦ | 독촉 문자 수작업 | D-7 · D-day · D+14 · D+21 단계 문자(스위치 켤 때만) |
| ⑧ | 금액 차이 설명 | «A.i 차이 진단» — 학원 숫자를 붙여 넣으면 다른 날짜·이유를 짚음 |
| ⑨ | 자동결제 없음 | 카드 등록 → 마감일 자동 청구(스위치 켤 때만) |
| ⑩ | 주1회가 3·4·5회 | 학생별 «그 달 실제 날짜» 를 그대로 세고 적어 줌 |
| ⑪ | 첫 달 두 달 치 | 첫 달은 남은 회차만 보충 청구서로 |
| ⑫ | 관리자 로그인 필요 | 무작위 48자리 링크(본사가 언제든 새로 만들어 끊음) |

## 검토했다가 버린 방법
- **서명 상수로 링크 만들기** — 저장소가 공개라 폴백 비밀값으로 위조 가능 → 무작위 토큰을 D1 에 저장.
- **정기 청구서를 매일 다시 계산** — 금액이 매일 흔들림(실측 525,000 → 427,500). 발행 뒤 고정, 차이는 충전금 → 다음 달 ②.
- **보충 청구서를 잔액만 보고 계산** — 1일에 같은 달 정기 청구서 미납분과 이중 청구(자동결제면 카드 두 번). 미납분을 «낸 셈» 으로 더함(`openMonthlyOwed`).
- **카페24 미러 수업까지 차감** — 옛 사이트에서 이미 청구 중일 수 있어 기본 제외(`include_c24=0`).
- **cron 자동 연결** — `src/index.ts`(공동 금지구역)라 이번엔 안 함. **지금은 본사 «지금 실행» 으로만 돕니다.**

## 안전장치
스위치 셋(auto·notify·autopay_live) 기본 꺼짐 · 못 읽으면 꺼짐 · 본사가 켠 학원만 · 켠 날 이전 수업은 절대 차감 안 함 ·
공개 화면에 학생 아이디·제외 사유 원문 없음 · 이의 신청 하루 10건 상한 · 모든 쓰기는 본사 전용(`enrollAdminHqOnly`).

## 사람이 정할 일 (남은 것)
1. cron 연결(`src/index.ts` scheduled 에 한 줄) — 그 전까지 수동 실행.
2. 자동결제 중간 실패 시 재청구 방지 가드, 같은 청구서 주문 여러 개.
3. 원장 경고(휴원·연기 조회 실패)가 있는 학생 차감 보류할지.
4. 학원 식별이 이름 기준(같은 이름 학원 합쳐짐), 학생 전학 시 이번 달 차감이 새 학원으로 옮겨감.
5. 대기 중인 무료 연기 신청의 만료(지금은 본사가 결정할 때까지 보류).
6. 이의 답변을 대리점 화면에 보여 줄지.
