# 관리자 평가 이름·날짜 호환성 (순차 수리 4단계)

## 상태·범위

운영 접근·DB 변경·배포 없이 로컬 코드와 격리 테스트만 작성했다.
3단계 `evaluation-scores.ts`의 점수 판정·환산·전체 통계 SQL은 변경하지 않았다.
`index.ts`, 공개 평가서 인증/권한, 다른 점수 대시보드는 변경하지 않았다.

## 원인과 수정

학생 상세 평가는 `user_id`, `eval_at`, `score_total`, `evaluator`를 저장했다.
전체 관리자 목록은 `student_name`, `teacher_name`, `lesson_date`를 읽어 빈 칸이 생겼다.
한편 다른 초기 스키마에는 `student_uid`와 `updated_at`이 NOT NULL이어서
학생 상세 INSERT가 실패했다. 모든 공백이 같은 원인은 아니므로 일괄 채우지 않는다.

- 새 `evaluation-records.ts`는 관리자 읽기 결과에만 표시 필드를 붙인다.
- 기록된 `student_name`이 있으면 우선한다. 없으면 대소문자·공백을 바꾸지 않은
  정확한 `students_erp.user_id`로 찾고, 유일한 행의 학생/한국어/영어 이름만 쓴다.
- 동일 UID가 여러 행이면 이름을 고르지 않는다. 두 UID 열이 서로 다르면 조회하지 않는다.
  `login_id`, `student_id`, `username`이나 이름 검색으로 다른 계정을 추측하지 않는다.
- 실제 이름이 없으면 UID와 미기록/미확인/중복/불일치/조회실패 상태를 보여 준다.
  이름 조회가 실패해도 평가 목록과 점수 통계는 남는다.
- `teacher_name`이 없고 `evaluator`만 있으면 반드시 **평가자**로 표시한다.
- 날짜 우선순위는 실제 `lesson_date` → `eval_at` → `created_at`이다.
  각각 **수업일 / 평가일(KST) / 기록일(KST)**로 표시하고, 수업일 부재를 별도로 알린다.
  날짜만 있는 값은 그대로 유지하고, 밀리초/명시적 시간대 ISO 시각은 KST로 변환한다.
  잘못된 날짜나 시간대 없는 시각을 조용히 정상 수업일로 만들지 않는다.
- 이 투영은 점수 집계가 끝난 목록에만 적용한다. 명부 중복으로 행/평균이 늘어나지 않는다.
  UID 조회는 최대 100개씩 나눠 D1 바인드 한도를 지킨다.

## 저장·기존 데이터 보존

- 학생 상세 POST 직전에 부족한 호환 열을 nullable ADD COLUMN으로 보장한다.
  새 행에 `user_id`와 `student_uid`를 같은 요청 UID로 넣고 `updated_at`도 기록한다.
  실제로 받은 평가자/평가일은 기존 열에 저장한다. 이름·강사·수업일을 만들어 넣지 않는다.
- 기존 레거시 NOT NULL `user_id`/`eval_at`, 기존 정본 NOT NULL `student_uid`/`updated_at`,
  신규 DB 모두 학생 상세/수동/초안/일괄/AI 작성이 가능함을 실제 핸들러로 확인했다.
- 호환 열 추가가 실패하면 새 학생 상세 평가를 중간 상태로 INSERT하지 않는다.
- 학생별 관리자 `/evaluations` 및 `/full` 조회는 기존 `user_id` 기반 결과 범위를 유지한다.
  정본 스키마에 그 열이 아예 없으면 빈 결과를 반환하여 페이지 실패만 막는다.
  이 화면의 기존 차트/보고서는 100점 학생 상세 계약에 의존하므로 정본 전용 과거 행을
  새로 섞어 넣지 않는다. 해당 화면과 차트의 통합은 별도 작업이다.
- 기존 행에 UPDATE/백필/점수 환산 저장/테이블 재작성은 없다.
- 수동/AI 작성의 기존 '날짜를 안 보내면 오늘 UTC 날짜' 기본 동작은 이번 범위에서 유지했다.
  이 기본 동작 자체의 의미·KST 전환은 별도 판단 사항이다.

## 표시와 캐시

`adm-r6.js`에 이름 상태·UID, 강사/평가자, 날짜 기준을 함께 표시했다.
새 표시 값도 HTML 이스케이프한다. 점수 분모·별점·미리보기·삭제 버튼은 유지한다.
`admin.html`의 adm-r6 버전은 v5로 올렸고 자산 하니스로 원장을 갱신했다.
그 과정에서 최신 main의 warmup-photo 자산 두 항목도 원장에 자동 등록되었다. 해당 소스는 수정하지 않았다.

## 검증

- `evaluation_records_harness.mjs`: 16개 묶음 통과. 실제 Worker 전체를 번들하여
  세션 인증과 라우팅을 거치고 실제 SQLite를 사용했다. 외부 호출 0회.
  레거시 76/100, 현대 행 보존, 정확/중복/충돌/미존재/실패 조회, KST 자정,
  205개 이름 조회 청크, LIMIT 독립 통계, 세 초기 스키마의 모든 작성 경로,
  학생별 두 GET의 기존 범위 보존 및 열 부재, 마이그레이션 실패 차단, 인증401, UI 이스케이프/기준 표기를 검증했다.
- `evaluation_score_scales_harness.mjs`: 기존 14개 묶음 통과. 새 모듈 import 배선만 추가했다.
- `tsc --noEmit`: 통과.
- `node --check public/js/adm-r6.js`: 통과.
- `asset_version_harness.mjs`: 266개 통과, 실패/파일누락 0.
- 전체 `run.mjs --fast`는 외부 fetch 차단 가드 하에서 실행 중이며 결과는 최종 수리 보고에 합친다.
- 실제 브라우저 QA는 앞 단계에서 확인한 로컬 소켓/localhost 환경 차단 때문에 실행하지 않았다.
  운영 사이트로 대신 시험하지 않았다. DOM 검사는 실제 JS를 VM에서 실행했다.

## 버린 방법

- 역사 행의 이름·날짜를 UPDATE하기: 관찰값과 추정값을 뒤섞어 원본 증거를 잃는다.
- 명부를 집계 쿼리에 바로 JOIN하기: 중복 명부가 평가 수와 평균을 바꿀 수 있다.
- 첫 번째 이름/비슷한 UID/동명이인 선택: 남의 이름을 붙이는 사고를 만든다.
- 평가일·기록일을 수업일이라고 표시하기: 다른 시점을 같은 뜻으로 만든다.
