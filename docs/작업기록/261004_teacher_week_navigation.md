# 강사 주간 달력의 선택 유지·응답 역전·KST 경계 수정

- 날짜: 2026-10-04
- 브랜치: fix/admin-audit-sequential-20261004
- 범위: `cloudflare-deploy/public/teacher.html`, 집중 회귀 검사, 이 작업기록. 원격 푸시/PR/병합/배포·운영 데이터 변경 없음.

## 1. 왜 했나

일정 이동 후 학생·강사·관리자 달력과 수업방이 일치하는지 검사하는 과정에서 강사 화면의 기존 문제 세 가지를 확인했다.

1. 주를 연속으로 고르면 늦게 도착한 옛 응답이 마지막으로 고른 주를 덮었다.
2. 주 이동이 `DATA.week`를 갱신하지 않아 언어 전환·탭 복귀가 옛 주를 다시 그렸다. 자동 갱신은 주를 지정하지 않아 서버의 이번 주로 되돌렸다.
3. 서버는 KST로 주를 계산하지만 화면은 단말 로컬 날짜를 썼다. 한국 월요일 00:05에 UTC·미국 단말은 지난주를 요청했다.

## 2. 무엇을 바꿨나

- 선택한 월요일을 ISO 날짜로 유지한다. `This week`는 KST 주 변경을 따라가고, 다른 주는 자정·월요일을 지나도 선택한 절대 날짜를 유지한다.
- 주 이동, 전체 새로고침, 자동 갱신이 하나의 요청 순서를 공유한다. 늦은 응답과 늦은 실패는 최신 결과를 덮지 않는다. 전체 로드의 늦은 401도 새 성공 이후 화면을 로그인으로 돌리지 않는다. 현재 요청의 401 처리는 그대로다.
- 성공한 주는 `WK_DATA`와 `DATA.week`에 함께 반영한다. 언어 전환·탭 복귀도 같은 주를 그린다. 범위·날짜 입력·바로가기 강조는 실제로 보이는 마지막 성공 주와 함께 움직인다.
- 조회 실패 또는 선택과 다른 주가 오면 이전 내용을 유지하고, 기존 새로고침 버튼으로 재시도하라는 한/영 안내를 표시한다. 다음 갱신도 선택한 목적 주로 재시도한다.
- KST 날짜를 UTC 필드로 계산한다. 날짜 입력도 UTC 자정과 UTC 필드를 짝으로 사용해 단말 시간대와 DST에 의존하지 않는다. 존재하지 않는 날짜는 요청하지 않는다.
- 첫 네트워크 응답 전에는 단말 시계가 정확하다고 가정하지 않고 서버의 기본 이번 주를 받는다. 서버 시각을 받은 뒤에는 기존 `SKEW` 보정으로 주를 계산한다.
- 오래 걸리는 첫 전체 로드를 자동 갱신의 부분 렌더가 추월하지 않게 `DATA`가 있을 때부터 자동 갱신한다.

수업방 식별자·입장 동작·평가 기능·별도의 HOME 1주 수업 기능은 변경하지 않았다.

## 3. 검토하고 쓰지 않은 방법

- 주 이동 함수만 순서 검사: 전체 새로고침/자동 갱신이 여전히 선택을 덮으므로 모든 포털 작성자가 같은 순서를 공유한다.
- 언어 전환 때 새 조회: 이미 받은 선택 주를 저장하면 추가 네트워크 없이 해결된다.
- 매번 `WK_OFFSET`으로 조회: KST 월요일이 지나면 같은 오프셋이 다른 주가 된다. 명시적 선택은 절대 날짜로 보관한다.
- 첫 로드부터 단말 계산 `?week=` 사용: 단말 시계가 한 달 어긋난 경우 서버가 정확한 이번 주를 알고도 잘못 요청한 주를 준다. 첫 기본 주는 서버가 결정한다.
- 실패하면 빈 목록: 수업이 없다는 뜻으로 오해될 수 있어 이전 성공 주와 실패 안내를 함께 남긴다.
- 기존 날짜 검사 문자열 유지: `new Date(dateStr + 'T00:00:00')` 자체가 문제였다. `teacher_page_problem_260807_harness`의 그 한 검사만 실제 날짜 정본 실행으로 교체했다. 기존 날짜 선택/바로가기 검사는 유지했다.

## 5. 확인 범위와 남은 일

- 실제 브라우저 화면 검증은 이 환경의 Chromium/로컬 접속 제약으로 수행하지 못했다. DOM/소스 실행 검사는 실제 픽셀·배치·클릭 가능 여부의 증명이 아니다.
