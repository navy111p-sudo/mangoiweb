# 토큰 서명 시크릿 고정 폴백 제거 (2026-10-04)

## 이유와 승인 범위

관리자 수리 변경을 게시하기 전 검사에서 환경 시크릿이 없으면 코드에 고정된 값을 쓰는 기존 경로가 발견됐다. 사용자에게 수업 입장·일부 로그인·레벨테스트 인증 영향과 설정 누락 환경의 기능 중단 가능성을 설명하고, 고정 폴백 제거 및 정상/누락 상황 재검증 승인을 받았다. 고정값 자체는 이 문서나 테스트에 복사하지 않았다.

## 변경

- `src/room-jwt-secret.ts`의 `requireRoomJwtSecret()`가 설정 판정을 한 곳에서 한다. `ROOM_JWT_SECRET`이 문자열이 아니거나 없거나 비었거나 공백뿐이면 `room_jwt_secret_not_configured` 오류를 낸다.
- 정상 설정값은 앞뒤 공백까지 원래 바이트 그대로 쓴다. 실제 키를 `trim()`해서 바꾸면 이미 발급한 서명이 깨지므로, `trim()`은 공백뿐인지 판정하는 데만 쓴다.
- `api-mango.ts`, `auth-token.ts`, `leveltest-ticket.ts`, `signaling-room.ts`의 네 고정 폴백을 제거했다. `MangoEnv`에는 기존 런타임 바인딩의 선택적 타입 선언을 추가했다.
- 발급 함수는 잘못된 설정에서 실패하고 검증 함수는 기존 실패 반환 계약(`null`, `false`, 거절 응답)을 유지한다. 방 입장 API는 토큰을 반환하거나 발급 이력을 쓰기 전에 실패한다.

## 공유 호출자 전체 영향

| 경로 | 정상 설정일 때 유지하는 계약 | 누락/잘못된 설정 |
| --- | --- | --- |
| UID 로그인 토큰 (`signUidToken`, `verifyUidToken`, `inspectSession`) | UID·선택적 SID, 기본 30일 TTL, HMAC 형식, 기존 세션 정책 | 발급 실패, 검증 실패·세션 invalid |
| 녹화 다운로드 서명 (`signRecDlSig`, `verifyRecDlSig`) | 녹화 1건 바인딩, 기본 6시간 TTL, 기존 서명 형식 | 발급 실패, 검증 false |
| 고스트 참관 서명 (`signGhostObserveSig`, `verifyGhostObserveSig`) | 방 1개 바인딩, 기본 30분 TTL, 기존 서명 형식 | 발급 실패, 검증 false |
| 레벨테스트 티켓·URL·일괄 URL | 신청번호, 기본 120일 TTL, 22자 서명, 기존 URL 형식 | 발급 실패, 검증 null |

| SignalingRoom 선택적 JWT 검증 | `REQUIRE_ROOM_TOKEN === 'true'`일 때만 검증, 기존 역할·방 판정 | 검증 활성화 때 거절; 비활성화 동작은 그대로 |

admin 세션 쿠키, SINGLE_SESSION 정책, 역할·프로토콜, 인증 플래그를 바꾸지 않았다. SignalingRoom 변경은 동일 비밀키 판정을 쓰게 하는 범위뿐이며 WebSocket 프로토콜이나 hibernation 처리는 그대로다.

## 검토 후 하지 않은 것

- 네 곳에 검사를 복제하지 않았다. 판정이 나중에 서로 달라지지 않도록 작은 공유 함수 하나를 썼다.
- 새 키 생성·교체, Cloudflare 설정 변경, 운영 API 호출, 실토큰 발급·검증을 하지 않았다.
- 기존에 설정된 키의 길이·엔트로피 기준을 새로 추가하지 않았다. 이 변경은 공개 고정값으로 대체하는 경로를 없애는 것이며 설정값 자체를 회전하거나 바꾸는 작업이 아니다.
- 기존 `REQUIRE_ROOM_TOKEN` 옵션을 강제로 켜지 않았다.

## 배포 검토 주의

별도 읽기 전용 메타데이터 확인으로 기본·production 워커에 `ROOM_JWT_SECRET`이라는 secret 바인딩 항목이 존재함은 확인됐다. 값은 읽지 않았으므로 비어 있지 않은지, 과거 고정값과 다른지는 이 확인으로 증명할 수 없다. 설정이 잘못된 환경에서는 위 서명 기능들이 실패한다. 이 작업에는 병합·배포 승인이 없으며 배포하지 않았다. 이전 git 기록의 값 제거·실제 키 회전도 이 변경에 포함되지 않는다.
