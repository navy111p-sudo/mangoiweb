# 주간 스케줄 «연기·변경» 드래그 스트레스 하니스 (2026-10-05)

## 왜
사장님: 「샌드박스랑 하니스를 이용해서 수업연기,변경 드래그 테스트를 수백번 해서 문제없을때까지 해줘」
「반드시 학생,교사 수업 스케줄 캘린더에서 잘 이동하고 표시되게 해야해」.
(앞 단계: PR #1374 드래그 확인창에 «연기/변경» 두 갈래, #1375 잠긴 채 끌기)

## 무엇을 만들었나
`test-harness/manual/weekly-drag-stress-browser.mjs` (자동으로 안 돕니다 — 사람이 부릅니다)

    PW_DIR=/tmp/pw node test-harness/manual/weekly-drag-stress-browser.mjs [회차=300] [seed=1]

- 진짜 Worker(`src/index.ts` esbuild 번들) + 메모리 SQLite(D1 모양) + 진짜 Chromium.
  화면은 배포되는 `public/` 그대로, `/api` 만 그 Worker 로. 운영 D1·외부 네트워크 0.
- 씨앗: 강사 3명, 사흘에 수업 12건(일회성·매주반복 섞음) + 그룹 수업 1개(학생 둘).
- 매 회차: 무작위 수업을 **실제 마우스로** 끌어 → 「연기」/「변경」/「아니요」, 잠김/풀림 무작위,
  같은 강사/다른 강사, 가끔 15초 «되돌리기».
- 매 회차 대조(전 수업): ① DB 행 ② 학생 «내 수업»(`/api/class/schedule/mine`)
  ③ 강사 3명의 주간 캘린더(`/api/teacher/portal?week=`) — 제자리 1번·다른 강사엔 유령 0
  ④ 관리자 주간(`/api/admin/schedules`) ⑤ 화면 격자 칸 ⑥ 보낸 요청 내용(연기는 강사를 안 보냄 ·
  그룹은 전부 보냄) ⑦ 겹침이면 서버 거절 ⑧ 찬 칸이면 모달 없이 요청 0 ⑨ 페이지 JS 오류 0.
- 회차가 예외로 끊기면 **FAIL 로 세고** 서버 행으로 모델을 맞춘 뒤 화면을 다시 엽니다
  (크래시가 «검출 0» 으로 위장하지 않게).

# 2부 — 날짜를 바꾸는 «이동 모달» 스트레스 (2026-10-05 같은 날)

## 왜
사장님: 「날짜 바꾸는 이동 모달도 수백번 테스트해줘」. 일간 드래그는 같은 날 안만 옮기므로,
다른 날로 가는 길(우클릭 메뉴의 세 모달)을 따로 돌렸습니다.

## 무엇을 돌렸나
같은 하니스에 «모달 단계» 를 붙였습니다(`WDS_ONLY=modal` 이면 모달만, 기본은 드래그+모달).

    WDS_ONLY=modal PW_DIR=/tmp/pw node test-harness/manual/weekly-drag-stress-browser.mjs 300 <seed>

매 회차: 수업 칸을 **진짜 우클릭** → 셋 중 하나
- 「🔄 시간 변경」 — 7일×시간 격자에서 빈 칸 클릭(`moveSlotStart` → `confirmMove`)
- 「📅 수업 연기」 — 요일 → 10분 칩(`openRescheduleModal('postpone')` → `rscConfirm`)
- 「🔄 수업 변경」 — 요일+10분 칩, 또는 «다른 강사로» 탭(서버 가능 여부로 잠긴 카드)

잠김/풀림·«편집을 켤까요?» 예/아니요·취소·막힌 칸 클릭·15초 되돌리기를 무작위로 섞고,
매 회차 1부와 같은 5방향 대조를 **원래 날과 옮겨 간 날 둘 다** 합니다. 덧붙여
- 격자에서 «열린 칸 = 그 강사가 빈 시간», 칸이 가리키는 날짜가 맞는가
- 10분 칩 «열림 = 20분이 통째로 들어가는 시각»
- 대체 강사 카드 «고를 수 있음 = 그 시간 비어 있음»
- 우클릭 메뉴가 화면 안·커서 옆에 뜨는가
- 잠겼으면 «먼저» 묻는가

## 찾은 제품 결함 4건 (전부 고침 — `admin/weekly-schedule.html`)
1. **우클릭 메뉴가 화면 밖으로 나감** — PC 는 `body{zoom:1.3}` 이라 `position:fixed` 의 left/top 에도
   1.3 이 곱해집니다. `clientX` 를 그대로 넣어 메뉴가 커서에서 30% 밀리고 화면 오른쪽 절반에서는
   **아예 화면 밖**이라 아무것도 못 골랐습니다(실측: 2600px 창에서 x=2478 우클릭 → 메뉴가 viewport 밖).
   → 배율로 나눔.
2. **되돌리기 토스트가 모달 «확인» 버튼을 덮음** — 토스트 z-index 9901 > 모달 9000. 저장 직후 15초 안에
   다음 모달을 열면 확인이 «보이는데 안 눌림»(실측 `undo-toast show intercepts pointer events`).
   우클릭 메뉴(9500)도 그 아래였습니다. → 모달이 열린 동안만 토스트를 그 아래로, 메뉴는 9950.
3. **「시간 변경」 격자가 잠금을 안 물음** — 10/4 정우영 건으로 연기/변경 모달은 «먼저 묻게» 고쳤는데
   이 입구만 빠져, 칸을 고른 뒤에야 「잠겨 있어 저장하지 않았습니다」(요청 0건)가 됐습니다.
   → 같은 확인을 넣음(최종 방어선 `persistSlotMove` 의 잠금 검사는 그대로).
4. **격자가 08시를 줌** — 캘린더는 `GRID_H0..GRID_H1`(09~23시)만 그려서, 08시로 옮기면 저장은 되는데
   **주간·일간 어디에도 안 보였습니다**(학생·강사 화면엔 있음). → 격자도 같은 범위만.

## 제품 결함이 아니었던 것 (하니스 모델을 고침)
- 「다른 강사로」에서 그 강사의 **정확히 같은 시작·길이** 수업이 있으면 서버가 허용합니다 —
  `schedule-conflict.ts` 의 «exact-slot group contract»(그룹 합치기). 화면도 한 칸으로 합쳐 그립니다.
  하니스가 그것을 «겹침» 으로 잘못 예상해 seed 2·4·6 에서 거짓 FAIL 이 났습니다.
  ⚠️ 의도된 규칙이라 손대지 않았지만, **다른 강사로 바꾸다 남의 1:1 수업이 그룹이 될 수 있다**는 뜻이라
  사람이 한 번 판단할 일입니다.
- 화면은 (강사·날짜·시각) 한 칸의 행을 **종류(매주/1회)와 무관하게** 한 슬롯으로 합칩니다 → 하니스 `groupOf` 도 그렇게.
