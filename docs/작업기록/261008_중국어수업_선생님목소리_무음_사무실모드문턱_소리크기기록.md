## 4. 한 일 (사장님 승인 «A+B»)

- **A.** `js/idx-vc-officemode.js` 문턱을 9/8 첫 판 값으로: OPEN_DB 16→12, HYST_DB 8→6, DUCK 0.03→0.08.
- **B.** 다음부터 데이터로 가르게 회선 기록에 다섯 칸:
  - `rx_alevel` — 받은 소리의 상위 10% 세기(dBFS, inbound-rtp `totalAudioEnergy`/`totalSamplesDuration` 4초 차분)
  - `tx_alevel` — 보낸 소리(sender `media-source` = 사무실 모드 가공 «뒤» 실제 송출) 세기
  - `office` — 사무실 모드 켜짐 1/꺼짐 0/모름 NULL
  - `gate_closed` — 그 1분 중 게이트가 닫혀 있던 %(10초 미만 표본이면 NULL)
  - `mic_db` — 게이트 «앞» 마이크 세기(상위 10%)
  - ⛔ dB 칸의 «모름» 은 NULL(‑1 로 적으면 «아주 큰 소리» 로 읽힘). 서버는 무인증 본문이라 범위로 자른다.
  - ALTER 로만 붙임(CREATE 가 두 벌이라) — **첫 로그가 들어와야 칸이 생긴다.**
- `index.html` 의 `?v=` 두 개를 같은 글자 수로(20→21, 8→9) — 첫 화면 예산 0바이트.

## 5. 다음 사고 때 읽는 법

```sql
SELECT strftime('%H:%M',ts/1000,'unixepoch','+9 hours') t, uid, rx_alevel, tx_alevel, office, gate_closed, mic_db
FROM vc_quality WHERE room = 'class-…' ORDER BY ts;
```

- 교사 `tx_alevel` 이 낮고(≈ -60 이하) `gate_closed` 가 높다 → 게이트·마이크 쪽.
- 교사 `tx_alevel` 정상인데 학생 `rx_alevel` 도 정상 → 학생 기기 재생 쪽(볼륨·출력 장치).
- 교사 `mic_db` 자체가 낮다 → 마이크가 멀다/작다(AGC off 영향).
