# 관리자 «쉬운 사용법» 26장 — 핵심 업무 5장에 화살표·번호 (2026-10-09)

## 왜 했나
사장님 지시: 「더 자세히, 업그레이드한 캡처로 — 수업 스케줄링·결제 확인·직원 급여·학생 결제를 특히 강조해서 화살표로」.
옛 21장은 그림이 작고 «어디를 누르는지» 표시가 없었습니다.

## 무엇을 바꿨나
- 21장 → **26장**. 「찾기」 다음에 **핵심 업무 묶음 6장**:
  흐름 한 장(수강신청 → 스케줄 → 연기·변경 → 학생 결제 → 강사 급여) + 큰 그림 5장(focus).
- **focus 장**: 왼쪽 큰 그림(63%) 위에 주황 테두리 + 빨간 번호 원 + 화살표, 오른쪽에 같은 번호의 설명.
  - 표시는 찍을 때 실제 요소 자리(px)를 `.shots/marks-<이름>.json` 에 남기고 build 가 sharp 로 그립니다(손으로 좌표를 안 적음 — 화면이 바뀌어도 다시 찍으면 따라옴).
  - 번호 원은 다른 표시를 안 가리는 자리를 고르고, 넓게 자른 그림일수록 표시를 크게 그립니다.
  - 못 찾은 표시는 `null` + 경고(조용히 빠지지 않게).
- **견본 데이터**(`sample-data.mjs`): 표가 비어 있으면 «어디를 보라» 가 성립하지 않아 지어낸 학생 8·강사 5명으로 채웠습니다. 실제 개인정보 0(이름은 `샘플`·영문 가명, 아이디는 `sample_*`).
- 옛 «결제» 장(12)은 핵심 업무 장과 겹쳐 지웠고, 제목의 ①~⑫ 를 걷어 냈습니다.
- 장 번호(큰 배지)는 `stepNo()` 가 저절로 매기고, **차례 장도 같은 번호**를 씁니다(따라하기 장이 아니면 점). 흐름 장 «자세히 → 04번 (8쪽)».
- 차례 장이 아래로 넘치던 것을 줄 간격을 줄여 한 화면에 넣었습니다.
- 뷰어 `adm-s18.js`: 제목 26장, 그림·PDF 주소에 `?v=26a`(그림은 7일 캐시라 같은 이름으로 갈아 끼우면 옛 그림이 보임), `admin.html` 은 `adm-s18.js?v=7` 과 PDF 링크 두 곳만.

## 검토했다가 버린 것
- **배포 화면을 직접 찍기** — 프록시가 `mangoi.ai` 를 막고, 찍히더라도 실제 학생 이름·금액이 그림에 남아 공개 저장소에 올라갑니다. 로컬 서버 + 견본 응답으로 «배포되는 그 파일» 을 찍었습니다.
- **표시 좌표를 slides.mjs 에 손으로 적기** — 화면이 1px 만 바뀌어도 화살표가 엉뚱한 곳을 가리킵니다.
- **흐름 장의 «자세히 → N쪽» 만 두기** — 그 쪽의 큰 번호(04)와 숫자가 달라 헷갈려 «04번 (8쪽)» 으로 둘 다 적었습니다.

## 확인한 방법
- `node build.mjs` — «adm-s18.js 제목도 같습니다 (26쪽)».
- 07·08·09·11·12·03·02 장을 눈으로 확인(번호·화살표 자리, 넘침).
- `node test-harness/run.mjs --fast` → 실패 26건, **`origin/main` 사본에서도 같은 26건**(이 컨테이너의 환경 사유) — 새로 생긴 실패 0.
- ⚠️ 배포된 화면에서 26장이 실제로 뜨는지는 **사람이 관리자 화면 «쉬운 사용법» 을 열어 봐야** 확정입니다.

## 남은 것
