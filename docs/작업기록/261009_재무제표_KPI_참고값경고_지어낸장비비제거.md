## 1. 왜 했나

같은 날 회계 화면 점검(월간 리포트 «정산 대기» · 지난달 손익 1~3일 «확정 아님» · 연간결산 귀속월)을 하면서,
분기·연간·월간 리포트에는 있는 «이 기간 자료가 온전한가» 표시(`coverageOf`)가
**KPI 경영지표와 재무제표에만 없었습니다.** 그래서

- 진행 중인 이번 달이나 통장·카드 연동 전 달을 골라도 반쪽 숫자가 **확정값처럼** 보였고,
- 재무제표 현금흐름표의 투자활동이 **「장비 구매 = 매출 × 2%」라는 근거 없는 추정**이었고,
- 서버가 만든 안내문(`notes` — 재무상태표 «완전한 표 아님», 시산표 차대 일치 등)이 **화면·PDF 어디에도 안 나왔고**,
- 재무제표 월 선택칸이 HTML 에 `2026-04` 로 박혀 있어 **열 때마다 4월**이 나왔습니다.

KPI 쪽은 «활동 학생 수» 가 `attendance.user_id`(실접속 시 기기 임시번호)로 세어져
선생님·관리자·기기번호가 섞여 있었습니다(2026-09 실측 762 → 학생만 531명). 그래서 ARPU 가 낮게 나왔습니다.

## 2. 무엇을 바꿨나

### #1487 KPI 경영지표 (`src/accounting-reports.ts` `kpiReport`, `public/js/adm-core.js`)
- 응답에 `coverage`(분기·연간·월간과 같은 `coverageOf`)를 싣고, 화면이 온전하지 않은 달이면 경고 띠 + 이익률·ROI·순이익에 «참고값» 표시.
- `monthActiveStudents`: 계정(`account_uid`, 카페24 씨앗은 `user_id`) 기준으로 **학생만** 셈.
- «수업시간 0» 건수에서 카페24 예약 씨앗(`c24-*`, 원래 시간 칸이 없음) 제외 — 2026-09: 3,858 → 297건.

### #1490 재무제표 (`src/accounting-reports.ts` `statementReport`, `public/js/adm-core.js`, `public/admin.html`)
- `coverage` 추가 — 분기는 세 달 중 **가장 나쁜 달**을 따르고, 온전하지 않은 달마다 이유를 적음. 화면·PDF·엑셀 모두 경고.
- 서버 `notes` 를 화면·PDF 에 그림(`_fsExtras`·`_fsNotes` — 화면과 PDF 가 같은 함수).
- 현금흐름표 투자활동: `매출 × 2%` → **0 + «자료없음 (구매·자산 기록이 없어 계산하지 않음)»**.
  «당기 현금 변동» 을 «(장부 기준 계산)» 으로 이름을 바꾸고, 아래에 **통장 기준 실제 현금흐름(신한 계좌, 내부 자금이체 제외)** 참고 섹션 추가(손익계산서의 같은 참고 섹션과 같은 값 `monthCash`).
- 월 선택칸: **지난달**로 시작. 사람이 이미 바꾼 값(`value !== defaultValue`)은 안 건드림.
- `adm-core.js` `?v=2610105-fscov` 로 올림(원장 `test-harness/asset-versions.json` 함께 커밋).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **온전하지 않은 달은 아예 안 보여 주기** → 버림. 이번 달 진행 상황을 보려는 경우도 있어, 숫자는 그대로 두고 «참고값» 이라고 말하게 했습니다(다른 리포트와 같은 방식).
- **장비비를 다른 비율로 «더 그럴듯하게» 추정** → 버림. 자산대장·구매기록이 없어 어떤 비율도 근거가 없습니다. 모르는 값은 0 + «자료없음» (재무상태표의 유형자산과 같은 처리). 대신 실제 통장 흐름을 옆에 두어 «진짜로 돈이 얼마나 나갔나» 는 볼 수 있게 했습니다.
- **coverage 판정을 재무제표용으로 새로 작성** → 버림. 정본 `coverageOf` 하나를 재사용해 리포트마다 답이 갈리지 않게 했습니다.
- **월 기본값을 «이번 달»** → 버림. 이번 달은 진행 중이라 언제나 반쪽 숫자(=참고값)입니다.

## 5. 남은 것 / 주의할 것

- 투자활동·재무활동(차입/상환)은 기록이 생기기 전까지 계속 0 입니다 — «0 = 지출 없음» 이 아니라 «모름» 입니다.
- 현금흐름표 «장부 기준» 과 «통장 기준» 은 원래 다릅니다(장부에 안 잡힌 매출, 수업료가 아닌 입금 등). 둘을 맞추려고 한쪽을 고치지 마세요.
- `coverageOf` 를 바꾸면 월간·분기·연간·KPI·재무제표가 **함께** 바뀝니다.
- 활동 학생 수가 762 → 531 로 줄어든 것은 데이터 감소가 아니라 **세는 기준이 바로잡힌 것**입니다(ARPU 는 그만큼 올라감).
