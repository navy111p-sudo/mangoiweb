## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

시안 3개를 사장님께 보여 드리고 A안을 받았습니다(시안 페이지: claude.ai 아티팩트, 사장님 계정에만 있음).

- **B안: 버튼마다 별도 칸(열)** — 찾기는 쉽지만 이미 20칸인 표가 4칸 더 넓어져 노트북에서 가로 스크롤이 길어짐. 버림.
- **C안: «관리 ▾» 드롭다운 하나** — 가장 깔끔하지만 자주 쓰는 스케줄·연기가 한 번 더 눌러야 보임. 버림.
- **A안(채택)** — 버튼이 «그 버튼이 바꾸는 값» 옆에 있어 의미가 맞고, 표는 오히려 한 칸 줄어듦.

구현 중 고른 것:
- ⏸ 연기·변경을 예약이 없는 학생에게 감춤 — 미룰 수업이 없는데 누를 수 있는 버튼을 주지 않기 위해. 📅 스케줄은 수업을 «넣는» 입구이기도 해서 늘 남김.
- `<button>` 이 아니라 `<a>` — `admin-inline-c.css` 의 `details.menu-card button` 전역 규칙이 인라인 크기를 무시하고 큰 파란 알약으로 만듦(CLAUDE.md 2장, 같은 표의 「수강신청」 칸과 같은 이유).
- ⏸ 링크의 클래스는 `class="sm-move-go"` **한 개 그대로** — `class_move_anywhere_harness` 가 그 모양을 찾음. 모양은 `.sm-acts a` 로 줌.
- 예약 칸 버튼 두 개가 처음엔 두 줄로 쌓여(칸 168px) 184px + `white-space:nowrap` 으로 한 줄에 맞춤(브라우저 실측으로 확인).

- 로컬 서버 + 크로미움(playwright, API 스텁 3명): 한 줄 높이 **182px → 104px**(예약 있는 줄, `zoom 1.3` 포함 값). 버튼 5개 모두 `elementFromPoint` 로 «맨 위» 확인, 머리글에 «상세보기» 없음 확인. 스크린샷으로 눈으로도 확인.
