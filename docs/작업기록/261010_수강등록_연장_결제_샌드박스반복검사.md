# 수강 등록·연장·결제 — 샌드박스 반복검사로 찾은 결함 5종 수리

> 2026-10-10 · 사장님 지시 「학생 수업 등록과 연장과 수업 결제에 오류가 없을 때까지 수백 번 하니스와 샌드박스로 테스트 계속 해줘」

## 1. 무엇을 만들었나

`test-harness/enroll_pay_renew_fuzz_harness.mjs` — **실제 Worker 핸들러**(`api-pay.ts`·`enroll-ops.ts`)를
Node `--experimental-strip-types` 로 그대로 돌리고, D1 은 `node:sqlite` 위의 얇은 껍데기(호출마다 한 박자 쉬어
동시 요청이 실제로 엇갈리게), 토스는 가짜 서버로 둡니다. 세상(학생·강사·기존 수업·공휴일)을 무작위로 만들고
조작(상품결제·신규등록·연장·같은 자리 동시결제·날짜 흐름·자동연장 청구)을 무작위로 섞어 돌린 뒤 **매 조작마다 불변식**을 잽니다.

결제 방식도 섞습니다: 정상 · 연타(같은 주문 confirm 두 번) · 재시도 · 웹훅이 먼저/동시에 · 카드 거절 · 네트워크 끊김 · 금액 위조 · 가상계좌.

| 불변식 | 뜻 |
|---|---|
| I1 | 토스가 DONE ⇔ DB 가 paid |
| I2 | 결제된 주문마다 수강 기록 1건, 미결제는 0건 |
| I3 | 산 회차 수 == 생긴 수업 수 |
| I4·I5 | 강사·학생 수업 겹침 없음(날짜 + 매주 반복) |
| I6·I7 | 공휴일에 수업 없음 · 시작일 전 수업 없음 |
| I8 | 견적 금액 == 주문 금액 |
| I9 | 연장은 마지막 수업 다음부터 · 같은 요일·시각·강사·길이 |
| I10 | 연타는 멱등 · 실패한 결제는 아무것도 안 만듦 · 이중청구 없음 |
| I11 | 충돌 검사가 예외를 삼키지 않음(삼키면 «충돌 없음» 으로 통과) |

`FUZZ_WORLDS`·`FUZZ_OPS`·`FUZZ_SEED`·`FUZZ_ONLY`(한 세상만, 경고 `FUZZ_WARNS` 줄) · `FUZZ_MUTATE=1`(변이시험).

## 2. 찾아서 고친 결함

| # | 증상 | 원인 | 고침 |
|---|---|---|---|
| ① | 결제 «확인» 연타 시 **돈은 나갔는데 주문이 failed** | 두 번째 confirm 이 토스 `ALREADY_PROCESSED_PAYMENT` 를 받고 실패 처리하면서 이미 paid 인 주문을 failed 로 덮음 | 그 코드면 토스 주문을 다시 조회해 DONE·금액 일치면 성공 처리 + 실패/금액불일치 UPDATE 는 `status NOT IN ('paid','await_deposit')` 일 때만 |
| ② | confirm·웹훅이 동시에 오면 수강 활성화 두 번 시도 | paid 표시가 무조건 UPDATE | `markOrderPaid()` 조건부 선점 — 이긴 쪽만 활성화 |
| ③ | 같은 강사·같은 자리를 **동시에 결제**하면 늦은 쪽 수업 0회(돈은 받음) 또는 강사 겹침 | 둘 다 «비어 있음» 으로 읽고 같은 날짜 선택 → `INSERT OR IGNORE` 가 조용히 버림 | 넣은 «뒤» 다시 재서, 남과 겹친 내 줄(늦게 생긴 쪽)만 물리고 모자란 회차를 다시 계획(최대 4회) |
| ④ | 연장이 겹친 학생에게 **수업 0회** | 충돌 조회 창이 `회차×2` 고정이라, 창 안이 다 막히면 창 «밖» 날짜를 «비었다» 로 가정해 골랐고 그 날짜가 이미 차 있었음 | `enrollFreeDates()` — 고른 날짜는 전부 «조회한 창 안», 모자라면 창을 2배씩 넓혀 다시 잼 |
| ⑤ | 자동연장 주문이 충돌 검사 없이 날짜를 잡음 | `chargeSubscriptionOnceInner` 가 `timesMin` 을 안 넘겨 `enrollConflicts` 가 예외 → catch 가 삼켜 «충돌 없음» | 연장 주문과 같은 계산으로 `timesMin` 전달 |
| ⑥ | **자동결제 이중청구** | 스윕 둘이 같은 행을 SELECT → 첫째가 청구·선점해제한 «뒤» 둘째가 낡은 행으로 선점 성공 | 선점 직후 `last_billed_at`·`next_billing_at` 을 다시 읽어 «내가 본 값 그대로» 일 때만 청구(재조회 실패 = 청구 안 함) |

## 3. 확인

- 기본(40세상×30조작 = 1,200조작) + 다른 씨앗 6개 → **총 8,400조작 · 결제 완료 약 5,700건 · 생긴 수업 약 15.8만 회차 · 불변식 위반 0건**
- 변이시험(`FUZZ_MUTATE=1`) — 고친 자리를 하나씩 되돌리면 **5종 전부 실제로 잡힘**
  (①은 두 겹이라 «둘 다» 되돌린 짝으로 시험 — 하나만 되돌리면 다른 겹이 막는 것이 정상)
- `tsc --noEmit` 통과

## 4. 버린 방법

- **충돌 조회 창을 크게 고정(×10)** — 창 밖 가정 문제는 그대로 남음. 넓히는 «반복» 이 맞음.
- **선점 SQL 에 스냅샷 조건을 넣기** — `billing_idempotency_harness` 가 그 SQL 모양을 실제로 돌려 검사하고 있어 함께 깨짐. 선점은 그대로 두고 «선점 뒤 재조회» 로 같은 효과.
- **주문 단계에서 자리를 예약(잠금)** — 결제 안 하고 나간 주문이 자리를 묶음. 결제 후 검증 + 물림이 더 단순.

## 5. 남은 것(사람이 정할 일)

- 수강 «미리보기»(`POST /api/pay/enroll/check`)는 아직 옛 고정 창입니다 — 화면 안내만 틀릴 수 있고 결제 뒤 생성은 새 판정을 탑니다.
- 관리자 수강신청 확정 경로(`enroll-activate.ts`)는 이번 샌드박스 범위 밖입니다.
