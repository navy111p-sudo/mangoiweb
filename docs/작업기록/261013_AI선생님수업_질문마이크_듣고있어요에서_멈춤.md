# A.i 선생님 수업 — 「선생님께 질문」 마이크가 «듣고 있어요» 에서 멈춤 (2026-10-13)

## 왜 했나
사장님 제보(두 번): 「🎤 한국어로 말하기 · 🎤 영어로 말하기 둘 다 작동 안 돼」.
화면은 「🎙 듣고 있어요… 말을 마치면 바로 물어봐요」에서 그대로 멈추고 아무 일도 없었습니다.
(두 번째 제보 화면은 아직 이 수리가 배포되기 전의 옛 코드입니다.)

## 원인 (코드에서 따라간 것 — 실제 크롬 음성 서버로는 못 쟀습니다)
1. **「자동 말하기: 켬」이면 수업 마이크(브라우저 음성인식)가 이미 듣는 중**입니다.
   질문 버튼은 그것을 `abort()` 하고 **곧바로** 새 음성인식을 `start()` 했습니다.
   크롬은 음성인식을 한 번에 하나만 돌리고 `abort()` 는 비동기라, 새 것이 **이벤트 없이 멈춥니다** →
   「듣고 있어요」에 영영 머뭅니다(에러·안내 없음).
2. 그 화면에는 **안전망이 없었습니다** — 시작 신호가 안 와도, 서비스 오류가 나도 «녹음 + 서버 Whisper» 로
   넘어가는 길이 없었습니다(웜업에는 있는 길).

## 고친 것 (`public/ai-class.html` 한 파일 + `js/mangoi-voice-input.js?v=5` 싣기)
- 끄라고 한 음성인식이 **전부 끝날 때까지 기다린 뒤** 켭니다(`recQuiet` — 버튼을 연달아 눌러도 앞서 끈 것을 다 기다림).
- 질문 마이크를 켜는 중·듣는 중에는 자동 말하기가 수업 마이크를 다시 켜지 않습니다(`armTalk` 가드).
- **안전망**: 4초 안에 시작 신호가 없거나 · network/service 오류이거나 · 아무 신호 없이 끝나면
  → **녹음 + 서버 Whisper**(`/api/voice/transcribe`, 한국어 버튼 = `ko`, 영어 = `en`)로 한 번 더 받습니다.
  음성인식이 아예 없는 브라우저(앱 WebView 등)도 같은 길로 갑니다.
- 마이크 권한 거절·«말이 없었다» 는 그대로 사실대로 말합니다(⛔ 그때는 녹음으로 넘어가지 않음).
- ⛔ 음성인식과 녹음을 동시에 열지 않습니다(안드로이드 일부는 오디오 입력이 하나뿐) — 끝낸 뒤 녹음.

## 검토했다가 버린 것
- **질문 마이크를 처음부터 Whisper 로만**: 한·영 섞인 질문에 강하지만, 서버 왕복으로 느려지고
  브라우저 인식이 잘 되는 대다수 환경까지 바꿉니다 → 폴백으로만 둠.
- **자동 말하기를 질문 상자 열 때 꺼 버리기**: 사람이 켠 설정을 몰래 바꾸게 됨.
