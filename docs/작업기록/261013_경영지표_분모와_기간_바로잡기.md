# 경영 지표 — 분모와 비교 기간 바로잡기 (2026-10-13)

## 왜 했나
사장님 화면(관리자 › 경영 지표)이 이렇게 말했습니다.
- 활동 학생 **28,825명** · 미납 **28,771명(99.8%)** · 2주+ 결석 **2,806명**

- AI 브리핑 「출석률 0% … **123명 중 28825명이 출석**」

## 원인 (코드에서 확인)
1. «활동 학생» = `students_erp` 명부 전체(카페24가 밀어 넣는 29,553행). 실제 수업이 있는 학생이 아닙니다.
2. «미납» = 그 명부에서 «35일 안에 결제 기록이 없는 사람». 우리 결제표(`student_payments`)에 결제가 들어오는 학생 자체가 적어서 «기록 없음» ≠ «안 냄».
3. 증감 = 이번 달 13일치 대 지난달 **한 달 전체** → 매달 초 늘 빨간불. 비교 대상이 0 이면 «+100%» 로 지어냈습니다.
4. «이번 달 출석» 타일 = `point_rule_log` 의 **출석 포인트 지급 건수**(출석이 아님).
5. 브리핑 출석률 = 어제 123명 / 명부 28,825명 → 0%. AI 가 그것을 뒤집어 읽었습니다.
6. 달 경계를 Worker 의 UTC 로 잘라 KST 와 9시간 어긋났습니다.

## 바꾼 것 — 정본 `cloudflare-deploy/src/kpi-active.ts` 하나
- **활동 학생** = 최근 30일 ⓐ 살아 있는 수업 예약(LMS·시드 자리표시 제외) ⓑ 카페24 예약 씨앗(c24-*) ⓒ 실제 화상방 접속 — 셋 중 하나.
- **미납** = 결제 기록이 «한 번이라도 있는» 활동 학생 중 35일 넘게 결제 없음(분모를 함께 표시).
- **14일 수업 기록 없음** = 활동 학생 중 최근 14일 attendance 0줄.
- **이번 달 수업 기록** = attendance (계정, 날짜) 한 번 · 강사 제외. 카페24 예약이 섞여 «출석» 이 아니라 «수업 기록» 이라고 부릅니다.
- **증감** = 지난달 «같은 날수» 대비. 비교 대상 0 이면 표시 안 함(null).
- **브리핑**: 같은 정의 사용 + 숫자가 상식에 안 맞으면(미납 > 활동 등) AI 를 부르지 않고 「숫자 확인 필요」. 옛 정의로 만든 같은 날짜 브리핑은 한 번 다시 만듭니다(`stats.def`), 화면 캐시 키 v1→v2.
