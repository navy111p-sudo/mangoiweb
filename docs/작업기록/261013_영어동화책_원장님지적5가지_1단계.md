원장님들이 A.i 영어 동화책 샘플(4편 — 빨간 우산·생일 케이크·로봇 춤·보물 지도)을 보고 지적한 5가지.

## 한 것 (4편 공통)
1. **응용문장 자동 고치기** — 「완성하기」를 누르면 `js/story-kit.js` 의 `StoryKit.review()` 가 구조·철자를 봅니다.
   - 문법(동사 원형 자리에 주어·-s·-ing·to, 주어-동사 일치, be 일치, -ing 앞 be 빠짐)이 틀리면 **도장을 막고** 고친 문장·이유(한/영)를 보여 줍니다.
   - 「✏️ 고친 문장으로 바꾸기」 → 「🔊 내 문장 듣기」를 누르면 도장. 직접 고쳐 다시 「완성하기」도 됩니다.
   - 철자만 틀리면 도장은 그대로 주고 «확인해 보세요» 만 말합니다.
   - 규칙 기반(결정론) — LLM 아님. **모르면 안 고칩니다**: 철자는 4글자 이상·글자 바꿈/빠뜨림·후보 하나일 때만, 주어는 대명사·한정사+명사·이름/가족 호칭만.
   - 사전 `js/story-dict.js`(4,805낱말)는 `scripts/build-story-dict.mjs` 가 `word-pictures.json`+`stopwords.json` 에서 만듭니다.
   - StoryKit 이 없으면(로드 실패) 예전 동작.
2. **심화 질문의 한국어 번역 줄 제거** + 학생 화면의 EN/한국어 전환 버튼 제거(언어 고정 ko). 데이터(`q.qko`)는 남김(기존 하니스가 요구).
3. **근거 설명만 한국어**(`q.why[0]`).
4. **뜻 맞히기 정답 노출** — 핵심단어 카드의 뜻을 «👀 뜻 보기» 뒤로 감춤. 게임을 끝내면 열림. 엿본 낱말은 게임에 한 번 더(`wqAgain`). 보기에 다른 편의 뜻 1개를 섞어 «같은 편 6개 중 소거» 를 막음(`poolFor`).
5. **요점정리 영어 글로** — 다 맞히면 요점정리 카드(문장 전부 + 누가/문제/해결 틀 + 문장별 읽기 강조)가 남음.

## 2단계 (같은 날, 사장님 「2단계도 진행해줘」)

### 한 것
- **AI 한 번 더 보기** — 규칙 점검을 통과한 문장만 AI 가 봅니다(정본 `src/story-correct.ts`).
  - 주소: `POST /api/ai/write-history { action:'story_fix' }` — 이미 등록된 경로의 «비어 있던 POST» 라 `src/index.ts` 무수정. 모르는 action 은 400.
  - AI 답은 `verifyStoryFix` 를 통과해야만 보여 줍니다: 영어만 · 낱말 수 ±2 · 새 낱말은 학생 낱말의 변형(철자·동사 변화)이나 기능어만 · 새 낱말 ≤ max(2, 절반) · 동사로 시작할 칸이 주어로 시작하지 않음. 탈락이면 `unverified` → 화면은 «지금은 확인하지 못했어요».
  - 고친 이유는 AI 가 아니라 결정론 설명기(`correction-reason.ts`).
  - 상한: 기기당 하루 30회(`localStorage mangoi_story_dev`) + 회선(IP)당 300회. 부르기 «전» 에 셈. 못 세면 막지 않음(fail-open).
  - 화면: AI 가 고칠 곳을 찾으면 규칙 때와 같은 «바꾸기 → 듣기» 도장, 또는 «내 문장 그대로 낼래요»(막다른 길 없음, 「AI 도 틀릴 수 있어요」 안내). 고칠 곳이 없으면 «🤖 AI 선생님도 확인했어요», 못 보면 «지금은 하지 못했어요», 상한이면 «오늘 30번을 다 썼어요» 와 함께 도장.
  - 그사이 학생이 고쳐 쓰면 늦게 온 AI 답은 버립니다(`WSEQ`).
- **강사 화면 기록** — 도장을 받은 문장을 로그인 학생(토큰 일치)에 한해 `story_write_log` 에 남기고(`action:'story_log'`, 하루 60건), 강사 «🤝 인수인계» 카드에 «📖 동화책 바꿔 쓰기 (7일): N문장 · 고친 곳 M개 — 최근 문장(고치기 전 → 후)» 한 줄.
  - 게스트·토큰 불일치는 저장 안 함(`saved:false` 로 정직하게). 표가 아직 없으면 인수인계는 «0» 으로 보고 수업 목록을 막지 않음.

- 학생 화면에 AI 기록 노출: 원장님 요청은 «선생님이 일일이 확인하기 어렵다» 라 강사 화면에만.

### 함정 대조(trap-check)로 고친 것
- 기기 상한에 막힌 요청이 회선(IP) 카운터를 먹던 것 → 두 카운터를 «먼저 다 읽고» 둘 다 허락될 때만 올림(`bumpAll`). 학원 한 회선의 공용 300회를 한 아이가 소진하지 않게.
- `AbortController` 없는 옛 WebView 에서 «보고 있어요…» 에 멈출 수 있던 것 → `Promise.race` 타이머가 직접 끝냄.
- 둥근 따옴표(don’t)와 곧은 따옴표(don't) 차이를 «고칠 곳» 으로 띄우던 것 → 서버·화면 둘 다 정규화.
- 기다리는 동안 «완성하기» 를 또 누르면 AI 를 두 번 부르던 것 → `WBUSY`.
- ⚠️ 남은 것: 한 요청이 모델을 최대 2번 부름(첫 모델 실패 시) — 실제 호출 상한은 기기당 60·회선당 600. 새 D1 표 `story_write_log` 가 운영 DB 에 생김(로그인 본인·하루 60건).
