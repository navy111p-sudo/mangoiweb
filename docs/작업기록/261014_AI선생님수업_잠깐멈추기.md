# A.i 선생님 수업 — ⏸ 잠깐 멈추기 (2026-10-14)

## 왜 했나
사장님 제보: «AI 선생님이 계속 말하고 진행되니 빠르다. 내일 세미나에서 설명하려고 켜 두면 AI 가 계속 말할까 걱정된다.»
실측(코드): 선생님이 한 문장을 다 읽으면 `run({type:'spoken'})` 이 저절로 다음 단계로 넘어갔고, 이것을 멈출 버튼이 없었다.
- 「자동 데모 멈춤」은 학생 대답 대신 넣기만 끈다(선생님은 계속 말함)
- 「소리 끔」은 소리만 끄고 진행은 계속된다
- 「끝내기」는 수업 자체를 끝낸다

## 한 것 (`cloudflare-deploy/public/ai-class.html` 한 파일)
- 아래 버튼줄에 **⏸ 잠깐 멈춤** 버튼 추가. **스페이스바**로도 켜고 끔(글자 칸·버튼·링크에 포커스가 있으면 그쪽 동작이 우선)
- 멈추면 선생님 말·자동 진행·노래·배경음악·마이크·자동 데모·타이머가 **함께** 멈추고, 버튼줄 위에 «⏸ 잠깐 멈췄어요 · ▶ 계속하기» 띠가 뜬다
- 계속하면 **끊긴 문장을 처음부터** 다시 읽고 이어 간다(노래는 처음부터 다시). 멈춘 시간은 수업 시간에 안 들어간다
- 시작 징글(1.6초) 도중에도 멈출 수 있다. 레슨을 바꾸거나 끝내면 멈춤이 저절로 풀린다(옛 문장을 다시 읽지 않음)
- 정본은 `pauseSet()` 하나, 기다리는 쪽은 `waitRun()` 을 지난다. 말하기 정본은 `speakRaw()`(멈춤에 끊기면 다시 읽음) → `speakOnce()`

## 함정 대조가 찾아 고친 것 (같은 날)
첫 판은 «말(speakRaw)» 에서만 기다려서, 말 «밖» 에서 진행하는 길이 열려 있었다.
- `run()` 의 말하기 루프가 자막·배경음악을 `speakRaw` **앞** 에서 정함 → 징글이 끝나는 순간이나 «말 안 함» 버튼으로 `run()` 이 불리면 멈춘 채 배경음악이 켜졌다. 루프 첫머리에서 `waitRun()`, 징글은 `.then(waitRun)`, sim 보기·입력·🎵 버튼에 `paused` 가드
- 노래 1절 도중 멈추면 `speakRaw` 의 재읽기가 끊긴 줄을 반주 없이 혼자 먼저 읽었다 → 노래 안에서는 한 번짜리 `speakOnce`
- `MU.stopAll()` 은 이미 예약된 음(노래 가락·징글)을 못 끊었다 → 소리 모듈에 `cut()`(master·bgmBus 를 새로 갈아 끼움, `?v=2`). ⛔ `ctx.suspend()` 는 안 씀 — 시계가 멈춰 풀 때 남은 음이 다시 울린다
- 반복 시험 320회 중 2회: 노래 도중 멈췄다 풀면 노래가 남은 박자(최대 ~4초)를 다 기다린 뒤에야 다시 시작해 그동안 조용했다 → 소리 모듈 `song()` 의 박자 대기를 `stopAll()` 이 곧바로 깨우고(`songWake`), 줄을 «부르는 중» 에 끊겼으면 박자 대기에 들어가지 않는다(그다음 320회에서 1회 남았던 경로)
- 계속할 때 배경음악을 늘 `talk` 로 켜던 것 → 멈추기 직전 음량(`model`·노래 중 `off`)으로
- 🪤 수리 중에 한 줄 주석이 `return; }` 를 삼켜 **페이지 스크립트 전체가 문법 오류**가 됐는데 자동 하니스는 초록이었다(브라우저 하니스가 잡음) → 자동 하니스 ⓪절에 «인라인 스크립트가 문법상 살아 있는가» 추가

## 검토했다가 버린 방법
- `speechSynthesis.pause()/resume()` — 크롬에서 믿을 수 없어 cancel + 다시 읽기로 함
- «한 걸음씩 모드»(한 문장마다 멈춤) — 이번엔 멈추기만. 필요하면 다음에 토글로 덧붙임
