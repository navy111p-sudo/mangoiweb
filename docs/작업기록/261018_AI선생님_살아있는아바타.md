# A.i 선생님(ai-class) 얼굴을 공용 살아 있는 아바타로 — 2026-10-18

## 왜 했나
사장님 요청: 「A.i 선생님도 A.i 말하기·A.i 친구의 Emma 선생님과 똑같이 입모양과 영어 단어가 일치하고, 눈을 깜빡이고 눈썹도 움직이고 머리도 조금씩 움직이게(살아 있는 것처럼). A.i 친구와 말하기의 아바타를 가져오면 될 것 같다.」
그전 `ai-class.html` 의 선생님 칸은 정지 사진 3장(닫힘·중간·벌림)을 글자 수 타이머로 번갈아 보여 주는 방식이라 실제 소리와 입이 안 맞았고 눈·머리는 움직이지 않았습니다.

## 무엇을 했나
- 선생님 칸을 공용 모듈 `js/mango-avatar.js`(warmup·ai-friend 와 같은 파일, 같은 `?v=`)의 캔버스로 바꿈. 캐릭터 `emma`.
  - 서버 음성(<audio>)이 나갈 때 `MangoAvatar.attach(audio)` 로 물려 **입모양 분석(AvatarVisemes) + 소리 크기** 로 입을 움직임. 재생 전에 `prepare()` 를 최대 1.2초 기다림(첫 문장이 너무 늦지 않게).
  - 눈 깜빡임·눈썹·숨쉬기·머리 기울임은 모듈이 쉬는 동안에도 계속 함.
- 모듈 v14 — 새 API `MangoAvatar.mouth('closed'|'medium'|'wide'|null)`: 서버 음성이 아니라 기기 목소리(speechSynthesis)·소리 꺼짐일 때 화면이 정한 입 단계를 그대로 그림(그때는 오디오가 없어 소리로 입을 못 맞춤). `plainStop()` 이 함께 지움. `attach()` 가 성공 여부(true/false)를 돌려줌. `window.__mgAvatarBaseW` 로 캔버스 폭(200~800) 선택 — 선생님 칸이 커서 512.
- 오디오 문맥은 사용자 첫 조작(pointerdown·keydown·touchstart, capture)에서 만듦(자동재생 정책).
- 모듈을 못 받으면 예전 정지 사진으로 떨어짐(`.av-off`).
- 나머지 5개 화면(warmup·ai-friend·speech-coach·speech-coach-cn·review-quiz-cn)의 `mango-avatar.js?v=33 → 34`.

## 검토했다가 버린 것
- 정지 사진 3장을 소리 크기로만 바꾸기 — 입은 소리와 맞지만 눈·머리는 여전히 멈춤. 요청이 «Emma 와 똑같이» 라 공용 모듈을 그대로 씀.
- prepare 를 끝까지 기다리기 — 워커가 늦으면 첫 문장이 수 초 늦어져 1.2초로 자름(그 뒤엔 소리 크기 립싱크로 떨어짐).
