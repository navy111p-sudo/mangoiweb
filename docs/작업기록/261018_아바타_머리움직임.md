## 2. 어떻게 (js/mango-avatar.js v13, `?v=32`)

1. **화면 밖 캔버스(comp)** 에 얼굴을 예전과 똑같이 그립니다(입모양·눈 깜빡임 그대로).
   comp 는 **두 개**입니다 — 초록 배경을 지우는 영상 캐릭터용(`willReadFrequently`, 픽셀을 읽음)과
   그림 캐릭터용(그리기 전용 = GPU). 캐릭터를 고를 때 하나를 쓰고 안 쓰는 쪽은 1x1 로 줄여 메모리를 돌려줍니다.
2. 머리 캐릭터는 comp 를 **2배**(원본 640x800 그대로)로 짭니다 — 1배로 짜서 기울이면 얼굴이 뿌예집니다(아래 3장).
3. `present()` 가 화면 캔버스에 세 장을 겹칩니다.
   ① **기운 «머리 경계»**(알파 = 머리 몫) → ② **안 기운 comp 를 `source-out`** 으로(= 몸 = comp × (1 − 기운 경계)) → ③ **기운 머리 층을 `lighter`** 로 더함.
   목에서 두 몫이 정확히 1 이 되어 투명한 틈이 안 생깁니다.
   머리 층은 **화면 크기(1배)** 입니다 — 2배 comp 를 «기울이면서» 한 번에 줄여 담고 같은 각도의 경계로 오립니다(줄이기가 한 번뿐이라 선명도는 그대로).
3-1. **입모양 그림 미리 올리기(`warmFace`)** — 그림을 다 받으면 «말할 때 쓰는 그 comp» 에 알파 1/255 로 1픽셀만 그리고
   곧바로 화면에 옮긴 뒤 **두 프레임**을 기다렸다가 `prepare()` 를 끝냅니다(숨은 탭은 rAF 가 안 돌아 300ms 타이머가 대신 넘깁니다).
   GPU 캔버스는 그림을 «처음 그리는 순간» GPU 로 올리는데, 그 순간이 말 첫마디면 그 프레임들이 통째로 밀려 짧은 입모양을 놓치기 때문입니다.
   이때 아래 3-2 의 «줄인 얼굴 바탕 사본» 도 함께 만들어 1픽셀 옮겨 둡니다.
3-2. **입·눈 칸만 다시 깔기(입모양 그림 캐릭터 — Lily·Noah·Emma·Jake)** — 말 첫 장만 얼굴을 통째로 그리고, 그 뒤는 장마다
   **입 칸·눈 칸 두 사각형만** 지우고 다시 깝니다. 다시 까는 바탕은 원본을 다시 줄여 그리지 않고, comp 와 같은 크기로
   **한 번 줄여 둔 사본(baseCv)** 에서 장치 픽셀 정수 사각형을 **1:1** 로 옮깁니다(배율 1 · 잘라 그리기 없음 · 사방 2px 여유).
   캐릭터·크기·배율·자르기가 바뀌거나 그림이 늦게 도착해 comp 를 다시 잡으면 다음 한 장은 다시 통째로 그립니다.
   이 경로는 입모양 전환 섞기를 안 쓰므로 섞기 사본(comp 통째 사본)도 안 뜹니다.
4. **머리 경계(HEAD 표)** — 초상화 원본 px 로 `y1`(위는 머리) · `y2`(아래는 몸) · `nw`(목 반폭) · `x`(축). 목 밖에서는 경계를 위로 들어 올려 **어깨가 섞이지 않게** 합니다. 경계 그림은 캐릭터·크기마다 한 번만 만듭니다.
5. 입모양 전환 섞기는 투명 그림 캐릭터에서 **캔버스 사본 + `source-atop`** 으로 — 2배 comp 에서 `getImageData` 픽셀 루프를 돌리면 폰에서 프레임이 끊깁니다.
6. 화면 밖 캔버스를 못 만드는 환경이면 **예전처럼 화면에 바로 그리고 안 움직입니다**(실패해도 얼굴은 그대로).

## 3. 검토했다가 버린 방법

| 방법 | 버린 이유(잰 것) |
|---|---|
| 캔버스·카드를 CSS 로 통째로 기울이기 | 어깨·몸까지 흔들립니다. 지시는 «머리» 입니다(기존 «숨쉬기» 가 이미 카드 전체를 아주 작게 기울입니다) |
| 몸·머리를 따로 오려 `source-over` 로 겹치기 | 목 이음매 알파 **245~248**(비침), 몸 픽셀 1~2 차이 → 기운 경계 + `source-out` + `lighter` 로 바꿔 **254~255 · 몸 0** |
| comp 1배 | 움직일 때 얼굴 선명도(라플라시안 분산)가 정지 화면의 **0.41~0.64배**(뿌옘) → 2배 comp 로 **1.08~1.37배** |
| `imageSmoothingQuality` medium/high | 0.6~0.7배로 오히려 부드러워짐. 기본값(low)은 정지 상태가 운영과 **동일**(1146=1146)하고 확대 비교에서 들쭉날쭉함이 안 보여 기본값 유지 |
| 픽셀(`getImageData`) 섞기 | 2배 comp 에서 비용이 4배 → 캔버스 사본 섞기 |
| rAF 를 매 프레임 다시 걸기 | 그리기는 초당 20번인데 **깨우기는 60번**(실측 rAF 180회/3초) → 타이머로 기다렸다 한 번만 |
| `setInterval` | 저장소 규칙 금지(홈이 멎은 전력) |
| comp 하나를 «픽셀 읽기용»(CPU)으로 모든 캐릭터에 | 그림 캐릭터의 2배 그리기가 전부 CPU 라 CPU 4배 제한에서 말하는 동안 프레임이 **2초에 70~78장**(원본 87~90) — 입모양을 덜 그립니다. 그래서 comp 를 둘로 나눴습니다 |
| 머리 층 2배 | 말하는 동안 프레임마다 2배 크기 그리기가 두 번 늘어 CPU 4배 제한에서 한 프레임 중앙 **0.7ms → 7~8ms**, 입모양 검사 시간초과 → 화면 크기(1배) |
| 미리 올리기 없이 GPU comp | 그림을 처음 그리는 순간(말 첫마디)에 GPU 업로드로 **67~233ms** 멈춤(헤드리스 SwiftShader) · 입모양 검사 **3/14** 실패 |
| 1x1·256x256 같은 «다른» 캔버스에 미리 그리기 | 효과 없음 — 크롬은 128x129 보다 작은 캔버스를 GPU 로 안 그려 업로드가 안 일어나고, 다른 큰 캔버스는 업로드가 그 캔버스 몫이라 말할 때 다시 올립니다(실측 말 첫마디 멈춤 **217·233ms**) |
| 미리 그리지 않고 프레임만 기다리기 | 업로드가 결국 말하는 도중으로 밀려 **117~167ms** 멈춤 |
| 입모양 캐릭터도 매 장 얼굴 통째로 다시 그리기 | 말하는 동안 >60ms 끊김(CPU 4배 제한 · 3회) **3·6·4회** · 입모양 검사가 1.3배속의 0.15초짜리 입을 가끔 놓침 → 칸만 다시 깔기로 **3·2·0회** |
| 칸을 잘라(clip) 그 안에 원본을 다시 줄여 그리기 | 배율이 정수가 아닌 얼굴(emma·jake 1.25배)에서 GPU 표본이 달라져 통째로 그린 것과 **최대 5/255** 차이 → 줄여 둔 사본에서 1:1 로 옮기기로 jake **0** |
| 잘라 둔 채(clip) 입을 그리기 | emma 입이 **±2/255** 달라짐 → 칸을 다시 깐 «뒤» 잘라 그리기 없이 통째로 그릴 때와 같은 상태로 입을 그려 **0** |
| 입모양 캐릭터에도 섞기 사본 계속 뜨기 | 이 경로는 섞기를 안 쓰는데 입 단계가 바뀔 때마다 2배 comp(2MB)를 통째로 베끼고 있었습니다 → 안 뜸 |

- 프레임 실측(헤드리스): 말하는 동안 >60ms 멈춤 **7회 · 최대 83ms**(원본은 전체 8회) · CPU 4배 제한에서 말하는 2초당 프레임 **108~121장**(원본 87~90) · 한 프레임 최대 11~22ms.
  칸만 다시 깔기 뒤(CPU 4배 제한 · 3회): 말하는 동안 >60ms 끊김 **3·2·0회**(통째로 그리던 판 3·6·4 · 원본 9·8·8 — 단 한 번은 183ms 까지 갔습니다) · 한 프레임 그리기 중앙값 **1.2~1.3ms**(통째 판 1.2~1.9 · 원본 0.6~0.7) · p95 **4.9~5.8ms**(통째 판 5.6~8.3) · 2초당 그리기 약 120장(원본 89~90). 재생을 다시 시작한 직후 짧은 입모양 놓침은 세 판 모두 0.
- 눈으로: 6배 과장 프레임에서 몸 고정·목 섞임 자연스러움 확인. Jake 만 6배에서 턱 모서리에 짧은 꼬리가 보이는데(목이 턱만큼 넓고 어깨가 턱 바로 밑) **실제 기울기에서는 1~2px** 라 확대해도 겹쳐 보이지 않습니다.

## 5. 비용

- 쉴 때 깨우기(rAF 콜백) 실측 — CPU 제한 없음 **59~60회/3초(≈20/초)** · p95 0.4ms, CPU 4배 제한 **48~50회/3초** · p95 **1.5ms**(헤드리스, Lily·Jake). 옛 방식(매 프레임 rAF)은 180회/3초였습니다.
- 메모리(화면 캔버스 320x400 일 때): 그림용 2배 comp 2.0MB + 머리 층(1배) 0.5MB + 경계 0.5MB + 사본 하나 2.0MB ≈ **5.0MB** + 안 쓰는 comp 1x1(아바타는 화면에 하나뿐).
  사본은 캐릭터에 따라 «둘 중 하나» 입니다 — 입모양 그림 캐릭터(Lily·Noah·Emma·Jake)는 줄인 얼굴 바탕 사본, 나머지(Mei·Long)는 전환 섞기 사본. 안 쓰는 쪽은 1x1 로 비워 두 사본이 함께 커지지 않습니다.
- ⚠️ **실제 폰의 배터리·발열은 못 쟀습니다.**

## 6. 사람이 볼 것

- 배포 후 PC 에서 `Ctrl`+`Shift`+`R` → 웜업·AI 친구에서 친구를 하나씩 골라 **머리만** 천천히 움직이는지, 말할 때 조금 더 움직이는지.
- 폰(특히 오래된 안드로이드)에서 화면이 끊기거나 뜨거워지지 않는지.
- 움직임이 «크다/작다» 는 사람 눈이 정할 일 — 숫자는 `SWAY_ROT_DEG`(1.0)·`SWAY_NOD`(0.007)·`SWAY_TALK`(1.35) 세 줄입니다(하니스가 «조금씩» 범위를 지킵니다: 기울기 ≤ 1.5° · 끄덕임 ≤ 1.2%).
