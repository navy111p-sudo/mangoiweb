# 단어장에서 틀린 낱말 → 웜업 대화·게임 (개선안 0순위 «약점 낱말 넣기»)

- 작업자: navy111p + Claude
- PR: navy111p-sudo/mangoiweb#1631 (병합 커밋 `a5e3a53`, 운영 배포 성공 2026-10-19 03:28 KST)

## 1. 왜 했나
개선안 0순위에서 남아 있던 일입니다. 학생이 단어장·단어 퀴즈에서 틀린 낱말이 **복습 일정에만** 남았습니다.
웜업 대화에도 게임 문제에도 다시 나오지 않아, 틀린 낱말을 «말해 보거나 다시 풀어 보는» 일이 끊겨 있었습니다.
`src/index.ts`(공동 금지구역)를 고치는 일이라 사장님께 여쭤 보고 «약점 낱말 넣기» 승인을 받았습니다.

[잰 것 — 2026-10-18 운영 D1, SELECT 만]
- 틀린 기록이 있는 낱말은 29개(17명)입니다. 그중 실제 학생은 6명·11개입니다.
- 지금 복습 단계가 처음(0)인 것은 10개이고, 전부 최근 60일 안입니다.
- 오늘 해당하는 실제 학생은 **5명·10개**입니다(kang 4 · jeong 2 · ysyt01 2 · bellet00 1 · delaware 1).
  - 한 명은 그 낱말을 한 번 맞혀 단계가 1로 올라 빠졌습니다.
- 그 10개 중 «정답이 오답보다 많은» 행은 0개, 1:1 인 행이 3개입니다.
- 다섯 명의 단어장 낱말은 10~17개이고 전부 뜻(korean)이 있습니다.

[그래서 내린 판단]
- 다섯 명 모두 게임 허브가 «학생 맞춤 단어 목록» 으로 바뀔 만큼 낱말을 가졌을 것으로 봅니다.
  - 그 조건(뜻이 있는 낱말 몇 개 이상인가)은 이번에 따로 재지 않았습니다.

## 2. 무엇을 바꿨나
- **`cloudflare-deploy/src/vocab-weak.ts`(새 정본)** — «단어장 약점» 은 아래 넷을 다 만족하는 낱말입니다.
  1. 틀린 기록이 있다(`wrong_count > 0`).
  2. 지금 복습 단계가 처음이다(level 0).
  3. 오답이 정답보다 적지 않다(`wrong_count >= correct_count`) — 게임 약점과 같은 판정입니다.
     - 2026-10-18 #1608 전에는 퀴즈가 level 을 안 건드렸습니다.
     - 그래서 옛 행의 level 0 은 «마지막 답이 오답» 이라는 뜻이 아닙니다. 여러 번 맞힌 낱말을 약점으로 읽지 않으려는 조건입니다.
  4. 최근 60일 안에 봤다 — 게임 약점 정본 `weak-words.ts` 와 같은 창(`weakSince`)입니다.
  - 정렬은 최근에 본 것 먼저입니다.
  - 정답을 한 번 맞히면 단계가 1이 되어 저절로 빠집니다(복습 일정 `vocabSrsNext` 가 다시 데려옵니다).
- **본인 확인 — `vocabWeakCallerVerified`(index.ts, 웜업·games/weak 이 함께 씀)**
  - 토큰 uid 가 요청 `user_id` 와 같거나, 같은 이름의 관리자 세션일 때만 참입니다(정확일치).
  - 요청의 `user_id` 는 화면이 보내는 값이라 그대로 믿지 않습니다.
  - 단어장의 «틀린 기록» 은 `/api/vocab/list` 에서도 본인에게만 보입니다(`gateVocabOwner`). 같은 수준으로 맞춘 것입니다.
  - 던지지 않습니다. 확인이 안 되면 그 기능만 빠집니다.
- **웜업 대화(`handleWarmupChat`)**
  - 단어장 약점을 먼저, 그다음 게임 약점을 합쳐 최대 3개(기초 1~2단계는 1개)를 시스템 프롬프트에 영어 한 줄로 넣습니다.
  - 그 줄은 «가끔(연달아 두 번은 안 되게), 어울릴 때 하나만 써 보게 하라» 고 지시합니다.
    - 화제를 바꾸지 말고, 목록으로 묻지 말고, 틀렸다는 말을 하지 말고, 수준 규칙을 깨지 말라는 내용입니다.
    - 매 턴 끼워 넣으면 2026-09-03 원장님 제보(「정해진 문장 안에서만 한다」)가 되살아납니다.
  - 본인 확인은 **캐시를 읽기 «전» 에** 매번 합니다. 확인 없이 남의 캐시를 꺼내 쓰는 길을 막았습니다.
  - 영어 대화만 해당합니다. 세션+학생별로 KV 에 30분 캐시합니다. 실패해도 던지지 않고 그 줄만 빠집니다.
- **`/api/games/vocab`** — 단어 목록에 약점 낱말을 «먼저» 담습니다(최대 8개, 아래 games/weak 과 같은 수).
  - 단어가 30개를 넘으면 오래전에 넣은 약점 낱말이 «최근 30개» 밖으로 밀리던 길을 막습니다.
  - 오늘 대상 학생은 단어가 10~17개라, 이 순서가 바꾸는 것은 아직 없습니다(구조상의 수리).
- **`/api/games/weak`** — `vocab_weak` 칸을 **따로** 싣습니다.
  - 본인 확인이 될 때, 영어 요청일 때만 채웁니다. 아니면 빈 배열입니다.
  - ⛔ `weak`(게임 기록)에는 섞지 않습니다. 교사용 게임 리포트(`game-report.html`)가 그 배열을 «게임에서 틀린 단어» 로 그리기 때문입니다.
  - 원래 있던 «누적» 게임 약점 SQL 은 그대로입니다.
- **게임 허브(`student-games.html`)**
  - 약점을 받아 올 때 `mango_token` 이 있으면 함께 싣습니다(본인 확인용).
  - 받은 응답을 기억해 두는 `_applyServerWeak()` 를 넣었습니다.
  - `vocab_weak` 는 **지금 단어 목록에 있는 낱말만**, 그 목록의 항목(다듬어진 뜻) 그대로 복습 큐에 넣습니다.
  - 학생 맞춤 어휘가 약점 응답보다 늦게 와도 한 번 더 맞춥니다. 전에는 1.8초 시딩이 먼저 끝나면 놓쳤습니다.
  - 그사이 언어를 바꿨으면 옛 언어의 약점은 버립니다. 다시 받을 때는 옛 응답을 먼저 비웁니다.

## 3. 검토했다가 버린 방법
- **게임 기록(`weak`) 배열에 단어장 약점을 섞기** → 교사 리포트가 «게임에서 틀린 단어» 로 그려 출처를 거짓으로 말합니다. 칸을 따로 뒀습니다.
- **목록에 없는 약점 낱말을 `{en, ko}` 로 지어 넣기** → 단어장의 뜻은 다듬기(`readableKoreanVocabulary`)를 안 거친 값입니다. 목록에 있는 항목만 씁니다.
- **`user_id` 만 보고 읽기**(웜업·games/weak 둘 다) → 아무 아이디로 남의 단어장 «틀린 기록» 을 받을 수 있습니다. 본인 확인을 붙였습니다.
- **본인 확인을 캐시가 비었을 때만 하기**(첫 판) → 같은 세션 id 로 남이 캐시를 꺼내 쓸 수 있습니다. 매번 먼저 확인합니다.
- **프롬프트를 한국어로 쓰기**(첫 판) → 영어 프롬프트 안에서 말투가 갈렸습니다. 영어로 쓰고 «가끔·연달아 두 번은 안 되게» 를 숫자처럼 적었습니다.
- **`/api/games/recommend` 의 취약 단어를 60일 창으로 바꾸기**(첫 판) → 이번 일(단어장 약점)과 무관하고, 중국어 추천까지 바뀌어 범위를 벗어납니다. 되돌렸습니다.
