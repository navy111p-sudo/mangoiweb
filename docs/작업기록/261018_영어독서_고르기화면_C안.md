## 덧붙임 2 — 실제 노트북 «창» 에서 한 장이 깨지던 것 (2026-10-19)
### 왜 했나
- 앞의 검사는 1280×720 같은 **화면 크기**로 쟀습니다. 그런데 브라우저 창은 주소창·탭·작업표시줄만큼 낮습니다. 1366×768 화면이면 창이 약 640px, 1280×720 이면 약 600px 입니다.
- 그 창 크기로 다시 재 보니 «한 장에 다 보인다» 가 깨져 있었습니다.

### 잰 것 (main, 4단계 × 12편 × 한/영 전부)
- **1366×640 · 1280×650 · 1280×600**: 48편 전부 **목록이 안쪽 스크롤**됐습니다. 12줄은 512px 가 필요한데 목록 칸은 477px 였습니다.
- **900×600 · 960×640 · 1100×620**: 48편 전부 **제목이 잘렸고** «이전·다음·읽기 시작» 줄이 상세 칸 밖으로 밀렸습니다.
  - 이것은 이번 C안 전부터 main 에 있던 결함입니다(origin/main 사본으로 같은 측정을 해서 확인).
  - 원인: 상세 칸은 세로 flex 이고, 제목칸은 `overflow:hidden` 입니다. 넘치면 칸이 스크롤하는 대신 **제목칸이 줄어들어** 글자가 잘렸습니다.
- 1024×700 · 1024×768(태블릿)도 제목이 잘렸습니다.

### 고친 것 (`public/stories.html` CSS 만 — 스크립트는 그대로)
1. `.rl-detail>*{flex-shrink:0}`: 칸 안 상자가 줄어들지 않고, 칸이 스크롤합니다. 이제 제목이 잘리지 않습니다.
2. 한 장 고정일 때(폭 821px 이상 · 높이 561px 이상)만 버튼 줄을 **상세 칸 바닥에 sticky** 로 붙입니다. 칸이 넘쳐도 «읽기 시작» 이 늘 보입니다. 폰(쌓는 화면)에는 붙이지 않습니다.
3. 높이 720px 미만 창에서는 목록 줄을 조였습니다(줄 최소 32px · 여백 축소). 이제 12편이 안쪽 스크롤 없이 다 보입니다.
