## 1. 왜 했나

사장님이 «AI 독서/글쓰기» v1 제안 이미지를 보여 주셨고, 거기서 빠진 것을 v2 로 정리한 뒤 «그것으로 라이브 AI 영작 화면을 직접 보완해 달라» 고 하셨습니다.
라이브 화면에 이미 있는 것(글감 고르기·6하원칙 브레인스토밍·뼈대·첨삭·따라 쓰기)은 두고, **v2 에서 비어 있던 넷**만 채웠습니다.

| v2 번호 | 비어 있던 것 | 이번에 한 것 |
|---|---|---|
| ④ | 글 길이 기준이 «2000자 상한» 하나뿐 | 단계별 **단어 수 목표**(A1 20~40 · A2 40~80 · B1 80~150 · B2 120~200)를 글자 칸 아래 한 줄로 |
| ⑦ | 실수로 닫거나 전화가 오면 쓰던 글이 사라짐 | **초안 자동 저장·되살리기**(이 기기 · 같은 계정 · 24시간) |
| ⑤ | 브레인스토밍에 적은 6하원칙이 실제 글에 들어갔는지 아무도 안 봄 | 첨삭 결과에 **«6하원칙 확인»** 표(같은 낱말이 있는지만 — AI 판정 아님) |
| ⑥ | 첨삭을 받으면 «새 글 작성» 만 있고 고쳐서 다시 낼 길이 없음 | **«✏️ 내 글 고쳐서 다시 첨삭»** + 차수·점수 변화(「🔁 2차 첨삭 · 지난번 72점 → 이번 85점 (+13)」) |

## 2. 무엇을 바꿨나 (`ai-write.html`)

- **v2 모듈 한 덩어리**(`const AW_WORD_GOAL` ~ `window.awReviseAgain`, ①~④ 머리 주석)로 모았습니다 — 흩어 넣지 않았습니다.
  - 기존 `updateCharCount()` 는 이 모듈로 바꿨고 이름은 그대로 둡니다(입력칸 `oninput` 등이 부르고 있습니다).
- **④ 단어 수 목표** — `awCountLine(text, level)`
  - 영어 낱말만 셉니다(`/[a-z]+(?:['’-][a-z]+)*/g`).
  - 「✏️ 12단어 · 목표 20~40단어 (8단어 더!)」 → 「✅ … 목표 달성」 → 「👍 … 길어요」.
  - 2000자 상한은 **1800자를 넘을 때만** 함께 보여 줍니다(짧은 글에 숫자 두 개를 띄우지 않으려고).
  - 단계 버튼을 누르면 다시 그립니다(단계마다 목표가 다릅니다). **막지는 않습니다** — 권장일 뿐 첨삭은 그대로 됩니다.
  - `currentLevel` 은 파일 뒤쪽 `let` 이라 앞에서 읽으면 TDZ 오류 → `awLevel()` 이 try 로 감쌉니다.
- **⑦ 초안 자동 저장** — `awDraftSave`·`awDraftRestore`·`awDraftForget`
  - 키 `mangoi_aiwrite_draft_v1`, 값 `{u: 계정, t: 글(최대 4000자), ts}`. 타이핑 600ms 뒤 · `pagehide`·`visibilitychange` 때 저장.
  - 되살리기는 **글자 칸이 비어 있고 · 같은 계정이고 · 24시간 안** 일 때만. 토스트 「💾 HH:MM에 쓰던 글을 되살렸어요」.
  - **처음 화면을 그릴 때는 저장하지 않습니다** — 빈 칸을 저장하면 같은 기기의 «다른 계정» 초안을 지웁니다(아래 3장 ⓑ).
  - 빈 글을 저장할 때는 **내 것일 때만** 지웁니다(`old.u === uid`). 다른 계정 초안은 되살리지도 지우지도 않습니다.
  - «🔄 새로» 를 누르면 초안도 지웁니다.
- **⑤ 6하원칙 확인** — `awWhCheck`·`awWhCheckHtml`
  - 제출 «순간» 의 질문·답 사본(`_awSubmitSnap`)과 글을 비교합니다(답 객체를 참조로 두면 제출 뒤 고친 답이 섞여서 사본으로 둡니다).
  - 줄마다: ✅ 들어감 · ⚠️ 글에서 못 찾음 · ✍️ 한글 메모(스스로 확인) · 직접 확인.
  - 맨 아래 「※ 같은 낱말이 있는지만 비교했어요 (AI 판정 아님)」 — 낱말 비교라 **동의어·바꿔 쓴 말은 못 잡습니다.** 그래서 «틀렸다» 가 아니라 «못 찾음» 으로 말합니다.
  - 브레인스토밍을 안 했으면 표 자체를 안 그립니다.
- **⑥ 고쳐서 다시 첨삭** — `awNoteRound`·`awRoundHtml`·`awReviseAgain`
  - 결과 맨 아래 버튼 줄 첫 자리에 초록 버튼(폰에서는 줄바꿈 — `.aw-result-acts{flex-wrap:wrap}`).
  - 누르면 글자 칸으로 스크롤·포커스 + 안내 토스트. 글은 지우지 않습니다.
  - 다시 내면 결과 맨 위에 차수와 점수 변화. 점수가 내려가면 「점수는 글 길이·문장에 따라 달라져요」 한 줄(벌주는 말로 안 씀).
  - 같은 글이면(지난 글 낱말의 40% 이상 겹침) 차수를 잇고, 아예 다른 글이면 1차로 다시 셉니다.
  - **한 글자도 안 고치고** 다시 내면 「그대로 다시 낼까요?」 확인(점수만 다시 뽑는 일을 막으려고 — 막지는 않습니다).
  - 차수 기록은 **메모리에만** 있습니다(새로고침하면 1차부터).
- 🌐 언어 전환: 목표 줄·결과 상자 다시 그림. 인라인 스크립트가 i18n 엔진(defer)보다 먼저 돌아 «처음 열 때» 영어 학생에게 한국어가 남지 않도록 `DOMContentLoaded` 에 한 번 더 그립니다(CLAUDE.md 2장 마지막 줄의 그 함정).
- 결과 상자는 그린 뒤 `applyI18n(resultBox)` 을 부릅니다(새 줄들의 `data-ko`/`data-en`).

## 3. 검토했다가 버린 방법

- **ⓐ 6하원칙 확인을 AI 에게 맡기기 → 안 함.** 첨삭 프롬프트에 «6하원칙이 다 들어갔나» 를 더하면 응답 모양·토큰이 바뀌고(서버 `api-ai.ts` 수정), 판정이 확률이 됩니다. 결정론 낱말 비교로 «못 찾음» 까지만 말하고, 그 한계를 화면에 적었습니다.
- **ⓑ 처음 화면을 그릴 때 `updateCharCount()` 를 그대로 부르기(=저장까지) → 버림.** 실제로 그렇게 짰다가 하니스가 잡았습니다 — 빈 글이 저장되면서 같은 기기의 다른 계정(형제·공용 PC) 초안이 지워집니다. 그래서 «그리기»(`awRenderCount`)와 «그리기+저장»(`updateCharCount`)을 나눴습니다.
- **ⓒ 단어 수가 모자라면 첨삭 버튼을 막기 → 안 함.** 기초 학생은 20단어도 어렵고, 막으면 «첨삭이 고장났다» 로 읽힙니다. 권장 + 남은 개수만 말합니다.
- **ⓓ 초안을 서버(D1)에 저장 → 안 함.** 표·API·`src/index.ts`(공동 금지구역)가 걸리는 별건입니다. 이번 목적(«실수로 닫아도 이 기기에서 되살림»)은 localStorage 로 충분합니다.
- **ⓔ 차수 기록을 localStorage 에 남기기 → 안 함.** 같은 글인지 판정이 흐려지고(며칠 뒤 다시 열면 엉뚱한 «3차»), 지금 화면 목적은 «지금 고쳐서 다시 내 보기» 입니다.
- **ⓕ 목표 줄 색을 옛 `--red`·`#10b981` 로 → 바꿈.** 픽셀로 재니(아래 4장) 그라데이션 위에서 빨강 3.36 · 초록 4.98 로 모자랐습니다.

## 5. 알고 둔 한계

- 6하원칙 확인은 **같은 낱말 비교**입니다 — 바꿔 쓴 말·동의어는 «못 찾음» 으로 나옵니다(화면에 그렇게 적음).
- 한글로 적은 메모는 비교하지 않고 «스스로 확인» 으로 둡니다(영어 글과 낱말이 안 맞으므로).
- 단어 수 목표는 권장입니다(막지 않음).
- 초안은 **이 기기·이 브라우저**에만 있고 같은 계정·24시간까지입니다. 시크릿 창·저장 차단에서는 조용히 저장 안 됩니다(쓰기는 try/catch).
- 차수(1차·2차)는 새로고침하면 처음부터입니다.

## 6. 남은 것 (사람이 정할 일)

- v2 제안의 ③ «한글 메모 → AI 영어 힌트»(`/api/translate` `mode:'learn'`)는 이번에 안 했습니다.
- 초안을 서버에 저장해 기기를 바꿔도 이어 쓰게 할지.
- 차수·점수 변화를 기록(D1)으로 남겨 선생님 화면에서 보게 할지.
