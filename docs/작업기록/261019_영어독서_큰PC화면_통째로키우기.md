# 영어 독서(stories.html) — 큰 PC 화면에서 통째로 키우기 (2026-10-19)

## 1. 왜 했나

사장님 제보(스크린샷 첨부): 「이거 글자가 너무 작아서 보기 힘들어 PC화면에 적합하게 크게 키워줘.」
— `mangoi.ai/stories.html` 고르기 화면(C안, 2026-10-18).

### 잰 것
- 코드상 글자: 목록 제목 14px · 우리말 부제 12px · 주제 칩 11.5px · 설명 12.5px · 버튼 14px.
  화면이 아무리 넓어도 그대로였습니다(1920·2560·3840 폭 모두 14px — 헤드리스 실측).
- 스크린샷의 화면 폭은 966px 인데 코드의 칸 폭은 1480px — **0.67배**. 제목 글자 폭도 같은 비율이고,
  주소창 오른쪽에 **크롬 확대/축소 표시(🔍)** 가 보입니다 ⟹ **그 브라우저가 이 사이트를 67% 로 축소해 보고 있었습니다**
  (판단 — 표시를 근거로 한 추론. 이 사이트 다른 화면 때문에 줄여 둔 것으로 보입니다).
- 그래서 두 원인이 겹쳤습니다: ① 브라우저 축소(67%) ② 화면이 커져도 글자가 안 커지는 CSS.

## 2. 한 것

`stories.html` 의 `<style>` 끝에 **zoom 단계표 한 덩어리**를 넣었습니다(동화책 4편 `story-*.html` 이
2026-10-13 에 쓴 것과 같은 방식 — 글자·버튼·칸을 같은 비율로 키워야 «한 장» 배치가 안 깨집니다).

- **고르기 화면(`html.rl-browse`, 한 장 고정)** — 폭과 **높이**를 함께 봅니다. zoom 뒤 남는 칸이 **1260×700** 이상인
  가장 큰 단계(1.2 ~ 2.5, 9단계). 1920×920 창 → **1.3배**(목록 제목 18.2px), 67% 축소된 1920 화면(CSS 창 2880×1380) → **1.8배**.
- **읽기·반복 연습 화면** — 아래로 스크롤하므로 폭만 봅니다(1400:1.1 ~ 3400:2.3). 980px 칸 × zoom 이 창 폭의 80% 안.
  1920 폭에서 본문 18 → **23.4px**.
- **1600px 아래(노트북 1366×640 · 1440×860 · 1280×600)는 어느 단계에도 안 걸립니다** — 10-19 에 맞춘 노트북 배치 그대로.

### 숫자 1260×700 의 근거 [잰 것]
- 48편 × KO/EN 을 zoom 뒤 남는 칸 크기별로 눌러 봄: 높이 **700 → 안쪽 스크롤 0**, 높이 **640 → 목록이 35px 넘침**(48편 전부).
- 영어 머리줄은 칸 폭 1181 에서 두 줄(97px), 1250 이상에서 한 줄(51px).
- 미디어쿼리는 «실제 창» 을 보므로, 남는 칸이 위 규칙들의 경계(1180·720)보다 커야 서로 말이 맞습니다.

## 3. 검토했다가 버린 것
- **글자 크기 숫자를 하나씩 키우기** — 글자만 커지면 «한 장 맞춤»(12줄 최소 높이·버튼 줄 sticky)이 깨지고, 60곳 넘는 px 를 고쳐야 합니다.
- **폭만 보는 단계(동화책 방식 그대로)** — 고르기 화면은 높이가 모자라면 목록이 안쪽 스크롤됩니다(1920×700 같은 낮은 창). 높이 조건을 함께 둡니다.
- **`.wrap{zoom}` 하나로 두 화면 공용** — 읽기 단계(폭만 보는)가 한 장 고정 화면에 새면 높이를 안 봐 목록이 넘칩니다. `html.rl-browse` / `html:not(.rl-browse)` 두 갈래로 나눴고 하니스가 못 박습니다.
