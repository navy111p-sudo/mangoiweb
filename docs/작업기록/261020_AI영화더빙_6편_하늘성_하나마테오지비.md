## 3. 검토했다가 버린 것

- **⑥-14(장면마다 캐릭터별 2줄 이상)를 그대로 두고 대본을 고치기** → 장면 4~6 은 위스커스 선장이 줄거리의 중심(정체 공개·화해)이라 6줄 중 2~3줄이 손님 몫이고, 남은 3~4줄을 셋이 2줄씩 나눌 수가 없습니다. 아티팩트에서 사장님이 «아주 좋아» 하신 대본을 바꾸는 대신 **검사를 넓혔습니다** — 단, 손님이 없는 장면은 여전히 2줄, 손님은 절반 이하, 1편의 «2줄» 기준은 그대로(⑥-14m3 이 못 박음). ⚠️ 사람이 정할 판단으로 남깁니다(설명서 6-1e).
- **위스커스를 고를 수 있게(playable 4명)** → 고를 수 있는 역이 3명이라는 규칙(⑥-13)이 깨지고, 장면 1~3 에서 위스커스를 고른 학생은 할 대사가 0줄입니다.
- **스템을 «대사 구간만» 잘라 올리기** → 설명서 3절이 «길이 = 장면 영상 길이, 0초 = 영상 0초» 를 요구합니다. 화면이 영상과 함께 트랙을 0초부터 틀고 0.3초 넘게 어긋나면 맞추는 구조라, 짧은 파일은 맞출 기준이 없습니다.
- **영상 끝을 넘는 줄(장면 3 지비)을 잘라 내기** → 마지막 낱말 끝이 사라집니다. 1.115배 빠르게(2.377 → 2.132초) 맞췄습니다.
- **BGM 을 원래 크기로 두기** → 스템만 −16 LUFS 로 올라가 음악이 상대적으로 4.5dB 작아집니다. 사장님이 들은 비율과 달라지므로 같은 만큼 올렸습니다(리미터는 −2dB 목표 — −1 로 잡으면 MP3 로 구운 뒤 트루피크가 다시 솟아 넘었습니다).

## 4. 확인한 방법

- 자동: `node test-harness/ai_dubbing_harness.mjs` → **PASS 224 / FAIL 0**(5편 병합 뒤 **251 / 0** — 5편도 같은 ⑥절 규격을 받으면서 늘어남). 6편이 ⑥절의 같은 규격(영상·첫 그림 실재·25MiB·36문장·3~8낱말·목소리 안 겹침·대사 id)을 통과하고, 일부러 망가뜨린 것 4가지(⑥-14m1~m4)가 전부 실제 FAIL.
- 브라우저: `PW_DIR=/opt/node-tools node test-harness/manual/ai-dubbing-ep6-browser.mjs` → **PASS 19 / FAIL 0** — 제목·6장면·«영상에 맞춰 진행» · 칩이 hana/mateo/zibi 셋 · 장면 1 에서 BGM + 음성 3줄이 실제로 돌고(크로미움 mp3 `probably`) 하나만 0 · 장면 4 에서 위스커스 음성 1 · TTS 0회 · 받은 mp3 가 전부 이 편 폴더 · 페이지 오류 0. 변이(위스커스를 playable 에 넣기) → ②-1 실제 FAIL.
