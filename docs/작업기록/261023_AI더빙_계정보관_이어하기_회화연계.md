# A.i영화더빙 — 계정 보관·이어하기·실제 대사로 회화 연습

- 날짜: 2026-10-23
- 브랜치: `codex/dubbing-learning-flow-20261023`
- 대상: `/ai-dubbing.html`, `/ai-dubbing-studio.html`, `/ai-friend.html`
- 상태: 구현·집중 검증 및 아래 **Chromium 브라우저 통합 검사 21개 통과**. 로컬 전체 회귀와 자산 버전 확인 완료(7-3절). CI·배포 상태는 PR 기록에서 별도로 확인한다.

## 1. 왜 했나

사장님이 유튜브 더빙 사례와 망고아이를 비교해 달라고 요청한 뒤, 제안한 개선안을 실제로 추진하도록 지시했다. 기존의 작품·역할·그룹 발표 기능을 바탕으로, 처음 시작하는 학생이 짧게 체험하고, 만든 결과와 중단한 연습을 다시 찾으며, 말한 문장을 다음 대화에 활용하도록 연결하는 작업이다.

이번 범위는 **시작 → 보관·이어하기 → 회화 연습**이다. 기존 영상을 새로 제작하거나 대본·화자·입모양 시각을 바꾸는 작업은 포함하지 않았다.

## 2. 실제 반영한 세 흐름

| 흐름 | 학생이 하는 일 | 반영한 동작 |
|---|---|---|
| **쉽게 시작하기** | 첫 화면의 «오늘의 짧은 더빙», «지난 연습 이어하기», «내 작품 보기» 중 선택 | 짧은 더빙은 현재 작품의 실제 재생 가능한 짧은 장면을 골라 역할 설정을 연다. **이 버튼이나 연습 불러오기만으로 마이크·녹음을 시작하지 않는다.** 기존 시작 버튼을 눌러 녹음한다. |
| **계정에 보관하고 이어하기** | 만든 영상을 다시 열거나 내려받고, 저장한 연습을 불러옴 | 두 더빙 화면이 공통 비공개 보관함을 사용한다. 완성·중간 녹음 영상과 진행 상태를 구분해 저장하며, 각 플레이어의 녹음 방식에 맞게 복구한다. 계정 저장 실패 시에는 기기 보관 여부와 재시도·내려받기 안내를 표시한다. |
| **실제 말한 문장으로 회화 연습** | 녹음한 대사를 확인하고 AI 친구로 이동 | 녹음한 역할의 실제 영어 대사를 최대 3개 전달한다. AI 친구 안내 카드에서 시작 문장을 준비하고, 학생이 기존 전송 버튼으로 확인해 보낸다. 새 일상 상황에서 짧은 역할극을 요청한다. |

### 2-1. «이어하기»는 두 화면의 녹음 구조에 맞춰 다르게 작동한다

| 항목 | 모험 3D 애니 — main | 키키와 토토 — studio |
|---|---|---|
| 저장 단위 | 역할·모드·장면 목록·다음 장면 위치·역할 순번과, 별도의 녹화 영상 | 역할·재생 설정·현재 대사 위치와 **대사별 녹음 원본 Blob** |
| 진행 위치 | 장면이 끝나야 다음 장면으로 확정한다. 장면 중간에 멈추면 그 장면의 시작부터 다시 연습한다. | 저장한 대사 위치와 대사별 녹음을 불러온다. 대본의 영어 원문·화자가 맞는 녹음 참조만 복구한다. |
| 다시 시작 | **저장한 장면부터 새 영상으로 이어 녹음**한다. 이전 클립은 별도로 보관한다. | 이미 녹음한 대사는 유지하고 남은 대사 또는 고른 대사를 다시 녹음한다. |
| 다시 녹음한 대사 | 이전 영상의 특정 음성 구간을 편집하거나 새 영상과 자동으로 합치지 않는다. | 새 take ID로 업로드하고, 새 연습 기록 저장이 확인된 뒤 교체된 옛 take를 정리한다. 저장 실패 때문에 기존 녹음을 먼저 지우지 않는다. |
| 중단·실패 | 중간에 멈추거나 오류가 난 경우에도 생성된 유효한 영상 Blob을 «중간 녹음»으로 보관한다. AI 채점 완료를 기다리지 않는다. | 계정 저장이 실패해도 남아 있는 로컬 녹음을 유지한다. 복구 중에도 기기에서 새로 녹음한 대사는 원격 녹음으로 덮지 않는다. |

main의 결과·채점 큐는 새 녹음 시작 때 구분한다. 이전 녹음의 늦은 점수가 새 녹음 결과에 다시 섞이지 않도록 했으며, 역할 선택 저장 키도 **계정 + 작품**으로 나눴다. 계정이 바뀌면 진행 중 작업과 화면 결과를 정리하고, 이전 계정에서 시작한 영상·음성을 새 계정으로 올리지 않는다.

## 3. 보관 구조와 계정 경계

### 비공개 R2 보관

기존 `RECORDINGS` R2 바인딩 안에 `dubbing-private/v1/<서버가 계산한 소유자 해시>/` 전용 영역을 사용한다. 학생의 서명된 토큰 또는 직원 세션을 서버에서 검증한 뒤 소유자를 정한다. 같은 아이디 문자열이라도 **학생과 직원은 별도 소유자**이며, 직원이라는 이유로 학생 작품을 열 수 없다.

`X-Dubbing-Actor`는 브라우저가 현재 보고 있는 계정과 인증된 주체가 맞는지 대조하는 표식이다. 이 헤더나 클라이언트가 보낸 uid를 인증 수단으로 사용하지 않는다. 예전 토큰·직원 쿠키가 남아 있는 상태에서 화면만 다른 계정으로 바뀐 요청은 차단한다. JSON과 영상·음성 응답은 `private, no-store`로 반환하고, 조회·다운로드·삭제 모두 소유 계정의 API를 거친다.

일반 녹화 다운로드·삭제·검사 및 녹화 원본을 읽는 전사 경로에서는 이 전용 영역을 제외한다. 수업 녹화용 `rec/`, `recordings/` 경로와 분리하여 기존 수업 녹화 정리 대상에 더빙 작품이 섞이지 않도록 했다. **새 D1 테이블·스키마 변경·버킷 규칙 변경은 없다.**

### 동시 수정과 저장 한도

연습 기록의 새 생성에는 `If-None-Match: *`, 수정에는 읽어 온 ETag의 `If-Match`를 요구한다. 다른 화면에서 바뀐 버전은 **412 충돌**로 거절하고, 클라이언트는 저장된 연습을 다시 불러오기 전까지 덮어쓰기를 재시도하지 않는다. 같은 페이지의 저장 요청은 계정·연습별로 순서를 지키며, 요청 시점의 상태를 고정해 저장한다.

영상과 대사 음성은 바뀌지 않는 별도 객체로 저장한다. 영상 재시도는 같은 `clientId`를 사용해 중복 작품 생성을 막는다. 서버의 조건부 쓰기 원장이 업로드 전에 용량·개수를 예약하므로, 동시에 여러 요청을 보내도 상한을 넘길 수 없다. 실패하거나 중단된 예약은 회복할 수 있고, 공간을 만들기 위해 기존 작품을 자동 삭제하지 않는다.

| 범위 | 한도 |
|---|---|
| 계정의 보관 영상 | **20작품** — main·studio 합산 |
| 영상 한 파일 | **64 MiB** |
| 계정의 저장 연습 | **12개** — main·studio 합산, 음성부터 올라간 연습도 포함 |
| 연습 상태 JSON 한 개 | 64 KiB |
| 대사 음성 한 파일 | 8 MiB |
| 연습 하나의 대사 음성 | 100개 |
| 계정의 대사 음성 총량 | 128 MiB |

영상·음성의 신고 크기와 실제 수신 바이트를 확인하며, 큰 영상 전체를 Worker 메모리에서 재조립하지 않고 스트림으로 저장한다. 한도에 도달하면 내려받기·사용자 선택 삭제·재시도를 안내한다.

### 로컬 보관과 늦게 도착한 응답

공통 클라이언트는 영상과 연습 상태를 IndexedDB의 계정별 키에 보관한다. 영상 업로드가 성공하면 로컬 대기본을 정리하고, 실패하면 남은 기기 보관본을 보관함에서 다시 저장할 수 있다. studio의 대사별 녹음과 체크포인트 역시 계정별로 구분한다. 기기 저장이 차단되거나 용량이 부족한 경우에는 «기기에 저장됨»으로 표시하지 않고 현재 화면의 녹음·내려받기 안내를 유지한다.

로컬 보관은 **그 기기·그 브라우저의 임시 대안**이며, 다른 기기에서 복구하려면 계정 저장이 성공해야 한다. 게스트에게 계정 보관 성공을 표시하지 않는다. 계정 변경은 저장소 이벤트뿐 아니라 요청·응답 경계, 창 복귀, 같은 탭의 주기적 확인으로 감지한다. 늦은 원격 응답, IndexedDB 응답, 갤러리의 재저장·삭제 버튼에서도 이전 소유자를 다시 확인한다.

## 4. 회화로 넘기는 내용과 학생 확인

공통 `ai-dubbing-practice.js`에는 **작품 제목·선택적 장면 제목·실제 녹음한 대본 문장**만 넘긴다. main은 녹음 완료 표시가 있는 결과, studio는 선택한 역할 중 실제 녹음이 존재하는 대사를 사용한다. 표현 이름이나 학습 문장을 새로 만들어 원문인 것처럼 표시하지 않는다.

- 영어 원문은 최대 3개이며, 기존 대화 API의 **전체 500자 상한**을 맞춘다. 세 문장이 안 들어가면 문장 수를 줄이고, 문장 중간을 잘라 전달하지 않는다.
- 학생 이름·점수·녹음 오디오·음성 인식 결과는 전달하지 않는다.
- 같은 탭의 `sessionStorage`에서 **20분 만료·한 번 소비·계정 확인**을 적용한다. 제목과 대사는 plain text로 렌더링한다.
- AI 친구의 «이 표현으로 대화 시작»은 기존 입력칸에 시작 문장을 준비한다. **자동 전송은 하지 않으며**, 이미 쓰던 내용이 있으면 덮지 않는다. 학생이 확인 후 기존 전송 버튼을 누른다.
- 기존 AI 친구의 대화·음성·인증 경로를 그대로 사용한다. 더빙 내용을 바탕으로 새 상황을 제시하고 한 번에 쉬운 질문 하나를 하도록 요청한다.

## 5. 선택한 방법과 제외한 범위

| 선택하지 않은 방법 | 이유와 이번 결정 |
|---|---|
| 수업 녹화 테이블·일반 다운로드 경로에 더빙 작품 합치기 | 수업 녹화의 권한·보존기간과 학생 작품의 경계를 섞지 않기 위해 전용 비공개 영역과 API를 추가했다. |
| AI 점수를 모두 받은 뒤 영상 저장하기 | 채점 실패·지연이 녹화 결과 보관까지 막지 않도록 영상 확정을 독립시켰다. |
| main의 중간 영상을 이어 붙이거나 한 줄만 교체하는 편집기 추가 | main은 연속 녹화 구조이므로 장면 경계에서 **새 클립**으로 이어가도록 했다. 대사별 원본 복구·재녹음은 해당 구조를 이미 가진 studio에 적용했다. |
| 다른 화면의 연습 기록을 무조건 마지막 저장으로 덮기 | ETag 충돌을 알리고 다시 불러오게 했다. studio는 새 녹음을 올린 뒤 기록을 확정하여 기존 take를 먼저 잃지 않도록 했다. |
| 모든 대본이나 새로 만든 표현을 AI 친구에게 자동 전송 | 실제 녹음한 줄만 전달하고 학생이 입력 내용을 확인해 전송한다. |
| 한도 초과 시 오래된 작품 자동 삭제 | 사용자가 내려받거나 삭제할 작품을 직접 고르도록 했다. |

기존 **혼자·여럿 역할 배정, 같은 역할 순번 나누기, 연습·발표, 먼저 보기, 배경음악·효과음**은 계속 기존 플레이어를 사용한다. 화상 수업·그룹 수업 방이나 수업 운영 흐름을 바꾸지 않았다. 기존 작품의 영상·음성 파일·이미지·매니페스트 대본·화자·입모양 시각도 이번 기능 구현에서 수정하거나 재생성하지 않았다.

## 7. 확인한 방법과 현재 상태

다음은 **이 기록 갱신 시점에 통과가 확인된 집중 검증과 로컬 브라우저 통합 검사**다. 운영 배포 완료를 뜻하지 않는다.

### 7-1. 집중 검증

| 검증 | 결과 | 확인 범위 |
