## 1. 왜 했나

사장님이 계정 보관·이어하기 기능을 구현한 화면을 보고 **«좀더 직관적이고 이해하기 쉽게 만들어줘»**라고 요청했다. 기존 화면에는 시작 안내가 여러 번 나오고 단계 이름도 달랐으며, 처음 하는 학생에게 여러 선택이 비슷한 비중으로 보였다. «출연 설정», «모드» 같은 말과 저장 한도 안내가 앞에 있어, 무엇을 먼저 누를지 찾기 어려웠다. 비어 있는 보관함에서도 다음 행동이 분명하지 않았다.

이번에는 **처음 시작하기·계속 연습하기·완성 영상 보기**의 목적을 구분하고, 실제로 눌러야 하는 버튼과 가까운 곳에 짧은 안내를 놓았다. 이전 작업의 보관·녹음 기능 위에서 화면과 문구를 정리한 작업이다.

## 2. 메인 화면에서 달라진 점

| 위치 | 바꾼 내용과 이유 |
|---|---|
| 첫 화면의 3개 버튼 | **짧은 더빙 시작**을 가장 눈에 띄게 배치했다. **하던 연습 계속하기**, **내 영상 보기**는 각각 저장한 연습과 영상을 여는 행동으로 구분했다. |
| 시작 버튼의 다음 행동 | «다음: 내 역할 고르기 →»를 표시했다. 현재 모험 작품에서 실제 재생 가능한 짧은 장면을 고른 뒤 역할 설정을 연다. 버튼을 누르는 것만으로 마이크나 영상 재생을 시작하지 않는다. |
| 권장 3단계 | **영상 먼저 보기 → 내 목소리로 더빙 → 내 영상 다시 보기**로 안내를 통일했다. «이 순서로 연습하면 쉬워요»라는 권장 순서이며, 순서대로 통과해야 하는 강제 단계가 아니다. |
| 역할·연습 설정 | «내 역할 고르기», «어떤 캐릭터가 될까요?», «연습 방법», «자막 보며 연습 (추천)»처럼 행동을 이해하기 쉬운 말로 바꿨다. 실제 녹음을 시작하는 버튼은 «내 목소리로 녹음 시작»으로 표시한다. |
| 보관함 | 이름을 «내 영상과 연습», 탭을 **내 영상 / 이어할 연습**으로 맞췄다. 비어 있으면 설명과 **짧은 더빙 시작** 버튼을 보여 다음 행동으로 연결한다. |
| 저장 안내 | 계정 저장·이 기기 저장의 차이와 보관 한도는 **«영상은 어디에 저장되나요?»**를 펼쳐 볼 수 있게 했다. 친구와 함께 하는 방법·자막 설명도 별도 펼침 안내로 정리했다. |
| 작품 찾기 | **모험 3D 애니와 키키·토토 두 장르를 계속 보여 준다.** 다른 작품·장면을 직접 고르는 기존 입구를 유지했다. |
| 한영·작은 화면 | 새 문구와 빈 보관함 안내에 한국어·영어를 모두 적용했다. 글자 크기와 버튼 배치를 조정하고 주요 터치 버튼·설정 조작을 최소 44px 높이로 맞췄다. |
| 메뉴·상단 제목 | 작은 화면에서 공통 메뉴 탭이 시작 버튼과 글자 위에 겹치는 것을 실제 캡처로 확인했다. 1280px 이하에서는 소개 영역의 메뉴 버튼으로 기존 메뉴를 열게 하고, 상단 제목에 홈·언어 버튼 공간을 확보했다. |

## 3. 키키·토토 스튜디오에서 달라진 점

상단 안내 **역할 고르기 → 대사 녹음하기 → 내 영상 만들기**를 각 영역으로 이동하는 링크로 만들었다. 링크 대상은 `#studio-setup`, `#studio-script`, `#studio-movie`이며, 실제 카드 순서도 **설정 → 대본·녹음 → 결과 영상**으로 맞췄다.

| 학생이 헷갈릴 수 있는 행동 | 화면에서 알려 주는 방법 |
|---|---|
| 재생하면 내 목소리도 저장되는가 | 재생은 먼저 듣는 행동이며, 녹음은 **내 대사 옆 «녹음하기»**를 눌러야 한다고 재생 버튼 가까이에 표시했다. 말을 마치면 같은 버튼의 «녹음 완료»를 누른다. |
| 녹음 확인과 영상 완성은 같은가 | **녹음 먼저 들어보기**와 **내 영상 만들고 저장하기**를 구분하고, 영상 만들기 버튼을 강조했다. |
| 중간 연습과 완성 영상은 어디에서 찾는가 | **하던 연습 계속하기 / 여기까지 저장하기 / 내 영상 보기**로 목적을 구분했다. 영상 저장 성공 문구도 «내 영상 보기»에서 다시 볼 수 있다고 한영으로 맞췄다. |
| 설정이 많아 무엇부터 골라야 하는가 | 역할과 연습 방법은 바로 보이게 두고, 속도·자막·배경음악은 펼침 안내로 정리했다. |

이어하기 버튼은 일반 버튼으로 표시해 새 녹음 시작과 혼동하지 않게 했다. 녹음 전체 삭제는 영상 완성 버튼과 줄을 나눴다. 주요 버튼을 최소 44px 높이로 조정하고 단계 링크·펼침 안내의 키보드 초점 표시도 추가했다. 기존 요소 ID와 한영 전환 연결은 유지했다.

## 4. 선택한 방법과 제외한 범위

| 검토했지만 선택하지 않은 방법 | 이유와 이번 결정 |
|---|---|
| 모든 학생에게 같은 순서의 마법사 화면을 강제하기 | 처음 온 학생에게 권장 순서를 알려 주되, 익숙한 학생은 기존 작품·장면·장르를 바로 고를 수 있게 했다. |
| 짧은 더빙 버튼에서 바로 마이크·영상 재생 시작하기 | 역할과 녹음 준비를 확인한 뒤 기존 시작 버튼을 누르도록 했다. 첫 화면과 빈 보관함의 시작 버튼은 같은 준비 동작을 사용한다. |
| 녹음·보관·영상 내보내기 구조까지 함께 고치기 | 이번 요청의 원인이 화면 이해도이므로, PR #1724까지 검증한 녹음·보관 동작을 유지하고 배치·명칭·설명을 정리했다. |
| 저장 한도·자세한 설정을 모두 첫 화면에 표시하기 | 당장 필요한 행동이 먼저 보이도록 상세 안내는 펼쳐 읽게 했다. 기능을 제거하지는 않았다. |

원본 영상·음성·대본·화자·시각 데이터는 수정하지 않았다. 메인 플레이어 JS의 수정은 `renderCast()`와 `updateDubMode()`의 표시 문구·마크업에 한정한다. 녹음·재생·내보내기 함수는 수정하지 않았고, 스튜디오의 `STORE_KEY` 이후 상태·실행 코드도 최신 병합 기준 `1aeb002`와 같다. 스튜디오의 `movieSaved` 변경은 상태 표시용 한영 문구에만 해당한다. 서버 API·계정별 보관·한도·권한 경계도 이번 작업에서 변경하지 않았다.

### 최신 main과의 병합

PR #1725의 6단계 모둠 사용 가이드와 공유 마이크·영상 저장 안내를 보존하고, 상세 가이드를 펼침 영역으로 배치했다. 안내 속 버튼 이름은 현재 UI와 맞췄다. PR #1727의 **말하기 완료 / +5초** 조작과 연습 차례 대기 동작, PR #1726의 영상 내보내기 자원 정리·오류 복구 코드는 그대로 합쳤다. 기존 main·studio 요소 ID 누락·중복 및 남은 충돌 표시는 없다. PR #1728의 모둠 이름 입력과 영상 제목·파일명·이어하기 기록 반영도 보존했다. 최신 main에서 home JS v2·main JS v15를 사용하므로 이번 버전은 **home JS v3·main JS v16**으로 올렸다.

## 5. 수정 파일과 캐시 버전

| 파일 | 변경 내용 |
|---|---|
| `cloudflare-deploy/public/ai-dubbing.html` | 시작·권장 단계·역할 설정·보관함의 배치와 한영 문구 |
| `cloudflare-deploy/public/css/ai-dubbing-home.css` | 시작 버튼의 우선순위, 가독성, 작은 화면, 펼침 안내·터치 크기 |
| `cloudflare-deploy/public/js/ai-dubbing-home.js` | 쉬운 상태 문구, 빈 보관함의 시작 연결 |
| `cloudflare-deploy/public/js/ai-dubbing.js` | 역할·연습 선택 등 화면 문구 |
| `cloudflare-deploy/public/ai-dubbing-studio.html` | 3단계 링크, 대본·결과 순서, 녹음·재생·저장 안내, 한영 문구 |

메인 HTML은 `ai-dubbing-home.css?v=2`, `ai-dubbing-home.js?v=3`, `ai-dubbing.js?v=16`를 참조한다. 공통 보관 클라이언트 `ai-dubbing-library.js?v=2`는 그대로다. 자산 버전 목록과 기존 검증의 화면 문구·선택자도 새 UI에 맞췄다.

UI 검사는 실제 Chromium에서 모바일 크기의 화면을 사용한 검사다. 실물 휴대전화·Safari·학생의 실제 발화·운영 계정 녹음까지 확인했다는 뜻은 아니다. 320px 영어는 보조 카드 설명의 아래 부분을 스크롤해 읽지만, 주 시작 버튼은 전부 보이고 두 보조 버튼 제목도 식별된다.
