# 대리점 청구서 결제 ③④⑤ — 명단·금액 대조, 안 낸 달, 수업료 «승인 중» 보호 (2026-10-23)

> 앞 PR #1717(①② 이중결제·취소 되돌리기)에 이어 «Toss 통합 순서 검토» 의 ③④⑤ 를 고쳤습니다.

## 왜 했나

| | 증상 | 뿌리 |
|---|---|---|
| ③ | AI 컨텐츠(MGB-)에서 30명분을 결제하는 사이 다른 탭에서 20명을 더 체크하면 **50명이 활성화**(낸 돈과 열린 학생 수가 갈림) | 금액은 결제창을 연 순간(checkout) 정해지고, 활성화는 «지금 체크된 학생» 에게 이용권을 준다. 그 사이 명단을 막는 장치가 없었다 |
| ④ | 달이 바뀌면 **안 낸 청구서가 화면에서 사라짐** — «마감 지남» 띠가 원리상 한 번도 안 뜸 | 화면이 `month` 를 안 보내 서버 기본값 «다음 달» 만 그렸다 |
| ⑤ | 수업료(MGT-): 승인 «중» 에 본사가 청구서를 거두거나(void) 금액이 갱신되면 옛 금액 돈이 거둔·줄어든 청구서로 들어감. 자동결제는 문지기를 아예 안 거침 | void·갱신 UPDATE 에 «승인 중 아님» 조건이 없었고, `chargeAutopay` 가 빌링 승인을 곧바로 불렀다 |

## 한 것

- **③** `claimB2bInvoiceForConfirm`(b2b-pay-guard.ts)이 선점을 «쥔 뒤» `mgbAmountNow`(ai-billing.ts — checkout 과 같은 `invoiceAmount` 정본)로 금액을 다시 재서 다르면 선점을 놓고 `invoice_amount_changed` 로 막는다(못 재면 `invoice_check_failed` = 막음). 쥔 뒤로는 명단 쓰기가 막히므로 여기서 잰 금액이 곧 활성화 금액이다.
  - 명단 쓰기(한 명·여러 명 라우트, 청구서 갱신 INSERT, 트랙 동기화 UPDATE)에 `MGB_UNCLAIMED_SQL`(신선한 선점이 없을 때만)을 **SQL 조건**으로 붙였다 — 라우트 앞 검사만으로는 «검사 뒤 선점» 경합이 남는다.
  - 활성화가 금액 불일치를 보면 로그를 남긴다(활성화는 그대로 — 돈은 이미 나갔다).
- **④** GET `/invoice` 가 month 없이 불리면 «이번 달에 체크된 학생이 있는 미결제 청구서» 를 먼저 보여 주고, 12개월 안의 다른 미결제 달을 `unpaid_months`(`overdue` 표시)로 싣는다. manager.html 이 그 달 버튼 띠(`.aib-unpaid`)를 그리고 고른 달을 `?month=` 로 보낸다. 못 읽으면 예전처럼 다음 달(목록만 빔).
- **⑤** 수업료 void(라우트·자동)·금액 갱신 UPDATE 에 `NOT_CLAIMED`. `chargeAutopay` 는 청구서를 다시 읽고(거둔·완납이면 안 긁음) 같은 문지기를 지난 뒤 빌링을 부른다. 분명한 4xx 거절에만 선점을 놓고, 5xx·끊김은 쥔 채 둔다(5분 뒤 문지기가 토스에 묻는다). `tossOrderProbe` 는 공용이 되어 b2b-pay-guard.ts 로 옮겼다.

## 검토했다가 버린 것

- **명단 변경을 «주문 금액에 맞춰» 자동으로 되돌리기** — 사람이 고른 체크를 말없이 바꾸는 것이라 안 했다. 막고 «다시 결제» 를 말한다.
- **활성화에서 «낸 돈만큼만» 학생을 열기** — 누구를 뺄지 정할 근거가 없다. 대신 승인 «전에» 막는다.
- **④ 를 화면만 고치기** — 화면은 어떤 달이 안 냈는지 모른다. 서버가 목록을 준다.
- **자동결제 선점을 모든 실패에서 놓기** — 5xx 는 승인됐을 수 있어 이중청구 위험. 분명한 거절만 놓는다.

## 함정 대조(trap-check) 반영

차단 수준 결함은 없었습니다(돈 경로는 전부 막는 쪽으로 실패). 고친 것:

- **청구서 생성/보강**이 «결제 상태를 못 물어봤다» 를 «결제 진행 중» 으로 말하던 것 → `claim_check_failed`(503)로 갈라 말함. 방금 **새로 만든** 청구서는 묻지 않음(조회가 흔들리면 학생 줄 없는 머리만 남던 경로 제거). 월 자동 청구는 그 경우를 «실패» 로 셈.
- **수업료 자동 sweep 로그**가 승인 중이라 0행인데도 «거둠·금액 갱신» 이라고 적던 것 → 0행이면 `unchanged`.
- **명단 여러 명 바꾸기**가 80명 묶음 사이에 결제가 시작되면 «전원 바뀜» 으로 답하고 신청 명단에 전원을 넣던 것 → 실제로 바뀐 학생만 세고 저장, 화면이 «N명만 바뀌었습니다» 라고 말함.
- **학원 화면(manager.html)**: 한 명 체크·생성 실패가 사유 없이 「저장하지 못했습니다」만 띄우던 것 → «결제 진행 중이라 지금은 못 바꿈» / «결제 상태 확인 실패» 를 사람 말로.
- **문지기 주석**이 «쥔 뒤라 언제나 같은 금액» 이라고 단정하던 것 → 502 뒤 5분이 지나 명단을 바꾸고 웹훅이 늦게 오면 어긋날 수 있고, 그 어긋남은 로그로만 남는다고 사실대로 적음.
- 자동 동기화(`syncItemTracks`)의 승인 중 조건에 검사 추가(`ai_billing_price_harness`, 조건을 지우면 실제 FAIL).
