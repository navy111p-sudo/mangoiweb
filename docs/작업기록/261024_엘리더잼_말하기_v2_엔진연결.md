# 엘리더잼 시범판 v2 — 기존 음성·Emma·AI 엔진 연결 코드

v1 안내형 결과물(`/workspace/eleader-pilot-review.zip`)은 변경하지 않고 보존했다. v2는 **기존 엔진 연결 코드와 모의 계약 검증**을 추가한 버전이다. 실제 모델/음성 장치 호출을 완료했다는 의미가 아니다. 운영 미배포, 실제 학생 등록/유료 호출/새 운영 자격증명 생성 없음.

## 연결 경로

기존 로그인 → `/api/ai/eleader/` 서버 소속 검증 → 배정/정책/동의 검증 → 다음 기존 함수로 내부 위임한다. 운영 URL을 다시 fetch하거나 별도 호스팅/로그인을 만들지 않았다.

- 녹음: 기존 `MangoiVoice.record`에 선택적 `transcribe(FormData)` 전송 함수를 주입. 기존 호출자는 원래 `/api/voice/transcribe` 경로 그대로 동작한다. 새 페이지는 인증·동의가 필요한 `/api/ai/eleader/transcribe`만 호출한다.
- 전사: `handleGamesApi`의 기존 Whisper 경로. 서버가 영어로 고정하고 고객이 보낸 언어·모범답·발음평가 옵션을 전달하지 않는다.
- 대화: 기존 `handleWarmupChat`. 현재 배정 문항/문장 예시를 서버에서 구성하고 Emma·난이도 1·아동 영어로 지정한다. 학생 uid·학원 식별자·실제 프로필은 모델에 보내지 않는다. 직전 튜터 답은 브라우저 메모리의 제한된 대화 데이터로만 전달하며 서버 이력을 만들지 않는다.
- 음성: `handleGamesApi`의 기존 영어 TTS, `speaker=asteria`(Emma). 클라이언트는 `MangoAvatar.attach(audio)`와 `prepare(audio)` 후 재생한다. 대체 화자가 오면 화면에 표시한다.
- 기존 엔진의 DB·KV·R2 바인딩과 외부 개인화 설정을 제거한 요청 전용 환경을 전달한다. 따라서 대화 이력·학생 프로필 조회·녹음/음성 캐시 저장 경로를 전용관 호출에 재사용하지 않는다. 모의 테스트에서 KV/R2 접근 0 및 warmup 로그 테이블 미생성을 단언했다.

## 활성화 조건 (현재 모두 운영 미설정)

1. 기존 `ELEADER_PILOT=on`.
2. 별도 배포 승인 값 `ELEADER_LIVE_AI=approved`, 확정된 `ELEADER_POLICY_VERSION`, 보호자/이용자에게 보여줄 `ELEADER_POLICY_NOTICE`가 모두 있어야 한다. `wrangler.toml`에 추가하지 않았다.
3. `eleader_consents`에 해당 학원/학생의 **신뢰할 수 있는 절차로 확인된 보호자 동의**가 있어야 한다. 정책 버전 일치, 음성/AI 처리 각각 동의, 미만료, 미철회가 필요하다. 시범판의 학생/원장 화면에서는 이 행을 생성하거나 자기 승인할 수 없다.
4. 화면에서 이번 기기의 처리 안내 확인을 선택하고 마이크/AI/Emma 버튼을 직접 눌러야 한다. 체크박스는 보호자 동의를 대신하지 않는다.
5. 모든 요청에서 학생 로그인, 학원 소속, 활성 학원, 유닛 배정, 정책/동의를 재검사한다. 다른 학원·원장/교사·미배정·철회 상태는 기존 엔진에 도달하지 못한다.

기존 `/api/consents`도 조사했다. 해당 경로는 로그인 없는 제출을 허용하는 기존 호환 규칙이 있고, guardian_status는 제출 본문에서 받는다. 따라서 그 값만으로 **확인된 보호자 승인**이라고 간주해 새 외부 AI 처리를 자동 활성화하지 않았다. 기존 동의 시스템의 동작은 변경하지 않았다. 실제 보호자 확인/수집 과정과 신뢰할 승인 레코드 연계는 운영 전 결정이 필요하다.

## 비용·취소·보관 경계

- 전사 본문 최대 1 MiB, 녹음 20초, 입력 텍스트 400자, 이전 답 400자. 음성·본문은 로그/DB/R2에 저장하지 않는다.
- 학생당 최근 24시간 120개의 요청 티켓 상한. 같은 요청 ID는 실패한 요청도 다시 실행하지 않는다. 승인/배정/동의 및 상한을 원자 INSERT 조건에서 재확인한다. 기존 엔진 내부 fallback은 한 티켓 안에서 여러 모델 호출을 할 수 있으므로 **120회가 모델 호출/요금 120회 보장은 아니다**.
- 티켓에는 학원·학생·요청 ID·작업 종류·시간만 저장한다. 24시간이 지난 티켓은 그 학생의 다음 요청 때 삭제한다. 미접속 학생에 대한 정기 삭제는 아직 없다. 운영 전 보관 정책과 정기 삭제 절차를 결정해야 한다.
- 녹음 취소는 공유 모듈의 cancel을 사용하고 네트워크는 AbortController, 재생은 pause와 URL 해제로 정리한다. 로그인·탭 숨김·문항 변경·동의 확인 해제 시에도 취소한다. 이전 전사/응답/음성 콜백은 새 화면을 갱신하지 못한다.
- **이미 서버/업체로 전송된 요청은 취소로 회수하거나 과금을 되돌릴 수 없다.** 기존 AI 바인딩 내부 실행 중단까지 검증한 것은 아니다.
- 업체 측 보관/처리 정책을 코드의 로컬 저장 차단으로 보장하지 않는다. 확정된 정책 안내와 처리업체 조건을 검토하기 전 활성화하면 안 된다.

## 변경 범위와 회귀 대응

라우팅 함수에 선택적 내부 어댑터를 전달하며 기존 일반 호출은 그대로 유지한다. 기존 `mangoi-voice-input.js`의 신규 옵션은 하위 호환이다. 이를 사용하는 기존 HTML의 변경은 캐시 버전을 v5→v6으로 올리는 내용이며, 원래 버전이 없던 avatar 화면에도 v6을 붙였다. 공용 녹음 코드의 중복 설명 주석을 줄여 첫 화면 바이트 예산을 유지했다. 실행 순서/defer를 변경하거나 테스트 예산을 올리지 않았다.

첫 통합 검사에서 라우팅 문자열 계약과 첫 화면 용량 예산 2개가 실패했다. 기존 기본 라우터 호출을 보존하고 추가한 모듈의 크기를 줄여 두 검사를 재통과했다. 테스트를 끄거나 기준선을 완화하지 않았다.

## 검증 종류

- 신규 API/Worker/녹음 계약 14개: 실제 Worker 라우터와 기존 엔진 함수는 실행하되 `AI.run`만 모의 응답으로 대체. 전사 필드·Emma 화자·질문 범위·개인 식별자 미전송·저장 차단·동의 차단·만료·철회·중복·상한을 검증.
- 실제 공용 recorder 코드를 VM에서 모의 마이크/MediaRecorder로 실행: scoped 전송 선택, 기존 기본 전송 유지, 권한 대기 취소 시 트랙 해제/업로드 없음, 권한 거절 확인.
- Chromium 기본 안내형 화면 및 별도 음성 연결 계약 검사: 모의 전사→답 입력→AI 답→TTS→avatar attach/prepare/play 순서, 이용 확인 전 차단, 문항 전환/취소/철회 검증. 외부 요청 0건.
- 실제 음성 장치, 실제 AI 품질/지연/비용, 실제 오디오와 입모양 동기화, 원격 D1/배포는 **미실행**.
- 최종 타입/회귀/문법/버전 결과는 v2 결과물의 검증결과.md 및 로그를 따른다.

## 최소 남은 결정

1. 보호자 확인 경로·승인 근거, 정책 버전/안내문(전송 대상·업체·보관·철회/삭제)을 확정하고 승인 레코드 연계 방식을 정하기.
2. 한 학생/학원의 호출 예산 및 정기 메타데이터 삭제 기준 확정. 기존 AI 바인딩은 설정 파일에 있으므로 연결 코드 작성에 새 키는 필요하지 않았다. 실제 사용 가능/과금은 호출하지 않아 미확인.
3. 격리 스테이징 migration/합성 음성 실호출 시험을 승인한 뒤 기존 엔진 실제 동작을 확인하기. 실제 학생 연결 및 운영 배포는 별도 승인.

## Library 전달 차단

v1 ZIP과 PNG 3개를 현재 Library 업로드 도우미로 하나의 배치로 저장하려 했으나 초기 `hosted apps tools/list request failed: network`로 실패했다. 권한을 확대한 동일 절차 재시도도 같은 단계에서 실패했다. **업로드 세션 생성 전 확정 실패**이며 저장된 library_file_id는 없다. 승인 거절이나 결과 불확실 상태가 아니다. 다른 업로드 경로로 우회하지 않았고 같은 절차를 더 반복하지 않았다. 필요한 것은 이 소비 실행 환경에서 Library 도우미 서비스까지의 연결 복구다. 기존 ZIP/PNG 바이트는 로컬에 그대로 있다.

## 추가 격리 샌드박스 검증

`node test-harness/eleader/sandbox-matrix.mjs`는 외부 fetch를 차단하고 메모리 SQLite 및 명시적인 모의 음성/대화 어댑터를 사용한다. 225개 고유 조건 조합 × 3회 = 675회: 동의·정책·배정·학원 활성·사용 확인 192개, 지연 응답 중 철회/배정 삭제/회원 삭제/학원 중지/정책 변경/취소 18개, 다른 학생·학원·게스트·위조 인증 12개, 10회 동시 중복 요청 3개. 이 수치는 독립된 225개 제품 기능이나 실제 AI 실증을 의미하지 않는다.

최초 54회 실패는 지연 응답 반환 전 권한 재확인 누락이었다. 응답 직전 기존 토큰, 회원/학원/배정, 현행 정책·동의, 취소 상태를 재검증하도록 수정한 뒤 675회 모두 통과했다. 이는 이미 업체에 전송된 입력을 회수한다는 뜻이 아니다. 기존 브라우저 검사는 새로고침·로그인 변경·문항 변경·녹음 실패/취소·늦은 콜백·원장 설정·학습 기록을 별도로 검사한다. 실제 마이크, 공급자 및 원격 D1은 미실행이다.
