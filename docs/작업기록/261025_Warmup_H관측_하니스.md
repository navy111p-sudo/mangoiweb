# Warmup H 입모양 관측 하니스 보완

PR1784의 Warmup browser run40164420638은 H anchor(pose8)를 기다리다30초 timeout이 났다. 관련32파일이 파일럿 전후/병합직전/배포커밋에서 동일했고 원본 하니스는 로컬 기준본·파일럿 모두18/18 통과했다. 실제CI 원인을 확정하지는 못했으나, 로컬에서 확인을1초 늦추면 실제H를 그렸어도 음성 종료 후pose0만 읽어 같은 유형의 실패가 발생함을 확인했다.

수정은 test-harness/manual/avatar-viseme-browser.mjs에 한정한다. 추가 로컬실행에서 같은 순간 상태 단언의G(pose7)도timeout이 발생해, F/D/G/H의짧은발음구간에 같은 관측방식을 적용했다. 각 구간재생 직전 기록을 지우고 관측을 시작해, drawImage가 완료되고 재생중이며 실제 미디어시각이 지정된발음구간 안인 기대anchor만 기록한다. 그 재생구간의 기록을 확인하므로 짧은 순간이 지나도 놓치지 않는다. 관측 뒤에는 해제한다. 원래18개 캐릭터/속도/화면폭 조합과 취소·닫힌입·전환 단언은 유지한다. timeout을 늘리거나 기대 입모양을 바꾸지 않는다.

자동 대조2개를 추가한다. 음성종료/닫힌입까지 기다린 뒤에도 실제H기록이 남아 있어야 한다. 다음 재생에서 H를 실제G타일로 대체하면H관측은 실패해야 하며, 직전 성공기록으로 통과할 수 없어야 한다. 누락 대조의500ms는 실패를 기대하는 단언에만 적용되고 정상H단언은 기존기본30초 그대로다.

합성2초 사인파 WAV만 로컬 재생하며 마이크/유료AI/학생데이터를 사용하지 않는다. 최종코드는 CI와 같은Playwright1.58.2 + 설치된Chromium154에서18사례와2대조 통과. H만 처리했던 중간안은G 단언실패로 교체했고 그 실패를 숨기지 않는다. CI와 같은Chromium145.0.7632.6 다운로드는403 Domain forbidden으로 차단돼 로컬동일버전검사는 못 했다. 최종원격CI결과는 PR의정확한head에서 확인한다. 기존 운영아바타/음성비활성gate/배포workflow/자격증명은변경하지 않는다. 이 작업은draft PR 검토/CI까지이며 병합·배포승인이 아니다.
