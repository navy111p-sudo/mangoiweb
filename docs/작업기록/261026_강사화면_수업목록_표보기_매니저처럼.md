## 1. 왜 했나

강사 제안 3번(사진 첨부):
> At teacher's page, can we have a calendar like manager's page with drop down menu for the dates,
> student's contact number, academy, student and ID search box, academy drop down menu,
> Summary / Calendar (for teacher to know who was the previous teacher).
> Can we make it like manager's page but without move button, observe, invite link, message, payment type.

강사 화면(`teacher.html`) 수업 목록은 카드만 있어서 연락처·학원·이전 강사를 한눈에 보기 어려웠습니다.
매니저 화면의 표를 그대로 가져오되, **강사가 쓰지 않는 조작(이동·참관·초대 링크·메시지·결제 유형)은 빼 달라**는 요청입니다.

이어서 사장님 지시: 「폰도 표로 시작하게 바꿔줘」(#1815).

## 2. 무엇을 바꿨나

### #1811 — 표 보기
`cloudflare-deploy/public/teacher.html` 한 파일.

| 함수 | 역할 |
|---|---|
| `classTableHtml(list, opt)` | 표를 그리는 정본. 칸은 매니저 화면 순서 15칸 — Date · Time · Status · Student / Action · Contact · Academy · Class calendar · Schedule · Teacher connection · Attendance · Previous teacher · Last class feedback · Today's feedback · Level · Textbook · Room. `opt.act`(버튼)·`opt.status`·`opt.wi` 를 넘겨받아 화면마다 다른 버튼을 그림 |
| `classActHtml(c,i,t,open,done)` | 카드에 있던 입장·기록 버튼을 떼어 낸 것 — 카드와 표가 같은 버튼을 씀 |
| `extrasHtml(c, wi, asParts)` · `portalContact(c, asParts)` | `asParts` 를 주면 «조각 객체», 안 주면 예전 문자열(카드 보기는 그대로) |
| `bindClassRows(box, list)` | 표·카드 공통 이벤트 연결 |
| `classViewIsTable()` | `#class-view` 선택값으로 판정. 날짜 보기(`renderClsDay`)도 같은 판정 |

- 보기 고르기 `#class-view`(표 / 카드) — 바꿀 때만 `localStorage['mangoi_teacher_class_view']` 에 저장.
- 학생·아이디 검색칸, 학원 드롭다운, 날짜 드롭다운, «요약 / 캘린더»(이전 강사 확인) 포함.
- 빠진 것: 이동·참관·초대 링크·메시지·결제 유형(하니스가 «없다» 를 못 박음).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **매니저 화면 표를 iframe 으로 띄우기** — 버렸음. 강사에게 이동·참관 등 빼야 할 조작이 그대로 따라오고, 권한도 매니저 기준이라 맞지 않음.
- **표 전용 렌더러를 따로 새로 쓰기** — 버렸음. 카드와 버튼·연락처 로직이 두 벌이 되어 한쪽만 고쳐지는 사고가 남. 대신 카드 쪽 함수에 `asParts` 를 더해 «같은 함수가 문자열/조각 둘 다» 를 내게 했음.
- **응답 데이터에 표용 칸을 직접 써 넣기(`st_html` 등 mutate)** — 버렸음. 다른 화면이 같은 객체를 다시 그릴 때 섞임. `opt` 객체로 넘김.
- **폰 기본 = 카드 유지**(#1811 의 원래 판단 — 15칸 표는 폰에서 옆으로 밀어야 함) — 사장님 지시로 뒤집음. 대신 «페이지 전체가 밀리지 않고 표 상자 안에서만 스크롤» 을 확인함(390px overflow −15).
- **기존 사용자 저장값을 지우고 모두 표로 강제** — 버렸음. 카드를 일부러 고른 강사의 선택을 덮어씀.

## 5. 남은 것 / 주의할 것

- **기본 보기를 바꾸면 «샌드박스 하니스» 가 그 경로를 처음 지납니다.** `teacher_week_navigation_harness` 는 `teacher.html` 의 일부 함수만 vm 에 올려 돌리는데, 예전엔 `window.innerWidth` 가 없어 저절로 «카드» 로 떨어졌고 표 경로를 한 번도 안 지났습니다. 기본이 표가 되자 `classTableHtml is not defined` 로 CI 배포 게이트가 빨간불 — 페이지 버그가 아니라 하니스 대역 누락이었습니다. 대역은 **학생 이름을 그리게** 해서 그 하니스의 label 검사가 여전히 뜻을 갖게 했습니다.
- 같은 CI 의 `offline-browser` 실패(관리자 주간 스케줄 `weekly-1280`, «Element is not attached to the DOM»)는 이 작업과 무관한 타이밍 문제였고 다음 실행에서 통과.
- 저장값이 «cards» 인 강사는 계속 카드로 보입니다 — 「표로 안 바뀐다」 문의가 오면 «보기» 에서 표를 한 번 고르라고 안내.
- 같은 날 다른 작업(`261026_강사화면_일지미작성칩_상세숨기기.md`)이 이 표 위에 «일지 미작성» 칩·«상세 숨기기» 를 얹었습니다.
- 로컬 클론이 `main` 만 fetch 하도록 설정돼 있으면(`remote.origin.fetch` 가 main 한 줄) 푸시해도 추적 ref 가 안 생겨 stop-hook 이 「push 안 됨」으로 오경보합니다. `git fetch origin <브랜치>:refs/remotes/origin/<브랜치>` 로 해결.
