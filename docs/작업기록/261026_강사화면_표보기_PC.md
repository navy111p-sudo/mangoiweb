## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법
- **표를 따로 그리는 renderTable() 신설** — 버림. `renderClasses` 는 지문(sig)·60초 tick·상태 판정·입장 시간창·연기/보류/노쇼/다른 방 경고 등
  수십 개 분기를 갖고 있다. 표를 따로 그리면 그 판정을 두 벌 갖게 되고(2장 「같은 판정이 두 곳이면 한쪽만 고쳐진다」), 반드시 어긋난다.
  → **줄 마크업은 한 글자도 안 바꾸고 CSS 배치만 바꿨다.** 브라우저 검사가 「보기 전환 전후 줄 HTML 동일」을 매번 확인한다.
- **renderClasses 안에서 머리줄을 그리기** — 버림. 지문이 같으면 일찍 return 하는 구조라 보기를 바꿔도 다시 안 그려진다(그렇다고 지문에 보기값을 넣으면 결합이 생긴다).
  → 관찰자(MutationObserver)가 innerHTML 교체를 보고 머리줄을 다시 넣는다. renderClasses 는 보기 설정을 모른다(하니스가 확인).
- **폰에서도 표 허용** — 버림. 390px 에서 3열은 가로 스크롤이 난다(보고서의 A안 단점 그대로). 폰은 저장값과 상관없이 늘 카드.
- **상세 숨기기에 다른 방 경고·학부모 요청·일지 버튼까지 포함** — 버림. 그것들은 «지금 해야 할 일» 이라 숨기면 사고가 난다. 참고 정보 3종만 숨긴다.
- hover 는 색만(1-3 규칙: 크기·위치 고정). 연기·보류·다른 방 줄은 hover 에도 제 배경 유지.
