## 1. 왜 했나

레벨 고르기 칸은 고르는 순간 저장됐습니다. 그런데 레벨이 바뀌면 판단력 훈련이 밴드 상태를 새로 만듭니다
(`api-judgment.ts` `resolveReadingBand` → `emptyBandState` — 학생이 고른 모드·나이대·자동 조절 이력이 기본값으로).
그래서 **잘못 고른 한 번**이 곧바로 원부 쓰기 + 그 초기화가 되고, 되돌리려고 다시 고르면 초기화가 한 번 더 일어났습니다.

## 2. 무엇을 바꿨나

| 파일 | 내용 |
|---|---|
| `cloudflare-deploy/public/teacher.html` `openEval` | 레벨을 고르면 저장 요청 «전» 에 `window.confirm` — 「이 학생의 레벨을 바꿀까요? / 학생 이름 / Lv 5 → Lv 12 / 판단력 훈련은 이 레벨부터 다시 시작해요(학생이 고른 모드·나이대 설정은 기본값으로 돌아가요)」(한/영). **취소**면 요청 0 · 칸을 지금 값으로 되돌림(미등록이면 «미등록» 줄로) · 칸 안 잠김 · 빨간 안내 안 띄움(실패가 아니라서). 라벨도 «고르면 바로 저장돼요» → «고르면 한 번 묻고 저장해요» |
| `test-harness/teacher_log_level_input_harness.mjs` | `window.confirm` 대역(묻는 글자 기록 · 답을 정해 둠) + 확인창 검사 13종 → 120종 |

서버(`src/`)는 한 줄도 안 바꿨습니다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **화면 안에 우리가 그리는 확인 상자** — 버림. 이 화면에서 «되돌릴 수 있지만 영향이 큰» 고르기는 이미 `window.confirm` 을 씁니다
  (4주 목표 바꾸기·지우기 `.cls-goal select` · 학부모 요청 «반영함»). 같은 화면에서 확인 방식이 둘이면 강사가 헷갈립니다.
- **«저장» 버튼을 따로 두기** — 버림. 일지에는 이미 «보내기» 가 있어 버튼이 둘이 되면 «레벨도 보내기로 저장되는 줄» 알기 쉽습니다
  (레벨은 일지가 아니라 학생 값이라 따로 저장합니다 — 앞 작업기록 3절).
- **판단력 훈련 안내를 빼고 짧게** — 버림. 확인창을 넣는 이유가 그 초기화라, 그 사실을 말하지 않으면 «예» 를 누르는 사람이 무엇을 정하는지 모릅니다.
