## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **출결을 «자동 판정만» 보여 주기** — 버림. 강사 화면 수업 줄에는 이미 «학생 출결» 이 자동으로 보인다. 요청은 «일지에
  넣어 달라» 이고, 자동 판정은 `unknown`(누군지 못 가린 접속)·`waiting` 이 흔해 강사가 확인할 자리가 필요하다.
  그래서 «자동으로 미리 고르고 강사가 확인·수정» 으로 했다.
- **고르지 않으면 «출석» 으로 채우기** — 버림(CLAUDE.md 2장 «측정할 수 없는 값을 그럴듯하게 채우고 싶을 때»). 안 고르면 null.
- **필수 입력으로 만들기** — 버림. 일지 창은 «칩만 눌러도 끝» 이 설계 원칙이고(필리핀 강사 부담), 저장이 막히면 일지 자체가 안 남는다.
- **이 값을 급여·노쇼 판정에 쓰기** — 하지 않음. 그 정본은 `class_no_show` + `no-show-truth.ts` 이고 급여가 걸려 있다.
  강사가 고른 출결은 «강사 확인 기록» 일 뿐이다(정본 머리말에 적어 둠).
- **레벨을 화면 값(body.student_level)으로 받기** — 버림(«본문 값을 안 받기» 원칙). 서버가 원부에서 직접 읽는다.
- **학부모 화면(`eval.html`)·관리자 평가 목록에 출결 표시** — 이번엔 안 함. 요청 범위가 «강사 화면» 이고, 학부모에게
  «지각·결석» 을 보이는 것은 사람이 정할 일. 값은 `student_evaluations` 에 남아 있어 한 줄로 붙일 수 있다.

## 5. 남은 것 / 주의할 것

- 🔴 **학생 레벨은 거의 비어 있습니다** — [잰 것 — 2026-10-27 D1] `students_erp` 29,570명 중 `level` 이 있는 학생 **9명**,
  예약이 살아 있는 학생 536명 중 **8명**. 그래서 창에는 대부분 «Student level: Not set» 이 뜹니다. 코드가 아니라 **데이터** 문제이고
  (레벨은 레벨테스트 배치 `student-placement.ts`·관리자 교재 일괄배정만 씀), 강사가 직접 레벨을 넣게 할지는 사람이 정할 일.
