## 1. 왜 했나

사장님이 스크린샷과 함께 전달한 제안 3건(영문 원문 요지):

1. **강사 화면(teacher.html)** — 「일부 학생의 연락처가 *여전히* 안 보인다」. 표의 «학생 · 연락처 · 학원» 칸이 `— · MANGOAI` 로 비어 있었다.
2. **관리자 화면(admin.html 「오늘 수업」 = `js/adm-today-classes.js`)** — 시간 칸이 `16:00`(24시간제)이라 «시작·끝을 한국 시간 12시간제로» 해 달라.
   ⚠️ 스크린샷의 화면은 manager.html 이 아니라 **admin.html 의 「오늘 수업」 카드**였다(「Joinable only」·「📚 Bulk assign」 문구로 확인). manager.html 은 이미 `MangoiClassDisplay.range` 로 «4:00pm – 4:20pm · 20 min» 을 그리고 있었다.
3. **강사 화면** — «관리자 화면(학생 상세 › 스케줄)처럼 월(Month) 보기를 넣어 달라». 강사 화면에는 «주간 전체 보기» 하나뿐이었다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **연락처: 강사 화면에 `student_retention` 조회를 «한 줄 더» 붙이기** → 버림. 번호 판정이 세 번째 파일에 복제된다(규칙서 2장: 번호 판정 정본은 `notify-contacts.ts`). 그래서 같은 파일에 «화면용 일괄» 정본을 두었다. 발송용 `phonesForStudent`(학생·학부모를 갈라서 줌)는 손대지 않았다.
- **연락처: 매니저 화면(`api-admin.ts` classes/today)도 같은 정본으로 바꾸기** → **이번엔 안 함**(지시 범위 밖). 지금 매니저 화면은 `student_retention` 만 보므로, 직원이 학생 상세에 넣은 번호(`student_erp_override`)는 **강사 화면에만 뜨고 매니저 화면엔 안 뜬다.** 맞추려면 classes/today 의 2000행 `phoneMap` 을 `loadContactPhones(그날 학생 uid)` 로 바꾸면 된다(사람 결정 대기).
- **연락처: 없는 학생 번호를 학부모·카카오 칸으로 채우기** → 금지(규칙서 2장 «틀린 번호로 학부모에게 전화하는 것이 빈칸보다 나쁘다»). 대신 «왜 비었는지» 를 화면이 말한다.
- **시간 칸: 기존 `hhmm()` 을 12시간제로 바꾸기** → 버림. `hhmm` 은 강사 입장·출결 시각 4곳에도 쓰여 요청에 없던 칸까지 바뀐다. 시간 칸 전용 함수를 따로 뒀다.
- **시간 칸: `toLocaleTimeString({hour12:true})`** → 버림. 로케일·엔진마다 «오후 4:00»/«4:00 PM» 으로 달라진다. 강사·매니저 화면의 `MangoiClassDisplay.time` 과 같은 모양(«4:00pm»)을 «+9시간 UTC» 로 결정론적으로 만든다.
- **월 보기: 화면이 `?week=` 를 5~6번 불러 한 달을 이어 붙이기** → 버림. 주간 호출은 오늘 목록 보강(출결·평가·노쇼·인수인계)까지 통째로 돌아 무겁다. 서버가 이미 읽어 둔 강사의 예약 행을 «한 달로 펼치기만» 하는 경량 경로가 한 번에 끝난다.
- **월 보기: 월 전용 판정을 새로 적기** → 버림. 주간의 판정·줄 모양을 함수로 빼서 둘이 함께 쓰게 했다(한쪽만 고쳐지는 사고 방지 — 하니스가 «둘 다 그 함수를 쓰는가» 를 본다).
- **월 보기: 페이지를 열 때 바로 이번 달을 받기** → 버림. teacher.html 머리말 계약 «첫 화면 API 1회». 접이칸을 «열 때» 처음 부른다.

## 5. 남은 것 / 주의할 것

- **연락처는 여전히 대부분 «—» 일 수 있다 — 고장이 아니다.** 카페24 원본에 학생 번호가 없다(명부 29,512행 중 번호 4행, 2026-09-16 실측). 보이는 번호는 «이탈 위험 명단»(만료·휴면 — 2026-09-07 실측 223행 중 번호 199명, 매일 바뀜)과 직원이 학생 상세·수강신청에서 넣은 번호뿐. 더 늘리려면 **직원이 학생 상세에서 번호를 넣거나**, 카페24 쪽 번호 적재(별건 — `docs/구서버_Neo4j_전화번호_적재요청_2차_2026-08-30.md`)가 필요하다.
- **매니저 화면과의 차이**(위 3장): 직원이 넣은 번호는 지금 강사 화면에만 보인다. 맞출지는 사람 결정.
- 강사 화면 연락처는 그 강사의 «자기 수업» 학생에게만 실린다(서버가 강사 예약으로 이미 거른 줄에만 붙임). 캐시(localStorage)에는 번호를 남기지 않는다(옛 동작 그대로).
- 월 달력은 «언제 무슨 수업이 있나» 만 그린다 — 출결·평가·연락처는 날짜를 눌러 그 날 목록에서 본다. 주간과 같은 규칙이라 **카페24 출석 기록에서만 오는 수업(c24-*)은 월·주 달력에 없다**(오늘 목록에만 있다 — 원래 동작).
- 월 달력은 주간과 같이 1회성 대체강사(`class_substitutions`)를 반영하지 않는다(주간도 오늘만 반영 — 원래 동작).

| 찾은 것 | 무엇이 문제였나 | 고친 것 |
|---|---|---|
| 🔴 «받아 둔 번호» 조회 실패가 «다 물어봤다» 로 위장 | `loadOverridePhones` 가 실패를 삼켜(빈 값) 정본이 `complete=true` 를 냈다 — 6장에서 명부·이탈위험은 고쳤는데 세 원천 중 첫째는 **일부러** 안 봤다(옛 주석: «그 표는 드물게만 채워져 있어 빠져도 크게 안 틀린다»). 그 판단을 뒤집었다 — 그 표는 직원이 손으로 넣은 번호라, 빠지면 바로 그 학생이 «명부에 번호가 없다» 는 거짓 안내를 받는다 | `loadOverridePhones(env, uids, { report })` — 표를 못 만들거나 청크가 실패하면 `report.complete=false`(던지지는 않는다). ⚠️ **받은 청크의 번호는 그대로 쓴다** — 처음엔 «한 청크라도 실패하면 던진다(strict)» 로 짰다가 함정 대조가 짚었다: 그러면 잘 받은 학생들까지 명부 번호로 떨어져 «받아 둔 값이 명부를 이긴다» 가 깨진다(「오늘 수업」은 하루 130명 남짓이라 청크가 둘). 그래서 공용 `selectInChunks` 에 `onChunkError`(건너뛴 청크가 있으면 알림만 — 건너뛰기는 그대로)를 더했다. report 를 안 넘기는 호출(학생 상세 쪽)은 예전과 똑같다 |
