## 1. 왜 했나
- 엘리더잼 원장님 제보: 「원장님 아이디로 로그인해서 A.i 말하기를 했는데, 제가 dog 을 얘기하자고 하는데 계속 고양이를 얘기하네요(녹화함)」.
  - ⚠️ 녹화 영상은 이 작업 환경에 첨부되지 않아 **못 봤다.** 아래 원인은 코드로 재현한 것이다.
- 코드 원인 셋 — 모두 `cloudflare-deploy/src/eleader-l1.ts` 의 `eleaderL1Topic()` 이 만드는 지시(`lesson_topic`)에 있었다.
  1. 1권(「반려 고양이와 좋아하는 마음」)은 **20문항이 전부 고양이**다. 지시는 매 턴 «다음 책 질문을 **뜻·핵심어 그대로**» 묻게 했다.
  2. 지시에 박힌 예문이 **고양이로 끌고 가는 문장**이었다 — 「Dogs are fun! By the way, do you like cats too?」, 「You told me you like dogs! … Do you like cats too?」.
  3. 지시는 **매 턴 새로** 만들어지고 «학생이 방금 한 말» 만 싣는다 → 「dog 얘기하자」 다음 턴에 아이가 「Yes」만 하면 그 요청은 지시에서 사라진다.
  - ⟹ 아이가 주제를 바꿔 달라고 해도 한 턴 안에 고양이로 돌아간다. 10/26 고침(#1809·#1817)은 «학생 대답에 먼저 반응» 까지였고, «주제를 바꿔 달라는 요청» 은 다루지 않았다.

## 2. 무엇을 바꿨나
- `cloudflare-deploy/src/eleader-l1.ts`
  - **`eleaderL1Wish(said)`** (판정 정본) — 학생 말에서 «고른 주제» 를 결정론으로 뽑는다. 결과: 주제(영어 소문자 낱말 1~3개) · `''`(책으로 돌아가기) · `null`(요청 없음).
    - 영어: `talk / speak / chat about X`, `tell me about X`. 「don't / stop / not … talk about X」 는 요청 아님.
    - 한국어: `X 얘기 / 이야기 / 에 대해`. X 는 영어 낱말(「dog을」→ dog) 또는 표(`L1_WISH_KO`)에 있는 낱말만(강아지→dogs …). 「X 얘기 그만 / X 말고」 는 요청 아님. 「책 얘기」 → 책으로 돌아가기.
    - 지시처럼 읽히는 낱말(ignore·system·prompt …)·아이 금지어(`reply-sanity.ts` `unsafe`)가 섞이면 주제로 받지 않는다.
  - **`learnerWish()`** — 고른 주제를 KV(`SESSION_STATE`) `eleaderl1wish:<uid>:<session>:<book>` 에 6시간 기억. 새 대화·다른 책은 책 주제로 시작. KV 가 없거나 고장이면 «이번 말» 만 따르고 대화는 막지 않는다(로그 한 줄).
  - **`eleaderL1Topic(…, wish)`** — 주제가 있으면: 「학생이 X 이야기를 골랐다 · 책 주제로 돌아가지 말 것」, 다음 책 질문은 **문형은 그대로 대상만 X 로**(「Can a cat run?」→「Can a dog run?」), 맞지 않으면 X 에 관한 쉬운 질문 하나, 예시답도 X 로. 고양이로 끌고 가는 예문은 싣지 않는다. 문항 번호는 그대로 넘어간다(진행 표시·힌트와 어긋나지 않게).
    - **주제가 없으면 지시가 예전과 한 글자도 같다**(main 대비 8,800건 대조).
  - 응답 헤더 `X-Eleader-Topic: <주제>` — 화면 표시용.
- `cloudflare-deploy/public/js/eleader-l1.js` (`?v=3`) — 진행 막대에 「🔄 주제: dog / Topic: dog」, 힌트에 「(책 예시예요 — 지금은 «dog» 이야기로 바꿔서 말해 보세요 / book example — say it about "dog" now)」. 새 대화면 지움.
- `cloudflare-deploy/public/warmup.html` — 스크립트 `?v=2` → `?v=3`, `test-harness/asset-versions.json` 원장 기록.
- 새 하니스 `test-harness/eleader_l1_topic_wish_harness.mjs`.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법
- **「관련 없는 질문 금지」 를 지우거나 책 질문을 빼기** → 버림. 책 20문항 진행(질문 n/20·힌트)이 원장님이 원한 수업 틀이다. 문항은 그대로 넘기고 «대상만» 바꾸면 문형 연습은 남는다.
- **주제 판정을 모델에게 맡기기**(«학생이 주제를 바꾸고 싶어 하면 따라라» 한 줄) → 버림. 지시는 매 턴 새로 만들어져서 모델이 히스토리에서 스스로 찾아야 하고, 지시의 다른 줄(«책 질문을 핵심어 그대로»)과 정면으로 부딪힌다. 결정론 판정이면 하니스가 그대로 돌려 볼 수 있다(10/26 접속사와 같은 이유).
- **화면이 주제를 본문에 실어 보내기** → 버림. 이 통로는 «본문 값을 믿지 않는다»(`lesson_topic`·`textbook` 을 버림)가 원칙이다. 서버가 학생 말에서 뽑아 서버에 기억한다.
- **웜업 히스토리(`warmup:<session>`)를 읽어 지난 요청 찾기** → 버림. 웜업 엔진(`src/index.ts`, 공동 금지구역) 내부 형식에 묶인다. 별도 KV 키 하나가 단순하다.
- **한국어 낱말을 기계번역** → 안 함. 모르는 말을 영어로 지어내지 않는다(이 저장소 원칙). 표에 없는 한국어 주제는 예전처럼 «학생 말 인용» 만으로 반응한다.

## 5. 남은 것 / 주의할 것
- 원장님이 말한 «캐피 주제» 가 무엇인지는 확인 못 했다(영상 미첨부). 이 통로는 웜업 엔진에 `user_id` 를 넘기므로, 그 계정에 `students_erp.textbook` 이 배정돼 있으면 웜업 엔진(`src/index.ts`, 공동 금지구역)이 «[오늘 수업 정보] 교재… 교재와 관련된 다음 질문» 줄을 **함께** 붙인다 — 엘리더잼 책 지시와 주제 지시가 두 개가 된다. 영상에서 교재 이름(예: CAPPY)이 보였다면 이 줄을 의심할 것(고치려면 A 담당자와 상의).
- 판정은 «명시적 요청» 만 본다. 아이가 「I like dogs」 만 반복하는 것은 주제 요청이 아니다(예전처럼 반응 후 책 질문).
- 한국어 주제 표(`L1_WISH_KO`)에 없는 낱말은 바뀌지 않는다. 자주 나오는 말이 있으면 표에 추가(하니스 ①절에 짝으로 넣을 것).
