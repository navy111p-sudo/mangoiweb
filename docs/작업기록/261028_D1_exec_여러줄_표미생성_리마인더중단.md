# 2026-10-28 — D1 `exec()` 여러 줄 CREATE: 운영에 없던 표 6개 · 9/20 뒤로 «원리상» 못 나가던 수업 전 리마인더

> 한 줄 요약: `env.DB.exec(\`CREATE TABLE … (\n…\n)\`)` 처럼 **여러 줄로 쓴 CREATE 는 운영 D1 에서 한 번도 돌지 않았다.**
> 그 방법으로만 만드는 표 6개가 운영에 없었고, 그중 «리마인더 발송 장부» 가 없어 **9/20(#1044) 뒤로는 번호가 있는 학생이 있어도 수업 30분 전 문자를 한 건도 못 보내는 상태**였다(판단).
> ⚠️ 그 전에도 실제로 나간 문자는 8건뿐이었다(8/7~9/18) — «잘 나가다 멈췄다» 가 아니다.
> 7곳을 `prepare(…).run()` 으로 고치고, 같은 이름의 옛 하니스(«이름만 찍기»)를 «전수 FAIL» 로 바꿨다.

## 1. 왜 했나 — 제보가 아니라 «다음 개선 3가지» 점검에서 나왔다

- 「다음 개선할 점」을 고르려고 운영 D1 을 SELECT 로만 대조하다가, 코드가 만드는 표 몇 개가 **운영에 아예 없다**는 것을 봤다.
- Cloudflare 문서(D1 Worker API — `exec()`): 「The input can be one or multiple queries separated by `\n`」.
  즉 exec 는 **줄마다 따로** 실행한다. 여러 줄 CREATE 의 첫 줄 `CREATE TABLE IF NOT EXISTS x (` 는 그 자체로 «incomplete input» 이라 던진다.

## 4. 고친 것

- 위 7곳(표 6 + `payment_orders` 1)을 **한 문장씩 `prepare(…).run()`** 으로. 인덱스처럼 한 줄인 것은 exec 그대로 둔다.
- `api-mango.ts` 의 여러 줄 exec **4곳은 일부러 안 고쳤다**:
  - `students_erp` 3곳 — 표는 카페24 동기화가 만든다. 둘은 `try{}` 안이라 동작 영향 없음.
    `POST /api/admin/students/erp`(옛 단건 등록, 화면 호출 0곳)는 고치면 «user_id 없는 옛 모양 행» 을 넣기 시작한다(되살리면 데이터를 바꾸기 시작하는 자리).
  - `enrollments` 1곳 — 데모 시드 `try{}` 안, 표는 이미 있다.
  - 하니스 `ALLOW` 에 «파일|표» 와 «정확한 개수·이유» 로 적었다(늘면 새 결함, 줄면 낡은 예외 → 둘 다 FAIL).

## 5. 검토했다가 버린 방법

| 방법 | 버린 이유 |
|---|---|
| 운영 D1 에 표를 MCP 로 직접 `CREATE` | 1-1 «D1 은 SELECT 만». 그리고 코드가 고쳐지지 않으면 새 환경에서 또 같은 일이 난다 |
| exec 에 넘기기 전에 줄바꿈을 공백으로 바꾸는 공용 헬퍼 | 문자열 안 줄바꿈(기본값·주석)까지 바뀌고, 「exec 는 여러 문장」이라는 뜻이 남아 다음 사람이 또 여러 줄을 넣는다. 한 문장은 prepare 가 정답 |
| `api-mango.ts` 4곳도 한꺼번에 고치기 | 위 4절 — 하나는 되살리면 옛 모양 행을 넣기 시작한다. «지금 죽어 있는 편이 안전한» 자리 |
| 옛 하니스처럼 «이름만 찍기» 유지 | **바로 그것이 3주 동안 이 사고를 살려 둔 이유** — 10/4 #1373 하니스가 이 자리들을 «ℹ️ 사람 확인 대기» 로 찍고 있었는데 아무도 안 읽었다 |
