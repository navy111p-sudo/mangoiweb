# 강사 «오늘의 수업» — 수업이 있는데 «검색 결과가 없습니다 / 수업 없음» 으로 보이던 것 (검색칸의 자기 로그인 아이디)

- 날짜: 2026-10-28
- 작업자: Claude (사장님 제보 — 중국어 강선생님 화면)
- 브랜치 / PR: `claude/teacher-search-own-id`

## 1. 왜 했나

사장님 제보(스크린샷): 「중국어 강선생님 분명히 수업이 있는데 왜 없다고 나와?」

화면(`teacher.html`, 강선생님 로그인 · 10-28):
- 제목 옆 **«오늘의 수업 (2)»**
- 그 아래 **«검색 결과가 없습니다»**
- 주간 목록(10-26 ~ 11-01)이 **7일 전부 «수업 없음»**
- **«학생 이름 / ID» 칸에 `hq_t_kang`**(= 강선생님 자기 로그인 아이디)

**[코드로 확인한 것]**
- 제목 옆 숫자(`cls-count`)는 필터 **전** 수업 수입니다 ⟹ 오늘 수업 2건은 실제로 내려왔습니다.
- «검색 결과가 없습니다» 는 `renderClasses` 의 `if(unfiltered.length && !list.length)` 분기 — **수업이 있는데 필터가 전부 걸렀을 때만** 나옵니다.
- 필터 정본 `portalRows()` 는 검색어를 «학생 이름 + 학생 ID + 영문 이름» 에서 찾습니다. `hq_t_kang` 은 강사 아이디라 어떤 학생에도 안 맞습니다.
- 주간 목록·다른 날 보기(`weekDayBodyHtml`)도 같은 `portalRows()` 를 거치는데, 걸러져 비면 **«수업 없음»** 이라고 적었습니다 ⟹ «수업이 사라졌다» 로 읽혔습니다.

**[확인 못 한 것]** 그 칸에 아이디가 «어떻게» 들어갔는지는 모릅니다. 화면 코드에 그 칸을 채우는 곳은 없고(`grep portal-search` — 읽기·이벤트 등록뿐),
`autocomplete="off"` 도 이미 있습니다. 가장 그럴듯한 것은 **브라우저 비밀번호 관리자의 아이디 자동완성**입니다 — 이 화면에는 `<form>` 이 하나도 없고
비밀번호 변경 칸(`pw-cur`)에 짝이 되는 아이디 칸도 없어, 브라우저가 아이디를 넣을 칸을 스스로 고릅니다. 하지만 재현하지 못했으니 **추정**입니다.
사람이 직접 쳤을 가능성도 남아 있습니다(아래 수리는 어느 쪽이든 막습니다).

## 2. 무엇을 바꿨나

모두 `cloudflare-deploy/public/teacher.html` 한 파일(외부 js 변경 없음 → `?v=` 올릴 것 없음).

1. **`portalRows()`** — 검색어가 `DATA.me.username`(로그인 아이디)과 **정확히 같으면**(대소문자·앞뒤 공백 무시) 검색어로 쓰지 않고 칸을 비웁니다.
   필터 정본이 여기 하나라 오늘 목록·주간 목록·다른 날 보기·표 보기가 한꺼번에 고쳐집니다.
2. **`portalFilteredHtml()`(신설)** — 필터가 «있는 수업을 전부» 숨기면
   「필터 «…» 에 맞는 수업이 없습니다 — 수업이 없는 게 아니라 숨겨진 것입니다」 + **«필터 지우기» 버튼**(EN/KO).
   오늘 목록의 그 분기가 이것을 씁니다.
3. **`weekDayBodyHtml()`** — 수업이 있는데 다 걸러진 날은 «수업 없음» 대신 **«필터로 숨겨짐»**. 진짜 빈 날은 «수업 없음» 그대로.
4. **«필터 지우기» 배선** — `document` 위임 클릭(`[data-portal-clear]`): 버튼 포커스를 먼저 놓고 → 검색어·학원을 비우고 → `portalRefresh()`.
5. **비밀번호 변경 카드(`#c-pw`)** — 숨은 읽기전용 `<input id="pw-user" autocomplete="username">` 를 비밀번호 칸 앞에 두고 `render(d)` 가 로그인 아이디를 채웁니다.
   브라우저에 «이 비밀번호 칸의 아이디 짝은 이것» 이라고 알려 주는 표준 방식입니다(크로미움 «비밀번호 폼 만들기» 권고).

회귀 감시: `test-harness/teacher_search_own_id_harness.mjs`(신설).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **`autocomplete` 값을 더 세게(`new-password`·엉뚱한 토큰 등) 바꾸기** — 버렸습니다. 원인이 자동완성이라는 것부터 추정이고,
  크롬은 비밀번호 관리자 채우기에 `autocomplete="off"` 를 무시하는 등 브라우저마다 동작이 달라 «이 값이면 안 채운다» 를 보장할 수 없습니다.
  대신 **어떤 경로로 들어오든 결과가 같게**(자기 아이디면 무시) 만들고, 숨은 아이디 칸은 «원인 쪽 예방» 으로만 덧붙였습니다.
- **칸을 그대로 두고 무시만 하기** — 버렸습니다. 칸에는 `hq_t_kang` 이 보이는데 목록은 전부 보이면 «검색이 고장났다» 로 읽힙니다. 그래서 비웁니다.
- **부분일치로 넓히기**(`hq_t` 로 시작하면 무시 등) — 버렸습니다. 사람이 일부러 친 검색어를 지울 수 있습니다. **정확일치만**.
- **검색칸을 아예 없애거나 학생 검색을 강사 아이디로도 걸리게** — 버렸습니다. 2026-10-26 강사 제안으로 넣은 기능이고, 강사 아이디로 거르는 것은 «이 강사의 수업» = 화면 전체라 뜻이 없습니다.
- **`renderClasses` 의 «조작 중이면 다시 그리기를 미룬다» 가드를 고치기** — 버렸습니다. 일지 저장·보고 요청 버튼이 누르는 도중 사라지지 않게 하는 장치입니다
  (`teacher_action_stability_harness`). «필터 지우기» 버튼 쪽에서 **포커스를 먼저 놓는** 것으로 풀었습니다.

## 5. 남은 것 / 주의할 것

- 🪤 **`#classes` 안의 버튼으로 목록을 다시 그리게 하면 «눌러도 그대로» 가 됩니다.** `renderClasses` 는 포커스가 `#classes` 안 버튼에 있으면
  «조작 중» 으로 보고 다시 그리기를 미루고(`classRenderDeferred`), 그 미룸은 `focusout` 에서야 풀립니다. 새 버튼은 **`blur()` 를 먼저** 하세요(CLAUDE.md 2장에도 적음).
- 아이디가 칸에 들어간 «원인» 은 확인하지 못했습니다. 같은 증상이 다시 오면 그 강사에게 **어떤 브라우저인지·저장된 비밀번호가 있는지**를 물어 보면 원인이 갈립니다.
- `hq_t_kang` 만의 문제가 아닐 수 있습니다 — 같은 브라우저 동작이라면 다른 강사 화면에서도 같은 일이 날 수 있었고, 이번 수리는 모든 강사에게 걸립니다.
- 숨은 아이디 칸 때문에 비밀번호 변경 뒤 브라우저가 «이 아이디로 비밀번호를 저장할까요?» 를 물을 수 있습니다(정상 — 그 계정이 맞습니다).
