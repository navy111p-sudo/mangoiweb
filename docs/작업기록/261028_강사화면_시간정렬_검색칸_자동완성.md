# 강사 화면 «시간 정렬» 확인 + 검색칸 자동완성 보강 (2026-10-28, #1870 후속)

## 1. 제보
사장님 스크린샷: 강사 화면(`teacher.html`) «오늘의 수업» 에서 [시간 정렬] 을 «오름차순» 으로 두자 목록 자리에 «검색 결과가 없습니다».
바로 위 «다음 수업» 줄에는 수업이 보였다. 요청: 오름차순·내림차순이 잘 되는지 확인하고 잘 작동하게.

## 2. 잰 것
- **정렬 계산은 원래 맞았다.** 기존 검사 3종 통과(`teacher_portal_filters` · `teacher_calendar_requirements` · `manual/teacher-today-past-days-browser.mjs` 289/0).
  실제 페이지에서도 오름 → 내림 → 오름, 새로고침 뒤 유지까지 정상(아래 새 검사 ①②).
- 비운 것은 «학생 이름 / ID» 검색칸 — 스크린샷에 강사 로그인 아이디가 **파란 자동완성 배경**으로 들어 있었다. 정렬을 바꾸는 순간 그 값으로 걸러 한 명도 안 남는다
  (새 검사 ③이 수정 전 코드에서 `[]` 로 재현). 크롬 비밀번호 관리자 자체는 헤드리스로 못 일으켜 «자동완성 때문» 은 배경색에서 읽은 추정이다.
- 같은 날 **#1870** 이 같은 뿌리를 고쳐 main 에 먼저 들어갔다 — 내 아이디 정확일치면 비우기 · 비밀번호 칸 앞 숨은 아이디 칸(`#pw-user`) · «필터로 숨겨짐» + [필터 지우기].
  처음 만든 내 수정이 그것과 거의 겹쳐서 **버리고 main 구현을 그대로 둔 채** 빠진 것만 얹었다(리베이스 때 발견).

## 3. 얹은 것 (`cloudflare-deploy/public/teacher.html`)
1. **자동완성 표시(`:autofill`/`:-webkit-autofill`)가 붙은 값도 검색어로 안 쓴다** — 저장된 «다른» 계정 아이디가 채워지면(예: 관리자 계정으로 들어와 있는데 강사 계정이 저장돼 있음)
   #1870 의 «내 아이디 정확일치» 로는 못 잡는다. 사람이 칸을 고치면 브라우저가 표시를 떼므로 그때부터는 정상 검색어다.
   ⚠️ `:autofill` 을 모르는 옛 브라우저는 `matches` 가 던지므로 선택자마다 따로 감쌌다.
2. **시간 정렬 핸들러가 `portalRefresh()` 하나를 부른다** — 같은 «다시 그리기» 코드가 복제돼 있던 것을 지웠다(검색·학원·필터 지우기와 한 곳).
3. ⛔ 처음 판의 «사람이 직접 친 내 아이디는 안 비운다» 예외는 **넣지 않았다** — #1870 이 «로그인 아이디는 학생과 맞을 일이 없다» 로 정하고 검사로 못 박았다(그 결정을 따른다).
