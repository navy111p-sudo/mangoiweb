# 강사 화면 — 쌍둥이 계정(`X` ↔ `mangoai_X`) «수업 요약 / 캘린더» 이력 합치기 (2026-10-28)

> 저장소가 공개라 실제 학생 이름·아이디는 적지 않습니다. 하니스의 이름(`가나다`·`kidaa`)은 지어낸 예시입니다.

## 1. 왜 했나

사장님 「쌍둥이 수업 요약·캘린더 이력도 고쳐줘」 — 바로 앞 작업(`261028_강사화면_쌍둥이계정_중복줄.md` §6)에서
«남은 일» 로 적어 둔 것입니다.

카페24에는 같은 학생이 두 계정(`X` 와 `mangoai_X`)으로 있고, 기록이 **계정마다 갈려** 있습니다.

- `X` — 망고아이 예약(class_schedules, 수강신청 확정 `adm-enroll:*`) · 수업일지(student_evaluations)
- `mangoai_X` — 옛 LMS 출석(attendance `c24-*` present) · 그 수업의 일지

강사 화면 이력창(`/api/teacher/portal?part=student_history`)은 **아이디 하나**로만 읽었기 때문에
예약 줄로 열면 옛 LMS 수업이, LMS 줄로 열면 예약·일지가 통째로 빠졌습니다(«지난 수업» 요약도 반쪽).

## 3. 무엇을 바꿨나

`cloudflare-deploy/src/teacher-student-history.ts` 한 파일(+하니스).

### 3-1. 짝 확인 — `historyTwinOf(db, uid)`

두 아이디를 **같은 학생으로 볼 때만** 잇습니다. 조건이 전부 맞아야 합니다.

1. 아이디가 정확히 `X` ↔ `mangoai_X` (`twinCandidate` — 양방향, **대소문자 그대로**)
2. 짝이 자리표시(`lms`·`type_seed`)가 아님
3. 각 계정의 이름을 세 군데에서 모음 — 예약 학생 이름 · 옛 LMS 출석 이름 · 명부 이름.
   «MANGOAI» 표식·공백을 지운 뒤 **아이디 모양이 아닌 이름만** 남김(`confirmedTwinName` — 중복 줄 작업과 같은 판정)
4. 양쪽이 **각각 정확히 한 이름**이고 **서로 같음**(정확일치)

이름을 못 읽으면(표 없음·D1 실패·1000행 초과) **잇지 않고** 경고 `twin_account` 를 남깁니다 —
«못 읽음» 을 «쌍둥이 없음» 으로 위장하지 않고, 학생 자기 계정 기록은 그대로 보입니다.

### 3-2. 이력 합치기 — `loadTeacherStudentHistory`

- 예약·관찰방·교사변경 이력·대타 조회를 `user_id = ? OR user_id = ?` 로 (uid, 짝 또는 uid). 짝이 없으면 같은 아이디를 두 번 바인딩해 예전과 같습니다.
- **예약은 계정마다 그 계정의 장부(출결·휴가·홀드)로** 판정합니다 — 그 계정 줄에서 열었을 때와 같은 답.
- 일지·옛 LMS 출석도 계정마다 읽고 합칩니다. 각 항목에는 **기록이 있는 계정**을 `student_uid` 로 붙입니다(일지 붙이기가 그 계정으로 찾음).
- 옛 LMS 줄 숨기기(«완료» 예약과 같은 시각이면 감춤)는 두 계정을 한 학생으로 보고 판정. 같은 `c24` 방이 두 계정에 다 있으면 한 줄.
- «지난 수업» 은 두 계정 중 **더 늦은 수업**.
- 짝 쪽 장부·일지·LMS 를 못 읽으면 경고(`twin_account`/`lms_attendance`)만 남기고 학생 자기 쪽은 그대로.

권한(그 학생을 가르친 강사만 열람)은 바뀌지 않았습니다 — 합치기는 권한 확인 «뒤» 입니다.

## 4. 검토했다가 버린 방법

- **명부(students_erp) 이름만으로 잇기** — 기존 `resolveStudentTwins` 방식. 실측 9쌍 중 7쌍이 `X` 쪽 명부 이름이 아이디라 거의 안 이어집니다.
- **이름 없이 아이디만으로 잇기** — 중복 줄 작업 §4 와 같은 이유로 버림. 잘못 이으면 **남의 학생 수업·일지가 강사 화면 이력에** 보입니다.
- **아이디를 대소문자 무시로 잇기** — `Kim`/`kim` 처럼 대소문자만 다른 별개 계정이 실재합니다(CLAUDE.md 2장).
- **두 계정을 한 장부로 합쳐 판정** — 한쪽 계정의 공용방 접속·휴가가 다른 계정 예약의 출결로 섞입니다. 계정별 장부로 두었습니다.
- **`IN (?,?)` 자리표시 만들기** — `d1_bind_limit_harness` 가 새 `map(() => '?')` 를 막습니다. 값이 늘 둘이라 `OR` 로 썼습니다.
