# 강사 화면 — 쌍둥이 계정(`X` ↔ `mangoai_X`) 중복 줄 (2026-10-28)

> 저장소가 공개라 실제 학생 이름·아이디는 적지 않습니다. 아래 «학생 A~F» 는 운영 D1 에서 잰 실제 학생 6명이고,
> 하니스의 이름(`가나다`·`kidaa`)은 지어낸 예시입니다.

## 1. 왜 했나

사장님 「쌍둥이 계정 중복 줄도 고쳐줘」 — 바로 앞 작업(옛 LMS 이력창, `261028_강사화면_옛LMS수업_이력창_오류_날짜목록_월선택.md` §5)에서
«남은 일» 로 적어 둔 것입니다.

카페24에는 같은 학생이 두 계정(`X` 와 `mangoai_X`)으로 있습니다. 강사 화면 수업 목록은
**예약표(class_schedules) 줄** 과 **옛 LMS 출석(attendance `c24-*`) 줄** 을 합쳐 그리는데,
같은 수업이 예약표에는 `X` 로, LMS 에는 `mangoai_X` 로 찍히면 **같은 시각에 두 줄**이 됩니다.
중복 제거(`dropTeacherCafe24Duplicates` → `dropCafe24SlotDuplicates`)가 «아이디 + 절대 시각» **정확일치** 라
아이디가 다르면 원리상 못 잡았습니다.

## 2. 잰 것 (2026-10-28 운영 D1, SELECT 만)

| 항목 | 값 |
|---|---|
| 예약 행과 «같은 날·같은 분» 에 쌍둥이 계정의 LMS 행이 있는 경우 (9/15~10/27) | **44줄 · 학생 6명** |
| 그중 예약 강사와 LMS 강사가 같은 사람(= 한 강사 목록에 두 줄) | **42줄** (나머지 2줄은 대타라 서로 다른 강사 목록) |
| 방향 | 6명 전부 «예약 = `X`(수강신청 확정 `adm-enroll:*`) · LMS = `mangoai_X`» |
| 이름 | LMS 쪽은 6명 전부 «이름 MANGOAI» · 예약 쪽은 5명이 진짜 이름, **1명(학생 F)은 이름 칸이 아이디 그대로** |
| 예약끼리 쌍둥이 겹침(같은 분) | 1건뿐이고 서로 다른 강사(10/1 — 앞서 고친 10/6 사고와 같은 학생) → 한 목록 안 중복 아님 |

실제 44줄을 고친 함수에 그대로 넣어 돌린 결과: **고치기 전 0줄 감춤 → 고친 뒤 36줄 감춤(학생 A~E)**,
학생 F 의 8줄은 그대로 남습니다(아래 §3 규칙 ④).

## 3. 무엇을 바꿨나

`cloudflare-deploy/src/teacher-cafe24-duplicates.ts` 한 파일입니다(공용 `dropCafe24SlotDuplicates` 는 손대지 않음 —
관리자·학생·이력창이 함께 쓰는 정본이라 반경을 넓히지 않았습니다).

정확일치 중복 제거 «뒤» 에 쌍둥이 단계(`dropTwinDuplicates`)를 하나 더 둡니다. 옛 LMS 줄을 감추는 조건 넷이 **전부** 맞아야 합니다.

1. 아이디가 정확히 `X` ↔ `mangoai_X` (`twinCandidate` — student-alias 정본을 그대로 씀, 양방향)
2. 같은 강사 목록 (입력이 이미 이 강사의 예약·LMS 로 좁혀져 있음)
3. 시작 시각이 밀리초까지 같음 — 열쇠를 새로 만들지 않고 `dropCafe24SlotDuplicates` 에 «아이디만 쌍둥이로 바꾼 자리» 를 넘겨 같은 판정을 씀
4. **두 줄의 이름이 둘 다 확인되고 같음** — 「MANGOAI」 표식·공백을 지운 뒤 정확일치(대소문자 그대로).
   비었거나 «아이디 그대로»(`mangoai_` 표기 포함)인 이름은 «모름» 으로 봄 (`confirmedTwinName`)

감추는 것은 늘 **LMS 줄** 입니다. 예약 줄(방·출결이 붙어 있음)은 그대로 남습니다(기존 정확일치와 같은 방향).

## 4. 검토했다가 버린 방법

- **이름 없이 «아이디 + 같은 분 + 같은 강사» 만으로 잇기** — 학생 F 까지 6명 다 풀리지만 버렸습니다.
  student-alias 규칙(2026-10-02)이 「이름이 비었거나 다르면 잇지 않는다 — 남의 수업이 섞이는 것이 더 나쁘다」이고,
  여기서 잘못 이으면 **다른 학생의 LMS 줄이 강사 화면에서 사라져** 그 수업의 일지 버튼이 없어집니다. 두 줄이 남는 것(지금 상태)보다 나쁩니다.
  학생 F 는 그 학생 이름(LMS 쪽)이 동명이인이 많은 이름이라 더더욱 이름 없이 잇지 않았습니다.
- **공용 `dropCafe24SlotDuplicates` 를 쌍둥이 인식으로 바꾸기** — 관리자 「오늘 수업」·학생 화면·이력창이 함께 바뀌는데,
  그쪽은 이번 제보가 아니고 이름 칸 모양도 다릅니다. 강사 목록 래퍼에서만 처리했습니다.
- **`students_erp` 이름을 따로 조회** — 한 번 더 D1 왕복이고, 예약 줄 이름은 이미 `resolveStudentName`(명부 폴백 포함)으로 채워져 옵니다. 새 쿼리 없이 했습니다.

## 5. 확인한 방법

- 타입체크: `node node_modules/typescript/bin/tsc --noEmit` 통과
- 하니스 `test-harness/teacher_cafe24_duplicates_harness.mjs` — 12개 테스트(쌍둥이 6개 추가). «감춘다» 옆에 «남긴다» 를 짝으로:
  이름 모름·다름·**양쪽 다 모름**·시각 1ms 차이·다른 날·쌍둥이 아닌 아이디·취소/연기·자리표시·대소문자 다른 라틴 이름은 남김.
  `api-teacher.ts` 의 실제 붙이기 블록을 오려 실행해 «한 줄만 남는가» 와, LMS 쿼리가 이름(`a.username`)을 계속 뽑는지도 봅니다.
- 변이 12종 전부 실제 FAIL — 쌍둥이 단계 끄기 · 아이디 모양 이름 검사 끄기 · 이름 무시 · **조건 뒤집기** · 쌍둥이 아이디로 안 바꾸기 ·
  감춘 수 안 세기 · 정확일치 결과로 되돌리기 · 지난 예약 이름 빼기 · SQL 에서 이름 빼기 · 대소문자 무시 · **«모름 == 모름» 으로 잇기** · 오늘 수업 이름 빼기.
  (처음 판은 «모름 == 모름» 변이가 통과해 «양쪽 다 모름» 짝 검사를 더했습니다.)
- 운영 44줄 그대로 넣어 실행: 0 → 36줄 감춤, 학생 F 8줄 유지.

## 6. 남은 일 (사람이 정할 일)

- **학생 F 는 아직 두 줄** — 예약 쪽 이름이 아이디라 같은 사람인지 확인할 수 없습니다. 그 예약의 학생 이름이나
  명부 이름(`students_erp.korean_name` — `resolveStudentName` 이 폴백으로 읽음)이 진짜 이름으로 채워지면 저절로 한 줄이 됩니다
  (명부 이름 지정은 야간 동기화 뒤 반영될 수 있음 — 확인 안 함).
- **쌍둥이의 «수업 요약 / 캘린더» 이력은 여전히 반쪽** — LMS 줄로 연 이력에 예약표(`X`) 수업이 안 나오고 반대도 같습니다(앞 작업 §5). 이번 범위 밖.
- 한 학생이 카페24에 두 계정인 것 자체는 카페24 쪽 정리가 근본 해결입니다.
