## 2-1. 병합 전 함정 대조(trap-check)가 찾은 것과 고친 것

PR navy111p-sudo/mangoiweb#1846 의 CI 가 초록인 상태에서 함정 대조를 돌렸고 **실제 문제 2건**이 나와 병합을 멈추고 고쳤습니다.

- 🔴 **이름 변경 + 비밀번호 바꾸기 한 번에 «다른 대리점» 계정 비밀번호가 바뀜**(재현됨) — 처음엔 «이 대리점 아이디인가» 를 `[새 이름, 옛 이름]` 으로 판정했습니다. A 를 B 의 이름으로 바꾸며 B 의 아이디를 넣으면 B 계정이 «주인» 으로 판정됐습니다. ⟹ 주인은 **저장 «전» 이름**으로만, 그 이름을 쓰는 대리점이 **하나뿐일 때만**(겹치면 `shared_center_name` 409 — 지사 판과 같은 판단).
- 🔴 **하니스가 «검사에 걸리면 실제로 막는가» 를 안 봄** — 거절 `return` 을 지워도 통과했습니다. ⟹ PATCH·POST 블록을 오려 **실제로 실행**하게 바꿨습니다. 🪤 그 과정에서 **하니스 자신이 헛돌았습니다** — 블록을 그대로 타입 제거하니 «함수 밖 return» 으로 실패해 실행 검사 15종이 **조용히 건너뛰어졌고** 70/0 이 나왔습니다(변이시험이 «안 잡힘» 으로 드러냄). 함수로 감싼 뒤 벗기고 «실제로 돌았다» 를 전제 검사로 두었습니다(CLAUDE.md 2장에 한 줄 추가).
- 🟡 함께 고친 것: 계정 만들기 두 줄을 **`batch`(한 묶음)** 로(범위만 빠진 계정이 `autoSeedOne` 으로 «none» 이 되는 것 방지) · 비밀번호 바꾸면 그 계정 **세션 전부 끊기 + 로그인 이력에 «누가 바꿨는지»** · 계정 작업 주체가 **강사면 403**(index.ts 한 곳에만 기대지 않음) · 로그인 아이디 정렬을 줄마다 도는 상관 서브쿼리 대신 **이름별로 한 번 묶은 표 LEFT JOIN**(그 정렬일 때만) · 낡은 주석 1줄.
- `adm-core.js` 가 주석 한 줄 바뀌어 `?v=` 를 `2610281-ctsort2` 로 한 번 더 올렸고, 배포된 적 없는 `2610280-ctsort` 는 원장에서 뺐습니다.

## 3. 검토했다가 버린 방법

- **카페24에서 대리점 아이디를 자동으로 가져오기** — 이번엔 못 함. 옛 LMS(`mangoi.co.kr/lms/center_list.php`)에는 «아이디»(예: playeng·sang1) 칸이
  있지만, 그것이 Neo4j `:Center` 의 **어느 속성**에 실려 오는지(또는 아예 안 오는지) 확인이 안 됐습니다. 10/26 에 만든 진단 주소
  (`/api/admin/centers?debug=cafe24_props[&find=playeng]`)의 결과가 아직 없어, 속성 이름을 추측으로 박지 않았습니다(그 진단 주석의 규칙).
  ⟹ 결과를 받으면 `cafe24-sync.ts importCafe24Org` 의 `:Center` Cypher 에 그 칸을 더하는 것이 다음 단계입니다.
  ⚠️ 그렇게 가져와도 **비밀번호는 없습니다**(옛 LMS 원문을 모름) — «보이는 아이디» 와 «로그인되는 계정» 은 별개입니다.
- **옛 아이디를 적어 두기만 하는 칸** — 사장님이 «실제 계정 만들기» 를 고르셔서 안 만듦(그 아이디로 로그인이 안 되면 칸만 늘어 헷갈림).
- **이 페이지(50건)만 화면에서 정렬** — 버림. 921건 중 50건만 섞이므로 «가나다 첫 번째» 가 거짓말이 됩니다. 강사 명부는 한 번에 다 받아 화면 정렬이지만 대리점은 서버 페이징이라 서버 ORDER BY.
- **올림·내림 두 단계만** — 버림. 강사 명부가 이미 «▲ → ▼ → 원래 순서» 라 같은 화면 안에서 규칙이 둘이면 헷갈립니다.
- **수정 창에서 «아이디 + 비밀번호 둘 다» 를 요구** — 버림. 아이디를 미리 채워 두므로 그 규칙이면 연락처만 고치려 해도 «비밀번호를 넣으세요» 로 막힙니다. 지사 PATCH 와 같은 «비밀번호를 넣었을 때만» 규칙.

## 6. 덧붙임 — 계정 만들기·비밀번호 바꾸기를 «본사(hq) 계정만» 으로 좁힘 (같은 날 2차)

**왜** — 5절의 «사람이 정할 일» 에 사장님이 「본사 계정만 만들 수 있게 좁혀줘」로 답하셨습니다. 남의 계정 비밀번호를 바꾸는 일이라 «대리점 정보 고치기» 보다 한 단계 좁아야 합니다.

**무엇을 바꿨나**
- 판정 정본 `cloudflare-deploy/src/agency-login-gate.ts` 의 `agencyLoginGate()` 하나(순수 함수). `admin_scope.scope_type` 이 `hq` 일 때만 통과하고, 행이 없으면 시스템 전체권한 계정(`FULL_ACCESS_ACCOUNTS` — admin·cfo·ops_lead)만 통과, 강사는 강사 차단 문구(`forbiddenTeacherBody` — 계정 이름 함께).
- ⛔ `getAdminActor()`·`getScope()` 의 범위 값을 쓰지 않습니다 — 그 둘은 조회 실패를 삼켜 `none` 이나 이름 추측으로 떨어집니다(CLAUDE.md 「getAdminActor().role 로 막았는데 D1 이 흔들리면 그대로 통과」). 그래서 `admin_scope` 를 **삼키지 않고 다시 읽고**, 못 읽으면 **막습니다**(`scope_unknown`).
- `api-admin.ts` 의 PATCH·POST `/api/admin/centers` 는 계정 칸이 손에 닿았을 때만 그 게이트를 지나고(연락처만 고치는 저장은 예전 그대로 `canEditOrg`), 목록 GET 이 `can_login` 을 함께 내려 줍니다(저장 때와 «같은 판정»).
- 화면(`js/adm-core.js` `?v=2610282-cthq`)은 `can_login === false` 일 때만 계정 칸과 안내를 감춥니다(옛 서버라 그 칸이 없으면 그대로 보임 — 최종 판정은 서버).
- 거절 문구는 한/영 병기: 「대리점 로그인 계정은 본사 계정만 만들거나 비밀번호를 바꿀 수 있습니다. / Only HQ accounts can create agency logins or reset their passwords.」

**누가 영향을 받나 — [잰 것 — 2026-10-28 운영 D1, SELECT 만]**
- `scope_type='none'` 계정 4개는 전부 `hq_t_*` 강사 계정이라 **원래 강사 차단에 걸려 있었습니다** ⟹ 오늘 이 기능을 잃는 계정은 **0개**입니다.
- 본사(`hq`) 계정(필리핀 매니저 `mgr_*` 포함)과 `ops_lead`(행 없음 + 전체권한)는 그대로 만들 수 있습니다.
- 그래서 이 변경의 실제 효과는 ① 앞으로 생길 «범위 없는 직원» 계정을 막는 것 ② D1 조회가 흔들릴 때 열리지 않고 닫히는 것 둘입니다.

**검토했다가 버린 방법**
