### `cloudflare-deploy/src/eleader-l1.ts`
- `ELEADER_L1_DAILY_CAP` 120 → **200**(학생 기본). 천장 `ELEADER_L1_CAP_MAX = 500`, 환급 상한 `ELEADER_L1_REFUND_MAX = 20`.
- **계정별 상한** — `eleader_l1_students.daily_cap`(NULL = 기본값). `eleaderL1Access()` 가 `{cap}` 을 돌려주고
  `eleaderL1Enrolled()` 는 그 위의 얇은 이름으로 남겼습니다. 값 해석은 `eleaderL1Cap()` 한 곳.
- 칸은 `addColumnOnce()` 로 **지연 ALTER**(`prepare(...).run()` — 한 문장). `duplicate column` 이면 붙은 것으로 봅니다.
  ⚠️ 칸이 없거나 ALTER 가 실패해도 `daily_cap` 없이 다시 물어 **기본 상한으로 계속 동작**합니다.
- `reserveTurn()` 이 `RETURNING n` 으로 «선점 뒤 오늘 쓴 수» 를 돌려줍니다(상한이면 null).
- **환급** — `refundTurn()`: 엔진이 200 이 아니거나, 던지거나, SSE 의 마지막 `done` 이 `ok:true` 가 아니거나 `done` 없이 끝나면
  한 칸을 돌려줍니다(`refunds < 20` 조건). SSE 는 `watchSseDone()` 이 본문을 그대로 흘리며 `done` 줄만 읽습니다.
- 응답 헤더 `X-Eleader-Used` / `X-Eleader-Cap`(429 에도). 책 목록의 `daily_cap` 도 계정 상한을 냅니다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **상한만 크게 올리기(전체 300 등)** — 버림. 사장님이 학생 200 · 원장 300 을 나눠 정하셨고, 상한은 비용 장치라 한 계정 사정으로 전원을 올리지 않습니다.
- **원장님 아이디를 코드 허용목록(`ELEADER_L1_STUDENTS`)에 넣고 상한을 코드에 박기** — 버림. 그 파일 머리말대로 저장소가 공개라
  학생·원장 아이디를 코드에 적지 않습니다(비밀번호 없는 계정은 아이디만으로 로그인됨). 그래서 D1 칸으로 갔습니다.
- **`daily_cap` 을 `CREATE TABLE` 에 더하기** — 버림. 운영 표는 이미 있어 CREATE 를 다시 안 봅니다(CLAUDE.md 2장 attendance.host).
- **재전송을 화면이 «재시도» 라고 알려 주면 안 세기** — 버림. 본문 값 하나로 비용 상한을 건너뛸 수 있게 됩니다(본문을 믿지 않기).
  대신 «첫 요청이 답을 못 줬으면 그 칸을 서버가 돌려준다» 로 풀어 재전송이 한 번만 세어지게 했습니다.
- **KV 로 «같은 말 30초 안 재전송» 을 서버가 알아채기** — 버림. 결과적 일관성이라 동시 요청에서 새고, 환급 방식이 더 단순합니다.
- **환급 무제한** — 버림. 엔진이 계속 실패하면(시간초과 등 비용이 나갈 수 있는 실패) 상한이 없어집니다. 하루 20번으로 묶어
  하루 엔진 호출은 많아야 «상한 + 20» 입니다.
- **화면이 횟수를 스스로 세기(성공 응답마다 +1)** — 버림. 환급·다른 기기·SSE 실패와 어긋납니다. 서버가 센 값을 헤더로 받습니다.
- **`window.addMsg` 를 감싸 «답변을 받아오지 못했어요» 를 걸러 내기** — 버림. 문구 일치에 기대는 우회라 문구가 바뀌면 조용히 죽습니다.
  `warmup.html` 한 줄에 표시를 보게 했습니다. 순서는 표준이 보장합니다 — 래퍼가 같은 프로미스에 먼저 건 `then` 이 화면의 `await` 보다 먼저 돕니다.

## 5. 남은 것 / 주의할 것

- **원장님 300 은 D1 값입니다** — `UPDATE eleader_l1_students SET daily_cap = 300 WHERE uid = 'ysyt01'`.
  칸은 코드가 첫 요청 때 붙이지만, 값은 사람이 넣어야 합니다. 다른 계정도 같은 줄로 바꿀 수 있고 NULL 로 되돌리면 기본 200 입니다.
- **환급은 «스트림이 정상으로 끝날 때» 판정합니다.** 학생이 중간에 화면을 닫아 스트림이 취소되면 환급하지 않습니다(센 채로 — 비용 쪽으로 안전).
- `addColumnOnce` 는 DB 객체별로 «한 번» 을 기억합니다. 워커가 요청마다 다른 `env.DB` 객체를 준다면 요청마다 ALTER 를 한 번 시도하고
  `duplicate column` 으로 끝납니다(가벼운 왕복 1회 — 동작에는 문제 없음). 못 쟀습니다.
- **턴 단위 사용 기록이 없습니다** — 「누가 언제 몇 번 썼나」를 다시 물으면 이번처럼 세션 단위까지만 답할 수 있습니다. 필요하면 별건.
- 상한·표시는 **한국시간 자정**에 바뀝니다(`kstDay`).
