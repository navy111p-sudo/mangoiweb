# 폰에서 스크롤만 해도 화면이 바뀌던 문제 (탭/스크롤 판정)

- 날짜: 2026-10-28
- 작업자: 사장님(jeong) 음성 제보 · Claude Code 작업
- 브랜치 / PR: `fix-mobile-scroll-mistap` / (PR 은 이 문서와 함께 올라감)

## 1. 왜 했나

- 사장님 음성 메모(20:04): 「휴대폰에서 살짝만 건드려도 자꾸 화면이 바뀌어. 액정이 너무 예민해서
  살짝만 건드려도 바뀌는데, 그러다 보니까 자꾸 터치를 많이 하게 돼.」
- 함께 보낸 화면: 로그인한 학생 홈 — 화면 절반을 차지하는 큰 노란 버튼 두 개
  「수업 입장」(`.cta-enter`)·「오늘의 A.i 학습」(`.cta-pay`).
- **액정이 예민한 게 아니었습니다.** 브라우저는 스크롤에 click 을 안 보내는데(정상),
  우리 코드가 touchend 만 보고 대신 눌러 버렸습니다.

### 원인 (헤드리스 실측으로 재현)

`index.html` ph166(2026-05-29 「모바일 quick-btn click rescue」)의 터치 보충:

```js
document.addEventListener('touchend', function(e){
  ...
  if (btn === touchStartTarget) {
    setTimeout(function(){ if (!tgt._ph166Clicked) tgt.click(); }, 50);   // ← 무조건
```

- 터치 이벤트의 `target` 은 손가락이 미끄러져도 **처음 닿은 요소 그대로**입니다.
  그래서 `btn === touchStartTarget` 은 스크롤이어도 항상 참이었습니다.
- 큰 버튼 위에서 스크롤을 시작하면 → 브라우저는 click 을 안 보냄 → 50ms 뒤 우리가 `click()`
  → 수업 로비로 가거나 `/today.html` 로 넘어감.
- 실제 터치 입력(CDP `Input.dispatchTouchEvent`, iPhone 13 에뮬레이션)으로 잰 것:
  120px 스크롤·25px 밀기 **모두** synthetic click 으로 실행됐습니다.
- 덤으로, click 이 50ms 넘어 늦게 오는 기기에서는 «보충 + 진짜 click» 으로 두 번 실행될 수 있었습니다.

같은 모양(움직임을 안 보는 touchend 실행)이 홈에서 갈 수 있는 자리 네 곳에 더 있었습니다:
전체메뉴 열기(`idx-allmenu.js` `allmenuTrigger`), 전체메뉴 닫기 X·배경, 연기/변경 모달의
방식 고르기 카드(`index.html` ph64), 「교사로 선택」 카드(`idx-x5.js`).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **ph166 터치 보충을 통째로 삭제** — 가장 단순하지만, 원래 «iOS 일부 환경에서 click 이 안 온다» 대비로
  넣은 것이라 그 기기에서 다시 «안 눌린다» 가 될 수 있습니다. 판정을 붙여 살렸습니다.
- **전역(window 캡처)에서 움직인 touchend 를 `stopPropagation`** — 한 곳으로 다 막히지만,
  교재 드래그·스와이프(`idx-vc-mobilefix.js`)와 연기/변경 드래그(`idx-lesson-change.js`)가
  touchend 로 «드래그 끝» 을 알아야 해서 그쪽이 깨집니다. 부르는 자리마다 판정을 묻게 했습니다.
- **판정을 index.html 인라인에 두기** — 첫 화면 예산(blocking)에 들어가고 공동 금지구역 수정이 커집니다.
  defer 파일로 빼서 index.html 은 **순감**(-1KB 남짓, 인라인 276KB → 275KB)입니다.
- **판정 파일이 없을 때 옛 동작(무조건 실행)으로 폴백** — 그러면 파일 로드 실패 시 버그가 돌아옵니다.
  모든 자리에 click 핸들러가 함께 있어 touchend 를 건너뛰어도 브라우저 click 이 처리하므로
  «없으면 건너뛴다(false)» 로 정했습니다. 오판(진짜 탭을 «아니다»)도 같은 이유로 안전한 쪽입니다.
- **스크롤 이벤트로 «아니다» 판정** — 홈에 저절로 스크롤되는 요소가 있으면 모든 탭이 막힐 수 있어
  재 봤습니다: 손대지 않은 4초 동안 scroll 이벤트 0건.

## 4. 확인한 방법

- **브라우저 실측**(Playwright·Chromium, iPhone 13 에뮬레이션, CDP 실제 터치 입력, 로컬 정적 서버):
  - 수정 전(HEAD): 큰 버튼 위 스크롤 120px·밀기 25px → **실행됨**(synthetic click). 경계 검사 2/6.
  - 수정 후: 스크롤·밀기 → 실행 안 됨 / 정상 탭·손떨림 5px 탭 → 1번 실행 / click 안 오는 기기 흉내 →
    탭은 보충 1번, 스크롤은 0번 / 관성 멈춤 터치 → 0번 / 전체메뉴 버튼 위 스크롤 → 안 열림, 탭 → 열림. **6/6.**
