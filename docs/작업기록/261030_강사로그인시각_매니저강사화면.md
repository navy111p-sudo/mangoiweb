# 강사 로그인 시각 — 매니저 화면·강사 화면 (2026-10-30)

- 요청: 2026-10-29 필리핀 매니저 제안 3번 «At managers and teacher's page is it possible to add teacher's log in time»
  → 사장님 «아직 안 되어 있으면 완성시켜줘 · 수백 번 하니스와 샌드박스로 테스트해서 이상 없으면 병합·배포»
- 브랜치: `claude/teacher-login-time`

## 1. 왜 «로그인 시각» 만으로는 안 되나

- 관리자 세션은 30일짜리이고 새벽 4시(KST)에 맞춰 저절로 늘어납니다(`auth-admin.ts` `sessionRenewalPlan`, #1868).
  그래서 강사는 **매일 다시 로그인하지 않습니다.** 로그인 시각만 보여 주면 대부분 «오늘 로그인 없음» 이 되어
  «안 들어왔다» 로 오독됩니다.
- 그래서 **«첫 접속»**(그날 처음 사이트를 쓴 시각 — 로그인된 상태로 연 경우 포함)을 따로 적기 시작했습니다.
- ⚠️ `admin_login_history` 의 `success=1` 에는 **로그인이 아닌 이벤트**도 섞여 있습니다 —
  `pwreset_done` · `created_by:…` · `password_reset_by:…` · `contact_set_by:…`. 진짜 로그인은
  `issueAdminSession` 이 남기는 `reason` 이 빈 행뿐입니다(비밀번호·지문·옛 LMS 통과 모두). `success=1` 만 세면
  «비번을 바꿔 준 날» 이 «로그인한 날» 이 됩니다.

## 2. 무엇을 만들었나

| 자리 | 내용 |
|---|---|
| `src/teacher-login-times.ts` (새 정본) | 하루 요약 판정(`summarizeLoginDay`) · 그날 처음 쓴 시각 적기(`dailySeenPlan`·`noteDailySeen`) · 본사 목록(`loadTeacherLoginDay`·`handleTeacherLoginList`) · 강사 본인 14일(`loadMyLoginDays`) |
| `src/auth-admin.ts` `checkAdminSession` | 세션이 «오늘(KST) 처음» 쓰이는 순간 `admin_daily_seen` 에 한 줄(세션마다 하루 한 번). **적기 → last_seen 갱신** 순서(갱신이 먼저 끝나고 적기가 잘리면 그날은 영영 못 적음). 실패해도 로그인 판정은 그대로 |
| `src/auth-admin.ts` 경로 | `GET /api/admin/login-history?scope=teachers&date=YYYY-MM-DD` — **이미 등록된 경로의 쿼리**라 `src/index.ts`(공동 금지구역) 무수정 |
| `src/api-teacher.ts` | `GET /api/teacher/portal?part=my_login` — 자기 계정만(주소의 아이디는 안 받음) |
| `public/manager.html` | 「🔐 강사 로그인 시각 / Teacher login times」 카드(날짜 선택) — 본사 계정만 보임 |
| `public/teacher.html` | 「내 로그인·접속 시각 (최근 14일)」 카드 — 펼칠 때만 부름(첫 화면 API 1회 계약) |

화면에 나오는 칸: **첫 접속 · 로그인(처음–마지막·횟수) · 마지막 활동(지금 접속 중이면 🟢) · 참고(로그인 실패 횟수 · 오늘 로그인이 없으면 마지막 로그인 날짜)**.
시각은 한국 시간이고 괄호 안에 필리핀 시간(1시간 빠름)을 함께 적습니다.

### 상태(서버가 정하고 화면은 그대로 말함)

- `login` — 그날 실제 로그인이 있음
- `active` — 로그인 없이 «전에 로그인한 상태로» 처음 접속
- `carried` — 탭을 연 채 자정을 넘겨 «이어서 접속»(직전 활동과 15분 안). **출근 시각이라 부르지 않습니다**
- `seen` — 활동은 있는데 시작 기록이 없음(이 기능 배포 «전» 부터 이어진 세션). 시작 시각을 지어내지 않습니다
- `none` — 그날 기록 없음(매니저 화면은 접힌 «이날 기록 없음 N명» 안으로)

## 3. 누가 볼 수 있나

- 강사 목록: **본사만.** 강사는 `index.ts` 의 `TEACHER_BLOCKED_PREFIXES` 가 그 경로를 이미 막고(+ 핸들러에서 한 번 더),
  지사·대리점은 `admin_scope` 를 «삼키지 않고» 다시 읽어 막습니다(못 읽으면 막음 — `org-scope-guard`).
  그 다시 읽은 값이 `teacher` 여도 막습니다 — 강사 차단 두 겹(`isTeacher`·index.ts)이 둘 다 `getAdminActor` 에 기대서,
  D1 이 흔들려 actor 가 «staff» 로 떨어진 날에도 막히게(함정 대조 지적 · `api-mango.ts` 번호없는학생 목록과 같은 짝).
  화면도 `IS_HQ` 일 때만 카드·메뉴를 엽니다(서버 403 + 화면 숨김 짝).
- 강사 본인: 자기 기록만.
- ⛔ IP·기기 정보는 싣지 않습니다(출근 시각을 보는 화면이지 보안 감사 화면이 아님).

## 4. 검토했다가 버린 방법

- **로그인 시각만 보여 주기** — 버림. 세션이 30일이라 대부분 비어 «안 왔다» 로 읽힘(1장).
- **«마지막 활동»(`admin_sessions.last_seen_at`) 만으로 출근 추정** — 버림. 그 칸은 하나뿐이라 «그날 처음» 을 모르고 지난날은 덮여 씀.
- **요청마다 기록 쓰기** — 버림. 관리자 요청마다 쓰기가 하나 늘어남. 지금은 «세션이 그날 처음 쓰일 때» 한 번뿐.
- **`오늘 수업` 표의 줄마다 강사 로그인 붙이기** — 버림. 카페24 줄은 강사 번호 체계가 달라(CLAUDE.md «강사 번호 세 벌») 남의 계정이 붙을 위험. 계정 단위 목록이 정확함.
- **새 API 경로 만들기** — 버림. `src/index.ts`(공동 금지구역) 게이트 3곳 등록이 필요. 이미 등록된 경로의 쿼리·`part` 로 얹음.

## 6. 남은 것·한계

- **«적기 → 갱신» 순서의 대가**(함정 대조 지적, 일부러 그대로 둠): 그날 첫 요청에서만 `last_seen_at` 갱신이
  기록(INSERT) 뒤로 밀립니다(waitUntil 없는 뒤쪽 작업이라 응답 뒤 끊길 위험이 조금 늘어남). 끊기면 다음 요청이
  다시 «오늘 처음» 으로 보고 한 번 더 적는데, `MIN`·`ON CONFLICT` 라 값은 그대로 맞습니다. 반대 순서(갱신 먼저)는
  «갱신만 끝나고 기록이 잘리면 그날은 영영 못 적는» 쪽이라 더 나빠서 이 순서를 골랐습니다(변이시험이 그 반대를 FAIL 로 못 박음).
  ⚠️ 그 갱신이 «계속» 실패하는 드문 경우에는 자정을 넘겨 이어진 접속이 «첫 접속» 으로 갈릴 수 있습니다. 로그인 판정 자체는 안전합니다.

- «첫 접속» 기록은 **배포한 뒤부터** 쌓입니다. 그 전 날짜는 실제 로그인만 보입니다(화면이 그렇게 말함).
- 탭을 연 채 밤새 화면이 켜져 있으면(숨김 상태가 아니면) 그 세션은 자정에 «이어서 접속» 으로 적힙니다 — 출근 시각으로는 안 셉니다.
- 운영 화면(mangoi.ai)은 이 환경에서 직접 못 봅니다. 배포 뒤 매니저 화면에서 카드를 한 번 열어 봐 주세요.
