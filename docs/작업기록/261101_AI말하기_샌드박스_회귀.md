# AI 말하기 샌드박스 반복 검증과 수정 (2026-11-01)

## 요청
사장님이 수백 번의 하니스·샌드박스 검증과 문제 해결을 요청했다. 운영 DB·AI·마이크 호출 없이 localhost에서 실제 페이지를 실행한다.

## 발견과 수정
1. 교재 초기 설정이 상단의 모드 선택 링크를 가려 실제 클릭이 불가능했다. 설정 화면 안에도 모드 선택을 추가하고 좁은 화면의 내비게이션 줄바꿈을 허용했다. 기존 상단 링크도 유지한다.
2. 아바타 closed 이미지 실패로 영상 폴백을 장착한 뒤 medium/wide 오류 콜백이 null 프레임 표를 건드렸다. 장착 당시 프레임 표의 객체 정체성과 현재 캐릭터를 함께 확인한다. 같은 캐릭터를 다시 고르는 경우에도 옛 콜백은 무시한다.
3. localStorage 접근 불가 시 웜업 API 기본 주소 읽기와 eLeader 입구의 토큰 읽기가 예외를 던졌다. 저장값이 없을 때와 같은 기본 경로로 처리하며 인증 없이 별도 API를 호출하지 않는다.
4. 320px 영어 화면에서 설정 라벨과 진행 제목이 넘쳤다. 라벨 줄바꿈 및 진행 제목의 축소·줄바꿈을 허용했다. 화면 전체를 overflow:hidden으로 가리는 방법은 쓰지 않았다.

## 검증 설계
- `manual/ai-speaking-browser.mjs`: 10 화면 크기 × 2 언어 × 4 저장소 상태 × 2 모드 × 2 입력 방식 = 320 실제 브라우저 왕복 시나리오. 실제 pointer hit-testing, 키보드 진입, 가로 넘침(브라우저 반올림 1px 허용), 저장 설정 유지, 새로고침, JS 오류를 검사한다. 외부 요청은 차단, API는 로컬 응답만 사용.
- `avatar_mount_race_harness.mjs`: 콜백 순서·폴백·같은 캐릭터 재장착·현재 콜백 정상 동작 26건. 옛 버그를 넣으면 실패하는 변이도 확인.
- 기존 `speech-preferences-browser.mjs`: 실제 인증·설정 API 코드를 메모리 SQLite에 연결하여 50개 계정/기기 시나리오를 실행. Windows Chrome 경로를 지정하는 환경변수만 추가했다.
- 새 GitHub workflow가 매번 320개 브라우저 조합을 검사한다. 기존 말하기 브라우저 CI와 전체 하니스도 유지한다.
