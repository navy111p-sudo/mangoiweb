# Eric 격리 회귀: 교재와 배경의 취소 경합

## 1. 왜 했나

Eric 수업의 영상 지연, 가상배경 지연, 소음 제거/Office Mode/Krisp,
이전 교재·페이지 복원, 페이지별 필기, 교사 안내를 격리 환경에서 반복 검증하라는 요청이다.
운영 데이터·계정·시간표와 기존 다른 작업 공간은 변경하지 않았다.
필기는 기존 설계대로 같은 탭에서 수업방·파일별로 보관하며 새로고침 이후 보존하지 않는다.

## 2. 무엇을 바꿨나

- `cloudflare-deploy/public/js/idx-main.js`: 취소된 `pdfLoad` 뒤에 원격 요청의 페이지를 적용하지 않는다.
  이전 로드가 늦게 끝나면 최신 30쪽이 이전 요청의 2쪽으로 바뀌던 문제를 재현했다.
- 같은 파일의 `vcSetBackground`: 초기화의 각 await와 초기 추론 뒤에 요청 세대를 확인한다.
  OFF 후 늦게 끝난 초기화가 처리·미리보기·송출을 다시 켜거나 상태 문구를 덮지 않는다.
  초기 추론도 RAF와 `sending` 잠금을 공유하고, A→OFF→A의 이전 타이머를 무효화한다.
  카메라 트랙을 잃은 상태에서도 OFF가 루프를 정리한다.
- `public/index.html`: 변경된 스크립트 캐시 버전을 71→72로 갱신한다.
- 새 회귀: `vc_remote_page_race_harness.mjs`, `vc_background_cancel_harness.mjs`,
  `vc_mic_permission_failure_harness.mjs`, `manual/vc-eric-guide-browser.mjs`,
  `manual/vc-eric-background-browser.mjs`.
- `manual/_pw.mjs`: 명시적인 `MANGOI_CHROME_EXECUTABLE` 경로를 지원한다.

## 3. 왜 그렇게 풀었나

정상 경로의 횟수만 늘리면 취소 이후의 후속 코드와 배경 설정 초기화를 놓친다.
기존 스트레스가 통과한 뒤에도 두 경합을 별도 검사로 재현했으므로 실제 배포 함수 전체를 실행하는 검사를 추가했다.
교재 로드를 직렬화하면 느린 이전 파일을 기다리게 되므로 기존 마지막 요청 우선 정책을 유지했다.
배경은 모드 문자열 비교만으로 A→OFF→A를 구분할 수 없어 요청 세대를 사용한다.
초기 추론과 RAF는 같은 모델에 동시에 send하지 않도록 하나의 잠금을 사용한다.

`REMOTE_MAIN_SOURCE`/`BG_MAIN_SOURCE`로 수정 전 main을 지정하면 신규 경합 검사의 실패를 확인할 수 있다.
Windows Git의 자동 CRLF 변환은 일부 기존 소스 추출 하니스에 오탐을 일으켜 로컬 복제에서 LF로 맞췄다.

전체 회귀에서 확인한 환경 실패의 예는 esbuild의 `Cannot read directory "../../../../..": Access is denied`,
Windows에서 URL pathname을 파일 경로로 사용한 `C:\\C:\\...`/`ERR_UNSUPPORTED_ESM_URL_SCHEME`,
부분 복제에서 생략한 그림·음원 파일이다. 108개를 전부 환경 문제로 분류한 것은 아니다.
범위 밖 나머지 실패는 미해결·미분류로 남긴다. 교재 입장의 유일한 이미지 누락 실패는 이후

SKIP 21개에는 인라인 문법 검사의 러너 90초 타임아웃이 포함된다. 같은 문법 검사는 별도 실행에서

## 5. 남은 것과 주의할 것

실제 교사 PC·카메라·헤드셋·Krisp 가상 장치·실수업·필리핀 회선의 음질과 지연은 미검증이다.
Krisp라는 모의 deviceId가 통과했다는 것은 Krisp 설치나 소음 제거 성능의 증거가 아니다.
Chrome 합성 음원과 DOM 검사는 물리 장치·실제 PDF 미디어·MediaPipe 성능 검증으로 계산하지 않는다.
운영 수업 참여나 유료 API 호출, 인증정보 생성, 감시 자동화 변경은 하지 않았다.
전체 회귀의 환경 실패와 범위 밖 실패는 Eric 해결 완료나 CI 전체 통과로 바꾸어 쓰지 않는다.
검증 후에도 모든 장치와 앞으로의 변경에서 문제가 다시는 없다고 보장할 수 없다.
