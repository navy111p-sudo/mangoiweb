# 수업 입장: ICE 설정 요청이 멈춘 뒤 재시도가 묶이는 문제

2026-11-01. 강사 수업 입장·연결·무음 제보를 조사하며 발견했다.

## 재현과 변경

`vcEnsureIceServers()`의 3초 `Promise.race`는 호출자의 대기만 끝낸다. 원래 `fetchIceServers()`는 제한 시간이 없어 요청 또는 JSON 본문이 멈추면 공유 promise가 영구 대기한다. 다음 입장·재연결도 같은 promise를 재사용하므로 TURN 설정을 다시 받을 수 없다. 페이지 최초 로드는 공유 promise를 통하지 않아 별도 요청도 중복했다.

- 요청부터 JSON 본문까지 2.8초 뒤 AbortController로 취소한다. finally에서 타이머를 지운다.
- 최초 로드도 `vcEnsureIceServers()`를 사용한다. 입장·재연결과 요청 하나를 공유한다.
- 기존 3초 입장 대기 상한, 4시간 갱신, 성공했던 설정 보존을 유지한다.
- index.html과 teacher.html의 idx-main 캐시 주소를 함께 v72로 갱신한다.

## 검증

- 실제 배포 JS의 ICE 블록을 VM에서 실행한 신규 하니스 4/4. 최초 요청 정지, JSON 본문 정지, 동시 입장, 정상 캐시, 갱신 정지 후 재시도, HTTP/JSON 실패를 검사한다.
- 변경 전 소스로 신규 하니스를 실행하면 중복 요청과 갱신 후 재시도 검사 2건이 실패한다.
- 안정성 체크리스트 50/50. 기존 fetch 문자열 검사는 옵션 인자도 허용하도록 수정했다. 취소 동작 자체는 신규 실행 검사로 확인한다.
- TypeScript `node node_modules/typescript/bin/tsc --noEmit` 통과. JS 문법·첫 화면 용량 예산 통과.
- 세션 연장 30/30, 강사 미입장 알림 36/36 회귀 통과.
- 전체 `run.mjs --fast`는 sparse checkout에서 없는 교재·vendor·ops 파일을 읽는 실패가 있어 중단했다. 전체 CI는 별도로 확인한다.

## 범위와 판단

이 결함이 특정 날짜의 입장 실패를 일으켰다는 브라우저 기록은 없다. 운영 회선 문제 전체를 고쳤다고 주장하지 않는다. 기존 중계 강제 정책과 소리 설정·권한·세션 정책은 바꾸지 않는다. 느린 요청을 무한 대기시키는 것이 아니라 다음 시도에서 복구할 수 있도록 하는 변경이다.

중국 전체나 특정 통신사 장애로 단정하지 않는다. TURN을 무조건 강제하는 변경도 하지 않는다. 실제 장애는 사이트 접속·인증·방 입장·미디어 전달·스피커 출력 단계로 나누어 양쪽 단말에서 확인해야 한다. 공개 저장소이므로 운영 조회의 개인별 원자료·접속 IP·자격증명은 기록하지 않는다.


## 후속 보강 (2026-11-01)
- 최신 main 변경을 보존해 병합하고, 겹친 idx-main.js v72 대신 v73을 사용한다.
- ICE 목록과 URL 형식을 전부 검사한 뒤 설정을 교체한다. 잘못된 응답은 기존 설정과 발급 시각을 보존해 다음 시도에서 다시 받는다.
- 완료된 입장 대기의 3초 타이머를 해제하고 관리자 참관도 공유 요청을 사용한다.
- 실제 ICE 블록 실행 테스트 8건, Chrome 모의 수업 입장 11건, 재연결 범위 26건, 순단 복구 18건, AudioContext 정리 검사와 TypeScript 검사를 통과했다.
- 중국 현지 왕복 음성과 운영 반영 여부는 이 로컬 검사 결과에 포함되지 않는다.
