# 집중교정 첫 턴 교정 누락과 반복 보존

## 제보와 확인

A.i 말하기·A.i 친구의 집중교정에서 교정 문장을 항상 총 3번 말하도록 요청. 특히 첫 부분에서 빠지며, 제공 화면에는 `my favorite animal is lion`에 대해 `You can say... "My favorite animal is a lion"` 한 번만 표시됐다.

실제 Worker 두 API를 메모리 D1·KV와 모델 대역으로 실행해 재현했다. 기존 소스에 새 회귀 검사를 적용하면 첫 턴의 교정이 undefined라 FAIL한다. 화면만으로 해당 운영 요청의 모델 원문을 알 수는 없으므로, 운영에서 어떤 모델 출력이 왔는지는 단정하지 않는다.

확인된 코드 경로:
- 답장에 교정이 있어도 fix 필드가 없거나 잘리면 3회 포매터에 교정이 전달되지 않았다. 관사 누락은 기존 과거형 보완으로 구할 수 없었다.
- 모델에도 3회 반복을 요구했지만 일반 반복·길이·새 질문 검사가 그 응답을 버리거나 다시 만들 수 있었다. 친구는 집중교정에서도 사소한 오류는 fix=null로 두라는 공통 프롬프트를 사용했다.
- 첫 턴부터 발생할 수 있다. 첫 턴에서 더 자주 발생한다는 운영 빈도는 측정하지 않았다.

## 수정

두 API의 집중교정에만 같은 helper를 적용한다. 검증된 fix 또는 명시적으로 인용된 `You can say...` 교정을 먼저 확보하고, 그것도 없으면 교정 전용 요청으로 한 번 재확인한다. 원문 포함·실제 변경·의미 유사성·언어·길이·안전 검증은 유지한다. 일반 답장을 교정이라고 추측하지 않는다.

검증된 교정은 대화용 이름·질문 반복·답변 축약 재시도로 덮어쓰지 않는다. 모델은 고친 문장을 한 번만 생성하고 서버가 기존 정본으로 총 3번과 따라 말하기 요청을 조립한다. 자유대화·균형에는 이 경로를 적용하지 않는다. 교정 없는 정상 문장을 3번 읽히지 않는다.

## 선택과 한계

프롬프트에 3번을 더 강조하는 방법은 버렸다. 반복 출력이 잘리거나 일반 검사가 버리는 경로를 해결하지 못한다. 전체 검증을 끄는 방법도 버렸다. 교정 단일 문장을 검증한 경우에만 대화용 재작성에서 보존한다.

교정이 정말 누락된 집중교정 턴은 모델 호출이 한 번 늘어 기다림·사용량이 늘 수 있다. 화면 사례처럼 명시적인 인용 교정이 있는 경우는 추가 호출 없이 복구한다. 모델 오류나 음소거·사용자 중단까지 무시하고 무조건 소리를 재생하는 변경은 아니다. 실제 운영 음성의 직접 청취는 수행하지 않았다.

## 검증

- 직접 tsc --noEmit 통과.
- focused_correction_speech_harness: 70 PASS / 0 FAIL. 두 실제 API, 첫 턴, SSE 미리듣기 차단, 관사 누락, 잘린 JSON, 잘못된 fix, 반복 답장, 정상 문장, 재확인 실패, 세 모드. 기존 친구 음성 큐 실행 검사 포함.
- warmup_honest_mode 95, ai_friend_focused_fix_voice 20, ai_friend_no_repeat_question 129 통과.
- 기존 소스에 회귀 검사를 적용해 실제 FAIL을 확인하고 수정본을 복원했다.
- 로컬 전체 fast 검사는 Windows 경로 C:\C:\ 및 sparse checkout 누락 자산 등 기존 환경 문제가 있다. 완전한 Linux 체크아웃의 최종 CI 결과를 PR에 기록한다. 검사 제외나 기준선 완화 없음.
- 화면 파일 변경 없음. 운영 D1 테스트 쓰기 없음. 병합·배포 결과는 PR에 실제 확인 후 기록한다.
