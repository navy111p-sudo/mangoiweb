## 1. 왜 했나

사장님이 mangoi.ai 「AI 말하기」 첫 화면 캡처와 함께 제안하셨습니다.
「교재로 연습하기와 A.i 친구와 이야기하기 중간에 자유대화를 추가 — 말하기 첫 페이지에 세 가지 선택이 있게」.
확인해 보니 그때까지 카드는 두 개였습니다. 자유대화는 「교재로 연습하기」(웜업) 안의 교정 방식 중 하나(`free_talk`)로만 있었고, 첫 화면에서 바로 고를 길이 없었습니다.

## 2. 무엇을 바꿨나

| 파일 | 바뀐 것 |
|---|---|
| `cloudflare-deploy/public/ai-speaking.html` | 두 카드 사이에 💬 「자유대화」 카드(`#free-talk-mode`)를 넣었습니다. 링크는 `/warmup.html?cmode=free_talk`입니다. 그리드는 `.modes-3`로 PC에서 3열, 폭 600px 이하에서는 기존 미디어쿼리대로 1열입니다. 문구는 전부 `data-ko`/`data-en`입니다. |
| `cloudflare-deploy/public/warmup.html` | 저장값(`WU_CMODE_KEY`)을 읽은 바로 뒤에서 주소의 `cmode`를 확인합니다. 그 값이 `CMODE_CATALOG`에 있는 id면 **이번 화면에서만** `_wuCorrMode`를 덮고, 저장은 하지 않습니다. 모르는 값이면 무시합니다. |
| `test-harness/manual/ai-speaking-browser.mjs` | 「카드 2개」 기대값 세 곳을 3으로 바꿨습니다. 사장님 지시로 카드 수 자체가 바뀌었기 때문입니다. 라벨도 `two modes`에서 `three modes`로 바꿨습니다. |

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **카드 클릭 때 `localStorage['mangoi_warmup_correction']='free_talk'`를 쓰는 방식(첫 판, 버림).**
  CI 게이트의 `test-harness/ai_speaking_entry_harness.mjs`가 막았습니다. 그 하니스는 «입구 화면은 학습 설정을 덮어쓰지 않는다»(`!hub.includes('localStorage.setItem')`)를 지킵니다.
  규칙을 지키는 것이 맞다고 판단했습니다. 카드를 한 번 누르면 학생이 웜업 ⚙️에서 골라 둔 교정 방식이 영구히 바뀌기 때문입니다.
- **주소 파라미터 `?cmode=free_talk`(채택).**
  저장하지 않으므로 «이번에 자유대화로 들어간다»만 정확히 표현합니다. 다음에 웜업을 그냥 열면 학생이 원래 고른 방식으로 돌아갑니다.
  값은 `CMODE_CATALOG` id와 «정확일치»할 때만 받습니다. 그래서 엉뚱한 값이 들어와도 아무 일도 일어나지 않습니다.
- **별도 「자유대화」 화면을 새로 만드는 방식(안 함).**
  웜업에 이미 `free_talk` 교정 방식이 있습니다. 화면을 하나 더 만들면 같은 기능이 두 벌이 됩니다.
- **하니스의 «입구는 저장하지 않는다» 검사를 완화하는 방식(안 함).**
  게이트를 우회하는 것이라 CLAUDE.md 4-1-1에 어긋납니다.

## 5. 남은 것 / 주의할 것

- ~~자유대화 카드도 설정 화면을 거친다~~ → 같은 날 사장님 지시로 바로 대화로 바꿨습니다(아래 6장).
- `?cmode=`는 웜업이 아는 모든 id(`free_talk`·`balanced`·`focused`)를 받습니다. 다른 입구에서도 같은 방식으로 쓸 수 있습니다.
- 병합 직후 배포 실행 하나가 `cancelled`로 보였습니다. 이것은 `deploy.yml`의 concurrency 정리이고, 실패가 아닙니다(CLAUDE.md 2장). 우리 커밋을 포함한 다음 실행이 성공했습니다.

## 6. 후속 — 설정 없이 바로 대화로 (같은 날, PR #1978)

### 왜
사장님 「자유대화 카드도 설정 없이 바로 대화로 보내줘」.

### 무엇을
- `cloudflare-deploy/public/ai-speaking.html`: 자유대화 카드 주소를 `/warmup.html?cmode=free_talk&setup=0` 로 바꿨습니다.
  `setup=0` 은 웜업에 원래 있던 기능입니다(`bootWarmup` — 수업 흐름이 눈높이를 정해 보낼 때 쓰던 것). 그래서 **웜업 화면은 한 줄도 안 고쳤습니다.**
- `test-harness/ai_speaking_entry_harness.mjs`: 자유대화 카드 주소가 `cmode=free_talk` 와 `setup=0` 을 둘 다 넘기는지 검사합니다.
  주소를 예전으로 되돌리면 「free talk skips setup screen」으로 실제 FAIL 납니다.

### 무엇이 달라지나
- 설정 화면을 건너뛰므로 웜업은 **지난번에 고른 연령·수준·교재**(localStorage)로 시작합니다. 처음 온 학생은 **기본값**(아동·기본 수준·교재 없음)으로 시작합니다.
- 바꾸고 싶으면 대화 화면 ⚙️ 의 「연령·수준·교재 다시 고르기」로 바꿉니다.
- 「교재로 연습하기」 카드는 예전처럼 설정 화면부터 엽니다.

### 버린 방법
- **웜업에 «자유대화면 설정 생략» 판정을 새로 넣는 방식(안 함).**
  이미 있는 `setup=0` 으로 충분하고, 판정을 한 곳 더 두면 두 벌이 됩니다.

### 확인
- 실제 크로미움으로 허브 카드를 **실제로 클릭** 100회 했고(PC 1280·폰 390 × 저장값 없음/`focused`) 604건 모두 통과했습니다. 매번 확인한 것:
  - 설정 화면(`#wuSetup`)이 숨겨져 있다
  - 대화가 시작됐다(`_warmStarted`)
  - 첫 인사가 나온다
  - 모드가 `free_talk` 이다
  - 저장값이 그대로다
  - 페이지 오류가 0이다
- 「교재로 연습하기」 카드는 설정 화면을 여는 것도 확인했습니다.
- 카드 주소를 예전으로 되돌린 판으로 같은 검사를 돌리면 **12건 FAIL** 입니다(대화 미시작·인사 없음).
- 입구 브라우저 검사(`manual/ai-speaking-browser.mjs`): 실패 0.
- `--fast`: 이 컨테이너의 실패 목록(35건, 환경 사유)이 변경 전과 같아 새 실패가 0입니다.
- CI 2종(CI, AI speaking entry sandbox)이 통과했습니다.
