## 1. 수정 이유

독립 재검토에서 `결과 5 통과, 1 실패`, `TOTAL 5 PASS / 1 FAIL`처럼 콜론 없는 명시적 요약 라벨이 붙은 exit 0 출력을 PASS로 분류했다. 숫자 전치형을 고친 뒤에도 남아 있던 알려진 실패 누락이다.

기존 prefix 처리 뒤에 명시적 라벨 제거 규칙 **1줄**을 추가했다. 자연어 전체를 해석하거나 임의의 콜론 없는 제목까지 허용하지 않았다. 결과 쌍의 왼쪽 우선 소비, 출력 전체 스캔, 구문 기반 browser 판정과 기존 E2E 정책은 그대로다.

## 2. 지원하는 텍스트 결과 계약

아래는 exit 0에서도 실패 집계를 확인하는 정의된 텍스트 형식이다. 프로세스의 nonzero 종료는 계속 실패의 기본 계약이다(기존 browser SKIP 정책 제외).

- 결과 라벨: `PASS`, `FAIL`, `passed`, `failed`, `통과`, `실패`. 영문은 대소문자를 구분하지 않는다.
- 집계 쌍: `PASS 5` 또는 `5 PASS`, `실패 1` 또는 `1 실패`. 각 쌍은 독립적으로 방향을 고를 수 있다. label-first의 `PASS5`도 지원한다.
- 집계 사이 구분: 공백, `/`, `,`, `·`, `|`, `;` 등 명시적 구분자. 양수 정수 실패 수는 FAIL, 0은 실패가 아니다. 겹치는 후보는 왼쪽부터 소비한다.
- 앞의 명시적 요약 라벨: **결과, 요약, TOTAL, SUMMARY, RESULT, RESULTS**. 뒤에 공백 또는 `:`/`：`가 있어야 한다. `TOTALITY`, `결과표`는 같은 라벨이 아니다.
- 기존 `Suite name: PASS 5 / FAIL 1` 같은 콜론 구분 제목도 유지한다. 장식·ANSI SGR 색은 정리하고 출력 전체에서 요약을 찾는다.
- 단순 따옴표/백틱 안 예문은 요약으로 세지 않는다. `✅ 실패 1회 안내`, `✅ 실패 1건이 집계된다`는 통과 항목 설명이지 실패 집계가 아니다.

예:

| 출력 | 판정 |
|---|---|
| `결과 5 통과, 1 실패` | FAIL |
| `TOTAL 5 PASS / 1 FAIL` | FAIL |
| `Summary PASS 5 FAIL 1` | FAIL |
| `RESULTS 5 PASS / FAIL 12` | FAIL |
| `TOTAL PASS0 FAIL0` | PASS |
| `결과 5 통과, 0 실패` | PASS |
| `TOTALITY 5 PASS / 1 FAIL` | 요약 계약 밖 — 이 문장만으로 실패 집계하지 않음 |
| `Summary expected 1 FAIL was caught` | 일반 설명 — 실패 집계하지 않음 |

## 3. 미지원 범위

콜론 없는 임의 제목, 일반 자연어의 뜻, JSON 결과 객체, Markdown 표 형태의 집계, 실수/음수 집계, `PASS5FAIL1`처럼 쌍 사이 구분이 없는 임의 밀집 표기, 중첩/이스케이프 문자열의 완전한 구문 해석은 계약에 포함하지 않는다. 계약 밖 출력이 어떤 모양으로든 반드시 텍스트 실패로 판정된다고 의존하면 안 된다. 하니스는 실패 시 nonzero로 종료해야 한다. 임의 자연어와 구조화 결과를 모두 추측하는 파서로 확장하지 않는다.

실제 browser 실패를 SKIP으로 내리는 기존 정책은 이번 범위에서 유지했다. 향후 명시적 machine result/skip 계약은 별도 검토 대상이다.
