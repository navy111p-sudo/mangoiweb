## 1. 왜 했나 / 점검 범위

사용자가 전체 스파게티 코드 정리, 버그 제거와 리팩터링을 요청했다. 이번 작업은 전체 파일의 재작성이나 무결함 보장이 아닌 **구조·검증 체계 점검과 재현된 문제의 1차 수정**이다.

tracked 파일 13,156개, 운영 백엔드 최상위 TS 모듈 281개, public/js 모듈 297개를 목록화했다. 전체 파일을 한 줄씩 검토한 것은 아니다. 실제 운영 정본은 cloudflare-deploy/이고, 레거시 modules/·public/·server.js는 저장소 지침에 따라 보존했다. AGENTS.md·.agents/skills/SKILL.md는 이 사본에 없었다. CLAUDE.md, MAINTENANCE.md, .claude/의 검증·작업기록·함정 검사 절차 및 기존 REFACTOR_PLAN.md를 참고했다.

열린 PR은 읽기 확인했다. 특히 #1979(class-ask 스트리밍), #1981(말하기 후속 문서), #1961(AI 친구 UI), #1923(WebRTC 검증)과 겹치는 기능 변경은 하지 않았다. Claude Code 세션 제어·메시지·변경은 하지 않았다.

## 2. 실제 변경

### 교재 해상도 판정 (운영 코드 1파일)

`cloudflare-deploy/src/textbook-resolution.ts`의 순수 함수 `imageSizeFromHeader`를 수정했다.

- PNG는 4바이트 접두사만으로 크기를 확정하던 것을 전체 시그니처·IHDR 식별자·IHDR 길이로 확인한다.
- WebP VP8 키프레임의 시작 코드와 frame type, VP8L 시그니처·version을 확인한다.
- 공통 24/30바이트 하한 때문에 읽을 수 있는 짧은 JPEG/VP8L 헤더를 놓치던 것을 형식별 필요한 길이로 나눴다.
- JPEG에서 SOS/EOI 뒤를 SOF로 오인하지 않고, SOF 길이·컴포넌트 수와 접근 범위를 확인한다.
- 서명 비교와 양수 크기 생성은 함수 내부 helper로 정리했다. API·권한·SQL·R2 접근량·응답 형식은 보존했다.

이는 관리자 **읽기 전용 진단**의 결과 정확성을 고치는 변경이다. 교재 표시·원본 이미지·아바타·음성·수업 연결 코드는 바꾸지 않았다. 전체 이미지 디코더가 아니므로 헤더가 정상인 파일의 본문 무결성을 보증하지 않는다.

새 `test-harness/image_header_bounds_harness.mjs`는 잘못된 서명, 잘린 필드, 짧은 정상 헤더, JPEG 종료 표식, 모의 DB/R2에서의 unknown 판정을 실행한다. 최종 검사를 시작 main에 적용하면 실패 13개가 재현되고 수정본에서는 18개가 통과한다.

### 회귀 러너 (개발 도구)

`test-harness/run.mjs`의 판정 함수를 `runner-result.mjs`로 추출했다. subprocess 실행은 러너에, 순수 결과 분류는 별도 모듈에 둔다. 자식 Node는 `process.execPath`를 사용해 부모와 같은 실행기를 쓴다.

- 비브라우저 하니스의 시간 초과를 SKIP으로 숨기던 것을 FAIL로 분류한다.
- JavaScript의 ASCII word boundary 때문에 `1 실패`를 PASS로 읽던 오류를 수정한다. `0 실패`, 영어 요약, 실제 브라우저 SKIP 정책은 보존했다.
- `runner_result_harness.mjs`는 모의 subprocess 결과 12개를 검증한다. 최초 재현에서는 timeout과 한국어 실패 2개가 잘못 분류됐다.

브라우저 실패를 일괄 SKIP하는 기존 정책이나 요약 마지막 25줄만 보는 기존 정책까지 바꾸지는 않았다. 이 제한은 후속 목록에 남겼다.

## 3. 검증 결과

검증은 localhost·모의 DB/R2/API·합성 음성으로 했다. Node 외부 fetch/socket은 preloader로 차단했고, Chromium 외부 요청은 하니스 route 또는 loopback만 우회하는 폐쇄 프록시로 막았다. 운영 로그인·DB 쓰기·실제 수업·마이크 새 권한·AI/TTS/STT 실호출은 하지 않았다.

초기 의존성 설치는 기본 npm 캐시 경로를 쓸 수 없어 실패했다. `/tmp` 캐시로 다시 설치했다. 최초 전체 검사에서 npx/esbuild 탐색·캐시 때문에 실패 7개가 발생했다. 로컬에서 설치된 의존성에 루트 node_modules 연결을 제공하고 같은 오프라인 조건으로 양쪽을 다시 돌렸다. 이 환경 설정은 저장소 코드나 package lock 변경이 아니다. 중간 결과를 최종 결과로 대체해 숨기지 않고 전달 로그에 남겼다.

검토 과정에서 새 테스트 자체의 두 빈틈도 고쳤다. Uint8Array가 Array.flat으로 복사되지 않아 일부 음성 대조가 잘못된 바이트만 검사하던 것을 실제 바이트 복사로 바꿨고, 러너 검사 속 import 예문이 브라우저 검사로 오인돼 fast에서 빠지던 것을 조립형 fixture로 바꿨다. 최종 로그에서 두 새 하니스가 실제 PASS로 실행됐는지 확인한다.

## 6. 검토와 남은 한계

운영 diff 전체를 다시 읽고 재현·정상 대조·변이 결과, API 응답 호환, 바이트 경계와 public 보존을 대조했다. 테스트의 약한 fixture 두 곳을 수정하고 재검사했다. 이는 **동일 작업자의 2차 자체 검토**이며, 별도 사람/다른 에이전트의 독립 검토가 끝났다는 뜻이 아니다. 부모 스레드에서 독립 리뷰 후 다음 진행을 판단해야 한다.

실제 기기·운영 환경·실제 AI 및 외부 인프라 검증은 남아 있다. 아바타 첫 실행의 짧은 cue 관측 timeout은 재검사에서 재현되지 않았으나 타이밍 민감성이 남는다. 전체 13,156개 파일 정리, 모든 버그 제거, 영구 무결함은 완료로 주장하지 않는다.

참고: [Cloudflare Workers 공식 검토 지침](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/), [WebP 공식 컨테이너 규격](https://developers.google.com/speed/webp/docs/riff_container). 의존성 버전·wrangler 설정·compatibility date는 변경하지 않았다.
