# A.i 친구하기 균형 교정 음성·다시 묻기·정직한 칭찬 (2026-11-03)

- 날짜: 2026-11-03
- 작업자: Claude Code (요청: 사장님)
- 브랜치 / PR: `ai-friend-balanced-correction-voice` / PR 은 이 기록과 함께 올림

## 1. 왜 했나

사장님 화면 제보(2026-11-03, A.i 말하기 › AI 친구하기, 교정 정도 «균형»):

- 학생이 **"My birthday was tomorrow."** 라고 했는데, 교정 카드도 교정 음성도 없이 AI 가
  **"Wait, that's not possible! 🤔"** 로만 받았다.
- 앞 턴 "Chocolate cake tomorrow." 에는 **"Great job!"** 이 붙었다.
- 사장님이 정한 모드 약속:
  - 자유대화 = 교정을 말로 하지 않고 대화만(교정 카드만)
  - 균형 = 교정 카드 + 고친 문장을 **한 번** 말해 줌
  - 집중교정 = 교정 카드 + 고친 문장 **3번**

코드를 따라가 확인한 원인(정본을 실제로 돌려 확인한 것과 추정을 나눠 적음):

| 원인 | 근거 |
|---|---|
| ① 교정이 **아예 안 만들어졌다** — 모델이 fix 칸을 비웠다 | 화면에 카드가 없음 + 코드상 카드는 모델 fix 또는 규칙 보완에서만 나온다. 모델이 «왜» 비웠는지는 로그가 없어 **추정**(문법이 아니라 내용으로 받아 대화만 함) |
| ① 의 안전망(`tense-backfill.ts`)이 이 모양을 못 잡는다 | `backfillPastTenseFix` 를 실제로 돌림: "I eat pizza yesterday." → 교정됨 / "I like chocolate cake tomorrow." → null / "My birthday was tomorrow." → null (과거 표시만 보고 `was` 가 있으면 건너뜀) |
| ② 교정이 있었어도 **균형은 고친 문장을 소리로 말하지 않는다** | 교재 연습은 `src/index.ts:4801` 의 `correctionLeadIn` 이 보장하지만 A.i 친구(`src/api-ai.ts`)에는 그 줄이 없고, 집중교정용 `ensureFocusedFixSpoken` 만 있었다 |
| ③ 틀린 문장에도 칭찬 | 교재 연습의 정직한 칭찬(`applyHonestPraise`)이 A.i 친구에 연결돼 있지 않았다 |

사장님 지시: 「1,2,3 모두 진행해줘」 — ① 균형에서 고친 문장 1번 말하기 ② 균형에서 교정 누락 보완(AI 에게 한 번 더 묻기) ③ 정직한 칭찬.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

1. **대화 프롬프트에 «시간 낱말과 시제가 어긋나면 고쳐» 를 더 얹기 → 버림.**
   이 저장소의 반복 실측이 「지시만으로는 안 지켜진다」이고, 모델이 그 문장을 «내용» 으로 받아 대화한 것이
   원인이라 같은 호출에 규칙을 더해도 같은 일이 난다. 대화와 **떼어 낸 짧은 검사 한 번**(집중교정의
   `recoverFocusedFix` 와 같은 방식)이 확실하다.
2. **«tomorrow + 과거형» 규칙을 tense-backfill 에 더하기 → 버림.** "I like chocolate cake tomorrow." 의 바른
   문장은 동사를 바꿔야 해서(«will have»?) 규칙으로 «지어내게» 된다. 지어낸 교정은 안 고치는 것보다 나쁘다.
3. **다시 묻기를 본 호출 «뒤» 에 차례로 → 버림.** 오류가 없는 턴(대부분)에도 호출 한 번만큼 기다림이 늘어난다.
   **동시에** 시작해 기다림이 «합» 이 아니라 «둘 중 긴 쪽» 이 되게 했다. 대가는 균형 턴마다 모델 호출 1회 추가(비용).
4. **균형도 집중교정처럼 미리듣기를 통째로 끄기 → 버림.** 미리듣기(A-1)는 «1턴만 하고 나가는 34%» 때문에 넣은
   기능이다. 대신 «교정 여부가 정해질 때까지만 잡아 두는 문»: 교정이 없으면 잡아 둔 문장을 바로 흘리고,
   있으면 미리듣기를 접어 정본(고친 문장 먼저)을 한 번에 읽힌다.
5. **그냥 흘리고 최종본에서 앞에 붙이기(replaced:1 로 다시 읽기) → 버림.** 학생은 질문을 먼저 듣다가 말이 끊기고
   처음부터 다시 듣는다 — «교정 먼저» 가 깨진다.
6. **정직한 칭찬을 교재 연습과 «똑같이»(낱말 3개 미만이면 칭찬 안 함) → 버림.** `student_call_name_sandbox`
   하니스가 잡았다: "Yes." 같은 자연스러운 짧은 대답에도 칭찬을 떼면 «Yay, Amy! …» 가 «Amy! …» 로 깨진다.
   자유 대화에서는 **검증된 교정이 있는 턴(=틀린 문장)** 에서만 뗀다. 칭찬 표는 교재 연습과 같은 정본
   (`applyHonestPraise` → `stripCheerLead`)을 쓰고, 칭찬 뒤에 이름만 남으면 그 조각도 뗀다.
7. **다시 묻기를 `env.AI.run` 으로 직접 부르기 → 버림.** `ai_friend_correction` A-3 이 «모델 호출은 감싼 함수
   (`runFriend`) 안에서만» 을 지킨다(JSON 모드·거절 시 재시도가 전 경로에 걸리게). `runFriend` 를 지나되
   `overlap` 으로 동시 호출 시간은 `model_ms` 에 안 더한다(더하면 «우리 코드 몫» 이 음수가 됨).

## 5. 남은 것 / 주의할 것

- **비용**: 균형 모드 + 영어 낱말 3개 이상인 턴마다 모델 호출이 1회 늘어난다(다시 묻기). 자유대화·집중교정은 그대로.
- **기다림**: 균형에서 오류가 없는 턴도 미리듣기가 «다시 묻기 결과» 를 기다린다(동시 시작이라 대개 본 답과 비슷하게 끝남 — **실측 안 함**).
- **공용 칭찬 표에 없는 말**(«Nice sentence!»·«That's right!» 등)은 틀린 문장에도 남는다. 표(`warmup-empathy.ts` `CHEER_LEADS`)를 넓히면 교재 연습·공감 가드도 함께 바뀌므로 **사람이 정할 일**.
- **교재 연습(웜업)의 자유대화**는 `src/index.ts:4801` 이 `honest?.mode !== 'focused'` 면 고친 문장을 앞에 붙여 **말로도** 한다 — 사장님 정의(자유 = 카드만)와 다르다. `src/index.ts` 는 공동 금지구역이라 이번에 안 건드림.
- 조사 중 본 것(이 변경과 무관, 원인 미확인): 학생 문장이 "I like chocolate cake very much." 일 때 `origin/main` 에서도 답장 앞 «Cool!»/«Great job!» 이 떨어진다(다른 문장은 그대로). 하니스 짝 검사는 그 문장을 피해 골랐다.
- 미리듣기 문을 바꾸면 `ai_friend_stream` · `focused_correction_speech` · `ai_friend_no_repeat_question` 이 함께 본다.
  새 모델 호출을 더하면 **가짜 모델을 쓰는 하니스들이 그 호출을 «대화 답» 으로 받아 대본이 밀린다** — 시스템 지시의 표식(`BALANCED_CORRECTION_CHECK`)으로 갈라 주세요.
