# Kaye 제보 관련 번역·교재 재입장·칠판 — 로컬 수정

## 범위와 기준

최신 main을 GitHub에서 읽고 `c372cf66590bb790ddb4201b08854b42aa85f743`을 별도 worktree/브랜치 `codex/kaye-classroom-recovery-local-20261103`에 체크아웃했다. 시작 시 기존 worktree는 clean이었고 같은 작업의 실행 흔적은 찾지 못했다. 이전 로컬 작업76bfed5a0 및 결제3fe8b065는 원래 브랜치에 보존했다. Eric의 기존 #1896/#1903 수정·문서와 연결 스트레스 #1923은 읽기만 했다. 원격 push/PR/병합/배포·다른 작업 제어·운영 DB/계정 변경·수업 참가·마이크 승인·실제 번역 AI/금융/SMS/메일 호출은 하지 않았다.

실제 Kaye 수업의 날짜·방·실행 로그를 확보하지 않았으므로 이번 결과는 **코드의 격리 재현**이다. 해당 수업의 실제 장애 원인 확정이나 운영에서 해결됐다는 뜻이 아니다. 운영 로그 API 스키마는 검색했지만 실제 계정/로그 쿼리는 실행하지 않았다.

## 재현한 코드 결함과 수정

1. **번역 실패/지연을 숨기는 자동 원문 전송.** `idx-vc-chat.js`는 번역 오류를 빈 map으로 바꾸고3초 뒤 원문을 자동 전송했다. 번역 중 입력·방·계정·받는 사람이 바뀌어도 늦은 결과가 새 입력/대상으로 전송될 수 있었다. 이제 HTTP/JSON/본문 지연을 포함해10초로 제한하고 실패·원문과 동일한 미확인 결과는 전송하지 않는다. 원본 입력과 안내를 남겨 사용자가 재시도하거나 번역을 끄고 원문을 보낸다. 이전 미전송 draft의 scope 검사도 번역으로 우회하지 못한다. 방/자신/로그인/연결/받는 사람/번역 설정/입력 경계를 재검사한다. 소켓 전송 실패 시 원래 draft를 복원한다. 수신 실패는 원문 아래 안내하고, 다른 방으로 간 뒤 늦은 번역은 붙이지 않는다. 실제 AI 번역 품질/응답속도·quota 원인은 미검증이다.

2. **늦은 교재 로드의 상태 덮어쓰기.** `vcApplySharedPdf`는 늦은 완료·실패 fallback이 새 방이나 더 나중 책의 URL/쪽수/키를 덮었다. `existing-users`에도 통합 함수를 우회하는 별도 로드 경로가 있었다. 통합 경로로 모으고 요청·방·자신·로그인·연결의 guard를 둔다. 취소된 실제 `pdfLoad`의 false 반환을 성공 표시하지 않으며, 다른 책을 읽는 중 현재 책으로 돌아오면 실제 로더의 세대 보호가 작동하도록 새 요청으로 되돌린다. Eric의 실제 `pdfLoad` 본문은 기준선과 SHA256 동일하다. 원래 폴링/교사 push 탭 정책·페이지 보호·형식 재시도·다른 기기에 불가능한 blob 차단은 유지한다.

3. **DO 재구성 후 칠판 이력 소실.** 칠판 wbOps는 메모리에만 있었다. 교재 pdfState는 이미 별도 KV에 저장되므로 같은 원인으로 단정할 수 없다. 기존 설정의 VideoCallRoom은 SQLite-backed DO이므로 새 helper `RoomWhiteboardHistory`가 해당 방의 전용 SQL 표에 칠판 이력을 보관하고 생성자에서 복원한다. 방 상태를 읽기만 할 때 이력 표를 만들거나 정리하지 않으며, 첫 칠판 기록에서만 표를 생성한다. 별도 D1/새 DO namespace/배포 migration은 추가하지 않았다. 실제 운영 namespace 상태는 조회하지 않았다.

   이력은 최신4000 op(기존 count 한도)와 **새4MiB JSON payload 예산** 중 먼저 닿는 범위다. 오래된 op부터 완결 단위로 버린다. 큰 op는 작은 SQL 행으로 분할하고 surrogate pair 경계를 보존한다. append/부품/정리는 transactionSync로 원자 처리한다. 명시 지우기·기존3시간 age/5분 빈 방 새 수업 기준에 맞춰 **다음 입장 때** 정리하며, board-only 수업도 정리한다. 자동 시간 삭제 타이머는 없으므로 **미접속 방의 물리 데이터가3시간 후 저절로 삭제된다는 주장이 아니다.** 이 보관/예산 정책과 운영 쓰기량은 배포 전 검토 대상이다.

   저장 실패 또는 예산 초과는 익명 경고를 남기고 기존 live relay를 계속하지만 그 op의 재시작 복원을 보장하지 않는다. 매우 큰 frame은 영속화용 추가 복사를 생략한다. durable clear 실패는 성공 방송하지 않는다. 새 수업 cleanup 실패 때는 옛 이력을 숨기고 empty marker를 유지해 다음 복원에서 다시 정리한다. PDF 위 판서 pdfAnnoOps는 여전히 메모리이며 이번 영속화 대상이 아니다. 새로고침 전 이미 사라진 이력은 소급 복구하지 못한다.

## 짧은 연결 끊김

현재 main은 transport close1000/1006을 dropped로 처리하고 explicit leave-room만 left로 처리한다. 학생의 종료 hook/poll도 dropped/미상 사유에는 자동 종료하지 않는다. 실제 함수의 가상 시계에서 연결 끊김·오프라인·복귀를 검사했고, 명시 left는 기존 종료 흐름으로 가는 양성 대조도 확인했다. **이 경로에서는 새 실패를 재현하지 못해** ICE/재연결/카메라/생존 알람/종료 정책은 변경하지 않았다. 실제 회선·TURN·장치·수업 로그는 미검증이다. 소음 제거·Office Mode·가상배경의 실제 동작도 미시험이다. Eric 스트레스 결과는 기존 모형 회귀일 뿐 실제 기능 검증으로 바꾸어 부르지 않는다.

## 검증과 한계

- 번역·교재: 실제 배포 IIFE/함수+합성 DOM/시계/Promise, 기준선3PASS/30FAIL → 최종33PASS. 실제 pdfLoad와 결합한 취소/다른 책 복귀도 포함한다.
- 서버: 실제 DO 메서드+합성 소켓/SQLite, 기준선12PASS/5FAIL → 최종17PASS. 이 수는 확장된 계약 검사를 포함하며35개의 별도 운영 버그를 뜻하지 않는다.
- 종료 hook/poll 가상 시계6PASS, 기존 재연결26PASS. 기존 Eric 모형 스트레스도 통과했다.
- 실제 로컬 workerd SQLite DO journal7PASS: 큰 Unicode roundtrip, 부분 쓰기 rollback, runtime restart, 방 격리, byte 예산, clear 후 restart. restart는 실제 hibernation 이벤트 발생을 측정한 것이 아니다. app 설정/원격 binding 없이 자체 임시 경로·합성 namespace·cf/telemetry off·outbound 차단으로 실행했고 outbound callback0이었다.
- 브라우저 하니스는 배포 sender/receiver·번역·PDF coordinator를 실제 DOM에서 PC/모바일로 실행하도록 준비했다. 그러나 Chromium이 SUID sandbox 설정 오류 및 user-namespace 경로의 `No usable sandbox`로 **launch 단계에서 종료**했다. sandbox를 끄거나 OS 권한을 고치지 않았으며 UI 시나리오는 미실행이다. 초기 crashpad 경로 문제만 임시 XDG profile로 처리했다. 브라우저 시작 실패를 PASS/SKIP 성공으로 바꾸지 않았다.
- 기존 테스트의 구조 단언은 helper 위임 및 중첩 if를 올바로 읽게 보완했고 새 실행 검사를 추가했다. 기존 runner의 `PASS N FAIL 0` 오판을 피하려 새 하니스 요약은 `N PASS / 0 FAIL` 계약을 따른다. runner 자체는 변경하지 않았다. SQL을 한 줄로 구성해 기존 D1 multiline exec 검사도 유지했다. 중간 호환 실패 로그는 전달 자료에 보존한다.
- 기준선 전체662PASS/20SKIP/0FAIL. 최종 전체/type/build/Node/캐시/첫 화면 예산·정확SHA는 전달자료 참조. 캐시 main74/chat3과 강사 preload 및 manifest를 동기화했다. 커밋만 했으며 운영에는 적용하지 않았다.
