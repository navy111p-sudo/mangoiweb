# 수업 관제탑 «회선» 칸을 강사 / 학생으로 나눠 보기

- 날짜: 2026-11-03
- 작업자: 정우영(사장님) 요청 · Claude 작업
- 브랜치 / PR: `monitor-wall-line-by-role`

## 1. 왜 했나

직원이 관제탑(`/admin/monitor-wall.html`) 화면을 찍어 보내며 물었습니다 — 「회선 칸의 **254ms · 0.1%** 는 강사 쪽인가요, 학생 쪽인가요, 수업 쪽인가요?」

코드로 확인한 답은 **«수업(방) 전체»** 였습니다.

- 화면: `js/monitor-wall.js` 의 `sigHtml(rid)` 가 방 번호 하나에 값 하나만 그립니다.
- 서버: `GET /api/admin/vc/quality?live=1` 이 최근 5분 `vc_quality` 행을 **`GROUP BY room`** 으로만 평균합니다(역할 구분 없음).
- 수집: 참가자마다 1분에 한 번 «내가 **보내는** 쪽» 손실·RTT 를 올립니다(`js/idx-vc-qlog.js`).

그래서 그 숫자로는 누구 회선이 나쁜지 알 수 없었고, 사장님이 「역할별로 나눠 보이게 고쳐줘」라고 지시하셨습니다.

### 2-1. (같은 날 후속) 심각도를 «가장 나쁜 역할» 기준으로 — 사장님 「심각도도 가장 나쁜 역할 기준으로 바꿔줘」

- `worst(q)` — 역할별 줄 중 신호가 제일 나쁜 것(단계가 같으면 **강사 먼저**)을 고르되, 그 줄이 방 전체보다 나쁘거나 같을 때만 씁니다. 역할 줄이 «모름» 뿐이면 방 전체 값으로 판정합니다(모름이 나쁨을 가리지 않게).
- `severity()`·`reasonHtml()` 이 그 줄을 씁니다 → 방 평균은 🟡 이어도 **강사 줄이 🔴 면 그 방이 「손봐야 할 방」 맨 위**에 뜨고, 사유가 «📶 강사 회선 나쁨 · 520ms · 6.2%» 처럼 **누구인지** 말합니다(EN «Teacher bad line»). `by_role` 이 없으면 예전 문구 «📶 회선 나쁨 · …».
- 🟡(주의)만으로는 심각도를 올리지 않습니다 — 예전과 같이 🔴(나쁨)만 올립니다.
- 52KB: 이 후속으로 371B 가 넘쳐, JS 구분선 5줄의 꼬리 장식(`───…`, 글자당 3바이트)만 «──» 로 줄였습니다(436B, 글 내용은 그대로) → 합계 53,183B · 여유 65B.
- 확인: 하니스 51/0(심각도 짝 검사 추가) · 변이 6종 전부 FAIL(방 평균으로 되돌리기 · 사유를 방 평균으로 · 동률이면 학생 · 모름 역할이 방을 가림 · 조건 뒤집기 · 사유에 역할 이름 빠짐) · 실제 브라우저에서 «방 평균 230ms·2.1% / 강사 520ms·6.2%» 방이 🔴 · 「손봐야 할 방」 첫 줄 · 사유 «강사 회선 나쁨» · 브라우저 하니스 31/0. `?v=11` 은 아직 배포 전이라 번호는 그대로 두고 원장 값만 다시 기록했습니다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **방 단위 쿼리 자체를 `GROUP BY room, role` 로 바꾸고 화면에서 합치기** — 버림. 방 단위 값은 신호등 심각도와 「🚨 지금 손봐야 할 방」의 근거라, 계산식이 바뀌면 그 판정이 **조용히** 달라집니다. 쿼리를 하나 더 «덧붙이는» 쪽을 택했습니다(D1 조회 1회 추가, 최근 5분 범위).
- **심각도를 «가장 나쁜 역할» 기준으로 바꾸기** — 처음에는 지시 범위 밖이라 안 했다가, 같은 날 사장님 지시로 바꿨습니다(2-1).
- **방 단위 값에서도 표본 없는 1분을 빼기** — 같은 이유로 안 했습니다(5-2).
- **52KB 상한 올리기** — 2026-09-14 사장님 「52KB 상한 그대로 유지해」(확정)라 올리지 않았습니다. 대신 자리를 만들었습니다:
  - 신호 기준·표기를 `lvl()`·`fmt()` 로 합쳐 중복 코드 제거
  - HTML 의 `<script>` 뒤 옛 버전 이력 주석 3개(v=9·v=7·v=6, 184B) 삭제 — git log 에 있음
  - HTML 머리말의 «2026-09-13 D안(상황판)…» 줄 삭제 — `260913_관제탑_D안_상황판_글자키우기.md` 에 그대로 있음
  - HTML 머리말 상한 줄의 «— 2026-09-13 D안으로 50→52» 괄호 삭제 — 같은 이력이 `monitor_wall_harness` 머리말에 있음
  - JS `rowHtml` 안 참관 정원 주석(위 `OBS_MAX` 주석과 겹침)을 한 줄로 · `OBS_MAX` 주석의 일반론 한 문장 삭제
  - 결과 합계 **53,194B / 53,248B**(여유 54B — 작업 전 45B 보다 조금 늘었습니다).
- **👩‍🏫·🧑‍🎓 이모지 라벨** — 버림. ZWJ 결합 이모지라 Win10 에서 두 글자로 갈라질 수 있어(1-4 «이모지» 규칙과 같은 걱정) 글자 라벨 «강사·학생» 으로 했습니다.
- **역할(role)로 «누가 있었나» 판정까지 하기** — 안 합니다. role 은 접속 기기가 보낸 값이라(CLAUDE.md 2장 — 판정 근거는 이름 일치뿐) **표시용**으로만 씁니다.

## 5. 남은 것 / 주의할 것

- 5-1. ✅ (같은 날 해결) 심각도·「손봐야 할 방」은 이제 «가장 나쁜 줄» 기준입니다(2-1). ⚠️ 그래서 그 상자에 뜨는 방이 **예전보다 늘 수 있습니다**(방 평균은 괜찮은데 한쪽이 나쁜 방). 본사·사장님이 직접 입장한 기기는 «강사» 로 세므로(5-3) 그분 회선이 나빠도 «강사 회선 나쁨» 으로 뜹니다.
- 5-2. **방 단위 값은 카메라를 끈 1분을 «손실 0% · 0ms» 로 섞습니다**(2026-11-03 코드 확인 — D1 실측은 못 함). 서버 주석은 «음수(-1) 행을 뺀다» 고 적고 있었지만 지금 화면(`idx-vc-qlog.js`)은 표본이 없으면 `avg_loss 0 · samples 0 · avg_rtt 0` 을 보내 음수가 안 옵니다 → 그 조건(`avg_loss >= 0`)은 사실상 아무것도 안 거릅니다. 그 주석에 정정 한 줄을 달았고, **역할별 값은 `samples > 0`·`avg_rtt > 0` 으로 따로 걸렀습니다.** 그래서 같은 방에서 «방 평균» 이 역할별 값보다 좋아 보일 수 있습니다. 방 단위도 고칠지는 사람이 정할 일입니다(고치면 신호가 지금보다 나빠지는 방이 생깁니다).
- 5-3. 역할은 **기기가 보낸 값**입니다(`vcIsTeacherRole()` 이면 teacher). 표시용입니다 — 출석·노쇼·급여에 쓰지 마세요.
  ⚠️ `vcIsTeacherRole()` 은 admin·hq 도 참으로 봅니다(`idx-main.js`) — **본사·사장님이 직접 입장하면 «강사» 줄에 섞여 «강사 2명»** 이 나올 수 있습니다. «기타» 는 기기가 teacher·student·빈 값이 아닌 글자를 보낸 드문 경우뿐입니다(함정 대조가 잡아 정정).
- 5-4. 관제탑 합계 여유가 **54B** 뿐입니다. 다음에 이 화면에 무엇을 더하려면 하니스 머리말의 «뺄 후보»(카페24 예약 목록·강제 종료)부터 사람이 정해야 합니다.
