# 매니저·강사 화면 새로고침 뒤 마지막 화면 유지 + 지난 연기 수업의 «↩ Restore» 숨김

## 1. 왜 했나

매니저 제안 두 가지(사진 1장 첨부):

1. 「매니저 화면·강사 화면에서 새로고침하면 늘 처음 화면으로 돌아간다. 예를 들어 Teacher Kaye 의 오늘 수업을 보고 있었다면 새로고침 뒤에도 거기 있게 해 달라.」
2. 사진 속 「⏸ Postponed — no new date yet」 줄에서 **↩ Restore** 를 누르면 「↩ Past classes cannot be restored.」 만 뜨고 아무 일도 안 일어났다 → 사장님 「이거 수리해줘」.

2번 원인: 서버 정본 `src/class-schedule-move.ts` 의 restore 갈래가 **원래 시각이 이미 시작한 수업**을 언제나 `past_date`(409)로 거절한다(CLAUDE.md 2장 첫 줄 «HQ restore must reject started/attended… classes» 규칙). 그런데 화면은 시각과 무관하게 버튼을 그려서 **«눌러 보면 반드시 거절되는 버튼»** 이었다.

## 2. 무엇을 바꿨나

### ① 새로고침 뒤 마지막 화면 유지
- `cloudflare-deploy/public/manager.html` (메인 IIFE, `taDatePick` 초기화 바로 뒤 블록 · `openCard` · `sideGo` · `paintTodayAll` · 새 `taPreset`)
  - 키 `sessionStorage['mgr_view_v1']` = `{card, taDate, taAcademy, taTeacher}`.
  - 카드: `details.card` 의 `toggle`(캡처 단계로 문서에서 받음)과 `openCard()` 에서 적고, 🏠 Home(`sideGo('top')`)에서 지운다. 휴대폰(PC 패널 모드가 아닐 때) 카드를 접으면 지운다.
  - 「오늘 전체 수업」: `paintTodayAll()` 이 고른 학원·강사·날짜를 적고, 첫 그리기에서 `taPreset()` 으로 그 값을 먼저 앉혀 `fillPick` 이 이어받게 한다(새 목록에 없으면 기존 규칙대로 «전체»).
  - 날짜는 **오늘이 아닐 때만** 적는다 → 다음 날 새로고침해도 어제에 갇히지 않음.
  - 복원은 로드 직후 1회 + 카드가 아직 `hidden`(권한 확인 전)이면 1.5초 간격 최대 4번만 다시 봄.
- `cloudflare-deploy/public/teacher.html` (`openCard` 정의 바로 뒤 IIFE)
  - 키 `sessionStorage['tch_view_v1']` = 마지막으로 연 카드 id(`details.card` 또는 `#c-week`). 접으면 지움. 숨은 카드는 강제로 꺼내지 않음.
- ⚠️ HTML 페이지라 `?v=` 대상이 아니다(no-cache + ETag).

### ② 지난 연기 수업의 «↩ Restore» 숨김
- `cloudflare-deploy/public/js/adm-today-classes.js` (오늘 수업 표 — `s.postponed` 갈래, `rsStarted`)
  - `start_ts` 가 있고 이미 지났으면 버튼 대신 「원래 시각이 지나 되돌릴 수 없음 — 새 날짜로 잡으세요」. «📅 Rebook» 은 그대로.
  - `past_date` 거절 문구를 「…«📅 Rebook» 으로 새 날짜를 잡으세요」로 바꿈(할 일을 말하게).
- `cloudflare-deploy/public/js/class-move-modal.js` (`canRestore`)
  - 같은 조건으로 «↩ 연기 취소 (원래 날짜·시각)» 버튼과 안내 문장을 뺌. `start_ts` 를 모르면 예전처럼 보여 줌(서버가 최종 판정).
- `?v=` 올림: `adm-today-classes.js` 57→58(`admin.html`), `class-move-modal.js` 11→12(`admin.html`·`manager.html`·`branch.html`·`admin/student.html`). 원장 `test-harness/asset-versions.json` 갱신.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **localStorage 대신 sessionStorage** — 새로고침만 살리면 되는 요청이고, localStorage 면 다음 날·다른 사람(공용 PC)까지 Kaye 필터에 갇힌다. 탭을 닫으면 사라지는 쪽이 안전.
- **URL 해시(#c-today)로 상태 저장** — 버림. `manager.html` 은 이미 `history.replaceState(…location.hash)` 를 쓰는 자리가 있고, 링크를 남에게 보내면 필터까지 따라가 혼란. 화면 안 상태로 충분.
- **상주 타이머·MutationObserver 로 카드 감시** — 금지(CLAUDE.md 2장, 홈 정지 전력). 토글 캡처 리스너 + 유한 재시도만.
- **서버의 past_date 거절을 풀어 «지난 수업도 되돌리기»** — 버림. 지난 수업을 «열린 수업» 으로 되살리면 결석·급여·출석 판정이 꼬인다. 서버 규칙은 그대로 두고 화면이 사실을 말하게 했다.
- **버튼은 두고 회색으로 비활성화** — 버림. 폰에는 hover 툴팁이 없어 «왜 안 눌리는지» 를 못 전한다 → 보이는 글자로 사유를 적음.
- `start_ts` 가 없을 때도 숨기기 — 버림. 모르면 예전 동작(서버가 판정)으로 실패하는 쪽이 맞다.

## 5. 남은 것 / 주의할 것

- 새로고침 유지는 **같은 탭에서만**. 새 탭·다른 기기는 처음 화면(의도).
- 강사 화면은 «카드» 만 기억한다 — 날짜 드롭다운(`CLS_DAY`)·주/월 이동은 기억하지 않는다(요청 범위 밖, 초기 로딩과 경합 위험).
- 시각 판단은 브라우저 시계(`Date.now()`) 기준이라, PC 시계가 크게 틀리면 버튼 표시가 서버 판정과 어긋날 수 있다(그때도 서버가 거절하고 바뀐 문구가 할 일을 말한다).
- manager 의 «오늘 전체 수업» 판정은 admin 과 두 벌이다(외부 스크립트 0 계약) — 이번 변경은 manager 쪽만 기억 기능을 넣었고 admin.html 「오늘 수업」 은 새로고침 유지 대상 아님.
