### 2-1. 곁에서 찾아 같이 고친 것 — 수준이 «안 정함» 인데 «1단계» 가 골라진 것처럼 보임

브라우저 캡처에서 발견. `renderSettings` 가 `typeof cur.level === 'number'` 이면 «아직 안 정함» 머리 줄을 빼는데,
안 정함은 `0`(숫자)이라 **머리 줄이 한 번도 안 나왔다** → 선택칸이 «1단계 · 첫걸음» 을 보여 주고, 1을 골라도 값이 같아 `change` 가 안 나서
**1단계는 고를 수 없었다**(예전 코드부터). 확인 버튼이 «수준을 골라 주세요» 라고 말하는데 1단계가 골라진 것처럼 보이면 모순이라 같이 고쳤다
(`cur.level >= 1` 일 때만 머리 줄을 뺀다).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **«누르면 바로 저장 + 확인은 장식» 은 버렸다.** 사장님 말씀이 「확인을 눌러서 완전히 3가지 모두 되게」라, 확인이 실제로 저장하는 순간이어야 한다.
- **언어를 «확인» 때 늘 쓰는 것은 버렸다.** `chooseLang` 은 `mangoi_lang_by='user'` 도 쓰므로, 언어를 안 건드리고 수준만 확인해도
  계정 자동판정 언어가 «사람이 고름» 으로 굳는다. 저장된 언어와 다를 때만 쓴다.
- **«화면마다 다름» 을 그대로 확인하게 두는 것은 버렸다.** 그 상태로 저장하면 «3가지 모두 같게» 가 안 된다 → 하나를 고르라고 잠근다.
- **처음 열 때 «✅ 적용됐어요» 로 보여 주는 것은 버렸다.** 누르기 전에 «적용됐어요» 라고 하면 버튼이 «확인» 이 아니게 된다(요청은 확인 버튼). 저장된 값이 있으면 «확인» 이 켜진 채로 시작한다.
- **결과 문구를 화면 아래 줄로 다시 두는 것은 버렸다** — 사장님이 지우라고 하신 바로 그 자리다. 버튼 글자로 말하고, 화면낭독기용 상태 줄만 숨겨 남겼다.
- **버튼 글자에 `data-ko`/`data-en` 을 달지 않았다** — i18n 루프가 `textContent` 를 갈아끼운다(CLAUDE.md 2장 「JS 로 그린 라벨」).

## 6. 후속(같은 날) — 언어는 누르는 즉시 저장

#2040 배포 뒤 «언어까지 확인에 묶여, 저장값이 없는 학생은 수준·교정을 골라야만 언어가 저장된다» 를 보고드렸고,
사장님이 **「언어는 바로 저장되게 되돌려줘」** 로 정하셨다.

- 언어 버튼: 누르는 즉시 `chooseLang`(예전과 같음 — `mangoi_lang` + `mangoi_lang_by='user'`). 확인 버튼이 잠겨 있어도 저장된다.
- «확인»: 수준·교정만 쓴다. 언어는 다시 쓰지 않는다(계정 자동판정 표식을 괜히 «사람이 고름» 으로 굳히지 않도록).
- 확인 뒤 언어를 바꿔도 «✅ 적용됐어요» 는 그대로다 — 수준·교정은 여전히 적용된 상태이므로(글자만 그 언어로).
- 저장이 막힌 기기에서 언어를 누르면: 화면 글자는 바뀌고, 버튼이 «⚠️» 로, 화면낭독기 상태 줄이 «언어 저장이 안 돼요» 로 사실대로 말한다
  (수준·교정을 덜 골라 버튼이 잠긴 상태면 버튼은 «무엇을 고를지» 를 계속 보여 주고 실패는 상태 줄에만 남는다 — 드문 경우라 그대로 둠).
- 확인한 방법: 하니스 PASS(새 블록 45종) · 변이 **16종** 전부 실제 FAIL(언어 탭이 저장 안 함 · 확인이 언어를 다시 씀 · 언어 탭이 «적용됨» 을 지움 ·
  실패를 조용히 삼킴 · 같은 언어 다시 눌러 또 씀 · 반대 언어 저장 + 앞의 10종) · 로컬 Chromium 390px: 빈 저장소에서 English 탭 →
  즉시 `mangoi_lang=en`·`by=user`(버튼은 잠긴 채) → 새로고침 뒤에도 English → 수준·교정 확인 → 한국어 탭 → 즉시 `ko`, «✅ 적용됐어요» 유지, JS 오류 0.

## 7. 후속(같은 날) — 확인 안 누르고 나가면 묻기

§5 의 «확인 없이 나가면 적용 안 됨» 을 보고드렸고, 사장님이 **「확인 안 누르고 나가면 물어보게 해줘」** 로 정하셨다.

- **언제 묻나**: 이 화면에서 **사람이 만진 칸**(수준·교정)이 **저장된 값과 다를 때만**(바꿨다가 원래대로 되돌리면 안 묻는다 · 확인 뒤엔 안 묻는다 ·
  안 만진 칸이 저장소와 다른 것은 다른 탭이 바꾼 것이라 묻지 않는다).
- **화면 안 링크**(홈 · 교재 연습 · AI 친구 · 상황 카드): 이 화면의 창 — **적용하고 이동**(확인과 같은 저장 후 그 링크로) ·
  **적용 안 하고 이동** · **머무르기**(Esc · 어두운 바깥을 눌러도 머무름). 창은 «고른 설정: 수준 3단계 · 교정 집중» 을 함께 보여 준다. 한/영.
- **하나만 바꿔 «확인» 이 잠긴 경우**: «교정 정도를 골라야 확인할 수 있어요» + **고르러 가기**(그 칸으로 데려가 포커스) · 적용 안 하고 이동.
- **뒤로가기·새로고침·탭 닫기**: 브라우저 기본 확인창(`beforeunload`). 문구는 브라우저가 정한다. 아이폰 사파리는 이 창을 띄우지 않는 것으로 알려져 있다
  (⚠️ 이 저장소에서 못 잼 — 휴대폰으로 확인 필요). 바꾼 것이 있을 때만 건다(MDN 권고: 늘 걸어 두면 «뒤로가기 보관(bfcache)» 을 막는 브라우저가 있다 — 재지는 않음).
- **안 묻는 경우**: 저장소가 아예 없는 기기 · 확인이 «⚠️ 저장이 안 돼요» 로 실패한 뒤(다시 물어도 저장할 수 없음).
  «적용하고 이동» 이 저장에 실패하면 이동하지 않고 그 «⚠️» 를 보이게 둔다 — 다음에 누르면 묻지 않고 간다.
- **새 탭 열기**(Ctrl/⌘ 클릭)·화면 안 이동(`#situations`)은 건드리지 않는다.
- 뒤로가기로 보관된 화면이 돌아오면(`pageshow` persisted) 저장된 값으로 다시 그린다 — 그 사이 다른 화면이 설정을 바꿨을 수 있어서.
- 창이 열리면 뒤 화면(`.wrap`)은 `inert`, 포커스는 «적용하고 이동»(스크롤 없이 — 낮은 화면에서 제목이 잘리지 않게), Tab 은 창 안에서만, Esc·바깥 = 머무르기,
  닫으면 누른 카드로 포커스가 돌아간다. 낮은 화면(높이 420px 이하)은 창을 조여 한 화면에 들어오게 하고, 더 낮으면 창 안이 스크롤된다.
- 다른 탭이 설정을 바꾸면(`storage`) 안 만진 칸을 그 값으로 다시 그리고 «✅ 적용됐어요» 는 거둔다. «확인»·«적용하고 이동» 은 쓰기 직전에 안 만진 칸을 저장소에서 다시 읽는다
  (그래야 다른 탭이 새로 정한 값을 옛 값으로 덮지 않는다).
- 이동을 시작한 뒤 멈추거나 실패해 이 화면에 남으면 3초 뒤 다시 묻도록 표시를 되돌린다.

### 7-1. 버린 방법

- `window.confirm()` 하나로 묻기 — 버튼이 둘(확인/취소)뿐이라 «적용하고 이동 / 그냥 이동 / 머무르기» 를 못 나누고, 글자도 바꿀 수 없다.
- 링크마다 핸들러 달기 — 상황 카드는 나중에 그려지므로 빠진다 → 문서에 위임 리스너 하나.
- 묻는 판정을 `renderSettings`·`renderOk` 안에 넣기 — 하니스 ③ 이 그 둘만 오려 «저장소를 안 읽는다» 를 확인하므로(그리고 그 원칙이 맞으므로)
  상태를 바꾸는 세 자리(고르기 · 확인 · 언어)에서 따로 부른다.

### 7-1-1. 함정 대조가 잡은 것(병합 전 · 전부 고침)
