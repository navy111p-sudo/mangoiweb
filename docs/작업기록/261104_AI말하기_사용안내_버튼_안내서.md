## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **Claude 공유 페이지(아티팩트)로만 배포** → 버림. 그 뷰어는 `window.print()`·일반 다운로드 링크를 막는다(인쇄 버튼이 «눌러도 아무 일 없음»). 공유 페이지 판도 만들었지만(`downloads` 기능 + Word 는 base64 텍스트로 올려 저장 때 되돌림 — .docx 는 그 플랫폼에 직접 못 올림) 학생이 실제로 쓰는 곳은 운영 화면이라 이쪽이 정본.
- **안내서 글을 `ai-speaking.html` 안에 직접 넣기** → 버림. 27KB 화면이 두 배가 되고, PDF·Word 와 같은 원본을 쓸 수 없다. → 별도 페이지 + 창(iframe). 인쇄도 iframe 안에서 그 문서만 찍힌다.
- **새 탭으로 열기** → 버림. 아이들이 탭을 잃는다. 창(dialog)으로 열고, 못 여는 옛 브라우저만 같은 탭.
- **버튼 위치**: 머리(제목 옆)는 휴대폰에서 «← 홈 · 제목 · 마스코트» 로 이미 꽉 참 → «오늘은 …» 줄 오른쪽(좁으면 다음 줄 오른쪽).
- **구글 글꼴(Jua·IBM Plex)** → 버림. 외부 주소 + 중국 회선. 사이트처럼 기기 글꼴 + 한자는 `MangoiHanSC`(hanzi_font_harness 규칙).
- **교정 정도 설명을 새로 쓰기** → 버림. 처음 판은 이름만 보고 «틀려도 OK / 중요한 것만 / 꼼꼼하게» 로 추측했는데 실제 동작과 달랐다. 화면 버튼의 `data-hint-ko/en`(서버 동작과 짝 — `ai_speaking_entry_harness` 가 숫자를 대조)을 **같은 글자로** 옮기고 하니스가 대조한다.
- **언어 선택을 `mangoi_lang` 에 저장** → 버림. 안내서에서 누른 것이 사이트 전체 언어를 바꾸면 안 된다(+ `mangoi_lang_by` 판정이 굳음). 안내서 자기 키에만 쓴다.
- **한 장 넘침을 글자 줄이기로만 해결** → 영어판이 한국어판보다 길어 2쪽이 됐다. 영어 문장을 뜻 그대로 줄이고, **영어판 인쇄만** 11pt → 10.2pt(한국어판·화면 글자는 그대로). 빌드가 1쪽 초과면 실패한다.

## 5. 남은 것 / 주의할 것

- **옛 브라우저(showModal 없음, iOS 15.4 미만 등) 분기는 같은 탭 이동이라 6차 «나가기 확인»(#leaveAsk)을 거치지 않습니다** — beforeunload 만 남고 iOS 사파리는 그 창을 안 띄우므로, 그 기기에서 설정을 바꿔 놓고 «사용 안내» 를 누르면 미적용 설정이 조용히 사라질 수 있습니다(추론 · 실기기로 안 잼).
- 공개 저장소에 PDF·Word·화면 사진 약 3.5MB 가 들어갑니다. 문구를 고쳐 다시 빌드할 때마다 git 기록에 그만큼 쌓입니다(개인정보 없음 — 함정 대조가 PDF 메타데이터·docx 작성자·화면 사진까지 확인).

- 안내서 문구를 고치면 **`node scripts/ai-speaking-guide/build.js` 로 PDF·Word 를 다시 만들어 함께 커밋**(안 그러면 화면과 내려받은 파일이 다른 말을 함). 빌드에는 pandoc·python-docx·한글 글꼴이 필요.
- AI 말하기 화면의 교정 정도 설명(`data-hint-ko/en`)이 바뀌면 안내서 두 장도 같은 글자로 바꿔야 하니스가 통과한다(의도된 짝).
- 화면 사진(`guide-screen.webp`)·번호 위치는 2026-11-04 화면 기준. 화면이 크게 바뀌면 다시 찍고 `ai-speaking-guide-full.html` 의 `.pin` 좌표도.
- 인쇄 버튼은 운영 화면(iframe 안)에서는 그 안내서만 찍히는 것을 로컬에서 확인했지만, 학생 기기(iOS 사파리 등)별 인쇄 동작은 못 봤다.
- 안내서 안 «AI 목소리 바꾸기·속도» 설명은 `warmup.html`(«AI 친구(목소리·얼굴)», «듣기 속도»)·`ai-friend.html`(«속도») 화면 글자를 근거로 했다. 그 화면이 바뀌면 함께.
