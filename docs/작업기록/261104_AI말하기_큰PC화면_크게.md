# AI 말하기 — 큰 PC 화면에서 크게 보이게 (9차)

- 날짜: 2026-11-04
- 작업자: Claude (사장님 요청)
- 브랜치 / PR: `ai-speaking-pc-bigger` / navy111p-sudo/mangoiweb#2070

## 1. 왜 했나

사장님 PC 화면 캡처(`mangoi.ai/ai-speaking.html`)와 함께 「이거 PC 화면에 적합하게 지금보다 크게 해서 잘 보이게 가장 적절하게 보이게 해줘」.

캡처를 재 보니 **1920 모니터 + 브라우저 80% 축소**(주소창 돋보기 아이콘, 카드 폭 866px ÷ CSS 1084px = 0.80)였습니다.
그러면 창은 CSS 기준 약 **2400×1149** 인데, 화면 본문이 `max-width:1120px` 로 고정이고 큰 화면용 규칙이 없어
**본문이 화면 폭의 45%** 만 쓰고 아래로 240px 가 비어 있었습니다(실측: 문서 높이 910px).

## 2. 무엇을 바꿨나

`cloudflare-deploy/public/ai-speaking.html` — CSS 만(스크립트는 한 글자도 안 바뀜). 같은 날 다른 작업(7차 «시작 링크 자동 적용» · 8차 «사용 안내» 버튼)과 병합했고, 이 작업은 머리 주석에 **9차**로 적었습니다.

| 창 폭·높이 | 바뀐 것 |
|---|---|
| 1600px 미만(노트북 1366·1440·1536, 태블릿, 휴대폰) | **그대로** |
| 1600px 이상 | 본문 1120 → **1280px**(카드 설명이 대개 한 줄) + 세로 여백 조금 줄임(위 32 → 24 · 안내줄 위아래 · 카드 안 간격 14 → 12 · 설정 칸 위 18 → 14 · 확인 위 18 → 14 · 아래 28 → 12). 문서 높이 **843px**(넓은 글꼴에서 영어 설명 두 줄이면 867) |
| 그 위로 폭·높이가 충분하면 | `.wrap` 에 **zoom 1.1 ~ 2.4** 단계(글자·카드·버튼이 같은 비율로 커짐) |

단계 조건(작은 것부터 적어 «맞는 것 중 가장 큰 단계» 가 이김):
- 폭: 본문 1280 × 배율 ≤ 창 폭의 80% → `min-width = 1600 × 배율`
- 높이: 문서 전체 875 × 배율 ≤ 창 높이 → **「확인」 버튼까지 스크롤 없이 한 화면**
  (875 = «최악의 경우» 실측 867 + 여유. 넓은 글꼴 DejaVu Sans — CI 러너 기본 — 에서는 영어 설명이 두 줄이 되어 867, 보통은 843. 8차 «사용 안내» 버튼 40px 가 안내줄에 든 상태)

결과(실측, 크로미움, 병합본):

| 창(CSS px) | 예시 | 배율 | 본문 폭 | 카드 |
|---|---|---|---|---|
| 2400×1149 | **사장님 화면**(1920 모니터 80%) | **1.3** | 1120 → 1664 (45% → 67%) | 348×371 → 522×446 |
| 1920×919 | 1920 모니터 100% | 1 | 1120 → 1280 (58% → 67%) | 401×343, 한 줄 설명 |
| 1920×1080 | 전체화면(F11) | 1.2 | 1536 | 482×411 |
| 2560×1300 | QHD | 1.4 | 1792 | 562×480 |
| 1366×657 · 1536×730 | 노트북 | 1 (그대로) | 1120 | 그대로 |

나가기 창(`.leave-box`, 6차)도 같은 배율로 커집니다. **zoom 은 `vh` 에도 배율을 곱하므로**(크로미움 실측: zoom 2 + 50vh → 창 높이 그대로 1000px) 창 높이 상한을 `calc((100vh - 36px) / var(--z,1))` 로 나눠 두었습니다. 8차 «사용 안내» 창(`#guideDlg`)은 `.wrap` 밖이라 배율을 받지 않습니다(안내서 자체 화면).

검사:
- `test-harness/ai_speaking_entry_harness.mjs` 9차 절(정적, `--fast` 에 포함) — 단계를 CSS 에서 읽어 창 크기 격자(900~4200 × 500~2400) 전체로 «폭 80% · 한 화면 · 순서 · 노트북 불변 · 사장님 창은 커짐» 을 돌림. 6차 절의 `max-height` 글자 검사는 여는 괄호 하나만 더 받게 넓힘(«100vh 다음 100dvh» 순서 검사는 그대로).
- `test-harness/manual/ai-speaking-pc-scale-browser.mjs`(새 파일, 실제 크로미움) — 13개 창 × 한국어·영어·**영어+넓은 글꼴(en-wide)** × 저장 전·후 + 나가기 창 + 상황 목록 + 사용 안내 창. `.github/workflows/ai-speaking-browser.yml` 이 함께 돌림(경로 필터에도 추가).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **본문 폭만 넓히기**: 카드만 옆으로 늘어나고 글자·그림은 그대로라 「크게」가 안 됨. 1280px 까지만 넓힌 것은 «카드 설명이 (보통 글꼴에서) 한 줄이 되는» 지점이라서.
- **글자 크기·간격을 하나하나 키우기**: 규칙 수십 줄을 단계마다 다시 적어야 하고 비율이 어긋나기 쉬움. 이 저장소는 같은 요청(리딩 래더 2026-10-19 「글자가 너무 작아」)을 `.wrap` zoom 단계로 풀었고(`stories.html`), 그 방식을 따랐음.
- **폭만 보고 키우기**: 2400 폭이면 1.7배까지 가능하지만 높이가 1149 라 「확인」 버튼이 화면 아래로 밀림 → 폭과 높이를 함께 봄. 사장님 창에서 1.3 이 «스크롤 없이 들어가는 가장 큰 배율».
- **노트북까지 키우기**: 1366·1536 노트북은 이미 화면의 71~79% 를 쓰고, 키우면 스크롤이 생김 → 건드리지 않음.
- **나가기 창은 그대로 두기**: 페이지만 1.3배가 되면 창이 상대적으로 작아 보임 → 같은 배율. 대신 위의 `vh` 보정이 필요했음.
- **첫 판(높이 기준 870, 여백 그대로)**: 이 컨테이너 기본 글꼴(Inter)로만 재서 «한·영 모두 한 줄» 이라 적었는데, **CI 러너(DejaVu Sans)에서 영어 설명이 두 줄**이 되어 문서가 894px 로 늘었고 2400×1149·1760×965 영어 창에서 아래가 몇 px 넘쳐 새 브라우저 검사가 잡았음(PR #2070 첫 CI).
  - «기준을 900 으로 올리기» 는 사장님 창(1149)이 1.3 → 1.2 로 내려가서 버림.
  - 대신 1600px 이상에서 세로 여백을 줄여 «두 줄인 최악의 경우» 도 875 안에 들게 함. 브라우저 검사에 **영어 + DejaVu Sans 강제(en-wide)** 판을 더해 로컬에서도 최악의 경우를 보게 함.
- **병합 중 다시 넘침**: 같은 날 main 의 8차 «사용 안내» 버튼(40px)이 안내줄에 들어와 최악의 경우가 880.7px 로 늘었음 → 안내줄 위아래·설정 칸 위 여백을 조금 더 줄여 866.7px. 7차 «시작 링크는 묻지 않고 간다» 때문에 나가기 창 검사는 «홈(←)» 링크로 열도록 바꿈.
