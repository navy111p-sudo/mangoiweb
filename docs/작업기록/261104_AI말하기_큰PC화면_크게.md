# AI 말하기 — 큰 PC 화면에서 크게 보이게 (7차)

- 날짜: 2026-11-04
- 작업자: Claude (사장님 요청)
- 브랜치 / PR: `ai-speaking-pc-bigger`

## 1. 왜 했나

사장님 PC 화면 캡처(`mangoi.ai/ai-speaking.html`)와 함께 「이거 PC 화면에 적합하게 지금보다 크게 해서 잘 보이게 가장 적절하게 보이게 해줘」.

캡처를 재 보니 **1920 모니터 + 브라우저 80% 축소**(주소창 돋보기 아이콘, 카드 폭 866px ÷ CSS 1084px = 0.80)였습니다.
그러면 창은 CSS 기준 약 **2400×1149** 인데, 화면 본문이 `max-width:1120px` 로 고정이고 큰 화면용 규칙이 없어
**본문이 화면 폭의 45%** 만 쓰고 아래로 240px 가 비어 있었습니다(실측: 문서 높이 910px).

## 2. 무엇을 바꿨나

`cloudflare-deploy/public/ai-speaking.html` — CSS 만(스크립트는 한 글자도 안 바뀜).

| 창 폭·높이 | 바뀐 것 |
|---|---|
| 1600px 미만(노트북 1366·1440·1536, 태블릿, 휴대폰) | **그대로** |
| 1600px 이상 | 본문 1120 → **1280px**, 아래 여백 28 → 12px. 카드 설명이 한·영 모두 한 줄이 되어 카드가 오히려 24px 낮아짐(문서 높이 910 → 870) |
| 그 위로 폭·높이가 충분하면 | `.wrap` 에 **zoom 1.1 ~ 2.4** 단계(글자·카드·버튼이 같은 비율로 커짐) |

단계 조건(작은 것부터 적어 «맞는 것 중 가장 큰 단계» 가 이김):
- 폭: 본문 1280 × 배율 ≤ 창 폭의 80% → `min-width = 1600 × 배율`
- 높이: 문서 전체 875 × 배율 ≤ 창 높이 → **「확인」 버튼까지 스크롤 없이 한 화면**
  (875 = 실측 870 + 글꼴 차이 여유 5px. 한글은 시스템 글꼴 — 윈도우는 맑은 고딕 — 로 그려져 줄바꿈이 조금 다를 수 있음)

결과(실측, 크로미움):

| 창(CSS px) | 예시 | 배율 | 본문 폭 | 카드 |
|---|---|---|---|---|
| 2400×1149 | **사장님 화면**(1920 모니터 80%) | **1.3** | 1120 → 1664 (45% → 67%) | 348×371 → 522×451 |
| 1920×919 | 1920 모니터 100% | 1 | 1120 → 1280 (58% → 67%) | 348 → 401 폭, 한 줄 설명 |
| 1920×1080 | 전체화면(F11) | 1.2 | 1536 | 482×416 |
| 2560×1300 | QHD | 1.4 | 1792 | |
| 1366×657 · 1536×730 | 노트북 | 1 (그대로) | 1120 | 그대로 |

나가기 창(`.leave-box`, 6차)도 같은 배율로 커집니다. **zoom 은 `vh` 에도 배율을 곱하므로**(크로미움 실측: zoom 2 + 50vh → 창 높이 그대로 1000px) 창 높이 상한을 `calc((100vh - 36px) / var(--z,1))` 로 나눠 두었습니다.

검사:
- `test-harness/ai_speaking_entry_harness.mjs` 7차 절(정적, `--fast` 에 포함) — 단계를 CSS 에서 읽어 창 크기 격자(900~4200 × 500~2400) 전체로 «폭 80% · 한 화면 · 순서 · 노트북 불변 · 사장님 창은 커짐» 을 돌림. 6차 절의 `max-height` 글자 검사는 여는 괄호 하나만 더 받게 넓힘(«100vh 다음 100dvh» 순서 검사는 그대로).
- `test-harness/manual/ai-speaking-pc-scale-browser.mjs`(새 파일, 실제 크로미움) — 13개 창 × 한/영 × 저장 전·후 + 나가기 창 + 상황 목록. `.github/workflows/ai-speaking-browser.yml` 이 함께 돌림(경로 필터에도 추가).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **본문 폭만 넓히기**: 카드만 옆으로 늘어나고 글자·그림은 그대로라 「크게」가 안 됨. 1280px 까지만 넓힌 것은 «카드 설명이 한 줄이 되는» 지점이라서(1240px 은 영어가 아직 두 줄).
- **글자 크기·간격을 하나하나 키우기**: 규칙 수십 줄을 단계마다 다시 적어야 하고 비율이 어긋나기 쉬움. 이 저장소는 같은 요청(리딩 래더 2026-10-19 「글자가 너무 작아」)을 `.wrap` zoom 단계로 풀었고(`stories.html`), 그 방식을 따랐음.
- **폭만 보고 키우기**: 2400 폭이면 1.7배까지 가능하지만 높이가 1149 라 「확인」 버튼이 화면 아래로 밀림 → 폭과 높이를 함께 봄. 사장님 창에서 1.3 이 «스크롤 없이 들어가는 가장 큰 배율».
- **노트북까지 키우기**: 1366·1536 노트북은 이미 화면의 71~79% 를 쓰고, 키우면 스크롤이 생김 → 건드리지 않음.
- **나가기 창은 그대로 두기**: 페이지만 1.3배가 되면 창이 상대적으로 작아 보임 → 같은 배율. 대신 위의 `vh` 보정이 필요했음.

## 4. 확인한 방법

- 실제 크로미움 스크린샷 비교(2400×1149 · 1920×919 등) — 화면을 위아래·좌우 알맞게 채우고 「확인」 까지 한 화면.
- `node test-harness/ai_speaking_entry_harness.mjs` — 7차 절 12건 포함 전체 PASS.
- `node test-harness/manual/ai-speaking-pc-scale-browser.mjs` — 314건 PASS.
- 기존 브라우저 검사: `ai-speaking-browser.mjs` 320가지(3,280건) PASS · `ai-speaking-leave-ask-browser.mjs` 313건 PASS (1920×1080 창이 이제 배율 1.2 를 받는데도 통과).
- 변이시험(위 두 검사): zoom 줄 제거 · 창 높이 배율 미보정 · 1.3 단계 높이를 1000 으로 · 1280px 본문 제거 · 단계 순서 뒤집기 · 1280px 본문을 1300px 부터 → 전부 실제 FAIL. «1.3 단계를 폭 1700 부터» 는 정적 하니스만 잡음(브라우저 창 목록에 해당 창 없음).
- 타입체크: TS 변경이 없어 돌리지 않음.
