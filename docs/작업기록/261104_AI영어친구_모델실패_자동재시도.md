# AI 영어친구 — 모델이 전부 실패한 턴을 자동으로 한 번 더 시도 / AI friend: auto-retry when every model fails

## 1. 왜 했나 / Why

- 사장님 화면(2026-11-04): 학생 문장 "Yeah, I really liked it yesterday." 뒤에
  「⚠️ 지금은 답을 만들지 못했어요. 잠시 뒤 다시 보내 주세요.」가 떴고, **바로 다음 턴은 정상**이었습니다.
- 이 안내는 버그가 아니라 2026-09-09 에 넣은 «정직한 실패 표시»(`ai_unavailable`)입니다.
  서버(`api-ai.ts` chat-friend)가 모델 3개(llama-3.3-70b → llama-3.1-8b → llama-3-8b)를 차례로 불러
  **셋 다 에러·빈 답**이면 그 표시를 붙입니다.
- 다음 턴이 바로 정상이었다는 것은 «잠깐» 의 실패라는 뜻 — 학생이 직접 다시 보내게 하지 말고
  **서버가 잠깐 기다렸다 한 번 더** 부르게 해 달라는 지시(「자동 재시도 기능 만들어서 PR 올려줘」).
- EN: The notice is the intended "honest failure" UI. The next turn worked, so the failure was transient;
  the server now waits briefly and retries the model list once before giving up.

## 3. 검토했다가 버린 방법 / Rejected options

1. **화면(ai-friend.html)이 같은 요청을 다시 보내기** — 버림.
   실패한 턴에도 서버는 ① 학생 발화를 `ai_friend_chats` 에 저장 ② 대화 포인트 2P 적립 ③ (집중교정·음성 턴) Azure 발음 채점을 합니다.
   화면이 다시 보내면 셋이 **두 번** 일어납니다 — 기록이 겹쳐 모델이 «학생이 같은 말을 두 번 했다» 로 보고,
   포인트가 두 번 나가고(1P=1원), 채점 비용이 두 번 듭니다. 서버 안에서 모델만 다시 부르면 셋 다 한 번입니다.
2. **예산 없이 무조건 다시 하기** — 버림. 실패가 타임아웃류(모델마다 수십 초)면 기다림이 두 배가 됩니다.
   첫 시도가 오래 걸린 턴은 다시 하지 않습니다(`retry:budget` 으로 기록에 남음).
3. **재시도에도 스트리밍 쓰기** — 버림. «스트리밍은 첫 모델에서 한 번만» 규칙(이미 보낸 문장과 새 답이 섞임)을 그대로 둡니다.
   미리 흘려보낸 문장이 있었다면 최종본과 달라지므로 기존 `replaced:1` 경로로 화면이 다시 읽습니다.
4. **오류 종류(429·용량 초과만)를 골라 재시도** — 이번엔 안 함. 빈 답(형식 깨짐)도 무작위성(temperature 0.8) 때문에
   다시 부르면 살아날 수 있고, 판정 목록을 손으로 두면 새 오류 문구에 조용히 안 맞습니다. 결정적 오류(예: 입력 초과)면
   최대 «1.5초 + 호출 3번» 이 더 들고 결과는 예전과 같은 안내입니다.
5. **살아난 턴은 기록하지 않기** — 버림. 그러면 재시도 뒤로 «첫 시도 실패» 가 `ai_failure_log` 에서 사라져
   실패가 줄어든 것처럼 읽힙니다. 그래서 `chat-friend-rescued` 로 따로 남깁니다(`chat-friend` 줄 수 = 끝내 실패한 턴).

```sql
SELECT feature, COUNT(*) AS n,
       SUM(models LIKE '%retry:budget%') AS skipped_budget
FROM ai_failure_log
WHERE feature IN ('chat-friend', 'chat-friend-rescued')
  AND created_at >= strftime('%s','now','-7 days') * 1000
GROUP BY feature;
```

`chat-friend-rescued` = 재시도로 살아난 턴 · `chat-friend` = 끝내 안내가 뜬 턴.
