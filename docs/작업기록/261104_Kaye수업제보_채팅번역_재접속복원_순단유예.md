## 3. 뿌리와 고침

### ③ 순단에 튕김 — 원인 둘

**(a) 생존 판정이 ping 을 한 번도 못 셌다.** `video-call-room.ts` 가 `(ws as any).getAutoResponseTimestamp?.()` 를 불렀는데 **WebSocket 에는 그런 메서드가 없습니다.** 정본은 `DurableObjectState.getWebSocketAutoResponseTimestamp(ws)`(Cloudflare 문서 «Durable Object State» — `Date | null`). `?.()` 라 에러 없이 늘 `undefined` → ping 자동응답이 생존 근거로 **2026-08-20 부터 한 번도** 안 쓰였습니다.
- 2026-09-15 전: 조용한 학생이 120초마다 끊김(그날 «2분마다 끊김» 의 뿌리 — 당시 작업기록은 «추론» 으로 남겼음)
- 그 뒤: 600초(`LIVENESS_NOPING_STALE_MS`)마다 끊김 → 실측 633초와 일치
- ✅ `autoRespAt()` 한 곳에서 정본 API 로 읽음. `lastSeenOf`·`autoSeenOf` 둘 다 그것을 씀.

**(b) 소켓이 닫히는 «순간» user-left 를 방송했다.** 상대 화면은 그 자리에서 `pc.close()`(`vcRemovePeer`) — P2P 영상이 멀쩡해도 끊기고, 다시 붙을 때 옛 소켓은 이미 `joined:false` 라 무중단 재연결(`VC_STICKY_UID=on`)이 신원을 못 물려받아 «새 사람» 으로 처음부터 다시 맺음.
- ✅ 같은 `clientId` 의 순단은 **20초 유예**(`DROP_GRACE_MS`). 기록은 storage `drop:<userId>`(hibernation 을 넘어 산다).
- 그 안에 돌아오면 `takeDrop()` 으로 **같은 userId** 를 물려받고 아무것도 방송 안 함 → 상대 화면 연결 유지.
- 안 돌아오면 알람(`flushExpiredDrops`)이 예전과 똑같이 `user-left(dropped)`.
- `leave-room`(나가기 버튼)은 미루지 않음 · 스위치가 꺼져 있으면 예전과 100% 동일 · 참관자 제외.
- 유예 «중» 에 새로 들어온 사람에게만 돌아온 사람의 `user-joined` 를 보냄(`joinedAt` > 끊긴 시각).
- 입장할 때마다 부르던 `scheduleLivenessAlarm()` 이 20초 알람을 45초로 밀지 않게(`inAlarm` 밖에서는 «당기기만»).

### ② 재입장 후 교재·칠판 질문이 안 보임

- 칠판(`wbOps`)·교재 판서(`pdfAnnoOps`)는 **메모리에만** 있었습니다. 이 DO 는 Hibernation 을 쓰고 ping 은 자동응답이라 DO 를 깨우지 않으므로, **수업 중에도 10초만 조용하면 인스턴스가 내려가** 버퍼가 빕니다(Cloudflare 문서 «Durable Object Lifecycle»). 2026-09-01 점검 주석이 이미 이 구멍을 적어 두었지만 고쳐지지 않았습니다.
  - ✅ 1.5초 모아(`LOG_FLUSH_MS`) storage 에 한 번에 씀(`wbl:`·`pal:`). 예약된 `setTimeout` 이 있는 동안은 hibernation 이 일어나지 않으므로(같은 문서) 모은 것을 잃지 않습니다. 재입장 때 `ensureLogsLoaded()` 가 다시 읽어 `whiteboard-replay`·`pdf-anno-replay` 로 돌려줌.
  - 교재 판서는 «원본 메시지» 를 쓰고 되읽을 때 `recordPdfAnno(…, false)` 에 다시 흘려 획을 재조립(점이 획 안에 쌓여 «완성된 획» 을 쓸 시점이 없음).
- 강사의 **현재 탭**(`tab-sync`)은 저장도 재전송도 안 됐습니다 → 재입장한 학생은 `pdf-sync` 에 끌려 교재 탭에 머물고, 강사가 칠판에 질문을 적어 둔 상태여도 못 봤습니다.
  - ✅ 강사·관리자가 보낸 `tab-sync` 만 `tabState` 로 저장, 입장 시 **`pdf-sync` 뒤에** 재전송.
- 정리: 칠판 지우기·다른 교재·«새 수업»(방이 5분 넘게 비었음)·아무도 다시 안 오는 빈 방(알람)에서 storage 까지 지움. ⚠️ 예전 «새 수업» 정리는 교재/영상이 있을 때만 돌아서, 판서가 storage 에 남게 된 지금은 따로 정리해야 지난 수업 칠판이 안 넘어갑니다.

### ① 채팅 번역

- 화면(`idx-vc-chat.js`)이 **3초**만 기다리고 못 받으면 **아무 말 없이** 원문을 보냈습니다(입력칸 «번역 중…» 안내는 글이 들어 있으면 안 보임).
  - ✅ 8초 대기(`WAIT_MS`) · 번역 중 버튼에 «⏳ 번역 중 / Translating» · 실패하면 원문을 보내되 «⚠️ 번역이 안 돼 원문 그대로 보냈어요 / Translation failed — sent as typed» 표시. `?v=2 → 3`(index.html 1줄 · teacher.html 미리받기 1줄).
- 서버(`/api/translate` chat 모드)는 언어모델이 한 번 던지면 끝이었습니다.
  - ✅ 일시 실패면 **1회 재시도**, 총 5초 상한(`CHAT_LLM_TIMEOUT_MS`) 넘으면 m2m100 대체. 시간 초과는 재시도 안 함(화면 8초 안쪽).
  - ✅ 덤: 중국어→한국어가 실패하면 학습 화면용 안내문 「뜻을 불러오지 못했어요…」가 **채팅 메시지로 학생에게 나갈 수 있었음** → chat 모드는 원문을 돌려줘 화면이 «실패» 로 알아봄. learn 모드는 그대로.

## 4. 검토했다가 버린 방법

- **`LIVENESS_STALE_MS` 를 늘리기** — 근거(ping)를 못 읽는 것이 문제라 늘려도 같은 순환이 길어질 뿐이고, 진짜 유령 청소까지 늦어짐(2026-09-15 기록과 같은 결론).
- **클라이언트 ping 문자열을 바꿔 자동응답을 피하기** — `idx-main.js` 는 blocking(첫 화면 예산), DO 가 25초마다 깨어나 hibernation 설계가 뒤집힘.
- **강사 화면이 새 입장자에게 칠판을 다시 보내기** — 강사가 재입장하는 경우를 못 덮고, `idx-main.js`(blocking)에 넣어야 하며 DO 에 새 메시지 타입도 필요. 서버 저장이 모든 경우를 덮음.
- **칠판 획을 하나씩 바로 storage 에** — `whiteboard-draw` 는 마우스 움직임마다 와서 쓰기가 너무 많음 → 1.5초 묶음.
- **번역 실패 시 보내지 않고 입력칸에 남기기** — 수업 중 대화가 멈추는 쪽이 더 나쁨. 원문을 보내고 «번역 안 됨» 을 분명히 알리는 쪽을 택함.
- **learn 모드에도 재시도·상한** — 게임이 한 번에 50문장을 물어 상한에 걸리면 직역(「훌륭한 직업!」)으로 떨어짐 → chat 모드에만.
