# 강사 «수업 요약 / 캘린더» — 같은 수업이 두 장(Unknown + 옛 LMS 출석)으로 나오던 것을 한 장으로

- 작업자: Claude Code (사장님이 강사 제안 «= DONE ✅» 과 배포 후 화면 스크린샷 전달)

## 1. 왜 했나

#1999 배포 뒤 사람이 강사(KAYE) 화면으로 본 2026년 10월 달력(스크린샷)에서, **매주 수요일 9:00am 수업이 두 장**으로 나왔다.

| 카드 | 색 | 내용 |
|---|---|---|
| 새 예약(망고아이 예약표) | 회색 | Regular class · 9:00am – 9:20am · 20 min · KAYE · **[Unknown]** · Report: not written |
| 옛 LMS(카페24) 출석 | 초록 | 9:00am – 9:20am · 20 min · TEACHER KAYE · **[Attended (old LMS)]** · Report: not written |

같은 학생 · 같은 날 · 같은 시각 = 같은 수업인데, 한 장은 «모름», 한 장은 «출석» 이라 서로 엇갈려 보였다.
강사 제안(«매니저 화면처럼 쉽게 보기»)과 반대 방향이다 — 매니저 달력은 수업 하나에 한 장이다.

### 원인

`teacher-student-history.ts` 의 옛 LMS 중복 거르기 규칙이 **예약이 «done» 일 때만** LMS 줄을 숨겼다.
원장(`buildStudentLedger`)은 c24 출석을 **읽지 않으므로**, 수업을 옛 LMS 에서 한 학생은 예약이 늘 «unknown» 이다
→ 숨기지도 합치지도 않고 두 장이 다 남았다. 하니스도 그것을 «LMS 근거를 지우지 않는다» 는 이유로 일부러 검사하고 있었다.

## 2. 무엇을 바꿨나

| 항목 | 파일 | 내용 |
|---|---|---|
| 같은 칸 = 한 장 | `cloudflare-deploy/src/teacher-student-history.ts` | 정확히 같은 칸(학생 + 절대 시각 — 수업 목록과 같은 열쇠 `dropCafe24SlotDuplicates`)에 LMS 출석이 있고 예약이 **«unknown»** 이면, **예약 카드가 LMS 출석을 넘겨받는다**: `state:'done'`, 라벨 «Attended (old LMS) / 출석 (옛 LMS)», `attendance_source:'lms'`, `lms_room_id:'c24-…'`. 예약 카드라서 수업 종류(Regular class)·강사·예약 id 는 그대로 |
| 그대로 둔 것 | 〃 | 예약 «done» → LMS 줄 숨김(예전과 같음). 예약이 **다른 상태**(학생 결석·연기 등)면 두 출처가 서로 다른 말을 하므로 **둘 다 남긴다**(예전과 같음) |

LMS 강사를 모르면(급여표 번호가 두 이름) 잃을 것이 없으니 한 장. 보고서가 붙은 카드는 그 보고서 작성자가 담당 교사(목록 보기와 같은 우선순위)라 한 장 유지. 같은 칸 «unknown» 예약이 둘이면 강사가 맞는 쪽에 붙인다 |
| 🔁 후속 — 원장 값은 그대로 | 〃 | 처음 판은 합친 카드의 `deduct`/`carry` 를 «완료» 값으로 덮어썼다(지금 읽는 곳은 없지만, 원장이 «차감 없음» 이라 한 회차를 이 응답만 «차감» 이라 말하게 됨). **표시만** 바꾸고 원장 칸은 원장이 말한 그대로 둔다. 쓰이지 않던 `duration_min` 대체 줄(원장은 늘 20분 기본값을 줌)도 뺐다 |
| 보고서 짝짓기 | 〃 | 합친 카드는 옛 LMS 방(`c24-…`)에 쓴 보고서도 자기 것으로 찾는다(`byRoom(lms_room_id)`). 같은 방 보고서의 수정본이 «출결 기록 미확인» 줄로 따로 튀어나오지 않게 고아 보고서 거르기에도 `lms_room_id` 를 본다. 덤으로 «그날 수업이 한 장» 이 되어, 방 번호 없는 보고서도 그날 카드에 붙는다(두 장이면 못 붙던 것) |

화면 스크립트(`public/js/teacher-student-history.js`)는 **안 바꿨다** — 서버가 주는 상태·라벨을 그대로 그린다.

## 3. 검토했다가 버린 방법

- **LMS 줄을 그냥 숨기기(매니저 달력처럼)** — 그러면 카드에 «Unknown» 만 남아 «출석했다» 는 유일한 근거가 사라진다.
  옛 규칙이 지키려던 것(근거를 «기록 없음» 으로 바꾸지 않는다)은 옳았다. 버린 것은 «두 장» 이지 «근거» 가 아니다.
- **원장(`buildStudentLedger`)이 c24 출석을 읽게 하기** — 원장은 차감·이월·급여까지 같은 답을 내야 하는 정본이라
  사고 반경이 이력 창 하나가 아니다. 이력 창의 «보여 주기» 문제는 이력 로더에서 끝낸다.
- **«unknown» 이 아닌 상태(학생 결석 등)도 합치기** — 두 출처가 서로 반대말을 하는 경우라 한쪽을 고르면 다른 쪽 근거가 묻힌다. 둘 다 남긴다(드문 경우).
- **강사 이름을 LMS(«TEACHER KAYE»)로 바꾸기** — 예약 카드의 강사는 대체강사·강사변경 이력 보정을 타는 값이라 그대로 둔다.
- **강사가 다를 때 한 장에 두 이름을 함께 쓰기**(«B · 옛 LMS 강사: A») — 화면 스크립트·`?v=` 를 함께 바꿔야 하고, «누가 가르쳤나» 를
  화면이 고르는 셈이 된다. 엇갈리면 두 장(기존 원칙 «각 출처가 아는 만큼»)이 더 정직하다. 대타는 드물다(44쌍 중 2쌍).
- **강사 비교를 합치는 순간(대타 보정 전)에만 하기** — 대타 기록이 나중에 이름을 바꾸면 비교가 어긋난다. 그래서 «최종 이름» 으로 끝에서 한 번 더 본다.
