# 관리자 화면 로딩 단축 — 색 보정 페인터를 «보이는 카드만» (2026-11-04)

## 왜
사장님: 「관리자 페이지를 들어갈 때 대부분의 페이지가 로딩이 너무 오래 걸려」.

## 잰 것 (로컬 서버 + 헤드리스 크로미움, API 는 즉시 응답 스텁)
- `admin.html` 은 js 196개(합계 3.7MB, defer 172개) + HTML 1.38MB.
- CPU 프로파일(저하 없음): 스크립트 자체 시간의 대부분이 **`js/adm-s13.js` 하나 2,245ms**
  (`ivoryLighten` 이 카드 100장의 «모든» 하위 요소에 `getComputedStyle` — 안 보이는 카드까지
  스타일을 강제 계산. 트레이스의 UpdateLayoutTree 1,639ms 도 대부분 이것).
- 그 페인터가 로드 때 1회 + 1.5초 뒤 1회 더 전체를 훑었다.
- `/admin/*.html` 하위 화면(exec·weekly-schedule·student·monitor-wall·teacher-payroll·finance-realtime)은
  0.2~1.3초로 이미 빨라 손대지 않았다(병목은 `admin.html` 하나).

## 한 일
`adm-s13.js`(v=11) — 로드 때 전체 스캔 대신 `IntersectionObserver` 로 카드가 화면 근처(위아래 400px)에
**처음 들어올 때 그 카드만** 칠하고, 1.5초 뒤 그 카드만 한 번 더 칠한다(옛 «1회 더» 와 같은 뜻 — 늦게
그려지는 표·목록). IntersectionObserver 가 없으면 예전 동작. 다크 정리 분기·카드 펼침(toggle) 재칠·
`applyAdminColor` 는 그대로.

## 결과 (같은 측정)
| 조건 | 전 DOMContentLoaded / load | 후 |
|---|---|---|
| CPU 저하 없음 | 2.2초 / 2.5초 | 0.85초(DCL 근사) |
| CPU 4배 저하 | 11.9초 / 15.6초 | 3.4초 / 5.3초 |
| CPU 4배 + 10Mbps·80ms | 16.4초 / 19.7초 | 6.5초 / 8.2초 |
- `adm-s13.js` 자체 시간 2,245ms → 193ms.

## 확인한 방법
- 카드 12장을 열어 페인터가 칠한 요소 수(`__ivLit`·`__ivTxC`·인라인 색 개수)를 옛 코드(origin/main 사본)와
  대조 — 11장 동일, `card-centers` 는 새 코드가 늦게 그려진 내용을 조금 더 칠함(의도대로).
- `asset_version_harness` 통과, `run.mjs --fast` (결과는 PR 본문).

## 버린 방법
- 스크립트 196개를 묶거나 defer 이동 — 범위가 크고 이득이 이 한 곳보다 작다(CLAUDE.md «blocking→defer 는
  실행 시간을 거의 안 줄인다» 실측).
- `adm-light-surfaces.js`(253ms)·`adm-s12.js`(127ms) — 이미 «보이는 요소만» 최적화가 있어 이번엔 둠.
