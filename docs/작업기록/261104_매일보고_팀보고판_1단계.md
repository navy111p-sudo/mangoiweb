# 매일보고 팀 보고판(1단계) — 경영진 전용 «사람별 한 줄» 보고판 신설

- 날짜: 2026-11-04
- 작업자: Claude Code (사장님 요청 · 「추천안대로 1단계 팀 보고판부터 개발해줘」)
- 브랜치 / PR: `feat/handover-team-board`

## 1. 왜 했나

사장님 요청: **「가능하면 일일보고에서 모든 매니저들과 본사 임직원들의 일일보고를 한 번에 확인하고 싶어」**.
출발은 이병엽 이사(`mgr_lby`, 본사 영업이사)의 이중 작성 문제였습니다. 외근·출장이 잦아 영업일지를 쓰는데, 본사 직원이라 매일보고도 써야 했습니다.
그 분석을 담은 제안서(Claude Docs «영업일지·매일보고 통합 및 팀 보고판 제안서»)에서 3단계 중 **1단계 = 보는 쪽(팀 보고판)** 을 먼저 하기로 했습니다.

지금까지의 증상은 이랬습니다.
- 매일보고 화면 «받은 보고 확인» 은 **«내 미확인 목록» 중심**입니다. 미확인이 0건이면 「해당 보고가 없습니다」만 보였습니다(사장님 화면 스크린샷).
- 그래서 **누가 냈고 · 누가 안 냈고 · 어디에 문제가 있는지**를 한 화면에서 볼 수 없었습니다.
- 영업 내용은 다른 화면(영업 실적·인사평가)에 따로 있었습니다.

**보고판 규칙(정본은 `handover-board.ts`)**

- 상태 순서: 문제·긴급이 적힌 미확인(`issue`) → 미확인(`awaiting`) → 보완 요청함(`returned`) → 확인됨(`acknowledged`) → 미제출(`missing`) → 오늘 안 씀(`off`).
- 같은 칸 안에서는 «문제가 적힌 것 → 긴급만 표시한 것 → 이름순» 입니다.
- 요약 5칸은 작성 대상·제출·미제출·문제 있음·미확인입니다. 칸을 누르면 그 줄만 보이고, **칸의 숫자와 보이는 줄 수가 같은 판정에서 나옵니다.**
- **초안(draft)은 «미제출» 로만 보입니다.** 내용은 물론 «초안이 있다» 는 사실도 내보내지 않습니다(`visible()` 와 같은 약속).
- 영업일지는 «읽기만» 합니다. 영업 담당자로 연결된 계정만 숫자가 나오고, 0건이면 «영업일지 0건», 표를 못 읽으면 `null`(«모름»)입니다.
- 명단은 «내 미작성 알림 설정» 을 켰거나(`enabled`) 필수 대상(`mandatory`)인 본사 계정입니다. 명단 밖 계정은 맨 아래 «보고 명단에 없는 본사 계정 N명» 에 이름만 나옵니다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **기존 `/home` 응답을 화면에서 다시 조립하기 → 버림.** `/home` 의 `required` 는 `enabled=1` 만 세어 **필수 대상(`mandatory`)이 빠질 수 있고**, 영업일지도 없습니다. 판정이 화면에 흩어지면 하니스로 잴 수도 없습니다. 그래서 새 `GET /board` 와 순수 함수로 갔습니다.
- **판정을 `daily-handover.ts` 안에 넣기 → 버림.** 이미 800줄이 넘습니다. import 0 파일로 빼서 하니스가 그대로 돌리게 했습니다. 대가로 그 정본을 불러오는 **하니스 5개에 import 등록 한 줄씩**이 필요했습니다.
- **동적 `import()` 로 하니스가 안 깨지게 하기 → 버림.** 숨은 의존이 되어 다음 사람이 모릅니다. 명시적 import 와 하니스 등록 쪽을 택했습니다.
- **초안을 «작성 중» 으로 보여 주기 → 버림.** 「초안은 보낸 뒤에만 남의 것」이라는 기존 약속을 깹니다(`daily_handover_harness` 가 «overview 에서도 초안은 비공개» 로 못 박음). 그래서 «미제출» 로만 보입니다.
- **«모두 확인» 버튼 → 넣지 않음.** 장지웅 부장의 «열고 10초 이상 읽어야 확인» 규칙(2026-10-14 대표님 지시)을 비켜 가는 길이 됩니다.
- **확인 버튼을 기존 읽기 화면으로 보내기 → 버림.** 그 자리에서 펼쳐 확인하는 쪽이 동선이 짧습니다. 대신 **새 판정은 만들지 않고** 기존 `POST /opened`·`/ack`·`/return` 을 그대로 부릅니다(허락은 서버가 매번 다시 봄). 이력·보류 같은 드문 기능은 «읽기 화면에서 열기» 링크(`?date=…&report=…`)로 기존 화면에 맡겼습니다.
- **«외근·출장» 거르개 → 1단계에서 뺌.** 근무 형태 칸이 2단계에서 생깁니다. 지금 넣으면 «영업일지가 있으면 외근» 같은 추측이 됩니다.
