# 수업 «취소» 는 서버에서도 본사 계정만 (권한 분리)

- 날짜: 2026-11-04
- 작업자: Claude Code (요청: 사장님 계정 — «추천안대로 상태 컬럼이랑 권한 분리 구현해줘» · «이렇게 만들어줘»)
- 브랜치: `cancel-hq-only-server-guard`
- 함께 본 것: 같은 날 다른 세션의 [261104_연기수업_원래날짜에_남기기.md](261104_연기수업_원래날짜에_남기기.md)(#2057 — 상태 칸·원래 날짜 줄)

## 1. 왜 했나

- 매니저 제보: «can we not delete the schedule if being cancelled? … add another column … No more cancel class option, I think it's okay as we all need postpone».
  - 상태 칸(취소·연기)은 11/3(06b676ae)과 11/4 #2057 로 이미 반영됐다. 남은 것이 «권한 분리» 였다.
  - «No more cancel class option» 은 «강사·지사 화면에는 취소가 없어도 된다(연기만 쓴다)» 는 확인이다. 화면(연기·변경 창)은 이미 본사(canCancel)에게만 취소 버튼을 준다.
- 그런데 **서버는 강사 세션의 직접 호출을 막지 않았다.** `DELETE /api/admin/class-schedules/:id` 에는 역할 확인이 없고, 그 경로는 강사 차단 접두사에도 없다(강사는 같은 경로의 PATCH 로 수업을 옮기므로 접두사로 막을 수 없다). 지사·대리점은 index.ts 스코프 관문이 이미 403 이다.

## 2. 무엇을 바꿨나

| 파일 | 내용 |
|---|---|
| `src/api-admin.ts` DELETE class-schedules/:id | 맨 앞에서 강사(역할 기준 `isTeacher`)·역할을 못 읽음(`ok=false`) → 403. 문구는 정본 `forbiddenTeacherBody(…, '수업 «취소» 는 본사 계정에서 합니다.', 'Cancelling a class is done by an HQ account.')` — 연기·변경 창이 이미 403 을 같은 말로 그린다(class-move-modal.js). |
| `test-harness/class_cancelled_visible_harness.mjs` | K절 — 강사 세 종류(일반 · 스코프 'hq' 인 hq_t_* · 스코프 'none' 인 «교사» 이름)·로그인 없음은 403 + 행 그대로 + 이력 안 남음, 짝으로 본사는 그대로 취소. 변이 3종(막기 제거 · 조건 뒤집기 · 역할 모름 통과). |

## 3. 검토했다가 버린 방법

- **취소 기능 자체를 없애기** — 퇴원·환불·휴원·오입력을 정리할 길이 사라진다(연기만 있으면 끝에 «보강» 회차가 계속 생겨 정산·급여·알림이 틀어진다). 제보도 «없어도 된다» 는 확인이었다. → 본사 전용으로 두고 서버에서 강사 직접 호출만 막았다.
- **강사 차단 접두사(index.ts)에 경로 추가** — 같은 경로를 강사가 PATCH(옮기기)로 쓴다. 접두사는 메서드를 가리지 않아 강사의 연기·변경까지 막힌다. 그리고 index.ts 는 공동 금지구역이다. → 핸들러 안에서 DELETE 만 막았다.
- **스코프(hq/none)로 판정** — 강사 계정 스코프가 잘못 'hq'·'none' 인 사례가 있다(index.ts «항상 role 기준»). → 역할(isTeacher)로.
- **원래 날짜 줄(옮겨 간 회차)도 따로 구현** — 처음엔 이 세션도 만들었지만 같은 기능이 #2057 로 먼저 들어가 버렸다(중복·같은 함수 이름 충돌). 그 세션에 빈틈 두 가지(매주 수업 «그 주 하루만 새 날짜로», 관리자 주간 시간표)를 메시지로 알렸다.
