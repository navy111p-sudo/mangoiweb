## 1. 왜 했나

사장님: 「학생이 말하면 아바타가 well, wow, by the way, anyway 같은 감탄사·표현을 문장 앞에서 말하게 해 달라고 했는데 **아직 안 됐어?**」
그 뒤 결정 세 가지:

- 소리형(hmm·aww·ooh 등)은 **뺀다**
- 빈도·초급 허용 여부·방식은 **알아서 가장 적합하게**
- **「절대로 지금보다 아바타의 응답이 느려서는 안 돼」**

### 첫 판(PR #2025)이 «거의 안 들린» 이유 — 코드에서 읽은 원인

| # | 원인 | 자리 |
|---|---|---|
| 1 | 빈도 지시가 «Occasionally · many replies need none» 에, 연결어 규칙의 «many good replies have none», 반복 방지 줄의 «or no linking word at all» 까지 — 세 줄이 모두 «안 써도 된다» 고 말함 | `conversation-connectors.ts` |
| 2 | 말머리 규칙은 «기존 길이 안에 넣고 좁으면 빼라» 인데 초급 S1 은 «반응 하나 + 질문 하나가 전부» → 자리 없음 | 같은 파일 · `ai-friend-level.ts` S1 |
| 3 | 칭찬 목록(Wow!, Awesome! …)이 더 구체적이라 첫자리를 차지 | `index.ts` [칭찬] · `api-ai.ts` |
| 4 | By the way·Anyway 는 말머리 목록에 없고, 초급 연결어 목록에서도 빠짐 | 같은 파일 |
| 5 | 실제로 몇 % 붙는지 잰 적이 없음 — 하니스는 «규칙이 실렸나» 만 봄 | `conversation_connectors_harness` |

⚠️ 위 표는 코드를 읽은 진단입니다 — 운영 대화 표본으로 «몇 %였다» 를 잰 것은 아닙니다(이 컨테이너는 D1·mangoi.ai 에 못 닿습니다).

## 2. 무엇을 바꿨나

### `cloudflare-deploy/src/conversation-connectors.ts` (정본 — 로직은 여기만)

- **④ `turnOpenerLine(history)` 신설** — 이번 턴에 «첫마디» 를 쓸지, 쓴다면 상황별 후보 한 개씩을 지시 한 줄로 만든다.
  - 상황 6칸: 슬픔·힘듦 / 부탁 / 나에게 질문 / 「모르겠어요」·헷갈림(→ 다음 질문을 **Anyway,** 로) / 짧은 예·아니오 / 그 밖(약 1/3 확률로 **By the way,** 로 새 질문)
  - **어느 칸인지는 모델이 학생 말을 보고 고른다** — 서버가 학생 말을 다시 판정하지 않으므로 판정 정본이 둘로 갈리지 않는다
  - **빈도**: 바로 앞 AI 답장이 첫마디로 시작했으면 이번엔 쉰다 ⟹ 약 «두 턴에 한 번»
  - **후보**: 칸마다 4개, 최근 시작 말 3개(③ `recentOpeners`)와 겹치지 않는 것 — 「다르게 시작해」 줄과 서로 다른 말을 하지 않게
  - 첫 답장(기록에 AI 답장 없음 — 인사)에는 정하지 않는다
- `connectorPromptBlock()` 이 그 줄을 **맨 끝**에 붙인다 → 이 함수를 부르는 **A.i 말하기(웜업)·AI 친구 두 화면에 자동으로** 실린다. `src/index.ts`(공동 금지구역)·`src/api-ai.ts` 는 **한 글자도 안 고쳤다**
- `AVATAR_NATURAL_OPENERS` 를 짧게 다시 썼다: «THIS TURN'S OPENER 줄이 있을 때만 · 짧은 반응·칭찬 자리를 대신(길어지지 않음) · 다른 턴엔 Oh/Well/By the way/Anyway 로 시작하지 않기 · 소리형 금지 · 집중교정 우선»
- 시작 말 판정 표(`MULTI_MARKERS`)에 첫마디 후보를 더했다 — 안 하면 「Oh, nice!」·「Oh, really?」 가 전부 «Oh,» 한 열쇠로 묶여 반복 방지가 후보를 다 지운다

### `cloudflare-deploy/src/ai-friend-level.ts` (AI 친구 초급 검사 — «다시 뽑기» 방지)

- 기초 문법 검사(`aiFriendBrokenQuestions`)가 질문 앞머리 **「Anyway,」·「By the way,」** 를 건너뛴다 — 안 그러면 「By the way, do you have a pet?」 를 «깨진 질문» 으로 보고 **모델을 한 번 더 불러** 응답이 늦어진다(실측: 수리 전 S1~S3 모두 걸림)
- 눈높이 길이 검사(`aiFriendMeasureReply`)가 문장 앞 «By the way, / Anyway,» 를 **낱말 수에서 뺀다** — 연결 표현 정본이 이미 「연결어는 단어 수에 안 센다」고 하는데 여기만 세고 있었다(S1 상한 7 에 「By the way, do you have a pet?」 = 8 → «길다» → 다시 뽑기)
- ⚠️ 넘기는 것은 «앞머리» 뿐 — 「By the way, you like dogs?」·「Anyway, dog is big?」 는 여전히 잡는다

## 3. 속도 — «절대로 느려지지 않게» 를 어떻게 지켰나

| 걱정 | 이번 변경 |
|---|---|
| 새 조회·새 호출 | **없음.** 이미 읽어 온 대화 기록만 보는 동기 문자열 계산(하니스가 «await·fetch·prepare 없음» 을 확인) |
| 지시가 길어져 첫 글자가 늦음 | 고정 규칙 619자 + 이번 턴 줄 최대 392자 = **1,012자** < 첫 판 **1,221자**(17% 짧아짐 — 하니스가 상한으로 잼) |
| 답이 길어짐 | 첫마디는 «짧은 반응·칭찬 자리» 를 **대신**한다고 지시 |
| 초급 검사에 걸려 «다시 뽑기»(모델 2회 호출) | 후보로 만든 답 40개가 S1~S3 문법·길이·조각 질문 검사를 **전부 통과**하게 맞춤(위 ai-friend-level 수리 포함) |

⚠️ 실제 운영에서 «몇 ms» 인지는 못 쟀습니다 — 위는 «느려질 원인을 만들지 않았다» 의 근거입니다.

## 4. 검토했다가 버린 방법

| 방법 | 버린 이유 |
|---|---|
| 서버가 답장 앞에 감탄사를 **덧붙이는 후처리** | 사장님이 앞선 작업에서 막음 · 아이가 따라 읽는 문장을 코드가 지어내면 안 된다(저장소 규칙) |
| 기다리는 동안 미리 녹음한 «Hmm…» 등을 먼저 틀기 | 사장님이 앞선 작업에서 «답변 앞 표현» 을 고르셨고, 이번에 소리형을 빼라고 하셨다 |
| 서버가 학생 말을 판정해(슬픔·질문…) 칸 하나만 지정 | 웜업은 그 판정에 `src/index.ts`(공동 금지구역)를 고쳐 학생 말을 넘겨야 함 · 판정 정본이 하나 더 생김. 모델에게 «상황별 후보» 를 주면 같은 효과 |
| AI 답장 **개수의 홀짝**으로 «두 턴에 한 번» | AI 친구는 최근 20줄만 읽어 개수가 어느 순간 멈춘다 → «늘 쓴다/영영 안 쓴다» 로 굳음. 앞 답장의 실제 시작을 보면 모델이 한 번 어겨도 다음 턴에 맞춰진다(하니스가 «20줄로 자른 기록» 으로 잼) |
| 칸마다 후보 2개 | 최근 시작 말 3개를 피하면 다 지워져 「다르게 시작해」 줄과 부딪힘(하니스 ⑧이 실제로 잡음 — 「Sure!」·「I see.」) → 4개 |
| 초급에는 By the way·Anyway 금지 유지 | 사장님 요청 표현이고, 초급도 «통째로 외우는 표현» 이라 쉽다. 대신 검사가 그 모양을 깨졌다고 보지 않게 맞춤 |

## 6. 남은 것 / 주의할 것

- **실제 모델(Llama 3.3 70B)이 지시를 얼마나 따르는지는 못 쟀습니다.** 배포 뒤 AI 친구 기록으로 잴 수 있습니다(SELECT 만):
  ```sql
  SELECT substr(content,1,24) AS head, COUNT(*) FROM ai_friend_chats
  WHERE role='assistant' AND created_at > (strftime('%s','now')-86400)*1000
  GROUP BY head ORDER BY 2 DESC LIMIT 40;
  ```
  웜업 기록은 KV 30분이라 표본이 남지 않습니다 — 화면에서 직접 대화해 보세요.
- 엘리더잼 L1 처럼 «이번 턴 연결어» 를 따로 정하는 지시가 있는 대화에서, 「모르겠어요」 칸의 Anyway·「그 밖」 칸의 By the way 가 겹칠 수 있습니다(연결어 규칙의 «턴별로 정한 연결어가 우선» 문장이 받습니다).
- 소리형은 고정 규칙에 «쓰지 마» 로만 남아 있습니다 — 다시 넣으려면 사람이 정할 일(음성 엔진 청취 필요).
