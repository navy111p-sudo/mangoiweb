# 날짜를 정해 연기·변경한 수업을 «↩ 원래대로» 되돌리기

- 날짜: 2026-11-04
- 작업자: Claude Code (요청: 사장님 계정 — 매니저 Mai 제보 전달)

## 1. 왜 했나

- 제보(영문, 관리자 «오늘 수업» 스크린샷): «At manager's page, I postpone the class but there's no restore or undo postponement option sir»
  - 화면: 2026-11-04 20:00 Jung Seo Yoon(HT NESS) 줄이 «⏸ Moved to another day» · «⏸ Postponed → 11/11 20:00 — no class this day» · Maimai (Head Office Manager) 11/04 18:03 — 버튼 칸은 «—».
- 원인(코드):
  - 그 줄은 같은 날 들어간 **«원래 날짜 줄»(moved_away)** — DB 에 없는 «읽을 때 만든» 줄이라 버튼을 일부러 하나도 안 줬다(`manager.html` `if (r.cancelled || r.moved_away) resch = ''`, `adm-today-classes.js` «버튼 없음»).
  - 기존 «↩ 연기 취소»(`POST /api/admin/class-schedules/:id {action:'restore'}`)는 **날짜 없이 연기**(status='postponed', 같은 날짜)한 줄 전용이다. 날짜를 정해 옮긴 행은 새 날짜에서 다시 active 라 그 경로가 `not_cancelled` 로 받지 않는다(⛔ CLAUDE.md «Postponed restore vs permanent time change» — 그 status 검사를 풀지 말 것).
  - ⟹ 날짜를 정해 연기한 수업은 «새 날짜 줄에서 다시 원래 날짜·시각을 골라 옮기는» 길밖에 없었고, 화면은 그 사실을 말하지 않았다.
- 사장님 지시: «응»(근본 해결안 — 그 줄에 «↩ 원래대로» 버튼, 지난 시각·겹침은 거절).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **기존 `restore` 의 status 검사를 풀어 옮긴 행에도 쓰기** — 규칙서가 막는다(«Do not remove status checks or restore an active moved target»). `restore` 는 «그 자리 그대로 status 만 active» 라 옮긴 행(이미 active)에는 뜻이 없고, 검사를 풀면 끌어 옮긴 수업이 «되살리기» 로 엉뚱하게 지나간다. ⟹ **별도 action**(`undo_move`) 으로 «원래 날짜·시각으로 다시 옮기기».
- **화면이 원래 날짜·시각을 보내 일반 이동(PATCH)으로 되돌리기** — 세 가지가 틀어진다: ① 화면 값을 믿는다 ② 기록이 `reschedule` 로 남아 **새 날짜(11/11)에 «📅 앞당김 → 11/04» 유령 줄**이 생기고, 원래 날짜 줄엔 «📅 11/11 에서 옮김» 이 붙는다(되돌렸는데 «옮겼다» 고 말함) ③ 일반 이동은 같은 강사의 같은 자리(그룹)에 끼워 넣기를 허용한다. ⟹ 서버가 기록에서 원래 자리를 찾고, 기록은 `restore`(정본 `loadMovedAwayEvents`·`judgeClassChange` 가 안 읽는 종류).
- **원래 행을 되살리거나 새 행 만들기** — PR #1889(같은 id 가 옮겨 다닌다 — 학생 입장·결석 감지·급여의 전제) 위반.
- **매주 반복 «그 주 하루만» 을 «하루짜리 줄 지우기 + 반복 행 skip_dates 에서 그 날 빼기» 로** — 두 행을 고치는 비원자 작업이고 recurring-one-week 정본 흐름을 거스른다. ⟹ 하루짜리 줄을 원래 날짜·시각으로 **옮기기만**(날짜 없이 연기한 기록 줄과 같은 모양 — 반복 행은 skip 그대로, 그 날은 하루짜리 줄이 진짜 수업).
- **강사도 되돌리기** — 기록에 «원래 강사» 가 없다(지어내지 않음). ⟹ 날짜·시각만, 확인창이 «담당 강사는 지금 그대로» 라고 말한다.
- **지사·대리점에도 열기** — «연기 취소» 와 같은 선(본사 전용)을 지켰다. 지사 화면(`branch.html`)은 안 건드렸다(버튼을 주면 403 이 나는 «눌러도 거절되는 버튼» 이 된다).
- **«누르면 거절되는 버튼»** — 원래 시각이 지났거나 새 자리가 이미 시작한 줄은 버튼 대신 사유를 글자로(폰엔 hover 가 없다). 판정은 버튼과 API 가 **같은 함수**(`judgeMovedAwayUndo`).

## 5. 남은 것 · 알고 둔 한계

- **원래 시각이 지나면 되돌릴 수 없다**(연기 취소와 같은 선 — 지난 시각에 «예정» 수업을 만들면 결석 감지·급여가 엉킨다). 스크린샷 줄(11/04 20:00)은 20:00 전에만 버튼이 뜨고, 그 뒤엔 «원래 시각이 지나 되돌릴 수 없음» 글자가 뜬다 → 새 날짜 수업에서 다른 날짜로 다시 잡는다.
- **되돌려도 학생·강사에게 알림은 안 간다** — 연기 때 안내가 나갔다면 «원래대로 한다» 는 사람이 따로 알려야 한다.
- 옮기면서 강사도 바꿨다면 강사는 바뀐 그대로.
- 지사·대리점 계정에는 버튼이 없다(본사 전용).
- 기록의 근거가 둘 다 없는 옛 이동은 원래 날짜 줄 자체가 없으므로 해당 없음(지어내지 않음).
