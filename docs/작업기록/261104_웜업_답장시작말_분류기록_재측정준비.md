# 웜업 답장 «시작 말 종류» 기록 — 내일 재측정 준비 (2026-11-04)

## 1. 왜 했나

사장님 「웜업 쪽도 내일 같이 재봐줘」.

- AI 영어친구는 대화가 D1 `ai_friend_chats` 에 남아, «첫마디 지시가 실린 턴에 실제로 첫마디로 시작했나 · 틀린 문장에 칭찬이 남았나» 를 셀 수 있습니다.
- 웜업(A.i 말하기 — 교재로 연습·상황별 말하기)은 대화를 **KV 에만 6시간** 두고 D1 에는 일부러 안 남깁니다(미성년자 대화 — `warmup-fix-trace.ts` 머리말 «⛔ 학생 발화·교정 문장·AI 답장은 싣지 않는다»). KV 값을 읽을 도구도 없습니다.
- ⟹ 이대로는 내일 웜업을 **원리상 못 잽니다.** 그래서 오늘 «분류만» 남기는 기록을 먼저 넣었습니다.

## 2. 무엇을 바꿨나

| 파일 | 바꾼 것 |
|---|---|
| `src/warmup-reply-start.ts` (새 파일) | 최종 답장의 «맨 앞» 만 보고 종류를 정하는 순수 함수 `replyStartOf` · 이번 턴이 첫마디 턴인가 `openerTurnState`. 칭찬 판정은 칭찬 떼기 정본(`stripCheerLead`), 첫마디 판정은 서버가 쉬는 턴을 정할 때와 같은 정본(`isTurnOpener`·`turnOpenerLine`) |
| `src/warmup-fix-trace.ts` | 이미 턴마다 한 줄 쓰는 «교정 판정 사유» 표에 네 칸(`opener_turn`·`start_kind`·`start_word`·`grade`). **쓰기 횟수는 그대로 한 번** |
| `src/index.ts` (공동 금지구역) | 기록 호출을 «교정 앞머리를 붙인 뒤» 로 옮기고 네 칸을 넘김(학생이 들은 «최종» 답장을 센다) |

칸의 뜻:

- `opener_turn`
  - `on` = 첫마디 줄이 실린 턴
  - `rest` = 앞 답이 첫마디라 쉬는 턴
  - `first` = 세션 첫 답
  - `off` = 중국어(엘리더잼 예시형도 조건상 off 지만, 그 경로는 DB 없는 환경으로 돌아 기록 자체가 안 남습니다)
- `start_kind`
  - `fix` = 교정 앞머리(«You can say…»·«Let's say it like this»)
  - `praise` = 칭찬 상투구
  - `opener` = 첫마디
  - `other` = 그 밖
- `start_word`: 그 시작 말을 **우리 목록의 말로만** 남깁니다. 목록 밖이면 빈 값이고, «Oh, Minsu!» 처럼 이름이 섞이면 «Oh» 만 남깁니다.
- `grade`: 정직한 칭찬 등급(perfect·partial·incomplete).

## 3. 버린 방법

- **답장 원문(앞 40자)을 그대로 저장** — 쉽지만 아이 이름·내용이 섞입니다. 이 표의 «답장은 싣지 않는다» 원칙을 깹니다.
- **학생 발화까지 저장해 «틀린 문장인가» 를 사람이 판단** — 같은 이유로 버렸습니다. 대신 **서버 자신의 판정**(`grade`가 perfect 가 아님)으로 «틀린 줄 알면서 칭찬이 남았나» 를 잽니다.
  - ⚠️ 서버가 틀린 줄 몰랐던 문장은 이 방법으로 원리상 못 잡습니다.
- **새 표를 따로 만들기** — 쓰기가 한 번 더 붙습니다(속도). 기존 한 줄에 칸을 더했습니다.
- **배포 직후 ALTER 4개를 매번 미리 보내기** — 차가운 워커마다 왕복이 4번 늡니다. 평소엔 새 칸으로 바로 넣고, «칸 없음» 오류가 날 때만 한 번 ALTER 합니다. 끝내 안 되면 옛 일곱 칸으로라도 남겨 판정 사유 기록이 죽지 않게 했습니다.

## 4. 검사가 잡은 것

- 첫 판은 첫마디 후보를 «앞 두 낱말 열쇠» 로 찾았습니다. 그런데 «Oh, fun!» 의 열쇠가 그냥 `oh` 라, «Oh, Minsu! …» 가 «Oh, fun!» 으로 잘못 남았습니다.
- 지금은 후보를 **글자 그대로** 먼저 맞추고, 열쇠 `oh` 는 표에서 뺐습니다.

## 4-1. 함정 대조가 잡은 것(병합 전 반영)

- **재시도가 한 번 흔들리면 그 워커가 몇 시간 네 칸을 버림** — 칸을 붙인 뒤 다시 넣기가 네트워크·과부하로 한 번 실패해도 «이 인스턴스는 옛 칸만» 으로 굳고 경고도 0줄이었습니다(가짜 D1 로 실측). 지금은 «또 칸 없음» 일 때만 굳히고, 일시 실패면 다음 턴에 다시 시도합니다. 그 턴은 옛 칸으로 «또» 쓰지 않습니다(다시 넣기가 실은 들어갔는데 응답만 끊긴 경우 한 턴이 두 줄이 되는 것을 막음). 옛 칸으로 내려갈 때는 경고 한 줄을 남깁니다.
- **하니스가 ALTER 를 진짜 SQLite 에 한 번도 안 돌림** — 가짜 D1 은 무효한 ALTER 도 받아 줘서 «DEFAULT 를 뺀 ALTER»(진짜 SQLite 에선 실패) 변이가 통과했습니다. 지금은 `node:sqlite` 로 운영과 같은 옛 표(일곱 칸)를 만들어 ALTER·다시 넣기·옛 줄 보존·일부 칸이 먼저 붙은 경우를 실제로 돌립니다.
- **«By the river,» 를 «By the way,» 로 셈** — 분류 잡음(개인정보 문제는 아님). 고쳤습니다.

## 6. 내일 재는 법 (SELECT 만)

```sql
-- 첫마디 턴에 실제로 무엇으로 시작했나(영어)
SELECT opener_turn, start_kind, COUNT(*) n
FROM warmup_fix_trace
WHERE created_at >= <배포 ms> AND lang = 'en'
GROUP BY 1, 2 ORDER BY 1, 3 DESC;

-- 많이 쓴 시작 말
SELECT start_kind, start_word, COUNT(*) n
FROM warmup_fix_trace
WHERE created_at >= <배포 ms> AND lang = 'en' AND opener_turn = 'on'
GROUP BY 1, 2 ORDER BY 3 DESC LIMIT 15;

-- 🔴 서버가 틀린 줄 아는데 칭찬으로 시작한 턴 = 칭찬 떼기 실패
SELECT created_at, user_id, mode, grade, reason, start_word
FROM warmup_fix_trace
WHERE created_at >= <배포 ms> AND lang = 'en' AND start_kind = 'praise'
  AND (grade IN ('partial', 'incomplete') OR reason IN ('shown', 'held_gap', 'mode_hidden'));
```

⚠️ 배포 전 기록은 네 칸이 빈 값입니다 — 기준선은 없습니다. 내일 숫자는 «배포 뒤» 만입니다.

### 읽을 때 주의(함정 대조)

- **«첫마디 준수율» 분모에서 교정 턴을 빼세요.** 기본 모드가 집중교정이라, 검증된 교정이 있는 턴은 답장이 «You can say…» 로 통째로 바뀝니다 — 모델이 첫마디를 썼든 안 썼든 `start_kind='fix'` 입니다(`opener_turn='on' AND start_kind <> 'fix'` 만 분모).
- **`on` 턴의 `praise` 를 전부 «안 따름» 으로 세지 마세요.** 첫마디 줄에는 «잘 해냈을 때» 칸(Great job!·Nice sentence!·You got it!·Well done!·Perfect!)이 있어, `grade='perfect'` 인 턴의 그 말은 지시를 «따른» 것입니다.
- **`grade='partial'` = «서버가 틀린 줄 앎» 이 아닙니다** — 등급 계산 예외·영어 3낱말 미만 답도 partial 입니다. 다만 칭찬 떼기는 perfect 가 아니면 늘 떼므로, 위 🔴 SQL(칭찬 떼기 실패)의 뜻은 맞습니다.
- **네 칸이 다 빈 영어 행이 있는지** 함께 세세요 — 있으면 그 시간 그 워커가 옛 칸으로 내려간 것입니다(Workers 로그 `extra columns unavailable`):

```sql
SELECT COUNT(*) FROM warmup_fix_trace
WHERE created_at >= <배포 ms> AND lang = 'en' AND opener_turn = '';
```

⚠️ 이 표에는 보관기간·정리 코드가 없습니다(원래부터). 이제 user_id 와 함께 턴별 `grade` 가 쌓입니다 — 정리 기준은 사람이 정할 일입니다.
