## 2. 무엇이 차례로 기다리고 있었나 (코드를 읽은 것)

`handleWarmupChat` 이 모델을 부르기 전에 아래를 **하나씩** 기다렸습니다. 첫 턴(첫 인사)은 캐시가 비어 있어 전부 실제로 돕니다.

1. 세션 기록(D1 쓰기) · 첫마디 표시
2. 오늘 교재 문맥(KV → 없으면 D1 명부 1 + 복습퀴즈 최대 3, 그것도 «차례로») + Neo4j 자주 틀린 문장(외부 HTTP)
3. 최근 교정(본인 확인 → KV → D1)
4. 약점 낱말(본인 확인 → KV → D1)

`/api/warmup/context`(첫 화면) 도 교재 조회 → 세션 기록 → Neo4j → 언어 힌트를 차례로 기다렸습니다.

## 3. 바꾼 것 (`src/index.ts` 만)

| 자리 | 어떻게 |
|---|---|
| `handleWarmupChat` | 2·3·4 를 **세션 기록보다 먼저 동시에 시작**(`_preLesson`·`_preMistake`·`_preWeakWord`). 각 블록 본문은 **글자 그대로** 두고 자기 문자열에만 쓰게 감쌌고, 원래 자리에서 **같은 순서**로 `sys` 에 붙입니다 → 프롬프트는 한 글자도 안 바뀜. 던지면 빈 문자열(그 줄만 안 붙음). |
| `warmupLessonContext` | 복습퀴즈 질의 최대 3개를 `Promise.all` 로 동시에. 결과를 쓰는 순서·«4개면 멈춤» 은 그대로. 질의마다 catch 라 하나가 죽어도 나머지는 씁니다(예전엔 그 자리에서 전부 멈춤 — 더 나아진 방향). |
| `handleWarmupContext` | 언어 힌트 조회를 교재 조회와 동시에 시작 · 세션 기록과 Neo4j 조회를 겹침(응답 전에 둘 다 기다림). |

## 4. 검토했다가 버린 것

- **블록 본문을 고쳐 «결과만 돌려주는» 함수로 빼기** — `vocab_weak_reuse`·`recent_mistakes_reuse` 하니스가 그 블록 «글자» 를 오려 내 실행합니다. 감싸기만 하면 그 검사들이 그대로 돌아 보호가 유지됩니다.
- **본인 확인(`vocabWeakCallerVerified`)을 한 번만 계산** — 두 블록이 각각 부르는 «글자» 를 하니스가 못 박아 둡니다. 지금은 두 호출이 동시에 돌아 시간 손해가 없어 그대로 뒀습니다.
- **`resolveWarmupHonest` 도 미리 시작** — `const honest = await resolveWarmupHonest(` 글자를 하니스가 봅니다. 세션당 KV 캐시라 첫 턴에만 D1 한 번 — 이번엔 안 건드림.
- **`ctx.waitUntil` 로 세션 기록을 응답 뒤로** — 이 핸들러는 `ctx` 를 받지 않아 시그니처가 바뀝니다. «동시에» 로 충분.

## 5. 확인한 것

- 새 하니스 `warmup_server_parallel_harness` 36종 — 미리 시작하는 위치·붙이는 순서를 보고, 감싸는 틀을 **실제로 돌려** «세 조회가 기록보다 먼저 시작 · 붙인 순서는 완료 순서와 무관하게 예전 그대로 · 걸린 시간 ≈ 가장 긴 하나» 를 짝으로 잼. `warmupLessonContext` 는 가짜 D1 로 **실제로 돌려** 순차판과 같은 답인지·동시에 나갔는지 확인.
- 변이 6종 전부 실제 FAIL(질의 순차로 · 블록 차례로 기다리기 · 붙이는 순서 바꾸기 · 힌트 미리 시작 제거 · 기록 기다리기 제거 · 실패 시 멈춤). 옛 코드로 돌리면 28건 FAIL.
- 이 블록들을 실행하는 기존 하니스(`vocab_weak_reuse`·`recent_mistakes_reuse`·`warmup_honest_mode`·`warmup_shop_mode`·`english_only`·`conversation_connectors`) 통과. tsc 오류 수 `origin/main` 과 같음(181 = 181, 전부 Cloudflare 타입 미설치 사유).
- ⚠️ **실제로 몇 ms 줄었는지는 못 쟀습니다** — 이 환경에서 운영 D1·Neo4j·mangoi.ai 에 닿지 않습니다. 첫 인사가 빨라졌는지는 사람이 폰에서 확인해야 합니다.
