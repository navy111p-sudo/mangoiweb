# 참관자 귓속말 — 강사가 «놓칠 수 없는» 알림 카드 + 강사 답장·읽음

- 날짜: 2026-11-04 (KST)
- 작업자: Claude Code (사장님 승인 — 1+2단계, 공동 금지구역 `index.html`·`video-call-room.ts` 포함)
- 브랜치 / PR: `observer-whisper-alert-reply`

## 1. 왜 했나

필리핀 매니저 제보(Sir L·Belle 선생님 수업 관찰 중):

> I sent her a message, but she didn't notice it. Would it be possible to add a notification feature
> similar to BODA? Whenever we send a message to a teacher, a notification will pop up so they can see it
> and respond immediately.

스크린샷: 참관 화면에서 «🔒 Teacher mangoi_172» 칩을 골라 「Hello teacher」를 보냈고,
채팅창에 「📢 Sent to teacher mangoi_172 only. — "Hello teacher"」가 남아 있었다.

### 잰 것
- 그 문구는 서버가 **delivered=1** 로 회신할 때만 나온다(`idx-whisper.js` 의 `ack()`).
  ⟹ «안 간» 것이 아니라 **«갔는데 강사가 못 본»** 것이다.
- 강사 화면 표시(바꾸기 전): 오른쪽 위 **구석**, 수업 화면과 거의 같은 **남색**(`rgba(28,38,54,.97)`),
  **소리 없음**, **8초 뒤 스스로 사라짐**, 새 메시지가 오면 **앞의 것을 지움**.
- 강사가 **답할 길이 없었다** — 참관자는 «유령»(`joined:false`)이라 1:1 채팅은
  `handleChatMessage` 의 `usernameOf()` 게이트에서 「상대방이 방에 없어 전달하지 못했어요」로 끝나고,
  방 채팅으로 답하면 학생 전원이 본다.

## 2. 무엇을 바꿨나

### 서버 — `cloudflare-deploy/src/video-call-room.ts` (공동 금지구역, 사장님 승인)
- `VcAttachment.ghost` 신설 — `handleJoinObserve` 가 **참관 서명 토큰(`verifyGhostObserveSig`)을 통과한 뒤에만** `true`.
  (`role` 은 클라이언트가 `join-room` 에 실어 보내는 값이라 학생도 `'observer'` 를 적을 수 있다 — 그래서 따로 표시.)
- `handleObserverWhisper` 가 강사(staff)에게 갈 때 **`fromId`(참관자 번호)** 를 싣는다. 학생에게 갈 때는 빈 값
  (학생은 참관자의 존재도 모르는 «투명 유령» 설계). 서명 토큰 없는 «참관자 흉내» 소켓도 빈 값.
- 새 메시지 타입 **`observer-whisper-reply`** → `handleObserverWhisperReply`:
  - 보내는 쪽: **수업에 들어온(joined) staff** 만.
  - 받는 쪽: **진짜 참관자(ghost) 소켓 하나** 만 — 번호로 찾고, 재접속으로 번호가 바뀌었으면 **이름 완전일치 + 후보 정확히 하나**일 때만.
  - `message` 가 있으면 답장(`kind:'reply'`), 없고 `read:true` 면 읽음(`kind:'read'`).
  - 강사에게 `admin-whisper-ack`(`kind:'reply-ack'`, `delivered` 0/1)로 정직하게 회신. 읽음은 회신 없음.
  - 받는 쪽 메시지 타입은 일부러 **기존 `admin-whisper`** — `idx-main.js`(첫 화면 blocking 예산) 분기를 안 건드리고,
    캐시에 남은 옛 참관 화면도 «귓속말 상자» 로 그대로 보여 준다.

### 화면 — `cloudflare-deploy/public/js/idx-whisper.js` (defer) · `index.html` 은 `?v=3 → 4` 한 글자만
- 강사·직원에게 온 귓속말 → **화면 위쪽 가운데 밝은 카드**(`#vc-whisper-alert`), **「확인」 전까지 남음**.
  - 짧은 «딩–동» (공용 `vcGetSharedAC` — 화면을 누를 때 이미 풀려 있는 AudioContext).
  - 다른 탭·창이면 탭 제목 깜빡임 + 알림 권한이 있으면 브라우저 알림. 권한은 카드의 「🔔」 버튼을 **사람이 눌렀을 때만** 묻는다.
  - 받은 글을 채팅창에 한 줄(내 화면에만).
  - **빠른 답장 3개**(👍 OK · ✅ Got it · ⏳ One moment / 👍 네 · ✅ 확인했습니다 · ⏳ 잠시만요) + 직접 입력·보내기.
    한글 조합 중 Enter 는 보내지 않는다. 못 보내면 카드·쓰던 글을 남기고 이유를 말한다.
  - 「확인」·답장 → 참관자에게 **읽음**.
  - 여러 건이면 «새 메시지 N개 · 앞의 것은 채팅창에». 쓰는 도중 **같은 참관자**의 새 글이 오면 쓰던 답장을 이어 받는다
    (다른 참관자면 옮기지 않는다 — A 에게 쓰던 답이 B 에게 가면 안 된다).
  - z-index **2147483646** — 강사 입장 때 «화면 전체» 로 자동으로 뜨는 사용법 안내 창(`#vc-guide-ov`, 2147483001)보다 위.
- 참관자 화면 → 강사 답장은 **초록 카드** + 채팅창 한 줄, 읽음은 「✓ … 님이 메시지를 확인했습니다」 한 줄.
- **학생 화면은 바꾸지 않았다** — 학생에게 콕 집어 온 귓속말은 예전 작은 상자(14초) 그대로.
- 모든 문구 EN/KO.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

| 버린 방법 | 이유 |
|---|---|
| `idx-main.js` 에 새 메시지 타입 분기 추가 | 849KB blocking 파일 — 첫 화면 예산. 기존 `admin-whisper` 타입에 `kind` 를 실어 해결 |
| 참관자를 `joined:true` 로 바꿔 일반 1:1 채팅으로 답하게 | 참관자가 인원수·입퇴장·참가자 목록에 드러난다(«투명 유령» 설계 파기) |
| 방 채팅으로 답하게 안내 | 학생 전원이 본다 |
| 답장 대상 판정을 `role === 'observer'` 로 | `role` 은 클라이언트 신고값 — 학생이 `observer` 를 적고 들어와 답장을 받아 갈 수 있다 → 서명 토큰 뒤에만 붙는 `ghost` |
| 번호를 못 찾으면 «방의 참관자 전원» 에게 | 오배달. 이름 완전일치 + 후보 하나일 때만, 아니면 `delivered:0` |
| 카드를 8초·60초 뒤 자동으로 닫기 | 그것이 바로 「못 봤다」의 원인. 「확인」이 있어 덮어도 닫을 수 있다 |
| 학생 화면에도 큰 카드·소리 | 요청 범위 밖. 수업 중 학생 화면에 소리가 나는 것은 사람이 정할 일 |
| 수업 중 브라우저 알림 권한을 자동으로 묻기 | 수업 중 갑자기 권한 창이 뜬다 — 버튼으로만 |
| 입력칸 자동 포커스 | 강사가 다른 칸에 치던 글이 카드로 새어 들어간다 |
| 카드 z-index 를 안내 창과 같은 값(2147483001)으로 | **실측으로 잡음** — 나중에 열린 안내 창이 카드를 덮고 클릭을 가로챘다(브라우저 검사가 TimeoutError) |

## 4. 확인한 방법

- **타입체크**: `node_modules` 가 없는 컨테이너라 `/opt/node22/bin/tsc` + 임시 tsconfig(`types: []`)로 돌리고
  `origin/main` worktree 와 줄 단위 대조 → **새 오류 0건**(양쪽 모두 180줄, 전부 `@cloudflare/workers-types` 부재).
- **회귀** `node test-harness/run.mjs --fast`: 브랜치 PASS 635 · main 사본 PASS 634, **「실제 확인 필요」 목록 35개가 양쪽 똑같음**
  (`comm` 대조 — 브랜치에서만 생긴 실패 0건). 그 35개는 `esbuild`·`typescript` 패키지 부재(환경 사유, 두 개 직접 확인).
- **신설 하니스** 71/0. **변이시험 22종 전부 실제 FAIL** — 서버 10종(joined·staff 게이트 제거, ghost 확인 제거, **ghost 조건 뒤집기**,
  이름 후보 ≥1, 학생에게 fromId, 가짜 참관자에게 fromId, switch 배선 제거, 읽음 회신 생략 제거, **방 전체로 답장**)
  · 화면 12종(강사 카드 8초 자동 닫힘, 옛 상자로 되돌림, 소리 제거, 역할 게이트 제거, 답장 대상 비움, 확인 때 읽음 안 보냄,
  조합 중 Enter 허용, 다른 참관자에게 초안 이월, 실패해도 닫기, 답장 분기 제거, 받는 사람 확인 제거, **학생에게 카드로 조건 뒤집기**).
  되돌리기는 `git checkout` 이 아니라 `cp` 사본으로.
- **브라우저**(로컬 `python3 -m http.server` + 컨테이너 Chromium, 진짜 `index.html` 수업 화면): 25/0.
  z-index 를 옛 값으로 되돌리면 「안내 창이 열려 있어도 맨 위」가 **실제로 FAIL**(맨 위: `vg-img`).
  기존 `observer-whisper-browser.mjs` 22/0(학생 화면·참관 이름표 회귀 없음).

## 5. 남은 것 / 주의할 것

- ❌ **배포된 실제 화면은 아직 아무도 안 봤다** — 이 작업 환경은 프록시가 `mangoi.ai` 를 막는다.
  오늘 밤 매니저가 Len·Kim 선생님 수업을 관찰할 때 «카드가 뜨는가 · 소리 · 답장 · ✓읽음» 을 사람이 확인해야 끝이다.
- ⚠️ **캐시**: 강사·참관자 브라우저가 옛 `idx-whisper.js?v=3` 를 들고 있으면 새로고침 전까지 예전 모양이다
  (`?v=4` 로 올렸으므로 새로 연 페이지는 새 파일을 받는다). 옛 참관 화면이 답장을 받으면 «귓속말 상자» 로 보인다(무해).
- ⚠️ 알림음이 강사 마이크로 들어가 학생에게 작게 들릴 수 있다(브라우저 반향 제거가 대부분 지우지만 보장은 없다).
- ⚠️ 브라우저 알림은 강사가 카드의 「🔔」 버튼으로 권한을 준 기기에서만, 그리고 **탭이 열려 있을 때만** 뜬다(웹푸시 아님).
- ℹ️ 보내는 쪽 «staff» 판정은 여전히 클라이언트 신고 `role` 이다(`isStaffAtt` — 기존과 같은 전제). 학생이 `teacher` 로 신고하면
  참관자에게 답장을 보낼 수 있다. 다만 받을 대상(`fromId`)은 강사에게 온 귓속말에만 실리고, 받는 쪽은 진짜 참관자(직원)뿐이다.
- 관리자 «수업 관찰» 화면(방 밖, `/api/admin/whisper/send`)에서 온 귓속말은 답장 대상이 없어 **카드에 「확인」만** 있다.
