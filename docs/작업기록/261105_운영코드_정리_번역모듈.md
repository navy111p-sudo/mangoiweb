## 이번 변경

- `api-mango.ts`의 연속된 번역 블록 470줄을 `api-translate.ts`로 이동했다.
- `/api/i18n/translate`와 `/api/translate`의 원래 순서와 POST 조건을 유지한다. 기존 위치에서 새 핸들러를 호출하고 `request`, `url`, `env`, `ctx`를 그대로 전달한다.
- 프롬프트, 모델명, 캐시 키·TTL, 재시도·시간 상한, 동시성 4개, note의 실명 가림, learn_report의 저장·상한 정책은 바꾸지 않았다.
- 새 모듈은 `MangoEnv`를 **타입으로만** 참조한다. 런타임 순환 import를 추가하지 않는다. 예외는 기존 `handleMangoApi`의 500 응답 경계가 처리한다.
- 기존 하니스 5개의 번역 소스 조회 경로만 새 위치로 바꿨다. 실행 검사·변이 검사와 단언은 유지했다.
- `translate_module_harness.mjs`는 실제 통합 핸들러를 번들링하고 Request로 실행한다. AI·KV·DB는 모형이며 외부 fetch는 차단한다. 실서비스 D1·AI·KV를 호출하지 않는다.

## 검토하고 택하지 않은 방법

전체 소스의 일괄 포맷, 전역 치환, 라우팅 테이블 전면 교체는 동작 변경과 이동을 구분하기 어렵게 하고 공동 유지보수 충돌을 키워 택하지 않았다. 별도 승인 없이 레거시 폴더·도메인·DO·서비스워커·운영 데이터·SMS 정책을 정리 대상으로 삼지 않았다.

번역을 분리하면서 프롬프트나 캐시 정책까지 개선하는 것도 택하지 않았다. 먼저 이동만 수행하고 같은 코드인지 대조해야 기존 응답과 회귀 검사의 의미를 유지할 수 있다.
