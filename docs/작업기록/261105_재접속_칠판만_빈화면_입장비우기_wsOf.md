# 재접속하면 칠판만 텅 빈 화면 — 입장 때 칠판 비우기를 «즉시» 로 · 서버 wsOf 열린 소켓 우선 (2026-11-05)

- 날짜: 2026-11-05 KST (제보 2026-11-04 사내 시험)
- 작업자: Claude Code (사장님 요청 — 「문제 확실하게 확인하고 해결, 하니스·샌드박스로 수백 번 시험 후 승인·병합·배포」)
- 브랜치 / PR: `wb-rejoin-blank-fix-261105`

## 1. 왜 했나

사내 시험 보고 2번(영문):

> 교재를 올리고 밑줄을 긋고 칠판에 메모를 적었다. Sir Karl 이 약 20초 끊긴 것처럼 했다가 다시 들어오니
> **교재는 그대로 보이는데 칠판이 완전히 비어 있었다.** 내 화면에는 칠판 내용이 그대로 있었다.
> 기대: 재접속 뒤에도 칠판이 교재처럼 강사·학생 양쪽에 남아 있어야 한다.

같은 날(11/4) PR #2037(Kaye 제보)이 «서버가 칠판을 hibernation 너머까지 저장하고 재입장자에게 `whiteboard-replay` 로 돌려준다» 를 넣었다(05:35 UTC 병합·배포). 그런데도 칠판이 비었다 = **서버가 돌려준 것을 화면이 지우거나, 서버가 엉뚱한 소켓으로 보내는** 구멍이 남아 있었다.

## 2. 뿌리 — 둘. 둘 다 «칠판만 비고 교재는 남는» 같은 모양

### Ⓐ 화면 — 입장 350ms 뒤의 «지난 수업 칠판 비우기» 가 지금 수업 복원본까지 지웠다 (확정 · 재현함)

- `js/idx-vc-textbook.js` 의 입장 처리(`onEnterCall`)는 `body.vc-in-call` 이 붙고 **350ms 뒤** 돈다. 그 안에서 2026-08-08 부터 `wbReceiveClear()` 로 «지난 수업 칠판» 을 비웠다.
- 그 사이 서버 복원본(`whiteboard-replay`)이 먼저 도착하면 → 기록에 넣고 그린 뒤 → 350ms 째에 통째로 지워졌다.
- 지금 입장 흐름은 카메라 권한·TURN 을 미리 잡아 두어 `vc-in-call` 직후 곧바로 소켓을 연다(샌드박스 실측: 입장→join-room 약 100~300ms). 그래서 **회선이 좋을수록** 복원본이 350ms 안에 온다.
- 교재는 `pdf-sync` + HTTP 폴링(`vcStartPdfPoll`)으로 다시 채워지고, 이 비우기가 교재 화면은 안 지우므로 «교재는 남고 칠판만 빈» 모양이 된다. 덤으로 같은 350ms 에 `vcSwitchTab('pdf')` 가 학생을 교재 탭으로 끌어온다.
- **새로고침 경로도 같다** — 새로고침하면 페이지가 sessionStorage 기록으로 스스로 재입장(`vc-refresh-stay-in-class` → `mangoiJoinClass`)하고, 그 입장도 같은 350ms 비우기를 탄다(샌드박스로 확인).

### Ⓑ 서버 — 20초 순단 유예로 돌아오면 입장 응답이 닫힌 옛 소켓으로 갈 수 있었다 (방어 · 운영 런타임에서는 못 잼)

- `video-call-room.ts` 의 `wsOf(userId)` 는 그 userId 를 가진 **첫 소켓**을 돌려줬고, `send()` 는 그 소켓이 OPEN 이 아니면 조용히 버린다.
- 서버가 끊김을 «못 본» 채 돌아오면(sticky 경로) 옛 소켓 userId 를 `stale-` 로 바꿔 비켜 둔다 — 그 자리 주석이 «wsOf 가 새 소켓을 가리키게(오배송 방지)» 라고 적어 두었다.
- 그런데 11/4 에 생긴 **순단 유예 경로**(`dropRec`)는 `inherited=true` 를 먼저 세워 그 이름 바꾸기를 건너뛴다. 닫힌/닫히는 옛 소켓이 `getWebSockets()` 에 남아 있으면 `wsOf` 가 그쪽을 먼저 골라 **room-joined·existing-users·whiteboard-replay·pdf-sync 가 새 소켓에 안 간다**(교재는 HTTP 폴링으로 살아남는다).
- 같은 파일 `joinedUsers` 의 «닫히는 중/닫힌 소켓(재연결 좀비 등)은 로스터에서 제외» 주석이 그런 소켓이 목록에 남는다는 전제다. ⚠️ **운영에서 실제로 남는지는 재지 못했다**(Cloudflare 문서도 시점을 말하지 않음). 그래서 «방어» 로 고쳤다.
- ⚠️ 이 경로가 실제로 났다면 영상 재협상도 함께 꼬였을 것이라, 「칠판만」 이라는 제보 모양에는 Ⓐ 가 더 잘 맞는다(추론).

## 4. 검토했다가 버린 방법

- **복원본이 왔으면 350ms 뒤 비우기를 건너뛰기**(타임스탬프 표시) — `idx-main.js`(blocking, 첫 화면 예산)의 복원 처리에 표시를 넣어야 하고, 복원본 «말고» 350ms 안에 오는 실시간 판서(강사가 그 순간 쓴 획)는 여전히 지워진다. 비우는 시점 자체를 «소켓 열기 전» 으로 당기면 둘 다 풀린다.
- **비우기를 아예 없애기** — 2026-08-08 에 넣은 이유(SPA 라 지난 수업 칠판이 다음 수업 첫 화면에 남음)가 그대로 살아 있다. 하니스가 «서버가 아무것도 안 돌려줘도 지난 수업 칠판은 비워진다» 를 짝으로 지킨다.
- **관찰자 콜백 안에서 가드 없이 비우기** — 수업 중 body class 는 계속 바뀐다(가벼운 모드·전체화면 등). 가드 없이 두면 그때마다 지워진다(변이 M2 — 퍼즈 500회 중 458회 실패).
- **서버: 유예 경로에서도 옛 소켓을 `stale-` 로 바꾸기** — 한 번 넣었다가 뺐다. 유예 경로의 옛 소켓은 이미 닫힌 뒤라 갱신이 거절될 수 있고(holdDrop 주석), 열린 채로 남을 수 없어 `wsOf` 수정과 중복이다. 금지구역 변경을 최소로.
- **`vcJoinRoom` 에서 소켓 열기 직전 비우기** — `idx-main.js`(blocking)를 건드려야 한다. 관찰자 콜백이 같은 보장을 준다.
- 교재 쪽 `_vcCurrentPdfUrl` 초기화도 같은 350ms 모양이지만 이번 제보 범위 밖이라 그대로 두었다(남은 것 참고).

## 6. 밟은 함정(규칙서 2장에 옮김)

## 8. 남은 것 / 주의할 것

- **사람 확인 필요**: 배포 뒤 실제 수업에서 ① 강사가 칠판에 쓰고 ② 학생이 새로고침(또는 나갔다 다시 입장) ③ 학생 칠판에 그대로 보이는지. 와이파이를 20초 끊었다 켜는 경우도.
- Ⓑ 는 «닫힌 소켓이 목록에 남는가» 를 운영에서 재지 못한 방어다.
- 교재 쪽 `_vcCurrentPdfUrl` 초기화도 같은 «350ms 뒤» 모양이다 — 교재가 350ms 안에 열리면 그 값이 비워져 `idx-vc-book-history.js`(교재 기록) 판정이 잠깐 어긋날 수 있다(추론, 못 잼). 제보 범위 밖이라 그대로 두었다.
- 재입장 직후 350ms 에 학생 화면이 교재 탭으로 옮겨지는 동작(`vcSwitchTab('pdf')`)은 그대로다 — 강사가 칠판에 있으면 그 뒤 오는 `tab-sync` 가 다시 칠판으로 데려가는지는 순서에 달려 있다(이번 변경과 무관, 예전과 같음).
- 서버가 배포·재시작으로 리셋되면 아직 storage 에 안 쓴 1.5초치 판서는 사라질 수 있다(#2037 설계 그대로).
