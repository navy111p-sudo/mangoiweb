# 매일보고 미작성자 로그인 경고

사장님 요청: 미작성 매니저가 로그인하면 빨간 경고와 경고음을 보게 하고, 계속 작성하지 않으면 1차·2차·3차로 올린다.

- 로그인 횟수가 아니라 마감이 지난 연속 근무일 미제출로 단계를 계산한다. 1일=1차, 2일=2차, 3일 이상=3차. 아직 해결되지 않은 과거 연속 미제출 구간 중 가장 긴 구간을 사용한다. 오늘 제출만으로 과거 미제출을 없애지 않는다.
- 기존 작성 대상 명단·근무 요일·국가 공휴일·개인 제외일을 사용하고 회사 휴무일도 제외한다. 규칙 시작일은 기존 `DUTY_START`(2026-10-06)를 따른다. 명단의 과거 변경 이력은 별도 저장돼 있지 않으므로 현재 명단의 근무 규칙으로 계산한다.
- 받은 보고의 확인 경고와 별도인 `writer.warning`을 인증된 inbox 응답에 추가한다. 초안은 미제출이고 제출 시각이 있는 보고는 이미 낸 것으로 본다. 이력·휴무일 조회 실패 시 단계를 만들어 내지 않는다.
- 관리자·매니저·결재함·매일보고 화면에서 빨간 배너를 유지한다. 경고창과 소리는 계정별 KST 하루 1회(해당 브라우저 오리진 localStorage 기준). 1차는 짧은 경고음, 2차는 긴 경고음, 3차는 약 2.4초의 주파수 변화 사이렌이다. 기존 소리 음소거 설정은 존중한다.
- 브라우저가 자동 재생을 막으면 발진기를 예약하지 않고 첫 클릭/키 입력에서 재시도한다. 그 전에 미제출이 해결되면 소리를 재생하지 않는다. 반복 폴링·새로고침으로 사이렌을 반복하지 않는다.
- 기존 매니저·결재함의 독립 HTML 계약 때문에 공유 스크립트와 인라인 복사본을 함께 갱신했다. 관리자 자산 버전은 v9로 올렸다.

검증: TypeScript 종료 코드 0. 기존 보고 대상 검사 PASS 100/FAIL 0, 로그인 경고음 검사 및 실제 inbox 핸들러 메모리 SQLite 검사 통과. 로컬 Chrome PC·모바일에서 경고창·닫기·배너 유지·같은 날 재접속 제한 및 JS 오류 없음 확인. 전체 회귀 검사와 GitHub 배포 결과는 채팅의 실제 실행 결과로 보고한다.

운영 DB 데이터 수정·운영 테스트 보고서 작성은 하지 않았다. 로컬 전체 폴더 배포 대신 별도 작업 브랜치 PR과 GitHub Actions를 사용한다. 배포된 실제 매니저 계정 화면은 사람이 마지막으로 확인해야 한다.
