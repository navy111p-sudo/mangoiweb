# 2026-11-06 배지·출석 스트릭 API 분리

## 목적과 범위

전체 코드 정리의 후속으로 `api-games.ts`에 남은 배지와 스트릭을 기능별로 분리했다. 진입 파일은 약 545줄에서 28줄로 줄었고 기능별 핸들러 호출·기존 export만 담당한다. 이전 음성·복습퀴즈·단어장 분리에 이어 학습 API 진입점의 책임을 정리하는 단계다.

| 파일 | 책임 |
|---|---|
| `api-games.ts` | 단어장 → 마이크로러닝 → 복습퀴즈 → 배지 → 스트릭 → 음성 순서로 위임, 기존 외부 export 유지 |
| `api-games-badges.ts` | 배지 카탈로그, 자동 검사·지급, 학생·관리자 API 3개 |
| `api-games-streak.ts` | 체크인·보석, 출결 기반 상태·리더보드·관리자 정합화 API 4개 |
| `api-games-attendance-streak.ts` | 출결 연속일 재귀 CTE와 야간·관리자 공용 일괄 정합화 |

배지 지급·보석 보상·KST 날짜·중복 처리·상태 조회의 출결 동기화·리더보드 이름 우선순위를 바꾸지 않았다. `reconcileAllStreaks`·`checkAndAwardBadges`·`BADGE_CATALOG`의 기존 import 경로도 유지하며 실행 함수와 카탈로그는 각각 한 곳이 정본이다. DB·요청·학생 상태를 전역에 저장하지 않는다.

배지와 스트릭을 하나의 큰 파일로 옮기는 방법 대신 각각 API를 나누고, 둘과 야간 cron이 공유하는 출결 계산을 별도로 두었다. 운영상 의미가 다른 기존 체크인 연속일·실제 출결 연속일을 이번에 통합하거나, 기존 출결 계정 매핑 정책을 바꾸지는 않았다. 재귀 CTE의 계정 조건 확대는 기존 하니스에 사람 결정 대기로 남아 있던 별건이며 그 보류도 유지한다.

## 확인한 검증

- 지정된 TypeScript 실행 경로로 `tsc --noEmit` 통과.
- 분리 전후 AST 비교: 기존 라우트 7개·catch 절 14개 동일. 출결 계산·일괄 정합화·배지 카탈로그·테이블 보장·지급 함수 5개 선언도 동일하다(내부 출결 함수의 새 모듈 export 표기만 제외).
- 실제 핸들러 번들+메모리 SQLite 동작 검사 15종 통과. 토큰 소유자, KST 날짜, 체크인 보너스 경계, 하루 중복 보상, 배지 조건·중복 지급, 연속 출결·30일 상한, 보석·최장 기록 보존, 50행 배치·실패 후 계속 진행, 리더보드 이름·순서·20명 상한, 요청별 격리를 확인했다.
- 변이 12종 모두 실제 assertion 실패로 검출: 두 디스패처 연결 누락, 배지 소유자 불일치 허용·중복 지급 보고, 체크인/상태 권한 우회, 당일 중복 보상, 최장 기록·보석 초기화, 배치 실패 중단·크기 확대, 오늘 출결 계정 별칭 누락. 빌드 실패나 단순 크래시는 검출로 세지 않는다.
- 실제 `index.ts`+운영 자산의 격리 workerd 샌드박스 요청 18종 통과. 합성 출결 7일로 배지·스트릭을 계산하고, 재실행 후 배지 3건·보석 거래 1건과 잔액 보존을 로컬 D1 SELECT로 대조했다. 관리자 통계·정합화 무인증 요청은 401이다.
- 샌드박스는 별도 로컬 D1/KV/R2/DO·상태 폴더와 합성 토큰 시크릿만 쓴다. 운영 시크릿·운영 DB 쓰기·유료 AI·실제 알림 발송은 없다.
- 기존 출석 계정 하니스는 이동한 파일을 개별 검사하도록 조정하고 정본 사용 두 곳을 각 파일의 한 곳씩 검사한다. 기존 재귀 CTE의 SQL 지문 예외는 새 출결 모듈로만 옮겼다. ERP 컬럼 감시 대상도 새 모듈까지 유지했다.
- silent-catch 알려진 항목 하나의 파일 키만 옮겼다. 기준선 갱신·검사 제외는 하지 않았다. 기존 스키마 부채·조용한 catch 수는 그대로다.

최종 전체 fast/PR CI, 병합 및 활성 배포 버전은 실제 완료 후 PR에 기록한다. UI·운영 데이터·도메인·cron 구성·DO·SMS·공동 금지구역·레거시는 수정하지 않았다. 사람의 UI 평가·운영 데이터 정합화 실행은 수행하지 않았다. 전체 서비스 코드 정리 완료를 뜻하지 않는다.
