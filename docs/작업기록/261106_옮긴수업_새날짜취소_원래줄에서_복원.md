# 옮긴 수업 — 새 날짜가 그 뒤 취소됐을 때, 원래 날짜 줄에서 바로 «수업 복원»

- 날짜: 2026-11-06 (KST)
- 작업자: Claude (사장님 요청)
- 브랜치 / PR: `undo-cancelled-destination-restore`

## 1. 왜 했나

사장님이 매니저 화면 스크린샷과 함께 다시 요청하셨습니다(«이거 왜 아직도 안되었지?»):

> at managers page, I postpone a class and I want to restore the class or undo postponement but there is no option for that.
> Can we still have undo postponement option even the time has passed already?

화면의 줄: `Jung Seo Yoon · ⏸ Postponed → 11/11 20:00 · later cancelled — no class this day` + `Original time has passed — cannot undo`.

**왜 지난 두 번의 수리(PR #2099 «↩ 원래대로», PR #2109 «과거 기록 정정 / 취소 수업 복원»)로도 안 됐나:**
이 줄은 «원래 시각 지남» + «새 자리(11/11)가 그 뒤 **취소**» 의 조합입니다.

- «↩ 원래대로» 는 원래 시각이 지나면 막힙니다(`orig_passed`).
- «↩ 과거 기록 정정» 은 새 자리가 **살아 있는(active)** 미래 수업일 때만 나옵니다.
- «↩ 취소 수업 복원» 은 **새 날짜(11/11) 목록에만** 있었습니다(PR #2109 문서: «A cancelled destination must be restored at its future date first»).

그래서 매니저가 보고 있는 원래 날짜 줄에는 «되돌릴 수 없음» 글자만 있었고, 11/11 로 가서 복원해야 한다는 것을 알 길이 없었습니다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

1. **원래 시각 검사를 풀어 지난 시각에 «열린 수업» 으로 되돌리기** — PR #2109 가 이미 버린 길. 지난 시각의 active 수업은 결석 감지·노쇼·급여(0원 처리)를 건드립니다. 그대로 버렸습니다.
2. **취소된 새 자리를 한 번에 «과거 기록 정정»(원래 날짜·postponed)으로 보내기** — 취소(cancelled)를 연기(postponed)로 바꾸는 상태 전환이 새로 생기고, PR #2109 문서가 «historical correction will not silently revive it» 로 막아 둔 것과 어긋납니다. 버렸습니다.
3. **새 API(`action:'restore_moved'`) 만들기** — 이미 있는 `action:'restore'` 가 대상 행만 알면 정확히 같은 일을 합니다. 판정(버튼을 줄지)만 서버가 내려주면 되므로 새 경로는 만들지 않았습니다(관문 3곳 등록 함정도 피함).
4. **날짜 없이 다시 연기된(postponed) 새 자리까지 포함** — 그건 «취소» 가 아니라 다른 상태라 `tSt === 'cancelled'` 로만 좁혔습니다(변이 «active 아니면 전부» 가 A9e 에서 잡힘).

## 5. 남은 것 / 주의할 것

- 새 자리 시각까지 이미 지난 «취소» 수업은 여전히 버튼이 없습니다(지난 수업을 열지 않음) — «📅 연기·변경» 으로 새로 잡아야 합니다.
- 매주 반복 수업의 «그 주 하루만» 줄도 같은 버튼이 나옵니다(대상 = 하루짜리 줄). 단 복원 뒤 «과거 기록 정정» 은 매주 반복 행에는 여전히 안 나옵니다(PR #2109 의 의도된 제한).
- **어떤 취소든** 버튼이 뜹니다 — 학생 상세 «🗓️ 종료·연장»(수강 종료)으로 내린 행도 포함. 새 날짜 줄에는 전부터 있던 동작이고 확인창이 «정상 출석·과금 적용» 을 알립니다. 취소 사유로 가를지는 사람이 정할 일.
- 복원 요청은 `{action:'restore'}` 만 보내므로, 목록을 연 뒤 누가 그 행을 «복원 → 다른 날로 이동 → 다시 취소» 했다면 버튼 글자와 다른 자리에서 열릴 수 있습니다(새 날짜 줄의 기존 복원도 같음 — 서버가 시작·겹침·출석은 막음).
- 실제 D1 데이터는 건드리지 않았습니다.
