# 운영 관리자 코드 모듈 정리와 하니스 이식성 (2026-11-06)

## 변경

`api-admin.ts`에 섞여 있던 통계·급여 라우트와 계산·캐시 도구를 역할별로 분리했다. 원래 파일은 17,796줄에서 14,430줄로 줄었다. 운영 동작을 바꾸는 작업과 분리해서 검증할 수 있도록 기존 라우트 본문·SQL·정산 정책은 유지했다.

| 파일 | 책임 |
|---|---|
| `cloudflare-deploy/src/api-admin-stats.ts` | 통계·KPI 라우트 10개 |
| `cloudflare-deploy/src/api-admin-payroll.ts` | 급여 라우트 19개 |
| `cloudflare-deploy/src/admin-lesson-fees.ts` | 요청별 수업료 계산과 관련 초기화 함수 |
| `cloudflare-deploy/src/admin-teacher-core.ts` | 강사 이름 정규화·평가·급여 공용 계산 |
| `cloudflare-deploy/src/admin-cache.ts` | 관리자 응답 캐시 읽기·쓰기 |
| `cloudflare-deploy/src/api-admin.ts` | 기존 관리자 라우팅과 새 도메인 핸들러 위임 |

인증은 기존 `index.ts` 기본 차단 게이트를 그대로 거친다. 급여 안의 강사별 조회 제한·쓰기 차단도 그대로다. `Cafe24TeacherInfo`는 기존 경로에서도 타입을 재수출해 사용처 호환을 유지했다.

## 하니스 정리

- 파일 URL의 `.pathname`을 파일 경로로 쓰던 부분을 `fileURLToPath`로 변경했다. Windows 드라이브 문자와 공백·한글 경로를 보존한다.
- 동적 `import()`·Node `--import`에 파일 경로를 넘기던 부분은 `pathToFileURL(...).href`로 변환했다. esbuild는 해당 하니스에서 JS API로 실행한다.
- `_srcbundle.mjs`의 관리자 소스 읽기는 실제 TypeScript import 구문을 따라간다. 주석의 가짜 import는 따라가지 않고, 모듈 누락은 실패한다.
- 하니스별 복사본 디렉터리·소스 override·변이 입력 경로를 보존했다. 급여 변이 두 건은 실제 코드가 이동한 `admin-lesson-fees.ts`를 고친다.
- `schema-drift-known.json`·`silent-catch-known.json`은 기존 코드의 파일 위치만 재지정했다. 파일별 키라서 기존 같은 결함이 두 모듈에 나뉘면 키 수는 늘지만, 실제 검출 수는 CREATE 434개 중 스키마 불일치 11건, 조용한 쓰기 catch 61건으로 같다. 새 결함을 허용한 것이 아니다.
- `harness_portability_harness.mjs`에 AST 기반 경로 검사와 정상·오류 예제 10개를 추가했다. 실행 하니스와 수동 브라우저 검사 파일 모두 검사한다.
- `admin_module_boundaries_harness.mjs`는 실제 관리자 핸들러를 번들링해 통계 응답, 오류 응답, 급여 조회·강사 차단, 캐시 장애, 미일치 경로, 소스 읽기 경계를 실행한다.

## 검증 근거

1. 리팩토링 전 소스와 AST 대조: 기존 최상위 라우트 248개, 공용 함수 14개, 수업료 계산 클로저 4개의 실행 본문이 정확히 같다. 새 위임 조건은 2개다.
2. 타입체크: `cloudflare-deploy`에서 `node node_modules/typescript/bin/tsc --noEmit` 통과.
3. Windows 경로 수정 직후 전체 기준: `node test-harness/run.mjs --fast --jobs=4` — PASS 686 / FAIL 0 / SKIP 20.
4. 새 모듈 런타임 하니스: PASS 8 / FAIL 0.
5. 변이 검사: 복사본에서 통계 위임 제거, 강사 급여 쓰기 차단 제거, 캐시 쓰기 오류 재던지기 — 3종 모두 실제 실패를 검출했다.
6. 로컬 workerd 샌드박스: 운영과 같은 compatibility date `2026-04-07`, 별도 설정·가짜 D1/KV로 통계·급여 3개 정상 응답과 미일치 경로 2개를 확인했다. 원격 바인딩은 없다.
7. 모듈 분리 후 전체 하니스: PASS 687 / FAIL 0 / SKIP 20 (707개, 350초). SKIP은 기존 fast 게이트 제외 목록으로, 이번 작업에서 늘리거나 테스트를 끄지 않았다. 뒤에 병합한 다른 유지보수자의 변경까지 포함한 최종 상태는 PR CI에서 다시 검사한다.

최종 CI 및 배포 결과는 실제 완료 후 PR에 기록한다. 여기의 로컬 샌드박스 결과를 운영 배포 완료로 해석하지 않는다.

## 범위와 남은 구조

이번 변경은 운영 관리자 도메인의 모듈 경계와 저장소 전반의 하니스 실행 경로를 정리한 것이다. 전체 서비스의 모든 파일을 리팩토링했다는 뜻은 아니다. `api-admin.ts`의 나머지 라우트와 큰 UI 파일 등은 여전히 후속 정리 대상이다. 실행 본문을 보존하는 단계와 기능·정책 변경 단계를 섞지 않았다.

원본 작업 폴더의 미완성 파일은 건드리지 않고 별도 worktree에서 작업했다. 레거시, 운영 DB 데이터, 도메인 배치, DO·cron·문자 정책, 공동 금지구역 파일은 변경하지 않았다. 다른 유지보수자의 최신 `main` 변경은 별도로 병합해 보존했다.
