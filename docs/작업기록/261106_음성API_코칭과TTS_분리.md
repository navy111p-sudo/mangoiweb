# 2026-11-06 음성 API의 코칭·TTS 분리

## 목적과 변경

전체 운영 코드 정리의 후속 작업이다. `api-games.ts`에 단어장·퀴즈·배지·스트릭과 함께 있던 음성 처리 약 670줄을 두 모듈로 옮겼다. HTTP 주소·메서드·응답과 기존 정책은 유지한다.

| 모듈 | 담당 |
|---|---|
| `cloudflare-deploy/src/api-games.ts` | 기존 학습 API, 마지막에 음성 핸들러 호출 |
| `cloudflare-deploy/src/api-games-voice.ts` | 전사, 코칭 채점, 학생 이력·통계, Azure 임시 토큰 |
| `cloudflare-deploy/src/api-voice-tts.ts` | TTS, R2 캐시, 화자별 폴백, Azure 호출 상한 |

`MangoEnv`는 type import로만 참조한다. 음성 테이블 초기화는 요청의 클로저로 유지하고, 실제로 필요한 라우트에서만 실행한다. 스트림·Response 본문을 분리 경계에서 읽거나 다시 만들지 않는다. 공용 채점기와 권한 판정기를 복사하지 않았다.

## 유지한 결정

- Aura-2의 일시 실패 재시도, 과금 한도 오류 때 재시도하지 않는 정책과 Aura-1/MeloTTS 폴백을 유지했다.
- 폴백 캐시는 요청한 화자가 아니라 실제 생성한 화자의 키로 저장한다. Azure 캐시 진단은 저장된 엔진 표시를 읽는다.
- Azure 호출 상한은 캐시 확인 뒤, 유료 호출 직전에 검사한다.
- 엄격 전사 모드의 무음·낮은 확신도는 종료이며, 인식기 실패는 503이다. 일반 코칭 전사의 기존 Whisper 폴백도 유지했다.
- 모범 문장을 Whisper의 프롬프트에 섞지 않는 경계를 유지했다.
- 다른 학생의 코칭 기록 쓰기와 음성 이력·통계 조회를 차단한다. 게스트의 연습 기록은 기존대로 허용한다.
- 기존 테이블/인덱스/ALTER 및 실패 처리도 옮겼을 뿐 바꾸지 않았다. 운영 DB에는 쓰기 테스트를 하지 않았다.

## 검토한 대안

학습 API 전체를 한 번에 여러 모듈로 나누는 대신 이번 변경은 음성 경계로 제한했다. 단어장·퀴즈는 SRS·보상·교재 문제은행과 연결되어 있어 별도의 실행 검증을 갖춘 뒤 옮기는 편이 검토하기 쉽다. 음성 공급자·가격 정책이나 채점 방식 개선을 이 구조 변경에 섞지 않았다.

모든 TS 파일을 이어 붙이는 검사는 끊어진 import를 놓친다. `gamesSrc`는 실제 `api-games-*`·`api-voice-*` import 그래프만 따라간다. 소스 override를 보존하며, 없는 의존성은 실패하고 연결되지 않은 파일은 검사에 포함하지 않는다. 기존 음성 관련 하니스 11개를 이 그래프에 연결했다. hashbang이 있는 하니스는 첫 줄 위치를 보존했다.

## 검증 근거

- 정확한 경로의 `node node_modules/typescript/bin/tsc --noEmit` 통과.
- TypeScript AST를 주석 없이 출력해 기준 main과 대조: 기존 라우트 44개, catch 절 96개가 동일하다. 그중 음성 라우트 6개를 옮겼다.
- `voice_module_boundaries_harness.mjs`: 실제 `handleGamesApi`부터 번들해 실행하는 계약 검사 13종 통과. 가짜 AI/R2/D1과 합성 서명 토큰만 사용한다. 예상하지 않은 외부 fetch는 실패하도록 막았다.
- 변이 5종 전부 검출: 학습→음성 연결 누락, 음성→TTS 연결 누락, 요청 화자 키로 폴백 저장, 이력 소유자 검사 우회, 엄격 모드의 일반 전사 폴백. 컴파일 실패는 검출로 인정하지 않았다.
- 실제 `src/index.ts`+운영 자산을 workerd로 실행한 별도 로컬 샌드박스 12개 요청 통과. D1/KV/R2/DO는 전부 로컬, AI 바인딩·운영 시크릿은 없다. 게스트 코칭은 200이며 로컬 SQLite에 합성 게스트 기록 1건이 저장됨을 SELECT로 확인했다. 다른 학생의 쓰기는 401이고 그 학생 기록은 없다.
- 기존 전체 fast 하니스와 PR CI 결과, 병합 커밋·실제 배포 버전 확인은 완료 후 PR에 기록한다. 실패한 검사를 제외하거나 기준선을 낮추지 않는다.

UI·도메인·cron·DO·SMS 정책·공동 금지구역·레거시는 수정하지 않았다. 실제 유료 음성 공급자 호출과 사람이 듣는 음질 평가는 이 구조 변경의 테스트에서 수행하지 않았다. 전체 서비스의 코드 정리 완료를 의미하지 않는다.
