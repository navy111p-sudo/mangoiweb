## 왜 바꿨나

이전 검증 브랜치의 교재·배경 후속 방어가 main에 없었다. 같은 실제 함수 검사에서 기준은 배경 42개 중 41개, 공유 교재 30개 중 19개가 실패했다. 늦은 교재 완료가 최신 페이지를 덮고, 배경 OFF 뒤 초기화가 다시 송출을 시작하는 문제다.

## 필요한 변경만

- 교재 로드 취소를 원격·공유·재시도·입장·업로드·붙여넣기·시퀀스·배정 교재의 후속 처리에도 적용한다.
- 배경 초기화와 첫 추론은 완료 Promise를 공유하고, 세대와 모드를 확인한다. 첫 결과 전 원본 미리보기를 유지한다.
- OFF·초기화 실패·추론 실패·성능 강등·루프 정지의 원본 복귀를 `vcBgRestoreRaw`로 모은다.
- RAF와 최초 추론의 전송 잠금은 `vcBgSendFrame` 한 곳에서 관리한다.
- main/textbook 스크립트와 teacher preload 버전을 함께 올린다. 진행 중이던 전송 큐 수정은 덮어쓰지 않는다.

새 의존성·옵션·서버 API·데이터 보존 정책은 추가하지 않았다. 느린 옛 교재를 기다리는 전체 직렬화 대신 취소 결과를 전파한다. 필기는 기존처럼 탭·방·파일별 메모리 보관이며 새로고침 이후 보관을 추가하지 않았다.

## 확인

- 타입 검사와 build 통과.
- 관련 하니스 20종 통과. 기존 스트레스 2,100회와 신규 교재·배경·마이크 오류 검사 포함. 실행 횟수는 독립 결함 종류 수가 아니다.
- Chrome 교재 300회, 안내 12개, 모의 모델을 쓰는 실제 DOM/canvas MediaStream 배경 취소 10개 통과.
- 원본·수정 코드 실패/통과 대조와 오류 처리, 카메라 제거, 직접 OFF, 초기화 재시도 검사 포함.
- 최초 WebRTC 오디오 검사는 closed 상태의 복구 전 무음 확인에서 한 번 실패했다. 오디오 제어·Office Mode·검사 파일은 이번 변경에서 동일하다. 판정 기준을 변경하지 않고 기준/수정본을 단독 순차 비교했다. 상세 결과는 PR의 실행 기록에 보고한다.
- 전체 회귀·문법·자산 버전 게이트는 PR의 Linux CI 결과를 기준으로 확인하며, 실패한 검사를 끄거나 기준선을 낮추지 않는다.

## 배포와 제한

사용자가 배포를 요청했다. CI 통과 후 저장소의 기존 수업 보호·실접속 판정을 유지하는 배포 경로를 사용한다. 운영 DB·일정·계정·권한 변경이나 실제 수업 참여, 유료 모델 호출은 하지 않는다.

물리 카메라·헤드셋·Krisp·실수업 회선·실제 MediaPipe 처리 성능은 미검증이다. 합성 음원 WebRTC의 수신 PCM 검사와 실제 장치 음질 검증은 다르다. 서버 반영은 배포 로그·스탬프·배포된 JS를 확인한 뒤 보고한다.
