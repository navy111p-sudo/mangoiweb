# 로컬 회귀 검사 환경과 시간 초과 정리

## 이유

사장님 요청: 앞선 로컬 검사 65 FAIL / 22 SKIP의 원인을 확인하고, 전체 722개를 다시 검사하되 90초 기준과 검증 범위는 유지한다.

기존 실패의 주원인은 sparse checkout에 빠진 정적 자산·문서·스크립트와 다른 작업 폴더의 오래된 Wrangler/Miniflare였다. 별도 worktree를 전체 checkout으로 바꾸고 그 worktree의 lockfile로 의존성을 설치했다. 앞선 실패와 추가 시간 초과를 대상으로 한 진단 재실행은 67/67 exit 0이었다. 이 진단은 180초 제한을 사용했으므로 정식 90초 게이트 통과로 취급하지 않았다.

## 변경

- `eleader/fixture.mjs`: 이미 Node가 같은 URL로 캐시하던 API 모듈을 사례마다 다시 빌드하지 않는다. 각 사례의 SQLite, 환경, 토큰은 계속 새로 만든다. 22개 교재 × 10개 접근 조건 × 2회 반복을 유지한다.
- `teacher_login_times_harness.mjs`: 비동기 작업을 비우는 5회 대기를 `setImmediate`로 처리한다. Windows의 `setTimeout(0)` 지연을 없애며 무작위 사례와 단언은 그대로다.
- 반복 수업과 취소 수업 변이 검사: 개별 자식 프로세스는 유지하고, 작업자별 임시 소스 복사본을 재사용한다. 바꾼 파일은 `finally`에서 원문으로 복구한다. 파일이 확인된 상대 TS import는 동기 resolve hook이 직접 URL을 반환한다.
- 반복 수업·외부 감시견 검사를 기존 단독 실행 목록에 넣었다. 90초 제한, 재시도, 기준선, 제외 목록은 변경하지 않았다. 모든 시간 초과를 netem E2E로 표시하던 문구도 일반적인 시간 초과 표시로 고쳤다.

## 측정과 검증

- 강사 접속 기록: 98 PASS / 0 FAIL, 약 2.3초. 이전 진단 143.1초.
- eleader: 162개 테스트 통과, 약 18.8초. 이전 진단 115.6초.
- 반복 수업: 195 PASS / 0 FAIL, 변이 10종 모두 검출. 복사본 재사용까지 적용한 측정은 약 73.4초(경로 직접 반환 전).
- 외부 감시견: 49 PASS / 0 FAIL, 단독 약 84.8초. 앞선 동시 실행 진단 101.9초.
- 취소 수업: 180 PASS / 0 FAIL. 작업자별 복사본 재사용만으로 약 123.2초, 경로 직접 반환 적용 후 약 93.8초. 이 개별 측정은 아직 90초 밖이므로 정식 게이트 통과라고 하지 않는다.
- 취소 수업 자식 CPU 프로파일 8.33초 중 existsSync 약 1.45초, open 약 1.21초, internalModuleStat 약 0.87초였다. 같은 PC에서 다른 worktree의 전체 검사도 여러 벌 실행 중이었다. 측정값은 동일 부하에서의 엄밀한 벤치마크가 아니다.
- TypeScript 검사는 최신 main 병합 후 exit 0이었다. 최종 전체 실행 결과와 CI는 [PR #2164](https://github.com/navy111p-sudo/mangoiweb/pull/2164)에 기록한다. `--fast`는 기존 정책상 20개(브라우저 19개와 worktree 무결성 검사 1개)를 제외한다.

## 하지 않은 것

90초 상한을 늘리거나 변이·무작위 사례·단언을 삭제하지 않았다. 컴파일 캐시는 실제 측정에서 더 느려져 적용하지 않았다. 프로파일용 파일과 자동 생성된 무관한 자산 원장 항목도 커밋하지 않는다. 서비스 코드나 운영 D1 데이터를 바꾸지 않았다. 다른 작업자의 프로세스를 종료하지 않았다.
