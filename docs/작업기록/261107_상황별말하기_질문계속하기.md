# 상황별 말하기 — 질문이 계속 이어지게 하기

- 날짜: 2026-11-07
- 작업자: Codex
- 브랜치: `codex/situation-keep-practicing`

## 왜 했나
병원 상황에서 학생의 인사 뒤 Emma가 “You are welcome! Get some rest now.”처럼 질문 없이 대화를 마무리했다. 사용자는 모든 상황에서 충분한 영어 말하기 연습을 하도록 다양한 질문을 계속하고, 샌드박스·하니스 통과 후 병합·배포하라고 요청했다.

## 바뀐 것
- `public/js/ai-situations.js`: 20개 상황별로 12개 이상 연습 소재를 제공한다. 답변에 반응한 뒤 새 질문 하나로 끝내고, 주문·진료·인사가 끝나도 같은 상황의 다음 장면·방문으로 이어 간다. 학생의 Thank you/OK/Bye만으로 화면의 종료 버튼을 대신하지 않는다. 학생 수준과 한 번에 한 질문 규칙을 지킨다.
- `public/warmup.html`, `public/ai-speaking.html`: 표의 캐시 버전을 함께 3으로 올렸다.
- `src/index.ts`: 상황별 역할 지시가 있는 대화만, 기존 재생성 단계가 끝난 뒤 질문으로 끝나는지 검사한다. 질문이 없으면 한 번만 재생성하고 길이·이름·조각 질문·반복 검사를 거친다. 실패해도 안전 질문으로 이어 간다. 교정 음성과 최종 히스토리 저장 앞에 둔다. 스트림은 기존 replaced 처리로 최종본을 다시 읽는다.
- `test-harness/conversation_connectors_harness.mjs`: 실제 Worker를 묶어 AI·KV·SQLite만 로컬 대역으로 바꾸고 20개 상황, 실패 경로, 정상 답변, 일반 대화, 스트리밍을 실행한다.

## 선택 이유와 버린 방법
프롬프트만 바꾸면 모델이 다시 인사로 끝내는 경우를 막지 못하므로 서버의 최종 답변도 검사한다. 질문을 한 번에 여러 개 쏟거나 특정 횟수 뒤 자동 종료하는 방법은 학생이 충분히 말하려는 요청과 맞지 않아 넣지 않았다. 모든 AI 대화에 강제하지 않고 상황별 경로에만 적용한다. 별도 엔진·의존성·운영 DB 변경은 없다.

## 검증
- 타입 검사: 통과.
- 실제 Worker 샌드박스 하니스: PASS 336 / FAIL 0. 20개 상황의 재생성·히스토리 일치, 재생성 오류·조각 질문·이름 오류 시 안전 질문, 일반 대화 제외, SSE 최종 질문 교체를 실행했다.
- Chromium 로컬 브라우저: 320개 사례 / 3,280개 검사 / 실패 0. 외부 요청·실제 AI·마이크·운영 DB는 차단했다.
- 조각 질문 하니스: PASS 131 / FAIL 0. Windows CRLF로 소스 블록 추출이 실패한 첫 실행 후 index.ts를 LF로 맞춰 재검사했다(검사 조건 변경 없음).
- 전체 회귀 결과와 병합·배포 이력은 PR CI 및 배포 워크플로에서 확인한다. 배포 성공 전 운영 반영을 완료로 기록하지 않는다.

## 한계
샌드박스 AI는 고의로 질문 없는 답을 내는 대역이다. 실제 모델의 장시간 대화 품질과 실제 마이크·음성은 이 검사로 증명하지 않는다. 질문이 빠진 턴에는 AI 재생성 한 번의 지연이 추가될 수 있다. 재생성까지 실패하면 상황 공통 안전 질문을 쓴다. 집중교정은 기존대로 따라 말하기 질문을 우선한다.
