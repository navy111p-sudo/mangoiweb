# A.i 말하기·친구 음성 품질 회복

## 확인한 원인
Aura-1 폴백은 실제 화자 이름으로 저장했지만 Aura-2와 같은 이름(Emma의 asteria 등)을 사용하므로 정상 음성 캐시를 덮었다. 정상 음성도 eng 메타데이터 없이 저장되어 둘을 구별하지 못했다. 브라우저도 화자 이름만 비교해 같은 이름의 구형 음성과 화자 헤더 없는 MeloTTS를 캐시했다. 또한 말하기 _speechText가 인용부호 앞 공백을 제거해 집중교정 반복문 사이의 `" "`를 `""`로 붙였다.

## 변경
영어 서버 캐시는 aura-2 출처가 확인된 항목만 재사용한다. 정상 저장 시 출처를 남기고 Aura-1은 MeloTTS와 마찬가지로 영구 저장하지 않는다. 브라우저의 일반 재생·미리받기·스트리밍 경로도 정상 엔진과 화자만 캐시한다. 중국어 캐시 정책과 장애 시 음성 폴백은 유지한다. 말하기 인용부호 사이 공백을 보존한다. 공용 JS를 읽는 HTML의 버전을 함께 올린다.

## 검증과 범위
실제 API 함수와 브라우저 함수를 가짜 AI/R2/fetch로 실행해 네 아바타의 장애→복구, 캐시 출처, 인용부호 경계를 검사했다. 새 하니스 17 PASS, 기존 음성 폴백 88 PASS, 집중교정 71 PASS. TypeScript 검사 통과. 전체 검사 및 배포 결과는 PR에 남긴다.

## 한계와 비용
실제 합성 음성을 직접 청취한 검증은 아니다. 사용자가 경험한 모든 오발음의 원인이 이것이라고 단정하지 않는다. 출처 표시가 없는 옛 영어 음성 캐시는 첫 요청 때 다시 생성하므로 초기 음성 생성 요청이 일시적으로 늘어난다. 화자·속도·집중교정 반복 횟수·사용자의 개별 발음 보정은 변경하지 않았다. 다른 작업자의 미커밋 파일은 별도 작업트리에서 보존했다.
