# 화상수업 공유 신호 전송 실패 보존

- 날짜: 2026-11-07
- 브랜치: codex/chinese-connection-cleanup
- 기준 main: b3b3cff213321dd3b972b89f645bda2949668510

중국어 수업 연결 코드를 Ponytail 방식으로 작게 정리해 달라는 요청에 따라 WebSocket 공유 대기열만 수정했다. 과거 수업 장애의 최초 원인을 확정한 변경은 아니다.

`idx-main.js`의 `flushQueue`는 전송 전에 대기열을 비우므로 중간 send 예외 시 미전송 교재 신호가 사라졌다. 전송에 성공한 항목만 순서대로 제거하고, 실패하면 나머지를 보존한다. OPEN 소켓의 send 예외도 기존 공유 대기열로 처리한다. 같은 종류의 새 신호가 성공하면 예전 대기 신호를 지워 뒤늦게 되돌아가지 않도록 했다. 일반 채팅은 계속 자동 재전송하지 않으며 반환값은 상대 수신 ACK가 아니다.

별도 모듈·새 재시도 타이머·외부 의존성·서버 변경은 추가하지 않았다. 기존 대기열의 타입 제한, 같은 타입 최신 값 유지, 최대 20개 제한, join-room 이후 전송을 유지했다. 홈페이지와 교사 preload를 v74로 맞췄다.

확인: 변경 전 코드에서 신규 유실 재현 2건 실패, 수정 후 범위 하니스 37건 통과. 문법·TypeScript 검사 통과. sticky reconnect 18건, 안정성 checklist 50건, observer reply 96건, whisper delivery 70건, chat blink 77건, chat history 13건, preload 12건 및 chat clearzone 통과. 자산 참조 323건 통과. 교재 검증 변이시험의 안내 앵커 1건 실패는 기준선에서도 동일했다.

전체 fast suite는 Windows의 npx/esbuild 실행 실패가 발생해 중단했다. 전체 회귀 통과로 간주하지 않는다. 새 캐시 원장에는 이 변경의 v74 항목만 남겼으며, 실행 중 자동 추가된 기존 main의 더빙 원장 누락 3항목은 관련 없는 변경이라 포함하지 않았다. Linux CI에서 전체 검증이 필요하다.

실제 중국↔한국 회선·실제 수업·업로드 API를 검증하지 않았으며 배포하지 않았다. 당시 HTTP 업로드 실패의 원인은 여전히 미확정이다.

PR 리뷰 반영: 같은 타입만 지우면 예전 공유 중지가 새 교재/영상을 닫을 수 있어, 새 공유·중지는 같은 미디어의 이전 공유·중지·동기화(교재 페이지 포함)를 함께 대체한다. 성공 전송과 오프라인 대기열 모두 같은 판정을 사용한다. 교재·영상 양방향 전환 6개 회귀를 추가했다. 캐시 해시는 Windows 작업 바이트가 아닌 Git index의 정규화 바이트로 계산한다.
