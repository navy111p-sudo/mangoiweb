# A.i 말하기 «얼굴 대화» 를 영상통화 화면처럼 (js/ftk-call.js)

- 작업자: Claude (사장님 요청)
- 브랜치 / PR: `claude/ai-speaking-video-call-skin`

## 1. 왜 했나

사장님이 영어회화 앱의 «일일 레슨» 화면녹화 2개(각 43초·42초)를 보내시며 「이것과 똑같이 A.i 말하기 모두 — 답변속도·입모양·디자인·분위기·얼굴표정」.

[잰 것 — 영상 프레임·소리 크기 분석]
- 화면: 밝은 회색 배경 · 상반신 아바타가 화면 가운데 · 위 «제목 / ✓ / 카메라(빨강) / ✕» · 왼쪽 가장자리 소리 버튼 · 말하는 대로 **한 낱말씩** 나오는 흰 자막(늘 마지막 2줄) · «듣는 중... / 생각 중...» · 아래 «🎤 · .5X · CC · 말소리 점 3개(말하면 막대) · 자동/손 모드» · 노란 진행 막대(목표 넘으면 초록) · 끝나면 점수 화면.
- 응답 속도: 학생 말 끝 → «듣는 중» 이 약 1.5초 더 남음 → «생각 중» 약 9~11초 → 목소리. **학생 말 끝~첫 소리 약 11~13초.**
- 입모양·고개·깜빡임: 같은 앱(23초 녹화) 분석으로 이미 v21(턱 내리기·고개 좌우)에 반영돼 있음 — `261109_아바타_턱내리기_고개좌우돌림.md`.

## 2. 무엇을 바꿨나

- `cloudflare-deploy/public/js/ftk-call.js` (신규) — 두 얼굴 화면(#ftk) 위에 «겉모습» 만 입히는 공용 스킨.
  - 자막: `capText(parts, idx, frac)` — 소리로 나간 조각 + 지금 조각의 «재생 비율» 만큼 낱말. 재생 위치는 실제 `<audio>` (`MangoiTTS.getAudioEl()` · 웜업 `_ttsAudio`)의 `currentTime/duration`. 새 조각은 `src` 가 바뀌거나 시간이 되돌아갈 때.
  - 상태 글자·말소리 점은 #ftk 의 `data-s`·`heard` 를 #ftk «하나만» 관찰(body 관찰자 없음, #ftk 속성을 쓰지 않음 → 되먹임 없음). 자막 rAF 는 «말하는 중» 에만.
  - 버튼: ✓ = 실제 «학습 결과»(A.i 친구 `AiSpeakingProgress.finish` · 웜업 `#wgFinish`) · 📷 = 내 얼굴 미리보기(이 화면 안에서만, 녹화·전송 없음, 기본 꺼짐) · 다시 듣기 · .5X(이 화면에서만 0.5배, 저장 안 함) · CC(기억) · 자동/손(기억, `mangoi_ftk_hands`) · 진행 막대(말한 횟수/5, 5번이면 초록).
- `js/aifriend-facetalk.js` — 손잡이 `CALL` + `build()` 끝 `FtkCall.mount(root, CALL)` · 말한 조각 기록(`said`) · 손 모드 `next()`(자동이면 듣기, 손이면 선생님 말이 끝난 뒤 쉬며 마이크 누르기를 기다림) · `replay()` · 도움판 `gl-open` class · `waitQuiet` 이 기다리는 동안 «말하는 중» 표시(아래 3-④).
- `js/warmup-facetalk.js` — 같은 손잡이(조각 = 화면의 `_speechChunks`, 다시 듣기 = `speak(text, btn)`, 손 모드 = 엔진 `setMode('button')`) · 나갈 때 원래 «자동» 이던 사람은 자동으로 되돌림.
- `ai-friend.html`·`warmup.html` — `ftk-call.js?v=1` 추가, 얼굴 화면 스크립트 `?v=` 올림. (웜업은 4-2 B 담당 파일 — 스크립트 줄 두 줄만)
- 하니스: `test-harness/ftk_call_harness.mjs`(신규·CI) · `test-harness/manual/ftk-call-browser.mjs`(신규·수동) · 기존 수동 2개(`ai-friend-facetalk-browser`·`warmup-facetalk-browser`)를 새 화면에 맞춤(얼굴 «화면 90%» → «높이 60%·가운데», ✕ → `.fc-close`, 도움판 열림은 실제 보임 여부로).

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

1. **응답 속도를 «똑같이»(11~13초) 맞추지 않았습니다.** 그 앱이 우리보다 느립니다. 늦추는 것은 사장님 뜻과 반대라 지금 속도를 유지했습니다. 말 끝 판단(조용함 1.5초)은 이미 그 앱과 같습니다.
2. **두 얼굴 화면 파일을 각각 다시 그리지 않았습니다.** 같은 모양을 두 벌 고치면 한쪽만 고쳐집니다 → 공용 스킨 1개 + 각 파일은 «손잡이» 만 넘김. 대화 순서·듣기·보내기는 한 줄도 새로 만들지 않았습니다.
3. **자막을 «시간 추정»(초당 낱말 수)으로 하지 않았습니다.** 오차가 쌓입니다 → 실제 `<audio>` 재생 비율. 조각 경계는 A.i 친구는 «실제로 읽힌 글»(`said`), 웜업은 화면이 쓰는 그 규칙(`_speechChunks`).
4. **(발견) 대답이 «생각 중» 으로만 보이던 것** — `sendMsg()` 가 끝나면 `listen()` 이 차례 번호를 올려 `watchSpeakState` 가 멈춥니다. 그래서 대답 소리가 나는 동안에도 상태가 `think` 였습니다(옛 화면에선 노란 테두리라 티가 덜 났음). 자막은 «말하는 중» 에만 나오므로 브라우저 검사에서 드러났고, `waitQuiet` 이 기다리는 동안 «말하는 중» 으로 바꿔 고쳤습니다.
5. **도움판(대답 보기·안내)은 없애지 않았습니다.** 영상 앱엔 없지만 «막혔을 때 저절로 열림»·«마이크 권한 안내» 는 우리 기능입니다 → 평소엔 숨기고 열릴 때만 밝은 카드로, 손잡이로 닫기.
6. **아바타 얼굴 그림은 그 앱 것을 쓰지 않았습니다**(남의 캐릭터) — 우리 Emma·Lily·Noah 등 그대로, 구도(상반신·밝은 배경)만 맞춤.

## 5. 남은 것 / 주의할 것

- 결과 화면은 기존 «학습 결과»(실제 평가) 그대로입니다. 영상 앱의 «점수 링 + 스티커» 모양으로 바꾸는 것은 별건(지어낸 점수는 안 만듭니다 — 5영역이 다 있어야 종합 점수).
- 진행 막대 목표 5번은 A.i 친구의 기존 퀘스트(«영어 수다 5번»)에 맞춘 값입니다. 바꾸려면 `ftk-call.js` 의 `GOAL` 한 곳.
- 기기 목소리(speechSynthesis)로 읽을 땐 재생 위치를 몰라 자막이 한 번에 나옵니다(서버 목소리가 기본이라 드묾).
- 웜업 «스트리밍 첫 문장» 경로는 조각 경계가 `_speechChunks` 와 다를 수 있어 자막이 조금 앞서거나 늦을 수 있습니다(끝나면 전부 보임).
