## 1. 왜 했나

사장님: 「휴대폰에서 A.i 말하기 반응을 오른쪽 Loora 의 반응속도처럼 똑같은 응답속도로 해줘」 (Loora 화면 녹화 23초 + warmup.html 얼굴 대화 화면).

Loora 녹화를 0.5초 간격으로 잘라 본 것:
- 학생 말 끝 → «Thinking…» 약 1.5초(첫 턴)~5초(둘째 턴) → 짧은 첫마디(«No problem at all!», «Of course.»)부터 소리와 자막이 함께 시작.
- 교정은 대화 중에 끼우지 않는다(상단 ✓ 버튼으로 따로).

우리 쪽(2026-11-08 같은 날 운영 실측, 앞선 작업기록): 첫 음성까지 교정 턴 10.7~18.8초 · 자유 대화 5.5~7.9초.

## 2. 원인 (코드를 읽고 내린 판단)

- 교정 기본값이 모든 학생 «집중교정»(`WARMUP_DEFAULT_MODE`). 집중교정은 미리듣기를 흘리지 않아 «최종 답» 이 나와야 소리가 난다.
- `src/index.ts` handleWarmupChat 은 본 모델 호출이 끝난 «뒤» 에 모델이 교정을 안 줬으면 `recoverFocusedFix`(같은 70B 모델 한 번 더)를 **차례로** 불렀다.
  2026-11-06 실측으로 집중교정 턴의 74% 가 «교정 없음» → 그 턴마다 모델 왕복 하나가 통째로 더해졌다.
- A.i 친구(`api-ai.ts`)는 11/6 에 이미 동시 시작으로 바꿨고, 하니스 주석도 «웜업(avatar)은 예전대로 필요할 때만» 이라고 남겨 두고 있었다.

## 3. 바꾼 것

- `src/index.ts` (공동 금지구역 — 사장님 직접 요청, handleWarmupChat 안만)
  - 본 호출을 시작한 직후(한 박자 뒤) 다시 묻기를 미리 시작(`focusedRecoverP`). 조건은 결정 자리와 같다(집중교정 + 지금 교정 시점) + 과거형 보완 규칙이 이미 잡는 문장이면 시작 안 함.
  - 결정 자리의 «순서» 는 그대로: 모델 교정 → 과거형 보완 → 답장 속 «You can say» → 미리 시작한 다시 묻기.
  - `runWarmup(…, overlap)` — 겹친 호출은 모델 시간에 안 더하고, 기다린 «안 겹친 나머지» 만 더한다(`api-ai.ts` runFriend 와 같은 규칙 — model_ms 가 ms 보다 커지지 않게).
- `test-harness/focused_correction_speech_harness.mjs`
  - «웜업은 필요할 때만» 기대를 «둘 다 동시 시작» 으로 바꿈.
  - 새 검사: 본 호출이 «아직 도는 동안» 다시 묻기가 시작되는가(correct·omitted) · 과거형 규칙이 잡는 문장은 다시 묻기를 안 부르는가.

## 4. 맞바꿈

- 모델이 스스로 교정을 준 턴(약 26%)에도 다시 묻기가 한 번 돈다 — 결과는 버린다. Workers AI 호출이 그만큼 는다(A.i 친구와 같은 맞바꿈).
- 한 턴에 70B 호출 두 개가 동시에 돈다 — 계정 동시 실행 한도에 더 빨리 닿을 수 있다(운영에서 못 쟀다).

## 5. 검토했다가 안 한 것

- **모델 교체**(더 빠른 모델): 11/7 기록이 «새 모델로 바꾸면 지연과 교정 품질이 함께 바뀌므로 유지» 로 정했다. 사람이 정할 일.
- **집중교정에서도 대화 답을 먼저 흘리기**: 교정이 있으면 답이 «고친 문장» 으로 통째로 바뀌어, 먼저 읽은 질문을 끊고 다시 읽게 된다. 안 했다.
- **«yes» 같은 짧은 답은 다시 묻기 생략**: 동시 시작이면 기다림은 이미 없어지고 비용만 준다. 범위 밖.
