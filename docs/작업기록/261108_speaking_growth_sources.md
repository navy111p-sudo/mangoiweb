# A.i 말하기 실제 평가 근거·성장 기록·보상 중복 방지

PR #2178 / 이슈 #2179 후속 작업. 최신 main `0a187d900`과 PR 원격 `2e51ccaef`를 로컬 작업 브랜치에 병합해 양쪽 교정 시점·평가 메타데이터·고유 단어·얼굴 대화 개선을 보존했다. 운영 DB나 유료 모델을 테스트에 사용하지 않았다.

## 연결한 범위

- 웜업과 AI 친구가 완료 응답에서만 서버 확인 결과를 현재 화면 결과 카드에 모은다. 중간 final만 받은 잘린 스트림, 실패 응답, kickoff는 제외한다. 다른 세션·수업으로 전환하면 분리한다.
- 명시적으로 고른 교정 시점을 기존 설정에 저장하고 실제 프롬프트와 표시 게이트에 연결한다. 종료 후 교정은 대화 중 반복을 막고 검증한 교정을 종료 화면에 보여 준다. 핵심 교정은 major만 세션 메모 기준 최대 3개이며 KV는 동시 요청에 대한 강한 일관성을 보장하지 않는다.
- 인증된 서버 결과를 기존 D1 안의 단일 `speaking_growth_events` 테이블에 저장한다. 새 DB·지갑은 없다. 전체 대화·음성 대신 범위가 제한된 교정 쌍과 판정·출처만 남긴다. 학생·기능·세션·이벤트 키로 중복을 막는다. 기록 실패는 대화를 멈추지 않는다.
- 기존 학부모 대시보드와 월간 성장 보고서에 별도 확인 기록 영역을 연결했다. 기존 인증을 통과한 정확한 학생 ID와 기간으로 읽는다. 테이블 부재·조회 실패는 미제공으로 처리한다. 기록 저장 이전의 사용량으로 소급 해석하지 않는다. 기존 월간 레이더 점수는 새 5영역 평가의 근거로 사용하지 않는다.

## 실제 평가 공급원 조사

문자 대화의 perfect/partial/incomplete는 기존 서버 문장 판정이다. 이를 숫자로 환산하지 않는다. 브라우저가 제출하는 Azure/음향 값이나 `/api/voice/coach`의 텍스트 유사도는 신뢰할 수 있는 5영역 공급원이 아니다.

기존 서버 `/api/voice/transcribe`의 Azure 호출이 실제 성공하고 원본 네 점수가 모두 존재할 때만 영어 기준 문장(3단어 이상)의 발음·유창성 두 항목을 별도 읽기 평가로 기록한다. 실제 0점은 보존하고, 누락 필드를 기존 구현이 0으로 채운 경우는 제외한다. 토큰의 본인 ID만 사용하고 동일 음성·기준 문장의 재전송은 해시로 중복을 막는다. 새 유료 호출이나 음성 저장을 추가하지 않았다.

이는 자유 대화의 5영역 평가가 아니다. 기존 speech-coach 브라우저 SDK 경로는 이 서버 평가를 항상 호출하지 않으므로 실제 서비스 공급 성공을 확인했다고 주장할 수 없다. 문법·어휘·문장 구성의 검증된 공급원과 평가 기준이 아직 없다. [Microsoft 공식 문서](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-pronunciation-assessment)는 SDK 1.46 이상에서 content assessment가 폐기되었다고 설명한다. 따라서 해당 필드를 사용할 수 있다고 가정하거나 별도 모델에 임의 수치를 생성시키지 않았다.

모든 5영역이 실제로 제공되지 않으면 종합 점수는 미측정이다. 결과 모듈의 별·보석 추정값도 제거했다. 새로운 별·보석·배지 지급 정책은 만들지 않았다.

## 기존 포인트의 안전한 지급

웜업의 기존 5P는 서명 본인·저장된 세션 소유자·서버 확인 발화 3회 이상을 요구한다. 세션 청구와 당일 청구, 지갑·거래·규칙 원장을 한 D1 batch로 기록한다.

AI 친구는 인증 일치·정상 모델 응답·실제 대화 저장·유효한 요청 UUID가 모두 있어야 기존 포인트 지급을 시도한다. 학생·요청·보상 종류별 원자적 청구와 일일 규칙별/전체 상한으로 재시도·동시 요청을 막는다. 중간 실패 시 지갑과 원장을 함께 롤백한다. 발음 유료 작업도 소유권 인증 후 시작한다. [D1 batch 공식 계약](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)에 따른다.

기존 voice/subtitle 선택 보너스는 여전히 한도가 있는 클라이언트 신호다. 이를 실제 말하기·듣기 능력 측정으로 간주하지 않는다. UUID가 없는 오래된 클라이언트는 대화는 가능하지만 새 지급·친구 성장 기록이 생기지 않으므로 배포 시 캐시 갱신과 호환성 검토가 필요하다.

## 검증과 출시 범위

- 실제 SQLite 트랜잭션을 사용한 로컬 하니스: 인증 불일치, 실패 모델·저장 실패, 요청 재전송, 20개 동시 실제 API 호출, 규칙별 한도·전체 한도, 원장 실패 롤백, 학생·기간 분리.
- 실제 서버 라우트에 공급자 fixture 주입: Azure 원본 0점 보존, 필드 누락 제외, 클라이언트 제출 점수 무시, 동일 음성 재전송 중복 방지. 실제 Azure 운영 성공 여부와 구분한다.
- 실제 HTML을 Chromium에서 열어 웜업·친구 결과/설정 및 학부모·월간 보고서를 각각 320/390/768/1366px에서 확인했다. 잘린 스트림 제외·XSS 문자 처리·가로 넘침도 검사했다. 마이크·카메라와 실제 휴대폰 검증은 아니다.
- 기존 회귀 하니스도 실제 새 의존성에 맞췄다. 음성 라우트 추출 검사에는 실제 referenceReadingEvidence 함수를 주입했고, status 예외는 api-reports.ts의 동일한 기존 쿼리가 import 추가로 549→552행으로 이동한 것만 반영했다. 월간 배치 대상을 바꾸지 않았다.
- 최종 `npm_config_cache=/tmp/mangoi-npm-cache bash test-harness/ci-gates.sh`: 4종 모두 통과. 회귀 하니스 PASS 721 / E2E SKIP 20 / FAIL 0 (316초), TypeScript 통과, JS 문법 1,586조각 통과, 자산 버전 339건 통과. 로그 `/tmp/speaking-final-verified-gates.log`. 라이브 화상수업 상태가 필요한 20개는 수행한 것으로 계산하지 않는다. 통합 중 중복 조건으로 발생한 TypeScript 좁히기 오류를 수정하고 재검사했다. 시간 제한을 늘리거나 검사를 끄지 않았다.

운영과 기본 환경은 같은 D1/KV를 사용한다. 격리 staging이 확인되지 않았으므로 운영 데이터를 실험하지 않았고 원격 push·병합·배포를 하지 않았다. PR 브랜치 변경도 운영 배포를 유발할 수 있어 로컬 커밋으로 보존했다. 출시 전 남은 항목은 격리 staging, 검증된 나머지 평가 공급원과 기준, 모바일 실제 기기/화상수업·녹화 실기기 회귀, 리뷰다. 이 문서의 로컬 통과를 실제 배포나 실제 기기 검증으로 바꾸어 보고하면 안 된다.

이슈 #2179 전체 완료를 뜻하지 않는다. 새 기록의 학원 단위 집계·기간별 성장 그래프, 결과에서 복습 퀴즈로 이어지는 추가 연결, 새 별·보석·배지 지급은 본 변경에서 구현하지 않았다. 기존 포인트와 판정·인증 경로를 안전하게 연결한 범위만 검증했다.

최신 입구 브라우저 매트릭스는 320 시나리오 / 3,280 assertions / 실패 0 (`/tmp/speaking-final-entry-browser.log`). 결과·설정 8개 화면 크기 조합과 성장 보고서 8개 조합도 통과했다 (`/tmp/speaking-merged-browser.log`, `/tmp/speaking-merged-report-browser.log`). 별도 단위 테스트 27건 통과. 보상·성장 출처·인증된 API 하니스 결과는 `/tmp/speaking-merged-rewards.log`에 있다.

이전 전체 검사 시간 초과는 브라우저 작업과 분리한 이번 실행에서 재현되지 않았다. 90초 제한이나 검사 목록은 완화하지 않았다. 동시 부하의 영향이 의심되지만 운영 환경의 지연 원인까지 입증한 것은 아니다.
