# A.i 말하기 결과 통합 — 미측정 정책과 보상 귀속 수정

원격 재조회 결과 PR #2178은 다른 작업에서 main `70369c80c`로 병합돼 있었다. 원격 head `42e936283`와 최신 main을 로컬 브랜치에 통합했다. 원래 PR에 추가 병합하는 작업이 아니라 이 main을 대상으로 한 후속 수정이다. 기존 코드와 로컬 보강을 모두 보존하고 겹친 결과 진입점만 하나로 정리했다. 원래 PR의 다섯 PR 검사도 성공 상태를 확인했지만, 이 사실을 새 수정의 검증이나 운영 배포 성공으로 계산하지 않는다.

## 평가 근거 표시

완료 API가 LLaMA에 임의 0~100 수치를 요구하던 추가 호출을 제거했다. 문법·어휘·문장 구성도 검증된 평가 계약이 없으므로 빈 skills와 종합 null, `validated_evaluator_unavailable`을 반환한다. 실제 발화 단어와 교정 복습 표현, 저장된 턴 수, 기존 원장 보상과 배지는 유지한다. 음성 없는 발음·유창성을 추정하지 않는다.

과거 `result_json`에 숫자가 저장돼 있어도 재조회 응답에서는 수치를 제거하고 미측정으로 바꾼다. 운영 DB의 과거 행을 실험하거나 일괄 덮어쓰지는 않는다. 뷰도 평가 unavailable이면 오래된 숫자를 렌더링하지 않는다. 기존 순수 결과 모듈의 실제 0점 처리 계약은 유지하며 새 임의 점수를 만들지 않는다.

## 지급과 귀속의 단일 계약

- 기존 원자적 지급·일일 한도·요청 중복 방지와 공통 earn-by-rule 우회 차단을 유지했다.
- AI 친구는 정상 모델 응답과 실제 채팅 저장 뒤, 인증된 학생의 열린 결과 세션에 턴을 기록한다. 세션 소유자·app·원래 웜업 source도 기존 조건으로 검사한다.
- 같은 논리 턴을 동시에 재전송하면 기존의 동일 학생 발화를 확인한 경우만 같은 세션으로 귀속한다. 다른 학생의 세션이나 기록 실패에는 세션 연동 보상을 지급하지 않는다.
- 현재 클라이언트는 요청 UUID와 progress_turn을 같게 보낸다. 서버 세션을 지정한 요청에서 두 키가 다르면 지급하지 않는다. 서버는 두 키가 일치하고 세션 기록이 확인된 경우만 원자적 지급 원장의 `meta.speaking_session`에 서버 세션 ID를 추가한다. 결과 조회는 같은 메타데이터를 사용한다.
- request_id가 없는 기존 클라이언트는 유효 UUID인 progress_turn을 재시도 키로 사용할 수 있다. 명시적으로 잘못된 request_id는 이 경로로 우회하지 못한다. 결과 세션이 없는 기존 참여 경로의 정책은 유지한다.
- 이전 캐시의 귀속 계약을 확인할 수 없으면 pointsEarned를 0으로 단정하지 않고 null로 표시한다. 새 결과에는 귀속 계약 버전을 기록한다.

이는 지급액을 늘리거나 새로운 별·보석 정책을 만드는 변경이 아니다. 기존 배지 검사와 평가서 점수 척도 정규화 변경도 보존했다.

## 화면과 계정 격리

결과 컨트롤러는 하나다. 로그인 결과는 소유권이 검증된 서버 완료 API에서, 게스트 결과는 기존 서버 완료 응답을 모은 화면 메모리에서 읽고 같은 카드/대화상자에 표시한다. 두 결과 버튼이나 두 요약 카드를 동시에 만들지 않는다. 화면 집계는 전체 실력 평가나 서버 영구 기록으로 표시하지 않는다.

기존 AiSpeakingSession 모듈은 확인된 응답 수집·재시도 UUID·교정 시점 선택을 보존하고 별도의 결과 UI를 만들지 않는다. 계정 변경과 reset 시 페이지 집계도 비운다. 결과 요청 도중 토큰이 바뀌면 이전 계정의 늦은 결과·잔액을 표시하지 않는다. 한 페이지에 중복 로드되던 결과 스크립트도 정리하고 자산 버전을 올렸다.

다른 작업의 학부모 주간 활동·종료 후 교정 기록, 학습 보고서, 집중 교정 단축 경로, 얼굴 대화 수정과 기존 완료/복구/지우기 동작을 보존했다.

## 격리 검증

실제 workerd와 임시 D1/KV에서 같은 턴의 실제 chat API 요청 네 개를 동시에 보내 총 2P만 지급되고 원장 메타데이터와 완료 결과의 적립 2P가 일치함을 확인했다. 재전송은 0P이며 다른 학생 세션으로의 귀속·기록·지급을 막는다. finish는 추가 추론을 실행하지 않는다. 모든 외부 요청은 차단했고 공급자·운영 자원·실제 학생/미성년자 정보는 사용하지 않았다.

추가 검사는 원자적 청구/한도/롤백, API 소유권, 오래된 완료 요청의 덮어쓰기 방지, 과거 미검증 점수 제거, 예전 보상 캐시의 unknown 처리, 단어 근거, 기존 배지 중복 방지와 정확한 만점 척도, 전체 Worker 라우팅을 포함한다. 단위 검사 39건 통과. 로그인 브라우저 24개 조합(320/390/768/1366px)에서 361 checks 통과. 게스트 설정·잘린 스트림 8개, 학부모/월간 보고서 8개 크기 조합도 통과했다. 실제 기기 검증이 아니다.

로그: `/tmp/speaking-unified-unit.log`, `/tmp/speaking-unified-runtime.log`, `/tmp/speaking-unified-browser.log`, `/tmp/speaking-unified-guest-browser.log`, `/tmp/speaking-unified-report-browser.log`.

## 출시 범위와 남은 조건

안전하게 제한한 제품 범위는 **실제 대화 관측치·단어·교정·기존 원장 보상·기존 배지**다. 자유 대화 5영역 수치 평가는 포함하지 않는다. 격리된 평가 공급자 계정/자격증명·측정 정의·표본 타당성이 마련될 때까지 미측정을 유지한다. 이 공급자 부재는 수치 평가 기능의 차단 조건이며, 관측 결과만 제공하는 후속 수정과 구분한다.

운영 배포에는 후속 변경의 별도 PR 검수, 운영과 분리한 원격 staging 검증, 실제 기기·라이브 화상/녹화 E2E 확인이 남아 있다. 기본/운영 설정의 공유 자원을 staging으로 쓰지 않는다. 이 작업에서는 원격 push·새 PR 병합·배포·운영 DB 시험을 하지 않았다. 다른 작업이 실행한 원래 PR의 운영 배포 상태도 여기서 확인했다고 주장하지 않는다.
