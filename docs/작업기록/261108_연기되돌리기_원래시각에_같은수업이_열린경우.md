## 2. 무엇을 바꿨나

**새 버튼 «↩ 연기 되돌리기 / ↩ Undo postponement»** — 원래 자리(같은 학생·같은 날짜·같은 시각·**같은 강사**)에 살아 있는 수업이 이미 있을 때만. 원래 시각이 지났어도 됩니다.

누르면(본사 전용, 확인창):
- **새 수업을 열지 않습니다**(지난 시각에 «예정» 수업을 만들지 않는 PR #2109 의 선은 그대로).
- 옮겨 간 사본이 **아직 시작 전 active** 면 → 취소(미러 행이면 `c24-mirror:manual` 도장) + 그 날짜에 `remove` 기록(누가·왜).
  사본이 **이미 취소**면 → 행은 그대로.
- `restore` 기록(`source='undo-held'`, lesson_date = 원래 날짜)을 남김 → 원래 날짜의 «옮겨 감» 줄이 사라짐
  (관리자 «오늘 수업»·주간 시간표·강사 달력이 같은 정본 `loadMovedAwayEvents` 를 읽어 함께 사라짐).
- 원래 자리 수업(#7772)·출석·결제·급여 기록은 건드리지 않습니다.

## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

1. **지난 원래 시각에 사본을 active 로 되돌리기** — 원래 자리에 이미 #7772 가 열려 있어 «같은 수업 두 줄» 이 되고, 없을 때는 PR #2109 가 버린 길(지난 시각의 active = 결석 감지·급여). 버렸습니다.
2. **사본을 원래 날짜로 «취소 상태로» 옮기기** — 줄은 사라지지만 11/04 에 «✕ 취소됨» 이 열린 수업 옆에 생겨 또 거짓. 버렸습니다.
3. **읽을 때 자동으로 숨기기(같은 자리에 수업이 있으면 «옮겨 감» 줄 생략)** — 버튼이 필요 없지만, 사본이 **active** 인 경우 11/11 의 중복 수업(강사 대기·급여)이 **조용히 남습니다**. 사람이 확인하고 닫는 버튼으로 했습니다.
4. **강사가 달라도 «같은 수업» 으로 보기** — 연기 뒤 그 자리에 «다른» 수업을 새로 잡은 경우 보강을 닫아 버립니다. 같은 강사일 때만.
5. **새 action 이름(`settle` 등)** — 범용 이력 POST 의 강사 차단 목록 밖이라 위조될 수 있어, `restore` + 서버 전용 source 로.
