# A.i 말하기 · A.i 친구하기 — 얼굴 대화가 «기본 화면» (누르지 않아도 열림)

- 날짜: 2026-11-09
- 작업자: Claude (사장님 요청)
- 브랜치 / PR: `claude/warmup-facetalk-default`

## 1. 왜 했나

#2216 을 배포한 뒤 사장님이 휴대폰 화면(예전 채팅 화면)을 보내며 「아직 그대로인데 · 휴대폰 키면 이것을 default 로 해주기로 했잖아?」.

실제로 그랬습니다 — 영상통화형 얼굴 대화는 **얼굴 카드의 ▶ 를 눌러야만** 열렸고, 앞 작업기록(`261109_AI말하기_PC_2단_버튼글자_자막겹침.md` 1장)의 「휴대폰은 아바타 전면 — 이미 배포됨 그대로」는 **사실이 아니었습니다**(누르면 그렇게 된다는 뜻이었지 기본 화면이 아니었음).

지시: 폰은 얼굴 전면 · 태블릿은 얼굴 크게 + 아래 버튼 · PC 는 왼쪽 얼굴 + 오른쪽 대화 기록(#2216 의 2단). 화면 배치는 #2216 이 이미 창 폭으로 가르므로, 이번에 바꾼 것은 «언제 여는가» 하나입니다.

## 2. 무엇을 바꿨나

- `js/warmup-facetalk.js`(v=7) — 웜업은 설정 화면(연령·수준·교재)이 먼저라, **«시작» 을 누르면** 곧바로 얼굴 대화를 엽니다. 인라인 스크립트의 전역 `startWarmup` 을 감쌉니다(`wrapStart`). ✕ 로 나가면 그 페이지에서는 다시 저절로 안 엽니다(▶ 로 다시 들어옴). 이 파일이 오기 «전» 에 이미 시작했으면(`_warmStarted`) 그때 엽니다. 손 모드(자동/버튼)는 ✕ 와 **페이지를 떠날 때(pagehide)** 모두 학생 설정으로 되돌립니다(`restoreMode`).
- `js/aifriend-facetalk.js`(v=13) — A.i 친구하기는 설정 화면이 없어 **페이지를 열자마자** 엽니다(`autoOpen`). 대화 기록을 다 불러온 뒤에 엽니다 — `ai-friend.html` 이 `window.__aiFriendHistory = loadHistory()` 로 건넵니다(그래야 «처음 인사» 와 «이어서 듣기» 가 바로 갈림). 불러오기가 실패하거나 옛 HTML 이어도 엽니다. 기록이 오기 전에 학생이 먼저 화면을 눌렀으면 끼어들지 않고, 숨은 탭이면 보일 때까지 기다립니다.
  - 🔊 소리 — 학생이 꺼 둔 소리는 얼굴 화면 «동안만» 켜고 ✕·pagehide 에 꺼 둔 그대로 되돌립니다(`forceSound`/`restoreSound`). 예전처럼 `'1'` 로 덮어 두면 열자마자 열리는 지금은 방문마다 설정이 사라집니다.
  - 🎤 첫 마이크 — 누르기(제스처) 없이 열렸는데 브라우저가 소리를 막는 중이면(`navigator.userActivation` 도 없고 시험 AudioContext 가 `suspended`) 인사 뒤 **«마이크를 눌러 말해요»** 로 기다립니다(`needTap`). 막혀 있는데 저절로 들으면 음성 감지(AudioContext)가 무음만 봐 «쉬는 중» 으로 빠졌습니다. 브라우저가 허락하면(running) 예전처럼 자동. ▶ 로 들어가면 늘 예전처럼 자동.
  - ✕ 로 나갈 때 대화가 비어 있으면 맨 아래로 안 내립니다 — 작은 폰(320×640)에서 «오늘의 단어» 카드가 아바타 밑으로 숨었습니다(main 에서도 ▶→✕ 하면 재현되던 옛 결함 · 이제 기본 경로라 고침).
- `js/ftk-call.js`(v=3) — 위 «눌러서 기다림» 동안 상태 글자가 «쉬는 중 · 다시 시작» 대신 «마이크를 눌러 말해요»(`waitTap`). 웜업은 그 손잡이가 없어 예전 그대로.
- 안내 문구 — `js/warmup-howto.js`(v=12)·`ai-guide.html` 이 «▶ 를 누르면» 이 아니라 «시작하면/열면 바로 얼굴 화면 · ✕ 로 닫으면 글 대화» 로 말합니다.
- 하니스 `ftk_call_harness` ⑦(웜업)·⑧(A.i 친구) — 두 블록을 소스에서 오려 내 가짜 `startWarmup`·`enter`·기록 Promise·`document`·AudioContext 로 실제로 돌립니다.
- 브라우저 검사 — CI 가 도는 `ai-speaking-browser`(320경우: 친구 모드는 «열자마자 얼굴 대화» 를 확인하고 ✕ → «모드 선택» 으로 돌아감) · `ai-speaking-progress`·`ai-speaking-observations`(채팅 칸에 쓰므로 먼저 닫음) · 수동 `ftk-call`·`ai-friend-facetalk`(«열자마자 열린다» 확인 · 이미 열렸으면 ▶ 를 안 누름).

## 3. 일부러 안 연 경우

- **수업 안(iframe)** — 마이크가 저절로 열리므로. 웜업은 `enter()` 가 원래 막고, A.i 친구는 `window.top === window` 일 때만.
- **웜업 `?setup=0`**(상황 연습·수업 흐름) — 감싸기 «전» 에 인라인이 시작하므로 채팅 화면 그대로(장면 고르기 칸이 거기 있음).
- **A.i 친구 `?practice=dubbing`**(더빙 연습) — 입력칸에 문장을 넣어 두고 학생이 보내는 흐름이라.
- **웜업 엘리더잼 책**(`WCTX.textbook` 이 `엘리더잼 L…`) — 진행 막대(질문 N/20·남은 횟수)가 채팅 쪽에 있어서. 같은 페이지에서 일반 교재로 다시 시작하면 그때 엽니다(«한 번» 을 엘리더잼이 먹지 않음).

## 4. 검토했다가 버린 방법

1. **기기(UA)로 «폰만» 자동으로 열기** — 지시가 PC·태블릿에도 각각의 배치를 원했고, 배치는 이미 창 폭으로 갈립니다.
2. **«✕ 로 닫았다» 를 기억해 다음 방문부터 채팅 화면** — 사장님 지시가 «기본» 이라 매번 엽니다.
3. **검사에서 `navigator.webdriver` 면 안 열기** — 검사가 실제 기본 화면을 안 보게 됩니다. 대신 검사가 사람과 같은 길(✕)로 닫습니다.

## 6. 남은 것 / 주의할 것

- **소리 자동재생** — A.i 친구는 누르기(제스처) 없이 열리므로, 브라우저가 소리를 막으면 첫 인사가 «글자만» 나오고(`audioEl.play()` 거절은 끝난 것으로 처리 — 멈추지는 않음) 마이크는 «눌러 말해요» 로 기다립니다. 한 번 누르면 그 뒤는 자동. 웜업은 «시작» 누르기가 제스처라 해당 없음. ⚠️ 실제 폰(같은 사이트에서 넘어온 탭)에서 브라우저가 허락하는지(=첫 마이크가 바로 자동인지)는 못 쟀습니다.
- 친구 고르기·🗺 주제·수준 제안 상자는 얼굴 화면 «뒤» 에 있습니다 — ✕ 로 닫아야 보입니다. 오늘의 A.i 학습 알약(today-bar)도 얼굴 화면 밑에 가립니다.
- ✕ 뒤 `FriendAutoTalk`(채팅 쪽 자동 대화)는 쉬는 상태로 남습니다(얼굴 화면이 멈춰 둔 것 — 원래 동작).
- 브라우저 검사 대부분은 얼굴 화면을 ✕(또는 `exit()`)로 닫고 예전 채팅 화면을 검사합니다 — 그 검사들이 «얼굴 화면이 기본» 을 지키지는 않습니다(지키는 것은 `ftk_call_harness` ⑦⑧·`ai-speaking-browser`·`ai-friend-facetalk`·`ftk-call`·`warmup-setup-reach` «먼저 열린다» 줄).
- 돌아가는 길은 ✕(얼굴 화면 닫기) → «모드 선택» 두 번입니다.
- 사장님이 보낸 옛 화면 사진(버튼 글자 없음)은 열려 있던 옛 탭입니다 — 새로고침하면 새 파일을 받습니다(HTML 은 매번 새로 받음).
