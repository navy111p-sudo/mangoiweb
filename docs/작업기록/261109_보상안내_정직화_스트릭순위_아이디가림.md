- 브랜치: `fix/reward-copy-streak-privacy`

## 1. 왜 했나

룰라 앱의 단점 «Streak·Gems·Stars 를 어디에 쓰는지 안내가 없다» 를 우리 쪽에 대조했더니 같은 문제가 더 크게 있었다.

- **🔴 공개 `GET /api/streak/leaderboard` 가 무인증으로 학생 아이디 + 실명 20명분을 내줬다.** 학생은 비밀번호가 없어 «아이디 = 로그인» 이다(api-points.ts 2026-08-28 주석). 포인트 랭킹·단어왕은 고쳤는데 연속 출석 순위만 빠져 있었다. 화면(streak.html)은 아이디를 그대로, 이스케이프 없이 그렸다.
- 스트릭 화면이 보너스를 «한 번 받는 마일스톤» 처럼 그렸다(지운 줄 처리). 서버는 그 단계부터 **매일** 주고(else-if 라 가장 높은 단계 하나만), 기본 +10 은 화면에 없었다.
- 순위 제목 «이번 주 리더보드» — 실제 정렬은 전체 기간 `current_streak`.
- 보석이 무엇인지 어디에도 안내가 없었다. 조사 결과 **보석은 쌓이기만 하고 쓰는 곳이 없다**(상점·환전·보호권 모두 없음).
- FAQ 포인트 답에 하루 상한·교환 최소액·유효기간이 없었다.

## 2. 무엇을 바꿨나

- `src/api-games-streak.ts` — 공개 응답은 `{student_name, current_streak, longest_streak, me}` 만. 이름이 아이디와 같으면 null, 게스트(`/^guest/i`) 제외, 본인 표시는 `?uid=` 정확일치로 서버가 `me` 판정. **관리자 세션(`checkAdminSession`)이면 종전 원본 행 그대로** — adm-core.js «연속 출석 랭킹» 이 같은 주소를 쿠키로 부르기 때문.
- `public/streak.html` — 보석 표(매일 +10 · 3/7/14/30일째부터 매일 보너스), 지금 받는 단계 하나에만 ✓, «보석은 포인트와 따로, 포인트상점에서 안 씀» 안내, 순위 제목 «연속 출석 순위 (전체 기간)», 이름 이스케이프 · «(나)». 전부 data-ko/data-en.
- `public/faq.html` — 포인트 답에 1P=1원·하루 100P(게임·퀴즈 30P)·3,000P부터 교환·12개월 소멸, 보석 문항 추가(한·영).
- 하니스: `public_api_auth_harness` 에 연속 출석 순위 5건, `badges_streak_module_boundaries_harness` 의 리더보드 계약을 «공개=아이디 없음 / 관리자=원본» 둘로, 새 `reward_copy_honesty_harness`(화면 숫자를 서버 정본에서 읽어 대조).

## 3. 검토했다가 버린 방법

- **관리자용 `/api/admin/streak/leaderboard` 신설** — 깔끔하지만 index.ts 전달 목록(공동 금지구역)과 adm-core.js(관리자 영역)를 함께 고쳐야 한다. 같은 주소에서 관리자 세션만 원본을 주면 두 파일을 안 건드린다.
- **홈 출석체크(js/idx-daily-checkin.js) 문구도 함께 수정** — «7일 연속 +20P · 30일 연속 +100P»(규칙 2026-07-30 꺼짐, 지급 코드 없음)와 학습목표 «자동으로 포인트가 적립됩니다»(진행도 갱신 코드 없음), 랭킹 제목 «이번 달»(실제 누적)은 **고쳐야 맞다.** 그런데 그 JS 는 index.html 이 `?v=2` 로 부르고 immutable 1년 캐시라 `?v=` 를 올려야 하고(asset_version_harness), index.html 은 공동 금지구역이다 → **A 담당 승인 뒤 별도 PR.** 패치는 준비돼 있다.
- **보석을 포인트로 합치거나 쓰임을 만드는 것** — 회계·포인트상점에 걸리는 정책 결정이라 사람이 정한다. 이번에는 «쓰는 곳이 없다» 를 정직하게 알리는 것까지만.
- 룰라 보고서 1단계의 나머지(A-1 대답 먼저·교정 나중, A-3 나이별 기본 교정, B-1 문장 사이 쉼, A-5 홈 이어하기)는 손대지 않았다 — A-3 은 2026-10-31 사장님 지시(«모든 학원·모든 학생의 기본은 집중교정», warmup-honest.ts:17)와 정면으로 부딪히고, A-1 은 261108 작업에서 «질문을 먼저 말하면 안 된다» 로 기각된 방식, B-1 은 «문장마다 잘게 나누지 않는다»(warmup.html `_speechChunks`) 설계, A-5 는 index.html.
