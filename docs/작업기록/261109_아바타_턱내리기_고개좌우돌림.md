## 3. 왜 그렇게 풀었나 — 검토했다가 버린 방법

- **실사 기본 영상 + 입 주변만 신경망 재생성(경쟁 앱 추정 방식)** — 가장 그럴듯하지만 캐릭터마다 «고개 돌리고 깜빡이는 4~5초 영상»을 새로 만들어야 하고(생성 비용·사람 검수), 서버 GPU 또는 큰 클라이언트 모델이 필요. 시안 범위 밖 → 다음 단계 후보로 남김.
- **WebGL 셰이더로 매끄러운 워프** — 품질은 가장 좋지만 컨텍스트·폴백·소실 처리 코드가 늘고, CI 의 SwiftShader 에서 입모양 타이밍 검사가 느려질 위험. 기존 `browWarp` 와 같은 2D «세 토막 직선» 으로 충분히 보였음.
- **세로 띠 여러 개(메시)로 고개를 돌리기** — 토막 경계에 반투명 이음매·계단이 생기고 drawImage 수가 수십~백 배. 띠 «하나» 를 가로 세 토막으로 미는 쪽이 같은 효과에 4번 그리기.
- **띠를 source-over 로 얹기** — 턱 옆이 배경(투명)인 곳(Noah 등)에서 옛 윤곽이 밑에 남아 «이중 턱». destination-out → lighter 로 정확히 섞음.
- **턱 크기 D 를 크게** — 경쟁 앱만큼 크게 하면 턱 밑 목이 (bot-b1)/(bot-b1-D) 배로 접혀 보임 → 1.5배 이하(하니스가 봄). 지금 D=8~9px(원본) = 화면 약 4~5px.

## 5. 남은 것 / 주의할 것

- Mei·Long(3장 그림 경로)은 턱 움직임 없음(고개 돌림은 됨).
- 2.5D 라 귀·옆얼굴이 실제로 돌아 보이지는 않음. 더 실사에 가깝게는 §3 첫 줄(기본 영상 + 입 재생성).
- 입 칸 경계의 희미한 가로 이음매는 v20 부터 있던 것(이번에 안 고침 · 턱이 내려가면 함께 내려감).
- JAW 표 값은 초상화를 눈으로 재서 정함 — 캐릭터 그림을 바꾸면 함께 다시 재야 함(`HEAD`·`EYES` 와 같은 사정).
