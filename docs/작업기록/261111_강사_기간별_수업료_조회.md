# 강사 화면 「기간별 수업료 조회」 (Class fee summary by date) — 2026-11-11

## 1. 왜 했나
사장님 요청: 강사가 정해진 날짜의 급여를 직접 확인할 수 있게, 시작일~종료일을 골라 조회하고
**수업 시간 · 학생 이름 · 학생 ID · 인센티브 · 수업료 · 합계**를 보여 달라.
참고 화면은 옛 LMS 의 「2022-08-16 To 2022-08-26 [Search]」 표였다(Lesson Time · Student · Status · Lesson Type · Level · Incentive · Total).

## 2. 한 것
- `teacher.html` 「수업료 정산 (이번 달)」 카드 바로 밑에 새 카드 `#c-feesum` 을 넣었다. 펼칠 때만 불러온다(첫 화면 API 계약 유지).
- 날짜 입력은 `<input type=date>` 두 개 + [조회]. 기본값은 이번 달 1일 ~ 오늘(`DATA.today`, KST).
- 열: 수업 시간 · 학생 · 학생 ID · 상태 · 수업료 · 인센티브 · 공제 · 합계. 맨 위에 기간·강사·등급·합계 한 줄, 맨 아래에 합계 줄.
- 상태 알약은 기존 «건별 명세» 와 **같은 함수**(`payStatusPill`)를 쓰도록 밖으로 꺼냈다(복제 없음).
- 언어 전환 때는 `repaintMy()` 가 다시 그린다.

## 3. 검토했다가 버린 방법
- **서버에 `from`/`to` 를 받는 새 기능** — 요청 한 번으로 끝나는 장점은 있지만, 월 계산(`computeLessonFeeMonth`)이 원래 월 단위라
  서버에서도 결국 달마다 한 번씩 돈다. 화면이 기존 월 API 를 걸친 달만큼 부르면 서버 수정이 0줄이고, 강사 본인만 보이는 제한도
  서버가 이미 강제한다. 그래서 화면 쪽만 고쳤다. 대신 한 번에 **3개월**까지만 받는다(달마다 서버 계산 1회).
  더 긴 기간이 필요해지면 그때 서버에 `from/to` 를 받게 하면 된다.
- **인센티브 값 채우기** — 저장소 어디에도 수업별 인센티브 자료·규칙이 없다(평가 점수가 «인센티브 근거가 된다» 는 주석뿐).
  없는 값을 0 이나 추정치로 채우지 않고 «—» 와 안내 문구(「아직 시스템에 기록된 것이 없습니다」)로 둔다. 규칙이 정해지면 그 칸을 채운다.
- **공제 열 생략** — 요청 목록에는 없지만, 빼면 «수업료 − ? = 합계» 가 설명되지 않아 넣었다.
- **기존 «건별 명세» 를 새 표로 바꾸기** — 지우는 변경이라 하지 않았다. 둘 다 남는다.
- **1~15일 / 16일~말일 같은 빠른 선택 버튼** — 요청에 없어 뺐다.

## 4. 알려진 한계
- 카페24 급여만 있고 D1 예약표에 수업이 없는 강사는 이 표가 0건이다(기존 «건별 명세» 와 같은 원천이라 같은 한계).
- 합계는 수업별 순지급(`net_amount`, 0 하한)의 합이다. 월 화면의 «실지급» 은 월 합계에 0 하한을 걸므로,
  단가 0 강사처럼 공제가 수업료보다 큰 수업이 있으면 두 숫자가 다를 수 있다.
