## 2. 2번 — 수업 요약 / 캘린더에서 «✎ 피드백 작성»

- **서버가 정한다**: `src/teacher-student-history.ts` `markWritableLessons()` 가 수업마다 `can_write` 를 단다.
  모두 참일 때만 true — ① 내 수업 ② 보고서가 필요한 상태(done·student_absent·late_postpone·unknown) ③ 보고서 없음
  (`feedback`·`today_eval` 둘 다) ④ 보고서 확인 자체가 됐음(`report_loaded !== false`) — **쌍둥이 계정 보고서를 못 읽었으면
  (경고 `twin_account`) 그 달 버튼 전부 없음**(못 읽은 보고서를 «미작성» 으로 보면 두 번째 일지 = 학부모 문자 두 번)
  ⑤ 옛 LMS 가 그 시각을 «다른 강사가 했다» 고 하지 않음(`lms_disagrees`) ⑥ 방·학생 계정 있음 ⑦ 이미 시작함(KST).
- **«내 수업» 판정** (`isMyLesson` — `src/api-teacher.ts` student_history 라우트 `withWritable` 이 부름):
  - 예약 수업 — 그날 «최종으로 보이는 강사 이름»(대체강사·강사 변경 반영 뒤)이 내 연결 강사 번호의 `teachers.name` 과 **정확히** 같을 때.
    부분일치 금지. 대체강사는 자기가 맡은 날만.
  - 옛 LMS 수업 — 카페24 강사번호가 내 번호(`resolveCafe24TeacherIds`, 0~1개)와 같을 때. 번호(`lms_teacher_uid`)는
    판정 뒤 응답에서 지운다(카페24 번호가 화면으로 나가지 않게).
  - 모르면 «내 것 아님»(버튼 없음). 판정이 던지면 이력은 그대로 보이고 버튼만 없다.
  - 매니저도 같은 규칙 — 직접 가르친 수업에만(매니저 겸 강사), 남의 수업에는 안 나온다.
- **화면** (`public/js/teacher-student-history.js` v6): 월 보기 칸·목록 보기 수업 밑에 `✎ Write feedback / 피드백 작성`.
  폰(≤600px) 월 칸은 ✎ 아이콘만(접근성 이름은 전체 문구). 누르면 캘린더가 닫히고 **닫힘 처리가 끝난 뒤**
  지금 쓰는 수업 일지 창(`teacher.html` `openEval`)이 열린다(먼저 열면 닫힘 처리가 포커스를 뒤로 뺏는다).
- **teacher.html `historyEvalItem()`**: 그 수업의 계정(`row.student_uid` — 쌍둥이 계정이면 그쪽)만 쓴다.
  이름·레벨은 «같은 계정» 의 오늘/주간 줄에서만 빌린다. 출결은 «학생 결석» 으로 기록된 수업만 결석을 미리 고르고
  나머지는 강사가 고른다(지어내지 않음). 저장·학부모 문자는 기존 일지 창 그대로.

### 알려진 한계 (사람이 정할 일)
- **나이 제한 없음** — 몇 달 전 수업에도 쓸 수 있고, 일지는 늘 학부모 문자(`notify_parent:true`)가 나간다. 주간 보기의 기존
  «피드백 작성» 도 같다. 제한(예: 14일)이 필요하면 정해 주세요.
- 학생이 오늘·이번 주 목록에 없으면(쌍둥이 계정 등) 일지의 학생 이름이 비어 저장된다(아이디는 정상). 저장·문자는 된다.
- `/api/eval/manual-create` 는 원래부터 «그 방·학생이 이 강사 것인지» 를 서버에서 확인하지 않는다(이번 변경 전부터).
  `can_write` 는 화면 게이트다.
- 옛 LMS 강사 이름이 모호(같은 번호에 이름 둘)하면 예약 카드와 합쳐진 채 예약 강사로 보인다(기존 병합 규칙).

### 검토했다가 버린 것
- 화면이 «내 수업» 을 추측(이름 비교)하게 두기 — 대체강사·강사 변경·옛 LMS 번호를 화면이 모른다. 서버 판정으로.
- 캘린더 칩(`<button>`) 안에 버튼 넣기 — 버튼 중첩은 HTML 위반. 칩 옆 별도 버튼으로.
- 맨 위 «이전 수업 / 담당 교사» 칸에도 버튼 — 같은 수업이 아래 달력에 있어 중복. 안 넣음.

## 3. 1번 — «끝난 수업 연기» 진단 (코드 수정 없음)

[잰 것 — D1 SELECT 만, 2026-11-11]
- **시간이 지난 수업도 연기는 된다.** 수업 시각이 지난 뒤 낸 연기·변경이 정상 승인된 예: #26(10/29 07:40 수업, 16:35 요청),
  #29(10/29 19:00 수업, 10/30 요청), #42(11/10 16:30 수업, 17:44 요청). 서버 `/schedule-requests`·`/decide` 와
  연기 창에는 «시작 시각이 지났으면 막기» 규칙이 없다(일괄 연기만 끝난 줄을 뺀다).
- **실패는 특정 수업에서 반복됐다**: `lby01` + 강사 BELLE(teachers.id 2) 월 14:00 수업.
  - #31 (11/2 14:00 수업, 14:21 Maimai 연기) · #40 (11/9 14:00 수업, 17:39 Maimai «한 회 뒤로 밀기» → 2027-04-12)
  - 둘 다 요청은 만들어졌는데(#40 은 알림 큐 1179 까지 기록됨) **승인도, 창이 자동으로 보내는 반려도 반영되지 않아**
    «대기» 로 남았다가 15분 정리 작업이 «자동정리(수업 시각 지남)» 로 닫았다.
  - 매번 1분 안에 Maimai 가 그 수업을 **취소**(class_audit_log remove 307·370)했다 → 화면에서 «연기 실패» 를 보고 취소로 대신한 것.
  - 그 수업은 열리지 않았다(attendance `class-4328-20261109` 0건) — 연기가 맞는 조치였다.
- **원인은 확정 못 함.** 오류 문구는 D1 에 남지 않고 Workers 로그는 5% 표본이다.
  후보: 승인 트랜잭션의 가드 스냅샷(`schedule-request-atomic.ts`)이 «그 강사의 전체 수업 + 그 학생의 전체 수업» 을
  JSON 으로 한 문장에 묶는데, BELLE+lby01 은 행 458개·약 81KB(다른 성공 건 BELLE+다른 학생 73KB, KRYSTEL+lby01 49KB)로
  D1 «한 문장 100KB» 한도 근처다. 단, 그렇다면 뒤따르는 «반려» 는 작아서 성공했어야 하는데 그것도 반영되지 않았다 —
  그래서 D1 일시 과부하(조사 중 실제로 `D1 DB is overloaded` 429 를 봄)일 수도 있다. 둘 다 미확정.
- ⚠️ 가드 스냅샷은 수업이 쌓일수록 커진다 — 한도 가설이 맞다면 시간이 지나며 다른 강사·학생에도 번진다.
  다음 실패 때 화면에 뜬 문구(또는 Workers 로그)를 받으면 확정할 수 있다.
