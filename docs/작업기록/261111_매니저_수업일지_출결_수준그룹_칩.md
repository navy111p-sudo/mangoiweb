# 2026-11-11 매니저·관리자 수업일지 창 — 학생 레벨 · 수업 출결 · 수준 그룹 칩

## 1. 왜 했나
매니저 제안: «매니저 화면에도 강사 화면과 같은 일지(지난·오늘 수업) — 학생 레벨·수업 출결까지».
확인해 보니 «오늘 전체 수업» 줄과 📄 전문 보기에는 레벨·출결이 **이미 보이고** 있었다.
빠진 것은 **쓰기(➕)·고치기(✏️) 창**이었다 — 글 두 칸뿐이라 매니저가 쓴 일지는 출결이 늘 «기록 없음».

## 2. 한 것
- 공용 창 `js/eval-quick-view.js` (관리자·매니저·강사 세 화면이 같이 씀)
  - ➕ 쓰기: 학생 레벨(보기만) · 출결 칩(출석·지각·결석) · 수준 그룹 칩(새싹·자람·열매, 선택)
    - 출결은 «오늘» + 입장 기록이 attended/late/absent 일 때만 미리 고름. «지난»·모름·대기는 안 고름.
    - 안 고르면 안 보낸다(서버 null). 레벨은 안 보낸다 — 서버가 저장 순간 학생 원부에서 읽는다(기존 규칙).
  - ✏️ 고치기: 저장 당시 레벨(보기만) + 출결 칩(저장값 켜짐). 바뀐 경우만 PATCH 에 싣는다. 끄면 `''` → 지움.
  - 칩 속성은 `data-evq-chips` — `data-evq-pick` 은 «어느 수업인가요?» 고르기 칸이 이미 쓴다.
- 서버 `PATCH /api/eval/:id` (`src/api-lessons.ts`): `attendance_status` 를 받는다.
  목록 안 값 또는 `''`(지움)만. 그 밖은 **400 `bad_attendance_status`** — 잘못 보낸 값으로 기록이 조용히 지워지지 않게.
  고치기 전 값은 기존 `edit_history` 에 남는다. 권한은 기존 `evalEditAllowed` 그대로(강사=자기 것, 본사=전부).
- 부르는 쪽: 관리자·매니저는 `level`·`attendance`, 강사는 `level`·`eval_band` 를 창에 넘긴다.
- `?v=`: `eval-quick-view.js` 4→5(세 곳) · `adm-today-classes.js` 69→70.

## 3. 검토했다가 버린 것
- **본사 매니저도 CEFR 레벨 지정** — 지금 레벨 저장 API 는 «강사 본인 학생만»(`teacher-student-level.ts`).
  레벨을 바꾸면 판단력 훈련 밴드가 초기화되는 등 영향이 있어 **사장님 결정 사항**으로 남김.
- **점수(1~5)·빠른 태그까지 똑같이** — 매니저는 수업을 직접 보지 않아 점수를 매기기에 맞지 않음(기존 원칙 «별점은 강사 일지 창의 몫»).
- **PATCH 에서 목록 밖 값을 null 로 받기** — 오타 하나로 기존 출결이 지워진다 → 400 으로 거절.
