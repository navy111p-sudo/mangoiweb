# 수업 «옮기기» 를 「수업 추가」로 한 것 — 같은 날 되묻기 + 「추가된 수업」 칸

- 작업자: Claude (사장님 전달 매니저 제보)

## 1. 왜 했나

매니저 제보(화면 사진, 11/10 KAYE 줄): 「Teacher Kaye 수업을 9:30 PM 으로 옮겼는데 시스템에 안 보인다.
옮기기·연기·취소한 정확한 시각을 Mangoi AI 에 보여 줄 수 있나?」

[잰 것 — 운영 D1, SELECT 만]
- 원래 수업 #4284(jye46712 · KAYE · 2026-11-10 13:20)는 **그대로 `active`**, 옮김 이력 없음.
- 20:57:51 KST 에 `Melca (본사 매니저)` 가 **새 수업 #8370(21:30)을 «추가»** — `class_audit_log.action='add'`.
- 출석: 강사 13:20 옛 방(학생 안 옴) → 21:06 새 방 → **21:34 옛 방 다시** → 21:37 새 방 → 21:48 학생 입장.
- 「취소·연기」 칸은 연기·변경·취소 이력만 읽어 `add` 를 몰랐다 → «—».
- 같은 모양이 11/04 에도 있었다(Melca 가 2분 간격으로 19:30·21:20 두 수업을 추가, 둘 다 active).
- 지금까지 `add` 이력 43건(날짜 수업 22건), 그중 같은 날 다른 수업이 있던 것 6건.

즉 «기능이 없다» 가 아니라 «옮기기 버튼 대신 추가 버튼을 썼고, 화면이 그걸 막거나 기록하지 않았다».
옮기기(📅 Move)로 했으면 칸에 「📅 11/10 13:20 에서 옮김 · Melca · 11/10 20:57」이 이미 떴다.

## 2. 무엇을 바꿨나

- `src/schedule-conflict.ts` — `sameDayAddNotice(rows, date)` (순수 함수): 같은 날 수업 시각을 모아 KO/EN 안내.
- `src/api-admin-scheduling.ts` — `POST /api/admin/class-schedules`: 일회성 추가일 때 그 학생의 그 날 수업을
  **한 번만** 읽어(겹침 검사와 공유) 겹침이 없는데 같은 날 수업이 있으면 **409 `conflict` + `same_day`**.
  `force:true` 면 그대로 등록(보강).
- `src/class-change-state.ts` — 이력 `add` 도 읽고, 옮김이 없으면 «➕ 추가된 수업 / ➕ Added class» + 언제(누가는 본사·내부직원만).
  우선순위: 취소 > 연기 > 옮김 > 추가. 매주 반복 행은 여전히 null.
- 화면(한 줄씩): `admin/weekly-schedule.html` 확인창 2곳이 EN 화면이면 `message_en` 을 씀(영어 쓰는 매니저에게 한국어만 뜨던 것),
  `admin/student.html` 확인창에 영어 문구 덧붙임, `manager.html`·`branch.html` 은 «추가» 를 경고색(hot)이 아닌 옮김과 같은 색으로.
- `test-harness/class_add_same_day_harness.mjs` (자동).

## 3. 검토했다가 버린 방법

- **새 오류코드(`student_same_day`)로 돌려주기** — 화면 두 곳(주간 시간표·학생 상세)에 새 처리 코드를 넣어야 한다.
  둘 다 이미 `409 conflict` 를 «확인창 → force 로 다시 보내기» 로 처리하므로 같은 코드를 쓰면 화면 수정이 문구 한 줄로 끝난다.
- **확인창에 [📅 그 수업 옮기기] 버튼** — `confirm()` 은 버튼이 둘뿐이다. 안내 문구로 «취소하고 그 줄의 📅 연기·변경» 을 말하는 것으로 줄였다.
- **같은 날 추가를 막기** — 보강으로 같은 날 한 번 더 넣는 일이 실재한다(11/04 건이 보강일 수도 있다). 되묻기만.
- **`findScheduleConflicts` 안에 넣기** — 이동·수강 운영 경로도 같은 함수를 써서 그쪽 동작까지 바뀐다. 추가 경로에만 둔다.
- **«7일 안에 추가된 수업만» 칸에 표시** — 처음 제안했지만 `add` 이력이 석 달간 22건뿐이라 소음이 없다. 조건을 뺐다.
