# 상황별 말하기 후속: 응답 본문과 기기 음성 수명 관리

이전 수정에 이어 응답 지연과 입 움직임을 점검했다.

재현: fetch는 헤더 도착 시 완료되어 기존 warmupFetch의 20초 타이머와 취소 목록이 그때 해제됐다. JSON 본문이 중간에서 멈추면 보내기 잠금이 끝나지 않고 화면 이탈 때도 요청을 취소하지 못했다. 변경 전 하니스는 취소 목록이 0개여서 실패했다.

수정: 기존 응답의 json 읽기에 20초 제한과 동일 AbortController를 적용한다. 정상 완료·JSON 오류·이탈·시간 초과에서 타이머와 이벤트를 정리한다. SSE 본문과 기존 읽기 제한은 유지한다. 자동 재전송은 추가하지 않는다. 헤더 대기 제한과 본문 읽기 제한은 각각 20초다.

기기 음성 폴백은 pause/resume 이벤트를 처리하지 않아 일시정지 중에도 입 움직임 타이머가 계속 돌았다. 일시정지 때 입을 닫고 타이머를 정리하며 재개 시 하나만 실행한다. 취소된 이전 음성의 늦은 이벤트는 새 아바타에 영향을 주지 않는다.

로컬 검증: 본문 타임아웃·취소·정상·오류·SSE 보존 하니스 통과. 자동 말하기 107개, 인증 헤더 13개, 스트리밍 138개, 속도 요청 44개 통과. Chromium은 이 환경의 소켓 권한 제한 때문에 GitHub의 기존 브라우저 워크플로에서 실행한다. 브라우저 회귀에 실제 HTTP 헤더와 부분 본문만 보내고 멈추는 서버를 추가하여 6초 안내, 20초 후 버튼 해제·입력 보존·자동 재전송 방지를 검사한다. 최종 CI 결과는 PR에 기록한다.

정상 서버 응답 속도와 실제 기기의 발음별 입 모양을 완전히 해결했다고 주장하지 않는다. 변경 범위는 지연·정지 후 복구이며 DB와 권한은 바꾸지 않는다. 되돌릴 때는 이 PR 변경만 되돌린다.
