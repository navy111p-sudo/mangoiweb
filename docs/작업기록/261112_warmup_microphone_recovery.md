# AI 말하기 마이크 대기 복구 및 인식 검증 (2026-11-12)

## 재현과 범위
- 서버 전사 Promise가 끝나지 않으면 record도 끝나지 않고 busy=true가 유지됨. 녹음이 이미 멈춘 뒤 cancel해도 풀리지 않았음.
- warmup에서 일시적인 live peak 하나가 speaking을 만들면 녹음 파일 검사를 건너뛰고 전사 문자열을 전송했음.
- peak도 전사도 없는 경우 학생에게 실패 안내가 없었음.
- 이는 코드/가상 마이크로 재현한 결함이며 학생 기기의 실제 권한·선택 장치·현장 음량 원인을 확정한 것은 아님.

## 변경
- 전사 fetch와 응답 본문까지 30초 제한, 네트워크 abort. 사용자 정의 전사 함수에도 녹음 세션의 30초 제한 적용.
- cancel은 권한 대기·녹음·전사 어느 단계든 즉시 빈 결과로 정리. 늦은 허용은 트랙 종료, 늦은 실패/성공은 무시.
- MediaRecorder 오류 시 트랙/타이머 정리. suspended AudioContext는 resume 시도.
- warmup 전사 결과는 live peak와 무관하게 기존 녹음 파일 검사에 통과해야 전송. 검사 도중 재녹음 경합 방지, 페이지/음성 epoch 재확인.
- 빈 결과·녹음 예외·시간 초과 안내 및 마이크 상태 복구. 작은 목소리 검사, 수동 전송, 영어 전치사 재검증 유지.
- 공용 JS v9→v10 모든 HTML 참조 갱신. 첫 화면 예산을 올리지 않고 기존 역사 주석 일부를 축약.

## 검증
- voice_early_harness 42: 기존 조기전사/수동/iOS/작은 뒷말 및 추가 무응답·응답 본문 정지·사용자 전사 정지·취소 후 늦은 응답·권한 대기 취소·새 녹음 재시도.
- warmup_quiet_mic_harness 34: 작은 발화·소음·충격음·전치사 재확인 및 peak 우회 차단·빈 응답 안내·예외 복구.
- voice_end_noise 18, voice_input_fallback 58, speech_recognition 34, voice_input_unify 24 통과.
- 인라인 JS 구문 및 첫 화면 무게 예산 통과. 자산 버전 해시 불일치 없음(로컬 sparse checkout의 34개 미포함 자산은 CI 전체 checkout에서 확인).
- 로컬 브라우저 실행은 환경의 socket 권한 제한으로 불가. GitHub 브라우저/전체 CI 결과가 병합 게이트.

## 제한·운영 확인·되돌리기
- 파형 검사는 사람/TV/다른 학생을 식별하는 음성 인증이 아님. 잡음 대비 신호 확인이며 실제 교실 기기 테스트가 필요함.
- 임계값을 임의로 낮추지 않았음. 아주 작은 발화가 녹음되지 않는 장치에서는 입력 장치·음량·권한 확인 필요.
- 수동 정지 후 전사 30초가 지나면 안내 후 재시도 가능해야 하며, 무음/잡음에서 대화 또는 점수 칭찬이 생성되면 안 됨.
- 회귀 시 이 PR을 revert 후 표준 main 배포. 서비스 워커/배포 설정/서버 평가 로직 변경 없음.
