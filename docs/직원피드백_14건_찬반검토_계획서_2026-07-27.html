수업 관찰이 별도 인증 없이 열림

P0채택

사실 확인: 지적이 맞습니다. 다만 실제 원인은 화면이 아니라 서버 인증 목록 누락이었습니다(위 0번 참조).

채택 근거
  • 미성년 학생의 실시간 영상·이름이 걸린 사안. 개인정보보호법상 영상정보는 목적 범위 내에서만 이용해야 하고, 접근 권한자 관리·교육이 요구됩니다.
  • 캠블리 키즈는 참관 주체를 학부모로 명시해 두고 정책을 공개합니다. 우리는 운영자 참관이 기록만 되고 통제는 없습니다.
  • 이미 참관 사유(reason)를 필수로 받고 감사 로그에 남기는 구조는 있습니다(api-admin.ts:6552). 게이트만 채우면 됩니다.
비용·주의
  • src/index.ts는 공동 금지구역 — 라우팅 게이트 수정은 반드시 A가.
  • 기본거부로 바꾸면 그동안 무인증으로 열리던 다른 화면들이 갑자기 로그인을 요구할 수 있습니다. 배포 전 /admin/* 전 경로 목록으로 회귀 확인 필요.
실행: ① rooms API 2개 인증 추가 ② isAdminPath 기본거부 전환 ③ 참관 시작 시 강사 화면에 “관리자 참관 중” 표시 검토(현재 notice_sent_to_others:false) ④ 하니스 검사 추가

“1,000명+ 검증된 강사” 문구 축소

P0채택 (법적 리스크)

사실 확인: 맞습니다. idx-grid-menu.js:811 “1,000명+ 검증된 강사들이 매일 7,000건+ 수업”, :396 “1,000명+ 원어민·전문 강사 풀”. 같은 모달이 바로 아래에서 “전체 강사진 (30명)”을 보여줍니다. 영문판까지 동일 문구가 번역돼 있습니다(i18n-sweep.js:951).

채택 근거 — 단순 과장이 아니라 제재 사례가 있는 영역
  • 공정위는 사교육 업체의 강사·집필진 규모 과장을 표시광고법 위반으로 제재했습니다. 메가스터디교육은 “박사진 15명·16명”이라 광고했으나 실제 박사 경력 1명으로 확인돼 제재를 받았습니다(2023). 강사 수 부풀리기는 전형적 적발 유형입니다.
  • 같은 화면에서 1,000명이라 하고 30명을 보여주는 건 학부모가 그 자리에서 바로 확인할 수 있는 불일치입니다. 신뢰 손상이 즉각적입니다.
  • 링글은 실제로 1,000명 이상의 튜터 프로필을 전부 열람 가능하게 두고 그 숫자를 씁니다. 우리는 숫자를 뒷받침할 노출이 없습니다.
반대 측 논리와 대응
  • “누적 등록 강사까지 세면 틀린 말은 아니다” → 광고에서는 현재 배정 가능한 인원으로 읽힙니다. 누적 기준이면 그렇게 명시해야 합니다.
  • 숫자를 줄이면 규모감이 떨어진다 → 대안: “20년 · 누적 수업 ○○만 건”처럼 검증 가능한 다른 숫자로 규모를 표현.
실행: 현재 재직 강사 수를 DB에서 SELECT로만 확정한 뒤(명부 기준 200명대로 파악됨) “검증된 정규 강사 ○○명” 형태로 교체. 한국어·영문 사전 동시 수정. 7,000건/일 수치도 같은 기준으로 근거를 확인해야 합니다.

중요 — 이모지로는 해결되지 않습니다. 사내 규칙상 Windows 10 호환 때문에 최신 이모지는 금지이고, 국기 이모지는 Windows에서 국가 코드 문자(“PH”)로 표시됩니다. 즉 다른 이모지로 바꿔도 같은 증상이 재발합니다. → SVG 아이콘 파일로 교체가 유일한 해법입니다.
채택 근거
  • “직영 센터”는 우리 핵심 차별점인데 아이콘이 깨져 있으면 설득력이 반감됩니다.
범위
  • 이 카드만이 아니라 국기 이모지를 쓰는 모든 화면을 함께 정리해야 재발이 없습니다(강사 소개 모달의 PH/US/GB/CN 필터 포함).

평가표 — 샘플 제공 + 셀프 비밀번호 찾기

P2조건부 채택 (둘로 분리)

사실 확인: 현재 평가표 로그인 화면은 “ID·비밀번호를 모르시면 카카오 채널로 문의”만 안내합니다(idx-grid-menu.js:1417, 1420). 샘플 보기는 없습니다.

(A) 샘플 평가표 — 강력 채택
  • 로그인 벽 앞에서 가치를 먼저 보여주는 전형적 전환 개선입니다. 링글은 수업 후 리포트 구성(총평 + 영역별 심층 피드백 + AI 분석)을 공개해 놓고 이를 설득 자산으로 씁니다.
  • 가망 학부모(계정 없음)에게 지금은 보여줄 것이 아무것도 없습니다.
  • 구현 비용 낮음 — 가상 학생 데이터로 만든 정적 샘플 1장.
(B) 셀프 비밀번호 찾기 — 보류 후 결정
  • 학생 계정에 본인확인 수단(이메일·휴대폰)이 실제로 채워져 있는지 먼저 확인해야 합니다. 미입력이 많으면 자가 재설정은 동작하지 않고, 무리하면 계정 탈취 경로가 됩니다.
  • 학생 다수가 미성년입니다. 본인확인 설계는 신중해야 합니다.
  • 중간 대안: “아이디 찾기”만 자가 처리 + 비밀번호는 카톡 유지(현행), 대신 안내 문구를 훨씬 눈에 띄게.
결론: 샘플은 이번 차수에 진행, 비밀번호 자가찾기는 계정 본인확인 정보 보유율 확인 후 별건으로 재상정.

신규결제 첫 화면 선택지 과다 → 단계형 필터

P2조건부 채택

사실 확인: 캡처 기준 첫 화면에 상품 타일이 15개 이상 한 번에 노출됩니다.

채택 근거
  • 힉의 법칙 — 선택지가 늘수록 결정 시간이 길어지고, 일정 수를 넘으면 “나중에 결정”이 “결정 안 함”이 됩니다. 요금제 페이지는 이 효과가 가장 강하게 나타나는 지점으로 꼽힙니다.
  • 업계 실무 권고는 3~5개 묶음. 캠블리 키즈·링글 모두 플랜을 소수로 압축하고 대상·기간을 먼저 고르게 합니다.
  • 직원 제안(대상 → 기간 2단계)은 그 정석과 정확히 일치합니다.
부분 반대 — 전체 가격표를 없애면 안 됩니다
  • 학부모 상당수가 비교표를 통째로 보고 싶어 합니다. 단계형만 남기면 “가격을 숨긴다”는 인상을 줍니다.
  • 결제 화면은 사고 반경이 매출입니다. 기존 화면을 지우지 말고 단계형을 기본으로 두고 “전체 요금표 보기” 링크를 남기는 방식으로.
  • 실제 판매 조합(대상×기간×횟수)이 코드에 하드코딩돼 있을 수 있어 재구성 공수가 커집니다 — 3~4일.
실행: 1단계 대상(키즈/일반/비즈니스/시험) → 2단계 기간(1/3/6/12개월) → 3단계 결과 2~3개 + 실시간 금액. 기존 전체표는 보조 링크로 유지.
