# 수업(`:Class`) — LMS에서 **연기·취소한 «시각» 과 «누가»** 를 실어 주세요

**받는 분:** 카페24 서버 담당자 (Neo4j :8880 에 `:Class` 를 적재하시는 분)
**보내는 곳:** 망고아이 개발
**날짜:** 2026-11-11
**성격:** **적재 요청** + 확인 질문 1개(5장). 2026-09-01 확인요청서
(`docs/카페24_수업취소표시_확인요청_2026-09-01.md`)의 질문 2(`class_state` 값의 뜻)도
아직 답을 못 받아 여기 함께 적었습니다.

---

## 1. 한 줄 요약

학생이 **LMS(mangoi.co.kr)에서 수업을 연기·취소하면, 그 사실이 `:Class` 에 남지 않습니다.**
그래서 망고아이 관리자 화면의 「취소·연기」 칸이 LMS 수업에는 늘 «—» 입니다.

👉 **`:Class` 에 «연기·취소한 시각», «누가 했는지», «새로 잡힌 수업» 을 속성으로 실어 주세요.**
(3장 표 — 이름·형식은 편하신 대로 정하시고 알려만 주시면 저희가 맞추겠습니다.)

## 2. 왜 필요한가 — 필리핀 매니저 요청 (2026-11-11)

망고아이 관리자 «오늘 수업» 목록에는 카페24(LMS) 수업도 함께 뜹니다. 매니저가 이렇게
요청했습니다.

> Would it be possible to include the exact date and time when a student postponed
> a class from the LMS? This would help us identify when the postponement was made
> and make it easier for us to monitor and track cancelled or postponed classes.
>
> (LMS에서 학생이 수업을 연기한 **정확한 날짜·시각**을 보여 줄 수 있나요? 언제 연기했는지
> 알면 취소·연기 수업을 관리하기 쉬워집니다.)

- **망고아이에서 연기한 수업은 이미 보입니다** — 「⏸ 연기됨 → 새 날짜」와 함께
  «누가 · 몇 월 몇 일 몇 시» 를 칸에 적습니다(망고아이 쪽 기록이 있기 때문입니다).
- **LMS에서 연기한 수업은 보여 줄 수가 없습니다** — 저희가 받는 값에 그 기록이 없습니다(3·4장).

매니저는 이 칸으로 «방금 연기가 들어왔다 → 강사에게 알리기» 를 하려는 것이라,
**연기를 «누른 시각»** 이 핵심입니다(수업 시각과 다릅니다).

## 3. 부탁드리는 속성

`:Class` 노드(수업 한 회차)에 아래를 실어 주세요. **연기·취소가 없는 수업은 비워 두시면
(null) 됩니다.**

| 속성 (예시 이름) | 뜻 | 형식 (예시) | 꼭 필요? |
|---|---|---|---|
| `postponed_at` | 이 수업을 **연기한 순간**(버튼을 누른 시각) | `"2026-11-09 13:05:22"` (KST) 또는 epoch ms | ✅ 꼭 |
| `postponed_by` | 누가 연기했나 | `"student"` · `"parent"` · `"staff"` · `"teacher"` · `"system"` 중 하나 | ✅ 꼭 |
| `postponed_to_class_id` | 연기로 새로 잡힌 수업의 `class_id` (날짜 미정이면 null) | `"519999"` | 있으면 좋음 |
| `cancelled_at` | 이 수업을 **취소한 순간** | 위와 같은 형식 | ✅ 꼭 |
| `cancelled_by` | 누가 취소했나 | `postponed_by` 와 같은 값 | ✅ 꼭 |
| `change_reason` | 사유(학생이 적은 글 등) | 문자열, 200자 이내 | 선택 |

📌 **부탁 세 가지**

1. **행(노드)을 지우지 말아 주세요.** 연기·취소된 원래 수업도 그대로 남기고 위 속성만
   채워 주시면 됩니다 — 저희가 지난 수업 기록·강사 급여 대사에 씁니다(9/1 문서와 같은 부탁).
2. **시각은 «KST» 인지 «UTC» 인지** 함께 알려 주세요. epoch ms 면 그대로 받겠습니다.
3. 이 값이 카페24 DB(MySQL) 원본 테이블에 **이미 있다면**(연기 신청 테이블의 등록 시각 등),
   새로 만드실 것 없이 **적재할 때 함께 실어 주시기만** 하면 됩니다.

## 4. 저희가 지금 읽는 값 — 이것만으로는 «연기» 를 알 수 없습니다

```cypher
MATCH (c:Class) WHERE c.date >= $since AND c.date <= $until
 RETURN c.class_id, c.user_id, c.start_ms, c.end_ms, c.date, c.class_state,
        coalesce(c.teacher_id, c.teacher_no, c.t_id) AS teacher_id
```

**잰 것** (2026-11-11, 망고아이 쪽 저장소 기준 · 숫자만 적고 학생 정보는 뺐습니다)

| 무엇을 | 결과 |
|---|---|
| 카페24 수업을 옮겨 만든 망고아이 시간표 행 | **6,594건 — 전부 «정상»**, 취소·연기 기록 0건 |
| 그중 «카페24에서 수업이 사라져» 저희가 내린 행 | **0건** |
| 2026-10-01 이후 행 3,879건의 카페24 원본 | **전부 같은 날짜·같은 시각으로 남아 있음** (옮겨지거나 사라진 것 0건) |
| 최근 30일 지난 수업의 상태 | 완료(`class_state=2`) 2,377건 · 그 외 1,116건 |

**거기서 내린 판단** (확인은 5장 질문으로)

- 학생이 LMS에서 연기해도 **원래 `:Class` 는 날짜·시각이 그대로 남는 것으로 보입니다**
  (사라지거나 옮겨진 것이 한 건도 없었으므로).
- 그렇다면 연기된 수업과 «아직 안 한 수업» 이 저희 쪽에서는 **똑같이 보입니다**.
- 지난 수업 1,116건 안에 결석·연기·취소가 섞여 있을 것인데, 저희는 `class_state` 를
  «2 = 완료, 나머지 = 예정» 으로만 쓰고 있어 **그 안을 가를 수 없습니다.**

## 5. 확인 질문 (답만 주셔도 큰 도움이 됩니다)

1. **학생이 LMS에서 연기하면 원래 `:Class` 는 어떻게 됩니까?**
   (ㄱ) 그대로 남고 `class_state` 만 바뀐다 (ㄴ) 그대로 남고 아무것도 안 바뀐다
   (ㄷ) 날짜·시각이 새 날짜로 바뀐다 (ㄹ) 지워지고 새 `:Class` 가 생긴다
2. **`class_state` 에는 어떤 값들이 들어갑니까? 값마다 뜻은?**
   (예: `1`=예정, `2`=완료, `3`=결석, `4`=연기, `9`=취소 …) — 9/1 문서 질문 2와 같습니다.
3. **연기·취소 기록(시각·누가)이 카페24 DB 원본에 이미 있습니까?** 있다면 테이블·칸
   이름만 알려 주셔도 됩니다.

## 6. 받으면 저희가 할 일

- 관리자 «오늘 수업» 의 **「취소·연기」 칸**에 LMS 수업도
  `⏸ LMS에서 연기 → 11/16 14:20` / `학생 · 11/09 13:05` 처럼 적습니다
  (망고아이 연기와 같은 모양 — 한국어·영어 둘 다).
- 연기된 원래 수업은 강사 시간표에서 **«연기됨» 으로 표시**해, 강사가 헛기다리지 않게 합니다
  (9/1 문서의 «유령 수업» 문제도 같은 값으로 함께 풀립니다).
- 확인은 아래 한 줄이면 됩니다(적재 후 0보다 크면 됩니다).

```cypher
MATCH (c:Class) WHERE c.postponed_at IS NOT NULL OR c.cancelled_at IS NOT NULL
 RETURN count(c)
```

저희 점검 화면에는 `:Class` 가 실제로 가진 **속성 «이름» 목록**이 이미 보이므로,

### English summary (for the Philippine staff)

- **Problem:** When a student postpones or cancels a class **in the LMS (cafe24)**, the data
  Mangoi receives (`:Class` in Neo4j) has **no postpone/cancel time and no "who"**, so the
  «Cancelled · Postponed» column shows «—» for LMS classes.
- **Already working:** postponements made **in Mangoi** already show «who · date time».
- **Request:** cafe24 adds `postponed_at`, `postponed_by`, `postponed_to_class_id`,
  `cancelled_at`, `cancelled_by` (names flexible) to each `:Class`, without deleting rows.
- **After that:** Mangoi shows «Postponed in LMS → new date · student · 11/09 13:05» in the same column.
