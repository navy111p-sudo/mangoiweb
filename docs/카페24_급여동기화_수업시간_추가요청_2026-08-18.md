# 급여 동기화에 「총 수업시간(분)」 한 칸 추가 요청

**받는 분:** 카페24 서버 담당자 (`/root/teacher-payroll-sync.sh` 를 관리하시는 분)
**보내는 곳:** 망고아이 개발 (워커 쪽은 이미 작업 완료 — 서버에서 보내 주시기만 하면 됩니다)
**날짜:** 2026-08-18

---

## 1. 한 줄 요약

매달 워커로 보내 주시는 급여 JSON에 **`total_minutes`(그 달에 실제로 가르친 분 합계)** 한 칸만
추가해 주세요. **나머지는 그대로**입니다. 워커 쪽은 이미 받을 준비가 끝났고, 안 보내셔도
지금과 똑같이 동작합니다(고장 나지 않습니다).

## 2. 왜 필요한가

망고아이 수업이 **20분 하나에서 20 / 30 / 40분 세 가지**로 늘었습니다.

강사 급여는 **「10분 토막 수 × 토막당 단가」** 로 계산합니다. 지금까지는 모든 수업이 20분이라
`수업 수 × 2` 로 토막 수를 구할 수 있었습니다. 이제는 **길이를 모르면 토막 수를 구할 수 없습니다.**

> 30분 수업 100회를 20분으로 계산하면 토막이 300개가 아니라 200개가 됩니다.
> **강사가 30분을 가르치고 20분 값을 받습니다.** 그대로 두면 임금 삭감이고, 강사 이탈로 갑니다.

지금은 이 값을 **급여 담당자가 매달 손으로** 관리자 화면에 넣게 되어 있습니다.
사람이 하는 일이라 **빠뜨리면 조용히 적게 지급**됩니다(빠뜨려도 화면이 멈추지 않습니다).
서버가 분을 함께 보내 주시면 **그 입력 자체가 없어집니다.**

## 3. 무엇을 바꾸면 되나

보내시는 위치·인증·주기는 **전부 그대로**입니다. 각 행에 칸 하나만 늘어납니다.

- 보내는 곳: `POST https://mangoi.ai/api/payroll-ingest?key=<지금 쓰시는 키 그대로>`
- 주기: 지금 그대로 (매달)

### 지금 보내시는 형태

```json
{ "rows": [
  { "teacher_id": 8, "teacher_name": "Jane", "year": 2026, "month": 8,
    "completed": 96, "total": 100, "pay_php": 5760 }
] }
```

### 바꿔 주실 형태 — `total_minutes` 한 칸 추가

```json
{ "rows": [
  { "teacher_id": 8, "teacher_name": "Jane", "year": 2026, "month": 8,
    "completed": 96, "total": 100, "pay_php": 5760,
    "total_minutes": 2160 }
] }
```

`total_minutes` = **완료된 수업들의 길이를 그대로 더한 값(분)**.
위 예시는 20분 60회 + 30분 32회 = 1,200 + 960 = **2,160분** 인 강사입니다.

- 이름은 `total_minutes` 를 권합니다. `minutes` 로 보내셔도 똑같이 받습니다.
- **완료(completed)된 수업만** 더해 주세요. 취소·노쇼는 빼는 것이 맞습니다
  (지금 `completed` 를 세시는 기준과 같게 맞춰 주시면 됩니다).
- 정수(분)로 보내 주세요. 소수점이 와도 반올림해 저장합니다.

### MySQL 쪽에서는 대략 이런 모양입니다

지금 `COUNT(*)` 로 완료 수업을 세고 계실 텐데, 그 옆에 합계를 하나 더 얹는 것입니다.
(컬럼 이름은 실제 스키마에 맞춰 주세요 — 수업 길이를 담고 있는 칸입니다.)

```sql
SELECT
  teacher_id,
  COUNT(*)                                AS completed,
  SUM(COALESCE(duration_min, 20))         AS total_minutes   -- ← 추가되는 부분
FROM classes
WHERE status = 'completed'
  AND YEAR(class_date) = ? AND MONTH(class_date) = ?
GROUP BY teacher_id;
```

> ⚠️ `COALESCE(..., 20)` 을 넣은 이유 — 옛 자료에 길이가 비어 있는 행이 있으면
> `SUM` 이 통째로 NULL 이 되거나 그 수업이 0분으로 빠집니다. **비어 있으면 20분**으로 봅니다
> (그것이 지금까지의 규칙이므로 값이 나빠지지 않습니다).

## 4. 안 보내면 어떻게 되나 (뒤로 호환)

**아무 일도 일어나지 않습니다.** 지금과 똑같이 동작합니다.

| 상황 | 워커의 동작 |
|---|---|
| `total_minutes` 를 보냄 | 그 값으로 급여 계산 (사람 입력 불필요) |
| 안 보냄 | 예전 규칙 그대로 — **전부 20분**으로 계산 |
| 예전에 보냈다가 이번에 빠뜨림 | **지우지 않고 이미 들어온 값을 유지**합니다 |
| `0` 이나 빈 값을 보냄 | 「안 보낸 것」으로 봅니다 (0분 지급 사고 방지) |

즉 **스크립트를 고치다 실수해도 급여가 0원이 되지는 않습니다.**

## 5. 값이 겹칠 때 누가 이기나

관리자 화면에서 급여 담당자가 직접 넣은 값이 **가장 셉니다.**

1. **사람이 화면에 넣은 값** (관리자 → 급여 관리)
2. **서버가 보낸 `total_minutes`**
3. 둘 다 없으면 **전부 20분**으로 가정

사람이 특별한 사정으로 고쳐 넣은 값을 다음 동기화가 덮어쓰지 않게 한 것입니다.
평소에는 1번을 쓰는 일이 없으므로 **서버 값이 그대로 급여가 됩니다.**

## 6. 보내신 뒤 확인하는 법

1. 응답이 `{"ok":true,"upserted":N,"received":N}` 인지 — `upserted` 가 보낸 행 수와 같아야 합니다
2. 관리자 화면 **급여 관리**에서 그 달을 열면, 「총 수업시간(분)」 칸에 숫자와 함께
   **「자동」** 이라는 작은 표시가 붙습니다. 이 표시가 보이면 서버 값이 쓰이고 있는 것입니다
3. 표시가 없고 회색 `~숫자` 이면 → **분이 안 들어온 것**입니다(전부 20분으로 계산 중)
4. 붉은 **「⚠️ 입력 필요」** 이면 → 그 강사에게 20분 초과 수업이 있는데 분이 없다는 뜻입니다.
   이 줄은 반드시 채워져야 합니다
