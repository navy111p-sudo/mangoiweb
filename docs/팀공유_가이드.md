# 🤝 클로드 코드 작업물, 팀에 공유하는 법

> 「클로드 코드로 내 계정에서 한 것들을 팀에 공유하고 싶다」 에 대한 답입니다.
> 결론부터 — **공유되는 것과 안 되는 것이 정해져 있고, 종류마다 방법이 다릅니다.**

---

## 1. 한 줄 요약

| 무엇을 | 어디에 두면 | 팀이 보는 법 |
|---|---|---|
| **작업 환경** (규칙·명령·에이전트) | 저장소 `.claude/` · `CLAUDE.md` | 클론하면 **자동 적용**. 설치할 것 없음 |
| **결과물 문서** (보고서·기획안) | 저장소 `docs/` | [docs/INDEX.md](INDEX.md) 목차에서 클릭 |
| **작업 판단 기록** (왜 그렇게 했나) | 저장소 `docs/작업기록/` | `/worklog` 로 남김 |
| **코드** | 깃허브 | PR → 병합 |
| **개발 안 하는 직원용** | 구글 드라이브 · Artifact 링크 | 링크만 누르면 됨 |

**정본은 언제나 깃허브입니다.** 드라이브·Artifact 는 «보기 편한 창구» 일 뿐,
거기서 고친 것은 저장소에 반영되지 않습니다.

---

## 2. 갈래별 방법

### 2-1. 클로드 코드 작업 환경 — ✅ 저장소로 자동 공유됩니다

이게 가장 중요합니다. **아무 설정 없이, 클론만 하면 됩니다.**

```bash
git clone --depth 50 https://github.com/navy111p-sudo/mangoiweb.git
cd mangoiweb
claude
```

이때 팀원의 클로드 코드가 자동으로 집어 가는 것:

| 파일 | 무엇이 공유되나 |
|---|---|
| `CLAUDE.md` | 작업 규칙 — 금지사항, 자주 밟는 함정. **클로드가 매번 자동으로 읽습니다** |
| `.claude/settings.json` | 허용/금지 명령 목록 (예: `wrangler deploy` 금지) |
| `.claude/commands/` | 슬래시 명령 — `/verify`, `/worklog`, `/newdoc` |
| `.claude/agents/` | 서브에이전트 — `trap-check` (함정 대조 검사) |

자세한 설명 → **[../.claude/README.md](../.claude/README.md)**

#### ⛔ 이것들은 저장소로 공유되지 **않습니다**

| 항목 | 왜 |
|---|---|
| `.claude/settings.local.json` | 개인 PC 전용. `.gitignore` 되어 있음 (그래야 맞습니다) |
| **MCP 연결** (깃허브·노션·구글 드라이브·클라우드플레어) | 각자 클로드 계정에 로그인해 붙이는 방식. 저장소에 적어도 남의 계정에선 안 붙습니다 → 각자 `/mcp` 에서 연결 |
| **대화 기록** | 2-3 참조 |
| `.env`, `.dev.vars` | **절대 올리지 마세요.** 사람에게 직접 받으세요 |

---

### 2-2. 결과물 문서 — 목차에 등록해야 «있는 문서»가 됩니다

`docs/` 에 이미 100개 넘는 보고서·기획안이 있지만, **목차가 없으면 아무도 못 찾습니다.**
그래서 [docs/INDEX.md](INDEX.md) 를 만들었습니다.

**새 문서를 만들면 반드시 목차에 한 줄 추가하세요.**

```
/newdoc
```

이 명령이 미등록 문서를 찾아 목차에 넣고, 링크가 실제로 열리는지까지 검사합니다.

> 💡 깃허브 웹에서 `.md` 파일은 그대로 예쁘게 보입니다. `.html`·`.pdf` 는
> 「Download」 를 눌러야 열리므로, 개발 안 하는 직원에게 보낼 때는 2-5 를 쓰세요.

---

### 2-3. 대화·세션 기록 — ❌ 자동으로는 공유되지 않습니다

**클로드 코드의 대화 기록은 작업한 사람의 계정·컴퓨터에만 남습니다.**
팀원 계정으로 넘어가지 않고, 팀 요금제로 묶어도 서로의 대화가 보이지는 않습니다.

그래서 **남길 가치가 있는 내용은 문서로 옮겨야** 합니다.

```
/worklog 가맹점 정산서에 B2B 매출 반영
```

→ `docs/작업기록/260818_가맹점정산서_B2B매출반영.md` 가 만들어집니다.

무엇을 남길지는 → **[작업기록/README.md](작업기록/README.md)**

#### 대화 전문을 통째로 옮기지 마세요

옮겨야 하는 건 **판단** 이지 **대화** 가 아닙니다. 특히 이 세 가지:

1. **왜 했나** — 어떤 제보·증상에서 출발했는지
2. **검토했다가 버린 방법과 그 이유** ← 가장 중요합니다. 코드에는 «택한 것» 만 남습니다
3. **확인한 방법** — 타입체크·하니스 결과, 사람이 화면에서 본 것

그리고 **새로 발견한 함정은 `CLAUDE.md` 2장 표에도 한 줄 넣으세요.**
작업기록은 사람이 찾아 읽어야 하지만, `CLAUDE.md` 는 클로드가 **매번 자동으로 읽습니다.**
같은 실수를 팀 전체가 안 밟게 하는 가장 효율적인 자리입니다.

---

### 2-4. 계정 · 접근 권한

| 팀원이 필요한 것 | 누가 주나 | 어떻게 |
|---|---|---|
| **깃허브 저장소 접근** | 저장소 소유자 | Settings → Collaborators → 이메일로 초대 → 팀원이 메일에서 수락 |
| **클로드 코드 사용** | 각자 | 각자 클로드 계정으로 로그인. 계정을 빌려주지 마세요 |
| **MCP 연결** | 각자 | 클로드 코드에서 `/mcp` → 필요한 것만 연결 |
| **배포 권한** | 저장소 소유자 | ⚠️ **아무에게나 주지 마세요.** 실학생 29,000명이 쓰는 서비스입니다 |

- 배포 권한이 없는 사람은 **코드만 고치고 PR 로 넘깁니다.** 이게 정상 동작입니다.
- 배포 권한자는 `deploy.ps1` 허용을 **자기 `.claude/settings.local.json`** 에만 넣으세요.
  공유 `settings.json` 에 넣으면 권한 없는 사람의 클로드도 배포를 시도하게 됩니다.

깃 사용법 전체 → **[개발_공동작업_안내_직원용.md](개발_공동작업_안내_직원용.md)** (쉬운 말로 되어 있습니다)

---

### 2-5. 개발 안 하는 직원에게 보낼 때

깃허브 계정이 없는 직원에게는 저장소 링크가 소용없습니다. 두 가지 창구가 있습니다.

| 창구 | 이럴 때 | 주의 |
|---|---|---|
| **구글 드라이브** | 완성된 PDF·PPTX·DOCX 를 그대로 넘길 때 | 폴더 하나를 정해 두고, 파일을 **덮어쓰기**로 갱신하세요. 새로 올리면 옛 링크를 계속 보게 됩니다 |
| **Artifact 웹페이지** | 보고서를 링크 하나로 바로 보게 할 때 | 기본은 **비공개**입니다. 팀에 공개할지는 발행한 사람이 직접 정합니다 |

> ⚠️ **두 창구 모두 «사본»입니다.** 저장소 원본을 고쳐도 자동으로 갱신되지 않습니다.
> 내용이 바뀌면 창구도 같이 갱신해야 합니다. 그래서 **정본은 항상 저장소**로 두세요.

**이미 웹페이지로 만들어 둔 것은 [INDEX.md 맨 위 「링크로 바로 보는 문서」](INDEX.md)** 에 모아 두었습니다.
`.html` 원본이 있는 문서는 이렇게 링크로 만들 수 있습니다.

## 3. ⛔ 어디에도 올리면 안 되는 것

| 안 됩니다 | 왜 |
|---|---|
| `.env`, `.dev.vars` 파일과 그 내용 | 서비스 전체 열쇠입니다. 깃허브·드라이브·Artifact 전부 금지 |
| API 키·토큰·비밀번호 | 문서 본문에 «참고로 키는…» 으로 적는 것도 금지 |
| 학생·학부모 실명, 전화번호, 결제정보 | 개인정보. 예시가 필요하면 `학생A`, `010-****-1234` 로 |
| 시연 계정 외의 실계정 비밀번호 | — |

문서에 실데이터를 넣어야 한다면 **먼저 사람에게 물어보세요.**
한 번 올라간 것은 나중에 지워도 기록에 남습니다.

## 4. 새 사람이 합류하면 — 체크리스트

- [ ] 깃허브 저장소에 초대하고, 수락했는지 확인
- [ ] [개발_공동작업_안내_직원용.md](개발_공동작업_안내_직원용.md) 읽게 하기 (깃 사용법)
- [ ] **`node -v` 가 24 이상인지 확인** — 22 이하면 설치가 「ERESOLVE / peer」 오류로 죽는데, 메시지에 Node 얘기가 안 나와서 원인을 못 찾습니다. 저장소의 `.nvmrc` 로 `nvm use` 하면 됩니다
- [ ] 클론 → `claude` 실행 → `CLAUDE.md` 가 자동으로 읽히는지 확인
- [ ] `/verify` 를 한 번 돌려 보게 하기 (타입체크 + 하니스가 도는지)
- [ ] [../CLAUDE.md](../CLAUDE.md) 의 **1장(절대 하지 말 것)** 을 같이 읽기
- [ ] 담당 영역 정하기 — `CLAUDE.md` 4-2장. `index.html`·`admin.html` 을 둘이 같이 만지면 충돌 해결이 사실상 불가능합니다
- [ ] 배포 권한을 줄지 결정 (기본은 **주지 않음**)
- [ ] `.env` / `.dev.vars` 가 필요하면 **깃이 아닌 경로로** 직접 전달

## 5. 자주 나오는 질문

**Q. 내가 클로드와 나눈 대화를 팀원이 그대로 볼 수 있나요?**
아니요. 계정을 넘나들어 공유되지 않습니다. `/worklog` 로 문서를 남기는 것이 정식 방법입니다.

**Q. 팀원도 `/verify` 같은 명령을 쓸 수 있나요?**
네. `git pull` 만 하면 바로 씁니다. `.claude/commands/` 가 저장소에 있기 때문입니다.

**Q. 팀원이 명령을 새로 만들면 나도 쓸 수 있나요?**
네. `.claude/commands/` 에 파일을 추가해 PR 로 올리면 됩니다.
**팀 전체에 적용되는 파일이니 올리기 전에 상대에게 알려 주세요.**

**Q. 노션·구글 드라이브 연결도 공유되나요?**
아니요. 각자 자기 클로드 계정에서 `/mcp` 로 연결해야 합니다.
저장소에 적어 둘 수는 있지만, 자격증명이 각자 것이라 실익이 없습니다.

**Q. 문서를 드라이브에만 두면 안 되나요?**
됩니다만 권하지 않습니다. 드라이브에는 **버전 기록이 없어서** 「어느 게 최신인지」
문제가 다시 생깁니다. 저장소에 두고 드라이브는 «보여 주는 창구» 로만 쓰세요.
