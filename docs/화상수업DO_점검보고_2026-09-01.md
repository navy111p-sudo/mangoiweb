# 화상수업 Durable Object 점검 보고 (2026-09-01)

> **대상**: `cloudflare-deploy/src/video-call-room.ts` (1,123줄) + 그 앞단 `src/index.ts` 의 WebSocket 라우트
> **성격**: 두 파일 다 **공동 금지구역**입니다. 그래서 이 문서는 **읽기만 하고 만든 보고서**이고, 코드는 한 줄도 안 고쳤습니다.
> **확인 방법**: 소스 정독 + D1 SELECT. ⛔ **라이브 수업방에 접속해 재현하지 않았습니다** — 실제 학생 수업이 도는 곳이라 프로브 자체가 사고입니다. 아래 🔴 항목은 **코드 경로 추적으로 낸 판단**이고, 「실제로 뚫어 봤다」가 아닙니다.

---

## 한 줄 요약

**화상수업 WebSocket 에는 인증이 한 겹도 없습니다.** 방 번호만 알면 누구나 들어가고, 들어가면서 **자기 역할을 스스로 «강사» 라고 선언**할 수 있습니다. 그리고 방 번호는 추측할 수 있습니다.

---

## 🔴 1. WebSocket 입장에 인증이 없다

`src/index.ts` 의 `handleVideoCallWebSocket` 은 이렇게 시작합니다.

```ts
const roomId = url.searchParams.get('roomId') || 'default';
const durableObjectId = env.VIDEO_CALL_ROOM.idFromName(roomId);
const durableObject = env.VIDEO_CALL_ROOM.get(durableObjectId);
const response = await durableObject.fetch(request);
```

토큰도, 세션 쿠키도, 예약 대조도 없습니다. DO 안에서도 마찬가지입니다 — `video-call-room.ts` 전체에서 `token`·`checkAdminSession`·`authUid` 는 **0건**입니다.

**그리고 방 번호는 결정론적입니다.** `class-{예약id}-{YYYYMMDD}` 형식이고(규칙서 0장), D1 실측으로 예약 id 는 **190 ~ 1,119**(923건)입니다. 즉 탐색 공간이 «약 930개 × 날짜» 라 사실상 열거할 수 있습니다.

> ℹ️ `/api/class/verify-room` 이라는 대조 API 가 따로 있지만, **화면이 «경고만» 하고 막지 않으며**(설계상 그렇습니다) **DO 는 그 결과를 아예 보지 않습니다.**

---

## 🔴 2. 그중 특히 — 아무 흔적 없이 «조용히 참관» 할 수 있다

`join-observe` 는 참관자를 **투명 유령**으로 만듭니다. 이건 관리자 수업 관찰 기능을 위한 **의도된 설계**입니다.

```ts
// 참가자 입장(join-room)과 같은 회신 묶음 — 단, 방송은 하나도 하지 않는다(유령).
```

- 인원수에 안 잡히고, 입·퇴장 방송이 없고, 참가자 목록에도 안 뜹니다.
- 들어가면 **교재 상태·칠판 전체·PDF 필기**를 그대로 받습니다.

문제는 **1번과 겹쳤을 때**입니다. 인증이 없으므로, 방 번호를 맞힌 사람이면 누구나 **미성년 학생의 수업을 아무도 모르게 지켜볼 수 있습니다.** 정원은 2명입니다.

⚠️ 영상·음성까지 받는지는 별개입니다 — 이 DO 는 시그널링만 하고, 참관자에게 미디어가 가는지는 `handleJoinObserve` 뒤의 WebRTC 협상에 달려 있습니다. **그 부분은 확인하지 못했습니다.** 다만 **채팅·칠판·교재·필기는 확실히 갑니다.**

---

## 🔴 3. 역할을 «클라이언트가 스스로» 선언한다 — 그리고 주석은 반대로 적혀 있다

강사 전용 기능은 전부 소켓 attachment 의 `role` 을 봅니다.

```ts
private staffOnly(userId: string, att: VcAttachment): boolean {
  const senderRole = (att?.role || '').toLowerCase();
  return this.isJoined(userId) && (senderRole === 'teacher' || senderRole === 'admin');
}
```

그런데 그 `role` 이 어디서 오냐면 — **클라이언트가 보낸 `join-room` 메시지**입니다.

```ts
const { username, role, clientId } = data || {};      // ← 클라이언트가 보낸 값
...
ws.serializeAttachment({ ..., role: role || 'student', ... });
```

WebSocket 업그레이드 시점(`fetch`)의 attachment 에는 role 이 아예 없고, 서버가 그 값을 **검증하는 곳이 없습니다.**

### 🔴 주석이 사실과 다릅니다

이 파일에는 이런 주석이 여러 곳에 있습니다.

> 「판정은 소켓 attachment 의 role 로 한다(**클라이언트가 보내는 값이 아니다**).」
> 「소켓 attachment 기준 강사·관리자 판정 — **학생이 위조 전송해도 통하지 않는다**.」

**attachment 의 role 이 곧 클라이언트가 보낸 값**이므로, 두 문장 다 사실이 아닙니다.

이건 규칙서 2장이 이미 경고한 것과 같은 뿌리입니다 — 「⛔ 오판 판정 근거로 `attendance.role='teacher'` 를 쓰지 마세요(**클라이언트가 보내는 값**)」. 같은 함정을 이 파일이 다시 밟았고, 그 위에 「안전하다」는 주석이 덮여 있습니다.

> ⚠️ **주석이 이렇게 적혀 있기 때문에 더 위험합니다.** 다음 사람이 「여긴 이미 막혀 있다」고 읽고 지나갑니다. 규칙서 2장 「문서에 «고쳤다» 고 적혀 있는데 같은 사고가 또 남」 그대로입니다.

### 학생이 `role:'teacher'` 로 들어오면 열리는 것

| 기능 | 무슨 일이 벌어지나 |
|---|---|
| `pdf-share` / `pdf-stop-share` | **반 전체의 교재를 갈아치우거나 없앰** (DO 에 저장까지 됨) |
| `pdf-page-change` | 반 전체의 교재 페이지를 넘김 |
| `class-lock` 4종(배경·마이크·집중·필기) | 다른 학생의 마이크를 잠그거나 필기를 막음 |
| `whiteboard-clear` | **필기 잠금 중에도** 칠판을 통째로 지움 |

## 🟡 4. 채팅 길이에 제한이 없다

귓속말은 `text.slice(0, 500)` 로 자릅니다. 그런데 **일반 채팅(`handleChatMessage`)에는 자르는 코드가 없습니다.**

```ts
const { message, toUserId } = data || {};
if (!message) return;
...
this.broadcastAll({ type: 'chat-message', data: { username, message, ... } });
```

받은 문자열을 그대로 방 전체에 방송합니다. 아주 긴 메시지 하나로 다른 학생들의 화면·메모리를 흔들 수 있습니다.

---

## 🟡 5. 칠판 기록은 «개수» 만 막고 «크기» 는 안 막는다

```ts
private static readonly WB_OPS_MAX = 4000;
...
if (this.wbOps.length > VideoCallRoom.WB_OPS_MAX) {
  this.wbOps.splice(0, this.wbOps.length - VideoCallRoom.WB_OPS_MAX);
}
```

`data` 는 아무 모양이나 받습니다. **한 획에 담긴 데이터가 아무리 커도 «1개» 로 셉니다.** 4,000개 × 큰 데이터 = DO 메모리.

> 📌 이건 오늘 포인트 쪽에서 고친 것과 **정확히 같은 함정**입니다 — 규칙표의 `daily_cap` 이 «점수» 가 아니라 «횟수» 라서, 금액이 오르자 상한이 5배가 됐던 그 건. **«몇 번» 을 막으면서 «얼마나» 를 안 막는** 패턴입니다.

---

## 🟡 6. 수업 중에 칠판·필기가 사라질 수 있다 — 주석의 전제가 틀렸다

`pdfState`·`videoState`·잠금 4종은 `state.storage` 에 저장되고 재기동 때 복원됩니다. 그런데 **`wbOps`·`pdfAnnoOps`·`pdfAnnoStrokes` 는 저장되지 않습니다.**

그 이유가 주석에 적혀 있습니다.

> 「⚠️ storage 에 넣지 않는다 — 획은 수천 개까지 늘어나고, 수업이 끝나면 값어치가 없다.
> **DO 가 잠들면 사라지는 것이 맞다(그때는 방도 비어 있다).**」

**뒷 문장이 틀렸습니다.** 이 DO 는 **WebSocket Hibernation 을 쓰고 있습니다**(생성자의 `setWebSocketAutoResponse`, `webSocketMessage`/`webSocketClose` 핸들러). Hibernation 의 요점이 바로 **소켓이 붙어 있는 채로 인스턴스를 내리는 것**입니다. 즉 **방이 비지 않아도 잠들 수 있고**, 깨어나면 그 세 버퍼는 빈 상태입니다.

그 결과: 수업이 도는 중에 학생이 새로고침하거나 늦게 들어오면 **그때까지 그려진 칠판·필기가 하나도 안 갑니다.** 2026-08-08 에 「학생 펜이 강사 화면에 안 보인다」를 고치려고 넣은 replay 기능이, 잠들었다 깨어난 뒤에는 다시 안 듣는 셈입니다.

⚠️ **얼마나 자주 잠드는지는 측정하지 못했습니다.** Cloudflare 가 정하는 것이고 로그로만 알 수 있습니다. 「가끔 필기가 안 보인다」류 제보가 있었다면 이것이 후보입니다.

---

## ℹ️ 7. 시그널 중계는 대상을 자유롭게 고를 수 있다 (반경은 작음)

`offer`/`answer`/`ice-candidate` 는 `data.targetUserId` 로 아무에게나 보낼 수 있습니다. 다만 **같은 방 안 참가자에게만** 가고, 잘못된 SDP 는 상대 브라우저가 거부합니다. **1번(인증 없음)이 막히면 이건 실질적 위험이 아닙니다.**

## ✅ 잘 돼 있는 것 (지우면 안 되는 것들)

공정하게 적습니다 — 이 파일은 상당히 조심스럽게 쓰여 있습니다.

- **생존 판정(liveness)** — hibernation 으로 `lastSeen` Map 이 비는 것을 알고, 1분에 한 번 attachment 에도 적습니다. 「멀쩡한 수업 전원이 120초에 끊긴다」는 사고를 미리 막아 뒀습니다.
- **재접속 교체** — 옛 소켓을 `4001` 로 닫습니다. `1000`(정상 종료)로 닫으면 학생 화면이 «강사 퇴장» 으로 읽고 수업을 끝내기 때문입니다. 순서(`joined:false` → `stale-` → close)까지 주석에 이유가 적혀 있습니다.
- **잠금 필드 이름 두 가지**(`locked`/`on`)를 둘 다 받습니다 — 한쪽만 보면 «항상 해제» 가 되는 것을 알고 있습니다.
- **교재가 바뀌면 필기 버퍼를 버립니다** — 페이지 번호가 다른 책과 섞이는 것을 막습니다.
- **참관자도 청소 대상**입니다 — 죽은 참관 소켓이 정원 2자리를 계속 먹던 것을 고쳐 뒀습니다.

## 무엇부터 하면 좋을까 (제 의견입니다 — 결정은 사장님)

| 순위 | 무엇 | 왜 이 순서인가 | 반경 |
|---|---|---|---|
| **1** | **입장에 토큰을 요구** — WS 업그레이드 때 `mango_token`(학생) 또는 관리자 세션을 확인하고, **그 사람이 그 예약의 당사자인지** 대조 | 3번(역할 위조)도 «아무나 들어올 수 있다» 를 전제로 성립합니다. 여기를 막으면 반경이 크게 줄어듭니다 | 🔴 큼 — 모든 수업 입장 경로. 잘못 조이면 **수업이 안 열립니다** |
| **2** | **역할을 서버가 정하기** — 클라이언트가 보낸 `role` 을 버리고, 예약(`class_schedules`)의 강사·학생과 대조해 서버가 붙임 | 1번을 하면 신원이 생기므로 이게 자연스럽게 따라옵니다 | 🔴 큼 — 강사·관리자 판정 전부 |
| **3** | **주석 정정** | 코드를 못 고치더라도 **지금 당장** 할 수 있습니다. 「안전하다」는 거짓 주석이 남아 있는 한 다음 사람이 여길 안 봅니다 | 🟢 없음(주석만) |
| **4** | 채팅 길이 자르기(귓속말과 같은 500자) | 한 줄이면 됩니다 | 🟢 작음 |
| **5** | 칠판 op **크기** 상한 | 4번과 같은 성격 | 🟢 작음 |
| **6** | 칠판·필기 버퍼를 storage 에 저장(또는 주석의 전제를 정정) | 「가끔 필기가 안 보인다」의 후보 | 🟡 중간 |

### ⚠️ 1·2번에 대해 꼭 드리고 싶은 말

이 저장소의 최우선 규칙은 **「수업이 절대 안 끊김」** 입니다. 인증을 새로 거는 변경은 **잘못 조이면 수업 자체가 안 열립니다.** 그리고 규칙서에는 이미 이런 전례가 적혀 있습니다:

- 강사는 «주소창이 없는 창» 을 쓰기도 해서 본인도 자기 상태를 모릅니다
- 교사 세션과 학생 세션이 **두 갈래**라, 한쪽만 보는 게이트는 교사를 «미로그인» 으로 판정합니다
- 카카오톡 인앱 브라우저는 **세션 쿠키를 돌려주지 않습니다**

그래서 제 의견은 — **막기 전에 «지금 누가 어떤 자격증명을 갖고 들어오는지» 를 먼저 로그로 세어 보는 것**입니다. 며칠치 실측 없이 게이트를 걸면 필리핀 강사·앱 사용자부터 못 들어옵니다.

3~5번은 반경이 작고 지금 바로 할 수 있습니다.

## 제가 확인하지 못한 것

정직하게 적습니다.

- **참관자에게 영상·음성이 실제로 가는지** — WebRTC 협상 쪽이라 이 파일만으로는 알 수 없습니다.
- **hibernation 이 얼마나 자주 일어나는지** — Cloudflare 가 정하고 로그로만 보입니다.
- **위 🔴 들을 실제로 재현하지 않았습니다** — 라이브 수업방이라 프로브 자체가 사고입니다. 전부 **코드 경로 추적**입니다.
- **누가 이미 이 구멍을 썼는지** — 알 방법이 없습니다. WS 접속에는 인증이 없으니 «누가 들어왔는지» 를 남기는 기록도 없습니다.
