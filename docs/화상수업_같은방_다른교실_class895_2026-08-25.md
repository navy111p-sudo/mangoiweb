## 1. 결론

**두 사람이 서로 다른 «서버 방»에 앉아 있었습니다.**

이 저장소는 Worker 를 **두 벌** 배포하고(`webrtc-unified-platform` · `-prod`),
화상수업 방(Durable Object)은 **스크립트마다** 만들어집니다. 그래서
`idFromName("class-895-20260825")` 이 워커마다 **다른 방**을 엽니다.
접속 주소(`location.host`)가 곧 어느 워커냐 = 어느 교실이냐입니다.

**2026-08-19 중국인 강선생님 건과 같은 뿌리의 재발**입니다
(`docs/작업기록/260819_강선생님_수업방_안보임_워커두벌_DO분리.md`).
그때 `test.mangoi.co.kr` 을 운영 워커로 옮겨 막았지만,
**기본 워커는 지금도 살아 있고 매 배포마다 최신 코드로 갱신**됩니다
(`deploy.yml` 1) 단계 · 헬스체크 `webrtc-unified-platform.navy111p.workers.dev`).
그 워커에 닿는 주소로 들어오면 오늘도 똑같이 갈립니다.

|---|---|---|
| 확정 | 방 번호가 두 화면 모두 같다 | 방 번호는 `class-{예약id}-{YYYYMMDD}` 로 결정론적 — `api-mango.ts:1672`, `api-teacher.ts:445` |
| 확정 | 「참여자 1명」은 **서버가 실시간으로 보내 준 값**이다 | `room-joined`·`user-joined`·`user-left` 마다 `updateUserCount()` — `js/idx-main.js:4065·4149·4164` |

| 확정 | 학생은 `mangoi.ai`(운영 워커) 였다 | 학생 화면 하단 전체화면 안내 문구가 `mangoi.ai:` 로 시작 |

| 위험 | 기본 워커가 살아 있다 | `.github/workflows/deploy.yml:136·164` — 폐기되지 않았고 겉보기에 완전히 정상 동작한다 |

### 왜 오래 못 찾는가

**D1·KV·R2 는 두 워커가 같은 id 를 공유합니다.** 출석·토큰·녹화는 한 곳에 쌓이므로
`attendance` 에는 두 사람이 **같은 방에 나란히** 남습니다. 갈리는 것은 DO 하나뿐이라
**DB 만 보면 완벽하게 정상**으로 보입니다. 8/19 건이 7/24~8/19 여덟 번의 수업 동안
발견되지 않은 이유가 이것입니다.

### (나) 출석 기록의 시간 겹침 — 사후에도 가능

```sql
-- ⚠️ SELECT 만. 개발·운영이 같은 DB 입니다 (CLAUDE.md 1-1)
SELECT user_id, username, role,
       datetime(joined_at/1000,'unixepoch','+9 hours') AS 입장,
       datetime(left_at  /1000,'unixepoch','+9 hours') AS 퇴장
```

시간이 **겹치는데도** 못 봤다 → 워커 분리 확정.

## 6. 해결 방안

### 6-1. 오늘 — 응급 처치

1. **강사 바로가기 재생성** — 지금 창을 지우고 `https://mangoi.ai` 에서 새로 「창으로 열기」
2. **강사 전원에게 한 번 확인** — 「수업 들어갈 때 주소가 mangoi.ai 맞나요?」 한 사람만의 문제가 아닐 수 있음
3. **휴대폰 앱 최신 버전 확인** — 옛 APK 에는 옛 주소가 박혀 있음(현재 최신 2.5)

### 6-2. 근본 수리 — 둘 중 하나 (사람이 결정)

#### A안 · 워커를 한 벌로 합친다 — **권고**

기본 워커 배포를 멈추고 모든 도메인을 운영 워커로 모읍니다. 방 목록이 하나가 되므로
이 사고가 **구조적으로 불가능**해집니다.

- ⚠️ **먼저 옮겨야 할 것 — 자동 작업(cron) 5종이 기본 워커에만 있습니다.**
  `[env.production.triggers] crons = []` 이라, 그냥 끄면 야간 동기화·미납 독촉·NPS·감시견이
  **전부 멈춥니다.**
- 배포 확인 주소 3곳도 함께: `deploy.ps1:77` · `deploy-full.ps1:130` · `deploy.yml:164·174`
- ⛔ 도메인은 **대시보드**에서만. `wrangler.toml` 에 `routes` 를 적으면 적지 않은 도메인이
  다음 배포에 지워집니다(CLAUDE.md 2장).

#### B안 · 화상수업 연결만 정본 주소로 고정 — 임시

`createWebSocket`(`js/idx-main.js:126`)이 `location.host` 대신 `mangoi.ai` 를 쓰게 합니다.
어느 주소로 페이지를 열었든 **교실은 한 곳**으로 모입니다.

- 기술적으로 가능: `/ws/video-call` 은 인증 게이트가 없고 쿠키를 쓰지 않아 교차 오리진이어도 깨지지 않음
- ⚠️ **위험**: 중국·필리핀 회선에서 `mangoi.ai` 만 막히면 그 수업이 **통째로** 못 붙습니다.
  실패 시 원래 주소로 되돌아가는 폴백이 반드시 필요
- A안이 늦어질 때의 임시 처방

### 6-3. 안전망 — A안·B안 어느 쪽을 하든 함께

이것이 없어서 8/19 에 여덟 번, 이번에 또 놓쳤습니다.
**막는 것보다 «났을 때 바로 알아채는 것» 이 더 급합니다.**

1. **입장 전 주소 경고** — `class-…` 방에 들어갈 때 현재 호스트가 정본 목록
   (`src/site-url.ts` 의 `SITE_HOSTS`)에 없으면 «이 주소로는 선생님과 만날 수 없어요»
   + [mangoi.ai 로 이동]. 주소창이 없는 앱 창에서 **사람이 볼 수 있는 유일한 신호**
2. **접속 주소를 기록** — 출석(또는 `vc_quality`)에 «어느 주소로 들어왔는가» 한 칸.
   그러면 노쇼 리포트가 «강사 A주소 / 학생 B주소» 라고 스스로 말해 줍니다.
   지금은 **어디에도 안 남아 사후 추적이 불가능**합니다
3. **수업 중 엇갈림 감지** — 입장 시 공유 D1 에 «지금 이 방에 있다» 를 적고,
   «DB 엔 두 명인데 내 교실엔 한 명» 이면 «상대는 다른 주소로 들어와 있어요» 안내.
   D1 은 두 워커가 **공유**하므로 이 방법만이 갈림을 **수업 도중에** 잡습니다
4. **감시 확장** — `test-harness/worker_do_split_harness.mjs` 는 지금 설정 파일만 봅니다.
   위 1·2 가 코드에 살아 있는지까지 못 박아야 다음 사람이 실수로 지우지 못합니다
