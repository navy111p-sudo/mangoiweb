# 화상 프레임 화질 계측기 (video-enhance-probe)

> **이 폴더는 운영 코드가 아닙니다.** `cloudflare-deploy/` 와 아무 관계가 없고 배포에 포함되지
> 않습니다. **«AI 화질 복원이 망고아이에 값어치가 있는가» 를 숫자로 재는 실험 장비**입니다.

---

## 0. 먼저 — 파이썬 코드는 운영에 «그대로» 못 붙습니다

요청하신 코드는 완전히 동작합니다. 다만 붙일 자리가 없다는 것을 먼저 적습니다.
이 문장을 안 적으면 「코드를 받았으니 이제 되겠지」로 읽히고, 그게 이 저장소가 네 번 사고를 낸
「하기로 한 것이 «했다» 로 적히는」 그 모양입니다.

| 막는 것 | 사실 |
|---|---|
| **서버가 영상을 안 봅니다** | 화상수업은 **브라우저↔브라우저 P2P 메시**입니다. `src/video-call-room.ts`(Durable Object)는 **시그널링만** 하고 프레임은 한 장도 지나가지 않습니다. 서버에 파이썬을 둬도 볼 것이 없습니다 |
| **Workers 에 파이썬·GPU 가 없습니다** | Cloudflare Workers 는 V8 아이솔레이트입니다. PyTorch·CUDA·OpenCV 가 돌 자리가 아닙니다 |
| **강사 PC 에 GPU 가 있는지 모릅니다** | 아래 표의 지연 숫자는 전부 **GPU 기준**입니다. CPU 로는 10~40배 느립니다. ⚠️ 필리핀 강사 노트북 사양은 **이 저장소에서 잰 적이 없습니다** — 「없을 것이다」는 추론입니다 |
| **CPU 가 이미 빠듯합니다** | 2026-09-02 에 «수업 중 녹화가 실시간 인코더와 같은 CPU 를 나눠 쓴다» 는 이유로 강사 자동 녹화를 껐습니다(`isStaffSkipRecording`). 그 자리에 GPU 도 없는 얼굴 복원을 얹으면 같은 사고를 더 크게 재현합니다 |

**⟹ 이 폴더는 «배포» 가 아니라 «판단 근거» 를 만드는 도구입니다.**

## 1. 그래서 값어치가 있는가 — 있습니다, 단 한 지점에서

### ✅ 있는 곳 — 「저해상도로 보내고, 받는 쪽에서 키운다」

적응 루프(`js/idx-main.js` 의 `STEPS`/`SCALE`/`vcQualityCaps`)는 회선이 나빠지면 이렇게 떨어집니다.

🔴 **먼저 짚을 것 — 화면의 화질 설정 «기본값은 `저`(low)» 입니다**
(`vcQualityMode()` 가 `localStorage` 에 값이 없으면 `'low'` 를 돌려줍니다. 값을 쓰는 곳은
설정의 화질 버튼뿐이라 **한 번도 안 만진 학생은 전부 여기**입니다). 그래서 아래 왼쪽 칸이
«대부분의 학생» 이고, 오른쪽은 «자동/고를 손수 고른 사람» 입니다.

| 단계 | **`저` = 기본값 (PC)** | | | `자동`/`고` (PC) | | |
|---|---|---|---|---|---|---|
| | 비트레이트 | 해상도(1280×720 기준) | fps | 비트레이트 | 해상도 | fps |
| 0 | 400 kbps | 1/2 = **640×360** | 15 | 1200 kbps | 1280×720 | 24 |
| 1 | 240 kbps | 1/3 = 426×240 | 10 | 720 kbps | 853×480 | 14 |
| 2 | 150 kbps | 1/4 = 320×180 | 10 | 420 kbps | 640×360 | 10 |
| **3** | **150 kbps** | **1/6 = 213×120** | 10 | 240 kbps | 426×240 | 10 |
| **4** | **60 kbps** | **1/8 = 160×90** | **5** | 96 kbps | 320×180 | 5 |

**3~4단계가 사장님이 말씀하신 「뭉개짐」 그 자체입니다.** 기본 설정에서는 **213×120 · 160×90**
까지 떨어져 브라우저 `<video>` 가 6~8배로 늘려 그립니다. 여기서 **받는 쪽 초해상도**는
«대역폭을 한 바이트도 더 안 쓰고» 체감 화질을 올립니다. 이건 진짜 이득이고,
**실제 해상도가 예상보다 낮았으므로 이득의 여지는 오히려 더 큽니다.**

> 🪤 **처음에 이 표를 틀리게 적었습니다 — 남기는 이유입니다.**
> `baseCaps()` 의 `return { br: 1200*1000 … }` 를 베꼈는데, 그 함수는 첫 줄이
> `if (window.vcQualityCaps) return window.vcQualityCaps();` 이고 그 함수는 항상
> 정의돼 있어 **그 `return` 은 평소에 안 돕니다.** 게다가 `applyStep` 은
> `(caps.scale || 1) * SCALE[step]` 로 **곱하는데** 그 곱셈도 빠뜨렸습니다.
> ⟹ 「대부분의 학생」이 아니라 「자동을 손수 고른 사람」을 재현하고 있었습니다.
> ⛔ **`return` 문을 베끼기 전에 그 위의 조기 반환을 먼저 보세요.**
> 지금은 `selftest.py` ⓪ 절이 **`idx-main.js` 를 읽어 대조**하므로 같은 실수가
> 다시 나면 그 자리에서 FAIL 합니다(변이시험: 폴백 베끼기 8건 · 곱셈 누락 6건 실제 FAIL).

더 좋은 것은 그 반대 방향입니다 — **복원이 되면 일부러 더 낮게 보낼 수 있습니다.**
1/3 해상도로 보내고 받는 쪽에서 키우면, 같은 240 kbps 로 지금보다 나은 화면이 나옵니다.
필리핀·중국 회선에서는 **bit 를 아끼는 것이 유일하게 확실한 지렛대**입니다.

### ❌ 없는 곳 — 사장님이 겪으신 문제의 «대부분»

`CLAUDE.md` 와 D1 실측이 이미 지목한 원인들입니다. **AI 복원은 이 중 어느 것도 못 고칩니다.**

- **경로 지연** — 중국 강사 회선 RTT 360~440ms, 손실은 1% 미만. 「회선이 나쁨」이 아니라 「경로가 멂」입니다 (`X-Turn-Source` / `X-Turn-Detail` 로 판별)
- **TURN 무료 폴백** — `public-fallback` 이면 모든 수업이 공개 릴레이를 탑니다
- **배포가 DO 를 재시작** → 진행 중인 모든 수업의 WebSocket 이 끊김 (화·목 14~23시 보류 게이트로 대응 중)
- **유령 피어 누적** → 같은 영상을 최대 9벌 업로드해 **학생** 업링크 포화
  (2026-09-01 `class-1070` 실측. ⚠️ 「그 학생 인터넷이 나쁘다」로 오진하기 쉬운 자리라
  «강사» 로 잘못 적으면 다음 사람이 볼 곳을 반대로 잡습니다)
- **적응 루프가 바닥에 굳던 문제** — 절대 RTT 문턱 때문에 기준 RTT 360ms 회선이 회복 조건을 영영 못 만나던 것 (#771 에서 «기준 RTT 대비» 로 수리)

**⛔ 복원을 붙이고 「화질 문제 해결」이라고 적지 마세요.** 위 항목이 살아 있으면 그대로 재발합니다.

### ⛔ 절대 쓰면 안 되는 곳 — 교재 화면

GFPGAN·CodeFormer 는 **없는 것을 그려 넣습니다**(hallucination). 뭉개진 얼굴을 «그럴듯한»
얼굴로 만드는 것이지 잃어버린 정보를 되찾는 것이 아닙니다.

**교재·칠판 화면(`#vc-content-pane`)에 절대 적용하지 마세요** — 없는 글자를 지어냅니다.
흐린 「b」가 선명한 「d」가 되면 흐린 것보다 나쁩니다. 얼굴 타일에만 씁니다.

## 4. 어느 모델을 쓰나 — 추천과 근거

**결론: 실시간에는 `gfpgan`(GFPGAN v1.4).** 얼굴 복원 성능 대비 가장 가볍습니다.

| 모델 | 512 얼굴 1개 (RTX 3060·FP16, 참고치) | 판단 |
|---|---|---|
| **gfpgan** ★ | **~15–25 ms** | 단일 forward 의 GAN. 30fps 예산(33ms) 안에 들어옵니다 |
| codeformer | ~50–110 ms | Transformer + VQ 코드북이라 2~4배 느림. 품질은 더 좋으니 **녹화 후처리**에 |
| realesrgan (general-x4v3) | ~10–20 ms | 얼굴 전용이 아닌 일반 초해상도. **A 경로(브라우저)에 가장 가까운 성격** |
| cv-sharpen | ~1–2 ms (CPU) | AI 아님. **기준선.** 이것과 차이가 작으면 AI 를 쓸 이유가 없습니다 |

> ⚠️ 위 ms 는 **일반적인 참고치이지 이 저장소에서 잰 값이 아닙니다.**
> `--bench` 로 **사장님 PC 에서 직접 재세요.** 그 숫자만이 근거입니다.

## 5. 지연을 줄이는 다섯 가지 — 코드 어디에 있나

| 기법 | 어디 | 효과 |
|---|---|---|
| **① ROI (얼굴만 크롭)** | `faces.py` | 1280×720(0.92MP) → 512×512(0.26MP). **화소 1/3.5**. 게다가 복원 모델은 «정렬된 얼굴» 로 학습돼 품질도 더 좋습니다 |
| **①-2 되붙이기도 ROI 로** | `faces.paste_back` | 🔴 **여기가 제일 크게 물렸습니다.** 처음에 전체 프레임에 `warpAffine` 두 번 + float 혼합을 했더니 **22.8ms** 로 «복원보다 오래 걸리는» 상태였습니다. 얼굴 상자(약 180×180) 안에서만 계산하도록 고쳐 **2.9ms**(약 8배). 결과는 화소 단위로 같습니다(`selftest.py` ④가 최대차 0 으로 못 박습니다) |
| **② FP16 (반정밀)** | `restorers._TorchRestorer` | CUDA 에서 약 **1.6~2배**. ⚠️ CPU/MPS 에서는 오히려 느리거나 터져서 자동으로 끕니다 |
| **③ cuDNN benchmark + TF32** | 같은 파일 | 입력 크기가 **512 로 고정**이라 자동 튜너가 크게 이득. 크기가 매 프레임 바뀌면 반대로 손해입니다 |
| **④ 프레임 스킵 + 텍스처 재사용** | `pipeline.py` | 복원은 N 프레임에 한 번, 사이 프레임은 **직전 복원 텍스처를 «지금 위치» 에** 다시 붙임 → 고개가 움직여도 따라옴 |
| **⑤ inference_mode + requires_grad_(False)** | `restorers.py` | `no_grad` 보다 한 겹 더 가볍고 그래프를 아예 안 만듭니다 |

### ⚠️ ④의 대가 — 이걸 모르고 쓰면 안 됩니다

말하는 얼굴에서 `--skip` 을 키우면 **입 모양이 소리보다 늦습니다.** 재사용한 텍스처가
직전 프레임의 입을 갖고 있기 때문입니다.

- `--skip 1` — GPU 가 버티면 **이게 정답**
- `--skip 2` — 빠듯할 때
- `--skip 3` 이상 — **입 모양 어긋남이 눈에 보입니다.** 과부하 밸브로만

### 덧 — 깜빡임(flicker)

GAN 은 프레임마다 독립적으로 그려서 정지 화면에서도 얼굴이 «지글거립니다».
- `randomize_noise=False` 로 노이즈를 고정했습니다 (`restorers.py`) — 이 한 줄이 체감 차이가 큽니다
- 그래도 남으면 `--temporal-ema 0.4`. ⚠️ 대가는 **움직임이 흐려지는 것**입니다

## 6. 알려진 마찰 / 함정

**`basicsr` 가 import 에서 터질 때** — `basicsr` 1.4.2 가 `torchvision.transforms.functional_tensor`
를 부르는데 torchvision 0.17+ 에서 그 모듈이 사라졌습니다.

```bash
# 방법 1 (권장): torchvision 을 낮춥니다
pip install "torchvision<0.17"   # requirements.txt 에 이미 걸어 두었습니다

# 방법 2: 한 줄을 고칩니다
python - <<'PY'
import basicsr, pathlib, re
p = pathlib.Path(basicsr.__file__).parent / "data" / "degradations.py"
p.write_text(p.read_text().replace(
    "torchvision.transforms.functional_tensor", "torchvision.transforms.functional"))
print("patched", p)
PY
```

**numpy 2.x** — `basicsr` 가 깨집니다. `requirements.txt` 가 `<2.0` 으로 묶어 두었습니다.

**CodeFormer** — pip 패키지가 없습니다. 저장소를 받아 `PYTHONPATH` 에 넣어야 합니다.
실시간 목적이면 그냥 `--model gfpgan` 을 쓰세요.

**가중치 내려받기** — 허깅페이스 Hub 를 먼저 시도하고, 미러 저장소가 사라졌으면 공식 릴리스
URL 로 떨어집니다. 둘 다 실패하면 «어디에 어떤 파일을 두라» 는 안내가 나옵니다 (`config.py`).

**열화 시뮬레이터는 근사입니다** — 실제 WebRTC 는 VP8/H.264 로 인코딩하는데 여기서는 JPEG 로
흉내 냅니다. 블록 모양이 다릅니다. **«복원이 얼마나 살리나» 의 상대 비교에는 쓸 수 있지만,
«필리핀 화면이 정확히 이렇게 생겼다» 고 단정하면 안 됩니다.**

**`LADDER_STEPS`/`LADDER_SCALE` 은 사본입니다** — 정본은 `cloudflare-deploy/public/js/idx-main.js`
의 `STEPS`/`SCALE`/`baseCaps()`. 그쪽을 고치면 `config.py` 도 함께 고쳐야 이 계측기가
«지금 학생이 실제로 보는 화면» 을 재현합니다.
