🎮 전체 게임 통합 분석 — 관리자 제안서

2026-08-08 · 대상: 사장님 · 본사 매니저 · 지사/대리점 · 필리핀 강사
요청: 「영어 배틀 관리」를 게임 하나가 아니라 전 게임 통합 분석으로. 최대한 가볍게·빠르게·안정적으로.
먼저 보고드릴 것 — 제안의 방향이 실측 때문에 바뀌었습니다.
화면의 「영어 배틀 관리」는 배틀 기능이 아닙니다. P2P 배틀 백엔드는 만들어진 적이 없고, 지금 보이는 숫자는 이미 전 게임의 단어 정답 누계를 「승수·vs AI」로 옷 입힌 것입니다. 즉 사장님 직감이 정확합니다 — 이건 기능을 넓히는 일이 아니라, 이름표를 사실대로 되돌리는 일입니다.

다만 그보다 더 큰 문제가 있습니다. 보여줄 데이터가 거의 없습니다. 분석 화면을 지금 만들면 빈 화면이 나옵니다. 그래서 이 제안서는 「계측 먼저, 화면 나중」 순서로 씁니다.

2. 제안 — 3단계, 그러나 1단계가 8할

단계내용기간없으면
0단계
계측		게임 이름 1칸 + 판(session) 1행 기록
미기록 게임 6종 연결		2~3일 화면을 만들어도 빈 화면

총 6~7일. 0단계 없이 1단계를 먼저 하자는 요청이 오면 거절해야 합니다 — 만들어도 보여줄 게 없습니다.

2-1. 0단계 — 계측 (최소 침습 설계)

원칙: 기존 표를 갈아엎지 않는다. 칸 하나 더하고, 표 하나 새로 만든다.

-- ① 기존 표에 게임 이름 한 칸 (기존 데이터 안 깨짐, 기본값 '')
ALTER TABLE game_progress ADD COLUMN game TEXT DEFAULT '';

-- ② 판(session) 단위 1행 — 게임이 끝날 때 딱 1번만 기록
CREATE TABLE IF NOT EXISTS game_sessions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  uid TEXT NOT NULL,          -- 학생(익명 uid, 실명 저장 안 함)
  game TEXT NOT NULL,         -- 'tetris' | 'shooter' | 'vocab' ...
  lang TEXT DEFAULT 'en',
  started_at INTEGER, ended_at INTEGER,
  items INTEGER DEFAULT 0,    -- 그 판에서 만난 단어 수
  correct INTEGER DEFAULT 0, wrong INTEGER DEFAULT 0,
  finished INTEGER DEFAULT 0, -- 끝까지 했나 (0이면 중도 이탈)
  coins INTEGER DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_gs_game_time ON game_sessions(game, ended_at);
CREATE INDEX IF NOT EXISTS idx_gs_uid ON game_sessions(uid, ended_at);

클라이언트 수정은 게임당 3줄입니다.

// 기존 호출에 game 이름만 추가
fetch('/api/games/progress', { ..., body: JSON.stringify({
  user_id, lang, game: 'tetris',   // ← 이 한 줄
  events
})});

// 게임이 끝날 때 딱 1번 (실패해도 게임에 영향 없게 catch 로 삼킴)
navigator.sendBeacon('/api/games/session', JSON.stringify({
  uid, game:'tetris', lang, started_at, ended_at:Date.now(),
  items, correct, wrong, finished:1, coins
}));
왜 「판 단위 1행」인가 — 이것이 경량화의 핵심입니다.
단어 하나 맞출 때마다 서버를 부르면 한 판에 수십~수백 요청이 됩니다. 필리핀 회선에서 이것은 게임을 끊기게 만듭니다.
· 판당 요청 1~2건(중간 progress 묶음 1 + 종료 beacon 1)
· sendBeacon 은 응답을 기다리지 않습니다 → 게임 프레임에 0 영향, 창을 닫아도 전송됨
· 학생 29,000명이 하루 1판씩 해도 하루 약 3만 행 — D1에 부담 없는 규모
· 90일 지난 원본은 일 단위 집계로 접고(rollup) 원본 삭제 → 표가 무한정 커지지 않음

서버는 API 2개만 추가합니다 (src/index.ts 라우팅 + 인증 게이트 둘 다 등록 — 안 하면 화면에 JSON 원문이 뜹니다):

  • POST /api/games/session — 학생용(익명 허용), 판 1행 기록
  • GET /api/games/insights?range=7d — 관리자용, 이미 집계된 JSON 하나를 돌려줌 (KV 10분 캐시)

2-2. 1단계 — 화면 (독립 경량 페이지)

⛔ admin.html 안에 카드로 넣지 않습니다. admin.html 은 이미 1.0MB · 카드 91개이고, 필리핀 회선에서 19~21초가 걸립니다. 여기에 카드를 하나 더 얹으면 전원이 함께 느려집니다.
→ /game-insights 독립 페이지. 이미 검증된 길입니다 — manager.html 이 같은 방식으로 934KB·19초 → 10KB·0.43초(44배)를 냈습니다.
항목설계이유
페이지 크기15KB 이하 (HTML 1개, 외부 리소스 0개)필리핀 회선은 굵기가 아니라 왕복 횟수가 아픕니다
차트라이브러리 없음. 막대 = <div> width %Chart.js 하나가 페이지보다 큽니다
요청 수3개 이하 (HTML + insights JSON + 폰트 캐시)집계는 서버가 끝내서 보냅니다
한/영data-ko / data-en + 5줄 applyLangi18n 사전(204KB)을 부르지 않습니다. 필리핀 강사 필수
목표 속도1초 이내 첫 화면/teacher 실측 0.83초와 같은 급
실패 처리API 죽으면 「데이터 없음」 표시, 화면은 살아 있음분석 화면 때문에 업무가 멈추면 안 됩니다
개인정보닉네임·익명 uid만. 실명·연락처 표시 안 함지사·대리점도 보는 화면입니다

얻는 것: 21개 게임 중 실제로 살아있는 게임과 죽은 게임이 한 줄에 드러납니다.
쓰는 법: 판수 0인 게임은 → 홍보 부족인가, 입구가 안 보이나, 재미가 없나를 다음 회의 안건으로. 3주 연속 0이면 내리는 것도 결정합니다.

② 재미 vs 학습 — 사분면 Fun × Learning

정답률만 보면 쉬운 게임이 1등이 됩니다. 그래서 두 축으로 봅니다.

  • 가로축 = 재방문율 (그 게임을 다시 한 학생 비율) → 재미
  • 세로축 = 판당 학습 항목 수 (한 판에 단어를 몇 개 만나나) → 학습량
재방문 높음재방문 낮음
학습량 많음주력 — 수업 숙제로 지정아깝다 — 재미 보강 (효과는 좋은데 안 옴)
학습량 적음사탕 — 보상용으로만. 학습 시간으로 세지 않음정리 대상

쓰는 법: 「주력」 칸의 게임만 강사가 숙제로 내줍니다. 「사탕」은 상으로만 씁니다.

③ 전 게임 통합 약점 단어 Top 20 Weakest Words (All Games)

이건 이미 만들어져 있습니다 — /api/games/weak 와 game-report.html(8KB, 교사용). 게임별로 흩어진 오답을 학생 단위로 합쳐서 봅니다.

쓰는 법 (가장 값어치 있는 부분):

  1. 학생별 약점 단어 5개를 다음 수업 워밍업(warmup)에 자동 투입 — 이미 /api/games/recommend 가 이 일을 합니다
  2. 반 전체에서 공통으로 틀리는 단어 → 교재·수업 자료의 문제일 수 있음. 강사가 아니라 콘텐츠를 고칩니다
  3. 학부모 리포트에 「이번 주 극복한 단어 7개」로 실어 보냅니다 (희망 톤 — 못 하는 것 나열 금지)

④ 학생 3구간 — 성장 / 정체 / 사라짐 Growing / Stuck / Gone

구간판정 기준(단순·설명 가능하게)행동누가
성장2주 연속 판수 ↑ 또는 정답률 ↑칭찬 메시지·뱃지자동
정체판수는 유지, 정답률 3주째 제자리난이도가 안 맞는 것 → 레벨 조정강사
사라짐이전엔 했는데 14일째 0판학부모 연락 — 이탈 신호매니저
이게 회사에 돈이 되는 지점입니다. 게임 이탈은 수업 이탈보다 먼저 나타납니다. 이미 있는 이탈위험 대시보드(churn-graph)에 「게임 침묵 14일」을 신호 하나로 추가하면 새 시스템을 만들지 않고 조기경보가 한 칸 정확해집니다.

⑤ 발음 분포 Pronunciation Spread

Azure 발음평가가 이미 붙어 있습니다(azure_accuracy·fluency·completeness). 지금은 73%가 'guest'라 학생에게 못 붙입니다.

0단계에서 uid만 제대로 넣으면 → 점수대별 학생 분포 → 하위 20%를 speech-coach 대상으로 자동 추출.
필리핀 강사에게는 「이 학생은 /r/ 발음이 약합니다」처럼 영어로 나가야 합니다.

⑥ 포기 지점 Drop-off

game_sessions.finished=0 비율. 「시작은 했는데 끝을 못 본 판」이 몇 %인가.

  • 포기율 50% 넘는 게임 → 난이도 or 로딩. 어느 쪽인지는 ended_at - started_at 이 말해줍니다
    (10초 만에 나갔으면 안 뜬 것이고, 3분 하다 나갔으면 어려운 것입니다)
  • 이건 필리핀·저사양 기기 문제를 잡는 유일한 창입니다 — 학생은 신고하지 않고 그냥 나갑니다

4. 매니저 주간 루틴 — 5분

화면만 있으면 아무도 안 봅니다. 월요일 아침 5분짜리 순서를 정해 둡니다.

순서본다기준한다

7. 결정이 필요한 것 — 사장님

  1. 「영어 배틀 관리」 카드를 「게임 학습 분석」으로 바꿉니다. 지금 이름은 사실과 다릅니다. (P2P 배틀을 진짜로 만들 계획이 따로 있다면 말씀해 주십시오 — 그건 별건입니다)
  2. 계측(0단계)부터 갑니다. 화면 먼저는 빈 화면입니다.
  3. 게임 21개를 다 살릴지, 주력을 고를지. 데이터가 2주 쌓이면 사분면이 답을 줍니다. 제 의견은 주력 5~6개 집중입니다 — 21개를 다 관리하는 비용이 만드는 비용보다 큽니다.
