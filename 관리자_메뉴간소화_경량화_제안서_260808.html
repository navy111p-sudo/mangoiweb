6. 왜 지금까지 못 줄였나 — 전제를 검증했습니다

메뉴를 합치지 않은 이유가 코드 주석에 적혀 있습니다(adm-quickmenu.js).

「겉보기에 중복인 카드들(자료실 5개, 리포트 5개 …)은 사실 역할별 접근권한을 따로 들고 있다.
즉 이 시스템에서는 카드 하나 = 권한 단위다. 합치면 권한 경계가 무너진다.」

세어 봤습니다. 이 말은 91개 중 27개에만 해당합니다. 나머지 64개는 권한 정책에 등록조차 되어 있지 않아 전부 「본사 전용」이라는 같은 한 칸에 들어 있습니다.

합치려던 묶음각 카드의 권한판정
자료실 5개5개 모두 미등록 → 본사 전용✅ 합쳐도 권한 안 무너짐
출결 3개3개 모두 미등록 → 본사 전용✅ 안전
평가서 6개6개 모두 미등록 → 본사 전용✅ 안전
알림 6개5개 미등록 + card-notifications만 mgrOrUp⚠️ 탭 1개만 권한 조건부
결제 5개4개 미등록 + card-accounting-mgmt만 mgrOrUp⚠️ 탭 1개만 권한 조건부
결론 — 「합치면 위험하다」는 27개 카드에는 참, 64개에는 거짓이었습니다. 그리고 참인 27개도 카드를 나눌 필요는 없고 탭에 권한을 걸면 됩니다. 지금 구조가 오히려 위험합니다 — 정책 미등록 64개는 「본사 전용」으로 조용히 떨어지므로, 새 카드를 만들 때 정책을 안 적으면 아무도 모르게 지사·대리점에서 사라집니다.

11. 하면 안 되는 것 — 이미 시도해서 막힌 길

  • 카드 91개를 <template>으로 지연 렌더 ⛔ — 시도했고 막혔습니다. 90개가 부팅 JS 가 getElementById 로 찾는 요소를 품고 있습니다(호출 319곳). 지연시키면 조용히 죽습니다. 그래서 정답은 「나중에 그리기」가 아니라 「그 페이지에 없기」입니다 → 3단계 페이지 분할.
  • 지연로딩 대상을 40개로 확대 ⛔ — 안전하게 미룰 수 있는 것은 이미 19개 전부 뽑혔습니다. 남은 것은 전역 참조가 있어 미루면 깨집니다.
  • 메뉴를 「더 깊게」 숨겨서 개수 줄이기 ⛔ — 지금 3단 33개가 이미 그 결과입니다. 넓고 얕게가 원칙입니다.
  • hover 확대(scale/translate) 부활 ⛔ — 「정신없다」고 의도적으로 제거했습니다. hover 강조는 색만.
  • 라벨 일괄 치환을 PowerShell 로 ⛔ — UTF-8 이 깨집니다. 일괄 수정은 node readFileSync(f,'utf8') 로만.
  • Unicode 13 이상 이모지 ⛔ — Win10 에서 두부(□)로 보입니다.

12. 검증 · 리스크 · 되돌리기

리스크대비
합친 탭에서 권한이 새는 것 — 가장 큰 위험 탭 단위 권한 검사를 서버에서 한 번 더. 지금 display:none 은 화면 가리기일 뿐입니다. 동시에 정책 미등록 64개를 전부 명시 등록해 「안 적으면 본사 전용」이라는 조용한 기본값을 없앱니다.
직원이 익숙한 메뉴를 못 찾음 3단계 배포 후 2주간 옛 이름 → 새 위치 안내를 검색 결과에 노출(옛 이름으로 검색해도 찾아짐).
다른 담당자 작업과 충돌 admin.html(1MB)은 공동 편집 시 충돌 해결이 사실상 불가. A 담당 단독 · 짧은 브랜치 · 단계별 배포.
「배포됐는데 옛 화면」 정적 자산 스탬프만 보고 판단하지 않고 API 를 실제로 찔러 확인.

단계마다 검증: ① node node_modules/typescript/bin/tsc --noEmit ② node test-harness/run.mjs --fast ③ 실제 브라우저 ④ 흉내 회선(지연 350ms·400KB/s)에서 로딩 시간 재측정 — 「고쳤습니다」가 아니라 「몇 초에서 몇 초가 됐습니다」로 보고합니다.
