망고아이 관리자 사이트 진단 · 개선 제안서 Mangoi Admin Site — Review & Improvement Proposal

대상: test.mangoi.co.kr/admin (실소스 cloudflare-deploy/public/admin.html) · 작성일 2026-08-08 · 실제 학생 약 29,000명 운영 서비스 Scope: test.mangoi.co.kr/admin (source cloudflare-deploy/public/admin.html) · 2026-08-08 · Live service, ~29,000 students

📌 한 줄 요약Executive Summary

기능은 이미 풍부하다. 문제는 “무게”와 “초점”이다. 관리자 화면 한 번 여는 데 비압축 기준 약 3.45MB(JS 93개 개별 요청, 단일 번들 adm-core.js 705KB, CSS 486KB)가 실린다. 필리핀 가정의 저사양 기기·불안정 회선에서는 이 무게가 곧 로딩·버퍼링·렉으로 이어진다. 해결책은 “다시 만들기”가 아니라 ① 역할별 경량 진입 화면 분리 ② 번들 다이어트·지연로딩 ③ 자주 쓰는 기능 상단 고정 ④ 보안·안전 장치 보강의 4단계다. 이미 존재하는 manager.html(50KB, 지연로딩) 이 그 방향의 좋은 출발점이다. The feature set is already rich — the real problems are weight and focus. Opening the admin loads about 3.45 MB uncompressed (93 separate JS requests, a single 705 KB adm-core.js bundle, 486 KB of CSS). On low-end home devices and unstable connections in the Philippines, that weight becomes loading, buffering and lag. The fix is not a rewrite but four steps: (1) split lightweight role-based entry screens, (2) slim the bundle with lazy-loading, (3) pin the most-used actions to the top, (4) harden security and safety. The existing manager.html (50 KB, lazy-loaded) is a good starting point.

2. 진단 — 6가지 핵심 문제2. Findings — 6 Core Issues

① 경량화·속도: 모든 것을 한 번에 싣는다Weight & speed: everything loads at once

본사·지사·대리점·매니저·교사가 모두 같은 3.45MB 화면으로 들어온 뒤 역할에 따라 카드를 숨긴다(CARD_POLICY/PERMS). 즉 필리핀 교사가 결코 쓰지 않을 정산·급여·경영지표 코드까지 전부 내려받는다. JS 93개를 개별 요청하므로 회선이 느릴수록 손해가 커진다. HQ, branch, agency, manager and teacher all enter the same 3.45 MB screen, then cards are hidden by role (CARD_POLICY/PERMS). A Philippine teacher still downloads all the settlement, payroll and executive code they will never use. 93 individual JS requests make slow links even worse.

② 반응형·모바일: 데스크톱 확대(zoom:1.3) 전제Responsive/mobile: built around desktop zoom:1.3

반응형 규칙이 404KB CSS 안에 76개 몰려 있고, 관리자 화면은 PC 확대(zoom:1.3)를 전제로 설계됐다. 가정에서 휴대폰으로 여는 교사에게는 표·사이드바가 버겁다. 카드형·세로 스택 모바일 레이아웃이 필요하다. Responsive rules are crammed (76) into a 404 KB CSS file, and the admin assumes desktop zoom (zoom:1.3). For a teacher opening it on a phone at home, the tables and sidebar are heavy. A card-based, vertically stacked mobile layout is needed.

③ 초점: 76개 카드에 “지금 할 일”이 묻힌다Focus: the day's task is buried under 76 cards

매니저가 매일 실제로 쓰는 것은 대개 6~10개(오늘 매출·출석·결석률·진행 중 수업·연기요청·정산·대기자)다. 그런데 이 기능들이 76개 카드 사이에 흩어져 있어 탐색 비용이 크다. 상단 고정 “자주 쓰는 기능” 영역이 해법(폴더의 관리자_자주쓰는기능 제안과 동일 방향). A manager really uses ~6–10 things a day (today's revenue, attendance, absence rate, live classes, postpone requests, settlement, waitlist). But those are scattered across 76 cards. A pinned "Quick Access" area at the top is the fix (same direction as the existing quick-access proposal in the folder).

④ 보안·안전: 실수 방지 장치가 얇다Security & safety: thin guardrails

innerHTML 143곳은 서버 데이터가 그대로 DOM에 들어가면 XSS 위험이 된다(값 이스케이프 점검 필요). 세션 만료 401 공통 배너와 pii-mask.js(개인정보 마스킹)는 이미 있어 좋다. 다만 관리자 로그인 2단계 인증(MFA) 부재, 삭제·정산 등 되돌리기 어려운 동작의 재확인, 감사 로그(누가 언제 무엇을) 노출이 약하다. CLAUDE.md에 따르면 D1이 개발=운영 공용이라 실수 반경이 크다. 143 innerHTML sites risk XSS if server data reaches the DOM unescaped (needs an escaping audit). The shared 401 session-expiry banner and pii-mask.js already exist — good. But there is no admin MFA, weak re-confirmation for irreversible actions (delete/settlement), and little audit-log visibility (who did what, when). Per CLAUDE.md, D1 is shared dev=prod, so the blast radius of a mistake is large.

⑤ 번역(EN/KO): 전체 문자열 일치 방식이라 잘 깨진다Translation: brittle full-string matching

현재 i18n는 data-ko/data-en 쌍 1,734개 + 172KB 사전의 “문자열 전체 일치” 방식이라, 라벨에서 이모지만 떼도 번역이 깨진다(CLAUDE.md 명시). JS로 textContent로 그린 라벨은 언어 전환에 안 따라온다. 키 기반 i18n로 점진 전환하면 안정적이고 사전 용량도 준다. The current i18n uses 1,734 data-ko/data-en pairs plus a 172 KB dictionary keyed on the full string — so removing even an emoji from a label breaks the translation (noted in CLAUDE.md). Labels drawn via textContent don't follow language switches. Moving gradually to key-based i18n is more robust and shrinks the dictionary.

⑥ 유지보수: 스파게티화 위험 (인라인 style·onclick 대량)Maintainability: spaghetti risk (mass inline style/onclick)

인라인 style= 2,685개, onclick= 468개는 CSS 우선순위 충돌(CLAUDE.md의 “카드 색이 안 먹음” 함정)과 이벤트 추적 어려움을 낳는다. 한 번에 걷어내면 위험하니 카드 단위로 공통 클래스·이벤트 위임 전환을 권장. 2,685 inline style= and 468 onclick= cause CSS-priority clashes (the "card color won't apply" trap in CLAUDE.md) and hard-to-trace events. Refactoring all at once is risky, so migrate to shared classes and event delegation card by card.
