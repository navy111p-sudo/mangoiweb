1판 정정 이 사이트에는 실사용자가 없습니다

1판에서 “학생 29,000명이 쓰는 라이브”라고 전제했는데 틀렸습니다. 확인한 사실:

  • 실제 학생이 쓰는 곳은 www.mangoi.co.kr — 완전히 다른 시스템입니다. Apache + PHP 7.2.5로 돌아가고, 첫 화면 57KB이며, 이 저장소와 코드를 한 줄도 공유하지 않습니다.
  • test.mangoi.co.kr(이 저장소)는 아직 출시 전입니다. 강사들이 남긴 사용 흔적은 테스트입니다.
  • DB의 학생 29,391명은 Cafe24에서 한 방향으로 복제해 온 미러입니다 (cafe24-sync.ts:89, INSERT OR REPLACE). 지워도 다시 받아올 수 있습니다.

그래서 이 보고서의 결론이 바뀝니다. 1판은 “깨지면 안 되니 몇 달에 걸쳐 조금씩”이었는데, 그 제약이 통째로 사라졌습니다. 아래 5장의 계획을 그 전제로 다시 썼습니다. 진단(1~4장)의 숫자와 문제는 그대로 유효합니다.

세 줄 요약
  • 망고아이 코드는 망가진 게 아니라 “너무 크게 자란” 상태입니다. 기능은 잘 돌아갑니다.
  • 문제는 “고치기가 점점 어려워진다”는 것입니다. 파일 하나가 3만 줄이 넘고, 고장이 나도 조용히 숨겨지고, 자동 배포에는 안전장치가 거의 없습니다.
  • 지금이 이걸 바로잡을 수 있는 거의 유일한 시기입니다. 사용자가 붙으면 다시 못 합니다. 다만 백지에서 새로 쓰는 것은 여전히 권하지 않습니다 — 이유는 5장에 적었습니다.

1. 지금 가장 위험한 것 (빨간불)

위험 1 고장이 나도 아무도 모른다 — “조용히 삼키는 코드”

프로그램에는 “여기서 문제 생기면 이렇게 하자”라고 적는 자리가 있습니다(catch). 그 자리에 아무것도 안 적어두면, 문제가 생겨도 프로그램은 아무 말 없이 그냥 지나갑니다.

어디“아무 말 없이 지나가는” 자리 수
public/index.html (학생·수업 화면)431개 (전체 catch 1,388개 중)
src/*.ts (서버 전체)약 700개 (전체 catch 1,604개 중)
왜 문제냐면 — 화재경보기 431개의 전선을 잘라 둔 것과 같습니다. 불이 안 나는 게 아니라, 불이 나도 소리가 안 나는 겁니다. 실제로 이 저장소의 사고 기록을 보면 “학생이 수업에 못 들어갔는데 서버는 정상(200)으로 응답했다”는 장애가 있었습니다. 화면은 멀쩡해 보이는데 속은 죽어 있는 상태가 이래서 생깁니다.
어떻게 고치나
  • 빈 자리를 전부 채울 필요는 없습니다. 돈·수업·로그인과 관련된 곳부터 골라 최소한 console.warn 한 줄이라도 남깁니다. (지금도 console.*은 296개뿐이라 너무 적습니다)
  • 서버에는 “에러 모아 보는 곳”을 하나 만듭니다. Cloudflare Workers에는 이미 로그 기능이 있어 새로 살 게 없습니다.
  • 새로 쓰는 코드에서는 빈 catch{}를 금지하고, 하니스에 검사 항목을 하나 추가해 자동으로 막습니다.
난이도: 중 · 효과: 매우 큼 (앞으로의 모든 버그 찾는 시간이 줄어듭니다)

위험 2 자동 배포에는 안전장치가 거의 없다

망고아이는 실서비스에 올리는 길이 두 개입니다. 그런데 두 길의 검사 수준이 완전히 다릅니다.

① 사람이 직접 (deploy.ps1)② 자동 (main에 push하면 GitHub Actions)
문법 검사(tsc)✅ 실패하면 배포 중단⚠️ continue-on-error: true — 실패해도 그냥 배포됨
회귀 테스트✅ 하니스 전체(run.mjs --fast, 114개)❌ 2개만 실행 (문법·캐시버전)
라이브 스모크 15종✅ 있음❌ 없음
왜 문제냐면 — 공항에 검색대가 두 개인데 한쪽만 제대로 검사하고 다른 쪽은 그냥 통과시키는 상황입니다. 실수로 ②번 길로 나가면 검사를 아예 안 받습니다. 게다가 npx tsc는 이 저장소의 CLAUDE.md에도 적혀 있듯이 조용히 실패했을 때와 통과했을 때의 화면이 똑같습니다 — 검사한 척만 하고 있을 수 있습니다.
어떻게 고치나 — 이건 반나절이면 끝나는 일이고 효과가 가장 큽니다.
  • .github/workflows/deploy.yml에서 continue-on-error: true를 지웁니다.
  • 같은 파일에서 npx tsc 대신 node node_modules/typescript/bin/tsc --noEmit을 씁니다.
  • node test-harness/run.mjs --fast 한 줄을 추가해 자동 배포도 같은 검사를 받게 합니다.
난이도: 하 (파일 1개, 3줄) · 효과: 매우 큼

위험 3 데이터베이스의 “설계도”가 어디에도 없다

DB(자료를 담는 창고)에는 보통 설계도 파일이 따로 있고, 바뀔 때마다 순서대로 기록합니다. 망고아이는 그게 아니라 서비스가 돌아가는 도중에 코드가 표를 만듭니다.

왜 문제냐면 —
  • 지금 DB가 정확히 어떤 모양인지 아무도 모릅니다. 324군데를 다 읽어야 알 수 있습니다.
  • 학생이 버튼을 누를 때마다 “표 있나? 없으면 만들어” 같은 명령이 같이 나갑니다 — 느리고, 돈도 더 듭니다.

  • 앞으로 표 모양이 바뀌면 migrations/0001_xxx.sql처럼 번호를 붙여 파일로 남깁니다.
  • 요청을 처리하는 코드 안의 CREATE TABLE은 한 번에 다 지우지 말고, 건드리는 파일이 생길 때마다 하나씩 걷어냅니다.

  3. api-admin.ts 9,561줄은 주제별로(급여 / 통계 / 강사 / 스케줄) 나눕니다.

문제 6 파일 이름만 봐서는 무슨 일을 하는지 알 수 없다

어떻게 고치나 — 테마가 항상 ivory 하나로 고정이므로, 다크 전용 규칙은 통째로 지울 수 있습니다. 다만 지우면 색이 바뀌는 곳이 나오니 화면 하나씩 사진을 찍어 비교하며 걷어냅니다. 난이도: 중 · 효과: 중 (앞으로 디자인 수정이 훨씬 쉬워집니다)
